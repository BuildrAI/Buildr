# Buildr自举激活（Buildr Self-bootstrap Activation）

本Skill只属于Buildr自举Workspace，是`buildr-self-bootstrap` Component唯一的Activation owner。它不是Delivery provider，也不是用户Workspace的默认能力。

## 定位与默认入口

本技能（Skill）只处理 Buildr 自举工作空间的激活，不负责交付业务内容或任务完成登记。明确的基线到交付提交命中实际自举输入时，使用同一执行脚本的直接模式：

```bash
# 智能体侧 HOME 是隔离目录，显式指向真实用户主目录；
# 开发数据目录由 BUILDR_HOST_HOME 推导，也可用 BUILDR_APP_DATA_DIR 直接指定。
HOME="${BUILDR_HOST_HOME:-$HOME}" \
  <development-host-node> skills/buildr-self-bootstrap-sync/scripts/closeout.mjs \
  --base-ref <base-commit> --delivered-ref <delivered-commit> \
  --branch <target-branch> --remote <remote> --agent <adapter> \
  --target <canonical-workspace> --node-executable <development-host-node> --detail full
```

`--node-executable` 是**开发宿主 node**（实例记录 `launcherIdentity.developmentRuntime.executable`，通常是 `BUILDR_HOST_HOME` 下的 node），不是 agent-service 运行时目录里的保留 node：安装后的启动器把它写成 `developmentRuntime`，网页构建又需要相邻 npm 或 PATH 中的 `npm`。省略该选项时按「实例记录 → `BUILDR_NODE` → 当前进程 node」解析。保留 node 与开发宿主 node 不是同一角色时，构建与安装用前者，最终验证用后者。

脚本通过 Git 复核基线、实际改动、当前分支及远端包含关系。正式任务记录不是前置条件；可选 `--task <task-id>` 在新同步提交中同时写入一行标准任务尾注（Trailer）`Buildr-Task: <task-id>`，保留原有 `Buildr-Activation-Task` 说明，不查询或修改任务状态。未提供任务编码时不写这两项任务尾注（Trailer）；恢复既有后继提交时不补写或改写提交说明。参数不是成功证明；脚本不写第二交付状态库。没有对应环境时也不补造环境。成功和失败都按实际动作返回，已有交付不撤销。

需要先核对更新范围时，在同一组交付参数后加 `--plan true`。该模式只读核对交付与远端，列出工作空间同步、开发应用（其中单列 Harness 网页和后台相关输入）与 DSH 插件命中的路径；不启动独立执行器、不安装或推送。预检只说明按差异选中的步骤，不等同当前本机已安装或具备换装条件；实际执行会重新核对。

默认模式先核验现场并短暂占用自举锁，再按实际变更执行适用的同步（显式发布本次交付的共享资源，普通打开不发布）、精确提交和普通推送、开发应用更新、显式开发入口检查与最终诊断。已推送内容不重复推送；提交后推送失败可用同一组输入恢复。未提交同步结果、未知锁或身份变化应保留并说明，不自动丢弃或夺锁。

最终诊断会核对当前宿主及工作空间已存在的其他受管运行时适配器（Adapter）；任一已存在运行时仅因工作空间根派生投射过期或受管孤儿残留而未就绪时，执行器会按对应适配器有界执行一次派生投射刷新并重新诊断，不为不存在的适配器创建新目录。该恢复不发布共享资源、不降低资源版本、不修改源文件；刷新失败、出现其他诊断、源内容漂移或复查仍未就绪时继续停止。调用者不得在执行器之外补跑同步、投射或最终诊断。

命令行入口在执行任何激活动作前，将同一执行器（Runner）交给独立进程（Process），标准错误先返回进程编号、结果文件和日志路径。调用方等待原有最终结果；旧宿主退出或原对话中断不取消独立执行。结果文件仅保全本次执行输出，不替代交付事实、待恢复信息或最终诊断。调用方中断后先读取该结果及当前锁和实例，不因断开重复发起激活；独立执行仍未结束时继续等待，不停止或夺取它的锁。

用户明确要求实际重启开发版（包括同版本验证）时，在同一入口追加 `--restart-development-web true`。该选项要求当前存在可核验的健康开发实例，沿用安装、认证退出、恢复、入口检查与最终诊断，不绕过归属保护；默认仍复用同版健康实例，不因普通同步中断工作。

页面重启与开发更新相遇时，连续性步骤依据认证健康状态有界等待，并在退出冲突后重读当前实例。仅在收据与健康身份一致、启动器来源与绑定运行时仍属于本次已核对范围时接续；旧进程编号只供追溯，不因同来源页面重启已完成而永久拒绝后续更新。不同归属、无法证明的替换或等待超时保留现场并报告，不能绕过退出协调或手工重建默认实例。

直接从源码启动的开发服务可能没有启动器标记。只有认证健康信息与本机实例记录一致、产品明确处于开发角色、源码根和 Node 路径均与本次保留来源匹配时，执行器才按同源服务接续更新；实际启动器标记仍保留原值。其他目录、其他 Node、发布版和证明不完整的服务继续保留，不按端口或名称接管。

开发应用更新与来源校验共用产品安装身份模块的运行输入定义，覆盖后端、依赖声明、网页生产构建输入及实际产物、启动入口。已交付运行输入变化时，执行器（Runner）重新构建适用内容，并正常退出和恢复已运行的开发版；恢复后核对运行内容证明。文档、测试及独立 DSH 插件变化不会仅因仓库提交编号变化而重启或失配，提交编号继续用于追溯。旧实例缺少新证明时保留原严格来源校验，首次运行更新正常重启后记录新证明。投射后的脚本从本次已核对的产品根加载共享定义，不复制路径清单。本机已安装且归属当前开发检出与数据目录的 `Buildr Harness Dev` 启动器随运行输入一并原位刷新，未安装不新建；若开发版智能体后台正在运行且命中 Harness 运行输入，同时激活新版运行单元并对已启用的独立 Harness 网页做无浏览器就绪核验，不替未启用环境开启独立网页。

独立 DSH 开发插件仍不是 Buildr Web 的运行输入。交付命中 `buildr-harness-dsh-plugin` 或 `buildr-development-dsh-plugin` 插件源码、包声明、组合补丁或打包脚本时，执行器在工作空间检查通过后分别更新本工作空间已装的本地 `@buildr-ai/dsh-buildr-harness-dev` 与 `@buildr-ai/dsh-buildr-dev`（兼容将本工作空间已安装的旧包名 `@buildr-ai/buildr-harness-dsh-plugin-dev`、`@buildr-ai/dsh-buildr-development-dev` 与 `@buildr-ai/buildr-development-dsh-plugin-dev` 先卸载再安装新包名）。只使用支持版本的 macOS DSH 桌面及其原 `desktop` 配置；未安装则跳过，来源不符则保留。文档、测试及单独 Harness 网页更新不重装。默认不停止或重开 DSH；DSH 正在运行或退出无法核验时只准备候选并返回待安装，保留本次执行返回的完整 `resultFile`；正常退出后给同一组交付参数追加 `--resume-dsh <resultFile>`，只接续插件换装并复验保留入口和 Doctor，不重做同步、推送或网页安装。接续要求同一保留提交和环境、上次没有尝试安装；文件丢失、来源漂移或结果未知时先核对，不覆盖运行配置、不公开发布。安装后回读包来源和文件，单独报告桌面尚未确认加载。

用户明确发起「更新 Buildr Harness / Buildr 开发插件并重开 DSH」时，在同一自举入口追加 `--restart-dsh true`（也可与 `--resume-dsh` 一起使用）。只在插件包确实改变、可确认桌面现持该开发包及自举维护的原绑定时尝试：若一次命中多个待更新插件，先批量准备全部候选并校验绑定，再仅正常请求退出一次、确认退出后顺序迁移并安装所有目标插件，最后仅以原开发宿主绑定重开一次并核对新进程的插件宿主回执。不会升级 DSH 应用、重启 Buildr Harness 后台来换包、打开原本未运行的 DSH 或在纯网页交付中退出 DSH。旧开发插件没有回执时，先按原流程完成一次换装；实例有自定义启动参数、归属不明或退出未确认时仍保留待安装，不强退。安装或启动结果不明时先核对，无自动重试。宿主回执不等同于界面已渲染。

安装与来源校验期间保留正在运行的开发应用；网页在独立目录构建并校验成功前不修改在线产物，编译或工具链失败保留旧页面。发布采用短暂目录切换并保留上一代哈希资源，不承诺零中断；发布失败尝试恢复旧产物，恢复失败保留备份并报告路径。校验通过后才认证退出旧实例。执行器（Runner）在退出前保存本机待恢复信息，更新失败时尝试恢复并分别报告原失败和恢复结果；恢复未完成时保留该信息，后续重试即使当前没有实例也必须继续恢复。进程身份和网页可用性分别核对：首页和关键同源脚本/样式都实际通过 HTTP 交付检查后，才能宣称网页已恢复并清除待恢复信息；HTTP 检查不等于浏览器已刷新或完成渲染。来源、数据目录或实例归属改变时保留现场并报告，不能误停其他实例或把未恢复报告为成功。不要仅凭旧启动器宣称可回退旧后端，不自动回退用户源码、依赖或数据库。

阶段与操作的开始、结束和单调耗时保存在既有结果中，固定字段进度事件提前写入独立执行日志；未结束时先看当前阶段，不重复发起运行。开发准备细分 Agent 准备、接口类型生成与网页构建，构建时长与退出/启动/页面验收时长分别报告。认证退出到页面验收完成只表示中断的保守上界；原页面此前已不可用、尚未恢复或未观察到中断必须分别说明，不伪报精确停机或零中断。日志不输出命令参数、环境秘密或完整原始子进程输出；输出展示截断不改变真实执行结果。

同步已经成功而暂存或提交失败时，先核对原失败返回中的成功同步及精确文件集合，再由智能体（Agent）根据当前事实构造临时恢复输入，通过同一脚本的 `--resume-sync <json-file>` 接续。普通未提交改动仍拒绝；该输入不是历史回执或额外授权，不自动生成、修复或放宽声明。

```json
{
  "schemaVersion": "buildr.self-bootstrap-sync-resume/v1",
  "workspaceRoot": "/absolute/canonical-workspace",
  "baseRef": "<原基线完整提交>",
  "deliveredRef": "<原交付完整提交>",
  "targetBranch": "dev",
  "remote": "origin",
  "agent": "codex",
  "expectedHead": "<当前已交付完整提交>",
  "stagedPaths": [],
  "files": [{ "path": "skills/buildr/example/SKILL.md", "sha256": "sha256-<当前文件64位十六进制摘要>" }]
}
```

基线、交付、分支、远端和宿主保持原值；必要的所有者修复另行交付后，`expectedHead` 绑定重新核验的当前提交。`files` 必须与原成功同步的已核验集合一致，并记录当前字节摘要；`stagedPaths` 精确记录当前暂存路径且不得含部分暂存。文件仅允许产品同步的源资产区及明确清单、回执，不接受运行时（Runtime）目录、实现源码、符号链接或路径穿越。执行器（Runner）重新检查实际未提交集合、暂存集合、文件摘要、当前提交和远端；暂存后再校验实际暂存内容摘要及身份。任一漂移只停止相关恢复，保留现场；核验通过才跳过重复同步，由原执行器（Runner）继续提交、推送及适用的安装、入口检查和诊断。输出记录本次恢复核验，不伪造新的同步执行。

恢复已创建提交后再遇推送或诊断失败时，去掉 `--resume-sync`，按原直接入口接续；不把旧临时快照改造成新的恢复事实。所有者修复的投射尚未更新时，也由同一执行器（Runner）按已交付修复范围执行正常同步。

适用范围包括根与项目/服务 `AGENTS.md`、`rules/`、`skills/`、`components/`、`commands/` 和产品运行输入。已交付范围命中时执行对应动作；不按是否有任务、任务是否完成或提交作者判断。未提交或尚未交付的源内容先完成交付。

本脚本只接受上述直接交付输入；失败恢复使用同一基线、交付提交、分支、远端和宿主，任务编号不参与新后继提交的身份。已有任务的成果、记录和资源依据当前事实核对后，再选择适用激活或原资源安全处置。

失败时报告已发生动作、具体失败点及当前交付事实；既有成果不重推。Worktree和具体资源由各自owner独立清理，不改写任务完成事实。
