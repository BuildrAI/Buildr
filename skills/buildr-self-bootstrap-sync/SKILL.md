# Buildr自举激活（Buildr Self-bootstrap Activation）

本Skill只属于Buildr自举Workspace，是`buildr-self-bootstrap` Component唯一的Activation owner。它不是Delivery provider，也不是用户Workspace的默认能力。

## 定位与默认入口

本技能（Skill）只处理 Buildr 自举工作空间的激活，不负责交付业务内容或任务完成登记。明确的基线到交付提交命中实际自举输入时，使用同一执行脚本的直接模式：

```bash
<retained-node> skills/buildr-self-bootstrap-sync/scripts/closeout.mjs \
  --base-ref <base-commit> --delivered-ref <delivered-commit> \
  --branch <target-branch> --remote <remote> --agent <adapter> \
  --target <canonical-workspace> --node-executable <retained-node> --detail full
```

脚本通过 Git 复核基线、实际改动、当前分支及远端包含关系。正式任务记录不是前置条件；可选 `--task <task-id>` 在新同步提交中同时写入一行标准任务尾注（Trailer）`Buildr-Task: <task-id>`，保留原有 `Buildr-Activation-Task` 说明，不查询或修改任务状态。未提供任务编码时不写这两项任务尾注（Trailer）；恢复既有后继提交时不补写或改写提交说明。参数不是成功证明；脚本不写第二交付状态库。没有对应环境时也不补造环境。成功和失败都按实际动作返回，已有交付不撤销。

默认模式先核验现场并短暂占用自举锁，再按实际变更执行适用的同步（显式发布本次交付的共享资源，普通打开不发布）、精确提交和普通推送、开发应用更新、显式开发入口检查与最终诊断。已推送内容不重复推送；提交后推送失败可用同一组输入恢复。未提交同步结果、未知锁或身份变化应保留并说明，不自动丢弃或夺锁。

命令行入口在执行任何激活动作前，将同一执行器（Runner）交给独立进程（Process），标准错误先返回进程编号、结果文件和日志路径。调用方等待原有最终结果；旧宿主退出或原对话中断不取消独立执行。结果文件仅保全本次执行输出，不替代交付事实、待恢复信息或最终诊断。调用方中断后先读取该结果及当前锁和实例，不因断开重复发起激活；独立执行仍未结束时继续等待，不停止或夺取它的锁。

用户明确要求实际重启开发版（包括同版本验证）时，在同一入口追加 `--restart-development-web true`。该选项要求当前存在可核验的健康开发实例，沿用安装、认证退出、恢复、入口检查与最终诊断，不绕过归属保护；默认仍复用同版健康实例，不因普通同步中断工作。

页面重启与开发更新相遇时，连续性步骤依据认证健康状态有界等待，并在退出冲突后重读当前实例。仅在收据与健康身份一致、启动器来源与绑定运行时仍属于本次已核对范围时接续；旧进程编号只供追溯，不因同来源页面重启已完成而永久拒绝后续更新。不同归属、无法证明的替换或等待超时保留现场并报告，不能绕过退出协调或手工重建默认实例。

直接从源码启动的开发服务可能没有启动器标记。只有认证健康信息与本机实例记录一致、产品明确处于开发角色、源码根和 Node 路径均与本次保留来源匹配时，执行器才按同源服务接续更新；实际启动器标记仍保留原值。其他目录、其他 Node、发布版和证明不完整的服务继续保留，不按端口或名称接管。

开发应用更新与来源校验共用产品安装身份模块的运行输入定义，覆盖后端、依赖声明、网页生产构建输入及实际产物、启动入口。已交付运行输入变化时，执行器（Runner）重新构建适用内容，并正常退出和恢复已运行的开发版；恢复后核对运行内容证明。文档、测试及独立 DSH 插件变化不会仅因仓库提交编号变化而重启或失配，提交编号继续用于追溯。旧实例缺少新证明时保留原严格来源校验，首次运行更新正常重启后记录新证明。投射后的脚本从本次已核对的产品根加载共享定义，不复制路径清单。

安装与来源校验期间保留正在运行的开发应用；校验通过后才认证退出旧实例。执行器（Runner）在退出前保存本机待恢复信息，更新失败时尝试恢复并分别报告原失败和恢复结果；恢复未完成时保留该信息，后续重试即使当前没有实例也必须继续恢复。只有确认同一来源的开发应用已健康运行才清除待恢复信息；来源、数据目录或实例归属改变时保留现场并报告，不能误停其他实例或把未恢复报告为成功。

同步已经成功而暂存或提交失败时，先核对原失败返回中的成功同步及精确文件集合，再由智能体（Agent）根据当前事实构造临时恢复输入，通过同一脚本的 `--resume-sync <json-file>` 接续。普通未提交改动仍拒绝；该输入不是历史回执或额外授权，不自动生成、修复或放宽声明。

```json
{
  "schemaVersion": "buildr.self-bootstrap-sync-resume/v1",
  "workspaceRoot": "/absolute/canonical-workspace",
  "baseRef": "<原基线完整提交>",
  "deliveredRef": "<原交付完整提交>",
  "targetBranch": "dev",
  "remote": "origin",
  "agent": "codex",
  "expectedHead": "<当前已交付完整提交>",
  "stagedPaths": [],
  "files": [{ "path": "skills/buildr/example/SKILL.md", "sha256": "sha256-<当前文件64位十六进制摘要>" }]
}
```

基线、交付、分支、远端和宿主保持原值；必要的所有者修复另行交付后，`expectedHead` 绑定重新核验的当前提交。`files` 必须与原成功同步的已核验集合一致，并记录当前字节摘要；`stagedPaths` 精确记录当前暂存路径且不得含部分暂存。文件仅允许产品同步的源资产区及明确清单、回执，不接受运行时（Runtime）目录、实现源码、符号链接或路径穿越。执行器（Runner）重新检查实际未提交集合、暂存集合、文件摘要、当前提交和远端；暂存后再校验实际暂存内容摘要及身份。任一漂移只停止相关恢复，保留现场；核验通过才跳过重复同步，由原执行器（Runner）继续提交、推送及适用的安装、入口检查和诊断。输出记录本次恢复核验，不伪造新的同步执行。

恢复已创建提交后再遇推送或诊断失败时，去掉 `--resume-sync`，按原直接入口接续；不把旧临时快照改造成新的恢复事实。所有者修复的投射尚未更新时，也由同一执行器（Runner）按已交付修复范围执行正常同步。

适用范围包括根与项目/服务 `AGENTS.md`、`rules/`、`skills/`、`components/`、`commands/` 和产品运行输入。已交付范围命中时执行对应动作；不按是否有任务、任务是否完成或提交作者判断。未提交或尚未交付的源内容先完成交付。

本脚本只接受上述直接交付输入；失败恢复使用同一基线、交付提交、分支、远端和宿主，任务编号不参与新后继提交的身份。已有任务的成果、记录和资源依据当前事实核对后，再选择适用激活或原资源安全处置。

失败时报告已发生动作、具体失败点及当前交付事实；既有成果不重推。Worktree和具体资源由各自owner独立清理，不改写任务完成事实。
