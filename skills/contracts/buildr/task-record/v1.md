# 任务记录

## Purpose

通过产品化动作创建、查看、明确更新、完成或放弃 canonical Workspace 中的正式 Task Record，使人和 Agent 共享同一份最小顶层任务事实。

## Consumer Obligations

consumer 必须先判断工作已经进入正式持久交付，而不是普通对话、只读探索、临时操作或只维护既有生命周期 metadata；必须提供稳定 Task ID、canonical Workspace target，以及动作要求的 title、intent、scope、Change 引用或终态摘要。当前位于 task environment 时，consumer 必须使用上游已经确认的 canonical Workspace target，不得要求 provider 从环境目录或 receipt 推断 retained root。按 Task ID 继续或 Local App 已创建记录时必须先 inspect，不得重复创建或要求用户重输顶层事实。

## Minimum Guarantees

provider 必须只通过 Task Record Application 的 `create`、`inspect`、`update`、`complete`、`abandon` 五个动作管理 `.buildr/tasks/<task-id>/task.yml`；必须校验 closed `buildr.task-record/v1` schema、Project/Service/Change identity、当前记录内去重、active 到 terminal 的单向转换、系统时间和响应级 `recordDigest`。provider 不得要求 Agent 手写 YAML、提交完整 next-state 文档或自行生成系统字段。Local App 是同一 Application 的独立人类客户端，不通过 Skill routing 写记录。

## Effects and Authorization

create 只能新建一个 Task 目录和 `task.yml`；update、complete、abandon 只能替换该 Task 的同一文件；inspect 零写入。provider 不创建、定位、记录或清理 Task Environment，不执行 Development、Review、Verification、Git、Finish、Board、Retrospective、publication 或其他专业动作，也不复制这些模块的 path、revision、result 或运行状态。任何 Git publication 都需要后续模块和独立授权。

## Result Evidence

provider 必须返回实际 operation、`created|inspected|updated|completed|abandoned|blocked` status、Task ID、canonical path、当前 record、响应级 `recordDigest`、精确 effects、diagnostic 和 nextActions。`recordDigest` 只用于证明当前 read model；不得写入 `task.yml` 或解释为持久 revision。失败时 effects 必须为空，且不得把候选生成、文件存在或专业模块结果冒充 Task Record 成功。

## Decision Points

目标不是已初始化 canonical Workspace、指向 task worktree、Task ID 冲突、记录损坏、引用无法解析、mutation 不明确、终态改写或 filesystem 替换失败时必须返回 blocked 并保留原记录。Local App update、complete、abandon 的 `expectedRecordDigest` 陈旧时必须返回 `task_record_conflict`，要求刷新，不自动合并。selected provider 在正式持久交付分支不 ready 时 consumer 必须停止首次交付写入；纯讨论、只读探索和其他非正式分支保持不依赖。

## Allowed Variations

provider 可以调整 CLI 文案、内部 YAML renderer、列表展示和 Local App 布局；必须保持 Task Record v1 closed schema、canonical path、五个动作、共享 Application、响应级 digest、终态单向性和专业 authority 边界。
