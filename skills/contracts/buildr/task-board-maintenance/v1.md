# 任务看板维护

## Purpose

为复杂任务创建或更新以 Project task identity 为主、由 Agent 单向维护且不替代权威事实的稳定任务看板。

## Consumer Obligations

consumer 必须提供 operation（`create` 或 `update`）、retained Workspace/Project/task identity、已核实任务事实、事实来源、当前授权范围和可用的真实 OpenSpec change 关联。调用发生在 task environment 中时，必须提供成功的 `buildr worktree context` result；provider 只消费其中的 `workspaceRoot`，不得要求 receipt 内容或额外显式 Workspace identity。没有 change 时必须显式提供空关联，不得使用 planned name 冒充真实 change。

## Minimum Guarantees

provider 必须在 retained Workspace checkout 解析拥有任务的 Project 和稳定 `openspec/knowledge/task-boards/yyyy-MM-dd-<task-id>.html` 路径；task environment 中的 retained root 必须唯一来自 `worktree context.workspaceRoot`。`create` 必须使用自包含 runtime 模板，`update` 必须复用同一路径。关联 task environment 只能作为事实来源，不得创建、复制、更新或持有看板。看板必须优先服务普通用户理解，保持只读交互和事实来源边界，并允许 `changes` 与 batch `changeIds` 为空。

## Effects and Authorization

provider 只有在 consumer 已授权 retained Workspace 中当前 Project task 范围的 task-board 写入时，才能创建或更新单个看板文件。不得写入关联 task environment，不得修改 canonical specs、active/archived Changes、代码、验证 evidence 或外部系统；不得移动、转换或覆盖既有 `task-cockpits/` 页面。

## Result Evidence

provider 必须返回 `operation`、`status: created|updated|aligned|blocked`、Workspace/Project/task identity、绝对与 workspace 相对路径、真实 change ids 或空集合、changedAssets、sourceIdentities、updatedAt、unresolvedItems 和 nextActions。未成功写入时不得返回 created/updated。

## Decision Points

`worktree context` blocked、未返回有效 `workspaceRoot`、environment identity 不匹配，或 retained Workspace、Project、task identity、事实来源、写入授权或稳定路径无法确认，既有页面冲突，或候选内容会覆盖权威事实时，provider 必须返回 `blocked` 并保留现场。不得读取 receipt 结构、扫描路径或接受显式 Workspace identity 作为 environment 内 fallback。发现业务契约变化时必须要求 consumer 先进入 task triage/change-flow；普通 code-only、外部依赖和验证进度不要求创建 Change。

## Allowed Variations

provider 可以调整 HTML 视觉设计、信息层级、模板内部 schema 扩展和事实采集工具；必须保持稳定 task identity/path、Agent 单向维护、普通用户优先、自包含、真实 change 关联、无 change 可用和结构化 result evidence。
