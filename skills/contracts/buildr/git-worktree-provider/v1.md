# Git Worktree Provider

## Purpose

为明确的 Task 和 repository selectors 创建、检查或清理 Git worktree，并返回窄 Git provider evidence。

## Consumer Obligations

consumer创建时必须提供canonical Workspace、Task ID、分支、start point和明确repository selectors。清理时consumer必须先核验实际交付，再用完整提交编号成对提供全部受管仓库的`cleanupDelivery.expectedSources`与`cleanupDelivery.deliveredRefs`；该输入只供当次删除，不是证明库。旧Environment可继续提供既有ancestor或Task Contribution兼容输入，但新公共Worktree CLI不暴露该历史模型。consumer不能要求provider判断Task完成、Runtime、依赖、Preview、业务等价或总cleanup。

## Minimum Guarantees

provider必须在`<workspace>/.worktrees/<task-id>`及canonical nested source paths操作，写入前检查Git common directory、remote、branch ownership、target occupancy和既有evidence。它只维护Git common-dir下`buildr/task-worktrees/<task-id>.json`中的repository identity/effects；该文件不是Task状态、Environment Receipt或交付证明。

## Effects and Authorization

provider 可以创建或删除已证明属于该Task的本地checkout和本地分支。对显式使用旧贡献证明的isolated carrier交付，它必须从当前Task source与Git objects独立复算原/应用后raw delta identities，只有source未漂移、target等于carrier且identity完全等价时，才可把Task-owned dirty checkout视为已集成并清理。已核验交付输入下，provider必须核对源提交和工作树状态未变化、交付提交仍由保留分支持有，并条件删除本地任务分支；不再检查原提交祖先或补丁等价，不得把caller核验标成软件证明。部分失败必须保留现场并返回blocked。删除远端分支、修改原Task worktree/index/branch、force push、以路径不重叠推断语义安全或清理非Git资源不属于本contract。

## Result Evidence

返回operation、Task ID、workspace、evidence path、repository selectors、source/checkout path、branch、start point、HEAD、clean/registered/remote state、effects和diagnostic。不得返回统一ready、runtime projection、依赖、session adoption、Preview或业务结果。

## Decision Points

路径、remote、branch、registered worktree、source snapshot、baseline/carrier/target ref或Task Contribution identity冲突，任一未获等价证明的checkout dirty，或integrated identity无法证明时必须停止且不扩大清理范围。

## Allowed Variations

Agent、Task Finish、OpenSpec/Change reader或过渡Environment可以组合此provider；全部入口必须产生同一Git evidence与删除安全语义。
