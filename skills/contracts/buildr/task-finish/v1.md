# 任务收尾执行器

## Purpose

把已具备收尾资格的候选通过 `preflight → prepare → verify → deliver → cleanup` 固定工作流完成交付。Task Finish 是确定性 closeout executor，不是研发、审查、测试修复或通用恢复引擎。

## Consumer Obligations

consumer 必须提供 receipt-bound task environment、Workspace Node identity、active change、Project 和目标分支语义，并在调用前确认开发、自审、必要审查、开发验证与 current knowledge 已达到完成标准。资产 observation 的 finalize 和人工决定发生在产品 Finish run 之外；仍为 `awaiting-human` 时不得开始会修改候选的阶段。

consumer 不得提交 caller evidence、fingerprint、execution plan、attempt outcome、repair authorization 或 recovery manifest 来替产品证明阶段完成。产品缺陷、语义冲突或候选内容问题必须退出 Finish，回到研发、审查和测试验证流程修正当前实现，形成新的 finish-ready candidate 后重新进入。

## Minimum Guarantees

provider 必须由单一 canonical `buildr task finish run` 顺序执行五个固定阶段，不暴露通用 DAG 或 action registry 作为正常路径。`preflight` 只读并一次聚合环境、CLI 实际可执行性、Change tasks、current knowledge、OpenSpec strict/并发计划、验证声明、Git identity、目标分支与 retained checkout 的廉价检查。

`prepare` 完成所有会改变候选的确定性动作，包括 OpenSpec convergence、生成资产同步、candidate commit、target convergence 和机械 fixed point；随后写入 frozen candidate identity。freeze 后任何候选变化都使 run 终止，不能在同一 run 中修复。

`verify` 对 frozen candidate 至多执行一次 required final assurance，或复用与 candidate identity、Workspace Node identity 和 assurance level 完全一致的通过证据。缺少 Node identity 的旧 evidence 不得复用。任何失败必须返回具体 phase、operation、check、exit code、bounded findings 与 diagnostic reference，并以 `upstream-candidate-defect` 终止 run、返回 `nextWorkflow: task-development`。provider 不得授权修复、修改候选或在同一 run 中重新验证；返工和重新验证时间不计为本次 Finish 时间。

`deliver` 必须使用短 target lease/fencing，核对 freeze 时与 push 前 target ref，只允许 fast-forward 集成和目标分支 push；远端竞态、网络失败、retained sync/install 等外部暂态可 blocked。`cleanup` 必须先写 canonical durable completion receipt，再从 retained checkout 清理 task-owned verification evidence、worktree、branch 和 receipt。

blocked 恢复输入只能由产品根据持久化事实生成，并绑定 run、phase、candidate 与 failure identity；恢复只重试当前 blocked phase 和下游。产品缺陷失败是终态，没有 resume token。客户端直接使用唯一 canonical `runs`、`completed` 与 lease namespace，不创建版本化运行目录；旧 run shape 不可恢复，也不解释、迁移或执行旧协议。

正常完成结果必须证明 canonical CLI invocation 为 1、Agent/provider completion 为 0、手写 recovery manifest 为 0、formal verification execution 不超过 1，并报告 product command observations、product execution 和 end-to-end wall-clock。

Task environment 的 `executionReady` 必须同时证明 receipt identity、runtime projection、Workspace Node identity 和 receipt-bound CLI 的真实 `version --json` 探针成功；冻结、恢复、验证与交付前任一 Node identity 漂移都必须停止。路径存在或 executable bit 不足以证明可执行。

## Effects and Authorization

普通“收尾”授权确定性的 OpenSpec convergence、生成资产收敛、候选提交、target rebase/fast-forward、目标分支 push、retained runtime sync/install 及 task-owned 本地清理。它不授权修复产品缺陷、解决语义冲突、force push、改写共享历史、丢弃用户改动、操作远端任务分支或删除非 task-owned 状态。

## Result Evidence

结果使用 `buildr.task-finish-result/v1`，包含 run/task/change/project/target/Workspace Node identity、五阶段状态、frozen candidate、verification、delivery、completion、具体 primary failure、产品生成的可选 resume token、next workflow 及效率指标。命令 observation 记录确定性 operation、cwd、exit、duration 和有界输出摘要及 digest，不要求 Agent 搜索日志猜测失败步骤。

## Decision Points

preflight 聚合发现候选尚未完成、OpenSpec 语义冲突、开发验证欠缺或 freeze/正式验证失败时，终止并返回研发流程。只有 target lease、远端竞态、网络、retained convergence/install 或 task-owned cleanup 等不改变候选语义的暂态失败可以 blocked 并由产品生成恢复令牌。

## Allowed Variations

Project 可以声明 `affected` 或 `candidate` assurance，也可以提供与 frozen identity 精确匹配的已有验证摘要。provider 可以扩充只读 preflight 检查与确定性 domain service，但不能增加 Agent completion、同 run repair/re-verification 或 caller-authored recovery 协议。
