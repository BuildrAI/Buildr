# 任务收尾

## Purpose

通过持久化、可恢复的 finish run 安全编排完整收尾，不接管 provider 专属的验证、Git 或 worktree 策略。

## Consumer Obligations

consumer 必须明确 task/change、请求的收尾范围、验证证据、目标分支、远端，以及所有明确排除的动作。

## Minimum Guarantees

provider 必须建立独立 finish run，并为步骤持久化 `pending|running|passed|blocked|stale`、input fingerprint、effects、evidence、invalidation dependencies 和 retry policy。run 绑定 task/change 而不绑定单个 session；resume 只重跑 blocked/stale 及其下游。正式 assurance 位于 canonical、target 与 runtime convergence 后。多个 run 不使用 Workspace 全局锁，只为真实共享资源取得短 lease；远端 ref 使用乐观并发检查。默认 push 只覆盖已集成目标分支。

## Effects and Authorization

当前轮次的收尾授权覆盖已披露的常规归档、任务提交、集成、目标分支推送和安全本地清理。创建、推送或删除远端任务分支、强制推送、丢弃改动、改写共享历史和语义冲突决策仍明确排除。

## Result Evidence

返回 run/task/change identity、当前步骤、已完成 effects、有效 evidence、blocked/stale、next action、provider identities、正式验证、归档、提交/集成/push、目标 ref observations、runtime/doctor、清理和未触碰并发环境。多次验证必须保留 run chain、失效原因、替代关系与独立耗时。

## Decision Points

遇到 required capability 被阻断、范围或目标不明确、验证不可信、语义冲突、检查失败、远端写入被拒绝、同端口 Local App 交接失败或无法安全清理时，必须停止。

## Allowed Variations

provider 可以按 Project policy 扩充 action payload，但必须保持持久化状态语义，并把验证、Git 集成、worktree、current knowledge 与资产审查策略交给各自 selected provider。
