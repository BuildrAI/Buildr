# Git Operations

## Purpose

为 consumer 已选定的一次 Git Operation 提供安全默认值、硬边界、操作前后 identity 与最小结果；不选择动作、目标或顺序，也不扩展为交付编排。

## Consumer Obligations

consumer 必须明确 repository、operation、相关 local/remote refs、精确 owned content 或 commit scope，以及本次允许的 local history、working tree 与 remote effects。`commit+push` 必须作为依次执行的 commit 和 push 两次 operation 调用；Task Finish、产品入口或直接用户继续拥有意图、目标和顺序。

## Minimum Guarantees

provider 必须在写入前核验实际 repository、branch/HEAD、working tree、相关 refs 与授权；只精确 stage owned paths 或可可靠分离的 hunks，不得使用 `git add -A`，并保留全部无关 dirty 与 scope 外 staged 内容。无法在不改变这些 index facts 的前提下生成精确 commit 时必须停止。push 前必须核验实际 destination remote/ref 和将发布的完整 commit range，存在 scope 外 unpublished commit 时停止。已 push 或以其他方式共享的 commit 默认冻结，不得自动 amend、rebase 或改写。

provider 不得自动 stash、reset、rebase、merge、force push、改写共享历史、切换 ref/remote 或在失败后改变策略；冲突语义、授权扩大和重大风险决定必须交还 Agent/用户。

## Effects and Authorization

只读事实检查属于执行已选 operation 所需的隐含授权。staging、commit/amend、working tree/history 变化和 remote 写入必须分别落在 consumer 明确授权内；commit 不隐含 push，push 不隐含 commit。只有能够证明当前 scope commit 尚未共享时才可按默认“一次 push 之间一个可变 commit”安全 amend；共享后的新变化使用新 commit。

## Result Evidence

每次 operation 只返回适用的最小结果：`repository`、实际 `operation`、`succeeded | blocked` 与 reason、before/after branch 和 commit identity、适用的 remote/source/target ref 与完整 push range、`treeChanged`、`historyChanged`、`remoteChanged`，以及已经发生的 effects 和当前 repository facts。不适用字段不填充，也不创建 Receipt。

commit 与 push 的 Result 必须分开。失败或组合动作部分成功时，provider 必须报告已经发生和未发生的 effects；不得把 push rejection、target drift 或 local commit 已产生伪装为零变化。

## Decision Points

repository/operation/ref/scope/授权不明确、同文件 ownership 无法可靠分离、完整 push range 含 scope 外 commit、remote identity 漂移、push rejection、dirty/divergence/冲突需要策略或共享历史需要改写时，必须 fail closed。恢复或重试由 caller/Agent 在重新核验事实后决定。

## Allowed Variations

provider 可以在不扩大 operation 的前提下选择只读观察命令、精确 staging 方式和符合当前 repository 约定的 commit message；更具体的 Project/Service/repository 规则可以进一步收紧。任何 rebase、merge、revert 或其他未由 consumer 明确选择的 operation 都不属于本次调用的隐含变体。
