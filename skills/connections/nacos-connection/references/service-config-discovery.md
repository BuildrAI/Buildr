# 从代码定位服务配置

用于“查询某服务在某环境使用的 Nacos 配置”。目标是依据代码及已知启动条件找到准确配置，再通过现有连接读取；不另建服务绑定登记，不修改业务代码或连接目标。

## 从加载声明确认位置

先按工作空间（Workspace）的服务（Service）及代码库登记定位真实代码目录、模块、当前分支（Branch）和版本。有多个同名服务或不同代码分支时分别辨认，不把一个分支的配置套到另一个分支。

按实际框架及版本检查启动配置、导入、共享配置、扩展配置，以及相关启动参数、环境变量和构建资源过滤。常见线索包括 `application.*`、`bootstrap.*`、`spring.config.import`、`spring.cloud.nacos.config.*` 和启动脚本；不要为凑齐清单读取无关业务文件。

为每项配置记录：

| 定位内容 | 必要依据 |
| --- | --- |
| Nacos 目标 | 配置中心的地址、真实命名空间（Namespace）编号；不能拿服务发现配置代替配置中心配置 |
| 专业对象 | 分组（Group）、准确配置编号（dataId）、导入或共享关系 |
| 加载条件 | 来源文件及行号、配置档案（Profile）、变量取值、是否可选、框架或客户端版本相关条件 |

先使用明确导入的准确名称；只有项目采用且当前客户端支持约定加载时，才按其规则展开应用名、后缀、配置档案（Profile）等。QA 目标可能使用 `dev` 等配置档案（Profile）；文件名中的 `dev` 也不能单独证明目标环境。未解析的变量或外部启动覆盖保留为待确认，不能把表达式当作已存在的远端编号。

仓库同名配置文件只证明本地文件存在；不能据此声称 Nacos 内容相同、自动同步，或缺失远端配置时会自动回退该文件。必要时核对实际依赖及加载代码，不能凭文件名推断加载。

## 匹配现有连接并读取

通过当前通用入口读取连接目录，以代码启动配置所指向的真实配置中心地址匹配 `apiBaseUrl`，核对完整目标与绑定来源；`consoleUrl` 仅是可选人工网站，不能代替接口地址。不要由网站端口推导服务端口或补写根路径。显示名称、类别和环境标签仅用于发现，执行使用明确的实例 `id` 及新读取的观察版本（Observed Revision）。网页显示的命名空间（Namespace）名称不能替代真实编号；`public` 的接口表示由专业程序处理。地址别名、端口或代理入口是否为同一目标需要依据，不能仅凭主机名称相似合并。

有多个匹配实例时，结合用户明确选择及已知用途核对；仍有同等候选就列明最少差异请用户选择，不按列表顺序取第一个，不静默改用另一账号。代码缺少外部注入值但用户已明确指定连接时，可以在该范围只读核对候选，注明尚未证实服务启动目标；其他已明确配置的读取继续进行。

按所选实例返回的实际技能（Skill）入口及程序帮助，经通用启动入口运行专业 `get --data-id <准确编号> --group <准确分组> --result-file <明确的新本机结果文件>`，用受限新文件接收完整原文。原文位置从私有结果的 `outputFile` 读取，或显式指定 `--output-file`；普通输出仅作展示，不复制可能被秘密遮蔽改写的位置。`list` 只在需要核对存在性或发现范围时有界调用，不把相似名称当作匹配成功。每项读取分别报告成功、缺失、拒绝或未知；可选导入缺失不自动等于服务启动失败，也不能把读取拒绝当作不存在。

只追踪与当前目标有关、当前加载机制支持的后续导入或共享项；保留已访问目标，避免循环或无界展开。敏感值、连接认证和完整业务配置不展开到普通输出或公共资产。原文用于本机核对，按本次目标决定保留或清理，不把脱敏文本当作原文。

## 核验与交付

报告准确代码版本、启动条件及待定覆盖项，列出每个 Nacos 位置、代码依据和实际读取结果；适用时核对原文大小与完整摘要。公共技能（Skill）只保存通用方法，公司地址、账号及业务内容不写进公共源、模板或发布物。

分别表达三个事实：代码声明了什么、Nacos 当前返回什么、运行服务（Service）实际加载了什么。读取成功只证明该账号在该目标可读；没有进程或加载证据时，不宣称运行服务（Service）已经采用这些值。只读授权下不发布、不改配置、不重启，也不为验证触发构建或部署。
