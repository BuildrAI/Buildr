# 变更协作与结果

## 操作

| 操作 | 输入与实际工作 |
|---|---|
| `assess` | 根据变更目标、提案、设计和相关规范识别事实影响，核对已有成果，维护已授权的 `brief.md`，把真实维护工作纳入执行清单 |
| `reconcile` | 根据最终实现、规范意图、配置与已确认决定，完成或确认本次受影响且已授权的成果 |
| `inspect` | 检查明确范围内成果与当前事实的一致性，按影响逐项返回；检查本身不冒充测试执行 |
| `maintain` | 独立建设或维护明确授权范围内的三类成果；不要求变更、变更说明或附加记录 |

调用方提供项目（Project）、实际工作根、目标或检查范围、已知来源与授权；具体文件可由提供者（Provider）在该范围内定位，不强迫用户预先枚举所有路径。前三项有实际变更时另外提供其身份和材料位置；只处理已有材料，不凭推测补造历史。

## 提醒与授权判断

| 当前事实与授权 | 智能体（Agent）的动作 |
|---|---|
| 新增、修改或删除事实，相关解释已受影响；未授权知识维护 | 主动给出具体成果、失准之处和建议校准范围，等待这一组授权；保留现有成果及真实维护依据 |
| 同一范围已有建设或维护授权且仍有效 | 告知实际影响，连续维护文章及必要图、地图、术语与关联；不逐文件重复确认 |
| 用户主动要求创建或维护某个架构主题 | 以阅读目标确定整组交付，调查事实并组合专业方法，直到真实成果可阅读、可追溯且必要验证完成 |
| 文件变化但含义与引用仍成立 | 核对后保留表达，说明无需改写的依据，不制造一次无意义的授权请求 |

提醒应能让用户作出决定，例如：“知识接口增加了来源摘要，现有文章和地图仍只解释路径。建议补充摘要的用途、职责文件与阅读示例；职责关系图无需重画。”不要只提醒运行某个技能（Skill）。

这套主动判断由遵循工作方法的智能体（Agent）在开发和复核中执行。Buildr Web 在打开或刷新时读取当前文件，只提示实际读取限制；它不负责版本追溯或自动唤醒智能体。未获得维护授权的项在本次工作结果中保留具体待办建议，不伪报同步完成。

## 变更说明与辅助记录

`brief.md` 作为任务需求或说明，按需要记录背景问题、目标、范围、约束及验收要点；可引用现有技术材料，没有补充内容时可以为空，不要求填写固定章节。新增产品行为先进入提案、设计或规范，不能只写解释。

`.buildr/knowledge-impact.yml` 是可选的变更内工作记录，已有且适用时更新目标、理由、状态与来源。执行清单或真实文件足以表达影响时不再复制一份清单。记录缺失或陈旧先直接核对相关事实，不停止无关验证、同步或收尾。独立 `maintain` 不创建此记录。

归档只处理对应变更，不附带当前知识写入。归档后的新维护仍可在明确授权内按当前事实执行，历史变更保持不变。

## 结果字段

跨技能（Skill）交接使用 `buildr.current-knowledge-maintenance/v3`：

```text
operation: assess | reconcile | inspect | maintain
project: <实际项目>
change: <实际标识或 none>
scope: <本次覆盖范围>
sourceIdentities: <实际核对的来源路径、必要符号和版本或内容观察>
impacts: <逐项的类型、目标、理由、状态、来源和受影响动作>
changedAssets: <实际改变的文件，或空>
proposals: <尚未授权但有价值的建设范围、目标、视角、来源、用途，或空>
validation: <实际检查、结果、仍适用的既有检查和未覆盖项>
```

每项状态为 `aligned|updated|not-applicable|attention|blocked|change-required`。`updated` 仅说明发生修改，是否通过检查由 `validation` 说明；不把全部项目合并成一个全局许可。多项目只报告实际检查过的项目，不补做全项目审计。

来源与写入文件在动作前重新核对；内容并发变化时重新判断并合并已理解的修改，不能静默覆盖。版本不一致本身触发重新观察，不自动使此前所有测试失效。只有实际变化影响的审查、验证或交付依据需要更新；绑定旧文档内容的依据不能声称覆盖新文档。

## 状态与局部停止

- `aligned`：已核对且无需修改。
- `updated`：授权内容已更新，报告实际检查结果。
- `not-applicable`：本次范围没有相关影响或不需要建设。
- `attention`：非关键漂移、辅助记录问题或尚未授权的有价值缺口，报告建议并继续无关工作。
- `blocked`：特定冲突、授权或并发问题会使相关动作产生错误结论或副作用，明确停止哪个动作，保留其他成果。
- `change-required`：候选内容需要改变现有产品承诺或业务语义，交回相应变更处理，不把新行为写成当前事实。

调用方据自己的目标验收，不把这些状态升级为验证、归档、交付或任务完成的唯一权威。
