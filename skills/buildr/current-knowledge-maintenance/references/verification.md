# 成果验证与代表场景

按本次成果类型和真实影响选择检查，先复用已有适用检查。检查失败后只修复并复查相关内容，不因流程阶段转换重复全量测试。

## 分类型检查

| 成果 | 必须核对的事实 | 不能冒充完成的情况 |
|---|---|---|
| 代码地图（Code Map） | 引用路径与符号存在，入口、职责、调用方向、数据归属和副作用与当前实现相符 | 只检查字符串存在，没有读调用和写入路径 |
| 技术图（Technical Diagram） | 节点与关系有来源，展示由当前图源生成，必要交互可用且实际视觉没有遮挡或溢出 | 只说渲染成功，未看实际结果；修改图源后仍交付旧展示 |
| 解释文档（Explanatory Documentation） | 关键陈述有依据，链接可用，当前事实、理由与未来方向区分清楚 | 将规划当成已实现，或仅检查文件存在 |
| 目录迁移 | 旧内容有明确去向，入口、链接、图源与实际消费者更新，历史原文保留 | 只移动文件；用历史路径更新为由改写历史正文 |
| 协作资产 | 已选提供者（Provider）、版本、调用方、结果字段与局部停止条件一致，资源可安装和投射 | 清单解析通过就宣称智能体行为已验证 |

符号存在检查可程序化，职责与关系仍需读对应实现。固定图源的生成、相对链接和资源投射可用已有工具检查；避免为一次维护增加常驻机制。

## 代表场景

| 现场 | 应执行和交付的结果 |
|---|---|
| 用户只追问当前项目或成果 | 在相关范围核实最新事实，交付解释、依据与未知；不新增文章或改索引 |
| 建设用于工程理解的结构化知识 | 检查目标、职责、关键行为和判断边界是否清楚，关系有依据且能继续探索；不以篇幅或图数代替理解效果 |
| 事实变化、已有映射受影响且维护已授权 | 说明影响，更新受影响节点、关系或陈述，核对来源及关联引用 |
| 事实变化、尚无知识维护授权 | 主动提出具体校准范围并等待授权，保留知识文件与旧观察，继续无关开发；授权后完成整组维护 |
| 有价值映射缺失、尚无建设授权 | 给出具体范围、文件、视角、来源与用途，返回 `attention`；等待相关授权时继续无关工作 |
| 一组建设成果已授权 | 自行确定文件，连续建设与验证，交付可打开成果，不逐文件询问 |
| 来源版本变化、表达仍适用 | 核对相关语义并返回 `aligned`，保留成果，不重建或重跑无关检查 |
| 规范与实现冲突 | 列出双方证据，局部 `blocked`，停止依赖确定结论的写入；不通过改图掩盖冲突 |
| 只改解释文档 | 检查该文档与引用，复用仍适用于当前代码与运行条件的测试，不宣称旧文档检查覆盖新内容 |
| 一项成果未完成 | 如实列出该项与相关影响，保留其他已完成成果和无关工作，不声称整组完成 |

验证技能（Skill）修改时说明这些场景是静态走查、实际任务执行还是隔离行为实验。静态文本和清单测试不能证明模型必然遵循流程；不要虚构运行日志或通过次数。

## 交付说明

给出成果入口、实际变化与关键来源、覆盖与未覆盖范围、执行的检查及结果、仍需决定的具体事项。可选记录只帮助接续，不替代成果。尚未通过的必要检查保持明确限制，不把内部登记、生成成功或版本相同当作验收。
