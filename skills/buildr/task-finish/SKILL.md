# 收尾与交付

日常表达中的“收尾”和“交付”都可以表示本轮工作完成后的结束动作；用户明确要求时即触发本技能（Skill）。该指令本身是当前任务范围内常规 Git 提交、集成和普通推送的明确授权，不要求用户再逐项重复。智能体（Agent）依据目标与现场持续推进，直到成果到达约定位置、已有任务结果登记、可安全处理的资源已处理，并交代遗留事项。部署或发布只有明确属于目标且已获授权时才执行。

## 按实际对象组合

| 现场 | 应完成的工作 |
|---|---|
| 有 Buildr 任务，无 Git | 使用实际业务工具交付成果，登记已有任务结果，处理相关资源 |
| 无 Buildr 任务，有 Git | 按约定提交、集成、普通推送并回读，不补建任务 |
| 两者都有 | 完成 Git 交付、已有任务登记和相关资源善后 |
| 两者都没有 | 完成成果本身需要的交付，不制造记录或提交 |

承接当前对话中已确认的目标、成果、执行位置、验证及授权，复用仍适用的技能（Skill）和能力提供者（Provider）。缺少上下文或发现变化时，只补读相关部分。有匹配任务时取得当前记录与 `recordDigest`，完成后用 `task complete --expected-record <recordDigest>` 保存实际结果；可以使用刚读取或前一步成功写入返回的版本，冲突后重读。没有匹配任务就交付实际成果，不补建记录。

将当前任务的常规 Git 授权连同已核验的 operation、对象、目标、范围和效果交给所选 `git-operations` 提供者（Provider），不让提供者重新索取同一授权。每次 Git 写入前核对真实仓库、分支、远端、暂存及未跟踪内容和完整推送范围，只纳入本轮成果；在目标和安全集成方式明确时按约定提交、集成与普通推送，回读实际目标。无法唯一确定对象、目标或完整范围时停止受影响的写入，不以“收尾”猜测。非 Git 成果检查实际业务结果，不能只看请求成功。复用已经成立的交付事实，多仓分别保留结果。

有明确正式任务（Task）且需要创建提交时，同时把已核验的任务编码交给 `git-operations`，由其按提交说明（Commit Message）约定写入唯一 `Buildr-Task` 尾注（Trailer），回读真实提交并通过 `task commits` 确认任务侧关联；复用它返回的实际代码库（Repository）、完整哈希值（Hash）、说明和读取诊断，不重复执行提交。没有任务时省略关联，不补建任务。提交成功但关联查询失败或未覆盖时，分别说明交付事实与尚未确认的关联，不因此改写历史、撤销任务结果或阻断其他安全收尾；关联存在也不能替代成果验收与交付核验。

## 常规收尾

成果已完成、验证仍适用、交付目标明确且没有待解决冲突时，直接组合下列动作。按实际对象省略不适用项，依赖前一步结果的动作顺序执行。

| 动作 | 完成依据 |
|---|---|
| 集中核对 | 当前任务版本、改动归属、仓库与目标、已有验证和待处理资源已明确；本次实际执行过但尚未登记的审查或验证，必须在 `task complete` 之前于任务仍为 `active` 时补登（`completed` 后验证报告槽位锁死不可补写），成果确需人验收确认时先登记 acceptance 待办事项，不补造未发生的检查 |
| 交付成果 | 适用的规范归档与业务交付完成，实际目标已回读；Git 推送前另核对远端现状及完整新增范围 |
| 采用更新 | 目标确实包含安装、部署或自举且已授权时，由原能力完成并返回结果 |
| 登记与善后 | 保存已有任务的实际完成摘要，核验归属及内容保全后清理资源，或说明保留原因 |

已确定的动作可在一次工具调用中编排：独立只读检查合并或并行，写入逐步核对返回值后继续，失败只停止依赖它的后续动作。每项结果与副作用分别保留，不把工具调用次数当作职责边界。已知命令使用已核对的入口与工作目录；未知用法才查相关帮助。

正常结果只提取状态、版本、关键结果和诊断；完整输出留在执行现场，必要时再展开。解析完整响应后再提取字段，不解析截断文本，也不为显示输出重复执行写入。任务完成摘要集中登记一次；工作摘要（Work Context）只在有新进展、答复或遗留需要接续，或旧摘要会误导时更新，不把中间动作逐条转存。

## 变化与清理

- **验证适用性：** 内容及相关运行条件未变就复用检查，不因收尾、归档材料移动或提交编号变化重跑测试、重建报告或完整审查。归档确实改变被验证内容时仍需重新判断。冲突处理、集成修改或已知问题影响行为时，只补最小充分检查，并在推进目标分支前通过；保留原执行事实，未验证范围如实说明。
- **工作树归属：** 清理前核对 `buildr.git-worktree-provider/v1` 契约（Contract）、当前有效能力绑定（Capability Binding）、创建归属与既有证据，由已选提供者（Provider）承接。接手智能体（Agent）负责继续核验并清理；绑定变化不自动转移历史资源归属，缺少历史登记时使用 `--observed-checkouts` 提供明确当前对象重新检查，不补造创建历史。身份冲突或安全仍无法证明时保留目录并报告具体差异，不混用不兼容入口，不撤销已成立的交付事实。目录名、分支名、相同提交或 OpenSpec 归档都不能替代该核验。
- **安全删除：** 预览（Preview）、容器等由创建者处理。完整核验 Git 交付后，向 `worktree cleanup` 成对传递逐仓 `--expected-source <selector>=<完整源提交>` 与 `--delivered-ref <selector>=<完整交付提交>`。提供者（Provider）复核归属、源版本、未保存内容和保留引用后清理；任务完成或提交存在不能替代交付核验，拒绝时只处理具体差异。

### 远端任务引用（Branch）

任务分支等任务级引用只在明确授权下进入远端：用户指令、任务声明的交付方式或适用于该仓库的持续授权；普通“收尾”指令本身不授权远端任务引用的创建或删除，也不扩大本地工作树（Worktree）清理能力的远端权限。授权推送任务引用时同时确定其生命周期处置——默认随用途结束删除，明示长期保留除外。

交付后核对本任务的远端残留，不依赖当次会话记忆：对任务范围每个仓库（Repository）以任务分支名查询实际远端（如 `git ls-remote <remote> <branch>`），分支名优先取自工作树证据或任务记录的 `branch`；仓库声明的常驻引用保留。只有已证明任务归属、成果交付及内容由保留引用保全的临时引用才进入删除；直接交付到开发主线而没有合并请求（Pull Request）的情况同样处理。单凭名称、任务完成或文件树相同不能证明可删除。

1. 删除前重新读取实际远端提交，完整查询开放合并请求（Pull Request）的源与目标引用以及未结束运行；使用分页结果时必须读完。存在活动用途、未交付内容、漂移、未知归属或查询失败时保留对应对象，继续处理其他已证明安全的对象。
2. 将删除授权连同精确仓库、引用、观察提交及允许效果交给所选 Git 操作提供者（Provider）的 `delete-remote-ref`，依据已观察的精确提交条件删除并回读远端。提交已变化时停止该引用的删除，不能改用无条件删除；返回错误或响应丢失时先核对实际效果。平台已自动删除时，核对实际合并、交付保全和远端不存在后复用事实，不重建或重复删除。
3. 分别报告已删除、已不存在、仍保留与查询未知的引用及原因。删除授权未覆盖时提出最小授权问题或如实说明未决残留，不静默保留；仓库开启自动删除设置不等于本次已经清理；一个 `cleaned` 状态不能代替逐项回读。发布引用由发布能力按绑定政策处理，不混入普通开发引用清理。

内容变化、冲突、失败或授权变化才展开对应调查，其余安全工作继续。不新增收尾状态库、统一验证记录或证明文件。常规收尾以少量主要工具往返完成；观察效率时区分工具执行、外部等待和智能体（Agent）处理时间，不为缩短时间省略必要核验。

## 失败与完成

已知、必要、已获授权且安全的后续动作继续完成，不把可执行工作留作建议。必要成果未交付不能标记整个目标完成；清理或可选激活失败不撤销已交付成果。登记失败只修复或重试登记，不重推业务内容。

遇到明确的权限、功能或访问限制，记录具体原因并处理其他安全工作；输入、环境或方法没有变化时，不原样重试。短暂故障按原能力允许的方式有界恢复；结果不明确时先核对实际状态，避免重复副作用。改变方法仍须遵守原有授权与安全边界。

保留未知归属、未交付内容、共享缓存、凭证和业务数据。普通收尾不授权强推、merge commit、丢弃内容、覆盖他人工作、改写共享历史、创建或删除远端任务引用或替用户选择语义冲突。只有需要扩大授权或业务取舍时提出最小问题。

成果已到达约定位置、已有任务结果已登记，且相关资源已安全处理或有明确保留原因时，结束收尾并简述这些结果。非关键遗留如实说明，不据此扩展检查；仍能安全完成的必要动作继续执行。适用的部署、发布、自举由原专业能力独立承担并分别报告结果；普通工作空间不触发 Buildr 自举。

父任务完成遵守 `task-manager` 的明确授权与总体验收边界。子任务收尾不授权完成父任务；整体目标已核对但尚无明确授权时，报告验收结果并保持父任务状态，不补造授权。
