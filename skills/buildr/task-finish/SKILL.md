# 收尾与交付

智能体（Agent）负责把本轮目标办完；本技能（Skill）提供方法和边界。收尾从确认本轮成果与交付目标开始，到成果已妥善交付、已有任务结果已登记、可安全处理的临时资源已处理，并说明剩余事项结束。

不要求所有场景走同一流程；不为收尾创建任务、候选、交接、收尾运行或新的证明文件。默认不调用 `task next`、`task finish run` 或 `task finish reconcile`。

## 按现场推进

1. **核对对象。** 确认用户目标、实际仓库集合、成果和归属、交付位置及当前授权。已有任务时确认唯一匹配的任务记录；无任务继续工作。只在答案影响对象或风险时询问，不把内部缺口转交用户。
2. **交付成果。** 按实际仓库边界使用 Git 或其他适用工具。Git 操作前核对分支、提交、暂存及未跟踪内容、远端和完整推送范围；只暂存本轮内容。按仓库约定提交、集成和普通推送，并回读实际目标。已包含的内容不重复提交或推送；多仓库逐项保留结果。已选择的能力提供者仍须遵守；技能不替用户改协作策略。
3. **补足必要验证。** 复用与当前内容相符的结果。只有实际变化、已知失败、风险或项目约束要求时，补做相关检查；不因一句收尾重跑全量测试、审查或诊断。未知不能报告为通过，失败不能报告为完成。
4. **登记已有任务。** 目标实际完成后，通过既有 `task inspect` / `task complete` 保存真实摘要与 `noChange`，说明交付位置、验证及遗留事项；沿用已观察版本，冲突时重读处理。完成记录不等于程序验证了远端。没有任务不建任务；尚未交付的必要成果不能标完成。仅资源清理或可选激活遗留不否定已成立的任务成果。
5. **安全善后。** 只处理本轮拥有且可证明安全的工作树、任务分支、临时文件和进程。受管资源交给已有所有者；有受管环境时调用 `task environment cleanup`，不要求重新准备完整环境。保留未交付内容、未知资源、共享缓存、凭证和业务数据。若工具无法证明删除安全，保留并说明，不制造成功记录。
6. **按需专项动作。** 部署、发布、环境激活只在属于目标且已有授权时执行，由对应技能或工具承担。Buildr 自举工作空间仍由其唯一自举技能执行；普通工作不触发自举。发布及其他不可逆外部动作不能由收尾一词自动授权。

以上是判断方法，不是固定串行门禁；例如验证应在影响其结论的最后一次内容修改之后、相关交付之前完成。局部失败只停止相关动作，继续其余安全工作。

## 安全边界与报告

普通收尾授权范围明确的提交、常规集成、普通推送和安全清理；不授权强推、丢弃内容、覆盖他人工作、改写共享历史、删除远端分支或代替用户选择语义冲突结果。

最后简要说明：交付了什么、在哪里；做过哪些相关验证及限制；任务记录是否更新；哪些资源已处理或保留；仍需哪项决定。不同仓库和动作的成功分别成立，不把组合动作描述为原子事务。

遇到新场景，重新观察事实并调整工具组合；只记录真实特殊情况，不为未知场景预建状态或把所有异常升级为全局阻塞。
