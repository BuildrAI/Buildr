# 已安装桌面验收

使用兼容 DSH Desktop、该检出的预编译插件和含生产 Web 的独立 Harness 安装包，记录真实宿主版本，不把它用作安装锁。在独立 DSH 配置和 Harness 数据域内执行，不使用日常账号或付费模型。

1. 用厂商命令安装开发包，核对启用状态。在没有匹配会话时进入 Harness：页面完成票据认证，最终地址没有票据；仍能使用自有工作区，不出现其他目录的原生工具。不带授权访问宿主启动端点必须被拒绝。
2. 准备两个有不同标记文件的本机目录：一处先有唯一同目录会话，核对自动连接、增加另一会话后不重新选择；另一处同时有两条同目录会话，核对自动优先当前已打开的同目录会话，否则选同目录最近活动的会话。不出现绑定步骤。在原生右栏开始页核对两个 Buildr 入口和原生卡片样式一致，分别显示文件夹和分支图标。打开工具核对文件来源，从 Git 差异按真实检出跳转到文件。重复打开和分栏/浮窗聚焦不保留重复模块标签。
3. 同空间切换对话不重置右栏；切到另一个工作空间，核对其文件、Git 与终端的新建目录及旧终端不被转移。返回原工作空间后查看原标签；返回 DSH 再进入 Harness 时原网页视图、对话与后台应保留。
4. 选择「应用内侧边栏」，从 Harness 点击普通 HTTPS 链接（账单入口不要求登录），核对原生浏览器标签；切换「默认浏览器」以后点击另一个 HTTPS 链接，核对宿主外部打开路径。无可用侧栏时核对明确降级。可以在宿主到操作系统的边界截获外部打开以免操作日常浏览器，报告需注明这一边界。
5. 结束本次准确绑定的隔离实例和测试后台，核对退出。安装包或启动成功不等于后续场景通过，未覆盖项按实际范围报告。

6. 展开和收起 DSH 原生左栏、从对话标题开合右栏；在窄窗口的单列表视图也应能收起右栏。核对 macOS 仅保留 48px 轻量工作台顶栏（左侧展示 Buildr Harness 图标、名称、开发标识与当前工作空间名称），左栏收起时内容自动右移避让红绿灯与左栏按钮；没有同目录会话时仍能使用自有工作区、且不弹绑定提示。打开原生会话或从更多菜单返回，再进入 Harness 核对网页视图和草稿保留。

7. 进入已匹配的 Buildr Harness 后，核对「开始」、「更多工具」和右栏顶部标签（含重启后恢复的已打开标签）均显示「资源管理器」和「源代码管理」，没有 Buildr 前缀；「开始」卡片分别显示橙色文件夹和紫色分支图标，顶部标签分别显示随标签文字颜色变化的单色文件夹和分支。在「资源管理器」或「源代码管理」标签聚焦时按 `Cmd + R` 刷新该标签；回到原生 DSH，由「开始」和「更多工具」确认不再提供这两个入口，原生入口照常可用。再进 Harness，已开的文件工具保持原页面。

8. 正式候选先装插件，确认缺包提示；在同一隔离环境安装正式 Harness 并登记默认启动器，点「重新检查」，不重装插件就打开认证网页。记录两包摘要。先用隔离 npm 源和 HTTP `.tgz` 直链预演两个入口，获准公开后再验实际官方地址与字节。

9. 开发候选保持插件和 DSH 进程不变，激活第二份兼容 Harness 负载，核对新版 Web。确认未交互页面静默更新；已交互页面不显示底部刷新提示条，不在对话菜单增加刷新项，且焦点在中栏 Harness 时按 `Cmd + R` 可随时刷新当前页面（保留未保存编辑保护）、焦点在右栏原生浏览器时按 `Cmd + R` 仍刷新原生浏览器；退出时记录准确实例和清理结果。

10. 核对 DSH 左侧 Buildr Harness / Dev 入口显示无白底方框的官方彩色 H 图标；在 macOS 中栏顶栏空白处按下拖动可移动 DSH 窗口、双击空白处可放大/缩小 DSH，且切换 Harness 工作空间时顶栏工作空间名称随之更新且不引起右栏闪烁。
