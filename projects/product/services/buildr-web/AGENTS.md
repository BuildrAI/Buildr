# Buildr Web 前端规则

本服务（Service）维护 Buildr Web 的 React/Vite 权威源码与正式构建。产品治理和 OpenSpec 归父级 `projects/product/`；本目录不维护第二个规范根。

## 构建与验收边界

- 本服务（Service）拥有 `package.json`、Vite/TypeScript 配置、`src/` 和依赖锁定。本地构建输出到相邻 `buildr` 服务（Service）的受忽略目录 `../buildr/web-dist/`；浏览器验收和候选（Candidate）构建使用调用方指定的隔离目录。
- 同源本机托管、会话（Session）注入和三种入口的打包由 `buildr` 服务（Service）负责。安装后或仅有构建产物的环境不能依赖前端源码树或 Vite 开发服务器。
- 界面使用 Ant Design 5 及必要图标，保持柔和的产品视觉。依赖、字体和资源由 Vite 打入 `web-dist`，禁止 CDN、远程字体、远程样式及远程脚本，保留内容安全策略（CSP）与离线托管能力。
- 正式浏览器验收针对生产托管的 `web-dist`。稳定 DOM `id` / `data-*` 是验收契约；改名或删除前核对现有浏览器检查仍可使用。

## 模块归属

| 位置 | 职责 |
|---|---|
| `src/app/` | 应用壳、布局、共享上下文（Context）与跨页壳层交互 |
| `src/features/<feature>/` | 对应功能的页面、局部组件、钩子（Hook）、客户端（Client）、纯逻辑与生成数据传输对象（DTO） |
| `src/components/` | 跨页复用、无单一路由绑定的公共组件 |
| `src/api/` | 通用请求、会话（Session）、工作空间（Workspace）传输，以及尚未迁移的客户端（Client） |
| `src/lib/` | 共享纯函数、格式化、标签映射与弱界面耦合工具 |
| `src/theme.ts` / `src/styles.css` | Ant Design 主题变量与全局、壳层补充样式 |
| `src/App.tsx` / `src/main.tsx` | 路由装配与启动，保持简洁 |

- 已迁移功能在同一 `features/` 内扩展。仍存在的旧 `pages/` 按原边界维护，迁移后移除对应旧入口，避免并存同一页面或复制客户端（Client）。
- 页面局部组件放在所属功能目录；只有真实跨页复用或明确通用界面语义时，才提升到 `components/`。公共组件和应用壳不得依赖具体页面，页面也不得直接引用其他页面的局部组件。
- `api/` 不包含 React 组件、钩子（Hook）或业务状态，也不得反向依赖 `features/`。网络访问使用已有客户端（Client）与会话（Session）适配，页面不直接绕过它们调用 `fetch`。

## 组件与样式

- 页面负责编排，子组件负责完整的局部展示与交互；默认每个文件导出一个主要组件，文件名与组件名一致。参数类型（Props）显式声明，保持 TypeScript 严格检查，避免万能参数包与循环依赖。
- 按职责组织界面结构（JSX）、业务计算和样式；复杂计算放在纯函数、钩子（Hook）或邻近模块，副作用集中在依赖与清理明确的 `useEffect` 或事件处理中。文件混合请求、表格、表单、弹层、样式且已妨碍独立理解时，先拆分受影响职责再扩展。
- 局部类型、常量、纯函数和组件先留在所属功能；共享内容再提取。公共组件不硬编码某一页面的数据形状或业务文案。
- 优先使用现有 Ant Design 能力；主题色、圆角和字体以 `theme.ts` 与 CSS 变量为准。组件私有样式使用带明确前缀的类名或同目录样式模块，避免污染全局选择器。
- 可复用样式不写成大段内联对象，少量动态布局样式可以内联。默认通过主题变量定制 Ant Design；确需覆盖内部结构时缩小作用范围并说明原因。新增依赖须服务明确前端职责并保持同源打包。

## 状态与数据

- 默认使用组件局部 `useState` / `useReducer` 与功能内钩子（Hook）；跨页壳层状态放在 `src/app/` 的 React 上下文（Context）。派生数据使用纯函数计算。
- `src/api/` 模块变量只保存请求装配所需的最小事实，例如 `workspaceState.ts` 的 `workspaceId`，不作为业务状态仓库（Store）。
- 引入 Redux、Zustand 等正式全局状态仓库（Store）前，须证明多个无关页面稳定共享可变业务状态，且现有方式造成明显重复渲染、难以维护的层层传参或独立测试困难；说明共享范围、现有方式不足及边界，并取得用户授权。
- 已获准的状态仓库（Store）集中到 `src/store/` 或等价单一目录，按领域组织，页面经钩子（Hook）或选择器消费。不要把服务端列表缓存、表单草稿全部集中，也不并行引入另一套全局状态方案。
