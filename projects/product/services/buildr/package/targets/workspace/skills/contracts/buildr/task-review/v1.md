# 任务审查

## Purpose

对正式 Task 的实际 planning target 或 completion Candidate 完成语义审查，并用同一个最小数据模型维护两份互不覆盖的 current Review Result。

## Consumer Obligations

consumer 必须提供正式 Task ID、`planning|completion` 类型、该类型当前目标的明确稳定 identity，并让 provider 读取 Task Intent 和真实目标后动态选择审查范围。Completion 只有在上游已形成明确 current Candidate identity 时才能执行；不得用 Git HEAD、dirty tree、Environment identity、时间或临时摘要伪造 Candidate。consumer 必须如实区分 self、independent-agent 与 human，不得把同一 Agent 的再次阅读描述为独立审查。

## Minimum Guarantees

provider 必须以一个参数化 Task Review 能力完成两类审查；必须动态记录至少一个实际 reviewed 对象、相关但未覆盖的对象与原因、findings 和 `ready|changes-required` 结论。完整结论形成后，provider 只能通过 Task Review Application `record` 写入 Workspace SQLite 中独立的 `planning|completion` current slot；Application 独占 closed schema、系统时间、serialization、digest、slot和事务替换。审查中断、目标不明或结论不完整时不得调用 writer，已有 current Result 即使 stale 也必须保留。

两个Result是Workspace本地事实，不发布到Git或跨机器同步；consumer不得直接打开SQLite或从旧`reviews/*.yml`恢复。

## Effects and Authorization

`inspect` 零写入；`record` 只事务替换同一 Task、同一 reviewType 的一份 current Result，不得读取后改写另一类型、Task Record、Environment Receipt 或其他 sibling。provider 不创建 Task、Environment、Development 或 Candidate，不执行 Verification/Finish/Git，不设置 lifecycle gate，也不直接编辑、删除或维护 Result history。语义审查本身只读取用户已授权的 Task 目标；任何外部写入或人类审批仍需对应独立授权。

## Result Evidence

provider 必须返回实际类型、target identity、method、reviewed、uncovered、findings、conclusion 和 Application operation result。Application read model 必须为两个可选槽位分别返回 present、Result、response-only `resultDigest` 与由调用方目标 identity 派生的 `current|stale|unknown|null` applicability。Result 不保存 revision、applicability、reviewer、session、policy、运行日志或 lifecycle receipt；两种 Result 同时存在时分别作为 planning 与 completion evidence，不合并为第三份 receipt。

## Decision Points

Task 不存在、canonical target 不明、SQLite current value损坏、reviewType/target identity 缺失、Completion 缺少 Candidate identity、审查未完成、terminal Task record、同类型current slot无法安全替换或 Application 返回 blocked 时必须停止写入并报告唯一 next action。`stale` 与 `unknown` 都不得描述为满足 Development Review gate；Task Review 本身不创建 gate，Task Development 只消费 Application read model 中 current Result 的最小引用。

## Allowed Variations

provider 可以按 Task 风险和目标形态选择审阅对象、阅读顺序、工具与表述，也可以由 self、独立 Agent 或 human 执行；不得拆成类型专属 capability/schema/provider，不得强制所有 Task 都审阅 OpenSpec、固定代码目录或固定测试清单，也不得扩展为通用 Review 状态机、finding lifecycle 或历史库。
