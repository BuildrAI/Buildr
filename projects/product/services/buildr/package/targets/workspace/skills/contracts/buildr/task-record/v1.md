# 任务记录

## Purpose

通过产品化动作创建、查看、明确更新、完成或放弃 canonical Workspace 中的正式 Task Record，使人和 Agent 共享同一份最小顶层任务事实。

## Consumer Obligations

consumer 必须先判断工作已经进入正式持久交付，而不是普通对话、只读探索、临时操作或只维护既有生命周期 metadata；必须提供稳定 Task ID、canonical Workspace target，以及动作要求的 title、intent、scope、Change 引用或终态摘要。当前位于 task environment 时，consumer 必须使用上游已经确认的 canonical Workspace target，不得要求 provider 从环境目录或 receipt 推断 retained root。按 Task ID 继续或 Local App 已创建记录时必须先 inspect，不得重复创建或要求用户重输顶层事实。

## Minimum Guarantees

provider 必须只通过 Task Record Application 的 `create`、`inspect`、`update`、`complete`、`abandon` 五个动作管理 canonical Workspace 本地SQLite中的规范化Task数据；必须校验 closed `buildr.task-record/v1` schema、Project/Service/Change identity、当前记录内去重、active 到 terminal 的单向转换、系统时间和响应级 `recordDigest`。provider 不得要求 Agent 手写SQL/YAML、提交完整 next-state 文档或自行生成系统字段。Local App 是同一 Application 的独立人类客户端，不通过 Skill routing 写记录。

Task Record是local-only数据，不声明portable exact path，也不进入Task Metadata Publication、Git或同步范围。旧 `.buildr/tasks/<task-id>/task.yml` 不读取、不迁移、不删除、不双写；同目录的Development、Review、Verification等专业记录保持各自authority。reference 已归档、退役或当前不可用时，read model 必须保留有效record并返回availability diagnostic；不得为publication改写历史引用。

## Effects and Authorization

create 只能在一个数据库事务中插入一条Task及其规范化关系；update、complete、abandon只能在同一事务中修改该Task；inspect在数据库未初始化时必须零写入。provider 不创建、定位、记录或清理 Task Environment，不执行 Development、Review、Verification、Git、Finish、Board、Retrospective、publication 或其他专业动作，也不复制这些模块的 path、revision、result 或运行状态。

## Result Evidence

provider 必须返回实际 operation、`created|inspected|updated|completed|abandoned|blocked` status、Task ID、当前record、响应级 `recordDigest`、精确effects、diagnostic和nextActions；不得暴露本地数据库路径。`recordDigest`只用于证明当前read model；不得写入数据库或解释为持久revision。失败时effects必须为空，且不得把候选生成、数据库文件存在或专业模块结果冒充Task Record成功。

## Decision Points

目标不是已初始化canonical Workspace、指向task worktree、Task ID冲突、数据库schema/checksum/integrity异常、记录损坏、引用无法解析、mutation不明确、终态改写或SQLite事务失败时必须返回blocked并保留原状态。Local App update、complete、abandon 的 `expectedRecordDigest` 陈旧时必须在同一写事务内返回 `task_record_conflict`，要求刷新，不自动合并。selected provider 在正式持久交付分支不 ready 时 consumer 必须停止首次交付写入；纯讨论、只读探索和其他非正式分支保持不依赖。

## Allowed Variations

provider 可以调整CLI文案、内部SQL查询、列表展示和Local App布局；必须保持Task Record v1 closed schema、local-only存储、五个动作、共享Application、响应级digest、终态单向性和专业authority边界。
