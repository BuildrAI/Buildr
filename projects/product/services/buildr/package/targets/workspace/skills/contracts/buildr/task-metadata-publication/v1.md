# Task Metadata Publication

## Purpose

把 canonical Workspace 中一个明确 Task 的、由真实 writer 声明的 portable exact owned paths 作为独立 metadata-only Git 内容发布；不拥有 record 内容、Task 状态、Candidate、Finish 或 Git policy。

## Consumer Obligations

consumer 必须明确 canonical Workspace、Task ID、实际 repository、source/local ref，以及 push 适用时的 remote 与 destination ref；必须分别授权 local commit 与 remote push effects，并提供对应 writer read models/reference diagnostics。consumer 必须把 `commit+push` 拆成依次执行的 commit 和 push 两次 `buildr.git-operations/v1` 调用，保留两个独立 Result。

consumer 只能组合以下 writer declarations：

- `buildr.task-development/v2` → `.buildr/tasks/<task-id>/development.yml`；
- `buildr.task-verification/v3` → `.buildr/tasks/<task-id>/verification.yml`；
- `buildr.task-review/v1` → `.buildr/tasks/<task-id>/reviews/planning.yml` 与 `.buildr/tasks/<task-id>/reviews/completion.yml`。

不得用目录扫描、glob、extension、exclusion list 或 `git add -A` 推断 ownership。缺失的可选 record 保持缺失；已跟踪但当前缺失的 declared path可以作为精确删除进入 operation scope。

## Minimum Guarantees

provider 必须只在 canonical、非 linked-worktree Workspace 中处理调用方明确 Task。确定性 helper 必须逐级拒绝 path escape、symlink、非普通文件/目录、不可读内容和重复 ownership；按固定 owner/path 顺序记录 present/absent、bytes SHA-256、Git tree state 与 snapshot identity。helper 只执行只读 filesystem/Git observation，不执行 stage、commit、amend 或 push，也不写 publication receipt/history。

commit 前后必须重新核验 live exact set；metadata commit tree 对每个 declared path的presence/bytes必须与snapshot一致，commit diff只能包含本次operation paths。发生revision drift、额外path、不同blob或repository/ref drift时必须阻止push并保留已实际发生的local effect。

provider required消费selected `buildr.git-operations/v1`。commit只授权verified operation paths与新的独立metadata commit；push前必须核验destination与完整unpublished range，range中任一commit含scope外path时停止。provider不得amend已共享Candidate/delivery commit，不得自动stash、reset、rebase、merge、force push、换ref或改写共享历史。

重试前必须检查是否已有未共享、diff scope单一且最终tree与当前snapshot内容等价的metadata commit；能证明时复用且不生成重复commit，不能证明时停止或创建新的独立commit。等价内容已在destination时返回aligned/no-op。

Task Record的SQLite数据、Environment `environment.json`、`.buildr/task-finish/**`、`.buildr/asset-review/**`、`.buildr/mutations/**`、`.worktrees/**`、Agent/task runtime、本机路径/进程/资源、Candidate、delivery source、其他Task或其他owner metadata没有publication eligibility，任何情况下不得进入scope或Git authorization。

## Effects and Authorization

preflight、snapshot、writer/reference diagnostic、equivalent commit与range检查是只读。staging、local commit/history变化与remote push必须分别由consumer明确授权，并只通过Git Operations执行。无Git Workspace返回`local-only / not-applicable`并保留records；不创建Git占位状态。

publication无论成功、blocked或部分失败，都不得修改Task status/result、Environment、Development Candidate/generation/gates/decision/handoff、Review/Verification Result、Finish evidence或delivery source。历史Project/Service/Change已归档、退役或当前unavailable但writer仍安全返回record时，只报告non-blocking reference diagnostic，不改写bytes。

## Result Evidence

provider必须返回Task、canonical Workspace、repository/ref inputs、writer/reference diagnostics、declared/present/absent/operation paths、snapshot identity、pre/post verification，以及适用的commit Result和push Result。状态使用`aligned|succeeded|blocked|local-only|not-applicable|partial`；partial必须列出已经发生与未发生的effects。

commit成功而push失败时，commit Result保持succeeded、push Result为blocked，local metadata commit保留且remote unchanged。Result只存在于当前调用，不创建Receipt、history、Task字段或统一Git schema。

## Decision Points

Task/Workspace/repository/ref/effects不明确、writer read blocked、path占用/损坏/symlink、ownership冲突、snapshot drift、commit tree不等价、完整range含scope外commit、remote drift或push rejection时必须fail closed。reference仅archived/retired/unavailable且writer仍安全可读时不阻塞。恢复方式需要扩大授权、选择Git策略或改写共享历史时交还用户，不自动重试。

## Allowed Variations

provider可以调整只读Git命令、snapshot token编码、commit message与结果排版，也可以在future writer通过独立Change明确声明后增加portable exact path；不得新增同义入口、公共Application/CLI、第二个Git executor、publication history、批量发布、目录ownership或lifecycle authority。
