# 任务记录

## Purpose

在 canonical Workspace SQLite 中维护 Task 的最小顶层事实：`todo` 保存已接受但未启动的意向，`active` 表示正式执行，terminal 状态保存结果；同时维护 Parent/Child 与窄复盘来源关系。

## Consumer Obligations

consumer 必须提供明确 operation、canonical Workspace、稳定 Task ID 及动作字段。创建 todo 必须明确尚未进入执行且不得带 Change；active 创建或 todo 激活前的语义分流、Git 基线与后续专业动作由 consumer 负责。复盘来源只提交已有 current 复盘的 terminal source Task ID，不提交 action item、报告副本或通用关系。

## Minimum Guarantees

provider 必须只通过 Task Record Application 的 `create`、`inspect`、`update`、`activate`、`complete`、`abandon` 六个动作管理 closed `buildr.task-record/v2`。状态只允许 `todo -> active|completed(noChange=true)|abandoned` 和 `active -> completed|abandoned`；`open` 只是 `todo + active` 查询。provider 必须事务化校验 scope/Change、Parent、来源 Task terminal/current retrospective、自引用、重复关系和 response-level digest。一个目标可以有多个来源，一个来源可以指向多个目标。

## Effects and Authorization

create/update/activate/complete/abandon 只写 Task-owned SQLite rows；inspect/query 零写入。todo create 不得创建 filesystem、Environment、Change、Development 或 Git 状态；activate 只改 status。Local App 是同一 Application 的有限客户端，不创建或激活 Task。

## Result Evidence

结果必须返回 operation、Task ID、closed v2 record、recordDigest、Parent/Child 与复盘来源/承接摘要、effects、diagnostic 和 nextActions。不得返回数据库 path、环境事实、action item、完整复盘副本或专业 Result。

## Decision Points

target/identity/授权不明、provider 不 ready、todo 携带 Change、非法状态转换、来源不存在/未终态/无 current retrospective、关系冲突、digest 陈旧或数据库不安全时必须 blocked 并保持原记录。不得回退为 YAML/SQL 或自动激活。

## Allowed Variations

provider 可以调整读取顺序、CLI 展示和查询实现；不得改变 SQLite 单一 authority、六个动作、todo data-only、单向状态、来源粒度与无专业副作用保证。
