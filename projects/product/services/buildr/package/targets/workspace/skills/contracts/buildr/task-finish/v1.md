# 任务收尾

## Purpose

安全编排已验证任务的完整收尾；当需要迁移运行中的 Local App 时，保留其已认证 loopback 端口，但不接管 provider 专属的 Git 或 worktree 策略。

## Consumer Obligations

consumer 必须明确 task/change、请求的收尾范围、验证证据、目标分支、远端，以及所有明确排除的动作。

## Minimum Guarantees

provider 必须解析 required capabilities，在写入前披露 selected providers 和影响；按 delivery convergence、final assurance、closeout-only delivery 三阶段编排，在最终保证前完成可预见的 sync、候选提交、目标分支 rebase 和 runtime 收敛，最终保证后只允许可证明的 closeout-only transition。任一阶段失败时停止，保持验证证据与 tree 等价性，并记录 optional 阶段的降级。默认推送只覆盖已集成的目标分支，远端任务分支必须有用户当前轮次的明确要求。需要从 task worktree 迁移健康 Local App 时，provider 必须先记录已认证实例端口，使用保留 checkout 在同一端口完成健康交接后才允许 cleanup。

## Effects and Authorization

当前轮次的收尾授权覆盖已披露的常规归档、任务提交、集成、目标分支推送和安全本地清理。创建、推送或删除远端任务分支、强制推送、丢弃改动、改写共享历史和语义冲突决策仍明确排除。

## Result Evidence

返回各阶段结果、provider identities、验证证据、归档的 change（如有）、目标 ref observations、提交/集成/目标分支推送结果、任务分支未推送状态或明确授权、清理结果、Local App 迁移前后端口与健康结果、跳过的 optional 阶段和剩余风险。多次正式验证时还必须返回 run chain、execute count、失效原因、替代关系和重复验证总耗时。

## Decision Points

遇到 required capability 被阻断、范围或目标不明确、验证不可信、语义冲突、检查失败、远端写入被拒绝、同端口 Local App 交接失败或无法安全清理时，必须停止。

## Allowed Variations

provider 可以调整编排细节和 optional 审查的处理方式，但必须把 Git 集成和 worktree 生命周期策略交给各自的 selected provider。
