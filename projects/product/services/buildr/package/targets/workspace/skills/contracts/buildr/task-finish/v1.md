# 任务收尾执行器

## Purpose

把已具备收尾资格的候选通过 `preflight → prepare → verify → deliver → cleanup` 固定工作流完成交付。Task Finish 是确定性 closeout executor，不是研发、审查、测试修复或通用恢复引擎。

## Consumer Obligations

consumer 必须区分 `change`、`code-only` 与 retained `metadata-only` 候选，并在调用前确认开发、自审、必要审查、开发验证与 current knowledge 已达到完成标准。产品 run 必须提供正式 Task ID、canonical Workspace、matching `ready` Task Environment、Workspace Node identity、Project 和目标分支语义；只有 Change 候选必须提供 active Change。资产 observation 的 finalize 和人工决定发生在产品 Finish run 之外；仍为 `awaiting-human` 时不得开始会修改候选的阶段。

retained metadata-only handoff 的 consumer 必须证明当前位置是 retained canonical Workspace、任务 paths 与无关 dirty paths 可精确区分、验证 evidence 匹配当前内容、目标 branch/remote 明确，并在该分支确认 selected `buildr.git-single-operation@1` provider ready。任一事实不可证明时必须 blocked，不得伪造 task environment 或 Change。

consumer 不得提交 caller evidence、fingerprint、execution plan、attempt outcome、repair authorization 或 recovery manifest 来替产品证明阶段完成。产品缺陷、语义冲突或候选内容问题必须退出 Finish，回到研发、审查和测试验证流程修正当前实现，形成新的 finish-ready candidate 后重新进入。

## Minimum Guarantees

provider 必须由单一 canonical `buildr task finish run` 顺序执行五个固定阶段，不暴露通用 DAG 或 action registry 作为正常路径。所有 run 以 receipt task identity 为主身份，并记录 `candidateKind: change|code-only` 与可空 Change。`preflight` 只读并一次聚合环境、CLI 实际可执行性、验证声明、Git identity、目标分支与 retained checkout 的廉价检查；Change 候选还检查 Change tasks、current knowledge、OpenSpec strict/并发计划，code-only 候选必须把这些检查稳定记录为 `not-applicable` 且不执行 OpenSpec 命令。

`prepare` 完成所有会改变候选的确定性动作，包括 Change 候选的 OpenSpec convergence、生成资产同步、candidate commit、target convergence 和机械 fixed point；code-only 候选必须把 convergence 记录为 `not-applicable`。frozen candidate identity 必须包含 task、candidate kind、可空 Change 与 Workspace Node identity。freeze 后任何候选变化都使 run 终止，不能在同一 run 中修复。

`verify` 必须通过 `buildr.task-verification/v3` 的同一 Application inspect frozen target 对应的 current Result。只有 target/declarations current、conclusion passed 且覆盖适用 `requiredForDelivery` capabilities 时可以复用；否则至多执行一次可确定的 command capability 集合、提炼 portable facts、原子 record Result 并清理 transient execution evidence。临时 adapter 只按 Project/Service scope 与 path 做确定性选择；自然语言 `conditions` 不能作为跳过依据，命中时必须保守执行。多 Project、Agent capability、需要语义排除或不完整事实必须退出并要求先完成正式 Task Verification。任何失败返回具体 phase、operation、check、exit code、bounded findings 与 diagnostic，并以 `upstream-candidate-defect` 终止 run、返回 `nextWorkflow: task-development`；不得在同一 run 修复或重新验证。

`deliver` 必须使用短 target lease/fencing，核对 freeze 时与 push 前 target ref，只允许 fast-forward 集成和目标分支 push；远端竞态、网络失败、retained sync/install 等外部暂态可 blocked。`cleanup` 必须先写 canonical durable delivery/completion facts，再把各 scope 的 delivery identity 与 cleanup eligibility 交给 `buildr.task-environment/v1`。Environment 独占动态资源停止、provider cleanup、共享根解除占用和 cleanup result；Finish 不得直接扫描资源、调用 worktree cleanup、删除 checkout/branch 或写第二份环境结论。

canonical retained readiness 按 Workspace Metadata Store 既定边界排除未 staged 的 `.buildr/**`，避免 Task/Review/Verification 各自唯一 Application writer 自我阻塞；Finish 不得 stage、commit、发布、修改或丢弃这些 metadata。任意源码/文档 dirty 或 staged Workspace metadata 仍必须阻塞；exact owned-path publication 继续属于后续 Task Metadata Publication。

blocked 恢复输入只能由产品根据持久化事实生成，并绑定 run、phase、candidate 与 failure identity；恢复只重试当前 blocked phase 和下游。产品缺陷失败是终态，没有 resume token。客户端直接使用唯一 canonical `runs`、`completed` 与 lease namespace，不创建版本化运行目录；旧 run shape 不可恢复，也不解释、迁移或执行旧协议。

正常完成结果必须证明 canonical CLI invocation 为 1、Agent/provider completion 为 0、手写 recovery manifest 为 0、formal verification execution 不超过 1，并报告 product command observations、product execution 和 end-to-end wall-clock。

Task Environment 的 `ready` read model 必须同时证明 Task/scope/environment/source/projection identity、Workspace Node identity 和 Environment 指定 CLI 的真实 `version --json` 探针成功；冻结、恢复、验证与交付前任一 identity 漂移都必须停止。路径存在或 executable bit 不足以证明可执行。

## Effects and Authorization

普通“收尾”授权确定性的适用 OpenSpec convergence、生成资产收敛、候选提交、target rebase/fast-forward、目标分支 push、retained runtime sync/install 及 task-owned 本地清理。retained metadata-only handoff 只授权已披露精确 paths 的 commit 和目标分支 push；provider 不得 `git add -A`、stash、回滚或移动无关 dirty state。它不授权修复产品缺陷、解决语义冲突、force push、改写共享历史、丢弃用户改动、操作远端任务分支或删除非 task-owned 状态。

## Result Evidence

产品结果使用 `buildr.task-finish-result/v1`，包含 run/task/candidate kind/可空 change/project/target/Workspace Node identity、五阶段状态、frozen candidate、verification、delivery、Environment cleanup handoff/result、completion、具体 primary failure、产品生成的可选 resume token、next workflow 及效率指标；completion receipt 同样记录 candidate kind。命令 observation 记录确定性 operation、cwd、exit、duration 和有界输出摘要及 digest，不要求 Agent 搜索日志猜测失败步骤。retained metadata-only 路径返回逐项 Git evidence 与 `completionMode: git-single-operation-handoff`，不伪造五阶段 completion receipt。

## Decision Points

preflight 聚合发现候选尚未完成、适用的 OpenSpec 语义冲突、开发验证欠缺或 freeze/正式验证失败时，终止并返回研发流程。只有 target lease、远端竞态、网络、retained convergence/install 或 task-owned cleanup 等不改变候选语义的暂态失败可以 blocked 并由产品生成恢复令牌。retained metadata-only 只在精确 path、验证 identity、目标 ref 与 Git provider readiness 全部可证明时 handoff。

## Allowed Variations

Project 可以声明多个明确 scope/applicability 的 command 或 Agent capability，以及哪些能力 `requiredForDelivery`。Task Finish Skill 可以把 optional `buildr.git-single-operation@1` 只在 retained metadata-only 分支提升为 required；普通产品 run 必须消费 `buildr.task-environment/v1` 和唯一 Task Verification Application，不依赖固定 Git/worktree provider。provider 可以扩充只读 preflight 检查与确定性 domain service，但不能增加 Result writer、assurance 层级、Agent completion、同 run repair/re-verification 或 caller-authored recovery 协议。
