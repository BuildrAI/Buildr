# Task Finish Handoff Consumer

## Purpose

消费 current formal Development handoff，准备与 Task Candidate Content Target 可证明等价的交付载体（Delivery Carrier），推进目标、完成 retained convergence 并把 cleanup eligibility 交给 Task Environment。Task Finish 是窄交付 adapter，不是 Development、Change、Review 或 Verification authority。

## Consumer Obligations

consumer 必须提供正式 Task ID、canonical Workspace、matching ready Environment 和由 `buildr.task-development@1` Application 读取的 current handoff。不得用 Project/Change 参数、Git HEAD、branch、worktree、时间或调用方摘要代替 handoff。retained metadata-only Git handoff 仍须证明 exact paths、验证 identity、目标 branch/remote 和 selected `buildr.git-operations@1` provider ready，并由 Task Finish 分别选择 commit 与 push operation。

Git-backed Product adapter 必须把 run 绑定到 retained checkout 当前符号分支；显式 target branch 必须与当前分支一致。Environment checkout `startPoint` 只描述候选来源，不得充当交付分支 identity；detached retained checkout、显式不一致或不可解析的 local branch 必须在创建 run 前停止。Product adapter 还必须绑定 retained checkout 中真实配置的 delivery remote。Environment 对 workspace source 没有 remote 时，consumer 可以依赖 target branch upstream 或唯一配置 remote；没有可用 remote、多个 remote 无法消歧或用户指定值未配置时必须停止，不得接受本地-only delivery 冒充远端交付。

consumer 不得提交 caller evidence、Candidate、generation、risk acceptance、Result 或 recovery manifest让产品解释；handoff stale、任务贡献（Task Contribution）漂移、carrier 不等价或 target 无法安全推进时必须返回 Task Development。

## Minimum Guarantees

- canonical `buildr task finish run --task <id>` 仍顺序执行 `preflight → prepare → verify → deliver → cleanup`，但五阶段只覆盖 handoff/current environment 检查、carrier preparation、内容等价检查、交付和 cleanup。
- `preflight` 只能读取 Development handoff、Environment、当前 adapter carrier 与 retained target readiness；不得检查或解释 Change/current knowledge/Review/Verification store。
- `prepare` 可以改变隔离carrier的commit identity，但不得改变Candidate内容或原Task worktree/index/branch。当前Git adapter从原任务基线到source snapshot计算任务贡献（Task Contribution），在最新交付基线（Delivery Baseline）的run-owned detached worktree中机械应用并比较canonical raw Git delta identity；不执行OpenSpec convergence/archive、runtime generation、target rebase、Candidate freeze或任何实现修复。
- `verify` 只调用Development Application的只读carrier-equivalence check，并复核Task Contribution/Delivery Baseline/carrier identities；formal Verification executions必须为`0`。不得选择capability、运行测试或record Verification Result。
- `deliver` 继续使用短 target lease/fencing、fast-forward target transition、普通 push，以及交付后 retained runtime sync/install/Doctor；push 后必须重新读取远端 target ref，只有真实 after ref 等于 carrier 才能形成 `remoteAfterRef`、`delivered` 与 cleanup eligibility。这些动作不取得 Development writer authority。
- `cleanup` 先写已有 Finish delivery/completion facts，再将 delivery identities 交给 `buildr.task-environment@1`。Environment 独占资源停止、provider cleanup、共享根解除占用和 cleanup result。
- Finish 不创建、递增、回退或删除Task Candidate/generation；只有Task Contribution在最新Delivery Baseline无冲突应用且identity等价时，才复用同一Candidate/generation、Verification、Completion Review、decision与handoff。Finish不执行Completion Review，不决定proceed/blocked，不接受用户风险，也不修改Development Receipt。
- blocked resume token 只能由产品绑定 run/phase/carrier/failure 生成；失败若涉及 handoff、Candidate、Content Target 或等价性，返回 `nextWorkflow: task-development`。

## Effects and Authorization

普通“收尾”授权内容等价 carrier commit、目标分支 fast-forward/push、retained sync/install/Doctor 和 Task-owned cleanup。它不授权 Change convergence/archive、候选内容生成或修复、target rebase、正式 Verification、Review、风险接受、force push、共享历史改写或丢弃用户改动。

## Result Evidence

产品结果使用 `buildr.task-finish-result/v2`，包含run identity、Development handoff identity、Task Candidate identity/generation、Content Target、Task Contribution、Delivery Baseline、Delivery Carrier、五阶段状态、只读equivalence、delivery、cleanup/completion、primary failure、可选resume token与效率指标。Git-backed正常路径的`observedTargetRef`、`carrierRef`与`remoteAfterRef`必须分别来自push前观察、carrier和push后远端回读；正常路径必须报告`formalVerificationExecutions: 0`。

## Decision Points

handoff非current、Environment/Workspace Node漂移、retained target branch detached/不一致、delivery remote缺失/歧义、Task Contribution冲突/漂移/不等价、carrier内容变化、push后远端ref不等于carrier、retained checkout含无关dirty、cleanup不安全时停止并按失败类型返回。carrier准备后target ref前进时，产品可以blocked并生成精确token；恢复同一run必须废弃旧carrier并从最新Delivery Baseline重做`prepare → verify → deliver → cleanup`，Candidate/generation与既有gates保持不变。无法重新证明贡献等价时terminal返回Task Development。路径不重叠或clean apply不得被表述为语义安全。

## Allowed Variations

Project 可以提供 Git、tarball、安装包或其他 carrier adapter。每个 adapter 都必须证明与 handoff Content Target 等价；不得把 adapter-specific Git/OpenSpec/Node/npm/Buildr registry 约束写回 Development schema，或恢复旧 Candidate/Verification writer。
