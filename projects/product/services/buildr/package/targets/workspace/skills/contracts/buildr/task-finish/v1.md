# Task Finish Handoff Consumer

## Purpose

消费 current formal Development handoff，准备与 Task Candidate Content Target 可证明等价的 Delivery Carrier，推进目标、完成 retained convergence 并把 cleanup eligibility 交给 Task Environment。Task Finish 是窄交付 adapter，不是 Development、Change、Review 或 Verification authority。

## Consumer Obligations

consumer 必须提供正式 Task ID、canonical Workspace、matching ready Environment 和由 `buildr.task-development@1` Application 读取的 current handoff。不得用 Project/Change 参数、Git HEAD、branch、worktree、时间或调用方摘要代替 handoff。retained metadata-only 单项 Git handoff 仍须证明 exact paths、验证 identity、目标 branch/remote 和 selected `buildr.git-single-operation@1` provider ready。

Git-backed Product adapter 必须把 run 绑定到 retained checkout 当前符号分支；显式 target branch 必须与当前分支一致。Environment checkout `startPoint` 只描述候选来源，不得充当交付分支 identity；detached retained checkout、显式不一致或不可解析的 local branch 必须在创建 run 前停止。Product adapter 还必须绑定 retained checkout 中真实配置的 delivery remote。Environment 对 workspace source 没有 remote 时，consumer 可以依赖 target branch upstream 或唯一配置 remote；没有可用 remote、多个 remote 无法消歧或用户指定值未配置时必须停止，不得接受本地-only delivery 冒充远端交付。

consumer 不得提交 caller evidence、Candidate、generation、risk acceptance、Result 或 recovery manifest让产品解释；handoff stale、carrier 不等价或 target 无法安全推进时必须返回 Task Development。

## Minimum Guarantees

- canonical `buildr task finish run --task <id>` 仍顺序执行 `preflight → prepare → verify → deliver → cleanup`，但五阶段只覆盖 handoff/current environment 检查、carrier preparation、内容等价检查、交付和 cleanup。
- `preflight` 只能读取 Development handoff、Environment、当前 adapter carrier 与 retained target readiness；不得检查或解释 Change/current knowledge/Review/Verification store。
- `prepare` 可以改变 commit、branch 等载体 identity，但不得改变 Candidate 内容。当前 Git adapter 只允许 stage/commit 相同 bytes 并要求 target 是 fast-forward ancestor；不执行 OpenSpec convergence/archive、runtime generation、target rebase、Candidate freeze 或任何实现修复。
- `verify` 只调用 Development Application 的只读 carrier-equivalence check，formal Verification executions 必须为 `0`。不得选择 capability、运行测试或 record Verification Result。
- `deliver` 继续使用短 target lease/fencing、fast-forward target transition、普通 push，以及交付后 retained runtime sync/install/Doctor；push 后必须重新读取远端 target ref，只有真实 after ref 等于 carrier 才能形成 `remoteAfterRef`、`delivered` 与 cleanup eligibility。这些动作不取得 Development writer authority。
- `cleanup` 先写已有 Finish delivery/completion facts，再将 delivery identities 交给 `buildr.task-environment@1`。Environment 独占资源停止、provider cleanup、共享根解除占用和 cleanup result。
- Finish 不创建、递增、回退、复用或删除 Task Candidate/generation，不执行 Completion Review，不决定 proceed/blocked，不接受用户风险，也不修改 Development Receipt。
- blocked resume token 只能由产品绑定 run/phase/carrier/failure 生成；失败若涉及 handoff、Candidate、Content Target 或等价性，返回 `nextWorkflow: task-development`。

## Effects and Authorization

普通“收尾”授权内容等价 carrier commit、目标分支 fast-forward/push、retained sync/install/Doctor 和 Task-owned cleanup。它不授权 Change convergence/archive、候选内容生成或修复、target rebase、正式 Verification、Review、风险接受、force push、共享历史改写或丢弃用户改动。

## Result Evidence

产品结果使用 `buildr.task-finish-result/v2`，包含 run identity、Development handoff identity、Task Candidate/Content Target identity、Delivery Carrier、五阶段状态、只读 equivalence、delivery、cleanup/completion、primary failure、可选 resume token 与效率指标。Git-backed 正常路径的 `observedTargetRef`、`carrierRef` 与 `remoteAfterRef` 必须分别来自 push 前观察、carrier 和 push 后远端回读；正常路径必须报告 `formalVerificationExecutions: 0`。

## Decision Points

handoff 非 current、Environment/Workspace Node 漂移、retained target branch detached/不一致、delivery remote 缺失/歧义、carrier 内容变化、目标 ref 前进或不是 fast-forward、push 后远端 ref 不等于 carrier、retained checkout 含无关 dirty、cleanup 不安全时停止；目标变化必须 terminal 返回 Task Development。只有 carrier 与 expected target ref 均未变时的 target lease、网络、远端回读不可用、retained sync/install/Doctor 或 Task-owned cleanup 外部暂态问题可以 blocked/resume。

## Allowed Variations

Project 可以提供 Git、tarball、安装包或其他 carrier adapter。每个 adapter 都必须证明与 handoff Content Target 等价；不得把 adapter-specific Git/OpenSpec/Node/npm/Buildr registry 约束写回 Development schema，或恢复旧 Candidate/Verification writer。
