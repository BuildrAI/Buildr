# 任务复盘（Task Retrospective）

## Purpose

对 terminal Task 的 Agent 执行效率进行一次按需复盘，并在 Workspace SQLite 中维护唯一 current Markdown Result，供 Local App 只读展示。

## Consumer Obligations

consumer 必须提供 canonical Workspace、正式 Task ID，并让 provider 读取当前可见的任务过程与结果证据。只有 Task 为 `completed|abandoned` 且完整报告已形成时才能调用 `record`；不能取得精确耗时或 token 时必须明确数据缺口，不得伪造数值。

## Minimum Guarantees

provider 必须聚焦 Agent 执行效率，优先识别高耗时/high-token、重复尝试、等待与人机选择成本，并允许 Agent 自由组织报告。Task Retrospective Application 独占 closed `buildr.task-retrospective-result/v1`、terminal status 校验、系统时间、serialization、digest 与 SQLite 单行事务替换。Result 只含 `taskId`、固定 focus、`reportMarkdown` 与 `completedAt`。

provider、Application 与 Local App MUST不读取隐藏推理、完整对话、完整工具日志、后台事件或旧`.buildr/asset-review/`；不得创建history、revision、评分、候选、跨任务索引或自动采集。

## Effects and Authorization

`inspect` 零写入；`record` 只创建或完整替换同一 Task 的一份 current Result。复盘不修改Task Record、Environment、Development、Review、Verification、Finish、Git或OpenSpec，不是terminal transition、handoff、delivery或cleanup门禁。报告中的建议不授权修改产品或工作资产。

## Result Evidence

provider 必须返回 focus、实际报告、已用证据边界与数据缺口，以及Application operation result。read model 返回present、Result、response-only `resultDigest`与逻辑path；absent只是“尚未复盘”，不表示blocked或failed。

## Decision Points

Task不存在、Task仍active、报告为空、current row损坏、SQLite事务无法安全替换或Application返回blocked时停止写入。任务过程证据不足时可以形成明确带数据缺口的复盘；不得用模板补造事实。

## Allowed Variations

provider可以自由选择分析顺序、篇章、证据粒度与建议表达，也可以替换实现；必须保持terminal-only、固定效率focus、自由Markdown、唯一Application/SQLite current row、只读Local App及非门禁边界。
