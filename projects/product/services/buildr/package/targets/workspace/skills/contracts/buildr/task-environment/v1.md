# 任务环境（Task Environment）

## Purpose

为正式 Task 准备、检查、恢复和清理实际执行环境，并通过唯一 Environment Receipt 提供当前机器的环境事实。

## Consumer Obligations

consumer 必须提供正式 Task ID 和 canonical Workspace。开始修改交付物、构建、测试或创建持久资源前，必须取得 matching `ready` 结果，并只使用结果允许的执行根和执行 CLI。consumer 不得手写 Receipt、从 cwd/分支猜环境，也不得把 Agent session 采用当作 P0.2 的 ready 条件。

## Minimum Guarantees

provider 必须通过共享 Task Environment Application 管理 `.buildr/tasks/<task-id>/environment.json`。Receipt 独占实际 scope/root、Task checkout/provider evidence、Runtime、Workspace CLI、依赖、runtime projection identity、动态资源、`ready / blocked`、恢复和 cleanup 事实；Task Record 不保存这些字段。retained Buildr 只作为可信 Environment Manager；其 content identity 最多是 Receipt 创建指纹，不是源码版本、ready、资源 ownership 或 Verification applicability authority。

`prepare` 必须幂等完成首次准备和串行恢复，`inspect` 必须只读重新探测当前机器事实，`cleanup` 必须只接受已交付的 Finish handoff 或明确 abandon 终态。隔离Delivery Carrier交付时，Environment必须把bounded Task Contribution/source/baseline/carrier/target proof交给Git provider独立复算，不得要求Finish改写原Task branch制造ancestor关系。候选 CLI 可以在本 Task 验证工作区测试，但不能写 retained、peer Task 或共享 user runtime，也不能认领或清理自己的 Environment。

## Effects and Authorization

Environment 可以调用 selected provider 创建执行位置、准备确定性依赖和投射任务验证 runtime，也可以登记已知产品 provider 创建的非敏感动态资源。部分失败保留可诊断现场并返回 blocked。资源停止和 provider cleanup 由 Environment 统一执行；任意 shell、凭证、远端删除和无法证明 ownership 的效果均不允许写入 Receipt。

## Result Evidence

返回 Task、Workspace、receipt availability、`current-machine`、`observedAt`、状态、实际 scopes/roots、controller、Runtime/CLI/依赖/projection probes、provider evidence、动态资源、effects、diagnostic、nextActions 和 cleanup 摘要。真实 Agent session 采用证据由 Task Verification 管理，不属于本结果。

## Decision Points

Task/Workspace不匹配、Receipt损坏、Environment Manager sourceRoot/adapter不可信、Git-backed manager source dirty、provider/resource identity漂移、执行根越界、必需probe blocked、可见并发writer、source drift、Task Contribution等价证明失败或cleanup authorization不足时必须fail closed。第一版只支持同一Task单一active writer，不建设锁、CAS、租约、调度器或通用状态机。

## Allowed Variations

provider 组合、共享根或 Git checkout 的选择可以不同；唯一 Environment Receipt、可信 retained Environment Manager、Task checkout/provider 源码基础、真实 probe、写入边界和统一 cleanup authority 不可省略。
