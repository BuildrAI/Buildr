# 任务环境（Task Environment）

## Purpose

为正式 Task 准备、检查、恢复和清理实际执行环境，并通过唯一 Environment Receipt 提供当前机器的环境事实。

## Consumer Obligations

consumer必须提供正式Task ID和canonical Workspace。Agent必须根据Task Record的完整Project/Service scope、Project `preparation.yml`及构建/验证事实选择Recipe并提交closed Plan Request；Formal Verification可提交admission生成的closed capability auxiliary preparation request。开始修改交付物、构建、测试或创建持久资源前，必须取得matching `ready`结果，并只使用结果允许的执行根、执行CLI和runtime invocation。consumer不得手写Receipt、从cwd/分支猜环境、转抄Node/PATH/cwd或把Agent session采用当作ready条件。

## Minimum Guarantees

provider必须通过共享Task Environment Application管理Workspace SQLite中按Task ID唯一的`task_environment_current` row，并通过公开read model返回`workspace-sqlite:task-environment/<task-id>` locator。Project `preparation.yml`是长期Recipe authority；Plan v3把恰好覆盖Task scope的基础选择与capability auxiliary preparation分开，后者不得改变Task/Change/Content Target/allowed execution roots或源码写入authority。Plan中的typed Workspace path reference与closed executable authority必须分离；Receipt v6独占实际scope/root、Task checkout/provider evidence、Declaration/Scope/Recipe/Step current与prepared facts、解析后的机器路径、closed runtime invocation、Workspace CLI、runtime projection identity、动态资源、`ready / blocked`、恢复和cleanup事实。Task Record不保存这些字段。不得由目录扫描、lifecycle projection或runtime current反向推导技术栈。retained Buildr只作为可信Environment Manager；其content identity最多是Receipt创建指纹，不是源码版本、ready、资源ownership或Verification applicability authority。旧Plan/Receipt只读兼容，只有显式Plan Request才能升级。

`prepare`必须幂等完成首次准备和串行恢复；Step只接受明确的无shell executable authority、args、typed Workspace-relative cwd/input/output、required和timeout。Workspace Foundation/runtime/machine requirement与Project/Service wrapper authority必须closed；实际机器executable、version/content identity、search prefix和来源只保存到Receipt。Project/Service wrapper真实路径不得越出所属execution root。只跳过Declaration/Recipe/executable/input identities与prepared identities一致且全部outputs ready的Step。CLI `inspect`必须只读重新观察这些facts，不执行Step、不创建输出、不升级Plan、不回写Receipt；Buildr Web GET必须使用saved-current reader。`cleanup`必须只接受Buildr已持久化并可独立复核的Delivery evidence，或明确abandon终态；不得要求Delivery只能由自动Finish产生。候选CLI可以在本Task验证工作区测试，但不能写retained、peer Task或共享user runtime，也不能认领或清理自己的Environment。

## Effects and Authorization

Environment 可以调用 selected provider 创建执行位置、准备确定性依赖和投射任务验证 runtime，也可以登记已知产品 provider 创建的非敏感动态资源。部分失败保留可诊断现场并返回 blocked。资源停止和 provider cleanup 由 Environment 统一执行；任意 shell、凭证、远端删除和无法证明 ownership 的效果均不允许写入 Receipt。

## Result Evidence

返回Task、Workspace、receipt availability、`current-machine`、`observedAt`、状态、实际scopes/roots、controller、Plan identity、逐Declaration/Scope/Recipe/Step current与prepared identity、executed、inputs/outputs/required/status/diagnostic、Runtime/CLI/projection probes、provider evidence、动态资源、effects、diagnostic、nextActions和cleanup摘要。Step的`executed`表示当前prepare调用是否实际执行；effect进一步给出本次执行位置。真实Agent session采用证据由Task Verification管理，不属于本结果。

## Decision Points

Task/Workspace不匹配、Plan缺失/越权/未完整覆盖scope、Receipt损坏、Environment Manager sourceRoot/adapter不可信、Git-backed manager source dirty、provider/resource identity漂移、required Step缺失/漂移/失败、执行根越界、必需probe blocked、可见并发writer、source drift、Task Contribution等价证明失败或cleanup authorization不足时必须fail closed。provider不枚举package manager或技术栈，也不建设包管理框架、锁、CAS、租约、调度器或第二套Environment store。

## Allowed Variations

provider 组合、共享根或 Git checkout 的选择可以不同；唯一 Environment Receipt、可信 retained Environment Manager、Task checkout/provider 源码基础、真实 probe、写入边界和统一 cleanup authority 不可省略。
