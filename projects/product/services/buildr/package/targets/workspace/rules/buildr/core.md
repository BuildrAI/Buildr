# Buildr Core

Buildr 产品及其生成的工作空间（Workspace）共同遵守本规则。按组织根（Organization/Root）→ 项目（Project）→ 服务（Service）读取当前作用域（scope）的 `AGENTS.md`。

## 产品哲学

> **Buildr 应该约束智能体（Agent）不要做错事，而不是要求智能体必须通过 Buildr 才能做事。**

人负责目标、业务判断和授权；智能体负责理解、推理和执行；Buildr 负责治理长期工作资产与少量确定性边界，不成为另一个智能体或通用许可层。

- 智能体是用户与 Buildr 专业机制之间的解释和执行层：Buildr 向智能体提供准确事实、证据和安全边界；智能体向用户说明目标、结果、影响与必要决定，不把 Buildr 内部术语和流程问题转交用户。
- 除非用户明确在开发 Buildr，发布版 Buildr 的用户不承担 Buildr 内部问题的诊断、修复或操作责任；只有涉及用户授权或业务判断时，才向用户请求决定。
- Buildr Web 面向用户展示的内部文档引用（internal document reference）使用可解析的具名相对引用（named relative reference），并验证正文当前可读；裸路径只用于诊断详情或代码语境。
- 规则（Rule）、技能（Skill）、诊断和工作流（Workflow）为智能体提供事实、方法与建议，不把推荐路径变成唯一合法路径。
- Buildr 采用宽而薄的治理：只有继续推进会造成越权、错误对象写入、未经授权的外部或不可逆副作用、证据失真或完成误报，或者覆盖他人工作时，才关闭式失败。
- Buildr 的内部登记、派生证据或自动化信心不足，不得否定可从权威来源验证的事实，也不得阻塞无关工作。
- 智能体反复犯错时，改进事实、指导、诊断和恢复能力，不把专业判断与执行收回 Buildr 状态机。
- 人和智能体使用一致术语；专业术语首次出现时使用“中文（English Term）”，无稳定译名时使用“中文释义（English Term）”，后续使用中文。

新增或收紧硬门禁，必须说明它保护的结果不变量、放行的具体伤害，以及 Buildr 失败后的安全降级方式；否则保持为诊断或建议。

## 规则边界

- 规则只承载价值观、权威与授权边界、约束和结果不变量；组织根、项目或服务的 `AGENTS.md` 只能增加当前作用域的这些内容。
- 规则不承担技能路由、命令序列、生命周期、恢复或专业状态。规则可以命名唯一责任主体（owner）和禁止绕过的不变量，但不得复制流程或当前状态。
- 技能说明（Skill description）发现用户意图，技能正文（Skill body）承担流程，能力绑定（capability binding）选择提供者（provider），项目声明（Project declaration）说明适用性与证明范围，技能或应用（Application）维护状态与结果（Result）；规则不成为第二权威。
- 必需且已安装的规则必须读取；可选且已安装的规则只在语义相关时读取；禁用或卸载的规则不生效。智能体运行时（Agent runtime）只负责发现和投射，不替智能体判断语义。

## 工作空间模型

Buildr 管理源资产和可重建的运行时投射；智能体选择相关资产形成任务上下文并推进工作。

工作空间按组织根 → 项目 → 服务分层：组织根承载组织资产；项目表示业务、产品线、系统或长期工作单元；服务表示代码仓、应用、模块或可执行资产。

## 工作空间硬边界

- Buildr 源资产是长期事实；运行时、本机状态、凭证、临时提示词（prompt）和一次性聊天不是源资产。
- 智能体必须遵守已安装且无歧义的能力绑定，不得猜测或绕过提供者。
- 组织资产、项目资产和服务代码仓的 Git 边界必须按实际仓库判断，不得凭目录名假设。
- Buildr 必需引用块（required block）只引用 Core；项目或服务的 `AGENTS.md` 只增加作用域约束，任务流程由技能承载。
- Buildr 必需规则由 Buildr 管理，不得手工改写；损坏时由 Buildr 恢复。
