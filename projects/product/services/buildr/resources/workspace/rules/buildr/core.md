# Buildr Core

Buildr 产品及其生成的工作空间（Workspace）共同遵守本规则。

## 责任与治理

- 人负责目标、业务判断和授权；智能体负责理解、推理和执行；Buildr 负责治理长期工作资产与少量确定性边界，不成为另一个智能体或通用许可层。
- 智能体（Agent）向用户说明目标、结果、影响与必要决定，不把 Buildr 内部术语和流程问题转交用户。
- 除非用户明确在开发 Buildr，发布版 Buildr 的用户不承担 Buildr 内部问题的诊断、修复或操作责任；只有涉及用户授权或业务判断时，才向用户请求决定。
- 只有继续推进会造成越权、错误对象写入、未经授权的外部或不可逆副作用、证据失真、完成误报或覆盖他人工作时，才关闭式失败。
- Buildr 的内部登记、派生证据或自动化信心不足，不得否定可从权威来源验证的事实，也不得阻塞无关工作。

## 用户沟通

- 面向用户时，使用直接、简练、易于理解的表达；仅在准确表达所必需时使用专业术语。
- 人和智能体使用一致术语；专业术语每次出现都必须使用“中文（English Term）”，无稳定中文译名时使用“中文释义（English Term）”，不得单独使用中文或英文专业术语。
- 命令、代码标识、字段名、接口名、文件路径、错误原文和产品专名必须精确对应实现；作为专业概念说明时补充中文名称或中文释义。
- 输出环境支持时，关系、时序、分支或状态转换用文字不易准确理解，就使用 Mermaid，并用一句话说明结论；简单线性内容使用文字或表格。
- 完成当前工作、到达阶段节点或遇到阻塞时，说明明确、可执行的下一步；任务已经完整结束时明确说明完成，不机械追加无关建议。

## 工作资产职责

- 当前作用域（scope）继承组织根（Organization/Root）→ 项目（Project）→ 服务（Service）的 `AGENTS.md`：组织根承载组织资产；项目表示业务、产品线、系统或长期工作单元；服务表示代码仓、应用、模块或可执行资产。
- Buildr 管理长期源资产和可重建的运行时投射；运行时、本机状态、凭证、临时提示词（prompt）和一次性聊天不是源资产。
- 规则（Rule）只承载价值观、权威与授权边界、约束和结果不变量；组织根、项目或服务的 `AGENTS.md` 只能增加当前作用域的这些内容。
- 规则不承担技能路由、命令序列、生命周期、恢复或专业状态；可以命名唯一责任主体（owner）和禁止绕过的不变量，但不得复制流程或当前状态。
- 技能说明（Skill description）发现用户意图，技能正文（Skill body）承担任务流程，能力绑定（capability binding）选择提供者（provider），项目声明（Project declaration）说明适用性与证明范围，技能或应用（Application）维护状态与结果（Result）；规则不成为第二权威。
- 必需且已安装的规则必须读取；可选且已安装的规则只在语义相关时读取；禁用或卸载的规则不生效。智能体运行时（Agent runtime）只负责发现和投射，不替智能体判断语义。

## 不可绕过边界

- 智能体必须遵守当前作用域已选择且可用的能力提供者，不得猜测或绕过能力绑定。
- 组织资产、项目资产和服务代码仓的 Git 边界必须按实际仓库判断，不得凭目录名假设。
- Buildr 必需引用块（required block）只引用 Buildr 核心规则（Buildr Core）。
- Buildr 必需规则由 Buildr 管理，不得手工改写；损坏时由 Buildr 恢复。
