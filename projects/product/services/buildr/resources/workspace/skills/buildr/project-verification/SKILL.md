# 项目验证

本技能（Skill）是 `buildr.task-verification/v4` 的默认提供者。智能体（Agent）依据用户请求、实际代码与项目测试登记选择并调用真实项目工具，交付检查证据及未覆盖项。正式任务（Task）是已有报告的归属对象，不是运行检查的前提；测试代码与 `verification.yml` 的唯一维护者是 `project-testing`。兼容旧能力调用中的地图维护请求时，直接组合该维护方法完成并返回原应用证据，不让用户或调用方重复转交，也不在本技能生成第二份候选或自行写入。

## 1. 确定请求与对象

承接用户指定的具体检查、类型、全量或相关范围；没有指定时，从目标、真实改动、公共调用面、构建与资源依赖追踪到用户实际交付物。已有正式任务时读取其当前说明作为补充；没有任务不创建占位任务、计划、比较基线或报告。用户请求是选择依据，项目登记和现有选择器用于发现，不把预设场景限制为唯一执行方式。

只使用静态检查（Static Check）、单元测试（Unit Test）、集成测试（Integration Test）、端到端测试（End-to-End Test，E2E）四类。具体定义由 `project-testing` 的测试模型维护，不在本技能（Skill）复制第二套分类。相关检查必须覆盖本次全部必要边界，包括共享逻辑调用方、真实数据/协议、安装后入口及必要平台差异；不是只执行成本最低或恰好匹配路径的项目。

## 2. 发现与选择

读取当前 `projects/<project>/verification.yml`、实际入口及适用规则。执行登记命令前核对 `locations`，按绑定根解析 `cwd` 并保留项目包装入口，不简化为系统 `PATH` 中的裸命令。路径不可用只形成该项缺口，继续无关已授权检查；根可用不证明命令覆盖完整。

已知具体检查直接调用；相关选择需比较时核对准确来源，缺少 Git 基线可从请求与实际文件选择，不阻断独立检查。先查看项目提供的 `--plan`；其结果只说明将执行什么，不证明覆盖与成功。按真实调用补齐漏选；缺少检查、错误声明或需要新增测试时交给 `project-testing`，本技能（Skill）不直接改写测试登记。

Buildr 产品在 `services/buildr` 通过项目包装入口调用 `npm test`、`npm run check`、`npm run test:static`、`npm run test:integration`、`npm run test:e2e`、`npm run test:related`；使用各入口提供的 `--plan` 查看范围、`--check <id>` 显式指定检查。具体检查与类型参数按当前入口帮助，用户的任意明确检查请求不强制改写为任务或发布流程。其他项目使用自身真实入口，不要求采用 Buildr 产品脚本。

## 3. 执行与证据

开发中按目标选齐相关四类检查；Buildr 产品推送前执行四服务全部静态检查（Static Check）与单元测试（Unit Test），包括真实类型检查。发布或明确要求时补足相应集成测试（Integration Test）和端到端测试（End-to-End Test，E2E），任务已涉及的必要边界不得推迟。推送前检查不授予 Git 推送授权；发布检查不授予公开发布授权。

复用仍适用于当前内容、配方、依赖、工具和必要环境的真实结果；只补新增、失败、未执行或已失效项，保留原来源和实际范围，不以阶段转换重跑全部。已检查内容或环境变化后重新判断，不能用旧成功证明新内容。运行期间不修改被测源码；一轮收集独立失败，修复后补失败与实际受影响项。

需要浏览器时读[前端证据](references/frontend-verification.md)，检查结束后关闭本次创建的临时标签页，成功、失败或中断都需处理；需要启动服务时读取当前 `buildr` 技能（Skill）的服务本地运行指引，在明确目录和授权范围使用隔离实例。服务就绪不等于业务验证通过，自动截图不等于视觉审查（Visual Review）。真实账号、付费模型、外部写入及业务取舍超出现有授权时，先完成独立检查，再把具体范围、影响与待决定事项反馈用户；普通内部准备、选择和执行不逐项确认。

用户指定全量时核对实际发现集合及全部结果，部分通过不得报告完整。环境缺失、未执行、缺少测试、真实失败和授权待定分别说明。没有执行的项放在缺口中，不写成跳过后通过；不因单个失败阻断无依赖的安全检查。

## 4. 交付与可选报告

报告当前检查对象、实际选择、命令与环境、通过/失败、复用来源、具体未覆盖项和必要用户决定。仅对已有且仍为 `active` 的正式任务，按[报告登记](references/record-report.md)核对合法写入入口与当前摘要，登记已完成的实际验证；开发临时反馈不写正式报告。没有正式任务时直接交付真实结果，不补造记录。

报告仍使用 `buildr.task-verification-report/v1` 和 `task verification inspect|record`，保留既有内容身份、项目地图身份及摘要冲突保护，不因技能更名改变应用协议。每次记录提交该时点完整相关检查集合；失败与缺口如实保留，不以报告保存成功代替业务验收、任务完成、推送或发布。
