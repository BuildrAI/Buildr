# 任务登记与按需代码更新

创建或激活任务前，确认目标工作空间（Workspace）、用户目标、项目（Project）或服务（Service）范围及写入授权；已有匹配任务先读取，不重复创建。激活已有任务使用刚读取的记录版本，冲突后重读并重新判断。

记录输入合法且任务记录提供者（Provider）可用时直接登记。无 Git、离线、未提交内容、进行中的 Git 操作、缺少上游或 Git 提供者不可用，不阻止合法登记；保持现有文件、分支和引用不变。记录目标、范围、授权或版本无法确认时，只停止对应记录写入。

后续修改代码前，核对真实仓库、内容归属和操作中的冲突；不能安全修改时保留现场，继续不依赖该动作的工作。登记成功只表示任务已记录或启动，不证明代码、环境、验证或交付已就绪。

仅当用户目标确实要求更新代码时，才读取 optional `buildr.git-operations/v1` 的绑定（Binding）、契约（Contract）和已选提供者（Provider）。明确仓库、引用、操作及授权后独立执行；更新失败保留实际结果，不撤销已成立的任务登记。工作空间（Workspace）更新遵循产品入口的适用同步与诊断约束，不把这些约束反向加到任务登记上。
