# 前端验证协作与证据

## 根据现场组合

1. 从项目（Project）的验收标准、关键流程、改动和 `verification.yml` 找到适用入口；核对入口实际覆盖、被测内容版本、运行依赖及清理责任。
2. 项目自动化依赖与智能体（Agent）现场工具分别核对。已有 Playwright 测试需要自身依赖和兼容浏览器；换用 Tabbit、egolite 或其他页面工具，不代表这些测试能原样执行。
3. 先核对当前作用域已选择的能力绑定（Capability Binding）。已绑定且可用的提供者（Provider）必须遵守；未绑定的现场动作按已暴露工具及其实际说明选择，不猜接口，不自动安装应用。需要替换绑定时交给已有能力适配机制，不绕过绑定。
4. 将待证明要求与真实能力对应：导航、点击、输入、视口调整、页面读取、几何测量、截图、控制台读取并不总是同时可用。只需读取和点击的检查不要求脚本执行；只有截图不能证明精确溢出或状态持久化。
5. 缺少能力只限制对应检查。例如可以完成表单提交和详情开关，但无法调整视口时，记录窄屏未执行；无法测量时，不把“看起来正常”写成无溢出的自动化证明。继续其他可执行检查。

外部工具（Tool）提供具体操作与观察；智能体（Agent）判断覆盖和失败归属。Buildr 保存声明与结果，不内置浏览器品牌、复制测试或转译工具接口，也不判断所有页面是否正确。工具同名或接口相似都不构成替代证明。

## 分别记录三类事实

报告沿用已有字段，无需新增报告协议：

- 自动化检查：`source: command`，`targets` 指明真实入口和场景；`summary` 写命令、依赖、尺寸、断言范围、结果及必要日志引用。
- 智能体（Agent）交互检查：`source: agent`，独立检查项中写工具、实际操作、可见结果和证据引用。
- 视觉审查（Visual Review）：`source: agent`，另设检查项，明确实际审阅的页面、尺寸、主题及截图引用。只生成截图但未查看，不算视觉审查；视觉判断不替代自动化断言。

`contentIdentity` 对应被测提交及未提交差异，必要时引用源文件摘要清单与构建产物摘要；不是工具名称、日志目录或登记时间。`gaps[].reason` 写具体未覆盖要求、缺少的能力、原因与影响。`summary` 可使用可移交的相对证据引用，说明访问与保留边界；完整日志、本机绝对路径、工具会话（Session）和临时执行状态不嵌入正式报告。证据包的实际本机位置在交付说明中提供，不发明不受支持的附件字段。登记成功只证明结果被保存。历史基线也失败可帮助归因，不能将当前失败改写为通过。

## 资产与清理

项目（Project）维护业务验收、适用声明和跨服务要求；服务（Service）维护自身稳定测试、数据、依赖、启动与清理入口。跨服务检查按真实组合责任归属，声明只引用入口与证明范围。

临时探索程序由本次执行者持有，可随任务结束清理；不要求把每次页面操作提交。反复使用、具有稳定价值的布局或交互检查交给 `project-testing` 沉淀到实际负责的服务（Service）。日志和截图由执行者保存到约定证据目录，报告引用实际位置、被测版本和保留范围；需要复核的证据先保留，临时工作空间（Workspace）、进程和测试数据由启动它们的入口在成功或失败后清理。长期测试代码、临时证据和验证报告各自独立，不将真实用户状态当测试数据。
