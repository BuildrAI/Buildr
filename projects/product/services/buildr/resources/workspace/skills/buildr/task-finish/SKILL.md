# 收尾与交付

日常表达中的“收尾”和“交付”都可以表示本轮工作完成后的结束动作。智能体（Agent）依据目标、现场与已有授权持续推进，直到成果到达约定位置、已有任务结果登记、可安全处理的资源已处理，并交代遗留事项。部署或发布只有明确属于目标且已获授权时才执行。

## 按实际对象组合

| 现场 | 应完成的工作 |
|---|---|
| 有 Buildr 任务，无 Git | 使用实际业务工具交付成果，登记已有任务结果，处理相关资源 |
| 无 Buildr 任务，有 Git | 按约定提交、集成、普通推送并回读，不补建任务 |
| 两者都有 | 完成 Git 交付、已有任务登记和相关资源善后 |
| 两者都没有 | 完成成果本身需要的交付，不制造记录或提交 |

先核对目标、实际仓库或业务对象、成果归属、交付位置和授权。已选择的能力提供者继续适用；有匹配任务时用 `task inspect` 读取当前结果与版本，目标完成后用 `task complete --expected-record <recordDigest>` 保存真实结果摘要，明确采用刚读到的记录版本，冲突后重读。记录完成不等于机器证明已交付。没有匹配任务就继续实际工作，不补建记录。

Git 写入前核对真实仓库、分支、远端、暂存及未跟踪内容和完整推送范围，只纳入本轮成果；按约定提交、集成与普通推送，回读实际目标。非 Git 成果检查实际业务结果，不能只看请求成功。复用已经成立的交付事实，多仓分别保留结果。

## 选择必要动作

下一动作应补齐尚未确认的事实、完成必要交付或恢复具体失败。已有事实足以支持当前判断时直接继续；对象、版本、覆盖范围、运行条件或授权变化时，只重新核对受影响部分。这是选择动作的方法，不要求额外生成计划或检查记录。

- 上下文中已读且仍适用的规则、技能和入口直接复用；缺失或更新时补读。任务版本及 Git 状态仍在写入前重验，已有观察不能代替当前写入所需的版本检查。
- 独立的只读核对合并或并行执行，集中提取所需状态、诊断和版本；写入、删除及依赖前一步结果的动作保持必要顺序。
- 已知路径和命令直接使用；未知入口先定位文件或查帮助，再读取相关部分。
- 大结果先提取状态、诊断和必要证据，缺口再展开。截断输出不作完整 JSON 解析，不因输出不全重跑有副作用的动作。

## 具体检查

- **写入前：** 对象、版本、归属、授权和实际影响范围明确。
- **写入后：** 回读交付位置及业务结果，不能把命令成功等同于目标完成。
- **删除前：** 核验资源归属、未保存内容和成果仍被保留。Preview、容器或其他资源交给创建者；Git成果已完整核验交付后，向`worktree cleanup`成对传递逐仓`--expected-source <selector>=<完整源提交>`与`--delivered-ref <selector>=<完整交付提交>`，由provider复核evidence、source版本、dirty和delivered提交仍由非任务retained ref持有，再删除工作树和本地任务分支。输入来自实际Git结果，不把completed或目标提交存在当作完整交付；清理拒绝时只处理具体差异，不重新交付已成立成果。
- **内容检查：** 先判断本次集成是否改变已有验证覆盖的内容或相关运行条件。没有改变就复用结果，不因收尾、重新生成提交或提交编号变化追加测试。冲突处理、其他集成修改或已知问题确实影响行为时，只选择覆盖实际影响的最小充分已有检查，并在推进目标分支前执行且通过，再集成推送。选择依据是风险与运行成本，不是测试条数；没有检查过就如实报告。

上述检查保护具体动作。收尾不建立统一验证记录、聚合流程状态或新的证明文件；不因一句收尾重跑全量测试、全局诊断或完整审查。已有审查和验证记录先核对适用性，确需更新时保留原始执行事实，只修订受变化影响的内容，不因阶段切换反复整理已成立的说明。需要修正成果时，在授权内完成修正及其相关检查，再交付受影响部分。

## 失败与完成

已知、必要、已获授权且安全的后续动作继续完成，不把可执行工作留作建议。必要成果未交付不能标记整个目标完成；清理或可选激活失败不撤销已交付成果。登记失败只修复或重试登记，不重推业务内容。

遇到明确的权限、功能或访问限制，记录具体原因并处理其他安全工作；输入、环境或方法没有变化时，不原样重试。短暂故障按原能力允许的方式有界恢复；结果不明确时先核对实际状态，避免重复副作用。改变方法仍须遵守原有授权与安全边界。

保留未知归属、未交付内容、共享缓存、凭证和业务数据。普通收尾不授权强推、丢弃内容、覆盖他人工作、改写共享历史、删除远端分支或替用户选择语义冲突。只有需要扩大授权或业务取舍时提出最小问题。

成果已到达约定位置、已有任务结果已登记，且相关资源已安全处理或有明确保留原因时，结束收尾并简述这些结果。非关键遗留如实说明，不据此扩展检查；仍能安全完成的必要动作继续执行。适用的部署、发布、自举由原专业能力独立承担并分别报告结果；普通工作空间不触发 Buildr 自举。

父任务完成遵守 `task-manager` 的明确授权与总体验收边界。子任务收尾不授权完成父任务；整体目标已核对但尚无明确授权时，报告验收结果并保持父任务状态，不补造授权。
