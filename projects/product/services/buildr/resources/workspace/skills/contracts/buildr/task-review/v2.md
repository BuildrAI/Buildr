# 任务审查

## Purpose

对正式 Task 的实际方案或完成结果做一次完整语义审查，并在需要长期留证时保存 Planning 或 Completion current Result。

## Consumer Obligations

consumer 必须提供正式 Task ID、`planning|completion` 类型和本次真实审查对象的稳定 `subjectIdentity`。Agent 必须重新读取 Task Intent、当前代码、文件、Git、外部系统或专业工具可观察的真实对象，自行选择与目标相关的审阅范围。`self|independent-agent|human` 必须反映真实执行方式；同一 Agent 复读仍是 `self`。

Task Review 是可选证据，不是 Task Verification、任务收尾或 Parent 管理的前置条件。consumer 不得建立统一门禁、waiver 或许可层，也不得把 Review 结论改写成其他模块的事实。

## Minimum Guarantees

provider 必须记录至少一个实际 `reviewed` 对象、相关但未覆盖的对象及原因、findings 和 `accepted|changes-requested` 结论。完整结论形成后，只能通过 Task Review Application 的 `record` 写入对应 `planning|completion` current slot。

Application 独占 closed schema、系统时间、序列化、摘要和 SQLite 事务。写入必须携带最近一次 `inspect` 返回的 `resultDigest`，槽位不存在时携带 `absent`；Application 必须在同一写事务中比较当前摘要，不一致时拒绝覆盖。审查中断、对象不明或结论不完整时不得写占位结果。

## Effects and Authorization

`inspect` 零写入，只返回两个已保存槽位；它不判断 Result 对当前现场是否仍适用。`record` 只替换同一 Task、同一 reviewType 的 current Result，不改写另一个槽位、Task Record、Verification、Environment、交付或 Git。terminal Task 不接受新 Result。

## Result Evidence

Result 只保存 `taskId`、`reviewType`、`subjectIdentity`、`method`、`reviewed`、`uncovered`、`findings`、`conclusion` 与 `completedAt`。响应额外返回 current slot 的 `resultDigest` 和观察时间。Result 不保存 revision、history、applicability、reviewer、session、统一门禁、运行日志或可重新观察的现场事实。

## Decision Points

Task 不存在、审查对象 identity 缺失、已有 Result 损坏、terminal Task、审查未完成或并发摘要冲突时停止写入并报告具体原因。对象是否仍代表当前方案或完成结果，由 Agent 在使用时重新观察和判断，不由 Application 推导。

## Allowed Variations

provider 可以按 Task 风险和对象形态选择工具、阅读顺序与表述，也可以由 self、独立 Agent 或 human 执行；不得拆成类型专属能力，不得强制所有 Task 审阅 OpenSpec、固定代码目录或固定测试清单，不得扩展为通用审查流程、finding 生命周期或历史库。
