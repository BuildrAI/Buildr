# 任务验证

## Purpose

维护 Project 测试地图，并为开发完成的正式 Task 保存一份绑定内容版本的有意义验证报告。智能体选择并直接调用项目已有测试工具；Application 不生成计划、不执行测试、不判断任务完成。

## Consumer Obligations

Project 测试地图候选必须来自真实前后端测试代码、构建脚本、测试目录、CI、说明和已确认团队边界。Task 报告必须由智能体完成实际验证后提交，包含当前内容版本、实际检查、选择范围、具体目标、来源、结果、未覆盖项和完整结论，并使用最近一次inspect返回的`absent|reportDigest`作为写入参数。开发过程中的临时反馈不得写入正式报告；冲突后必须重新读取真实报告与当前内容再判断，不自动重试。

## Minimum Guarantees

- `buildr.project-verification/v4` 只声明稳定测试体系、发现范围、完整入口、选择指导和环境要求，不列举每个测试文件或保存一次性计划。
- Project Verification Application 独占 `inspect|validate|update`，校验 Project/Service scope、安全路径、schema 与 expected identity；不理解测试语义或生成声明。
- Task Verification Application 独占 `record|inspect` 和唯一 Workspace SQLite current报告；Repository在同一`BEGIN IMMEDIATE`事务中读取current、比较调用方摘要、原子替换、写后回读并提交，冲突或失败保留旧值。调用方摘要不进入报告。
- `buildr.task-verification-report/v1` 绑定Task、内容版本和当前Project测试地图identities，保存实际checks、gaps、`passed|not-passed|incomplete`结论与系统时间；Application校验check属于Task scope并由可用地图声明。
- Project测试地图缺失或损坏时，Task报告仍保存真实check，并派生`map-unavailable`和地图gap；不得伪装成已声明testing family。
- 读取时只按调用方提供的内容版本和当前测试地图派生`current|stale|unknown`；未提供current内容identity时内容为unknown，派生值不持久化。
- Application不创建或执行Maven、npm、Playwright、Browser、HTTP或其他项目测试，不创建Verification Plan、Run、Candidate、Execution Record、风险授权或Task状态。

## Effects and Authorization

Project map update只修改目标Project的`verification.yml`，必须提供当前identity。Task record只替换同一Task的验证报告。外部环境和有副作用测试的授权由智能体在调用对应工具时取得，不由报告写入补造。

## Result Evidence

Project操作返回文件、identity、规范化声明、错误与实际effects。Task操作返回current slot、report digest、内容/声明适用性、诊断与effects；冲突诊断包含最新current report digest。完整日志、本机路径、临时执行状态和工具session不进入报告。

## Decision Points

测试体系或外部环境边界不明确、Project地图维护候选无效、expected identity/report digest冲突、Task非active、check超出Task scope、check与可用地图不一致、报告没有实际check/gap、内容版本缺失或三态结论与checks/gaps矛盾时停止对应写入。Project地图缺失或损坏只在Task报告中形成gap，不阻止保存真实测试事实；局部测试不可用不阻止无关开发和其他测试。

## Allowed Variations

项目可以使用任意后端、前端、Browser、HTTP、CI或环境工具；Skill根据现场调整测试选择。稳定项目工具可以有自己的affected选择器或DAG，但不进入Buildr通用Application或报告schema。
