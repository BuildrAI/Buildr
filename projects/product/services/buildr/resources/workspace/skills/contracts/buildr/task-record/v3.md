# 任务记录

## Purpose

在canonical Workspace SQLite维护Task的最小顶层事实：目标、范围、Parent/Child、`todo|active|completed|abandoned`、结果、结果更正历史，以及可空的本机复盘文档摘要和人的决定状态。

## Consumer Obligations

consumer必须提供明确operation、canonical Workspace、稳定Task ID及动作字段。更新只提交实际变化字段；状态、终态事实或复盘文档事实更新提供已观察`recordDigest`。复盘文档只使用`.buildr/local/task-retrospectives/<task-id>.md`；Agent先取得用户生成授权并写文件，再提交实际摘要。只有用户明确决定是否继续行动后才能标记`decided`。

创建active Task或激活todo前的语义分流、Git基线和后续专业动作由consumer负责。Parent/Child只用于可独立说明目标、范围及真实结果的协调层级；临时Agent分工不创建Child。复盘建议需要行动时使用普通Task，不提交专用来源关系、行动项或报告副本。

## Minimum Guarantees

provider必须通过Task Record Application管理closed `buildr.task-record/v3`。记录只保存可空`retrospective: { state: pending-decision|decided, documentDigest }`，不保存复盘正文或路径；路径由Task ID固定派生。登记必须校验终态Task、固定文件、普通文件、非符号链接、非空、安全体积和实际摘要；标记`decided`必须匹配当前Task与已登记文档版本；清除登记不得删除文件。

provider必须事务化校验新增Task scope/Change、Parent、自引用、重复关系、完成条件和recordDigest。Task Record自身结构有效时，inspect/query必须返回完整记录；Project、Service或Change当前不可用只形成响应级局部诊断，不写回记录，也不阻止删除失效引用或修改无关字段。文件与SQLite采用“文件先写、记录后登记”的可恢复顺序；详情读取必须报告引用、文档缺失或摘要漂移，但不得自动修改状态。

## Effects and Authorization

create/update/activate/complete/abandon只写Task-owned SQLite rows；inspect/query和本机文档读取零写入。复盘登记、决定或清除只修改指定Task的复盘字段，不改Task结果、其他专业记录或Markdown正文。Buildr Web是同一Application的有限客户端，不创建Task、不生成或编辑复盘文档，也不因打开文档自动标记决定。

## Result Evidence

结果必须返回operation、Task ID、closed v3 record、recordDigest、Parent/Child摘要、引用局部诊断、复盘文档固定路径/登记摘要/状态、effects、diagnostic和nextActions。单Task文档读取另外返回存在性、实际摘要、登记摘要、有效状态、正文和局部诊断；Task列表不读取正文或扫描文件系统。

## Decision Points

target/identity/授权不明、provider不ready、非法状态转换、Task或文档摘要漂移、非终态Task登记复盘、固定文件缺失/非法、关系冲突或数据库不安全时必须blocked并保持原记录。不得回退为旧Retrospective Application、YAML、直接SQL或自动激活。

## Allowed Variations

provider可以调整读取顺序、CLI展示和查询实现；不得改变SQLite单一Task authority、固定本机文档位置、两态决定语义、明确版本保护、无正文持久化、无专用后续关系和非门禁保证。

## 父任务完成扩展

任务记录可保存显式`isParent`，建立子关系后身份保留。父任务完成必须接收当前任务摘要、父子观察身份及`parentCompletion`：总体验收、精确覆盖直接子任务的处置、明确用户授权来源与原意。应用在同一写事务内重验关系和结果；未结束子任务、陈旧输入、缺少授权或验收时保持状态不变。完成依据及记录时间只进入既有结果，不形成审批队列。普通任务维持原有输入；历史完成不补造授权。
