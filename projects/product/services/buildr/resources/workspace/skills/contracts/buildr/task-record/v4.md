# 任务记录

## Purpose

在主工作空间（Canonical Workspace）的 SQLite 维护任务（Task）的目标、独立任务说明（Task Brief）、范围、父子关系、`todo|active|completed|abandoned`、结果与更正历史，以及可空的本机复盘文档摘要和人的决定状态。

## Consumer Obligations

调用方（Consumer）必须提供明确动作、主工作空间、稳定任务标识及实际变化字段。所有非创建写入提供已观察的 `recordDigest`；冲突后重读判断，不静默覆盖。`intent` 是一句话目标，`brief: string | null` 是每个任务独立的 Markdown 正文；空值表示尚未填写。正文至少说明真实问题、目标、必要范围与完成依据，不能用短目标、聊天或变更说明代替。

创建进行中任务或激活待办前，调用方负责确认目标、范围、授权及适用记录版本；Git 和专业动作按真实目标独立选择。父子关系只用于可独立说明目标、范围与真实结果的协调，临时智能体（Agent）分工不创建子任务。

旧说明导入必须明确授权并提供已观察记录、唯一旧 `brief` 关联与实际正文版本，或明确选择逐项观察的批次；不得扫描同名文件或选择主变更。复盘文档只使用 `.buildr/local/task-retrospectives/<task-id>.md`；先取得用户生成授权并写文件，再提交实际摘要，只有用户明确决定后才能标记 `decided`。

## Minimum Guarantees

提供者（Provider）必须通过任务记录应用（Task Record Application）管理闭合的 `buildr.task-record/v4`。`brief` 保存真实 Markdown，保留原始格式与内容，按 1 MiB UTF-8 字节上限校验；空正文统一为空值。正文随任务数据库保存，不随代码分支变化，不建立文件与记录双写。正文变化进入记录版本、终态更正历史与适用的父任务验收观察；方案、实施、交付引用及专业结果保持独立，不成为统一就绪门禁。

提供者必须在同一事务（Transaction）校验新增范围、变更引用、父关系、自引用、重复关系、完成条件和记录版本。记录自身结构有效时，单任务读取必须返回完整记录；项目、服务或变更当前不可用只形成响应级局部诊断，不写回记录，也不阻止修改无关字段或删除失效引用。列表不得读取或返回说明正文，但同一任务的列表与详情记录摘要必须一致。普通读取零写入，不导入旧说明或生成占位正文。

显式导入必须核对记录、关联及实际正文，保留原文件和其他材料，释放已迁移的旧说明关联。已有记录正文不得被覆盖；明确请求可只释放退休说明关联并保留当前正文。普通过程材料更新必须保留尚未释放的旧说明关联，不能隐式丢失迁移来源。来源缺失、安全失败、漂移或部分完成分别报告，重试不得覆盖导入后已编辑的正文。可证明的文档链接转换为明确引用，未知引用报告诊断，不能扩大读取范围。终态导入只记录本次真实更正，保留原状态、结果与历史，不补造旧时间。

记录只保存可空 `retrospective: { state: pending-decision|decided, documentDigest }`，不保存复盘正文或路径；路径由任务标识派生。登记必须校验终态任务、固定文件、普通文件、非符号链接、非空、安全体积和实际摘要；决定必须匹配当前记录与文档版本；清除登记不得删除文件。

## Effects and Authorization

创建、更新、激活、完成和放弃只写指定任务的 SQLite 事实；单任务和列表读取零写入。显式旧说明导入只写记录正文及释放对应旧材料关联，不删除源文件，不改变其他专业结果。复盘登记、决定或清除只修改指定任务的复盘字段，不改正文、结果或其他专业记录。Buildr Web 是同一应用的有限客户端，可编辑现有任务说明，不创建任务、不编辑复盘文档，也不因打开文档自动标记决定。

## Result Evidence

结果必须返回动作、任务标识、v4 记录或不含正文的列表投影、`recordDigest`、父子摘要、引用局部诊断、复盘文档登记事实、实际效果、诊断与下一动作。单任务详情返回当前 `brief`；列表不读取正文或扫描文件系统。旧说明导入分别返回记录写入与关联释放的实际结果及局部诊断；文件存在、正文导入、任务完成和 Git 交付不得互相替代。

## Decision Points

对象、身份或授权不明、提供者不可用、非法状态转换、版本漂移、关系冲突、数据库不安全或复盘文档非法时，只停止受影响写入并保留现场。旧说明缺失、正文尚空或专业报告缺失不得阻止无关合法记录动作；不能回退为 YAML、直接 SQL、旧复盘应用或自动激活。

## Allowed Variations

提供者可调整读取顺序、命令行展示与查询实现；不得改变 SQLite 的唯一任务正文权威、原始 Markdown 保存、正文体积与版本保护、轻量列表、显式导入及原文件保全、固定复盘位置、两态决定语义、无复盘正文持久化、无专用后续关系和非门禁保证。新材料清单不得重新建立 `brief` 文件关联。

## 父任务完成扩展

任务记录可保存显式 `isParent`，建立子关系后身份保留。父任务完成必须接收当前任务摘要、父子观察身份及 `parentCompletion`：总体验收、精确覆盖直接子任务的处置、明确用户授权来源与原意。应用在同一事务内重验关系、正文版本和结果；未结束子任务、陈旧输入、缺少授权或验收时保持状态不变。完成依据及记录时间只进入既有结果，不形成审批队列。普通任务维持原有输入；历史完成不补造授权。
