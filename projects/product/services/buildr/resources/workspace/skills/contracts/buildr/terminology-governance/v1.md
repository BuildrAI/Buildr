# 术语治理

## Purpose

在 Project 与 Service 范围内发现、核对和维护 canonical terminology，使人和 Agent 使用相同概念边界，同时避免把可由现有资产确认的问题反复交给用户。

## Consumer Obligations

consumer 必须提供当前 Workspace/Project context、任务或 Change identity、待核对的术语或受影响资产，以及本次是否授权修改长期 knowledge。consumer 必须把 glossary 作为解释性当前知识，不得用术语结果覆盖 canonical specs、实现或 registry facts。

## Minimum Guarantees

provider 必须解析 Project canonical glossary 及适用的 Service 局部术语，核对已有定义、同义词、一词多义、中英文不一致、新概念和作用域冲突；必须先调查 specs、实现、registries、knowledge 与已确认 Change artifacts 中可确定的事实，只对会改变长期语义、作用域、所有权或责任边界的决策询问用户。未确认术语不得写入 canonical 资产，Service 不得静默重定义 Project term。

## Effects and Authorization

读取与返回诊断无需额外授权。只有 consumer 已明确允许维护当前任务范围内的 Project/Service knowledge，且定义已由权威资产或用户决策确认时，provider 才能创建或更新 glossary/Service 术语小节。provider 不得创建 Task 专属 glossary，不得修改 archived Change，也不得把任务中偶然出现的词自动提升为长期术语。

## Result Evidence

provider 必须返回 `status: aligned|updated|unresolved|not-applicable`、`termsConsulted`、`canonicalTerms`、`changedAssets`、`unresolvedConflicts` 与 `sourceIdentities`。发生写入时必须精确列出路径；发生冲突时必须给出作用域、候选定义、权威来源与需要决定的问题。

## Decision Points

当候选定义会改变领域模型、持久数据语义、公开产品模型、跨 Service 所有权或团队责任边界，或权威来源彼此冲突时，provider 必须返回 `unresolved` 并停止 canonical 写入。难以逆转的决定应建议进入 OpenSpec design 或 ADR，但不得强制固定记录工具。

## Allowed Variations

provider 可以使用文件检索、数据库/API 查询、语义检索、MCP 或其他已授权来源，也可以采用不同 glossary 排版和访谈方式；不得降低先调查后追问、作用域显式、只写确认事实和结构化 evidence 的最低保证。
