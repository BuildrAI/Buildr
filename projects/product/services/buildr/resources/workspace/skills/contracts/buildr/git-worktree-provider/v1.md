# Git Worktree Provider

## Purpose

为明确的 Task 和 repository selectors 创建、检查或清理 Git worktree，并返回窄 Git provider evidence。

## Consumer Obligations

调用方（Consumer）须按当前有效能力绑定（Capability Binding）选择满足本契约的提供者（Provider），并在创建、检查与清理时核对同一任务及资源身份。宿主原生工具可用不等于满足本契约，不得自动替换已选实现或放宽目录与删除安全保证。绑定变化不自动转移既有资源归属；新实现必须核验原有登记与证据；只有证据缺失时，可以通过显式当前对象独立核验身份，不能补造创建历史冒充兼容。

consumer创建时必须提供canonical Workspace、Task ID、分支、start point和明确repository selectors。清理时consumer必须先核验实际交付，再用完整提交编号成对提供全部受管仓库的`cleanupDelivery.expectedSources`与`cleanupDelivery.deliveredRefs`；该输入只供当次删除，不是证明库。没有已核验交付输入的既有内部调用可使用真实祖先关系；当前公共命令不接受旧Task Contribution或Environment证明。consumer不能要求provider判断Task完成、Runtime、依赖、Preview、业务等价或总cleanup。

## Minimum Guarantees

provider新建时必须在`<workspace>/.worktrees/<task-id>`及canonical nested source paths操作；已有位置可由显式当前对象指定，写入前检查Git common directory、remote、branch ownership、target occupancy和既有evidence。它只维护Git common-dir下`buildr/task-worktrees/<task-id>.json`中的repository identity/effects；该文件不是Task状态、Environment Receipt或交付证明。

检查和清理接受可选 `observedCheckouts` 数组，每项精确包含 `selector`、`sourceRepository`、`checkoutPath`、`branch`。调用方先确认任务范围、占用和需保留内容；提供者（Provider）核对当前来源声明、绝对路径、Git 公共目录（Common Directory）、精确工作树（Worktree）登记和完整嵌套集合。已有登记优先且不可由观察输入绕过；缺失时只形成当前观察，不写入历史证据。观察清理必须提供完整源与交付提交（Commit），不得绕过未保存内容保护。

## Effects and Authorization

provider 可以创建或删除已证明属于该Task的本地checkout和本地分支。已核验交付输入下，provider必须核对源提交和工作树状态未变化、交付提交仍由保留分支持有，并条件删除本地任务分支；不再检查原提交祖先或补丁等价，不得把caller核验标成软件证明。部分失败必须保留现场并返回blocked。删除远端分支、修改原Task worktree/index/branch、force push、以路径不重叠推断语义安全或清理非Git资源不属于本contract。

## Result Evidence

返回operation、Task ID、workspace、evidence path、repository selectors、source/checkout path、branch、start point、HEAD、clean/registered/remote state、effects和diagnostic。检查与成功清理以 `evidenceSource: stored|observed` 区分依据；本次观察不推断历史起点，`startPoint` 为 `null`。不得返回统一ready、runtime projection、依赖、session adoption、Preview或业务结果。

## Decision Points

宿主要求与本契约无法同时满足，或已选实现不能核验既有资源身份时，只停止受影响动作并报告具体不兼容；保留现场，不自动迁移、另建同任务副本或混用清理入口，已成立的交付事实保持不变。

路径、remote、branch、registered worktree、source snapshot、baseline/carrier/target ref或Task Contribution identity冲突，任一未获等价证明的checkout dirty，或integrated identity无法证明时必须停止且不扩大清理范围。

没有历史登记且没有明确当前对象时必须返回具体诊断，不能返回 `cleaned`。部分删除后允许对同一显式对象重验并继续；只有实际删除或逐项确认全部对象不存在后才可报告 `cleaned`，效果区分本次删除与不存在确认。锁定、其他检出位置占用及未知嵌套代码库（Repository）必须阻止相关删除。

## Allowed Variations

Agent、Task Finish、OpenSpec/Change reader或过渡Environment可以组合此provider；全部入口必须产生同一Git evidence与删除安全语义。
