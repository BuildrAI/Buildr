# Git Worktree Provider

## Purpose

为明确的 Task 和 repository selectors 创建、检查或清理 Git worktree，并返回窄 Git provider evidence。

## Consumer Obligations

consumer 必须提供 canonical Workspace、Task ID、分支、start point 和明确 repository selectors。已完成任务的consumer可提供`cleanupDelivery.expectedSources`与`cleanupDelivery.deliveredRefs`，用完整提交编号成对覆盖全部受管仓库，并负责先核验实际交付。该输入只供当次清理，不是证明库；正常旧Finish cleanup还必须提供每个scope的delivery ref；原Task branch不是delivery ancestor时，Environment可以提供source snapshot、原任务基线、交付基线（Delivery Baseline）、carrier/target ref与任务贡献（Task Contribution）identity。consumer 必须自行拥有上层环境或 Git 操作授权，不能要求 provider 判断 Task ready、Runtime、依赖、动态资源、Agent session、语义安全或总 cleanup。

## Minimum Guarantees

provider 必须在 `<workspace>/.worktrees/<task-id>` 及 canonical nested source paths 操作，写入前检查 Git common directory、remote、branch ownership、target occupancy 和既有 evidence。它只维护 `.buildr/worktrees/<task-id>.json` 中的 repository identity/effects；该文件不是 Environment Receipt，也不能与 Environment authority 竞争。

## Effects and Authorization

provider 可以创建或删除已证明属于该Task的本地checkout和本地分支。对显式使用旧贡献证明的isolated carrier交付，它必须从当前Task source与Git objects独立复算原/应用后raw delta identities，只有source未漂移、target等于carrier且identity完全等价时，才可把Task-owned dirty checkout视为已集成并清理。已核验交付输入下，provider必须核对源提交和工作树状态未变化、交付提交仍由保留分支持有，并条件删除本地任务分支；不再检查原提交祖先或补丁等价，不得把caller核验标成软件证明。部分失败必须保留现场并返回blocked。删除远端分支、修改原Task worktree/index/branch、force push、以路径不重叠推断语义安全或清理非Git资源不属于本contract。

## Result Evidence

返回 operation、Task ID、workspace、evidence path、repository selectors、source/checkout path、branch、start point、HEAD、clean/registered/remote state、effects 和 diagnostic。不得返回环境 ready、runtime projection、依赖、session adoption 或动态资源结论。

## Decision Points

路径、remote、branch、registered worktree、source snapshot、baseline/carrier/target ref或Task Contribution identity冲突，任一未获等价证明的checkout dirty，或integrated identity无法证明时必须停止且不扩大清理范围。

## Allowed Variations

上层 Environment 可以组合此 provider，也允许用户显式调用窄 worktree CLI；两种入口必须产生同一 Git evidence 语义。
