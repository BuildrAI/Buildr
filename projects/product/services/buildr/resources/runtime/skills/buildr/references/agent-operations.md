# 本机智能体接入与调用

内部对话、一次生成和外部原生会话（Session）关联是独立入口，先按用户目标选择。新对话采用 Buildr 独立配置，不接管用户已经使用的桌面聊天；原有 `buildr agent` 登记与默认选择不用于新内部对话。

## 内部对话与持续执行

独立账号目录用于隔离登录，不代表本机工具缺失。需要额外工具时，结合 `PATH`、项目依赖及 `BUILDR_HOST_HOME` 指向的原用户目录检查已有安装；浏览器缓存使用实际 `PLAYWRIGHT_BROWSERS_PATH`，保留用户明确覆盖，未设置时指向原用户的官方默认缓存。缺少工具时，由智能体（Agent）根据当前任务选择相应技能（Skill）或官方说明准备并验证，不复制桌面凭据。

用户想在 Buildr 内使用 Codex、DSH 或 Qoder 时，从全局对话打开“账号与模型”，在账号卡片登录；本机程序缺失时由同一入口准备，低频的程序检查位于卡片“更多”菜单。发现多个程序时选择准确来源；缺少程序时按页面官方入口安装后重新检查，或显式准备独立程序。Codex 可复用经核验的 ChatGPT App 内程序或独立 CLI；DSH 使用独立 CLI，Qoder 由 Buildr 管理配套 SDK 与执行程序。通过官方登录建立独立账号，再核对实际账号及非空模型目录；不把程序安装成功或打开登录页当作接入可用。需要用户本人登录时，只交接当前尝试的官方页面；不要提取桌面令牌（Token）、复制默认账号文件或把秘密写入任务、消息、日志及 Git。当前没有新的 `buildr agent-conversations` 命令，不猜造命令或把原有 `buildr agent register` 当作该入口。

- Codex 使用独立 `codex app-server` 应用服务（App Server）；DSH 使用独立 `dsh web --no-open --port 0` 完整本机网页宿主（Web Host）及官方客户端（Client）；Qoder 使用官方软件开发工具包（SDK）与 `qodercli`。不要求外部桌面应用保持运行，也不等于提供桌面版全部功能。
- 每家一套本机独立配置，可供多个工作空间（Workspace）使用。配置和统一交互库属于 Buildr 本机运行配置（Profile）的私有数据，不是组织源资产；不自动复制桌面插件、用户级规则（Rule）、技能（Skill）、工具连接或任意第三方模型凭据。缺程序时发现并核对真实安装及兼容版本，不静默下载程序或改绑用户默认配置。
- 准备进度可查询、可取消；切换厂家和关闭面板不取消后台准备，重启后重新观察安装和账号。版本准入按主版本：Codex、DSH 为 `0.x.x`，Qoder CLI 为 `1.x.x`，包含有效预发布版本与构建标记。符合范围只允许继续实际协议、账号和模型检查，不单独代表接入可用；固定下载版本不等于唯一兼容版本；同来源兼容更新保留账号和原生上下文，仍检查实际协议。原程序缺失或版本不兼容时保留账号与历史，不通过切换程序、配置或会话编号冒充恢复。浏览器工具由智能体（Agent）按已有技能（Skill）检查、准备并真实验证；本机浏览器品牌或安装成功都不等于已具备浏览器操作能力。
- 普通对话先确认工作空间（Workspace）及真实起始目录（Working Directory）；任务页“打开对话”创建或打开关联该任务（Task）的内部对话。起始目录是原生规则（Rule）、技能（Skill）发现的起点，不是跨目录访问的禁止边界；实际访问仍按原生权限和用户授权。任务关联不自动把任务全文、当前页面或其他工作空间资料注入模型。
- 发送前核对接入、模型、起始目录及“查看发送内容”。流式回答、工具观察、待答问题、授权与停止在同一对话处理；授权只对应准确本轮请求。不要因历史中有人同意过，就重放原工具或复用旧许可。
- 权限选择位于当前对话输入区，新对话默认为“默认权限”；用户明确选择“完全访问”后，后续执行按各家原生免逐次工具审批模式工作，同一对话换家时分别应用，不改变外部桌面配置或旧一次生成。业务问题仍需用户回答，未知交互不能自动批准；改回默认时必须逐轮重新应用，不继承上次完全访问。发送预览与实际本轮模式分别核对，不能只凭界面选择推断原生已经生效。
- 同一段对话可以依次使用多个智能体（Agent），历史不按厂商分类。首次换一家创建它自己的原生上下文；换回时恢复它原来的上下文，补交它未见的可见历史。隐藏推理、工具内部状态和权限不会迁移；接续信息过大或图片能力不兼容时，继续原参与者或由用户明确提供精简说明后重新预览，不静默截断历史。
- 重新打开、刷新或服务（Service）重启不重发指令。遇到“待确认”（`unknown`）先观察原执行；“模型已中断，仍有命令运行”需要按准确命令继续停止。已发送、已受理、已结束和已确认停止分别判断；断开账号或关闭面板不等于执行已经停止。
- DSH 对话选择模型会更新这套独立配置的后续默认模型；外部桌面配置不受此独立配置改动。检查可用不等于某次真实模型执行成功，图片也只按对应执行器（Executor）实际开放的能力使用。

内部对话只保存交流和执行观察；代码、文档、任务状态与业务数据仍以各自当前对象为准。继续工作前重读实际成果。后续图形界面（GUI）与对话界面（Talk UI）接入业务动作时，仍须交接明确对象身份和已观察版本，由原能力保护写入；首版没有自动捕获所有页面现场或通用图形操作能力。

### 统一模型与额度设置

在“账号与模型”中，已登录账号直接显示真实额度窗口，未登录或过期在同一卡片登录；Codex、DSH、Qoder 复用本应用原生登录，Devin 使用明确发起的独立登录。未知额度不能当作零余额，旧观察不能冒充本次读取。模型页只把已启用项目加入新选择；刷新保留开关，新发现模型默认停用，组合预设单独管理。

上下文数字是本地执行偏好，不扩大上游容量；可恢复平台默认，已知上限时不得设置更大数字。Devin 按真实支持配置提供思考和速度档位，不推导笛卡尔积；未知档位保留语义，不伪装有序深度。设置改变用于新的执行上下文，现有对话历史保留，不能静默重发指令。通过已发现的 HTTP 操作管理偏好时，先读取准确账号和模型身份，再携带当前 `expectedRevision` 调用 `/api/v1/app/agent-service/model-accounts/:accountId/preferences`；冲突后重新读取，不覆盖其他入口，也不直接修改私有账号文件。

## 原有的一次生成与外部会话关联

用户要求“把本机 Codex 或 DSH 接入 Buildr”用于原有生成或外部会话关联时，由当前智能体（Agent）发现真实本机入口并调用登记能力。这里的执行适配器（Adapter）负责调用协议，与 `runtime list` 展示的规则、技能文件投射适配器（Adapter）分别管理。以下命令及桌面依赖只属于这条原有链路，与内部对话的独立配置分开。

## 接入 Codex

优先使用 Buildr 接入页的“接入 → Codex”：在二级抽屉发现本机候选，确认后保存原聊天关联范围与独立生成来源。不安装 Buildr 插件（Plugin）或卡片，不启动工具服务，不要求桌面加载或重启。取消不保存登记或默认选择；未发现时明确说明并允许重新检测或取消。生成来源、关联配置与具体聊天关系分别核对；下面的路径登记命令继续兼容，仅登记生成来源。

一级条目和对齐的紧凑详情浮窗分别展示生成来源与原聊天关联配置。`configured` 只表示安装及配置范围已确认，不能说桌面在线、聊天已打开或生成成功。读取失败显示无法确认，不沿用旧成功；查看与刷新无登记或配置写入，不周期检查插件存活。

已有 Codex 时新接入禁用，接口也在登记锁内拒绝重复新接入。详情的“重新检查接入”只确认同一程序和配置来源，请求携带 `existingAgentId` 且 `makeDefault:false`；编号、默认项和其他接入保持，不安装扩展。错误目标或不匹配候选局部失败，不能转为新接入；结果不明先查询。全部登记均显示，DSH 不隐藏；隔离预览与日常数据目录分别核对，不能误判登记丢失。

1. 确认当前宿主确实为 Codex，并使用当前合法 Buildr 入口。先运行 `buildr help agent` 和 `buildr agent list --json`，取得当前登记版本；已有同一实际入口及配置身份时复用，不重复要求接入。
2. 从当前进程、宿主公开信息或本机命令发现 Codex 可执行入口，解析真实绝对路径并检查 `--version` 和 `app-server --help`。不能把桌面应用目录、其他安装、别名字符串或猜测路径登记为当前入口；未知时只说明确切缺口，不把诊断步骤转给普通用户。
3. 使用 `buildr agent register codex --executable <actual-absolute-entry> --expected-revision <observed-revision> --json`。当前使用显式 `CODEX_HOME` 时，同时传入已核对的 `--codex-home <actual-absolute-home>`；否则沿用 Codex 正常默认配置。只登记调用身份，不复制凭证、不替用户登录、不把进程编号当接入身份。
4. 核对返回记录的实际名称、身份与默认选择；首个接入自动成为默认。必要时按用户选择运行 `buildr agent select <agent-id> --expected-revision <observed-revision> --json`。版本冲突后重新读取判断，不覆盖别的入口的新选择。

登记不调用模型，也不连接或接管用户正在使用的 Codex 桌面会话（Session）。首次功能调用才启动 Buildr 专用应用服务（App Server），后续复用，完全空闲 30 分钟回收；退出 Buildr 清理自己启动的实例。关闭浏览器标签不等于退出 Buildr。

### 桌面原聊天与任务关联

使用 `buildr codex connections --json` 查看已确认关联范围。持续讨论、开发和记忆（Memory）留在原聊天，Buildr 不替换桌面后台。提交说明继续由独立服务执行，不使用内部共享服务开关，也不继承原聊天的记忆（Memory）或工具能力。

用户给出任务编号并要求关联时，由当前聊天直接读取 `CODEX_THREAD_ID`，调用 `buildr codex link --target <workspace> --task <code> --native-session-id <direct-thread-id> [--connection-id <id>] --json`。不要求网页创建请求或卡片确认；不能委派身份采集，不能用 `CODEX_SESSION_ID`、工具服务环境或子执行身份代替。从 Codex 原聊天新建任务后默认关联，用户明确不关联时遵从。没有准确身份或有效接入时保留任务并说明未关联。

一个任务可关联多个聊天，一个聊天可关联多个任务。重复关联幂等；解除校验关系版本，不改变任务正文或状态。使用 `buildr codex sessions --target <workspace> [--task <code>] [--native-session-id <id>] [--connection-id <id>] --json` 正反查询；结果不明先查询，不重建任务或发送消息。旧插件工具服务及卡片绑定/交接入口已退役，不能继续调用；旧数据保留。

Codex 协作任务链接采用 `/workspaces/<workspaceId>/codex#/tasks/<taskId>`，同一工作空间内保持基址稳定，以便宿主（Host）复用已有侧边页面。旧路径继续正确到达；历史任意路径、多页精确选择与跨窗口行为保留实际能力边界。不能以地址变化或 `queued` 认定任务到达，须核对页面身份和实际内容。

DSH 的原聊天关联和生成均直接使用已确认桌面后台，见下文。Codex 保持独立生成服务，不将某一提供者的进程划分当作通用要求。

### 移除 Codex 接入

Codex 条目提供“移除接入”，使用已观察登记版本调用 `POST /api/v1/app/agents/codex/remove`，请求仅包含 `agentId` 和 `expectedRevision`。DSH 在自己的条目通过 `/api/v1/app/agents/dsh/remove` 使用同一请求字段移除；两者均没有对应命令行入口。

存在排队、生成或关联配置检查时，移除局部失败并保留接入，先等待结束或取消已有生成。空闲时 Codex 先确认 Buildr 自有服务退出，DSH 只释放自有连接和请求，再校验登记版本并移除；清理未确认、版本冲突均保留登记，不启动替代实例。移除默认项只清空默认选择，不切换其他智能体（Agent）。结果不明先刷新登记核对，不自动重放请求。

移除接入不退出桌面，不删除聊天、记忆（Memory）、配置、其他扩展、任务（Task）或多对多关系。关联登记保留为 `disconnected`，缺少生成登记时不得新建关系；明确重新确认同范围可恢复稳定身份及保留关系。卸载退役的 Buildr 插件（Plugin）是独立动作，不能用移除接入代替；卸载后仍保留生成来源和原聊天关联。

## 接入 DSH

优先使用“接入 → DSH”：只读发现本机桌面、当前配置范围和现有 Buildr 插件（Plugin）连接，确认后保存同一桌面生成及原聊天关联来源。沿用现有插件，不另装新的桥接插件；桌面未运行、插件不兼容或身份不明时明确不可用，不启动替代后台。插件的安装或更新是独立动作，使用受支持管理入口及已核实包来源。

已有 DSH 从原条目“重新检查接入”，携带 `existingAgentId` 和已观察版本；只有真实入口、配置目录及已确认渠道完全匹配才原地迁移，保留编号、名称和默认项。取消不写入，范围不同不改绑，新接入不重复登记。登记成功不等于模型已经执行。

智能体（Agent）也可先读取 `buildr help agent` 与 `buildr agent list --json`，核对真实桌面安装和当前数据目录，再使用 `buildr agent register dsh --executable <actual-desktop-cli-entry> [--dsh-home <actual-home>] --expected-revision <observed-revision> --json`。此兼容命令会确认匹配的桌面连接并复用原登记，不再测试 ACP 或启动独立 DSH 服务；不把普通独立命令行安装冒充桌面。

DSH 生成直接由正在运行的桌面后台完成，每次读取当前默认模型（Model）及提供者（Provider），经原生准备调用确认。普通调用继承桌面推理级别（Reasoning Effort）；提交说明明确请求轻量生成，按同一模型（Model）的原生声明选择并确认最低受支持级别，仅本次生效，不改桌面聊天配置或复制凭据。生成不带会话编号、工具或自动项目上下文，不新增聊天或污染历史。取消仅中断本连接拥有的请求；空闲30分钟或 Buildr 退出只释放自己的连接，不退出 DSH 或取消其他聊天。桌面离线明确失败，不回退旧独立进程。

使用 `buildr dsh link --target <workspace> --task <code> --native-session-id <direct-DSH_SESSION_ID> [--connection-id <id>] --json` 关联当前工作；必须由本次原生 Bash 工具（Tool）直接采集准确身份，不能用桌面选中聊天或子执行代替。新任务默认关联，失败保留已创建任务。`buildr dsh sessions --target <workspace> [--task <code>] [--native-session-id <id>] --json` 查询多对多关系；`buildr dsh open-task <code> --target <workspace> --native-session-id <direct-id> [--connection-id <id>] --json` 按已有关联打开准确任务并复用侧栏。多个窗口无唯一目标时明确歧义，实际观察目标后才确认成功。统一任务面板按品牌查看和解除关系，DSH 打开准确原聊天，Codex 深链保持。

移除 DSH 前必须结束或取消本项未完成工作；移除只释放自有连接、删除登记并停用业务调用，保留聊天、配置、插件和长期关系。移除默认项只清空，不自动替选。重新确认同范围可恢复稳定连接编号；结果不明先查询，不重放写入。

## 说明生成与 Git 操作

源代码管理的统一图标生成当前已登记代码库（Repository）及具体工作树（Worktree）全部未提交变更的说明。Codex 每次使用临时会话（Ephemeral Session），DSH 每次使用不创建会话（Session）的独立调用，结果填回输入框，不新增持久生成对话。本次执行者在发起时固定；本次覆盖调用后复位，全局默认只影响新调用。

模型（Model）与提供者（Provider）沿用各自原生配置：Codex 按本次工作目录解析，DSH 沿用桌面当前默认模型（Model）、认证和路由。Codex 提交说明使用经服务端确认的低推理级别（Reasoning Effort），DSH 提交说明使用原生模型（Model）声明的最低受支持级别，不把所有模型（Model）统一设成 `low`；例如最低支持 `medium` 就使用 `medium`。只有本次生成采用该级别，不修改原生全局配置，普通调用仍继承桌面设置。运行（Run）记录及结果来源提示使用本次原生准备确认值，智能体（Agent）详情展示最近一次业务使用值；首次调用或字段未返回时明确尚未确认，不猜默认值，不把选定配置称为执行遥测，也不为展示启动模型（Model）请求。

DSH 轻量生成要求桌面插件（Plugin）明确声明支持该能力；旧插件（Plugin）缺少能力时提示更新，不静默使用高推理。通过原生接口读取准确模型（Model）声明后，只在全部级别语义可确认时选择最低值；声明不可读取、存在未知级别或原生准备未确认准确模型（Model）和所选级别时，局部失败并保留草稿。原生明确不支持可选推理级别（Reasoning Effort）时省略覆盖，使用原生默认；这与读取失败不同。

说明生成由 Buildr 准备有硬上限的必要材料：当前分支及全部未提交变更的准确范围统计、有限路径样本、少量真实差异（Diff）或新增内容片段、与提交有关的规范摘录，以及可靠关联任务的编码、标题和一句目标。完整业务提示词（Prompt）按UTF-8硬限制为16 KiB；超量时缩减样本和片段，明确展示/省略数量及证据、规范的局部范围，不将裁剪当作全部分析。真实工作位置仅作内部执行参数，不向模型重复发送目录与读取权限路径包。

智能体（Agent）只据给定材料一次撰写，不再自行读取或补查。执行时关闭原生命令、代码执行宿主（Code Mode Host）、外部工具（Tool）、自动项目文档和宿主技能注入；异常工具执行则局部失败并保留草稿，不回退读取或重放已接受请求。Codex 自带基准说明仍由其配置装配；DSH 提供者另加必要的 JSON 输出约束并确定性校验一次返回，不自动发起修复请求。16 KiB仅指Buildr业务输入，不能宣称是完整供应商上下文上限。

固定要求是遵循实际适用提交约定，默认采用 `type(scope): subject`，范围可省略，语言遵循所给规则。材料优先保留显式提交语言及通用输出语言条目，保留原文与作用域顺序；近期英文提交或格式示例不覆盖当前语言要求，产品不固定中文。说明有证据的实际目的或行为变化，正文只在需要解释动机、行为差异或破坏性影响时添加，不预设条数，不编造效果、测试结果或任务完成。大文本取有限片段，二进制使用准确元数据，不因未完整注入而直接拒绝。规范仅提供提交相关有界摘录，未纳入内容不能被猜测为已知。只有可靠核验了任务关联才包含对应 `Buildr-Task` 尾注（Trailer）。结果发布前校验源码、实际材料依据、规则入口和任务事实；变化时保留草稿并要求重新核对。

60秒总调用预算涵盖排队、准备、执行和结果校验，超时保留原说明；排队过期不会取消其他工作。10–30秒是日常响应目标，须以真实源码场景测量输入字节、工具次数、总耗时和结果质量；不再用6000词元（Token）软预算代表实际硬上限。

完整上下文的原 512 KiB 生成拒绝已移除，新的16 KiB业务输入预算通过裁剪材料满足。现有Git精确版本观察仍有1000路径、16 MiB当前文件总量边界；超过的是来源观察限制，不能宣称无限量生成。

生成、提交和推送是不同动作。生成不提交；用户可以手写说明，由 Buildr 直接操作 Git，不依赖智能体（Agent）可用。提交范围是当前来源全部最终文件变更，推送使用已核实上游及该分支全部未推送提交。无上游不猜目标；推送失败保留已完成提交，重试只推送。收到陈旧内容、来源或目标错误时重新观察，保留说明，不能静默重放。

完成接入应报告登记事实、默认选择及实际检查范围。登记成功不证明模型生成已通过；仅验证过临时生成、结果、取消或复用等真实调用后，才报告相应能力已验证。协议或授权失败只影响该功能，不要求用户重新初始化工作空间（Workspace）。

## 统一模型套餐与来源选择

Buildr 内部对话将智能体（Agent）与套餐模型独立选择。账号入口复用原生登录并自动发现模型，程序详情负责准备 Codex、Qoder、DSH；选用其他套餐时不应重复要求原厂模型账号登录。Qoder 自身必要的平台认证与模型套餐认证分别判断。

使用已授权的本机应用接口时，先发现 `agent-service` 的模型账号与目录操作，读取来源身份及观察版本，再选择准确账号和模型。不得通过复制默认桌面凭据、修改系统代理或运行完整智能体循环冒充模型来源；失败不自动换用另一付费账号。Devin 是模型套餐来源，所选 Codex、Qoder、DSH 仍负责工具执行与权限。

核验结果时分别说明程序就绪、账号登录、目录发现、真实模型工具闭环及实际套餐额度。没有真实账号或未执行调用时如实保留未验证项，不把替身测试或模型数量当作账号权益证明。模型目录的声明不代表所有模型均已真实调用，按实际验证范围报告。

已有Codex、DSH、Qoder登录会自动发现共享模型，无需另建套餐账号。模型来源中的`connectionId`表示其登录由对应原生账号维护；不要为它调用套餐登录或断开，应使用原生账号入口。Qoder模型通过真实模型协议供其他执行方消费，不由Qoder代执行工具。旧独立套餐按需从更多账号管理。
