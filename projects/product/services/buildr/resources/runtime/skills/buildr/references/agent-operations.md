# 本机智能体接入与调用

用户要求“把本机 Codex 或 DSH 接入 Buildr”时，由当前智能体（Agent）发现真实本机入口并调用登记能力。这里的执行适配器（Adapter）负责调用协议，与 `runtime list` 展示的规则、技能文件投射适配器（Adapter）分别管理。

## 接入 Codex

1. 确认当前宿主确实为 Codex，并使用当前合法 Buildr 入口。先运行 `buildr help agent` 和 `buildr agent list --json`，取得当前登记版本；已有同一实际入口及配置身份时复用，不重复要求接入。
2. 从当前进程、宿主公开信息或本机命令发现 Codex 可执行入口，解析真实绝对路径并检查 `--version` 和 `app-server --help`。不能把桌面应用目录、其他安装、别名字符串或猜测路径登记为当前入口；未知时只说明确切缺口，不把诊断步骤转给普通用户。
3. 使用 `buildr agent register codex --executable <actual-absolute-entry> --expected-revision <observed-revision> --json`。当前使用显式 `CODEX_HOME` 时，同时传入已核对的 `--codex-home <actual-absolute-home>`；否则沿用 Codex 正常默认配置。只登记调用身份，不复制凭证、不替用户登录、不把进程编号当接入身份。
4. 核对返回记录的实际名称、身份与默认选择；首个接入自动成为默认。必要时按用户选择运行 `buildr agent select <agent-id> --expected-revision <observed-revision> --json`。版本冲突后重新读取判断，不覆盖别的入口的新选择。

登记不调用模型，也不连接或接管用户正在使用的 Codex 桌面会话（Session）。首次功能调用才启动 Buildr 专用应用服务（App Server），后续复用，完全空闲 30 分钟回收；退出 Buildr 清理自己启动的实例。关闭浏览器标签不等于退出 Buildr。

## 接入 DSH

先读取 `buildr help agent` 和 `buildr agent list --json`，发现本机实际 DSH 命令行入口并核对版本及 ACP 能力；安装目录不在 PATH 时仍须验证真实可执行文件，不要求用户手填路径。使用 `buildr agent register dsh --executable <actual-absolute-entry> --expected-revision <observed-revision> --json`。只有实际使用了非默认 DSH 原生目录时才同时传 `--dsh-home <actual-absolute-home>`，相同入口及原生配置身份重复接入应复用登记。

Codex 使用应用服务（App Server），DSH 使用智能体客户端协议（ACP）。登记保存调用身份，不接管桌面对话；每个被使用的智能体（Agent）最多一个 Buildr 自有服务进程，串行执行并复用，空闲与退出回收规则相同。DSH 使用内存临时上下文，不把普通持久会话关闭等同于临时生成。

DSH 沿用桌面有效默认和必要提供者路由，认证仍由 DSH 原生读取；不复制凭据或修改原生全局配置。自定义提供者若配置了本机模型代理，该代理仍须可用；Buildr 不擅自启动会写入原生设置的桌面插件，也不静默改用其他模型。缺少路由、确认或必要能力时仅该次生成失败，Codex 与直接 Git 功能继续可用。

## 说明生成与 Git 操作

源代码管理的统一图标生成当前已登记代码库（Repository）及具体工作树（Worktree）全部未提交变更的说明。每次使用临时会话（Ephemeral Session），结果填回输入框，不新增持久生成对话。本次执行者在发起时固定；本次覆盖调用后复位，全局默认只影响新调用。

模型（Model）与提供者（Provider）沿用各自原生配置：Codex 按本次工作目录解析，DSH 桥接桌面有效默认及必要路由。提交说明使用经该提供者确认的低推理级别（Reasoning Effort），仅覆盖本次会话（Session），不修改原生全局配置。其他调用继续继承原配置，不增加设置界面。运行记录及结果来源提示使用本次会话（Session）确认值，智能体详情展示最近一次业务使用值；首次调用或字段未返回时明确尚未确认，不猜默认值，不把会话选定配置称为执行遥测，也不为展示启动模型请求。

说明生成由 Buildr 准备有硬上限的必要材料：当前分支及全部未提交变更的准确范围统计、有限路径样本、少量真实差异（Diff）或新增内容片段、与提交有关的规范摘录，以及可靠关联任务的编码、标题和一句目标。完整业务提示词（Prompt）按UTF-8硬限制为16 KiB；超量时缩减样本和片段，明确展示/省略数量及证据、规范的局部范围，不将裁剪当作全部分析。真实工作位置仅作内部执行参数，不向模型重复发送目录与读取权限路径包。

智能体（Agent）只据给定材料一次撰写，不再自行读取或补查。执行时关闭原生命令、代码执行宿主（Code Mode Host）、外部工具（Tool）、自动项目文档和宿主技能注入；异常工具执行则局部失败并保留草稿，不回退读取或重放已接受请求。Codex 自带基准说明仍由其配置装配；DSH 提供者另加必要的 JSON 输出约束并确定性校验一次返回，不自动发起修复请求。16 KiB仅指Buildr业务输入，不能宣称是完整供应商上下文上限。

固定要求是遵循实际适用提交约定，默认采用 `type(scope): subject`，范围可省略，语言遵循所给规则；说明有证据的实际目的或行为变化，正文只在需要解释动机、行为差异或破坏性影响时添加，不预设条数，不编造效果、测试结果或任务完成。大文本取有限片段，二进制使用准确元数据，不因未完整注入而直接拒绝。规范仅提供提交相关有界摘录，未纳入内容不能被猜测为已知。只有可靠核验了任务关联才包含对应 `Buildr-Task` 尾注（Trailer）。结果发布前校验源码、实际材料依据、规则入口和任务事实；变化时保留草稿并要求重新核对。

60秒总调用预算涵盖排队、准备、执行和结果校验，超时保留原说明；排队过期不会取消其他工作。10–30秒是日常响应目标，须以真实源码场景测量输入字节、工具次数、总耗时和结果质量；不再用6000词元（Token）软预算代表实际硬上限。

完整上下文的原 512 KiB 生成拒绝已移除，新的16 KiB业务输入预算通过裁剪材料满足。现有Git精确版本观察仍有1000路径、16 MiB当前文件总量边界；超过的是来源观察限制，不能宣称无限量生成。

生成、提交和推送是不同动作。生成不提交；用户可以手写说明，由 Buildr 直接操作 Git，不依赖智能体（Agent）可用。提交范围是当前来源全部最终文件变更，推送使用已核实上游及该分支全部未推送提交。无上游不猜目标；推送失败保留已完成提交，重试只推送。收到陈旧内容、来源或目标错误时重新观察，保留说明，不能静默重放。

完成接入应报告登记事实、默认选择及实际检查范围。登记成功不证明模型生成已通过；仅验证过临时生成、结果、取消或复用等真实调用后，才报告相应能力已验证。协议或授权失败只影响该功能，不要求用户重新初始化工作空间（Workspace）。
