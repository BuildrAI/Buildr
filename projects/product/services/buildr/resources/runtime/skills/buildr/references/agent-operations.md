# 本机智能体接入与调用

内部对话与单次生成共用智能体（Agent）和模型（Model）配置。外部桌面会话（Session）关联已退役，不再建立或保留这些关系。

## 内部对话与持续执行

统一对话的新版私有存储按条目修订单份保存正文，并对稳定的大工具记录无损压缩；查看完整历史、工具详情或搜索不需要发送模型请求，也不意味着原生上下文被归档。格式升级只在原写入后台安全释放后进行，迁移前保留 `conversations.pre-v5-<内容身份>.sqlite` 一致性备份；空间统计须计入该备份和 WAL，不能把正文压缩比例称为实际已回收空间。升级被占用阻止时保留原工作，不为迁移停止执行或手改数据库。新库已有输入后不能用旧备份覆盖回滚；恢复失败先核对数据版本及准确 owner，不降级覆盖、不新建会话重放。备份、原生恢复库、已发交接来源及账号不属于普通编译缓存回收对象。

持续执行由独立执行进程（Agent Process）持有。Buildr 主程序重启只释放连接，重新打开后核对原轮后台代次、原生上下文和待回应，不因此重发指令。通过已发现且认证的 `GET /api/v1/app/agent-service/runtime` 观察当前入口、保留实例、待采用内容摘要、忙闲原因及切换失败；此接口不返回凭据。两版显式声明并行兼容时，新版取得唯一配置维护权并确认就绪后接新工作，旧版继续保存原轮输出，处理准确停止、问题与审批。兼容后台中，当前输入与保留执行分离：新要求使用所选执行方的独立上下文，不等待旧命令释放；旧上下文仍由准确原后台控制。存储版本不兼容的旧程序不能热接管，不得为采用候选而停止业务。

工具调用 Buildr 时仍保留智能体的私有 `HOME`。共享能力按宿主路径线索定位，显式产品目录配置优先；不要通过改回用户 `HOME`、复制账号或重新安装 OpenSpec 绕过定位错误。Git 全局配置、凭据帮助器与 SSH 配置同样按 `HOME` 定位；需要用户 Git 身份时，按 `git-operations` 的“Git 身份与用户主目录”只对当前命令读取 `BUILDR_HOST_HOME` 下的真实配置并核对作者、确认帮助器存在可用凭据；不输出或保存凭据内容，不复制凭据、不改仓库远端或账号。任务工作树缺少派生采用回执不妨碍读取已声明且完整的共享源，不能把源读取失败报告成程序版本缺失。

后台版本变化不等于用户更换智能体或模型。同一执行选择下，原轮结束后由系统安全释放控制资源并在新后台恢复最新原生会话；已结束旧轮控制尚未释放时，保留待发送，不通过另建会话绕过。对话中的原生会话交接记录提供前后会话与后台身份、原因及实际受理状态；仅创建或恢复上下文不等于新要求已送达。诊断时先区分待回答、在途工具、控制资源未释放和模型协议失败，不把未释放称为失联，不重放未知操作。原轮仍在途时的独立新目标可使用独立上下文，但必须保留准确交接记录。

上一轮执行或停止期间，用户可以提交一条待发送指令；界面显示“已提交，等待自动发送”，支持修改或取消，关闭页面或重启主程序不会丢失。已保存待发送不代表已经开始执行，普通未提交草稿不会自动发送。当前接收后台就绪后，后台重新核对当前历史、宿主事实、目录、账号身份、模型和权限，按原请求身份自动接续，无需用户再次发送。旧执行停止未确认或工具结果未知不阻塞独立的新要求；选择失效或接续失败时保留内容和原因，不自动换模型或提高权限。响应丢失属于结果未知，先核对原请求，不能另建请求重发。

所有执行方（Codex、DSH、Qoder）使用相同输入语义，由Agent Service统一调度、Adapter映射原生能力：问题卡片提交只回应准确原请求并继续原轮；输入框发送新指令在同一可见对话开启新轮，不自动作为原轮补充，也不隐含回答或批准。独立新轮收到原生受理回执后，系统才结束旧问题的活动等待并保留未回答事实；新轮未受理或失败时旧卡片保持。预览、编辑草稿或单独更换选择不清理问题。适配器声明支持安全释放纯问题等待、同组合且无活动工具时，优先在准确等待释放后复用原生会话；该路径释放后启动失败不能伪装回滚。原生不支持时，Buildr先隔离新轮，再核对并释放旧轮纯问题等待。仍有活动工具、后台任务或未知工作时保留其准确控制，不因新指令整轮停止，不重放旧指令。参与者归属从提交起固定，不在执行途中改写。卡片回答不因下方模型选择变化而自动交接；显式跨模型交接仍按准确已提交回答办理。

新轮实际受理后，系统结束其接续计划中的旧问题等待；仅核对为纯问题等待时按准确归属安全释放，活动工具和后台工作保持原控制；旧卡片迟到事件不重新激活，未回答事实和未知操作结果内部保留。新要求不等待停止确认，不重放未知操作。内部善后默认静默，不在进展或最终回复追加旧卡片、旧执行说明；只有实际影响当前目标且需要用户决定时，说明具体影响。单独选择、预览、取消未发送内容不触发该善后。DSH、Qoder 普通问题支持“其他”文字回复，多选可以同时提交选项与自定义文字；Codex 按原生声明提供，工具审批不使用自由回答。

旧后台按自己实际持有的执行控制资源、待回应、辅助工作、模型调用和重要写入决定能否退出；历史结果未知本身不占用后台。`RunView.executionState` 和 `resourcesReleased` 分别表示原执行判断和原后台控制资源释放事实，均不等于任务完成；原生主进程退出后，独立命令仍可能继续，释放空闲控制资源不能把它误报为已结束或成功，也不能重发。明确登记的后台任务及仍依赖该后台的工作继续受保护。确认准确进程退出和释放后，只清理不再被引用的实例及运行文件，保留历史、账号、附件和成果。未声明并行兼容的旧版本或资料格式不兼容时仍等待受保护的空闲交接。不要直接改写进程记录或私有账号文件，不按端口或旧编号接管其他实例。预览停止与维护核对全部新旧后台，退出未确认时保留数据；首次从同进程旧版升级须先完成或准确停止旧工作。

Codex、Qoder 和 DSH 使用同一控制资源释放判断，保留各自原生状态的必要适配；DSH 同时核对官方后台任务，仍运行、停止中或观察失败时保留控制资源。在途模型调用只保护自己所属的准确连接，不阻塞其他对话释放。DSH 补写的 `TOOL_OUTCOME_UNKNOWN` 是结果未知，不能当作操作完成或自动重发依据；已准确收到的完成回执继续有效。原生控制进程退出后，失效连接会关闭，原操作结果仍按上述规则核对。

独立账号目录用于隔离登录，不代表本机工具缺失。需要额外工具时，结合 `PATH`、项目依赖及 `BUILDR_HOST_HOME` 指向的原用户目录检查已有安装；浏览器缓存使用实际 `PLAYWRIGHT_BROWSERS_PATH`，保留用户明确覆盖，未设置时指向原用户的官方默认缓存。缺少工具时，由智能体（Agent）根据当前任务选择相应技能（Skill）或官方说明准备并验证，不复制桌面凭据。

对旧对话的“重新读取”应优先恢复准确原生持久结束证据。Qoder 的主链输入、并行工具结果、最终模型响应和结构化结束记录能相互核实时，可以补回结束状态及遗漏答复，不启动模型或重发要求；只看到最终文字或连接释放仍不能证明结束。已释放且无明确活动工作或有效待回答问题的历史疑点，可在原对话“继续工作”核对已有成果后接续，或“关闭对话”结束关注。关闭只撤下提醒并从最近隐藏，保留记录、未知操作和关联任务；可从对话列表“查看隐藏”找回，再发送新要求会恢复到最近。不要把关闭当作停止命令、操作成功或任务完成。

用户想在 Buildr 内使用 Codex、DSH 或 Qoder 时，从全局对话打开“账号与配置”，在“智能体”页准备 Buildr 独立程序，在“模型”页登录账号。新接入仅使用 Buildr 独立安装，不发现或依赖桌面应用内程序；Qoder 由 Buildr 管理配套软件开发工具包（SDK）与执行程序，按同一安装包加载；升级候选通过无工具的真实对话后才切换，失败保留旧组合。已有桌面来源仍可使用，在统一更新或“智能体”页明确点击更新并确认后，才下载独立程序、核验并在工作结束后切换和重启；原桌面应用不变。路径、来源和技术信息在详情中查看。通过官方登录建立独立账号，再核对实际账号及非空模型目录；不把程序安装成功或打开登录页当作接入可用。需要用户本人登录时，只交接当前尝试的官方页面；不要提取桌面令牌（Token）、复制默认账号文件或把秘密写入任务、消息、日志及 Git。当前没有新的 `buildr agent-conversations` 命令，不猜造命令或使用已退役的接入命令。

- Codex 使用独立 `codex app-server` 应用服务（App Server）；DSH 使用独立 `dsh web --no-open --port 0` 完整本机网页宿主（Web Host）及官方客户端（Client）；Qoder 使用官方软件开发工具包（SDK）与 `qodercli`。不要求外部桌面应用保持运行，也不等于提供桌面版全部功能。
- 每家一套本机独立配置，可供多个工作空间（Workspace）使用。配置和统一交互库属于 Buildr 本机运行配置（Profile）的私有数据，不是组织源资产；不自动复制桌面插件、用户级规则（Rule）、技能（Skill）、工具连接或任意第三方模型凭据。缺程序时通过页面显式准备独立安装并核对兼容版本，不静默下载程序或改绑用户默认配置。
- 准备进度可查询、可取消；切换厂家和关闭面板不取消后台准备，重启后重新观察安装和账号。版本准入按主版本：Codex、DSH 为 `0.x.x`，Qoder CLI 为 `1.x.x`，包含有效预发布版本与构建标记。符合范围只允许继续实际协议、账号和模型检查，不单独代表接入可用；固定下载版本不等于唯一兼容版本；同来源兼容更新保留账号和原生上下文，仍检查实际协议。原程序缺失或版本不兼容时保留账号与历史，不通过切换程序、配置或会话编号冒充恢复。浏览器工具由智能体（Agent）按已有技能（Skill）检查、准备并真实验证；本机浏览器品牌或安装成功都不等于已具备浏览器操作能力。
- 普通对话先确认工作空间（Workspace）及真实起始目录（Working Directory）；任务页“打开对话”创建或打开关联该任务（Task）的内部对话。起始目录是原生规则（Rule）、技能（Skill）发现的起点，不是跨目录访问的禁止边界；实际访问仍按原生权限和用户授权。任务关联不自动把任务全文、当前页面或其他工作空间资料注入模型。
- 发送前核对接入、模型、起始目录及“查看发送内容”。流式回答、工具观察、待答问题、授权与停止在同一对话处理；授权只对应准确本轮请求。不要因历史中有人同意过，就重放原工具或复用旧许可。
- 权限选择位于当前对话输入区，没有已保存权限选择的新草稿初始选择“完全访问”；工作空间（Workspace）内明确选择过默认权限或完全访问时，新草稿及刷新优先恢复该选择，不清除其他工作空间的记忆。已有对话继续使用自己的实际运行模式或准确选择，旧记录缺失模式时按默认权限解释。完全访问的后续执行按各家原生免逐次工具审批模式工作，同一对话换家时分别应用，不改变外部桌面配置或旧一次生成。业务问题仍需用户回答，未知交互不能自动批准；改回默认时必须逐轮重新应用，不继承上次完全访问。发送预览与实际本轮模式分别核对，不能只凭界面选择推断原生已经生效。
- 同一段对话可以依次使用多个智能体（Agent），历史不按厂商分类。首次换一家创建它自己的原生上下文；换回时恢复它原来的上下文，补交它未见的可见历史。隐藏推理、工具内部状态和权限不会迁移。普通消息直接提交，不要求先读取交接预览，也不等待辅助模型摘要；主动查看交接内容时仍可预览，携带预览令牌的提交必须核对其准确版本。接续材料过大时，直接使用本地完整索引和分轮原始记录，由接手者按需读取，不要求用户手工总结；图片能力或必要输入仍不兼容时保留草稿、说明限制并允许选择其他模型，不静默截断历史。
- 用户要从既有答复探索另一方向时，可在该轮最终答复旁选择“分支到新对话”，保留截至该轮的历史与附件，等待新指令后重新生成标题。读取新对话的 `forkedFrom` 核对直接来源身份、原工作空间（Workspace）、条目、轮次、继承边界、标题快照与分叉时间，不凭标题推断来源；再次分叉指向直接父对话。需要通过已发现且认证的接口组合时，向该对话的 `/fork` 提交 `expectedRevision`、`entryId` 和稳定的 `clientRequestId`；原生结果未知时保留该请求并核对，不换请求身份自动再建。分叉不发送工作、不回退文件、不复制原轮工具许可；新对话继续工作前仍须重读当前成果。程序或旧记录无法证明准确边界时只拒绝本次分叉，不改成全部历史或文字复制，原对话继续可用。
- “核对状态”先恢复准确原生观察；旧执行已结束且当前对话独占资源得到原持有者确认释放时，由新版同步结果并接续已提交的待发送要求。核对不重启整个后台、不暂停其他对话，也不重发原要求。仍在运行时继续观察；身份、工具或释放不确定时保留原因；旧版本不支持释放确认时不强行接管。
- 用户明确要求恢复原目标，准确原控制资源已经释放、原轮已受理且没有待决定或该对话在途工作时，可按准确 `continueRunId` 预览并手动继续原组合；参与者、模型来源、模型、档位及权限必须保持一致。先核对原轮身份和当前版本，再发送一次；旧轮及独立命令结果仍未知，不把恢复原目标冒充旧命令退出或成功，不逐条重放命令。没有释放证明、切换组合、普通发送和排队不使用此手动恢复例外；系统中断的自动接续按下方独立边界处理；用户明确提交的独立新要求仍按下方交互连续性处理，不重放原操作。
- 重新打开、刷新或服务（Service）重启不重发指令。当前交互与保留执行分别核对；`retainedRuns` 保留原轮、参与者、服务代次、工具状态。新要求或更换选择不等待旧工具退出；忙碌上下文不会被新轮覆盖。`canContinue` 只描述原生正常答复事实，不是用户输入门禁或资源释放证明。
- 每次接续先用本次输入附带的本地控制程序 `read` 查看当前与保留执行；`observe` 核对，带准确控制 JSON 的 `observe` / `stop` 处理指定原执行或 `toolId`。从刚读取的记录取 `expectedRevision`、`runId`、`participantId`、`generation`；冲突先重读，不自动重试副作用。该程序复用已有认证后台，不新启服务，凭据不进入指令。按最新目标决定继续使用、准确停止或保留待核对，并说明未完成善后；不要把善后丢给用户，不按命令名称或时长强杀，不重放未知操作。
- 普通新要求不构成旧问题答复或审批。未回答问题和旧执行保持原归属，新的智能体（Agent）仍缺必要决定时使用正式提问；不以发送新要求或切换模型推断同意。
- 原生执行连接确认断开后，系统会保留原绑定并自动核对准确执行；开发版与正式版都在确认原执行及工具停止，或准确原控制已释放且没有活动工具及必要用户决定时，沿用原智能体（Agent）、账号、模型（Model）、档位、推理强度和权限自动接续原目标。先核对真实成果与未知副作用，只继续剩余工作，不重发原要求或逐条重放操作；未知结果仍保留。接续与暂时失败重试共用持久的三次预算，发送前重启、重复核对不另发一轮。用户主动停止不自动恢复，必要用户决定不代答。存量“状态待确认”缺少系统中断来源时，只更新已确认的原生终态，不推定可以续做；不能以通用连接提示认定账号过期或程序不兼容。预算耗尽或仍有无法核对的活动工作时保留具体原因。同一组合的内部上下文（Context）重建不显示用户交接；已释放且无活动、未知工具或问题的旧轮仅保留历史。Codex、DSH 与 Qoder 都按此边界处理；DSH 跟随观察中断时有界重订阅同一会话，回补遗漏记录及工具结果，恢复仍在进行的输出，不重发提示。具体诊断保留清洗后的原因。旧后台缺少兼容恢复能力且仍有其他工作时，保留准确归属及未完成状态；不要为解除一条对话的输入锁而中断其他工作，也不要手改记录冒充恢复。
- DSH 对话选择模型会更新这套独立配置的后续默认模型；外部桌面配置不受此独立配置改动。检查可用不等于某次真实模型执行成功，图片也只按对应执行器（Executor）实际开放的能力使用。

内部对话只保存交流和执行观察；代码、文档、任务状态与业务数据仍以各自当前对象为准。继续工作前重读实际成果。后续图形界面（GUI）与对话界面（Talk UI）接入业务动作时，仍须交接明确对象身份和已观察版本，由原能力保护写入；首版没有自动捕获所有页面现场或通用图形操作能力。

### 统一模型与额度设置

在“账号与模型”中，已登录账号直接显示真实额度窗口，未登录或过期在同一卡片登录；Codex、DSH、Qoder 复用本应用原生登录，Devin 使用明确发起的独立登录。未知额度不能当作零余额，旧观察不能冒充本次读取。模型页只把已启用项目加入新选择；刷新保留开关，新发现模型默认停用，组合预设单独管理。

Devin 账号下任一已启用模型可供 Codex、DSH 与 Qoder 选择；保留原选择及草稿，模型不可用或执行方无法表达所选档位时改选后再发送，Qoder 只接受部分思考档位；Devin 来源的 Codex 会按所选权限使用对应原生上下文，旧记录保留并通过现有可见历史接续。已知审批问题说明仅作等义兼容，保留示例、必要规则及原生沙箱和审批策略。不要自动提高权限、删除原生权限说明，也不要以某一模型的拒绝、声明接纳或额度错误冒充其他模型不可用或整轮成功；完全访问会跳过逐次工具审批，仍遵守本轮用户授权与厂家限制。

上下文数字是本地执行偏好，不扩大上游容量；可恢复平台默认，已知上限时不得设置更大数字。Devin 按真实支持配置提供思考和速度档位，不推导笛卡尔积；未知档位保留语义，不伪装有序深度。设置改变用于新的执行上下文，现有对话历史保留，不能静默重发指令。通过已发现的 HTTP 操作管理偏好时，先读取准确账号和模型身份，再携带当前 `expectedRevision` 调用 `/api/v1/app/agent-service/model-accounts/:accountId/preferences`；冲突后重新读取，不覆盖其他入口，也不直接修改私有账号文件。

## 提交说明单次生成

提交说明从已配置模型（Model）目录选择明确来源。Buildr 准备有界变更材料，只调用一次模型，不创建持久对话、不提供工具；失败或取消保留草稿。没有可用模型时仍可手写说明并提交。

旧 `buildr agent`、`buildr codex` 和 `buildr dsh` 生成及外部关联入口已删除，不再采集当前外部会话身份。任务（Task）可关联 Buildr 内部对话，也可独立工作；关联不成为创建、验证或完成的前提。

新的明确输入会暂停 DSH 旧目标自动续行并保留目标正文；旧目标后续记录仍归原请求。重试回执独立分轮，迟到的旧答复不能归入新输入。读取和停止后查看具体反馈；明确初始化失败是未送达，回执丢失仍是未知，不据此重发。

整轮“停止”包括该轮模型请求、派生子任务、后台工作和自动续行，保留已完成成果及其他对话。模型入口会拒绝持续异常空白或超限工具参数，给出准确失败原因。DSH 原生通道失响应时，仅对归属完全匹配、没有其他受保护工作的独占宿主做有界终止；共享宿主及归属未知的进程不强停。没有完成回执的操作继续待核对，不能因进程退出当作成功或直接重做。界面显示停止中及真实结果；重新读取只观察，重复点击不创建第二份停止或执行。旧连接没有原轮控制权时保留工具状态并明确说明停止未确认。

### 前台期限与后台服务

Buildr 隔离 DSH 的前台 shell 命令超时会真正终止，不会自动转成后台作业。有限操作按工具提供的 `timeoutMs` 设置合理期限；需持续运行且在用户授权范围内的服务才显式 `run_in_background`，保留 `jobId`、归属与停止方式。模型已结束且仅有后台作业时，历史显示后台仍运行，模型执行统计不计入该作业；未读与待决策继续提醒。不要把统计不活跃理解为进程已经退出，不重发未知结果的操作。

迁移备份仅在提交后重新打开新库、完整性和准确备份内容比对均通过且文件身份未变时立即删除，不保留固定天数。验证失败或删除失败保留备份；删除失败不否定有效新库。不扫描批删未知历史备份，也不用旧备份覆盖新输入。
### 按需核对 Buildr 参与

需要优化规则、技能或命令输出时，复用本对话已提供的准确工作控制命令，不猜端口、数据根、凭据或其他对话身份：将动作换成 `participation '{"runId":"从当前记录核对的执行标识"}'` 读取单次事实；`participation-summary '{}'` 读取此绑定工作空间最近七天的汇总。范围可传 `from`、`to`（半开区间、最多九十天），以及 `provider`、`model`、`kind`、`identity`、`version`、`limit`（默认五十、最多二百）和原响应 `cursor`；翻页保留相同时间及筛选。后台不支持时保留具体缺口，不启动、重放或更换执行来补统计。

区分可发现、实际提交、请求读取／调用、实际观察，以及来源已确认、候选、未知。只有已观察证据能确认消费；路径名称、工具结束、来源确认均不能替代动作成功。供给版本不等于当次观察版本；旧记录未采集和隐式加载不可见不能当作零使用。字节数不是 Token 或费用，`contextUsage` 是原生上下文背景而非累计账单。失败比例只计算 `failed / (succeeded + failed)`，未知与进行中单列。统计只形成调查线索，不自动删除低调用资产，不重读当前文件补写历史，不手工填写参与标记。


## 对话过程出站 Webhook

Agent Service 可把当前执行过程推给用户指定的可信接收端（例如 Grok Bot）。默认配置是宿主主目录 `~/.buildr-webhook.json`，一个 JSON 对象包含 `url` 和 `secret`；文件须属于当前服务用户、仅本人可读写（`0600`），不得使用符号链接。配置保存后即时生效，保留进程也会重新核对；可用 `BUILDR_AGENT_WEBHOOK_CONFIG` 显式选择文件。缺省文件不存在才兼容 `BUILDR_AGENT_WEBHOOK_URL` 和 `BUILDR_AGENT_WEBHOOK_SECRET`；文件存在但无效时不回退到另一个目标。不要在命令参数、聊天、日志或源资产中填写真实秘密，不打印响应正文；迁移后核对文件内容与权限，不保留两份活动配置。

人可在「智能体与模型 → 事件通知 / Webhook」管理当前本机服务的单一目标、启停与密钥，保存不自动发送。密钥默认遮罩，主动点击查看，再次隐藏或关闭设置后清除明文；不要代用户把明文抄入聊天。外部指定文件或旧环境来源明确只读，不在界面隐式接管。配置、查看和测试均沿用本机会话认证，写入与主动操作携带已观察版本，冲突先重读，不覆盖。测试按钮只发送独立的 `test` 通知，无业务正文、5秒超时且不自动重试；正常业务事件仍保持下述七类。最近投递显示当前服务进程观察到的时间、成败与 HTTP 状态，不展示响应正文。自动化回归必须显式绑定隔离配置（例如一个确认不存在的 `BUILDR_AGENT_WEBHOOK_CONFIG` 文件），不得继承真实接收端。

公共通知只使用 task_started、status_changed、reply、pending_question、pending_approval、completed、error 七种事件。每条必带 eventId、conversationId、agent.name/id、machine、eventType、summary、timestamp；附加字段原样转发。agent.name 为 Buildr，id 为本实例持久 UUID，不同实例不同、重启不变；machine 是真实主机名，与 agent 并列，不用模型或执行器身份替代。

问题卡片、审批、完成和出错立即持久入队；reply 仅通知有新回复并提供 entryId 等位置，完整正文与流式片段不推，通过 `buildr agent read <conversation-id>` 按需拉取。问题通知有准确问题/选项 ID；审批命令、内部思考、原始工具正文不外发。关闭卡片不表示回答或同意。

发送端使用私有持久日志去重并负责补推；POST JSON、Bearer 鉴权、不跟随重定向、5秒超时、最多16并发，仅2xx确认。非2xx、断线和超时保留相同 eventId，从1秒指数退避至5分钟，服务恢复后自动补投。配置目标改变不自动转发旧事件。成功事件可使用 `buildr agent replay <conversation-id> <event-id> --target <workspace>` 原样重放，服务核对准确空间与对话；不重做模型或业务动作，不手改私有数据库。

响应丢失时可能重复到达同一 eventId，不能宣称恰好一次。接收端只接收并原样转发附加字段，不承担业务判断、去重调度、重试或断线恢复。2xx仅证明接收端确认，不证明后续转发成功。候选测试不证明共享服务已采用；不得为采用候选自行重启共享服务。

## CLI 卡片回答与同对话新轮次

新建对话的 send 不接受 --connection，仅自动选择唯一 enabled 且 ready 连接；零个或多个时先核对设置，不猜选。先用 `buildr agent read <conversation-id> --target <workspace>` 核对当前 requests。正式回答结构化问题卡片时，用 `buildr agent reply <conversation-id> <request-id> --option '问题ID=选项ID' --other '问题ID=补充文本'`；两类参数可重复，使用准确 ID，单选一个值，多选可多个值，自由文本须符合 allowOther。也可互斥使用 `--answer-json '{"问题ID":["选项ID或文本"]}'`。不把默认选中、推荐或普通新消息当成回答；文本模式不会自动解析 JSON。

用户明确放弃本次卡片回答并要求发新内容时，使用 `buildr agent send '新内容' --conversation <conversation-id> --skip-questions --target <workspace>`，在同一对话新起一轮；两个参数配对，沿用原连接、模型和权限，不能与配置覆盖混用。不创建新对话、不提交答案、不修改任务数据；旧问题保留未回答事实，仍缺必要业务决定时重新询问。预发送后通过持久待发送接口投递，返回保存成功不等于执行完成；用 read 核对。问题、版本变化或结果未知时不盲目重试，不自行重启服务。

### 原执行补充与通知重放

运行中的对话需要插入新内容时，用 `buildr agent supplement <conversation-id> '补充要求' --target <workspace>`。CLI 观察并使用原 runId、participantId、generation，不新建对话、不提交卡片答案；原执行不支持、已结束或状态未知时明确失败，不退化为新建对话。delivery=unknown 时先 read 核对，不重发。

send 不接受 --connection 或 --model；已有对话跳过卡片沿用原执行配置，新建对话仅选择唯一 enabled 且 ready 连接。卡片正式答复使用 reply 的 --option/--other 或 --answer-json，不把普通文字输入视为批准。

CLI supplement 显式使用 sameRunOnly=true，仅向原 runId 追加。挂起问题卡片时不接收该补充；需要放弃卡片并开启新轮时用 send --conversation <id> --skip-questions。投递过程中原轮已结束则返回 rejected 并保留内容，不自动转成新轮；delivery=unknown 仍须先读取核对，不能重发未知操作。

连接只在发送时准备，不提前准备、也不为尚未采用的连接保留实例；保留进程不等于原轮仍执行，也不等于物理资源已释放。升级和准确交接仍自动核验回收，不要求用户清缓存或重发输入。
