# harness-host-integration Specification

## Purpose
定义目录型与业务型宿主对共享 Harness 的接入约定，明确调用者、权威来源、执行范围和控制身份的区别，使跨入口操作具备准确授权与恢复依据，并在宿主离线或旧客户端兼容时保全已有工作及关系。

## Requirements

### Requirement: 目录宿主必须提供准确位置而不复制业务工作空间

独立 Harness MUST 允许本机用户明确登记或选择目录，并以稳定的来源化引用保存目录及已观察身份；对同一数据域内已在本机工作空间登记文件（`workspace-registry.json`）登记的工作空间及默认工作空间（`@default`），Harness MUST 能直接读取其名称、路径并按同一文件系统身份摘要算法核验目录，而不加载 Development 业务模块或要求 Development 进程在线。每段对话 MUST 绑定一个准确初始位置；多段对话可绑定不同目录。登记目录 MUST NOT 创建 Development 任务、项目或工作空间。通过 Harness 选择或登记本机目录时，若目标目录已对应同一数据域内健康的已登记本地工作空间，MUST 复用既有工作空间身份而不生成重复的 `harness-local` 登记，名称冲突时 MUST 拒绝并保留原登记。程序凭据 MUST 只能使用已授权引用，不能用任意路径绕过范围准入。目录不存在、身份冲突、身份变化、链接替换或权限不满足时 MUST 局部拒绝新工作并保留旧记录。CWD MUST NOT 被宣称为全部文件访问的沙箱。

#### Scenario: 选择普通目录
- **WHEN** 用户经本机页面认证选择一个未被登记的本机目录
- **THEN** Harness MUST 可创建目录来源引用并开始工作，不写入 Development 登记和任务库

#### Scenario: 重复选择已登记的本机工作空间目录
- **WHEN** Development 未运行，用户通过 Harness 目录登记选择已存在于同数据域 `workspace-registry.json` 的工作空间目录
- **THEN** 系统 MUST 直接复用原工作空间身份与名称而不创建第二份 `harness-local` 记录
- **AND** 若提供了与既有工作空间名称不同的自定义名称，系统 MUST 拒绝并保留原记录

#### Scenario: 目录被替换
- **WHEN** 已保存目录身份与新执行前的当前观察不匹配
- **THEN** 系统 MUST 拒绝在新对象上继续，保留原对话、目录信息和草稿，不静默重绑定

#### Scenario: 旧默认目录与新目录来源共存
- **WHEN** 独立入口首次打开且存在 Development 的旧默认对话
- **THEN** 旧 `sourceId=buildr`、`@default`、目录和原生引用 MUST 保持，新目录来源 MUST 使用独立引用而非批量迁移旧记录

#### Scenario: Harness 首先启动已有资料
- **WHEN** Development 未运行，独立 Harness 首先启动包含旧裸范围 ID 或 `@default` 的既有数据域
- **THEN** 旧记录 MUST 仍解释为原 `buildr` 来源，读取、关联及准确控制保持原义，不因启动入口或缺省来源改变归属

### Requirement: 调用入口身份不得替代对象的权威来源

系统 MUST 分离受认证调用者、目标来源/范围及权威回调提供方。宿主注册 MUST 只接受该主体被允许提供的来源；客户端传入的来源字符串 MUST NOT 自行授予身份或权限。跨入口读取和控制 MUST 同时核验数据域、目标范围、操作权限与准确对象身份。列表、统计、待回应、事件、附件及原生详情 MUST 使用同一权限边界，不得从聚合或查询捷径泄露其他来源数据。

第一方完整用户页面通过本机认证后，MUST 默认获得同用户同配置域所有来源的对话读取、既有执行停止及有效问题/审批处理能力；对于需要外部宿主回调解析的来源，新执行 MUST 仍通过原宿主核验；对于由 Harness 内置解析的本机工作空间与目录范围，Harness MUST 直接核验目录身份并报告为内置可用（`builtin`）。Development 的工作空间筛选 MUST 仅影响呈现，其全局对话入口与独立 Harness 列表 MUST 可访问全部获准来源。普通宿主连接、v1 客户端和程序凭据 MUST NOT 继承此页面默认权限。

#### Scenario: 默认显示 Development 历史
- **WHEN** 同用户同配置域首次从已认证的独立 Harness 页面打开对话列表
- **THEN** 系统 MUST 默认列出包括既有本地工作空间在内的全部已有来源对话及准确名称，无需逐条复制或额外授权
- **AND** Development 工作空间列表可按范围筛选，但全局入口必须可查看同域全部对话

#### Scenario: 来源离线不改变默认可见性
- **WHEN** 独立入口打开无实时宿主连接且不属于本机内置目录/工作空间的外部来源历史
- **THEN** 已保存历史和准确既有执行控制 MUST 仍按用户页面权限可用；新执行 MUST 按宿主不可达规则拒绝，不将会话重归为目录来源
- **AND** 同一数据域内已在本机工作空间登记表或 `@default` 中的本地工作空间仍保持内置可用，不因 Development 进程未运行而退化为离线

#### Scenario: 程序凭据伪造来源
- **WHEN** 程序只获一个 Development 范围的读取权，却请求其他来源或管理操作
- **THEN** 系统 MUST 拒绝且不产生副作用，不因产品共用后台而扩大权限

#### Scenario: 同编号不同来源
- **WHEN** 两个来源具有相同范围 ID 或对话局部标识
- **THEN** 查询、缓存、事件和控制 MUST 按完整身份区分，不能混合记录或目标

### Requirement: 宿主可选能力与恢复策略必须按来源隔离

宿主 MUST 提供准确执行范围解析与必要发现能力。工作对象核验、描述及参与观察 MUST 为可选能力；缺少它们 MUST 不妨碍无业务对象的目录工作。系统中断接续策略 MUST 由所属来源按版本维护，宿主连接先后、断连或其他来源的配置 MUST NOT 覆盖它。已受理轮次的权限及准确待回应 MUST 不因另一入口选择变化而改变。旧契约客户端 MUST 保持同来源语义，未经新版协商不得得到跨来源能力。

#### Scenario: 无任务核验能力的宿主
- **WHEN** 目录宿主不提供工作对象核验
- **THEN** 无链接对话 MUST 正常工作；请求新增需要核验的工作对象时仅该关联操作被拒绝

#### Scenario: 两个来源恢复策略不同
- **WHEN** 两来源按相反顺序接入、配置不同接续策略后重连
- **THEN** 各来源 MUST 保持自身策略和版本，不以最后连接者或兼容来源名覆盖全局策略

#### Scenario: 旧客户端接入新版服务
- **WHEN** v1 同来源客户端与支持新版多来源契约的服务连接
- **THEN** 服务 MUST 保留已声明兼容的同来源操作，不把调用者字段按新版来源权限解释

### Requirement: 契约升级必须保持真实旧客户端兼容且不伪装存储能力

首个多来源版本 MUST 同时提供真实 v1 同来源行为及经显式协商的新版能力；旧发现和身份读取 MUST 保持旧客户端可接受的兼容表达，不能仅改契约标识而使旧客户端在发现阶段失败。新客户端面对旧服务 MUST 只使用可确认支持的能力，不能将协议不支持当作另起同域后台或扩大权限的理由。协议兼容、持久格式兼容及并行写入资格 MUST 分别核验，不得以兼容名称掩盖实际不兼容。

#### Scenario: 未修改的旧客户端连接新服务
- **WHEN** 使用拆分前的真实 v1 客户端构建连接新服务
- **THEN** 发现、同来源注册和已声明的读取控制 MUST 可用，旧客户端不会因新版能力公告而被错误拒绝或自动获得跨来源权限

#### Scenario: 新客户端遇到旧服务
- **WHEN** 新客户端连接只提供 v1 的既有服务
- **THEN** 可兼容的同来源操作 MUST 按实际能力使用，新增能力明确不可用，不伪装 v2 成功、不启动同数据根的第二个写入核心

#### Scenario: 协议兼容但数据格式不兼容
- **WHEN** 两代可以协商操作协议，但旧代次不能保全新持久字段或不满足并行条件
- **THEN** 系统 MUST 保留旧工作并等待受保护的写入交接，不能通过沿用旧存储或并行标记放行双写

### Requirement: 宿主不可达必须按具体动作降级

原业务宿主不可达时，系统 MUST 保留已受理执行、可读历史及准确控制能力，不把不可达当作对象不存在。已有执行的停止、观察和对当前有效待决请求的答复，MUST 在调用者有对应权限且原执行可控制时独立可用；对于不属于 Harness 内置本机工作空间/目录的外部范围，新执行、派生或目录改绑 MUST 在原宿主不可达时局部拒绝并保留输入，MUST NOT 改用默认目录或其他宿主绕过核验；对于本机已登记工作空间与 `@default`，Harness MUST 独立完成目录存在性、权限与文件系统身份核验以支持新执行、续发与自动恢复，同时对新增外部工作对象关联（`verifyWorkObject`）在原宿主不可达时继续局部拒绝。

#### Scenario: Development 离线时使用本机已登记工作空间
- **WHEN** Development 进程未运行，独立 Harness 打开同数据域已登记的本地工作空间或 `@default`
- **THEN** 范围发现 MUST 返回准确名称、路径与内置可用状态，用户 MUST 能新建对话、续发既有对话并自动恢复中断执行
- **AND** 若同时请求核验或新增关联业务任务对象而 Development 不可达，系统 MUST 局部拒绝该工作对象核验而不阻断无业务对象对话

#### Scenario: Development 离线后停止既有执行
- **WHEN** 用户从已授权的独立入口停止仍由 Harness 持有的 Development 执行
- **THEN** 服务 MUST 按原 run/participant/generation 控制，不要求任务查询成功才允许停止

#### Scenario: Development 离线后回复待决请求
- **WHEN** 有答复或审批权限的用户对原执行仍有效的准确请求提交答案
- **THEN** 服务 MUST 按原请求身份校验并仅消费一次，不自动创建新轮或扩大权限

#### Scenario: Development 离线后发送新工作
- **WHEN** 对未在本地登记且无内置解析能力的外部离线来源或未知范围提交新的执行要求，而原宿主回调不可达
- **THEN** 系统 MUST 返回宿主不可达的明确原因并保留草稿或已提交待发送事实，不切换默认目录绕过核验

### Requirement: 工作对象关联必须兼容旧任务字段且保持唯一关系

Harness MUST 以来源、范围、对象种类和对象 ID 标识外部工作对象，不保存其业务状态权威。关联 MUST 使用已观察版本追加或修改、核验准确来源、去重并保留其他关系；显示快照 MUST 标明其非权威性质。Development 的既有任务关联及 `taskLinks/taskIds/taskId`、`link-task` 行为 MUST 映射到同一关系集合，旧客户端写入 MUST 保留无法表达的其他来源及对象种类。缺少任务能力 MUST 不要求独立 Harness 建立任务系统。

#### Scenario: 旧接口修改任务关联
- **WHEN** 对话已有其他来源或种类链接，旧任务接口新增或解除一个可表达的任务
- **THEN** 系统 MUST 只修改目标关系并保留不可见链接，不修改任务状态或发送指令

#### Scenario: 跨空间同码与重复追加
- **WHEN** 两个工作空间存在相同任务编码，用户重复关联其中一个
- **THEN** 系统 MUST 按完整身份区分并去重，其他任务关联保持

#### Scenario: 存储格式与旧写入者不兼容
- **WHEN** 新关系格式不能被仍活动的旧代次无损维护
- **THEN** 系统 MUST 推迟该格式启用直到准确写入权交接，不能让旧代次覆盖新关系或丢弃未知字段

### Requirement: 两入口必须消费同一套公开交互协议

Harness MUST 拥有唯一公开 HTTP/SSE 语义、Schema、公开类型、输入输出校验及程序文档。Development MUST 经同源认证代理接入，旧网页和程序路径 MUST 通过兼容映射进入同一能力，不保留第二套发送、答复、停止或存储实现。该协议 MUST 可由不加载 Development 业务模块的目录型客户端消费。

#### Scenario: 从两入口执行同一操作
- **WHEN** 独立入口和 Development 兼容入口对同一对象调用同一操作
- **THEN** 权限以各自有效主体核验，操作语义、修订保护、幂等与结果 MUST 一致

#### Scenario: 目录型协议客户端
- **WHEN** 最小客户端只消费 Harness 公开包和交付负载
- **THEN** 对话 API MUST 可独立验证，不读取 Development 私有模块或生成目录

### Requirement: 同源代理必须保全认证与执行语义

Development 代理 MUST 先验证当前页面身份与写入来源，再使用限定作用域和操作的服务端身份连接已核验后台。代理 MUST NOT 接受浏览器指定任意目标 URL、内部令牌或权威来源声明，MUST NOT 以宽泛 CORS 或透传秘密替代认证。Development 浏览器 MUST 只访问自身同源代理，不直接连接后台内部端口。程序 Bearer 凭据 MUST NOT 成为页面管理会话。

#### Scenario: 跨站或伪造转发目标
- **WHEN** 请求缺少有效会话、来自非法 origin，或试图更换代理目标/身份
- **THEN** 系统 MUST 拒绝并保留现有工作，不泄露内部令牌、模型秘密或敏感诊断

#### Scenario: 浏览器刷新和登录恢复
- **WHEN** 浏览器会话需要刷新或观察链路重连
- **THEN** 系统 MUST 重新核验身份；结果未知的写入必须先查询，不能因刷新认证再次发送工作

### Requirement: 事件与附件传输必须保持准确范围和有界恢复

代理和独立入口 MUST 保留对话、执行、后台代次、事件游标、修订和增量基线，不因代理缓冲改变可用流式反馈。断开观察 MUST 不停止执行。附件上传/读取 MUST 使用准确对象与权限、大小和格式限制；任何失败 MUST 局部报告，不以完整历史重传或自动重发工作作为恢复方式。

#### Scenario: SSE 断线后重连
- **WHEN** 一个入口在执行中断开后重新订阅
- **THEN** 系统 MUST 从合法快照/游标恢复并拒绝混代次拼接，不重复提交输入或影响另一入口

#### Scenario: 上传回执丢失或附件越权
- **WHEN** 附件上传结果未知，或调用方请求其他来源的附件
- **THEN** 未知结果 MUST 可核对，越权 MUST 被拒绝，既有附件和其他工作保持
