# task-changes-workbench Specification

## Purpose
定义任务「改动与提交」工作台的可观察行为：把本任务关联仓库的未提交改动与本任务的提交按仓库分组展示，支持按提交查看文件改动与全文差异；读取为只读观察，不执行 Git 写入。

## Requirements

### Requirement: 任务改动与提交工作台入口
任务详情 MUST 在「任务收尾」之后提供内容标签「改动与提交」，与四个工作阶段并列且不新增工作阶段；标签 SHALL 显示当前未提交改动的文件数。

#### Scenario: 打开工作台
- **WHEN** 用户打开任务详情并选择「改动与提交」
- **THEN** 阅读区展示主从式工作台：左侧按仓库分组的更改与提交树，右侧差异面

#### Scenario: 未提交改动计数
- **WHEN** 任务范围内存在未提交的改动文件
- **THEN** 「改动与提交」标签显示该文件总数；为零时不显示数字

### Requirement: 仓库分组与只读观察
工作台 MUST 按仓库分组展示「更改」（未提交文件）与「提交」：每个仓库显示名称、当前分支（可得时）、领先远端计数（可得时）与分组计数；文件行 SHALL 标注状态（M 已修改、U 未跟踪、D 已删除、R 已重命名、C 冲突）与增删行数（可得时）。面板 MUST NOT 执行暂存、提交、回滚或抓取远端。

#### Scenario: 多仓库分组
- **WHEN** 任务范围内包含多个真实仓库或任务工作树
- **THEN** 每个仓库成组展示其更改与提交，组内提交按时间从新到旧

#### Scenario: 局部仓库不可读
- **WHEN** 范围内某个仓库暂不可读取
- **THEN** 其他仓库照常展示，并给出读取不完整提示与重新读取入口，不扩大为整个面板失败

### Requirement: 差异阅读面
差异面 MUST 支持统一视图（默认）、并排对照与全文三种视图，并带行号与增删行着色；差异面宽度不足约 1000px 时并排禁用并提示原因，宽度足够时自动可用且可手动切换；文件 SHALL 提供复制路径入口。

#### Scenario: 宽度自适应
- **WHEN** 差异面宽度小于约 1000px
- **THEN** 默认展示统一视图且并排选项禁用；宽度恢复至约 1000px 以上时并排自动可用

#### Scenario: 无差异文件
- **WHEN** 选中已删除或纯重命名的文件
- **THEN** 差异面说明不提供差异预览的原因，而不是静默留空

#### Scenario: 未跟踪文件
- **WHEN** 选中未跟踪文件
- **THEN** 差异面按新增行展示文件全文预览

### Requirement: 全屏与浮窗
工作台 MUST 提供「展开全屏」：阅读面脱离居中限宽铺满右屏，左侧文件栏折叠为边侧条并支持悬停弹出浮窗；「恢复分屏」 MUST 回到限宽居中且还原文件栏状态。该交互本变更只落在任务模块，不声明为右屏通用行为。

#### Scenario: 展开与恢复
- **WHEN** 用户点击「展开全屏」
- **THEN** 阅读面铺满右屏、文件栏收成边侧条；悬停该条弹出浮窗供文件导航；点击「恢复分屏」还原

#### Scenario: 文件栏可调
- **WHEN** 用户在非全屏状态
- **THEN** 文件栏右缘可拖拽调宽（约 220–480px），并可整体收起；过窄时自动堆叠到差异面上方

### Requirement: 只读变更文件读取
变更文件读取 MUST 按任务范围解析真实仓库与已知任务工作树，读取各仓库工作区状态与每条提交的文件清单及差异预览；结果 MUST 带读取时间、覆盖范围、完整性说明与局部诊断，并标注截断上限。

#### Scenario: 读取范围说明
- **WHEN** 用户查看工作台
- **THEN** 面板提供读取范围说明：本机可达仓库、扫描上限、读取时间与是否有截断或局部失败

#### Scenario: 读取失败可重试
- **WHEN** 变更文件读取失败或返回不完整
- **THEN** 面板保留已读结果并提供「重新读取」，不把读取失败表述为没有改动

### Requirement: 任务详情轻量改动计数

任务详情 MUST 在打开时通过只读 `GET /tasks/:taskId/changed-file-count` 读取工作区文件数，不依赖进入改动标签。计数 MUST 使用完整改动读取相同的任务仓库范围、文件去重及截断边界，不读取提交历史、增删行数或差异正文。结果 MUST 包含任务身份、读取时间、计数、完整或局部状态、覆盖上限、截断和诊断。任务切换 MUST 隔离读取结果，显式刷新 MUST 重核当前数量；完整列表与差异 MUST 在进入标签后按需读取。

#### Scenario: 打开说明立即读取数量

- **WHEN** 用户从列表打开普通任务详情
- **THEN** 文件数无需读取提交历史或差异即可显示，说明正文可独立读取

#### Scenario: 相同范围的数量一致

- **WHEN** 同一文件现场存在多个检出位置、重命名、删除及未跟踪文件
- **THEN** 计数与完整读取可见文件数一致，同仓库同路径不重复计数

#### Scenario: 局部失败及截断

- **WHEN** 一个仓库读取失败或文件超过上限
- **THEN** 保留其他已读计数并返回局部状态、诊断和截断，不冒充完整精确数量

#### Scenario: 切换和刷新

- **WHEN** 用户快速切换任务或刷新当前任务
- **THEN** 旧任务响应不覆盖当前数量，刷新后显示本次读取结果

### Requirement: 所选文件的差异定位与行号

选择变更文件后，阅读面 MUST 在当前文件完整差异读取结束后自动定位到第一处新增或删除行；左右对比 MUST 保持两侧与中间行号同步。当前文件同一模式的普通重绘及刷新 MUST NOT 反复重置人的阅读位置。上下对比 MUST 只显示一列行号：删除行使用旧版本行号，新增和上下文行使用新版本行号；纯重命名等没有内容差异的文件 MUST 从正文开始显示。

#### Scenario: 修改位于文件中间

- **WHEN** 所选文件的第一处内容改动前有大量未修改行
- **THEN** 读取完成后第一处内容差异位于可见阅读区顶部附近，不停留在文件开头

#### Scenario: 切换来源与阅读模式

- **WHEN** 用户选择另一文件、同文件的另一提交来源，或切换对比模式
- **THEN** 定位对应当前文件和来源的第一处差异，左右对比三列滚动保持对齐

#### Scenario: 人继续阅读

- **WHEN** 人手动滚动后同一文件同一模式完成刷新或发生普通重绘
- **THEN** 保留人的阅读位置，重新点击文件时可再次定位第一处差异

#### Scenario: 单列上下对比行号

- **WHEN** 上下对比显示普通行、删除行和新增行
- **THEN** 每行只有一列行号，分别对应新版本、旧版本和新版本

### Requirement: 从差异定位完整文件并返回审阅
任务差异面 MUST 提供“查看完整文件”入口，绑定所选文件的代码库、实际工作目录或明确提交（Commit）版本及相对路径，进入代码区域资源管理器并定位文件；任务服务引用可以提供可调整的代码库范围预设，文件树 MUST 展示这些代码库的完整文件，不按任务差异文件裁剪。任务当前阶段、所选提交/文件和阅读位置 MUST 保留；完整文件缺失、已删除或来源不能确认时 MUST 显示对应来源诊断，MUST NOT 改读其他目录或版本。

#### Scenario: 查看未提交文件的完整实现
- **WHEN** 用户在当前任务的未提交文件差异点击“查看完整文件”
- **THEN** 系统 MUST 在资源管理器打开该实际工作目录的完整文件并定位适用行
- **AND** 返回任务 MUST 保留原文件差异选择

#### Scenario: 查看提交中的完整文件
- **WHEN** 用户在明确提交中的文件差异点击“查看完整文件”
- **THEN** 系统 MUST 使用该提交的完整标识读取文件及适用目录，明确历史版本
- **AND** 用户选择查看当前文件时 MUST 明确打开当前目录版本，不能把历史标签替换为当前内容
