# harness-directory-workbench Specification

## Purpose
让 Buildr Harness 在不运行 Development 的情况下提供可独立装配的文件与 Git 工作台，使人与智能体面对同一份真实目录、工作树和文件，并能安全接手、审阅和完成本地工作。

## Requirements

### Requirement: 目录级功能可独立运行和组合

Harness MUST 提供独立的资源管理器和源代码管理（Source Control），两者 MUST 能单独装配，MUST NOT 要求创建对话、配置模型、运行 Development 或登记其工程对象。组合 MUST 对齐明确选定的目录或检出身份；打开或切换文件/Git 视图 MUST NOT 改绑对话、自动发消息或执行 Git 写入。Development MUST 能以工程范围复用通用视图并保留现有工程入口和行为。

#### Scenario: 无工程产品和对话的仓库
- **WHEN** 用户仅打开独立 Harness，选定一个本机 Git 工作树
- **THEN** 两个视图 MUST 能分别使用同一获准范围，展示实际文件/变更，不创建工程记录或发送消息

#### Scenario: 非 Git 目录及模块局部故障
- **WHEN** 工作目录不是准确选定的 Git 工作树根，或 Git 当前不可读
- **THEN** 资源管理器 MUST 仍可操作获准文件，源代码管理 MUST 显示实际局部原因，不替换范围或展示为仓库干净

### Requirement: 资源管理器使用准确来源和文件版本

资源管理器 MUST 支持获准目录的浏览、搜索及文件打开。可完整读取且允许编辑的 UTF-8 文本 MUST 可以保存；保存 MUST 核验目录、实际文件、内容版本及保护区块。目录替换、外部编辑、不可安全修改对象或失败 MUST 保留用户输入，禁止陈旧覆盖。Git 管理目录、范围外对象和不能确认地址的链接 MUST 不通过工作台访问或修改。

#### Scenario: 文件被外部编辑
- **WHEN** 人或智能体读取后另一入口修改该文件，旧观察随后尝试保存
- **THEN** 工作台 MUST 拒绝陈旧写入，保留本地草稿并提示重新读取核对

#### Scenario: 核验目录被替换
- **WHEN** 已选择目录的实际身份或链接发生变化
- **THEN** 文件和 Git 操作 MUST 拒绝使用旧引用，不自动改绑到新位置

### Requirement: 源代码管理核验本地 Git 动作

源代码管理 MUST 区分未暂存、已暂存及未跟踪变更，提供差异及固定提交历史。暂存、取消暂存和提交 MUST 是显式独立动作，核对工作树身份及已观察版本，本地提交只包含实际已核对的暂存范围。自动查询 MUST NOT 更新远端或修改检出，显式本地动作 MUST NOT 隐式推送、改变任务状态或清理工作树。未知写入 MUST 先核对 Git 当前事实，不能自动重放。其他关联工作树不可因 Git 发现、目录同名或任务旧链接而自动扩大授权。

#### Scenario: 保留其他未暂存内容
- **WHEN** 用户在独立 Harness 审阅两个文件，仅暂存其中一个再显式提交
- **THEN** 新提交 MUST 只含已核对的暂存变化，其他未暂存内容保持，远端不变

#### Scenario: 外部索引变更
- **WHEN** 从外部暂存或切换分支后，用户对旧观察发起操作
- **THEN** 工作台 MUST 阻止陈旧动作并提供重新读取，无静默混入别的变更

### Requirement: 对话工作区与对话共用导航

独立 Harness Web MUST 在对话信息流顶部将标题与消息正文左对齐，将更多操作和工作区开关放在同一内容栏的右端，开关位于更多操作右侧，不新增占位顶栏。左侧 MUST 按新建、当前对话、对话列表排序；点击当前对话不关闭工作区。右侧工作区展开时 MUST 通过统一的可调宽度分隔组件（`ResizablePanels` 与 `SplitDivider`）与对话区并排，并在桌面宽屏（>= 1172px）下支持与左侧对话列表及核心对话信息流同时展开形成三分屏，同时保证核心对话信息流保持可读最小宽度且窄宽度工作区下文件树不挤压阅读区。右侧工作区首页 MUST 提供“资源管理器”和“源代码管理”两个模块入口；打开模块后 MUST 在右侧以可独立关闭的标签呈现；“＋” MUST 在标签下方显示同一首页和所有模块，不隐藏已打开项；选择已打开模块 MUST 激活原标签，MUST NOT 重复创建或重置其内容；两个模块 MUST 能同时保持打开，切换活动标签 MUST 保留另一标签的阅读和编辑现场，关闭最后一个标签 MUST 返回首页，资源管理器不重复展示目录工具栏，完整目录位置仍可核对。

#### Scenario: 从对话进入文件或变更
- **WHEN** 用户打开工作区，先打开资源管理器，再用“＋”打开源代码管理
- **THEN** 对话仍在左侧，右侧 MUST 同时保留两个模块标签；切换时不丢弃未保存的输入，关闭任一标签不关闭另一标签

#### Scenario: 拖拽调节工作区宽度并保持三分屏协作
- **WHEN** 用户在桌面三分屏模式下打开右侧工作区并将工作区分隔条向左或向右拖拽
- **THEN** 工作区与对话区域 MUST 顺滑调整宽度并保留已打开标签与编辑状态，核心对话信息流始终保持不低于 520px，且当工作区缩窄到 560px 以下时资源管理器文件树按工作区宽度自适应而不挤扁阅读区域

### Requirement: 对话工作区跟随准确工作空间

独立 Harness Web MUST 在对话右侧提供可收起的工作区，分别提供资源管理器和源代码管理切换入口，文件或差异 MUST 在右侧内容区查看，不替换对话。工作区 MUST 按可独立装配的内容组织，新增内容不要求修改对话执行模型。

右侧 MUST 使用当前对话所属工作空间，或新对话已选工作空间所解析的目录；同一数据域内已登记的本地工作空间、默认工作空间（`@default`）和本机目录均 MUST 无需重复登记即可解析，且不要求 Development 进程在线。不能解析时 MUST 说明原因，MUST NOT 选用其他目录或沿用旧工作空间。无对话也无已选工作空间时 MUST 保留显式打开本机目录的能力。切换展示 MUST NOT 改写对话执行目录或丢弃未保存的文件输入。

#### Scenario: 切换两个不同工作空间的对话
- **WHEN** 用户从一个工作空间的对话切到另一个工作空间的对话
- **THEN** 右侧 MUST 保留已打开的模块标签及活动项，并切换到后者的准确目录，前者正在读取的结果、文件选择和差异 MUST NOT 显示为后者的内容

#### Scenario: 新对话尚未发送消息
- **WHEN** 用户已选择新对话的工作空间但尚未发送消息
- **THEN** 右侧 MUST 能直接打开该工作空间的文件或查看其 Git 状态，无需再次选目录或启动模型

#### Scenario: Development 未运行时打开已登记工作空间的工作区
- **WHEN** Development 进程未运行，独立 Harness 中打开绑定本地已登记工作空间或 `@default` 的对话（或选中对应新对话草稿范围）
- **THEN** 右侧对话工作区 MUST 能直接解析其准确目录并浏览文件或查看 Git 状态，无需再次添加工作空间

#### Scenario: 工作空间暂不可用
- **WHEN** 当前对话的工作空间无可用目录
- **THEN** 右侧 MUST 显示局部原因且对话仍可用，MUST NOT 自动替换成其他目录

### Requirement: 工作台按实际 Git 工作树浏览

独立 Harness MUST 无需 Development 或工程登记，从获准目录有界发现真实 Git 仓库。发现 MUST NOT 跟随范围外目录，且 MUST 区分没有结果与部分结果。对实际发现的仓库，Harness MUST 枚举其真实 Git 工作树，并允许显式选择；文件与 Git 面板 MUST 共用当前浏览来源且不改变对话执行位置。操作 MUST 按准确检出身份核对，不因同名或失效回退。其他仓库、任务范围及远端操作 MUST NOT 因发现而自动授权。

#### Scenario: 从另一工作树差异打开同名文件

- **WHEN** 用户选中关联工作树并从差异打开一个当前文件
- **THEN** 资源管理器 MUST 打开该检出下的文件；主目录中的同名文件和已打开草稿 MUST 保持独立

#### Scenario: 原检出消失

- **WHEN** 选中工作树已被移除、替换或不再属于原仓库
- **THEN** 读取和写入 MUST 拒绝旧身份，不得改用主工作树冒充

### Requirement: 文件工作台保留通用阅读现场

独立 Harness MUST 支持多个来源明确的文件标签及打开当前文件所在文件夹。大文本续读 MUST 携带同一版本；文件改变 MUST 提示重读，不拼接新旧内容。

#### Scenario: 续读和外部修改

- **WHEN** 用户继续读取一个未改变的大文件
- **THEN** MUST 读取下一段；若文件先被外部改动，MUST 拒绝旧版本续读

### Requirement: 通用目录源代码管理与工作树全生命周期操作
Harness SHALL 在不依赖 Buildr 研发任务、服务与登记代码库的前提下，针对用户选择的本地工作空间目录提供与 Development 一致的源代码管理与工作树操作能力，并作为两端的共享底座。

#### Scenario: 大型 Git 工作区准确发现代码库与全量工作树实时状态
- **WHEN** 用户在包含大量已追踪目录或 `.worktrees` 的目录打开目录工作台并读取源代码管理目录（`catalog`）
- **THEN** 系统通过 Git 感知扫描跳过已追踪目录与已知成员工作树子树，不误触发目录上限警告
- **AND** 为发现到的所有代码库的全部工作树成员并发返回实时分支、上游与未提交/未推送状态，不显示 `☁️? 📄?`

#### Scenario: 工作台工具栏不展示冗余工作树切换器且保持统一交互布局
- **WHEN** 用户处于目录源代码管理或资源管理器视图
- **THEN** 顶部标签行不再渲染独立的多余工作树下拉选择器，由右侧源代码管理栏与资源管理器选择器承担精确切换
- **AND** 源代码管理提供行内分支管理气泡、状态同步快捷按钮、工作树 `...` 菜单（含新建与移除工作树）、全局 `...` 批量菜单、提交历史分支/作者筛选、放弃更改确认、AI 生成提交说明、单行自动增高提交框与组合提交按钮、以及可实时编辑的差异编辑器

### Requirement: 通用目录资源管理器与共享编辑器会话
Harness SHALL 提供与 Development 一致的全局目录资源管理器与 CodeMirror 文件编辑器，并作为两端的共享实现底座，仅在折叠收起或无文件打开时保持界面简洁无冗余控制。

#### Scenario: 右侧目录树与单一对象标签栏协同及折叠态整洁展示
- **WHEN** 用户在资源管理器查看文件或折叠右侧目录树
- **THEN** 编辑器视图使用与源代码管理共享同一 `FileEditingSessionStore` 的 `FileEditingPane`，支持语法高亮、自动保存、保护块与外部变更三方冲突解决、Markdown 阅读/编辑预览及隔离 HTML 预览
- **AND** 标签行仅保留单一的已打开文件标签条与目录折叠开关，不在无文件且未折叠时显示冗余开关，也不在折叠态 44px 窄条内堆叠失效的刷新图标

#### Scenario: 研发侧复用底座并仅扩展工程能力
- **WHEN** Buildr Development 运行代码源代码管理与资源管理器页面
- **THEN** `buildr` 与 `buildr-web` 直接复用 `buildr-harness` 与 `buildr-harness-web` 导出的通用后端应用模块与前端工作台组件
- **AND** `buildr` / `buildr-web` 仅叠加研发登记仓库管理、任务作用域与 `Buildr-Task:` 尾注校验、工程规则目录提示与项目文档协同扩展，`buildr-harness-web` 不存在对研发侧或路由包的反向依赖

### Requirement: 独立工作台提供显式 Git 管理

Harness MUST 在当前检出下提供按观察版本执行的分支切换、普通工作树创建与移除、获取远程、同步和普通推送。移除 MUST NOT 删除分支或强制丢弃内容；本地提交 MUST NOT 自动推送。Development 复用通用实现，工程关系和交付策略 MUST 由工程宿主解释。

#### Scenario: 确认普通工作树移除

- **WHEN** 用户确认移除一个存在未保存改动、未跟踪内容或忽略文件的工作树
- **THEN** Harness MUST 拒绝移除并保留文件及分支

#### Scenario: 普通获取与推送目标漂移

- **WHEN** 用户在确认获取或推送前，所选检出或远程配置发生变化
- **THEN** 旧观察 MUST NOT 用于发起写入，用户可以重新核对实际目标

### Requirement: 活跃源代码管理反映实际 Git 拓扑

独立 Harness 和 DSH 内嵌的源代码管理 SHALL 在可见时自动观察当前目录的 Git 工作树和本地分支变化，合并更新并保留仍有效的查看位置；保留手动刷新。不得以对话开始替代真实 Git 观察。

#### Scenario: 左侧执行在后台创建工作树
- **WHEN** 用户留在对话区，当前目录的 Git 工作树或分支随后变化
- **THEN** 已展示的源代码管理无需重新取得焦点即可更新；不会切走仍有效的工作树，不显示其他空间的观察结果

### Requirement: 对话列表与资源管理器使用一致的搜索控件

对话列表 SHALL 省略独立标题行并保留操作、状态与模型统计；单行模型信息只在延迟停留或键盘访问时显示，不改变列表排版。资源管理器和对话列表 SHALL 共用输入与下拉呈现，分别保留查询语义。

#### Scenario: 切换下拉选项
- **WHEN** 用户更换对话工作空间，或在资源管理器选择文件名或内容
- **THEN** 对话立即使用新范围（包含空关键词）；资源管理器的选择只显示于下拉及输入提示，没有有效输入不搜索，有有效输入时用所选模式搜索

### Requirement: 工作台先展示仓库清单再分批核对

目录工作台 MUST 优先显示获准工作空间根内的登记仓库；普通目录 MUST 先做有界浅层发现。待核对仓库 MUST 可点选并优先读取，状态逐库更新；写入仍 MUST 按已核对 Git 身份授权。更深扫描 MUST 显式继续，并区分待继续、读失败与确认没有仓库，MUST NOT 把正常待继续显示为读取失败。

#### Scenario: 已登记的第二层仓库
- **WHEN** 已登记工作空间有多个第二层仓库
- **THEN** MUST 不依赖深扫先显示这些仓库，并在有界并发下逐库核对。

#### Scenario: 普通目录继续发现
- **WHEN** 用户在普通目录浅层发现后要求继续
- **THEN** MUST 从原有有界扫描进度继续，保留已显示来源；过期或跨作用域的游标 MUST NOT 用于访问其他目录。
