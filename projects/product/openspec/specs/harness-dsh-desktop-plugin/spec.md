# harness-dsh-desktop-plugin Specification

## Purpose
定义 DSH 桌面如何打开完整的 Harness 工作区，以及开发插件如何仅连接经过核验的本机 Harness 实例，保留双方各自的配置和执行状态。

## Requirements

### Requirement: DSH 桌面提供独立的 Harness 主工作区

开发插件 SHALL 通过受支持的 DSH 桌面面板入口展示完整独立 Harness Web。该页面 MUST 使用 Harness 的原有账号、对话、权限、目录与执行接口，不需要 DSH 对话，不跳转外部浏览器。返回入口 MUST 还原 DSH 画面；切换本身不得开始或停止任一套执行。

#### Scenario: 在 DSH 打开 Harness 后再返回
- **WHEN** 用户从受支持的 DSH 桌面入口进入已绑定的 Harness、返回并再次进入
- **THEN** 整块工作区显示 Harness 服务的真实网页，DSH 的输入框不参与操作，同一窗口保留 Harness 的页面和原运行

### Requirement: 开发包仅委托已绑定的本机 Harness

开发插件 MUST 独立于 Development 插件，采用显式本机安装身份与数据域。桌面客户端 MUST 经宿主的本机认证和隔离网页租约进入准确的环回网页；普通 Web 客户端、鉴权失败或不匹配目标不得取得进入票据。插件不得打包另一份 Harness、削弱网页来源限制或修改日用配置。

#### Scenario: 缺少桌面桥或绑定不可用
- **WHEN** 非桌面客户端加载插件，或用户点击入口但明确绑定无法核验
- **THEN** 插件不得从另一配置域启动或发放会话票据；已绑定的其他入口和执行保持原状

### Requirement: Harness 与 DSH 原生右栏按工作空间协作

开发插件 MUST 让同一 Harness 工作空间内的对话共用目录已核验的原生 DSH 会话右栏，跨工作空间切换时 MUST 使用对应的真实绑定。插件 MUST 优先复用仍有效的已记住会话；没有有效绑定时，对已经就绪的会话目录清单，只在同目录可用会话中自动连接并记住，优先使用当前打开的同目录会话，否则沿用同目录最近活动的会话。零条时 MUST 保留 Harness 自有工作区；不得要求用户选择会话，不按名称或父子目录匹配。已归档、子智能体、需要迁移或被另一工作空间绑定的会话不得作为候选。未就绪、无绑定或目录不匹配时 MUST 不显示其他工作空间的原生工具。插件不得为打开工具创建 DSH 会话、发送消息或更改其执行目录。

#### Scenario: 进入工作空间时默认匹配
- **WHEN** 首次打开一个工作空间且恰有一条可用同目录会话，之后 DSH 在同目录新增另一条会话
- **THEN** 初次自动连接，之后仍复用已记住的会话；若第一次已有多条，优先当前同目录会话，否则使用同目录最近活动的会话，不从其他空间搬来标签

#### Scenario: 同空间及跨空间切换
- **WHEN** 用户先切换同空间的两条 Harness 对话，再切换到另一个有绑定的空间，最后返回
- **THEN** 同空间切换保留原生标签和终端；跨空间使用另一准确绑定且不移动既有终端；返回可看到原右栏

#### Scenario: 使用 Buildr 工作台标签
- **WHEN** 在已绑定右栏中从开始页、其他分栏或浮窗重复打开资源管理器或源代码管理，或在已打开的工具标签内触发宿主刷新快捷键（如 macOS `Cmd + R`）
- **THEN** 资源管理器与源代码管理在开始页使用原生入口样式，分别显示文件夹与分支图标；开始页入口及右栏顶部标签（包括从本地持久化布局恢复的历史标签）均显示无 `Buildr ` 前缀的「资源管理器」与「源代码管理」；每类工具在当前工作空间最多一个模块标签，打开已有项时聚焦原标签；聚焦于对应工具标签时按刷新快捷键可刷新该标签内容且不影响原生浏览器；浏览器、终端保留多标签

#### Scenario: 只在 Harness 显示工具入口
- **WHEN** 用户在可用的 Harness 工作空间、DSH 原生会话或无匹配右栏之间切换
- **THEN** 「开始」和「更多工具」仅在已连接当前 Harness 工作空间时提供资源管理器与源代码管理入口；切换不得关闭已有标签或改变原生工具。

### Requirement: Harness 普通网页链接沿用 DSH 偏好

开发插件 MUST 让用户直接点击的普通 HTTP(S) 链接（包括账单）在使用 DSH 时遵循宿主既有偏好；不可用时 MUST 提供明确外部打开或复制路径，不转发任意 guest 弹窗。文件、认证回调和原执行不受该策略改变。

#### Scenario: 同一账单链接在两种偏好下打开
- **WHEN** 用户分别选择应用内侧边栏与默认浏览器后点击账单链接
- **THEN** 前者使用当前工作空间的 DSH 浏览器新标签，后者交给系统默认浏览器，原对话与草稿不变

### Requirement: Harness 仅替换 DSH 中栏

Harness MUST 保留 DSH 原生左栏、右栏及开合；在 macOS 下不得在系统窗口控件或收起左栏后的宿主按钮上布置可遮挡控件，不得永久增加带操作按钮的工具栏，同时 MUST 在中栏顶部安全留白区提供支持 DSH 原生窗口拖拽与双击放大/缩小的轻量工作台顶栏（展示 Buildr Harness 图标、名称、开发标识及当前工作空间名称，中间与右侧保留空白拖拽区，并在左栏收起时自动向右避让）。右栏开合和返回 DSH MUST 分别位于对话标题操作和更多菜单；桥接不出现绑定步骤。左栏打开原生会话或其他原生页面时 MUST 交回原生界面，不改写对话或重载保留的 Harness 输入。

#### Scenario: 原生导航与窗口调整
- **WHEN** 用户进入 Harness、折叠或展开两侧、在中栏顶栏空白处拖动或双击窗口，再从左栏打开原生会话并重新进入 Harness
- **THEN** Harness 主工作区只占中栏下方区域，macOS 顶部轻量顶栏清晰显示当前名称与工作空间且左栏收起时自动右移避让不遮挡系统红绿灯和左栏按钮，空白处可正常拖动窗口与双击放大/缩小 DSH，两侧仍由 DSH 管理，Harness 对话和草稿保持

### Requirement: 自举采用同工作空间的 DSH 开发插件

自举 SHALL 在已交付范围命中开发插件包输入时更新本工作空间已安装的同源 DSH 开发插件。不得注册新插件、改绑其他工作空间、更新正式版或发布。默认 MUST 不停止桌面进程；只有用户显式选择重开开发插件宿主且确认同源实例，才可请求正常退出。安装证明与桌面加载证明 MUST 分开。

#### Scenario: 交付开发插件且 DSH 仍在运行
- **WHEN** 自举确认同源插件且桌面仍运行，或无法确认其已退出
- **THEN** 已准备的候选可在 DSH 退出后采用；报告待安装，不改目标配置也不强退 DSH

#### Scenario: 只更新 Harness 网页
- **WHEN** 未改变插件包输入
- **THEN** 自举不因网页构建或提交号变化重装该插件

#### Scenario: 执行前检查更新范围
- **WHEN** 操作者对准确交付范围请求自举预检
- **THEN** 同一分类器列出适用的工作空间、开发运行（含 Harness）及 DSH 插件操作依据，不执行同步、构建、推送或换装

#### Scenario: 仅接续 DSH 待换装
- **WHEN** 使用同一交付的原完整结果接续，已验证其他阶段成功且此前因 DSH 尚运行而未尝试安装
- **THEN** 自举复核交付、保留检出和已安装插件，然后只尝试插件操作，不重复网页更新、同步和推送；若源码或绑定不匹配则不换装

#### Scenario: 显式更新插件并重开已绑定的 DSH
- **WHEN** 交付确实需要换包，用户发起重开，且自举核对当前桌面与开发包、配置及 Harness 数据域匹配
- **THEN** 独立执行器 MUST 在候选就绪后正常请求退出，确认退出后换包，并以原开发绑定重开；分别核对安装与插件宿主加载。绑定不明、拒绝退出或未验证退出时 MUST 保留待安装，不强杀。

### Requirement: 正式与开发入口使用相应 Harness

正式插件 SHALL 核对本机正式安装与启动身份，通过受认证桌面桥连接对应 Harness；开发插件 SHALL 显示 Buildr Harness Dev 并连接已明确配置的开发域。两者在 DSH 左侧入口均 SHALL 使用 Buildr Harness 官方彩色 H 品牌图标（无白底方框）。缺失、漂移或不兼容时 MUST 提供修复及复查入口，不静默安装、升级或接管其他实例。

#### Scenario: 先装插件后装 Harness

- **WHEN** 用户打开正式插件而正式 Harness 未就绪，随后按提示安装并重试
- **THEN** 插件 MUST 从缺失状态转为连接核验后的正式 Harness，无须重装插件

### Requirement: 以能力判断 DSH 兼容并保全开发更新

开发和正式插件 MUST 将宿主兼容范围及准确验收版本分别记录，不把一个精确 RC 写成唯一允许版本；缺少必要能力 MUST 不阻断 DSH 原生工作。开发 Harness 的兼容更新 MUST 不依赖重装 DSH 插件或重启 DSH；已打开页面换版 MUST 保全草稿、未保存编辑与活动执行。

#### Scenario: 开发 Harness 更新而插件不变

- **WHEN** 已明确绑定的开发 Harness 完成兼容激活
- **THEN** 新打开的页面 MUST 可用新版，未交互的已打开开发页面 MUST 自动静默刷新采用新版，已交互页面 MUST 保留现有工作而不显示底部刷新提示条或额外菜单刷新按钮，且在 Buildr Harness 中栏随时可通过宿主刷新快捷键（macOS 默认 `Cmd + R`）刷新当前页面并保留未保存保护、不抢占右栏原生浏览器或弹窗焦点，不重启 DSH
