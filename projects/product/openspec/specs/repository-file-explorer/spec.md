# repository-file-explorer Specification

## Purpose
定义当前工作空间（Workspace）已登记代码库（Repository）的完整文件浏览与只读观察能力，包括稳定身份、已核对物理位置或历史版本、目录与内容读取边界、搜索阅读和任务定位，使人和智能体（Agent）能查看同一代码现场而不依赖外部编辑器。

## Requirements

### Requirement: 资源管理器覆盖全部已登记代码库
系统 MUST 以当前工作空间的代码库实例（Repository Instance）登记作为选择范围，提供全部实例的名称与可用状态；普通入口不以当前任务或项目自动过滤；首版 MUST 支持代码库多选筛选，空筛选表示全部实例，多个已选实例按根分别展示完整文件树，不按任务改动文件或服务模块路径裁剪，不按远端地址归并不同实例。读取 MUST 按所选实例及已核对位置执行，MUST NOT 自动克隆、切换分支（Branch）、修改登记或生成任务。

#### Scenario: 在任务外浏览代码
- **WHEN** 用户直接进入代码区域并选择一个未关联当前任务的代码库
- **THEN** 系统 MUST 允许浏览该实例当前可读目录中的文件，且不要求先选择任务

#### Scenario: 某个代码库不可用
- **WHEN** 一个已登记实例缺少本机目录或目录不可读取
- **THEN** 系统 MUST 保留该实例身份并显示局部状态，其他代码库仍可选择和查看

#### Scenario: 代码库范围可以扩展与清除
- **WHEN** 用户多选几个代码库或清空已选范围
- **THEN** 系统 MUST 分别显示所选实例的完整文件树，清空后恢复当前工作空间全部实例
- **AND** 已打开文件 MUST 保留；范围外仍在阅读的文件 MUST 明确标识并允许主动加入范围，不能静默改写筛选

### Requirement: 目录和文件读取受明确位置限定
目录、文件和搜索请求 MUST 指定当前工作空间的已登记实例、可核对的查看位置及规范化相对路径；服务端 MUST 验证位置身份及实际路径包含关系，拒绝绝对路径、路径穿越、越界符号链接（Symbolic Link）和 Git 管理目录访问。目录枚举与文件正文 MUST 按需读取，结果 MUST 返回实际观察版本、内容种类和完整性边界；读取 MUST 不产生文件或 Git 写入。

#### Scenario: 请求越出所选代码库
- **WHEN** 请求包含绝对路径、上级越界片段或通过符号链接跳到外部目录
- **THEN** 系统 MUST 拒绝该请求并保持代码库、任务与文件不变

#### Scenario: 目录和正文使用不同读取
- **WHEN** 用户展开文件夹但未选择其中的文件
- **THEN** 系统 MUST 只返回该目录的有界条目，不预读全部后代文件正文
- **AND** 只有明确选择文件或执行内容搜索时才读取必要正文

#### Scenario: 大文件或不支持类型
- **WHEN** 所选文件超过读取上限或无法用支持的文本/图片方式展示
- **THEN** 系统 MUST 明确表达实际大小、上限或类型及可用预览，MUST NOT 把截断内容标为完整文件

#### Scenario: 文本完整读取范围为五MiB
- **WHEN** 当前文件或明确历史提交中的普通文本文件不超过5 MiB
- **THEN** 系统 MUST 返回完整正文
- **AND** 超过5 MiB的文本 MUST 显示真实大小与大文件告警，并允许按约512 KiB的有界段读取，图片读取上限保持8 MiB

#### Scenario: 大文件分段保持同一观察版本
- **WHEN** 用户继续读取大文件的上一段或下一段
- **THEN** 系统 MUST 仅返回并展示当前段，保留真实字节范围、全局行号与跨段续行提示，有效UTF-8字符不得被边界破坏或重复
- **AND** 续读 MUST 核对已观察文件版本，当前磁盘文件变化时 MUST 明确拒绝并要求重新读取，历史文件 MUST 固定到同一完整提交和对象
- **AND** 定位或读取超时、页码/行号超界 MUST 明确返回局部诊断，MUST NOT 把未读内容或不同版本拼为完整文件

#### Scenario: 大文件搜索匹配定位到实际段
- **WHEN** 搜索匹配不在大文件当前显示段
- **THEN** 系统 MUST 读取真实行及首次字面匹配所在段并显示全局行号与可见命中，超长行仍须按实际命中字节定位；命中跨段时 MUST 明示并高亮当前段可见部分
- **AND** 部分Markdown MUST 以源码段表达，协作指令 MUST 包含当前段范围与观察版本，MUST NOT 宣称完整正文

### Requirement: 资源管理器支持目录搜索与多文件阅读
资源管理器 MUST 支持展开目录、文件名搜索、有界内容搜索、源码行号、Markdown 阅读与原文、常见图片预览及多个文件标签。搜索 MUST 显示匹配文件及适用行位置，说明覆盖或截断；忽略文件显示可以切换。当前所选目录和版本 MUST 可见，文件身份 MUST 同时区分实例、查看位置或版本及相对路径。

#### Scenario: 从内容匹配进入文件
- **WHEN** 用户选择内容搜索的一条结果
- **THEN** 系统 MUST 打开该来源的完整文件并定位匹配行；清除搜索后仍可继续浏览当前目录

#### Scenario: 两种搜索均显示文件所在路径
- **WHEN** 文件名或内容搜索返回匹配文件
- **THEN** 页面 MUST 在文件名下显示相对于该代码库根的文件路径，单行省略时 MUST 能查看完整路径
- **AND** 折叠匹配行时路径 MUST 保持可见；文件名搜索点击文件块或路径 MUST 打开文件，内容搜索点击文件块或路径 MUST 只展开/折叠匹配，点击具体匹配行才定位阅读，两者均不得重新搜索；实际绝对目录继续由查看位置表达

#### Scenario: 搜索保留结果且不受旧累计扫描预算裁剪
- **WHEN** 用户搜索当前代码库中一个普通文本文件里的字面内容，并连续打开匹配结果或切换同一来源的文件
- **THEN** 系统 MUST 使用 ripgrep 搜索完整的未忽略普通文件范围，不因旧的累计文件数、字节数或短扫描预算遗漏普通源码
- **AND** 系统 MUST 保留当前结果；仅查询、范围、版本或忽略条件变化以及主动刷新才重新执行，超时、输出或结果上限 MUST 如实提示覆盖不完整

#### Scenario: 阅读布局与产品其他文档一致
- **WHEN** 用户切换 Markdown 阅读/原文或展开阅读后恢复分屏
- **THEN** 阅读 MUST 沿用产品统一的 1200px 正文限宽，原文 MUST 使用满宽源码视图
- **AND** 右上角 MUST 使用一致的“展开阅读 / 恢复分屏”交互，保留当前文件、搜索结果和目录宽度，分隔边界不得因命中区域形成空白带

#### Scenario: 文件内的多条搜索匹配可独立定位
- **WHEN** 同一个来源文件具有多个匹配行
- **THEN** 系统 MUST 按来源文件聚合结果，文件名后显示所属代码库，默认展开全部匹配文件，允许独立折叠和展开该文件的多条匹配
- **AND** 每条匹配 MUST 保留真实行号和包含命中文字的摘要；点击时右侧 MUST 定位对应行并同时高亮该行及实际命中文字，字面匹配不能误作正则表达式（Regular Expression）
- **AND** 不同代码库的同名文件 MUST 保持独立，折叠/展开和打开匹配 MUST NOT 重复执行相同搜索；文件数、匹配行及执行/输出限制触发时 MUST 明示部分覆盖

#### Scenario: 人工搜索达到最小输入且结果保持可查看
- **WHEN** 用户在网页输入文件名或内容查询
- **THEN** 系统 MUST 去除两端空白并在至少两个非空白Unicode字符时才执行搜索，不足时提示门槛且不保留旧匹配结果
- **AND** 每个代码库 MUST 最多返回100个匹配文件、200条匹配行，触发上限时 MUST 引导缩小关键词或范围，命令行（CLI）和网页接口（API）仍兼容明确的单字符查询

#### Scenario: 查看位置与忽略开关说明真实文件范围
- **WHEN** 用户选择代码库目录、任务关联目录或历史提交，或切换忽略文件显示
- **THEN** 页面 MUST 明确显示实际路径，并解释代码库目录是登记位置的实时文件、任务关联目录来自已核对任务位置，两者不汇总其他工作树
- **AND** 忽略开关 MUST 只包含所选目录中被Git规则或常见构建目录排除的内容，隐藏名称本身不得成为忽略条件，Git管理目录始终不可浏览，不得以其他目录的文件补足当前目录

#### Scenario: 顶栏与文件标签沿用已有分屏样式
- **WHEN** 用户在代码区域查看文件树和多个文件标签
- **THEN** 顶栏 MUST 与其他区域保持43px高度，通过短竖线区分内容组，文件标签 MUST 使用与工作空间对象阅读相同的组件（Component）和样式

#### Scenario: 多个来源具有同名文件
- **WHEN** 用户打开两个实例或两个工作目录中同名的文件
- **THEN** 系统 MUST 保留可区分的文件标签和位置，切换时展示各自内容，MUST NOT 按相对路径覆盖另一份文件

#### Scenario: 明确重新读取
- **WHEN** 其他入口改变文件后用户执行重新读取
- **THEN** 系统 MUST 返回当前观察版本及正文，MUST NOT 使用其他来源或失败响应冒充成功内容

### Requirement: 任务入口保留准确文件现场与返回状态
任务到资源管理器的定位 MUST 使用任务公开范围、稳定代码库关联及已核对工作树（Worktree）身份，明确选择实际工作目录；历史文件 MUST 绑定明确完整提交（Commit）标识。缺失或身份不明 MUST 显示局部诊断，MUST NOT 按分支名、目录名或同名文件猜测。任务阶段、审阅选择、筛选与阅读位置 MUST 在返回时恢复；定位 MUST 不修改任务记录。

#### Scenario: 任务服务预选代码库范围
- **WHEN** 用户在任务点击“查看源文件”
- **THEN** 系统 MUST 沿任务显式服务的代码库引用收集并去重实例，预填资源管理器的普通代码库筛选；只有项目范围时 MUST 沿已登记项目服务集合解析
- **AND** 所选代码库 MUST 展示完整文件树，用户 MUST 可以更改或清空范围，不限于本任务改动或提交文件

#### Scenario: 任务未确定服务范围
- **WHEN** 任务没有可确定的服务或项目范围，或部分引用失效
- **THEN** 系统 MUST 明确说明未能预选的原因；无确定范围时显示全部代码库，部分引用失效时保留已解析结果与局部诊断
- **AND** MUST NOT 从分支、目录命名或当前文件猜测任务关联，也不得改变任务范围

#### Scenario: 从未提交改动阅读完整实现
- **WHEN** 用户从任务当前改动打开完整文件
- **THEN** 资源管理器 MUST 定位对应代码库与实际改动目录，并允许继续浏览同一目录中的关联文件
- **AND** 返回任务 MUST 恢复原来的阶段和审阅选择

#### Scenario: 所选历史内容不存在
- **WHEN** 文件属于已删除内容、提交不可读取或相应位置身份已漂移
- **THEN** 系统 MUST 显示该来源的真实缺失或错误，MUST NOT 静默改读当前目录的同名文件

### Requirement: 人与智能体共享只读代码观察能力
代码文件能力 MUST 提供确定性的命令行接口（CLI）与网页接口（API），声明作用实例、位置/版本、输入、输出、无写入副作用、读取上限和失败边界。界面生成的文件协作指令 MUST 携带同一文件身份、实际观察版本和适用行范围；智能体（Agent）继续工作前 MUST 能重新核对当前文件。

#### Scenario: 从阅读区交给智能体
- **WHEN** 用户在当前文件选择行范围并请求解释或提出修改
- **THEN** 页面 MUST 生成含文件位置、观察版本与范围的指令，不直接执行修改、不创建任务或发送未授权消息

#### Scenario: 两个入口核对同一文件
- **WHEN** 网页和命令行接口以相同实例、位置和版本读取同一文件
- **THEN** 两者 MUST 使用同一只读应用能力并表达对应观察结果与局部失败，不能形成两份独立代码事实

### Requirement: 代码库与工作树联动筛选
资源管理器 MUST 允许多选代码库与单选已观察的工作树（Worktree）组。代码库候选 MUST 由所选组的真实成员限定，组候选 MUST 由所选代码库限定；代码库多选取并集，再与所选单个组取交集。首次进入及未选择工作树（Worktree）时 MUST 查看各实例主目录；清空工作树（Worktree）MUST 恢复各实例主目录，清空代码库 MUST 表示全部实例。跨库成员 MUST 分别展示完整文件树，并按具体来源区分搜索结果及文件标签；范围变化 MUST NOT 改写已打开文件的内容或来源。

#### Scenario: 两种选择顺序得到相同范围
- **WHEN** 用户先选代码库再选相关工作树（Worktree），或先选工作树（Worktree）再选成员代码库
- **THEN** 候选只包含对方条件真实关联的对象，最终展示相同交集

#### Scenario: 默认及清空
- **WHEN** 用户直接进入资源管理器，随后清空工作树（Worktree）选择
- **THEN** 首次只展示各代码库登记主目录，清空后仍展示当前代码库范围中各实例主目录，不更改代码库或Git

#### Scenario: 切换同库工作树
- **WHEN** 一个代码库存在主目录和两个工作树（Worktree），用户从其中一个组切换到另一个组，且各自具有同名文件
- **THEN** 当前文件树及搜索 MUST 只展示所选组，已打开文件标签 MUST 保留各自具体来源及对应内容；将范围外文件加入查看时 MUST 切换到该文件实际来源组

### Requirement: 工作树分组与明确检出身份
系统 MUST 从已登记代码库的真实Git工作树（Worktree）登记发现目录。跨库任务组 MUST 依据已核对任务关联证据建立并使用统一名称，MUST NOT 仅凭分支（Branch）、目录或显示名称归并。无任务关联的原生工作树（Worktree）MUST 可独立选择。目录、搜索、正文与协作输入 MUST 保持已观察的具体检出身份；选中目录不存在或同路径重建时 MUST 返回局部诊断，MUST NOT 静默替换为主目录或其他同名文件。固定历史提交（Commit）读取 MUST 不依赖原工作树（Worktree）继续存在。

#### Scenario: 同任务跨库关联
- **WHEN** 一个任务有两个实际代码库工作树（Worktree）成员
- **THEN** 页面 MUST 以一个任务名称单选项关联两个成员；代码库筛选仍分别保留实例身份

#### Scenario: 名称相同但关联不同
- **WHEN** 两个原生工作树（Worktree）显示相同分支（Branch）或目录名称且无共同任务证据
- **THEN** 系统 MUST 独立展示，不能按名称合并

#### Scenario: 来源消失或被重建
- **WHEN** 人选择的工作树（Worktree）在后续读取前被移除，或同路径被另一检出位置替代
- **THEN** 该来源 MUST 明确失败，其他来源继续可读，保留原文件身份且不改读同名文件

#### Scenario: 任务预选及改动实际来源
- **WHEN** 用户从有实际工作树（Worktree）的任务查看源文件，或从任务主目录独有改动打开完整文件
- **THEN** 普通入口 MUST 预选任务关联组与相关代码库；具体文件 MUST 以改动实际检出身份为准，目录和关联文件继续使用同一来源；主目录文件 MUST 只选择主目录组，不同时选择任务组
