# harness-web-composition Specification

## Purpose
定义完整 Harness 对话功能在独立网页、Development 专注及内嵌模式中的共享边界，以及独立回环网页的唯一监听、身份发现、登录和代次交接，使用户在两产品中使用同一事实而不复制核心行为。

## Requirements

### Requirement: Harness 必须提供完整唯一对话并支持公开同页装配

系统 MUST 将对话导航、历史、消息、工具展示、输入、附件、发送、模型与账号设置、问题、审批、停止、接续和恢复全部实现在 buildr-harness-web。独立 buildr-harness-ui 包 MUST 删除；Development MUST 通过公开完整对话组件入口装配，MUST NOT 导入内部组件重组对话或执行状态容器。第一方组合 MUST 使用同一 React 页面树，不加载对话 iframe；独立完整网页入口 MUST 继续可用。

Development 的 harness-ui 模块 MUST 只准备工程现场、选择工作空间、挂载完整对话、维护任务关联和工程导航；任务选择控件 MUST 由 Development 提供并通过语义上下文插槽原位呈现，MUST NOT 依赖跨窗口坐标覆盖。Harness MUST 不管理工程任务状态。Development MUST NOT 在外壳复制第二套收起态对话导轨、窄屏对话入口或分屏宽度分隔条；展开态与收起态导轨、分屏宽度分隔条 MUST 均由 buildr-harness-web 唯一提供并向宿主同步开合、宽度与停靠方位，Harness 通用对话与对话列表能力 MUST NOT 以专注模式或分屏模式作为功能门控。

上下文插槽 MUST 是可选工作上下文区域，而非工程任务专属空位；未提供内容时 MUST NOT 保留固定任务占位。文件能力与工作对象打开 MUST 由产品装配显式接入，Harness MUST NOT 将通用打开入口写死为 Development。通用资源管理器和源代码管理 MUST 由 Harness 提供可分别装配的入口；Development MUST 提供准确工程范围，在原导航与文件深链上复用通用界面，并继续拥有任务、跨库编排与交付。模块 MUST NOT 依赖对话对象、Development 私有状态或未装配的相邻模块；不新增通用插件路由或 DSH 适配。

#### Scenario: 相同网页服务两种产品
- **WHEN** 用户独立打开 Harness 或在 Development 使用内嵌/专注模式
- **THEN** 页面 MUST 复用同一完整对话实现，Development 不实现第二套对话控制

#### Scenario: 工程上下文交接
- **WHEN** Development 选择工作空间并新建对话
- **THEN** Development MUST 提供准确工作范围，Harness 自己创建对话并拥有执行交互；选择不自动发送模型消息

#### Scenario: 页面通信校验
- **WHEN** 页面接收非准确父/子窗口、错误 origin 或未知协议消息
- **THEN** 接收方 MUST 忽略消息，不改变选择或触发执行

#### Scenario: 显式工程操作只由 Harness 提交
- **WHEN** 用户在 Development 发起已授权的工程上下文交接
- **THEN** Development MUST 用准确请求身份交给 Harness 处理，Harness 自己维护首次提交及恢复；响应未知不得自动重发

#### Scenario: 工程业务独立工作
- **WHEN** 工程页面未装配 Harness 网页
- **THEN** 任务、知识和代码事实 MUST 可独立读取，不隐式创建执行

#### Scenario: 真实工程区域挂入外壳
- **WHEN** Development 装配入口提供现有工程页面和完整对话组件
- **THEN** Harness 通用外壳 MUST 承载双方，工程区域开合不卸载对话，工程页面不能包含第二个对话实例
- **AND** 同页工程导航 MUST 展开工程区域，但不得改变已有对话的准确执行范围

#### Scenario: 工程抽屉随所属区域隐藏
- **WHEN** 用户切换离开保留的工程页面，或收起其工作环境
- **THEN** 该区域打开的工程编辑抽屉 MUST 同步隐藏，不遮挡当前区域；重新展开后 MUST 恢复未保存草稿而不写入业务数据

#### Scenario: 同页工程上下文与链接
- **WHEN** 用户在完整对话内查看任务关联或点击文件、工程对象链接
- **THEN** 对话 MUST 分别通过明确文件能力或工作对象接口请求打开；当前 Development 装配 MUST 核验准确工程来源，工程控件 MUST 在可选上下文插槽中渲染，不使用窗口消息执行同页工程动作

#### Scenario: 同页装配与状态保全
- **WHEN** 用户切换工程路由、专注或分屏及环境开合
- **THEN** 同页完整对话 MUST 保持同一实例、执行身份、草稿及阅读位置，不重复发送或创建执行

#### Scenario: 工程上下文局部失败
- **WHEN** Development 提供的工程上下文组件渲染失败
- **THEN** 页面 MUST 在该插槽显示局部不可用提示，完整对话输入、观察及停止控件 MUST 保持同一实例且可用

#### Scenario: 收起态复用唯一导轨与分屏左右停靠
- **WHEN** Development 收起对话面板，或在分屏模式菜单切换“对话移到最左侧 / 对话移到右侧”
- **THEN** 页面 MUST 保留唯一的 Harness 导轨与宽度分隔条而不渲染宿主重复导轨或分隔条
- **AND** 收起态悬停“展开当前对话” MUST 展示暂看浮层（Peek），左/右停靠切换 MUST 真实移动整个分屏对话区到工程区域对应一侧并在刷新后保持

### Requirement: 多入口必须共享持久事实而不覆盖未提交输入

同一 Development 页面切换专注/内嵌或业务页面时 MUST 保留对话身份、未提交草稿、选择和阅读位置，不改执行目录。不同窗口及 origin MUST 通过服务端修订同步持久事实；未经明确设计的未提交本地文字 MUST 不跨窗口互相覆盖。缓存与事件 MUST 按稳定数据域、来源范围、对话和适用代次隔离。多入口重复答复、发送或停止 MUST 沿同一幂等和准确版本边界处理。

#### Scenario: 同页模式切换
- **WHEN** 用户在输入或阅读中切换专注与内嵌模式
- **THEN** 输入、滚动和当前对话 MUST 保持，模式变化不发起执行

#### Scenario: 两窗口各有草稿并共同答复
- **WHEN** 两窗口编辑各自未提交文字，并同时回复同一待决请求
- **THEN** 本地文字 MUST 不互相覆盖；准确请求只消费一次，另一请求明确返回已处理或版本冲突

### Requirement: 独立网页只能按明确入口意图启用

独立 Harness Web MUST 有可托管的生产静态产物，提供完整唯一网页和前置的唯一 API。仅使用 Development 时 MUST 默认不监听独立 Harness 网页端口，内嵌和专注 MUST 通过 Development 受认证的同源路径托管该网页并使用同一 API。用户显式打开独立 Harness 时，MUST 允许在同一逻辑服务中启用一个独立回环网页入口，包括两产品同装、同开；它 MUST 不创建第二个执行核心、目录宿主进程或对话库。内部通信和模型网关端口 MUST 不作为浏览器接口公开。

#### Scenario: 只打开 Development
- **WHEN** 用户仅从 Development 使用内嵌或专注模式
- **THEN** 浏览器 MUST 只访问 Development origin，独立 Harness 网页监听器默认不启动

#### Scenario: 同时打开独立网页
- **WHEN** 用户在 Development 已运行时显式打开独立 Harness
- **THEN** 两产品页面 MUST 能并存并观察同一服务资料；独立入口不得抢占 Development 端口、关闭其网页或被重定向成 Development 页面

### Requirement: 网页端点必须在兼容换代时唯一交接

独立网页端点 MUST 归逻辑数据域而非 npm 目录或临时执行代次；只有当前被授予监听权的代次能提供该入口。兼容升级 MUST 保持 origin 和未失效的页面会话，旧代次只保留原执行与私有控制通道，不保留第二个公开监听器。交接允许短暂断线，MUST 保留输入、准确请求身份和事件恢复基线；未知写入不得重发。不能确认释放或地址被其他程序占用时，MUST 报告局部入口不可用，不强杀占用者或发布虚假就绪。

#### Scenario: 旧轮仍运行时换代
- **WHEN** 兼容新版接收新工作而旧代次仍持有轮次
- **THEN** 网页 MUST 经交接后的同一 origin 观察并控制原轮，静态资源和会话保持声明的兼容性，不迁移或重放原执行

#### Scenario: 切换失败或端口被占用
- **WHEN** 新监听未就绪、旧监听释放未知或原地址由其他进程占用
- **THEN** 系统 MUST 保留准确失败和原工作，不宣称网页 ready、不并行争抢；仅在已证明监听权和兼容条件后恢复入口

### Requirement: 启动登录必须绑定准确网页入口而不泄露服务秘密

本机入口 MUST 从受保护的实例发现及就绪观察取得准确地址，不能只根据端口或 PID 信任页面。登录引导 MUST 使用短时单次、绑定产品/数据域/目标端点的票据或等价认证能力，不能向浏览器交出后台主令牌、模型凭据或宿主秘密。独立与 Development 页面会话 MUST 分离；鉴于回环地址不同端口的 Cookie 不隔离，独立入口 MUST 对会话命名和范围隔离并核验 Host/Origin，不能仅依赖 SameSite。有效会话在兼容换代后继续校验当前有效期和撤销状态。页面会话 MUST 使用有限的不活动窗口（30 天）并按认证活动滑动续期；续期 MUST NOT 使票据可重复使用，MUST NOT 恢复已撤销或已换绑撤销的会话。会话有效时加载页面文档 MUST 同步刷新浏览器 Cookie 寿命，Cookie MUST NOT 先于服务端会话失效。

#### Scenario: 登录引导与重复打开
- **WHEN** 启动入口确认准确服务和网页已就绪并打开浏览器
- **THEN** 票据 MUST 只兑换一次有限页面会话；重复点击复用现有入口，不创建后台或重复工作
- **AND** 过期、被重复消费或目标不符的票据必须拒绝，日志、URL query 和转发头不得含长期秘密

#### Scenario: 同机另一 origin 冒用页面状态
- **WHEN** 另一端口页面携带同机 Cookie 或伪造 Host/Origin 访问独立 Harness
- **THEN** 系统 MUST 拒绝越权访问，不因同属回环或 Cookie 名相同获得管理能力

#### Scenario: 长期使用后刷新恢复
- **WHEN** 同一浏览器在票据兑换后超过原固定寿命、但仍在不活动窗口内刷新页面（含兼容重启或更新之后）
- **THEN** 会话 MUST 仍有效并恢复页面，Cookie 寿命 MUST 同步刷新
- **AND** 超过不活动窗口、已显式登出或已换绑撤销的会话 MUST 拒绝，需重新从启动器引导登录

### Requirement: 独立网页必须按渠道使用固定端口并安全更换已有端点

独立 Harness CLI 与启动器 MUST 默认在 development 使用9519、released使用9518，显式 --port 可以覆盖。Development自身的端口与入口 MUST 保持不变。已绑定其他端口时，本机第一方 Harness 管理者 MUST 使用已观察端点、原端口和协调代次进行换绑。系统 MUST 先取得新回环监听，再按版本与持有者校验更新网页端点；占用、陈旧观察或协调身份变化 MUST 保留原端点，不抢占其他服务、不重启或停止Agent执行。成功换绑 MUST 撤销旧网页登录并仅关闭旧网页连接；账号、历史和执行归属 MUST 保持，未知工作 MUST NOT 重放。

#### Scenario: 开发与发布入口
- **WHEN** 用户分别启动开发版或发布版独立Harness且未覆盖端口
- **THEN** 前者 MUST 使用9519，后者 MUST 使用9518，Development自身入口保持不变

#### Scenario: 已有端点安全换绑
- **WHEN** 本机第一方以准确观察请求更换独立网页端口
- **THEN** 系统 MUST 在新端口就绪后提交换绑并关闭旧网页连接，原执行继续由原持有者管理

#### Scenario: 端口占用或陈旧请求
- **WHEN** 新端口被占用或端点/原端口/代次观察已过期
- **THEN** 系统 MUST 拒绝并保留原网页及运行，不冒充9519或9518就绪

### Requirement: 工作空间选择必须优先显示名称
Harness Web MUST 显示准确来源提供的工作空间名称；目录型工作空间 MUST 优先显示用户保存的名称，名称未填写时 MUST 使用目录名称并保留完整路径供核对。名称 MUST NOT 替代执行范围身份；名称缺失或来源离线时 MUST 保留准确身份回退。

#### Scenario: 选择已登记工作空间
- **WHEN** 宿主范围发现提供工作空间名称
- **THEN** 独立页面 MUST 使用该名称而不是来源加 UUID，选择仍绑定原范围

### Requirement: 添加目录工作空间必须通过本机选择并支持命名
独立 Harness Web MUST 提供服务所在本机的目录选择器，确认目录后登记并直接用于新对话；添加表单 MUST 支持填写名称并持久保存；名称留空 MUST 使用所选目录名。目录 MUST 通过选择器取得，MUST NOT 提供手填路径入口。取消 MUST NOT 登记或发送消息。不支持图形选择的平台 MUST 明确说明，保留已填写名称，不登记工作空间。接口 MUST 校验页面写入权限。

#### Scenario: 选择及取消目录
- **WHEN** 用户添加工作空间并选择本机已有目录
- **THEN** 系统 MUST 核验并登记该目录、选择对应工作空间；取消选择 MUST 保留原状态

#### Scenario: 自定义名称与默认名称
- **WHEN** 用户选择目录并填写名称或将名称留空
- **THEN** 系统 MUST 保存填写的名称或默认目录名，刷新后仍显示同一名称；名称不改变目录身份

### Requirement: Development 必须保留对话模块展开偏好
Development 与嵌套的 Harness 网页 MUST 在同浏览器配置域内记住用户明确选择的展开或收起状态、专注或分屏模式以及专注模式下的对话列表展开状态，刷新时稳定恢复，不得因可驱逐工作缓存占用浏览器存储配额或嵌入式 iframe 初始化握手顺序而退回默认状态；无偏好时根入口 MUST 展示专注对话，工程直达路径 MUST 完整展示工程区域并保留收起的对话入口。显式工程目录入口 `/?catalog=1` MUST 显示目录，不得被专注偏好遮挡。普通分屏模式刷新时仍保持分屏对话视图；收起面板或退出专注模式 MUST 同步清理专注与对话列表展开偏好。嵌入式页面再次加载时，宿主 MUST 重新下发当前模式与列表视图配置，在内层确认首次配置前不得以默认对话视图覆盖已恢复的列表视图；切换专注或分屏模式事件 SHOULD 携带明确目标状态。写入浏览器持久化存储遇到配额异常时，MUST 允许按需清理可重建的源码控件缓存后重试，并结合同标签页会话存储兜底；浏览器存储完全不可用 MUST NOT 阻止当前操作；恢复 MUST NOT 发送消息。

#### Scenario: 刷新恢复展开
- **WHEN** 用户处于展开的分屏对话模式或收起状态并刷新页面（包括存在缓存占用浏览器存储配额的场景）
- **THEN** 外层模块 MUST 稳定恢复展开与分屏模式或收起状态，不因刷新退回专注或丢失当前模式，原对话由 Harness 自身恢复

#### Scenario: 刷新恢复专注模式与对话列表
- **WHEN** 用户进入专注对话模式并切换对话列表展开状态后刷新页面（包括 `buildr:source-control-cache:*` 已占满 `localStorage` 或 iframe 重新加载的场景）
- **THEN** 页面 MUST 稳定保持在专注对话模式，桌面满足并排宽度时对话列表 MUST 保持刷新前的展开或收起状态，原对话选择与草稿保持不变，且不自动发送消息

#### Scenario: 首次使用根入口和工程深链
- **WHEN** 浏览器没有明确布局偏好并打开根路径或具体工程路径
- **THEN** 根路径 MUST 从完整对话开始，具体工程路径 MUST 显示对应工程页面；两者不自动创建执行或发送消息

### Requirement: Harness 外壳必须支持可选工作环境且保持对话独立

Harness MUST 提供构建时显式装配的前端外壳，接收完整对话区域和单个可选工作环境。不装配环境时 MUST 保留完整对话，不显示空的环境入口。装配环境后 MUST 默认保持对话为主，环境仅在用户打开时挂载；收起和重新打开 MUST 保留已挂载环境及对话的本地状态，MUST NOT 发送消息、改变对话身份或执行目录。

工作环境区域的渲染失败 MUST 只影响该区域，外壳 MUST 提供明确的局部不可用提示且仍允许收起。该边界只隔离组件渲染失败，MUST NOT 声称同页工作环境是不可信代码安全沙箱。Development 当前网页嵌入协议及完整对话的唯一实现责任 MUST 保持，不因本步框架建立而迁移工程业务。

当 Harness 作为独立完整网页运行（未嵌套于父窗口且未装配可选工作环境，或使用内置工作区运行在独立网页外壳中）时，页面 MUST 保持当前对话始终展开并固定左侧导轨，未展开右侧工作区时保持全宽，MUST NOT 在主对话右上角更多菜单中展示面向宿主分屏的布局项（`收起对话`、`专注对话`/`恢复分屏`、`对话移到最左侧`/`对话移到右侧`），也 MUST NOT 在左侧导轨展示用于收起或展开当前对话的入口；子对话浮窗自身的收起入口以及 Buildr Development 同页或嵌入场景中的分屏与折叠控制 MUST 保持不变。独立网页在支持左右并排分栏的桌面视口下无明确偏好时 MUST 默认展开左侧对话列表，并跨刷新记住用户在该配置域对桌面对话列表的展开或收起选择；在不支持左右并排分栏的窄屏视口下 MUST 默认先显示当前对话而不覆盖桌面展开偏好，且用户切换到对话列表时 MUST 在列表标题栏提供“返回当前对话”入口。

当独立 Harness 外壳展开右侧可选工作环境时，外壳 MUST 使用统一的 `ResizablePanels` 与 `SplitDivider` 组件在桌面视口提供横向可调分栏（并在窄屏视口自动切换为纵向上下分栏），支持指针拖拽、方向键微调与双击复位并记住桌面比例偏好；在宽度满足桌面三分屏条件（至少容纳 52px 导轨、240px 对话列表、520px 核心对话信息流与 360px 工作区）且桌面对话列表处于展开状态时，页面 MUST 支持同时展示并协同调节「对话列表」「核心对话信息流」与「右侧工作区」三栏并行布局。任何拖拽、窗口缩放、切换对话、新建对话或开合工作区操作 MUST 优先保证核心对话信息流的最小可读宽度（520px，仅当整体视口无法同时满足最小要求时按比例安全降级或自动退回非并排列表），缩小某一侧栏时释出的空间 MUST 优先归还核心对话信息流；点击任一栏分隔条而未发生指针位移时 MUST NOT 误提交比例或改变当前宽度；视口临时缩小导致列表退回单栏展示时 MUST NOT 覆盖桌面已保存的对话列表展开偏好。

#### Scenario: 不装配工作环境
- **WHEN** 独立 Harness 入口未提供工作环境
- **THEN** 页面 MUST 使用通用外壳展示现有完整对话，不出现环境占位或安装要求

#### Scenario: 独立网页移除宿主分屏控制并默认桌面展开对话列表
- **WHEN** 用户在支持并排分栏的桌面视口首次访问独立 Harness 网页（无既有布局偏好）
- **THEN** 主对话 MUST 保持展开并默认在左侧并排显示对话列表，左侧导轨按新建对话、当前对话、对话列表排序；当前对话入口仅导航，不折叠主对话或工作区，主对话更多菜单 MUST NOT 包含收起对话、专注对话/恢复分屏或左右移动选项
- **AND** 用户点击左侧导轨对话列表开关收起或再次展开列表后刷新页面，桌面列表展开状态 MUST 保持与刷新前一致，且不触发任何消息发送

#### Scenario: 独立网页窄屏默认展示对话并提供返回入口
- **WHEN** 用户在不支持左右并排分栏的窄屏视口打开独立 Harness 网页并点击对话列表入口
- **THEN** 初始页面 MUST 默认显示当前对话而非列表，切换到对话列表时列表标题栏 MUST 显示“返回当前对话”按钮，点击后返回当前对话；窄屏打开或切回对话 MUST NOT 覆盖桌面视口已保存的对话列表展开偏好

#### Scenario: 按需展开与收起
- **WHEN** 用户展开、收起并重新展开已装配的工作环境
- **THEN** 环境 MUST 在首次展开时挂载，随后保留其本地状态；原对话输入、阅读位置和身份 MUST 保持，布局操作不触发执行

#### Scenario: 工作环境渲染失败
- **WHEN** 工作环境组件在首次或后续渲染时抛错
- **THEN** 页面 MUST 只在环境区域显示不可用提示，仍能收起环境、编辑对话及操作原对话控制

#### Scenario: 桌面三分屏并行调节与核心对话信息流宽度保护
- **WHEN** 用户在桌面宽屏下同时打开独立 Harness 左侧对话列表与右侧对话工作区，并拖拽或使用键盘调节左侧列表分隔条或右侧工作区分隔条
- **THEN** 对话列表、核心对话信息流与右侧工作区 MUST 同时保持可见，且两侧均使用统一的 `SplitDivider` 调节宽度
- **AND** 核心对话信息流宽度 MUST 始终保持不低于 520px；向内拉宽一侧时仅在核心信息流触及 520px 下限后才平滑压缩相邻可让渡侧至其最小宽度，向外收缩一侧时另一侧宽度保持稳定、释放空间优先归还核心对话信息流，对话输入节点、草稿与滚动位置保持不变

#### Scenario: 视口不足三分屏阈值时平滑退回双栏并保留桌面偏好
- **WHEN** 三分屏展开期间浏览器视口缩窄至不足 1172px（但仍大于 760px 移动断点）
- **THEN** 页面 MUST 自动退回保留核心对话信息流（不低于 520px）与右侧工作区的双栏并排视图，MUST NOT 覆盖桌面已保存的对话列表展开偏好
- **AND** 当视口重新拉宽至 1172px 以上时，页面 MUST 自动恢复三分屏并行展示

### Requirement: Development 专注模式必须提供就近的设置、额度和对话入口

独立 Harness 和 Development 专注模式 MUST 在对话主区以保留最左 52px 唯一侧边导轨的两级左侧导航全屏设置视图展示设置，同时隐藏已展开的左侧对话列表与宽度分隔条（独立 Harness 中已展开的右侧工作区及工作区分隔条也 MUST 同步临时隐藏而不卸载内部状态）而不改写其展开偏好、宽度、筛选及未发送草稿；Development 普通分屏 MUST 继续使用右侧设置抽屉而不遮挡工程工作区。任一单栏覆盖展示对话列表的模式（独立网页窄屏、专注模式窄屏、Development 分屏展开及收起态暂看）MUST 在列表标题栏提供“返回当前对话”入口，仅并排双栏与三分屏并行列表省略该按钮；所有非隐藏对话列表（包括分屏模式）MUST 在工作空间分组标题右侧提供快捷“新建对话”入口并在无筛选条件时保留无历史记录的工作空间。

全屏设置 MUST 采用从左到右的两级左侧导航：最左为一级设置分类（模型、智能体、程序接入、系统提示词），且“模型”分类不显示向右展开箭头；选中“模型”时紧邻向右展开分组供应商二级菜单与右侧详情区，两个导航栏与详情区各自独立滚动；切换到无二级菜单的分类时二级栏自动收起，单栏内容区贴左并在舒适阅读宽度内展示；窄屏视口下折叠为顶部导航且不产生横向溢出。设置入口提示、全屏设置与 Development 普通分屏设置抽屉标题 MUST 统一收口为「设置」，去掉「智能体与模型」旧标题、枚举式副标题及全屏下的「返回对话」文字按钮；全屏设置顶栏展示当前路径与右上角「关闭设置」（`×`）按钮，并支持通过 `Escape` 键或再次点击导轨设置图标返回对话。

独立 Harness、Development 专注模式与 Development 普通分屏（含展开态与收起态）MUST 共用唯一侧边导轨并在设置图标上方提供独立的“供应商额度”入口，原设置齿轮图标统一仅用于打开或关闭设置而 MUST NOT 触发额度摘要。展开态与收起态悬停或键盘聚焦该额度图标 MUST 展示已有的供应商额度摘要；点击该额度图标（包括收起态点击后展开分屏）MUST 打开设置并直达模型的全部供应商“账号与额度”页签，不受前一次设置选项影响；收起态点击“设置”或“展开当前对话”或“新建对话” MUST 同步展开分屏并保持原对话与草稿。全屏设置打开期间，侧边导轨仅设置图标高亮；点击导轨“对话列表” MUST 退出设置并确保展示对话列表而不反向收起列表；点击导轨“当前对话”（Development 专注模式） MUST 退出设置回到当前对话而不收起对话面板。无论是全屏设置还是分屏设置抽屉，通过外部工程指令、提醒浮窗或对话列表切换或新建对话时均 MUST 自动关闭设置视图；打开或关闭设置 MUST NOT 改变对话选择、未发送草稿或已有执行，退出全屏设置后 MUST 原样恢复打开前的对话、对话列表以及已展开的右侧工作区视图。

#### Scenario: 从设置返回原对话
- **WHEN** 用户在独立 Harness 或 Development 专注模式下保留对话列表（及独立 Harness 右侧工作区）展开并输入草稿，点击侧边导轨的“设置”按钮，然后通过右上角「关闭设置」（或按 `Escape` 键、再次点击设置图标）返回对话
- **THEN** 打开设置期间最左 52px 唯一侧边导轨 MUST 保持可见且仅设置图标高亮，左侧对话列表、宽度分隔条及右侧工作区 MUST 隐藏，主区展示标题为「设置」的两级左侧导航全屏设置页
- **AND** 关闭设置后，系统 MUST 还原打开前的对话列表展开状态、右侧工作区展开状态、各栏宽度、原对话以及未发送输入；打开或关闭设置 MUST NOT 发起或停止执行

#### Scenario: 从左到右的两级左侧导航与单栏贴左宽度
- **WHEN** 用户在全屏设置中查看「模型」并切换到「智能体」「程序接入」或「系统提示词」
- **THEN** 「模型」分类不显示右侧箭头图标，选中时自左向右依次呈现一级设置导航、分组供应商二级菜单与右侧详情区并各自独立滚动
- **AND** 切换到「智能体」「程序接入」或「系统提示词」时供应商二级栏收起，单栏内容贴左并在舒适阅读宽度内展示；窄屏视口下导航折叠到顶部且无横向溢出

#### Scenario: 全屏设置期间点击左导轨切回对话或列表
- **WHEN** 用户在全屏设置中点击侧边导轨的“对话列表”或 Development 专注模式中的“当前对话”图标
- **THEN** 点击“对话列表” MUST 退出设置并确保对话列表可见而不反向折叠列表
- **AND** 点击“当前对话” MUST 退出设置回到当前对话而不错误收起整个对话面板

#### Scenario: 从额度入口进入模型账号与额度
- **WHEN** 用户悬停或键盘聚焦设置上方的额度图标
- **THEN** 系统 MUST 展示已有的供应商额度摘要；齿轮不再触发该摘要
- **AND** 点击额度图标 MUST 打开设置中模型的全部供应商“账号与额度”页签，不受前一次设置选项影响

#### Scenario: 分屏模式展开态与收起态使用独立额度入口
- **WHEN** 用户处于 Development 普通分屏展开态或收起态
- **THEN** 唯一导轨设置图标上方 MUST 显示独立的“供应商额度”图标，齿轮图标不再悬停触发额度摘要
- **AND** 展开态与收起态悬停或聚焦独立额度图标 MUST 展示现有供应商额度摘要且不越出视口，点击 MUST 保持或展开分屏并在「设置」抽屉直接打开全部供应商“账号与额度”页签
- **AND** 收起态悬停“展开当前对话” MUST 展示暂看浮层而不自动固定，点击设置或新建对话 MUST 展开分屏，同时保持原有对话、未发送草稿与执行不变

#### Scenario: 在指定工作空间新建对话
- **WHEN** 用户在专注模式或分屏模式打开对话列表，并点击工作空间标题右侧的新增按钮
- **THEN** 系统 MUST 使用该空间打开新对话输入并聚焦，且不创建空对话、不改变该组折叠状态；点击名称仍可折叠或展开

#### Scenario: 单栏列表返回当前对话与设置自动关闭
- **WHEN** 用户在分屏模式等单栏覆盖展示对话列表时查看列表，或打开设置抽屉后从提醒浮窗、对话列表或外部工程页面触发打开/新建对话
- **THEN** 单栏列表标题栏 MUST 显示“返回当前对话”按钮，点击后返回当前对话并保留原草稿
- **AND** 打开或新建对话时设置抽屉 MUST 自动关闭并切换到目标对话或新对话输入

### Requirement: 本机已认证对话必须支持打开本地文件与隔离预览 HTML

在通过本机同源会话认证的独立 Harness 网页及 Buildr Web 对话中，用户点击对话消息或工具成果中的本地文件引用时，系统 MUST 按调用方已核验权限允许预览可读的本机普通文件，不再将打开范围限制为 `harness-local` 目录对话或当前工作空间/已登记代码库根目录内；其中已登记代码库内文件在 Buildr Web MUST 继续优先在代码浏览器打开，含父级穿越或主目录缩写等不能唯一确认来源的相对引用（如 `../outside.md`、`~/...`）MUST 继续拒绝。

对于 `.html` 与 `.htm` 文件（上限 20 MiB），服务端的独立只读 HTML 预览端点 MUST 使用隔离沙盒策略响应（`Content-Security-Policy` 包含 `sandbox allow-scripts`、`connect-src 'none'`、`frame-ancestors 'self'` 且不包含 `allow-same-origin`），前端预览组件 MUST 支持在沙盒 `iframe` 内就地交互预览、切换查看源码、在新标签页打开及复制路径，且打开本地文件预览弹窗 MUST NOT 退出当前专注模式；未携带有效同源会话凭据或跨站请求 MUST 被拒绝。

#### Scenario: 独立 Harness 网页打开 Buildr 对话及工作空间外文件
- **WHEN** 已通过页面会话认证的本机用户在独立 Harness 网页中查看 `buildr` 工作空间或 `@default` 对话，并点击工作空间外（如 `/tmp`）的本地文件
- **THEN** 系统 MUST 允许读取并打开该文件的本地预览，不再返回「仅能读取准确目录对话的来源文件。」或目录越界 403 错误

#### Scenario: Buildr Web 区分代码库文件、外部绝对路径与模糊相对路径
- **WHEN** 用户在 Buildr Web 对话中分别点击已登记代码库内文件、工作空间外明确绝对路径（如 `/tmp/demo.md`）以及相对父路径穿越（如 `../outside.md`）
- **THEN** 已登记代码库文件 MUST 继续进入代码浏览器，工作空间外明确绝对路径 MUST 在本页弹窗预览而不退出专注模式，而 `../outside.md` MUST 继续报错拒绝

#### Scenario: HTML 交互预览、源码切换与未认证拒绝
- **WHEN** 已认证用户点击 `.html` / `.htm` 本地文件或在文件卡片选择预览，并切换源码视图或点击「新标签页打开」
- **THEN** 预览端点 MUST 以无 `allow-same-origin` 的 `sandbox allow-scripts` CSP 返回完整 HTML（最高 20 MiB），弹窗与新标签页均可正常渲染交互且不能读取宿主会话或接口；未携带有效 Cookie 或跨站请求 MUST 返回 403

### Requirement: 对话中的本机 HTML 章节链接支持隔离预览

系统 MUST 将本机 `.html` 或 `.htm` 文件链接的非空章节锚点与读取路径分开。打开时 MUST 沿用既有的来源解析、权限检查及隔离策略，且仅将锚点附加到获准的 HTML 预览地址。有无锚点均默认就地隔离预览。

#### Scenario: 打开对话中链接指向的 HTML 章节

- **WHEN** 用户在 Buildr Web 或独立 Harness 网页对话中打开可读的 `report.html#skills`
- **THEN** 系统 MUST 读取 `report.html` 而不是 `report.html#skills`
- **AND** 预览及新标签页 MUST 保留 `#skills`，如章节不存在仍显示报告

#### Scenario: 保留已有文件引用语义

- **WHEN** 用户打开原样工具文件路径、不带章节的普通文件链接，或非 HTML 代码行号链接
- **THEN** 系统 MUST 不将文件名中的 `#` 或非 HTML 代码行号误作 HTML 章节

### Requirement: 对话文件链接默认就地预览并可定位资源管理器

两种对话入口 MUST 共用链接位置解析并默认在对话中预览。合法行号 MUST 在预览中定位；原样文件路径不得误拆。仅为当前资源管理器可定位的准确文件 MUST 在短暂停留后提供「在资源管理器中打开」，键盘和触屏也可调用。所有动作 MUST 沿用原有权限，不自动登记目录。

#### Scenario: 预览文件行号
- **WHEN** 用户点击 `AGENTS.project.md#L7`
- **THEN** 系统 MUST 预览同一文件并定位第 7 行，不切换页面

#### Scenario: 在资源管理器中打开同一文件
- **WHEN** 用户选择可用的「在资源管理器中打开」
- **THEN** 资源管理器 MUST 展开父目录、选中并读取该文件；对话草稿与阅读位置保持

#### Scenario: 工作范围外的文件
- **WHEN** 文件可预览但不能在当前资源管理器定位
- **THEN** 系统 MUST 不提供资源管理器动作，普通点击仍按原权限预览

### Requirement: 对话中的本机 Markdown 章节链接打开原文并定位

Buildr Web 与独立 Harness 网页 MUST 将本机 `.md` 或 `.markdown` 链接的非空章节锚点从读取路径分离，沿用已核验的文件来源和权限。预览 MUST 显示文件并在标题锚点匹配时定位；标题不存在时 MUST 仍显示文件。合法 `#L<行号>` MUST 保持行号语义，原样工具文件路径与 `file:` URL 文件名中编码的 `#` MUST NOT 被误作章节。

#### Scenario: 预览对话里的中文 Markdown 章节

- **WHEN** 用户点击 `skills/references/naming-rules.md#前缀选择` 或其百分号编码锚点形式，源文件可读
- **THEN** 系统 MUST 读取无锚点的原文件，显示 Markdown 预览并尝试定位到标题「前缀选择」
- **AND** 即使找不到该标题，也 MUST 显示原文件而不报文件不存在

#### Scenario: 保留 Markdown 行号和字面文件名

- **WHEN** 用户点击 `notes.md#L7`，或打开文件名本来包含 `#` 的原样路径或 `file:` URL 编码路径
- **THEN** 系统 MUST 分别定位第 7 行或读取含有 `#` 的真实文件
