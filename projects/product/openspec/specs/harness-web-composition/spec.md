# harness-web-composition Specification

## Purpose
定义完整 Harness 对话功能在独立网页、Development 专注及内嵌模式中的共享边界，以及独立回环网页的唯一监听、身份发现、登录和代次交接，使用户在两产品中使用同一事实而不复制核心行为。

## Requirements

### Requirement: Harness 必须提供完整唯一对话并支持公开同页装配

系统 MUST 将对话导航、历史、消息、工具展示、输入、附件、发送、模型与账号设置、问题、审批、停止、接续和恢复全部实现在 buildr-harness-web。独立 buildr-harness-ui 包 MUST 删除；Development MUST 通过公开完整对话组件入口装配，MUST NOT 导入内部组件重组对话或执行状态容器。第一方组合 MUST 使用同一 React 页面树，不加载对话 iframe；独立完整网页入口 MUST 继续可用。

Development 的 harness-ui 模块 MUST 只准备工程现场、选择工作空间、挂载完整对话、维护任务关联和工程导航；任务选择控件 MUST 由 Development 提供并通过语义上下文插槽原位呈现，MUST NOT 依赖跨窗口坐标覆盖。Harness MUST 不管理工程任务状态。

上下文插槽 MUST 是可选工作上下文区域，而非工程任务专属空位；未提供内容时 MUST NOT 保留固定任务占位。文件能力与工作对象打开 MUST 由产品装配显式接入，Harness MUST NOT 将通用打开入口写死为 Development。当前组合继续使用 Development 已有文件浏览器，不迁移文件能力、不新增通用插件路由或 DSH 适配。

#### Scenario: 相同网页服务两种产品
- **WHEN** 用户独立打开 Harness 或在 Development 使用内嵌/专注模式
- **THEN** 页面 MUST 复用同一完整对话实现，Development 不实现第二套对话控制

#### Scenario: 工程上下文交接
- **WHEN** Development 选择工作空间并新建对话
- **THEN** Development MUST 提供准确工作范围，Harness 自己创建对话并拥有执行交互；选择不自动发送模型消息

#### Scenario: 页面通信校验
- **WHEN** 页面接收非准确父/子窗口、错误 origin 或未知协议消息
- **THEN** 接收方 MUST 忽略消息，不改变选择或触发执行

#### Scenario: 显式工程操作只由 Harness 提交
- **WHEN** 用户在 Development 发起已授权的工程上下文交接
- **THEN** Development MUST 用准确请求身份交给 Harness 处理，Harness 自己维护首次提交及恢复；响应未知不得自动重发

#### Scenario: 工程业务独立工作
- **WHEN** 工程页面未装配 Harness 网页
- **THEN** 任务、知识和代码事实 MUST 可独立读取，不隐式创建执行

#### Scenario: 真实工程区域挂入外壳
- **WHEN** Development 装配入口提供现有工程页面和完整对话组件
- **THEN** Harness 通用外壳 MUST 承载双方，工程区域开合不卸载对话，工程页面不能包含第二个对话实例
- **AND** 同页工程导航 MUST 展开工程区域，但不得改变已有对话的准确执行范围

#### Scenario: 工程抽屉随所属区域隐藏
- **WHEN** 用户切换离开保留的工程页面，或收起其工作环境
- **THEN** 该区域打开的工程编辑抽屉 MUST 同步隐藏，不遮挡当前区域；重新展开后 MUST 恢复未保存草稿而不写入业务数据

#### Scenario: 同页工程上下文与链接
- **WHEN** 用户在完整对话内查看任务关联或点击文件、工程对象链接
- **THEN** 对话 MUST 分别通过明确文件能力或工作对象接口请求打开；当前 Development 装配 MUST 核验准确工程来源，工程控件 MUST 在可选上下文插槽中渲染，不使用窗口消息执行同页工程动作

#### Scenario: 同页装配与状态保全
- **WHEN** 用户切换工程路由、专注或分屏及环境开合
- **THEN** 同页完整对话 MUST 保持同一实例、执行身份、草稿及阅读位置，不重复发送或创建执行

#### Scenario: 工程上下文局部失败
- **WHEN** Development 提供的工程上下文组件渲染失败
- **THEN** 页面 MUST 在该插槽显示局部不可用提示，完整对话输入、观察及停止控件 MUST 保持同一实例且可用

### Requirement: 多入口必须共享持久事实而不覆盖未提交输入

同一 Development 页面切换专注/内嵌或业务页面时 MUST 保留对话身份、未提交草稿、选择和阅读位置，不改执行目录。不同窗口及 origin MUST 通过服务端修订同步持久事实；未经明确设计的未提交本地文字 MUST 不跨窗口互相覆盖。缓存与事件 MUST 按稳定数据域、来源范围、对话和适用代次隔离。多入口重复答复、发送或停止 MUST 沿同一幂等和准确版本边界处理。

#### Scenario: 同页模式切换
- **WHEN** 用户在输入或阅读中切换专注与内嵌模式
- **THEN** 输入、滚动和当前对话 MUST 保持，模式变化不发起执行

#### Scenario: 两窗口各有草稿并共同答复
- **WHEN** 两窗口编辑各自未提交文字，并同时回复同一待决请求
- **THEN** 本地文字 MUST 不互相覆盖；准确请求只消费一次，另一请求明确返回已处理或版本冲突

### Requirement: 独立网页只能按明确入口意图启用

独立 Harness Web MUST 有可托管的生产静态产物，提供完整唯一网页和前置的唯一 API。仅使用 Development 时 MUST 默认不监听独立 Harness 网页端口，内嵌和专注 MUST 通过 Development 受认证的同源路径托管该网页并使用同一 API。用户显式打开独立 Harness 时，MUST 允许在同一逻辑服务中启用一个独立回环网页入口，包括两产品同装、同开；它 MUST 不创建第二个执行核心、目录宿主进程或对话库。内部通信和模型网关端口 MUST 不作为浏览器接口公开。

#### Scenario: 只打开 Development
- **WHEN** 用户仅从 Development 使用内嵌或专注模式
- **THEN** 浏览器 MUST 只访问 Development origin，独立 Harness 网页监听器默认不启动

#### Scenario: 同时打开独立网页
- **WHEN** 用户在 Development 已运行时显式打开独立 Harness
- **THEN** 两产品页面 MUST 能并存并观察同一服务资料；独立入口不得抢占 Development 端口、关闭其网页或被重定向成 Development 页面

### Requirement: 网页端点必须在兼容换代时唯一交接

独立网页端点 MUST 归逻辑数据域而非 npm 目录或临时执行代次；只有当前被授予监听权的代次能提供该入口。兼容升级 MUST 保持 origin 和未失效的页面会话，旧代次只保留原执行与私有控制通道，不保留第二个公开监听器。交接允许短暂断线，MUST 保留输入、准确请求身份和事件恢复基线；未知写入不得重发。不能确认释放或地址被其他程序占用时，MUST 报告局部入口不可用，不强杀占用者或发布虚假就绪。

#### Scenario: 旧轮仍运行时换代
- **WHEN** 兼容新版接收新工作而旧代次仍持有轮次
- **THEN** 网页 MUST 经交接后的同一 origin 观察并控制原轮，静态资源和会话保持声明的兼容性，不迁移或重放原执行

#### Scenario: 切换失败或端口被占用
- **WHEN** 新监听未就绪、旧监听释放未知或原地址由其他进程占用
- **THEN** 系统 MUST 保留准确失败和原工作，不宣称网页 ready、不并行争抢；仅在已证明监听权和兼容条件后恢复入口

### Requirement: 启动登录必须绑定准确网页入口而不泄露服务秘密

本机入口 MUST 从受保护的实例发现及就绪观察取得准确地址，不能只根据端口或 PID 信任页面。登录引导 MUST 使用短时单次、绑定产品/数据域/目标端点的票据或等价认证能力，不能向浏览器交出后台主令牌、模型凭据或宿主秘密。独立与 Development 页面会话 MUST 分离；鉴于回环地址不同端口的 Cookie 不隔离，独立入口 MUST 对会话命名和范围隔离并核验 Host/Origin，不能仅依赖 SameSite。有效会话在兼容换代后继续校验当前有效期和撤销状态。页面会话 MUST 使用有限的不活动窗口（30 天）并按认证活动滑动续期；续期 MUST NOT 使票据可重复使用，MUST NOT 恢复已撤销或已换绑撤销的会话。会话有效时加载页面文档 MUST 同步刷新浏览器 Cookie 寿命，Cookie MUST NOT 先于服务端会话失效。

#### Scenario: 登录引导与重复打开
- **WHEN** 启动入口确认准确服务和网页已就绪并打开浏览器
- **THEN** 票据 MUST 只兑换一次有限页面会话；重复点击复用现有入口，不创建后台或重复工作
- **AND** 过期、被重复消费或目标不符的票据必须拒绝，日志、URL query 和转发头不得含长期秘密

#### Scenario: 同机另一 origin 冒用页面状态
- **WHEN** 另一端口页面携带同机 Cookie 或伪造 Host/Origin 访问独立 Harness
- **THEN** 系统 MUST 拒绝越权访问，不因同属回环或 Cookie 名相同获得管理能力

#### Scenario: 长期使用后刷新恢复
- **WHEN** 同一浏览器在票据兑换后超过原固定寿命、但仍在不活动窗口内刷新页面（含兼容重启或更新之后）
- **THEN** 会话 MUST 仍有效并恢复页面，Cookie 寿命 MUST 同步刷新
- **AND** 超过不活动窗口、已显式登出或已换绑撤销的会话 MUST 拒绝，需重新从启动器引导登录

### Requirement: 独立网页必须按渠道使用固定端口并安全更换已有端点

独立 Harness CLI 与启动器 MUST 默认在 development 使用9519、released使用9518，显式 --port 可以覆盖。Development自身的端口与入口 MUST 保持不变。已绑定其他端口时，本机第一方 Harness 管理者 MUST 使用已观察端点、原端口和协调代次进行换绑。系统 MUST 先取得新回环监听，再按版本与持有者校验更新网页端点；占用、陈旧观察或协调身份变化 MUST 保留原端点，不抢占其他服务、不重启或停止Agent执行。成功换绑 MUST 撤销旧网页登录并仅关闭旧网页连接；账号、历史和执行归属 MUST 保持，未知工作 MUST NOT 重放。

#### Scenario: 开发与发布入口
- **WHEN** 用户分别启动开发版或发布版独立Harness且未覆盖端口
- **THEN** 前者 MUST 使用9519，后者 MUST 使用9518，Development自身入口保持不变

#### Scenario: 已有端点安全换绑
- **WHEN** 本机第一方以准确观察请求更换独立网页端口
- **THEN** 系统 MUST 在新端口就绪后提交换绑并关闭旧网页连接，原执行继续由原持有者管理

#### Scenario: 端口占用或陈旧请求
- **WHEN** 新端口被占用或端点/原端口/代次观察已过期
- **THEN** 系统 MUST 拒绝并保留原网页及运行，不冒充9519或9518就绪

### Requirement: 工作空间选择必须优先显示名称
Harness Web MUST 显示准确来源提供的工作空间名称；目录型工作空间 MUST 优先显示用户保存的名称，名称未填写时 MUST 使用目录名称并保留完整路径供核对。名称 MUST NOT 替代执行范围身份；名称缺失或来源离线时 MUST 保留准确身份回退。

#### Scenario: 选择已登记工作空间
- **WHEN** 宿主范围发现提供工作空间名称
- **THEN** 独立页面 MUST 使用该名称而不是来源加 UUID，选择仍绑定原范围

### Requirement: 添加目录工作空间必须通过本机选择并支持命名
独立 Harness Web MUST 提供服务所在本机的目录选择器，确认目录后登记并直接用于新对话；添加表单 MUST 支持填写名称并持久保存；名称留空 MUST 使用所选目录名。目录 MUST 通过选择器取得，MUST NOT 提供手填路径入口。取消 MUST NOT 登记或发送消息。不支持图形选择的平台 MUST 明确说明，保留已填写名称，不登记工作空间。接口 MUST 校验页面写入权限。

#### Scenario: 选择及取消目录
- **WHEN** 用户添加工作空间并选择本机已有目录
- **THEN** 系统 MUST 核验并登记该目录、选择对应工作空间；取消选择 MUST 保留原状态

#### Scenario: 自定义名称与默认名称
- **WHEN** 用户选择目录并填写名称或将名称留空
- **THEN** 系统 MUST 保存填写的名称或默认目录名，刷新后仍显示同一名称；名称不改变目录身份

### Requirement: Development 必须保留对话模块展开偏好
Development 与嵌套的 Harness 网页 MUST 在同浏览器配置域内记住用户明确选择的展开或收起状态、专注或分屏模式以及专注模式下的对话列表展开状态，刷新时稳定恢复，不得因可驱逐工作缓存占用浏览器存储配额或嵌入式 iframe 初始化握手顺序而退回默认状态；无偏好时根入口 MUST 展示专注对话，工程直达路径 MUST 完整展示工程区域并保留收起的对话入口。显式工程目录入口 `/?catalog=1` MUST 显示目录，不得被专注偏好遮挡。普通分屏模式刷新时仍保持分屏对话视图；收起面板或退出专注模式 MUST 同步清理专注与对话列表展开偏好。嵌入式页面再次加载时，宿主 MUST 重新下发当前模式与列表视图配置，在内层确认首次配置前不得以默认对话视图覆盖已恢复的列表视图；切换专注或分屏模式事件 SHOULD 携带明确目标状态。写入浏览器持久化存储遇到配额异常时，MUST 允许按需清理可重建的源码控件缓存后重试，并结合同标签页会话存储兜底；浏览器存储完全不可用 MUST NOT 阻止当前操作；恢复 MUST NOT 发送消息。

#### Scenario: 刷新恢复展开
- **WHEN** 用户处于展开的分屏对话模式或收起状态并刷新页面（包括存在缓存占用浏览器存储配额的场景）
- **THEN** 外层模块 MUST 稳定恢复展开与分屏模式或收起状态，不因刷新退回专注或丢失当前模式，原对话由 Harness 自身恢复

#### Scenario: 刷新恢复专注模式与对话列表
- **WHEN** 用户进入专注对话模式并切换对话列表展开状态后刷新页面（包括 `buildr:source-control-cache:*` 已占满 `localStorage` 或 iframe 重新加载的场景）
- **THEN** 页面 MUST 稳定保持在专注对话模式，桌面满足并排宽度时对话列表 MUST 保持刷新前的展开或收起状态，原对话选择与草稿保持不变，且不自动发送消息

#### Scenario: 首次使用根入口和工程深链
- **WHEN** 浏览器没有明确布局偏好并打开根路径或具体工程路径
- **THEN** 根路径 MUST 从完整对话开始，具体工程路径 MUST 显示对应工程页面；两者不自动创建执行或发送消息

### Requirement: Harness 外壳必须支持可选工作环境且保持对话独立

Harness MUST 提供构建时显式装配的前端外壳，接收完整对话区域和单个可选工作环境。不装配环境时 MUST 保留完整对话，不显示空的环境入口。装配环境后 MUST 默认保持对话为主，环境仅在用户打开时挂载；收起和重新打开 MUST 保留已挂载环境及对话的本地状态，MUST NOT 发送消息、改变对话身份或执行目录。

工作环境区域的渲染失败 MUST 只影响该区域，外壳 MUST 提供明确的局部不可用提示且仍允许收起。该边界只隔离组件渲染失败，MUST NOT 声称同页工作环境是不可信代码安全沙箱。Development 当前网页嵌入协议及完整对话的唯一实现责任 MUST 保持，不因本步框架建立而迁移工程业务。

#### Scenario: 不装配工作环境
- **WHEN** 独立 Harness 入口未提供工作环境
- **THEN** 页面 MUST 使用通用外壳展示现有完整对话，不出现环境占位或安装要求

#### Scenario: 按需展开与收起
- **WHEN** 用户展开、收起并重新展开已装配的工作环境
- **THEN** 环境 MUST 在首次展开时挂载，随后保留其本地状态；原对话输入、阅读位置和身份 MUST 保持，布局操作不触发执行

#### Scenario: 工作环境渲染失败
- **WHEN** 工作环境组件在首次或后续渲染时抛错
- **THEN** 页面 MUST 只在环境区域显示不可用提示，仍能收起环境、编辑对话及操作原对话控制
