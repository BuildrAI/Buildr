# web-read-efficiency Specification

## Purpose
为本机 Buildr Web 提供低成本且仍然可信的读取方式，在保持认证、状态及时性与既有客户端兼容的前提下，减少静态资源及后台状态观察的重复传输与重复工作。

## Requirements

### Requirement: 哈希资源支持安全缓存与压缩协商
系统 SHALL 对带内容哈希的构建资源支持长期不可变缓存，并按请求接受的编码返回可用压缩表示。含会话注入的 HTML 与私有 JSON MUST 保持 no-store，不得缓存会话凭证；不支持压缩的客户端 MUST 可读取原始表示。

#### Scenario: 压缩资源与普通客户端
- **WHEN** 客户端请求同一带哈希脚本，分别接受 Brotli、gzip 或不接受压缩
- **THEN** 服务 MUST 返回可解码为相同原始内容的表示、准确的编码与 Vary，并允许该哈希资源缓存

#### Scenario: 会话页面
- **WHEN** 客户端读取应用 HTML
- **THEN** 响应 MUST 保持 no-store，不能因静态资源缓存策略泄漏旧会话

### Requirement: 活动提醒支持轻量联合观察
系统 SHALL 提供受现有认证保护的活动与提醒联合摘要以及内容版本；摘要 MUST 保留排序、计数、运行状态、准确身份和详情导航所需信息，不携带历史执行或原生上下文。相同版本的请求 SHALL 可以只返回未变化标记。旧列表及提醒接口 MUST 保持兼容。

#### Scenario: 未变化与发生变化
- **WHEN** 客户端带上次摘要版本进行观察
- **THEN** 相同内容 MUST 仅返回未变化标记，变化 MUST 返回新版本与完整摘要；客户端 MUST 保留上次成功观察并在失败后允许重试

#### Scenario: 后台轮询
- **WHEN** 页面可见但对话栏收起
- **THEN** 客户端 MUST 用单次联合观察维持不超过现有 5 秒周期的刷新，页面不可见时暂停周期读取，恢复后重新观察

### Requirement: 重复读取保持取消隔离与权威校准
系统 SHALL 合并相同目录的并发读取，单个消费者取消不得取消其他消费者；写入后新读取 MUST 不复用写入前的在途观察。代码状态初始化 MUST 不因首次监听握手重复安排同一完整扫描，实际变更和手动读取仍 MUST 触发必要权威校准。

#### Scenario: 并发目录读取与写入
- **WHEN** 两个组件同时读取目录，其中一个取消，随后发生登记修改
- **THEN** 未取消者 MUST 获得结果，修改后的新请求 MUST 发起新观察

#### Scenario: 首次代码监听
- **WHEN** 工作空间正在执行首次代码状态读取并收到首次监听握手
- **THEN** 握手 MUST 不再重复安排完整扫描，实际变更通知仍能触发后续读取

### Requirement: 默认目录与连接使用同一运行配置
默认工作目录读取 SHALL 复用当前进程连接绑定的运行配置，仍 MUST 核对目录实际路径；不能因重复产品身份发现阻塞其他本机接口，也不能把该复用扩展到写入前的身份与版本校验。

#### Scenario: 重复读取默认目录
- **WHEN** 同一宿主进程重复读取默认目录且连接绑定未改变
- **THEN** 返回 MUST 使用同一运行配置，不重复发现产品 Git 身份；目录真实路径变化仍 MUST 在使用时被观察

### Requirement: 发布提示观察不阻塞首页读取
发布版本提示 SHALL 沿用既有来源校验与通知事实，通过有界后台读取完成；同步来源探测 MUST NOT 占用 HTTP 主事件循环阻塞独立首页读取。

#### Scenario: 发布来源探测未完成
- **WHEN** 发布提示正在等待来源查询
- **THEN** 独立应用 HTML 和状态请求 MUST 能先完成，发布提示最终仍返回原有协议结果
