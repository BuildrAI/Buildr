# model-usage-controls Specification

## Purpose
定义在统一账号界面中管理模型套餐真实额度、模型启用及有效上下文的行为，并准确归并基础模型及其支持的配置，使用户能在不同原生执行者之间使用明确来源的模型而不误认目录配置为独立权益。

## Requirements

### Requirement: 同一账号卡片完成登录与额度查看
系统 MUST 在同一账号卡片表达未登录、登录中、过期、已登录和观察失败。已登录 MUST 展示真实额度窗口、重置时间及观察时间；未知额度 MUST 明确未知且不得当作零余额。账号登录与额度不得要求用户切换独立登录页面。

#### Scenario: 原位登录
- **WHEN** 用户对未登录账号发起登录并成功
- **THEN** 原卡片显示账号额度与模型入口，复用已有登录的账号不需要再次添加套餐

### Requirement: 模型启用偏好持久且有版本保护
系统 MUST 按账号和模型保存单项或批量启用偏好；目录刷新和服务重启 MUST 保留偏好，新发现模型及组合模式 MUST 默认停用。旧目录普通模型 MUST 保留迁移前启用意图。停用模型 MUST 从新选择候选中移除并拒绝新执行，已有执行不被意外中断。

#### Scenario: 刷新后保留选择
- **WHEN** 用户停用模型并刷新目录或重启
- **THEN** 已停用模型仍停用；批量更新按观察版本校验，冲突不覆盖当前偏好

### Requirement: 上下文数字可设置和恢复
系统 MUST 允许以正整数设置模型有效上下文并恢复平台默认，MUST 持久保存偏好并传给原生执行方。已知平台上限时 MUST 拒绝更大设置；刷新后上限降低 MUST 使用不超过最新上限的有效值。未知上限 MUST 明确表达，不把本地设置当作上游保证。

#### Scenario: 设置与恢复上下文
- **WHEN** 用户将平台报告 258000 的模型设置为 128000 并随后恢复默认
- **THEN** 新执行先使用 128000，恢复后使用平台当前报告值；零、负数、小数、超大或超过已知上限的请求被拒绝

### Requirement: 基础模型和真实支持变体分别表达
系统 MUST 将同一基础模型的思考强度、速度等支持配置归并，不得生成笛卡尔积；组合模式 MUST 独立计数和管理。调用 MUST 选择准确上游配置，未支持组合 MUST 被拒绝。思考强度 MUST 从低到高排列，自动或未知语义不得强制映射为有序深度。

#### Scenario: 快速档映射
- **WHEN** 同一模型提供标准档低/中/高和快速档低/高
- **THEN** 列表按基础模型显示一行，快速档只能选择真实支持的低/高，调用映射到其准确配置

### Requirement: 余额制账号显示实际账户余额
系统 MUST 通过原生账号提供的只读能力读取 DeepSeek 充值及赠送钱包，以对应币种显示实际账户余额，保留十进制精度；不同币种 MUST 分列，MUST NOT 将余额折算成无依据的限额百分比。余额读取失败 MUST NOT 阻断模型目录或其他账号，未知不得作为零余额。

#### Scenario: 读取充值与赠送钱包
- **WHEN** 已登录 DeepSeek 账号返回同币种充值与赠送钱包
- **THEN** 系统显示精确合计的该币种账户余额及两类钱包明细，账号卡片和入口概览使用相同事实

#### Scenario: 余额失败与合法零值
- **WHEN** 余额读取失败或返回合法零余额
- **THEN** 前者明确未知或标记保留的旧观察，后者显示实际零余额；两者不得混淆，模型目录仍独立可用

### Requirement: 右下角入口悬停查看全部已启用来源额度

系统 MUST 在右下角供应商设置图标悬停或键盘聚焦时显示全部已启用供应商中已登录或已连接账号的额度概览，保留账号身份、平台报告的每个周、日、小时或其他额度窗口、余额币种、剩余 credits（平台返回时）与观察时间；不得只展示当前模型账号或只展示周窗口。概览 MUST 按供应商显示名称稳定排序，同一供应商内按账号名排序；供应商顺序不得随接口返回顺序或刷新变化。未知、失败和旧观察 MUST 明确表达。点击 MUST 保留打开原设置的行为。供应商级停用 MUST 按供应商停用规则隐藏其账号；模型级停用 MUST NOT 隐藏已登录或已连接账号。

#### Scenario: 多账号混合额度
- **WHEN** 已启用供应商中的已登录或已连接账号分别提供周窗口、日或小时窗口、账户余额或未知额度
- **THEN** 悬停概览逐账号显示对应事实及时间，无百分比的余额不产生进度条，模型级停用不隐藏已登录或已连接账号

#### Scenario: 多来源按显示名称排序
- **WHEN** 已登录或已连接账号来自 `ChatGPT`、`ChatGPT API`、`DeepSeek`、`Qoder`、`Qoder CN` 与自定义供应商等供应商
- **THEN** 概览 MUST 按供应商显示名称排序，同一供应商的多个账号按账号名排序
- **AND** 排序 MUST NOT 改变账号身份、额度事实或点击行为

#### Scenario: 自定义供应商额度未知
- **WHEN** 已启用的自定义供应商已保存配置且模型可用，但没有可读取的平台额度
- **THEN** 概览 MUST 显示该供应商及额度未知事实
- **AND** MUST NOT 将其显示为零余额或耗尽

#### Scenario: 读取失败及入口可用
- **WHEN** 概览读取失败或没有已登录或已连接账号
- **THEN** 显示读取失败或空状态，点击按钮仍能打开原设置，未登录与断开账号不伪装为已登录

### Requirement: 账号卡片必须支持独立 ChatGPT API 来源原位配置

账号设置 MUST 提供与订阅账号分开显示的内置 `ChatGPT API` 供应商卡片。未配置时 MUST 在原卡片提供密码输入与保存动作，不要求切换独立页面；内置 `ChatGPT API` 卡片 MUST NOT 提供 URL 输入。用户自定义供应商 MUST 使用独立编辑界面声明名称、Base URL、协议、可选 API Key 与模型列表，并按 `custom-model-providers` 规范管理。校验成功后 MUST 在同一卡片展示供应商状态、模型入口、观察时间及额度未知事实；校验失败 MUST 保留输入操作与其他供应商，不得把失败账号显示为已登录。订阅供应商与 API Key 供应商 MUST 能同时显示为已连接或可用，不提供互斥启用要求。供应商列表 MUST 按显示名称稳定排序，`全部供应商` 固定在首位，使 `ChatGPT` 与 `ChatGPT API` 相邻显示，并使自定义供应商按名称参与排序。

#### Scenario: 首次配置 API Key

- **WHEN** 用户在 ChatGPT API 卡片填写密钥并保存
- **THEN** 卡片 MUST 显示校验中状态，完成后显示可用模型与观察时间
- **AND** 密钥 MUST 以密码输入呈现且保存后不再显示原文

#### Scenario: 无效密钥诊断

- **WHEN** 保存的密钥被服务商拒绝
- **THEN** 卡片 MUST 显示具体认证或权限诊断并允许重新输入
- **AND** 其他账号卡片 MUST 保持原状态和模型

#### Scenario: 管理已连接 API Key

- **WHEN** ChatGPT API 供应商已连接
- **THEN** 用户 MUST 能刷新模型、更换密钥、管理模型启停和上下文并断开该供应商
- **AND** 断开或更换 MUST 不影响 ChatGPT 订阅账号及无关供应商

#### Scenario: 订阅和 API Key 同时可用

- **WHEN** ChatGPT 订阅账号和 ChatGPT API 供应商均已成功连接
- **THEN** 两张供应商卡片 MUST 同时保持可用状态
- **AND** 系统 MUST NOT 要求停用其中一个供应商才能启用另一个

#### Scenario: 账号来源名称排序

- **WHEN** 账号设置同时展示 ChatGPT 订阅、ChatGPT API、自定义供应商与其他供应商
- **THEN** 供应商列表 MUST 按显示名称排序，`ChatGPT` 与 `ChatGPT API` MUST 相邻
- **AND** `全部供应商` MUST 始终位于供应商列表首位，排序不得改变当前选择或账号状态

#### Scenario: 自定义供应商卡片

- **WHEN** 用户添加并保存有效的自定义供应商配置
- **THEN** 供应商列表 MUST 显示其卡片、供应商状态、模型入口、观察时间与额度未知事实
- **AND** 配置无效时 MUST 保留输入操作并显示诊断，其他供应商 MUST 保持原状态

### Requirement: Qoder 套餐额度与资源包必须分别表达

Qoder 来源 MUST 同时解析 `/usage` 返回的套餐额度与资源包额度，个人账号的 `addOnQuota` 与组织账号的资源包字段 MUST 按真实响应表达。系统 MUST 分别展示套餐窗口与资源包窗口，并按可用额度和总量计算账号级剩余比例；平台返回剩余与总量时，账号卡片与额度概览 MUST 在对应窗口同时显示剩余 credits 数量与总量，MUST NOT 只显示百分比。未返回数量时 MUST NOT 推算或伪造数值。MUST NOT 仅因套餐窗口为 0% 判定整个账号耗尽，也 MUST NOT 因额度读取失败阻断模型目录。

`/usage` 返回 `dedicatedResourcePackages` 时，系统 MUST 为其中每个可用资源包生成独立额度窗口，名称取 `displayLabels` 中 `dimension` 为 `title` 的 `valueI18n['zh-CN']`，其次取同项 `value`，均缺失时回退“千问专属积分”。窗口 MUST 使用包含资源包 `id` 的唯一标识，并在平台返回时显示该资源包的剩余与总量 credits；`resetsAt` MUST 取该资源包的 `expiresAt`。`available` 不为 `true` 或已过期的资源包 MUST NOT 生成窗口，`description` 等说明文案 MUST NOT 进入额度窗口。专属积分只在对应模型系列内抵扣，MUST NOT 计入账号级剩余比例或通用额度耗尽判断。

#### Scenario: 套餐耗尽但资源包仍有余额

- **WHEN** `/usage` 返回套餐总额 1000、剩余 0，资源包总额 2700、剩余 1599
- **THEN** 账号卡片与额度概览 MUST 同时显示套餐与资源包窗口，并显示 `0 / 1,000 credits` 与 `1,599 / 2,700 credits`
- **AND** 账号级剩余比例 MUST 大于零，模型执行 MUST NOT 因额度耗尽被拒绝

#### Scenario: 数量字段缺失

- **WHEN** `/usage` 返回额度百分比但缺少剩余或总量数值
- **THEN** 系统 MUST 保留百分比或未知表达，MUST NOT 推算数量

#### Scenario: 资源包读取失败

- **WHEN** 资源包字段缺失或本次额度读取失败
- **THEN** 系统 MUST 保留模型目录并明确额度未知或保留旧观察
- **AND** MUST NOT 把未知资源包当作零余额

#### Scenario: 千问专属积分独立展示

- **WHEN** `/usage` 返回一项 `available` 为 `true`、总量 2000、剩余 2000、`expiresAt` 有值的资源包，且其标题文案为“Qwen 专属积分”
- **THEN** 额度窗口 MUST 新增该专属积分窗口，显示“Qwen 专属积分”与 `2,000 / 2,000 credits`
- **AND** 窗口重置时间 MUST 对应该资源包的到期时间
- **AND** 账号级剩余比例与额度耗尽判断 MUST NOT 因该窗口变化

#### Scenario: 专属积分名称回退

- **WHEN** 资源包缺少 `dimension` 为 `title` 的 `displayLabels`，或其中缺少 `valueI18n['zh-CN']`
- **THEN** 系统 MUST 依次使用同项 `value` 与“千问专属积分”作为窗口名称
- **AND** `description` 文案 MUST NOT 出现在额度窗口

#### Scenario: 不可用资源包不生成窗口

- **WHEN** `dedicatedResourcePackages` 中某项 `available` 不为 `true` 或已过期
- **THEN** 系统 MUST NOT 为该资源包生成额度窗口
- **AND** 其余可用窗口 MUST 保持正常展示

### Requirement: ChatGPT API 额度未知必须明确且区分模型观察

ChatGPT API 账号卡片 MUST 区分模型目录观察时间与额度观察时间。普通 API Key 无法读取剩余余额时，系统 MUST 明确显示额度未知，并说明费用与余额由 OpenAI 平台管理；MUST NOT 显示为零余额、已耗尽，或把模型目录已成功观察误显示为“尚未读取”。

#### Scenario: 模型已读取但余额不可读

- **WHEN** ChatGPT API 模型目录读取成功而官方 API 不返回剩余余额
- **THEN** 卡片 MUST 显示模型目录观察时间与额度未知说明
- **AND** 模型 MUST 保持可用，系统 MUST NOT 推断零余额

#### Scenario: 普通 API Key 无法读取账单

- **WHEN** 普通 API Key 请求组织账单或余额接口被拒绝
- **THEN** 系统 MUST 保留未知状态并指向 OpenAI 平台用量/账单，不得要求用户把管理员密钥或会话 Cookie 交给 Buildr

### Requirement: 模型候选来源快捷行必须保持单行

模型候选弹层中的来源快捷行 MUST 在常见桌面与窄视口宽度内保持单行，超出时 MUST 采用可访问的横向滚动或其他不折行方式；来源按钮 MUST 保持可点击和可聚焦。

#### Scenario: 多个来源同时存在

- **WHEN** 模型候选同时包含 ChatGPT、DSH、Qoder、Devin 与 ChatGPT API
- **THEN** 来源快捷行 MUST 不折成第二行
- **AND** 每个来源 MUST 仍能定位到对应模型分组

### Requirement: 账号来源停用必须默认隐藏且保留账号事实

系统 MUST 以独立于登录、断开和账号可用状态的持久化供应商状态表达供应商停用，MUST NOT 复用“断开”语义。停用 MUST 保留凭证、登录尝试、账号身份、历史对话、已有租约与模型偏好，MUST NOT 更换身份、释放已有租约或使凭证失效。

停用供应商 MUST 从默认供应商列表、模型目录、模型选择器和额度概览中隐藏，MUST NOT 参与新对话或新执行的模型租约。系统 MUST 继续支持按准确账号身份读取停用供应商及历史记录；已有执行 MUST 继续到终态，不因供应商停用被中断。账号管理 MUST 提供明确的“显示已停用供应商”和“重新启用”入口；重新启用 MUST 恢复同一供应商及其既有凭证和偏好，不要求重新登录或重新填写自定义配置。

#### Scenario: 停用来源后隐藏且可恢复
- **WHEN** 用户停用一个已登录或已连接的模型供应商并刷新页面
- **THEN** 该供应商不再出现在默认供应商列表和模型选择器中，也不能创建新租约
- **AND** 管理界面通过“显示已停用供应商”仍能读取该账号，重新启用后恢复原账号、模型偏好与登录或连接状态

#### Scenario: 停用不破坏历史与运行中工作
- **WHEN** 供应商停用前已有历史对话或正在执行的租约
- **THEN** 历史对话和运行记录仍按原供应商可读，运行中的租约不被中断
- **AND** 新执行 MUST 明确拒绝该供应商，而不是伪装为模型不存在或账号未登录

#### Scenario: 模型级停用与来源级停用分离
- **WHEN** 用户只停用某供应商下的一个模型
- **THEN** 该供应商仍出现在供应商列表和额度概览中，仅该模型退出新选择
- **AND** 供应商级停用才隐藏整个供应商，两种状态互不覆盖
