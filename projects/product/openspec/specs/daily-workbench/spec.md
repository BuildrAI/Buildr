# daily-workbench Specification

## Purpose
为工作空间（Workspace）内的人提供以当下关注事项为中心的日常工作台（Workbench），以已有任务（Task）、项目（Project）、每日演进与资料为真实来源，提供可持久但独立的浏览偏好，并保持局部失败和来源边界。

## Requirements

### Requirement: 日常概览使用真实有界来源
工作概览 MUST 展示待我处理、继续推进、项目变化与常用入口，按明确工作空间和可选项目范围读取。待处理只来自显式请求；进行中不表示智能体（Agent）实时执行。每区 MUST 有界查询并表达总数或更多入口，不复制任务结果或全量扫描代码库。

#### Scenario: 跨项目工作
- **WHEN** 一个任务关联多个项目且用户查看概览
- **THEN** 同一任务 MUST 只出现一次并保留范围，选择任一关联项目仍可找到它。

#### Scenario: 首批以外的关注对象
- **WHEN** 被置顶、加入接下来或有明确待处理事项的任务不在普通列表第一批
- **THEN** 概览 MUST 按明确身份或索引读取并正确展示，不因只筛选前一批而丢失。

#### Scenario: 没有显式待处理
- **WHEN** 工作空间没有待处理记录或只有缺失的专业报告
- **THEN** 待我处理 MUST 显示真实空态，MUST NOT 由四态或报告缺失制造请求。

### Requirement: 偏好按对象独立维护
本机偏好 MUST 支持任务置顶、接下来、项目关注、站内资源收藏与有界最近访问。偏好 MUST 与任务状态和工作事实独立，以稳定对象或受限站内引用保存；逐项增删 MUST 幂等且不覆盖其他对象，工作空间之间隔离。

#### Scenario: 保存和恢复偏好
- **WHEN** 用户置顶或安排一项待办并刷新页面
- **THEN** 界面 MUST 恢复偏好并从原来源读取对象，MUST NOT 激活或完成任务。

#### Scenario: 无效或恶意资源引用
- **WHEN** 收藏或访问输入包含其他工作空间、外部网址、绝对文件路径或逃逸路径
- **THEN** 写入 MUST 被拒绝且不影响已有偏好。

#### Scenario: 并发维护不同偏好
- **WHEN** 两个入口分别改变不同对象的偏好
- **THEN** 两次合法操作 MUST 保留各自结果，不用整份页面状态覆盖。

### Requirement: 每日演进按来源范围展示
项目变化和动态页面 MUST 复用已有每日演进来源，展示项目、日期、摘要、截至时间与覆盖说明，并提供进入项目完整每日演进的入口。读取 MUST NOT 自动同步、扫描 Git 或生成缺失摘要。

#### Scenario: 单个来源失败
- **WHEN** 一个项目的每日演进暂不可读
- **THEN** 页面 MUST 局部提示并允许重试，其余项目、任务与偏好继续可用。

#### Scenario: 尚未生成
- **WHEN** 所选日期没有摘要
- **THEN** 页面 MUST 说明暂无已生成内容并可交接生成请求，MUST NOT 虚构近期活动。

### Requirement: 原型路径接入真实工作现场
页面 MUST 延续已确认原型的柔和视觉、顶部双入口、四区概览、完整任务列表、详情优先呈现目标/进展/下一步/成果以及并排资料阅读。项目入口 MUST 到达同一真实对象并保留可返回路径。窄屏 MUST 可用且无横向页面溢出。

#### Scenario: 接续工作与阅读
- **WHEN** 用户从概览打开任务、阅读关联资料并返回
- **THEN** 界面 MUST 显示真实内容并恢复原有列表范围和筛选，不跳到第一条任务。

#### Scenario: 专业动作仍可达
- **WHEN** 用户需要原型、审查、验证或父子任务维护
- **THEN** 页面 MUST 保留对应已有能力和安全约束，不以新布局删除专业结果。

### Requirement: 新目标与接续只交接明确范围
工作台 MUST 提供提出新目标与继续工作入口，生成包含真实范围、任务身份和已有摘要的智能体指令。已结束任务 MUST 引导基于已有成果提出新目标，不暗中重开或执行。

#### Scenario: 复制指令
- **WHEN** 用户准备或复制工作指令
- **THEN** 页面 MUST 明确尚未执行，MUST NOT 自动创建任务、启动智能体或产生发布副作用。

### Requirement: 新存储兼容既有只读工作
新增偏好与工作摘要数据 MUST 使用本机结构化存储并按既有安全边界写入。仅新增数据结构尚未初始化时，合法读取 MUST 仍可访问旧任务与空的新数据，MUST NOT 为 GET 请求创建或迁移数据；未知较新版本或损坏仍需明确诊断。

#### Scenario: 从旧版本直接阅读
- **WHEN** 用户只读打开仍未执行本轮新增迁移的有效旧数据库
- **THEN** 既有任务 MUST 继续可读，新数据按未登记呈现，数据库内容与迁移台账不变。
