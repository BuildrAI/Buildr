# agent-buildr-participation Specification

## Purpose
为 Buildr 内部智能体执行提供自动、可追溯的参与事实：说明 Buildr 提供了哪些内容、观察到哪些读取或能力请求及其结果，并以明确范围和覆盖限制形成单次明细与持续汇总，支持优化判断而不推断贡献价值、计费归属或任务完成。

## Requirements

### Requirement: 参与事实必须自动关联原执行和原证据

系统 SHALL 在现有内部执行的实际发送和工具事件路径自动记录参与元数据，不要求 Agent 或用户逐条上报。记录 MUST 关联准确来源、执行范围、对话、本轮执行、参与者、代次及原输入或工具条目；可取得的原生父子身份 MUST 保留。系统 MUST 保持原请求、正文、顺序、工具结果及执行控制语义，MUST NOT 为观察创建第二执行流水、复制正文仓库或重放动作。

#### Scenario: 新执行产生 Buildr 内容和工具请求
- **WHEN** 一次内部执行提交 Buildr 指令并产生带原身份的工具请求
- **THEN** 系统 MUST 自动保存能取得的参与元数据，并使每项关联其准确输入尝试或原工具条目
- **AND** 原执行不需要先关联任务或由 Agent 填写观察报告

#### Scenario: 子调用与其他轮次事件交错
- **WHEN** 原生明确提供子调用父身份，且其结果在其他轮次开始后返回
- **THEN** 参与事实 MUST 按准确原身份归属，不继承父来源或最近轮次猜测归属

### Requirement: 可发现、提交、请求和观察结果必须分别表达

系统 MUST 区分可发现 `available`、实际提交 `submitted`、读取／能力请求 `requested` 与有原生证据的实际动作 `observed`。预览、排队、已提交、已受理和送达未知 MUST 沿用原交付事实。系统 MUST NOT 把可用清单当作加载、把调用请求当作实际成功、把受理当作模型实际接收全部内容。沿用上下文配置 MUST 与本轮新增提交分开，MUST NOT 每轮重复计算一次注入。

#### Scenario: 预览后没有发送
- **WHEN** 用户查看发送预览或保留待发送内容但尚未实际提交
- **THEN** 系统 MUST NOT 增加已提交或已受理参与次数

#### Scenario: 沿用已有交互策略
- **WHEN** 后续轮次复用已配置的原生上下文，没有再次提交该配置
- **THEN** 该轮 MUST 能关联原配置事实并说明沿用，MUST NOT 新增该配置的提交体积

#### Scenario: 厂商隐式加载规则没有上报
- **WHEN** 规则处于可发现范围但没有消费证据
- **THEN** 系统 MUST 表示可发现和是否加载未知，MUST NOT 报告零使用或已加载

### Requirement: Buildr 提供关系和当次版本必须有独立依据

系统 MUST 区分提供者与管理者，至少表达 Buildr、工作空间自定义、外部和未知来源；来源确认、候选与未知 MUST 分开。已确认 Buildr 主统计 MUST 只纳入有当次提供关系证据的项目。观察版本与供给版本 MUST 分开，缺少实际版本时 MUST 保持未知，不使用当前同名文件、路径子串、助手声明或工具输出反推来源与历史版本。

#### Scenario: Buildr 管理了用户资料
- **WHEN** 工具读取用户项目规则、任务说明、代码或业务数据，但没有 Buildr 方法提供关系
- **THEN** 系统 MUST NOT 将这些正文归为 Buildr 提供的方法，即使它们通过 Buildr 接口返回
- **AND** 已确认的接口调用开销与承载的用户内容 MUST 分开表达

#### Scenario: 当时读取后文件发生变化
- **WHEN** 当前文件版本与当次实际内容摘要不同，或当次没有保存版本证据
- **THEN** 查询 MUST 保留当次证据或版本未知，MUST NOT 以当前文件替换

#### Scenario: 请求中出现同名 CLI
- **WHEN** 只能识别字面量 `buildr`，没有与适用运行范围中获准实际入口匹配的身份和版本依据
- **THEN** 系统 MUST 将该来源保持为候选或未知，不能按名称确认 Buildr 或声称该程序已启动

#### Scenario: 规则包含不同来源片段
- **WHEN** 当次内容同时包含有证明的 Buildr 片段和用户片段
- **THEN** 来源及体积 MUST 仅覆盖实际有证明的片段，MUST NOT 将整个文件归为 Buildr

### Requirement: 请求解析必须有界且不能伪造实际动作

系统 SHALL 对支持的原生技能、文件读取及字面量命令请求进行结构化识别，并保存解析版本与原输入引用。解析 MUST NOT 搜索结果正文或引用材料作为调用依据，MUST NOT 为消歧执行命令。动态命令、别名和无法证明的包装 MUST 标为候选或未知；复合命令中的字面量仅能作为请求，除非存在准确实际执行证据。

#### Scenario: 输出或检索模式提到 Buildr 命令
- **WHEN** `echo`、目录列举、检索模式或工具输出包含 Buildr 技能路径与命令文字
- **THEN** 系统 MUST NOT 据此增加这些方法的读取或调用次数

#### Scenario: 条件分支包含多个命令
- **WHEN** shell 请求包含多个可能不执行的分支且只有整体工具结果
- **THEN** 系统 MUST 保留可识别请求与未知动作结果，MUST NOT 断言所有命令已经执行或成功
- **AND** 混合输出 MUST NOT 任意分摊给各命令

### Requirement: 工具结果必须采用准确原生证据

系统 MUST 将来源状态与动作结果独立保存，动作结果 MUST 区分成功、失败、未知及尚在执行。原生明确错误、可信退出码和未知修复事实 MUST 保留；仅有工具 completed、正常 stdout、助手完成声明或整轮结束 MUST NOT 证明具体能力成功或用户目标达成。

#### Scenario: 已确认 Buildr 请求执行失败
- **WHEN** 来源已确认的 Buildr 能力取得准确失败回执
- **THEN** 系统 MUST 保留确认来源并报告失败，不能把失败请求从参与统计中删去

#### Scenario: 工具结束但命令结果缺失
- **WHEN** 只知道整体工具已结束，没有特定动作的成功或失败证据
- **THEN** 动作结果 MUST 保持未知，MUST NOT 将 completed 直接转换为动作成功

### Requirement: 体积和上下文用量必须说明计量边界

系统 SHALL 在可取得时记录原生可见文本经展示截断前的 UTF-8 字节数及文本长度，并说明其计量边界与完整性。缺失、部分或已被上游截断的数据 MUST 与完整数据分开，不能以零补齐或使用页面压缩预览代替。Buildr 自身方法、用户输入／历史载荷与显示包装 MUST 分开计量。既有 `contextUsage` MUST 保持最近报告的上下文含义，MUST NOT 当作累计费用、按资产分摊或用差值推算厂家余量。

#### Scenario: 大工具结果在展示时截断
- **WHEN** 适配器收到的原生可见文本超过展示长度上限
- **THEN** 系统 MUST 能保留该上报范围的截断前长度，并标明正文展示不完整
- **AND** MUST NOT 将截断提示、命令显示包装或页面预览长度当作完整原生输出

#### Scenario: 原生未提供完整长度或历史只有片段
- **WHEN** 只保存了可见片段，无法证明完整原生长度
- **THEN** 系统 MUST 显示局部计量或未知，不将它与完整输出无差别相加

#### Scenario: 交接包含大量用户历史
- **WHEN** Buildr 提交交接包装及用户原始历史
- **THEN** 体积 MUST 区分 Buildr 包装和用户载荷，MUST NOT 把全部交接正文算成 Buildr 方法

### Requirement: 原记录保存必须幂等并支持准确重载

参与字段 MUST 随其所属原记录保存，在支持该字段的后台重启后可读。工具开始、结果、重试投影、历史重载及候选升级 MUST 按同一原身份更新，不能重复计数；继承历史和交接副本 MUST NOT 产生新的原动作。晚到元数据 MUST 校验原条目和观察版本，发生冲突不得覆盖较新内容或错误归属。

#### Scenario: 同一工具重复投递和冷重载
- **WHEN** 同一原工具先后收到开始、结果、重复结果，并在后台重启后重读
- **THEN** 系统 MUST 保持一个原动作及准确最终状态，不因更新或重载增加调用数

#### Scenario: 其他对话继承同一段历史
- **WHEN** 已有工具条目作为背景被子对话或交接引用
- **THEN** 系统 MUST 保留引用关系但不把原动作再次计入全局原调用次数

### Requirement: 单次明细和跨次汇总必须共享准确口径

系统 SHALL 提供只读的单次参与结果 `buildr.agent-participation/v1` 和范围汇总 `buildr.agent-participation-summary/v1`，保留对象、原执行、版本、证据引用及覆盖说明。汇总 MUST 按明确执行范围、执行开始时间半开区间、Agent、模型和对象／版本筛选，默认分开不同版本和未知版本。主统计、候选与未知 MUST 分开；结果 MUST 来自整个选择范围的有效观察切点，不能用当前已加载历史页面推算总量。

#### Scenario: 同一对象三个请求分别成功失败未知
- **WHEN** 选择范围内同一对象具有三个不同原请求，其中一个成功、一个失败、一个结果未知
- **THEN** 汇总 MUST 展示三个请求、各一项已知成功和失败及一项未知，失败比例为已知结果中的二分之一
- **AND** 未知 MUST NOT 进入已知结果分母，调用成功 MUST NOT 被解释为业务目标成功

#### Scenario: 只加载了部分对话页面
- **WHEN** 界面只加载部分对话，而查询范围中存在更多已采集执行
- **THEN** 汇总 MUST 使用完整范围的有效投影或明确标记覆盖不足，MUST NOT 将页面条数作为统计总量

#### Scenario: 可用快照缺失
- **WHEN** 历史有调用请求但没有当时可用清单或消费观察覆盖
- **THEN** 系统 MUST 展示已有请求和覆盖缺口，不制造以全部执行为分母的精确使用率

### Requirement: 查询必须有界可取消并保护原范围

查询 MUST 使用既有认证及执行范围核验，MUST NOT 因查询扩大可访问空间、读取其他配置域或修改业务状态。默认汇总窗口 SHALL 为最近七天、默认每页五十行，行数上限 SHALL 为二百、单响应上限一 MiB、单窗口上限九十天；超过限制必须明确拒绝或返回有游标的部分结果，不能静默漏项。游标 MUST 绑定筛选与观察切点，陈旧切点必须显式处理。

#### Scenario: 请求跨空间或篡改游标范围
- **WHEN** 调用方请求未获准范围，或以其他筛选条件复用游标
- **THEN** 系统 MUST 拒绝该读取并保留原执行，不能静默改用另一空间或混合结果

#### Scenario: 汇总索引未就绪或查询取消
- **WHEN** 读侧索引缺失、部分构建、失效或调用方取消请求
- **THEN** 系统 MUST 如实表达 building、partial 或 unavailable，并释放该查询资源
- **AND** MUST NOT 将其显示为零参与、阻断原执行或重新调用模型

### Requirement: 查看必须提供两个清晰入口和原证据导航

系统 SHALL 在现有对话轮次提供“Buildr 参与”明细入口，在全局对话功能提供“Buildr 参与汇总”。单次入口 MUST 能区分已提供、读取与调用、未知与缺口；汇总 MUST 显示实际工作空间和时间条件，没有明确范围时不能默认统计所有空间。选择统计项后 MUST 能定位准确原执行与可用原证据，保留草稿、筛选、选择与滚动上下文。正文缺失只能说明限制，不能读取当前文件伪装当时正文。

#### Scenario: 从汇总定位原动作再返回
- **WHEN** 用户选择汇总行、打开原执行证据，再关闭详情
- **THEN** 系统 MUST 保留原筛选、滚动位置和未发送草稿，并使用原证据版本

#### Scenario: 空结果存在不同原因
- **WHEN** 选择范围没有执行、没有确认项、尚未采集、索引未就绪或读取失败
- **THEN** 系统 MUST 分别说明实际原因，不能统一显示“Buildr 没有参与”

### Requirement: Agent 查询必须复用准确对话绑定和同一只读结果

系统 SHALL 为现有准确绑定的对话控制入口增加只读 `participation` 和 `participation-summary` 操作。单次操作 MUST 限于绑定对话，汇总 MUST 限于绑定执行范围，不接受通过参数覆盖来源、空间或数据根；既有控制动作语义 MUST 保持。Buildr Skill SHALL 提供按需发现、调用、覆盖解释和完成判断指引，不要求手工上报或将方法全文重复注入每次执行。

#### Scenario: Agent 查询当前对话的一轮参与
- **WHEN** Agent 使用本轮提供的准确控制命令及已核对 runId 请求参与明细
- **THEN** 系统 MUST 返回与界面同语义的只读结果，不发送用户消息、修改任务或执行原工具

#### Scenario: 没有绑定或旧后台不支持
- **WHEN** 缺少准确控制绑定，或运行单元不支持新增观察操作
- **THEN** 指引与结果 MUST 说明无法查询或不支持，不能猜测脚本、端口、账号或自动重启升级原后台

### Requirement: 历史和能力不对等必须保持诚实兼容

Codex、DSH、Qoder SHALL 采用共同参与语义，各自只上报实际可证明字段；缺少某项原生能力必须表达覆盖限制，不填伪造值。旧记录缺字段 MUST 保持未采集，重建派生统计 MUST NOT 反查当前资产补来源或改写原历史。新增可选宿主能力 MUST 不成为普通执行、停止、回应和保存的前提；兼容性不能证明时必须保全数据与旧控制，不能强停。

#### Scenario: 新旧后台同时保存不同对话
- **WHEN** 兼容后台并行工作而旧后台尚未上报参与字段
- **THEN** 旧轮 MUST 保留未采集范围，新轮已存事实 MUST 不被旧投影覆盖，所有结果按原对话修订校验

#### Scenario: 最小宿主没有资产解析能力
- **WHEN** 符合原执行契约的宿主没有新增来源能力或执行中暂时离线
- **THEN** 原工作 MUST 保持可执行与可控制，来源观察局部降级为未知或未采集

### Requirement: 观察必须本机有界且不复制秘密

新增参与数据 MUST 仅保存必要身份、版本、计量、状态及原证据引用，默认随原对话本机保留，MUST NOT 新增云端遥测、用户正文副本、环境／凭据快照或秘密参数摘要。采集 MUST 有有限预算并支持局部降级，超时、非法附加字段或超限必须只影响观察，不改变可成功的原执行和原记录。实际原数据库失败仍按既有持久化语义处理。

#### Scenario: 来源核对超时或附加元数据超限
- **WHEN** 来源核对超出局部预算，或工具附加字段超过支持容量
- **THEN** 系统 MUST 保留原工具与结果，记录可取得事实及 partial／unknown 原因，不等待来源完整才放行

#### Scenario: 查询内容包含命令和秘密参数
- **WHEN** 原工具输入或返回资料中含敏感信息、命令文字或其他方法路径
- **THEN** 新增索引与摘要 MUST NOT 复制这些正文或秘密摘要，也不能递归当作新的参与动作

### Requirement: 统计只能支持优化判断不能替代验收

界面、查询结果和 Agent 指引 MUST 明确区分可观察使用、内容体积、失败／未知与贡献价值；系统 MUST NOT 根据低频、未观测、调用成功、读取完成或整轮结束自动删改方法、宣称节省费用或完成用户目标。任何收益结论 MUST 说明样本范围、版本、覆盖和实际验证依据。

#### Scenario: 长期没有规则消费事件
- **WHEN** 某项规则可发现但消费方式不可观测，或某技能只在少量样本出现
- **THEN** 系统 MUST 允许将其作为调查线索，MUST NOT 自动标记无用、建议安全删减或生成已证明收益
