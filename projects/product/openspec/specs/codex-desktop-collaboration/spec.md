# codex-desktop-collaboration Specification

## Purpose
为用户日常使用的 Codex 原聊天与 Buildr 任务提供准确身份关联、独立多对多关系、双向打开和侧边固定入口导航；原聊天保持桌面自己的历史、记忆（Memory）与执行能力，一次性生成使用独立应用服务（App Server），核心接入不依赖插件（Plugin）或卡片。

## Requirements

### Requirement: 桌面连接保持原生后台

Buildr MUST 将已确认 Codex 安装和配置范围保存为稳定关联登记，不要求插件（Plugin）、卡片或握手。接入 MUST NOT 安装扩展、启动工具服务、要求重启、替换后台、修改桌面启动配置或复制聊天库及凭证。同范围维护 MUST 保留编号，实质范围变化 MUST NOT 原地重定向关系。状态 MUST 表达已配置或需检查，不得宣称桌面当前在线或模型已执行。

#### Scenario: 安装后尚未加载
- **WHEN** 旧扩展尚未加载但用户已确认本机 Codex 安装与配置范围
- **THEN** 系统 MUST 保存关联及生成登记，不安装扩展、不创建聊天、不要求重启

#### Scenario: 旧握手字段
- **WHEN** 旧登记仍保存等待加载或活跃握手字段
- **THEN** 系统 MUST 按当前范围判定关联配置，不以旧字段阻塞或伪装桌面在线

### Requirement: 移除后的桌面连接不复活

关联登记 MUST 保留明确断开状态，以 Codex 登记存在性作为新关联可用性的权威。移除接入后旧请求 MUST NOT 恢复接入；原关系和聊天链接 MUST 保留，明确重新接入同范围 MUST 复用稳定编号。卸载 Buildr 扩展 MUST 与移除 Codex 接入分开，不得停止独立生成或删除长期关系，也不得删除桌面聊天、记忆（Memory）或结束桌面后台。

#### Scenario: 卸载扩展保留接入
- **WHEN** 用户要求卸载 Buildr 插件并保留核心协作
- **THEN** 系统 MUST 保留生成登记、关联编号及全部任务关系

#### Scenario: 迟到准备与重新接入
- **WHEN** 接入移除后旧调用到达，或用户明确重新接入同范围
- **THEN** 旧调用 MUST 不复活接入；重新接入 MUST 保留稳定身份及既有关系

#### Scenario: 旧组件仍加载
- **WHEN** 旧扩展仍加载而用户已移除 Codex 接入
- **THEN** 旧调用 MUST 无法新建关系，旧插件专用入口明确退役

### Requirement: 具体原聊天绑定与恢复

系统 MUST 接受用户在具体聊天中要求关联指定任务，由该聊天直接提交准确身份，不以插件、网页请求或卡片确认为前提。系统 MUST NOT 用共享根、子执行、工具服务环境或匿名页面身份代替当前聊天。已确认且范围有效时 MUST 幂等关联；缺少有效接入或范围变化时 MUST 拒绝新关联并保留旧关系。结果不明 MUST 先查询，不自动重建任务或发送指令。

#### Scenario: 聊天直接关联任务
- **WHEN** 用户给出任务编号并要求当前聊天关联，聊天直接提交准确身份
- **THEN** 系统 MUST 幂等保存关系并返回双向链接，不要求卡片或二次确认

#### Scenario: 分叉聊天绑定
- **WHEN** 原聊天与分叉共享根编号而具体身份不同
- **THEN** 系统 MUST 使用实际承载聊天身份

#### Scenario: 接入范围无法唯一确定
- **WHEN** 无有效接入或多个有效接入而未指定目标
- **THEN** 系统 MUST 明确说明未关联，不猜测接入或修改默认项

#### Scenario: 面板重开
- **WHEN** 历史卡片尝试恢复专用面板
- **THEN** 专用入口 MUST 明确退役，不创建请求，长期关系仍可通过核心入口读取

#### Scenario: 旧请求兼容
- **WHEN** 直接关联后旧请求仍待处理或晚到
- **THEN** 系统 MUST 保留旧数据并拒绝新专用动作，不重复关系或恢复已解除关系

### Requirement: 任务与原聊天多对多

系统 MUST 独立保存工作空间（Workspace）、任务、Codex 关联登记和具体聊天的多对多关系。建立 MUST 幂等，解除 MUST 校验关系版本且不改任务正文或状态。正反向查询 MUST 可用，聊天侧可通过命令行（CLI）按具体身份查询，不依赖卡片。聊天关闭、默认变化或扩展卸载 MUST 不删除关系或自动改绑；临时生成身份 MUST 不作为长期关系。

#### Scenario: 双向多对多查询
- **WHEN** 一个任务关联两个聊天且其中一个聊天关联其他任务
- **THEN** 任务详情和按聊天身份查询 MUST 返回完整准确关系，重复建立不增加关系

#### Scenario: 并发解除关系
- **WHEN** 使用过期关系版本解除
- **THEN** 系统 MUST 报告冲突并保留当前关系，不改任务正文版本

### Requirement: 原聊天交接与双向打开

任务详情 MUST 打开准确关联聊天，聊天返回的任务链接 MUST 使用固定入口，均不得依赖插件或卡片。打开 MUST 不冒称消息送达或工作完成。旧工具服务及卡片专用绑定、恢复和交接创建入口 MUST 退役；旧调用 MUST 返回明确退役诊断，不创建请求或发送业务消息。旧请求及回执数据 MUST 保留，不恢复已解除关系；历史聊天中已渲染卡片不承诺被抹除。

#### Scenario: 目标聊天不是当前聊天
- **WHEN** 用户选择某个关联聊天
- **THEN** 系统 MUST 通过具体身份打开准确聊天，不改发其他聊天或创建替代聊天

#### Scenario: 旧扩展调用
- **WHEN** 旧工具服务、卡片绑定或交接入口被调用
- **THEN** 系统 MUST 明确报告退役且零新业务写入，已有关系和旧数据保留

### Requirement: 固定入口优先复用侧边页

Codex 协作新任务链接 MUST 使用同一工作空间的固定基址，将具体目标放入网址片段（URL Fragment）。存在宿主匹配页时 MUST 利用其原页导航，不为每个任务新建页。Buildr MUST 在首次加载、片段变化、刷新和返回／前进时显示准确目标，保护未保存内容，旧资源状态 MUST 不覆盖新目标。当前可控制旧页 MUST 可安全采用固定入口；原路径链接 MUST 继续正确到达。系统 MUST 如实保留历史任意路径、多页精确选择及跨窗口能力边界，不以地址变化或请求接受冒充任务到达。

#### Scenario: 概览原页打开任务
- **WHEN** 侧边已打开固定入口概览，用户点击同入口任务链接
- **THEN** 原页身份 MUST 保持且页面数不增加，实际任务内容 MUST 与目标相同

#### Scenario: 旧页采用及草稿
- **WHEN** 用户在当前旧路径页面启用 Codex 协作入口
- **THEN** 系统 MUST 在同页保留可恢复位置及草稿，不刷新或关闭其他页面

#### Scenario: 历史旧链接
- **WHEN** 用户点击历史聊天中的旧路径任务链接
- **THEN** 目标任务 MUST 正确到达；宿主新增页时 MUST 如实说明，MUST NOT 将其计为任意旧页复用已覆盖

### Requirement: Codex 聊天新建任务默认关联

任务管理技能（Skill）在 Codex 原聊天中新建任务成功后 MUST 默认使用本聊天直接采集的具体身份显式建立关联，用户明确不关联时 MUST 尊重其选择。任务记录命令 MUST NOT 从工具服务或继承进程环境隐式猜测聊天身份。没有准确身份或有效 Codex 接入时 MUST 保留新任务并明确说明尚未关联，不把关联失败当作创建失败，不影响 DSH 或无聊天的任务创建。

#### Scenario: 从 Codex 聊天创建任务
- **WHEN** Codex 原聊天创建任务成功，已取得准确聊天身份且存在明确有效接入
- **THEN** 任务管理技能 MUST 默认调用显式关联动作，并核对返回的任务与聊天身份

#### Scenario: 创建成功但不能关联
- **WHEN** 新任务已创建但聊天身份或有效 Codex 接入不可用
- **THEN** 系统 MUST 保留任务并说明尚未关联，不创建替代聊天或阻止其他任务操作

#### Scenario: 无聊天来源或明确不关联
- **WHEN** 任务来自 DSH、无聊天的命令入口，或用户明确要求不关联
- **THEN** 系统 MUST 不自动建立 Codex 关系

### Requirement: 任务关联入口清楚展示当前事实

任务无会话（Session）关系时 MUST 简洁显示“尚未关联会话”，不得默认展示确认流程、大块空态或不可操作入口。帮助 MUST 提供包含任务编号及工作空间定位的可复制指令。已关联任务 MUST 提供准确会话（Session）的打开与解除，关系展示 MUST 不依赖插件状态，旧请求 MUST 不阻塞长期关系。

#### Scenario: 空状态
- **WHEN** 任务没有会话（Session）关系
- **THEN** 任务页 MUST 简洁显示尚未关联并提供具体关联指令

#### Scenario: 已有关联无需面板
- **WHEN** 任务有准确关系且没有安装 Buildr 插件
- **THEN** 任务页 MUST 继续提供准确会话（Session）链接及管理操作

### Requirement: 智能体关联入口必须使用会话术语

相关界面、帮助与知识说明 MUST 用会话（Session）表示有身份及上下文的智能体工作单元，用对话表示交流内容。会话 MAY 持续保存或临时生成；统一名称 MUST NOT 合并 Codex 原生 thread 与 ACP session 的身份、协议、历史或生命周期，既有字段和命令参数 MUST 保持兼容。

#### Scenario: 关联与临时生成并存
- **WHEN** 用户查看任务关联或生成提交说明
- **THEN** 入口 MUST 使用会话用语，并区分 Codex 原生会话关联与独立临时生成，不暗示共用执行后台
