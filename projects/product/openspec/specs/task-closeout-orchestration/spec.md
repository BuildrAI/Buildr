# task-closeout-orchestration Specification

## Purpose

定义已有自举脚本如何独立处理直接交付后的激活；不要求旧收尾运行，不撤销已成立交付。 脚本核对明确任务、Git 基线、目标和远端，再处理适用的同步、开发应用更新与最终诊断，资源清理仍由原所有者独立执行。

## Requirements

### Requirement: 自举激活必须支持无旧收尾运行的直接交付
同一自举技能（Skill）脚本 MUST 支持以真实基线、已交付提交、目标分支、远端与明确 Node 为待核验输入。脚本 MUST 以 `deliveredRef`、远端回读及 Git 身份证明交付；任务编号 MAY 作为说明，但 MUST NOT 要求任务存在、已完成或包含特定范围。脚本 MUST 不读取旧 Finish run、`noChange` 或其他任务结果分类作为交付证明，也不创建虚假收尾运行。

#### Scenario: 直接交付
- **WHEN** Git 证明交付提交在目标远端，且实际改动命中自举范围
- **THEN** 唯一脚本 MUST 执行适用自举动作，不要求任务记录、`noChange`、Candidate 或 Handoff

#### Scenario: 输入不匹配
- **WHEN** 工作空间（Workspace）、基线、提交、目标、远端或 Node 不能证明一致
- **THEN** 脚本 MUST 在相关副作用前停止并保留原交付结果

#### Scenario: 激活局部失败
- **WHEN** 交付已成立但同步、安装或诊断失败
- **THEN** 脚本 MUST 记录已发生动作并返回独立 attention
- **AND** MUST 不撤销任务完成或重新推送业务内容

### Requirement: 已知未提交同步结果必须支持显式安全恢复

唯一自举执行器 MUST 接受显式临时恢复输入，绑定原基线、交付提交、目标分支、远端、智能体适配器（Agent Adapter）、预期当前提交和精确同步文件的内容摘要。仅当当前 Git 身份、全部未提交路径和文件内容均与该输入一致，且文件属于允许同步的源资产范围时，执行器 MUST 接续自身提交、推送及后续激活，不重复同步或要求额外持久状态库。恢复输入 MUST NOT 被视为交付已成立的证明，实际远端和祖先关系仍须核对。

#### Scenario: 同步成功但暂存失败
- **WHEN** 智能体（Agent）核对已成功同步的产物并提供精确恢复输入，当前现场与输入一致
- **THEN** 原执行器 MUST 接续精确提交与后续适用激活，返回已实际发生的副作用

#### Scenario: 恢复输入或现场发生漂移
- **WHEN** 交付参数、当前提交、文件路径或内容不匹配，或包含允许同步范围外的文件
- **THEN** 执行器 MUST 在提交或推送前拒绝恢复，保留全部未提交内容，不自动丢弃、隐藏或夺锁

#### Scenario: 普通未提交内容没有恢复输入
- **WHEN** 保留工作空间（Workspace）存在未提交内容且未提供显式恢复输入
- **THEN** 执行器 MUST 继续拒绝把未知内容混入激活
