# project-knowledge-browsing Specification

## Purpose
让用户在 Buildr Web 的项目和服务范围内，围绕同一对象阅读架构关系、代码组织和解释，并追溯指导技能（Skill）、规范、代码与验证依据；保持内容唯一、来源可观察及局部缺失可理解。

## Requirements

### Requirement: 知识阅读必须保持对象和范围身份
Buildr MUST 按当前已登记项目（Project）、服务（Service）及代码库实例（Repository Instance）解析知识范围，支持项目与服务内入口；同一服务被多个项目引用时 MUST 阅读同一服务成果，保留进入时的项目上下文，不复制正文或混用分支副本。

#### Scenario: 从两个项目进入共享服务
- **WHEN** 两个项目引用同一服务并打开其知识
- **THEN** 服务对象和成果身份相同，各自保留项目返回路径，来源对应同一已选代码库实例

#### Scenario: 当前范围尚未建设知识
- **WHEN** 该范围没有知识导航或相关成果
- **THEN** 页面说明尚未建设，保留已有文档阅读入口，不生成空内容或阻止无关操作

### Requirement: 多种成果必须围绕同一对象互相定位
页面 MUST 支持解释、技术图（Technical Diagram）和代码地图（Code Map）的关联阅读，并提供术语解释；同一对象可有多种图，图、目录和模块可一对多关联。切换或返回 MUST 保留对象与适用阅读位置，多个关联目标 MUST 明确供用户选择。

#### Scenario: 从图示进入对应实现
- **WHEN** 用户选择跨服务关系中的一个对象并查看代码地图（Code Map）
- **THEN** 页面定位该对象对应的实际服务、职责与目录文件，而非仅按同名猜测路径
- **AND** 返回图示时仍能识别原对象

### Requirement: 指导与事实来源必须可独立追溯
用户 MUST 能从对象查看相关技能（Skill）、规范条目、代码文件及适用验证依据；关系 MUST 区分指导、实现、依据和解释。技能（Skill）展示 MUST 说明实际来源与当前选择，未安装或未创建项不得冒充可用；源码 MUST 只读显示并支持必要定位。

#### Scenario: 查看建设方法与实现
- **WHEN** 用户从知识建设与维护对象分别打开指导技能（Skill）和实现文件
- **THEN** 页面展示对应的真实内容及来源身份，返回不丢失当前对象，不因查看执行技能或修改文件

### Requirement: 来源观察必须表达实际内容和局部限制
每次读取知识正文、图示、地图或来源 MUST 返回当前本地文件内容及可读性；成功状态 MUST 为 `readable`，缺失或不可读 MUST 分别表达。历史摘要字段 MUST 不触发变化、过期或待核对状态；读取 MUST 不写回文件或核对记录，不提供本轮新增的历史比较、确认与正文编辑接口。当前内容摘要可用于读取一致性，不得解释为语义验证或历史版本。

#### Scenario: 来源在两次阅读间改变
- **WHEN** 用户再次展开或刷新对象，其正文或来源内容已改变
- **THEN** 页面显示当前文件内容，不显示基于历史版本的告警，不要求更新索引摘要或人工确认
- **AND** 读取前后的文件及索引内容保持不变

#### Scenario: 一项来源缺失
- **WHEN** 相关来源被删除或访问失败
- **THEN** 页面明确该项限制，其他可读内容仍能查看，不用空白或全局故障隐藏事实

#### Scenario: 旧索引保留观察摘要
- **WHEN** 现有索引携带与当前内容不同的 observedDigest 或 graphDigest
- **THEN** 当前内容正常读取，旧摘要不影响可读状态，也不产生待核对要求

### Requirement: 知识读取和图示展示必须保持既有安全边界
读取 MUST 限于登记范围和允许的知识、技能（Skill）、规范与文本源码，拒绝绝对路径、路径穿越、符号链接越界、凭证文件及超限内容；MUST 不自动切换分支或访问任意本机文件。图示展示 MUST 隔离其脚本与主页面权限，保持离线能力，不扩大网络或主页面访问权限。

#### Scenario: 关联试图读取范围外文件
- **WHEN** 关联路径经真实路径解析后越界或指向禁止内容
- **THEN** 接口拒绝该项且不返回正文，其他合法引用不受影响

#### Scenario: 图示包含主动脚本
- **WHEN** 用户打开包含交互脚本的图示
- **THEN** 图示不能读取主页面会话、访问外部网络或导航顶层页面，允许的节点选择只定位已关联对象

### Requirement: 修改意见必须携带当前上下文
从知识阅读提出修改时 MUST 复用已有智能体（Agent）动作方式，携带当前范围、对象、已观察版本及用户选择的相关引用；MUST 不把查看或形成上下文当作批准、发送或执行修改。

#### Scenario: 用户基于当前对象提出建议
- **WHEN** 用户在服务对象阅读中提出建设意见
- **THEN** 接续入口能够识别同一服务、对象和来源观察，用户意见保持原意，未实际执行的动作明确说明

### Requirement: 用户必须能围绕理解目标发起架构知识建设
项目与服务知识首页 MUST 提供“构建架构知识”入口，包括尚未建设知识的范围。用户只需描述主题，可限定关注范围与想弄懂的问题；页面 MUST 使用当前登记范围身份，MUST NOT 要求用户选择专业技能（Skill）或枚举源码文件。首轮沿用既有智能体（Agent）动作接续，生成可查看、复制的建设指令；MUST 明确区分指令形成、复制与实际成果完成，不直接伪造文章或创建占位成果。

#### Scenario: 在尚无知识的项目发起建设
- **WHEN** 用户在有效项目范围填写主题并生成建设指令
- **THEN** 指令保留用户原意、当前项目身份与限定范围，说明以事实源建设架构文章并按需引用图和地图
- **AND** 页面明确显示尚未执行，生成或复制不改变项目知识文件

#### Scenario: 完善当前架构文章
- **WHEN** 用户在文章页选择“完善这篇说明”并描述问题
- **THEN** 接续内容指向当前文章、对象、来源观察和用户意见，优先完善唯一正文，不另建同名内容

### Requirement: 建设成果必须回到项目知识中供阅读和判断
已授权建设的结果 MUST 包含可独立阅读的实际文章及必要关联；智能体（Agent）按当前范围维护已有知识入口或创建适用局部索引。页面刷新后 MUST 读取真实成果，能从项目知识找到文章，打开其引用并继续完善。文章 MUST 帮助理解目的、职责、关系、约束、实现位置和修改影响，按主题选择必要内容，MUST NOT 以技能触发或提示词生成作为建设完成。

#### Scenario: 智能体完成文章后再次阅读
- **WHEN** 智能体完成真实文章、必要图示或地图及阅读关联
- **THEN** 用户刷新项目知识可进入该文章并追溯来源
- **AND** 当前事实、有依据的设计理由、尚未证实的推断和建设建议明确区分

### Requirement: 知识导航必须保留项目阅读上下文
项目知识 MUST 在同一项目主标签内进入，保留返回项目及浏览历史。三个分类列表 MUST 统一进入主屏详情，文中关联的技术图、地图与文件 MUST 在副屏阅读；同一范围切换正文或分类 MUST 保留已有副屏及其阅读状态。源码与技能详情 MUST 复用已有副屏模式，关闭后回到原阅读上下文。

#### Scenario: 从文章对照图示与代码地图
- **WHEN** 用户从项目进入知识文章并打开内嵌成果
- **THEN** 不增加第二个项目主标签，副屏显示同一成果，主文档仍可阅读
- **AND** 切换项目、返回或关闭副屏不静默混用其他主题与来源

服务知识 MUST 在当前服务副屏进入，目录、成果与下级资料在原位阅读且支持返回服务；直接地址也 MUST 保留对应目录与服务身份，不新增服务知识主标签。文章关联知识 MUST 具有与知识入口一致的链接、图示、代码地图和来源诊断能力，合法引用不得显示原始标记或默默失效；读取仍限于已登记范围。

#### Scenario: 从服务及文章接续知识阅读
- **WHEN** 用户从服务详情进入知识，或从文章相关资料打开知识正文并跟随其链接
- **THEN** 主屏来源 MUST 保持，副屏原位展示完整内容、可读图示和链接，并可返回上一级
- **AND** 未登记或不可读引用 MUST 局部提示，不能扩大文件读取范围

从代码地图（Code Map）、来源文件或关联资料进入的 Markdown 阅读模式 MUST 与同一范围成果正文具有一致的链接、内嵌技术图及地图能力；只在选择查看原文后显示源标记。来源属于其他登记范围时 MUST 按其实际身份解析引用，不套用宿主范围。服务主页 MUST 以身份与职责为首；仅已有独立成果时在资料区提供次要知识入口，无内容不显示空卡，读取失败不得冒充尚无内容。

#### Scenario: 从代码地图打开正文来源
- **WHEN** 用户从项目代码地图打开含相对链接与内嵌成果的 Markdown 来源文件
- **THEN** 副屏 MUST 展示可点击链接和已登记的图示与地图，并可继续阅读及返回
- **AND** 查看原文 MUST 展示同一文件真实内容，不能因阅读入口不同退化为裸标记

#### Scenario: 服务尚无知识内容
- **WHEN** 用户打开没有独立知识成果的服务主页
- **THEN** 页面 MUST 先展示服务身份与职责，不显示顶部知识卡；已有资料、代码库与编辑仍可用
- **AND** 服务确有独立成果时 MUST 在资料区提供次要入口，旧知识地址继续可访问

### Requirement: 三类成果目录必须共享检索方式
知识目录 MUST 提供架构知识、技术图和代码地图三个分类，使用同样的关键词检索与列表样式；检索范围明确为标题、主题说明和已登记路径，空结果可清除条件。代码地图区 MUST 区分专题地图与未建设的全景地图。技术图分类 MUST 提供单独构建入口，指令以图示与事实依据为交付，不强制新建文章。

#### Scenario: 检索与单独构建技术图
- **WHEN** 用户切换分类或检索词后选择构建技术图
- **THEN** 目录展示匹配条目并保留当前范围，接续指令明确只构建所请求图示和必要关联
- **AND** 生成或复制指令不创建空图、不报告建设完成

### Requirement: 阅读内容必须按理解目标组织来源
正文与地图 MUST 就近呈现必要规范、技能职责、代码位置和协作解释，默认不重复展开全部来源清单；实际来源缺失或不可读 MUST 保持可发现，并可打开相应文件查看；不为文件内容变化增加核对入口。目录与文件 MUST 使用原生可点击引用，范围根明确，长路径不得挤压职责文字。

#### Scenario: 不阅读源码理解实现
- **WHEN** 用户查看地图
- **THEN** 能结合职责说明、协作次序和带说明的目录结构理解实现，点击文件或技能后才进入具体内容

### Requirement: 文件树必须支持理解后的渐进展开
代码地图 MUST 包含相关规范与真实实现文件，并区分关联成果文件。目录树 MUST 紧凑、可点击和可折叠，按作者标明的业务范围默认展开祖先、收起业务目录内部；未标明时使用明确的层级默认值。文件详情 MUST 先呈现有依据的总体说明，再展示实际文件；缺少说明时如实提示，不依目录名编造职责。

#### Scenario: 展开到业务实现并阅读文件
- **WHEN** 用户进入知识维护地图并展开业务目录
- **THEN** 可通过目录名称、引导线或键盘展开与收起，展开到具体文件后先读职责说明再读源文件
- **AND** 规范与成果文件也有真实可点击入口

### Requirement: 独立技术图必须保留原生呈现
独立技术图详情 MUST 使用原 Archify HTML 的完整查看界面，只有文内预览使用嵌入模式；Buildr MUST 不复制图示内部工具栏或改写生成内容，列出明确关联的图源、展示、依据与引用文件。图示导出只允许下载本地成果，仍禁止主页面同源访问、外部连接及顶层导航。来源读取 MUST 只在缺失或不可读时提示，不保留独立来源核对栏目，也不因图源或展示与历史摘要不同而要求确认。

#### Scenario: 查看原图与维护文件
- **WHEN** 用户从技术图列表进入独立详情
- **THEN** 原生主题、检索、缩放及适用导出入口保持，图示文件树可以读取对应的实际文件
- **AND** 文件打开不执行其内容或放宽其他页面的隔离策略

### Requirement: 专业方法必须优先展示可阅读正文
技能（Skill）详情 MUST 默认显示实际 `SKILL.md` 正文，其他参考文件按需查找和打开，保留既有编辑与来源信息。技术图（Technical Diagram）的建设方法 MUST 按技能身份归并，以名称和职责呈现；同一方法的补充材料不得重复挤占主要入口。独立图示 MUST 保留原生交互，在有限阅读高度内可滚动和放大。

#### Scenario: 从技术图打开建设方法
- **WHEN** 用户点击某项建设方法
- **THEN** 副屏直接读取该技能的正文，可展开查找其他文件，返回后继续阅读原图
- **AND** 不因查看而执行技能或修改文件

### Requirement: 技术图尺寸必须来自当前安全读取的展示成果

知识读取的 JSON 响应 MUST 在成果对象中提供只读字段 `diagramSize`，值为 `{ width, height }` 或 `null`。有效尺寸 MUST 来自当前已通过既有有界读取的原生 HTML 主 SVG `viewBox`，宽和高 MUST 为有限正数；不得以可能陈旧的图源或固定比例冒充实际尺寸。非技术图（Technical Diagram）、不可读成果或无法可靠识别的展示 MUST 返回 `null`，不阻止其他内容阅读。JSON 中的图示 `content` MUST 继续为 `null`，完整 HTML 仍仅由既有隔离展示入口提供；尺寸读取 MUST 不执行 HTML、不新增任意文件读取或写回。

#### Scenario: 返回当前原生展示的尺寸

- **WHEN** 用户读取含有可识别主 SVG 及有效 `viewBox` 的技术图
- **THEN** 成果的 `diagramSize` 为该 `viewBox` 的宽和高，`content` 为 `null`
- **AND** 尺寸与该次读取的展示内容对应，即使配套图源尚未同步也不改用图源尺寸

#### Scenario: 无法识别或读取尺寸

- **WHEN** 成果不是技术图、展示不可读、主 SVG 无法识别或尺寸缺失及非法
- **THEN** `diagramSize` 为 `null`，来源限制沿用已有诊断，其他可读成果不受影响

### Requirement: 文内技术图预览必须按实际比例适配容器

文内技术图（Technical Diagram）预览在有有效 `diagramSize` 时 MUST 按当前容器宽度、图示宽高比及既有嵌入模式留白计算高度，容器宽度改变后 MUST 重新适配，避免固定比例造成的额外底部空白或裁切。尺寸为 `null` 或旧响应没有尺寸字段时 MUST 沿用既有尺寸回退。独立详情和放大阅读 MUST 保留原生完整查看界面、正常内容阅读和既有隔离策略，不得通过隐藏、裁切内容或放宽脚本权限消除空白。

#### Scenario: 阅读不同宽高比的内嵌图示

- **WHEN** 用户阅读横向或较高的原生图示，并调整正文容器宽度
- **THEN** 预览高度随图形实际比例及嵌入留白更新，完整图面可见，底部不残留固定比例额外撑出的区域

#### Scenario: 阅读旧图及独立图示

- **WHEN** 用户打开未知尺寸图示，或进入独立详情和放大阅读
- **THEN** 未知尺寸内嵌图沿用原有回退，独立详情及放大阅读保留原生主题、检索、缩放和适用导出
- **AND** 不修改展示 HTML，不改变主页面、网络及顶层导航隔离边界

### Requirement: 知识目录必须按页查询并返回有限摘要
项目与服务知识目录 MUST 使用目录专用只读查询，支持架构知识、技术图、代码地图分类及现有关键词匹配范围。每页默认且最多返回 20 项，响应 MUST 包含当前范围、索引版本、匹配总数、当前页条目及后续游标；条目仅提供导航所需摘要，MUST NOT 随目录响应返回完整索引、全部来源或正文。原有对象、成果和来源读取接口 MUST 保持兼容与既有读取边界。

#### Scenario: 打开有超过一页内容的目录
- **WHEN** 用户打开包含 45 项匹配内容的知识目录
- **THEN** 首次请求仅返回前 20 项摘要、匹配总数与续页游标
- **AND** 页面不并行请求旧的完整索引来实现目录渲染

#### Scenario: 分类检索与空结果
- **WHEN** 用户切换分类或输入匹配标题、主题说明或路径的关键词
- **THEN** 后端按条件分页，最后一页允许少于 20 项且没有后续游标
- **AND** 空结果保持构建与清除检索入口可用

### Requirement: 知识续页必须绑定同一读取范围和索引版本
续页游标 MUST 绑定当前知识范围、分类、查询、页大小与索引版本。无效或不匹配的游标 MUST 被拒绝；索引版本变化 MUST 返回可识别的刷新提示，MUST NOT 把不同版本的条目静默拼接。读取和拒绝游标均 MUST 不修改知识文件。

#### Scenario: 两页之间目录改变
- **WHEN** 用户读取下一页前索引已改变
- **THEN** 接口返回目录变化的明确诊断，页面保留已读内容并提供刷新入口
- **AND** 刷新从当前条件的第一页重新开始

#### Scenario: 游标被用于其他范围或条件
- **WHEN** 请求将已有游标用于不同范围、分类、查询或页大小，或传入损坏游标
- **THEN** 接口拒绝该请求，原有知识与其他读取不受影响

### Requirement: 知识目录必须连续续载并保护阅读上下文
目录 MUST 每批请求和追加 20 项，在已加载内容的第 15、35、55 项附近进入可见区域时请求下一批。重复观察 MUST 不产生同一游标的并发请求；失败 MUST 保留已读条目并允许显式重试或刷新，MUST NOT 无界自动重试。切换范围、分类或关键词后，旧响应 MUST 不污染新列表。追加、进入详情再返回目录 MUST 保持适用的已加载内容和阅读位置。

#### Scenario: 滚动到续载触发位置
- **WHEN** 用户滚动至首批第 15 项附近且存在下一页
- **THEN** 页面请求下一页并追加结果，用户当前位置不被重置
- **AND** 到达最后一页后不再请求不存在的下一页

#### Scenario: 续载失败或筛选在请求中改变
- **WHEN** 续页请求失败，或用户在请求完成前改变筛选条件
- **THEN** 失败可显式重试且已有内容保留；过时请求被取消或其结果被忽略
- **AND** 成功结果按身份去重，不重复追加已有条目

### Requirement: 知识阅读必须保留可达的返回与回顶部入口
知识主阅读区的面包屑 MUST 在列表或正文滚动时保持可见，并保留返回项目、服务和知识目录的原有能力。页面 MUST 提供一键回到顶部入口，该动作只改变当前知识主阅读区的滚动位置，MUST NOT 改变右侧引用内容的阅读位置、筛选条件或已加载批次；导航 MUST 不遮挡正文。

#### Scenario: 阅读长列表或长文
- **WHEN** 用户向下滚动知识主阅读区
- **THEN** 面包屑持续可用，用户能一键返回顶部
- **AND** 左右阅读区同时打开时，回顶部不移动右侧引用区
