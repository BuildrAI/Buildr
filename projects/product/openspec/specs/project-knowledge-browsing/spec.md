# project-knowledge-browsing Specification

## Purpose
让用户在 Buildr Web 的项目和服务范围内，围绕同一对象阅读架构关系、代码组织和解释，并追溯指导技能（Skill）、规范、代码与验证依据；保持内容唯一、来源可观察及局部缺失可理解。

## Requirements

### Requirement: 知识阅读必须保持对象和范围身份
Buildr MUST 按当前已登记项目（Project）、服务（Service）及代码库实例（Repository Instance）解析知识范围，支持项目与服务内入口；同一服务被多个项目引用时 MUST 阅读同一服务成果，保留进入时的项目上下文，不复制正文或混用分支副本。

#### Scenario: 从两个项目进入共享服务
- **WHEN** 两个项目引用同一服务并打开其知识
- **THEN** 服务对象和成果身份相同，各自保留项目返回路径，来源对应同一已选代码库实例

#### Scenario: 当前范围尚未建设知识
- **WHEN** 该范围没有知识导航或相关成果
- **THEN** 页面说明尚未建设，保留已有文档阅读入口，不生成空内容或阻止无关操作

### Requirement: 多种成果必须围绕同一对象互相定位
页面 MUST 支持解释、技术图（Technical Diagram）和代码地图（Code Map）的关联阅读，并提供术语解释；同一对象可有多种图，图、目录和模块可一对多关联。切换或返回 MUST 保留对象与适用阅读位置，多个关联目标 MUST 明确供用户选择。

#### Scenario: 从图示进入对应实现
- **WHEN** 用户选择跨服务关系中的一个对象并查看代码地图（Code Map）
- **THEN** 页面定位该对象对应的实际服务、职责与目录文件，而非仅按同名猜测路径
- **AND** 返回图示时仍能识别原对象

### Requirement: 指导与事实来源必须可独立追溯
用户 MUST 能从对象查看相关技能（Skill）、规范条目、代码文件及适用验证依据；关系 MUST 区分指导、实现、依据和解释。技能（Skill）展示 MUST 说明实际来源与当前选择，未安装或未创建项不得冒充可用；源码 MUST 只读显示并支持必要定位。

#### Scenario: 查看建设方法与实现
- **WHEN** 用户从知识建设与维护对象分别打开指导技能（Skill）和实现文件
- **THEN** 页面展示对应的真实内容及来源身份，返回不丢失当前对象，不因查看执行技能或修改文件

### Requirement: 来源观察必须表达实际内容和局部限制
每次读取知识正文、图示、地图或来源 MUST 返回当前本地文件内容及可读性；成功状态 MUST 为 `readable`，缺失或不可读 MUST 分别表达。历史摘要字段 MUST 不触发变化、过期或待核对状态；读取 MUST 不写回文件或核对记录，不提供本轮新增的历史比较、确认与正文编辑接口。当前内容摘要可用于读取一致性，不得解释为语义验证或历史版本。

#### Scenario: 来源在两次阅读间改变
- **WHEN** 用户再次展开或刷新对象，其正文或来源内容已改变
- **THEN** 页面显示当前文件内容，不显示基于历史版本的告警，不要求更新索引摘要或人工确认
- **AND** 读取前后的文件及索引内容保持不变

#### Scenario: 一项来源缺失
- **WHEN** 相关来源被删除或访问失败
- **THEN** 页面明确该项限制，其他可读内容仍能查看，不用空白或全局故障隐藏事实

#### Scenario: 旧索引保留观察摘要
- **WHEN** 现有索引携带与当前内容不同的 observedDigest 或 graphDigest
- **THEN** 当前内容正常读取，旧摘要不影响可读状态，也不产生待核对要求

### Requirement: 知识读取和图示展示必须保持既有安全边界
读取 MUST 限于登记范围和允许的知识、技能（Skill）、规范与文本源码，拒绝绝对路径、路径穿越、符号链接越界、凭证文件及超限内容；MUST 不自动切换分支或访问任意本机文件。图示展示 MUST 隔离其脚本与主页面权限，保持离线能力，不扩大网络或主页面访问权限。

#### Scenario: 关联试图读取范围外文件
- **WHEN** 关联路径经真实路径解析后越界或指向禁止内容
- **THEN** 接口拒绝该项且不返回正文，其他合法引用不受影响

#### Scenario: 图示包含主动脚本
- **WHEN** 用户打开包含交互脚本的图示
- **THEN** 图示不能读取主页面会话、访问外部网络或导航顶层页面，允许的节点选择只定位已关联对象

### Requirement: 修改意见必须携带当前上下文
从知识阅读提出修改时 MUST 复用已有智能体（Agent）动作方式，携带当前范围、对象、已观察版本及用户选择的相关引用；MUST 不把查看或形成上下文当作批准、发送或执行修改。

#### Scenario: 用户基于当前对象提出建议
- **WHEN** 用户在服务对象阅读中提出建设意见
- **THEN** 接续入口能够识别同一服务、对象和来源观察，用户意见保持原意，未实际执行的动作明确说明

### Requirement: 用户必须能围绕理解目标发起架构知识建设
项目与服务知识首页 MUST 提供“构建架构知识”入口，包括尚未建设知识的范围。用户只需描述主题，可限定关注范围与想弄懂的问题；页面 MUST 使用当前登记范围身份，MUST NOT 要求用户选择专业技能（Skill）或枚举源码文件。首轮沿用既有智能体（Agent）动作接续，生成可查看、复制的建设指令；MUST 明确区分指令形成、复制与实际成果完成，不直接伪造文章或创建占位成果。

#### Scenario: 在尚无知识的项目发起建设
- **WHEN** 用户在有效项目范围填写主题并生成建设指令
- **THEN** 指令保留用户原意、当前项目身份与限定范围，要求以事实源组织目标、职责、关系、关键行为及重要取舍，按当前阅读问题选择必要解释和视图
- **AND** 页面明确显示尚未执行，生成或复制不改变项目知识文件

#### Scenario: 完善当前架构文章
- **WHEN** 用户在文章页选择“完善这篇说明”并描述问题
- **THEN** 接续内容指向当前文章、对象、来源观察和用户意见，优先完善唯一正文，不另建同名内容

### Requirement: 建设成果必须回到项目知识中供阅读和判断
已授权建设的结果 MUST 包含可独立阅读的实际结构化解释及必要关联；智能体（Agent）按当前范围维护已有知识入口或创建适用局部索引。页面刷新后 MUST 读取真实成果，能从项目知识找到内容，打开其引用并继续完善。成果 MUST 帮助理解目标、职责、关系、关键行为、重要约束和有依据的设计取舍，按主题选择必要内容与视图；实现细节按需要深入，MUST NOT 以技能触发或提示词生成作为建设完成。

#### Scenario: 智能体完成文章后再次阅读
- **WHEN** 智能体（Agent）完成真实解释、必要图示或地图及阅读关联
- **THEN** 用户刷新项目知识可进入该成果并追溯来源
- **AND** 当前事实、有依据的设计理由、尚未证实的推断和建设建议明确区分

### Requirement: 知识导航必须保留项目阅读上下文
项目知识 MUST 在同一项目主标签内进入，保留返回项目及浏览历史。左侧目录中的主题与成果入口 MUST 统一进入主屏详情，文中关联的技术图、地图与文件 MUST 在副屏阅读；同一范围切换正文、阅读方式或筛选 MUST 保留已有副屏及其阅读状态。源码与技能详情 MUST 复用已有副屏模式，关闭后回到原阅读上下文。

#### Scenario: 从文章对照图示与代码地图
- **WHEN** 用户从项目进入知识文章并打开内嵌成果
- **THEN** 不增加第二个项目主标签，副屏显示同一成果，主文档仍可阅读
- **AND** 切换项目、返回或关闭副屏不静默混用其他主题与来源

服务知识 MUST 在当前服务副屏进入，目录、成果与下级资料在原位阅读且支持返回服务；直接地址也 MUST 保留对应目录与服务身份，不新增服务知识主标签。文章关联知识 MUST 具有与知识入口一致的链接、图示、代码地图和来源诊断能力，合法引用不得显示原始标记或默默失效；读取仍限于已登记范围。

#### Scenario: 从服务及文章接续知识阅读
- **WHEN** 用户从服务详情进入知识，或从文章相关资料打开知识正文并跟随其链接
- **THEN** 主屏来源 MUST 保持，副屏原位展示完整内容、可读图示和链接，并可返回上一级
- **AND** 未登记或不可读引用 MUST 局部提示，不能扩大文件读取范围

从代码地图（Code Map）、来源文件或关联资料进入的 Markdown 阅读模式 MUST 与同一范围成果正文具有一致的链接、内嵌技术图及地图能力；只在选择查看原文后显示源标记。来源属于其他登记范围时 MUST 按其实际身份解析引用，不套用宿主范围。服务主页 MUST 以身份与职责为首；仅已有独立成果时在资料区提供次要知识入口，无内容不显示空卡，读取失败不得冒充尚无内容。

#### Scenario: 从代码地图打开正文来源
- **WHEN** 用户从项目代码地图打开含相对链接与内嵌成果的 Markdown 来源文件
- **THEN** 副屏 MUST 展示可点击链接和已登记的图示与地图，并可继续阅读及返回
- **AND** 查看原文 MUST 展示同一文件真实内容，不能因阅读入口不同退化为裸标记

#### Scenario: 服务尚无知识内容
- **WHEN** 用户打开没有独立知识成果的服务主页
- **THEN** 页面 MUST 先展示服务身份与职责，不显示顶部知识卡；已有资料、代码库与编辑仍可用
- **AND** 服务确有独立成果时 MUST 在资料区提供次要入口，旧知识地址继续可访问

### Requirement: 三类成果目录必须共享检索方式
主题阅读与文档目录 MUST 共用位于左侧目录上方的关键词检索和可选类型过滤，支持说明文档、技术图与代码地图，默认可查阅全部适用类型；检索范围明确为标题、主题或章节说明和已登记路径，空结果可清除条件。目录 MUST 保留匹配项祖先并展开可达条目，包括命中的补充阅读；过滤只影响导航，不清空右侧正文。代码地图 MUST 按实际成果提供专题与实现定位入口；没有明确建设状态依据时 MUST NOT 推断全景地图尚未建设。页级动作 MUST 保留单独构建技术图入口，指令以图示与事实依据为交付，不强制新建文章。

#### Scenario: 检索与单独构建技术图
- **WHEN** 用户切换分类或检索词后选择构建技术图
- **THEN** 目录展示匹配条目并保留当前范围，接续指令明确只构建所请求图示和必要关联
- **AND** 生成或复制指令不创建空图、不报告建设完成

### Requirement: 阅读内容必须按理解目标组织来源
正文与地图 MUST 就近呈现必要规范、技能职责、代码位置和协作解释，默认不重复展开全部来源清单；实际来源缺失或不可读 MUST 保持可发现，并可打开相应文件查看；不为文件内容变化增加核对入口。目录与文件 MUST 使用原生可点击引用，范围根明确，长路径不得挤压职责文字。

#### Scenario: 不阅读源码理解实现
- **WHEN** 用户查看地图
- **THEN** 能结合职责说明、协作次序和带说明的目录结构理解实现，点击文件或技能后才进入具体内容

### Requirement: 文件树必须支持理解后的渐进展开
代码地图 MUST 包含相关规范与真实实现文件，并区分关联成果文件。目录树 MUST 紧凑、可点击和可折叠，按作者标明的业务范围默认展开祖先、收起业务目录内部；未标明时使用明确的层级默认值。文件详情 MUST 先呈现有依据的总体说明，再展示实际文件；缺少说明时如实提示，不依目录名编造职责。

#### Scenario: 展开到业务实现并阅读文件
- **WHEN** 用户进入知识维护地图并展开业务目录
- **THEN** 可通过目录名称、引导线或键盘展开与收起，展开到具体文件后先读职责说明再读源文件
- **AND** 规范与成果文件也有真实可点击入口

### Requirement: 独立技术图必须保留原生呈现
独立技术图详情 MUST 使用原 Archify HTML 的完整查看界面，只有文内预览使用嵌入模式；Buildr MUST 不复制图示内部工具栏或改写生成内容，列出明确关联的图源、展示、依据与引用文件。图示导出只允许下载本地成果，仍禁止主页面同源访问、外部连接及顶层导航。来源读取 MUST 只在缺失或不可读时提示，不保留独立来源核对栏目，也不因图源或展示与历史摘要不同而要求确认。

#### Scenario: 查看原图与维护文件
- **WHEN** 用户从技术图列表进入独立详情
- **THEN** 原生主题、检索、缩放及适用导出入口保持，图示文件树可以读取对应的实际文件
- **AND** 文件打开不执行其内容或放宽其他页面的隔离策略

### Requirement: 专业方法必须优先展示可阅读正文
技能（Skill）详情 MUST 默认显示实际 `SKILL.md` 正文，其他参考文件按需查找和打开，保留既有编辑与来源信息。技术图（Technical Diagram）的建设方法 MUST 按技能身份归并，以名称和职责呈现；同一方法的补充材料不得重复挤占主要入口。独立图示 MUST 保留原生交互，在有限阅读高度内可滚动和放大。

#### Scenario: 从技术图打开建设方法
- **WHEN** 用户点击某项建设方法
- **THEN** 副屏直接读取该技能的正文，可展开查找其他文件，返回后继续阅读原图
- **AND** 不因查看而执行技能或修改文件

### Requirement: 技术图尺寸必须来自当前安全读取的展示成果

知识读取的 JSON 响应 MUST 在成果对象中提供只读字段 `diagramSize`，值为 `{ width, height }` 或 `null`。有效尺寸 MUST 来自当前已通过既有有界读取的原生 HTML 主 SVG `viewBox`，宽和高 MUST 为有限正数；不得以可能陈旧的图源或固定比例冒充实际尺寸。非技术图（Technical Diagram）、不可读成果或无法可靠识别的展示 MUST 返回 `null`，不阻止其他内容阅读。JSON 中的图示 `content` MUST 继续为 `null`，完整 HTML 仍仅由既有隔离展示入口提供；尺寸读取 MUST 不执行 HTML、不新增任意文件读取或写回。

#### Scenario: 返回当前原生展示的尺寸

- **WHEN** 用户读取含有可识别主 SVG 及有效 `viewBox` 的技术图
- **THEN** 成果的 `diagramSize` 为该 `viewBox` 的宽和高，`content` 为 `null`
- **AND** 尺寸与该次读取的展示内容对应，即使配套图源尚未同步也不改用图源尺寸

#### Scenario: 无法识别或读取尺寸

- **WHEN** 成果不是技术图、展示不可读、主 SVG 无法识别或尺寸缺失及非法
- **THEN** `diagramSize` 为 `null`，来源限制沿用已有诊断，其他可读成果不受影响

### Requirement: 文内技术图预览必须按实际比例适配容器

文内技术图（Technical Diagram）预览在有有效 `diagramSize` 时 MUST 按当前容器宽度、图示宽高比及既有嵌入模式留白计算高度，容器宽度改变后 MUST 重新适配，避免固定比例造成的额外底部空白或裁切。尺寸为 `null` 或旧响应没有尺寸字段时 MUST 沿用既有尺寸回退。独立详情和放大阅读 MUST 保留原生完整查看界面、正常内容阅读和既有隔离策略，不得通过隐藏、裁切内容或放宽脚本权限消除空白。

#### Scenario: 阅读不同宽高比的内嵌图示

- **WHEN** 用户阅读横向或较高的原生图示，并调整正文容器宽度
- **THEN** 预览高度随图形实际比例及嵌入留白更新，完整图面可见，底部不残留固定比例额外撑出的区域

#### Scenario: 阅读旧图及独立图示

- **WHEN** 用户打开未知尺寸图示，或进入独立详情和放大阅读
- **THEN** 未知尺寸内嵌图沿用原有回退，独立详情及放大阅读保留原生主题、检索、缩放和适用导出
- **AND** 不修改展示 HTML，不改变主页面、网络及顶层导航隔离边界

### Requirement: 知识目录必须按页查询并返回有限摘要
兼容保留的项目与服务成果分页接口 MUST 使用目录专用只读查询，支持架构知识、技术图、代码地图分类及现有关键词匹配范围。每页默认且最多返回 20 项，响应 MUST 包含当前范围、索引版本、匹配总数、当前页条目及后续游标；条目仅提供导航所需摘要，MUST NOT 随目录响应返回完整索引、全部来源或正文。原有对象、成果和来源读取接口 MUST 保持兼容与既有读取边界。

#### Scenario: 打开有超过一页内容的目录
- **WHEN** 调用方通过分页接口读取包含 45 项匹配内容的目录
- **THEN** 首次请求仅返回前 20 项摘要、匹配总数与续页游标
- **AND** 分页查询不隐式读取完整索引正文或全部来源；主阅读导航可使用独立的有界元数据查询

#### Scenario: 分类检索与空结果
- **WHEN** 调用方以分类或匹配标题、主题说明或路径的关键词请求分页接口
- **THEN** 后端按条件分页，最后一页允许少于 20 项且没有后续游标
- **AND** 空结果返回零条目和无后续游标，不影响其他读取

### Requirement: 知识续页必须绑定同一读取范围和索引版本
续页游标 MUST 绑定当前知识范围、分类、查询、页大小与索引版本。无效或不匹配的游标 MUST 被拒绝；索引版本变化 MUST 返回可识别的刷新提示，MUST NOT 把不同版本的条目静默拼接。读取和拒绝游标均 MUST 不修改知识文件。

#### Scenario: 两页之间目录改变
- **WHEN** 用户读取下一页前索引已改变
- **THEN** 接口返回目录变化的明确诊断，页面保留已读内容并提供刷新入口
- **AND** 刷新从当前条件的第一页重新开始

#### Scenario: 游标被用于其他范围或条件
- **WHEN** 请求将已有游标用于不同范围、分类、查询或页大小，或传入损坏游标
- **THEN** 接口拒绝该请求，原有知识与其他读取不受影响

### Requirement: 知识目录必须连续续载并保护阅读上下文
主阅读界面 MUST 使用独立的有界完整导航，不依赖滚动追加才发现主题或成果。查询、类型过滤、用户展开和选中正文 MUST 独立保留；进入正文、切换阅读方式及历史返回 MUST 恢复适用导航与阅读定位。搜索临时展开 MUST NOT 覆盖用户原展开状态。范围变化后旧异步响应 MUST NOT 污染新范围，失败 MUST 保留可用内容并允许显式重试，不无界自动重试。

#### Scenario: 滚动到续载触发位置
- **WHEN** 导航包含45项成果，用户滚动经过旧第15项续载位置或检索第45项
- **THEN** 无需加载更多即可定位该成果，导航不预读正文

#### Scenario: 检索与阅读独立
- **WHEN** 用户阅读正文时改变检索、选择匹配条目，再清空搜索或返回
- **THEN** 输入过程中原正文持续可读，选中文章后才切换正文，清空搜索恢复原树展开
- **AND** 历史返回恢复适用查询、过滤与阅读位置，其他范围的响应不得混入

#### Scenario: 续载失败或筛选在请求中改变
- **WHEN** 旧调用者的分页请求失败，或导航请求期间用户改变范围或筛选
- **THEN** 已读内容保持且可显式重试，过时响应被取消或忽略，成功条目按身份去重
- **AND** 主阅读目录不依赖续页，不因查询变化清空已选正文

### Requirement: 知识阅读必须保留可达的返回与回顶部入口
知识主阅读区的面包屑 MUST 在列表或正文滚动时保持可见，并保留返回项目、服务和知识目录的原有能力。页面 MUST 提供一键回到顶部入口，该动作只改变当前知识主阅读区的滚动位置，MUST NOT 改变右侧引用内容的阅读位置、筛选条件或已加载批次；导航 MUST 不遮挡正文。

#### Scenario: 阅读长列表或长文
- **WHEN** 用户向下滚动知识主阅读区
- **THEN** 面包屑持续可用，用户能一键返回顶部
- **AND** 左右阅读区同时打开时，回顶部不移动右侧引用区

### Requirement: 主题目录与全部资料必须共享唯一成果登记
主题目录 MUST 从当前范围索引的主题及父子关系呈现，主题资料（旧称“全部资料”）MUST 从同一索引的成果登记检索；两种入口 MUST 读取同一正文，MUST NOT 各维护一套文件或资料清单。主题阅读与文档目录 MUST 在顶部清晰切换，下方只展示当前阅读方式需要的目录；文档模式 MUST NOT 同时展示无关主题侧栏。全部主题资料 MUST 可从同一目录检索到，不用额外醒目的模式按钮与正文列表竞争；默认阅读仍由已登记默认主题决定。说明文档分类 MUST 包含普通说明与术语资料。

#### Scenario: 一份资料关联多个主题
- **WHEN** 同一已登记成果关联多个主题或暂未关联主题
- **THEN** 全部资料仍只列出该成果一次；关联主题中的入口指向同一份正文，未关联资料仍可检索

#### Scenario: 术语资料参与统一检索
- **WHEN** 当前范围登记了术语资料
- **THEN** 用户可在全部资料的说明文档分类检索和打开该成果，无需额外复制为普通说明

### Requirement: 尚无知识的项目必须得到可直接接续的建设引导
项目主页与知识页面在成功确认当前范围没有已登记成果时 MUST 主动提供建立知识入口，自动带上已解析范围、已观察修订和预置理解目标。打开该入口 MUST 立即得到可查看复制的建设指令，用户 MAY 补充关注点，MUST NOT 被要求先拟主题、枚举文件或选择技能（Skill）。指令 MUST 使用现有知识建设能力，要求先核对最新事实、已有主题及未登记资料，再建立整体认识、主干主题与继续探索方向；MUST NOT 固定复制某个示例项目的目录或为目录节点机械生成文章。

#### Scenario: 首次为项目建立知识
- **WHEN** 用户打开已确认尚无登记成果的项目并选择建立项目知识
- **THEN** 当前项目身份与理解整体、主要部分及探索方向的目标已准备好，可直接复制接续；关注点可选
- **AND** 页面明确尚未执行，打开或复制不会写入知识文件或创建占位成果

#### Scenario: 已有结构需要补齐内容
- **WHEN** 范围有主题结构但尚未登记实际成果
- **THEN** 建设请求保留该观察并要求复用当前主题和已有资料，必要时补齐默认整体认识与引用，而非覆盖重建

#### Scenario: 局部空结果不等于项目没有知识
- **WHEN** 范围已有图、地图、术语或说明成果，但当前分类为空或搜索没有匹配项
- **THEN** 页面仍按已有知识提供正常阅读与检索，不出现首次建设误报
- **AND** 导航只根据索引计算全部成果总数，不为判断空状态提前读取正文

#### Scenario: 读取状态尚不确定
- **WHEN** 范围仍在加载或知识读取失败
- **THEN** 页面保留相应读取或重试状态，不将未知状态判为尚无知识，不自动发起建设

### Requirement: 知识入口必须呈现可持续探索的主题结构
项目与服务知识 MUST 复用索引中主题的父子关系与顺序呈现完整目录，MUST NOT 根据成果分页推断主题全集。索引 MAY 声明已登记的默认主题；正常进入时 MUST 阅读该主题，未声明时 MUST 提供主题入口，未建设时仍可发起探索和建设。目录读取 MUST 只获取有界主题和成果导航元数据，不读取成果正文和来源；成果只包含身份、标题、类型、路径及关联主题，MUST NOT 重复扩张主题长说明。用户指定的主题、成果、来源和文档定位 MUST 优先于默认主题；检索定位保留在左侧且不改变已经选中的正文，旧索引与旧链接 MUST 保持有效。

#### Scenario: 从整体认识进入专题
- **WHEN** 用户进入已声明默认主题的项目知识
- **THEN** 页面打开该主题，目录展示可继续选择的主题及其父子关系
- **AND** 切换主题后目录仍可到达，宽阅读区并列展示，窄阅读区可折叠展开

#### Scenario: 在主题内选择表达形式
- **WHEN** 主题关联了说明、技术图或代码地图
- **THEN** 用户可在该主题内查看这些成果，阅读引用与返回能力保持
- **AND** 没有直接成果的父主题仍提供子主题入口，不伪造正文

#### Scenario: 资料分页不隐藏主题
- **WHEN** 当前范围的成果超过目录单页数量，或某主题没有直接成果
- **THEN** 主题导航仍完整展示已登记结构，不依赖加载更多资料

#### Scenario: 保留全部资料与明确定位
- **WHEN** 用户主动进入全部资料、检索内容或打开已有成果链接
- **THEN** 页面遵守明确内容定位，检索保留在目录，旧全部资料地址仍进入主题阅读；未归入主题的成果仍可找到
- **AND** 从目录阅读内容后返回仍回到原检索范围

#### Scenario: 旧索引与无知识范围
- **WHEN** 有效索引没有声明默认主题，或范围尚无知识索引
- **THEN** 前者呈现主题入口与全部资料，后者保留只读探索与建设入口，不因新字段缺失报错

### Requirement: 知识阅读必须支持有范围的探索与追问
项目与服务知识入口 MUST 提供看全貌、跟一个场景、深入某部分的探索方式，并允许自由描述问题；当前内容 MUST 提供追问理解入口，与建设及完善长期内容区分。指令 MUST 携带当前登记范围、已读取的对象及来源上下文，要求智能体（Agent）核实相关最新事实后解释，默认只读、不自动建设或修改长期知识。页面 MUST 使用既有可查看复制的接续方式，明确未执行；没有有效范围或必要问题时不得生成指令。

#### Scenario: 尚无知识时了解项目全貌
- **WHEN** 用户在有效项目范围选择看全貌
- **THEN** 无需预先创建文档或知道主题名称，即可生成带当前范围的只读探索指令

#### Scenario: 跟随场景或深入部分
- **WHEN** 用户选择跟一个场景或深入某部分
- **THEN** 页面要求明确场景或部分，保留用户补充的问题，并生成对应的有界调查指令

#### Scenario: 从当前内容追问
- **WHEN** 用户在可读成果中提出进一步理解的问题
- **THEN** 指令保留该成果、当前项目或服务身份与已观察来源，明确只读回答；复制不触发执行或文件写入

#### Scenario: 从解释转向维护
- **WHEN** 用户明确选择完善当前内容并提交意见
- **THEN** 生成有该范围维护授权的指令，保留当前成果身份；不沿用只读追问分支造成实际维护请求丢失

### Requirement: 知识入口必须提供由实际文件形成的文档目录
项目与服务知识 MUST 在现有主题阅读之外提供文档目录，以安全发现的实际 Markdown 文件为范围，按读者的阅读目的与章节编排显示标题、用途、顺序和数量；列表 MUST NOT 用物理目录树或文件名承担阅读结构，真实路径和来源 MUST 在具体阅读时仍可查看。目录 MUST 独立于知识成果登记，复用同一文件正文，读取不写回索引或另建正文；无知识索引时仍可发现允许位置的文档。范围 MUST 包括当前登记范围、项目关联服务的真实文档位置以及工作空间根级阅读入口和 docs 说明；重复真实文件 MUST 去重，工作空间公共说明的来源身份 MUST 保留。目录扫描 MUST 有界，达到上限或部分读取失败时 MUST 明确说明，不能把已发现数量当作完整总数。

#### Scenario: 未登记手册与已有主题并存
- **WHEN** 项目包含未登记的使用指南和已登记知识主题
- **THEN** 用户可从同一知识入口的目录找到指南，同时继续按原主题、图和地图阅读
- **AND** 目录的章节、标题、用途及兼容路径搜索与文件数量基于实际可发现文件，不把每份指南创建为新主题

#### Scenario: 当前文件发生变化
- **WHEN** 文件被新增、改名、合并或删除后刷新目录
- **THEN** 目录按当前文件重新发现，条目不因旧编排而虚构存在；已删除内容打开时明确不可读
- **AND** 返回目录保留适用的关键词与定位

#### Scenario: 无索引与大型目录
- **WHEN** 当前范围没有知识索引，或文档扫描达到上限
- **THEN** 前者仍能查阅已有普通文档；后者明确范围不完整且允许继续读取已列文件

#### Scenario: 按阅读目的选择正文与补充材料
- **WHEN** 文档已编排阅读章节、用途、顺序及补充阅读属性
- **THEN** 用户看到章节与有意义的标题，主正文优先，补充阅读可展开且全部参与搜索
- **AND** 搜索命中的补充材料可直接打开，返回保留适用检索条件

### Requirement: 自动文档发现必须限制扫描和读取范围
文档目录 MUST 排除隐藏路径、凭证与敏感内容、依赖和构建产物、规范与历史变更、技能与规则、随包资源副本及测试样本。目录与正文 MUST 使用同一允许位置和安全校验，拒绝符号链接、绝对路径、路径穿越、禁止位置、二进制与超过读取上限的文件；查询 MUST 不执行命令、不跟随外部链接、不改变任何文件或 Git 状态。关联服务 MUST 依据实际登记解析，不能任意浏览工作空间外文件。

#### Scenario: 任意文档标识尝试越界
- **WHEN** 调用方篡改标识指向隐藏、敏感、未关联服务或范围外文件
- **THEN** 接口拒绝且不返回正文，合法目录仍可读取

#### Scenario: 普通文档内继续阅读
- **WHEN** 文内链接能匹配允许目录中的另一份文档或已登记成果
- **THEN** 用户可在现有阅读界面继续打开同一正文，已登记成果保留图与来源能力
- **AND** 不可读取的引用有明确提示，不通过放宽路径边界或复制正文实现跳转

### Requirement: 文档编排必须与实际发现共同形成完整阅读目录
文档阅读编排 MUST 在现有知识索引中可选维护，只保存章节及已发现文件的阅读元数据，不复制正文或强制增加主题。编排 MUST 有界并按显式顺序呈现，同一文件只计一次；编排只能匹配当前允许范围已经发现的文件，MUST NOT 授予任意路径读取权限。未编排、无编排或局部无效的已发现文件 MUST 保留在其他文档中；失效条目只诊断，不能虚构文件、破坏已有主题读取或把辅助阅读隐藏出总数。编排变化 MUST 影响目录读取版本，正文的标题与章节元数据 MUST 与同次目录解释一致。

#### Scenario: 新增文件但尚未组织
- **WHEN** 已发现文档没有编排，或已有文档旁新增未编排文件
- **THEN** 它们仍在其他文档中可检索与阅读，总数包括这些文件
- **AND** 页面不依目录名编造阅读用途

#### Scenario: 编排部分失效或试图越权
- **WHEN** 条目引用不存在、敏感或未发现文件，重复引用同一文件，或者一部分编排格式无效
- **THEN** 系统仅对相应编排诊断，合法文档继续阅读，重复内容不重复计数，未成功编排的实际文件保留
- **AND** 原主题读取不因文档编排字段局部无效而失败

#### Scenario: 编排改变后刷新
- **WHEN** 章节、显示标题、用途、次序或补充阅读属性改变，正文文件没有改变
- **THEN** 刷新得到新的目录版本和当前编排，打开正文继续对应原来的唯一文件

### Requirement: 两种知识阅读方式必须共享持续导航布局
主题阅读与文档目录 MUST 使用相同层级和交互：顶部切换阅读方式，左侧检索、可选类型过滤和语义目录树，右侧展示选中内容。选择内容后目录 MUST 仍可到达，不用物理文件树或大卡片列表替代语义阅读结构。宽阅读区 MUST 并列显示，窄屏和服务侧读 MUST 提供可折叠目录并保证搜索在目录上方，不挤出正文。探索与建设动作 MUST 与检索分离，主题内部成果切换仍限于当前主题。

#### Scenario: 主屏和侧读阅读
- **WHEN** 用户在项目主屏、服务侧读或窄屏切换两种阅读方式并打开内容
- **THEN** 使用同一目录和搜索交互，正文留在原阅读区，目录不消失或造成横向溢出
- **AND** 文内关联仍复用既有安全阅读器和主副屏身份

### Requirement: 文档目录必须支持已有真实文件作为入口
知识索引 MAY 可选指定文档入口的位置和相对路径；系统 MUST 仅从当前安全发现的文件中解析入口并返回可空的真实文档身份。正常进入文档模式时 MUST 打开有效入口，显式文档或成果定位优先。入口 MUST 在导航中可达，同一文件不得重复列入章节或计数；未配置、失效或格式错误时 MUST 保留文档目录供选择，局部诊断不得破坏主题读取或扩大扫描和读取权限。

#### Scenario: 默认阅读和明确定位
- **WHEN** 当前范围有有效文档入口且用户没有指定其他内容
- **THEN** 页面打开该入口，左侧选中同一真实文档，全部文档计数只包含它一次
- **AND** 带明确文档或成果身份的旧链接仍打开指定内容

#### Scenario: 入口不存在或试图越权
- **WHEN** 入口引用已删除、敏感、范围外或未发现文件，或入口配置无效
- **THEN** 文档目录保留合法内容，显示适用局部诊断，入口身份为空
- **AND** 不猜测打开其他文件，不阻止正常主题阅读，不通过入口绕过原安全扫描
