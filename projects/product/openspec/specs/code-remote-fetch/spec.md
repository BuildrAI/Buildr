# code-remote-fetch Specification

## Purpose
为已登记代码库（Repository）提供由明确用户动作发起的单库及批量获取远程（Fetch），更新本机远程跟踪记录，使新分支可发现；以已观察 Git 身份、明确配置和逐库结果保护当前工作、隔离联网失败，并保持目录刷新与 Git 写入职责独立。

## Requirements

### Requirement: 显式范围与身份保护

获取远程（Fetch）MUST 是独立的显式写入能力，单库与批量输入 MUST 绑定已观察代码库（Repository）身份及 Git 身份，不接受任意目录、远程地址或命令。服务端 MUST 重新核对登记来源和当前 Git 身份，只执行请求明确列出的实例；来源、检出目录或 Git 元数据被替换（包括相同路径替换）MUST 拒绝该实例，不扩展到新登记对象。超文本传输协议（HTTP）入口 MUST 复用当前同源会话（Session）写入授权，只读命令和工作进程 MUST NOT 因此取得写入能力。

#### Scenario: 单库与已观察全部范围
- **WHEN** 用户选择单库获取或对当前已观察全部代码库执行获取
- **THEN** 系统 MUST 仅操作该明确范围，逐项核对当前登记及 Git 身份，不从任意目录或未观察新实例推断目标

#### Scenario: 来源漂移
- **WHEN** 请求中的代码库身份已移除或 Git 来源被替换，包括同路径 Git 元数据替换
- **THEN** 对应实例 MUST 不执行获取，其他健康实例仍可按明确范围继续

### Requirement: 远程记录更新与当前成果保留

获取远程（Fetch）MUST 基于服务端已核对的本机远程配置，固定本次地址及远程跟踪映射并在执行前复核配置；仅支持写入远程跟踪引用的映射。会写入本地分支（Branch）或其他不支持目标的配置 MUST 局部拒绝，不静默改写配置。获取 MUST 保留当前分支、索引（Index）、未提交文件及本地分支成果，MUST NOT 自动拉取（Pull）、合并、变基、切换、推送、清理远程跟踪引用或递归更新子模块。联网与认证失败 MUST 明确表达，不能报告为已同步。

#### Scenario: 新远程分支可发现
- **WHEN** 本地观察之后远程新增 dev，用户显式获取
- **THEN** 本机远程跟踪记录及刷新后的管理清单 MUST 包含实际获取的 origin/dev，当前本地分支和未提交内容 MUST 保持；获取 MUST NOT 自动创建或切换本地 dev

#### Scenario: 现有改动与不安全映射
- **WHEN** 当前存在暂存或未提交文件，或一个远程映射指向本地分支
- **THEN** 安全获取 MUST 保留原文件和索引，不安全映射 MUST 在对应远程执行前拒绝，MUST NOT 修改本地分支或配置

### Requirement: 有界批量与逐库结果

同一批获取 MUST 按真实 Git 公共目录（Common Directory）去重，同库多个工作树（Worktree）MUST NOT 重复联网获取。批量 MUST 有明确并发和超时边界，某个代码库或远程失败 MUST 不阻止其他健康对象完成。结果 MUST 按请求实例及远程表达成功、失败、不可用或结果未知；超时、部分完成或身份漂移后 MUST 保留已知效果，MUST NOT 假定未发生更新或自动重发写入。

#### Scenario: 多库部分失败与共享工作树
- **WHEN** 批量包含同一真实仓库的多个工作位置，另一个仓库认证失败
- **THEN** 共享仓库 MUST 只获取一次且映射回各请求结果，健康对象 MUST 成功，失败对象 MUST 单独表达原因

### Requirement: 页面入口与受影响内容更新

分支（Branch）管理 MUST 提供单库获取远程（Fetch），代码库列表 MUST 提供全部已观察代码库的获取入口，并与只读刷新区别。操作进行中 MUST 有真实等待状态；完成后 MUST 提供逐库结果并重新观察受影响目录及已打开的分支清单。单库获取 MUST 不刷新无关代码库；全部获取 MAY 使用一次明确的全目录刷新。跨工作空间迟到结果 MUST 不更新其他工作空间，不依赖原行组件仍挂载，也不自动重发获取。

#### Scenario: 获取后本机分支清单更新
- **WHEN** 用户在已打开的分支管理中执行单库获取并完成
- **THEN** 该清单及该库状态 MUST 重新读取，其他库和当前固定阅读 MUST 保持；失败或未知 MUST 可单独查看
