# agent-conversations Specification

## Purpose
定义 Buildr 内部统一对话（Conversation）的创建、执行、可见历史、准确恢复及顺序切换智能体（Agent）行为，使日常咨询和实际工作具有完整交互闭环，并保持各家原生会话（Session）、任务（Task）和真实工作成果各自的权威边界。

下文的原生程序、厂家配置及原生会话（Session）操作描述首版 Codex、DSH、Qoder 的适配行为。公共执行契约按 `agent-runtime-connections` 定义，只依赖可核验的绑定与恢复引用；未来执行者（Executor）不必伪造外部命令行或厂家会话编号，也不能省略准确身份、状态观察和未知不重发的边界。

## Requirements

### Requirement: 自动标题必须是与工作上下文隔离的简短摘要

新对话开始执行、原生上下文可用后，系统 MUST 尽早使用可信原生摘要或一次有界独立摘要回填简短主题名称；首轮执行成功后仍未命名时 MUST 继续完成同一有界生成作为兜底。系统 MUST NOT 把首条指令的截取冒充智能体（Agent）总结。起名 MUST 不向工作原生上下文追加消息、不重放工具、不改变执行位置或原生恢复身份。标题生成失败 MUST 不阻止对话使用，保留中性名称；生成尝试状态 MUST 在重启后保持，避免重复调用。手动改名 MUST 优先于自动标题，迟到结果 MUST 校验准确对话及已观察版本。

#### Scenario: 执行开始后尽早回填
- **WHEN** 新对话的首次执行开始且原生上下文已可用
- **THEN** 系统 MUST 基于本次用户输入以有界独立摘要尝试生成精短标题并回填
- **AND** 生成失败、执行方未提供摘要能力或结果被拒时 MUST 保留中性名称，不影响本次执行，且首轮成功后的兜底生成仍可进行

#### Scenario: 用户在自动标题返回前改名
- **WHEN** 用户已经手动保存名称，原摘要稍后完成
- **THEN** 系统 MUST 保留手动名称，MUST NOT 用后台结果覆盖
- **AND** 原工作对话及执行状态 MUST 不受起名成功或失败影响

#### Scenario: 厂家只返回首句截取标题
- **WHEN** 原生标题元数据表明结果为简单回退截取而非模型摘要
- **THEN** 系统 MUST 不将其标为已生成摘要标题
- **AND** 可使用已声明的隔离摘要能力，或保持中性名称，MUST NOT 向工作会话塞入起名指令

#### Scenario: 旧对话请求简短标题
- **WHEN** 用户对已完成且具有真实问答的准确对话明确请求“生成简短标题”
- **THEN** 系统 MUST 以已观察修订有界生成该段对话的名称，MUST NOT 根据猜测批量覆盖其他旧名称
- **AND** 请求期间用户再次手动保存名称时 MUST 保留新的手动名称，失败 MUST 不影响工作历史或发起工作重放

### Requirement: 内部对话必须具有独立稳定身份和准确工作范围

Buildr MUST 为每段内部对话（Conversation）保存稳定身份、标题、所属工作空间（Workspace）、准确起始目录（CWD）及观察版本。标题、可见历史和入口 MUST 不随执行方切换而改变归属。普通对话 MUST 不要求关联任务（Task）；每段对话只保存至多一个可选任务引用，创建后 MUST 可以按当前观察版本设置、更换或解除，任务身份 MUST 由宿主权威校验且 MUST 不复制任务状态。工作目录 MUST 在首次发送前明确可见并固定到该原生执行范围，查看其他页面 MUST 不自动改写它或注入页面内容。

#### Scenario: 普通咨询无需任务
- **WHEN** 用户从全局入口创建普通对话
- **THEN** 系统 MUST 创建独立对话并显示当前保存的工作空间（Workspace）与执行位置，不强制创建任务（Task）
- **AND** 创建或打开动作 MUST 不自动发送模型指令

#### Scenario: 创建后维护任务引用
- **WHEN** 用户对准确对话明确设置、更换或解除任务引用并提供当前观察版本
- **THEN** 系统 MUST 校验任务身份后原子保存新引用，隐藏、标题等其他字段 MUST 不被该动作改写
- **AND** 任务不可用、版本冲突或工作空间不受支持时 MUST 拒绝并保留原引用与全部历史

#### Scenario: 浏览另一工作对象
- **WHEN** 用户在保留当前对话时打开另一任务或项目页面
- **THEN** 当前对话的身份、草稿、归属和执行位置 MUST 保持
- **AND** 新页面内容 MUST 只有在用户明确加入时才成为交付输入

### Requirement: 任务入口必须只维护内部对话引用

一个任务（Task）MUST 可以具有多段内部对话（Conversation），任务入口 MUST 按零、一、多条实际关系分别创建、直接打开或选择准确对话。创建前 MUST 核对已登记工作空间（Workspace）及任务身份，保存任务引用而非复制任务状态。内部关系 MUST 不混入旧外部原生会话（Session）关系数量，也不因新增参与者而重复关联。第一版 MUST 不增加跨任务移交或通用关系管理器。

#### Scenario: 任务尚无内部对话
- **WHEN** 用户在任务中选择打开内部对话且不存在对应记录
- **THEN** Buildr MUST 创建关联该准确任务的新对话并展示输入界面
- **AND** MUST NOT 自动寻找或打开外部桌面会话

#### Scenario: 任务存在多个内部对话
- **WHEN** 一个任务有多段内部对话
- **THEN** 系统 MUST 允许用户按对话标题、时间及状态选择准确目标
- **AND** MUST NOT 仅根据最近活动或当前 Agent 品牌猜测目标

### Requirement: 统一可见历史必须保留来源并与原生上下文分离

Buildr MUST 持久保存属于统一对话（Conversation）的用户输入、展示回复、参与变化、必要工具结果及其来源引用，并为可见记录提供稳定身份和顺序。各参与者 MUST 绑定准确连接、执行者绑定身份和可核验的恢复引用；首版三家将该引用映射到准确配置来源与原生会话（Session）编号。隐藏推理、上下文压缩与执行恢复状态 MUST 继续由相应执行者（Executor）维护，公共层不复制或解释其私有格式。历史入口 MUST 按对话组织，不能按 Agent 品牌拆散同一主题。文件和外部系统 MUST 继续作为成果当前事实的权威来源。

#### Scenario: 同一主题由多家参与
- **WHEN** Codex、DSH、Qoder 依次参与同一内部对话
- **THEN** 用户 MUST 在一个历史主题中看到原顺序的记录及每条内容的实际来源
- **AND** 输入框选择变化 MUST 不重标已有回复或生成新的历史主题

#### Scenario: 原生历史重读
- **WHEN** 重连后重新读取已显示过的原生条目
- **THEN** Buildr MUST 按准确参与关系和稳定原生来源去重，不重复显示同一用户输入
- **AND** 无法可靠映射的来源 MUST 明确诊断，不猜测合并或重放历史工具和授权

### Requirement: 创建和发送必须保留尝试与接收事实

用户首次发送时，Buildr MUST 按需建立或恢复准确原生会话（Session），保存本次创建和发送尝试、输入身份及实际原生接收结果。重复提交同一已受理请求 MUST 返回其原有身份；并发或过期请求 MUST 明确冲突而非产生第二次执行。原生创建已成功而本地绑定未完成时 MUST 保留已知身份并重新观察。结果未知 MUST 不自动解释为未执行，也 MUST 不自动另建会话或重发指令。

#### Scenario: Codex 空会话尚未持久化
- **WHEN** 本次新创建的 Codex 原生编号尚未接收首条输入，历史读取明确报告未物化
- **THEN** 系统 MUST 仅对这个确知未发送的新建对象表达空历史，并继续准确记录创建与发送事实
- **AND** 已有绑定恢复失败 MUST NOT 被吞掉或显示为新空会话

#### Scenario: 发送超时但可能已被接收
- **WHEN** 发送返回前连接断开或后端退出，无法确认原生是否已接收
- **THEN** 系统 MUST 保留输入与未知结果，并先观察原生历史、本轮状态及必要工作现场
- **AND** 刷新、重连及用户重复提交同一请求 MUST NOT 自动造成第二次执行

### Requirement: 输入与执行反馈必须构成日常使用闭环

对话 MUST 支持文本输入、流式回复、基本工具进度、必要文件改动与错误反馈；必要图片 MUST 按所选接入及模型的真实能力提供有界输入和本机私有保存。不支持或超限时 MUST 在发送前说明并保留草稿。执行中用户主动发送的补充 MUST 使用当前执行身份与原配置；未发送输入仍为草稿，MUST NOT 因输入或刷新自动交付。补充 MUST 不切换参与者、模型、权限或执行位置，不隐含回应原生授权和业务问题。

#### Scenario: 执行中主动补充图文
- **WHEN** 当前执行身份已确认，用户主动发送文字、图片或图文组合
- **THEN** 系统 MUST 将该输入交付同一执行并独立保存其尝试与接收结果，原执行继续可观察及可停止
- **AND** 界面 MUST 沿用普通消息展示，不要求切换插入或排队模式

#### Scenario: 执行中继续编辑
- **WHEN** 用户只编辑输入，或原执行正在启动、停止、工具退出或状态未知而不能安全追加
- **THEN** 系统 MUST 保留草稿；用户尝试发送时 MUST 明确解释当前受影响动作，MUST NOT 自动另开执行或假称已送达

#### Scenario: 图片输入超过限制
- **WHEN** 图片不符合所选模型支持范围或超过已声明大小
- **THEN** 系统 MUST 提示受影响图片和原因，并保留可继续编辑的文本与材料
- **AND** MUST NOT 通过静默删图把请求显示成完整发送

#### Scenario: 等待明确授权时补充
- **WHEN** 原执行等待授权或业务问题，而用户发送普通补充
- **THEN** 原请求 MUST 继续保留，只有其独立回应才可以解决该请求
- **AND** 补充失败 MUST 不停止原执行或删除待回应事实

#### Scenario: 文件已被其他入口修改
- **WHEN** 智能体（Agent）继续读取或修改已有成果
- **THEN** 工作依据 MUST 是当前文件或外部系统事实，历史工具摘要不能证明内容仍未变化
- **AND** 工作页面 MUST 能继续使用原查询与刷新读取同一成果，不要求新增通用工作对象库

### Requirement: 控制请求必须及时作用于准确执行

同一内部对话（Conversation）第一版 MUST 只允许一个活动执行者，多个页面可以观察同一事实。发送准入与状态写入 MUST 使用有界短操作，不持锁等待整轮模型结束。停止、授权回复和问题回答 MUST 能独立及时处理，并核对连接、配置、参与者、本轮执行、原生请求及服务代次。原生未知交互 MUST 不默认批准；迟到或已失效回复 MUST 不应用到新执行。

#### Scenario: 权限选择绑定准确本轮
- **WHEN** 用户准备并发送默认权限或完全访问模式的输入
- **THEN** 系统 MUST 将实际权限模式纳入能力校验、发送预览、输入身份与本轮持久记录，模式变化后原预览 MUST 失效
- **AND** 刷新或重启 MUST 能读回本轮模式，旧记录缺失模式时 MUST 解释为默认权限而非推断完全访问
- **AND** 同一对话换家 MUST 保留明确选择；新对话 MUST 恢复软件级记住的权限选择，没有已保存选择的新草稿 MUST 初始选择完全访问，已有明确选择 MUST 优先且不改写旧轮次

#### Scenario: 模型正在等待授权
- **WHEN** 原生执行发出工具授权请求
- **THEN** 系统 MUST 展示原生动作、对象与实际可选决定，并将答复送回产生请求的准确执行
- **AND** 停止请求 MUST 不需要等待模型本轮完成

#### Scenario: 输入框已选择另一参与者
- **WHEN** 当前仍存在原参与者的授权或补充问题
- **THEN** 对该请求的答复 MUST 继续指向其原参与者及本轮身份，不随输入框选择改变

#### Scenario: 服务重启后收到旧回应
- **WHEN** 回应携带的服务代次或原生请求已失效
- **THEN** 系统 MUST 拒绝应用该回应并重新观察当前待回应事实
- **AND** MUST NOT 把其内容用于新的授权请求

### Requirement: 停止必须区分模型中断和活动工具退出

用户停止时系统 MUST 先发送原生中断并显示正在停止，自动观察本轮模型及相关活动工具的真实结果。中断请求成功或模型本轮结束 MUST 不单独证明命令退出。仍有活动工具时 MUST 显示准确未停项并提供可验证的针对性停止；状态无法确认时 MUST 明确未知。只有本轮相关执行已确认停止且不会继续延迟写入时，才可显示已停止。停止 MUST 不误停此前用户有意保留、与本轮无关的后台服务。

#### Scenario: 正常停止得到完整确认
- **WHEN** 原生确认本轮中断且相关活动工具均退出
- **THEN** 系统 MUST 自动显示已停止并保留历史和已发生的修改
- **AND** MUST 不要求用户为正常路径再手动核验一次

#### Scenario: Codex 中断后命令仍在运行
- **WHEN** 模型本轮已中断而本轮原生终端仍有活动命令
- **THEN** 系统 MUST 显示命令仍运行，并按准确原生终端身份停止与核对退出
- **AND** MUST NOT 用全对话清理或未经核实的操作系统进程号替代针对性处理

#### Scenario: 当前工具不支持单独停止
- **WHEN** 原生接入无法按准确工具身份单独停止某活动命令
- **THEN** 界面 MUST 不将该工具展示为可单独停止，仍保留活动事实与重新观察入口
- **AND** 单工具停止被拒绝时 MUST 保留原本轮状态，MUST NOT 先标为整轮正在停止或据后续空闲误标全部已停止

#### Scenario: 断线后结果未知
- **WHEN** 连接断开导致不能确认执行或工具终态
- **THEN** 系统 MUST 显示状态未知并允许重新观察，保留历史和草稿
- **AND** 未确认结束前 MUST 拒绝该对话的新执行或换家发送，但不阻止其他独立对话

### Requirement: 查看和恢复必须优先观察原生事实

查看对话 MUST 首先提供统一可见历史；继续执行前 MUST 恢复所选参与者的原连接、配置来源及准确原生会话（Session），核对活动执行、待回应和新增历史。刷新、重连及后端重启 MUST 不自动重发可能产生副作用的输入。原生上下文不能恢复时 MUST 保留历史和原因，由用户明确决定是否另起执行上下文，不能静默冒充连续恢复。

#### Scenario: 重启后继续原对话
- **WHEN** 后端重启后用户打开此前已有原生绑定的对话
- **THEN** 系统 MUST 使用保存的准确原生编号恢复并补齐可见记录
- **AND** MUST NOT 通过“最近一段会话”或桌面焦点猜测目标

#### Scenario: 原生历史暂不可读
- **WHEN** 某参与者连接失效或原生历史读取失败
- **THEN** 已保存统一历史 MUST 保持可读，受影响恢复明确诊断
- **AND** MUST NOT 将失败显示为空历史，也不据此自动重建参与绑定

### Requirement: 同一对话换家必须展示真实接续材料

用户 MUST 能手动选择同一对话（Conversation）的下一位智能体（Agent）和模型（Model），选择本身不创建执行、不发送输入、不改变任务或历史身份。只有原执行及相关工具已确认结束时，才允许发送新工作。系统 MUST 在同一对话中从本地原始记录组织交接，并允许查看实际发送正文、来源范围与执行位置。材料 MUST 不含秘密、隐藏推理或无关工作空间信息，不宣称迁移私有上下文。界面 MUST 只提示实际改变的执行维度，采用紧凑轮次列表，完整正文默认收起且与页面说明明确分开；详情 MUST 从对话所在一侧展开。正常发送 MUST 不强迫用户再确认一份交接清单。

#### Scenario: 首次切换到另一家
- **WHEN** 原执行已结束，用户选择另一家并发送
- **THEN** 系统 MUST 按该选择交接同一工作并保持同一内部对话，实际交接正文可在同侧详情查看
- **AND** 历史工具操作和授权 MUST 仅作有来源的参考，不作为可重放协议请求

#### Scenario: 原执行尚未确认结束
- **WHEN** 对话执行中、待回应、正在停止、仍有活动工具或状态未知
- **THEN** 系统 MUST 阻止开始新工作并允许处理原请求、停止或重新观察
- **AND** MUST NOT 因另一家可用而自动代选或并行执行

#### Scenario: 查看发送内容
- **WHEN** 用户展开完整交接内容
- **THEN** 框内 MUST 仅展示准备实际发送的正文，框外解释 MUST 不混作发送文字
- **AND** 关闭重开 MUST 恢复正文收起，已发送回执 MUST 读取当次快照且区分确认接收与未知

### Requirement: 换回参与者必须恢复原生上下文并准确推进交付位置

换回曾参与的执行方时，系统 MUST 恢复该参与者自己的原生会话（Session），补充其尚未收到的可见变化。交付位置 MUST 绑定实际输入身份、来源范围及接收事实，只有原生确认接收后才能推进；超时未知 MUST 保留尝试并先核对，不能凭本地已发送或界面显示推进。交付位置 MUST 不代替执行完成或成果正确的判断。

#### Scenario: Codex 经两家参与后返回
- **WHEN** Codex、DSH、Qoder 顺序参与后用户换回 Codex
- **THEN** 系统 MUST 恢复原 Codex 原生编号并仅补充其未收到的 DSH、Qoder 可见变化及本次要求
- **AND** MUST 保留 Codex 已有原生上下文，不新建同名会话冒充恢复

#### Scenario: 交付确认丢失
- **WHEN** 接续输入可能已被接收但确认未返回
- **THEN** 系统 MUST 保留原交付位置和未知尝试，按原生输入身份重新观察
- **AND** MUST NOT 自动重复提交整包历史或把未确认范围标记为已交付

### Requirement: 接续超限必须保留历史并由用户明确选择

系统 MUST 分别遵守目标接入的字节容量与模型可用上下文预算，预留新输入和输出空间，不把固定 64 KiB 视为所有目标的上下文。正常交接 MUST 由 Buildr 直接组织；超过预算时 MUST 仅尝试有界、无工具且不向工作上下文追加消息的原模型整理。额度耗尽、不可用、超时或整理失败 MUST 回退到本地必要信息及可读取的分轮索引。原始记录 MUST 保留，摘要 MUST 标明来源和覆盖范围，MUST NOT 静默截断、把引用路径冒充已读取内容或要求用户手工总结。必要资料或附件仍无法安全交付时 MUST 保留草稿、说明限制并允许用户选择其他模型。

#### Scenario: 历史超过接续容量
- **WHEN** 直接组织的材料超过目标接收预算
- **THEN** 系统 MUST 才尝试原模型精简，精简仍不适用时提供本地可读取索引和准确覆盖说明
- **AND** 必要内容仍不能安全交付时 MUST 明确限制，不伪报完整交接

#### Scenario: 用户采用精简说明
- **WHEN** 旧客户端仍提交用户明确提供的精简说明
- **THEN** 系统 MUST 保存原文和来源并作为补充交付，不以该说明覆盖本地原始历史
- **AND** 后续换家或换回 MUST 仍从本地原始记录组织，不递归转发旧说明

#### Scenario: 旧模型不可用
- **WHEN** 旧模型额度不足、失效、不支持隔离整理或整理超时失败
- **THEN** 系统 MUST 不向原工作会话发送整理请求，也不阻止使用本地记录继续
- **AND** 索引缺失或不可读 MUST 明确失败，不能在缺少来源时声称交付完整

#### Scenario: 整理期间内容变化
- **WHEN** 整理返回前本地对话修订或模型绑定变化
- **THEN** 系统 MUST 拒绝把迟到结果用于旧预览或实际发送，保留草稿并重新读取当前事实
- **AND** 实际提交 MUST 使用所查看正文的准确版本，不再次悄悄生成另一份正文

### Requirement: 事件与待回应状态必须可重连且不成为成果权威

事件 MUST 保留准确对话、参与者、本轮执行、原生条目或请求来源及服务代次。事件订阅 MUST 支持有界追赶；位置失效时 MUST 重新读取历史和原生状态并去重，不能将短期事件缓存（Cache）作为唯一恢复依据。收起面板后 MUST 保留最小待授权、待回答和未知状态提示，并能定位准确对话；第一版 MUST 不增加通知中心或通用事件总线。

#### Scenario: 页面短暂断线
- **WHEN** 页面重连且原事件位置仍可用
- **THEN** 系统 MUST 补齐安全增量并对齐当前原生状态，不重复执行操作

#### Scenario: 事件位置已过期
- **WHEN** 页面请求的事件位置不在可追赶范围
- **THEN** 系统 MUST 明确要求重读当前历史及状态，再建立后续观察
- **AND** MUST NOT 以丢失事件推断执行未发生

#### Scenario: 对话面板收起后等待用户
- **WHEN** 后台对话出现有效授权、补充问题或未知执行状态
- **THEN** 全局入口 MUST 保留可发现提示，点击后打开准确对话或准确待回应列表
- **AND** 页面导航和其他安全工作 MUST 保持可用

### Requirement: 每轮模型来源必须固定并可追溯

系统 MUST 将模型账号、模型、档位及绑定版本纳入发送预览、本轮持久记录与真实请求。跨来源不兼容的原生上下文 MUST 在同一可见对话内准确接续，MUST NOT 搬运隐藏推理或静默覆盖旧恢复引用。

#### Scenario: 同名模型有多个来源
- **WHEN** 用户选择 Devin 账号的 GPT 而另有 Codex 账号提供同名模型
- **THEN** 本轮 MUST 固定使用 Devin，记录真实来源，失败时不自动扣另一套餐

#### Scenario: 原执行仍未结束
- **WHEN** 原执行、活动工具或受理结果尚未确认结束
- **THEN** 系统 MUST 保留原绑定，阻止换源开始新轮，不重放未知输入

### Requirement: 工具过程条目必须携带稳定工具名称

执行器（Executor）上报的工具条目 MUST 在确知时携带稳定工具名称（name），统一对话记录 MUST 原样保存并随条目提供。名称表示工具步骤的身份（如命令执行、文件修改或具体工具名），不表示展示文案。来源未提供稳定名称时 MUST 缺省该字段，不得伪造。

#### Scenario: Codex 工具条目
- **WHEN** Codex 会话产生命令执行、文件修改或工具调用条目
- **THEN** 记录 MUST 分别携带能区分这三类步骤的名称
- **AND** 文件修改条目的文本 MUST 保留涉及文件路径

#### Scenario: DSH 与 Qoder 工具条目
- **WHEN** DSH 或 Qoder 会话产生工具调用条目
- **THEN** 记录 MUST 携带原生工具名称
- **AND** 调用与结果更新同一记录时，名称 MUST 保留

#### Scenario: 旧记录或无名来源
- **WHEN** 条目缺少工具名称（历史数据或未上报来源）
- **THEN** 展示 MUST 以既有文本形式呈现该条目
- **AND** MUST NOT 用猜测的名称替代

### Requirement: 每轮主线必须保留用户消息与最终答复

视图 MUST 按执行轮（Run）聚合中间过程；同一执行被用户补充消息分段时 MUST 只在整轮最后一条助手消息处确定最终答复，不能将补充前的过程说明误当结束答复；用户消息、补充图片与该轮最终助手答复 MUST 按实际顺序独立留在主线。MUST NOT 用字符长度区分说明与最终答复。缺少消息阶段的历史记录 MUST 以每轮最后一条助手消息作为结束答复回退；正在执行的当前轮 MUST NOT 提前将过程说明作为结束答复。

#### Scenario: 短最终答复
- **WHEN** 一轮的最后答复为“收尾完成”或其他短消息
- **THEN** 折叠过程后该答复 MUST 仍在主线可见

#### Scenario: 长过程说明
- **WHEN** 一轮中间出现长说明且后续仍有助手消息
- **THEN** 该说明 MUST 按真实顺序位于折叠过程内
- **AND** 展开后 MUST 保留完整 Markdown 正文

#### Scenario: 运行中
- **WHEN** 当前轮尚在执行或等待操作
- **THEN** 已有说明 MUST 留在过程内
- **AND** 结束后 MUST 将最后答复呈现在过程之后

#### Scenario: 同轮中途补充
- **WHEN** 过程说明之后出现用户补充图文，再有继续过程与最终答复
- **THEN** 两段过程 MUST 分别在原位置折叠，用户补充图文 MUST 仍可见，整轮仅有最后一份最终答复
- **AND** 新一轮开始 MUST 不改写旧轮的最终答复、配置或明确展开选择

### Requirement: 工具必须按类型提供可核验详情

每个工具调用 MUST 可独立展开；命令 MUST 使用与代码导航不同的符号并展示实际命令和输出。已知文件读取或修改 MUST 根据真实工具输入提供文件打开动作，使用对话工作目录与已登记检出位置解析当前文件；无法确认唯一来源时 MUST 给出局部提示，不得打开其他工作树的同名文件。历史记录不得伪造丢失的输入。

#### Scenario: 工具完成后保留输入
- **WHEN** 来源提供原始输入而结果更新仅提供输出
- **THEN** 记录 MUST 以可选 input 保存已知原始输入并在结果更新时保留
- **AND** 旧数据缺省字段 MUST 继续可读

#### Scenario: 读取文件
- **WHEN** 文件读取调用包含可解析的真实文件路径
- **THEN** 文件名 MUST 可点击并在已有查看器打开相同实际检出位置的当前文件
- **AND** 点击文件 MUST NOT 折叠整轮过程

#### Scenario: 执行命令
- **WHEN** 展开命令调用
- **THEN** MUST 可分别核验已知原始命令与输出；缺少原始输入时 MUST 保留原始记录供查看

### Requirement: 交接必须按本地执行轮次保存可查来源

交接 MUST 从本地已有用户输入、助手说明、工具动作与结果、可确认成果和最终答复组织。执行中问题答复及授权决定 MUST 保存其问题、轮次和来源，MUST NOT 因视作另一用户消息而拆错轮次。执行概况 MUST 说明做了什么、结果怎样、到哪里查，不携带文件、脚本或日志全文；失败、未知和可能生效的操作 MUST 保留。成果 MUST 有可核对证据与位置，无法确认则明确，不把助手的完成声明视为已验证事实。原执行中断或没有最终答复 MUST 可辨识。整体交接提示词（Prompt）MUST 说明目标连续、来源解释、有效授权范围、按需查阅和继续前核对当前现场；摘要只是辅助资料。

#### Scenario: 连续三次切换
- **WHEN** A 交给 B 再交给 C，包括换回已有参与者
- **THEN** 新材料 MUST 从本地原始来源和当前成果引用组织，已有原生恢复继续只补未收到的记录
- **AND** 历史交接包和回执 MUST 不递归嵌入正文

#### Scenario: 失败与执行中回答
- **WHEN** 一轮中存在工具失败、用户回答或尚未确认结果
- **THEN** 后续执行方 MUST 能读到对应轮次的真实状态、问题和回答及证据位置
- **AND** 一次性许可 MUST 不自动变成新执行的授权

### Requirement: 对话身份必须便于识别与复制

系统 MUST 在对话历史每项显示对话 ID，并尽量将标题与元信息控制在两行内。历史筛选 MUST 搜索在前、紧凑工作空间选择在后，默认选择当前所处工作空间而非上次对话所在工作空间。当前对话标题区域 MUST 显示同一 ID 且支持复制完整值。空间不足时允许视觉省略，但 MUST NOT 改变复制内容或原有选择、重命名行为。

#### Scenario: 查找与复制当前对话
- **WHEN** 用户查看历史或打开已有对话
- **THEN** 历史与标题区域 MUST 显示同一个对话 ID，长标题不挤出第三行
- **AND** 点击复制 MUST 复制完整对话 ID，并给出成功或失败反馈

### Requirement: 对话阅读辅助必须集中且克制

标题、对话标识和前置复制图标 MUST 使用单行布局，不增加标题栏高度。复制 MUST 使用完整标识，成功浮层 MUST 自动隐藏。当前执行状态 MUST 位于输入框上方，MUST NOT 因滚动历史而不可见；历史记录与待回答请求继续可查。

#### Scenario: 复制并继续阅读
- **WHEN** 用户点击标题后标识前的复制图标
- **THEN** 系统 MUST 复制完整标识并短暂显示已复制，不能在输入区留下常驻提示

### Requirement: 交接成功动作必须去重组织

系统 MUST 合并相同类别的成功动作并保留原始数量和可读取来源；失败、未知、未结束操作与用户决定 MUST 保持可区分，原始历史和既有交接回执 MUST NOT 改写。分轮正文 MUST 易读，不逐条重复无信息增量的成功文案。

#### Scenario: 工具密集轮次
- **WHEN** 一轮多次读取、搜索或执行并含失败
- **THEN** 成功动作 MUST 统计组织，失败与对应来源 MUST 单独保留，所有原记录可按引用读取

### Requirement: 更早记录必须按用户阅读意图渐进加载

打开对话时，系统 MUST 默认返回最近 5 轮可见记录，并定位最新内容；向前分页 MUST 同样按最多 5 轮选择记录。轮次 MUST 依据真实执行身份组织，执行中的用户答复不得误算为新轮；缺少执行身份的旧记录 MUST 保持原始顺序且可继续读取。现有字节容量保护仍适用，容量受限的轮次 MUST 保留续读位置，不删除或静默跳过原始记录；显式条数限制和原有续读位置 MUST 保持兼容。

用户向上阅读且接近已加载内容顶部时，系统 MUST 提前分批加载更早记录，支持鼠标、触摸、键盘和滚动条；MUST NOT 要求点击加载按钮或完成顶部下拉手势，也 MUST NOT 显示常驻加载入口或下拉提示。每次读取 MUST 有界并防重入；补入记录 MUST 保持原阅读锚点和已有展开状态，不跳到底部。打开对话、收到流式更新或补入记录本身 MUST NOT 自动连续耗尽历史。跨对话迟到结果 MUST NOT 改变新对话的内容、加载状态和阅读位置。加载失败 MUST 保留当前内容并给出局部原因，用户继续向上阅读时 MUST 能重试。

#### Scenario: 默认读取最近轮次
- **WHEN** 打开具有超过 5 轮历史的对话，且最新 5 轮未触及容量保护
- **THEN** 系统 MUST 展示最新 5 轮的用户输入、过程和答复，工具条数不得改变轮数
- **AND** MUST 保留继续向前的准确位置，初次打开不自动拉取剩余全部历史

#### Scenario: 工具密集轮次受容量限制
- **WHEN** 一轮包含大量工具记录，选中范围触及现有字节容量保护
- **THEN** 系统 MUST 有界返回记录并保留准确续读位置，继续向上时仍可读取该轮剩余内容
- **AND** 不得删除原始记录或把容量截取误报为历史起点

#### Scenario: 连续向上阅读
- **WHEN** 用户用鼠标、触摸、键盘或滚动条向上阅读并接近顶部
- **THEN** 系统 MUST 在到达顶部前自动读取前一批，补入后正在阅读的内容保持原位置
- **AND** 不显示手动加载按钮或下拉提示，不把当前阅读强制移到最新消息

#### Scenario: 重复触发与切换对话
- **WHEN** 更早记录尚在加载时重复向上滚动，或用户在结果返回前切换对话
- **THEN** 同一选择范围 MUST 只保留一个活动读取，旧结果 MUST NOT 改变新对话
- **AND** 一批补入本身不得自动引发无阅读意图的下一批读取

#### Scenario: 加载失败后继续阅读
- **WHEN** 读取更早记录失败后用户继续向上阅读
- **THEN** 已显示内容和阅读位置 MUST 保留，失败原因只影响该次读取
- **AND** 后续向上阅读 MUST 可以重试，不能永久锁住分页

#### Scenario: 首批旧记录仍属于折叠过程
- **WHEN** 字节容量保护使更早记录只返回同一轮工具过程的一部分
- **THEN** 系统 MUST 保留该轮剩余记录的准确续读位置及已有展开状态
- **AND** 用户继续向上阅读时 MUST 能自然读取下一批，不要求使用按钮补齐用户表达

#### Scenario: 下拉和并发
- **WHEN** 用户用触摸向上阅读更早内容，或读取过程中重复触发相同范围
- **THEN** 系统 MUST 在接近顶部时自动读取一批有界记录，保持原位置并防重入
- **AND** 不要求顶部下拉手势，不显示下拉提示，完成后新的向上阅读可触发下一批

### Requirement: 连接中断必须有界自动恢复观察

浏览器连接中断后 MUST 有界退避重连，状态未知时 MUST 自动核对原执行身份，不重发原请求。宿主退出导致的停止 MUST 保留明确原因，不能冒充用户主动停止。额度耗尽和待确认结果 MUST NOT 因重连自动重新执行。

#### Scenario: 重启与断线
- **WHEN** 服务短暂不可达或已知执行在新宿主中状态未知
- **THEN** 客户端 MUST 自动恢复连接并按准确身份核对原执行，失败后保留明确诊断和手动入口

### Requirement: 开发版必须自动接续可确认的系统中断

可信开发版宿主启动后 MUST 自动发现被系统中断且未完成的对话执行，不以用户发送继续或页面保持打开为前提。系统 MUST 先核对原上下文和执行身份，已有执行仍运行时只恢复观察，已完成时不重做。仅确认原执行停止且无活动或未知工具、无待用户决定时，才可按原参与者、模型来源、工作位置与权限继续最后用户目标。接续 MUST 明确标注为系统恢复，不冒充新用户授权；旧命令不得逐条重放。每次中断 MUST 有持久化的一次性恢复身份与次数，重复启动或并发核对不得重复执行。

#### Scenario: 开发版重启后继续
- **WHEN** 原执行因系统退出停止，可信开发版启动且身份和结束事实均可确认
- **THEN** 系统 MUST 自动查回现场并至多续做一次，无需用户再次输入继续
- **AND** 已有执行仍在运行或已完成 MUST 不发起第二次工作

#### Scenario: 无法安全恢复
- **WHEN** 存在身份失配、活动工具、待决定、额度不可用、未知结果或恢复失败
- **THEN** 系统 MUST 保留准确原因和未完成状态，不重发不确定操作、不换账号模型、不绕过用户决定
- **AND** 用户主动停止 MUST 取消对应自动恢复

### Requirement: 正式版必须明确表示未完成执行

正式版宿主 MUST 默认不自动发起系统中断后的新执行，并明确表示执行未完成与原因，保留核对和继续入口。系统中断 MUST 不冒充用户主动停止，已完成的执行 MUST 不因启动恢复而变为未完成。产品 MUST 不把所有进行中的正式任务自动视作可重跑对话。

#### Scenario: 正式版启动
- **WHEN** 正式版发现上次系统中断留下的执行
- **THEN** 系统 MUST 显示执行未完成及可核对原因，不自动发送续做请求

### Requirement: 原生连接中断必须自动核对并安全恢复

宿主仍运行时原生连接确认断开，系统 MUST 保留准确会话和执行身份，重建同一绑定并有界自动核对。开发版 MUST 将已受理、非用户主动停止的系统连接中断纳入单次自动接续；只有原执行和工具均确认停止、无待用户决定且原账号和权限仍有效时才可接续，不得重放原指令。正式版 MUST 只恢复观察，不自动续做。用户主动停止 MUST 取消待执行的自动接续。已确认失效的连接 MUST NOT 持续复用；诊断 MUST 区分连接观察中断与账号或程序不可用。

#### Scenario: 宿主存活时连接断开
- **WHEN** 已受理执行的连接断开且准确原生历史确认原执行和工具均停止
- **THEN** 开发版 MUST 在原绑定至多接续一次，重复观察与并发恢复不得重复发送

#### Scenario: 结果仍不确定
- **WHEN** 原执行仍运行、身份失配或工具结果未知
- **THEN** 系统 MUST 只观察或保留明确未完成原因，不发送第二次工作

#### Scenario: 用户停止或待决定
- **WHEN** 用户主动停止或中断前存在待回答及待授权事项
- **THEN** 系统 MUST 不自动续做

#### Scenario: 存量未知执行
- **WHEN** 启动后存在已受理但缺少系统中断来源的未知执行
- **THEN** 系统 MUST 自动核对准确原生终态以解除已结束执行的输入锁定，但 MUST NOT 仅凭未知状态自动续做

### Requirement: 对话输入选择必须具有软件级记忆

Buildr MUST 在应用配置域内跨工作空间记住对话输入区上次明确使用的智能体（Agent）、权限（Permission）和模型（Model）选择，MUST 将其应用于后续新对话。智能体与权限属于对话模块偏好，模型选择器偏好 MUST 独立保存模型、服务档位和思考深度；二者 MUST 与生成提交说明使用的执行模型选择器偏好保持独立。偏好 MUST 只用于新对话草稿，MUST NOT 追溯改写已有对话的实际运行记录、历史或本轮权限。

恢复偏好前 MUST 核对当前接入、模型来源、能力与权限可用性。权限 MUST 按工作空间保留明确选择；没有已保存选择的新草稿 MUST 初始选择完全访问。初始策略 MUST NOT 改写已有对话或旧轮次；能力不支持时 MUST 明确提示。偏好不可用时 MUST 回退到当前接入的官方默认选择或等待用户选择，MUST NOT 静默采用另一个共享套餐来源。浏览器存储不可用时 MUST 保持当前页面选择可用，MUST NOT 阻止对话发送。

#### Scenario: 新对话沿用上次智能体与模型
- **WHEN** 用户在一个工作空间明确选择智能体和模型后新建对话
- **THEN** 新对话 MUST 恢复同一智能体，并在来源、模型、档位和思考深度仍可用时恢复同一选择
- **AND** 新建动作 MUST NOT 创建执行、发送输入或改写已有对话

#### Scenario: 跨工作空间保留选择
- **WHEN** 用户在另一个工作空间新建对话
- **THEN** 智能体与模型选择器偏好 MUST 继续适用
- **AND** 系统 MUST 重新核对模型来源与当前智能体的兼容性，不能直接沿用失效绑定

#### Scenario: 初始权限与空间记忆
- **WHEN** 用户创建没有已保存权限选择的新草稿
- **THEN** 输入区 MUST 初始选择完全访问，并在发送预览和实际请求中携带同一模式
- **AND** 用户在空间 A 选择默认权限后，A 的新草稿和刷新 MUST 恢复默认权限；B 的明确选择 MUST 保持，未设置的 B 使用初始策略

#### Scenario: 完全访问权限不跨工作空间扩张
- **WHEN** 用户在空间 B 已明确选择默认权限，随后在 A 选择完全访问再返回 B
- **THEN** B MUST 恢复自己已保存的默认权限，不继承 A 的选择
- **AND** A 的明确选择 MUST 保留，已有对话的实际权限 MUST 不被新草稿策略修改

#### Scenario: 已有对话不被新偏好改写
- **WHEN** 用户更改软件级偏好后打开一段已有对话
- **THEN** 该对话 MUST 继续使用自己的运行记录或本对话明确选择
- **AND** 新的软件级偏好 MUST NOT 改变其历史参与者、模型、权限或已发送内容

#### Scenario: 对话选择与执行模型记忆分离
- **WHEN** 用户更改对话输入区的模型、服务档位或思考深度
- **THEN** 生成提交说明所用的执行模型偏好 MUST 保持不变
- **AND** 更改执行模型偏好 MUST NOT 改写新对话的模型选择器记忆

### Requirement: 对话入口必须可以查看并维护所属任务引用

每段内部对话（Conversation）MUST 提供关联任务（Task）的入口，展示当前任务引用，并允许在同一工作空间（Workspace）内选择已有任务建立关联或解除关联。建立或更换前 MUST 核对准确工作空间及任务身份；解除 MUST 只移除引用，不删除任务或对话。第一版 MUST 不在对话入口创建任务、不做跨任务移交或通用关系管理器；未关联任务时对话 MUST 继续可用。

#### Scenario: 从对话关联已有任务
- **WHEN** 用户在对话的关联入口选择同一工作空间内一个存在的任务
- **THEN** 系统 MUST 保存该任务引用并展示当前关联
- **AND** 对话历史、执行状态与任务记录本身 MUST 不受影响

#### Scenario: 解除或更换任务关联
- **WHEN** 用户在关联入口解除或改选其他任务
- **THEN** 系统 MUST 只更新引用并保留原任务与对话各自事实
- **AND** 任务侧按引用列出的对话清单 MUST 反映最新关系

### Requirement: 执行工作上下文必须携带当前对话事实

向执行方交付本地工作位置与来源时，Buildr MUST 在上下文中包含当前对话标题与任务引用，使执行中的智能体（Agent）后续创建或更新任务（Task）时可与对话保持一致命名，不反向把任务状态写回对话记录。

#### Scenario: 执行中创建与对话一致的任务
- **WHEN** 对话已具有标题或任务引用且执行方收到本地工作上下文
- **THEN** 上下文 MUST 含当前对话标题与任务引用
- **AND** 智能体据以创建任务时使用一致标题，上下文缺失或标题尚未生成时不得编造

### Requirement: 执行状态与未查看消息必须独立表达

系统 MUST 分别表达确定执行中、等待用户回应、执行状态未知及未查看新消息；未查看 MUST 能与执行状态同时存在。查看 MUST NOT 停止执行或自动回复请求，执行结束 MUST NOT 自动清除未查看。页面隐藏、收起面板或只看历史列表 MUST NOT 被视为已查看正文。

#### Scenario: 后台对话完成
- **WHEN** 未打开的执行中对话收到新回复并结束
- **THEN** 执行中标记 MUST 消失，未查看提醒 MUST 保留至对应新内容真正被查看

#### Scenario: 查看期间继续输出
- **WHEN** 用户查看到某个已呈现位置，而该对话随后又有新内容
- **THEN** 查看确认 MUST 仅覆盖已呈现位置，新内容 MUST 仍可被发现
- **AND** 跨页签迟到确认 MUST NOT 回退查看位置或清除更新的消息

#### Scenario: 阅读旧消息
- **WHEN** 用户打开对话但停留在旧消息、浏览器后台或正文被收起
- **THEN** 系统 MUST NOT 仅凭选中对话就清除最新消息的未查看提醒

### Requirement: 对话入口必须自然展示活动提醒

右侧 MUST 保留“当前对话”气泡图标的悬停临时预览和点击固定展开/收起行为，并新增列表样式“所有对话”入口。活动对话 MUST 收纳于新增入口的悬停浮窗（Popover），不得常驻铺开额外条目；活动数量 MUST 只在新增入口显示。两个临时浮层 MUST 互斥，但 MUST NOT 因查看活动而关闭已固定对话。双入口点击 MUST 打开自己的视图、切换另一视图或在当前视图再次点击时收起；高亮 MUST 只指示实际显示的对应视图。历史固定显示时 MUST NOT 弹出活动浮窗。悬停或键盘聚焦 MUST 默认展示全部已登记空间的活动对话，并按准确工作空间身份分组，不提供空间筛选；组标题 MUST 显示空间名称与条数，组顺序 MUST 按用户最新输入、组内 MUST 保持同一规则倒序，包括执行中、等待回应、状态待确认及有未查看新消息；每条 MUST 可直接打开准确对话，并保留所属工作空间（Workspace）。每条 MUST 只显示一个静态主状态，不使用转圈或闪烁，也不重复堆叠执行与未查看标记。打开 MUST NOT 自动发起工作、代答或改变执行事实。浮层为悬停临时预览时 MUST 允许短暂移出后继续停留，不得在指针短暂离开时立即消失。

#### Scenario: 多空间后台执行
- **WHEN** 用户浏览一个空间而另一已登记空间的对话开始执行
- **THEN** 统一入口 MUST 在正常可见页面刷新周期内更新活动数量，悬停浮窗 MUST 展示该对话，用户无需先切换空间
- **AND** 点击 MUST 打开提醒所指空间和对话，保留当前工作页面

#### Scenario: 已结束且已查看不属于活动
- **WHEN** 用户悬停“所有对话”入口
- **THEN** 浮窗 MUST NOT 混入已结束且已查看的对话
- **AND** 已结束但仍未查看的对话 MUST 留在活动区，查看后移出；执行中或等待回应 MUST NOT 因查看而移出

#### Scenario: 浮窗移动与无鼠标入口
- **WHEN** 用户将鼠标从入口移入浮窗，或使用键盘及窄屏触控访问入口
- **THEN** 浮窗 MUST 可继续操作，键盘可聚焦条目并按 Escape 关闭，窄屏点按 MUST 与桌面点击遵守相同的视图开合规则
- **AND** 多条活动 MUST 在浮窗内有界滚动，桌面点击图标或浮窗顶部独立“查看全部对话”文字按钮 MUST 可进入全部空间历史；MUST NOT 在滚动列表底部重复该入口。空间名称 MUST 仅在分组标题显示，浮窗行辅助信息 MUST 紧凑展示智能体与模型，MUST NOT 重复展示更新时间
- **AND** 浮窗行 MUST 展示对话 ID 并提供与对话标题栏一致的复制入口，复制 MUST NOT 改变当前对话或消息查看状态

#### Scenario: 当前对话原交互保留
- **WHEN** 用户悬停当前对话气泡图标，再点击固定展开并再次点击收起
- **THEN** 临时预览和固定对话 MUST 使用同一内容、草稿和执行事实，临时预览 MUST NOT 自动确认查看
- **AND** 移入新增所有对话图标 MUST 关闭临时预览并展示活动；从活动条目打开 MUST 固定准确对话

#### Scenario: 双入口切换与重复点击
- **WHEN** 面板收起、显示当前对话或显示历史时，用户点击气泡或列表图标
- **THEN** 收起时 MUST 打开目标视图，显示另一视图时 MUST 切换到目标视图，已经显示目标视图时 MUST 收起
- **AND** 显示历史时悬停列表 MUST NOT 弹出活动浮窗；关闭历史后悬停气泡 MUST 预览当前对话而不是历史

### Requirement: 对话列表必须按活动优先与最新消息统一排序

历史列表 MUST 将当前筛选范围内所有活动对话集中置于顶部活动区，包括执行中、等待回应、状态待确认与未查看；已结束且已查看的其他对话 MUST 按所属工作空间分组置于下方，不重复列入两组。活动区 MUST NOT 按空间拆分。活动区与各分组的对话顺序 MUST 只由用户正式输入决定：用户发送新输入或答复有效问题后该对话前移；智能体回复、工具日志与状态变化 MUST NOT 改变顺序。同时间 MUST 有稳定身份次序，MUST NOT 在活动组内对执行中再额外置顶。“默认”空间组 MUST 固定置于最后且不参与排序调整；其他空间组 MUST 支持整组拖动改变显示顺序，并由本机偏好保存，偏好 MUST NOT 改变组内顺序或对话归属。每组 MUST 默认展示 5 条，超出时 MUST 可在组内展开与收起。改名、查看及隐藏操作 MUST NOT 单独改变顺序或活动归属。隐藏 MUST NOT 令仍活动的对话从活动区消失，隐藏筛选 MUST 只改变下方非活动历史。分页与刷新 MUST 使用一致排序，不能只重排浏览器已加载的一页。列表行辅助信息 MUST 展示智能体与模型，MUST NOT 重复展示更新时间，并 MUST 展示对话 ID 与复制入口。

#### Scenario: 智能体回复不改变顺序
- **WHEN** 一个已有用户输入的对话收到智能体回复、工具日志或状态变化
- **THEN** 该对话 MUST 保持原有位置，同时按执行与未查看规则进入或保留在活动区
- **AND** 顺序 MUST NOT 因输出时间重新排列其他对话

#### Scenario: 用户输入决定位置
- **WHEN** 用户在一个较早的对话中发送新输入或答复问题
- **THEN** 该对话 MUST 移到同组最前，其他对话按各自用户输入时间依次排列

#### Scenario: 普通对话收到新消息
- **WHEN** 一个已结束且已查看的对话收到最新有效消息且尚未查看
- **THEN** 该对话 MUST 进入活动组并在组内按用户输入时间定位，原有位置不在最前的对话 MUST NOT 因输出被提前

#### Scenario: 查看结束对话
- **WHEN** 已结束但未查看的对话最新消息已真正被查看
- **THEN** 它 MUST 退出活动组，按用户输入时间进入所属空间分组，不因查看动作更新排序时间

#### Scenario: 调整空间组顺序
- **WHEN** 用户把一个非默认空间组拖到另一个非默认空间组之前
- **THEN** 该组整体移动到目标位置，组内对话顺序不变，“默认”组 MUST 仍位于最后
- **AND** 重新打开对话列表或刷新页面 MUST 保持调整后的组顺序，直到用户再次调整

#### Scenario: 组内展开
- **WHEN** 一个空间组包含超过 5 条非活动对话
- **THEN** 该组默认只展示前 5 条并提供展开入口；展开后 MUST 展示该组全部已加载对话并可收起
- **AND** 展开与收起 MUST NOT 改变分组顺序、组内顺序或执行统计

#### Scenario: 后台变更与分页
- **WHEN** 用户停留历史列表，后台消息改变排序或分页边界
- **THEN** 列表 MUST 自动反映新顺序，失效的分页位置 MUST 重新读取或明确提示，MUST NOT 静默漏掉对话

### Requirement: 对话列表必须支持全部已登记工作空间

工作空间筛选 MUST 增加“全部工作空间”，默认仍选择当前页面空间。全部视图 MUST 在宿主已登记且可访问的范围内统一搜索、排序、隐藏筛选和分页，并标明每项来源；MUST NOT 通过同名目录猜测范围，MUST NOT 将查询错误表示为无对话。

#### Scenario: 全部视图搜索并打开
- **WHEN** 用户选择全部工作空间并输入关键词
- **THEN** 系统 MUST 返回跨登记范围的匹配结果及准确来源，点击后打开原属对话，不迁移归属或执行位置

#### Scenario: 切换筛选时旧请求返回
- **WHEN** 用户已切换空间或关键词，旧查询随后返回
- **THEN** 旧结果 MUST NOT 覆盖当前范围，当前分页 MUST 只使用对应筛选的有效位置

### Requirement: 查看记录必须持久且兼容旧对话

查看位置 MUST 在刷新与服务重启后保留，并以准确对话身份单调推进。启用新提醒前已有的内容 MUST 使用兼容基线而非一次性触发全部历史为新消息；该基线 MUST NOT 被解释为用户过去确已阅读。旧对话之后出现的新内容 MUST 正常产生提醒。

#### Scenario: 升级后第一次打开
- **WHEN** 应用从没有查看记录的版本升级
- **THEN** 旧内容 MUST 保持可读且不产生全库未查看提醒，升级后的新增消息 MUST 可以产生未查看标识

### Requirement: 中性标题必须提供可解释的生成状态

保留“新对话”时，系统 MUST 允许用户区分等待执行开始、正在生成、生成失败、能力不可用或旧记录状态未知。系统 MUST 保留现有独立有界摘要、失败不阻塞工作、手动改名优先及重启不重复消耗自动尝试的约束；MUST NOT 为消除中性名称而截取首句冒充摘要或自动重放工作。

#### Scenario: 新对话仍在执行
- **WHEN** 新对话执行开始且原生上下文可用
- **THEN** 系统 MUST 尽早以本轮输入有界生成简短标题，未得到合格结果时保留中性名称并说明实际生成状态；首轮成功后可继续同一有界补生成，不得仅因执行未结束而阻止早期标题

#### Scenario: 自动标题失败
- **WHEN** 标题生成超时、结果不合格或生成期间对话版本变化
- **THEN** 系统 MUST 保留当前名称及工作历史，提供安全原因说明及适用时的显式生成入口
- **AND** 刷新、后续普通消息或重启 MUST NOT 无界重复自动生成

### Requirement: 活动浮窗与对话列表共享当前执行统计
系统 SHALL 在既有所有对话活动浮窗与对话列表中复用同一当前轮次执行事实；浮窗仅显示一小块按真实智能体与模型组合汇总的执行中摘要，完整列表保留既有统计展示和筛选。浮窗总览覆盖全部已登记工作空间，对话列表总览跟随空间选择；总览不得从已加载的一页推算，也不受搜索或统计项筛选影响。每个对话按实际智能体与模型组合计一次，完整列表继续只按模型维度展示，仅 starting、running、stopping、tools-active 计入确定执行；等待、未知及结束未查看不计入执行数。未知或读取失败 SHALL 明确反馈，不得显示为零。

#### Scenario: 查看与筛选执行统计
- **WHEN** 用户悬停所有对话入口，或在完整列表点击某个模型统计项
- **THEN** 浮窗 SHALL 以静态小标签显示每个准确智能体与模型组合及执行数，不从一页推算或猜测配对；完整列表筛选 SHALL 继续只展示匹配执行，再次点击或清除恢复原列表，且不确认消息已查看

#### Scenario: 对话列表范围与布局
- **WHEN** 用户切换工作空间或调整面板宽度
- **THEN** 空间切换重算总览并清除统计分组筛选；卡片按实际容器宽度并排或上下排列，可收起，零执行时压为一行

#### Scenario: 名称和全量入口
- **WHEN** 用户查看活动浮窗或完整列表
- **THEN** 页面称为“对话列表”；浮窗顶部右侧提供“全部对话”，统计下方不增加解释小字，不新增统计入口、列表入口以外的额外数字、转圈或闪烁；同一列表入口 MUST 遵循待处理优先的单角标；浮窗只提供待处理与执行中两组及执行模型摘要，完整列表保留分类数量和筛选

#### Scenario: 单组统计布局
- **WHEN** 用户查看存在正在执行对话的提醒浮窗或完整列表
- **THEN** 浮窗 SHALL 只保留一小块实际智能体与模型组合摘要，完整列表 SHALL 仅展示按模型分布，不恢复智能体分组筛选
- **AND** 模型名称 SHALL 自然换行；完整列表统计至少容纳两排后再滚动

#### Scenario: 统计与活动区衔接
- **WHEN** 完整列表同时展示执行统计与活动对话
- **THEN** 两者 SHALL 保持既有紧凑衔接；浮窗摘要与待处理、执行中两组 SHALL 有清楚的层级

### Requirement: 顶部参与方必须展示实际智能体与模型组合
系统 SHALL 在“参与过此对话”区域按已实际参与的智能体（Agent）与模型（Model）组合展示，不能只按智能体去重。同一组合重复出现只显示一次；同一智能体使用不同模型必须分别显示。读取的模型 MUST 来自准确参与绑定或准确匹配该参与方的当前执行，不得由下一轮草稿或另一参与方的当前模型推断；旧记录缺失时明确显示“模型未记录”。

#### Scenario: 同一智能体切换模型
- **WHEN** 一个对话中同一智能体实际使用过两个模型
- **THEN** 顶部显示两个智能体与模型组合；模型区域按钮完整可见，较多统计项有界滚动，不裁切普通两组内容

### Requirement: 模型名称与两排统计必须保持可读
系统 SHALL 在执行统计、活动辅助信息及顶部参与方复用模型选择器中的完整显示名称，以准确模型编号和已知来源解析；筛选继续使用原始身份，不得按名称或强制大写猜测模型。无法可靠匹配时明确显示名称待确认，缺失模型显示未记录。浮窗组合摘要 SHALL 使用完整模型名称并附真实智能体，内容可自然换行，较多项目可滚动；完整列表原有分布 SHALL 至少完整容纳两排实际换行按钮后才滚动，按实际行高与容器宽度计算，不裁切第二排。

#### Scenario: 完整名称占用更多空间
- **WHEN** 选择器名称比内部模型编号长并在窄浮窗内自然换行
- **THEN** 界面使用完整显示名称，两排按钮完整可见，更多项目在该摘要或分布区域内滚动；完整列表点击统计项仍携带原模型编号筛选

### Requirement: 未执行草稿必须与对话列表分离
系统 MUST 保留未发送文本和上传附件，但仅创建空对话或添加附件 MUST 不使草稿进入全局、工作空间及任务对话列表。已尝试发送而失败或状态未知的记录 MUST 保留可发现性。

#### Scenario: 附件准备后仍未发送
- **WHEN** 创建草稿并上传附件但未发送任何输入
- **THEN** 所有对话列表 MUST 不显示该空草稿，重新打开准确草稿仍可读取附件
- **AND** 首次发送形成用户记录后 MUST 能从对应列表找到

### Requirement: 执行过程必须自然平铺并保留失败提醒

执行中助手说明与工具组 MUST 按实际顺序展示；连续工具 MUST 默认汇总折叠，第一条起 MUST 保持稳定身份与布局。工具组展开后各调用 MUST 按原顺序可读，助手说明 MUST NOT 被压入工具组。每条工具的原输入输出 MUST 可独立展开查看。执行结束后过程 MUST 自动折叠；再次展开 MUST 与最终答复保持同一左边界，不添加层级竖线。工具组折叠时 MUST 保留调用数量、失败及结果未知的文字与图标提醒，不增加整行背景强调。加载更早记录与实时事件 MUST 保留可见阅读位置和明确展开选择。

#### Scenario: 执行从一条增长到多条
- **WHEN** 当前过程收到更多助手说明或连续工具
- **THEN** 新说明和工具组 MUST 按原顺序显示，连续工具 MUST 汇总到原组；已明确展开或收起的选择、已有工具详情和阅读位置 MUST 保持

#### Scenario: 完成后查看过程
- **WHEN** 本轮结束且用户再次展开已折叠过程
- **THEN** 说明与工具组 MUST 与最终答复同级展示，组内不得添加层级竖线；失败及结果未知摘要 MUST 仍明确可见

#### Scenario: 旧记录并入同一分组
- **WHEN** 用户主动加载更早记录
- **THEN** 系统 MUST 保留已观察的阅读位置和工具详情展开选择，不因首条来源变化丢失定位

### Requirement: 新对话共享唯一可切换归属的草稿
系统 MUST 在同一应用配置域内保存唯一的新对话草稿；已创建对话 MUST 继续各自隔离未发送输入。没有已保存选择时，新草稿 MUST 默认选择当前页面所处工作空间；已有草稿 MUST 保留其明确选择，不跟随查看的旧对话或页面切换而改写。用户 MUST 可以切换或清除草稿工作空间，清除后 MUST 使用默认工作空间；选择器 MUST 不列出默认工作空间选项。切换 MUST 保留文本、附件和模型选择，但 MUST 解除跨空间任务绑定。创建真实对话 MUST 迁移同一草稿，已受理发送只能清理实际已提交输入，不覆盖之后编辑。

#### Scenario: 从旧对话返回新建
- **WHEN** 用户在新对话输入后打开其他对话，再次点击新建
- **THEN** 系统 MUST 恢复同一未发送输入及工作空间选择

#### Scenario: 首次新建与取消工作空间
- **WHEN** 没有已保存的新草稿，用户从工作空间 A 新建，然后清除选择
- **THEN** 初始 MUST 选择 A，清除后 MUST 显示空选择并使用默认目录，列表 MUST 不包含默认空间

#### Scenario: 切换草稿工作空间
- **WHEN** 用户将带任务绑定的新草稿从 A 切换到 B
- **THEN** 系统 MUST 保留输入和附件，解除 A 的任务绑定，返回新建及刷新后 MUST 恢复 B

#### Scenario: 应用域与已创建对话隔离
- **WHEN** 用户在其他应用配置域或已经创建的对话中输入
- **THEN** 输入 MUST 不覆盖当前配置域唯一的新对话草稿

### Requirement: 活动提醒必须区分需要用户关注的对话

系统 SHALL 继续按准确身份互斥区分等待批准或回答、确定执行、其余有未查看消息及未知执行。侧栏 MUST 只显示一个角标：待处理（等待批准或回答与其余未查看之和）大于零时显示待处理数；否则确定执行数大于零时显示执行数；两者为零时隐藏角标。未知执行 MUST NOT 计入待处理或执行数，SHALL 单独提示需核实。执行中有新消息 MUST NOT 重复计为待查看。角标 MUST 静态显示，并由说明及可访问名称准确区分待处理与执行中，不仅依赖颜色。

#### Scenario: 混合状态数量
- **WHEN** 完整范围有三个执行中、两个等待回应、两个已结束未查看和一个未知执行
- **THEN** 入口 MUST 仅显示待处理 4，浮窗 MUST 提供待处理 4、执行中 3，并单独解释一个执行状态需核实
- **AND** 每条等待回应 MUST 标为待决策，其他未查看 MUST 标为待查看

#### Scenario: 仅执行与静默
- **WHEN** 没有待处理而有三个确定执行的对话
- **THEN** 角标 MUST 显示执行中 3
- **AND** 确定执行结束且没有待处理时 MUST 隐藏角标，未知执行 MUST NOT 冒充执行中

#### Scenario: 零值与大数量
- **WHEN** 显示数量大于 99 或汇总读取失败
- **THEN** 大数 MAY 缩写为 99+，可访问名称 MUST 保留准确数量；失败 MUST 保留已有数量并提示未更新，首次不可读 MUST NOT 冒充零

#### Scenario: 执行同时有未查看消息
- **WHEN** 正在执行的对话产生尚未查看的新消息
- **THEN** 它 SHALL 仅计入执行中，不重复计为待处理；结束后仍有未查看消息 SHALL 转入待查看

### Requirement: 活动分类必须覆盖完整范围并支持准确定位

系统 SHALL 在同一空间完整活动集合上计算分类数量，MUST NOT 根据已加载一页推算。提醒浮窗 MUST 只有一组“活动中”清单，待处理条目位于前面，同类及工作空间内 MUST 按最近用户输入倒序，只有用户输入才更新排序时间，模型回复、工具、定时刷新与查看确认 MUST NOT 改变该时间。顶部 MUST 标为“执行中模型”并按真实账号身份与模型组合汇总，MUST NOT 展示智能体名称或将其推断为账号；来源缺失 MUST 明示账号未记录。系统 MUST 保留工作空间身份与分组，移除常驻分类筛选及重复统计；未知执行 SHALL 仅在出现时单独提示，条目保留在共同活动清单。每组 MUST 使用对应筛选的有效分页，待处理位于后续活动页时 MUST 仍可直接发现。完整列表 SHALL 保留既有全部活动、需关注、待处理、待查看、执行中及状态待确认筛选和执行分布筛选，原筛选互斥、分页、空间范围和搜索行为继续有效。各入口 MUST 保留准确身份定位、查看确认和最近用户输入排序，不引入自动执行。

#### Scenario: 待处理位于未加载页
- **WHEN** 未筛选活动第一页被执行中的对话占满，待处理位于后续页
- **THEN** 提醒浮窗 MUST 仍能展示待处理，不显示假空态；组内可继续加载，切换或刷新后的旧响应 MUST NOT 覆盖较新数据

#### Scenario: 键盘与触屏
- **WHEN** 用户悬停或键盘聚焦提醒入口，或从触屏进入完整列表
- **THEN** 浮窗 MUST 可用鼠标或键盘打开准确对话并退出；触屏入口 MUST 保留完整列表开关语义

#### Scenario: 分类切换和异步返回
- **WHEN** 用户在完整列表从模型分布切换至待查看，旧分页或筛选响应返回
- **THEN** 原分布条件 SHALL 清除，旧响应 MUST NOT 覆盖当前分类或分页
- **AND** 切换完整列表空间 SHALL 清除原分类并按新空间汇总

#### Scenario: 提醒读取失败
- **WHEN** 首次汇总未完成或刷新失败
- **THEN** 系统 SHALL 显示未知或未更新，不将失败表示为零；已有可信观察 SHALL 保留并标明未更新

#### Scenario: 仅筛选不确认查看
- **WHEN** 用户悬停提醒、在完整列表选择分类或触屏进入列表
- **THEN** 系统 MUST NOT 推进查看位置、回答问题、批准或发送输入
- **AND** 打开条目 SHALL 定位准确空间及对话，只有既有可见正文流程可推进查看位置

#### Scenario: 相同模型的不同账号
- **WHEN** 同一模型分别由两个账号执行，或一个账号通过不同执行方运行
- **THEN** 顶部 MUST 按账号身份与模型准确合并或区分，不以智能体名称猜测账号

#### Scenario: 活动排序不跟随后台回复
- **WHEN** 用户未输入而模型回复、工具输出或定时读取更新
- **THEN** 同类内顺序 MUST 保持；用户输入后 MUST 按该输入时间重新排序，待处理优先于确定执行

### Requirement: 执行补充必须独立保留接收事实和输入身份

每条补充 MUST 有独立请求身份并绑定已观察的对话、执行、参与者与服务代次。相同请求身份重试 MUST 返回原事实，内容不同 MUST 冲突；补充 MUST 不另建并行执行。原生输入 MUST 以准确请求或原生输入身份映射，不能只因属于同一执行就合入首条输入。确定未接收 MUST 保留可编辑文字和图片；接收未知 MUST 保存可发现记录并先观察，MUST NOT 自动重发。图片集合的写入 MUST 校验自身已观察版本，实时回复与工具事件 MUST 不单独使安全上传失效；上传结果 MUST 不覆盖更新的历史。

#### Scenario: 连续补充及重复请求
- **WHEN** 同一执行收到多条补充并有同编号请求重试
- **THEN** 每条不同输入 MUST 各自准确映射，同编号同内容 MUST 不重复交付，不同内容 MUST 明确冲突

#### Scenario: 完成临界点及断线
- **WHEN** 原生完成与补充准入交错，或发送后无法确认接收
- **THEN** 系统 MUST 如实区分拒绝、已接收与未知，保留已成立的原执行和内容事实，不自动转发到后续执行

#### Scenario: 流式输出期间上传
- **WHEN** 图片正在上传，原执行同时产生工具或回复事件
- **THEN** 上传 MUST 按准确图片集合版本准入并保留实时事件，不因无关历史版本变化产生持续冲突

### Requirement: 自动恢复观察不打扰正常使用
对话页面 MUST 在自动重连和自动核对执行状态期间静默恢复观察，MUST NOT 仅因进入恢复过程展示故障提醒。有界重试耗尽或确认原执行失败时 MUST 保留准确错误，MUST NOT 隐藏待用户决定、授权或真实执行失败，MUST NOT 自动重发原请求。

#### Scenario: 短暂事件连接中断
- **WHEN** 事件连接短暂中断并在有界重试中恢复
- **THEN** 页面 MUST 静默恢复，不显示重连或恢复成功提示

#### Scenario: 持续连接故障
- **WHEN** 事件连接的有界重试耗尽
- **THEN** 页面 MUST 显示真实连接错误并保留当前对话与草稿

### Requirement: 对话视频必须保留原件并明确视觉交付边界

对话 MUST 支持通过文件选择、剪贴板中的文件与拖放添加 MP4、WebM 和 MOV 视频，与图片共用每次最多四份材料的边界。视频单个 MUST 不超过32 MiB，图片原限制 MUST 保留；无效、超限或无法解码 MUST 说明受影响材料并保留已有文字及附件。草稿及已发送记录 MUST 提供视频播放，刷新后 MUST 可通过原对话认证读取。视频与附属画面 MUST 遵守同一对话归属、内容校验、附件版本和临时保留边界，MUST NOT 通过公开地址或任意文件路径读取绕过认证。

系统 MUST 有界提取最多八张带时间点的画面，发送和执行中补充时向支持图片的执行方交付这些画面及准确原件来源，MUST 明确只是视觉抽样且没有交付音轨，MUST NOT 宣称模型已连续观看视频。换执行方、待发送和历史交接 MUST 保留可核对的原件及画面对应；缺失、不支持或接收未知 MUST 保留输入及准确状态，MUST NOT 静默删减并伪报完整发送。

#### Scenario: 三种入口加入录屏并发送
- **WHEN** 用户选择、粘贴或拖入有效视频并明确发送
- **THEN** 同一草稿 MUST 显示可播放材料，执行方 MUST 收到带时间的抽样画面和准确原件来源，已发送记录 MUST 能重读并播放

#### Scenario: 编码无效或容量超限
- **WHEN** 视频为空、超过大小、类型与字节不符或浏览器无法解码
- **THEN** 系统 MUST 说明原因，保留已有文字及材料，MUST NOT 显示视频完整发送成功

#### Scenario: 模型不支持图片或原执行接收不确定
- **WHEN** 视频准备发送到无视觉能力的执行组合，或执行中补充接收无法确认
- **THEN** 系统 MUST 分别解释能力限制或未知接收状态，保留草稿和原执行事实，MUST NOT 自动换执行方或重复发送

#### Scenario: 视频及画面跨刷新和交接
- **WHEN** 已发送视频的对话刷新、换执行方或清理未发送临时材料
- **THEN** 原件及附属画面 MUST 保留准确关联，历史交接 MUST 提供可按需读取的来源，其他对话 MUST 无法使用该附件编号读取或发送它

### Requirement: 临时故障必须有界自动重试

当前宿主存活期间，系统 MUST 自动重试可确认没有发送工作输入的临时连接故障；模型明确报告繁忙或临时服务故障时，只有准确原执行结束、相关工具均已结束且无待决定时才可自动接续。针对同一用户请求的临时故障重试 MUST 最多额外尝试三次，采用逐步延长的等待，显示原因及次数并允许用户停止。系统 MUST 保留原输入、来源、模型、权限与历史失败，接续 MUST 标为系统消息并要求核对当前成果，不逐条重放历史工具。已发送但结果未知 MUST 先观察且不得直接重发；原生上下文创建结果未知 MUST NOT 自动另建上下文。认证、权限、额度耗尽、身份变化及用户主动停止 MUST NOT 自动重试；取消或宿主关闭 MUST 结束等待，不因刷新或并发观察重复发送。

#### Scenario: 临时连接失败尚未发送
- **WHEN** 原生连接准备临时失败且没有发送工作输入
- **THEN** 系统 MUST 退避重建原连接并以原输入身份继续，超过次数上限后保留具体原因

#### Scenario: 模型繁忙后继续
- **WHEN** 模型明确返回繁忙且准确执行与工具均已结束
- **THEN** 系统 MUST 在同一可见对话和原来源内有界接续，保留已完成成果及原失败记录

#### Scenario: 不可自动重试与取消
- **WHEN** 结果未知、工具未结束、需要用户决定、额度耗尽、认证权限或身份变化，或用户停止、宿主退出
- **THEN** 系统 MUST 保留当前记录和准确原因，取消待执行的自动重试且不重发工作

### Requirement: 切换执行组合必须支持直接继续交接

已有用户历史且切换模型或执行者后，用户打开交接或明确发送时，系统 MUST 允许使用默认的继续当前工作要求生成可查交接并发送，不要求用户先填写无信息增量的“继续”。选择本身 MUST 不发送；新空白对话 MUST 继续拒绝空输入。未交付用户要求 MUST 保留在交接来源，不能因失败丢失。

#### Scenario: 切模型后空草稿查看并发送
- **WHEN** 已有对话切换模型，用户未补充文字并查看交接后明确发送
- **THEN** 系统 MUST 展示并发送已有工作及默认继续要求，不显示空输入错误；切换选择和单独预览 MUST 不执行

### Requirement: 异常结束必须提供原目标恢复动作

一轮执行（Run）异常结束或已结束但没有可见答复时，界面 MUST 在异常附近提供“重试”或“继续”入口，不依赖用户是否切换模型或智能体（Agent）。未送达请求 MUST 恢复原输入及附件；已接收请求 MUST 先核对已有成果并接续原目标，MUST NOT 逐条重放旧工具。恢复 MUST 使用用户当前选择的执行组合，保存为关联原执行的系统动作，MUST NOT 额外制造用户“继续”消息、重写历史或清空草稿。原执行与工具未确认结束、有待用户决定或正在自动重试时 MUST NOT 另起恢复执行；未知状态 MUST 提供核对入口。恢复提交 MUST 校验原执行身份及当前版本，重复提交 MUST 保持同一执行身份；迟到或过期请求 MUST NOT 接续其他轮次。

#### Scenario: 同一执行组合恢复未送达或中断请求
- **WHEN** 用户没有切换选择，在异常提示旁点击“重试”或“继续”
- **THEN** 系统 MUST 根据原送达事实恢复原请求或接续原目标，保留历史并且不新增用户“继续”消息

#### Scenario: 切换模型或智能体后恢复
- **WHEN** 用户选择另一模型或智能体（Agent），再点击恢复动作
- **THEN** 系统 MUST 按当前选择组织原目标及交接，保留草稿和原附件，恢复动作只执行一次

#### Scenario: 未知、过期和正常完成不重做
- **WHEN** 执行状态未知、工具未结束、来源轮次已变化，或已经正常答复
- **THEN** 系统 MUST 拒绝直接重发，保留现场；未知可核对，正常答复不展示异常恢复入口

### Requirement: 上下文统计必须保持最近真实报告与准确来源
同一页面使用期间，对话上下文统计 MUST 在新执行尚未报告时保留已观察的最近真实用量、原模型来源与对应窗口口径。选择下一轮模型 MUST NOT 清空统计或改变当前执行。新报告到达后 MUST 整体替换旧统计，包括合法零用量；MUST NOT 将旧用量与新选择的模型窗口混算。说明区 MUST 区分当前配置和最近报告来源，不增加过程通知。没有可信报告时 MUST 明确未收到报告，不伪造零用量。不同工作空间及对话 MUST 隔离，新对话 MUST 不继承旧统计。

#### Scenario: 新指令已发送但尚无统计
- **WHEN** 同一对话已有报告，用户发送新一轮指令，新一轮未报告用量
- **THEN** 统计 MUST 保持最近报告及其百分比，不能短暂清空

#### Scenario: 执行中选择下一轮模型
- **WHEN** 模型 A 正在执行，用户选择模型 B
- **THEN** 当前执行 MUST 保持 A，统计 MUST 继续展示 A 的最近报告和原窗口，说明区标明报告来源
- **AND** 下一轮 B 的真实报告到达后 MUST 替换为 B 的数据，不混用两个窗口

#### Scenario: 新报告为零或没有窗口
- **WHEN** 当前执行报告合法零用量，或报告用量但缺少窗口
- **THEN** 零 MUST 作为有效新数据替换旧报告；窗口缺失时 MUST 仅使用同一真实来源的已知窗口，无法确认时不显示伪造百分比

#### Scenario: 对话隔离与页面重载
- **WHEN** 用户打开其他对话、新建对话或完整重载页面
- **THEN** MUST 不从另一对话沿用报告；重载后仅展示可从当前事实恢复的数据，没有报告时明确未知，不声称恢复未保存的数据

### Requirement: 输入区任务关联信息必须统一垂直对齐
工作空间、分隔符、任务引用和关联按钮 MUST 在同一行中垂直居中对齐。窄宽度和长名称 MUST 可换行且不遮挡按钮，既有点击、键盘操作及任务链接 MUST 保持。

#### Scenario: 未关联与已关联任务
- **WHEN** 用户在宽屏或窄面板查看未关联或已关联任务的输入区
- **THEN** 同行文字与按钮 MUST 垂直对齐，长内容换行后关联入口仍完整可操作
