# agent-conversations Specification

## Purpose
定义 Buildr 内部统一对话（Conversation）的创建、执行、可见历史、准确恢复及顺序切换智能体（Agent）行为，使日常咨询和实际工作具有完整交互闭环，并保持各家原生会话（Session）、任务（Task）和真实工作成果各自的权威边界。

下文的原生程序、厂家配置及原生会话（Session）操作描述首版 Codex、DSH、Qoder 的适配行为。公共执行契约按 `agent-runtime-connections` 定义，只依赖可核验的绑定与恢复引用；未来执行者（Executor）不必伪造外部命令行或厂家会话编号，也不能省略准确身份、状态观察和未知不重发的边界。

## Requirements

### Requirement: 自动标题必须是与工作上下文隔离的简短摘要

新对话开始执行、原生上下文可用后，系统 MUST 尽早使用可信原生摘要或一次有界独立摘要回填简短主题名称；首轮执行成功后仍未命名时 MUST 继续完成同一有界生成作为兜底。系统 MUST NOT 把首条指令的截取冒充智能体（Agent）总结。起名 MUST 不向工作原生上下文追加消息、不重放工具、不改变执行位置或原生恢复身份。标题生成失败 MUST 不阻止对话使用，保留中性名称；生成尝试 MUST 按准确参与者分别保存早期和完成后两个有界阶段，状态 MUST 在重启后保持，避免重复调用。尚无有效标题且更换参与者时，旧参与者的失败标记 MUST NOT 消耗新参与者的尝试；切回已尝试参与者、刷新和普通后续消息 MUST NOT 重置预算。手动改名 MUST 优先于自动标题，迟到结果 MUST 校验准确对话及已观察版本。

#### Scenario: 执行开始后尽早回填
- **WHEN** 新对话的首次执行开始且原生上下文已可用
- **THEN** 系统 MUST 基于本次用户输入以有界独立摘要尝试生成精短标题并回填
- **AND** 生成失败、执行方未提供摘要能力或结果被拒时 MUST 保留中性名称，不影响本次执行，且首轮成功后的兜底生成仍可进行

#### Scenario: 用户在自动标题返回前改名
- **WHEN** 用户已经手动保存名称，原摘要稍后完成
- **THEN** 系统 MUST 保留手动名称，MUST NOT 用后台结果覆盖
- **AND** 原工作对话及执行状态 MUST 不受起名成功或失败影响

#### Scenario: 厂家只返回首句截取标题
- **WHEN** 原生标题元数据表明结果为简单回退截取而非模型摘要
- **THEN** 系统 MUST 不将其标为已生成摘要标题
- **AND** 可使用已声明的隔离摘要能力，或保持中性名称，MUST NOT 向工作会话塞入起名指令

#### Scenario: 旧对话请求简短标题
- **WHEN** 用户对已完成且具有真实问答的准确对话明确请求“生成简短标题”
- **THEN** 系统 MUST 以已观察修订有界生成该段对话的名称，MUST NOT 根据猜测批量覆盖其他旧名称
- **AND** 请求期间用户再次手动保存名称时 MUST 保留新的手动名称，失败 MUST 不影响工作历史或发起工作重放

#### Scenario: 标题失败后切换执行方
- **WHEN** 中性标题保留且先前参与者没有得到有效标题，用户切换到新的参与者执行
- **THEN** 系统 MUST 允许新参与者尽早尝试生成，仍按阶段有界且不影响工作执行

#### Scenario: 旧标记与切回已尝试执行方
- **WHEN** 记录来自旧版本、只有全局尝试标记，或用户切回已经尝试过的参与者
- **THEN** 系统 MUST 根据已有失败记录及执行身份保留原参与者已消耗预算，不把失败当成已生成，也不因切换、刷新或重启重置同一参与者预算

#### Scenario: 标题调用跨层时间预算一致
- **WHEN** 原生标题需要初始化后等待模型返回
- **THEN** 外层通信 MUST 覆盖已承诺的内部阶段预算，MUST NOT 在内部合法等待期间提前报原生超时，整体仍保持有界

#### Scenario: 取消独立标题
- **WHEN** 标题请求超时或调用方取消
- **THEN** 系统 MUST 按准确辅助请求释放查询和其子进程，不中断工作查询或其他标题；未确认释放时 MUST 保留原因

### Requirement: 内部对话必须具有独立稳定身份和准确工作范围

Buildr MUST 为每段内部对话（Conversation）保存稳定身份、标题、所属工作空间（Workspace）、准确起始目录（CWD）及观察版本。标题、可见历史和入口 MUST 不随执行方切换而改变归属。普通对话 MUST 不要求关联任务（Task）；每段对话只保存至多一个可选任务引用，创建后 MUST 可以按当前观察版本设置、更换或解除，任务身份 MUST 由宿主权威校验且 MUST 不复制任务状态。工作目录 MUST 在首次发送前明确可见并固定到该原生执行范围，查看其他页面 MUST 不自动改写它或注入页面内容。

#### Scenario: 普通咨询无需任务
- **WHEN** 用户从全局入口创建普通对话
- **THEN** 系统 MUST 创建独立对话并显示当前保存的工作空间（Workspace）与执行位置，不强制创建任务（Task）
- **AND** 创建或打开动作 MUST 不自动发送模型指令

#### Scenario: 创建后维护任务引用
- **WHEN** 用户对准确对话明确设置、更换或解除任务引用并提供当前观察版本
- **THEN** 系统 MUST 校验任务身份后原子保存新引用，隐藏、标题等其他字段 MUST 不被该动作改写
- **AND** 任务不可用、版本冲突或工作空间不受支持时 MUST 拒绝并保留原引用与全部历史

#### Scenario: 浏览另一工作对象
- **WHEN** 用户在保留当前对话时打开另一任务或项目页面
- **THEN** 当前对话的身份、草稿、归属和执行位置 MUST 保持
- **AND** 新页面内容 MUST 只有在用户明确加入时才成为交付输入

### Requirement: 任务入口必须只维护内部对话引用

一个任务（Task）MUST 可以具有多段内部对话（Conversation），任务入口 MUST 按零、一、多条实际关系分别创建、直接打开或选择准确对话。创建前 MUST 核对已登记工作空间（Workspace）及任务身份，保存任务引用而非复制任务状态。内部关系 MUST 不混入旧外部原生会话（Session）关系数量，也不因新增参与者而重复关联。第一版 MUST 不增加跨任务移交或通用关系管理器。

#### Scenario: 任务尚无内部对话
- **WHEN** 用户在任务中选择打开内部对话且不存在对应记录
- **THEN** Buildr MUST 创建关联该准确任务的新对话并展示输入界面
- **AND** MUST NOT 自动寻找或打开外部桌面会话

#### Scenario: 任务存在多个内部对话
- **WHEN** 一个任务有多段内部对话
- **THEN** 系统 MUST 允许用户按对话标题、时间及状态选择准确目标
- **AND** MUST NOT 仅根据最近活动或当前 Agent 品牌猜测目标

### Requirement: 统一可见历史必须保留来源并与原生上下文分离

Buildr MUST 持久保存属于统一对话（Conversation）的用户输入、展示回复、参与变化、必要工具结果及其来源引用，并为可见记录提供稳定身份和顺序。各参与者 MUST 绑定准确连接、执行者绑定身份和可核验的恢复引用；首版三家将该引用映射到准确配置来源与原生会话（Session）编号。隐藏推理、上下文压缩与执行恢复状态 MUST 继续由相应执行者（Executor）维护，公共层不复制或解释其私有格式。历史入口 MUST 按对话组织，不能按 Agent 品牌拆散同一主题。文件和外部系统 MUST 继续作为成果当前事实的权威来源。

#### Scenario: 同一主题由多家参与
- **WHEN** Codex、DSH、Qoder 依次参与同一内部对话
- **THEN** 用户 MUST 在一个历史主题中看到原顺序的记录及每条内容的实际来源
- **AND** 输入框选择变化 MUST 不重标已有回复或生成新的历史主题

#### Scenario: 原生历史重读
- **WHEN** 重连后重新读取已显示过的原生条目
- **THEN** Buildr MUST 按准确参与关系和稳定原生来源去重，不重复显示同一用户输入
- **AND** 无法可靠映射的来源 MUST 明确诊断，不猜测合并或重放历史工具和授权

### Requirement: 创建和发送必须保留尝试与接收事实

用户首次发送时，Buildr MUST 按需建立或恢复准确原生会话（Session），保存本次创建和发送尝试、输入身份及实际原生接收结果。重复提交同一已受理请求 MUST 返回其原有身份；并发或过期请求 MUST 明确冲突而非产生第二次执行。原生创建已成功而本地绑定未完成时 MUST 保留已知身份并重新观察。结果未知 MUST 不自动解释为未执行，也 MUST 不自动另建会话重发原指令。用户明确提交的新要求 MUST 使用独立输入身份；需要独立上下文时 MUST 保留原执行并交接现场，MUST NOT 将旧未知结果当作新要求的发送门禁。

#### Scenario: Codex 空会话尚未持久化
- **WHEN** 本次新创建的 Codex 原生编号尚未接收首条输入，历史读取明确报告未物化
- **THEN** 系统 MUST 仅对这个确知未发送的新建对象表达空历史，并继续准确记录创建与发送事实
- **AND** 已有绑定恢复失败 MUST NOT 被吞掉或显示为新空会话

#### Scenario: 发送超时但可能已被接收
- **WHEN** 发送返回前连接断开或后端退出，无法确认原生是否已接收
- **THEN** 系统 MUST 保留输入与未知结果，并先观察原生历史、本轮状态及必要工作现场
- **AND** 刷新、重连及用户重复提交同一请求 MUST NOT 自动造成第二次执行

### Requirement: 输入与执行反馈必须构成日常使用闭环

对话 MUST 支持文本输入、流式回复、基本工具进度、必要文件改动与错误反馈；必要图片 MUST 按所选接入及模型的真实能力提供有界输入和本机私有保存。不支持或超限时 MUST 在发送前说明并保留草稿。仍在运行且所选组合及权限未改变、支持同轮补充时，补充 MUST 使用当前执行身份与原配置；其他新要求 MUST 在保留原执行的同时独立投递，不等待旧工具或问题结束。未发送输入仍为草稿，MUST NOT 因输入或刷新自动交付。补充 MUST 不切换参与者、模型、权限或执行位置，不隐含回应原生授权和业务问题。

#### Scenario: 执行中主动补充图文
- **WHEN** 当前执行身份已确认且仍在运行，用户保持相同选择并主动补充文字、图片或图文组合
- **THEN** 系统 MUST 将该输入交付同一执行并独立保存其尝试与接收结果，原执行继续可观察及可停止
- **AND** 界面 MUST 沿用普通消息展示，不要求切换插入或排队模式

#### Scenario: 执行中继续编辑
- **WHEN** 用户只编辑输入而未提交发送
- **THEN** 系统 MUST 保留草稿，不自动发送；用户明确提交新要求时 MUST 按所选组合独立接收，MUST NOT 假称已送达或重发原未知操作

#### Scenario: 图片输入超过限制
- **WHEN** 图片不符合所选模型支持范围或超过已声明大小
- **THEN** 系统 MUST 提示受影响图片和原因，并保留可继续编辑的文本与材料
- **AND** MUST NOT 通过静默删图把请求显示成完整发送

#### Scenario: 等待明确授权时补充
- **WHEN** 原执行等待授权或业务问题，而用户发送普通补充
- **THEN** 原请求 MUST 继续保留，只有其独立回应才可以解决该请求
- **AND** 补充失败 MUST 不停止原执行或删除待回应事实

#### Scenario: 文件已被其他入口修改
- **WHEN** 智能体（Agent）继续读取或修改已有成果
- **THEN** 工作依据 MUST 是当前文件或外部系统事实，历史工具摘要不能证明内容仍未变化
- **AND** 工作页面 MUST 能继续使用原查询与刷新读取同一成果，不要求新增通用工作对象库

### Requirement: 控制请求必须及时作用于准确执行

同一内部对话（Conversation）MUST 维护唯一当前交互及可准确识别的保留执行；保留执行 MUST 继续由原参与者、原生上下文及准确后台控制，MUST NOT 覆盖当前交互。多个页面可以观察同一事实。发送准入与状态写入 MUST 使用有界短操作，不持锁等待整轮模型结束。停止、授权回复和问题回答 MUST 能独立及时处理，并核对连接、配置、参与者、本轮执行、原生请求及服务代次。原生未知交互 MUST 不默认批准；迟到或已失效回复 MUST 不应用到新执行。

#### Scenario: 权限选择绑定准确本轮
- **WHEN** 用户准备并发送默认权限或完全访问模式的输入
- **THEN** 系统 MUST 将实际权限模式纳入能力校验、发送预览、输入身份与本轮持久记录，模式变化后原预览 MUST 失效
- **AND** 刷新或重启 MUST 能读回本轮模式，旧记录缺失模式时 MUST 解释为默认权限而非推断完全访问
- **AND** 同一对话换家 MUST 保留明确选择；新对话 MUST 恢复软件级记住的权限选择，没有已保存选择的新草稿 MUST 初始选择完全访问，已有明确选择 MUST 优先且不改写旧轮次

#### Scenario: 模型正在等待授权
- **WHEN** 原生执行发出工具授权请求
- **THEN** 系统 MUST 展示原生动作、对象与实际可选决定，并将答复送回产生请求的准确执行
- **AND** 停止请求 MUST 不需要等待模型本轮完成

#### Scenario: 输入框已选择另一参与者
- **WHEN** 当前仍存在原参与者的授权或补充问题
- **THEN** 对该请求的答复 MUST 继续指向其原参与者及本轮身份，不随输入框选择改变

#### Scenario: 服务重启后收到旧回应
- **WHEN** 回应携带的服务代次或原生请求已失效
- **THEN** 系统 MUST 拒绝应用该回应并重新观察当前待回应事实
- **AND** MUST NOT 把其内容用于新的授权请求

### Requirement: 停止必须区分模型中断和活动工具退出

用户停止时系统 MUST 先发送原生中断并显示正在停止，自动观察本轮模型及相关活动工具的真实结果。中断请求成功或模型本轮结束 MUST 不单独证明命令退出。仍有活动工具时 MUST 显示准确未停项并提供可验证的针对性停止；状态无法确认时 MUST 明确未知。只有本轮相关执行已确认停止且不会继续延迟写入时，才可显示已停止。停止 MUST 不误停此前用户有意保留、与本轮无关的后台服务。

#### Scenario: 正常停止得到完整确认
- **WHEN** 原生确认本轮中断且相关活动工具均退出
- **THEN** 系统 MUST 自动显示已停止并保留历史和已发生的修改
- **AND** MUST 不要求用户为正常路径再手动核验一次

#### Scenario: Codex 中断后命令仍在运行
- **WHEN** 模型本轮已中断而本轮原生终端仍有活动命令
- **THEN** 系统 MUST 显示命令仍运行，并按准确原生终端身份停止与核对退出
- **AND** MUST NOT 用全对话清理或未经核实的操作系统进程号替代针对性处理

#### Scenario: 当前工具不支持单独停止
- **WHEN** 原生接入无法按准确工具身份单独停止某活动命令
- **THEN** 界面 MUST 不将该工具展示为可单独停止，仍保留活动事实与重新观察入口
- **AND** 单工具停止被拒绝时 MUST 保留原本轮状态，MUST NOT 先标为整轮正在停止或据后续空闲误标全部已停止

#### Scenario: 断线后结果未知
- **WHEN** 连接断开导致不能确认执行或工具终态
- **THEN** 系统 MUST 显示状态未知并允许重新观察，保留历史和草稿
- **AND** 未确认结束前 MUST NOT 自动重放或恢复原未知操作；用户明确提交的新要求或更换选择 MUST 能独立接收，保留原执行、未知结果及准确控制，MUST NOT 以旧工具结束为前提

### Requirement: 查看和恢复必须优先观察原生事实

查看对话 MUST 首先提供统一可见历史；继续执行前 MUST 恢复所选参与者的原连接、配置来源及准确原生会话（Session），核对活动执行、待回应和新增历史。刷新、重连及后端重启 MUST 不自动重发可能产生副作用的输入。原生上下文不能恢复时 MUST 保留历史和原因，由用户明确决定是否另起执行上下文，不能静默冒充连续恢复。

#### Scenario: 重启后继续原对话
- **WHEN** 后端重启后用户打开此前已有原生绑定的对话
- **THEN** 系统 MUST 使用保存的准确原生编号恢复并补齐可见记录
- **AND** MUST NOT 通过“最近一段会话”或桌面焦点猜测目标

#### Scenario: 原生历史暂不可读
- **WHEN** 某参与者连接失效或原生历史读取失败
- **THEN** 已保存统一历史 MUST 保持可读，受影响恢复明确诊断
- **AND** MUST NOT 将失败显示为空历史，也不据此自动重建参与绑定

### Requirement: 同一对话换家必须展示真实接续材料

用户 MUST 能手动选择同一对话（Conversation）的下一位智能体（Agent）和模型（Model），选择本身不创建执行、不发送输入、不改变任务或历史身份。用户明确发送新要求时 MUST 按所选组合接续，不等待原执行或工具结束；忙碌的原上下文 MUST 保留，新要求 MUST 使用独立上下文。系统 MUST 在同一对话中从本地原始记录组织交接，并允许查看实际发送正文、来源范围与执行位置。材料 MUST 不含秘密、隐藏推理或无关工作空间信息，不宣称迁移私有上下文。界面 MUST 只提示实际改变的执行维度，采用紧凑轮次列表，完整正文默认收起且与页面说明明确分开；详情 MUST 从对话所在一侧展开。正常发送 MUST 不强迫用户再确认一份交接清单。

#### Scenario: 首次切换到另一家
- **WHEN** 用户选择另一家并明确发送新要求
- **THEN** 系统 MUST 按该选择交接同一工作并保持同一内部对话，实际交接正文可在同侧详情查看
- **AND** 历史工具操作和授权 MUST 仅作有来源的参考，不作为可重放协议请求

#### Scenario: 原执行尚未确认结束
- **WHEN** 对话执行中、待回应、正在停止、仍有活动工具或状态未知
- **THEN** 系统 MUST 保留原执行及其准确控制，并允许用户发送新要求、更换选择及重新观察
- **AND** MUST NOT 因另一家可用而自动代选；独立执行新要求 MUST 以用户明确提交为依据，旧工作是否停止由智能体（Agent）按现场判断

#### Scenario: 查看发送内容
- **WHEN** 用户展开完整交接内容
- **THEN** 框内 MUST 仅展示准备实际发送的正文，框外解释 MUST 不混作发送文字
- **AND** 关闭重开 MUST 恢复正文收起，已发送回执 MUST 读取当次快照且区分确认接收与未知

### Requirement: 换回参与者必须恢复原生上下文并准确推进交付位置

换回曾参与的执行方时，原参与者没有未结束工作且归属可安全复用时，系统 MUST 恢复其准确原生会话（Session），补充其尚未收到的可见变化；原上下文仍活动、待决定或结果未知时 MUST 保留该绑定，并为新要求使用独立上下文，MUST NOT 冒充恢复或覆盖旧工作。交付位置 MUST 绑定实际输入身份、来源范围及接收事实，只有原生确认接收后才能推进；超时未知 MUST 保留尝试并先核对，不能凭本地已发送或界面显示推进。交付位置 MUST 不代替执行完成或成果正确的判断。

#### Scenario: Codex 经两家参与后返回
- **WHEN** Codex、DSH、Qoder 顺序参与且原上下文已空闲后，用户换回 Codex
- **THEN** 系统 MUST 恢复原 Codex 原生编号并仅补充其未收到的 DSH、Qoder 可见变化及本次要求
- **AND** MUST 保留 Codex 已有原生上下文，不新建同名会话冒充恢复

#### Scenario: 交付确认丢失
- **WHEN** 接续输入可能已被接收但确认未返回
- **THEN** 系统 MUST 保留原交付位置和未知尝试，按原生输入身份重新观察
- **AND** MUST NOT 自动重复提交整包历史或把未确认范围标记为已交付

### Requirement: 接续超限必须保留历史并由用户明确选择

系统 MUST 分别遵守目标接入的字节容量与模型可用上下文预算，预留新输入和输出空间，不把固定 64 KiB 视为所有目标的上下文。正常交接 MUST 由 Buildr 直接组织；超过预算时 MUST 仅尝试有界、无工具且不向工作上下文追加消息的原模型整理。额度耗尽、不可用、超时或整理失败 MUST 回退到本地必要信息及可读取的分轮索引。原始记录 MUST 保留，摘要 MUST 标明来源和覆盖范围，MUST NOT 静默截断、把引用路径冒充已读取内容或要求用户手工总结。必要资料或附件仍无法安全交付时 MUST 保留草稿、说明限制并允许用户选择其他模型。

#### Scenario: 历史超过接续容量
- **WHEN** 直接组织的材料超过目标接收预算
- **THEN** 系统 MUST 才尝试原模型精简，精简仍不适用时提供本地可读取索引和准确覆盖说明
- **AND** 必要内容仍不能安全交付时 MUST 明确限制，不伪报完整交接

#### Scenario: 用户采用精简说明
- **WHEN** 旧客户端仍提交用户明确提供的精简说明
- **THEN** 系统 MUST 保存原文和来源并作为补充交付，不以该说明覆盖本地原始历史
- **AND** 后续换家或换回 MUST 仍从本地原始记录组织，不递归转发旧说明

#### Scenario: 旧模型不可用
- **WHEN** 旧模型额度不足、失效、不支持隔离整理或整理超时失败
- **THEN** 系统 MUST 不向原工作会话发送整理请求，也不阻止使用本地记录继续
- **AND** 索引缺失或不可读 MUST 明确失败，不能在缺少来源时声称交付完整

#### Scenario: 整理期间内容变化
- **WHEN** 整理返回前本地对话修订或模型绑定变化
- **THEN** 系统 MUST 拒绝把迟到结果用于旧预览或实际发送，保留草稿并重新读取当前事实
- **AND** 实际提交 MUST 使用所查看正文的准确版本，不再次悄悄生成另一份正文

### Requirement: 事件与待回应状态必须可重连且不成为成果权威

事件 MUST 保留准确对话、参与者、本轮执行、原生条目或请求来源及服务代次。事件订阅 MUST 支持有界追赶；位置失效时 MUST 重新读取历史和原生状态并去重，不能将短期事件缓存（Cache）作为唯一恢复依据。收起面板后 MUST 保留最小待授权、待回答和未知状态提示，并能定位准确对话；第一版 MUST 不增加通知中心或通用事件总线。

#### Scenario: 页面短暂断线
- **WHEN** 页面重连且原事件位置仍可用
- **THEN** 系统 MUST 补齐安全增量并对齐当前原生状态，不重复执行操作

#### Scenario: 事件位置已过期
- **WHEN** 页面请求的事件位置不在可追赶范围
- **THEN** 系统 MUST 明确要求重读当前历史及状态，再建立后续观察
- **AND** MUST NOT 以丢失事件推断执行未发生

#### Scenario: 对话面板收起后等待用户
- **WHEN** 后台对话出现有效授权、补充问题或未知执行状态
- **THEN** 全局入口 MUST 保留可发现提示，点击后打开准确对话或准确待回应列表
- **AND** 页面导航和其他安全工作 MUST 保持可用

### Requirement: 每轮模型来源必须固定并可追溯

系统 MUST 将模型账号、模型、档位及绑定版本纳入发送预览、本轮持久记录与真实请求。跨来源不兼容的原生上下文 MUST 在同一可见对话内准确接续，MUST NOT 搬运隐藏推理或静默覆盖旧恢复引用。

#### Scenario: 同名模型有多个来源
- **WHEN** 用户选择 Devin 账号的 GPT 而另有 Codex 账号提供同名模型
- **THEN** 本轮 MUST 固定使用 Devin，记录真实来源，失败时不自动扣另一套餐

#### Scenario: 原执行仍未结束
- **WHEN** 原执行、活动工具或受理结果尚未确认结束
- **THEN** 系统 MUST 保留原绑定，不重放未知输入；用户明确换源并提交新要求时 MUST 独立投递，旧工作保持原归属

### Requirement: 工具过程条目必须携带稳定工具名称

执行器（Executor）上报的工具条目 MUST 在确知时携带稳定工具名称（name），统一对话记录 MUST 原样保存并随条目提供。名称表示工具步骤的身份（如命令执行、文件修改或具体工具名），不表示展示文案。来源未提供稳定名称时 MUST 缺省该字段，不得伪造。

#### Scenario: Codex 工具条目
- **WHEN** Codex 会话产生命令执行、文件修改或工具调用条目
- **THEN** 记录 MUST 分别携带能区分这三类步骤的名称
- **AND** 文件修改条目的文本 MUST 保留涉及文件路径

#### Scenario: DSH 与 Qoder 工具条目
- **WHEN** DSH 或 Qoder 会话产生工具调用条目
- **THEN** 记录 MUST 携带原生工具名称
- **AND** 调用与结果更新同一记录时，名称 MUST 保留

#### Scenario: 旧记录或无名来源
- **WHEN** 条目缺少工具名称（历史数据或未上报来源）
- **THEN** 展示 MUST 以既有文本形式呈现该条目
- **AND** MUST NOT 用猜测的名称替代

### Requirement: 每轮主线必须保留用户消息与最终答复

视图 MUST 按执行轮（Run）聚合中间过程；同一执行被用户补充消息分段时 MUST 只在整轮最后一条助手消息处确定最终答复，不能将补充前的过程说明误当结束答复；用户消息、补充图片与该轮最终助手答复 MUST 按实际顺序独立留在主线。MUST NOT 用字符长度区分说明与最终答复。缺少消息阶段的历史记录 MUST 以每轮最后一条助手消息作为结束答复回退；正在执行的当前轮 MUST NOT 提前将过程说明作为结束答复。

#### Scenario: 短最终答复
- **WHEN** 一轮的最后答复为“收尾完成”或其他短消息
- **THEN** 折叠过程后该答复 MUST 仍在主线可见

#### Scenario: 长过程说明
- **WHEN** 一轮中间出现长说明且后续仍有助手消息
- **THEN** 该说明 MUST 按真实顺序位于折叠过程内
- **AND** 展开后 MUST 保留完整 Markdown 正文

#### Scenario: 运行中
- **WHEN** 当前轮尚在执行或等待操作
- **THEN** 已有说明 MUST 留在过程内
- **AND** 结束后 MUST 将最后答复呈现在过程之后

#### Scenario: 同轮中途补充
- **WHEN** 过程说明之后出现用户补充图文，再有继续过程与最终答复
- **THEN** 两段过程 MUST 分别在原位置折叠，用户补充图文 MUST 仍可见，整轮仅有最后一份最终答复
- **AND** 新一轮开始 MUST 不改写旧轮的最终答复、配置或明确展开选择

### Requirement: 工具必须按类型提供可核验详情

每个工具调用 MUST 可独立展开；命令 MUST 使用与代码导航不同的符号并展示实际命令和输出。已知文件读取或修改 MUST 根据真实工具输入提供文件打开动作，使用对话工作目录与已登记检出位置解析当前文件；无法确认唯一来源时 MUST 给出局部提示，不得打开其他工作树的同名文件。历史记录不得伪造丢失的输入。

#### Scenario: 工具完成后保留输入
- **WHEN** 来源提供原始输入而结果更新仅提供输出
- **THEN** 记录 MUST 以可选 input 保存已知原始输入并在结果更新时保留
- **AND** 旧数据缺省字段 MUST 继续可读

#### Scenario: 读取文件
- **WHEN** 文件读取调用包含可解析的真实文件路径
- **THEN** 文件名 MUST 可点击并在已有查看器打开相同实际检出位置的当前文件
- **AND** 点击文件 MUST NOT 折叠整轮过程

#### Scenario: 执行命令
- **WHEN** 展开命令调用
- **THEN** MUST 可分别核验已知原始命令与输出；缺少原始输入时 MUST 保留原始记录供查看

### Requirement: 交接必须按本地执行轮次保存可查来源

交接 MUST 从本地已有用户输入、助手说明、工具动作与结果、可确认成果和最终答复组织。执行中问题答复及授权决定 MUST 保存其问题、轮次和来源，MUST NOT 因视作另一用户消息而拆错轮次。执行概况 MUST 说明做了什么、结果怎样、到哪里查，不携带文件、脚本或日志全文；失败、未知和可能生效的操作 MUST 保留。成果 MUST 有可核对证据与位置，无法确认则明确，不把助手的完成声明视为已验证事实。原执行中断或没有最终答复 MUST 可辨识。整体交接提示词（Prompt）MUST 说明目标连续、来源解释、有效授权范围、按需查阅和继续前核对当前现场；摘要只是辅助资料。

#### Scenario: 连续三次切换
- **WHEN** A 交给 B 再交给 C，包括换回已有参与者
- **THEN** 新材料 MUST 从本地原始来源和当前成果引用组织，已有原生恢复继续只补未收到的记录
- **AND** 历史交接包和回执 MUST 不递归嵌入正文

#### Scenario: 失败与执行中回答
- **WHEN** 一轮中存在工具失败、用户回答或尚未确认结果
- **THEN** 后续执行方 MUST 能读到对应轮次的真实状态、问题和回答及证据位置
- **AND** 一次性许可 MUST 不自动变成新执行的授权

### Requirement: 对话身份必须便于识别与复制

系统 MUST 在对话历史每项显示对话 ID，并尽量将标题与元信息控制在两行内。历史筛选 MUST 搜索在前、紧凑工作空间选择在后，默认选择当前所处工作空间而非上次对话所在工作空间。当前对话标题区域 MUST 显示同一 ID 且支持复制完整值。空间不足时允许视觉省略，但 MUST NOT 改变复制内容或原有选择、重命名行为。

#### Scenario: 查找与复制当前对话
- **WHEN** 用户查看历史或打开已有对话
- **THEN** 历史与标题区域 MUST 显示同一个对话 ID，长标题不挤出第三行
- **AND** 点击复制 MUST 复制完整对话 ID，并给出成功或失败反馈

### Requirement: 对话阅读辅助必须集中且克制

标题、对话标识和前置复制图标 MUST 使用单行布局，不增加标题栏高度。复制 MUST 使用完整标识，成功浮层 MUST 自动隐藏。当前执行状态 MUST 位于输入框上方，MUST NOT 因滚动历史而不可见；历史记录与待回答请求继续可查。

#### Scenario: 复制并继续阅读
- **WHEN** 用户点击标题后标识前的复制图标
- **THEN** 系统 MUST 复制完整标识并短暂显示已复制，不能在输入区留下常驻提示

### Requirement: 交接成功动作必须去重组织

系统 MUST 合并相同类别的成功动作并保留原始数量和可读取来源；失败、未知、未结束操作与用户决定 MUST 保持可区分，原始历史和既有交接回执 MUST NOT 改写。分轮正文 MUST 易读，不逐条重复无信息增量的成功文案。

#### Scenario: 工具密集轮次
- **WHEN** 一轮多次读取、搜索或执行并含失败
- **THEN** 成功动作 MUST 统计组织，失败与对应来源 MUST 单独保留，所有原记录可按引用读取

### Requirement: 更早记录必须按用户阅读意图渐进加载

打开对话时，系统 MUST 默认返回最近 5 轮可见记录，并定位最新内容；向前分页 MUST 同样按最多 5 轮选择记录。轮次 MUST 依据真实执行身份组织，执行中的用户答复不得误算为新轮；缺少执行身份的旧记录 MUST 保持原始顺序且可继续读取。现有字节容量保护仍适用，容量受限的轮次 MUST 保留续读位置，不删除或静默跳过原始记录；显式条数限制和原有续读位置 MUST 保持兼容。

用户向上阅读且接近已加载内容顶部时，系统 MUST 提前分批加载更早记录，支持鼠标、触摸、键盘和滚动条；MUST NOT 要求点击加载按钮或完成顶部下拉手势，也 MUST NOT 显示常驻加载入口或下拉提示。每次读取 MUST 有界并防重入；补入记录 MUST 保持原阅读锚点和已有展开状态，不跳到底部。打开对话、收到流式更新或补入记录本身 MUST NOT 自动连续耗尽历史。跨对话迟到结果 MUST NOT 改变新对话的内容、加载状态和阅读位置。加载失败 MUST 保留当前内容并给出局部原因，用户继续向上阅读时 MUST 能重试。

#### Scenario: 默认读取最近轮次
- **WHEN** 打开具有超过 5 轮历史的对话，且最新 5 轮未触及容量保护
- **THEN** 系统 MUST 展示最新 5 轮的用户输入、过程和答复，工具条数不得改变轮数
- **AND** MUST 保留继续向前的准确位置，初次打开不自动拉取剩余全部历史

#### Scenario: 工具密集轮次受容量限制
- **WHEN** 一轮包含大量工具记录，选中范围触及现有字节容量保护
- **THEN** 系统 MUST 有界返回记录并保留准确续读位置，继续向上时仍可读取该轮剩余内容
- **AND** 不得删除原始记录或把容量截取误报为历史起点

#### Scenario: 连续向上阅读
- **WHEN** 用户用鼠标、触摸、键盘或滚动条向上阅读并接近顶部
- **THEN** 系统 MUST 在到达顶部前自动读取前一批，补入后正在阅读的内容保持原位置
- **AND** 不显示手动加载按钮或下拉提示，不把当前阅读强制移到最新消息

#### Scenario: 重复触发与切换对话
- **WHEN** 更早记录尚在加载时重复向上滚动，或用户在结果返回前切换对话
- **THEN** 同一选择范围 MUST 只保留一个活动读取，旧结果 MUST NOT 改变新对话
- **AND** 一批补入本身不得自动引发无阅读意图的下一批读取

#### Scenario: 加载失败后继续阅读
- **WHEN** 读取更早记录失败后用户继续向上阅读
- **THEN** 已显示内容和阅读位置 MUST 保留，失败原因只影响该次读取
- **AND** 后续向上阅读 MUST 可以重试，不能永久锁住分页

#### Scenario: 首批旧记录仍属于折叠过程
- **WHEN** 字节容量保护使更早记录只返回同一轮工具过程的一部分
- **THEN** 系统 MUST 保留该轮剩余记录的准确续读位置及已有展开状态
- **AND** 用户继续向上阅读时 MUST 能自然读取下一批，不要求使用按钮补齐用户表达

#### Scenario: 下拉和并发
- **WHEN** 用户用触摸向上阅读更早内容，或读取过程中重复触发相同范围
- **THEN** 系统 MUST 在接近顶部时自动读取一批有界记录，保持原位置并防重入
- **AND** 不要求顶部下拉手势，不显示下拉提示，完成后新的向上阅读可触发下一批

### Requirement: 连接中断必须有界自动恢复观察

浏览器连接中断后 MUST 有界退避重连，状态未知时 MUST 自动核对原执行身份，不重发原请求。宿主退出导致的停止 MUST 保留明确原因，不能冒充用户主动停止。额度耗尽和待确认结果 MUST NOT 因重连自动重新执行。

#### Scenario: 重启与断线
- **WHEN** 服务短暂不可达或已知执行在新宿主中状态未知
- **THEN** 客户端 MUST 自动恢复连接并按准确身份核对原执行，失败后保留明确诊断和手动入口

### Requirement: 系统中断必须自动核对并接续原目标

Buildr 开发版与正式版 MUST 默认自动恢复已受理、非用户主动停止的系统中断，不以用户再发消息或页面打开为前提。恢复 MUST 沿用原智能体（Agent）、账号身份、模型（Model）、档位、工作位置及权限。原执行仍在运行时 MUST 只恢复观察，已确认正常完成时 MUST 不追加重复工作。准确控制资源已释放且无活动工作及待决定时，历史结果未知 MUST NOT 单独阻止智能体先核对现状并继续原目标；恢复 MUST 保留未知结果，要求先查当前成果、原工具及未决副作用，MUST NOT 重放原提示或未知操作、推定独立命令退出、扩展权限或替用户决定。没有准确原身份或资源释放证明时 MUST 继续保护相关工作。

#### Scenario: 开发版重启后继续
- **WHEN** 系统中断导致原轮停止或准确控制资源已经释放，原组合仍有效且没有待决定
- **THEN** 系统 MUST 自动组织已有成果和原目标并交给原组合执行，不要求人发送“继续”或“如何了”
- **AND** 结果未知仍保留未知，智能体 MUST 先核对事实再继续，不逐条重放旧工具

#### Scenario: 无法安全恢复
- **WHEN** 原执行仍运行、控制释放未确认、原账号身份失配、额度或认证不可用，或存在待决定
- **THEN** 系统 MUST 只推进可安全观察的部分并保留准确原因，MUST NOT 重复执行、换组合或代答
- **AND** 用户主动停止 MUST 取消对应自动接续

### Requirement: 自动恢复必须保留未完成事实并防止重复执行

系统 MUST 保留系统中断及旧轮未知结果，不能冒充用户停止或工作完成。自动接续 MUST 使用持久唯一请求身份并关联原运行，重复启动及并发核对 MUST 不重复发送。连续失败 MUST 共享持久有界恢复预算，至多三次自动接续并退避；恢复执行再次中断 MUST 在剩余预算内继续，MUST NOT 一次失败后永久冻结目标或形成无限恢复链。发送前中断 MUST 可按同一恢复意图接续。新用户要求、用户停止、必要决定或实际身份变化 MUST 阻止旧恢复覆盖当前工作。已正常完成的对话及普通正式任务 MUST NOT 被启动核对自动重跑。

#### Scenario: 重复启动与发送前中断
- **WHEN** 自动恢复意图已保存后系统再次退出，或并发请求恢复相同原运行
- **THEN** 系统 MUST 沿同一请求身份核对受理事实并只接续一次，不生成重复业务输入

#### Scenario: 恢复再次中断
- **WHEN** 同一目标的自动恢复再次因系统连接失败中断
- **THEN** 系统 MUST 在共享的三次预算内自动接续，耗尽后给出准确原因并保留成果

#### Scenario: 取消与新要求
- **WHEN** 人停止恢复、提交新要求或原轮已正常完成
- **THEN** 系统 MUST 取消旧恢复意图，不覆盖新轮、不继续旧目标

#### Scenario: 正式版启动
- **WHEN** 正式版发现具有可信系统中断来源的未完成执行
- **THEN** 系统 MUST 默认自动核对并按原目标恢复，保留未完成与未知事实，不因发行角色要求用户补发消息

### Requirement: 原生连接中断必须自动核对并安全恢复

宿主仍运行时原生连接确认断开，系统 MUST 保留准确会话和执行身份，重建同一绑定并有界自动核对。已受理且非用户停止的中断 MUST 纳入同一原目标自动接续策略，开发版与正式版 MUST 一致。只有原执行已停止，或准确原控制资源已释放且无活动工具及待决定时，才可自动交给原组合先核对成果再继续；未知历史结果 MUST 保持未知而不冻结全部目标。用户停止 MUST 取消待执行的接续。已确认失效的连接 MUST NOT 持续复用；诊断 MUST 区分观察中断与账号或程序不可用。

#### Scenario: 宿主存活时连接断开
- **WHEN** 已受理连接断开且准确原执行已停止或控制资源已释放
- **THEN** 系统 MUST 按原组合自动接续，保持同一目标来源、原权限及有界恢复身份

#### Scenario: 结果仍不确定
- **WHEN** 原执行仍运行、身份失配或资源释放尚未确认
- **THEN** 系统 MUST 继续核对并保护原工作，不另起重复执行

#### Scenario: 用户停止或待决定
- **WHEN** 用户主动停止或中断前存在待回答及待授权事项
- **THEN** 系统 MUST 不自动续做相关工作

#### Scenario: 存量未知执行
- **WHEN** 启动后存在已受理但缺少可信系统中断来源的未知执行
- **THEN** 系统 MUST 核对原生事实，MUST NOT 仅凭未知状态自动重跑历史；当前已提交的新要求继续独立执行

### Requirement: 对话输入选择必须具有软件级记忆

Buildr MUST 在应用配置域内跨工作空间记住对话输入区上次明确使用的智能体（Agent）、权限（Permission）和模型（Model）选择，MUST 将其应用于后续新对话。智能体与权限属于对话模块偏好，模型选择器偏好 MUST 独立保存模型、服务档位和思考深度；二者 MUST 与生成提交说明使用的执行模型选择器偏好保持独立。自动初始选择 MUST 只用于新对话草稿；用户在已有对话中主动切换模型或智能体时，可以恢复该模型的推理强度。偏好 MUST NOT 追溯改写已有对话的实际运行记录、历史或本轮权限。

恢复偏好前 MUST 核对当前接入、模型来源、能力与权限可用性。权限 MUST 按工作空间保留明确选择；没有已保存选择的新草稿 MUST 初始选择完全访问。初始策略 MUST NOT 改写已有对话或旧轮次；能力不支持时 MUST 明确提示。偏好不可用时 MUST 回退到当前接入的官方默认选择或等待用户选择，MUST NOT 静默采用另一个共享套餐来源。浏览器存储不可用时 MUST 保持当前页面选择可用，MUST NOT 阻止对话发送。

#### Scenario: 新对话沿用上次智能体与模型
- **WHEN** 用户在一个工作空间明确选择智能体和模型后新建对话
- **THEN** 新对话 MUST 恢复同一智能体，并在来源、模型、档位和思考深度仍可用时恢复同一选择
- **AND** 新建动作 MUST NOT 创建执行、发送输入或改写已有对话

#### Scenario: 跨工作空间保留选择
- **WHEN** 用户在另一个工作空间新建对话
- **THEN** 智能体与模型选择器偏好 MUST 继续适用
- **AND** 系统 MUST 重新核对模型来源与当前智能体的兼容性，不能直接沿用失效绑定

#### Scenario: 初始权限与空间记忆
- **WHEN** 用户创建没有已保存权限选择的新草稿
- **THEN** 输入区 MUST 初始选择完全访问，并在发送预览和实际请求中携带同一模式
- **AND** 用户在空间 A 选择默认权限后，A 的新草稿和刷新 MUST 恢复默认权限；B 的明确选择 MUST 保持，未设置的 B 使用初始策略

#### Scenario: 完全访问权限不跨工作空间扩张
- **WHEN** 用户在空间 B 已明确选择默认权限，随后在 A 选择完全访问再返回 B
- **THEN** B MUST 恢复自己已保存的默认权限，不继承 A 的选择
- **AND** A 的明确选择 MUST 保留，已有对话的实际权限 MUST 不被新草稿策略修改

#### Scenario: 已有对话不被新偏好改写
- **WHEN** 用户更改软件级偏好后打开一段已有对话
- **THEN** 该对话 MUST 继续使用自己的运行记录或本对话明确选择
- **AND** 新的软件级偏好 MUST NOT 改变其历史参与者、模型、权限或已发送内容

#### Scenario: 对话选择与执行模型记忆分离
- **WHEN** 用户更改对话输入区的模型、服务档位或思考深度
- **THEN** 生成提交说明所用的执行模型偏好 MUST 保持不变
- **AND** 更改执行模型偏好 MUST NOT 改写新对话的模型选择器记忆

### Requirement: 对话入口必须可以查看并维护所属任务引用

每段内部对话（Conversation）MUST 提供关联任务（Task）的入口，展示当前任务引用，并允许在同一工作空间（Workspace）内选择已有任务建立关联或解除关联。建立或更换前 MUST 核对准确工作空间及任务身份；解除 MUST 只移除引用，不删除任务或对话。第一版 MUST 不在对话入口创建任务、不做跨任务移交或通用关系管理器；未关联任务时对话 MUST 继续可用。

#### Scenario: 从对话关联已有任务
- **WHEN** 用户在对话的关联入口选择同一工作空间内一个存在的任务
- **THEN** 系统 MUST 保存该任务引用并展示当前关联
- **AND** 对话历史、执行状态与任务记录本身 MUST 不受影响

#### Scenario: 解除或更换任务关联
- **WHEN** 用户在关联入口解除或改选其他任务
- **THEN** 系统 MUST 只更新引用并保留原任务与对话各自事实
- **AND** 任务侧按引用列出的对话清单 MUST 反映最新关系

### Requirement: 执行工作上下文必须携带当前对话事实

向执行方交付本地工作位置与来源时，Buildr MUST 在上下文中包含当前对话标题与任务引用，使执行中的智能体（Agent）后续创建或更新任务（Task）时可与对话保持一致命名，不反向把任务状态写回对话记录。

#### Scenario: 执行中创建与对话一致的任务
- **WHEN** 对话已具有标题或任务引用且执行方收到本地工作上下文
- **THEN** 上下文 MUST 含当前对话标题与任务引用
- **AND** 智能体据以创建任务时使用一致标题，上下文缺失或标题尚未生成时不得编造

### Requirement: 执行状态与未查看消息必须独立表达

系统 MUST 分别表达确定执行中、等待用户回应、执行状态未知及未查看新消息；未查看 MUST 能与执行状态同时存在。查看 MUST NOT 停止执行或自动回复请求，执行结束 MUST NOT 自动清除未查看。页面隐藏、收起面板或只看历史列表 MUST NOT 被视为已查看正文。

#### Scenario: 后台对话完成
- **WHEN** 未打开的执行中对话收到新回复并结束
- **THEN** 执行中标记 MUST 消失，未查看提醒 MUST 保留至对应新内容真正被查看

#### Scenario: 查看期间继续输出
- **WHEN** 用户查看到某个已呈现位置，而该对话随后又有新内容
- **THEN** 查看确认 MUST 仅覆盖已呈现位置，新内容 MUST 仍可被发现
- **AND** 跨页签迟到确认 MUST NOT 回退查看位置或清除更新的消息

#### Scenario: 阅读旧消息
- **WHEN** 用户打开对话但停留在旧消息、浏览器后台或正文被收起
- **THEN** 系统 MUST NOT 仅凭选中对话就清除最新消息的未查看提醒

### Requirement: 对话入口必须自然展示活动提醒

右侧 MUST 保留“当前对话”气泡图标的悬停临时预览和点击固定展开/收起行为，并新增列表样式“所有对话”入口。活动对话 MUST 收纳于新增入口的悬停浮窗（Popover），不得常驻铺开额外条目；活动数量 MUST 只在新增入口显示。两个临时浮层 MUST 互斥，但 MUST NOT 因查看活动而关闭已固定对话。双入口点击 MUST 打开自己的视图、切换另一视图或在当前视图再次点击时收起；高亮 MUST 只指示实际显示的对应视图。历史固定显示时 MUST NOT 弹出活动浮窗。悬停或键盘聚焦 MUST 默认展示全部已登记空间的活动对话，并按准确工作空间身份分组，不提供空间筛选；组标题 MUST 显示空间名称与条数，组顺序 MUST 按用户最新输入、组内 MUST 保持同一规则倒序，包括执行中、等待回应、状态待确认及有未查看新消息；每条 MUST 可直接打开准确对话，并保留所属工作空间（Workspace）。每条 MUST 只显示一个静态主状态，不使用转圈或闪烁，也不重复堆叠执行与未查看标记。打开 MUST NOT 自动发起工作、代答或改变执行事实。浮层为悬停临时预览时 MUST 允许短暂移出后继续停留，不得在指针短暂离开时立即消失。

#### Scenario: 多空间后台执行
- **WHEN** 用户浏览一个空间而另一已登记空间的对话开始执行
- **THEN** 统一入口 MUST 在正常可见页面刷新周期内更新活动数量，悬停浮窗 MUST 展示该对话，用户无需先切换空间
- **AND** 点击 MUST 打开提醒所指空间和对话，保留当前工作页面

#### Scenario: 已结束且已查看不属于活动
- **WHEN** 用户悬停“所有对话”入口
- **THEN** 浮窗 MUST NOT 混入已结束且已查看的对话
- **AND** 已结束但仍未查看的对话 MUST 留在活动区，查看后移出；执行中或等待回应 MUST NOT 因查看而移出

#### Scenario: 浮窗移动与无鼠标入口
- **WHEN** 用户将鼠标从入口移入浮窗，或使用键盘及窄屏触控访问入口
- **THEN** 浮窗 MUST 可继续操作，键盘可聚焦条目并按 Escape 关闭，窄屏点按 MUST 与桌面点击遵守相同的视图开合规则
- **AND** 多条活动 MUST 在浮窗内有界滚动，桌面点击图标或浮窗顶部独立“查看全部对话”文字按钮 MUST 可进入全部空间历史；MUST NOT 在滚动列表底部重复该入口。空间名称 MUST 仅在分组标题显示，浮窗行辅助信息 MUST 紧凑展示智能体与模型，MUST NOT 重复展示更新时间
- **AND** 浮窗行 MUST 展示对话 ID 并提供与对话标题栏一致的复制入口，复制 MUST NOT 改变当前对话或消息查看状态

#### Scenario: 当前对话原交互保留
- **WHEN** 用户悬停当前对话气泡图标，再点击固定展开并再次点击收起
- **THEN** 临时预览和固定对话 MUST 使用同一内容、草稿和执行事实，临时预览 MUST NOT 自动确认查看
- **AND** 移入新增所有对话图标 MUST 关闭临时预览并展示活动；从活动条目打开 MUST 固定准确对话

#### Scenario: 双入口切换与重复点击
- **WHEN** 面板收起、显示当前对话或显示历史时，用户点击气泡或列表图标
- **THEN** 收起时 MUST 打开目标视图，显示另一视图时 MUST 切换到目标视图，已经显示目标视图时 MUST 收起
- **AND** 显示历史时悬停列表 MUST NOT 弹出活动浮窗；关闭历史后悬停气泡 MUST 预览当前对话而不是历史

### Requirement: 对话列表必须按活动优先与最新消息统一排序

历史列表 MUST 将当前筛选范围内所有活动对话集中置于顶部活动区，包括执行中、等待回应、状态待确认与未查看；已结束且已查看的其他对话 MUST 按所属工作空间分组置于下方，不重复列入两组。活动区 MUST NOT 按空间拆分。活动区与各空间分组 MUST 优先展示待决策及待查看，两者共享最高优先级；其余活动随后，非活动历史最后。同一优先级的对话顺序 MUST 只由用户正式输入决定：用户发送新输入或答复有效问题后该对话在当前优先级内前移，不得越过待处理条目；智能体回复、工具日志与时间变化 MUST NOT 改变排序时间。状态与查看变化 MUST 只按当前准确分类调整优先级。同时间 MUST 有稳定身份次序，MUST NOT 在活动组内对执行中再额外置顶。“默认”空间组 MUST 固定置于最后且不参与排序调整；其他空间组 MUST 支持整组拖动改变显示顺序，并由本机偏好保存，偏好 MUST NOT 改变组内顺序或对话归属。每组 MUST 默认展示 5 条，超出时 MUST 可在组内展开与收起。改名、查看及隐藏操作 MUST NOT 单独改变顺序或活动归属。隐藏 MUST NOT 令仍活动的对话从活动区消失，隐藏筛选 MUST 只改变下方非活动历史。分页与刷新 MUST 使用一致排序，不能只重排浏览器已加载的一页。列表行辅助信息 MUST 展示智能体与模型，MUST NOT 重复展示更新时间，并 MUST 展示对话 ID 与复制入口。

#### Scenario: 智能体回复不改变顺序
- **WHEN** 一个已有用户输入的对话收到智能体回复、工具日志或状态变化
- **THEN** 该对话 MUST 保持用户输入排序时间，同时按执行与未查看规则进入或保留在相应优先级
- **AND** 同优先级内顺序 MUST NOT 因输出时间重新排列其他对话

#### Scenario: 用户输入决定位置
- **WHEN** 用户在一个较早的对话中发送新输入或答复问题
- **THEN** 该对话 MUST 移到同组同一优先级最前，其他对话按各自用户输入时间依次排列，执行中即使有最新输入也 MUST NOT 超过待决策或待查看

#### Scenario: 普通对话收到新消息
- **WHEN** 一个已结束且已查看的对话收到最新有效消息且尚未查看
- **THEN** 该对话 MUST 进入待查看优先级并在同级内按用户输入时间定位，原有位置不在最前的对话 MUST NOT 因输出在同级内被提前

#### Scenario: 查看结束对话
- **WHEN** 已结束但未查看的对话最新消息已真正被查看
- **THEN** 它 MUST 退出活动组，按用户输入时间进入所属空间分组，不因查看动作更新排序时间

#### Scenario: 调整空间组顺序
- **WHEN** 用户把一个非默认空间组拖到另一个非默认空间组之前
- **THEN** 该组整体移动到目标位置，组内对话顺序不变，“默认”组 MUST 仍位于最后
- **AND** 重新打开对话列表或刷新页面 MUST 保持调整后的组顺序，直到用户再次调整

#### Scenario: 组内展开
- **WHEN** 一个空间组包含超过 5 条非活动对话
- **THEN** 该组默认只展示前 5 条并提供展开入口；展开后 MUST 展示该组全部已加载对话并可收起
- **AND** 展开与收起 MUST NOT 改变分组顺序、组内顺序或执行统计

#### Scenario: 后台变更与分页
- **WHEN** 用户停留历史列表，后台消息改变排序或分页边界
- **THEN** 列表 MUST 自动反映新顺序，失效的分页位置 MUST 重新读取或明确提示，MUST NOT 静默漏掉对话

#### Scenario: 待处理位于分页之后
- **WHEN** 多个较新的执行中对话与较旧的待决策、待查看同时存在，列表每页容量有限
- **THEN** 系统 MUST 在完整查询集上先返回待处理条目，跨页按相同优先级、用户输入时间与身份读取，无重复或遗漏

### Requirement: 对话列表必须支持全部已登记工作空间

工作空间筛选 MUST 增加“全部工作空间”，默认仍选择当前页面空间。全部视图 MUST 在宿主已登记且可访问的范围内统一搜索、排序、隐藏筛选和分页，并标明每项来源；MUST NOT 通过同名目录猜测范围，MUST NOT 将查询错误表示为无对话。

#### Scenario: 全部视图搜索并打开
- **WHEN** 用户选择全部工作空间并输入关键词
- **THEN** 系统 MUST 返回跨登记范围的匹配结果及准确来源，点击后打开原属对话，不迁移归属或执行位置

#### Scenario: 切换筛选时旧请求返回
- **WHEN** 用户已切换空间或关键词，旧查询随后返回
- **THEN** 旧结果 MUST NOT 覆盖当前范围，当前分页 MUST 只使用对应筛选的有效位置

### Requirement: 查看记录必须持久且兼容旧对话

查看位置 MUST 在刷新与服务重启后保留，并以准确对话身份单调推进。启用新提醒前已有的内容 MUST 使用兼容基线而非一次性触发全部历史为新消息；该基线 MUST NOT 被解释为用户过去确已阅读。旧对话之后出现的新内容 MUST 正常产生提醒。

#### Scenario: 升级后第一次打开
- **WHEN** 应用从没有查看记录的版本升级
- **THEN** 旧内容 MUST 保持可读且不产生全库未查看提醒，升级后的新增消息 MUST 可以产生未查看标识

### Requirement: 中性标题必须提供可解释的生成状态

保留“新对话”时，系统 MUST 允许用户区分等待执行开始、正在生成、生成失败、能力不可用或旧记录状态未知。系统 MUST 保留现有独立有界摘要、失败不阻塞工作、手动改名优先及重启不重复消耗自动尝试的约束；MUST NOT 为消除中性名称而截取首句冒充摘要或自动重放工作。

#### Scenario: 新对话仍在执行
- **WHEN** 新对话执行开始且原生上下文可用
- **THEN** 系统 MUST 尽早以本轮输入有界生成简短标题，未得到合格结果时保留中性名称并说明实际生成状态；首轮成功后可继续同一有界补生成，不得仅因执行未结束而阻止早期标题

#### Scenario: 自动标题失败
- **WHEN** 标题生成超时、结果不合格或生成期间对话版本变化
- **THEN** 系统 MUST 保留当前名称及工作历史，提供安全原因说明及适用时的显式生成入口
- **AND** 刷新、后续普通消息或重启 MUST NOT 无界重复自动生成

### Requirement: 活动浮窗与对话列表共享当前执行统计
系统 SHALL 在既有所有对话活动浮窗与对话列表中复用同一当前轮次执行事实；浮窗仅显示一小块按真实智能体与模型组合汇总的执行中摘要，完整列表保留既有统计展示和筛选。浮窗总览覆盖全部已登记工作空间，对话列表总览跟随空间选择；总览不得从已加载的一页推算，也不受搜索或统计项筛选影响。每个对话按实际智能体与模型组合计一次，完整列表继续只按模型维度展示，仅 starting、running、stopping、tools-active 计入确定执行；等待、未知及结束未查看不计入执行数。未知或读取失败 SHALL 明确反馈，不得显示为零。

#### Scenario: 查看与筛选执行统计
- **WHEN** 用户悬停所有对话入口，或在完整列表点击某个模型统计项
- **THEN** 浮窗 SHALL 以静态小标签显示每个准确智能体与模型组合及执行数，不从一页推算或猜测配对；完整列表筛选 SHALL 继续只展示匹配执行，再次点击或清除恢复原列表，且不确认消息已查看

#### Scenario: 对话列表范围与布局
- **WHEN** 用户切换工作空间或调整面板宽度
- **THEN** 空间切换重算总览并清除统计分组筛选；卡片按实际容器宽度并排或上下排列，可收起，零执行时压为一行

#### Scenario: 名称和全量入口
- **WHEN** 用户查看活动浮窗或完整列表
- **THEN** 页面称为“对话列表”；浮窗顶部右侧提供“全部对话”，统计下方不增加解释小字，不新增统计入口、列表入口以外的额外数字、转圈或闪烁；同一列表入口 MUST 遵循待处理优先的单角标；浮窗只提供待处理与执行中两组及执行模型摘要，完整列表保留分类数量和筛选

#### Scenario: 单组统计布局
- **WHEN** 用户查看存在正在执行对话的提醒浮窗或完整列表
- **THEN** 浮窗 SHALL 只保留一小块实际智能体与模型组合摘要，完整列表 SHALL 仅展示按模型分布，不恢复智能体分组筛选
- **AND** 模型名称 SHALL 自然换行；完整列表统计至少容纳两排后再滚动

#### Scenario: 统计与活动区衔接
- **WHEN** 完整列表同时展示执行统计与活动对话
- **THEN** 两者 SHALL 保持既有紧凑衔接；浮窗摘要与待处理、执行中两组 SHALL 有清楚的层级

### Requirement: 顶部参与方必须展示实际智能体与模型组合
系统 SHALL 在“参与过此对话”区域按已实际参与的智能体（Agent）与模型（Model）组合展示，不能只按智能体去重。同一组合重复出现只显示一次；同一智能体使用不同模型必须分别显示。读取的模型 MUST 来自准确参与绑定或准确匹配该参与方的当前执行，不得由下一轮草稿或另一参与方的当前模型推断；旧记录缺失时明确显示“模型未记录”。

#### Scenario: 同一智能体切换模型
- **WHEN** 一个对话中同一智能体实际使用过两个模型
- **THEN** 顶部显示两个智能体与模型组合；模型区域按钮完整可见，较多统计项有界滚动，不裁切普通两组内容

### Requirement: 模型名称与两排统计必须保持可读
系统 SHALL 在执行统计、活动辅助信息及顶部参与方复用模型选择器中的完整显示名称，以准确模型编号和已知来源解析；筛选继续使用原始身份，不得按名称或强制大写猜测模型。无法可靠匹配时明确显示名称待确认，缺失模型显示未记录。浮窗组合摘要 SHALL 使用完整模型名称并附真实智能体，内容可自然换行，较多项目可滚动；完整列表原有分布 SHALL 至少完整容纳两排实际换行按钮后才滚动，按实际行高与容器宽度计算，不裁切第二排。

#### Scenario: 完整名称占用更多空间
- **WHEN** 选择器名称比内部模型编号长并在窄浮窗内自然换行
- **THEN** 界面使用完整显示名称，两排按钮完整可见，更多项目在该摘要或分布区域内滚动；完整列表点击统计项仍携带原模型编号筛选

### Requirement: 未执行草稿必须与对话列表分离
系统 MUST 保留未发送文本和上传附件，但仅创建空对话或添加附件 MUST 不使草稿进入全局、工作空间及任务对话列表。已尝试发送而失败或状态未知的记录 MUST 保留可发现性。

#### Scenario: 附件准备后仍未发送
- **WHEN** 创建草稿并上传附件但未发送任何输入
- **THEN** 所有对话列表 MUST 不显示该空草稿，重新打开准确草稿仍可读取附件
- **AND** 首次发送形成用户记录后 MUST 能从对应列表找到

### Requirement: 执行过程必须自然平铺并保留失败提醒

执行中助手说明与工具组 MUST 按实际顺序展示；连续工具 MUST 默认汇总折叠，第一条起 MUST 保持稳定身份与布局。工具组展开后各调用 MUST 按原顺序可读，助手说明 MUST NOT 被压入工具组。每条工具的原输入输出 MUST 可独立展开查看。执行结束后过程 MUST 自动折叠；再次展开 MUST 与最终答复保持同一左边界，不添加层级竖线。工具组折叠时 MUST 保留调用数量、失败及结果未知的文字与图标提醒，不增加整行背景强调。加载更早记录与实时事件 MUST 保留可见阅读位置和明确展开选择。

#### Scenario: 执行从一条增长到多条
- **WHEN** 当前过程收到更多助手说明或连续工具
- **THEN** 新说明和工具组 MUST 按原顺序显示，连续工具 MUST 汇总到原组；已明确展开或收起的选择、已有工具详情和阅读位置 MUST 保持

#### Scenario: 完成后查看过程
- **WHEN** 本轮结束且用户再次展开已折叠过程
- **THEN** 说明与工具组 MUST 与最终答复同级展示，组内不得添加层级竖线；失败及结果未知摘要 MUST 仍明确可见

#### Scenario: 旧记录并入同一分组
- **WHEN** 用户主动加载更早记录
- **THEN** 系统 MUST 保留已观察的阅读位置和工具详情展开选择，不因首条来源变化丢失定位

### Requirement: 新对话共享唯一可切换归属的草稿
系统 MUST 在同一应用配置域内保存唯一的新对话草稿；已创建对话 MUST 继续各自隔离未发送输入。没有已保存选择时，新草稿 MUST 默认选择当前页面所处工作空间；已有草稿 MUST 保留其明确选择，不跟随查看的旧对话或页面切换而改写。用户 MUST 可以切换或清除草稿工作空间，清除后 MUST 使用默认工作空间；选择器 MUST 不列出默认工作空间选项。切换 MUST 保留文本、附件和模型选择，但 MUST 解除跨空间任务绑定。创建真实对话 MUST 迁移同一草稿，已受理发送只能清理实际已提交输入，不覆盖之后编辑。

#### Scenario: 从旧对话返回新建
- **WHEN** 用户在新对话输入后打开其他对话，再次点击新建
- **THEN** 系统 MUST 恢复同一未发送输入及工作空间选择

#### Scenario: 首次新建与取消工作空间
- **WHEN** 没有已保存的新草稿，用户从工作空间 A 新建，然后清除选择
- **THEN** 初始 MUST 选择 A，清除后 MUST 显示空选择并使用默认目录，列表 MUST 不包含默认空间

#### Scenario: 切换草稿工作空间
- **WHEN** 用户将带任务绑定的新草稿从 A 切换到 B
- **THEN** 系统 MUST 保留输入和附件，解除 A 的任务绑定，返回新建及刷新后 MUST 恢复 B

#### Scenario: 应用域与已创建对话隔离
- **WHEN** 用户在其他应用配置域或已经创建的对话中输入
- **THEN** 输入 MUST 不覆盖当前配置域唯一的新对话草稿

### Requirement: 活动提醒必须区分需要用户关注的对话

系统 SHALL 继续按准确身份互斥区分等待批准或回答、确定执行、其余有未查看消息及未知执行。侧栏 MUST 只显示一个角标：待处理（等待批准或回答与其余未查看之和）大于零时显示待处理数；否则确定执行数大于零时显示执行数；两者为零时隐藏角标。未知执行 MUST NOT 计入待处理或执行数，系统 MUST NOT 为其显示常驻聚合提示条；其条目 SHALL 在活动清单与完整列表保留“状态待确认”身份徽标，入口说明及可访问名称 SHALL 保留未知计数。执行中有新消息 MUST NOT 重复计为待查看。角标 MUST 静态显示，并由说明及可访问名称准确区分待处理与执行中，不仅依赖颜色。

#### Scenario: 混合状态数量
- **WHEN** 完整范围有三个执行中、两个等待回应、两个已结束未查看和一个未知执行
- **THEN** 入口 MUST 仅显示待处理 4，浮窗 MUST 提供待处理 4、执行中 3
- **AND** 未知执行条目 MUST 标为状态待确认，入口说明 MUST 解释一个执行状态需核实
- **AND** 每条等待回应 MUST 标为待决策，其他未查看 MUST 标为待查看

#### Scenario: 仅执行与静默
- **WHEN** 没有待处理而有三个确定执行的对话
- **THEN** 角标 MUST 显示执行中 3
- **AND** 确定执行结束且没有待处理时 MUST 隐藏角标，未知执行 MUST NOT 冒充执行中

#### Scenario: 零值与大数量
- **WHEN** 显示数量大于 99 或汇总读取失败
- **THEN** 大数 MAY 缩写为 99+，可访问名称 MUST 保留准确数量；失败 MUST 保留已有数量并提示未更新，首次不可读 MUST NOT 冒充零

#### Scenario: 执行同时有未查看消息
- **WHEN** 正在执行的对话产生尚未查看的新消息
- **THEN** 它 SHALL 仅计入执行中，不重复计为待处理；结束后仍有未查看消息 SHALL 转入待查看

### Requirement: 活动分类必须覆盖完整范围并支持准确定位

系统 SHALL 在同一空间完整活动集合上计算分类数量，MUST NOT 根据已加载一页推算。提醒浮窗 MUST 只有一组“活动中”清单，待处理条目位于前面，同类及工作空间内 MUST 按最近用户输入倒序，只有用户输入才更新排序时间，模型回复、工具、定时刷新与查看确认 MUST NOT 改变该时间。顶部 MUST 标为“执行中模型”并按真实账号身份与模型组合汇总，MUST NOT 展示智能体名称或将其推断为账号；来源缺失 MUST 明示账号未记录。系统 MUST 保留工作空间身份与分组，移除常驻分类筛选及重复统计；未知执行 SHALL NOT 显示聚合提示条，条目保留在共同活动清单并带“状态待确认”身份徽标。每组 MUST 使用对应筛选的有效分页，待处理位于后续活动页时 MUST 仍可直接发现。完整列表 MUST 同样移除常驻分类统计筛选栏与未知执行聚合提示条，SHALL 保留执行分布筛选、空间范围、搜索、分组与分页行为，原执行分布筛选互斥、分页和搜索行为继续有效。各入口 MUST 保留准确身份定位、查看确认和最近用户输入排序，不引入自动执行。

#### Scenario: 待处理位于未加载页
- **WHEN** 未筛选活动第一页被执行中的对话占满，待处理位于后续页
- **THEN** 提醒浮窗 MUST 仍能展示待处理，不显示假空态；组内可继续加载，切换或刷新后的旧响应 MUST NOT 覆盖较新数据

#### Scenario: 键盘与触屏
- **WHEN** 用户悬停或键盘聚焦提醒入口，或从触屏进入完整列表
- **THEN** 浮窗 MUST 可用鼠标或键盘打开准确对话并退出；触屏入口 MUST 保留完整列表开关语义

#### Scenario: 分类切换和异步返回
- **WHEN** 用户在完整列表切换或清除执行分布筛选，旧分页或筛选响应返回
- **THEN** 原分布条件 SHALL 清除，旧响应 MUST NOT 覆盖当前筛选或分页
- **AND** 切换完整列表空间 SHALL 清除原分布筛选并按新空间汇总

#### Scenario: 提醒读取失败
- **WHEN** 首次汇总未完成或刷新失败
- **THEN** 系统 SHALL 显示未知或未更新，不将失败表示为零；已有可信观察 SHALL 保留并标明未更新

#### Scenario: 仅筛选不确认查看
- **WHEN** 用户悬停提醒、在完整列表选择执行分布筛选或触屏进入列表
- **THEN** 系统 MUST NOT 推进查看位置、回答问题、批准或发送输入
- **AND** 打开条目 SHALL 定位准确空间及对话，只有既有可见正文流程可推进查看位置

#### Scenario: 相同模型的不同账号
- **WHEN** 同一模型分别由两个账号执行，或一个账号通过不同执行方运行
- **THEN** 顶部 MUST 按账号身份与模型准确合并或区分，不以智能体名称猜测账号

#### Scenario: 活动排序不跟随后台回复
- **WHEN** 用户未输入而模型回复、工具输出或定时读取更新
- **THEN** 同类内顺序 MUST 保持；用户输入后 MUST 按该输入时间重新排序，待处理优先于确定执行

### Requirement: 执行补充必须独立保留接收事实和输入身份

每条补充 MUST 有独立请求身份并绑定已观察的对话、执行、参与者与服务代次。相同请求身份重试 MUST 返回原事实，内容不同 MUST 冲突；补充 MUST 不另建并行执行。原生输入 MUST 以准确请求或原生输入身份映射，不能只因属于同一执行就合入首条输入。确定未接收 MUST 保留可编辑文字和图片；接收未知 MUST 保存可发现记录并先观察，MUST NOT 自动重发。图片集合的写入 MUST 校验自身已观察版本，实时回复与工具事件 MUST 不单独使安全上传失效；上传结果 MUST 不覆盖更新的历史。

#### Scenario: 连续补充及重复请求
- **WHEN** 同一执行收到多条补充并有同编号请求重试
- **THEN** 每条不同输入 MUST 各自准确映射，同编号同内容 MUST 不重复交付，不同内容 MUST 明确冲突

#### Scenario: 完成临界点及断线
- **WHEN** 原生完成与补充准入交错，或发送后无法确认接收
- **THEN** 系统 MUST 如实区分拒绝、已接收与未知，保留已成立的原执行和内容事实，不自动转发到后续执行

#### Scenario: 流式输出期间上传
- **WHEN** 图片正在上传，原执行同时产生工具或回复事件
- **THEN** 上传 MUST 按准确图片集合版本准入并保留实时事件，不因无关历史版本变化产生持续冲突

### Requirement: 自动恢复观察不打扰正常使用
对话页面 MUST 仅为尚未确认结束的轮次、未结束工具、待回应请求或已提交待发送事项维持持续消息观察。每轮已明确结束且无上述遗留事项时，页面 MUST 停止本轮持续连接、重试与执行状态轮询；重新打开该对话 MUST 只读取当前记录。单纯连接断开 MUST NOT 否定已确认结束的事实。下一轮提交或既有全局活动刷新发现该对话真实变化时，页面 MUST 按准确身份重新读取当前记录并在需要时建立观察，不要求已结束轮次保持连接。

对话页面 MUST 在自动重连和自动核对执行状态期间静默恢复观察，MUST NOT 仅因进入恢复过程展示故障提醒。仍需观察且有界重试耗尽时 MUST 显示准确连接错误并保留当前记录和草稿；连接故障 MUST NOT 被表述为原执行已经失败或已有完成事实未知。确认原执行失败时 MUST 保留准确错误，MUST NOT 隐藏待用户决定、授权或真实执行失败，MUST NOT 自动重发原请求。重连 MUST 先核对当前记录，期间发现准确结束时 MUST 停止重试且不显示连接告警。

#### Scenario: 短暂事件连接中断
- **WHEN** 未结束轮次的事件连接短暂中断并在有界退避重试中恢复
- **THEN** 页面 MUST 静默恢复，不显示重连或恢复成功提示，也不重发工作

#### Scenario: 持续连接故障
- **WHEN** 仍需观察的事件连接有界重试耗尽，且重新读取未能证明观察可以结束
- **THEN** 页面 MUST 显示无法同步最新进展的连接错误并保留当前对话与草稿，不宣称执行失败

#### Scenario: 已完成轮次不再维持连接
- **WHEN** 当前轮次已明确结束，相关工具均已完成且无待回应或待发送事项
- **THEN** 页面 MUST 取消本轮连接和重试，不再主动轮询该轮执行状态；后续连接关闭 MUST NOT 显示故障提醒

#### Scenario: 遗留工作仍需观察
- **WHEN** 当前轮次未知、仍有未结束工具、待回应请求或已提交待发送事项
- **THEN** 页面 MUST 保留必要观察，不得仅凭最终回复文字或后台控制资源已释放而视为观察结束

#### Scenario: 重连时读到完成
- **WHEN** 消息连接丢失完成事件，而重连前读取的准确当前记录已明确结束且无遗留事项
- **THEN** 页面 MUST 保存该结束事实并停止重试，不显示原执行状态未知提醒

#### Scenario: 下一轮和其他入口变化
- **WHEN** 已结束对话收到下一轮受理事实，或既有全局活动刷新发现该对话有新变化
- **THEN** 页面 MUST 重新核对当前记录，并按当前需要恢复持续观察；旧轮或其他对话的迟到失败 MUST NOT 污染新轮状态

### Requirement: 对话视频必须保留原件并明确视觉交付边界

对话 MUST 支持通过文件选择、剪贴板中的文件与拖放添加 MP4、WebM 和 MOV 视频，与图片共用每次最多四份材料的边界。视频单个 MUST 不超过32 MiB，图片原限制 MUST 保留；无效、超限或无法解码 MUST 说明受影响材料并保留已有文字及附件。草稿及已发送记录 MUST 提供视频播放，刷新后 MUST 可通过原对话认证读取。视频与附属画面 MUST 遵守同一对话归属、内容校验、附件版本和临时保留边界，MUST NOT 通过公开地址或任意文件路径读取绕过认证。

系统 MUST 有界提取最多八张带时间点的画面，发送和执行中补充时向支持图片的执行方交付这些画面及准确原件来源，MUST 明确只是视觉抽样且没有交付音轨，MUST NOT 宣称模型已连续观看视频。换执行方、待发送和历史交接 MUST 保留可核对的原件及画面对应；缺失、不支持或接收未知 MUST 保留输入及准确状态，MUST NOT 静默删减并伪报完整发送。

#### Scenario: 三种入口加入录屏并发送
- **WHEN** 用户选择、粘贴或拖入有效视频并明确发送
- **THEN** 同一草稿 MUST 显示可播放材料，执行方 MUST 收到带时间的抽样画面和准确原件来源，已发送记录 MUST 能重读并播放

#### Scenario: 编码无效或容量超限
- **WHEN** 视频为空、超过大小、类型与字节不符或浏览器无法解码
- **THEN** 系统 MUST 说明原因，保留已有文字及材料，MUST NOT 显示视频完整发送成功

#### Scenario: 模型不支持图片或原执行接收不确定
- **WHEN** 视频准备发送到无视觉能力的执行组合，或执行中补充接收无法确认
- **THEN** 系统 MUST 分别解释能力限制或未知接收状态，保留草稿和原执行事实，MUST NOT 自动换执行方或重复发送

#### Scenario: 视频及画面跨刷新和交接
- **WHEN** 已发送视频的对话刷新、换执行方或清理未发送临时材料
- **THEN** 原件及附属画面 MUST 保留准确关联，历史交接 MUST 提供可按需读取的来源，其他对话 MUST 无法使用该附件编号读取或发送它

### Requirement: 临时故障必须有界自动重试

当前宿主存活期间，系统 MUST 自动重试可确认没有发送工作输入的临时连接故障；模型明确报告繁忙或临时服务故障时，只有准确原执行结束、相关工具均已结束且无待决定时才可自动接续。针对同一用户请求的临时故障重试 MUST 最多额外尝试三次，采用逐步延长的等待，显示原因及次数并允许用户停止。系统 MUST 保留原输入、来源、模型、权限与历史失败，接续 MUST 标为系统消息并要求核对当前成果，不逐条重放历史工具。已发送但结果未知 MUST 先观察且不得直接重发；原生上下文创建结果未知 MUST NOT 自动另建上下文。认证、权限、额度耗尽、身份变化及用户主动停止 MUST NOT 自动重试；取消或宿主关闭 MUST 结束等待，不因刷新或并发观察重复发送。

#### Scenario: 临时连接失败尚未发送
- **WHEN** 原生连接准备临时失败且没有发送工作输入
- **THEN** 系统 MUST 退避重建原连接并以原输入身份继续，超过次数上限后保留具体原因

#### Scenario: 模型繁忙后继续
- **WHEN** 模型明确返回繁忙且准确执行与工具均已结束
- **THEN** 系统 MUST 在同一可见对话和原来源内有界接续，保留已完成成果及原失败记录

#### Scenario: 不可自动重试与取消
- **WHEN** 结果未知、工具未结束、需要用户决定、额度耗尽、认证权限或身份变化，或用户停止、宿主退出
- **THEN** 系统 MUST 保留当前记录和准确原因，取消待执行的自动重试且不重发工作

### Requirement: 切换执行组合必须支持直接继续交接

已有用户历史且切换模型或执行者后，用户打开交接或明确发送时，系统 MUST 允许使用默认的继续当前工作要求生成可查交接并发送，不要求用户先填写无信息增量的“继续”。选择本身 MUST 不发送；新空白对话 MUST 继续拒绝空输入。未交付用户要求 MUST 保留在交接来源，不能因失败丢失。

#### Scenario: 切模型后空草稿查看并发送
- **WHEN** 已有对话切换模型，用户未补充文字并查看交接后明确发送
- **THEN** 系统 MUST 展示并发送已有工作及默认继续要求，不显示空输入错误；切换选择和单独预览 MUST 不执行

### Requirement: 异常结束必须提供原目标恢复动作

一轮执行（Run）异常结束或已结束但没有可见答复时，界面 MUST 在异常附近提供“重试”或“继续”入口，不依赖用户是否切换模型或智能体（Agent）。未送达请求 MUST 恢复原输入及附件；已接收请求 MUST 先核对已有成果并接续原目标，MUST NOT 逐条重放旧工具。恢复 MUST 使用用户当前选择的执行组合，保存为关联原执行的系统动作，MUST NOT 额外制造用户“继续”消息、重写历史或清空草稿。原执行与工具未确认结束且控制未核验释放、有待用户决定或正在自动重试时 MUST NOT 另起重复恢复执行；系统中断 MUST 优先自动核对并接续，未知状态 MUST 保留准确事实和核对入口。恢复提交 MUST 校验原执行身份及当前版本，重复提交 MUST 保持同一执行身份；迟到或过期请求 MUST NOT 接续其他轮次。

#### Scenario: 同一执行组合恢复未送达或中断请求
- **WHEN** 用户没有切换选择，在异常提示旁点击“重试”或“继续”
- **THEN** 系统 MUST 根据原送达事实恢复原请求或接续原目标，保留历史并且不新增用户“继续”消息

#### Scenario: 切换模型或智能体后恢复
- **WHEN** 用户选择另一模型或智能体（Agent），再点击恢复动作
- **THEN** 系统 MUST 按当前选择组织原目标及交接，保留草稿和原附件，恢复动作只执行一次

#### Scenario: 未知、过期和正常完成不重做
- **WHEN** 执行状态未知、工具未结束、来源轮次已变化，或已经正常答复
- **THEN** 系统 MUST 拒绝直接重发，保留现场；未知可核对，正常答复不展示异常恢复入口

### Requirement: 上下文统计必须保持最近真实报告与准确来源
同一页面使用期间，对话上下文统计 MUST 在新执行尚未报告时保留已观察的最近真实用量、原模型来源与对应窗口口径。选择下一轮模型 MUST NOT 清空统计或改变当前执行。新报告到达后 MUST 整体替换旧统计，包括合法零用量；MUST NOT 将旧用量与新选择的模型窗口混算。说明区 MUST 区分当前配置和最近报告来源，不增加过程通知。没有可信报告时 MUST 明确未收到报告，不伪造零用量。不同工作空间及对话 MUST 隔离，新对话 MUST 不继承旧统计。

#### Scenario: 新指令已发送但尚无统计
- **WHEN** 同一对话已有报告，用户发送新一轮指令，新一轮未报告用量
- **THEN** 统计 MUST 保持最近报告及其百分比，不能短暂清空

#### Scenario: 执行中选择下一轮模型
- **WHEN** 模型 A 正在执行，用户选择模型 B
- **THEN** 当前执行 MUST 保持 A，统计 MUST 继续展示 A 的最近报告和原窗口，说明区标明报告来源
- **AND** 下一轮 B 的真实报告到达后 MUST 替换为 B 的数据，不混用两个窗口

#### Scenario: 新报告为零或没有窗口
- **WHEN** 当前执行报告合法零用量，或报告用量但缺少窗口
- **THEN** 零 MUST 作为有效新数据替换旧报告；窗口缺失时 MUST 仅使用同一真实来源的已知窗口，无法确认时不显示伪造百分比

#### Scenario: 对话隔离与页面重载
- **WHEN** 用户打开其他对话、新建对话或完整重载页面
- **THEN** MUST 不从另一对话沿用报告；重载后仅展示可从当前事实恢复的数据，没有报告时明确未知，不声称恢复未保存的数据

### Requirement: 输入区任务关联信息必须统一垂直对齐
工作空间、分隔符、任务引用和关联按钮 MUST 在同一行中垂直居中对齐。窄宽度和长名称 MUST 可换行且不遮挡按钮，既有点击、键盘操作及任务链接 MUST 保持。

#### Scenario: 未关联与已关联任务
- **WHEN** 用户在宽屏或窄面板查看未关联或已关联任务的输入区
- **THEN** 同行文字与按钮 MUST 垂直对齐，长内容换行后关联入口仍完整可操作

### Requirement: 图片草稿与首次对话提交必须分离
系统 MUST 独立保存新草稿图片，上传或粘贴图片 MUST NOT 创建真实对话、显示对话编号或锁定工作空间。刷新、切换旧对话再返回以及更换或清除草稿归属 MUST 保留图片和文字。已有对话 MUST 各自隔离未发送输入。

#### Scenario: 带图草稿更换归属
- **WHEN** 用户在新草稿添加图片后更换或清除工作空间并刷新
- **THEN** 同一图片和输入 MUST 恢复，页面仍无真实对话编号且可继续选择归属

### Requirement: 首次发送必须可靠转入真实对话
首次发送 MUST 在目录、任务、模型、权限及图片校验完成后，原子保存真实对话及本次输入的受理事实；明确未受理 MUST 保留草稿且不遗留空对话。提交 MUST 使用可恢复的唯一请求身份，同身份同内容 MUST 不重复创建或执行，不同内容 MUST 冲突。结果未知 MUST 先读取原提交事实，MUST NOT 自动创建替代请求。已受理 MUST 仅清理实际提交的草稿，不覆盖后续编辑。

#### Scenario: 校验失败与响应丢失
- **WHEN** 首次发送校验失败，或提交受理后响应丢失并刷新
- **THEN** 前者 MUST 保留可更换归属的草稿且没有空对话；后者 MUST 能按原请求找到准确对话且不重复执行

### Requirement: 执行控制与来源展示必须对应真实对象
对话停止入口 MUST 位于输入区上方的执行状态栏，不在标题栏重复；请求停止与确认停止 MUST 分别表达。左侧停靠及专注显示 MUST 将对话竖栏置于面板左侧。本地来源链接 MUST 展示简短可识别标签，按该对话准确工作位置打开文件及有效行号；无法安全定位 MUST 提示且允许复制原路径，MUST NOT 猜测其他来源或放开任意文件访问。

#### Scenario: 停止与来源阅读
- **WHEN** 用户停止执行或打开包含行号的本地来源引用
- **THEN** 停止 MUST 在下方状态栏反馈确认过程；有效引用 MUST 打开准确文件及行号，正文不展示整段原始链接标记

### Requirement: 重新核对必须支持对话级安全接管

重新核对 MUST 先恢复准确原生观察。新后台 MUST 能按准确身份同步原执行结果，并独立接收已明确提交的新要求；原上下文的接管或资源关闭仍 MUST 取得准确持有者证明，MUST NOT 将此要求扩展为新输入门禁。系统 MUST NOT 为一条对话暂停整个旧后台，MUST NOT 因核对重发原要求或自动中断仍在运行的工作。身份、工具或释放不确定时 MUST 保留原因与原持有者。

#### Scenario: 原执行完成但旧观察失效
- **WHEN** 旧后台跟随连接丢失且同一请求的持久历史已经明确完成
- **THEN** 核对 MUST 同步最终回复和准确终态，并保留独占资源的准确归属，MUST NOT 因等待该资源释放而阻塞新版投递新要求

#### Scenario: 其他对话仍在执行
- **WHEN** 同一旧后台的其他对话仍运行
- **THEN** 核对 MUST 仅释放当前对话的可独立资源，不停止其他对话

#### Scenario: 原执行仍活动或状态未知
- **WHEN** 原执行仍运行、工具未知、有待决定或身份未匹配
- **THEN** 核对 MUST 恢复观察或保留明确原因，不自动重放原工作；用户明确提交的新要求 MUST 可以独立执行

#### Scenario: 旧后台不支持释放确认
- **WHEN** 旧后台没有返回精确执行的释放确认
- **THEN** 新后台 MUST 保留旧归属并沿用观察，不将请求成功当作接管成功

### Requirement: 目标结果执行结束和后台释放必须独立判定

系统 MUST 分别保持任务成果的完成判断、准确原生执行是否结束、旧后台是否仍持有执行资源三个事实。原生执行结束或后台资源释放 MUST NOT 自动把任务或未知操作结果标为成功。执行器仅在准确执行身份及原后台持有的控制资源可安全关闭得到证明时确认可释放；独立命令结束未知时 MUST 保留原执行未知，不把控制资源释放冒充操作完成。单纯连接断开、空工具列表、历史未结束记录或孤立进程编号 MUST NOT 代替该证明。

#### Scenario: 操作结果未知但受管执行资源已结束
- **WHEN** 原操作可能已生效且结果记录缺失，而原后台控制资源已确认可释放
- **THEN** 系统 MUST 保留结果待核对及原操作证据，允许关闭已确认空闲的独占资源；MUST NOT 重发原要求、重做操作或将任务标为完成

#### Scenario: 工具或另一对话仍在运行
- **WHEN** 仍依赖该后台的工具活动、存在明确登记的原生后台任务或待决定，或同一资源组的另一对话仍活动
- **THEN** 系统 MUST 保留相应资源及准确归属，MUST NOT 为释放一条历史疑点而中断其他工作

### Requirement: 旧后台退役必须基于资源持有事实

旧后台 MUST 按实际执行、辅助工作、重要写入及未释放原生资源决定是否仍忙。准确资源关闭成功后，历史结果待核对 MUST NOT 单独阻止该后台退出或使退出确认失败。停止发生错误且未确认结束时 MUST 返回待确认，MUST NOT 长期把停止请求当作确定模型执行。缺少释放证明的旧后台或旧执行器 MUST 沿用保守保护，MUST NOT 仅为清理提醒强行放行。

#### Scenario: 仅剩历史结果疑点
- **WHEN** 旧后台没有实际工作且全部所属原生资源已确认释放，但历史操作结果仍待核对
- **THEN** 旧后台 MUST 能正常退出并确认自身资源释放；历史结果 MUST 保留且不能触发自动重发

#### Scenario: 隐藏已释放的历史疑点
- **WHEN** 用户已隐藏对话，其原执行结束和资源释放均有准确证明，而操作结果仍未知
- **THEN** 系统 MUST 保留历史的未知结果，不再将它计入活动提醒和执行模型数；没有这两项证明时隐藏 MUST NOT 掩盖活动执行

#### Scenario: 独立命令继续而原生控制进程已经退出
- **WHEN** 原生主进程退出、原后台控制资源已可安全释放，但独立命令缺少结束证据
- **THEN** 系统 MUST 允许空后台释放并分别保存 executionState=unknown 和 resourcesReleased=true，保留操作待核对；MUST NOT 终止该独立命令、宣称执行完成或自动重发

### Requirement: 必要用户决定必须通过问题卡片等待并接续原执行

工作对话 MUST 向支持提问的智能体（Agent）提供普通执行中可用的原生提问能力及使用指引。缺少无法自行取得的必要信息、新的授权或无法从已有目标推导的关键业务取舍时，智能体（Agent）MUST 发起明确问题并等待回答，MUST NOT 仅输出文字问题后继续依赖该答案的工作。Buildr MUST 复用现有问题卡片和准确本轮答复入口显示等待、选项或填写回答，并只把有效回答交回产生请求的原执行。完全访问 MUST NOT 自动回答业务问题；普通补充 MUST NOT 隐含解决待答请求。普通文字 MUST NOT 被推断为结构化请求（Structured Request）。

选项说明 MUST 随原生问题展示；原生允许其他回答时，卡片 MUST 提供可填写的其他回答，未填写有效答案前 MUST NOT 提交。有效问题 MUST 在页面重新读取后保持可见；原生取消、失效或停止后 MUST 结束该问题的可回应状态。迟到、重复或属于其他执行的答复 MUST NOT 继续原生工作。标题与交接摘要等无工具辅助生成 MUST 不获得工作对话的提问能力或等待用户决定。

#### Scenario: 普通执行中请求用户决定
- **WHEN** 智能体（Agent）在普通工作对话中确实缺少必要的用户输入
- **THEN** 原生提问 MUST 可用，页面 MUST 展示现有问题卡片，并按真实执行状态表达等待；收到回答前 MUST 不继续依赖该决定的工作
- **AND** 用户提交有效回答后 MUST 继续同一原执行，保存对应问题及回答，不另发一轮工作

#### Scenario: 等待期间刷新与补充
- **WHEN** 有效问题待回答，用户刷新页面或通过其他已有入口提交普通补充
- **THEN** 原问题 MUST 保留并可通过卡片回答，普通补充 MUST 不代替选择或清除等待

#### Scenario: 等待期间编辑草稿
- **WHEN** 当前有效业务问题待回答，用户刷新页面或编辑底部草稿及附件
- **THEN** 原问题 MUST 保留并可通过卡片回答，底部草稿 MUST 不自动发送、搬入回答或被当成选择

#### Scenario: 问题等待时普通发送不可用
- **WHEN** 原页面曾因有效业务问题待回答而禁用普通发送，用户继续在同一对话提交新要求
- **THEN** 界面 MUST 允许普通发送及快捷键，提交的新要求 MUST 独立接收并保留原执行；MUST NOT 自动回答原问题、批准权限或以问题未答为由无限排队
- **AND** 底部草稿 MUST 保持可编辑和保留，定位 MUST 不自动选择或提交答案

#### Scenario: 其他入口提交普通补充
- **WHEN** 有效问题待回答，其他已有入口向原执行提交普通补充
- **THEN** 原请求 MUST 继续保留，普通补充 MUST 不代替正式回答或隐含清除等待

#### Scenario: 不回答问题而停止本轮
- **WHEN** 用户通过现有停止入口结束等待中的本轮
- **THEN** 系统 MUST 只在准确确认请求取消、失效或原执行结束后移除可答卡片，保存未回答事实，MUST NOT 伪造用户答复或同意
- **AND** 停止尚未确认时 MUST 保留准确原状态，不自动重发原操作；用户明确提交的新输入 MUST 可以作为独立新轮处理

#### Scenario: 取消与迟到回应
- **WHEN** 原生取消问题、原轮停止或结束，随后旧卡片尝试提交回答
- **THEN** 系统 MUST 移除失效请求并拒绝旧回应，MUST NOT 影响其他问题或执行

#### Scenario: 辅助生成及文字询问
- **WHEN** 生成标题或交接摘要，或助手只输出含问句的普通文字
- **THEN** 辅助生成 MUST 继续禁止工具，普通文字 MUST 不自动形成问题卡片或执行许可

### Requirement: 三家原生接入必须共享控制资源释放规则

Codex、Qoder 和 DSH MUST 复用相同的控制进程所有权、准确执行引用、资源组空闲证明及释放结论，不得各自复制物理释放策略。厂商适配器 MUST 只提供其原生执行和依赖事实；任务成果、原执行状态和后台控制资源释放 MUST 保持独立，未知操作 MUST NOT 自动重发。

#### Scenario: DSH 服务已退出但独立命令结果未知
- **WHEN** 准确 DSH 控制进程退出，相关控制资源已可安全关闭，而独立命令或操作回执仍未知
- **THEN** 系统 MUST 允许释放已空闲控制资源，保留未知执行及操作结果，不终止独立命令、不重发原要求

#### Scenario: DSH 原生后台工作仍依赖服务
- **WHEN** DSH 原生会话有运行或停止中的后台任务、待决定、未确认补充输入或其他活动执行
- **THEN** 系统 MUST 保留该服务和准确持有；后台观察失败 MUST NOT 阻止普通发送，但 MUST NOT 以空列表推定可释放

#### Scenario: 同源模型辅助调用尚未结束
- **WHEN** 对应原生资源的准确模型连接仍有在途调用
- **THEN** 共用释放逻辑 MUST 保留该资源，不得中断调用，也不得因其他对话的调用而占住已空闲的独立资源

#### Scenario: DSH 恢复补写未知工具结果
- **WHEN** 原生恢复补写 `TOOL_OUTCOME_UNKNOWN`，而没有准确收到该执行及工具的真实完成回执
- **THEN** 实时与历史观察 MUST 保留工具结果未知，不得以合成记录判定操作完成或允许重发；已准确收到的同次工具完成事实 MUST 继续有效

#### Scenario: 旧记录缺少控制资源证明
- **WHEN** 原执行没有可验证的资源引用或所属平台不能证明控制组空闲
- **THEN** 系统 MUST 保留兼容读取与保守核对，不猜测原进程、不按恢复的编号发送退出信号

### Requirement: 等待回答时必须支持显式交接到新执行组合

原轮仅等待普通问题回答，用户切换模型或智能体（Agent）后，系统 MUST 提供两条明确路径：提交问题卡片的有效回答并交接，或提交输入框中的新指令并交接。无新增内容时 MUST 允许明确继续原目标。单独选择和查看交接 MUST 不停止、答复或发送。提交 MUST 先持久保存新内容、准确原轮及问题身份，保留原执行；系统 MUST 向所选新组合独立发送一次，不自动停止原轮，也不等待工具退出。执行未知、问题或原轮身份变化 MUST 保留具体原因及输入，MUST NOT 停止其他工作或推定成功。

交接资料 MUST 保留准确原问题；经卡片明确提交的回答 MUST 连同问题交给新组合，MUST NOT 先答复并唤醒旧执行。未提交的选项或填写内容 MUST 仍为未回答。交接动作本身 MUST NOT 被视为验收、选项答复或权限批准；实际业务回答 MUST 保持其明确范围。工具授权 MUST 继续归属原请求，不沿用本交接路径。普通原组合的卡片答复与补充 MUST 保持既有语义。

#### Scenario: 换模型后回答并交接
- **WHEN** 原轮等待问题，用户换模型并在问题卡片提交有效答案
- **THEN** 卡片 MUST 明确显示回答将交给新模型；系统 MUST 保存原问题与答案、保留准确原轮等待并向新模型交接，MUST NOT 把答案送回旧执行
- **AND** 其他未提交的输入草稿及未答问题 MUST 保留，实际回答 MUST 不扩大其授权范围

#### Scenario: 换模型后发新要求或继续
- **WHEN** 用户未提交原问题的回答，换模型后在输入框发送新要求或明确点击继续
- **THEN** 系统 MUST 交接已有现场与新要求，原问题 MUST 保留为未回答；选择了但未提交的选项 MUST 不作为答案

#### Scenario: 仅预览或取消交接
- **WHEN** 用户只切换模型、打开交接资料，或在实际投递前取消已保存的待发送
- **THEN** 原轮 MUST 继续等待，MUST 不自动答复、停止或投递新执行
- **AND** 如果另有明确停止操作，MUST 单独显示其事实；取消只撤回尚未发送的新轮，不改变旧停止的真实结果

#### Scenario: 停止未知或并发答复
- **WHEN** 原轮停止无法确认，或原问题被其他入口答复、原轮身份变化
- **THEN** 系统 MUST 保留交接内容和准确原因；停止未知 MUST NOT 单独阻塞新要求，已答复或身份变化时 MUST 拒绝过期问题的回答或交接，MUST NOT 重发原操作

#### Scenario: 重复提交和后台恢复
- **WHEN** 同一交接重复提交、页面刷新、接收后台重启或切换
- **THEN** 已持久保存的内容 MUST 能继续观察准确原轮并按原提交身份核对送达，MUST 不重复答复、重复发送或停止其他对话

### Requirement: 对话列表工作空间顺序必须稳定且可调整

对话列表 MUST 使用独立于对话活动的稳定工作空间顺序，并允许拖动及键盘调整，在当前应用配置域内记住顺序；默认空间 MUST 保持最后。组内对话 MUST 继续使用既有活动状态与最近指令排序。筛选或暂时无结果 MUST NOT 删除其他空间的排序偏好。

#### Scenario: 新指令不移动工作空间
- **WHEN** 某工作空间的对话收到新指令或执行状态变化
- **THEN** 工作空间位置 MUST 不改变，组内对话仍按既有规则更新

#### Scenario: 调整后刷新和筛选
- **WHEN** 用户调整工作空间顺序，再刷新或切换筛选
- **THEN** 系统 MUST 恢复已保存顺序，未设置偏好的空间使用稳定次序，其他空间偏好 MUST 保留

### Requirement: 对话列表必须统一按工作空间分批展开

每组 MUST 默认展示最多 5 条，用户点击“加载更多”时 MUST 使用当前末条对应的分页游标追加最多 10 条；工作空间整行 MUST 单击折叠，再次展开 MUST 恢复首批 5 条；包括活动对话在内 MUST 遵守同一展示上限。系统 MUST 将续读归入该组展开，MUST NOT 提供列表底部独立“加载更多”或一次展开全部。初次展示 MUST 不因全局分页遗漏其他工作空间，且 MUST 不自动加载所有剩余对话。列表 MUST NOT 定时或因窗口获得焦点自动刷新，续读 MUST NOT 从头重读已有前缀；作用域变化 MUST 回到默认数量。读取失败 MUST 保留该作用域已读取内容并提供重试；迟到结果 MUST NOT 污染新的作用域。

#### Scenario: 按批展开与收起
- **WHEN** 有至少 26 条的工作空间依次加载两次，随后点击工作空间整行收起并再次展开
- **THEN** 可见条数 MUST 依次为 5、15、25、0、5，未展开的剩余对话 MUST 不被一次全部加载

#### Scenario: 多空间与尾批
- **WHEN** 一个空间有很多新对话，另一个空间只有旧对话且有 8 条匹配结果
- **THEN** 两个空间 MUST 均可发现，后者初次展示 5 条，展开只增加剩余 3 条

#### Scenario: 刷新和过期请求
- **WHEN** 用户已加载到 15 条后等待或切回窗口，或搜索变化时旧请求晚到
- **THEN** 等待或切回窗口 MUST 不发起列表重读且保持已有 15 条，旧作用域结果 MUST 不写入新结果，失败 MUST 保留已有内容并可重试

#### Scenario: 整行拖动与折叠分离
- **WHEN** 用户拖动工作空间整行，或使用 Alt+上下方向键调整顺序
- **THEN** 系统 MUST 保留既有排序偏好及默认空间固定最后的约束，MUST NOT 因实际拖动误触折叠；普通单击和 Enter/空格 MUST 可切换折叠，不保留独立拖动手柄或收起按钮

### Requirement: 记住各模型的推理强度
对话模型选择器 MUST 按执行方、模型来源和模型记住用户明确选择的推理强度；切回模型时 MUST 恢复仍受当前档位支持的上次选择，不得改写历史运行记录。没有记录或记录不再受支持时 MUST 使用当前默认行为；浏览器存储不可用时 MUST 不阻止选择和发送。

#### Scenario: 切换模型后恢复
- **WHEN** 用户选择某模型的推理强度、切换到另一模型后再切回
- **THEN** 该模型恢复上次选择的受支持强度

#### Scenario: 记忆失效
- **WHEN** 模型当前档位不再支持已记住的强度
- **THEN** 选择器使用当前默认行为且不发送失效强度

#### Scenario: 不同来源隔离
- **WHEN** 不同模型来源提供相同模型标识
- **THEN** 各来源的强度选择互不覆盖

#### Scenario: 已有对话中主动切换
- **WHEN** 用户在已有对话中主动切换模型或智能体后切回原模型
- **THEN** 选择器恢复当前来源及档位支持的上次强度，历史运行记录保持不变

### Requirement: 正式问题自由回答必须共享完整媒体输入能力

正式问题的自由回答 SHALL 复用普通对话的文字、图片、视频编辑能力，支持选择、粘贴、拖放、预览和移除，同时 MUST 保持独立草稿与正式回答动作，不夹带底部未提交草稿。每次请求回答 MUST 最多包含四份原始图片或视频；图片 MUST 不超过8 MiB，视频 MUST 不超过32 MiB，并继续遵守所选执行组合的真实容量和视觉能力。旧字符串和多选回答 MUST 保持兼容。

服务端 MUST 验证原件及派生画面属于同一对话，MUST NOT 接受客户端指定任意文件路径。视频 MUST 沿用最多八张带时间点画面的有界抽样，保留准确原件来源及关联，明确没有交付音轨，MUST NOT 宣称连续观看。原生问题协议只支持文本时 SHALL 随正式回答交付经过验证的私有材料来源及读取边界，不伪造原生多模态支持或材料已经被理解。

#### Scenario: 正式提交图文回答
- **WHEN** 用户在自由回答中输入文字或添加图片，并正式提交
- **THEN** 系统 MUST 将实际回答与已验证图片来源交付给对应问题的准确执行者并接续原轮，保存回答与附件引用，MUST NOT 夹带底部草稿或自动另起一轮

#### Scenario: 视频回答与历史回读
- **WHEN** 用户选择、粘贴或拖入有效视频并在问题中正式提交，随后回读历史
- **THEN** 输入与历史 MUST 提供可播放原件，回答 MUST 保留原件及带时间点画面来源并说明视觉抽样与无音轨边界，其他对话 MUST 无法借用附件编号读取或发送

#### Scenario: 失败、超限与未提交草稿
- **WHEN** 材料超限、不支持、上传或原生回应失败，或用户只编辑尚未提交
- **THEN** 系统 MUST 说明受影响材料并保留已有文字及成功添加的材料，MUST NOT 静默删减、把草稿当作回答或伪报完整发送；接收未知 MUST 先观察，不自动重发

#### Scenario: 切换选项与独立草稿
- **WHEN** 用户在其他回答和已有选项之间切换，或底部另有未发送图文视频草稿
- **THEN** 自由回答材料 MUST 在本次编辑期间保持可继续编辑，MUST NOT 自动提交、移入底部草稿或将底部草稿混入正式答案

#### Scenario: 明确交接保全材料
- **WHEN** 用户通过既有明确交接入口提交问题回答与图片或视频
- **THEN** 系统 MUST 按原有身份与停止确认边界将回答及材料来源交给新执行方，保全原件与画面关联，MUST NOT 回应或批准旧原生执行，也不能由普通发送隐式触发该动作

### Requirement: 工具执行光点必须与类型图标协调且保持状态真实

执行中工具行 SHALL 与智能体（Agent）标识行使用相同的主题光点颜色和动效节奏，顺序 MUST 为光点、工具类型图标、最新执行内容；图标 MUST 继续按工具类型区分。执行中 MUST 不显示调用次数统计，结束后 MUST 移除执行光点并恢复实际统计。减少动态效果的系统偏好 MUST 被尊重，MUST NOT 仅依赖动效表达执行事实。

#### Scenario: 执行中与结束后
- **WHEN** 最新工具正在执行，随后该轮执行结束
- **THEN** 执行中光点 MUST 前置且与标识行同色，工具图标 MUST 对应真实类型；结束后 MUST 恢复统计而不保留虚假执行动效

#### Scenario: 减少动态效果
- **WHEN** 用户系统启用减少动态效果
- **THEN** 系统 MUST 停止呼吸动画，同时保留可识别的执行事实和工具内容

### Requirement: 账号配置入口必须固定于对话竖条底部

桌面对话竖条 MUST 在最底部提供账号与模型配置入口，与上方当前对话、对话列表入口分区，MUST NOT 紧跟对话列表图标或放在列表内容底部。入口 MUST 打开既有配置界面，关闭后保留此前对话与列表状态，MUST NOT 创建对话、发送输入或改变账号配置。移动端 MUST 保留既有配置入口。

#### Scenario: 展开或收起时直接打开配置
- **WHEN** 当前对话或列表处于展开或收起状态，用户点击竖条底部配置图标
- **THEN** 系统 MUST 打开原配置界面，图标 MUST 保持竖条底部位置，关闭后 MUST 保留原状态且不触发工作输入

### Requirement: 从已结束答复准确分叉原生上下文

系统 MUST 在每轮已结束的最终答复提供分叉入口，创建具有独立身份及原生上下文的新对话；新对话 MUST 保留截至所选轮次结束的统一历史和已引用附件，排除后续内容。动作 MUST 不发送工作指令、不修改原对话、不复制活动执行、待答交互或待发送队列，不回退文件与外部系统。原对话后续正在执行 MUST 不单独阻止从既有稳定轮次分叉。不支持准确分叉或缺少准确边界时 MUST 明确拒绝，不静默降级为文字复制或完整历史复制。

#### Scenario: 从较早答复分叉
- **WHEN** 用户选择较早已结束轮次的最终答复创建分支
- **THEN** 新对话 MUST 获得准确截断的独立原生上下文，保留所选轮次以前的内容和附件且不带入后续内容
- **AND** 原对话和当前文件 MUST 保持不变，新对话等待新指令

#### Scenario: 重复提交及未知结果
- **WHEN** 同一请求身份被重复提交，或原生创建后的响应丢失
- **THEN** 系统 MUST 返回已有新对话或明确报告该次结果待核对，MUST NOT 自动再创建一个原生分支
- **AND** 已知原生身份 MUST 持久保全，版本或边界冲突 MUST 显式报告

### Requirement: 分叉来源关系必须持久可复用

新对话 MUST 持久保存直接来源的对话身份、工作空间身份、条目身份、轮次身份、继承边界、当时标题及分叉时间，并通过公开对话读取结果提供。来源信息 MUST 不依赖临时页面状态或标题推断，普通改名和隐藏 MUST 不改写来源快照。网页 MUST 展示来源提示及返回原对话的入口，并说明文件仍是当前状态。再次分叉 MUST 指向本次直接来源，保留可沿关系追溯的链条。

#### Scenario: 改名及重启
- **WHEN** 原对话改名、隐藏，或服务重启后读取新对话
- **THEN** 新对话 MUST 仍返回原始来源身份和标题快照，并能据准确身份打开原对话

#### Scenario: 从分支再次分叉
- **WHEN** 用户从已有分支的已结束答复再次分叉
- **THEN** 新记录 MUST 指向该直接父对话，MUST NOT 把所有分支扁平归到最早根对话

### Requirement: 分叉后的新指令主导新标题

分叉新对话 MUST 使用中性初始名称，并在首次新指令发送后按该指令生成新标题，继承历史只提供必要背景。原生继承标题 MUST NOT 被当成新标题。生成 MUST 与工作上下文隔离，失败不影响工作，手动命名继续优先；刷新和后续发送不重置尝试预算。

#### Scenario: 首次发送新方向
- **WHEN** 分叉后用户首次输入不同方向的新指令
- **THEN** 标题生成 MUST 主要基于该新指令而非原对话首条指令或旧标题
- **AND** 生成失败 MUST 保留中性名称并允许继续对话

### Requirement: 子对话必须独立继承创建时的全部已保存背景

用户 MUST 能从准确主对话创建独立子对话。系统 MUST 冻结截至已观察创建版本的全部已保存背景与附件引用，并持久保存直接父对话、来源标题、时间、版本与截止位置。后续父记录及标题变化 MUST NOT 改写该背景。系统 MUST 复用正常交接的容量检查、来源索引和原始记录保全，不要求用户手写总结，不声称复制隐藏推理或私有压缩状态。

#### Scenario: 创建后独立发送
- **WHEN** 用户创建子对话，随后在子对话中发送新要求
- **THEN** 子对话 MUST 在独立执行中接收冻结背景和新要求，历史消息 MUST 只作背景而不重放历史工作或授权
- **AND** 父对话消息、执行、草稿及版本 MUST 不被创建或子对话发送改写

#### Scenario: 创建时父轮尚未结束
- **WHEN** 父轮仍在执行或等待回应，用户创建子对话
- **THEN** 系统 MUST 继承创建时已保存内容并保留未完成状态，MUST NOT 等待、停止或回应父执行
- **AND** 创建 MUST 不调用模型，子对话 MUST 不复制父轮控制身份、待回答问题或待发送内容

#### Scenario: 多轮决定及长背景
- **WHEN** 早期轮次包含必要决定，或全部背景超过目标输入容量
- **THEN** 背景来源 MUST 保留早期决定并可按轮读取，MUST NOT 只带最近一轮或静默截断

#### Scenario: 重复创建与准确附件
- **WHEN** 相同创建请求重复到达，或继承背景引用图片与视频
- **THEN** 相同父对象和创建版本 MUST 返回同一子对话，冲突 MUST 明确拒绝
- **AND** 子对话 MUST 可以独立读取准确原件及视频画面，不继承未发送草稿，附件准备失败 MUST 不返回成功子对话

### Requirement: 子对话必须以主对话内的单展开浮窗使用

主对话右上角 MUST 为每条子对话保留独立浮动入口。点击 MUST 展开对应非遮罩窗口，同一时间 MUST 只展开一个；选择另一入口 MUST 收起前一个且保留各自草稿、阅读位置及后台工作。展开、切换与收起 MUST 不改变主对话选择、阅读位置或未发送文字。刷新后 MUST 能重新发现持久关系。

#### Scenario: 多窗口入口和切换
- **WHEN** 主对话有多条子对话，用户依次点击不同入口
- **THEN** 每条子对话 MUST 有自己的入口，同时只出现一个展开窗口，主对话 MUST 保持原位置与草稿
- **AND** 再次打开原子对话 MUST 恢复其未发送内容及阅读位置

#### Scenario: 收起后继续执行与回应
- **WHEN** 用户收起正在执行的子对话，随后子对话等待授权或回答
- **THEN** 后台工作 MUST 不因收起停止，入口 MUST 显示真实待回应状态
- **AND** 用户重新展开后 MUST 能对准确子对话停止、回答或授权，不影响父轮

#### Scenario: 起始位置与后续工作安排
- **WHEN** 用户创建子对话，随后提出新的工作要求
- **THEN** 创建 MUST 只沿用主对话的起始工作位置，MUST NOT 因创建子对话自动新建或切换工作树（Worktree）
- **AND** 后续任务（Task）及实际工作位置 MUST 按用户本次要求和适用工作规则安排，界面及交付背景 MUST NOT 将起始位置描述为永久共享或阻止按要求隔离开发
- **AND** 系统 MUST NOT 声称仅创建子对话就完成代码隔离、回退或合并

### Requirement: 后台版本漂移必须有界恢复主动发送

用户主动发送已有对话的新一轮要求时，系统 MUST 保留观察版本与请求身份保护。明确拒绝且可证明尚未受理、重读后仅标题生成、用量或时间及已读信息发生变化时，系统 SHALL 自动重新准备并恢复同一次发送，最多恢复一次。历史正文、附件、参与者、模型、权限、执行状态或工作范围等发送相关事实改变时 MUST 保留草稿并要求核对；结果未知、网络失败或取消及切换对话后 MUST NOT 自动发送。自动重读成功后 MUST NOT 再要求用户手动刷新。

#### Scenario: 后台更新发生在准备或提交期间
- **WHEN** 主动发送被版本或预览过期明确拒绝，重读证实只有用量或标题等后台元信息变化
- **THEN** 系统 SHALL 在同一请求身份下重新准备并最多恢复一次发送，无需用户刷新或重复输入

#### Scenario: 实际来源或执行发生变化
- **WHEN** 重读发现历史正文、图片、问题、执行、参与者、工作范围、模型或权限变化，或恢复再次冲突
- **THEN** 系统 MUST 保留输入并提示已更新、需要核对后重发，MUST NOT 静默提交

#### Scenario: 送达未知或原操作失效
- **WHEN** 发送结果未知、网络失败、用户取消或切换对话
- **THEN** 系统 MUST NOT 自动重复提交；未确认送达的输入 MUST 保留

### Requirement: 问答卡片必须紧凑且展开后保持确认动作可见

等待正式问题回答时，底部 MUST 用一处简短提示表达等待状态及前往回答，保留停止、草稿及真实错误，MUST NOT 重复堆叠同义说明。问答卡片的确认动作与必要提示 SHALL 在有空间时同行、窄屏自然换行。用户展开“其他”后，当前卡片回答区末端及确认动作 MUST 在对话内可见，无需额外手动滚动；已处于记录底部时 SHALL 跟随卡片高度变化，阅读旧记录时 MUST NOT 被无关后台更新拉回底部。普通草稿 MUST NOT 被当作正式回答或自动提交。

#### Scenario: 展开其他回答
- **WHEN** 用户在位于记录末尾的正式问题选择“其他”并展开文字及媒体输入
- **THEN** 系统 MUST 在当前对话内露出回答区末端与确认动作，保留选择及已有回答，不自动发送

#### Scenario: 紧凑等待与确认
- **WHEN** 正式问题等待回答，页面有足够宽度
- **THEN** 底部 SHALL 只显示一处等待引导，卡片确认及必要说明 SHALL 同行；窄屏 MUST 允许换行且不溢出

#### Scenario: 阅读与草稿保护
- **WHEN** 用户阅读较早记录，或普通输入框已有未发送内容
- **THEN** 后台及卡片尺寸变化 MUST NOT 抢走旧记录位置，普通草稿 MUST 保留且仅卡片正式提交算作回答

### Requirement: 未结束命令与待发送必须紧凑且真实呈现

模型不再输出但仍有本轮命令未结束时，界面 MUST 突出命令尚未结束及准确未结束数量，MUST NOT 仅据模型状态显示全部已停止。该状态 SHALL 只显示一处紧凑反馈，完整命令与诊断默认收起且按需有界查看；核对、停止剩余执行和真实支持的单项停止 MUST 保留，未知项 MUST 明确待确认，旧记录缺少单停能力 MUST NOT 推定支持。待发送 MUST 使用轻量状态与有界完整正文，保留修改、取消、实际失败原因和正式交接取消后果，MUST NOT 改变自动发送准入或隐含重复发送。

#### Scenario: 长命令尚未结束
- **WHEN** 模型不再输出，本轮存在包含很长命令文本的活动工具
- **THEN** 页面 SHALL 默认只显示命令未结束摘要和必要控制，原始命令 MUST 可展开查看，不撑出内容区或铺满默认界面

#### Scenario: 混合已完成与未知命令
- **WHEN** 本轮包含已完成、运行中和状态未知的工具，部分支持单独停止
- **THEN** 未结束数 MUST 排除已完成项，未知项 MUST 明示待确认；单项停止 MUST 仅对真实支持项开放，并保持准确工具身份

#### Scenario: 待发送与失败保留
- **WHEN** 用户的新要求已保存为待发送，或排队处理实际失败
- **THEN** 系统 SHALL 紧凑展示状态与内容，保留修改、取消及具体失败原因，MUST 不提前发送或宣称上一轮已停止

### Requirement: 统一交互指引必须由服务拥有并适配全部执行方

Buildr 智能体服务（Agent Service）MUST 统一维护自主调查、专业取舍、必要提问及授权边界的指引。Codex、DSH、Qoder MUST 通过正式接入机制应用同一指引，不替换原生基础指令或写入用户全局配置。已授权范围内多个方案均可行 MUST 不单独构成要求用户选择的理由；可自行取得的信息 MUST 先调查。必要事实、授权和关键目标取舍 MUST 不由智能体编造。辅助标题与摘要 MUST 保持无工具隔离。

#### Scenario: 三家创建及恢复工作
- **WHEN** 使用任一家内置执行方创建或恢复工作上下文
- **THEN** 同一服务交互指引 MUST 生效，适配能力 MUST 如实声明，MUST NOT 仅在某一家程序中定义该产品行为

### Requirement: 问题生命周期必须独立于执行状态

统一问题契约 MUST 支持表达是否阻塞原执行，旧接入未声明时 MUST 按阻塞兼容。服务及界面 MUST 区分“仍有有效问题”和“执行正在等待”。运行观察 MUST NOT 单独删除仍有效问题；只有准确解决事件、明确待答快照或相关执行终态才结束相应可回答状态。MUST NOT 根据推荐标签或等待时长补造答复。界面 MUST 仅依据真实执行事实显示继续进行，未知 MUST 不显示为继续。

#### Scenario: 非阻塞问题与运行观察
- **WHEN** 有效非阻塞问题存在且原执行报告仍运行
- **THEN** 原问题 MUST 保持可答且执行 MUST 显示运行，不把整轮标成等待，也不因运行观察删除问题

#### Scenario: 准确结束及迟到回答
- **WHEN** 准确问题取消、已解决、明确快照移除或原执行结束，随后旧回答提交
- **THEN** 服务 MUST 结束对应卡片并拒绝旧回应，不移除其他有效问题、不记录虚构同意

### Requirement: 必要问题等待时必须支持用户明确发起讨论

用户 MUST 能在不回答必要问题的情况下明确发起“先讨论”，保留其反问及原问题。服务 MUST 复用持久待发送机制，以同一执行组合的独立上下文接续讨论并保留原轮，不以准确停止或工具结束为前提。讨论 MUST 不回应旧请求、不构成同意、不自动更换执行方或重放旧工作；普通补充及草稿 MUST 继续保持原边界。并发回答、旧问题身份变化及重复提交 MUST 按实时事实处理，不自动另起重复执行；原轮停止未知 MUST 只影响该停止，不阻塞已明确提交的新讨论。

#### Scenario: 反问并接续
- **WHEN** 用户在必要问题等待期间明确选择先讨论并提交反问
- **THEN** 系统 MUST 保存原问题与反问，保留原轮并在同一执行组合的独立上下文接续，明确原问题未回答且相关动作仍需必要输入

#### Scenario: 停止未知或并发回答
- **WHEN** 讨论提交后原停止无法确认或其他入口已正式回答
- **THEN** 系统 MUST 保留输入及准确原因，停止未知 MUST 不阻塞新讨论；已被正式回答的问题 MUST 不再按旧等待交接，MUST NOT 重复提交或重放原操作

### Requirement: 遗留执行不得阻塞用户的新指示

系统 MUST 区分当前交互和保留执行。用户发送新要求、更换执行选择时，系统 MUST 允许接续，不以旧工具退出、原问题回答或未知结果消除为前提。系统 MUST 保留旧执行归属、状态、准确观察和停止能力，由智能体（Agent）判断保留、结束和清理。系统 MUST NOT 自动强杀、推断授权或重放未知操作。资源保护和版本冲突检查 MUST 保持。

#### Scenario: 遗留命令仍活动或结果未知
- **WHEN** 用户发送新要求或更换执行选择
- **THEN** 系统 MUST 将新要求交给所选执行方，保留原执行和控制，不要求用户先手工结束旧命令

#### Scenario: 原轮等待问题而用户改变方向
- **WHEN** 用户发送普通新要求
- **THEN** 系统 MUST 接收新要求，MUST NOT 把它当作原问题的正式回答或审批；原问题及未回答事实 MUST 保留

#### Scenario: 迟到结果与准确控制
- **WHEN** 新轮开始后收到原执行结果，或人和智能体请求停止原执行
- **THEN** 系统 MUST 按准确执行身份更新或控制原工作，MUST NOT 覆盖新轮、丢失控制或重复原操作；停止未知 MUST 只影响对应动作

#### Scenario: 已保存的新要求
- **WHEN** 待发送内容先前等待旧工具或问题结束
- **THEN** 系统 MUST 沿用原提交身份投递一次，MUST NOT 继续等待旧资源退出；页面 MUST 明确实际发送状态和仍保留的工作

### Requirement: 控制资源释放后的显式继续

用户已明确要求继续原目标、准确原轮已受理且结果未知、原控制资源释放已经核验、没有待决定及该对话的在途工作、并且原参与者、模型来源、模型、档位和权限保持一致时，系统 MUST 允许用准确原轮身份手动预览并接续一次。系统 MUST 保留原轮未知结果、工具条目和原生执行引用，接续提示 MUST 要求先核对当前成果及未知命令，MUST NOT 重放原指令或工具、推定独立命令退出、宣称旧工作成功或代答问题。预览和发送 MUST 校验同一已观察版本与准确原轮；没有释放证明、存在待决定或选择变化时 MUST 拒绝此例外。普通发送和排队 MUST NOT 冒充该显式请求。具有可信系统中断来源的自动恢复 MUST 按原目标恢复契约独立判断，不以历史结果未知为整个目标的阻塞；同样 MUST 先核对现场且不得重放未知操作。

#### Scenario: 已释放但原结果未知时明确继续
- **WHEN** 用户要求恢复原对话，准确资源释放已成立，原轮仍有未知工具结果且没有其他在途工作或待决定
- **THEN** 原组合的显式继续 MUST 被接受一次，原轮和工具结果 MUST 继续保持未知并可查，接续提示 MUST 要求先核对现状

#### Scenario: 没有释放证明或存在待决定
- **WHEN** 释放未确认、原轮身份或版本变化、请求仍待答、原轮中断前有未解决决定、或者选择发生变化
- **THEN** 手动继续 MUST 被拒绝，原记录和输入 MUST 保留

#### Scenario: 禁止隐式恢复未知结果
- **WHEN** 页面刷新、后台重启、自动恢复、普通发送或排队发生
- **THEN** 系统 MUST NOT 据资源释放直接重发或续做未知操作；满足系统中断恢复契约时 MAY 自动发起先核对成果的原目标接续

### Requirement: 对话状态与历史必须按需有界读取并保全旧写入

系统 MUST 根据精简状态定位待处理及忙闲对象，MUST NOT 在每次状态查询中读取解析未命中的全部正文。详情与实时观察 MUST 按准确对话及稳定消息序号读取有界页面；未变化的观察 MUST 不重复读取历史。工具完整输入输出 MUST 保留，并可按准确条目及已观察内容版本读取。系统 MUST 保留全部原始历史、问题、执行身份及恢复引用，MUST NOT 为优化强制停止正在运行的对话。旧后台继续保存时，新的状态及消息读取 MUST 与同一已提交版本一致，不得展示过期缓存。

#### Scenario: 历史量膨胀但待处理集合不变
- **WHEN** 已完成对话的正文与数量增长而待处理对象保持不变
- **THEN** 待处理与后台忙闲查询 MUST 读取精简状态并只为命中对象取必要内容，不解析无关历史

#### Scenario: 打开与翻阅大对话
- **WHEN** 用户打开具有大量历史及工具结果的对话并向上读取
- **THEN** 系统 MUST 只读取当前页，使用稳定序号继续，不重复或遗漏历史；大工具正文 MUST 在展开时可完整读取

#### Scenario: 保留旧后台继续写入
- **WHEN** 原后台在新读取表建立前后继续保存同一对话
- **THEN** 精简状态 MUST 在同一提交更新；过期消息投射 MUST 不作为当前事实返回，重建和回退 MUST 保留原数据且不重发执行

#### Scenario: 工具内容在读取期间变化
- **WHEN** 用户展开一个工具条目而内容版本已经变化
- **THEN** 系统 MUST 明确要求重新读取当前条目，不把另一版本内容悄悄并入原快照

### Requirement: 统一对话必须准确区分主助手与原生子任务来源

统一执行条目 MUST 在原生提供可靠关系时保留父工具来源和原始角色。子任务报告 MUST NOT 被作为主助手的独立最终答复重复展示或交接；原工具详情和必要来源 MUST 保留。缺少可靠来源的旧记录 MUST NOT 根据文本相似度猜测重写。

#### Scenario: 子任务报告与主助手同时输出
- **WHEN** 原生流提供带父工具身份的子任务报告和主助手消息
- **THEN** 系统 MUST 保留二者准确来源，主线只将主助手消息作为答复，子任务结果可从父工具查看
- **AND** 子任务事件 MUST NOT 单独证明主轮已接收、结束或目标完成

### Requirement: 交错执行必须按归属合组并准确呈现当前工作

不同执行的到达顺序 MUST NOT 切碎同一可见分段的工具摘要。系统 MUST 保留用户补充消息边界、真实失败与展开选择，只对实际当前最新工具组呈现实时指示。相同组合的独立接续 MUST 明确表达继续处理新要求，MUST NOT 冒充换模型或原工作全部交接。

#### Scenario: 新旧执行记录交错
- **WHEN** 同轮两个工具之间插入另一执行的记录，且没有本轮用户补充分界
- **THEN** 两个工具 MUST 在归属本轮后合为同一组，旧组 MUST NOT 因整轮仍运行持续呈现实时指示

#### Scenario: 用户补充形成独立可见分段
- **WHEN** 同一轮工具之间有用户明确提交的补充消息
- **THEN** 补充 MUST 保持主线可见，前后工具 MUST 分段合组，不跨过该消息合并

### Requirement: 未回答问题必须静默保留准确事实

问题未回答时系统 MUST 不执行依赖该回答的操作，不推断同意。准确等待结束后系统 MUST 仅保留必要内部事实，MUST NOT 追加包含请求编号、内部状态或授权解释的技术性消息；旧系统存档 MUST 在普通对话中隐藏。明确用户回答、仍有效的问题和真实错误 MUST 保持可见。

#### Scenario: 未回答问题等待结束
- **WHEN** 原问题未被回答且准确请求或执行已结束
- **THEN** 原问题 MUST 不再可提交，系统 MUST 不补造回答，也不向普通对话追加技术存档

#### Scenario: 读取含旧存档的历史
- **WHEN** 历史包含系统生成的未回答问题存档及明确用户回答
- **THEN** 普通视图 MUST 隐藏系统存档，保留用户回答和其他真实错误，底层历史不被删除

### Requirement: 对话独占资源必须在持有工作结束后自动回收

系统 MUST 在执行及相关观察、标题、输入和模型请求结束后自动核验并回收准确所属的空闲独占资源，无需升级或关闭页面触发。历史核对产生的临时连接 MUST 服从同一回收边界。资源回收 MUST 保留持久历史和未知操作结果；有其他持有者、活动工具、待决定或释放证明不足时 MUST 保留准确资源，不中断工作。旧后台全部所属工作和资源排空后 MUST 自动退出。

#### Scenario: 正常执行自然结束
- **WHEN** 对话执行完成且全部相关辅助工作及原生资源可安全释放
- **THEN** 系统 MUST 自动关闭其独占连接并撤销对应临时模型凭据，保留原生上下文供后续准确恢复

#### Scenario: 再次核对已完成历史
- **WHEN** 已释放的历史通过准确原生连接完成核对
- **THEN** 新建观察连接 MUST 自动回收，MUST NOT 因只读核对永久占用后台

#### Scenario: 旧任务晚于新版启用结束
- **WHEN** 新版接收新任务后，旧后台最后一项工作自然结束并取得释放证明
- **THEN** 旧资源 MUST 自动回收且旧后台 MUST 自动退出，新任务及其他有意保留的独立进程 MUST 不受影响

#### Scenario: 释放与新输入交错
- **WHEN** 同一资源正在释放时出现新输入，或原生证明仍显示活动
- **THEN** 系统 MUST 在准确归属下等待释放后重新获取或保留原活动资源，MUST NOT 关闭正在使用的连接或重复执行输入

### Requirement: 同一执行组合的内部恢复必须透明

同一智能体（Agent）、账号身份、模型（Model）、档位、思考强度及权限下的内部重连或原生上下文（Native Context）重建 MUST 继续同一可见对话及原目标。系统 MUST 传递必要原始历史和当前成果来源，但 MUST NOT 仅因参与者或上下文编号变化生成用户交接事件、展示“交接内容”或要求人工确认交接。真正更换执行组合 MUST 保留既有交接及来源核对能力。已有历史交接记录 MUST 保持原样。

#### Scenario: 同组合替代失效上下文
- **WHEN** 同组合因系统故障需要新的原生上下文
- **THEN** 原目标和来源 MUST 自动送达，用户 MUST 不看到虚假的换人交接动作

#### Scenario: 真实切换模型
- **WHEN** 用户明确更换智能体、账号、模型或执行配置
- **THEN** 系统 MUST 按真实选择组织交接并保留来源，不与内部恢复混淆

### Requirement: 已释放历史执行必须与当前待处理分离

准确资源已释放且无活动工作、未知工具或待决定的历史旧轮 MUST 保持可追溯，但 MUST NOT 在当前输入区域常驻“保留原执行”折叠项或被当作仍需人工处理的执行。仍有活动、未知工具或待决定时 MUST 继续呈现准确风险与可执行动作。系统 MUST NOT 因收起或移除提示改写旧结果、删除原引用或冒充目标完成。

#### Scenario: 仅终态未知的旧轮已回收
- **WHEN** 旧控制已释放，全部工具有完成回执，且没有原问题或待决定
- **THEN** 当前对话 MUST 继续原目标，不展示无操作价值的常驻旧执行折叠项，原历史仍可核对

#### Scenario: 仍有真正未决工作
- **WHEN** 控制尚未释放、存在活动或未知工具、或需要用户决定
- **THEN** 页面 MUST 保留准确风险和必要控制，不隐藏真实问题
