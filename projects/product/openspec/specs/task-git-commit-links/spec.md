# task-git-commit-links Specification

## Purpose
定义任务与实际 Git 提交（Commit）的双向关联：提交说明记录稳定的任务编码，任务按明确代码库范围读取并展示同一提交的说明与完整哈希值（Hash），同时说明当前可达范围、局部失败和历史兼容边界，不把关联存在当作任务完成证明。

## Requirements

### Requirement: 明确任务的提交必须携带可解析的任务编码

智能体（Agent）在已授权范围内为明确任务创建 Git 提交（Commit）时 MUST 保留语义化主题，并在实际提交说明（Commit Message）的尾注（Trailer）中写入一行 `Buildr-Task: <taskId>`。任务编码 MUST 使用当前工作空间（Workspace）中存在的任务身份；无明确任务时 MUST NOT 为提交关联自动创建任务或猜测归属。

#### Scenario: 一个任务产生多次提交
- **WHEN** 同一明确任务分多次创建独立提交
- **THEN** 每条实际提交说明 MUST 包含同一 `Buildr-Task` 编码，且主题继续表达各次改动

#### Scenario: 没有明确任务
- **WHEN** 已授权 Git 工作没有匹配任务
- **THEN** 提交 MUST 继续按既有方式执行，且 MUST NOT 自动补建任务或使用最近任务编码

### Requirement: 双向关联必须由实际提交和任务读取共同确认

Buildr MUST 从实际 Git 对象解析规范尾注（Trailer），只在有一个不同的合法任务编码、该编码能解析为目标任务且读取结果返回同一真实代码库（Repository）、完整哈希值（Hash）与实际说明时确认双向关联。正文普通提及、分支名或工作目录 MUST NOT 作为任务归属证明；同值重复尾注 MUST 视为一个值，不同值 MUST 显式报告冲突。

#### Scenario: 正文只提及任务编码
- **WHEN** 提交正文包含目标任务编码，但不存在有效 `Buildr-Task` 尾注
- **THEN** 查询 MUST NOT 把它列为已确认关联

#### Scenario: 同一提交指向多个任务
- **WHEN** 提交含两个不同的 `Buildr-Task` 值
- **THEN** 查询 MUST 返回局部冲突诊断，且 MUST NOT 静默选择其中一个作为唯一归属

#### Scenario: 提交成功但任务读取失败
- **WHEN** 实际提交已经含正确任务编码，而关联查询暂时失败
- **THEN** 智能体（Agent）MUST 保留提交成功事实并说明任务侧尚未确认，且 MUST NOT 仅因该失败改写提交或任务状态

### Requirement: 关联查询必须覆盖明确范围内当前可达的本机提交

任务提交查询 MUST 只读解析任务范围中的真实代码库（Repository）和已知任务工作树（Worktree），读取本机分支、已存在的远端跟踪引用、标签及相关工作树当前 `HEAD` 可达的提交，包括未推送提交。结果 MUST 带有读取时间、实际覆盖范围、完整性说明及局部诊断。查询 MUST NOT 自动抓取远端、遍历任意目录或写入 Git 与任务状态。

#### Scenario: 本机提交尚未推送
- **WHEN** 任务工作树包含当前可达且带正确尾注的未推送提交
- **THEN** 查询 MUST 返回该提交，不以远端存在或任务完成为前置条件

#### Scenario: 同一代码库被多个服务引用
- **WHEN** 任务涉及的多个服务指向同一真实代码库且读取到同一提交
- **THEN** 查询 MUST 按代码库身份和完整哈希值（Hash）去重，并只计一次

#### Scenario: 工作空间级任务
- **WHEN** 任务没有项目、服务和变更范围，且其权威工作空间（Canonical Workspace）根自身是 Git 代码库
- **THEN** 查询 MUST 在该根代码库读取带本任务编码的可达提交，不要求先建立任务工作树（Worktree）
- **AND** 根自身不是 Git 代码库时 MUST NOT 从命令当前目录或上层代码库猜测范围

#### Scenario: 读取只完成部分范围
- **WHEN** 某个代码库不可读、读取超时或有未读取的剩余结果
- **THEN** 查询 MUST 保留已经成功读取的结果并指出未覆盖范围，且 MUST NOT 将其表述为全量结果或确定的零提交

### Requirement: 网页和命令必须呈现同一真实提交内容

命令行（CLI）和网页 MUST 使用同一只读应用结果。每条已确认提交 MUST 包含实际主题、完整说明、完整哈希值（Hash）、作者、提交时间和代码库（Repository）身份，按提交时间从新到旧展示；显示用短值 MUST 能对应和复制完整值。任务详情 MUST 在“任务收尾”后提供第五个阅读标签“提交记录”，且 MUST NOT 将该入口新增为任务工作阶段或状态。

#### Scenario: 查看并展开提交
- **WHEN** 用户从任务详情进入提交记录并展开一条提交
- **THEN** 页面 MUST 显示同一提交的完整说明和完整哈希值（Hash），并支持复制
- **AND** 原有任务状态和当前工作阶段 MUST 保持不变

#### Scenario: 成功读取没有匹配项
- **WHEN** 全部声明的范围读取成功且没有符合条件的提交
- **THEN** 页面 MUST 显示当前检查范围内无关联提交，区别于读取失败

### Requirement: 历史兼容与读取失败必须保持局部影响

Buildr MUST NOT 为补任务编码自动改写既有共享提交。修改提交或变基（Rebase）生成新身份后，查询 MUST 重新读取实际可达提交，不能把旧哈希值（Hash）冒充新身份；只读结果 MUST NOT 承诺恢复已经不可达或清理的对象。关联存在、缺失、冲突或读取失败 MUST NOT 自动改变任务完成状态、审查结论或验证结论。

#### Scenario: 历史提交没有任务尾注
- **WHEN** 旧提交不含 `Buildr-Task` 尾注
- **THEN** Buildr MUST 保留原历史，不为满足关联查询自动修改它

#### Scenario: 原提交被重写
- **WHEN** 当前可达提交的哈希值（Hash）因历史重写变化
- **THEN** 刷新结果 MUST 使用新的真实身份，已不可达旧身份 MUST NOT 继续作为当前读取结果
