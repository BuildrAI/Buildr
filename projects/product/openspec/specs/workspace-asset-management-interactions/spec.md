# workspace-asset-management-interactions Specification

## Purpose
定义工作空间中项目（Project）、服务（Service）、代码库实例（Repository Instance）和技能（Skill）的共同列表、主页及编辑交互，使用户能从相同位置发现和修改对象，并在项目创建及关系维护中连续完成关联和就地新增。

## Requirements

### Requirement: 对象列表与主页交互一致
四类对象列表 MUST 支持点击条目或名称进入主页，并提供编辑入口；主页 MUST 提供同一编辑入口。行内编辑 MUST 不触发页面导航，名称链接 MUST 支持键盘操作。

#### Scenario: 从列表编辑
- **WHEN** 用户点击服务列表中的编辑
- **THEN** 系统 MUST 打开该服务编辑抽屉并保留列表位置，不跳转主页

#### Scenario: 从主页编辑
- **WHEN** 用户打开项目、服务、代码库或技能主页并选择编辑
- **THEN** 系统 MUST 使用与列表入口一致的编辑行为、字段边界和冲突反馈

### Requirement: 项目主页维护服务关系
项目主页 MUST 展示关联服务并提供关联已有、就地新增和解除关联入口。

#### Scenario: 添加并解除服务
- **WHEN** 用户从项目主页维护服务
- **THEN** 系统 MUST 保存项目引用并更新主页；解除不删除服务及代码，也不影响其他项目

### Requirement: 创建流程支持逐级新增
创建项目 MUST 允许没有服务。服务选择列表 MUST 使用共用过滤与新增组件并提供靠左新增入口，打开服务抽屉；代码库选择 MUST 为单选，缺少对象时在服务抽屉内展开 Git 表单而非第二层抽屉。

#### Scenario: 连续新增
- **WHEN** 用户创建项目时新增服务并新增代码库
- **THEN** 系统 MUST 自动回填代码库与服务，保留项目输入，在项目提交时保存草稿关系

#### Scenario: 取消与保存失败
- **WHEN** 用户取消内层表单或提交失败
- **THEN** 系统 MUST 保留外层输入，且未提交草稿不产生真实对象登记

### Requirement: 对象状态与编辑边界真实可见
系统 MUST 区分登记成功与本地代码准备完成。技能编辑 MUST 保持既有受管内容边界，并在不允许直接编辑时说明原因及可执行的维护入口。

#### Scenario: 代码待准备
- **WHEN** 新代码库已登记而目录不存在
- **THEN** 系统 MUST 展示待准备代码，不能声称已克隆或阻止无关项目编辑

#### Scenario: 陈旧编辑
- **WHEN** 任一对象保存时版本冲突
- **THEN** 系统 MUST 提示重新核对并保留输入，不能静默覆盖

### Requirement: 同类目录采用一致的信息层级
四类目录 MUST 采用同一标题、说明、搜索、数量、可见表头、行密度和右侧操作列。差异 MUST 限于业务字段与已有编辑权限，不能依赖不同页面的独立样式猜测行为。

#### Scenario: 切换资源目录
- **WHEN** 用户依次查看项目、服务、代码库和技能列表
- **THEN** 每个列表 MUST 显示名称说明列、明确表头和一致操作位置，筛选状态在页面切换后保留

### Requirement: 阅读材料与对象导航及操作分离
项目（Project）上下文内的服务和代码库 MUST 在副屏打开并保留主屏卡片与已有文档标签；全局目录条目 MUST 复用同类副屏详情标签；当前主屏对象的文档材料 MUST 在副屏阅读，副屏对象的文档 MUST 在原位置阅读并可返回详情；长代码准备指令 MUST 在操作抽屉展示而非扩展主页。主页 MUST 优先表达职责和关联，服务的代码库信息保持紧凑摘要。

#### Scenario: 阅读服务文档
- **WHEN** 用户点击服务的 README.md 或 AGENTS.md
- **THEN** 系统 MUST 使用与项目一致的副屏，支持切换和关闭，保留主页及页面标签状态

#### Scenario: 窄屏阅读
- **WHEN** 并排空间不足
- **THEN** 副屏 MUST 使用带遮罩的覆盖式阅读区域，关闭后恢复主页面，键盘用户可关闭且减少动态效果设置有效

### Requirement: 同类对象复用副屏详情
从全局目录查看服务（Service）、代码库（Repository Instance）和技能（Skill）时，MUST 各自只有一个副屏详情标签。打开同类条目 MUST 更新该标签内容并保留主列表筛选、滚动与主标签集合；副屏内文档 MUST 在原位置阅读并可返回详情，不产生第三分屏。

#### Scenario: 连续浏览技能
- **WHEN** 用户在技能列表依次打开两个不同技能
- **THEN** 副屏 MUST 始终只有一个“技能详情”标签，展示第二个技能，主标签数量不增加

#### Scenario: 从项目查看服务与代码库
- **WHEN** 用户从项目进入服务详情，再进入关联代码库
- **THEN** 系统 MUST 保留主屏项目卡片及已有文档标签，在副屏复用同类详情，不新增主标签、不收起副屏

#### Scenario: 直接访问详情链接
- **WHEN** 用户直接访问服务、代码库或技能详情链接
- **THEN** 系统 MUST 展示对应目录及副屏详情，不能恢复旧的逐对象主标签

### Requirement: 创建编辑与对象选择一致
项目创建及四类资源编辑 MUST 使用抽屉。服务与代码库选择 MUST 共用过滤、新增、已有选项的排列；新增动作左对齐，即使没有匹配结果仍可使用。旧整页编辑和创建地址 MUST 转到对应抽屉，不形成新的主标签。

#### Scenario: 无匹配项时新增
- **WHEN** 用户过滤服务或代码库后没有结果
- **THEN** 系统 MUST 保留新增动作，创建时保留外层输入，只有外层提交才登记嵌套草稿

### Requirement: 关联解除与浏览历史可预期
关联服务行 MUST 提供可键盘访问的解除图标，触屏常显。解除 MUST 直接提交当前版本并仅修改关联。对象副屏 MUST 支持浏览器前进后退；从项目列表进入 MUST 显示项目主页。

#### Scenario: 从服务返回文档
- **WHEN** 项目打开文档后再打开关联服务，并使用浏览器返回
- **THEN** 主屏项目 MUST 保持原位，副屏恢复之前的文档阅读

#### Scenario: 一键解除关联
- **WHEN** 用户点击行尾解除图标
- **THEN** 系统 MUST 更新项目引用，保留服务和代码库，失败时显示错误

### Requirement: 桌面菜单支持折叠
桌面菜单 MUST 能折叠为图标栏和重新展开，并记住偏好。折叠后的导航 MUST 保留可访问名称及提示。

#### Scenario: 折叠菜单
- **WHEN** 用户选择折叠菜单
- **THEN** 主内容 MUST 使用释放的宽度，用户仍可访问全部导航并重新展开

### Requirement: 菜单目录不重复显示标签
菜单对应的目录与设置页 MUST 不显示主标签；项目和副屏标签 MUST 保留，目录页面状态和导航 MUST 不因隐藏标签而丢失。

#### Scenario: 切换菜单目录
- **WHEN** 用户切换项目、服务、代码库、技能目录或设置
- **THEN** 系统 MUST 通过菜单表示当前页面，不新增可见目录标签，并保留既有项目标签

### Requirement: 窄分屏保留全部业务列
列表 MUST 不因分屏宽度而移除业务列，宽度不足时 MUST 支持表格内部横向滚动，操作列保持可访问。

#### Scenario: 在服务分屏列表访问代码库
- **WHEN** 用户在打开副屏后向右滚动服务列表
- **THEN** 用户 MUST 能查看关联项目和代码库列，并点击代码库链接打开详情，页面本身不发生横向溢出

### Requirement: 菜单恢复栏目查看上下文
项目菜单 MUST 始终打开项目列表；已打开项目 MUST 由主标签定位。其他工作空间菜单 MUST 恢复该栏目在当前工作空间最近打开的页面、副屏和已有页面状态；没有历史时进入目录。显式从项目列表点击条目 MUST 仍进入项目主页，不能恢复旧详情。关闭的项目标签 MUST 不被菜单重新恢复。

#### Scenario: 切换栏目后继续查看
- **WHEN** 用户打开项目和服务副屏，切换其他栏目，再点击项目菜单
- **THEN** 系统 MUST 打开项目列表并保留原项目标签及其副屏现场，不新增主标签

#### Scenario: 目录显式进入与空间隔离
- **WHEN** 用户从项目列表点击条目或切换到另一个工作空间
- **THEN** 系统 MUST 分别显示该项目主页或新工作空间自身的栏目状态，不复用错误上下文

### Requirement: 项目关联服务直接使用共用选择入口
项目关联区 MUST 就地使用过滤、新增、已有选项的共用组件，不打开独立关联抽屉。选择已有服务 MUST 直接保存关联；新增服务 MUST 沿用创建抽屉和原子关联，取消不产生登记。

#### Scenario: 直接关联与失败反馈
- **WHEN** 用户选择一个尚未关联的服务
- **THEN** 系统 MUST 校验当前版本、保存引用并更新列表，提交中阻止重复操作；失败时显示错误，不删除其他引用

#### Scenario: 就地新增
- **WHEN** 用户在关联选择中新增服务并提交
- **THEN** 系统 MUST 同时登记该服务及项目引用，失败保留创建输入

### Requirement: 项目视角的服务详情省略反向项目区
从项目主页打开服务时，服务详情 MUST 使用当前项目上下文并省略“关联项目”区域；从全局服务目录打开时 MUST 保留完整关联信息。

#### Scenario: 同一服务在两个入口查看
- **WHEN** 用户先从项目主页、再从全局服务目录打开同一服务
- **THEN** 前者 MUST 省略关联项目区，后者 MUST 展示该区，文档、代码库和编辑能力保持不变

### Requirement: 设置页面采用共同内容布局
设置页 MUST 与资源目录采用一致内容限宽、外间距、标题层级和卡片表达，并保留设置保存、只读信息及冲突反馈。

#### Scenario: 宽窄窗口查看设置
- **WHEN** 用户在桌面或窄窗口打开设置
- **THEN** 内容 MUST 与目录页对齐，窄屏卡片单列且不产生页面横向溢出

### Requirement: 项目服务删除入口
项目（Project）和服务（Service）的列表与主页 MUST 提供移除登记入口，确认内容 MUST 显示受影响关联并说明保留代码、文件和历史任务。移除成功 MUST 刷新列表并关闭已移除对象标签，失败 MUST 保留现场与明确错误。

#### Scenario: 删除服务确认
- **WHEN** 用户选择移除一个共享服务的登记
- **THEN** 确认框 MUST 显示引用它的项目，只有确认后才提交当前版本的移除请求

### Requirement: 文章详情必须复用副屏并支持展开阅读
文章列表或关联入口打开文章 MUST 使用同类复用的副屏详情，保留来源列表查询、排序、滚动和项目主标签。副屏 MUST 提供展开阅读及恢复分屏，不新增主标签、不重新丢失阅读位置、不产生第三分屏；相关资料在当前阅读区域继续进入并可返回。直接访问文章地址 MUST 还原对应目录与详情。

#### Scenario: 连续阅读文章
- **WHEN** 用户筛选文章并连续打开两篇文章
- **THEN** 主列表状态保持，副屏只保留一个文章详情标签且显示最新选择，主标签数量不增加

#### Scenario: 展开与恢复
- **WHEN** 用户展开当前文章并恢复分屏
- **THEN** 原列表和阅读位置 MUST 保留，文章链接、资源与编辑入口仍可用

### Requirement: 文章编辑必须在适配抽屉中完成
从列表、阅读页面或旧编辑地址进入编辑 MUST 打开同一文章编辑抽屉，桌面保证正文宽度，窄屏全宽，保存操作保持可访问。保存 MUST 使用已观察版本并在成功后更新原阅读现场；未保存关闭 MUST 提醒，保存失败和版本冲突 MUST 保留输入与已有资源操作能力。编辑不得新增主标签。

#### Scenario: 编辑后继续阅读
- **WHEN** 用户在分屏编辑文章并保存
- **THEN** 抽屉 MUST 关闭，原文章显示最新内容，主列表筛选和阅读位置保持

#### Scenario: 未保存与冲突
- **WHEN** 用户有未保存内容时关闭抽屉，或保存遇到其他入口的新版本
- **THEN** 系统 MUST 分别允许继续编辑或显式放弃，以及保留输入并查看最新稿件，不静默覆盖

### Requirement: 项目主页必须区分主要工作与资料入口
项目主页 MUST 使用紧凑的项目身份与说明，以查看项目工作为主要入口，知识与文章以同组紧凑入口展示，知识在前，服务关联和项目资料各有清晰分组。删除 MUST 放在更多操作并保留原确认；显示数量 MUST 对应实际项目内容。窄容器 MUST 自动转为单列且不产生页面横向溢出。

#### Scenario: 查看项目主页
- **WHEN** 用户在宽屏或窄屏打开项目
- **THEN** 用户 MUST 能识别查看工作、文章、知识、服务和项目资料入口，关联编辑和资料阅读保持可用且数量无矛盾

服务关联条目 MUST 保留足够内边距及名称、说明、导航与解除关联的独立位置；窄宽度不能裁切名称或挤压操作。服务代码库摘要 MUST 按字段对齐名称、目录、分支、状态与检查操作，长路径和远端地址可以换行，不能混成难以扫描的连续段落。

#### Scenario: 阅读关联服务与代码库
- **WHEN** 用户在项目主页查看关联服务并在分屏打开服务代码库摘要
- **THEN** 各条目的图标、文本和操作 MUST 对齐且无裁切，长分支或路径 MUST 在对应字段内换行，不推出容器边界

### Requirement: 网页必须支持登记已有项目
新增项目入口 MUST 区分创建新项目与登记已有项目。登记模式 MUST 展示工作空间 projects/ 下未登记的可用目录，允许选择目录、编辑名称与说明并明确选择已有服务；保存 MUST 只增加登记及所选关联，不覆盖、补写、移动已有目录内容。系统 MUST 校验清单当前版本、目录身份、来源合法性与服务引用，不能把重复登记或已变化目录静默保存为新项目。

#### Scenario: 移除后重新登记
- **WHEN** 用户移除项目登记后，在登记已有项目中选择保留目录并保存
- **THEN** 项目重新出现在目录中，原文件内容保持不变，服务关联来自本次明确选择
- **AND** 页面不宣称自动恢复原项目身份和历史关联

#### Scenario: 登记前目录或清单变化
- **WHEN** 用户选择目录后，该目录被替换、移走或登记清单发生变化
- **THEN** 系统拒绝陈旧写入并保留表单，要求重新核对；原目录与登记不受覆盖

### Requirement: 页面级刷新必须表达一致读取动作
项目、服务、代码库、技能、知识、任务、工作概览、动态和文章目录的页面级重新读取 MUST 使用一致刷新图标、提示、可访问名称及加载反馈；文字操作行 MUST 使用图标加文字并保持同排高度一致；紧凑工具区可使用纯图标。读取中 MUST 阻止重复提交。错误重试与有明确局部作用范围的动作 MUST 保持其原有语义。

#### Scenario: 知识页面刷新
- **WHEN** 用户在知识目录或详情点击刷新
- **THEN** 按钮显示加载状态，完成后恢复，重新读取当前范围内容，不执行知识生成或确认
