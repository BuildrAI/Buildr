# workspace-asset-management-interactions Specification

## Purpose
定义工作空间中项目（Project）、服务（Service）、代码库实例（Repository Instance）和技能（Skill）的共同列表、主页及编辑交互，使用户能从相同位置发现和修改对象，并在项目创建及关系维护中连续完成关联和就地新增。

## Requirements

### Requirement: 对象列表与主页交互一致
四类对象列表 MUST 支持点击条目或名称进入主页，并提供编辑入口；主页 MUST 提供同一编辑入口。行内编辑 MUST 不触发页面导航，名称链接 MUST 支持键盘操作。

#### Scenario: 从列表编辑
- **WHEN** 用户点击服务列表中的编辑
- **THEN** 系统 MUST 打开该服务编辑抽屉并保留列表位置，不跳转主页

#### Scenario: 从主页编辑
- **WHEN** 用户打开项目、服务、代码库或技能主页并选择编辑
- **THEN** 系统 MUST 使用与列表入口一致的编辑行为、字段边界和冲突反馈

### Requirement: 项目主页维护服务关系
项目主页 MUST 展示关联服务并提供关联已有、就地新增和解除关联入口。

#### Scenario: 添加并解除服务
- **WHEN** 用户从项目主页维护服务
- **THEN** 系统 MUST 保存项目引用并更新主页；解除不删除服务及代码，也不影响其他项目

### Requirement: 创建流程支持逐级新增
创建项目 MUST 允许没有服务。服务选择列表 MUST 使用共用过滤与新增组件并提供靠左新增入口，打开服务抽屉；代码库选择 MUST 为单选，缺少对象时在服务抽屉内展开 Git 表单而非第二层抽屉。

#### Scenario: 连续新增
- **WHEN** 用户创建项目时新增服务并新增代码库
- **THEN** 系统 MUST 自动回填代码库与服务，保留项目输入，在项目提交时保存草稿关系

#### Scenario: 取消与保存失败
- **WHEN** 用户取消内层表单或提交失败
- **THEN** 系统 MUST 保留外层输入，且未提交草稿不产生真实对象登记

### Requirement: 对象状态与编辑边界真实可见
系统 MUST 区分登记成功与本地代码准备完成。技能编辑 MUST 保持既有受管内容边界，并在不允许直接编辑时说明原因及可执行的维护入口。

#### Scenario: 代码待准备
- **WHEN** 新代码库已登记而目录不存在
- **THEN** 系统 MUST 展示待准备代码，不能声称已克隆或阻止无关项目编辑

#### Scenario: 陈旧编辑
- **WHEN** 任一对象保存时版本冲突
- **THEN** 系统 MUST 提示重新核对并保留输入，不能静默覆盖

### Requirement: 同类目录采用一致的信息层级
四类目录 MUST 采用同一标题、说明、搜索、数量、可见表头、行密度和右侧操作列。差异 MUST 限于业务字段与已有编辑权限，不能依赖不同页面的独立样式猜测行为。

#### Scenario: 切换资源目录
- **WHEN** 用户依次查看项目、服务、代码库和技能列表
- **THEN** 每个列表 MUST 显示名称说明列、明确表头和一致操作位置，筛选状态在页面切换后保留

### Requirement: 阅读材料与对象导航及操作分离
项目（Project）上下文内的服务和代码库 MUST 在副屏打开并保留主屏卡片与已有文档标签；全局目录条目 MUST 复用同类副屏详情标签；当前主屏对象的文档材料 MUST 在副屏阅读，副屏对象的文档 MUST 在原位置阅读并可返回详情；长代码准备指令 MUST 在操作抽屉展示而非扩展主页。主页 MUST 优先表达职责和关联，服务的代码库信息保持紧凑摘要。

#### Scenario: 阅读服务文档
- **WHEN** 用户点击服务的 README.md 或 AGENTS.md
- **THEN** 系统 MUST 使用与项目一致的副屏，支持切换和关闭，保留主页及页面标签状态

#### Scenario: 窄屏阅读
- **WHEN** 并排空间不足
- **THEN** 副屏 MUST 使用带遮罩的覆盖式阅读区域，关闭后恢复主页面，键盘用户可关闭且减少动态效果设置有效

### Requirement: 同类对象复用副屏详情
从全局目录查看服务（Service）、代码库（Repository Instance）和技能（Skill）时，MUST 各自只有一个副屏详情标签。打开同类条目 MUST 更新该标签内容并保留主列表筛选、滚动与主标签集合；副屏内文档 MUST 在原位置阅读并可返回详情，不产生第三分屏。

#### Scenario: 连续浏览技能
- **WHEN** 用户在技能列表依次打开两个不同技能
- **THEN** 副屏 MUST 始终只有一个“技能详情”标签，展示第二个技能，主标签数量不增加

#### Scenario: 从项目查看服务与代码库
- **WHEN** 用户从项目进入服务详情，再进入关联代码库
- **THEN** 系统 MUST 保留主屏项目卡片及已有文档标签，在副屏复用同类详情，不新增主标签、不收起副屏

#### Scenario: 直接访问详情链接
- **WHEN** 用户直接访问服务、代码库或技能详情链接
- **THEN** 系统 MUST 展示对应目录及副屏详情，不能恢复旧的逐对象主标签

### Requirement: 创建编辑与对象选择一致
项目创建及四类资源编辑 MUST 使用抽屉。服务与代码库选择 MUST 共用过滤、新增、已有选项的排列；新增动作左对齐，即使没有匹配结果仍可使用。旧整页编辑和创建地址 MUST 转到对应抽屉，不形成新的主标签。

#### Scenario: 无匹配项时新增
- **WHEN** 用户过滤服务或代码库后没有结果
- **THEN** 系统 MUST 保留新增动作，创建时保留外层输入，只有外层提交才登记嵌套草稿

### Requirement: 关联解除与浏览历史可预期
关联服务行 MUST 提供可键盘访问的解除图标，触屏常显。解除 MUST 直接提交当前版本并仅修改关联。对象副屏 MUST 支持浏览器前进后退；从项目列表进入 MUST 显示项目主页。

#### Scenario: 从服务返回文档
- **WHEN** 项目打开文档后再打开关联服务，并使用浏览器返回
- **THEN** 主屏项目 MUST 保持原位，副屏恢复之前的文档阅读

#### Scenario: 一键解除关联
- **WHEN** 用户点击行尾解除图标
- **THEN** 系统 MUST 更新项目引用，保留服务和代码库，失败时显示错误

### Requirement: 桌面菜单支持折叠
桌面菜单 MUST 能折叠为图标栏和重新展开，并记住偏好。折叠后的导航 MUST 保留可访问名称及提示。

#### Scenario: 折叠菜单
- **WHEN** 用户选择折叠菜单
- **THEN** 主内容 MUST 使用释放的宽度，用户仍可访问全部导航并重新展开

### Requirement: 菜单目录不重复显示标签
菜单对应的目录与设置页 MUST 不显示主标签；项目和副屏标签 MUST 保留，目录页面状态和导航 MUST 不因隐藏标签而丢失。

#### Scenario: 切换菜单目录
- **WHEN** 用户切换项目、服务、代码库、技能目录或设置
- **THEN** 系统 MUST 通过菜单表示当前页面，不新增可见目录标签，并保留既有项目标签

### Requirement: 窄分屏保留全部业务列
列表 MUST 不因分屏宽度而移除业务列，宽度不足时 MUST 支持表格内部横向滚动，操作列保持可访问。

#### Scenario: 在服务分屏列表访问代码库
- **WHEN** 用户在打开副屏后向右滚动服务列表
- **THEN** 用户 MUST 能查看关联项目和代码库列，并点击代码库链接打开详情，页面本身不发生横向溢出
