## Why

工作空间克隆后、部分已登记代码库尚未拉到本机时，同一不可读事实被重复表达：登记诊断与工作树读取失败各产生一条「本机目录或 Git 身份当前不可读取」，文件监听继续对不存在目录重试并追加「暂不可监听」诊断，多条提示拼成长文本。用户分不清原因，页面被刷屏。

## What Changes

- 同一代码库的不可读取原因只登记一次，保留实例与真实原因，区分「登记目录不存在」与「目录存在但 Git 身份不可读取」。
- 目录不可读的代码库不再分配文件监听与恢复重试，不产生监听诊断；既有低频补偿观察保留，目录补齐后的下一次核对自动恢复正常监听。
- 多个代码库产生相同监听诊断时按来源数量聚合表达；页面诊断按一条一条列出并可展开，不再拼接为整段文本。

无破坏性变更（Breaking Change）；接口字段不变，仅调整诊断内容与前端呈现。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `code-source-control`：收紧不可读来源的诊断唯一性、监听分配与紧凑呈现语义。

## Impact

涉及后端目录读取（source-control-application）、共享观察（source-control-observations）与前端源代码管理、资源管理器提醒组件。无存储迁移、无新增接口参数。
