## 取舍

- **诊断唯一性放在读取结果合并处，而非只在前端去重。** 目录清单诊断与工作树枚举失败来自两个不同层次，同一库可能因不同原因叠加其他诊断；只在响应合并阶段按「同一代码库 + 同一诊断码」去重，保留原因不同的其余诊断，避免误删独立事实。
- **不可读来源跳过监听而非降级重试。** 目录不存在或 Git 身份不可读时，文件监听必然失败且会持续上报；直接不分配监听并清空旧重试标记，让既有低频补偿负责在目录补齐后重新观察。代价是补齐目录后到下一次低频核对之间不自动发现变化，可由手动刷新即时弥补，与现状的自动失效监听等价但更安静。
- **前端按条列出并支持展开/收起。** 保留逐条诊断事实与来源名称；默认只在多条时折叠为「N 条」计数并支持原位展开，符合「真实诊断可原位展开具体原因」的既有约定。
- **不新增克隆动作。** 是否克隆属于用户授权范围；诊断只提示真实原因，不代发起外部副作用。

## 兼容与风险

- `code_repository_unavailable` 等诊断码与接口结构不变，仅文案区分目录不存在与 Git 身份不可读；依赖诊断码的测试与筛选不受影响。
- 跳过监听只作用于「本次目录读取已确认不可读」的来源；可读但部分目录监听失败的既有诊断与低频补偿保持不变。
- 已有低频轮询仍会读到补齐后的目录，届时按新指纹重建监听，无需迁移。
