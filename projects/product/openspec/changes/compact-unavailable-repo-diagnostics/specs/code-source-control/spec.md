## MODIFIED Requirements

### Requirement: 全部代码库真实清单

源代码管理的缺省目录 MUST 展示当前工作空间全部已登记代码库实例，每个稳定身份只列一次，不按服务数量或远端地址归并。清单 MUST 表达已观察目录、当前分支或游离提交、按路径去重的未提交文件数、可得的本机上游领先／落后数、读取时间及局部诊断；未知数量 MUST NOT 表达为零或“已同步”。普通入口 MUST NOT 自动限定任务范围。同一代码库（Repository）因同一原因不可读取时 MUST 只登记一条局部诊断；登记目录不存在与目录存在但 Git 身份不可读取 MUST 分别表达真实原因，不合并为歧义文案。多个代码库（Repository）因同一监听原因产生诊断时 MUST 聚合为一条带数量的提示，不逐条重复同一文本。

每个代码库 MUST 展示Git实际登记的主目录及全部关联工作树（Worktree），分别表达真实分支、目录、分层变更和观察版本，不因没有Buildr任务登记而遗漏。工作树计数 MUST 在本来源内按路径去重，代码库汇总 MUST 保留不同工作树的同名路径。代码库、工作树和比较层 MUST 可折叠展开，折叠 MUST NOT 清除仍有效的文件选择或已打开正文。

代码库（Repository）行 MUST 同时代表其主工作树（Main Worktree），选择该行即选择该真实来源，不再重复显示主工作树（Main Worktree）子行；行前图标 MUST 独立控制关联工作树（Worktree）的折叠展开。整个代码库（Repository）目录区域的头部 MUST 支持折叠展开。页面 MUST 使用一个当前具体来源同步控制未提交变更（Uncommitted Changes）和提交历史（Commit History），两种模式 MUST NOT 再提供独立的代码库（Repository）或工作树（Worktree）过滤入口；提交历史（Commit History）可独立指定本地或远程分支（Branch）及作者（Author），只改变读取范围。目录清单仍展示全部已登记实例和可发现来源，任务（Task）预选不得隐藏无关来源。

每个来源行右侧 MUST 在符合来源名称优先及逐级收起规则的可用空间内紧凑组合远程状态与未提交文件状态，只常驻有意义的非零数量；收起时完整状态和原有动作 MUST 仍可按需查看及使用。上游（Upstream）数量已知且存在差异时 MUST 分别用向上箭头及数量表达未推送提交（Commit）、向下箭头及数量表达本机远程跟踪引用中尚未同步的提交（Commit）；零数量 MUST NOT 占用常驻空间。没有上游（Upstream）跟踪时 MUST 显示明确未跟踪标识，数量不可确定或不可读取时 MUST 分别表达未知或不可读取，MUST NOT 表达为干净。文件数量大于零时 MUST 显示实心文件标识及去重数量，单方面确认无差异时 MAY 省略对应标识；两方面均已确认无差异时 MUST 合并为一个可展开的干净标记。非零上下箭头及数量 MUST 提供同步（Sync）快捷按钮，鼠标点击或键盘聚焦后按回车 MUST 发起该具体工作树（Worktree）的显式同步（Sync）；悬停及可访问名称 MUST 说明同步（Sync）作用与目标，执行中 MUST 防止重复请求。文件状态与干净标记 MUST 保留独立详情入口，鼠标点击或键盘聚焦后按回车 MUST 可查看远程与文件两方面的完整事实（包括零值）；未知及未跟踪状态 MUST 保留真实说明，不以箭头同步（Sync）冒充可用操作。远程状态本身 MUST 表达本机已观察引用，普通查看或刷新 MUST NOT 隐式抓取远程。

来源列表 MUST 优先完整展示代码库（Repository）或工作树（Worktree）名称及树层级，其次才展示紧随其后的完整当前分支（Branch）名称。按该行实际可用宽度及内容，名称和分支（Branch）组合放不下时 MUST 先以剩余空间渐进省略分支（Branch），并以省略号明确截断；仅在不足以辨认的最小宽度时才隐藏整段分支（Branch），仍不足时 MUST 收起后部状态及任务（Task）快捷图标，只有以上内容均已收起且仍不足时才允许省略来源名称；MUST NOT 提前压缩或省略来源名称来保留分支（Branch）或快捷图标，也 MUST NOT 以没有省略标识的残缺分支（Branch）碎片占位。分支（Branch）文字可见时点击 MUST 打开该具体工作树（Worktree）的既有分支（Branch）管理浮层（Popover），提供检出（Checkout）及切换；隐藏时完整分支（Branch）及该入口仍 MUST 可按需查看和使用。各来源行最右侧 MUST 提供固定宽度、父子来源共用对齐边界的三个点操作菜单（Menu）入口。游离提交（Detached HEAD）使用明确提交（Commit）标识；实际分支（Branch）或完整提交（Commit）标识 MUST 保留在现有按需信息层和阅读标题中。状态与任务（Task）入口 MUST 按实际信息自然占位，没有任务时 MUST NOT 保留空槽；图标尺寸 MUST 一致，远程状态与任务（Task）标识 MUST 明显区分。完整路径 MUST 按需在可移入、选择和复制的悬停层（Hover Card）显示，MUST NOT 固定展开占用来源目录高度。下方未提交变更（Uncommitted Changes）及提交历史（Commit History） MUST NOT 再重复显示代码库（Repository）及分支（Branch）来源栏，当前来源仍 MUST 能由选中行或阅读标题核对。

目录父来源 MUST 使用可辨认的代码库（Repository）图标，折叠展开状态 MUST 可区分；子工作树（Worktree）的图标及名称 MUST 以一致缩进表达父子层级。主来源与子来源的末尾操作入口 MUST 共用右侧对齐边界，MUST NOT 随名称缩进而错位；状态与任务（Task）入口 MUST 紧凑相邻，MUST NOT 为其他行的大数量或空任务预留固定列。来源名称 MUST 在所属层级尽量利用剩余宽度，并按上述顺序收起其他内容；状态与任务（Task）事实及原有快捷能力 MUST 继续由该来源的三个点菜单（Menu）和按需信息表达，MUST NOT 因收起而被解释为零值、无关联或不可用。目录信息层 MUST 以准确任务（Task）标题或真实未关联／未确认状态为首行，第二行 MUST 统一表达“代码库名称 · 工作树 · 工作树名称”，尚未读取的身份 MUST 明示。

#### Scenario: 多个服务引用一个实例
- **WHEN** 多个服务引用相同代码库实例
- **THEN** 清单 MUST 只展示该实例一次，保留其实际身份和目录

#### Scenario: 单库不可读取
- **WHEN** 登记中的一个目录缺失、身份变化或Git状态暂不可读取
- **THEN** 清单 MUST 保留该实例及原因，其他库已读取内容仍可查看，不把错误表达为干净目录
- **AND** 同一原因在该实例上 MUST 只呈现一次，不重复登记读取清单与工作树枚举两条同义诊断

#### Scenario: 多个代码库尚未克隆
- **WHEN** 工作空间已克隆但其中多个已登记代码库目录不存在
- **THEN** 每个代码库各表达一条不可读原因；相同的监听类诊断 MUST 聚合为一条说明受影响数量，不逐库重复同一文本

#### Scenario: 同库多个工作树
- **WHEN** 同一登记代码库具有主目录及多个Git关联工作树，包括未登记为Buildr任务的来源
- **THEN** 清单 MUST 在同一代码库下列出全部来源，各自展示实际分支和分层变更
- **AND** 一个工作树不可读取 MUST 只影响该来源，其他来源的变更仍可查看

#### Scenario: 折叠后继续阅读
- **WHEN** 用户打开文件后折叠代码库、工作树或暂存／未暂存分组，再展开或刷新
- **THEN** 系统 MUST 保留仍有效的选择、已打开正文及分组状态，不因折叠改读其他来源

#### Scenario: 跨代码库工作树过滤
- **WHEN** 两个登记代码库（Repository）具有同名工作树（Worktree），用户选择其中一个来源
- **THEN** 未提交变更（Uncommitted Changes）及提交历史（Commit History） MUST 只读取该代码库（Repository）与工作树（Worktree）身份对应的内容
- **AND** 相同显示名称 MUST NOT 聚合阅读范围、替代具体来源标识或形成任务（Task）关联

#### Scenario: 代码库行选择主工作树
- **WHEN** 用户选择代码库（Repository）行，再操作该行前方的折叠图标
- **THEN** 两种阅读模式 MUST 继续使用该主工作树（Main Worktree），图标操作 MUST 只折叠或展开子来源
- **AND** 目录 MUST 没有重复的主工作树（Main Worktree）子行，折叠 MUST 保留有效文件或提交（Commit）阅读

#### Scenario: 未跟踪和未知状态分别表达
- **WHEN** 一个来源没有上游（Upstream）跟踪，另一个来源已有跟踪但提交（Commit）数量不可读取
- **THEN** 两者 MUST 分别显示未跟踪与未知状态，MUST NOT 显示零数量或无差异图标
- **AND** 一个来源的状态失败 MUST NOT 阻止其他来源的数量和阅读

#### Scenario: 两组无差异状态
- **WHEN** 所选来源上游（Upstream）领先与落后数量均为零且未提交文件数量为零
- **THEN** 来源行 MUST 合并为一个可展开的干净标记，完整详情 MUST 分别说明本机与远程没有提交（Commit）差异以及没有未提交文件

#### Scenario: 来源切换统一两种阅读模式
- **WHEN** 用户在任一模式选择另一工作树（Worktree），再切换到另一模式
- **THEN** 两种模式 MUST 都只读取新来源，旧来源的迟到响应 MUST NOT 覆盖当前内容
- **AND** 页面 MUST 明确所选分支（Branch）或游离提交（Detached HEAD），失效来源 MUST 显示局部错误，不静默读取另一个来源

#### Scenario: 来源摘要与按需完整路径
- **WHEN** 用户查看来源目录并悬停来源名称，再移入路径信息层
- **THEN** 来源名称及可完整显示时紧随其后的当前分支（Branch）名称 MUST 在名称区域共同使用剩余身份空间且不保留行末分支（Branch）列，三个点操作入口 MUST 等宽靠右；状态与任务（Task）按实际信息紧凑占位且图标可区分，信息层 MUST 显示真实分支（Branch）或完整提交（Commit）标识并支持复制
- **AND** 完整路径 MUST 可选择和点击复制，下方模式内容 MUST 不重复来源栏，悬停及复制 MUST 不改变所选来源或固定文件阅读
- **AND** 键盘聚焦来源行 MUST 能查看路径；点击来源行 MUST 保留选择动作并立即关闭路径信息层，同次指针停留及延迟悬停 MUST NOT 重新打开并遮挡其他来源或模式操作；离开后再次悬停或键盘重新聚焦 MUST 可以查看，MUST NOT 要求先点击空白；移入信息层及聚焦复制操作 MUST 保持可操作
- **AND** 仅悬停打开而尚未点击时，路径信息层 MUST 位于来源列表右边界之外，用户沿同一文字列向上或向下移动并选择相邻行 MUST 不被遮挡；正常宽度及300px右侧阅读区 MUST 同样成立，信息层 MUST 按实际可用宽度收窄，并跟随尺寸及滚动变化保持此边界

#### Scenario: 树状层级和状态列
- **WHEN** 同一代码库（Repository）展开多个关联工作树（Worktree），包括长名称和窄分屏
- **THEN** 父来源 MUST 使用代码库（Repository）图标，子工作树（Worktree）图标和名称 MUST 向右缩进，可完整显示的当前分支（Branch）名称 MUST 紧随各自来源名称，三个点操作入口 MUST 与父来源等宽并对齐右沿
- **AND** 状态与任务（Task）MUST 自然紧凑占位，选择、折叠和按需完整路径 MUST 保持原行为，MUST NOT 以整行缩进破坏末尾操作入口对齐或使分支（Branch）名称遮挡图标

#### Scenario: 远程箭头同步与文件详情独立
- **WHEN** 来源行同时存在非零上下箭头及未提交文件数量，用户依次悬停并点击两个入口
- **THEN** 箭头及数量 MUST 提供带目标说明的同步（Sync）快捷操作，文件入口 MUST 只打开完整状态详情，MUST NOT 触发同步（Sync）
- **AND** 键盘 MUST 能分别访问两个入口，执行等待中 MUST 防止重复同步（Sync）；没有差异的干净标记 MUST 继续查看详情，三个点 MUST 仍能发现同步（Sync）入口

#### Scenario: 实际宽度下名称优先逐级收起
- **WHEN** 同栏内存在不同长度的代码库（Repository）或工作树（Worktree）名称，用户逐渐缩窄再恢复来源栏
- **THEN** 每行 MUST 按自身实际空间先渐进省略分支（Branch）并显示省略号，低于可辨认下限后才隐藏整段分支（Branch）、再隐藏后部快捷图标，只有这些内容均收起后仍不足才省略来源名称；行末三个点菜单（Menu） MUST 始终可见可操作
- **AND** 宽度恢复时 MUST 恢复适用内容，完整名称和分支（Branch） MUST 仍按需可查，MUST NOT 将一个长名称触发的密度变化错误施加于同栏其他可完整显示的行

#### Scenario: 收起快捷入口仍可使用同一来源能力
- **WHEN** 当前分支（Branch）或状态及任务（Task）快捷图标已被收起，用户打开该来源三个点菜单（Menu）
- **THEN** 菜单（Menu） MUST 提供原有检出（Checkout）／切换分支（Branch）、打开已核实关联任务（Task）、状态详情、同步（Sync）及获取远程（Fetch）等适用能力，并按原有准确身份、等待和不可用边界执行
- **AND** 鼠标及键盘 MUST 均可访问；隐藏不得生成未经核实的任务（Task）关联或丢失动作，分支（Branch）切换的已确认事实 MUST 立即进入该来源及按需信息，恢复文字展示时 MUST 显示实际新分支（Branch）

### Requirement: 文件变化驱动共享自动观察

本机应用 MUST 在当前工作空间（Workspace）被使用期间持续感知已登记来源的文件及 Git 元数据变化，包括外部编辑、原子保存、暂存、提交及分支（Branch）变化。系统 MUST 合并连续变化并限制最大等待，同一来源读取期间的新变化 MUST 至少触发一次后续核对且不得无限取消在途读取，按受影响代码库（Repository）局部重新核对真实状态；多个页面 MUST 共享观察，MUST NOT 为导航或每次文件保存重复扫描全部来源。无实际内容变化的自动观察 MUST NOT 反复失效历史、正文或提交上下文。恢复前台、重新进入或观察连接恢复 MUST 补充核对，监听失败或漏事件 MUST 有低频补偿及可辨认诊断。登记目录不可读取或 Git 身份未能确认的代码库（Repository） MUST NOT 分配文件监听或上报监听诊断；其低频补偿核对 MUST 继续，目录补齐并被后续观察确认后 MUST 自动恢复监听。观察 MUST 不获取远程或执行 Git 写入。

#### Scenario: 外部编辑与多库隔离
- **WHEN** 用户停在资源管理器或其他页面，智能体（Agent）连续修改一个代码库（Repository）的文件
- **THEN** 合并变化后自动更新该来源，其他来源不因每次保存被重读，导航提示与文件标记反映相同观察

#### Scenario: 已修改文件再次保存与 Git 操作
- **WHEN** 已有改动的文件再次保存，或外部工具执行暂存、提交、切换分支（Branch）
- **THEN** 即使文件数量不变，相关内容及状态仍自动更新

#### Scenario: 已跟踪目录内的本机忽略数据变化
- **WHEN** 某目录包含已跟踪资产，而其被忽略的本机数据子目录产生连续临时文件变化
- **THEN** 被忽略数据不触发重复状态核对，同目录内已跟踪资产的真实变化仍被感知

#### Scenario: 恢复连接及局部失败
- **WHEN** 页面休眠后恢复、服务重连或一个来源不可读
- **THEN** 系统补查当前事实，失败来源保留最后结果并说明待更新，其他来源继续更新，未知不可表示为干净

#### Scenario: 未克隆目录恢复
- **WHEN** 一个登记目录此前不可读取，用户在 Buildr 之外补齐该目录或其 Git 身份
- **THEN** 下一次低频或手动核对读取到真实来源后 MUST 恢复文件监听，不再保留旧的监听诊断
