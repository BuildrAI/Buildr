## MODIFIED Requirements

### Requirement: 全部代码库真实清单

源代码管理的缺省目录 MUST 展示当前工作空间全部已登记代码库实例，每个稳定身份只列一次，不按服务数量或远端地址归并。清单 MUST 表达已观察目录、当前分支或游离提交、按路径去重的未提交文件数、可得的本机上游领先／落后数、读取时间及局部诊断；未知数量 MUST NOT 表达为零或“已同步”。普通入口 MUST NOT 自动限定任务范围。同一代码库（Repository）因同一原因不可读取时 MUST 只登记一条局部诊断；登记目录不存在与目录存在但 Git 身份不可读取 MUST 分别表达真实原因，不合并为歧义文案。多个代码库（Repository）因同一监听原因产生诊断时 MUST 聚合为一条带数量的提示，不逐条重复同一文本。

#### Scenario: 多个服务引用一个实例
- **WHEN** 多个服务引用相同代码库实例
- **THEN** 清单 MUST 只展示该实例一次，保留其实际身份和目录

#### Scenario: 单库不可读取
- **WHEN** 登记中的一个目录缺失、身份变化或Git状态暂不可读取
- **THEN** 清单 MUST 保留该实例及原因，其他库已读取内容仍可查看，不把错误表达为干净目录
- **AND** 同一原因在该实例上 MUST 只呈现一次，不重复登记读取清单与工作树枚举两条同义诊断

#### Scenario: 多个代码库尚未克隆
- **WHEN** 工作空间已克隆但其中多个已登记代码库目录不存在
- **THEN** 每个代码库各表达一条不可读原因；相同的监听类诊断 MUST 聚合为一条说明受影响数量，不逐库重复同一文本

#### Scenario: 同库多个工作树
- **WHEN** 同一登记代码库具有主目录及多个Git关联工作树，包括未登记为Buildr任务的来源
- **THEN** 清单 MUST 在同一代码库下列出全部来源，各自展示实际分支和分层变更
- **AND** 一个工作树不可读取 MUST 只影响该来源，其他来源的变更仍可查看

### Requirement: 文件变化驱动共享自动观察

本机应用 MUST 在当前工作空间（Workspace）被使用期间持续感知已登记来源的文件及 Git 元数据变化，包括外部编辑、原子保存、暂存、提交及分支（Branch）变化。系统 MUST 合并连续变化并限制最大等待，同一来源读取期间的新变化 MUST 至少触发一次后续核对且不得无限取消在途读取，按受影响代码库（Repository）局部重新核对真实状态；多个页面 MUST 共享观察，MUST NOT 为导航或每次文件保存重复扫描全部来源。无实际内容变化的自动观察 MUST NOT 反复失效历史、正文或提交上下文。恢复前台、重新进入或观察连接恢复 MUST 补充核对，监听失败或漏事件 MUST 有低频补偿及可辨认诊断。登记目录不可读取或 Git 身份未能确认的代码库（Repository） MUST NOT 分配文件监听或上报监听诊断；其低频补偿核对 MUST 继续，目录补齐并被后续观察确认后 MUST 自动恢复监听。观察 MUST 不获取远程或执行 Git 写入。

#### Scenario: 外部编辑与多库隔离
- **WHEN** 用户停在资源管理器或其他页面，智能体（Agent）连续修改一个代码库（Repository）的文件
- **THEN** 合并变化后自动更新该来源，其他来源不因每次保存被重读，导航提示与文件标记反映相同观察

#### Scenario: 已修改文件再次保存与 Git 操作
- **WHEN** 已有改动的文件再次保存，或外部工具执行暂存、提交、切换分支（Branch）
- **THEN** 即使文件数量不变，相关内容及状态仍自动更新

#### Scenario: 已跟踪目录内的本机忽略数据变化
- **WHEN** 某目录包含已跟踪资产，而其被忽略的本机数据子目录产生连续临时文件变化
- **THEN** 被忽略数据不触发重复状态核对，同目录内已跟踪资产的真实变化仍被感知

#### Scenario: 恢复连接及局部失败
- **WHEN** 页面休眠后恢复、服务重连或一个来源不可读
- **THEN** 系统补查当前事实，失败来源保留最后结果并说明待更新，其他来源继续更新，未知不可表示为干净

#### Scenario: 未克隆目录恢复
- **WHEN** 一个登记目录此前不可读取，用户在 Buildr 之外补齐该目录或其 Git 身份
- **THEN** 下一次低频或手动核对读取到真实来源后 MUST 恢复文件监听，不再保留旧的监听诊断
