## MODIFIED Requirements

### Requirement: 临时故障必须有界自动重试

当前宿主存活期间，系统 MUST 自动重试可确认没有发送工作输入的临时连接故障；模型明确报告繁忙或临时服务故障时，只有准确原执行结束、相关工具均已结束且无待决定时才可自动接续。针对同一用户请求的临时故障重试 MUST 最多额外尝试三次，采用逐步延长的等待，显示原因及次数并允许用户停止。系统 MUST 保留原输入、来源、模型、权限与历史失败，接续 MUST 标为系统消息并要求核对当前成果，不逐条重放历史工具。已发送但结果未知 MUST 先观察且不得直接重发；原生上下文创建结果未知 MUST NOT 自动另建上下文。认证、权限、额度耗尽、身份变化及用户主动停止 MUST NOT 自动重试；取消或宿主关闭 MUST 结束等待，不因刷新或并发观察重复发送。执行因本机模型网关不再接受执行进程持有的租约凭据（`模型调用的本机凭据已失效。`）而失败时，若准确执行已结束、工具均已结束、无待定请求、账号身份未变化且账号仍可用，系统 MUST 撤销该执行来源的旧凭据与租约、重新签发租约、重建执行来源，然后自动接续恰好一次；第二次仍因同一原因失败 MUST 保留真实原因并停止自动重试。该接续 MUST 单独计数，MUST NOT 占用三次临时故障重试名额，也 MUST NOT 在账号身份变化、账号不可用、请求仍待定或旧来源撤销未确认时发生。账号可用性以当前账号状态判断：账号已断开或已停用时 MUST NOT 接续；账号状态不是可用时，系统 MUST 先按原生账号重新核对一次，核对后仍不可用 MUST NOT 接续，核对结果可用才继续撤销来源并接续。该核对 MUST 最多进行一次，MUST NOT 代替用户重新登录。

#### Scenario: 临时连接失败尚未发送
- **WHEN** 原生连接准备临时失败且没有发送工作输入
- **THEN** 系统 MUST 退避重建原连接并以原输入身份继续，超过次数上限后保留具体原因

#### Scenario: 模型繁忙后继续
- **WHEN** 模型明确返回繁忙且准确执行与工具均已结束
- **THEN** 系统 MUST 在同一可见对话和原来源内有界接续，保留已完成成果及原失败记录

#### Scenario: 不可自动重试与取消
- **WHEN** 结果未知、工具未结束、需要用户决定、额度耗尽、认证权限或身份变化，或用户停止、宿主退出
- **THEN** 系统 MUST 保留当前记录和准确原因，取消待执行的自动重试且不重发工作

#### Scenario: 本机模型凭据失效后自动恢复
- **WHEN** 一轮执行因本机模型网关拒绝执行进程持有的租约凭据失败，准确执行已结束、工具均已结束、无待定请求，账号身份未变化且账号仍可用
- **THEN** 系统 MUST 撤销该执行来源的旧凭据与租约、重新签发租约、重建执行来源，并以系统消息接续一次
- **AND** 第二次仍因同一原因失败时 MUST 保留真实原因、停止自动重试且不占用三次临时故障名额

#### Scenario: 本机模型凭据失效但不满足接续条件
- **WHEN** 同一失败发生在账号身份已变化、账号不可用、请求仍待定或旧来源撤销未确认时
- **THEN** 系统 MUST NOT 自动接续，MUST 保留真实原因并保留已完成的工作记录

#### Scenario: 账号状态是同一刷新留下的过期观测
- **WHEN** 该失败发生时账号仍启用但状态不再是可用，且重新核对原生账号后恢复可用
- **THEN** 系统 MUST 重新核对一次账号，核对可用后按上一场景撤销来源并接续一次
- **AND** 核对后仍不可用时 MUST NOT 接续，MUST 保留真实原因与工作记录
