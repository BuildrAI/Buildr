## Why

候选准备已支持本机结果复用，但完整通用检查仍按 Windows 名义重复，且混合源码与包消费的分片迫使已验证源码再次进入远端。测试输入发现过宽，又让无关测试修复撤销大量成功结果，放大重试成本。

## What Changes

- 将通用源码检查统一为一次完整证明；受控准备先在本机补齐，远端消费有效结果。
- 明确 Windows 的真实命令、路径、目录链接、快捷方式及进程清理边界；独立的小范围检查替代整组业务生命周期重复。
- 分离源码分片与最终原包消费，保留两系统的安装启动、宿主兼容及真实平台入口证明。
- 收窄可证明的测试输入，保留未知依赖的保守处理与完整覆盖汇总。
- 发布专用代码归 `skills/buildr-release/scripts/`，全部检查及汇总归既有验证框架；本机与 GitHub 调用同一实现。
- 去掉重复断言，按真实成员发现输入，清理失败保全旧结果，并按缺项准备和逐包回读。
- 不改变用户产品行为或公开包格式。候选检查编排身份变化，旧汇总不能冒充新架构验收；原公开发布和包字节保持原事实。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `product-verification-quality`: 明确通用源码与真实平台差异的证明职责、候选分片和结果复用范围。

## Impact

涉及 Buildr 服务的验证登记、选择、输入识别、候选汇总及现有 GitHub 工作流消费者；同步 Product 验证声明、发布流程和验证架构说明。DSH 继续使用独立包身份及既有源码/消费证明，不把主包成功替代插件成功。本轮不派发新的 GitHub 运行。
