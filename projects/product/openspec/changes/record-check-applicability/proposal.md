# 审查与验证适用性显式留痕

## 为什么
正式任务的三项检查——方案审查（Planning Review）、实现审查（Implementation Review）与开发验证（Task Verification）——其执行结论或"不适用"判断目前只存在于对话与自由文本中。任务详情把"从未执行"与"不适用"都呈现为"暂无记录"，人和接续的智能体无法区分，曾出现实际执行测试但未登记、且各项默认豁免不留痕的情况。

## 改变什么
- 工作摘要（Work Context）契约扩展可选 `checks` 字段，按检查名（`planning-review`/`implementation-review`/`verification`）记录当前适用性结论（`needed`/`not-applicable`）与事实理由；原子 compare-and-set 随上下文版本保存。
- CLI 与 HTTP 各加一个最小入口，允许在任务仍为 `active` 时逐项记录或更新该结论；记录检查结论不替代审查/验证结果本身，专业结果仍由各自应用维护。
- 任务详情在"方案设计""开发实现"的对应目录项区分"未执行""不适用（理由）"与已有真实结果。
- 任务指引更新：有提案或设计材料即需要方案审查、开发完成即需要实现审查、实际执行过检查即登记验证报告；不适用必须在任务详情留痕。收尾前补登已发生证据的既有要求保持。

## 不改什么
- 审查结果与验证报告的专业模型、槽位与历史不变；适用性结论不构成门禁、审批或第二结果库。
- 不回补历史任务的留痕。
