## ADDED Requirements

### Requirement: 浏览器恢复上次本机状态

源代码管理 MUST 按当前浏览器来源和工作空间（Workspace）隔离保留有容量与有效期上限的上次目录观察。页面重新加载且缓存有效时 MUST 在本轮状态请求完成前展示上次分支、数量及来源，保留原观察时间并明确表达正在核对；缓存 MUST NOT 包含文件正文、凭据，或被当作本轮已确认的来源及写入授权。缓存缺失、损坏、格式不匹配、超期、超限或存储不可用 MUST NOT 阻止正常读取。

#### Scenario: 重载后先看已有结果
- **WHEN** 用户已经完成一次读取，随后重新加载页面而本轮状态请求尚未完成
- **THEN** 页面 MUST 已显示该工作空间上次结果及待核对状态，而不是逐库从空白重新出现
- **AND** 依赖本轮来源观察的动作 MUST 不直接依赖缓存开启，既有服务端写入前核对仍 MUST 保持

#### Scenario: 后台核对无变化或部分变化
- **WHEN** 后台逐库核对完成，部分或全部内容与缓存相同
- **THEN** 系统 MUST 逐库确认新观察，仅变化内容更新，无变化 MUST NOT 重置仍有效的阅读、选择和输入

#### Scenario: 核对失败及来源替换
- **WHEN** 一个缓存来源本轮读取失败，或实际读取证明其身份已经更换
- **THEN** 失败来源 MUST 保留上次结果及真实诊断，其他来源正常更新；身份已更换时 MUST NOT 将旧文件和旧确认身份移到新来源

#### Scenario: 工作空间隔离及不可用存储
- **WHEN** 用户切换工作空间，或缓存损坏、超期、超限、浏览器拒绝存储
- **THEN** 系统 MUST 不显示其他工作空间的状态，也不因缓存失败阻止本轮真实读取

### Requirement: 被动核对复用且显式刷新即时

自动状态核对 MUST 正确使用既有同范围共享读取，合并相同范围的在途被动核对，保留原观察时间及变化后的重新检查。手动刷新 MUST 立即发起实际核对，不把浏览器缓存或已完成的短期共享结果当作本轮成功。外部文件变化、恢复前台和重连的现有自动感知 MUST 保持，读取并发 MUST 保持有界，普通刷新 MUST NOT 隐式获取远程。

#### Scenario: 多页面自动核对与手动刷新
- **WHEN** 多个页面读取同一来源，或用户在已有缓存后主动刷新
- **THEN** 自动读取 MUST 共享适用的实际检查，手动刷新 MUST 绕过已完成的共享观察并返回真实新观察

#### Scenario: 同范围重复被动核对与期间变化
- **WHEN** 相同范围核对尚在进行，又收到页面激活核对或外部文件变化
- **THEN** 页面激活 MUST 复用在途核对，不重复取消和启动；真实变化 MUST 保留一次必要后续检查，不能因去重漏掉更新
