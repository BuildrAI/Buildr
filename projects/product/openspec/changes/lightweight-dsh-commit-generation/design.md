## Context

问题和目标见 [proposal.md](proposal.md)。当前 `code-commit-message-application.ts` 已通过内部执行参数请求 `reasoningEffort: 'low'`，Codex 会实际确认该值；`DshDesktopProvider` 仅向桌面桥传递时限，桌面桥再直接把默认模型（Model）的 `reasoningEffort` 传给原生准备调用。因此，统一业务意图没有落到 DSH 调用上。

DSH 官方本机软件开发工具包（SDK）的 `llm.resolveModelInfo(provider, model, signal)` 解析准确路由，返回包含 `reasoning?.efforts` 的模型（Model）声明；`efforts` 是显示顺序，标识本身不承诺可排序。原生 `prepareCall` 会再次校验受支持级别并固定本次配置。当前 `swe-2` 声明支持的最低标准级别为 `medium`，不能直接发送 `low`。

提交材料通过 `commitRuleExcerpt` 提取后受每来源及总字节预算约束。独立语言条目即使来自适用规则，也可能被前面的相关文字挤出，结果只剩格式约定和英文示例。

## Goals / Non-Goals

**Goals:**

- 保持同一桌面后台、准确提供者（Provider）及模型（Model）路由，只降低本次提交说明的可选推理开销。
- 将“轻量”表达为提供者（Provider）可确认的能力语义，支持最低级别不叫 `low` 的模型（Model），保护普通继承调用。
- 在原有字节预算内保留适用的显式语言要求，不改变规则作用域或推导新的语言默认。

**Non-Goals:**

- 不调整用户桌面全局配置、当前聊天设置、原生认证或公开网页输入。
- 不更换模型（Model）、创建持久会话（Session）、增加工具（Tool）或自动补读。
- 不扩展为通用推理策略设置、耗时元数据平台或新的性能观测系统。

## Decisions

### 1. 内部轻量意图映射为桌面专用请求

保留现有统一业务调用及 Codex `low` 请求，DSH 提供者（Provider）把该内部意图映射为桌面传输参数 `reasoningEffort: 'lowest-supported'`。桌面桥能力可选增加 `lightweightGeneration`；新调用明确请求轻量策略时先确认该能力，旧插件（Plugin）未声明时明确失败并提示更新，不静默沿用高推理。

普通未指定该参数的请求继续直接继承桌面推理级别（Reasoning Effort），不额外要求模型目录接口。可选字段保持已有发现、查询及普通生成兼容；不建立新公开设置面板，也不把字面 `low` 当作各模型（Model）的通用协议值。

### 2. 从准确模型声明选择，准备后复核

桌面桥先固定当前默认提供者（Provider）和模型（Model），通过同一原生 `llm` 服务的 `resolveModelInfo` 获取准确路由声明，并使用当前请求的取消信号。只有声明中的全部可选级别均具已知标准语义时，按 `off`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max` 的顺序选最低实际存在值；显示顺序不参与优先级判断。包含任意未知标识时不能证明全体最低值，局部失败，不为不透明标识推导排序。

成功读取准确声明且 `reasoning` 缺席表示原生不提供可选级别：本次省略 `reasoningEffort`，让原生默认处理。目录接口不可用、读取失败、空或非法可选级别与“不支持可选级别”是不同事实，前者不能冒充后者。

把仅本次的配置传给 `prepareCall`；准备后的提供者（Provider）和模型（Model）必须与观察值一致，有明确所选级别时确认值也必须一致；不支持可选级别时不能出现意外级别覆盖。先确认再发送生成内容，仍使用空工具列表和无 `sessionId` 的一次调用。运行（Run）配置来自准备响应，不拿桌面 `max` 冒充实际 `medium`。

### 3. 优先保留原文语言条目，仍按原作用域解释

规则摘录按规范原文选择相关段落或列表项，在单一来源的预算内优先保留明确提交语言和通用输出语言条目，其后保留提交格式与其他相关文字。仅改变来源内部的保留优先级；来源、作用域、覆盖顺序、部分摘录标记和内容版本检查继续有效。

不从中文界面、文件名、近期英文提交或请求语言推导规范，不注入固定中文要求。为中文和英文显式条目均增加回归场景，并覆盖长列表挤占与规则来源顺序，保证修复针对遗漏机制。

## Risks / Trade-offs

- 新主程序遇到旧桌面插件（Plugin）不能证明专用轻量能力 → 仅该生成失败并保留草稿，普通 Git 操作和其他已成立接入事实保持；通过匹配插件（Plugin）更新启用能力。
- 原生适配器（Adapter）将来引入未知推理标识 → 无可证明排序时局部失败，后续基于官方语义单独增加映射；不猜测隐藏成本。
- 选择最低受支持级别不保证网络或供应商一定在目标时长内响应 → 保留现有 60 秒总预算及取消隔离，真实源码实际测量只报告本次观察。
- 有界摘录不能完整理解任意规则 → 保留原文、作用域与截断事实，回归验证显式语言条目，维持结果发布前的材料版本核验。

## Migration Plan

不迁移持久数据，不修改已有接入编号、默认选择或桌面聊天配置。主程序与插件（Plugin）按各自交付方式更新；本次开发验证只证明实际测试及所用桌面版本，不等同公开发布。需要回退时回退本次源码与配套构建，桌面全局设置无需恢复。
