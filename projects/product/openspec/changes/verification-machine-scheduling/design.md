## Context

调查记录位于canonical工作区的`.buildr/local/verification-runs/verification-concurrency-investigation/`。同内容四个浏览器组两路110秒、四路88秒，但单组准备变慢；两路复核有独立页面等待失败，不能承诺稳定20%。当前DAG支持混合类型，入口只缺完整组合选择；I/O预算为整组声明额度，不是硬件测量。

## Goals / Non-Goals

目标是让选择、实际准入、预算来源和准备成本一致且可解释。非目标是跨独立npm命令自动协调所有额度、复杂实时伸缩、合并HTTP服务、提高CI默认并发或修剪业务断言。保留已有真实进程负载保护，本轮不重写准备DAG或引入新的执行引擎。

## Decisions

### 共同入口

目标：两类无需人为顺序等待。目的：共享同一准备和总预算。方案：`test:system`是Integration与E2E类型并集，消费原登记及同一executePlan。不是两个后台命令。有效性：类型并集和去重均能直接检查；真实混合补验验证实际重叠，资源锁仍负责真正冲突。不会承诺总时间等于两类最大值。

### 机器初始预算

目标：机器差异能改变实际并行。方案：新增`local-auto`，作为非CI默认；显式`local`及CI固定档位保留。使用可用CPU并行度和总内存/进程内存上限形成初始组宽度，保守取每3个CPU和每4GiB一个组，自动宽度1至3。浏览器并发保持固定2。对话组内部改为1个worker串行：单独的setup、tasks、recovery场景组分别通过，但同一组两个worker并行时出现setup角标、tasks取消和recovery事件流失败，说明组内争抢而非产品断言本身；代价是该组约9至11分钟。工作空间重型组同样最多3组。实测四组外层并发在15 CPU机器上使负载达到12至21，并出现对话页面等待、Qoder原生对话未结算和真实进程交接超时；三组以内且对话组降为1个worker后未再出现。三组及以上的I/O额度保留4份，使两组重型生命周期仍可重叠；更低宽度机器沿用更小I/O额度。工作进程额度不低于单组现有需要的4，自动上限16。真正独占及具名正确性资源不随机器放大。

`BUILDR_VERIFICATION_JOBS`允许明确指定组宽度，联合调整global、workspace-heavy、浏览器和I/O；保留CPU-heavy的独立上限及已有单组最低需求。输入须为安全正整数；无效值在准备前拒绝。机器观测、策略、覆盖和最终额度进入计划与证据。预算是声明单位，不声称限制真实OS进程数。选择初始档位而非实时控制器，是因为现有样本不足以建立稳定反馈模型；固定档位提供兼容和可重复对照。

### 排队原因

目标：调大参数前知道被什么挡住。方案：保留原准入判断，记录本地依赖、全局/class/资源数量/多维额度/独占约束的等待区间；多个原因同存，不相加冒充墙钟。跨执行租约等待沿用已有独立证据。不改优先级或释放语义。

### 准备路径

目标：减少已证明的重复CLI冷启动，保留私有环境和完整业务证明。方案：浏览器文件使用本进程既有测试应用适配器的完整初始化、项目/服务/任务创建能力，缓存该私有夹具runtime；仅替换前置造数据。初始化仍完成原登记、sync和Doctor，不能降成source-only或手改身份文件。场景内公共CLI操作及CLI专属测试保持真实入口。每组服务、数据根及浏览器独立，不复活失败的共享服务候选。

有效性：原init应用与CLI调用相同，减少入口解析、运行时和进程重复加载；原UI断言验证数据能被真实生产HTTP消费。同集合、固定档位对照准备调用次数、阶段耗时和整组墙钟；无效时回看初始化真正成本，不把移出计时当收益。

### 版本轻量入口

目标：消除已定位的无关完整runtime加载。方案：在完整registry导入前识别精确版本参数，身份读取沿用原实现的窄来源，不从安装模块聚合出口拉入无关能力。其他命令与内部Web恢复捕获保持。以真实CLI输出一致、完整bootstrap故障注入及模块加载反例验证；该收益单独报告，不外推浏览器整套。

### 真实失败收口

目标：先把真实失败变成可重复关闭的缺陷，再讨论并发收益。目的：避免把失败控制、取消场景或放宽期限误算成提速，也避免在失败未收口时合入。方案：三项失败分别按真实边界处理。

- 存储锁：发布锁目录rename报`ENOTEMPTY`/`EEXIST`后重新检查锁是否存在；只有原持有者已释放时才重新发布，最多有限次数，其他错误原样抛出。以确定性反例证明旧实现复现生产堆栈、新实现通过，并保留具名锁语义。
- 任务材料拦截器：不再在延迟回调里用`route.fetch()`二次抓取未保护响应；请求到达即标记，放行后转发真实请求，转发异常归入当前场景并保留后续场景执行与清理责任。
- 首屏补页：自动补页不以瞬时贴底状态作为继续条件，布局位移不冒充读者接管；显式滚轮、触摸、键盘和指针操作仍停止自动补页。以布局回调反例和真实生产托管浏览器场景验证。

有效性：三个准确检查分别通过，且目标组不再取消兄弟场景或复现竞争错误；完整四类复核前不能宣称任务全绿。失效条件：修复依赖放宽期限、删除断言、跳过真实服务、把取消场景算通过，或确定性反例在旧实现上不能复现。

### 重型组 I/O 有界准入

目标：消除“额度调大时重型组申请量一起变大，因而继续互斥”的假并发。方案：真实Agent进程、Archify和嵌套Git组的工作空间I/O申请统一为`min(2, workspaceIo)`；四份额度最多允许两组重型生命周期重叠，三份及以下保持原有互斥。`agent-process-tests`具名正确性锁、组内workers/processes、处理器预算、清理和其他资源锁不随之放大。

有效性：调度单测证明四份额度最多两组、三份及以下最多一组，且worker与具名资源授权不变；完整运行记录实际重叠、等待原因、墙钟、失败率和清理。失效条件：出现具名锁或状态隔离回归、清理未确认、失败率上升，或实际重叠没有发生。该改动只释放被整组I/O申请挡住的并行度，不承诺固定节省时间，也不把失败控制算作收益。

## Risks / Trade-offs

- 高并发使准备变慢 → 默认自动宽度有界，固定档位可复现，保持期限和真实失败；用同内容实测验收，不直接外推四组结果。
- 机器预算与子进程租约不一致 → 将实际profile传递到子执行，显式覆盖进入同一解析入口，核对对话父/子资源数量。
- 缓存采用错误工作线程证明 → 复用继续核对实际worker授权；机器观测与明确档位可回读。
- 应用夹具跳过CLI证明 → 仅替换前置阶段，CLI专属及场景内CLI原样保留；核对初始化完整链和身份。
- 控制复核出现页面等待失败 → 保留独立未知，不用于性能收益，不放宽断言掩盖，也不据此提高默认期限；四路重型组实测不稳定后，将重型组上限收敛为3并重新全量验证。

## Migration Plan

旧类型入口、固定档位和输出语义保留；新增组合入口及可解释机器默认。使用`BUILDR_VERIFICATION_PROFILE=local`恢复旧固定额度。无需状态迁移或清理历史证据，本轮不归档或交付Git。
