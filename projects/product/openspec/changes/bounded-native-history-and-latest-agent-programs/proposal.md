## Why

Codex 的一次真实恢复请求因完整线程历史超过本机 16 MiB JSON-RPC 帧上限而持续失败，既有对话因此无法重新打开；Qoder 的历史读取同样可能把完整转写压入单个工作进程响应。另一条路径仍以产品内固定版本作为新下载目标，使新接入拿到旧版 Codex、DSH 或 Qoder 配套程序。两处都会把可实现的本机操作错误地变成不可恢复或版本滞后。

## What Changes

- Codex 恢复改为只读取线程元数据，历史、观察和派生边界通过回合与条目分页重建；不再使用携带完整回合的恢复或线程读取。
- Qoder 历史在工作进程内形成稳定快照，并按字节和条目预算分页传输；游标、快照、上下文和目录必须匹配，过期或损坏时局部失败。
- 新接入准备独立程序时从各厂商固定 npm 包源读取官方默认发布的最新版本，不再以内置固定版本或旧受管包冒充新下载目标；读取失败时明确停止且不降级安装。
- 保留已经准备、绑定或可离线发现的受管程序，不用新下载策略自动替换既有绑定；清理逻辑以显式准备指针保护尚未绑定的最新包。
- 补充真实大线程、分页边界、最新版本、读取失败及包保留验证。

无破坏性接口变更；存储路径新增按准确版本命名的受管包和准备指针，旧受管默认目录继续可读。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `agent-runtime-connections`：新增原生历史有界分页与完整重建要求，并将首次程序准备的下载目标收紧为官方默认发布的最新版本。

## Impact

涉及 `services/buildr-agent` 的 Codex、Qoder 适配器，程序发布读取、安装与回收，以及对应集成和单元验证；不删除原生历史、不提高全局传输上限、不自动替换已有连接或账号。
