## Context

Codex `thread/resume` 与 `thread/read includeTurns:true` 会把完整线程编码为单个 JSON-RPC 响应。真实故障线程的 rollout 约 46.5 MB，仅 16 个回合就超过本机 16 MiB 帧上限；失败发生在请求受理前，不能通过重试或扩大无界缓冲解决。Codex 已提供线程元数据、回合列表和条目列表分页接口。Qoder 的 SDK 历史读取在工作线程内完成，完整数组通过工作进程消息返回，同样需要稳定快照和分页边界。

新接入曾以产品内置版本作为下载目标。该版本只是兼容性声明和遗留回退资料，不能代表厂商当前发布；新下载必须查询固定官方包源，同时保持既有绑定和已有受管包可用。

## Decisions

### Codex 元数据与双层分页

恢复使用 `thread/resume excludeTurns:true`，线程身份使用 `thread/read includeTurns:false`。历史读取按 `thread/turns/list` 分页取得回合，再按 `thread/items/list` 分页取得每个回合的条目；观察和派生边界只读取准确回合。所有调用校验线程、回合和条目身份，并拒绝重复游标。派生仍由 Codex 自己解释并裁剪原生历史，Buildr 不复制或重写历史内容。

### Qoder 稳定快照分页

首次历史读取在 worker 内完成原有 SDK 投影与中断核对，并保存不可变快照。后续页只按游标读取同一快照，快照绑定上下文、目录和有效期；最后一页、错误、替换或关闭时释放。分页按 UTF-8 JSON 字节预算和条目数双重限制，单条超限明确失败，避免控制通道被超大响应终止。

### 官方最新版本与新下载分离

程序目录仍在发现阶段读取固定 npm registry 的 `latest`，并以该准确版本构造安装目标。读取或版本格式无效时 `canInstall:false`，不退回内置固定版本。安装成功后写入显式准备指针，让尚未绑定的最新包可被发现和回收保护；既有绑定和已准备版本不被网络检查失败或新版本发布自动替换。

## Risks / Trade-offs

- 分页增加往返次数。通过批量回合和每回合条目页控制调用数量，真实故障线程探测的最大单帧约 500 KB，优先保证可恢复性。
- 单个不可分页条目仍可能超过帧预算。此时返回局部失败并保留会话，不以无界传输或部分历史冒充成功。
- 快照在 worker 内占用短期内存。以有效期、最大快照数和最后一页释放限制保留范围。
- 最新版本可能不属于当前准入主版本。下载仍受实际程序检查约束，不因“最新”自动放宽主版本或改绑既有连接。

## Migration

无数据迁移。既有原生线程和受管程序继续按原身份读取；新安装目录按 `package-<version>-<platform>-<arch>` 并列保留。旧默认目录只作为兼容发现与清理保护，不再作为新的下载目标。
