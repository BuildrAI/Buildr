# 对话执行过程语义折叠

统一对话当前把工具调用平铺为等宽文本卡片，执行过程淹没对话主线。本变更把执行过程提升为一等展示单位：执行器（Executor）为工具条目上报稳定的工具名称（name），对话视图按轮（Run）聚合为可折叠的过程块，块内呈现工具步骤与过程叙述的真实交叉顺序，最终答复始终留在主线，不同工具使用一致的语义标签。

## 为什么改

- 用户需要看见对话结论，也需要按需核验执行过程；当前平铺使一段执行占据大量空间，对话连续性被打断。
- 工具行的可用性取决于能否用准确名称表达"读了哪个文件、跑了什么命令、改了哪些文件"，而不是整段命令文本。

## 做什么

- `ExecutorItem` 与 `ConversationEntry` 增加可选 `name` 字段，承载工具步骤的稳定名称；缺名条目继续以现有文本形式展示。
- 已接入执行器在产生工具条目时写入已知名称：Codex 按条目类型给出命令、文件修改、工具调用三类名称；DSH 与 Qoder 透传原生工具名。
- Buildr Web 对话面板按执行轮聚合过程条目（工具条目及最终答复之前的助手说明）为单个可折叠过程块；块头给出执行状态与用时，块内每条过程步骤以语义标签单行展示并可展开核验完整内容。

## 范围边界

- 不解释执行者私有推理格式；思考内容若执行者以条目提供，按现有 kind 展示，不新增条目类型。
- 不改动消息正文、审批、回答等已有交互语义；过程块仅为展示聚合。

## 本轮修订

取消按字数折叠消息，以每轮最后助手答复作为历史兼容回退，运行中不提前认定最终答复。工具可选 input 保留原始调用输入；命令详情与文件点击按实际类型呈现，文件复用代码查看器并核对真实检出位置。视觉采用中性正文、紧凑工具行与克制摘要，避免全篇灰绿和重复导航图标。
