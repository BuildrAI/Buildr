## Context

`task-finish` 的发现描述已覆盖“收尾”，正文也列出普通 Git 交付；`git-operations` 要求 consumer 提供明确授权。缺口在两者之间对自然语言指令的解释。参见 [proposal.md](proposal.md)。

## Goals / Non-Goals

**Goals:** 让规则和技能把用户的收尾指令作为常规 Git 授权传递，同时保持每次写入前的身份、范围和效果核验。

**Non-Goals:** 不增加 Git 命令路由、自动选择冲突策略、改变强推或发布授权，不改变任务记录格式。

## Decisions

- 在随包核心规则写授权不变量，在 `task-finish` 写触发与交接方法，在 Git 契约和 provider 写消费边界。这样各层只承担自己的职责；只改某一技能会留下规则与消费方的歧义。
- 保留 `buildr.git-operations/v1`：常规操作及效果集合未变，本次只是明确已有“用户指令或上游 consumer 可提供授权”的解释。若未来扩展操作或副作用，再升级契约。
- 契约测试同时检查发现描述、授权连续性和越界场景，避免只测某一段文案。

## Risks / Trade-offs

- [将“收尾”误读为任意远端写入] → 每次按真实任务成果、目标引用和完整推送范围核验，额外副作用另行授权。
- [不同作用域规则收紧交付] → 保留更具体的业务约束；仅免除针对同一常规动作的重复授权询问。

## Migration Plan

随包源资产经正常产品交付和自举同步投射到工作空间；无需数据迁移。回退可恢复这些文字资产，既有 Git 结果不自动撤销。
