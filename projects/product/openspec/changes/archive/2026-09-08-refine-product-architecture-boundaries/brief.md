# 架构边界与目录地图收敛

## 一句话摘要

让当前 Buildr 的源码、构建结果、模块职责和目录地图真正一致。

## 背景与问题

上一轮统一目录后仍有宽泛对象装配、工程检查混入产品、分散生成物与地图缺少整体树的问题。

## 目标与非目标

每日演进归入任务子能力，保持单机版 Git 提交主导并关联本地任务；构建结果归入 build，保留 web-dist；前端和后端依赖按真实职责组织。未来企业版任务主导汇总、自动知识维护、正式发布和父任务完成不在本轮范围。

## 受影响用户与核心流程

维护者从项目目录树进入两个服务，再定位模块、文件、方法、调用和数据写入者。CLI、网页、安装及每日演进用户继续使用既有行为。

## 关键变化

生成物路径与公开测试库入口收敛；每日演进迁移；宽依赖和工程检查拆分；前端客户端与设置归位；现有地图和技术图同步。

## 影响、风险与兼容性

无数据迁移或新增依赖。生成路径、工程命令和公开测试库存在消费兼容风险，必须通过干净构建、生产装配、真实浏览器与包验证证明。

## 验收与技术入口

目录树可定位所有主要职责；跨模块依赖明确；生成物可删除重建且不被 Git 跟踪；每日演进公开结果保持兼容；运行和浏览器验证通过。见 [设计](design.md)、[清单](tasks.md) 与 specs。
