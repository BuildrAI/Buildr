## Context

`mysql-connection` 的连接声明只有 `test` 与 `databases` 两个只读槽位（Hook），程序 `buildr-mysql` 只识别这两个命令；独立查询工具 `mysql-query` 固定为单条只读 SELECT、只读事务与内置绑定校验。连接定义层强制槽位 `effect: 'read'`，因此写入能力无法通过新增槽位表达。

同仓库的 Nacos 接入已经提供写路径：`publish` 是程序子命令，经通用启动入口执行，写前发送 `buildr.connection-revalidate` 由宿主复核实例、声明、程序与认证版本，结果用 `published` / `verified` 区分受理与回读。本次沿用该形态。

## Goals / Non-Goals

**Goals:**

- 让智能体在已声明目标环境的连接上执行单条 DML 或 DDL，并如实区分「已提交且可回滚」「已执行且不可回滚」「结果未知」。
- 破坏性结构语句默认拒绝，用户可在连接配置中显式解除；环境与策略进入程序可见的配置。
- 既有实例的只读测试、发现与查询行为保持不变，不要求重录认证。

**Non-Goals:**

- 不改变 `mysql-query` 的只读语义、绑定校验或页面行为。
- 不新增 `plan` / `verify` 子命令，不做批量迁移、多语句事务或结构版本化。
- 不改变槽位（Hook）只读约束，不修改连接配置版本。
- 不在本变更内强制个人认证来源，也不执行发布或自举同步。

## Decisions

1. **写入做成程序子命令而非槽位**。连接定义校验要求槽位 `effect` 为 `read`，扩展槽位等于改连接声明模型与配置页的运行入口；子命令沿用 Nacos `publish` 的既有形态，改动面只在程序、声明与技能文档。

2. **一次 `apply` 只接受一条语句，且按类别分流**。数据修改类在事务内执行，受影响行数超过本次上限即回滚；结构变更类明确报告不可回滚。MySQL 的 DDL 隐式提交，混合两类会得到无法诚实叙述的部分提交结果，因此拒绝混合，也暂不支持多语句。需要多条时由智能体分次执行，各次独立报告；原子批量留待确有需求时再设计。

3. **执行提交原文，不做 AST 往返重生成**。只读查询路径为可重生成而限制语法；DDL 的 MySQL 方言（`ALGORITHM=INSTANT`、分区等）往返会丢失，强行重生成会把有效语句拒之门外。`apply` 只用语法树分类与拒绝，执行时依赖驱动 `multipleStatements: false`、拒绝 `/*!` 可执行注释与空字节来排除隐藏的多语句。

4. **结构变更以「目标对象当前定义摘要」为写前条件**。程序提供只读子命令 `fingerprint`，由智能体先行观察目标表当前定义的摘要（目标表不存在时返回明确的缺席摘要），再把该值传给 `apply`。`apply` 执行前重新读取并比对，不一致即拒绝；执行后回读 `information_schema` 并报告实际结构。数据修改类同样核对目标表摘要存在且未变。第一版不支持一次涉及两个对象的重命名语句。

5. **环境是显式保护，不是前置配置**。`targetEnvironment` 与 `allowDestructive` 都是连接配置字段，随实例文件进入 Git——它们是策略声明而非凭据。未声明环境时按非生产执行并在结果中标注，更新后即可写入；只有显式标记 `prod` 才拒绝，避免把“先补配置”变成使用门槛。`prod` 一律拒绝的理由是 MySQL 的结构变更缺少可比较的正文差异，无法像 Nacos 那样用单次授权限定具体目标。

6. **不升 `configVersion`**。两个字段都设计为可缺失：旧实例没有字段时只失去 `apply`，读写与查询完全不变。升版本会让既有实例被判定为不兼容并强制重录认证，收益不足以抵消成本；`mysql-query` 也无需同步修改版本校验。

7. **破坏性开关只解除一类限制**。开关放行 `DROP TABLE` 与 `TRUNCATE`；权限与账号、服务器全局状态、过程/触发器/事件、文件导入导出类语句属于能力范围之外，不受开关影响。

## Risks / Trade-offs

- [DDL 不可回滚，护栏只能降低误操作概率] → 环境门禁、结构指纹、破坏性默认拒绝与结果回读分别覆盖不同失败面；技能文档要求执行前展示目标与语句。
- [原文执行依赖解析器与服务器的理解一致] → 语法树用于分类和拒绝，任何无法识别或命中拒绝清单的语句都不执行；驱动层关闭多语句。
- [团队共享开发账号是常见做法] → 认证来源不因写入而改变；团队共享账号与个人账号都可用于写入，凭据是否进入团队文件由团队自行选择。
- [未声明环境的生产连接没有额外保护] → 账号权限仍是真实边界；破坏性语句默认拒绝、数据修改要求 `WHERE` 与行数上限、写后回读分别覆盖不同失败面。需要额外保护时给该连接标注 `prod`。
- [程序版本升级后约束变化] → 连接声明的程序版本约束随程序版本同步上调；在 Buildr 运行时更新到新包之前，该连接会因为程序版本不符而不可用，属于既有版本校验行为，实施与验证阶段以源码测试为准。

## Migration Plan

无数据迁移。既有实例不带新字段时行为不变；用户需要在连接配置页补充目标环境后才能使用 `apply`。技能正文、命令参考与连接声明同次提交；程序版本与声明约束同步变化。自举同步与发布不在本变更内，按各自授权单独执行。
