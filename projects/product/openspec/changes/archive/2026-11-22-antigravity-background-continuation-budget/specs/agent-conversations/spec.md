## MODIFIED Requirements

### Requirement: 已释放的待确认对话必须提供继续与关闭出口

当对话未能自动恢复（例如自动恢复策略未启用、恢复预算耗尽、连接曾失配待确认、后台自动续行达到上限或用户取消自动续行），且不存在明确活动工作、有效待回答问题或已提交待发送要求、原生控制资源均已确认释放时，系统 MUST 提供单一“继续原任务”出口。提示 MUST 以可见文案说明中断来源、结果未确认以及记录与已完成操作保留，提示本身 MUST NOT 再提供关闭、隐藏、重新读取或停止动作；关闭（隐藏）MUST 继续可从对话菜单完成，并沿用保留对话历史、未知执行与工具事实及关联 Task 状态的约束。继续 MUST 先核对原轮及成果，再接续未完成目标，不重放历史要求。读取仍未知时 MUST 明确说明没有取得新结束证据及可用动作，MUST NOT 把读取成功冒充工作完成。

当执行因达到后台自动续行上限而暂停时，系统 MUST 在观察到该诊断后立即触发空闲控制资源释放并保持原有上限诊断不被空闲释放、服务退休、跨代读取或控制核对改写，且 MUST NOT 自动触发重启恢复重跑该轮；用户确认后经“继续原任务”出口即可接续原目标。

#### Scenario: 服务重启中断后的单一继续出口

- **WHEN** 当前轮因服务退休中断、原生控制资源已释放、结果未知且没有待决定，且未触发或已耗尽自动恢复
- **THEN** 提示 MUST 显示可见的中断原因与“继续原任务”一个动作
- **AND** MUST NOT 显示关闭、隐藏、重新读取或停止动作
- **AND** 原记录、未知工具结果和已完成事实 MUST 保留

#### Scenario: 后台自动续行达到上限后的暂停与手动继续

- **WHEN** 执行因达到单轮后台自动续行上限暂停
- **THEN** 系统 MUST 及时释放空闲控制资源并保留上限暂停诊断，MUST NOT 自动触发系统恢复重跑
- **AND** 即使随后发生后台服务更新或重启，系统也 MUST 保留原上限暂停诊断而不覆盖为服务重启中断
- **AND** 界面 MUST 向用户显示明确的自动续行上限暂停说明与单一“继续原任务”出口，点击后可接续原目标与已取得后台结果

#### Scenario: 关闭遗留待确认对话

- **WHEN** 用户从对话菜单关闭原生控制资源均已释放、没有明确活动工作和有效待回答问题的待确认对话
- **THEN** 对话 MUST 从活动提醒撤下并保留在可恢复的历史中，原执行和未知工具结果 MUST 不变，关联 Task MUST 不被完成

#### Scenario: 另一原轮仍在工作

- **WHEN** 最新轮已释放但保留轮次尚未释放，或仍有明确活动工具、有效待回答问题或已提交的待发送要求
- **THEN** 关闭入口 MUST 不可用，隐藏 MUST 不掩盖相应活动，不发送替代停止命令

#### Scenario: 再次继续工作

- **WHEN** 用户选择继续已释放但结果待确认的原目标
- **THEN** 系统 MUST 先重新读取；取得正常结束和最终答复证据时 MUST 告知用户可直接提出新要求，否则按原执行身份核对已生效成果后接续，不自动重复旧操作

#### Scenario: 仍有活动工作的未知轮

- **WHEN** 当前轮结果未知但原生控制资源尚未确认释放
- **THEN** 提示 MUST 继续提供停止与重新读取，MUST NOT 把真实在途工作表达为可结束的历史
