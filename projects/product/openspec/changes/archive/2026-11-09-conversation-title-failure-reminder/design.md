## Context

自动标题现有两个有界阶段：执行开始后的早期尝试和首轮成功后的完成兜底，按参与者分别记录在 `titleAttemptsByParticipant`，旧记录仍可能只有全局尝试标记。失败原因写入 `titleDiagnostics` 与 `titleState`，标题保持“新对话”。本设计只改变最终失败后的名称表现，动机见 `proposal.md`。

读取路径有两条：详情与 `list` 通过 `view()` 返回记录内标题；主列表 `listAll` 通过 `querySummaries` 的 SQL 摘要投影读取已保存的 `title`。因此只在 `view()` 派生提醒无法覆盖主列表。启动恢复已在 `recoverInterrupted()` 中扫描中断的标题任务，可作为历史数据的一次性修复入口。

## Goals / Non-Goals

**Goals:**

- 当前参与者早期与完成两个有界阶段都失败、标题仍为中性名称时，持久化显示「生成标题错误，请手动修改」。
- 升级前已经耗尽两个阶段的历史对话，在服务启动后同样显示提醒。
- 手动改名、已生成标题、显式手动生成失败不被提醒覆盖；不新增自动重试。
- 失败提醒保留后更换参与者，仍允许新参与者尽早尝试。

**Non-Goals:**

- 不调整标题超时、重试预算、参与者隔离或错误码归一化。
- 不新增前端状态、接口字段或数据库 schema。
- 不改写已生成或手动名称，不为旧记录补造摘要结果。

## Decisions

### 1. 提醒作为持久化标题保存，`titleOrigin` 保持 `default`

最终失败时把 `view.title` 写成提醒文案，`titleOrigin` 仍为 `default`，`titleState` 保留原有的 `failed` / `unavailable` 与原因。这样 `list`、`listAll`、详情和搜索共享同一个权威标题，无需在两套读取路径重复派生。备选方案是读取时动态投影，但 `querySummaries` 的摘要投影不含尝试记录，派生需要额外 SQL/JS 逻辑并造成搜索与显示不一致；新增 `titleState` 状态则要求前端适配，超出本变更范围。

`titleOrigin` 不作为 `generated`，避免把提醒冒充摘要结果，也保证后续参与者尝试和显式生成仍然适用。

### 2. 只在完成阶段最终失败时回填

在 `recordTitleFailure` 的 `completion` 阶段，当 `titleOrigin === 'default'` 且标题仍为“新对话”时写入提醒。早期阶段失败继续保留中性名称，符合“自动尝试尚未全部失败时保留中性名称”；`manual` 阶段失败不改写标题，保留当前名称或已有提醒。

### 3. `titleEligible` 接受提醒标题

判断条件从“标题等于新对话”放宽为“中性名称或提醒标题”，且 `titleOrigin === 'default'`。这样失败提醒保留后切换到新参与者，仍可执行早期尝试；早期尝试失败不会把提醒退回中性名称，显式手动生成仍优先。已生成或手动标题的 `titleOrigin` 不同，不会被自动尝试覆盖。

### 4. 历史数据由启动恢复一次性补齐

新增仓库查询，按 `titleOrigin='default'`、标题为“新对话”、`titleState` 为 `failed` / `unavailable` 过滤候选，避免全量加载。`recoverInterrupted()` 在中断标题修复之后逐个核对当前参与者是否已消耗早期与完成两个阶段（复用 `titleAttempts` 对旧全局标记的归属迁移），满足时通过正常保存路径写入提醒。

这样两条读取路径无需改动；重复启动时候选条件不再命中，操作幂等。无法确认当前参与者已耗尽预算的记录保持中性名称，避免误报。备选方案是在 `view()` 与 `querySummaries` 同时派生，仍会遗漏摘要投影中的尝试信息，并增加不一致风险。

### 5. 修复沿用正常保存语义

修复通过 `save()` 更新 revision、写模型并发布对话事件，使已连接客户端同步看到标题变化；不做绕过 revision 的直接数据库写入。并发修改导致 revision 冲突时跳过该条，下次启动重试。

## Risks / Trade-offs

- [升级时修复会更新受影响对话的 revision 与 `updatedAt`] → 仅命中已失败且标题未命名的记录；主列表按活动时间排序，通常不改变业务顺序，但旧版 `list` 可能把修复记录前移一次，属于一次性可见变化。
- [启动扫描增加一次查询] → 候选条件使用 JSON 字段过滤且限定失败状态，只 hydrate 少量记录；修复失败按记录隔离，不阻塞其他恢复工作。
- [旧记录缺少按参与者的尝试记录] → 复用既有全局标记迁移逻辑；无法确定当前参与者预算时不回填，保持中性名称。
- [提醒标题被误认为已生成] → `titleOrigin` 保持 `default`，`titleState` 仍为失败并带原因；界面可继续显示失败说明与手动生成入口。
- [降级兼容] → 旧版本把提醒视为普通非默认名称，不会自动覆盖或重试；用户仍可手动改名。
- [搜索命中变化] → 提醒文案会作为标题参与搜索，这是标题变化的自然结果，不新增单独搜索规则。

## Migration Plan

无 schema 迁移。新常量与回填逻辑随服务版本生效，历史记录在启动恢复阶段补齐；回滚时提醒标题作为普通名称保留，不触发自动重试。
