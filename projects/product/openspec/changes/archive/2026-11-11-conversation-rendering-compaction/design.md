## 取舍

- **`file://` 只在既有来源边界内解析。** 对话内容可能来自模型或外部系统，不能因此获得任意本机文件读取能力。解析后复用当前对话工作空间、已登记代码库和文件 API 的路径校验；允许读取的只是用户本来就能在该对话中打开的文件。
- **无法安全打开时保留原始路径，而不是删除链接。** 用户仍需要知道模型引用了什么，也可能要复制到终端处理。渲染为带说明的局部提示并保留可复制路径，比静默丢弃或伪造成可点击更可信。
- **绝对 POSIX 路径继续受控支持，`file://` 归一化为同一解析路径。** 两者共享同一套越界和来源检查，避免为 `file://` 单独开一条绕过校验的通道；Windows 盘符按既有解析规则处理。
- **原生预算。** 保留真实窗口和来源能力；DSH 默认不注入 maxTokens，由原生执行器管理输出与压缩。较小输出能力在协议边界保护，不设置统一固定限额或复制 headroom 公式。
- **压缩按钮和提示不新增推断。** 修复容量声明后，压缩应由真实压力触发；前端仍只消费准确 `compaction/start`／`compaction/end`，不根据 Token 增长或静默猜测。

## 兼容与风险

- Markdown 解析新增 `file:` 方案支持，但必须继续拒绝 `javascript:`、`data:` 等危险方案；现有相对链接和绝对路径测试不能回归。
- 本地链接打开依赖当前对话工作空间与来源解析；没有可用来源时只显示局部提示，不影响整条消息渲染和其他链接。
