## Context

动机见 [proposal.md](proposal.md)。已有 `agent-first-design`、`code-architecture`、`ux-design-laws`、`archify`、`ui-prototype` 分别负责专业判断和成果制作，缺少按用户当前问题收敛范围并组合这些方法的入口。外部 OpenSpec 技能（Skill）继续保持上游所有权。

## Goals / Non-Goals

本变更交付可选方法及一组讨论案例；既有专业方法仍拥有制作、保存和验证职责。案例中的外部连接模型、环境页面及查询行为都是拟议设计，不成为本变更新增的正式接入产品承诺。

讨论成果：[环境与身份边界图](diagrams/external-environment-architecture.html)、[环境目录与 MySQL 查询原型（UI Prototype）](prototypes/external-environments.html)。

## Decisions

### 新增轻量组合技能

使用 `feature-design` 作为意图入口，新增正文及可选随包登记。扩展代码架构或体验技能（Skill）会混合其专业职责；修改 OpenSpec 上游技能（Skill）会越过所有权边界。组合方法不等于程序化调用，因此不新增契约、状态、命令或固定顺序。

### 每轮围绕当前决定展开

技能（Skill）提示核对现状、划清本轮结果、选择足以支持判断的图示和界面成果，用代表场景检验模型；较大方向可以保留，但不把未来所有系统变成本轮清单。用户已给出的范围、原型偏好和同范围授权持续有效。

### 外部环境首例：拟议架构与界面

架构职责、资料归属和界面入口分别判断：外部接入拥有独立领域职责；环境登记属于当前工作空间（Workspace），可被其中多个项目（Project）引用；首版建议把“环境”放在工作空间（Workspace）左侧，与项目（Project）、服务（Service）等长期对象同级，顶部保留“工作台 / 工作空间 / 代码”。增加顶层入口会提前承诺一个独立高频工作区域；先放在现有长期对象区域，更容易检验是否确有独立工作区需求。以后提升入口位置也不自动改变对象归属。

qa/prod 分别持有明确的连接和资源引用；共享声明只记录非秘密事实，本机执行端（Executor）按连接绑定认证来源。MySQL 专业对接器（Connector）实现可以共用，真实目标和身份分别解析。目录分组和颜色只能帮助辨认，访问范围需要由工具与原生账号落实，图示不宣称已经证明网络隔离。

首例只模拟 MySQL 只读查询。查询始终绑定当时的环境、连接和库；切换环境目录打开另一份查询，已有编辑内容与结果保留原目标。每次结果显示模拟性质、目标、观察时间、行数和截断情况。SQLite 只核对文件身份与执行位置是否容得下；Nacos、Redis、日志和调度暂不展开。

原型（UI Prototype）复用当前源码中的应用壳、主题、阅读器及联动组件，只隔离数据和副作用，生成自包含正文与独立阅读页。案例保存在本变更内，通过既有任务入口发现。正式界面与接口保持当前行为。

## Risks / Trade-offs

- 通用技能（Skill）过宽会吸引局部修复 → 描述聚焦功能讨论和方案收敛，局部已定设计沿用专业实现方法。
- 案例容易被误读为接入已完成 → 图示和原型（UI Prototype）明确使用拟议设计及模拟数据，不连接真实系统。
- 原型（UI Prototype）成为独立视觉副本 → 导入本工作树现有组件和主题，构建核对依赖与源码来源。
- 同时展开过多技术会重现原问题 → 只深入 MySQL 使用路径，扩展方向保留在讨论边界。

## Migration Plan

技能（Skill）随产品源登记交付；正式投射及自举生效由既有唯一执行器在交付时负责。本轮不从候选工作树更新共享运行时（Runtime）。没有存储迁移、外部系统变更或兼容性破坏。
