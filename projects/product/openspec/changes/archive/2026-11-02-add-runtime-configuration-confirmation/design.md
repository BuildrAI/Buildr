## Context

`configurationAction.ts` 已把配置请求、内部对话提交与复制交接收敛到一处；`useRuntimeConfiguration` 持有三个入口共用的提交状态。本次改变的是交接发生的时点：说明必须先于创建对话和提交请求。内部对话的提交、模型与权限选择、首条提交身份和恢复语义保持不变。运行定义仍由本地运行读取与刷新机制观察；完成反馈同时要求本次对话执行结束和运行定义可读，不由提交成功或对话创建单独推断。

## Goals / Non-Goals

**Goals:**

- 让用户在创建执行前看到目标、步骤、授权影响和完成后的查看位置。
- 让三个配置入口共享同一套说明、确认、提交和失败反馈，不再因内部智能体是否可用而改变顺序。
- 保持“未接入时可复制”的既有能力，并让“尚未执行”在两种路径上都清晰可见。
- 关闭或取消确认不产生任何副作用；提交中不重复提交。
- 让用户在交接后知道配置是否完成、为什么未完成，以及完成后可以启动或查看什么。

**Non-Goals:**

- 不改变配置请求正文、技能调查方法、运行定义结构或启动流程。
- 不新增运行配置专用执行接口、后台状态或运行定义格式；完成状态由现有对话执行事实与运行定义读取派生。
- 不把完成反馈扩展为自动启动、部署或业务验证；配置完成与服务就绪、业务验证完成保持不同事实。
- 不提供“下次不再提示”的持久偏好；该动作会修改配置并启动进程，说明不能被永久跳过。
- 不重画服务目录、运行区或对话面板的外围布局。

## Decisions

### 1. 交接抽屉承载“说明 → 确认 → 提交”，入口只负责打开

新增统一的配置交接抽屉，由共享钩子持有待确认目标、提交中状态和失败反馈；服务目录、运行区、配置摘要、定义抽屉和任务本地运行只调用同一个打开动作。抽屉正文复用 `AgentDiscoveryContent`，同时承载确认与复制两种模式。

不采用就地 `Popconfirm` 或短弹窗：目标、步骤、影响和完整请求需要分组阅读，短弹窗无法承载而不隐藏授权信息；也与既有启动配置、运行定义的抽屉形态一致。

不采用“预检连接后决定打开哪种抽屉”：可用性判断需要模型目录、权限和偏好，打开时预检会复制提交入口的选择逻辑，并可能与真实提交结果不一致。确认时由既有提交入口核对，失败时在原抽屉切换为复制优先，保持说明位置不变。

### 2. 只有一个主操作，复制入口随内容按需出现

未确认时主操作是“开始配置”，取消为次操作；完整请求默认收起，展开后可在正文旁复制。提交返回未接入或提交前失败时，同一抽屉保持打开，提示尚未执行，主操作切换为“复制指令”，并说明原因。可用时复制仍作为完整请求旁的辅助能力，不增加常驻第三按钮。

相比“始终并列开始与复制”，该层级让主要路径明确，也不把复制误当成执行。相比“未接入时关闭抽屉再弹复制抽屉”，避免重复阅读同一份说明和状态跳变。

### 3. 提交后的状态归属：对话负责执行事实，抽屉负责交接事实

- 确认中：主操作显示提交中，禁用关闭、遮罩关闭和键盘关闭，防止“以为取消但已提交”。
- 已提交：关闭抽屉并打开既有内部对话；受理、执行、待回应和结果由对话展示。
- 已恢复原提交或结果未知：打开或恢复原对话并关闭抽屉，如实提示未重复发送。
- 提交前失败或未接入：抽屉保持打开，显示真实原因与复制路径，不伪装成已执行。

抽屉只展示“是否已经交接”，不展示配置成功或进度；交接后的完成状态由运行定义读取与本次对话执行事实共同判定，通过服务行状态和结果通知反馈，不在抽屉内推断。

### 4. 完成后反馈：本次执行结束 + 运行定义可读

完成判定必须同时满足两个事实：本次配置对话的执行已经正常结束，且 Buildr 能读取该服务可用的运行定义。提交成功只表示对话已创建；进程启动只表示候选可访问；智能体的文字说明可能不完整。三者都不能单独证明 Buildr 已能读取并启动这份配置。

提交成功后，服务目录、运行区或任务运行入口显示“配置中”（尚无定义）或“检查中”（已有定义），并把原入口切换为回到原对话的操作。同一页面实例在待完成期间不并发发起第二项配置交接，避免多个通知与目标混淆；页面刷新或切换入口后会失去这层界面观察，完成事实仍以运行定义读取和原对话为准。

执行结束后读取一次服务运行状态：

- 定义变为可读且执行完成：提示“运行配置已完成”，可跳到服务运行区启动。
- 定义可读但执行失败或停止：提示“已保存，执行未完成”，不宣称验证完成。
- 定义没有变化且执行完成：提示“检查完成”，说明现有配置仍可使用。
- 定义仍不可读：提示“配置尚未完成”，带上读取诊断，不显示启动入口。

结果通过轻量的 Ant Design 通知和服务行状态反馈，不阻塞对话；服务行的事实仍来自运行状态读取，刷新页面或重新进入服务页不会丢失。通知只在当前页面实例观察期间出现，属于即时补充，不成为新的权威状态。观察对话使用 3 秒一次的读取，最多等待 30 分钟；超时只停止本次观察，并提示可回到对话继续，不伪造成功或失败。

### 5. 关闭语义与无障碍

确认前关闭、取消、遮罩和 `Esc` 均不产生副作用；提交中全部关闭方式禁用并保持焦点在抽屉内。抽屉用 `role="status"` 播报“尚未执行 / 正在提交”，完整指令用原生 `details` 展开，主操作使用既有 Ant Design 按钮与 `DrawerShell`，保持键盘可达和窄屏不横向溢出。

### 6. 兼容与迁移

`AgentDiscoveryDrawer` 由新的交接抽屉替代，`AgentDiscoveryContent` 保留并扩展为两种模式共用正文，避免复制近似说明。稳定选择器改为 `#service-runtime-configuration-drawer`；现有端到端旅程中的配置段同步更新。无数据迁移；回退只需恢复入口的直接提交接线。

## Risks / Trade-offs

- [多一步确认降低一次点击的效率] → 只有配置定义缺失或需要检查时才出现，且抽屉提供单一主操作和紧凑信息；不在高频启动路径增加确认。
- [提交失败后用户重复点击] → 提交中禁用关闭与主操作，未接入或失败时保持原抽屉并明确原因；已创建或未知时先恢复原对话，不提供第二次默认提交。
- [复制入口被误认为已执行] → 两种模式都显示“尚未执行配置”，复制只改变剪贴板，完成后的查看位置保持一致。
- [抽屉与对话面板同时出现] → 提交成功或恢复时先关闭抽屉，再由对话呈现执行事实。
- [旧选择器与知识描述失效] → 同步更新端到端检查、代码地图与解释文档中的交接顺序。
- [把提交成功或进程启动当成配置完成] → 完成判定同时要求本次执行结束和运行定义可读；定义不可读时明确提示未完成。
- [观察对话增加读取或页面关闭后收不到通知] → 仅待完成期间 3 秒读取一次，最多 30 分钟；通知只是即时补充，服务行和运行区仍以运行定义读取为准。
- [待完成期间无法发起另一项配置] → 明确提示原交接仍在进行，并可从服务行回到原对话；完成或超时后恢复入口。

## Migration Plan

仅改变前端交接顺序与完成反馈，不迁移数据。既有运行定义、实例、对话和已复制内容不受影响。按任务工作树构建并在生产托管页面验证“有可用智能体”“未接入”以及“完成/未完成反馈”三种状态；若需回退，恢复入口直接提交并保留统一请求生成即可。
