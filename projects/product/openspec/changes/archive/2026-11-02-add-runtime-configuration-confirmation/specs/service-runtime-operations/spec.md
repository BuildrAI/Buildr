## MODIFIED Requirements

### Requirement: 运行配置按内部智能体可用性交接

服务目录、服务详情和任务本地运行的配置入口 MUST 使用同一交接语义。用户触发配置入口时，Buildr Web MUST 先打开统一的配置交接抽屉，说明目标服务与工作空间、智能体将完成的步骤、本次允许的影响、配置完成标准和完成后查看真实配置的位置；完整请求 MUST 可按需展开，并可在展开处复制。在用户明确确认“开始配置”之前，页面 MUST NOT 创建对话、提交请求或修改 `services/<service-code>/runtime.yml`。

用户确认后，存在已启用且就绪的可用执行入口时，Buildr Web MUST 直接提交本次配置请求并打开现有内部对话展示真实执行过程，不得再要求用户复制同一段请求。没有可用执行入口或可用性读取失败且尚未提交执行时，MUST 在同一抽屉内保留复制交接并明确尚未执行，不得伪装成已经执行。

配置提交 MUST 复用内部对话现有的智能体、模型、权限和恢复选择，不得建立运行配置专用执行状态或绕过既有授权。提交期间 MUST 防止同一动作重复提交；提交前的可用性、提交中和未创建执行前的失败反馈 MUST 在交接抽屉内可见。已经创建对话、恢复原提交或提交结果未知时，MUST 打开或恢复对应对话、关闭交接抽屉并如实反馈，不得静默重复提交或以复制交接替代原执行。

关闭或取消交接抽屉 MUST NOT 创建对话、提交请求或修改运行定义。交接抽屉的说明也 MUST NOT 被当作配置已经验证、进程已经就绪或业务验证完成。

#### Scenario: 打开入口先交代再执行

- **WHEN** 用户从任一服务运行配置入口触发操作
- **THEN** 页面打开配置交接抽屉，显示目标服务、智能体将完成的步骤、本次允许的影响和完成后的查看位置，并保持“尚未执行”
- **AND** 此时不创建对话、不提交请求、不修改 `services/<service-code>/runtime.yml`

#### Scenario: 已接入时直接配置

- **WHEN** 用户在交接抽屉中确认开始配置，且当前存在已启用且就绪的内部智能体
- **THEN** Buildr 直接提交一次绑定当前工作空间和服务的配置请求，打开现有内部对话展示受理、执行、待回应和结果状态，并关闭交接抽屉，不要求用户复制同一段请求

#### Scenario: 取消或关闭不产生执行

- **WHEN** 用户在确认前关闭或取消交接抽屉
- **THEN** 页面不创建对话、不提交请求、不修改运行定义，入口保持可再次发起

#### Scenario: 未接入时保留复制

- **WHEN** 用户确认开始配置，但当前没有可用内部智能体，或提交前读取失败且尚未创建配置执行
- **THEN** 交接抽屉保持打开并明确尚未执行，说明真实原因，将复制同一配置请求作为可用操作交给外部智能体

#### Scenario: 提交结果未知

- **WHEN** 配置请求已经创建对话、恢复了原提交或提交响应未能确认
- **THEN** 页面打开或恢复对应对话并关闭交接抽屉，如实展示原提交的状态，不自动生成另一次执行，也不把复制指令作为默认下一步

#### Scenario: 重复点击配置

- **WHEN** 用户在一次配置提交尚未完成时再次确认配置入口或提交动作
- **THEN** 页面不提交第二个相同请求，并继续在交接抽屉中显示原动作的真实状态

## ADDED Requirements

### Requirement: 运行配置完成以运行定义可读为准

运行配置的完成状态 MUST 由两个可核对事实共同决定：本次配置对话中的执行已经正常结束，且 Buildr 能读取该服务可用的运行定义（`services/<service-code>/runtime.yml` 校验通过，`definitionDiagnostic` 为空）。提交成功、对话创建、进程启动或智能体口头说明 MUST NOT 单独作为配置完成依据。

交接成功后，服务目录、服务运行区和任务本地运行 MUST 在本次页面观察内显示“配置中”（尚无运行定义）或“检查中”（已有运行定义），并允许用户回到原对话。同一页面实例在待完成交接结束前 MUST NOT 再次发起新的配置交接，并应说明原交接仍在进行。页面刷新或重新进入后，以原对话和运行定义读取恢复事实，不伪造完成。

配置完成时，Buildr Web MUST 明确反馈“运行配置已完成”，让用户能从服务页启动或查看真实配置。已有运行定义在本次执行后没有变化时，MUST 说明配置检查完成且现有配置仍可使用；执行结束但运行定义仍不可读时，MUST 反馈“配置尚未完成”并说明读取诊断，不得显示成功；执行未正常结束但运行定义已可读取时，MUST 说明配置已保存但验证未完成。

完成反馈 MUST NOT 表示服务已经启动、进程已经就绪或业务验证通过。完成状态只用于本次交接的界面反馈，MUST NOT 新增运行配置专用后端状态、修改运行定义格式或替代既有运行事实读取。

#### Scenario: 首次配置完成

- **WHEN** 本次配置对话中的执行已经结束，且 Buildr 读到该服务新保存的有效运行定义
- **THEN** 页面提示“运行配置已完成”，服务目录显示“未运行”并提供“启动”，不把完成等同于服务已启动或业务验证通过

#### Scenario: 配置执行结束但定义不可读

- **WHEN** 本次配置对话已经结束，但 Buildr 仍读不到该服务的有效运行定义
- **THEN** 页面提示“配置尚未完成”并说明读取诊断，服务页保持“未配置运行定义”，不显示成功或启动入口

#### Scenario: 已有配置检查未变化

- **WHEN** 本次配置对话执行完成，运行定义与交接前一致
- **THEN** 页面说明配置检查完成、运行定义未变化且现有配置仍可使用，不宣称产生了新的配置

#### Scenario: 配置执行未正常结束

- **WHEN** 本次配置对话以停止或失败结束，且运行定义已经可读取
- **THEN** 页面说明配置已保存但本次执行未正常完成，提示用户查看对话中的验证范围和剩余事项，不显示“运行配置已完成”
