## Context
文字和附件草稿已保存在 sessionStorage；列表由宿主转发给智能体服务 SQLite 查询并按游标分页。欢迎区旧选择器要求直接子节点，而保留消息节点引入了 ac-transcript 包装。

## Goals / Non-Goals
目标：准确发现已有对话未发送的非空白文字或附件，保留现有活动优先级，分页一致，恢复欢迎区居中。
非目标：跨设备同步草稿、新增空草稿列表项、修改活动状态或提醒数量、发送未授权内容。

## Decisions
- 从当前 profile 的现有文字/附件存储派生草稿 ID 集合，并对当前页内存变动通知订阅者；只在集合变化时重读列表。存储不可用时仍保留当前页已知事实，不影响输入发送。
- 现有数据库对话 ID 为唯一键；HTTP 可选参数 draftConversationIds 仅包含这些 ID，查询仍限定宿主登记空间。服务端绑定参数查询，优先级依次为待处理、其余活动、有草稿、普通历史；不修改持久数据和统计。无参数保持原相对顺序。
- 拒绝只重排已加载页：旧草稿会留在下一页。草稿身份集合参与游标作用域，变化时刷新分页，不静默复用过期位置。
- 草稿标识独立于真实执行状态，允许执行中同时显示有草稿；不将草稿变为待决策或通知。
- 欢迎区使用沿包装层传播的弹性布局；仅空态生效，不拉伸真实消息。

## Risks / Trade-offs
草稿属于当前标签页，不提供跨标签页或跨设备保证；无草稿正文离开浏览器。HTTP JSON 数组严格校验。集合变化重读已展开窗口而不是逐键触发请求。既有附件存储使用全局唯一对话 ID，沿用现有身份契约，不迁移数据。
