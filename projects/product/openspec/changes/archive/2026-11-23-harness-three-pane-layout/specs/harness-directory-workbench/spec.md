## MODIFIED Requirements

### Requirement: 对话工作区与对话共用导航

独立 Harness Web MUST 在对话信息流顶部将标题与消息正文左对齐，将更多操作和工作区开关放在同一内容栏的右端，开关位于更多操作右侧，不新增占位顶栏。左侧 MUST 按新建、当前对话、对话列表排序；点击当前对话不关闭工作区。右侧工作区展开时 MUST 通过统一的可调宽度分隔组件（`ResizablePanels` 与 `SplitDivider`）与对话区并排，并在桌面宽屏（>= 1172px）下支持与左侧对话列表及核心对话信息流同时展开形成三分屏，同时保证核心对话信息流保持可读最小宽度且窄宽度工作区下文件树不挤压阅读区。右侧工作区首页 MUST 提供“资源管理器”和“源代码管理”两个模块入口；打开模块后 MUST 在右侧以可独立关闭的标签呈现；“＋” MUST 在标签下方显示同一首页和所有模块，不隐藏已打开项；选择已打开模块 MUST 激活原标签，MUST NOT 重复创建或重置其内容；两个模块 MUST 能同时保持打开，切换活动标签 MUST 保留另一标签的阅读和编辑现场，关闭最后一个标签 MUST 返回首页，资源管理器不重复展示目录工具栏，完整目录位置仍可核对。

#### Scenario: 从对话进入文件或变更
- **WHEN** 用户打开工作区，先打开资源管理器，再用“＋”打开源代码管理
- **THEN** 对话仍在左侧，右侧 MUST 同时保留两个模块标签；切换时不丢弃未保存的输入，关闭任一标签不关闭另一标签

#### Scenario: 拖拽调节工作区宽度并保持三分屏协作
- **WHEN** 用户在桌面三分屏模式下打开右侧工作区并将工作区分隔条向左或向右拖拽
- **THEN** 工作区与对话区域 MUST 顺滑调整宽度并保留已打开标签与编辑状态，核心对话信息流始终保持不低于 520px，且当工作区缩窄到 560px 以下时资源管理器文件树按工作区宽度自适应而不挤扁阅读区域
