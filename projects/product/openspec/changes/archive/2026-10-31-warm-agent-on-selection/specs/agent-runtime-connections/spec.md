## ADDED Requirements

### Requirement: 选择智能体后可提前准备准确连接

Buildr MUST 在可见对话输入区域具备有效智能体（Agent）及模型配置时支持提前准备对应原生连接。准备 MUST 不提交用户工作、不推理、不执行工具、不提前确认指令送达、不产生可见空对话。发送 MUST 重新校验程序、账号、目录、模型与权限身份，并仅采用准确匹配的准备结果；准备失败或不存在 MUST 不阻断正常冷启动。

#### Scenario: 选择后发送复用准备连接
- **WHEN** 用户选择已接入的 Qoder 和 GPT，完成准备后发送
- **THEN** 首次工作 MUST 使用同一原生连接，准备阶段的工作输入和推理次数 MUST 为零

#### Scenario: 选择配置变化
- **WHEN** 准备后用户改变目录、账号、模型或权限
- **THEN** 旧准备 MUST 不得用于新配置，正常发送 MUST 使用准确配置

#### Scenario: 初始化已有账号和模型观察
- **WHEN** 同一原生初始化返回可验证账号与模型列表
- **THEN** 接入 MUST 复用该次观察，MUST NOT 紧接着为同一次准备重复查询；热接续仍须在输入前校验当前账号与模型

### Requirement: 预启动与已使用资源按连续空闲回收

Buildr MUST 对选择准备及采用后的自有连接提供默认30分钟连续空闲回收，最多一分钟检查间隔；准备完成或工作结束开始计时，普通观察和目录检查 MUST 不续期。执行、未结工具、待回答问题和未经准确证明释放的资源 MUST 不因超时中断。并发发送与关闭 MUST 保持准确归属；断开、升级和退出 MUST 覆盖未采用准备，失败保留未确认事实。

#### Scenario: 预启动后未使用
- **WHEN** 准备成功后连续空闲30分钟
- **THEN** 后台 MUST 关闭准确自有连接并释放相应模型绑定，不删除账号、历史或用户数据

#### Scenario: 长时间执行或等待
- **WHEN** 超过30分钟仍有执行、工具或待回答问题
- **THEN** 超时回收 MUST 不停止该工作或清除问题

#### Scenario: 回收后再次发送
- **WHEN** 资源已回收且用户再次发送
- **THEN** Buildr MUST 按原准确上下文冷恢复，不重发旧要求
