## Context

见 proposal.md。现有注册表（Registry）、选择器（Planner）、执行器（Executor）已能表达检查归属、依赖、资源、阶段与清理；缺口是跨执行结果复用和原包交接。候选聚合把每项结果绑定同一提交及远端运行，本机结果不能进入；DSH 在源码候选与主分支准备分别完整验证、打包。日常远端反馈只有合并请求触发，本轮直接交付 dev 没有提前反馈。

## Goals / Non-Goals

**Goals:**

- 同一有效输入的源码检查在本机默认复用；发布准备可以消费合法本机或已有远端结果，只执行缺项。
- 完整候选保留全部 required owner 和平台覆盖；来源、执行、复用、准备与清理均可解释。
- 主包及 DSH 各自只有一份最终原包，受保护纳入和公开副作用继续独立核验。
- 实测执行次数与恢复范围下降；不把远端完整检查变为开发时的新强制等待。

**Non-Goals:**

- 不建设通用测试服务、签名机构、许可系统或新任务状态；不把普通任务验证报告当作可执行结果证明。
- 不降低平台、真实安装、迁移和恢复覆盖，不提高超时预算换通过，不扩展公开发布授权。

## Decisions

### 1. 在现有执行入口复用步骤结果

扩展 executePlan，在计算必要测试上下文前查找可复用源码结果，依赖图仍保留所有节点；命中节点明确返回 reusedFrom，不伪造新进程、日志或执行耗时。没有可信输入范围的检查按保守完整相关内容计算身份，不能直接把 changed 选择映射当作完整依赖证明。

结果记录输入内容、检查配方、环境、实际来源和清理事实。提交与运行编号用于追溯；读取 Git 历史、引用或提交身份的检查必须纳入对应 Git 输入，未知时保守不复用。有输出被后续消费的准备与生成步骤必须保证输出仍存在且匹配，或禁用结果复用。最终包生产和消费不进入普通源码结果缓存。

缓存由现有运行器维护在系统临时目录，按真实 Git 公共目录隔离并跨本任务工作树共享；丢失只导致重新执行。显式导入/导出可搬运结果，强制诊断关闭读取。仅完整通过、输入前后一致且清理干净的结果可保留；新失败、输入漂移或清理失败使同身份旧成功失效。

替代方案是继续绑定 HEAD/run，成本无法下降；或仅按 changed 路径复用，但缺少依赖闭包，可能错误放行。

已核对的八个运行步骤使用完整代码与源资产范围，排除 Product knowledge/openspec/tasks 的行政内容；治理检查及未知步骤继续保守覆盖。依赖安装身份排除 Web tsconfig 明确声明的两份增量编译缓存，保留其他未知文件和真实模块变化。源码分片按声明的同一操作系统接受证明，保留原架构，不声称在另一处理器执行；最终宿主与原包矩阵仍真实运行。

### 2. 受控候选消费本机结果并补齐覆盖

本机准备可以对冻结内容运行完整适用源码检查，并导出同一运行器生成的精简结果。发布编排读取这些结果与缓存，经受控 workflow_dispatch 传入候选；普通外部合并请求不能通过提交手写布尔值跳过检查。输入采用有严格体积限制的压缩 JSON，超限在派发前明确报告，不能静默丢弃证明后意外整套重跑。

远端计划先核对当前内容、配方和结果原环境，再省去已经证明的源码检查及其专属准备。核对者所在平台不能被误当成原执行平台；源码运行时需满足声明范围并保留实际版本，宿主最低/当前版本能力由独立包消费矩阵证明。平台不同、必要工具/SDK或对端不匹配只使相关结果失效。

最终外层候选仍绑定准确选择、当前运行及原包；内部源码结果保留原执行来源。聚合区分本次执行和复用，并拒绝失败、缺项、漂移、伪造结构或不完整证明。局部失败保留绿色结果；修复后仅重新执行真实受影响输入。远端前置环境失败必须上传已有 operations，说明检查未运行。

替代方案是把完整远端候选移到每次开发，仍保留远端长等待；或接受任意聊天/手工报告，会失去实际执行依据。

### 3. 最终包只生产一次

主包继续由唯一生产者形成最终压缩包，后续消费者只下载原包。源码结果相同不代表包含源码身份的包字节相同；最终提交、内容或入包身份变化时重新生产并验证对应新包，匹配源码结果仍可复用。

DSH verify 作业成为其最终原包唯一生产者。main prepare 接收 source_candidate_run_id、source_commit 和 selection_identity，下载候选及原聚合，核对固定 SDK、准确主包对端、完整检查和字节，再证明受保护 main 第一父/第二父及整树纳入关系。接纳时原 candidate.json 与压缩包不改写，不再 verify-all/build/pack。candidate_run_id 继续指向 main 上的接纳运行，可信发布的 OIDC/GITHUB_SHA 继续绑定真实 main；被测源码身份与纳入提交分别保留。已有旧 prepare 运行按原协议恢复。

### 4. 保留事实并降低准备成本

准备、执行与清理分开记录。子检查原退出结果不能因清理失败被覆盖；最终动作仍可失败，但明确检查是否已通过。超时显示内外限时、最后阶段/用例和清理结果，不把包装断言误判成真实业务断言；外层超时与之前真实子断言失败同时存在时，两项事实都保留。暂态恢复只重试必要失败作业且有界；未知先定位。

发布恢复测试共享同一顶层测试的临时包内容缓存，仍执行全部真实离线安装，安装目录与其他可变状态逐例隔离。缓存可能被 npm 更新，不宣称物理只读；不共享可变仓库或安装前缀。

## Risks / Trade-offs

- 输入声明遗漏导致错误复用 → 默认完整相关内容；Git、环境与产物敏感检查保守纳入必要事实，新增步骤未知时不自动开放。
- 结果被当作另一平台/版本证明 → 保存原环境并按明确检查要求匹配；实际宿主矩阵独立保留。
- 本机通过被误当成最终包通过 → 源码与原包身份分开；包消费不从源码结果推导。
- 故障被掩盖为缓存命中 → 强制执行可关闭复用，新失败失效旧成功，输出明确原来源。
- 工作流边界迁移破坏旧发布恢复 → 旧证据协议保留读取，新行为只应用新准备；不修改既有公开事实。

## Migration Plan

先实现和验证输入匹配、执行复用及故障表示，再接本机准备与远端计划；随后统一 DSH 原包接纳。按实际稳定入口同步说明和测试地图，运行受影响检查、完整低成本回归及独立审查。使用隔离候选和无公开副作用验证；本轮不发布产品。部署后可通过强制执行关闭结果读取，保留原检查入口诊断，不能修改失败历史或移动已发布引用。
