# 源代码管理首版

按已确认原型补齐“代码”中的源代码管理，使工作空间全部登记代码库的改动、历史和文件可以直接查看。整体目标及授权见[任务说明](@task/code-source-control)。

共享界面从模拟数据接入确定性只读观察：各库保留实际身份，依据Git清单列出主目录及全部关联工作树，各来源的变更与版本独立。代码库、工作树和比较层可折叠展开，跨库同名工作树可联合过滤，两种模式选中清楚。暂存内容读取索引对象，历史固定完整提交；名称聚合只组织查看，任务关联只认明确身份和有效尾注。上下和中右分屏可拖动，完整提交信息按需悬停，不增加提交、回滚、远端操作或任意目录选择。

已有任务内的“改动与提交”继续提供原来的查看。任务与全局源代码管理只有准确来源的双向入口，不复制或替代详情；任务入口可预选已确认代码库和工作树，返回保留任务阶段和选择。完整文件保持同一来源，缺失、读取上限与局部失败如实说明。此前首版未展示其他工作树的范围缺口已由用户指出，本轮重新验证该覆盖，不沿用旧版通过结论冒充新版证据。

产品能力不迁移任务或Git状态，不提供Git写入，也不发布。用户审看修正版后明确要求收尾；按既有授权完成本任务的常规交付与适用自举激活，组合任务保持进行中。集成沿用最新资源管理器的共享检出身份和过滤能力，源代码管理进入当前文件时显式传递同一身份。验证以真实分层改动、分支历史、固定版本、边界错误和实际浏览器操作为依据。原型见同目录 `prototypes/source-control.html`，实现及取舍见 `design.md`。

当前知识影响：现有产品概览与项目／服务／代码库关系含义不变，不需改写。若技术地图仍把代码区域描述为占位，应提出有界校准建议；本轮不扩大为整体知识建设。

已核对 `knowledge/docs/overview.md`、`knowledge/code-map/README.md` 与 `knowledge/code-map/technical-layers.md`：现有职责和装配说明仍成立，未发现需要替换的源代码管理占位说明。具体校准建议是在下一次技术地图维护中补充代码观察应用（Code Observation Application）的定位：`services/buildr/src/modules/code/` 共享只读命令行与网页能力，`services/buildr-web/src/features/code/` 装配真实页面和阅读器；解释暂存、当前文件与固定提交三个来源及显式任务尾注关联。本轮已在实现文档与技能参考中说明这些边界，不新增整体知识建设。
