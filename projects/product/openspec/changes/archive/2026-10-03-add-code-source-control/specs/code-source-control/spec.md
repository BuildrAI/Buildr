## Purpose

定义工作空间（Workspace）全部已登记代码库实例（Repository Instance）的只读源代码管理能力，使人和智能体（Agent）以明确身份、目录、比较层及固定版本查看当前改动、提交历史和完整文件，保持局部失败可辨认且不产生Git写入。

## ADDED Requirements

### Requirement: 全部代码库真实清单

源代码管理 MUST 展示当前工作空间全部已登记代码库实例，每个稳定身份只列一次，不按服务数量或远端地址归并。清单 MUST 表达已观察目录、当前分支或游离提交、按路径去重的未提交文件数、可得的本机上游领先／落后数、读取时间及局部诊断；未知数量 MUST NOT 表达为零或“已同步”。普通入口 MUST NOT 自动限定任务范围。

每个代码库 MUST 展示Git实际登记的主目录及全部关联工作树（Worktree），分别表达真实分支、目录、分层变更和观察版本，不因没有Buildr任务登记而遗漏。工作树计数 MUST 在本来源内按路径去重，代码库汇总 MUST 保留不同工作树的同名路径。代码库、工作树和比较层 MUST 可折叠展开，折叠 MUST NOT 清除仍有效的文件选择或已打开正文。

#### Scenario: 多个服务引用一个实例
- **WHEN** 多个服务引用相同代码库实例
- **THEN** 清单 MUST 只展示该实例一次，保留其实际身份和目录

#### Scenario: 单库不可读取
- **WHEN** 登记中的一个目录缺失、身份变化或Git状态暂不可读取
- **THEN** 清单 MUST 保留该实例及原因，其他库已读取内容仍可查看，不把错误表达为干净目录

#### Scenario: 同库多个工作树
- **WHEN** 同一登记代码库具有主目录及多个Git关联工作树，包括未登记为Buildr任务的来源
- **THEN** 清单 MUST 在同一代码库下列出全部来源，各自展示实际分支和分层变更
- **AND** 一个工作树不可读取 MUST 只影响该来源，其他来源的变更仍可查看

#### Scenario: 折叠后继续阅读
- **WHEN** 用户打开文件后折叠代码库、工作树或暂存／未暂存分组，再展开或刷新
- **THEN** 系统 MUST 保留仍有效的选择、已打开正文及分组状态，不因折叠改读其他来源

#### Scenario: 跨代码库工作树过滤
- **WHEN** 两个登记代码库具有同名工作树，用户选择该工作树名称
- **THEN** 变更范围 MUST 聚合各库同名来源，并可与代码库筛选联合；清除过滤 MUST 恢复全部可用来源
- **AND** 同名聚合 MUST NOT 替代独立来源标识或凭名称形成任务关联

### Requirement: 比较层与版本准确

未提交变更 MUST 分别展示已暂存、未暂存和未跟踪文件；同路径在已暂存与未暂存层 MUST 独立选择，计数按路径去重。差异 MUST 分别比较上次提交与索引、索引与当前文件、空内容与新文件，根提交和空仓库 MUST 适用；完整文件 MUST 读取所选层的实际内容，不能将当前磁盘内容标为暂存版本。结果 MUST 保留来源、比较层、相对路径、观察版本及完整性边界。

#### Scenario: 一个文件同时暂存及继续编辑
- **WHEN** 同一文件的索引内容和当前文件均已变化
- **THEN** 用户 MUST 能分别查看两层正确差异和全文；两次选择 MUST NOT 互相覆盖或混读

#### Scenario: 不同工作树的同名文件
- **WHEN** 同一代码库的两个工作树在相同相对路径拥有不同暂存内容与当前内容
- **THEN** 差异、全文及“查看当前文件” MUST 始终读取所选工作树；旧工作树请求迟到 MUST NOT 覆盖新的来源

#### Scenario: 空仓或新文件
- **WHEN** 代码库还没有提交，或文件尚未跟踪
- **THEN** 系统 MUST 以真实已有内容形成适用新增差异，不因假定HEAD存在而使整库失败

### Requirement: 本机历史与固定提交

系统 MUST 按所选代码库读取本机可达提交历史，支持本机分支范围及关键词查找，表达有限读取范围；分支范围 MUST 按其可达提交确定，不能只匹配指向分支尖端的标签。提交 MUST 包含完整标识、说明、作者与时间及可得引用；选择提交后 MUST 按需读取其文件和明确比较基线，合并提交首版使用第一父提交。历史文件和差异 MUST 固定到完整提交标识；缺失对象 MUST 明示，不静默改读当前版本。

#### Scenario: 分支包含祖先提交
- **WHEN** 用户选择一个本机分支
- **THEN** 历史 MUST 包含其读取范围内的祖先提交，不仅列出带该分支名的尖端提交

#### Scenario: 合并或根提交
- **WHEN** 用户选择合并提交或无父提交的根提交
- **THEN** 系统 MUST 返回适用的文件变化及可解释比较基线，不能因无普通父提交而显示假空历史

### Requirement: 确定性只读能力

命令行接口（CLI）和网页接口（API） MUST 共享同一只读应用能力，输入明确工作空间、登记实例、可选Git真实枚举的工作树标识、已核对任务位置、文件路径、比较层和历史标识。服务端 MUST 按Git当前工作树清单及公共目录重新验证工作树标识，MUST 拒绝伪造、已移除或被其他来源替换的标识，以及未登记实例、路径穿越、越界符号链接、Git管理目录及无效版本。读结果 MUST 表达各库、工作树及内容上限、截断、非文本和局部失败，MUST NOT 执行Git写入、隐式抓取、克隆或任务记录修改。

#### Scenario: 网页与智能体核对相同现场
- **WHEN** 两个入口以相同实例、来源和版本读取
- **THEN** 两者 MUST 得到同一观察语义及版本边界，不另建第二份代码事实

#### Scenario: 越界请求
- **WHEN** 请求使用绝对路径、越界相对路径、越界符号链接或任意Git管理路径
- **THEN** 系统 MUST 拒绝该读取且保持文件、索引、引用和任务不变

### Requirement: 任务关联与原有查看保留

提交到任务的关联 MUST 只接受有效且唯一的 `Buildr-Task` 尾注及可核对任务身份；正文示例、冲突或无效标记 MUST NOT 形成可点击关联。任务内“改动与提交” MUST 保持其当前改动、任务提交、提交详情、差异及完整文件查看，全局源代码管理只补充查看，不替换该标签。进入代码或任务并返回时 MUST 保留仍有效的原选择与阅读现场。

#### Scenario: 明确任务尾注
- **WHEN** 所选提交末尾存在有效任务尾注且对应任务可读取
- **THEN** 完整提交信息 MUST 提供该任务的准确入口；返回源码后保留所选提交和文件

#### Scenario: 保留任务内查看
- **WHEN** 用户选择任务“改动与提交”
- **THEN** 系统 MUST 在原任务阅读区展示原有工作台，不跳到全局页面

#### Scenario: 任务与源码双向关联
- **WHEN** 用户从任务入口查看全局源代码管理
- **THEN** 全局页面 MUST 依据该任务已确认范围和来源预选代码库及工作树，并提供返回该任务的入口
- **AND** 返回 MUST 保留原任务内容标签及仍有效的文件选择；全局页面 MUST NOT 复制或替代原任务详情

### Requirement: 共享分屏和按需信息

正式页面和已批准原型 MUST 复用同一界面组件及Buildr主题。中屏代码库与下方变更／历史 MUST 可拖动调高，中屏与右阅读区 MUST 可拖动调宽、分别滚动，恢复分屏保留尺寸和选择。完整提交信息 MUST 按需悬停或聚焦显示，支持移入停留、选择文字和复制，不占固定阅读空间；实际来源 MUST 清楚可见，允许选择已枚举工作树，MUST NOT 新增任意目录选择或Git写入按钮。“未提交变更”和“提交历史” MUST 通过既有主题的选中样式清楚区分当前模式。

#### Scenario: 两种模式清楚区分
- **WHEN** 用户切换未提交变更或提交历史
- **THEN** 当前模式 MUST 有清楚的选中语义与视觉状态，沿用Buildr已有导航主题，非选中项仍可操作

#### Scenario: 调整并恢复阅读
- **WHEN** 用户拖动两个分隔线，展开阅读后恢复
- **THEN** 组件 MUST 保留所选文件或提交与已调尺寸，不产生额外空白带

#### Scenario: 从悬浮信息复制
- **WHEN** 用户悬停提交或信息按钮并将鼠标移入信息层
- **THEN** 信息层 MUST 保持可操作，文字可选择、完整信息及提交标识可复制；离开或跳转后适时关闭

#### Scenario: 工作概览组合任务
- **WHEN** 工作概览显示已登记为组合任务的条目
- **THEN** 标题旁 MUST 显示与任务列表和详情一致的组合任务标记，并保留原有子任务数量
