## Context

现有 `workspace` 模块以项目为服务集合的父对象；`Service.source` 同时承担代码位置与 Git 声明。服务页面仅有行内详情链接，项目主页未提供关系编辑。原型已验证创建项目、抽屉新增服务、抽屉内新增代码库、回填、取消恢复及缺失代码状态。用户随后确认统一列表、主页和编辑入口。

## Goals / Non-Goals

**Goals:** 以可移植清单保存稳定事实，三类对象分别维护；人和智能体（Agent）操作相同对象及当前版本，目录状态局部诊断。

**Non-Goals:** 不新增部署管理、代码托管、自动分支切换或第四种检出目录业务对象；不操作集鲜业务代码，不自动迁移用户现有物理目录，不改写已完成任务历史。

## Decisions

### 关系与唯一事实

- `projects/manifest.yml` 的项目（Project）条目增加 `serviceIds`，允许空集合。
- `services/manifest.yml` 维护全局服务（Service）：稳定标识、名称、说明、类型、唯一 `repositoryId`、可选相对模块目录。业务规则放 `services/<code>/AGENTS.md`。
- `repositories/manifest.yml` 维护代码库实例（Repository Instance）：稳定标识、代码、名称、说明和来源。Git 来源包含地址、远端、集成分支；默认位置为 `repositories/<code>`。外部附接目录及旧位置继续显式表达。
- 本地检出目录（Checkout）是实例的物理位置，登记成立不要求代码已准备。工作空间内源码继续支持 `workspace` 来源，不能为同仓模块虚构远端或分支。
- 使用稳定标识关联。反向关系派生。相同 Git 地址、甚至相同分支，不足以证明实例身份相同，不自动合并。

### 应用与持久化

在现有 `src/modules/workspace/` 内增加对象关系领域规则、全局清单存取和有界应用用例，复用既有路径校验、版本摘要和工作空间写入事务。接口入口负责请求与响应契约，不直接读写清单。单对象修改、项目服务关联、新建项目及嵌套草稿保存均核对已观察版本；对象引用必须在事务内重新验证。新建代码库只是登记，不在 HTTP 表单保存中克隆。

旧模型通过显式兼容读取投影；不能形成新旧双写。旧路径和任务引用通过保留的旧定位映射到稳定身份。普通读取零写入。共享代码变动涉及的检查由智能体依据实际依赖判断，不以所有关联项目的数量替代验收。

### 一致交互

项目、服务、代码库、技能：点击名称或行进入主页；行内编辑不触发行导航；主页提供同名编辑入口；同一对象使用同一编辑抽屉和保存逻辑。保留键盘链接、列表筛选、滚动位置和草稿。项目（Project）保留主标签；从全局目录查看服务（Service）、代码库（Repository Instance）和技能（Skill）时按类型复用副屏详情标签，切换同类条目只更新内容，不新增主标签。从项目（Project）打开关联服务及其代码库时，同样复用副屏详情；主屏项目卡片和已有文档标签保持不变。对象打开、切换和关闭写入浏览器历史，可前进、后退恢复。保存更新当前列表与主页，失败保留输入，版本冲突提示重读。

项目主页的关联服务区提供“关联服务”，选择已有对象、就地新增、解除关联；解除只修改项目引用，不删除服务或代码。服务主页展示唯一代码库和引用项目；代码库主页展示引用服务、来源、声明分支与真实位置状态。

创建项目采用右侧抽屉；服务和代码库选择统一使用共用组件，按“过滤输入 → 左对齐新增动作 → 已有选项”排列。新增服务打开子抽屉，新增代码库在服务抽屉内展开表单。新增对象先保留为草稿，返回项目后统一保存，避免取消项目留下意外登记；独立新增服务则在自身提交时保存。项目可以不关联服务。

技能（Skill）保持既有源资产及受管边界。统一“编辑”发现入口，能直接修改的字段使用已有安全动作，不能直接修改的受管内容展示原因并交接智能体，不把按钮一致理解为允许篡改受管区块。

### 智能体发现与代码准备

任务先读取项目引用、服务的代码库引用和实例声明，再加载明确项目业务规则、服务实现规则和代码目录适用规则。多个引用项目的规则不自动拼接。已有声明而目录缺失时，在已授权任务内核对远端和分支，克隆至 `repositories/<code>/`；已有目录只核对身份与当前状态，不覆盖、清空或擅自切换分支。来源缺失不得猜测；准备失败只阻止依赖该代码的动作。技能负责过程，核心规则只保存身份、授权和内容保护边界。

### 源码职责地图

| 层 | 位置 | 责任 |
|---|---|---|
| 领域（Domain） | `src/modules/workspace/domain/` | 对象身份、关联基数、字段和安全路径 |
| 持久化（Persistence） | `src/modules/workspace/persistence/` | 清单格式、摘要、兼容读取 |
| 应用（Application） | `src/modules/workspace/application/` | 查询、创建、更新、关联及迁移事务 |
| 接口（Interface） | `src/modules/workspace/interfaces/` | CLI、HTTP、公开契约 |
| 前端 | `buildr-web/src/features/{project,service,repository,skills}/` | 对象主页、列表与抽屉；实际技能目录沿用现有结构 |

## Risks / Trade-offs

- 旧服务兼有业务和代码身份 → 保留原身份与旧定位，不自动推断集鲜具体业务划分。
- 多清单并发写入 → 复用事务与版本比较，悬空引用只报告相关对象。
- 分离目录后遗漏规则 → 明确关系发现指引，保留实际祖先规则，不靠工作目录猜项目。
- 新旧定位消费者遗漏 → 覆盖任务、诊断、准备、验证、导航与旧链接回归。
- 嵌套创建中途取消 → 草稿保留但不写真实清单，提交后展示代码待准备状态。

## Migration Plan

预检现有清单、标识冲突、实际路径和仓库边界；提供只读计划。显式执行将旧源信息移入代码库实例、旧服务转为全局登记并建立项目引用；保留旧身份、历史定位及物理位置。所有清单写入与旧登记退役位于同一可恢复事务；失败不接受半完成状态。普通读取和启动不迁移；代码目录移动必须另行核对真实 Git 边界。迁移后验证旧任务可定位、共享引用成立、两个不同分支实例未合并。

## 2026-09-16 界面复核修订

用户指出原实现存在服务主页技术信息过重、文档就地展开、目录表头与样式不一致等问题；先前功能测试通过不能代表界面验收完成。主用户是维护工作资产并与智能体协作的人，主要任务是识别对象、理解关系、阅读材料和发起明确操作。

- 相似律（Law of Similarity）：四类目录共享标题、说明、搜索、数量、表头、行密度与固定操作列，仅业务字段不同。列表名称为键盘可达链接，行内操作不触发行导航。
- 认知负荷（Cognitive Load）：主页先呈现职责与关系；服务代码库只保留名称、分支、状态摘要，完整来源与路径留在代码库主页。原始声明和长指令不在主页铺开。
- 共同区域定律（Law of Common Region）：四类详情统一使用概览卡片与内容分组卡片；在分组内使用行、间距和轻分隔，避免重复套卡片，编辑动作靠近作用对象。图标按含义区分：项目为文件夹，服务为应用网格，代码库为分支，技能为闪电，每日演进为历史记录。
- 项目（Project）保留主标签作为持续工作上下文；全局目录中的服务（Service）、代码库（Repository Instance）、技能（Skill）分别复用“服务详情”“代码库详情”“技能详情”副屏标签。同类条目替换当前内容，主列表保留搜索与滚动；直接访问对象链接时进入对应目录并打开详情。旧版本持久化的对象主标签不再恢复。
- 项目上下文内也在副屏打开服务、代码库；不替换主屏项目卡片，不收起已有文档副屏。通过浏览器历史状态恢复对象视图；从项目目录进入时回到项目主页，切换已有项目标签时保留该标签状态。
- 项目文档使用副屏；副屏详情中的文档在同一详情标签内阅读，提供“返回详情”，不创建第三分屏或新的主标签。编辑、创建、关联与准备代码使用抽屉。窄屏退化为有遮罩的覆盖式详情区，关闭恢复主列表。
- 目录始终保留完整业务列；分屏或窄屏通过表格内部横向滚动访问全部字段，编辑列固定在右侧。
- 验收同时包括桌面并排截图、窄屏覆盖、四类目录逐页对比、保存和取消、文档副屏与代码准备抽屉，不以构建成功替代体验复核。

- 解除关联使用行尾叉号，悬停或键盘聚焦可见，触屏常显；点击直接提交当前版本，不弹确认框，失败显示原因，不删除服务及代码库。桌面菜单可折叠为图标栏，保留名称提示、键盘访问和折叠偏好；窄屏保留原导航抽屉。

关联服务以完整背景条目表达一个对象，行尾解除按钮属于该条目，去除多余右箭头。四类目录共用刷新入口，主动作统一为“新增 xxx”且不额外加加号；刷新保留筛选。

代码库来源变更仍为设计讨论，未纳入本次已实现范围：建议独立展示共享引用影响，核对真实代码状态后应用明确的 Git 地址或分支变更。若只是另一业务需要不同长期分支，应新增隔离实例并修改引用，不改变已有共享实例。当前实现仍只允许编辑代码库名称与说明。

菜单对应的目录和设置页不再显示主标签，仅过滤标签显示，保留目录页面缓存、筛选和导航状态；项目与副屏标签保持原行为。Git 地址和分支变更按用户要求暂不实施，本轮范围到上述界面细节为止。
