# 项目、服务与代码库解耦

让项目（Project）引用业务服务（Service），让多个服务共用一个代码库实例（Repository Instance），并统一列表、主页和编辑体验。

## 背景与目标

当前模型把业务能力、项目归属和代码位置绑在一起。新的模型将业务与代码基础分开，支持相同 Git 地址的不同分支实例以及多个业务共用代码；人和智能体（Agent）从同一清单定位工作。

## 使用流程

创建项目时可以暂不关联服务；选择服务列表中的左对齐入口可新增服务，在服务抽屉内可新增代码库，完成后逐级回填。项目主页可以随时维护服务关联。项目、服务、代码库和技能的列表条目进入主页，列表与主页均提供一致编辑入口。

## 边界与兼容

代码登记不等于代码已准备。缺失目录时由智能体按照声明在 `repositories/` 准备；已有内容不覆盖、不擅自切换分支。旧登记通过兼容读取和显式迁移处理，不自动合并同源实例或搬迁用户代码。本任务不发布，不操作集鲜真实仓库。

## 验收与风险

重点验收共享关系基数、解除关联不删除代码、两处编辑一致、取消保留草稿、陈旧版本不覆盖、迁移保留历史定位和局部代码缺失不阻塞无关工作。
