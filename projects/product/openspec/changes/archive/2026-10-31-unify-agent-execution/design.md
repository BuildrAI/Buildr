## Context

现有公共执行契约已隔离原生内核与 Buildr。缺口发生在原生事件转成统一事实、跨模型协议转换和事实呈现，而非缺少另一套推理或团队编排器。问题记录与旧候选见 proposal；旧候选不作为已通过实现。

## Goals / Non-Goals

**Goals:** 三家共用输入身份、消息归属、业务提问及执行观察语义；各适配器保留真实原生来源。修复跨协议参数丢失、子报告重复、分组与内部存档泄漏，并减少已证实的重复初始化。

**Non-Goals:** 不将目标完成等同原生轮结束，不自动回答问题或审批未知请求，不用固定流程替代智能体判断，不迁移或删改历史，不改变付费账号与模型选择。

## Decisions

1. 公共条目增加可选 `parentToolId`，原始角色与稳定消息编号保留。原生子报告归属父工具，应用保存来源、主答复和交接摘录排除子报告，界面通过父工具详情查看；旧记录没有来源时不猜测。各家没有相应事件时保持原有主会话语义。相较全量新增子任务数据库，此方案只保存原生已经给出的必要事实。
2. 原生已证明的普通工具调用按本轮权限执行；业务问题始终等待真实回答，未知请求不因完全访问自动放行。Qoder 需以真实初始化工具目录等证明请求性质，不采用无限制回调批准。DSH 和 Codex 继续原生权限设置与读回路径。
3. 公共模型转换按稳定工具身份累积增量并核对完整参数事件。完整事件可以补齐尚未到达的后缀，已给出的内容冲突则局部失败。并行调用分别保存，不因相邻事件或数组位置变化混合；向下游输出的工具名称必须完整。
4. 对话展示先确定执行及用户补充分段归属，再重新合组；实时指示只属于当前最新组。保留原记录顺序和展开选择。相同执行组合另开上下文时表达继续处理新要求，不表达换模型或旧工作整体接手。
5. 未回答问题继续由原请求事实保护相关操作；问题等待结束时不额外向用户追加技术存档。内部必要保留与明确用户回答不删除，旧系统存档在展示层兼容隐藏，真实失败继续可见。
6. Qoder 原生连接与单轮执行状态分离，仅在准确上下文、目录、模型、档位及权限一致，前轮正常完成且工具、问题和追加确认均结清时复用。一个连接只有一个输入队列和读取循环，每轮独立状态及完成承诺；历史变化、配置变化、失败、中断或证据不完整时冷恢复准确原编号。读取到结果不退出迭代，迟到事件按原执行身份路由；异步检查后重新核对原轮仍结清。未结请求、工具或确认仍保护原连接，仅拒绝受影响的新输入；可安全关闭与正常完成后可复用分别判断，释放前关闭准确空闲连接并继续核对进程组。外部来源的账号/模型检查放在实际连接初始化之后、输入交付之前，避免独立重复启动。
7. 共用交互指引要求持续管理已授权目标、区分子任务启动与完成、依据成果验收；不添加新的通用批准门禁。前端留白沿用现有容器，不重做界面。

## Risks / Trade-offs

- 原生消息阶段、后台事件可能不完整 → 不猜测成功或来源；已证明结清但无法复用时关闭并准确恢复，仍有未结或未知工作时保留原控制。
- 工具完整参数与增量矛盾 → 保留错误，不以空对象或最终快照静默覆盖。
- 旧存档已混入历史 → 仅按明确的系统条目标识隐藏，不按正文或用户话语删除。
- 保留空闲原生进程可能影响更新退出 → 释放检查负责有界关闭该准确连接；仍活动或未知工作继续受保护。
- 网络时延波动 → 启动次数和本地阶段独立验证，不承诺未测得的固定秒数收益。

## Migration Plan

新增字段可选，旧记录继续读取；不迁移账号、原生编号或统一历史。候选先在任务工作树验证，不更新共享环境。原两任务的工作树保留，通过真实结果衔接，不伪造其完成。受影响的现有架构说明按最终实现维护。
