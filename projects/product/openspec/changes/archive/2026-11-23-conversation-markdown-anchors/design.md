## Context

两个宿主都使用 `conversationFileLink` 提取 HTML 锚点和代码行号。预览已保留片段，Markdown 阅读器可复用现有标题定位逻辑。

## Goals / Non-Goals

只修本机 Markdown 链接打开及章节定位；不新增文件查找回退、不读取历史或修改文件权限，不改变资源管理器的独立入口。

## Decisions

- 在共享解析器分离 Markdown 片段，优先保留已支持的 `#L<行号>`；`file:` URL 先分离再解码。相比服务端遇到失败才截断，客户端能区分原样路径和链接，并保留章节用于展示。
- 由 Markdown 预览复用现有阅读器与标题 ID，章节不匹配时仍显示原文，不另造标题规则。

## Risks / Trade-offs

字面 `#` 不应误判：工具原样路径不解析；本地文件 URL 的文件名内可以用 `%23` 表达 `#`。使用回归测试锁定两种入口共用的边界。
