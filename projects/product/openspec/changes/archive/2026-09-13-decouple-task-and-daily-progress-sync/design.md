## Context

见 [proposal.md](proposal.md)。现有 Task Record 和 Daily Progress Application 已不执行 Git 或全局同步；过度执行来自随包技能和对应规范、测试。此次不新增应用接口或流程状态。

## Goals / Non-Goals

**Goals:** 登记只依赖登记所需事实，日报只依赖明确的提交观察与合法输入，实际 Git 写入继续使用已选提供者及已有安全边界。

**Non-Goals:** 不修改外部 OpenSpec、当前认知维护能力、双语规则、Git Operations 的操作保证和数据格式；不自动归档本次变更。

## Decisions

- 任务创建和激活不执行更新基线。保留现有参考路径，但将内容收窄为记录核对与按需代码更新，避免交付映射的路径迁移。仅登记无需读取 Git 提供者；后续用户目标要求更新代码时再使用 optional 依赖。
- 日报以本次已观察的本地引用为默认范围。固定每个相关仓库的引用和完整提交标识，按目标日及时区收集；用户要求远端最新信息时独立 fetch 并直接读取所选远端引用，不要求检出或变基。
- 观察范围和截至时间通过已有 `daySummary.drawbacks` 保留；无须增加字段或另一份记录。远端不可用时明确本地范围；用户明确要求只接受远端最新数据时保留旧日报并报告缺口。
- 对既有规范使用完整条目更新，清除旧强制前置。沿用真实功能检查，删除固化旧命令顺序的断言；不建设模拟智能体平台。

## Risks / Trade-offs

- 本地范围可能落后远端 → 日报明确引用、观察时间和未确认远端状态，不声称远端最新或覆盖所有分支。
- 创建任务后仍可能暂时无法安全修改代码 → 单独说明相关动作限制，保留真实登记结果，不把记录成功解释为开发环境可用。
- 旧组织实践依赖自动更新 → 更新目标需明确表达；技能与随包描述同步调整。

## Migration Plan

修改产品源资产，完成静态与相关功能验证，再通过正常交付和自举入口投射；不手改工作空间或运行时副本。数据无需迁移，回退只涉及源资产，不回滚已经成立的任务或日报。
