## Context

见 proposal.md。既有任务节点从关联变更读取 `brief.md`、提案和设计；审查与验证各自读取独立记录。旧实现每次任务详情响应都会触发完整材料读取，加载时先显示空态；还在默认说明节点提前请求 Git 文件扫描。

本设计记录当前方案，布局相关部分是在实现后补写，读取优化在实施前形成。它不是历史审查证明。

## Goals / Non-Goals

**Goals:** 保持全局分屏及节点阅读的一致性；让提交和任务依据可完整阅读；减少切换与重复请求造成的等待，仍能主动取得最新内容。

**Non-Goals:** 不更改任务四态、记录格式、材料来源权限或历史事实；不在页面自动生成说明；不把短目标复制成需求正文。

## Decisions

### 1. 统一分隔与阅读布局

共享分隔组件（SplitDivider）使用 1px 线、32px 短抓手和 9px 操作区，复用已有拖动逻辑。顶部单独贯通，下方各屏为同层。清单只使用一个分隔，不再叠加自身左边框。文件栏与其他节点目录使用相同白底及间距。

### 2. 提交详情占用正文阅读区

点击提交时显示完整说明、作者、时间及完整哈希，并允许复制和选择文本。文件选择按仓库、路径和提交共同确定来源；同名文件在工作区和多个提交之间不能混用。相较仅增加悬停浮窗，这个方案可持续阅读且适用于键盘和触屏。

### 3. 有界材料复用与明确刷新

材料读取按工作空间（Workspace）、任务和关联引用组成身份，在当前页面会话内有界保存已读结果；新任务首次仍读取正式记录，返回已读任务可复用材料并后台重核。未完成时明确显示读取中，切换立即隐藏旧任务内容；中止及晚到响应不能覆盖新任务。

相同引用和详情对象更新不自动重复拉取全部材料。刷新任务显式刷新已打开材料，并等待读取结束；旧内容在刷新期间保留，错误显示局部提示。材料失败不缓存为成功。未打开改动节点不扫描文件和提交。

### 4. 证据和预览使用真实当前来源

需求及设计位于本任务受管工作树（Worktree），正式审查和验证保存于主工作空间（Canonical Workspace）。验收预览读取实时正式库，文件材料仍由工作树证据解析，避免旧快照把最新证据显示为空。

## Risks / Trade-offs

- [会话缓存可能短时陈旧] → 返回任务后台重核，主动刷新等待最新正文；有界容量，不跨工作空间共享。
- [取消旧请求形成误报] → 取消不显示材料错误；代次和任务身份双重校验。
- [布局在窄屏越界] → 验证 1920、1280 和 390px，清单窄屏保持悬浮，提交正文换行。
- [补写材料被误认为历史证据] → 明确创建时点，审查使用实际当前内容身份和自审方式。

## Migration Plan

无数据迁移。构建工作树前端后使用受管预览验证；回滚前端文件即可。历史已完成任务仍显示真实缺失，不重新开放其证据槽位。

## 后续反馈：改动读取与模式辨识

首次按需读取把 Git 扫描等待暴露在点击后，实测约 850 毫秒，其中数据读取约 800 毫秒。任务提交与文件读取共享一次范围观察；同一 Git 检出根的项目和服务来源合并扫描，仍保留全部来源标识，任务工作树优先。改动结果按工作空间及任务有界保留最近 8 份，返回时立即复用并后台更新；刷新仍等待读取完成，取消后的晚到响应不得写入缓存。未打开节点不预扫描。模式选择使用主题色实底、白字和加粗，保持选中与悬停可区分。

## 冷读取与差异语义继续修正

实际拆分测量：模块加载约356毫秒，运行装配约109毫秒，改动应用读取约510毫秒；总共40个Git进程。单次读取合并Git根与公共目录查询，局部复用已观察的检出身份；状态响应复用分支与领先信息，干净检出不读取空差异。跨请求重新观察。

提供左右对比和类 GitHub 的上下对比，两种模式均保留增删与上下文。窄屏使用并选中上下对比。补丁头不占用伪行号；两边代码和中间行号使用同一个固定行高，空白占位不塌缩，滚动保持对齐。顶部19px短竖线由下方分隔组件定位，跟随同一拖动边界。

后台读取线程（Worker）在Web启动时预热固定的两份容量，仅加载执行代码，不扫描未打开任务；首个请求复用已加载线程。代价为将这部分加载成本移到服务启动阶段，并提前占用既有有界容量的内存。预热失败仍由实际请求重试和报告，取消、队列上限与关闭逻辑不变。

## 用户澄清后的纠正

此前将上下差异误改为新版本正文，是智能体理解错误。当前方案恢复两种差异模式，按钮明确标为左右对比、上下对比；不新增文件全文阅读模式。顶部短线与下方分隔共用定位，避免右侧标签栏开始位置与实际边界相差约半个操作区。

## 完整文件上下文与最后两处反馈

用户要求两种差异模式均包含文件前后未修改内容。目录仍读取轻量差异，选择文件时通过同一有界读取线程加载当前文件的完整上下文，保持任务、代码库、路径与提交来源检查。单份差异有行数和字节上限，大文件明确标注截断，不冒充完整。手动刷新等待当前选中完整差异的新读取；存在旧的后台读取时主动刷新会替换它，自动目录重核不重复强制加载正文。切换取消旧读取并按工作空间、任务、代码库、路径和提交隔离响应。完整差异请求使用封闭参数，并交给所属读取模块校验；通用任务接口不能提前拒绝合法的专用查询。

任务列表等待刷新结果时保留已读取的数量和列表，使用固定尺寸的刷新图标旋转提示；成功后按新结果更新列表及统计，包括同样条件下新增的匹配任务。首次读取仍显示加载状态。完整差异正常显示时不增加说明行；读取中仅在工具栏固定占位显示小图标，失败或截断时保留必要提示。禁用的左右对比固定灰色与透明底，悬停仅提示宽度不足，不改变灰度。
