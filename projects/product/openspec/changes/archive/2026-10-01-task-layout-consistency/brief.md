# 统一全局布局与任务改动阅读体验

让工作台布局一致、提交信息完整可读，并让任务说明、方案和检查依据能够直接核对。

## 背景与问题

用户提供的四张截图指出：顶部栏折叠后错位、不同分屏和标签样式不一致、文件栏没有标题、仓库分支排布松散、提交说明被截断、固定清单出现重复竖线。后续验收又指出本任务没有说明和设计，审查未执行，预览也看不到已登记验证；查看历史任务时正文显示慢半拍。

## 目标与范围

面向使用 Buildr Web 查看任务和修改的用户，统一顶部与下方分屏层次、拖动抓手、任务节点间距和清单分隔；完整阅读并复制提交内容；主动刷新确实更新当前记录、材料和已打开结果。减少重复读取和不必要扫描，并明确区分加载、无材料和读取失败。

不修改任务状态规则、材料权限、发布行为或数据库格式，不自动补造历史任务材料，也不把一句目标当成完整需求。

## 核心流程与变化

1. 用户打开任务，先显示当前任务主体及说明加载状态，随后显示实际 `brief.md`。
2. 进入方案设计可读提案、设计、规范与实际审查；进入开发实现可读实现审查和开发验证。
3. 打开改动与提交才扫描文件及提交；点击提交在正文读取完整信息，选择文件读取该来源的差异。
4. 返回已读任务复用材料并重核；主动刷新等待最新正文和已打开结果完成。旧任务的晚到响应不显示到新任务。
5. 清单固定与其他节点保持相同边距，只显示一个分隔和抓手。

## 验收要点

- 展开、折叠菜单时顶部高度与标签样式一致，四处可拖动分隔使用同一短抓手。
- 1920、1280、390px 下核心内容可访问，无横向溢出；固定清单没有多余竖线。
- 完整提交说明、作者、时间、哈希可读、可选择、可复制；相同路径在不同提交之间差异正确。
- 快速切换不会闪现错误空态或上一任务正文；已读材料复用，主动刷新读取最新正文。
- 本任务的需求、设计、方案审查、实现审查和完整验证报告可从当前预览读取。

## 影响与兼容性

只调整前端布局及读取策略，沿用现有材料及专业结果接口（API）。缓存限定当前会话并重核，主动刷新仍读取当前事实。旧任务缺少材料时保留真实空态。

## 材料入口与记录时点

[提案](proposal.md)、[设计](design.md)、[行为要求](specs/buildr-web-client/spec.md)、[实施清单](tasks.md)。本材料在用户指出遗漏后创建，布局实现已经存在，读取优化在材料创建时尚待执行，现已完成验证；不冒充过去已写材料或已做审查。验证执行状态以正式报告为准。

## 本轮继续反馈

解释技能执行遗漏的原因，减少改动与提交读取卡顿，并让差异和全文模式的当前选择清楚可见。验收覆盖共享代码库来源去重、返回已读任务时后台更新不挡正文、主动刷新等待最新数据及模式切换。范围包括前端和本机读取实现。首次冷读取仍需真实 Git 扫描，不能用缓存速度冒充首次性能。

## 最新反馈

继续追查首次冷读取耗时，减少重复Git查询，并提前加载固定后台读取容量而不扫描未打开任务。恢复原本类 GitHub 的上下差异与左右差异对比，不改为新版本正文；中间行号必须与代码逐行对齐，顶部栏短竖线必须与下方分屏线对齐。

## 完整文件与刷新细节

用户明确要求左右和上下对比显示全文件，使前后未修改内容也可辅助理解。目录仅提供轻量预览，选中文件后按真实工作区或提交来源读取完整上下文；删除和重命名仍正确表达，超大文件明确截断。任务列表主动刷新不替换已读数量或清空已有列表；宽度不足时左右对比立即灰显，悬停只显示提示。
