## Context

对话消息由 `MarkdownHost` 把 `renderMarkdown` 生成的 DOM 插入面板；Markdown 图片经 `imageResolver` 换成同源 `/api/v1/conversation-image?path=…` 地址，该接口按原始字节返回并要求会话认证。引用图片文件的**链接**已能打开 `ConversationImagePreview` 模态框（宽 1000px、图片最高 70vh、只能适应窗口），内联图片则只是不可交互的 `<img>`。

## Goals / Non-Goals

**Goals:**

- 内联图片可被发现、可用鼠标与键盘打开预览，并显示原始引用路径。
- 预览足够大，且能切到 1:1 原始像素、在新窗口看原图。
- 复用同一认证图片地址、同一预览组件与对话归属校验。

**Non-Goals:**

- 不新增图片读取接口、缓存、缩略图生成或权限模型。
- 不改变对话消息内容、草稿、执行事实或 Markdown 语法。
- 不为知识库、文章等其他 Markdown 阅读面同时开放该交互。

## Decisions

### 1. 在 `MarkdownHost` 上附加交互，而不是把图片包成链接

`renderMarkdown` 保持纯渲染；`MarkdownHost` 在插入 DOM 后为 `img` 增加 `role="button"`、键盘处理与点击回调。这样不改变 Markdown 结构，也不把图片语义变成导航链接；未提供回调的阅读面（知识、文章、任务文档）行为不变。

备选“图片包 `<a>` 指向原图”：会把预览变成整页导航，且需要处理链接内图片的嵌套语义，不能复用既有模态框。

### 2. 复用既有预览组件与同一认证 URL

预览继续使用 `ConversationImagePreview` 与内联图片相同的 `src`，只扩展尺寸与操作。备选“新建全屏灯箱”：会形成两套图片预览和两套失败/重试语义。

### 3. 实际像素用“可滚动容器 + CSS 尺寸切换”

切换实际大小时给预览容器加类名，让图片保持原始像素、由容器滚动；不重写图片尺寸数据，也不发起新请求。窗口尺寸变化时保持用户选择的模式。

### 4. 图片点击优先于外层链接

Markdown 允许 `[![图](图.png)](目标)`。图片点击触发预览并阻止外层链接导航，避免一次点击同时打开预览与跳转。

## Risks / Trade-offs

- [大图在新窗口打开离开应用] → 保留既有外部链接的 `noopener` 与用户主动选择；默认仍在应用内预览。
- [1:1 在窄屏需双向滚动] → 容器限制在视口内并显式滚动，不撑破面板。
- [远程图片与受控本地图片行为不同] → 预览只做显示，远程图片沿用既有 CSP 与链接边界，不新增读取能力。
- [图片位于链接内时行为变化] → 明确图片点击优先，链接文字仍可正常打开目标。
