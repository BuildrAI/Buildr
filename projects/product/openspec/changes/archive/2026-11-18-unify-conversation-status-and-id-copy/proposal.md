## Why

1. 对话列表、活动提醒浮窗、侧栏角标和子对话入口的状态计算与同步存在多处偏差：当同一消息版本下先记录已读快照、随后在不产生新正文消息的情况下出现待决策或状态待确认时，列表叠加已读快照时误覆盖新增的 `pendingDecisionCount` 与 `active`，导致浮窗正确显示「待决策」而对话列表仍显示「执行中」；同时，活动浮窗未同步叠加已确认已读与当前对话实时状态、分组拉取遗漏不在运行中的「等待发送 / 发送失败」、发送失败未计入橙色「待处理」角标，且子对话入口使用另一套状态判断与文案，未能正确识别运行中非阻塞待决策。
2. 对话列表、活动提醒浮窗与当前对话标题栏常驻展示完整对话 ID 文本，视觉噪声大且挤占智能体、模型名和对话标题宽度。

## What Changes

- **统一对话状态收敛与角标/浮窗对齐**：
  - 将实时活动覆盖与已读快照叠加分离，使同消息版本下已确认过 `seenThrough` 的旧已读快照绝不回写后续新增的 `pendingDecisionCount` 与 `active`，并让对话列表、活动提醒浮窗及子对话入口共用同一套实时收敛管线；
  - 后端活动统计补充可选 `sendFailed` 计数并计入 `attention`，活动状态筛选 `attention` 扩展涵盖等待发送与发送失败，前端侧栏角标与提醒说明同步将发送失败纳入「待处理」；
  - 子对话入口复用 `activityState` 判断（覆盖运行中非阻塞待决策、待发送、发送失败等）并统一使用与主列表一致的状态名称（`待决策`、`执行中`、`待查看`、`状态待确认`、`等待发送`、`发送失败`、`后台作业运行中`、`执行失败`、`已停止`、`已答复`、`尚未开始`）。
- **精简对话 ID 展示为带 8 位短 ID 提示的复制按钮**：
  - 对话列表行、活动提醒浮窗行与当前对话标题区域移除常驻对话 ID 文本，仅保留复制按钮，按钮无障碍名称保持 `复制对话 ID`、悬停提示显示 `复制对话 ID（<前8位>）`，点击仍复制完整对话 ID；
  - 关联对话与搜索候选浮层对对话项展示 8 位短 ID 以区分重名对话（任务编码保持不变）。

### Modified Capabilities

- `agent-conversations`: 更新对话身份展示与复制规则（列表、浮窗与标题区域仅保留带 8 位短 ID 提示的复制按钮）、统一列表/浮窗/角标/子对话的活动状态判定与双向同步，并将发送失败纳入待处理统计与提醒分组。
