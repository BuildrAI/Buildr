## MODIFIED Requirements

### Requirement: 对话身份必须便于识别与复制

系统 MUST 在对话历史每项提供对话 ID 复制按钮（悬停提示包含前 8 位短 ID，点击复制完整值），不在列表行常驻显示完整对话 ID 文本，并尽量将标题与元信息控制在两行内。历史筛选 MUST 搜索在前、紧凑工作空间选择在后，默认选择当前所处工作空间而非上次对话所在工作空间。当前对话标题区域 MUST 提供同一对话 ID 的复制按钮（悬停提示包含前 8 位短 ID）且支持复制完整值，不常驻展开对话 ID 文本，且 MUST NOT 改变原有选择、重命名行为。关联对话列表与候选中的对话条目 MAY 仅展示前 8 位短 ID 以便区分重名对话，任务编码保持原样。

#### Scenario: 查找与复制当前对话
- **WHEN** 用户查看历史、关联浮层或打开已有对话
- **THEN** 历史行与当前对话标题区域 MUST 仅提供带前 8 位短 ID 提示的复制图标而不常驻显示 ID 文本，长标题不挤出第三行
- **AND** 点击复制 MUST 复制完整对话 ID，并给出成功或失败反馈

### Requirement: 对话阅读辅助必须集中且克制

标题与紧随其后的对话标识复制图标 MUST 使用单行布局，不增加标题栏高度，不常驻展示对话标识文本。悬停复制图标 MUST 展示前 8 位短 ID 提示，复制 MUST 使用完整标识，成功图标反馈 MUST 自动恢复。当前执行状态 MUST 位于输入框上方，MUST NOT 因滚动历史而不可见；历史记录与待回答请求继续可查。

#### Scenario: 复制并继续阅读
- **WHEN** 用户悬停或点击标题后的复制图标
- **THEN** 系统 MUST 在提示中展示前 8 位短 ID，点击后复制完整标识并短暂切换为已复制反馈，不能在输入区留下常驻提示

### Requirement: 对话入口必须自然展示活动提醒

右侧 MUST 保留“当前对话”气泡图标的悬停临时预览和点击固定展开/收起行为，并新增列表样式“所有对话”入口。活动对话 MUST 收纳于新增入口的悬停浮窗（Popover），不得常驻铺开额外条目；活动数量 MUST 只在新增入口显示，并将等待发送与发送失败纳入活动范围、将发送失败纳入暖色待处理角标与提醒说明。两个临时浮层 MUST 互斥，但 MUST NOT 因查看活动而关闭已固定对话。双入口点击 MUST 打开自己的视图、切换另一视图或在当前视图再次点击时收起；高亮 MUST 只指示实际显示的对应视图。历史固定显示时 MUST NOT 弹出活动浮窗。悬停或键盘聚焦 MUST 默认展示全部已登记空间的活动对话，并按准确工作空间身份分组，不提供空间筛选；组标题 MUST 显示空间名称与条数，组顺序 MUST 与对话列表共用工作空间排序偏好，默认空间固定最后；只显示有活动对话的空间，不改变其相对顺序。列表排序调整 MUST 同步到浮窗，无需刷新；组内 MUST 与对话列表采用相同的待处理优先、最近用户输入倒序及稳定身份次序，包括等待发送、发送失败、执行中、等待回应、状态待确认及有未查看新消息，并与当前打开对话及已确认查看状态保持实时一致；每条 MUST 可直接打开准确对话，并保留所属工作空间（Workspace）。每条 MUST 只显示一个静态主状态，不使用转圈或闪烁，也不重复堆叠执行与未查看标记。打开 MUST NOT 自动发起工作、代答或改变执行事实。浮层为悬停临时预览时 MUST 允许短暂移出后继续停留，不得在指针短暂离开时立即消失。

#### Scenario: 多空间后台执行
- **WHEN** 用户浏览一个空间而另一已登记空间的对话开始执行
- **THEN** 统一入口 MUST 在正常可见页面刷新周期内更新活动数量，悬停浮窗 MUST 展示该对话，用户无需先切换空间
- **AND** 点击 MUST 打开提醒所指空间和对话，保留当前工作页面

#### Scenario: 已结束且已查看不属于活动
- **WHEN** 用户悬停“所有对话”入口且对话没有尚未受理的提交
- **THEN** 浮窗 MUST NOT 混入已结束且已查看的对话
- **AND** 已结束但仍未查看的对话 MUST 留在活动区，查看后移出；执行中或等待回应 MUST NOT 因查看而移出

#### Scenario: 浮窗移动与无鼠标入口
- **WHEN** 用户将鼠标从入口移入浮窗，或使用键盘及窄屏触控访问入口
- **THEN** 浮窗 MUST 可继续操作，键盘可聚焦条目并按 Escape 关闭，窄屏点按 MUST 与桌面点击遵守相同的视图开合规则
- **AND** 多条活动 MUST 在浮窗内有界滚动，桌面点击图标或浮窗顶部独立“查看全部对话”文字按钮 MUST 可进入全部空间历史；MUST NOT 在滚动列表底部重复该入口。空间名称 MUST 仅在分组标题显示，浮窗行辅助信息 MUST 紧凑展示智能体与模型，MUST NOT 重复展示更新时间
- **AND** 浮窗行 MUST 仅提供与对话标题栏一致的对话 ID 复制按钮（悬停提示前 8 位短 ID，不常驻显示 ID 文本），复制 MUST NOT 改变当前对话或消息查看状态

#### Scenario: 发送失败与分组分页提醒对齐
- **WHEN** 对话处于等待发送或发送失败（包括当前并未运行模型）且同时存在较多活动对话
- **THEN** 提醒浮窗在分组拉取时 MUST 包含等待发送与发送失败条目
- **AND** 发送失败 MUST 计入侧栏暖色待处理角标与入口提醒说明

#### Scenario: 当前对话原交互保留
- **WHEN** 用户悬停当前对话气泡图标，再点击固定展开并再次点击收起
- **THEN** 临时预览和固定对话 MUST 使用同一内容、草稿和执行事实，临时预览 MUST NOT 自动确认查看
- **AND** 移入新增所有对话图标 MUST 关闭临时预览并展示活动；从活动条目打开 MUST 固定准确对话

#### Scenario: 双入口切换与重复点击
- **WHEN** 面板收起、显示当前对话或显示历史时，用户点击气泡或列表图标
- **THEN** 收起时 MUST 打开目标视图，显示另一视图时 MUST 切换到目标视图，已经显示目标视图时 MUST 收起
- **AND** 显示历史时悬停列表 MUST NOT 弹出活动浮窗；关闭历史后悬停气泡 MUST 预览当前对话而不是历史

#### Scenario: 列表排序同步浮窗
- **WHEN** 用户在对话列表调整工作空间顺序后打开活动浮窗
- **THEN** 浮窗 MUST 立即使用相同空间顺序，且组内共同对话的相对顺序 MUST 与列表一致
- **AND** 没有活动对话的空间 MUST 不显示，默认空间若有活动对话 MUST 固定最后

### Requirement: 对话列表必须按活动优先与最新消息统一排序

历史列表 MUST 将当前筛选范围内所有活动对话集中置于顶部活动区，包括执行中、等待回应、状态待确认与未查看；已结束且已查看的其他对话 MUST 按所属工作空间分组置于下方，不重复列入两组。活动区 MUST NOT 按空间拆分。活动区与各空间分组 MUST 优先展示待决策及待查看，两者共享最高优先级；其余活动随后，非活动历史最后。同一优先级的对话顺序 MUST 按以下规则决定：活动、等待回应、未查看和待决策对话按最近用户输入时间排序；非活动历史按最近用户输入时间与最新一轮 `completed` 执行的最终可见主助手消息时间中较晚者排序。用户发送新输入或答复有效问题时，该对话 MUST 在当前优先级内前移，不得越过待处理条目。智能体中间输出、工具日志、无变化刷新、改名及查看操作 MUST NOT 改变排序时间；最新一轮 `completed` 执行的最后一条可见主助手消息 MUST 作为非活动历史的最终答复时间，`thinking`、工具消息、子工具消息、通知、失败消息以及 `failed`、`stopped`、`unknown` 轮次 MUST NOT 作为最终答复。最新一轮没有可见最终助手消息时，排序 MUST 退回最近用户输入时间。状态与查看变化 MUST 只按当前准确分类调整优先级。同时间 MUST 有稳定身份次序，MUST NOT 在活动组内对执行中再额外置顶。“默认”空间组 MUST 固定置于最后且不参与排序调整；其他空间组 MUST 支持整组拖动改变显示顺序，并由本机偏好保存，偏好 MUST NOT 改变组内顺序或对话归属。每组 MUST 默认展示 5 条，超出时 MUST 可在组内展开与收起。改名、查看及隐藏操作 MUST NOT 单独改变顺序或活动归属。隐藏 MUST NOT 令仍活动的对话从活动区消失，隐藏筛选 MUST 只改变下方非活动历史。分页与刷新 MUST 使用一致排序，不能只重排浏览器已加载的一页。列表行辅助信息 MUST 展示智能体与模型，MUST NOT 重复展示更新时间，并 MUST 提供对话 ID 复制入口（悬停提示前 8 位短 ID，不常驻显示 ID 文本）。

当对话列表与当前对话正文并排展示时，用户进入处于“待查看”状态的对话并在视口看到最新可见消息后，系统 MUST 立即持久化查看位置、更新全局待查看统计并隐藏左侧列表该行的“待查看”提示，同时在停留于该对话期间保持该行当前的列表排序席位不变，不因本次已读确认重排或触发无关列表及执行统计请求；等用户切换到其他对话、新建对话或退出并排列表视图离开该对话后，再刷新所属工作空间分组使其按最新已读事实自然归位。若停留期间停留在旧消息尚未看到最新回复，MUST 仍保留“待查看”不提前隐藏；若停留期间直接在该对话发送新消息、出现待决策请求或出现状态待确认等新活动状态，MUST 立即解除或更新状态展示，此前已确认的同消息版本已读记录 MUST NOT 覆盖后续新增的待决策或活跃状态。

#### Scenario: 智能体回复不改变顺序
- **WHEN** 同一条已存在的智能体回复继续流式增长，或仅有中间助手输出、工具日志、状态更新、改名、查看
- **THEN** 该对话 MUST 保持当前排序时间，并按执行与未查看规则进入或保留在相应优先级
- **AND** 同一消息的流式增长、中间助手输出、工具日志与单独状态变化 MUST NOT 改变排序时间

#### Scenario: 同消息版本下后续出现待决策或待确认
- **WHEN** 用户已查看当前对话最新消息后，同一消息版本下对话在执行期间提出待回答问题或转为状态待确认
- **THEN** 对话列表、活动浮窗与当前对话 MUST 一致显示“待决策”或“状态待确认”
- **AND** 先前保存的同版本已读快照 MUST NOT 覆盖新增的待决策或活跃标记

#### Scenario: 用户输入决定位置
- **WHEN** 用户在一个较早的对话中发送新输入或答复问题
- **THEN** 该对话 MUST 移到同组同一优先级最前；活动、等待回应、未查看和待决策对话仍按用户输入时间排列，非活动对话按用户输入或最终答复时间排列
- **AND** 执行中即使有最新输入也 MUST NOT 超过待决策或待查看

#### Scenario: 普通对话收到新消息
- **WHEN** 一个已结束且已查看的对话收到最新有效消息且尚未查看
- **THEN** 该对话 MUST 进入待查看优先级并在同级内按最近用户输入时间定位
- **AND** 最终答复时间 MUST NOT 改变待查看优先级内部的相对顺序

#### Scenario: 查看结束对话
- **WHEN** 已结束但未查看的对话最新消息已真正被查看，且列表并非并排停留在该对话中，或用户随后离开该对话
- **THEN** 它 MUST 退出活动组，按最近用户输入时间或最新一轮 `completed` 执行的最终答复时间进入所属空间分组
- **AND** 查看动作本身 MUST NOT 更新排序时间

#### Scenario: 并排查看期间先隐藏待查看并在离开后重排
- **WHEN** 对话列表与对话正文并排展示时，用户点击进入处于“待查看”状态的对话并看到最新可见消息，随后在停留阅读后切换到其他对话、新建对话或收起列表
- **THEN** 确认已读后服务端已读位置与侧栏待查看计数 MUST 立即更新且左侧该行“待查看”标签 MUST 立即隐藏，同时在停留期间左侧列表行序保持原席位不动且不触发无关列表与统计刷新；若仍停留在旧消息未看到最新回复，则“待查看”MUST 保持可见
- **AND** 离开该对话后所属工作空间列表 MUST 立即刷新并使已读对话退出待查看优先位、按真实历史时间归位，且在此期间直接发送新消息或产生新活动状态时 MUST 立即解除锁位展示新状态

#### Scenario: 最终答复移动非活跃对话
- **WHEN** 一个非活跃对话最新一轮 `completed` 执行产生了可见最终主助手消息，且该时间晚于最近用户输入
- **THEN** 该对话 MUST 按最终答复时间在同组非活动对话中前移
- **AND** 中间助手输出、工具消息、`thinking`、失败消息以及 `failed`、`stopped`、`unknown` 轮次 MUST NOT 触发该前移

#### Scenario: 非活跃最终答复不越过待处理
- **WHEN** 一个非活跃对话的最终答复时间晚于待决策或待查看对话的用户输入时间
- **THEN** 该对话 MUST 仍排在待决策和待查看之后，只在非活动历史内部按最终答复时间排列

#### Scenario: 调整空间组顺序
- **WHEN** 用户把一个非默认空间组拖到另一个非默认空间组之前
- **THEN** 该组整体移动到目标位置，组内对话顺序不变，“默认”组 MUST 仍位于最后
- **AND** 重新打开对话列表或刷新页面 MUST 保持调整后的组顺序，直到用户再次调整

#### Scenario: 组内展开
- **WHEN** 一个空间组包含超过 5 条非活动对话
- **THEN** 该组默认只展示前 5 条并提供展开入口；展开后 MUST 展示该组全部已加载对话并可收起
- **AND** 展开与收起 MUST NOT 改变分组顺序、组内顺序或执行统计

#### Scenario: 后台变更与分页
- **WHEN** 用户停留历史列表，后台消息改变排序或分页边界
- **THEN** 列表 MUST 自动反映新顺序，失效的分页位置 MUST 重新读取或明确提示，MUST NOT 静默漏掉对话

#### Scenario: 待处理位于分页之后
- **WHEN** 多个较新的执行中对话与较旧的待决策、待查看同时存在，列表每页容量有限
- **THEN** 系统 MUST 在完整查询集上先返回待处理条目，跨页按相同优先级、用户输入时间、最终答复时间与身份读取，无重复或遗漏

#### Scenario: 新回复更新同优先级顺序
- **WHEN** 一个非活跃对话收到新的可见助手回复且尚未查看
- **THEN** 该对话 MUST 进入待查看优先级并在同级内按最近用户输入时间定位
- **AND** 最终答复时间 MUST NOT 改变待查看优先级内部的相对顺序

### Requirement: 子对话必须以主对话内的单展开浮窗使用

主对话右上角 MUST 为每条子对话保留独立浮动入口。入口的悬停状态提示与未读/待处理徽标 MUST 使用与对话列表和活动提醒浮窗一致的活动状态判定与文案（包括运行中出现非阻塞提问时的“待决策”、等待发送、发送失败、执行中、待查看、状态待确认，以及非活动时的后台作业运行中、执行失败、已停止、已答复、尚未开始）。点击 MUST 展开对应非遮罩窗口，同一时间 MUST 只展开一个；选择另一入口 MUST 收起前一个且保留各自草稿、阅读位置及后台工作。展开、切换与收起 MUST 不改变主对话选择、阅读位置或未发送文字。刷新后 MUST 能重新发现持久关系。

#### Scenario: 多窗口入口和切换
- **WHEN** 主对话有多条子对话，用户依次点击不同入口
- **THEN** 每条子对话 MUST 有自己的入口，同时只出现一个展开窗口，主对话 MUST 保持原位置与草稿
- **AND** 再次打开原子对话 MUST 恢复其未发送内容及阅读位置

#### Scenario: 收起后继续执行与回应
- **WHEN** 用户收起正在执行的子对话，随后子对话等待授权、提出非阻塞问题或出现待处理状态
- **THEN** 后台工作 MUST 不因收起停止，入口 MUST 亮起暖色待处理指示并使用统一状态文案（如“待决策”）展示真实待回应状态
- **AND** 用户重新展开后 MUST 能对准确子对话停止、回答或授权，不影响父轮

#### Scenario: 起始位置与后续工作安排
- **WHEN** 用户创建子对话，随后提出新的工作要求
- **THEN** 创建 MUST 只沿用主对话的起始工作位置，MUST NOT 因创建子对话自动新建或切换工作树（Worktree）
- **AND** 后续任务（Task）及实际工作位置 MUST 按用户本次要求和适用工作规则安排，界面及交付背景 MUST NOT 将起始位置描述为永久共享或阻止按要求隔离开发
- **AND** 系统 MUST NOT 声称仅创建子对话就完成代码隔离、回退或合并
