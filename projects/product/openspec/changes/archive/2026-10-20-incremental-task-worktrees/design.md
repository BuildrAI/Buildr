## Context

动机见 proposal.md。当前实现把选择、来源、路径、分支（Branch）、起点及远端文本共同散列，在创建前要求摘要不变；失败只登记已遍历成员。非 Git 根的登记位置由排序首项决定，预览（Preview）也把摘要用作固定归属。

## Goals / Non-Goals

实现已确认的增量语义，沿用现有入口和登记格式。真实身份检查及删除授权保持有效；不自动缩减成员、移动已有目录、变更已有分支（Branch）或重新定位创建起点，不重建任务环境。

## Decisions

1. 在主工作空间（Canonical Workspace）的本机临时目录使用已有互斥锁（Mutex）实现，同组创建与清理共享锁，锁内重新读取登记。选择固定组身份作为锁位置，避免非 Git 根新增来源时锁随排序改变；锁不形成新的业务状态。
2. 新计划以旧成员为底，合并显式选择。以真实来源路径和 Git 公共目录（Common Directory）核对同源关系，保留旧选择身份；项目（Project）与服务（Service）同源时兼容去重，显式追加完整项目（Project）时允许选择归一到项目（Project）以保留完整语义，实际位置不变。相同选择指向其他来源或旧路径、远端身份、分支（Branch）发生冲突时在 Git 写入前拒绝。
3. 起点只用于创建新成员。已有成员保持已登记起点，无需再次解析旧起点是否仍可用。完整组预检仍先于任何新增 Git 写入；逐项状态预先覆盖整个集合，失败保留后续未创建项，避免重试只能看到局部清单。
4. 更新沿用既有登记文件，首次创建继续使用当前锚点规则；摘要描述当前完整集合，不作为集合永不变化的保证。格式保持 v1，兼容旧的部分失败记录，不能推断旧记录未保存的成员。
5. 预览（Preview）把摘要视为观察版本，摘要变化时要求原成员是已核验当前集合的子集，路径及分支（Branch）不变；不以提交（Commit）推进否定同一运行归属。停止可检查有效旧成员，即使新增成员失败；新启动继续要求其所需集合可用。仅删除摘要比较会削弱身份保护，因此必须保留逐项证明。

## Risks / Trade-offs

- 并发导致成员丢失 → 同组创建与清理互斥，取得锁后重新读取，不对未知或存活持有者强行解锁。
- 追加失败丢失旧登记 → 先建立完整成员结果，再逐项更新；旧目录不重建，成功效果不自动回滚。
- 同源的不同选择改变语义 → 保留既有选择并核对实际来源、起点及登记，不凭选择文本或同名目录接管其他对象。
- 非 Git 根锚点变化 → 已有组只写原登记位置，仍拒绝多份记录。
- 摘要不同掩盖原成员被替换 → 预览（Preview）逐项检查当前集合，缺少原成员证明时拒绝。

## Migration Plan

无需批量迁移旧登记。首次重复调用读取 v1 记录并按当前事实扩展；旧部分失败记录只从实际已知成员继续。产品技能（Skill）与协作约定同步说明追加入口。候选修改仅在隔离位置运行，正式自举激活等待实际交付后由唯一执行器处理。
