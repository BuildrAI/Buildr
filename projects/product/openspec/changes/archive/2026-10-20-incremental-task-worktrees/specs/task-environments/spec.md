## ADDED Requirements

### Requirement: 同一任务的工作树集合必须支持增量追加

重复创建同一任务（Task）的工作树（Worktree）时，提供者（Provider）MUST 合并已有登记与显式选择的新增来源，逐项核对真实 Git 身份，只创建缺少的成员；MUST NOT 因完整清单摘要变化而拒绝安全追加。已有检出路径（Checkout Path）、分支（Branch）、创建起点及未提交内容 MUST 保留，未再次列出的旧成员 MUST NOT 被移除。共享同一实际来源 MUST 去重；同一选择指向其他来源、已有身份冲突或目标被占用 MUST 在新增 Git 写入前明确拒绝。

#### Scenario: 从方案扩展到多仓实现

- **WHEN** 已有位置包含未提交方案，调用方为同一任务（Task）选择两个新增独立来源
- **THEN** 提供者（Provider）MUST 保留方案内容和已有身份，只新增所选来源并返回完整成员集合
- **AND** 相同调用或只列出其中一个来源再次执行 MUST 复用全部已有成员

#### Scenario: 起点变化不重写已有成员

- **WHEN** 调用方省略起点或使用不同起点文本，已有成员身份仍一致
- **THEN** 提供者（Provider）MUST 保留已有创建起点和内容，新成员按其适用来源声明解析起点

#### Scenario: 追加途中失败后继续

- **WHEN** 完整预检通过后，一个新增成员创建失败
- **THEN** 提供者（Provider）MUST 保存旧成员、成功新增成员、失败成员及尚未创建成员的完整登记，不回滚已完成效果
- **AND** 再次调用 MUST 只补齐未完成成员，不丢失既有内容或历史身份

#### Scenario: 并发追加与清理

- **WHEN** 多个进程同时操作同一任务（Task）的成员集合
- **THEN** 创建与清理 MUST 互斥并在取得写入权后重新读取当前登记，不能以旧清单覆盖其他调用已成立的成员
- **AND** 清理输入遗漏新增成员时 MUST 拒绝删除

#### Scenario: 非 Git 根内追加排序靠前的来源

- **WHEN** 已有完整登记位于一个独立来源的 Git 公共目录（Common Directory），新选择来源的排序更靠前
- **THEN** 追加 MUST 保留原登记位置且更新同一完整组，不创建第二份记录
