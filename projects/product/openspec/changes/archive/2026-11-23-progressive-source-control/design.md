## Context

已有清单与逐库发布，但清单逐仓查询克隆状态并重复解析整份登记；仓库行要求已有工作树才能点击。

## Goals / Non-Goals

冷打开先看到完整名单并可指定要查的仓库；热打开保留已读取结果。保留后台全量状态与有界并发，不改 Git、远端或登记。

## Decisions

- 区分静态登记和实时观察。只复用命中当前内容版本的登记解析；读前后核对登记，仍实时核对目标克隆状态和 Git 身份。旧入口无需新参数。
- 使用现有逐库管线。点选只提升尚未开始的目标，不取消正在运行的读取、不额外开启同库请求；结果确认真实工作树后才切换正文。
- 稳定展示仓库行；进度用真实结果计算。无结果显示待核对，失败只影响本仓库，旧进度不能抢占新选择。

## Risks / Trade-offs

两条读取都忙时，目标等下一个空位；不靠提高并发占用更多资源。保留既有超限和局部诊断。
