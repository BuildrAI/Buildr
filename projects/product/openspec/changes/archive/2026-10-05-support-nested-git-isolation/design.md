## Context

动机见 [proposal.md](proposal.md)。当前提供者（Provider）无条件先规划 `workspace`，证据位置调用根的 Git 公共目录（Common Directory），观察集合核验要求 `workspace`；任务提交又只在根属于 Git 时读取工作树（Worktree）证据。代码查询仅枚举单一证据目录。

## Goals / Non-Goals

按真实 Git 身份保护隔离与删除，保持已有根布局和 `buildr.git-worktree-evidence/v1` 的完整组记录。明确非 Git 根内的来源选择与组证据发现。资料维护、任务状态、远端策略及部分目录的开发预览（Preview）各自沿用原有边界，不把这些代码检出目录投射为完整工作空间（Workspace）。

## Decisions

### 按实际来源判断，选择与发现分开

根是精确 Git 顶层时保留 `workspace` 默认项；确实无 Git 时省略此项，要求显式的项目（Project）或服务（Service）来源。真实来源来自规范登记，优先完整的 `repositorySource`；无远端的本地 Git 来源仍适用。历史 `workspace` 声明不得直接当作无 Git：核对实际顶层，共享已选父仓库时去重，独立根时参加规划。已声明 Git 的来源缺失、损坏、权限失败或错误父根不得被吞为无 Git。没有有效 Git 来源时返回具体诊断与零效果。读取候选登记仅用于发现证据，不自动扩大任务范围。

### 组证据保存在确定性实际 Git 锚点

有 `workspace` 时继续使用根的旧证据目录；没有它时在按既有深度和规范来源路径顺序排列的首个参与代码库（Repository）公共目录（Common Directory）保存同一份完整记录。不在 `.buildr` 新增索引，不在每个仓库复制组记录。写入已有明确组来源时直接定位；读取从根和已登记的实际来源发现候选目录，多个记录、损坏记录或身份冲突必须显式诊断，不用当前对象覆盖。无关坏来源不能让已选健康组的动作全局失败；相关来源仍在完整预检和当前身份核验中拒绝。

### 观察集合以同一组目录校验

没有历史证据时允许仅有子代码库（Repository）的完整观察集合，以规范来源相对路径核对其共同组目录，并逐项核验实际 Git 登记、公共目录（Common Directory）、分支（Branch）、锁及占用。扫描已核对的共同组目录以拒绝未列出的兄弟或嵌套 Git 来源，设置数量和时间上限，不跟随符号链接（Symbolic Link）；组根不能覆盖保留来源或文件系统根。保留外部既有路径，不凭 `.worktrees` 名称推断归属，不补造起点。多个服务（Service）共享实际来源按已有选择器（Selector）去重；同一实际来源明确选择项目（Project）时，代表身份优先保留完整项目，`workspace` 仍优先，避免选择顺序丢掉完整项目材料语义。

### 生命周期与读取方共享提供者能力

代码查询通过提供者（Provider）的窄证据目录发现能力枚举；任务提交在根无 Git 时也读取真实组记录。非 Git 项目资料在仅服务（Service）检出时仍从真实项目根读取；项目实际属于 Git 或身份未知时保留完整根诊断。项目中落在已选服务（Service）来源内的代码资料读取对应检出候选，缺失或失效不回退原文件。代码组异常时，仅在仍能读取有效且没有完整项目或 `workspace` 候选的组证据，并确认资料项目无 Git 时继续读取原地资料。证据候选损坏、重复或读取不完整时，关联查询继续列真实 Git 目录，但不生成伪唯一任务关联。开发预览（Preview）没有完整根时继续给出局部范围诊断。创建仍完整预检后逐仓执行，失败保留实际效果。清理只删除已证明归属的 Git 检出、本地分支（Branch）与证据，留下组容器及非 Git 资料。

## Risks / Trade-offs

- 坏来源被误认为无 Git → 区分确认无 Git 与未知身份；测试错误父根、损坏来源和全部预检零效果。
- 候选发现遗漏或重复 → 统一发现端口，校验完整记录与工作空间（Workspace）身份；覆盖关联查询和重复证据拒绝。
- 缺登记恢复放宽删除 → 复用完整集合、字面路径、当前登记、交付保留引用核验，保留旧 Git 根安全回归。
- 锚点代码库（Repository）被移走 → 返回证据或身份缺口，已知当前对象可按原有无历史路径核验；不创建第二权威修补丢失。

## Migration Plan

无需批量迁移或新格式。已有 Git 根记录继续原位读取；新布局在首次明确选择后创建组证据。实现和说明同时交付，由既有自举执行器更新采用内容；恢复旧实现需先保留新布局证据与实际工作树（Worktree），不能删除用户成果。
