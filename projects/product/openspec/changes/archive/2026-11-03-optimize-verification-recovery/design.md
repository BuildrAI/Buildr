## Context

见 proposal.md。普通验证已有文件输入选择与进度事件；候选轮次只按节点成功复用。工作流 artifact/host 作业隐式依赖祖先成功，源码全复用时可能连带跳过。编排等待每次重进完整操作，原包交接直到 aggregate 才实际下载。

## Goals / Non-Goals

目标：可信保留独立成功、及时并行交接、诊断实际成本。非目标：再次公开发布、改变原包生产、另建验证结果库、推导另一系统成功或把预算增加称为启动性能改善。

## Decisions

- 候选轮次继续是唯一普通结果；失败节点附带文件记录，使用既有文件发现、输入选择、环境身份和进度事件。只在文件输入前后相同、进程正常回收、上下文清理成功时保留新文件成功。整组已有成功仍服从显式 invalidation，失效节点不可采用其旧文件证明；新增成员必跑。相比拆成大量检查 ID，不改变稳定登记。
- 原包交接以 GitHub 同一 run 的未过期 candidate-package artifact 可读为准，下载准确原包并校验 manifest/source/hash 后返回 local-artifact-verification-required。已经提交本机证明后不再重复交接；远端不取消。未知或尚未上传只继续等，不重打包。
- 消费者用 always() 加明确 plan/bootstrap 成功条件，不依靠伪源码作业改变 skipped 状态；汇总继续负责缺项，不能豁免失败。
- 等待器保留同请求、有界时间和进度，只读候选等待轮询不反复 fetch；进入真实主线采用仍刷新。进度输出本机轮询工作与休眠分离，远端排队/作业/步骤时间仅使用 API 可证明边界，缺失为未知。
- 监听证明拆成独立真实 OS 通道与使用真实文件／Git 的受控传输矩阵；不再每个分支反复启动原生订阅。真实通道有界观察实际事件，替身不能满足它；矩阵缩短心跳并保留归属、忽略、共享元数据及清理断言。生产超时不变。实测原生冷启动约 5.9 秒，原 5 秒夹具就绪上限不足，因此独立通道使用 10 秒总观察预算，而非延长所有用例。

## Risks / Trade-offs

- 命令型动态编译／发现入口无法解析为已知源码 → 保守保留完整读取范围，测试内容或成员变化不得复用旧静态结果。
- 文件输入扫描有成本 → 复用已有选择策略，保守 fallback 扩大失效；无可证明身份时整文件重验。
- 部分日志/信号中断 → 不生成新的文件成功；完整汇总必须发现全部成员且每个匹配。
- 原包下载尚不可见 → 不将未知当失败或已就绪，下一轮只读查询。
- 工作流平台语义不能由本机完全证明 → 对 YAML 条件做场景矩阵回归，明确未执行真实 GitHub/Windows。

## Migration Plan

旧普通结果继续可读；没有文件证明的失败节点首次整组运行。新文件证明附在现有结果，非全局缓存，不跨候选轮次。用户当前授权不包括提交、集成或激活，保留隔离成果。
