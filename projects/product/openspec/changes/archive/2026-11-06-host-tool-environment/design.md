## Context

见proposal.md。已交付整类退役使用原storage锁、系统占用与版本复查，重扫描位于维护worker。三家适配器均显式覆盖账号目录。Qoder SDK按os.tmpdir和版本/用户构造带.ready的原生载荷目录。

## Goals / Non-Goals

**Goals:** 使用本机环境，账号及历史隔离，安全回收历史可再生副本。

**Non-Goals:** 不建设工具管理器、宿主清理平台或逐包迁移，不处理未知业务临时成果，不修改运行中的环境。

## Decisions

1. accountEnvironment使用明确宿主的标准TMPDIR/TMP/TEMP；没有可靠宿主临时路径时仍使用原私有兼容目录。isolatedEnvironment继续用于安装等真正隔离场景。Buildr自己的标题请求仍放私有目录，避免碰撞和账号泄漏。不把整个旧tmp合并到公共位置。相比增加共享组件目录，让工具自行使用其标准缓存更简单。
2. 原storageDependencies保留严格原生证据语义，在回调提供准确run、executionRef及pending事实；缓存调用方只对可再生数据使用目的明确的判断。已释放控制不等于业务成功；终态且executionState=ended、工具均完成、准确控制组消失的旧执行不再保护下载缓存。进程组观察失败或证据不足继续保护。待发请求及活动任务保留。未接受、无执行资源且无工具的旧失败/未知启动只解除缓存引用，仍要求整个配置域无系统占用，不能缩小到缓存子树；状态和原生证据不变。删除前沿原链路再次观察。原生诊断和会话引用规则不变。
3. 适配器提供少量准确旧缓存目录声明：仅Qoder私有tmp中版本/用户名载荷、完成标记、受管所有者及已知原生布局符合时声明为可再生。原collector整目录回收，活跃映射由lsof保留。未完成.setup、未知额外文件和账号内容不纳入。新执行直接复用供应商宿主TMP缓存，不先复制或逐包对齐。

## Risks / Trade-offs

- 宿主TMP缺失或相对路径 → 私有兼容退回，不改变账号根。
- 业务结果仍未知 → 保留原生证据与状态，仅已释放的可再生缓存允许清理。
- 原生组件布局变化 → 未识别对象保留并报告；不扩大为任意tmp清理。
- 并发运行与空间写入 → 条件删除与自动重试，分开报告目录分配减少和卷可用变化。

## Migration Plan

候选通过专项及四服务检查后常规集成推送，经唯一自举执行器启用。新执行使用宿主环境；旧任务不重启。历史副本后台接续。回退源码仅改变未来环境选择，不恢复或重放业务任务；已退役缓存允许工具自行重建。
