# 当次来源采集与原记录直接读取

本次变化将旧“查看时反查当前资产”的来源关联改为：真实生产者（Producer）在动作发生时写入来源元数据（Provenance Metadata），原 DSH 会话事件（Session Event）保存并重载，原查询直接返回，三入口读取同一当次事实。唯一目标、授权与完成依据见[任务说明](@task/dsh-buildr-provenance)；总体观察目标见[父任务说明](@task/buildr-agent-observation)。

## 本轮具体变化

- 使用正式 `dsh.event-sources/v1` 契约，工具及受支持子调用的原事件使用 `data.eventSources`，规则注入消息使用 `message.source.eventSources`。不增加事件顶层字段、第八种轨迹类型、模型正文或另一条执行流水。
- 来源在当次规则（Rule）注入、技能（Skill）实际胜出读取及能力调用时取得。`matches` 保存提供者、对象身份、实际定位、观察版本、证据及可取得的动作；正文仅引用原事件的 `contentRefs`，不复制为来源正文仓。
- 状态 `confirmed`／`unknown`／`not-applicable` 与执行成功／失败分开。没有来源字段明确“未采集”；旧记录不自动反查，也不从当前资产、目录、名称、入口文本或管理关系追认来源。
- `EventSources.execution` 只保存当次实际命令解释器（Bash）前台正规化结果的 `outcome` 及可取得的 `exitCode`；后台／转后台保持未知，原生失败优先，不在查看时解析输出文本推成功。来源状态不因执行结果改变。
- Buildr 公开 `source inspect` 输入增加可选 `mode: metadata|content`，默认 `content` 保持独立接口兼容。采集提供者用 `metadata` 核对实际原始摘要与资产提供证据，响应不含当前／观察正文，输入不发送普通用户正文；三入口阅读完全不调用该接口。
- 原来源列、原详情与 Buildr 标签共用持久来源标记；标签只过滤已加载窗口中确认由 Buildr 提供的原记录。标记在客户端（Client）直接读取元数据，不再建立自动来源查询队列；按需正文和刷新只读取原事件及其片段引用。
- 原七类、顺序、参数、结果、定义、计时、搜索和折叠保留。普通用户资料直接读取不纳入 Buildr 参与；资料能力只保留调用及必要引用，辅助来源采集失败不阻断原动作。

## 交付与当前知识影响

本轮实际依赖由旧显示补丁扩大为选定 Host 生产者、正式事件契约、正规化、原持久化（Persistence）与重载、查询及轨迹组装。旧准备器仅允许轨迹源码，旧组合仅携带入口与轨迹；必须扩展明确补丁范围、编译实体产物及摘要核验，不能借旧 SDK 就绪回执声明新链路成立。当前源码与现装 Host 不同，官方组合只替换已观察的三个根服务，五个实际预设（Preset）生产者通过公有配置编辑器（ConfigEditor）仅更改其原声明的模块引用；原条件、隔离与其余配置保持，不强开停用根行或回填默认值。仅预设（Preset）叶更新且原 `AgentLoop` 未卸载时，旧智能体（Agent）保留已绑定版本。本次三个根服务停换触发热重载（HMR），释放旧 `AgentLoop` 拥有的运行智能体并从列表撤下；原会话（Session）先由公开元数据（Metadata）接口确认仍在持久存储，后续通过受支持恢复入口核对原会话可用；具体范围见实施索引，不承诺恢复时文件字节不变。完整撤回先恢复graph-only阶段及原根服务、保留图并完成必要重启，再公开RPC比较恢复五叶且验证可用后才移除图；共享核心仍使用现装版本时须证明新增字段兼容。必须改共享核心才能保全来源时，以正式运行时（Runtime）交付处理，不手改应用归档、配置档或原日志。

原 V4 会话格式（Session Format）的兼容性按实际持久字段分类判断；可选、可缺失且原读取链保全的附加字段可以保持既有版本，但须保全本轮中英变更确认、持久模式（Persistence Schema）与目录清单（Catalog），不以声明编译或版本号相同代替正式维护和往返验证。旧确认与检查点不修改。

知识评估（Knowledge Assessment）限于本变更五材料、插件说明、SDK 说明及已有构建流程：读路径不再依赖当前 Buildr 资产查询，构建范围新增选定生产者，验证必须包含保存重载和原查询字段往返。项目、服务职责不新增；不机械创建图、代码地图或影响占位文件。本轮阅读优化复用已存在公开查询，不新增SDK包或项目／服务声明；性能比较和当前事实说明只维护上述现有成果。稳定声明入口的变化先按声明接续（Declaration Intake）核对，正式结果由原责任主体维护。

## 本轮阅读与性能调整（实施中）

用户已确认四项调整：52px 固定两行列表采用可视区域虚拟化（Virtualization）和随已加载记录版本更新的本地索引；无正文能力直接使用已加载来源及执行事实，正文请求有界批读；列表先表达动作、对象和结果，详情去除同义重复并保留实际退出码；方法片段使用公共 Markdown 预览并可切换原文，明示片段范围，详情保留单一正文滚动区域。

正文批读优先组合现有公有 `sessionQuery.observeSession(..., { projectionMode: 'none' })`，同一会话每批一次观察租约（Observation Lease）、最多 32 个真实序号，只复制选中的原事件，最终释放租约；不替换共享查询模块，也不回退逐引用的整日志复制。正文缓存（Content Cache）按原记录版本与引用校验，限制为 32 项及 8MiB，退出消费后释放。能力 `completeness: none` 且没有合法正文引用时不读取原事件，未知执行结果不当成功。

基线分两层保全：[受控页面性能](../../../services/dsh-plugin/build/source-performance-companion-20261005/performance-result.json)的 5000 条全部来源记录曾全部进入页面元素（DOM），初开中位数约 597ms；[真实原查询成本](../../../services/dsh-plugin/build/source-read-performance-observed-d49af21f-2dc8-476b-b9a9-51fd131e1678.json)中，95 事件内存会话的两引用读取约 2ms，17MB 非活动历史首次约 315ms、重复约 143ms。该测量不是冷盘或内存泄漏证明，执行通过不代表性能目标通过。本轮实现、精确新客户端、受控前后比较及真实主机端（Host）批内读取分别验收，不沿用旧界面结果冒称优化完成。

交付保持原八模块实体图、三个根服务配置、十五个预设模块引用和已固定的 OAuth 0.0.114 外部依赖；只更新本轮确切变化的入口及客户端内容地址，使用项目声明的 Node 24.15。新行为与剩余采集／撤回样本分别见[第 10 节与第 9 节](tasks.md)。不新造原型，已确认的四项调整优先于旧模拟内容。
