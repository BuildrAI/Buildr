## Goals / Non-Goals

**Goals:**
- 当次正式来源字段经原正规化、持久化（Persistence）、重载和查询保全；三入口读同一事实。
- 标记在已加载元数据上直接计算，正文按需定位原文本块；缺失、未知、错误和执行结果分别说明。
- 当次规则（Rule）、技能（Skill）、受支持能力及子工具（Subtool）可追溯，普通资料排除，原交互和结果保持。

**Non-Goals:**
- 不保留旧记录自动反查或当前关系回退，不改写历史、不重放动作补证。
- 不复制用户资料或历史正文仓，不由读取推断采纳、遵循、贡献或业务完成。
- 不开展全会话参与统计、评分、回传、双向导航、其他智能体（Agent）接入或公开发布。

## Decisions

### 1. 在原事件载荷建立正式来源契约

使用 `dsh.event-sources/v1`，状态为 `confirmed`／`unknown`／`not-applicable`；工具及受支持嵌套调用在原 `data.eventSources` 保存，规则注入消息在 `message.source.eventSources` 保留。字段不进入事件顶层外壳。`matches` 记录 `providedBy`、`kind`、`identity`、`name`、`locator`、`observedVersion`、`evidence` 及可取得的 `action`、`contentRefs`，不携带额外正文。

来源状态不等于执行结果：实际入口已确认的失败能力仍可有确认来源；来源采集缺证据可为未知而原动作继续。没有字段是“未采集”，未知版本、非法字段或损坏引用是相关来源不可用，不能合并为不适用或零参与。正式解析拒绝不受支持字段和越界引用；证据来自受支持生产者，不接受模型、用户或任意命令文本自行声明来源。

可选 `EventSources.execution={outcome,exitCode?}` 由当次实际命令解释器（Bash）前台正规化结果写入。原 DSH 返回即使没有把非零退出码表达为 `isError`，仍可由该同期事实说明失败；原生 `isError` 或错误事实优先。后台／转后台结果没有最终退出事实时保持未知，不能在查看端解析标准输出推定成功；来源状态与执行结果各自保全。

### 2. 当次生产者拥有来源事实，采集失败局部化

首步入口盘点分别记录当前可用规则、技能、主命令行（CLI）包装入口及已投射的本地技能附属执行入口。元数据查询的开发候选绑定不等于实际命令安装身份；命令须由正常公开安装状态或明确候选绑定证明本渠道的准确入口与观察版本。同安装明确路径符号链接（Symbolic Link）仅在真实文件身份等于批准入口且摘要复核时成立，相同摘要的复制文件或其它检出不作为别名。裸名称缺当次命令解释器（Shell）执行世界证据时保持未知，不采用主机端（Host）PATH代替实际解析。

Buildr提供的本地技能附属命令在明确解释器的真实脚本参数位置核对实际入口和投射回执（Projection Receipt）；不能遍历任意参数寻找Buildr路径。记录能力调用、该入口版本、必要引用及`completeness: none`，原结果仍由DSH保存。非Buildr提供、仅管理、版本不匹配或无法证明的成员不确认。

对象引用按真实操作语义最小化：`task materials inspect <task-id>`是资料集合，任务引用足以描述；`task materials write <task-id> --path <relative-md>`另外保存确切资料路径。`--materials`清单及`--content`正文输入不作资料对象，不解析输出推断采纳的文档。非法或歧义路径仅缺该附加引用，不否定已确认能力入口或原执行。

采集从实际规则注入、技能胜出定位和实际能力入口取得；提供者严格由当次权威证明，`managedBy` 不代替 `providedBy`。必要的 Buildr 当前资产身份核对只在发生阶段进行，且有界、只读，不启动网页服务、同步或修复资产。采集失败保留原动作和返回，记录未知或局部失败，不能把来源辅助能力变为执行门禁。

Buildr 公有 `source inspect` 输入的可选 `mode` 为 `metadata`／`content`，默认 `content` 保持既有独立查询兼容。采集提供者选 `metadata`，只传必要定位与实际原始摘要，校验资产提供证据，不发普通用户正文，响应剥离当前／观察正文。服务端仍可读取自身资产字节核对，不能宣称完全无资产读取；查看端不调用这个接口。当前核验发生在当次写入之前，其结果不能被复用于补写旧记录。

成功、失败及程序工具调用（PTC）的受支持子调用必须在正规化与写事件时保留字段，同时保全既有 `meta`、呈现及错误信息。每个子动作保留自己的真实调用／事件引用，不继承父来源。无法取得当次证据的路径明示未采集或未知，不通过结果后反查补齐。

### 3. 原保存与查询保全字段，阅读只读原事实

原事件保存、重载、精确事件查询、会话控制器及轨迹组装传递正式字段，不能只在内存或模拟输入中存在。原 V4 会话格式（Session Format）的新增可选字段须作兼容分类；保持原版本时仍须本轮中英变更确认、持久模式（Persistence Schema）及目录清单（Catalog）一致维护，旧确认和检查点保持不变。来源列与 Buildr 主列表使用轨迹上下文的少量来源元数据（Metadata），标记无需远程过程调用（RPC）；移除 `sourceMarkers` 自动队列和阅读时当前资产、目录、名称、绑定安装反查。

需要正文时，以原 `recordId`、整数 `eventRefs[].seq` 及 `callId` 查询原 DSH 事件，返回其来源字段与原内容引用。刷新只重新读取原事件，不重新判断当前归属；没有当次字段始终未采集，即使当前同名内容存在。公开资产查询可继续作为独立能力，但不属于这条阅读链。已加载窗口不代表全部历史，未采集数量、查询失败或空过滤结果不证明零参与。

### 4. 片段引用指向实际原文，保持阅读边界

`contentRefs` 的 `block` 是实际持久事件文本块位置，`start`／`end` 使用 `unit: utf16` 的半开区间 `[start,end)`；范围须与同一事件块校验，不指向格式化显示、当前文件或拼接行窗口。每个匹配对象的 `completeness` 为 `complete`／`partial`／`none`，只说明其原读取范围的完整性，不因片段完整宣称整个文件完整。Unicode 代理对、多个块、截断和混合区块均需定向验证。

混合 `AGENTS.md` 仅引用当次实际读取中已证明的 Buildr 区块；用户段继续由原 DSH 原结果承载，不进入新增方法片段。普通资料的直接读取不标为 Buildr；资料能力只保存能力与必要目标引用。正文缺失、引用非法或仅取得部分片段时说明限制，并保留查看原调用／结果入口，不查询当前文件补齐。

附加阅读对象的 `capturedCompleteness` 依据当次匹配完整性表达完整／片段／无正文，不从当前内容推定，也不将完整片段等同完整文件。

### 5. 保持三个入口和连续浏览

原七类 `system`、`user`、`context`、`compacted`、`message`、`tool`、`subtool` 保持；来源列和原详情继续使用两个正式扩展位（Slot），并列标签只过滤持久标记已确认且 `matches` 中确由 Buildr 提供的原记录。缺字段、未知及不适用记录留原轨迹，不进入主列表。

默认全宽列表，显式选择才打开可关闭详情；关闭保留搜索、原序、可视锚点和有效结果，回焦原行、可见行或搜索框。原搜索、折叠、分页、虚拟滚动、计时、参数、结果和呈现保留。迟到的原事件正文返回不能重开详情；同原记录版本复用内容缓存，最后消费者释放原文缓存，不建立当前资产反查缓存。

### 6. 交付实际生产者，而非仅交付新声明

新的源码清单明确选定 Host 生产者与轨迹源码包、每文件原始／候选摘要和正式协议义务；准备器编译实际生产者实体、生成声明及轨迹，逐项验证后发布新的独占 SDK。旧补丁、SDK 和 v10b 产物不可覆盖或作为新输入。

新私有组合携带八个实体生产者、轨迹与 Buildr 插件（Plugin），但安装拥有者必须按真实作用域（Scope）区分。当前原主机端（Host）快照证明 Tools、AgentLoop、Skill 三条根服务已激活；其余五条根声明明确 `rawDisabled: true`，实际能力由独立预设（Preset）的 `config.plugins` 装载，不能强开根条目或把根层状态当预设配置。

交付分阶段：先以显式 `--host-stage graph-only` 安装实体图和必要客户端（Client）贡献，三个原根服务保持；预设五叶经外部明确触发的公开远程调用（RPC）编辑，不能在热重载（HMR）插件安装上下文内自动编辑。先用公有 `hmr.runExclusive()` 的空操作验证外部触发确实可用，编辑结果再核对当前预设无 `broken` 及适用行。全部适用预设已可用且现场无未完成动作后，才启用根服务替换阶段；过渡期间不运行新版本工具，以免新预设与原执行上下文的不同契约混用。

组合只正式停用三个已观察根拥有者，再插入不同标识和内容摘要地址的三个新条目；使用已观察的原始 `config`／`disabled`／`inject`，原解析值只作比对证据，不用 `agents:[]` 等解析默认值回填。没有必要快照仅阻止组合动作，不阻止独立 SDK 构建。五个模块只作为同一共享产物图的实体文件供预设引用，不新增重复全局实例。

实际预设拥有者通过公有 `ConfigEditor.entries()` 精确定位；公有 `livePresetMounts(ctx.root.fiber)` 只读核对必要生产者运行行。临时适配器（Adapter）使用 `ConfigEditor.edit()` 的锁内最新原始配置，仅将已观察且唯一的五个 `config.plugins[].name` 叶改为已安装同图的确切文件地址；其余层次、条件、配置、隔离域（Isolate Realm）、权限和预设身份保持。原始条件表达式（`!!js`）原样保全，不复制完整预设或凭证进候选包、日志或回执。适配器补配置摘要的比较并交换（CAS）；缺失、重复、别名或漂移仅拒绝受影响编辑，不猜位置。

配置编辑成功返回不证明内部生产者激活：预设注册表（Registry）可能记录 `broken` 而不抛错，须另以原 `agentPresets.resolve()` 和当前版本的 `compositionInventory()` 核对新五项及适用运行状态。失败补偿经同一配置编辑器进行，仅在本轮候选仍是当前配置时恢复五叶；普通撤回只比较五个当前模块引用，保留用户对其它配置的新变化，冲突不覆盖。完整撤回先将同一组合恢复为 `graph-only`，保留被引用图并恢复原根服务，按实际生命周期完成必要重启；再以外部公开远程调用（RPC）恢复五叶并验证原预设可用，最后才卸载图。过渡期间不运行新版本工具；恢复后须按现场生命周期与阶段结果验证，不把此前暖态 `tool-skill` 失败推断为原生产者与新根服务已知静态不兼容。

仅预设（Preset）叶更新且原 `AgentLoop` 未卸载时，已有智能体（Agent）保留已绑定版本，子智能体继承该版本；不对已有工作会话（Session）偷换预设或绕过非空重组限制。本次三个根服务停换触发热重载（HMR），释放旧 `AgentLoop` 拥有的运行智能体并从列表撤下；原会话（Session）先由公开元数据（Metadata）接口确认仍在持久存储，后续通过受支持恢复入口核对原会话可用；具体范围见实施索引，不承诺恢复时文件字节不变。实际新采集以新会话、自然的新版本或受支持的恢复入口验证，分别报告哪些现场已经换代。共享核心继续来自现装 Host 时必须证明字段兼容；必要整体运行时（Runtime）换代使用正式交付，不手改应用、配置档或内部导入。构建、安装、选择、拥有者编辑、激活和真实新事件分别核对。

`--host-config` 仅包含已观察激活的三项根拥有者：`id`、原始 `config`、原 `disabled`／`inject`（确实存在时）及根拥有者／启用／运行／解析配置的 `observed` 事实；原始表达式对象保留，解析值仅作比对，不采用旧布尔 `condition` 格式。独立标识不自动继承旧配置覆盖或设置命名空间，不能以默认值、`agents:[]` 或平台猜测代替实际声明。原 AgentLoop 设置卡必须继续对应当前实际配置服务；必要修正只显式选择原 `ui-settings-agent-loop` 客户端（Client）贡献，使用公开配置表单（ConfigForms）的描述与实际命名空间，不另造 Host 别名或换根产物地址。缺配置只阻止该组合构建；构建不读取整配置档或凭证，回执分别记录原始摘要、观察值、设置贡献及待核对依赖，不冒称实际恢复完成。

阅读优化前的当次采集主路径已验证到限定真实样本：精确 `f3b934` 组合已通过官方入口安装并冷启动激活，新入口为 `runtime-entry-c2f1a25bb563a49d`；三个根服务及 standard／ptc／cordis 共十五个模块引用保持同一 `774a` 图。原窗口显示五条 Buildr 记录，含规则注入、规则读取、技能加载及命令行（CLI）成功／失败各一条。95 个事件的原查询、原事件读取、持久读取及同主机端（Host）两个只读句柄重开完全一致，历史来源和原模型／请求元数据保留；失败调用来源仍为 `confirmed`，同期 `exitCode: 1`，原 `isError: false` 保持，能力没有新增正文引用。技能原事件正文、原调用跳转、来源列与详情、过滤后关闭／回焦已实际验证。正常整应用退出并重启后，原 95 个事件前缀的来源、工具及请求事实保持；恢复后的总数为 96，不声称事件总数不变。实际查询、持久读取及重开通过，五条来源记录和原技能正文仍可读。真实技能文件读取、程序工具调用（PTC）子动作、资料能力目标引用、后台／转后台及完整撤回仍未完成；父观察体系与业务价值不据此完成。

本轮无界面的只读探针（Probe）激活后自动执行一次，不注册客户端（Client）、扩展位（Slot）或按钮；变更仍由插件管理页 `plugins.item` 的外部明确公开远程调用（RPC）触发。公开编辑后须立即核对实际 `ConfigEditor.documentPath` 文件版本和 `configuration()` 继承／覆盖摘要，安装字节不替代当前加载地址及运行状态。第三方受管区块导致覆盖丢失的因果证明、精确 `0.0.114` 来源恢复、原会话恢复与各阶段失败保全于[实施索引](implementation-progress.md)，不将此前代码变化归因于未经核验的操作。来源进程只允许同一绑定 Node 和已登记源码根下精确规范化且实际路径一致的 `bin` 入口；不放宽任意入口、名称或符号链接逃逸，不回填原记录。

### 7. 按可视区域和真实引用限制阅读成本

Buildr 标签继续只投影当前已加载窗口。52px 两行记录采用可视区域加有限缓冲的虚拟化（Virtualization），页面元素（DOM）数量随窗口高度变化，不随全部来源记录数量增长；可点击、键盘焦点、原序、过滤、选择、关闭后的可视锚点保全。标记与检索索引按稳定记录及其已加载来源版本更新，不在每次呈现中重复遍历／序列化全部来源，也不建立后台历史扫描或新的持久索引。

能力来源已记录但 `completeness: none` 且无合法正文引用时，已加载元数据足以呈现动作、对象、结果及同期退出码，不启动原事件内容请求。原参数和结果继续由“查看原调用／结果”入口承载。需要正文时，同一批针对同会话至多 32 个去重的真实 `seq`，使用现有公有 `sessionQuery.observeSession` 的 `projectionMode: none` 取得一次不可变切点，再校验原身份／调用关系，仅复制被选中事件并按合法 UTF-16 引用提取片段；异常、取消及迟到租约均最终释放。不得回退逐引用 `readEvent` 的整日志复制；公有 API 不可用只报告该正文局部不可用。首个非活动会话观察仍可能读取和准备整日志，不能把返回少量引用解释为零后台成本。

正文缓存（Content Cache）使用原记录、引用和来源版本身份，最多 32 项及 8MiB，按最近使用淘汰；取消、会话／窗口变更、最后消费者撤回与迟到返回仍保全既有语义，不把旧缓存覆盖新的记录版本。标记始终零来源查询，正文仅由明确选择／刷新触发。

### 8. 以动作、对象及结果组织方法阅读

列表的主表达回答“做了什么、作用于什么、结果如何”，保留实际发生时间及必要来源说明，避免重复展示对象身份作为主标题。详情保留来源身份、原事件定位与原调用入口，去除列表和同一详情中的同义重复；失败、未知及同期 `exitCode` 明确，原生失败优先，不由正文文本猜测成功。

规则／技能片段复用公共 Markdown 阅读组件，提供预览和原文切换；原文是同一 `contentRefs` 引用的当次文本，预览不改变 UTF-16 引用或扩大来源范围。片段、完整读取和无正文分别说明，渲染失败保留原文及原调用入口。正文只使用一个纵向滚动容器，公共 Markdown 自身不再嵌套同向滚动；窄容器及输入区上方最后一行可达，原参数／结果详情继续保留。

### 9. 将性能执行与性能验收分开

受控基线以精确 WC8 客户端、B1 阅读器、1440×1000 和三次样本记录；5000 条全来源初开中位数约 597ms、选择约 299ms，来源列表有 5000 个实存行，原轨迹约 34 行。真实 Host 的原 `readEvent` 两引用读取另测：95 事件约 2ms，17MB 非活动历史首次约 315ms、重复约 143ms，并有显著自然堆分配。它们不包含相同范围：受控远程调用（RPC）即时返回，不测真实 Host／磁盘；真实引用探针不测整个页面及完整方法正文传输。

本轮分别验证有界实存行、本地索引复用、无正文零请求、同批一次租约／选中引用、缓存上限与释放、公共 Markdown 阅读，以及同条件前后时长／长任务记录。实际 `observeSession` 同场对照另保全来源切点、选择数、释放及堆变化；保留自然缓存和垃圾回收影响，不宣称强制冷盘、缓存命中或内存泄漏结论。源码、受控、真实 API 与原窗口结论分别登记，新精确产物尚未验收时清单保持待完成。

## Risks / Trade-offs

- [当次来源缺失被当前关系掩盖] → 完全移除反查回退，无字段明确未采集，旧日志不迁移。
- [正规化或共享库丢字段] → 用实际新生产者成功／失败／子调用及保存重载、原查询链验证；安装成功不等于兼容通过。
- [来源耗时或失败影响工作] → 发生阶段有界只读采集，局部未知／失败不阻断原动作；读标记不再启动来源进程。
- [片段或用户内容被扩大归属] → 校验原块 UTF-16 边界、实际提供者和完整性，正文不复制、当前文件不补齐。
- [旧构建被升级为新证据] → 旧阶段独立保全，本轮清单按精确新证据逐项核销，剩余范围明确待验；固定新源码、SDK、产物和现场范围。

## Migration Plan

1. 更新同一变更五材料并以最新任务正文为准；旧 1—8 清单保留历史阶段，新采集清单未完成。
2. 建立正式字段和生产者接线，贯穿正规化、原保存重载、查询及轨迹上下文；删除旧反查主路径。
3. 扩展受支持 SDK 源码边界、实际 Host 构建和实体组合，核对现装共享库兼容及声明影响，不手改应用或配置档。
4. 用新字段验证当次事实、无字段未采集、真实原文片段、失败／子调用、用户资料排除及原交互；取得精确新产物。
5. 唯一安装执行者通过官方入口交付并核对新生产者、运行激活及新产生事件三入口；失败从保全组合撤回或恢复。源码检查、受控检查和真实桌面范围分别登记，整个观察体系仍按父任务授权推进。
