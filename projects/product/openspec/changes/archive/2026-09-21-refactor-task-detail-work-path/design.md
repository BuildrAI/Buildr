## Context

当前 Task Record、工作摘要（Work Context）、OpenSpec、任务审查（Task Review）与任务验证（Task Verification）各有独立权威。前端已有 WorkspaceStage 副屏与 DrawerShell 抽屉，任务详情尚在使用旧页签、单独阅读栏及弹窗。

已确认交互参考：[任务详情原型](ui-prototype/task-detail.html)。原型数据为示例，保留工作路径参考；2026-09-21 用户进一步明确列表打开详情副屏、紧凑标签及节点直接正文，正式页面以本次修订为准。

## Goals / Non-Goals

目标是把现有事实按工作路径串起来，明确区分“正在做什么”“已有材料”“保存过什么结论”。默认首屏聚焦任务与需求；选择审查或验证时直接显示对应完整结果，来源摘要值保持折叠。

不增加通用流程状态机、审查门禁、专业结果副本、测试岗位能力、验证历史、自动运行智能体或自动确认。任务标题/目标沿用现有维护能力；专业文件仍由智能体通过其原有文件能力维护，页面只读，不新增任意文件编辑器。

## Decisions

1. 任务列表接入已有资源预览（Resource Preview）和 WorkspaceStage：左侧保留列表、筛选与滚动，右侧展示 TaskDetailPage。详情接受明确 taskId，既有深链恢复成列表与详情；关闭副屏恢复原列表。详情内部不再使用分屏或另一个资料容器。维护动作继续用 DrawerShell。
2. 顶部紧凑显示标题、编码和目标。工作路径压缩为单层可切换标签，默认 requirements，当前工作标记与阅读选择独立；四个主节点不再单列两类审查、开发验证和用户确认：审查在设计或实现内部，用户确认在收尾内部。四个主节点保持稳定，简单任务允许内容为空，不强制补齐材料。文件存在只标注“已有内容”，清单数量只表达清单，不推断完成比例或验收。
3. 工作摘要增加可选 stage：requirements、design、planning-review、implementation、implementation-review、verification、acceptance、closeout。省略保留原值，null 清除；旧数据继续有效。当前节点可向前、向后或清除，无转换门禁，不从文字、报告时间或文件数量猜阶段。终态任务不再显示进行中的当前标记。
4. 审查保留现有 task_review_current 和写入输入。新增专业历史表，在相同事务中把被替换的完整当前结果保存后更新当前值；版本冲突和写入失败不追加历史。读取同一观察中的历史和当前结果，HTTP 追加 history 字段。旧数据库只读时当前结果仍可用；合法写入才迁移，不追补已经丢失的旧结果。
5. 节点正文直接消费已有文档与报告阅读组件。需求默认 brief 正文，设计默认 proposal 并同层切换 design/specs/已有原型，实现默认 tasks 加进展，审查在所属节点内默认最新结果并可选择历史；验证聚焦结果和检查问题；收尾同时展示用户确认及已有交付记录。多变更材料保留来源，只有多份时才需要内容选择，不先展示文件入口列表。正文链接在共享阅读抽屉中打开，关闭后保留原正文。
6. 首层显示标题、编码、目标及必要当前节点提示；正文空间优先留给所选节点。完整进展、记录、来源、父子关系和复盘可在同一详情中阅读。用户确认复用已有 attention/response；记录答复不自动认定通过、不改任务状态、不启动执行。关闭抽屉后保持阅读现场，冲突保留输入并要求重读。
7. 文件读取通过任务关联与受管工作树证据选定来源，未提交内容直接从匹配工作树读取。需求中引用的项目文档也用任务范围读入口，不走主目录文档入口；工作树文件缺失如实报缺失，来源漂移局部失败，不能静默读回主目录冒充开发现场。副屏显示工作副本或保留副本来源。
8. 方案审查与实现审查直接显示最新对象、结论、范围、问题和未覆盖项；历次结果通过同层选择切换。验证仅呈现现有当前报告的通过/未通过/未完成以及适用性；修复进展来自当前工作摘要，不把上次通过当成本次重新验证通过。

## Risks / Trade-offs

- 旧任务无当前节点 → 不标记当前节点，仍可查看所有已有材料，不填造历史步骤。
- 只读观察未迁移数据库 → 新历史返回空集合，旧当前结论保持可读；只允许明确新增表的迁移兼容，不忽略未知迁移。
- 报告与当前成果可能已不同 → 首层使用“最近审查/最近验证”的真实保存结果，副屏展示对象与时间；变化后的适用范围仍由智能体核对。
- 工作摘要只有一条关注事项 → 展示现有记录，不假装已有完整决定流水；后续是否需要扩展由实际使用决定。
- knowledge/docs/overview.md 仍描述审查只保留当前结果 → 本轮在 brief/tasks 中记录准确影响，建议后续按用户知识维护授权更新产品概览中的审查与任务页面说明，代码地图补充新页面组件，避免扩大为全项目知识重建。

## Migration Plan

新增连续 SQLite 迁移只创建审查历史表与索引；工作摘要可选字段不改旧记录。新旧请求保持已有必填字段。回退旧运行时前必须按正常数据库版本保护处理，不删除新增历史。前端、接口类型、源技能指引、测试一起交付；安装与正式自举由既有收尾能力承接。

## 内容取舍与阅读连续性

- 主路径四个节点只用于定位工作；内部阶段仍保留原专业事实，规划审查映射到设计，实现审查和开发验证映射到实现，用户确认映射到收尾。全局用实际阶段和当前进展说明正在做什么，不从历史审查通过推导当前成果通过。
- 顶部只保留标题、编码、目标、状态、当前工作及必要待答复事项；低频操作在更多菜单。已答复记录放回其所在内容，不在全页重复；验收请求引导至收尾。
- 需求与方案保留文件正文原貌，省去重复外围标题。多份重名文档显示关联变更名，工作树来源用短标记说明；不把内部摘要值、重复路径及技术目录当正文。
- 设计与实现的审查在文档工具栏显示最新结论入口，点击后同区阅读报告；抽屉正文保留结论、时间、审查对象、实际问题和未覆盖范围。不显示空的“无”栏目或结果摘要值；审阅范围仅在有内容时显示。历史通过节点左侧审查记录列表选择，不铺满按钮。
- 概况提供全局实施清单入口，实现显示审查与验证结论；当前进展统一在顶部，只有当前实现相关的下一步在节点内出现。验证保留结论、时间、验证对象说明、适用性、每项实际检查结果及未覆盖项；删除内部报告摘要和与用户判断无关的检查执行字段。失败时提供回到实现的入口，不复制全局进展。
- 收尾显示用户待确认内容/已记录意见和真实交付摘要，未发生的内容用一句空态；复盘只在已有时提供入口。意见仍不自动代表验收通过。
- 节点切换记住该节点选中的文档/审查及滚动位置；打开关联文档后返回原阅读位置，新任务仍默认需求。仅在任务详情内维护阅读状态，不新增专业状态或文件副本。

## 顶部总览、操作取舍与列表密度

总览在宽副屏正文右侧使用轻量属性栏，窄副屏回流顶部；这只是响应式网格，不增加分屏组件。标题、编码、目标与状态之后，显示所属项目/服务、当前实际工作、进展、下一步和更新时点；缺失信息不填造，待人处理的具体事项就地展示。任务关系只有存在时显示。实现内不重复下一步，用户确认仍在收尾。已完成任务用真实交付摘要作为概况，不突出陈旧执行进展。

“保存说明”是任务原文中的文档引用，保留原文链接语义，不作为固定按钮。“查看关联变更”和“任务信息”入口从正文删除；已分节点展示的材料不再重复引导至技术目录。收藏与置顶保留一种任务组织方式，以列表置顶为准；详情不再展示收藏/置顶。接续能力仍只生成指令，因此低频菜单明确命名“生成接续指令”，避免暗示已执行。任务目标编辑和放弃在更多菜单，完成登记在收尾位置。进展由智能体维护，用户通过答复参与，不要求在页面另填工作摘要。

列表复用现有 Ant Design 表格、表头与目录密度，每项最多标题加一行进展；项目、状态、更新时间分列，置顶为紧凑操作。窄副屏优先保留任务和状态，横向空间不足时收起低优先列且详情仍能查看对应信息；分页、查询、筛选和滚动语义不变。

偏好性能先测实际延迟，不把所有等待都归因于单一接口。消除前端写后重复GET、后端逐项任务详情与重复项目登记读取；保持实时名称解析、缺失对象提示、工作空间身份和数据并发保护，不靠长期过期缓存制造加速。

并发实测确认原型与任务材料的同步读取会占用 HTTP 主线程，使偏好读取从十几毫秒延长至约两秒。使用现有有界读取执行器承接任务变更、关联 Markdown、原型列表与原型正文，保持两个工作线程与既有队列/取消规则；只传已解析工作空间和受限任务标识，不开放任意执行。首屏不预读原型，进入方案设计后按需发现。所有来源范围和工作树身份仍由原 Application 校验。

## 阅读层级重排

参考 Asana 的列表与详情并排、Linear 的正文与属性分工，以及飞书项目按工作对象组织内容的方式。具体采用单一四节点导航、文件正文和进展属性栏；节点下不再铺第二排标签。多份文档通过当前文档名菜单直接切换，单份无需菜单。审查/验证是文档工具栏右侧的具名结论入口，一次点击在现有抽屉读完整报告；历史入口属于报告，不重复显示状态与时间。没有专业记录时一句空态。授权内例行审查与验证由智能体执行，页面删除常驻执行按钮；手动接续仍在更多菜单。

## 阅读抽屉与全局材料

在保留默认节点正文的基础上，引用文档继续使用既有 DrawerShell；两类审查、开发验证和收尾内容在节点目录右侧直接阅读，实施清单直接呈现在全局侧栏。抽屉关闭后原正文和滚动不变，历史只切换抽屉中的报告，文档支持同项目相对导航。实施清单入口与工作树来源在任务概况全局可见，不再每篇文档重复标注。开发实现节点显示两类真实结果摘要，避免与全局清单重复。详情不监听窗口焦点或可见性刷新；仅初次读取、明确刷新和相关维护触发更新。

## 最终统一阅读结构

简介下的一行属性承载项目、工作树来源及最后更新时间；进展和下一步紧凑呈现，人的待处理事项保留明确答复入口。右侧只承载真实 OpenSpec tasks.md 实施清单，保留未勾选和已勾选原文，不把勾选数解释为任务完成比例。窄屏清单回流正文之后。

任务需求单文档直接读取；方案设计按提案、设计、各规范、实际原型、方案审查记录排列左侧目录。审查按最新在前逐次展示次数、日期与结论，右侧呈现对应完整报告。开发实现使用实现审查历次记录和开发验证；收尾使用用户确认、交付结果、适用的子任务交付与复盘。所有目录在同一节点中选择，不再为报告另开抽屉。任务级更多菜单提供登记完成，仍沿用既有任务完成并发校验与父任务授权约束。

MarkdownReader 只组合已有安全 MarkdownHost 与技能页面的原文/阅读切换模式，任务文件、引用文档、清单与技能文件共用。原文直接展示实际文件内容，不重新序列化渲染结果；相对链接仍交回原领域解析。

## 目录层级细化

标题下显示任务编码。简介下保留属性行及必要的待人处理事项，删除常规进展和下一步重复展示；工作路径当前标记仍由明确阶段事实驱动。规范目录项固定为类型与名称两行。审查采用具名分组、子项缩进和引导线，区分普通文档、验证入口与历次记录；两类审查均保持多次历史。报告删除单独的审查对象与版本区块，只展示现有正文结论、问题和未覆盖内容，不改写历史正文或专业数据，也不提前修改未来的审查写作规范。

## 逐页审查修正

规范与两类审查均采用同级分组和同缩进子项，以留白分组，不再加组间横线。审查正文标题标明所选次数。验证正文按结论、检查明细、范围说明组织：只有一项检查且其状态与总结果相同时不重复状态标签；状态不同或多项时在检查名旁显示，不删除任何检查摘要、未覆盖项或适用性说明。去掉检查末尾横线和分散的装饰竖线。已知测试地图诊断用中文呈现，未知诊断保留原义。

引用文档使用单一阅读器文件名和一行来源；收尾标题与其他节点同尺寸，用户确认不再重复叠加提示标题。任务菜单将放弃与普通操作分隔；编辑字段使用一致中文说明。保留可见键盘焦点，不把鼠标焦点当常驻选中样式。
