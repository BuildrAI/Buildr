# 按工作路径重构任务详情

用户需要先看懂任务目标和当前进展，再按工作路径查看需求、方案、两次审查、验证和结果，深入时直接阅读已有内容。

保留已确认的工作路径。打开任务即在列表旁的已有副屏显示详情，默认预览任务需求正文；顶部标题、编码、目标和工作路径紧凑呈现。工作路径只保留任务需求、方案设计、开发实现、任务收尾四个节点；方案审查归入方案设计，实现审查归入开发实现，开发验证归入开发实现，用户确认归入收尾。每个节点直接展示对应内容：brief.md 是需求或说明；方案使用 proposal.md、design.md 和规范；实施使用 tasks.md 与当前进展；审查按次保留；验证只保留当前结果及修复进展；确认与收尾使用已有记录。

任务详情复用现有副屏，节点内容在详情内直接阅读，维护复用抽屉，保留原有主题和控件。空内容保持为空，不要求简单任务补齐所有文档。人在目标、重要决定与验收中参与；智能体（Agent）在授权内继续推进。

验收覆盖完整任务、缺少材料的简单任务、审查追加、验证失败后返回修复、用户答复、并发冲突和窄屏阅读。方案与实现见本目录的 proposal.md、design.md、specs/ 和 tasks.md。

本轮进一步优化：顶部总览直接说明目标、实际阶段、进展、下一步、需要人处理的事项和所属范围；不再用任务信息入口承载基本认知。列表改为有表头的紧凑任务/项目/状态/更新时间列，正文入口与重复偏好动作删减。偏好接口保持现有契约，减少重复读取、逐项查详情及访问记录后的额外往返，并验证并发与工作空间隔离。

本轮按用户否定现有设计的反馈重排阅读层级：只保留四个节点导航，主区直接显示文件；节点文档工具栏只保留本节点的审查和验证结论入口，点开同区读报告与历史。删除重复状态、文件标签墙和例行执行按钮。进展与属性在宽副屏侧栏、窄副屏顶部显示。

本轮细节：表格左右内边距对齐系统目录列表；引用文档、两类审查及验证用现有抽屉阅读。概况集中显示材料工作树来源和全局实施清单入口，开发实现集中呈现审查与验证结论。取消窗口重新获得焦点时的详情自动刷新，保留显式刷新与维护后的更新。

最新交互统一：节点左侧常驻内容目录、右侧正文；审查历次记录直接列出，无下拉中转。开发实现与任务收尾沿用同一结构。项目、材料来源和更新时间移到简介下方一行，右侧直接显示 OpenSpec 实施清单。Markdown 文档复用共享原文/阅读模式组件；登记完成与编辑、放弃同处任务级菜单。

细节收紧：编码置于标题下；取消顶部常规进展/下一步重复内容；规范名称两行显示；审查分组与子记录建立明确层级；删除独立审查对象区块，保持两类多次审查。

按逐页审查统一规范和审查二级目录，报告减少重复状态及分隔线，保留真实检查结果和范围说明；引用文档只保留一个文件名与来源行，收尾和维护文案对齐系统样式。
