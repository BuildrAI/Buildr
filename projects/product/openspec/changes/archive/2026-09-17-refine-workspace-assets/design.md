## Context

现有三个清单已是共同事实；列表读取逐仓库同步调用七条 Git 命令。旧迁移按服务生成仓库，导致单仓库多模块重复登记。

## Goals / Non-Goals

保持单一声明与版本保护，移除列表的 Git 阻塞；不搬迁或删除代码，不改历史任务，不发布或激活共享运行环境。

## Decisions

- 独立 `/services`、`/repositories` 读取摘要；完整 `/asset-catalog` 供关系编辑，全部读取均只读声明。单仓库 `/repositories/:id/status` 承担 Git 观察，详情显式刷新。
- 全部新代码库使用 `git` 来源；无远端本地仓库不虚构 Git 地址或集成分支，旧 `workspace` 仅兼容读取。根位置与模块位置分开，已有目录必须经 Git 根目录校验；缺失目录只有明确远端声明才允许登记。`repositories/` 仅为新克隆默认值。
- 旧 workspace 声明显式归并，同一真实根只保留一个仓库身份，服务身份不变，模块路径重算。普通读取只报告待迁移。
- 删除沿用清单事务及 revision，服务删除同步清理项目引用，保留文件和历史记录。
- 页面编辑才加载完整关系，列表展示来自独立摘要。单仓库状态不自动触发全量扫描。

## Risks / Trade-offs

- 仓库可能离线或路径缺失：只阻止相关迁移，保留当前声明。
- 状态加载失败：明确显示未检查或失败，不把目录存在称为 Git 可用。
- 删除留下原目录：避免数据损失；同名重建仍遵守已有目录保护。

## Migration Plan

保留旧声明读取，新增显式规范化动作；迁移复用原事务并更新引用。自举声明只能经正式同步更新，本次不直接改受管工作空间清单。
