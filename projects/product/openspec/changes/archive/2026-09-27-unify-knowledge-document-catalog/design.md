## Context

知识查询已有按登记范围解析、安全文本读取、主题导航、成果分页及正文阅读器；普通文件未登记时无法列入“全部资料”。项目 README 阅读器可打开手册，但缺乏全量树。本次为文件发现增加只读查询，不改已有索引结构。

## Goals / Non-Goals

目标是让主题阅读保持紧凑、实际文档全集可浏览，并减少真实重复。实现不新增数据库、独立文档站、正文编辑器、文件监控、Git 操作或智能体托管；规范与技能仍由各自功能负责。

## Decisions

1. 保留旧 catalog 与 browse=all 行为，仅改称主题资料；新增 documents 查询与 browse=documents 模式，避免普通文件破坏图/地图分页和旧链接。
2. 文件发现归属知识查询，登记范围与关联服务由现有资产目录解析。当前范围内扫描普通 Markdown；工作空间公共内容仅扫描根级 README/CONTRIBUTING/SECURITY/CHANGELOG 与 docs 目录，分组显示，禁止目录跳转和符号链接。按真实文件去重，避免项目内服务重复出现。
3. 查询返回稳定文件身份、所在位置、相对路径、标题、已有成果标识和发现数量；读取只接受当前目录内的身份。正文按需读取，标题只读有限开头，目录有文件数和扫描项数上限。文件源始终权威，不缓存第二份目录状态。
4. 目录树由返回路径生成，各组显示数量、标题/路径过滤；重复或陈旧请求不覆盖新选择。已登记成果继续用原阅读器，其余使用同一 Markdown 渲染组件。相对引用只在已发现/登记范围内解析。
5. 合并产品说明与未来方向至概览，短流程至任务说明，开发导航至统一目录；架构入口不固定额外 index.md。调整引用与有实际影响的治理检查，不改历史归档或无关图示。

## Risks / Trade-offs

- 自动发现扩大可见范围 → 固定排除规则与安全文本边界一致，符号链接不扫描也不读取。
- 大仓库扫描耗时 → 跳过依赖、构建、规范历史和样本，限制目录项数与文件数，报告截断和局部诊断。
- 合并使旧文件路径失效 → 更新当期导航、索引与检查引用；保留 Git 历史，不制造长期重定向文档。
- 根公共说明不属于单个项目 → 独立分组，不伪装项目文件或利用 ../ 绕过范围。

## Migration Plan

新增只读接口兼容旧索引与 URL；正文迁移与导航在同次交付完成。回退代码和对应文档提交即可，无数据库迁移。
