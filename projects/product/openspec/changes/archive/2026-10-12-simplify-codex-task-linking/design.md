## Context

当前任务页先创建短期请求，再把用户导向全局面板；该面板不能发送当前聊天身份确认。已有长期关系按工作空间、任务、接入及具体聊天保存，支持幂等和关系自身版本校验，可以直接复用。动机见 proposal.md。

## Goals / Non-Goals

**Goals:** 用当前聊天的明确授权和准确身份直接建立关系，简化任务页操作，并使 Codex 聊天新建任务默认关联。

**Non-Goals:** 不改变任务记录事务，不让网页猜测当前桌面聊天，不替换桌面后台，不增加共享执行服务，不改变 DSH 或一次性生成。

## Decisions

1. 新增公共命令 `buildr codex link --target <workspace> --task <task-code> --native-session-id <direct-CODEX_THREAD_ID> [--connection-id <id>] --json`。由调用聊天直接采集身份，复用 Codex 关联应用的对象校验与存储。返回准确关系和双向链接；只读、关联和执行任务保持不同动作。
2. 已有接入范围有效即可直接关联，不把面板加载当作保存关系的前提。未指定接入时仅在存在唯一有效 Codex 接入时自动选择，多接入明确提示选择，不借默认生成智能体猜测。
3. 任务管理技能在 Codex 聊天创建任务成功后显式调用上述命令。通用任务创建命令不自动读取进程环境，以免子执行、工具服务、DSH 或无聊天任务误绑。关联失败只影响关系，不撤销已创建的任务。
4. 任务页不再创建或恢复待确认流程。默认只显示空状态或实际关系；展开帮助提供含固定任务链接的明确指令。已有面板和短期请求接口保留兼容，不迁移或删除旧数据。
5. 当前交付通过命令完成关联和返回任务链接，不要求升级或重新加载桌面面板才能使用。当前任务管理技能随正常 Buildr 同步投射；原插件的旧面板流程继续兼容，不重装当前桌面扩展。

## Risks / Trade-offs

- [调用方提交错误聊天身份] → 指引要求当前聊天直接读取 `CODEX_THREAD_ID`，禁止根编号、工具服务环境和委派代取；提交后核对返回的任务、工作空间和聊天身份。
- [显式新关联与旧请求并发] → 共用关系去重逻辑，保留旧回执重放不复活已解除关系的保护。
- [新建任务默认依赖智能体执行技能] → 明确这是 Codex 聊天工作步骤的默认行为，不声称任意命令或网页知道当前聊天；用真实命令链验证创建与关联。
- [聊天链接宿主行为变化] → 日常版验收必须由真实聊天链接点击证明原页面身份、数量和任务内容，不能用程序打开返回代替。

## Migration Plan

新增命令与简化后的 Web 一同交付，不改变现有关系结构。旧待确认请求留给旧面板流程处理；新 UI 不依赖它。按唯一自举执行器更新日常 Buildr，不修改当前桌面配置或重启桌面。回退界面和命令不删除已经保存的长期关系。
