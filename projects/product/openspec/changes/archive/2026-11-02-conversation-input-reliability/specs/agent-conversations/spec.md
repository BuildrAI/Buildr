## ADDED Requirements

### Requirement: 流式文字不得积压执行控制状态

系统 MUST 在有界窗口内合并同一执行和消息的可替代累积文字快照及重复运行观察；工具变化、问题、接收回执和最终状态 MUST 保持原身份与顺序及时处理，MUST NOT 等待旧文字逐帧持久化。合并 MUST 保留完整最终文字、原历史读取兼容和写入版本校验，不得改变真实工具结果。

#### Scenario: 长历史中的突发文字
- **WHEN** 大历史对话在短时间内产生大量累积文字与重复观察，随后出现工具或终态
- **THEN** 保存与传输次数 MUST 按有界合并窗口增长，最终文字及控制状态 MUST 及时可读，不逐帧重写整段历史

### Requirement: 补充消息必须核对原生接收与结束竞态

投递补充前 MUST 核对准确原执行及当前归属。只有原生接收回执或准确请求身份对应的原生用户记录才能证明送达。准确证明原轮已结束或原生明确拒绝且没有接收时，系统 MUST 使用稳定关联请求将已提交内容按原选择接续至独立新轮，明确返回接续结果；用户主动停止、并发新要求或身份变化 MUST 阻止旧输入自动接续。超时后 MUST 先核对准确原生接收记录，仍未知时 MUST 保留未知且不重发、不改写成成功。

#### Scenario: 发送瞬间原轮结束
- **WHEN** 同轮补充已明确提交，但原生核对证明原轮已结束或明确拒绝
- **THEN** 内容 MUST 只通过稳定关联身份接续一次，原轮记录保留真实未接收事实，新轮持有新要求和原选择

#### Scenario: 回执丢失但原生记录已有输入
- **WHEN** 补充接收等待异常但准确原生用户记录包含同一请求身份
- **THEN** 系统 MUST 回补接收事实且不再次发送；缺少准确证据 MUST 保持未知
