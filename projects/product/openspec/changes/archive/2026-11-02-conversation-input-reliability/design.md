## Context

Qoder 每段文字与重复观察均进入同步保存链，长历史放大重复序列化成本。补充当前仅等待10秒回执；原生先结束而展示仍落后时会发往旧轮。详情读取已有分页投影及旧写入兼容，本次保持。

## Goals / Non-Goals

修复高频事件进入保存链的数量、准确接收核对与结束竞态。不更换数据库权威、不重放未知命令、不修改真实运行记录。

## Decisions

- 在Qoder事件源合并累积文字，重复观察去重；控制事件立即冲刷此前文字，保持消息、工具和终态顺序。用可注入调度的独立小模块验证数量与顺序，避免在持久化失败边界添加异步写队列。
- 补充先观察准确原生执行；仅明确结束或明确拒绝允许接续新轮。使用原生回执或准确clientRequestId的用户记录确认接收，不根据文字相似猜测。
- 复用普通新要求的prepare/submit接续，持久保存的稳定关联请求身份及原尝试关联保证幂等，实际选择从原执行取得。未知输入不自动补送，当前交互变化停止旧输入的自动接续。
- 指定旧消息后来已有独立接收与针对性答复，保留最初未知及后续已接收事实，当前新要求不受干扰。

## Risks / Trade-offs

合并延迟 → 有界短窗口且重要事件立即冲刷；新轮接续与并发发送竞态 → 每次写入核对当前版本及执行身份；原生历史缺少准确请求身份 → 保留未知，不按正文推断。

## Migration Plan

无数据库格式迁移；只增加私有可选关联字段。旧记录与旧读取投影继续兼容。
