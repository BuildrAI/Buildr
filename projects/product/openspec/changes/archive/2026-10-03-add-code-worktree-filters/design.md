## Context

动机见[提案](proposal.md)。现有代码应用（Application）统一读取代码库登记位置、任务提供者证据或固定提交（Commit）；前端缓存键包含实例/任务/提交，但不含具体检出位置。任务列表将多个检出位置按相对路径去重，当前结果没有实际来源身份。

## Goals / Non-Goals

**Goals:** 保留同一只读能力，增加可观察的具体来源；所有入口按相同身份读取，单选同名任务组并浏览跨库成员；不同组的已打开文件仍可独立阅读。

**Non-Goals:** 不新增长期目录登记、不推测跨库分支关系、不管理Git写入；不改变现有任务列表的路径去重规则与计数语义。

## Decisions

### 真实目录与分组分开

`repositories` 输出增加 `worktrees`（具体成员）和 `worktreeGroups`（筛选组选项），另返回 `selectedWorktreeGroupIds`。每个成员包含 `id/repositoryId/groupId/path/branch/kind/taskId/available`，分组包含 `id/name/kind/taskId/repositoryIds`。`main` 表示各实例登记主目录；`task:<taskId>` 仅由提供者的真实关联证据建立，跨库名称统一；没有任务关联的原生工作树（Worktree）各自独立分组，即使名称相同也不合并。

目录来自注册实例的 `git worktree list`。提供者证据只证明任务关联，不作为目录存在或交付事实；不存在成员保留局部诊断。选择界面不让用户输入任意绝对路径。

### 具体检出身份固定读取

只读输入增加可选 `checkoutId`，来源输出返回 `checkoutId/worktreeGroupId`。身份依据Git公共目录（Common Directory）、真实检出根和Git管理目录的路径及文件身份生成；切换分支（Branch）不改变目录身份，移除后同路径重建不能冒充原来源。每次目录、搜索及正文请求重核Git登记和包含关系。固定提交（Commit）仍读取对象库，不依赖工作树（Worktree）继续存在。

未带新字段的既有请求兼容默认及任务解析；新的界面一旦观察到具体目录即携带该身份，不因刷新消失而回退。对消失和身份变化返回明确局部失败。

### 筛选与阅读独立

工作树（Worktree）使用单选，空选择统一对应 `main` 主目录；代码库保留多选，空选择表示全部实例。代码库维度取并集，再与单个组取交集；代码库候选由工作树（Worktree）选择限定，组选项由代码库选择限定，不静默扩大选择。同组跨库成员分别展示文件树，缓存键包含具体检出身份；已打开文件保持自身来源，不随着范围变化替换内容。旧标签在范围外明确标识，可主动切换到该文件的实际来源组。后端列表字段仍兼容既有调用，界面内部使用单个组状态，不构造多组筛选。

### 任务传递实际改动来源

任务改动列表在读取每个检出位置时保存 `checkoutId`；完整差异读取、刷新和跳转传递该身份。显式请求只能命中任务当前允许的真实检出位置，失效不重新按任务优先级选择。普通任务入口预选关联代码库与实际任务组；点击具体改动时实际来源优先，来源在主目录时直接选择主目录，不追加任务组。历史请求继续携带完整提交（Commit）。

### 跨库统一命名保持在创建职责

任务工作树技能（Task Worktree Skill）指导同一任务所有代码库（Repository）共用同一任务标识（Task ID）和工作树（Worktree）名称；默认位置仍为 `<workspace-root>/.worktrees/<task-id>`，独立代码库（Repository）保留其真实嵌套路径。Git 操作技能（Git Operations Skill）只指向该创建职责，不复制另一套规则。命名便于识别，实际跨库归组仍依据明确任务关联；不从同名目录或分支推断归属，不自动重命名已有对象。这是既有提供者（Provider）行为的操作说明补充，不新增契约（Contract）、绑定或写入能力。

## Risks / Trade-offs

- [多库目录枚举成本] → 枚举有界、按实例隔离失败；正文和后代目录仍按需读取，搜索保留结果上限。
- [证据失效与同名外部目录] → 以真实Git登记与提供者关联双重核对，不按名称建立关系。
- [旧任务入口缺少具体来源] → 保留兼容解析，新的改动路径始终传递来源，代表测试覆盖主目录与任务目录不同内容。
- [局部状态或响应竞争] → 缓存和请求键包含具体来源，旧响应不能覆盖新选择；选中成员消失明确告警。

## Migration Plan

输入和输出为兼容增量，无数据库迁移或新增依赖。构建生成的数据传输对象（DTO）与前后端一起更新。回退代码恢复原入口，不删除工作树（Worktree）或任务事实。
