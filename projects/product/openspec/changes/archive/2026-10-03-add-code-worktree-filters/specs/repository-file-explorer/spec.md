## ADDED Requirements

### Requirement: 代码库与工作树联动筛选
资源管理器 MUST 允许多选代码库与单选已观察的工作树（Worktree）组。代码库候选 MUST 由所选组的真实成员限定，组候选 MUST 由所选代码库限定；代码库多选取并集，再与所选单个组取交集。首次进入及未选择工作树（Worktree）时 MUST 查看各实例主目录；清空工作树（Worktree）MUST 恢复各实例主目录，清空代码库 MUST 表示全部实例。跨库成员 MUST 分别展示完整文件树，并按具体来源区分搜索结果及文件标签；范围变化 MUST NOT 改写已打开文件的内容或来源。

#### Scenario: 两种选择顺序得到相同范围
- **WHEN** 用户先选代码库再选相关工作树（Worktree），或先选工作树（Worktree）再选成员代码库
- **THEN** 候选只包含对方条件真实关联的对象，最终展示相同交集

#### Scenario: 默认及清空
- **WHEN** 用户直接进入资源管理器，随后清空工作树（Worktree）选择
- **THEN** 首次只展示各代码库登记主目录，清空后仍展示当前代码库范围中各实例主目录，不更改代码库或Git

#### Scenario: 切换同库工作树
- **WHEN** 一个代码库存在主目录和两个工作树（Worktree），用户从其中一个组切换到另一个组，且各自具有同名文件
- **THEN** 当前文件树及搜索 MUST 只展示所选组，已打开文件标签 MUST 保留各自具体来源及对应内容；将范围外文件加入查看时 MUST 切换到该文件实际来源组

### Requirement: 工作树分组与明确检出身份
系统 MUST 从已登记代码库的真实Git工作树（Worktree）登记发现目录。跨库任务组 MUST 依据已核对任务关联证据建立并使用统一名称，MUST NOT 仅凭分支（Branch）、目录或显示名称归并。无任务关联的原生工作树（Worktree）MUST 可独立选择。目录、搜索、正文与协作输入 MUST 保持已观察的具体检出身份；选中目录不存在或同路径重建时 MUST 返回局部诊断，MUST NOT 静默替换为主目录或其他同名文件。固定历史提交（Commit）读取 MUST 不依赖原工作树（Worktree）继续存在。

#### Scenario: 同任务跨库关联
- **WHEN** 一个任务有两个实际代码库工作树（Worktree）成员
- **THEN** 页面 MUST 以一个任务名称单选项关联两个成员；代码库筛选仍分别保留实例身份

#### Scenario: 名称相同但关联不同
- **WHEN** 两个原生工作树（Worktree）显示相同分支（Branch）或目录名称且无共同任务证据
- **THEN** 系统 MUST 独立展示，不能按名称合并

#### Scenario: 来源消失或被重建
- **WHEN** 人选择的工作树（Worktree）在后续读取前被移除，或同路径被另一检出位置替代
- **THEN** 该来源 MUST 明确失败，其他来源继续可读，保留原文件身份且不改读同名文件

#### Scenario: 任务预选及改动实际来源
- **WHEN** 用户从有实际工作树（Worktree）的任务查看源文件，或从任务主目录独有改动打开完整文件
- **THEN** 普通入口 MUST 预选任务关联组与相关代码库；具体文件 MUST 以改动实际检出身份为准，目录和关联文件继续使用同一来源；主目录文件 MUST 只选择主目录组，不同时选择任务组
