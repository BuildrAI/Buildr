## ADDED Requirements

### Requirement: Git 来源代码库登记后默认异步克隆

登记 git 来源的代码库实例（Repository Instance）时，系统 MUST 在同一版本保护内先完成登记写入，随后为该实例自动发起后台克隆（Clone）到其声明位置；克隆 MUST 使用登记的远程地址（URL）、远程名（Remote）与集成分支（Integration Branch），由本机 git 执行并继承既有认证环境。登记动作 MUST NOT 同步等待克隆完成，也 MUST NOT 要求用户额外选择是否克隆；克隆结果 MUST 不否定已成立的登记事实。

克隆发起条件 MUST 限于来源类型为 git 且目标位置尚不存在真实代码目录的登记：目录已存在的代码库 MUST 视为已准备，不再克隆；登记时目标位置已由他人建立的并发情形 MUST 不覆盖既有内容，并表达为已准备而非克隆失败。

#### Scenario: 新增 git 代码库登记成功
- **WHEN** 用户以 git 来源新增代码库并提交成功
- **THEN** 系统 MUST 返回登记成功及该代码库实例，并自动发起后台克隆；不返回克隆已完成承诺

#### Scenario: 服务或项目新增内嵌 git 代码库
- **WHEN** 用户在新增服务或新增项目流程中内联新增 git 代码库并整体提交成功
- **THEN** 系统 MUST 在完成对象及代码库登记后为新代码库发起后台克隆，行为与独立新增一致

#### Scenario: 克隆被并发目录成立抢占
- **WHEN** 后台克隆开始前，目标位置已出现真实代码目录
- **THEN** 系统 MUST 终止克隆并保留登记，把实例表达为已准备而非失败

## MODIFIED Requirements

### Requirement: 对象状态与编辑边界真实可见
系统 MUST 区分登记成功与本地代码准备完成，并区分「等待克隆」「克隆进行中」「克隆失败」与真实缺失目录。技能编辑 MUST 保持既有受管内容边界，并在不允许直接编辑时说明原因及可执行的维护入口。

#### Scenario: 代码待准备
- **WHEN** 新代码库已登记而目录不存在且克隆尚未发起
- **THEN** 系统 MUST 展示待准备代码，不能声称已克隆或阻止无关项目编辑

#### Scenario: 代码待克隆或克隆中
- **WHEN** 新代码库已登记、后台克隆尚未发起或正在进行
- **THEN** 系统 MUST 展示代码正在准备中，不能声称已克隆或阻止无关对象编辑

#### Scenario: 克隆失败
- **WHEN** git 代码库的后台克隆未建立可用目录
- **THEN** 系统 MUST 表达登记已成立且本地代码未能克隆的具体原因，保留该实例及源代码管理中的重试入口，不得表达为登记失败或干净目录

#### Scenario: 非登记目录缺失
- **WHEN** 已登记代码库的本地目录被移除、并非克隆进行中
- **THEN** 系统 MUST 展示代码目录缺失及重新克隆入口，不影响其他实例展示

#### Scenario: 陈旧编辑
- **WHEN** 任一对象保存时版本冲突
- **THEN** 系统 MUST 提示重新核对并保留输入，不能静默覆盖
