# git 来源代码库登记默认异步克隆，源代码管理提供克隆入口

## 问题

登记 git 来源代码库只写登记清单，不产生本地代码：新增代码库、服务新增抽屉内嵌新增代码库、项目创建内嵌新增代码库，登记后本地目录缺失，源代码管理页仅显示「登记目录不存在」。用户必须自行 `git clone`，本可自动完成的一步变成人工工序。

## 目标

- git 来源的代码库登记成功后，默认异步克隆到声明位置（`path`，使用登记的集成分支）。
- 克隆进行中与失败在源代码管理页真实可见，提供「克隆到本地」/重试入口；成功后可正常读取。
- 登记保持快速返回：克隆失败不回滚登记，诊断显式上报。
- 历史缺失库同样可通过源代码管理入口克隆，不再要求命令行。

## 范围

- `services/buildr/`：登记动作接入异步克隆；源代码管理新增克隆操作（异步、状态可观察、失败诊断可重试）；相关 HTTP 契约与 DTO。
- `services/buildr-web/`：源代码管理页对未克隆、克隆中、克隆失败的库提供入口与状态显示；创建抽屉不新增选项（默认行为）。
- `openspec/`：`workspace-asset-management-interactions` 与 `code-source-control` delta。

## 非目标

- 不处理凭证与网络认证策略，沿用本机 git 既有认证。
- 不提供「仅登记不克隆」选项；本地路径（workspace/attached）来源不涉及。
- 不改变已有克隆的更新语义（同步、拉取仍由现有操作负责）。

## 完成依据

- git 来源登记后源代码管理显示克隆中→可读取；失败显示诊断与克隆入口，点击重新异步克隆。
- 服务新增内嵌代码库同样触发克隆。
- openspec validate --strict 与 convergence preflight 通过；逻辑测试与浏览器端到端验证通过。
