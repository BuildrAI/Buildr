## MODIFIED Requirements

### Requirement: 关键页面说明与源码来源可以独立接续
新生成的原型 MUST 提供关键页面、必要状态、本次变化、主要功能、操作结果及边界的对应说明，并保持当前画面和说明一致。项目已有统一原型阅读器时 MUST 复用其页面目录、状态选择和说明交互，MUST NOT 只复用卡片后另造说明外壳；没有现成阅读器时才按技能（Skill）示例组装。独立预览的标题、关键状态选择、刷新与功能说明入口 MUST 在桌面首行共同呈现，窄屏 MUST 允许自然换行并保持操作可达。功能说明 MUST 复用技能（Skill）提供的组件（Component）、脚本与样式；独立预览 MUST 默认收回说明且不固定，用户悬停或点击入口时 MUST 以浮窗（Popover）临时查看，空间充足时 MUST 允许用户手动固定并排；窄屏 MUST 沿用统一阅读器的清晰入口和展开方式，避免初始遮住画面。任务阅读 MUST 使用宿主说明面板，不重复叠加独立面板。原型 MUST 记录可追溯的源码观察与已验证范围；自包含成果 MUST 能在离线安全隔离中独立展示，MUST NOT 依赖开发服务器、真实网络、父页面权限或浏览器持久存储。

#### Scenario: 说明随页面变化
- **WHEN** 用户从目录或原型交互进入另一已制作的关键页面或状态
- **THEN** 对应说明 MUST 与当前画面一致，重看指定画面 MUST 使用明确初始数据

#### Scenario: 交给后续智能体
- **WHEN** 后续智能体（Agent）读取本次演示成果
- **THEN** MUST 能确定覆盖的关键页面、来源观察、模拟边界和未验证项；成果 MUST 不替代正式行为规范

#### Scenario: 宽屏打开独立原型
- **WHEN** 用户直接打开新生成的自包含原型，且宽度足够并排阅读
- **THEN** 当前页面的功能说明 MUST 默认收回且不固定，保留清晰的“功能说明”入口
- **AND** 用户悬停或点击入口时 MUST 临时显示浮窗（Popover），手动固定后 MUST 并排阅读
- **AND** 说明悬停、聚焦及定位 MUST 使用同一说明组件（Component）及样式，不重置模拟数据

#### Scenario: 窄屏打开独立原型
- **WHEN** 用户直接打开新生成的自包含原型，且宽度不足以并排阅读
- **THEN** 页面 MUST 保留清晰的“功能说明”入口，按统一阅读器的既有方式展开和关闭
- **AND** MUST NOT 为默认展开说明而初始遮住原型画面

#### Scenario: 首行切换关键状态
- **WHEN** 用户在桌面查看带必要状态的独立原型
- **THEN** 标题、关键状态选择、刷新与功能说明入口 MUST 位于同一顶部操作行，来源说明 MUST 不将状态选择隔到下一行
- **AND** 窗口变窄时控件 MUST 自然换行，MUST NOT 导致页面横向溢出

#### Scenario: 在任务中查看原型
- **WHEN** 同一原型由 Buildr Web 任务阅读器加载
- **THEN** 原型 MUST 通过既有消息协议（Message Protocol）与宿主说明联动，MUST NOT 重复显示独立说明面板
