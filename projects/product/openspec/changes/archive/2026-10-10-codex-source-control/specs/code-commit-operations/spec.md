## Purpose

为当前已登记代码库（Repository）及具体工作树（Worktree）提供确定性的 Git 提交和普通推送能力，以明确来源、已观察内容、目标与真实结果隔离失败，并使智能体（Agent）不可用时仍能由用户手写说明完成提交。

## ADDED Requirements

### Requirement: 精确来源与内容观察

操作 MUST 只接受已登记实例和当前 Git 可核对的工作树（Worktree）身份，MUST 不接受任意目录。写入 MUST 核对已观察来源、分支、当前提交、索引（Index）及拟提交内容；内容、来源或相关配置变化 MUST 明确拒绝陈旧请求。未知、截断及冲突 MUST 不伪装成可完整提交；失败 MUST 只影响相关动作。

#### Scenario: 生成后内容变化
- **WHEN** 用户生成或填写说明后文件、索引（Index）或当前提交变化，再使用旧操作观察提交
- **THEN** 系统 MUST 拒绝旧观察并保留说明，允许刷新后按当前内容重新判断

#### Scenario: 工作位置被替换
- **WHEN** 原工作树（Worktree）被移除或同路径替换
- **THEN** 系统 MUST 拒绝旧身份，MUST 不改读或提交另一个来源

### Requirement: 提交全部当前变更

提交 MUST 由 Buildr 直接执行 Git，不依赖智能体（Agent）。范围 MUST 明确为所选来源全部未提交变更，包含新增、修改、删除、未跟踪和当前暂存文件的最终工作树（Worktree）内容。空说明、无变更或未解决冲突 MUST 明确失败，不执行空提交。失败 MUST 保留原有索引（Index）和未提交文件；已成立的提交 MUST 返回真实完整标识，后续变化不得被清理或覆盖。

#### Scenario: 暂存后继续修改
- **WHEN** 同一文件先暂存又继续编辑，另有新文件及删除文件，用户点击提交
- **THEN** 新提交 MUST 包含全部当前内容和删除，其他来源 MUST 保持不变，界面 MUST 重新观察文件及历史

#### Scenario: 未接入也能提交
- **WHEN** 没有可用智能体（Agent），用户手写非空说明并提交
- **THEN** 提交 MUST 独立完成，MUST 不为此启动模型服务

### Requirement: 固定目标普通推送

推送 MUST 固定已核实来源提交、当前分支、实际远端配置及完整上游引用，MUST 包含该分支所有未推送提交，并在操作处按需说明。系统 MUST 不猜测上游、不自动创建跟踪、不强推，也不依赖用户默认推送策略扩大范围。相关目标或提交变化 MUST 明确拒绝旧观察。

#### Scenario: 分支已有未推送提交
- **WHEN** 分支已经存在未推送提交，用户再提交并推送
- **THEN** 系统 MUST 推送完整当前分支范围到已核实上游，不把操作描述成只推送最后一条

#### Scenario: 没有上游
- **WHEN** 提交并推送时当前分支没有可核实上游
- **THEN** 已完成提交 MUST 保留，系统 MUST 明确尚未推送且不猜测远端或引用

### Requirement: 部分成功与安全重试

提交和推送结果 MUST 分别表达；推送失败、拒绝或结果不确定 MUST 不否定已成立提交。重试 MUST 仅操作已保存来源和已有提交，重新核对固定目标与版本，MUST 不重复提交。超时或响应未知 MUST 明示实际已知事实，不能把未知成功或失败当成可安全重放的依据。

#### Scenario: 提交成功但推送失败
- **WHEN** 本机提交成功后推送失败，用户点击重试推送
- **THEN** 系统 MUST 保留提交身份，只推送原来源已有提交，历史 MUST 不增加重复提交
