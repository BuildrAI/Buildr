## ADDED Requirements

### Requirement: 紧凑提交说明与操作

未提交变更模式 MUST 在文件列表前提供默认单行说明输入框、右侧统一智能体（Agent）生成图标及本次选择下拉，下方提供提交主按钮与提交并推送选择。多行说明 MUST 在同一输入框按需扩展；功能区域 MUST 不单独常驻执行者名称。顶部全局入口 MUST 显示当前默认智能体（Agent），抽屉 MUST 以紧凑列表表达名称、状态及唯一默认，接入和运行详情按需展开。智能体抽屉（Drawer）MUST 复用现有公共抽屉壳及关闭和窄屏行为；详情及生成结果来源提示 MUST 按需展示对应确认配置，不把模型设置加入首期界面。

生成 MUST 以当前具体来源全部未提交变更为目标范围，固定来源及已观察内容；读取不足 MUST 明示，不把截断当成全部内容。说明草稿与结果 MUST 按代码库（Repository）和工作树（Worktree）独立保留；切换来源、取消或失败 MUST 不清除原说明，迟到响应 MUST 不覆盖另一来源或新草稿。内容变化 MUST 提示核对。生成说明、Git 写入与既有代码读取 MUST 保持各自失败边界。

已有清单、差异（Diff）、历史及完整文件读取 MUST 继续遵守确定性只读边界；提交和推送 MUST 由 `code-commit-operations` 的显式写入能力承担，MUST NOT 因查看、筛选或刷新而触发。

#### Scenario: 日常手写或生成后提交
- **WHEN** 用户在未提交变更中手写说明，或点击图标生成后修改
- **THEN** 页面 MUST 在同一区域呈现可编辑结果及提交操作，默认布局 MUST 紧凑，读取和历史 MUST 保持

#### Scenario: 来源切换保留独立草稿
- **WHEN** 用户填写说明后切换工作树（Worktree），再返回
- **THEN** 原说明 MUST 保留，其他来源 MUST 不接收本来源的生成或提交结果

#### Scenario: 本次选择与全局显示
- **WHEN** 用户从统一图标旁下拉选择本次执行者
- **THEN** 顶部全局默认 MUST 不变；执行开始后本次覆盖 MUST 复位，结果来源 MUST 可按需查看

### Requirement: 有依据且有界的提交说明

生成 MUST 遵循实际适用的提交规则，默认采用 `type(scope): subject` 且不猜范围；语言 MUST 遵循适用规则，必要时才添加正文。标题 MUST 概括可见实际变化，MUST 不用泛泛文件清单代替变化含义，不编造动机、测试结果或目标完成。近期提交标题仅作有界格式参考；只有已核验关联的真实任务（Task）才能加入背景及唯一正确的 `Buildr-Task` 尾注（Trailer），无关联或冲突时 MUST 省略，不阻止普通生成。

Buildr MUST 准备有体积硬上限的必要材料，完整业务提示词（Prompt）MUST 按UTF-8限制为16 KiB。资料 MUST 包含实际全部未提交范围的准确统计、有限路径样本、少量真实差异（Diff）或新增内容片段、适用提交规范的有界摘录及最小已核验任务背景；MUST NOT 注入完整差异（Diff）、整份源码/规则/技能（Skill）/任务正文或聊天历史。材料 MUST 明确样本省略、规范与证据不完整事实；超预算 MUST 缩减资料继续生成，MUST NOT 以完整注入上限拒绝大文本或二进制。现有精确Git观察的局部路径及体积边界 MAY 保留并明确。

智能体（Agent）MUST 只据给定材料一次撰写，MUST NOT 自行读取文件、规则或Git，MUST NOT 调用工具（Tool）、修改、暂存、提交、推送或联网。资料不足时 MUST 保守概括，不编造未提供的事实或声称完整分析。规则准备 MUST 复用当前已选择规则的读取语义，按实际作用域和覆盖顺序提供提交相关摘录，不把局部摘录声称任意规范的完整语义解析。

结果发布前 MUST 重核 Git 内容版本、规则入口与已核验任务事实，以及本次材料实际依据的版本；已观察来源漂移 MUST 保留草稿并拒绝旧生成，不把旧关联尾注（Trailer）当当前结果。

#### Scenario: 大文本与二进制混合
- **WHEN** 当前未提交变化包含超过512 KiB的文本和二进制，且未超过既有Git内容版本观察边界
- **THEN** Buildr MUST 提供16 KiB以内的必要资料及省略说明，智能体（Agent）MUST 一次撰写且不补读，MUST 不因完整注入上限直接拒绝或编造未提供内容

#### Scenario: 无可靠任务关联
- **WHEN** 当前工作位置没有唯一且可核验的任务（Task）关联
- **THEN** 系统 MUST 生成普通提交说明，不猜测任务编码或追加虚假尾注（Trailer）

#### Scenario: 生成期间来源或任务关联变化
- **WHEN** 生成过程中 Git 内容、已观察规则入口或任务（Task）关联事实变化
- **THEN** 系统 MUST 拒绝发布旧来源或旧任务关联的生成结果，保留已有说明并提示重新核对

### Requirement: 提交说明采用轻量执行

提交说明 MUST 使用同一已选模型（Model）的低推理级别（Reasoning Effort），MUST 经内部端口指定60秒调用预算，MUST NOT 修改 Codex 全局配置或正式任务配置。Buildr MUST 在硬字节预算内准备必要资料，智能体（Agent）MUST 一次生成且不自行补读。输出 MUST 遵循适用提交规范，必要时添加正文，不预设条数，MUST NOT 编造未提供的内容或测试结果。

#### Scenario: 真实源码变更快速生成
- **WHEN** 用户对实际工作树（Worktree）的较多源码变更发起生成
- **THEN** 系统 MUST 在60秒调用预算内交付符合规则的结果或明确失败并保留草稿；性能验收 MUST 使用真实源码场景，MUST NOT 仅以填充大文件代替
