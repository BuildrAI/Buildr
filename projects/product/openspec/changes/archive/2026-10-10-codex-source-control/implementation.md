# 实现与边界

统一智能体操作层（Agent Operations）位于 `services/buildr/src/modules/agent-operations/`，代码业务通过公开模块端口调用；Codex 应用服务（App Server）的启动、协议、临时会话（Ephemeral Session）及关闭由具体适配器（Adapter）维护。代码业务绑定真实来源、完整内容版本和结构化生成结果，Git 提交与推送独立执行。

正式前端分工如下，沿用既有服务（Service）、构建和接口授权，没有新增依赖：

| 位置 | 职责 |
| --- | --- |
| `app/AgentRuntimeContext.tsx`、`features/agents/` | 全局登记、当前默认及紧凑抽屉 |
| `components/AgentActionControl.tsx` | 跨场景统一生成图标与本次选择 |
| `features/code/source-control-actions.ts` | 来源草稿、生成、提交与推送状态 |
| `features/code/api/code-actions-api.ts` | 所属功能的接口客户端（Client） |
| `features/code/components/SourceControlCommitPanel.tsx` | 紧凑输入与提交交互 |
| `SourceControlWorkbench` 的 `renderChangeActions` | 公共工作台的替换插槽 |

智能体抽屉（Drawer）使用公共 `DrawerShell`，与工作空间设置共享标题、右侧关闭、间距、遮罩及窄屏行为。模型（Model）与提供者（Provider）继承 Codex 配置；提交说明仅在本次会话（Session）使用已批准的低推理级别（Reasoning Effort），其他调用仍继承原配置，公开运行记录捕获 `thread/start` 的确认值，登记详情仅保留内存中的最近一次使用值；字段缺失明确未确认，不为展示启动服务。生成结果复制本次配置，后续切换或其他调用不重标旧成果。

提交说明输入在空白或单行手写时保持紧凑；生成或多行内容自动展开至6–12行，超出后内部滚动。提交与操作下拉使用 Ant Design `Space.Compact`，由共同来源管理高度、共边和外侧圆角，保留既有禁用、加载及独立Git状态。两条受影响浏览器旅程已验证空白、生成、长内容滚动、提交后复位、按钮几何及无智能体手写提交，不改变接口或写入规则。

提交提示词（Prompt）位于 `code-commit-message-application.ts`，有界材料由 `code-commit-material.ts` 构造。`code-commit-guidance.ts` 仍发现真实检出位置、规则入口和最小已核验任务，同源入口优先使用候选工作树（Worktree）版本，不合并共享代码库（Repository）的其他项目。Buildr提供准确范围统计、有限路径样本、少量真实差异（Diff）/新增内容片段及提交相关规范摘录；完整业务输入按UTF-8硬限制为16 KiB，超额缩减并声明省略，不发送完整目录权限路径包或全文上下文。证据先跨服务（Service）轮转，再在各实现区域取样，最多8份、共同8 KiB预算，避免路径顺序和单个文件挤占其他实现。材料版本绑定最终送出的内容摘要，发布前重核源码、入口、任务及实际材料依据。差异（Diff）样本关闭外部差异、文本转换和本次命令的清理过滤器（Clean Filter），不修改仓库配置；这不等同于改写既有Git观察或提交的过滤器语义。

提交规范沿用 Git 操作技能（Git Operations Skill），不固定语言、不猜范围、不编造动机、效果或测试；正文只在需要解释动机、行为差异或破坏性影响时添加，不预设条数。任务背景只使用可靠编码、标题和一句目标。规范摘录只面向当前说明，不保证任意超大或无标题自定义规则的语义完备，裁剪和未纳入来源须明确。

提交说明省略原生读取环境，使用现有供应资料执行路径；关闭原生命令、代码执行宿主（Code Mode Host）、外部扩展和MCP，同时关闭自动项目文档与宿主技能发现，只据已提供材料发起一次生成。意外工具执行事件会使本次生成失败并有界关闭自有实例，不降级补读或重放。模型（Model）仍继承，提交说明使用已确认的低推理级别（Reasoning Effort）和60秒总调用预算，公开HTTP不能覆盖；临时会话（Ephemeral Session）、实例复用、取消和已有草稿保护保留。输出先检查结构，再校验非空标题和真实唯一任务尾注（Trailer），最后重核来源与材料版本。

其他明确请求原生读取的内部调用保留现有具名权限配置（Permission Profile）及最小工具环境、范围身份检查、成功读取守卫和Git运行支持，不扩大为提交说明的执行要求。供应资料模式不再需要原生命令完成才能成功。Codex自身基准说明仍由配置装配，16 KiB仅约束Buildr业务输入；实际供应商词元（Token）与请求次数须另外实测。

## 明确限制

- 首期仅接入 Codex；正式任务的持久对话与 DSH 尚未实现。
- 完整提交观察当前最多1000条变更路径、16 MiB当前文件内容，生成和提交保持同一内容版本算法。业务输入另有16 KiB硬上限，通过有限材料和显式裁剪满足；大文本与二进制仍可生成，超过源码观察边界才局部拒绝。材料样本不代表逐文件完整分析，资料不足时保守表达。提交说明的60秒总预算包括排队、准备、生成和校验，超时保留草稿；普通调用保留原默认3分钟提供者执行预算。
- 首期不提供文件勾选、独立暂存管理、自动创建上游或强制推送。普通推送固定实际观察到的上游及全部待推送提交。
- 本机Codex必须确认临时会话（Ephemeral Session）、只读参数与实际执行配置，外部工具停用未经确认时不启动生成。具名权限配置（Permission Profile）及成功读取守卫仅适用于保留的其他原生读取模式，提交说明不要求或开放这些工具。
- 精确 Node.js 24.15.0 与本机 macOS 是本次验证现场。未执行原生 Windows/Linux 验收、公开发布或日常环境采用。

## 原型接续

`prototype/body.html` 保留用户确认的第四版原字节，供任务“方案设计”和“单独查看”展示同一组三个页面。原 `viewer.html` 的全部字节保全于 `prototype/viewer.html.accepted`，避免阅读器重复嵌套与重复列出页面。构建来源及重建入口仍保留，讨论期间临时入口用于对照。

本轮外壳完善后，模拟入口同样导入公共 `DrawerShell`，重建结果放入 `prototype/rebuilt/` 供对照；确认快照保持原字节，模拟入口不接入真实业务请求。
