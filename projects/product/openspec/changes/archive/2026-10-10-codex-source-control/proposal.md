## Why

源代码管理已经能查看真实变更，但用户仍需离开 Buildr 生成提交说明，再到其他工具提交。现在以已确认的第四版原型为入口，补齐 Codex 接入和确定性 Git 操作，让用户在同一现场完成说明、检查和提交。

## What Changes

- 新增本机智能体（Agent）登记、唯一默认选择及统一操作层（Agent Operations），首期仅实现 Codex 执行适配器（Adapter）。接入由智能体（Agent）调用 Buildr 能力完成，界面不要求用户填写本机路径、端口或凭证。
- 复用按需启动的专用 Codex 应用服务（App Server），每次生成建立临时会话（Ephemeral Session）；完全空闲 30 分钟回收，退出时关闭自己启动的实例。
- 按第四版原型增加紧凑说明输入、统一生成图标及本次选择、顶部当前默认入口与全局抽屉。
- 模型（Model）沿用 Codex 配置，仅提交说明使用已批准的低推理级别（Reasoning Effort）及60秒调用预算；按每次临时会话（Ephemeral Session）的确认值展示实际配置；抽屉复用现有公共壳。生成说明由 Buildr 准备有硬上限的必要材料，包含提交规范、可靠任务背景、完整范围统计、路径样本及少量差异（Diff）片段；智能体（Agent）只据所给材料一次撰写，不自行读取或调用工具（Tool）。
- 新增直接 Git 提交和提交并推送。提交当前来源全部未提交变更，推送固定已核实上游及全部待推送范围；漂移明确拒绝，部分成功保留，重试不重复提交。
- 保持已有读取接口、文件投射适配器（Adapter）、任务记录与分支切换兼容。无破坏性命令或数据迁移，不增加运行依赖。

## Capabilities

### New Capabilities

- `agent-operations`: 本机登记、统一调用与取消、Codex 临时生成及实例生命周期。
- `code-commit-operations`: 精确来源观察、提交全部变更、固定目标推送及部分成功恢复。

### Modified Capabilities

- `code-source-control`: 在未提交变更中提供已确认的紧凑说明与提交交互，保持读取和历史功能独立。

## Impact

后端涉及独立智能体操作模块、代码业务应用与 HTTP 契约、命令发现和网页退出资源回收；前端涉及全局入口、公共生成控件及源代码提交面板。测试覆盖本机进程协议、临时 Git 仓库及裸仓库、HTTP 授权、来源漂移和浏览器交互。任务说明见[任务说明](@task/codex-source-control)，确认原型归于本变更的 `prototype/`。
