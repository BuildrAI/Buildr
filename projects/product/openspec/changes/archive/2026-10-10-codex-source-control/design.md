## Context

现有代码模块拥有登记来源、真实工作树（Worktree）解析、只读接口和分支切换；现有 `observedRevision` 只覆盖状态及文件元信息，不足以证明拟提交内容。`agent-assets` 管理规则与技能文件投射，不能承载本次执行适配。网页具有全局配置档（Profile）与会话（Session）写入授权，但现有退出未等待模块资源回收。前端已采用 Ant Design 与公共源代码工作台。动机见 `proposal.md`，用户目标见[任务说明](@task/codex-source-control)。

## Goals / Non-Goals

**Goals:** 在既有模块边界内连接已确认原型与真实能力，以明确对象、版本和局部结果处理生成及 Git 副作用。首个执行提供者为 Codex，业务不依赖其协议。

**Non-Goals:** 不接入 DSH，不扩展为通用对话或调度平台，不增加文件勾选与暂存管理，不发布或替换日常环境。

## Decisions

### 1. 接入登记、统一操作与具体协议分别负责

新增 `modules/agent-operations/`，登记保存在当前本机网页配置档（Profile）数据目录，原子写入并校验版本。公开视图包含稳定身份、名称、能力、可用性、运行状态及必要确认配置，不暴露程序路径或凭证。`agent list/register codex/select` 供当前智能体（Agent）发现真实安装后使用；产品入口技能补充发现与完成标准。重复身份登记幂等，不从网页猜测安装。

统一应用提供异步开始、查询、取消和关闭；具体适配器（Adapter）声明能力并处理 Codex 协议。已有 `agent-assets` 保持文件投射职责。使用一个默认身份，并允许调用参数覆盖；运行记录保留捕获的接入版本。只保存有界内存执行状态，不建立持久生成对话库。

### 2. 专用进程与临时会话分别管理

通过已登记程序启动 `app-server --listen stdio://`，按逐行 JSON-RPC 协议（JSON-RPC）握手。每次生成建立 `ephemeral: true` 且经确认的只读会话（Session），按结构化输出模式生成 `{commitMessage}`。提交说明使用供应资料模式：不传原生读取环境，关闭原生命令、代码执行宿主（Code Mode Host）、应用、插件、MCP、钩子、多智能体及其他工具（Tool），显式关闭自动项目文档注入和宿主技能发现；只发送一次 `turn/start`，不静默重试已接受请求。若出现工具执行事件则局部失败并关闭自有实例，不能回退到读取。Codex 自带基准说明仍由其配置装配，不把业务16 KiB上限冒称完整供应商上下文上限。其他明确请求原生读取的内部调用保留具名受限权限与最小工具环境，不删除既有只读能力；其读取路径、写入/网络禁用及至少一次成功检查的边界只适用于该模式。供应商输出视为结果数据，不作为 Buildr 新授权。取消使用中断能力并保留草稿。

专用实例按登记身份复用，活动计数为零后启动 30 分钟回收计时，探测不延时。异常退出使实例失效并终结相关运行，下次新请求重新准备。退出通过可等待的资源关闭回调停止接受新请求、取消活动工作并有界关闭自有子进程，不接管桌面应用进程。

模型（Model）继承 Codex 对本次目录解析的配置。普通调用继续继承推理级别（Reasoning Effort）；提交说明经统一内部端口传入 `execution: {reasoningEffort: 'low', timeoutMs: 60000}`，仅在本次会话（Session）覆盖推理级别（Reasoning Effort），不改模型（Model）、提供者（Provider）或全局配置，也不新增设置界面。端口校验、复制并捕获参数，网页接口不开放任意执行配置。显式低级别必须由 `thread/start` 确认；不匹配或缺失时不发模型请求。普通调用缺展示字段仍不阻断。

适配器（Adapter）只从 `thread/start` 响应提取 `model`、`modelProvider`、`reasoningEffort` 白名单字段，运行记录固定本次确认配置，登记列表仅保留最近一次业务使用值。它们表达会话选定配置，不宣称模型执行遥测。提交说明的60秒预算从统一操作接收调用开始计时，涵盖排队、准备、模型执行和结果校验；超时立即终止本次结果并保留草稿，排队过期不打断别的运行（Run），当前执行则中断并有界清理自有资源。普通调用保留原默认180秒提供者执行预算，不采用上轮普遍只读300秒的延长。


### 3. 代码业务只负责场景与精确 Git 观察

代码业务解析已登记实例及真实工作树（Worktree），由内部材料构造器准备有界资料。完整业务提示词（Prompt）按UTF-8严格限制为16 KiB，固定指令先占预算，再给材料剩余额度。材料只包含当前分支/目标范围、最小已核验任务背景、全部变更范围的准确统计、有限相对路径样本、少量真实差异（Diff）或新增内容片段，以及适用提交规范的相关原文摘录；不传完整工作目录路径包、可读根清单、完整差异（Diff）、规则全文、技能（Skill）全文、任务正文或聊天历史。真实目录仍是内部执行参数，不因省略路径包而改变来源。

提交规范默认沿用 Git 操作技能（Git Operations Skill）：`type(scope): subject`，范围可省略且不得猜测；标题概括有证据的实际目的或行为变化，正文仅在需要说明动机、行为差异或破坏性影响时添加，不预设条数。适用语言和格式约定优先。Buildr 根据真实作用域及覆盖顺序、有界读取并摘录与语言、提交格式及尾注相关的规范；所选必需规则使用既有规则读取端口，不构造第二套清单解释。该摘录不是任意自定义规则的语义完备解析，超大、无标题或未命中片段的约定可能未纳入，须在材料中明确裁剪与未覆盖事实，不把它当已完整读取。没有可靠任务关联时不猜编码；有已核验关联则要求唯一正确的 `Buildr-Task` 尾注（Trailer）。

范围统计覆盖当前全部变更，路径只是有界样本；材料标明总数、已展示及省略数量、规范和证据是否局部。片段预算最多约8 KiB、最多8个文本文件、每文件约1–1.5 KiB，规范摘录约2 KiB、路径摘要约2 KiB，其余留给指令、小背景与编码余量。具体配额是内部实现，16 KiB完整业务输入是硬边界。已有文本不得冒称差异（Diff）：跟踪文件优先读取固定当前提交的有限补丁，新增文件提取有意义的有限当前内容；大文件、生成产物及二进制优先使用准确元信息。超预算时减少样本和片段继续生成，不能恢复旧512 KiB完整上下文拒绝或直接否定二进制变更。智能体（Agent）只据供应资料一次撰写，不再自己查看文件、Git或规则；资料不足时保守概括，不编造动机、效果、测试或完成情况，也不声称全面分析。

提交说明仍用已确认低推理级别（Reasoning Effort）和60秒总调用预算，日常10–30秒作为实际目标；真实源码必须重新测量输入字节、工具次数、耗时和说明质量，不能用填充大文件替代性能验收。既有精确Git观察的1000路径及16 MiB当前文件内容边界保持，它们不是模型输入上限。发布前重核同一源码内容、规则入口及已核验任务事实，同时重核本次材料实际依据的版本；漂移时拒绝旧结果并保留草稿。输出结构、非空标题和真实唯一任务尾注（Trailer）校验保留。

新增独立提交观察，覆盖来源身份、完整当前提交、分支、索引（Index）和全部拟提交文件的内容身份；提交前后分阶段重核。写入采用专用异步 Git 执行器与有界超时，保留必要错误信息，不复用会吞错误的只读执行器。提交阶段保护真实索引（Index），失败不把暂存状态作为附带损失；若采用临时索引（Temporary Index），成功同步必须受自有锁及已观察原索引保护。仓库配置的钩子（Hook）、过滤器（Filter）和签名保持，不宣称多命令为原子事务。操作期间后续文件修改保留为新未提交内容。

### 4. 接口与部分成功

保留已有 `GET /code/commit` 历史读取；新增 `GET /code/commit-context`、`POST /code/commit-changes`、`POST /code/push`、`POST /code/commit-message`。上下文返回精确观察版本、当前分支及推送目标观察；写入携带相应已观察值，经现有网页授权校验，写操作不进入只读执行器。

全局接口使用 `/api/v1/app/agents` 查询，`/select` 条件修改默认，`/runs?runId=...` 查询运行及 `/cancel` 取消；不开放任意目录和提示词的通用网页启动接口。代码生成入口只允许已登记来源。

提交结果独立包含是否成立、完整标识及推送状态；推送固定来源提交、实际远端配置和完整上游引用，返回可核对的重试观察。无上游只停止推送，失败重试只推送原已有提交；目标或提交漂移重新判断。Git 直接操作不依赖登记或模型可用。

### 5. 正式页面接续第四版原型

确认版位于 `prototype/`，保全 HTML、必要构建来源与截图。公共源代码工作台增加当前来源操作插槽，由页面编排业务钩子（Hook）；HTTP 访问保留在客户端（Client）。顶部使用独立全局智能体（Agent）上下文（Context）及抽屉，公共生成控件仅接收展示和动作参数。草稿按来源键保存；生成、提交、推送分别记录状态，页面切换不撤销已经发出的 Git 写入，不把迟到结果写入新来源。提交后刷新真实读取，清除的仅是已提交说明，不伪造文件清空。

智能体抽屉（Drawer）复用 `DrawerShell`，沿用工作空间设置等已有抽屉的标题、右侧关闭、浅遮罩、间距、窄屏及关闭行为，保留紧凑列表和按需详情。详情展示最近一次确认配置；首次使用前明确尚未确认。生成结果的来源提示固定本次执行者及配置，默认切换不改写旧结果。已确认原型快照保持，模拟入口共享本次公共壳源码并重建到独立输出。

### 6. 验证与知识影响

进程协议用真实子进程替身覆盖临时参数、复用、取消、失败及定时回收，再用本机 Codex 做有界真实生成。Git 测试使用独立临时仓库和本机裸仓库（Bare Repository），不推送产品仓库。前端执行类型、逻辑及对应页面浏览器检查，并在任务预览中与原型核对。

现有 `knowledge/docs/overview.md` 的“Buildr 不托管执行”解释以及相关技术说明受影响；当前仅评估，未取得知识维护授权时保留并提出具体校准建议，不把旧文档作为阻止实现的理由。实现必需产品入口技能和操作指引属于本次交付。没有新增服务（Service）、依赖或测试入口，复用已有声明。

最终职责、已验证现场、局部限制和具体知识校准建议见[实现与边界](implementation.md)。

## Risks / Trade-offs

- Codex 协议或本机版本变化 → 登记能力验证、握手和明确错误，禁止静默降级为持久会话（Session）。
- 文件、索引（Index）及配置并发变化 → 精确观察、分阶段校验和保留实际副作用，不能承诺阻止所有外部编辑。
- Git 钩子（Hook）或网络超时 → 有界执行、完整提交身份和分别报告，未知结果先核对，不自动重放。
- 全局默认与本次选择混淆 → 顶部显示默认，统一控件只覆盖下一次生成，运行捕获后复位。
- 进程资源泄漏 → 唯一实例所有者、活动计数、空闲计时和退出关闭测试。

## Migration Plan

新增本机登记文件从不存在状态开始，不迁移既有会话（Session）或凭证。已有只读和分支操作保持；未接入时生成不可用但手写提交可用。回退程序版本不删除用户代码或本机生成成果，新增登记文件可保留供后续版本读取。
