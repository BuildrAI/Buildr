## Context

现有文件监听按工作空间（Workspace）共享，但状态读取由每个浏览器文档各自启动。工作台聚合同步读取任务、偏好与每日演进；摘要读取还展开提交关联任务，动态复用全部聚合。

## Goals / Non-Goals

**Goals:** 降低多标签页启动时的实际 Git 状态检查数量，减少工作台无关数据读取；保持来源身份、变化失效、局部失败和即时刷新。

**Non-Goals:** 不改变页面布局、任务存储、Git 写入、远程获取或业务资料。

## Decisions

- 在现有后端观察的生命周期内保存共享读取。自动请求使用 `observation=shared`；默认请求继续即时读取。按工作空间、任务与代码库隔离，同一来源的在途请求共用承诺（Promise）。与纯浏览器主节点协调相比，后端共享可以覆盖不同浏览器并复用现有有界工作进程（Worker）。
- 共享结果最多保留 10 秒，单工作空间最多 128 项、4 MiB；每次先读取轻量登记与目录身份作为来源版本，变化通知在批量发送前立即使对应共享项失效。失败、监听诊断和变更中的结果不复用为完成结果；保留原 `readAt`，低频补查继续保留。显式刷新绕过并失效相关共享项。
- 后端读取接受观察拥有的取消信号（AbortSignal），不绑定第一个客户端的连接。释放观察和关闭应用取消工作；读取中发生变化时先完成在途检查，再为后续请求核对一次，避免无限取消。
- 新增 `/workbench/activity` 返回项目列表、范围和摘要。摘要读取不展开提交关联任务。前端依照工作空间页面可见上下文（Context）触发自动刷新，避免隐藏页面重复读取。
- 项目侧栏动态复用同一摘要客户端（Client）；资源管理器（Explorer）的代码库清单在本次请求内复用登记核对所得的 Git 公共目录，并按真实来源去重任务关联核对。下一请求重新观察，工作树（Worktree）成员身份继续独立核对，不引入跨请求目录结果缓存（Cache）。
- 连接目录的来源证明通过现有有界工作进程（Worker）池运行，沿用三阶段批量读取和全部文件描述符（File Descriptor）核验。后台入口按需加载完整应用，连接检查只加载目录及源读取模块；池在服务启动时提前就绪一个轻量线程，其余容量按需启动，不额外创建专用池。认证和实例投影仍由原应用在主侧执行，后台不接收认证。
- 同一真实来源与工作空间编号仅合并在途目录检查，每次加入重新核对范围；完成或失败立即释放，不缓存完成结果。写操作前后使相关在途共享项失效，关闭应用取消所有共享检查；单个客户端断开不取消其他等待者。来源检查后重新核对工作空间及根目录身份，变化则拒绝混用。
- 目录客户端（Client）显式设置 `cache: 'no-store'`，与响应的禁用缓存（Cache）策略一致，避免浏览器对同址请求排队使后台无法合并。
- 冷启动和多标签耗时需与修改前同条件比较；同时观察普通读取延迟，不能以后台化掩盖首次打开退化。
- 无新依赖或存储迁移，旧客户端按原契约继续工作；回退时移除新客户端参数及接口调用即可。

## Risks / Trade-offs

- 漏监听可能让共享结果短期滞后 → 最长 10 秒、恢复及低频核对、手动即时刷新；不把旧观察时间伪造成刚检查。
- 来源替换或登记变更 → 每次校验轻量登记版本及真实目录和 Git 入口身份，范围隔离，变化即失效。
- 共享工作增加存活时间和内存 → 有界项数、字节预算、空闲释放和关闭取消。
- 摘要优化遗漏详情 → 保留原完整每日演进接口和分组测试。
