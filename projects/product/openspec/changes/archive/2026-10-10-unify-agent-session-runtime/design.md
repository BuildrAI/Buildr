## Context

现有 `agent-operations` 已有登记、默认选择、`startGeneration`、执行（Run）查询与取消、串行队列、进程回收和配置确认。内部提供者类型仍引用 `CodexAppServer`；提交说明业务已通过该应用调用，不需要另建任务执行平台。

Codex 已通过应用服务（App Server）提供临时生成。DSH 本机版本的 ACP 入口会启动独立服务进程；协议本身没有等价的临时标志或原生输出结构约束。已核对的源码提供会话持久化接缝，且 ACP 默认组合与桌面默认配置不完全相同。因此，“用 ACP 接入”不能替代临时语义、工具禁用和配置来源的实际验证。

## Goals / Non-Goals

**Goals:** 用最小改动让 Codex 与 DSH 复用现有统一生成能力，以提交说明验证两条接入路径。明确登记、进程、内部临时上下文和单次执行的区别，不把这些概念都升级为新管理实体。

**Non-Goals:** 持久会话（Session）表或增删改查、历史投影、恢复旧桌面对话、正式任务对话页面、待输入或待授权交互、配置档编辑、多策略实例池、并发调度器、面向所有产品的通用 ACP 平台。

## Decisions

### 1. 沿用统一操作层，只提取最小提供者接口

业务继续调用现有 `startGeneration`、查询和取消能力。将当前 `Pick<CodexAppServer, 'alive' | 'start' | 'generate' | 'close'>` 提取为中立生成提供者接口，输入、结果和运行状态复用现有结构，仅补足 DSH 所需的协议、配置来源及明确失败原因。

| 业务与统一操作层 | 具体提供者 | 自有服务进程 |
|---|---|---|
| 现有提交说明 → 统一生成入口 | Codex 提供者 | Codex 应用服务（App Server） |
| 同一入口 | DSH 提供者，内部使用 ACP 客户端 | DSH ACP 服务 |

ACP 客户端首版只服务 DSH 所需调用，不先抽象全产品协议框架。Codex 保留原接入方式。相较于新建统一会话控制器，这一边界已有第二个真实使用者，且可保持业务接口稳定。

### 2. 每个智能体最多一个服务进程

接入登记保存调用方式，不绑定某个进程编号。每个已登记且被使用的智能体（Agent）最多一个 Buildr 自有服务进程；Codex 与 DSH 是不同程序，各用自己的进程。只使用一个时，不启动另一个；二者都使用过时，各可保留一个。首版不增加“全局只能运行一个 Agent”的切换策略。

沿用每个智能体串行队列。首次调用才启动，后续复用；完全空闲30分钟回收，状态查询不续期；退出 Buildr 时停止接受请求并有界关闭自有进程，关闭网页不算退出。不会关闭用户独立运行的桌面应用或命令行程序。

每次生成解析原生默认配置。若变化可在新临时上下文中设置，复用进程；若 DSH 必须重启才可应用配置，则等当前执行结束，确认旧进程退出，再启动新配置。排队和重新准备仍计入本次原有预算，不允许旧、新策略进程并存。

取消或超时先中断当前请求；中断无法确认时，有界关闭该智能体的唯一自有进程。尚未发出的排队请求保留独立状态，后续可重新启动；已接受的模型请求不自动重放。排队请求过期不得打断正在运行的其他请求。

### 3. 临时会话只作为一次生成的内部资源

一次 `generate` 内创建独立临时上下文，取得并校验结果后释放；不向业务新增会话管理接口或持久会话标识。统一操作层只保留已有执行（Run）身份、状态、结果、取消和必要诊断。

Codex 继续使用已确认的 `ephemeral` 行为。DSH 使用最小 ACP 兼容组合，以内存实现接替原生会话持久化，并在每次生成结束后释放对应内存记录。关闭会话不等于删除已落盘记录，不能把普通 ACP 的关闭动作冒充临时会话。

DSH 必须实际禁用原生工具（Tool）、外部工具（Tool）、自动项目上下文及可关闭的对话日志上传；原生认证能力仍保留。验证本地不产生持久生成对话、第二次请求不带前次上下文、无工具可用且没有工具事件。只搭建这条生成路径所需组合，不复制或修改厂商源码，不静默回退到其他接入方式。

### 4. 默认配置直接使用，结果如实显示

Codex 保留按工作目录解析配置的行为。DSH 复用原生登录凭据，由接入层桥接桌面有效默认模型（Model）、推理级别（Reasoning Effort）及必要自定义提供者路由；凭据由 DSH 在自己的原生位置解析，不复制进 Buildr，不启动桌面组合来代替 ACP 服务。

提交说明保持选定模型，仅对本次采用低推理级别（Reasoning Effort）。DSH 按实际模型能力映射并取得确认，不能直接假定 Codex 的 `low` 值通用。缺少必要确认时在模型请求前局部失败。详情区分配置来源和最近一次实际确认值，不为展示而启动服务，不新增模型设置表单、未来配置档结构或版本体系。

### 5. 复用现有提交说明和界面

保留已确认原型与当前界面：全局智能体（Agent）列表和默认选择、统一图标及单次选择、可编辑说明、取消、复制、提交和提交并推送。仅补充 DSH 接入方式、原生默认配置来源、实际使用值及本次不能生成的原因。不增加会话页面或执行过程面板。

Buildr 继续提供上限16 KiB的必要材料，整个调用上限60秒，包含排队、启动、准备、生成和校验；一次模型生成、零工具，不补读，不用第二次模型请求修复格式。结果沿用既有提交规范、`Buildr-Task` 归属规则、来源版本及草稿保护。

Codex 保留原生 `outputSchema`。DSH ACP 没有等价字段，由提示词（Prompt）要求 JSON，返回后执行结构与既有业务校验；这不宣称原生约束输出。格式失败明确失败并保留草稿。普通 Git 提交、推送与模型服务保持独立。

### 6. 原清单的审查处置

| 上一版内容 | 首版处置 |
|---|---|
| 1.1–1.4 中立类型、登记兼容、临时执行、Codex 回归 | 保留并合并；删除完整会话对象和公开会话接口 |
| 2.1–2.4 ACP、原生配置、实际确认 | 保留；能力检查限于本次生成必需项 |
| 2.5 策略进程池 | 改为每个智能体一个进程、串行执行及顺序重启 |
| 3.1–3.5 临时无工具、结果校验、现有界面、真实验收 | 保留并合并 |
| 4.1–4.4 持久会话、历史、回应、多会话故障管理 | 移出；当前请求取消和超时并入既有执行管理 |
| 5.1–5.5 文档、持久数据设计、检查 | 只维护本次实际受影响指引和说明，删除持久数据设计，保留相关验证 |

未来出现多轮正式协作或独立配置需求时，再扩展会话操作与配置能力。本次不预建接口、数据表或页面占位。

## Risks / Trade-offs

- DSH 版本中的内存持久化组合或工具禁用无法兑现 → 在接入阶段实测，不能验证则只阻止 DSH 生成，不改用别的协议，也不影响 Codex 或直接 Git。
- DSH 原生配置桥接遗漏自定义路由 → 同时验证默认官方提供者与已有自定义提供者；只传必要路由，保留原生认证。
- 单进程串行执行可能排队 → 复用既有60秒总预算和取消，不为首版扩建并行实例。
- ACP 文本结果无法保证原生结构输出 → 一次返回后确定性校验，格式错误保留草稿并明确失败，不自动追加请求。

## Migration Plan

1. 提取现有生成提供者接口并扩展登记，验证旧 Codex 登记、默认选择和调用行为兼容。
2. 实现 DSH 最小 ACP 生成路径、原生配置桥接及单进程生命周期；在真实版本验证临时、无工具和实际配置。
3. 接入现有界面，使用真实源码变更测量耗时、材料量、模型请求及工具次数，核对提交规范与取消、来源、草稿保护，校准实际受影响的指引。

本轮按已确认精简范围实施；以上能力须以实际运行验证后报告。回退时保留原 Codex 登记和用户草稿，禁用未通过验证的 DSH 生成；不迁移或删除桌面已有会话。
