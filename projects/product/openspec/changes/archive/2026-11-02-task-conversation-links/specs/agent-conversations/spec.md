## MODIFIED Requirements

### Requirement: 内部对话必须具有独立稳定身份和准确工作范围

Buildr MUST 为每段内部对话（Conversation）保存稳定身份、标题、所属工作空间（Workspace）、准确起始目录（CWD）及观察版本。标题、可见历史和入口 MUST 不随执行方切换而改变归属。普通对话 MUST 不要求关联任务（Task）；每段对话 MUST 可以保存零到多个同工作空间任务引用，与任务构成多对多关系，旧单任务引用 MUST 无损兼容读取，创建后 MUST 可以按当前观察版本设置、更换或解除，任务身份 MUST 由宿主权威校验且 MUST 不复制任务状态。工作目录 MUST 在首次发送前明确可见并固定到该原生执行范围，查看其他页面 MUST 不自动改写它或注入页面内容。

#### Scenario: 普通咨询无需任务
- **WHEN** 用户从全局入口创建普通对话
- **THEN** 系统 MUST 创建独立对话并显示当前保存的工作空间（Workspace）与执行位置，不强制创建任务（Task）
- **AND** 创建或打开动作 MUST 不自动发送模型指令

#### Scenario: 创建后维护任务引用
- **WHEN** 用户对准确对话明确设置、更换或解除任务引用并提供当前观察版本
- **THEN** 系统 MUST 校验任务身份后原子保存新引用，隐藏、标题等其他字段 MUST 不被该动作改写
- **AND** 任务不可用、版本冲突或工作空间不受支持时 MUST 拒绝并保留原引用与全部历史

#### Scenario: 浏览另一工作对象
- **WHEN** 用户在保留当前对话时打开另一任务或项目页面
- **THEN** 当前对话的身份、草稿、归属和执行位置 MUST 保持
- **AND** 新页面内容 MUST 只有在用户明确加入时才成为交付输入

### Requirement: 任务入口必须只维护内部对话引用

一个任务（Task）MUST 可以具有多段内部对话（Conversation），任务入口 MUST 按零、一、多条实际关系分别创建、直接打开或选择准确对话。创建前 MUST 核对已登记工作空间（Workspace）及任务身份，保存任务引用而非复制任务状态。内部关系 MUST 不混入旧外部原生会话（Session）关系数量，也不因新增参与者而重复关联。关联 MUST 不授权跨任务执行或建立通用关系管理器。

#### Scenario: 任务尚无内部对话
- **WHEN** 用户在任务中选择打开内部对话且不存在对应记录
- **THEN** Buildr MUST 创建关联该准确任务的新对话并展示输入界面
- **AND** MUST NOT 自动寻找或打开外部桌面会话

#### Scenario: 任务存在多个内部对话
- **WHEN** 一个任务有多段内部对话
- **THEN** 系统 MUST 允许用户按对话标题、时间及状态选择准确目标
- **AND** MUST NOT 仅根据最近活动或当前 Agent 品牌猜测目标

#### Scenario: 点击必须展示准确对话
- **WHEN** 用户点击关联对话或从多条清单选择一条
- **THEN** 系统 MUST 展开对话面板并读取该准确身份，失败时 MUST 展示错误，不发送消息

### Requirement: 对话入口必须可以查看并维护所属任务引用

每段内部对话（Conversation）MUST 提供关联任务（Task）的入口，展示当前任务引用，并允许在同一工作空间（Workspace）内选择已有任务建立关联或解除关联。建立或更换前 MUST 核对准确工作空间及任务身份；解除 MUST 只移除引用，不删除任务或对话。系统 MUST 不在对话入口创建任务或建立通用关系管理器；未关联任务时对话 MUST 继续可用。

#### Scenario: 从对话关联已有任务
- **WHEN** 用户在对话的关联入口选择同一工作空间内一个存在的任务
- **THEN** 系统 MUST 保存该任务引用并展示当前关联
- **AND** 对话历史、执行状态与任务记录本身 MUST 不受影响

#### Scenario: 解除或更换任务关联
- **WHEN** 用户在关联入口解除或改选其他任务
- **THEN** 系统 MUST 只更新引用并保留原任务与对话各自事实
- **AND** 任务侧按引用列出的对话清单 MUST 反映最新关系

#### Scenario: 多任务双向导航
- **WHEN** 用户给同一对话添加第二个任务并刷新
- **THEN** 两个任务 MUST 均保留且可点击打开准确任务，两个任务的对话清单 MUST 均包含此对话

#### Scenario: 逐项解除关联
- **WHEN** 用户移除其中一个任务引用并提交当前对话版本
- **THEN** 其他引用 MUST 保留；版本冲突 MUST 不覆盖最新集合

## ADDED Requirements

### Requirement: 智能体执行任务必须维护当前对话关联
在准确绑定的 Buildr 内部对话中，智能体 MUST 在成功创建、激活或明确接续本轮实际执行任务后维护该任务与当前对话的关联，不要求用户手动补关联。系统 MUST 提供接受准确任务身份、在同次调用内读取当前集合并按已观察对话版本条件写入的追加关联动作；调用方 MUST 也能提供明确观察版本进行校验，复用同工作空间宿主校验及版本化写入，MUST 保留其他关联；重复关联 MUST 不创建重复关系或修改任务状态。仅提及、只读查询、浏览页面 MUST NOT 自动建立关系。缺少准确对话绑定时 MUST NOT 按最近对话、进程或目录猜测。任务登记成功与对话关联成功 MUST 分别核对，关联失败 MUST 保留已成立任务和其他关系，不冒充已关联或回滚任务。

#### Scenario: 智能体创建任务后自动关联
- **WHEN** 智能体在已绑定内部对话中创建本轮实际执行任务成功
- **THEN** 智能体 MUST 使用当前对话观察版本追加该任务并核对保存结果，用户无需点击关联

#### Scenario: 接续多个任务
- **WHEN** 智能体明确接续本轮第二个实际执行任务且当前对话已有第一个关联
- **THEN** 新关联 MUST 保留第一个任务，重复追加 MUST 不改变集合或发送模型指令

#### Scenario: 版本变化或任务不可用
- **WHEN** 追加关联使用陈旧版本或不属于当前工作空间的任务
- **THEN** 系统 MUST 拒绝相关写入，保留任务记录、当前关联及对话历史，智能体 MUST 重读判断而非覆盖集合

#### Scenario: 普通查询不建立关联
- **WHEN** 智能体仅查询其他任务或用户只浏览另一任务页面
- **THEN** 当前对话的关联集合 MUST 保持不变
