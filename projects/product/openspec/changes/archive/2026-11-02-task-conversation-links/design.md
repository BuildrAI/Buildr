## Context
现有对话使用 taskId、任务按 task_id 筛选；Web 已有任务关联选择器和任务对话入口。

## Goals / Non-Goals
**Goals:** 多对多关联持久化，旧数据无损读取，智能体工作中自动维护关联，双向准确导航与错误反馈。
**Non-Goals:** 不创建任务、不从聊天推断关联、不改变执行目录或任务状态。

## Decisions
- 用 taskIds 数组维护完整集合，taskId 作为首项兼容投影；旧记录缺数组时按单项读取。显式空数组表示解除全部。
- 复用对话 JSON 持久化及当前版本事务，不建立任务数据库双写；任务筛选通过 JSON 数组成员匹配，兼容旧 task_id。
- 对话多选入口逐项增加/移除，已有任务链接独立导航。任务入口继续使用准确 workspaceId/conversationId，读取失败可见；选择器支持后续页。
- 执行与派生对话保留完整关联集合，taskId 继续用于兼容的单任务执行定位，不把多关联解释为执行授权。

- 复用当前对话的本机控制命令增加 `link-task`，只接受准确任务标识和可选已观察版本；同次命令内先读当前集合，再把即时观察版本交给现有对话更新应用追加保存。可选版本显式钉住观察，避免正常工具执行自身的版本变化导致关联总是过期。复用后台认证、宿主校验和版本事务，不新增任务数据库双写、不自动启动后台。
- 由任务技能要求智能体在成功创建、激活或明确接续本轮执行任务后调用追加动作并核对结果。仅查询、提及、浏览不关联；没有准确内部对话绑定时不猜关系。登记与关联分别报告；失败不回滚任务，不把关联动作变成人工待办。
- 关联判断属于智能体，不把任务命令全局拦截或聊天关键词识别作为关系权威；系统提供确定性追加能力，手动 UI 作为纠正入口。

## Risks / Trade-offs
- 关联更新限制为最多 100 项，避免关系数据无界放大对话执行上下文；超限明确拒绝，原集合保留。
- JSON 成员查询不如独立索引快，但复用现有低频任务查询，避免额外迁移与双写风险。
- 旧客户端提交 taskId 仍表示替换集合；新客户端使用 taskIds，不同时提交两个字段。
- 失效任务引用仍可见、可移除，导航失败不伪装成功；新增引用须由宿主验证。
