# 连接 MySQL 与直接看数据：第五轮设计

状态：generated，讨论草案与离线原型（UI Prototype）。未接真实 MySQL 或加载真实智能体（Agent）工具。第四轮已保全在 previous-v4/，仅供历史对照。

## 本轮只解决两个目标

1. 智能体（Agent）在已有会话中能自行查 MySQL，取得真实数据以核实问题。
2. 用户能在 Buildr 直接查看数据，必要时改查询语句（SQL）继续查，无需另开 DataGrip。

用户描述现象、场景、业务编号和已知线索，智能体（Agent）结合代码与可用工具自行寻找证据；不要求用户提前知道库表或提供完整排查步骤。这轮只设计上述使用方式，实际网络、认证及工具装载留到接入实施时验证。

## 架构：两个入口，共用连接与只读查询能力

| 入口 | 做什么 | 用户看到什么 |
| --- | --- | --- |
| 已有智能体（Agent）会话 | 发现连接（Connection）、查看结构、执行只读查询，按现场继续分析 | 会话中的解释和一个“查看数据”引用 |
| Buildr 数据页 | 选择连接（Connection）与库，查看结果，按需编辑运行查询语句（SQL） | 数据表格，必要时展开语句 |

Buildr 保存连接（Connection）信息；本机执行端（Executor）负责网络、认证身份与凭据解析。两种入口使用同一专业查询能力和相同执行边界。MySQL 维护实际数据的权威事实，结果是一次查询时的观察。

“查看数据”引用指向该次查询的目标、实际语句、时间与返回数据，不是一个需要人接管的会话。用户从这里修改语句并运行，形成自己的新结果；首版不设计人与智能体（Agent）同步编辑同一份草稿、自动接管或观察版本协议。智能体（Agent）仍可按用户后续目标重新查询。

工作空间（Workspace）管理连接（Connection），环境（Environment）是用户可自行命名的文本属性，可选择已有值或直接输入新值，例如 qa、prod、uat、staging、客户A测试；这些只是示例，不是固定枚举，不建设独立环境模块。类别（Category）与具体类型（Type）保留在整体架构；当前唯一设计类型为 MySQL，界面不要求用户反复选择已固定的类别或类型。项目（Project）与服务（Service）关联可用于以后定位，首版不在连接编辑之外增加解释卡片。

## 页面一：连接

简单连接列表显示名称、环境（Environment）、类型、地址及默认数据库（Database）。每条连接（Connection）只有“查询”和“编辑”两个主要动作。

- 查询：为该连接（Connection）打开新的查询，使用其默认库生成示例语句或留空，展开编辑区；不把另一连接（Connection）的旧语句当成新查询。
- 编辑：直接打开统一抽屉（Drawer）。
- 新增连接：同样使用统一抽屉（Drawer）。

移除单独的“查看连接”详情页、配置详情页签、引用关系卡、目标版本号和认证诊断长说明。必要配置集中在编辑抽屉（Drawer）：名称、环境（Environment）、主机、端口、用户、密码和可选默认数据库（Database），参考用户提供的 DataGrip 常规表单，保留统一抽屉（Drawer）。不暴露认证来源引用等内部实现，不增加驱动、协议、SSH 等高级选项。正式接入时凭据在本机安全保存，不写入仓库、提示词（Prompt）或结果内容；本轮密码仅作虚构内存演示，不连接或保存真实凭据。环境（Environment）可输入新值或选择当前已有值，保存时去掉首尾空白并保留大小写和中文；命名不授予权限。

连接表单可提供“测试连接”的演示入口，只报告离线演示，不冒充实际连通。配置保存仅代表声明更新，不表示已经连通。执行所需条件不满足时就地说明，不为首版新增一套诊断模块。

## 页面二：查看数据

页面默认以结果表格为主。顶部选择连接（Connection），名称及用户自定义环境（Environment）可清楚辨认。编辑器旁选择当前默认数据库（Database），用于未写库名的表。

从智能体（Agent）返回的结果引用进入，先看到数据，语句默认收起。用户点击“查询语句”可以展开编辑区，再修改和运行。从连接列表点击“查询”进入时，编辑区默认展开。

语句、运行、结果在同一页，结果区只显示数据、行数、查询时间和必要分页。实际执行的语句按需查看；修改输入后保留旧数据时只显示简短提示“语句已修改，运行后更新结果”，避免把未执行输入冒充结果来源。

保留一列简洁数据库（Database）资源列表，在编辑语句时显示；可勾选要显示的库，不展开表和字段树。移除多层查询页签、本次查询列表、历史选择器、操作者版本标签、观察状态、接管/重读按钮和产品中的离线演示菜单。演示入口差异仅由原型阅读器（Prototype Reader）状态表达，产品本身无需选择协作模式。

在数据页切换连接（Connection）时清空旧结果、不自动执行，并保留输入。修改编辑器默认库时，未限定表名的旧结果清空；已明确限定库名的查询仍显示其实际结果目标，不被默认库重标。从连接列表打开新查询则生成对应连接（Connection）的新稿。再次运行时按实际语句和账号权限查询，不把旧数据放到新目标下继续展示。

## 三种数据库（Database）概念

| 项目 | 表达什么 | 不承担什么 |
| --- | --- | --- |
| 连接表单的默认库 | 新查询的初始库，可不填 | 不把连接（Connection）锁定到一个库 |
| 资源列表勾选的库 | 哪些库显示在资源列表中 | 不授予或限制权限，不改当前语句 |
| 编辑器的当前库 | 未限定表名时的默认库 | 不覆盖语句明确写出的库名 |

查询 `orders` 时使用编辑器当前库；查询 `billing_qa.invoices` 时使用语句明确指定的库，即使当前默认库是 `orders_qa`。未勾选显示的库仍可明确指定，前提是同一连接（Connection）的账号实际可访问。不能用显示过滤或默认库不同作为拒绝依据；未知库、无权访问或其他连接（Connection）的对象仍按实际边界失败。

结果显示实际查询目标与执行语句，不能把编辑器默认库误标成显式限定名使用的库。首版封闭示例执行器（Executor）只演示单表查询，复杂跨库关联不在本轮模拟范围。智能体（Agent）发现结构也依据账号可访问库，独立于人的显示勾选。

## 两条基本使用路径

### 智能体（Agent）查询，用户看数据

用户在已有会话描述问题 → 智能体（Agent）自行发现结构并查询 → 返回解释及“查看数据”引用 → 用户打开表格。需要继续探索时，再展开语句修改运行。

### 用户直接查询

连接列表点击“查询” → 选择当前默认库，输入或粘贴查询语句（SQL），也可用 `database.table` 指定库 → 运行 → 查看数据。

排查不固定为应用内工作流（Workflow），不新增聊天页面，不要求每次由人执行，也不要求先命名保存查询。智能体（Agent）的使用指引放在专业技能（Skill）中：先核实连接（Connection）与库范围，按问题查看结构并收窄查询条件；以实际结果作判断，达到行数上限时不推断已经查完。指引帮助组合工具，不把这些内部步骤增加到人的数据页。

## 默认 100 行，最多 500 行

人和智能体（Agent）共用同一执行规则：

| 输入情况 | 行为 |
| --- | --- |
| 没有 LIMIT | 默认限制 100 行，实际执行的语句可核对 |
| LIMIT 不超过 500 | 保留原值 |
| LIMIT 超过 500 | 拒绝本次执行，保留输入和已有结果，说明如何调整 |
| 需要更多记录 | 修改条件或显式翻页，每页最多 500 |

行数限制落实在专业查询入口，不在取回全量后仅裁剪界面。达到上限只表示本次取数受限，是否还有更多尚未确认；不自动执行全量计数或连续取完所有页。

分页要求明确排序。返回行数不等于数据库（Database）扫描量，正式接入时需要独立超时与取消能力；具体支持及时间设置以后核实。首版原型（UI Prototype）不增加用于演示这些机制的产品菜单。

## 生产与扩展范围

生产 MySQL 使用原生只读账号，修改数据和表结构仍按现有 DMP 审批方向处理，具体对接以后讨论。首版不提供写数据操作，查询失败不自动改走 DMP。

Nacos、Kibana 及其他类型只保留整体扩展方向，不在本轮页面增加入口或操作。代码工作树（Worktree）不自动复制真实数据库（Database）。

## 本轮评审标准

- 从连接列表编辑配置是否直接，是否不再需要理解详情页，环境（Environment）是否能方便自定义。
- 从智能体（Agent）结果入口打开时，是否直接看懂数据。
- 需要自己查时，是否能找到目标、语句、运行和结果。
- 默认库、显示库与实际访问权限是否分清，`database.table` 是否按明确库名查询；当前页是否没有协作协议、版本号和重复说明干扰。
- 默认 100、最多 500 与目标切换后的结果是否准确。
