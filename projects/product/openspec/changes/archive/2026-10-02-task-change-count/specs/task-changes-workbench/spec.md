## ADDED Requirements

### Requirement: 任务详情轻量改动计数

任务详情 MUST 在打开时通过只读 `GET /tasks/:taskId/changed-file-count` 读取工作区文件数，不依赖进入改动标签。计数 MUST 使用完整改动读取相同的任务仓库范围、文件去重及截断边界，不读取提交历史、增删行数或差异正文。结果 MUST 包含任务身份、读取时间、计数、完整或局部状态、覆盖上限、截断和诊断。任务切换 MUST 隔离读取结果，显式刷新 MUST 重核当前数量；完整列表与差异 MUST 在进入标签后按需读取。

#### Scenario: 打开说明立即读取数量

- **WHEN** 用户从列表打开普通任务详情
- **THEN** 文件数无需读取提交历史或差异即可显示，说明正文可独立读取

#### Scenario: 相同范围的数量一致

- **WHEN** 同一文件现场存在多个检出位置、重命名、删除及未跟踪文件
- **THEN** 计数与完整读取可见文件数一致，同仓库同路径不重复计数

#### Scenario: 局部失败及截断

- **WHEN** 一个仓库读取失败或文件超过上限
- **THEN** 保留其他已读计数并返回局部状态、诊断和截断，不冒充完整精确数量

#### Scenario: 切换和刷新

- **WHEN** 用户快速切换任务或刷新当前任务
- **THEN** 旧任务响应不覆盖当前数量，刷新后显示本次读取结果

### Requirement: 所选文件的差异定位与行号

选择变更文件后，阅读面 MUST 在当前文件完整差异读取结束后自动定位到第一处新增或删除行；左右对比 MUST 保持两侧与中间行号同步。当前文件同一模式的普通重绘及刷新 MUST NOT 反复重置人的阅读位置。上下对比 MUST 只显示一列行号：删除行使用旧版本行号，新增和上下文行使用新版本行号；纯重命名等没有内容差异的文件 MUST 从正文开始显示。

#### Scenario: 修改位于文件中间

- **WHEN** 所选文件的第一处内容改动前有大量未修改行
- **THEN** 读取完成后第一处内容差异位于可见阅读区顶部附近，不停留在文件开头

#### Scenario: 切换来源与阅读模式

- **WHEN** 用户选择另一文件、同文件的另一提交来源，或切换对比模式
- **THEN** 定位对应当前文件和来源的第一处差异，左右对比三列滚动保持对齐

#### Scenario: 人继续阅读

- **WHEN** 人手动滚动后同一文件同一模式完成刷新或发生普通重绘
- **THEN** 保留人的阅读位置，重新点击文件时可再次定位第一处差异

#### Scenario: 单列上下对比行号

- **WHEN** 上下对比显示普通行、删除行和新增行
- **THEN** 每行只有一列行号，分别对应新版本、旧版本和新版本
