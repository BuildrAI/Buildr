## Why

日常开发缺少统一入口回答“本地服务能否启动、谁占用哪个端口、QA 怎么提交”：开发者依赖个人脚本与记忆，智能体（Agent）在各任务工作树（Worktree）启动的服务也不可见、不可管，削弱交付信心。集鲜工作空间已完成原型评审并确认首期范围，用户确认按原型实施，且要求该模式可推广到其他团队与企业（本地自检 + 可替换 CI/CD 提供者），因此现在需要把原型收敛为产品能力。

## What Changes

- 新增服务级运行定义（`runtime.yml`）：启动命令、工作目录、profile、首选端口与覆盖方式、就绪检查、超时与环境部署目标（首期 qa，其他环境在同一映射按需登记）；只由智能体发现并实际验证后写入，页面只读展示来源与验证时间，首期不提供手动配置入口。
- 新增本地受管运行：按工作树独立运行实例（每个工作树最多一个受管实例）、全局端口分配与避让、就绪检查、停止、运行记录与进程标准输出/错误输出日志（智能体经托管启动的运行同账）。
- 新增 Buildr Web 视图：工作台只读本地运行汇总、服务目录（合并“运行与部署”状态列 + 悬停/点击浮窗）、服务详情（运行列表、启动抽屉、日志抽屉、识别抽屉、QA 部署抽屉）。
- 新增部署适配器契约：Buildr 只提交部署请求并保存归一化最近结果与外链；具体提交、目标发现与日志遮蔽由连接技能（Connection Skill）实现（首期为集鲜云雀），换 CI/CD 提供者只需新连接技能实现同一契约。
- QA 部署确认默认登记集成分支（Integration Branch），可改选其他远端分支；只部署远端提交，不提交不推送本地改动；不接管 CI/CD 进度、历史与日志页面。
- 不包含破坏性变更：既有服务登记、连接技能运行时与页面壳层行为保持兼容。

## Capabilities

### New Capabilities
- `service-runtime-operations`: 服务级运行定义模型与写入来源、本地受管运行生命周期（启动/停止/端口/就绪/日志）、运行记录与 Buildr Web 本地运行视图。
- `service-deployment-adapters`: 部署适配器契约（提交、归一化结果、外链）、QA 部署确认与分支选择、提供者替换边界与 Buildr Web 部署入口。

### Modified Capabilities

（无：连接技能执行机制复用 `connection-skill-runtime` 的私有子进程通道，槽位（Hook）仍限定只读效果，部署提交经 `connection-skill run` 调用声明程序，不改变其既有要求。）

## Impact

- `projects/product/services/buildr/`：新增运行定义存储与校验、受管进程生命周期、端口分配、日志捕获、runtime HTTP/CLI 表面、部署适配器调用与归一化结果存储。
- `projects/product/services/buildr-web/`：新增工作台汇总卡片、服务目录状态列与浮窗、服务详情与四个抽屉；复用既有壳层、页签与 DrawerShell。
- 连接技能（外部工作空间，如集鲜云雀）：按契约实现部署适配器程序与只读目标发现；Buildr 仓库只定义契约与诊断。
- 测试：runtime 单测/集成测试、Buildr Web 浏览器旅程（目录、详情、启动、QA、日志）。
- 知识：`knowledge/` 代码地图与模块说明需在校验后校准新增模块。
