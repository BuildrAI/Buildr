## MODIFIED Requirements

### Requirement: 旧后台退役必须基于资源持有事实

旧后台 MUST 按实际执行、辅助工作、重要写入及未释放原生资源决定是否仍忙。准确资源关闭成功后，历史结果待核对 MUST NOT 单独阻止该后台退出或使退出确认失败。停止发生错误且未确认结束时 MUST 返回待确认，MUST NOT 长期把停止请求当作确定模型执行。缺少释放证明的旧后台或旧执行器 MUST 沿用保守保护，MUST NOT 仅为清理提醒强行放行。

#### Scenario: 仅剩历史结果疑点
- **WHEN** 旧后台没有实际工作且全部所属原生资源已确认释放，但历史操作结果仍待核对
- **THEN** 旧后台 MUST 能正常退出并确认自身资源释放；历史结果 MUST 保留且不能触发自动重发

#### Scenario: 隐藏已释放的历史疑点
- **WHEN** 用户已关闭或隐藏对话，所有未被替代的在途轮次均已准确释放原生控制资源，没有明确运行工具或有效待回答问题或已提交的待发送要求，而历史执行或操作结果仍未知
- **THEN** 系统 MUST 保留历史的未知结果，不再将它计入活动提醒和执行模型数；未释放的原控制、明确运行工具、有效待回答问题或已提交的待发送要求仍 MUST 保持活动可见，关闭或隐藏 MUST NOT 将它们冒充已结束

#### Scenario: 独立命令继续而原生控制进程已经退出
- **WHEN** 原生主进程退出、原后台控制资源已可安全释放，但独立命令缺少结束证据
- **THEN** 系统 MUST 允许空后台释放并分别保存 executionState=unknown 和 resourcesReleased=true，保留操作待核对；MUST NOT 终止该独立命令、宣称执行完成或自动重发

### Requirement: 内部交接必须依据准确持久证据收敛已结束执行

系统 MUST 在重启接续与显式重新读取时优先核对准确程序配置、上下文、目录和原执行身份对应的持久完成证据。原生轮次已成功结束且本轮工具、派生工作均有结束证据时，系统 MUST 补回遗漏的可见结果及最终答复并收敛完成状态，不以旧代次仍存活、旧观察通道超时或资源尚待释放否定该终态。此核对 MUST NOT 启动新模型执行、重放工具、转移旧执行控制权或把推断的目标完成冒充执行完成。缺失、损坏、变化中、跨绑定或尚有未结束工作时 MUST 保留准确未知及诊断，不伪造结束。正常内部切换 MUST 自动处理，不要求用户反复重读；无法恢复的真实故障 MUST 保留具体诊断。

#### Scenario: 已结束原轮的旧通道失响应
- **WHEN** 原轮持久记录包含准确成功结束、全部工具及派生工作结束证据，而旧代次仍活动或观察通道超时
- **THEN** 重启核对或重新读取 MUST 补回本轮遗漏结果和最终答复并返回完成，不恢复执行或重发原要求

#### Scenario: 没有安全的持久终态
- **WHEN** 绑定不符、记录仍变化、格式不支持、末尾损坏或工具结果未确认
- **THEN** 系统 MUST 不凭助手宣称或附近轮次宣布本轮完成，保留原事实并只按已有安全恢复边界处理

#### Scenario: Qoder 正常结束回执遗漏
- **WHEN** 已绑定的 Qoder 主链中准确输入、最终模型结果和结构化原生结束回执一致，且工具与派生工作均已确认结束
- **THEN** 重新读取 MUST 恢复本轮完成状态及缺失的答复与工具结果，保留原生会话身份，不启动模型或重放原要求

#### Scenario: 正常答复但缺少准确结束证据
- **WHEN** 已显示助手最终文字，但没有与本轮准确匹配的原生结束记录，或仍存在未结束工作
- **THEN** 系统 MUST 保留待确认，MUST NOT 仅凭文字内容或后台资源释放宣称成功

## ADDED Requirements

### Requirement: 已释放的待确认对话必须提供继续与关闭出口

系统 MUST 为没有明确活动工作、有效待回答问题或已提交待发送要求、且原生控制资源均已确认释放的待确认对话提供“继续工作”和“关闭对话”。继续 MUST 先核对原轮及成果，再接续未完成目标，不重放历史要求。关闭 MUST 保留对话历史、未知执行与工具事实及关联 Task 状态，只撤下已关闭对话的提醒；用户 MUST 能在历史中找到并恢复显示。读取仍未知时 MUST 明确说明没有取得新结束证据及可用动作，MUST NOT 把读取成功冒充工作完成。

#### Scenario: 关闭遗留待确认对话
- **WHEN** 用户关闭原生控制资源均已释放、没有明确活动工作和有效待回答问题的待确认对话
- **THEN** 对话 MUST 从活动提醒撤下并保留在可恢复的历史中，原执行和未知工具结果 MUST 不变，关联 Task MUST 不被完成

#### Scenario: 另一原轮仍在工作
- **WHEN** 最新轮已释放但保留轮次尚未释放，或仍有明确活动工具、有效待回答问题或已提交的待发送要求
- **THEN** 关闭入口 MUST 不可用，隐藏 MUST 不掩盖相应活动，不发送替代停止命令

#### Scenario: 再次继续工作
- **WHEN** 用户选择继续已释放但结果待确认的原目标
- **THEN** 系统 MUST 先重新读取；取得正常结束和最终答复证据时 MUST 告知用户可直接提出新要求，否则按原执行身份核对已生效成果后接续，不自动重复旧操作
