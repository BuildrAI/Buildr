## Context

动机见 proposal.md。现有连接模块管理通用类别和类型、版本摘要及绑定目标的本机加密认证，元数据在 `connections/manifest.yml`；已有工作空间 SQLite 与受保护事务注入可复用。前端已有统一资源目录、抽屉和 CodeMirror；当前选库仅在组件内存，运行整段 SQL，结果字段自动换行。

## Goals / Non-Goals

保留通用连接扩展及工具入口，只改变本机存储和已确认的查询体验。不建立多人共享配置协议，不保存业务查询结果，不引入查询协作状态或其他外部系统。

## Decisions

1. 复用 `.buildr/local/workspace.sqlite`，通过现有 SQLite 读/事务端口注入连接模块。新增连续迁移创建通用连接、查询偏好及旧清单导入记录；类型专用配置保持 JSON。相比新增数据库或继续文件双写，这样复用现有归属、迁移和写入保护。
2. 首次使用执行受保护初始化及旧清单导入事务。完整校验清单身份、数据及重复编号后一次提交；导入记录与连接同事务提交。已有数据库记录与旧声明冲突时明确失败。完成标记后永久读取数据库；保留旧文件用于人工恢复。保留原连接和认证编号、时间及绑定摘要，不读取或重写密码。首次列表请求只升级和导入已有配置，不发起外部网络或创建其他配置；完成后列表继续纯只读，不反复争抢写锁。
3. 查询偏好独立于连接配置和认证版本：`enabledDatabases`、`currentDatabase`、`revision`。新增 `GET/PUT /api/v1/workspaces/:id/connections/:connectionId/query-preferences`，PUT 使用已观察版本；删除连接清理偏好。初始空列表和未选择，不用连接默认库隐式启用。切换连接时隔离请求，加载完成前不允许旧偏好写到新连接。
4. 页面采用共享资源目录，按实际环境值过滤，统计登记连接。只有 MySQL 时不增加无用类型过滤；以后真实有多类别类型时扩展。保存仍用现有抽屉。
5. 编辑器抽取独立纯语句定位逻辑，识别单引号、双引号、反引号和 MySQL 注释，选中优先、否则定位光标。发现多条、空白或未闭合结构时停止本次执行；实际只读语法与行数仍由后端验证。
6. 结果单元格单行省略，固定紧凑行高、清楚网格；点击用统一只读抽屉呈现全文及复制入口。不保存结果或增加历史。

## Risks / Trade-offs

- 迁移重试或并发造成重复/覆盖 → 同事务导入记录、稳定编号、冲突检测；旧文件保持原状。
- 候选源码写入正式工作空间 → 复用现有 SQLite 写入来源保护，验证使用隔离工作空间。
- 偏好与资源请求晚返回造成串连接 → 目标序号及请求取消；版本冲突重读并明确提示。
- UI 启用列表被误认为权限 → 仅限制页面当前库选项，专业工具和限定库名继续使用原生权限。
- SQL 选段不完整或含分号 → 定位器只确定范围、不修补 SQL；后端继续单条只读校验。
- SQLite schema 高于旧程序 → 激活后需同版或更新程序；回滚不得删除数据库或用旧 YAML 覆盖新数据。

## Migration Plan

部署包含新增迁移的程序，首次连接操作受保护地升级 schema 并导入旧清单。无旧清单时登记已初始化空状态；导入成功后原清单不再参与当前读写。先在隔离工作空间验证配置、版本与认证保全、失败原子性和重试，再随正常交付激活。公司 qa 连接不进入源码和测试；正式应用通过同一路径迁移。
