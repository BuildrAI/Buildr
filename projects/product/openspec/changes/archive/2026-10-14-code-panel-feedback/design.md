## Context

动机见 [proposal.md](proposal.md)。变更开始时，`AppLayout.tsx` 用 `codeDestination` 记忆最后代码页面，并以资源管理器（Explorer）作为初始目标。`RepositoryFileBrowser.tsx` 的文件选择副作用无条件合并所有代码库（Repository）根到展开集合，且保留页面重新激活时不会重置目录。根路径由 `CodeExplorerPage.tsx` 拼接查看种类、路径及观察标识，再通过共享浏览器（Browser）组件（Component）的副行常驻展示。初次实现已修复这些问题，后续反馈进一步明确来源名称优先，以及仅异常通知。

初始 `CodeSourceControlPage.tsx` 将获取和同步（Sync）结果放进 `catalogFeedback`；既有结果组件（Component）已表达逐库、失败远程及逐阶段状态，应保留这些内容。写请求发布结果和局部重新观察使用 `source-control-events.ts`，不依赖来源行继续挂载。来源行的名称、分支（Branch）、状态和任务（Task）快捷入口原先同时竞争宽度，三个点菜单（Menu）只覆盖远程操作，需要按同一具体来源补足原有入口。

初始代码模块（Module）有六处直接强制 `GIT_CONFIG_NOSYSTEM=1`，覆盖普通读取、内容进程、搜索、分支（Branch）切换、提交材料以及写进程。macOS 现场系统配置里的 `osxkeychain` 因此失效；相同来源的只读远端观察在保留系统配置后成功。配置观察与写执行必须一并修复，否则地址展开、凭证、作者（Author）或过滤器（Filter）可能继续不一致。

## Goals / Non-Goals

**Goals:**

- 在现有页面、事件与组件（Component）职责内完成默认入口、目录折叠、路径按需展示和短时结果反馈。
- 用统一 Git 环境装配消除配置分歧，保持现有副作用与授权边界，不引入平台特例。
- 用受控配置及本地远端证明行为，以实际浏览器（Browser）验证交互。

**Non-Goals:**

- 不增加远端地址编辑、凭证管理、自动认证提示、自动重试或同步（Sync）策略选择。
- 不新增全局状态仓库（Store）、通知历史页、业务代码库（Repository）修改或 Windows 实机认证承诺。

## Decisions

### 顶部代码导航固定默认目标

顶部“代码”直接指向 `/code/source-control`，移除该入口对上次子页面的记忆；`App.tsx` 中未指定子页的 `/code` 入口也默认跳转至源代码管理（Source Control）。资源管理器（Explorer）侧栏入口、文件定位和返回动作继续保留真实路径与状态。仅修改默认目的地，避免把所有代码路径重定向而破坏直接文件定位。

### 目录展开区分普通进入与显式定位

普通进入或保留页面再次激活时清空根和文件夹展开状态；同次进入的目录刷新保持手动展开。文件定位携带明确定位变化信号，使同文件再次定位仍能触发，只展开真实根及父目录。保留已打开文件及读取状态，不将折叠等同于清空阅读。共享组件（Component）仅在适用的全局资源管理器（Explorer）入口采用此默认，避免意外改变原有模拟或局部阅读用途。

### 根路径复用按需浮层

代码库（Repository）根名称使用可移入的浮层（Popover），正文分开表达完整实际路径与查看种类／适用历史版本，路径可选字并复制。常驻根行只显示名称，不把内部观察标识拼入路径值。使用现有 Ant Design 能力及局部样式，无需引入新的提示库；普通原生提示不能满足移入选择复制，故不作为唯一展示。

### 结果在通知浮窗中展示

使用现有 Ant Design 通知浮窗（Notification），先判断当前操作全部结果是否正常：全部成功或已确认无需执行时静默，异常、不可用、未知或部分失败时才呈现对应批次或具体工作树（Worktree）的结果。异常通知默认约 6 秒，悬停暂停，支持关闭及长详情滚动，以现有主题变量形成清楚边框、实体背景和可读状态颜色。复用或改造现有逐库、逐阶段结果展示，移除目录的 `catalogFeedback` 常驻结果。请求期间保留现有等待标识；静默成功与通知关闭只影响展示，不取消已发写入或跳过事件引起的局部重新观察。

完成事件仍按发起工作空间（Workspace）及操作序列处理，旧或跨工作空间（Workspace）迟到结果不替换当前通知与事实。批量数只统计当前发起批次，通知不拼接历史结果缓存。同步（Sync）开始前不可用或读取失败也必须得到短时反馈，执行后详情保留已成功阶段与查看冲突改动入口。

### 来源名称优先与按实际宽度逐级收起

每个来源行按自身实际可用宽度决定密度，完整代码库（Repository）或工作树（Worktree）名称优先于分支（Branch）和后部快捷图标。正常宽度下保留完整名称和紧随其后的完整分支（Branch）；组合放不下时把剩余空间分配给分支（Branch），文字随空间逐步缩短并显示省略号，低于可辨认的最小宽度时才隐藏整段分支（Branch）。这避免一处宽度临界值使整段分支（Branch）突然消失、留下空白。仍放不下时收起状态和任务（Task）快捷图标，最后才省略来源名称。名称完整优先，三个点菜单（Menu）始终保留固定可操作空间，父子来源沿用右侧对齐和真实层级。完整文字的自然宽度与实际分配宽度分别测量，避免缩短后的宽度使密度状态来回变化。

收起改变的是展示密度，不能改变来源事实或丢失动作。该来源的三个点菜单（Menu）始终提供原有检出（Checkout）／切换分支（Branch）入口、已核实关联任务（Task）入口、状态详情和远程操作，分别沿用既有提供者（Provider）、就地浮层（Popover）、精确来源和不可用说明，不新增任务（Task）关联写入或独立动作实现。仅按固定栏宽设置全局断点无法区分同栏的长短名称，故按实际内容判断；宽度恢复时恢复适用快捷展示，分支（Branch）事实变化即时采用，即使文字暂时被收起，按需信息和菜单（Menu）也使用新事实。

### Git 环境统一且只保留有用的外部选择

代码模块（Module）采用统一环境装配：原有过滤外部 `GIT_*` 的来源隔离继续保留；仅透传 `GIT_CONFIG_SYSTEM`、`GIT_CONFIG_GLOBAL` 配置文件选择及环境明确给出的 `GIT_CONFIG_NOSYSTEM`，去掉 Buildr 自行强制的系统配置禁用。`GIT_DIR`、`GIT_WORK_TREE`、`GIT_CONFIG_COUNT` 等外部定位或配置注入不透传；获取执行自身为固定已核实地址构造的受控配置仍在该调用内使用。

六处现有代码模块（Module）Git 读取／执行入口复用此装配，保留 `GIT_TERMINAL_PROMPT=0`、`GIT_NO_LAZY_FETCH=1`、只读无可选锁、禁止维护，以及适用的钩子（Hook）、过滤器（Filter）、签名和范围约束。系统默认凭证助手（Credential Helper）由 Git 自身选择，macOS、Windows、Linux 使用同一规则。硬编码 `osxkeychain` 无法覆盖其他平台或用户配置，故不采用。

### 必要的本机 Git 读取优化

获取远程（Fetch）按已观察代码库（Repository）身份及固定远程映射执行，同一 Git 仓库（Repository）的远程依次执行，最多两个独立 Git 仓库（Repository）并发。同步（Sync）先读取上下文并以观察版本发起写入，随后依次获取固定上游、必要时整合、必要时精确推送；完成后只进行当前操作需要的一次目录重新观察。

只在一次完整观察内部复用已经读取的有效配置字节，供过滤器（Filter）解析和配置摘要共同使用；尾部仍重新读取配置、状态和索引以发现观察期间变化。同步（Sync）每轮观察使用现有工作树（Worktree）观察会话（Observation Session）保存本轮来源解析结果，原来的两次来源回核改为会话（Observation Session）的真实注册位置、成员和检出身份重新核对。跨网络等待、引用发布、整合或推送边界必须重新完整观察，不缓存上次已通过的安全结论。

获取远程（Fetch）可在同次请求内、相同位置且有效配置字节完全一致时复用静态远程解析和引用格式核对；每次校验仍重新读取有效配置、真实身份和当前符号引用（Symbolic Ref），重新判断目标映射安全性，不删减原有写入前后校验。保留真实前后性能测量，区分本机进程成本和网络认证成本，不以本地场景推导业务远程总耗时。

## Risks / Trade-offs

- [短时浮窗可能来不及阅读多库错误] → 悬停暂停，保留逐库详情并允许内部滚动，提供明确关闭；结果消失不影响真实操作与状态重新读取。
- [来源快捷入口收起后难以发现能力] → 三个点菜单（Menu）始终可见并完整承接同一来源原有动作及状态，长名称与窄栏验证每级收起顺序和键盘可达性。
- [保留页面普通激活时误展开旧文件] → 普通激活重置与显式文件定位使用不同信号，覆盖同文件重新定位及跨页返回代表场景。
- [系统配置恢复可能使既有安全观察和执行产生差异] → 六处入口统一装配，同时回归地址配置、过滤器（Filter）及来源漂移保护，不透传外部任意 Git 注入。
- [凭证助手（Credential Helper）自身行为因平台不同] → 使用 Git 有效配置及非交互边界；用受控助手验证系统配置生效，报告 Windows 实机本次未覆盖，不把 macOS 成功推导为所有环境认证成功。

## Migration Plan

无数据或接口迁移。实现和检查在当前工作树（Worktree）中完成，正式浏览器（Browser）验收使用该工作树（Worktree）的构建预览；用户现有 Git 配置和凭证不变。回退对应源码即可恢复原页面交互和环境装配，不需要改写任何业务代码库（Repository）的历史或配置。
