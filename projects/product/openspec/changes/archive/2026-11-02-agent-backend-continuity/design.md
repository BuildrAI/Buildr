## Context

见 proposal。旧后台按准确执行持有控制权；新版接收新输入。当前 canRelease 同时要求进程组空闲，Qoder SDK 守护进程使“关闭前核验”无法通过。

## Goals / Non-Goals

保持当前轮和问题控制不变，安全释放后恢复同一原生会话。不是新增通用调度器，不自动重试模型失败，不强杀未知工作，不迁移厂商凭据。

## Decisions

- 新增可选的原生结束准备检查，确认无在途工具、问题、其他共享执行后允许关闭准确运行时；关闭后仍使用原有物理释放证明。拒绝忽略存活子进程或直接删除占用记录。
- 会话匹配选取最新同选择参与者。当前轮已结束且旧后台存活、控制未释放时返回可等待的忙状态，而非寻找更旧会话或新建；选择变化和原轮在途时仍允许独立新要求，新增会话均记录原因和身份。
- 增量会话事件保存原生身份、后台代次、原因和发送状态；恢复原生身份与上下文创建成功后落盘，受理/失败沿用原轮状态更新，不将本地创建当成成功交付。
- 普通发送使用中性准备提示，真正切换才使用交接措辞。保留现有有界发送冲突恢复，不放宽未知受理的重试条件。

- 共享资源定位复用现有 `BUILDR_HOST_HOME`，优先级为显式 `BUILDR_PRODUCT_DATA_DIR`、合法绝对宿主 HOME、当前 HOME。原生工具环境仅传递必要的显式产品目录配置，不继承凭据。拒绝硬编码用户路径、复制共享资源或取消私有 HOME。

- 资源采用回执只描述派生入口准备，不能阻止已声明且完整的共享文件只读消费；工作树不复制回执、不自动sync，继续核对声明、路径、摘要和权限。

## Risks / Trade-offs

- 共享资源误关 → 准备阶段逐成员核对，问题/工具/活动执行均阻止关闭，关闭后再次证明物理退出。
- 跨后台并发 → 原控制未释放不能恢复同一会话，原请求身份保持不变。
- 旧后台不支持新准备检查 → 保留现有安全检查，不能强行接管；修复生效需要后续正常交付。

## Migration Plan

可选能力与可选事件字段兼容旧记录；不回填旧会话交接、不改历史。正常安装新版本后逐对话接续，保留未确认资源。
