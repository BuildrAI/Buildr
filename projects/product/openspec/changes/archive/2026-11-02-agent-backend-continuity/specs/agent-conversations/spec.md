## ADDED Requirements

### Requirement: 后台换代保持原生会话连续性
系统 MUST 在同一执行选择下优先复用最新原生会话。旧后台完成当前轮并确认释放控制资源后，已就绪的新后台 MUST 能恢复同一原生会话；当前轮已结束而旧控制未释放时 MUST NOT 静默新建或回退到更旧会话。原轮仍在途时用户明确提交的新要求可使用独立会话，但必须记录交接，不得将其当作对原问题的回答。待回答、活动工具和未知副作用 MUST 保全，不得重放原输入。

#### Scenario: 已结束的 Qoder 控制资源关闭
- **WHEN** 当前轮结束、无待回答或活动工作，仅配套控制进程仍存活
- **THEN** 系统安全关闭准确拥有的控制运行时并核验物理释放，不能因配套进程常驻而永久阻止正常关闭

#### Scenario: 新后台等待原控制释放
- **WHEN** 同选择的当前轮已结束，但原生会话仍被存活旧后台持有
- **THEN** 系统保留待发送内容且不新建原生会话，确认释放后复用原身份

### Requirement: 原生会话交接可追溯
系统 MUST 在对话中持久保存后台接管或原生会话替换的事件，包括前后原生会话与后台身份、原因及实际发送状态。同智能体同模型也不得隐藏原生会话替换。普通发送 MUST NOT 被描述为模型交接。

#### Scenario: 原生会话确需替换
- **WHEN** 用户改变执行选择而创建新的原生会话
- **THEN** 对话记录前后身份与切换原因，并区分准备、受理与失败；刷新后仍可查看

#### Scenario: 后台接管但原生会话不变
- **WHEN** 新后台恢复旧后台已释放的原生会话
- **THEN** 对话记录后台接管和保留的原生会话身份，不声称换模型或重放历史
