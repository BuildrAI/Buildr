## Context

动机见 [proposal.md](proposal.md)。现有 `service-runtime` 已有服务级定义、代码观察、受管进程、日志和单服务启动；页面缺任务上下文，运行记录缺连接与启动来源。QA 部署通过同一模块耦合连接程序。确认版原型为 [prototype/index.html](prototype/index.html)，保全原始评审文件并在本设计记录用户最后两处修正。

## Goals / Non-Goals

目标是最小完整的本地验证闭环，复用真实任务、代码、目录和运行记录。每项能力可以由人或智能体（Agent）独立调用并恢复，组合不引入新的环境或运行组权威。

本轮不建设通用许可层、角色切换页、环境编排平台、部署替代品，不修改业务仓库、不自动更新代码、不把就绪等同业务验证。

## Decisions

### 职责及目录

| 所属层 | 对象与位置 | 负责 |
|---|---|---|
| 领域（Domain） | `service-runtime/domain/{runtime-definition,runs,worktrees}.ts` | 运行定义、实例、身份与连接事实 |
| 应用（Application） | `service-runtime/application/service-runtime-application.ts` | 单实例启动、等待、停止、日志及安全状态迁移 |
| 应用（Application） | `service-runtime/application/service-task-runtime-application.ts` | 从真实任务范围及工作树选择服务，复用并组合单项能力，返回部分结果 |
| 基础设施（Infrastructure） | `service-runtime/infrastructure/managed-process.ts` | 进程身份、独立进程组、输出和终止 |
| 存储（Persistence） | `service-runtime/persistence/` | 本机运行快照与日志；旧配置兼容读取 |
| 接口（Interface） | `service-runtime/interfaces/{http,cli}/` | 同一应用的网页与命令适配，写入沿用现有授权 |
| 界面 | `buildr-web/src/features/service-runtime/` | 共享运行展示、启动选项和日志，数据操作由既有客户端隔离 |

服务目录与详情提供测试动线，任务工作路径新增“本地验证”；页面布局及双栏沿用现有系统。每张实例卡显示真实启动时快照和当前状态。“打开”使用实际地址的新浏览器页签（Tab）；原型中的业务弹窗只属模拟，正式界面不复刻它。

### 单服务能力与任务组合

单项输入保留 `serviceCode`、`worktreeId`，增加观察来源版本、任务、启动入口及连接选择；服务器重新观察并核对，不能接受任意目录。任务读取从实际任务范围解析服务，工作树必须明确属于同一任务，不回落主工作库。主工作库只由 `main/isMain` 判断。

明确任务的入口只读取当前任务的既有工作树提供者证据，并与代码观察中的真实检出身份、共同 Git 目录及当前分支核对；提交始终使用当前观察。无关服务缺目录不能使本任务有效目录失去归属。切换原实例连接时保留任务上下文交给服务端重验；用户改选其他目录时不沿用原任务身份。

任务组合接收明确选中的服务及工作树。用户可选前后端，也可只选某个服务；组合先启动/复用已选后端，等待就绪后解析真实端口再启动前端。本地连接缺少匹配后端时只返回该项错误，不能暗中扩大选择；远程连接只需所选前端。每项返回成功、复用或错误，已成功项保留。停止只作用于明确运行编号；停止任务服务不影响主工作库或其他任务。

### 真实连接与当前事实

运行定义在 `local.backend` 可选声明 `{serviceCode,environmentVariable,remoteUrl}`。只在已有、经过智能体（Agent）实际验证的声明存在时显示前端连接选项；单选值是 `local|remote`，服务端解析目标并注入这个已声明变量。不接受任意环境变量或任意远程地址输入，不改业务代码和配置文件。配置未声明时准确说明需准备配置，不伪造连接生效。

运行记录增加 `main/taskId/taskTitle/dirty/origin/url/connection/launch`。连接保存实际模式、URL、后端服务及匹配运行编号；它表示启动目标，不自动证明业务请求联通。任务本地匹配同任务后端，主工作库匹配主工作库后端；多候选拒绝歧义。可选本地目标由应用层复用同一筛选规则提供给详情及任务页面，界面显示其来源、分支和实际地址，没有唯一就绪目标时禁选并阻止提交。任务同时选择后端时保持组合启动，由系统等待后端就绪后确定实际地址。远程目标始终只读显示固定声明，不提供每次启动输入地址的表单。

切换通过服务器重启动作完成：先重新核对代码来源、当前实例和新目标，失败保持原前端；通过后只停止该前端并以同目录启动。页面提交已展示后端的运行编号作为观察条件，目标被替换时要求刷新；启动时再次核对目标身份及地址，避免静默换成后来出现的其他实例。停止后启动失败保留已停止事实及错误，不承诺恢复已停止进程。未变连接的有效实例可由组合层复用，必须核对实际后端编号和端口。

### 进程与并发安全

启动、停止和状态迁移在共享实例资源上互斥；写入前重新读当前记录，迟到日志/HTTP 响应不能让停止或失败实例恢复运行。命令启动失败记录可排查错误，不生成可广播的进程号。终止只针对可证明的受管进程身份与其子进程；旧记录缺少身份时保留诊断并拒绝危险停止。

使用直接写日志的独立进程，命令行启动显式等待就绪/失败后退出，服务不依赖这次命令继续存活。没有端口覆盖方式时不能声称已避让；工作目录真实路径必须留在所选服务目录内，符号链接逃逸拒绝。

新启动暂时无法读取进程身份时，先保留实际进程号，只能通过本次仍持有的子进程句柄清理。清理未完成则保留失败诊断、目录和端口占用以及停止入口，不能直接重试新增实例；从磁盘读回的未知身份不享有此退化清理路径。

### QA 退场与兼容

去除部署应用、网页接口、命令及专属连接模板，模块不再依赖连接技能应用。旧 `runtime.yml` 的 `environments` 兼容忽略，不因旧 QA 字段损坏阻塞本地；读取旧记录时新增字段未知显示为空或未知，不推断为主库/干净/人工启动。不自动删除用户配置、日志、部署历史和外部连接。通用连接程序及独立 CI/CD 技能继续存在。

## Risks / Trade-offs

- 不同前端有不同代理配置 → 只支持已验证的显式变量注入声明；未配置时由智能体（Agent）准备，不猜测。
- 主机重启或进程号复用 → 保存可验证启动身份；身份不确定只阻止危险终止，界面如实说明。
- 多个服务部分成功 → 每项独立返回结果，不用一条成功提示覆盖失败；本地后端未就绪不启动依赖它的前端。
- 旧 QA 接口移除存在兼容影响 → 公开说明退场、保留用户数据；旧环境字段不参与本地运行。
- 跨平台进程组存在差异 → 采用本机可验证停止方式并测试；本机验证不冒充另一系统实测。

## Migration Plan

在独立工作树实现与验证，确认版原型保全到变更供任务内阅读。旧运行记录按兼容规则读取，后续启动生成新快照；没有数据破坏式迁移。普通回退可以保留用户源文件与本机记录；不在本轮自动回退或发布。
