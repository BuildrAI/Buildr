## Context

动机及破坏性范围见 proposal.md。现有新 MySQL 查询仍导入旧 connections 内核；旧预览认证桥接也仅向旧仓储提供认证。旧实例数据与新实例、认证、查询偏好分离，允许在不改变新机制的情况下退役。

## Goals / Non-Goals

保留新连接及查询行为，消除旧实现依赖和第二套当前入口。不重写 MySQL 查询器，不新增专业业务控制台、依赖或真实外部写入。历史归档保持原文。

## Decisions

1. MySQL 专用代码归入既有 mysql-query 模块：domain 保存必要访问/结果和校验，infrastructure 保留 SQL 校验与执行内核，application 负责实例及查询用例，persistence 只维护本机偏好。接入程序使用 test/databases，查询应用使用 databases/tables/columns/query，共享内核；删除四类系统通用 ConnectionProvider 包装及 selectedDatabases 残留，避免另建抽象框架。
2. 旧模块与专属测试整体删除，仅在命令解析和本机 HTTP 路由保留明确退役诊断。旧页面保留跳转，新旧持久标签规范化成同一身份；新页面及查询布局不变。
3. 新增连续 SQLite 迁移删除旧三张表，历史脚本保持原文。旧清单、凭证及授权消费记录由有界清理函数按已核验工作空间和当前应用数据根处理，拒绝符号链接和不明对象；仅在读取该工作空间的现行连接目录时清理，离线帮助不写用户数据。当前目录的新实例不参与清理，旧私人密码不写入新文件。清理失败报告局部结果并可重试，不把登记缺陷扩大为其他功能阻塞。
4. 移除旧预览认证来源参数及桥接；保留预览其他所有权和隔离行为。新个人认证预览复用不作为本次新增能力。
5. 当前知识以一篇外部系统连接主文档解释对象、认证和专业分工，其余文档仅保留自身职责及引用，技能保留实际操作方法；不把类名、字段清单和退役过程写成知识主线。

## Risks / Trade-offs

- 删旧目录误伤新 MySQL → 保留执行逻辑并运行只读、防漂移、精度、容量及包程序检查。
- 旧清理越界或删除新认证 → 精确路径、普通文件/目录与链接检查，隔离夹具覆盖新旧共存、失败重试和越界路径。
- 删除历史迁移破坏其他数据库数据 → 历史脚本原文保留，用新增迁移删除旧表。
- 活文档或测试仍推荐旧入口 → 检索当前源与指引，历史归档作为独立事实保留。

## Migration Plan

用户选择直接删除旧数据，无数据迁移或恢复承诺；采用新版本后读取连接目录时执行所属旧数据清理，用户自行建立新实例。候选在独立工作树验证；正式集成、自举激活和发布按各自授权另行执行，不从未交付候选更新保留工作空间。
