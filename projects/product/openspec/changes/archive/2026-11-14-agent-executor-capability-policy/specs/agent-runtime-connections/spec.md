## ADDED Requirements

### Requirement: 独立程序可由厂商官方发布清单准备

程序策略 MUST 声明独立程序的固定官方发布源，取值为厂商 npm 包源或厂商官方发布清单；“首次程序准备与连接”中的固定厂商包源 MUST 包含这两种来源，并共用最新版本核对、读取失败不降级、按准确版本受管与既有绑定保留规则。通过官方发布清单准备时，清单与产物请求的每一跳重定向 MUST 是 HTTPS 且主机属于策略声明的官方主机；清单版本 MUST 通过严格格式校验后才可用于受管目录名；系统 MUST 校验清单给出的完整性摘要，并对清单、下载与解压大小设置上限；归档解压 MUST 只取策略声明的程序成员，拒绝链接、越出准备目录的路径与多余成员，MUST NOT 执行归档或官方安装脚本中的安装步骤与环境改写。只有产物完整校验并通过版本核对后，系统才可原子更新准备指针；并发或中断的准备 MUST NOT 破坏旧程序、准备指针与已有绑定。

#### Scenario: 官方发布清单归档准备
- **WHEN** 程序策略声明使用官方发布清单，用户执行显式准备
- **THEN** 系统 MUST 按当前平台读取清单得到版本、官方下载地址与摘要，下载并校验摘要后解出声明成员到按准确版本命名的受管目录
- **AND** 准备结果 MUST 可被发现、绑定并通过实际协议检查后才显示可用

#### Scenario: 清单或产物异常
- **WHEN** 清单缺少当前平台、版本格式非法、任一跳重定向不属于声明的官方主机、摘要不符、大小超限，或归档含链接、越界路径、多余成员
- **THEN** 准备 MUST 明确失败，不留下半成品，保留既有程序与绑定，且 MUST NOT 改用其他来源或降级安装

#### Scenario: 中断与并发准备
- **WHEN** 准备在下载或解压中被中断，或同一程序同时收到两次准备请求
- **THEN** 旧受管程序、准备指针与已有绑定 MUST 保持可用；并发请求 MUST 归并为同一尝试或得到明确的进行中结果，不得产生两份互相覆盖的准备

### Requirement: 模型路径必须在执行前确定并各自校验

系统 MUST 在打开执行方运行时之前，依据执行方声明与所选来源声明把组合确定为且只为一条模型路径，并在准备、发送、恢复与释放中沿用：网关路径 MUST 先签发并校验租约再启动执行；原生直通路径 MUST 按执行方声明的绑定方式工作——沿用租约绑定的执行方（Qoder、Qoder CN）MUST 保持现有租约与原生模型路由行为，按账号身份绑定的执行方 MUST 不签发租约，而是在打开前校验来源就绪、账号身份与参与者绑定一致、模型在来源目录且已启用，并由执行方在工作输入前核对原生当前账号与模型。任一路径的校验失败 MUST 使工作输入为零，返回准确原因并保留草稿与既有绑定。

#### Scenario: 不提供网关推理的来源进入原生执行
- **WHEN** 执行方声明按账号身份原生直通，用户选择其关联来源中已启用的模型并发送
- **THEN** 系统 MUST 不签发网关租约，以来源账号身份与模型打开执行方并完成输入前核对

#### Scenario: 原生账号身份不一致
- **WHEN** 按账号身份直通的执行方在输入前观察到的原生账号与参与者绑定身份不同
- **THEN** 执行方 MUST 拒绝输入，系统 MUST 提示重新选择模型，MUST NOT 以当前原生账号继续执行旧对话

#### Scenario: Qoder 既有直通保持不变
- **WHEN** 用户为 Qoder 或 Qoder CN 选择其原生来源模型
- **THEN** 租约签发、原生模型路由与失败原因 MUST 与升级前一致

### Requirement: 执行方模型消费方式必须由执行方声明并统一判定

每个执行方 MUST 在其描述中声明模型消费方式：是否可经本机模型网关消费其他模型来源及所用入口协议、关联的原生账号来源、是否只接受自身原生来源、是否需要平台基础登录、是否拥有自带账号。对话发送前校验、原生直通路由、网关配置与账号状态呈现 MUST 依据该声明与所选来源的共享范围统一判定，MUST NOT 依据执行方或来源的品牌标识另行分支。新增执行方 MUST 只通过声明表达这些差异。本要求 MUST NOT 改变现有执行方已对用户呈现的可选组合、拒绝原因与登录要求。

#### Scenario: 只接受自身原生来源的执行方
- **WHEN** 执行方声明只接受自身原生来源，用户为其选择其他供应商的模型并发送
- **THEN** 系统 MUST 在工作输入产生副作用前拒绝，给出该执行方只支持自身原生模型的原因，并保留草稿与选择
- **AND** 选择其关联原生来源的模型时 MUST 走原生直通路由，不经本机模型网关转换

#### Scenario: 无自带账号的执行方
- **WHEN** 执行方声明没有自带账号、必须选择模型来源
- **THEN** 连接视图 MUST 如实表达“需选择模型来源”，MUST NOT 呈现伪造的已登录账号
- **AND** 未选择可用模型来源时发送 MUST 局部拒绝并提示选择模型

#### Scenario: 现有组合保持不变
- **WHEN** 升级到按声明判定的版本后，用户使用 Codex、DSH、Qoder、Qoder CN 或 Claude Code 与已接入来源的既有组合
- **THEN** 可选组合、拒绝提示、登录要求、原生绑定与原生会话编号 MUST 与升级前一致

### Requirement: 原生工具详情来源必须由执行方注册

需要从原生记录读取工具完整详情的执行方 MUST 在注册时声明原生详情读取能力及其原生内容根的解析方式；公共层 MUST 只按准确执行方身份调用其声明，MUST NOT 维护按品牌标识分派的读取链或路径拼接。未声明详情能力的执行方 MUST 被视为不提供原生详情，相关展开 MUST 如实表示不可读取而不影响其他内容。界面 MUST 依据条目是否具备原生详情引用决定按需读取，不依据执行方品牌列表。

#### Scenario: 展开已注册执行方的工具详情
- **WHEN** 用户展开由已声明详情能力的执行方产生的工具条目
- **THEN** 系统 MUST 按该执行方声明从准确原生内容根读取详情，并继续拒绝越界、错误会话及错误工具身份

#### Scenario: 执行方未声明详情能力
- **WHEN** 条目所属执行方没有声明原生详情能力
- **THEN** 系统 MUST 仅展示已保存的摘要，MUST NOT 猜测路径或借用其他执行方的读取方式
