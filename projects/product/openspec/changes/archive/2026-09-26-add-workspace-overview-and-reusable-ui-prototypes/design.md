## Context

动机与范围见 [提案](proposal.md)。用户已确认名称“总览”、默认关键页面、任务菜单直接列页、独立三栏阅读以及复用已有交互。用户已同意分两段实施：先完成共用基础、技能（Skill）和阅读入口并生成修订后的关键页面供审看，再按反馈接入总览真实数据。

现有事实：

- `CreatableResourceSelect.tsx` 已接受候选项与回调；`ProjectServicesPanel.tsx` 直接连接真实保存。当前关联是选择一个已有服务（Service）后立即保存，下拉列表另有新增入口。
- `TaskChecklist.tsx` 与 `useTaskChecklist.ts` 已实现悬停、离开延迟关闭、点击、键盘退出和固定阅读；可固定条件由容器宽度决定。
- `TaskNodeContent.tsx` 已有方案设计目录，但 `PrototypeTab.tsx` 再放一份文件列表，占用画面空间。
- 原型读取已有任务（Task）与变更（Change）限定、普通文件检查和 2 MiB 单文件限制；`isolatedHtmlResponse` 禁止网络、嵌套框架与同源权限。
- `/overview` 已属于工作台的“概览”，新增总览不能覆盖该入口。
- 现有临时演示是手写模拟，不能作为源码复用的完成证据。其中多选确认式关联、仅画面的独立阅读和多组阅读控制已被本轮决定替代。

## Goals / Non-Goals

**Goals:**

1. 用户看清工作空间（Workspace）在做什么、有哪些组成部分，以及从哪里进入具体工作。
2. 原型、正式页面共享相关组件（Component）和主题源码，差别主要来自数据、操作和页面装配入口。
3. 原型可独立审看，方案范围与当前画面、说明保持一致，后续智能体（Agent）可以继续读取和实施。
4. 技能（Skill）形成可重复采用的方法，并在本次真实功能中验证，而非只增加文档约束。

**Non-Goals:**

不全量重构前端，不建立通用低代码平台，不引入专用组件管理后台、标签系统或新的任务状态；不增加项目间依赖、真实调用链、复杂图编辑、统计仪表盘；不借原型放宽安全隔离或变更已有保存语义。

## Decisions

### 1. 一个目标、三个相互验证的交付部分

| 部分 | 职责 | 用本次功能证明什么 |
| --- | --- | --- |
| 前端开发技能（Frontend Development Skill） | 引导发现、复用、按职责拆分、隔离副作用及验证 | 正式与模拟入口导入同一组件（Component）源码 |
| 原型技能（UI Prototype Skill）及阅读能力 | 选择关键画面、组织说明、生成可携带成果并验证 | 任务内和独立页使用同一阅读能力，原型保持隔离 |
| 工作空间总览 | 提供简洁、真实的整体认识与工作入口 | 前两部分方法能支撑实际页面交付 |

方法与示例一起演进，不先建完整组件平台，也不等全部页面完成才补原型。一个任务（Task）和一个变更（Change）承接这组连贯成果，不为三个工作包重复登记同一行为。

### 2. 前端开发技能的边界

新增可选 `frontend-development`，在开发或修改前端页面、交互和样式，或建设前端复用方式时发现。它引导智能体（Agent）调查当前体系，先找到可复用能力，再决定本次局部调整。适配项目技术栈，不把 React、Ant Design 或某个目录结构推广为所有工作空间的要求。

`code-architecture` 继续负责总体职责和文件拆合；`ux-design-laws` 负责体验取舍；新技能（Skill）负责前端实施中的复用与一致性；`ui-prototype` 负责明确请求后的演示成果。不要求为了使用一个而全量执行其他技能（Skill），不新增能力绑定或统一门禁。

样式通过既有主题变量和局部样式维护；交互通过完整组件（Component）及真正共享的钩子（Hook）维护；页面负责装配。避免为每个元素机械拆分，局部专用实现留在所属功能，跨功能稳定复用才提升到公共目录。组件示例说明输入、操作结果与关键状态，和源码就近维护，不建设第二份状态登记。

### 3. 同一源码，两种数据与操作入口

正式入口连接既有客户端（Client）、导航与版本校验；演示入口连接固定样例和内存操作。共享层提供界面与交互，不直接导入真实写入能力。异步等待、失败和成功由可替换操作返回，界面保持相同反馈。

首批调整：

- 直接复用 `CreatableResourceSelect`；把 `ProjectServicesPanel` 中确实妨碍演示的真实操作与展示装配分开，不复制一套选择器。
- 从 `TaskChecklist`、`useTaskChecklist` 提取内容无关的侧边阅读容器和交互；实施清单、功能说明分别提供内容，保留现有键盘和指针行为。
- 总览的节点、引用展示及组成视图在对应功能内组织；正式与模拟入口导入同一实现。

候选组件（Component）可在隔离工作树（Worktree）中先用于演示，确认后继续完善同一源码；不提前宣称已上线。复用旧组件（Component）无法满足明确的新需求时，说明变化及原因，再修改共同来源。没有可靠来源或无法隔离真实副作用时，只停止受影响画面的生成，不能悄悄以手写近似替代并声称同源。

### 4. 关键页面与最小交付内容

智能体（Agent）识别新增关键页面、主要布局或核心功能交互变化后，先询问是否需要原型；判断为大改动不构成制作授权。普通小改动直接实现，前端开发技能（Skill）不自动触发原型制作。只有用户明确同意才使用原型技能（Skill），同一任务已有偏好继续适用。本次已有明确原型授权。

默认覆盖五组画面：工作空间总览、进入具体项目概览、查看项目组成、关联已有服务、查看对象详情。小改动在相关说明中体现。空白、局部失败和关联失败属于必要状态，不各增加一个主要菜单项。

每张画面说明本次变化、主要功能、操作后果及必要边界；新增与沿用明确区分。原型既支持直接定位关键状态，也允许体验关键路径；重看画面使用确定的初始数据。

独立预览构建导入当前候选源码、主题和模拟入口，输出带现有发现标记的自包含 HTML。同源指同一份源码，不表示直接依赖开发服务器。成果记录来源提交、涉及源码路径及未提交差异的内容摘要；构建结果是该次设计的固定快照，不随未来代码变化自动改写。相关源码改变后重建受影响成果，并重验，不能继续引用陈旧验证。

首批利用现有 Vite/React 构建能力，必要脚本、样式与资源内联；不引入网络请求、真实会话、真实路由初始化或浏览器存储依赖。优先裁剪实际导入范围，验证符合当前 2 MiB、20 页及扫描边界；不把扩大限制作为默认解决方案。

### 5. 任务内和独立阅读共用一套呈现

任务方案设计的现有左侧菜单按“方案文档 / 界面原型 / 方案审查”组织，原型组直接列关键页面，主内容不再重复文件列表。来源和路径放在可展开信息中，避免抢占阅读空间。

任务内“功能说明”默认关闭：悬停临时查看、离开延迟收起、点击开关、键盘退出；空间充足可固定并排。说明与实施清单采用同一阅读机制；同一阅读区域一次展示一类辅助内容，切换时不叠出两层面板。页面切换保留说明的固定选择，并更新内容；数据刷新导致当前页面消失时给出提示并选择仍可用页面。

“单独查看”以新的浏览器页签打开受信任的独立阅读路由，保留当前任务限定、选中页面和有效状态标识。阅读页移除任务标题、阶段和工作台外壳，显示页面列表、原型画面、功能说明；宽度足够时说明默认固定，窄屏使用同一浮层机制。两入口共用页面选择和阅读组件（Component），但不在页签之间共享模拟修改，独立页从明确状态开始。

删除扩大阅读与手动缩放按钮，画面自动适应可用宽度；长内容可滚动。这里的删除只针对原型工具条，不删除产品自身对象副屏的展开、恢复和调宽能力。

### 6. 内容协议与安全边界

现有 HTML 只提供标题，无法支持宿主侧的页面状态与功能说明；因此在现有文件内增加可选、带版本的非执行元信息，描述局部页面标识、标题、顺序、关键状态、纯文本说明及对应位置标识。它是成果格式，不是任务字段、独立描述文件、固定目录或新数据库。可以一文件一页，也可以一个自包含文件包含一组关键画面；宿主使用“已发现文件身份＋局部页面标识”定位。

读取方只解析有界数据，限制条目数、文本长度和嵌套深度，不执行脚本、不信任路径或任意 URL。说明使用受信任文本组件（Component）渲染，不能把原型 HTML 注入 Buildr Web。元信息缺失时按旧标题作为单页显示；格式无效时给出局部诊断，旧页面仍可在安全边界内阅读。

页面选择、当前状态和双向位置提示通过最小消息协议传递。宿主只接受当前框架窗口、当前加载代次及已发现页面/状态集合中的消息；不以不透明来源的 `null` 值作为信任依据。装载建立随机关联标识，旧页面消息、未知操作、任意链接及接口调用要求被忽略。消息只改变阅读选择或高亮，不触发真实写入、外部导航或扩大读取范围。

正式原型仍在 `sandbox="allow-scripts"` 中运行；内容响应继续使用现有内容安全策略（CSP），禁止网络、同源权限、嵌套框架、父页面访问及真实接口（API）。“单独查看”的外层由 Buildr 提供，内部加载同一任务限定的隔离内容响应；直接访问裸内容响应仍保持原有隔离。

临时第二版使用同文档隔离样式来演示外观，不把它直接嵌入真实 Buildr 页面。正式阅读必须采用上述宿主与隔离内容边界。

### 7. 工作空间总览的首版产品方案

工作空间导航增加“总览”，页面标题“工作空间总览”。保留工作台现有“概览”和 `/overview`；新增独立工作空间入口，避免改变旧链接含义。

首屏用当前名称和已有说明建立业务背景，再展示项目（Project）、服务（Service）及代码库实例（Repository Instance）。关系来自已登记的稳定身份，一个对象只出现一次；共享引用清楚可追踪，独立登记但未被引用的对象也保留。默认排布稳定，有明确列标题和连线含义，不支持画布编辑、复杂筛选或运行状态推断。

具体项目保留概览和已有服务列表，增加“项目组成”查看方式。关联入口复用现有选择器：选择一个已有服务后即保存，保留过滤和新增入口；新增表单不在此次重新设计。保存使用现有版本校验，冲突或失败保留真实原状并提供重读，不出现模拟中的多选确认流程。

从总览点击项目直接进入主屏项目组成；从普通项目列表进入时仍先显示概览。重新进入项目时清空该项目旧副屏。服务和代码库进入右侧完整对象页，同类替换、异类页签并存；沿用 `WorkspacePages` 与 `paneDimensions` 的当前规则，不另做一套分屏算法。

图是现有登记事实的派生展示，不新建关系存储，不整组关联“基础服务”，不推导项目间依赖或规则继承。可用的现有登记读取优先复用；确有按类失败表达缺口时局部补充诊断，不进行全量 Git 状态扫描。一个来源失败不能伪装成零数据或删除已知关系；保留已知内容，标记缺失，支持重试。

只读入口 `GET /api/v1/workspaces/:workspaceId/workspace-composition` 优先复用 `readAssetCatalog`。严格清单读取失败时，按项目、服务、代码库来源分别校验并保留有效条目，返回来源完整程度及诊断；不返回写入版本、不修复或迁移清单。前端（Frontend）按工作空间身份保留上次已读对象，完整重读才确认对象删除；未读到的已登记引用显示不可打开的占位。关联写入仍通过原严格清单与版本校验，重读不会自动重放失败修改。

## Risks / Trade-offs

- 单靠指导文档无法形成真实复用 → 首阶段用真实选择器和侧边阅读完成两个入口的构建与行为对照，再扩展总览。
- 为模拟而过度抽象 → 仅分离本次明确的副作用边界，保留完整局部交互，不要求所有组件（Component）无状态。
- 演示包过大或仍依赖上下文 → 在首个样例验证当前大小限制、样式完整性、导航替换和离线隔离；未通过不能声称交付方案已验证。
- 说明与交互漂移 → 状态、说明和例子在同一成果中定位，消息只承担阅读联动；以实际画面检查一致性。
- 关系较多导致首版难读 → 稳定分列、必要区域滚动并保留列表入口；复杂探索能力留待反馈，不承诺首版覆盖无限密集图。
- 旧原型被误当新规范 → 下方变更说明明确替代内容；正式开发读取现有原型与本轮设计，先修正已明确的差异。

## Migration Plan

1. 先完成前端复用边界和最小独立构建样例，再更新技能（Skill）及交付资源。
2. 增量扩展旧原型读取：旧文件继续工作，新元信息可选且有界；无需迁移任务记录或新增存储。
3. 两种阅读入口共用组件（Component），维持裸内容响应隔离与任务限定；完成安全和兼容验证。
4. 用共同源码生成修订后的关键页面，审看确认后接入总览真实数据并验证原有交互。
5. 实施结束按实际变化校准说明与代码地图（Code Map）；本轮规划不提前重写当前事实。
6. 回退时撤去新增入口及交付资源，旧原型读取与真实关联数据继续有效；候选源码不影响正式安装。发布与自举激活由其既有专门流程另行处理。

## 本轮审阅纠偏

用户指出候选原型偏离真实 Buildr Web。保留真实顶部“工作台／工作空间”、侧栏入口与折叠方式，通过共同展示源码接入模拟数据；不得用自画的简化外壳替代。画面按实际容器宽度响应，不再用整页缩放把字号与目标缩小。总览恢复名称与用途搜索、项目聚焦及关联高亮。图中项目直接打开“项目组成”，普通项目列表仍打开概览。演示中不覆盖的技能、文章及真实动作保留位置并明确不可用，不能伪装成已实现操作。

## 功能说明与画面对照

功能说明综合提案目标与设计中的交互、结果，只覆盖本次任务在当前关键画面呈现的功能。无需将全部需求或实现设计逐项映射到原型；保留作上下文的既有功能不自动成为说明项。组件复用、制作过程及验证记录放在来源或审查材料中。

复用 `PrototypeFeatureNotes` 展示功能卡片：悬停或键盘聚焦高亮对应区域，移开或失焦清除，点击定位；没有位置的旧说明仍可阅读。不绘制说明卡片与画面的连接线。高亮使用独立的瞬时消息，只接受当前页面、状态和已声明位置，不切换画面或重置模拟数据；页面切换清除旧高亮。原型内区域悬停可对应强调说明卡片。关闭最后一个对象详情时回报主画面，使页面目录与功能说明同时恢复。

功能卡片、区域高亮与阅读联动作为 `ui-prototype/assets/feature-notes.js` 和样式随原型技能分发，提供无框架依赖的挂载、更新、销毁及画面回报能力。Buildr Web 与总览原型直接导入同一来源，React 适配层只负责生命周期。后续原型复用组件，只填写本任务说明、标记区域并接入本地画面状态；构建时内联，不引入外部运行依赖。
