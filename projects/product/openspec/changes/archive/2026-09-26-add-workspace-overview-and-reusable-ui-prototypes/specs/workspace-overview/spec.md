## Purpose

为用户提供工作空间（Workspace）整体认识和具体项目（Project）的组成入口，基于现有登记说明业务目标、实现职责与代码位置，保留已有工作方式，避免把引用误解为归属、项目依赖或真实调用关系。

## ADDED Requirements

### Requirement: 总览展示已登记的整体组成
系统 MUST 在工作空间导航提供“总览”，以“工作空间总览”为标题，展示当前范围及项目（Project）、服务（Service）、代码库实例（Repository Instance）的名称、已有用途说明和已登记引用。系统 MUST 使用稳定对象身份去重，显示共享及独立登记对象，MUST NOT 推导未登记依赖、整组服务关联或规则继承；已有工作台概览和列表入口 MUST 保持可用。

#### Scenario: 共享服务与独立对象
- **WHEN** 多个项目引用同一服务，同时存在未被项目引用的独立服务
- **THEN** 总览 MUST 只显示一次该共享服务并展示各方引用，独立服务 MUST 仍可查看
- **AND** 系统 MUST NOT 创建项目之间的依赖或移动对象

#### Scenario: 空白与部分不可读取
- **WHEN** 全部登记内容为空，或仅部分来源读取失败
- **THEN** 系统 MUST 区分真实空白与不可读取，保留已知内容及引用，提供必要提示和重试
- **AND** 系统 MUST NOT 将未知数量显示为零或以局部失败阻断其他可用对象

#### Scenario: 直接探索已登记引用
- **WHEN** 用户搜索名称或用途、选择聚焦项目，或将指针移到一个对象
- **THEN** 总览 MUST 提供匹配结果、当前范围与关联高亮，清除条件后恢复全部内容
- **AND** 无结果 MUST 与读取失败区分；点击项目节点 MUST 直接进入项目组成

### Requirement: 总览沿用既有对象打开与关联语义
从总览点击项目 MUST 在主屏直接进入其项目组成并清理该次重新进入目标的旧副屏；点击服务或代码库 MUST 保留主屏并在右侧打开完整对象页，同类替换、异类并存。具体项目 MUST 提供“项目组成”的组成查看方式，关联行为 MUST 沿用选择单个已有服务即提交、过滤与新增入口及现有版本校验，不引入多选后确认流程。

#### Scenario: 从整体进入具体工作
- **WHEN** 用户从总览打开项目，再查看其组成并点击一个服务
- **THEN** 项目 MUST 直接显示组成视图，保留切换概览的入口；服务 MUST 在右侧打开且主屏范围保留

#### Scenario: 保存和冲突
- **WHEN** 用户选中尚未关联的服务，或提交时登记版本已变化
- **THEN** 系统 MUST 使用同一关联能力提交该选择；成功后总览与项目组成 MUST 反映已成立结果
- **AND** 冲突或失败 MUST 不覆盖新事实、不显示虚假成功，并允许重读受影响内容

### Requirement: 总览保持轻量的派生读取
总览 MUST 由既有登记事实派生，不建立第二关系存储，不要求获取所有代码库的本地状态。首版 MUST 保留简洁组成展示、对象入口和必要滚动，MUST NOT 将复杂图编辑、运行监控或任务统计作为使用前提。

#### Scenario: 多代码库读取
- **WHEN** 用户打开包含多个代码库的总览
- **THEN** 系统 MUST 不等待全量 Git 状态扫描，单个对象状态读取失败 MUST 只影响相关对象
