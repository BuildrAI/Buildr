# 工作空间总览与前端同源原型

## 本轮要形成的结果

人可以在“工作空间总览”看清整体组成、了解每部分的用途，并进入具体工作。智能体（Agent）开发正式页面或制作界面原型（UI Prototype）时，使用同一套已有组件（Component）和样式来源，通过真实或模拟的数据与操作接入运行。

本次包含三个部分：新增前端开发技能（Frontend Development Skill），优化原型技能（UI Prototype Skill）及任务中的阅读体验，完成简洁的工作空间总览。详细设计见 [连贯方案](design.md)，可执行步骤见 [实施清单](tasks.md)。规划已完成，用户已同意分两段实施；当前先实现共用基础与阅读方式，再提供修订后的关键页面供审看。

## 已确认的产品方向

- 名称采用“工作空间总览”，入口简称“总览”；具体项目保留已有概览，以“项目组成”展示组成。
- 原型须经用户明确授权；智能体（Agent）识别核心或大页面变化后先询问，普通小改动直接实施，不自动制页。本次已获授权，默认只覆盖关键页面及必要状态。
- 任务方案设计的左侧菜单直接列出页面，中心展示画面；“功能说明”沿用实施清单的临时查看和固定阅读方式。
- “单独查看”打开新的浏览器页签，呈现页面列表、画面、说明三栏；删除重复的扩大阅读与手动缩放按钮。
- 正式和模拟入口复用同一份源码；原型使用模拟数据（Mock Data）及本地操作，不连接真实业务写入。
- 首版总览保持简洁，先做好组成、引用与对象入口，根据使用反馈继续演进。

现有临时演示 `/tmp/buildr-panorama-v2.YbvM9H/review.html` 只供了解关键画面与阅读方向，不作为同源复用的实现依据。它仍包含需要纠正的旧行为：多选确认式关联、单独查看仅展示画面、说明固定常驻以及旧名称。正式实现前必须读取本轮方案，并以真实选择器的单选即关联语义重新生成对应演示；旧版本的检查不证明新实现已验证。

旧临时文件不复制成正式成果，以免任务页面把未修订版本呈现为当前方案。

## 交付判断

| 判断问题 | 可以检查的结果 |
| --- | --- |
| 是否真正同源复用 | 能指明两个入口导入的相同源文件，且相同操作顺序和反馈一致 |
| 是否只是换了数据和操作 | 模拟操作只影响当前演示，正式操作仍使用既有版本校验和业务保存 |
| 用户能否看懂这次要改什么 | 五组关键画面可直接选择，功能说明与当前画面对应，小改动不重复成页 |
| 阅读方式是否一致 | 任务菜单无重复列表，说明与实施清单同样操作，独立页保留完整三栏 |
| 总览是否真实清楚 | 共用与独立对象正确显示，点击进入符合既有习惯，未知数据不伪装成空白 |
| 是否保持原有能力 | 旧原型、原列表、工作台概览、项目概览、真实关联和分屏行为继续可用 |

## 实施顺序

先用关联服务和侧边阅读建立最小源码复用与隔离构建样例，再完成技能（Skill）和两种阅读入口；随后生成修订后的五组画面供审看，再接入总览真实数据。最后按实际影响维护现有说明和检查，发布及激活另按既有授权处理。
