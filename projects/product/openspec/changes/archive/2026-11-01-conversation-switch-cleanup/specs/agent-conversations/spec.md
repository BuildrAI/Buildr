## MODIFIED Requirements

### Requirement: 等待回答时必须支持显式交接到新执行组合

原轮仅等待普通问题回答，用户切换模型或智能体（Agent）后，系统 MUST 提供两条明确路径：提交问题卡片的有效回答并交接，或提交输入框中的新指令并交接。无新增内容时 MUST 允许明确继续原目标。单独选择和查看交接 MUST 不停止、答复或发送。提交 MUST 先持久保存新内容、准确原轮及问题身份，结束原轮问题的活动等待并保留未回答事实；系统 MUST 向所选新组合独立发送一次，并自动请求准确停止本对话被替代的旧执行，不等待工具退出。执行未知、问题或原轮身份变化 MUST 保留具体原因及输入，MUST NOT 停止其他工作或推定成功。

交接资料 MUST 保留准确原问题；经卡片明确提交的回答 MUST 连同问题交给新组合，MUST NOT 先答复并唤醒旧执行。未提交的选项或填写内容 MUST 仍为未回答。交接动作本身 MUST NOT 被视为验收、选项答复或权限批准；实际业务回答 MUST 保持其明确范围。工具授权 MUST 继续归属原请求，不沿用本交接路径。普通原组合的卡片答复与补充 MUST 保持既有语义。

#### Scenario: 换模型后回答并交接
- **WHEN** 原轮等待问题，用户换模型并在问题卡片提交有效答案
- **THEN** 卡片 MUST 明确显示回答将交给新模型；系统 MUST 保存原问题与答案、结束准确原轮等待并向新模型交接，MUST NOT 把答案送回旧执行
- **AND** 其他未提交的输入草稿及未答问题的历史事实 MUST 保留，实际回答 MUST 不扩大其授权范围

#### Scenario: 换模型后发新要求或继续
- **WHEN** 用户未提交原问题的回答，换模型后在输入框发送新要求或明确点击继续
- **THEN** 系统 MUST 交接已有现场与新要求，原问题 MUST 保留为未回答且不可再向旧执行提交；选择了但未提交的选项 MUST 不作为答案

#### Scenario: 仅预览或取消交接
- **WHEN** 用户只切换模型、打开交接资料，或在实际投递前取消已保存的待发送
- **THEN** 原轮 MUST 继续等待，MUST 不自动答复、停止或投递新执行
- **AND** 如果另有明确停止操作，MUST 单独显示其事实；取消只撤回尚未发送的新轮，不改变旧停止的真实结果

#### Scenario: 停止未知或并发答复
- **WHEN** 原轮停止无法确认，或原问题被其他入口答复、原轮身份变化
- **THEN** 系统 MUST 保留交接内容和准确原因；停止未知 MUST NOT 单独阻塞新要求，已答复或身份变化时 MUST 拒绝过期问题的回答或交接，MUST NOT 重发原操作

#### Scenario: 重复提交和后台恢复
- **WHEN** 同一交接重复提交、页面刷新、接收后台重启或切换
- **THEN** 已持久保存的内容 MUST 能继续观察准确原轮并按原提交身份核对送达，MUST 不重复答复、重复发送或停止其他对话


## ADDED Requirements

### Requirement: 确认切换必须自动善后且隔离旧交互

用户确认切换执行组合并发送或继续后，系统 MUST 在持久登记新执行时结束本对话被替代旧轮的活动问题，保留未回答事实并拒绝迟到回应。旧问题事件与观察 MUST NOT 重新激活卡片。系统 MUST 按准确身份自动请求停止，停止未知 MUST 保留真实结果且不阻塞新要求、不重放、不强杀共享资源。仅预览、取消未发送内容及同组合先讨论 MUST 保持原等待。系统 MUST 不把内部善后作为普通答复附注；仅实际影响目标且需要用户决定时说明具体影响。

#### Scenario: 迟到问题与未知停止
- **WHEN** 切换提交后旧停止未知且迟到问题事件或快照到达
- **THEN** 新要求正常执行，旧卡片不再激活，未知内部保留，其他对话不受影响

#### Scenario: 重复投递和重启
- **WHEN** 同一请求重复提交或后台重启后发现已登记切换
- **THEN** 系统 MUST 不重复发送新要求或重复发起已请求的停止，能够观察原执行结果

### Requirement: 原生普通问题必须开放支持的自定义回复

DSH、Qoder 普通问题 MUST 显示其他回答并将自定义文字交给准确原问题；多选 MUST 支持选择与自定义文字同时提交。Codex MUST 保留原生声明的自定义能力。空回答 MUST 不可提交，工具审批 MUST 不增加自由回答或扩大授权。

#### Scenario: 单选其他回答
- **WHEN** 用户为 DSH 或 Qoder 普通选择问题选择其他并填写文字
- **THEN** 文字 MUST 按原问题协议交付一次，固定选项保持可选

#### Scenario: 多选附加文字
- **WHEN** 用户选择已有选项并填写其他回答
- **THEN** 选项和文字 MUST 同时保留并准确交付，不把未提交内容视为回答
