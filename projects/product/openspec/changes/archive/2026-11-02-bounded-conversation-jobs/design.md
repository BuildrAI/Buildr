## Context

见 proposal.md。DSH 原生 shell 工具提供 promoteOnTimeout 开关和显式 run_in_background，当前 Buildr 未覆盖前者。tools-active 表示模型结束但工具仍活动；现有提醒和统计把它与模型运行混算。

## Goals / Non-Goals

**Goals:** 原生确定性超时；显式后台服务保留；活动投影与模型统计、历史展示一致；零写入兼容旧摘要。

**Non-Goals:** 不自研 shell 执行器，不按命令文本猜用途，不根据最终文字宣告模型结束，不按统一时长杀死所有服务，不重发历史命令。

## Decisions

- 通过原生配置层把 tool-bash/tool-pwsh 的 promoteOnTimeout 设为 false，保留原生默认期限、显式覆盖及后台启动。避免自行管理 PID 或引入第二作业库。原生 web 能力配置可能在独立预设内加载同类工具，默认层覆盖不足以控制其配置；因此同时安装原生 post-execute 兜底，仅对未显式后台启动且返回 promoted 的 shell 作业校验 原生工具返回的 jobId 与 owner 身份，用原生 jobs.kill/wait 终止并确认。超时以失败结果返回，无法确认时保留作业与未知说明。
- 仅排除已确认 tools-active 的模型活动判定；真正 running、待决策、未读与 unknown 仍保留。后台状态及停止入口保留，绝不伪造资源释放。
- 列表只为可能陈旧的后台摘要加载版本匹配的轻量状态头重算；不全量读消息正文，不在查询中写库。
- 历史元数据标出后台作业，执行概览只统计真实模型处理。复用现有界面，不新增页面或布局。

## Risks / Trade-offs

- 前台长任务原本依赖自动提升 → 原生工具 schema 和执行指引明确期限及显式后台选择。
- 已存活旧宿主仍使用旧配置 → 本次不自动中断旧宿主，激活时遵守既有准确归属和安全释放边界。
- 旧摘要或真实未知状态 → 仅对已知 tools-active 重算；未知不会伪装完成。

## Migration Plan

独立工作树验证后按正常交付激活；新建隔离 DSH 使用覆盖配置。原历史不重发，后台作业仍可核对与停止。回退仅恢复配置与投影实现，不撤销已发生的超时或命令副作用。
