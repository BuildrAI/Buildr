## Why

统一对话正文目前同时存在于整段记录 JSON、分页正文及预览，短条目甚至重复全文。近期测量表明工具记录占单份正文约 97%，正文去重与稳定大工具无损压缩比整条原生会话归档更值得先做。

## What Changes

- 将对话控制头、顺序与正文修订分离，正文只保存一份；预览不再复制相同的小条目。
- 稳定的大工具条目采用有界无损压缩，原始内容摘要、详情修订、分页与交接保持；可见消息保留单份未压缩正文以保持现有搜索，不新增 FTS。
- **BREAKING**：升级私有数据库格式。迁移前保护活跃旧后台并建立一致性备份；旧写入器不能继续写入新结构，旧程序应明确拒绝较新存储。读取旧库本身不迁移。
- 复用现有存储维护机制，集中受管 Node 编译缓存，并仅回收已确认空闲、内容与占用未变化的旧编译缓存；不清理普通工作成果、原生日志或整个私有 HOME。
- 保留原生执行存储与账号隔离；完整冷热归档仍由独立待办承担。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `agent-storage-lifecycle`：增加统一正文的单份持久化、无损读取、迁移保护及编译缓存生命周期约束。

## Impact

影响 `services/buildr-agent/src/persistence/`、运行时存储版本声明、原生环境及缓存声明与相关测试。公共对话 API 和现有 UI 保持，宿主继续只消费公开包。正式任务为[近期优化](@task/agent-storage-optimization)；长期任务使用另一工作树，不进入本次实现。不会将候选应用到真实配置，不执行真实会话清理或付费模型试验。
