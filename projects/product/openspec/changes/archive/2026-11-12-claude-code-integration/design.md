## Context

现有四个执行器共享 `AgentExecutor`/`AgentRuntime`、模型租约和独立后台。Claude 文件投射已经存在。当前模型网关提供 Anthropic Messages，但尚未有 Claude 原生消费者。动机见 proposal。

## Goals / Non-Goals

**Goals:** 原生执行与共享模型解耦，保持可恢复的准确身份；对齐现有适用功能，复用统一应用层。

**Non-Goals:** 不重写推理循环，不复制终端界面，不自动接管桌面凭据，不提供未经许可的订阅登录，不自动发布或激活候选。

## Decisions

1. 使用固定官方 Agent SDK 驱动明确 CLI，专用工作进程隔离 SDK 的配置与历史发现。优于解析终端文本或手写私有控制协议；CLI 版本准入后仍须实际握手。
2. 配置根由 `CLAUDE_CONFIG_DIR` 定点隔离；在完整隔离未获证明前保持私有 HOME，工具通过既有宿主路径与缓存能力共享。工作目录继续承载项目规则，显式追加 Buildr 交互约定，不加载用户默认账号。
3. 模型只经过既有本机租约。主、子、默认轻量模型统一映射到选定模型；不配置 fallback。按模型能力限制思考、上下文和输出，不把不支持的扩展盲传给其他厂商。
4. SDK 流式输入带稳定请求 UUID。原生回显才证明受理；控制与执行读取独立。首次回显迟到时，以原生追加文件中的准确输入 UUID 确认受理；游标只读取新字节。中断通过 SDK 自定义启动面为其原生 interrupt 控制增加已文档化的 cancel_queued 字段，并核对能力声明及取消回执；不另建推理或控制循环。后台任务与未证实的结果独立保留。每个工具保留调用 ID、来源消息和父调用。
5. 原生会话是工具正文权威。适配器按准确配置、会话和调用有界读取 JSONL 与子智能体记录；不把完整正文复制进统一数据库。历史恢复、分叉和附件沿公共契约接入。跨配置分叉由来源 SDK 按准确消息边界创建，再仅导入该独立 JSONL，目标排他创建、不覆盖、不复制账号或整个配置。已知新身份先登记，导入失败不自动重建。模型层只为仍有效、同账号身份、同模型配置和同执行器的两个租约重新封装加密推理；密钥与解密正文不交给执行器。目标副本中的准确模型租约别名随之映射，避免 CLI 误判切换模型而丢弃推理。
6. 官方 Claude API 来源使用独立 API Key 提供者，复用模型管理；不将 Claude 程序就绪与账号登录混为一谈。共享模型失败不否定程序可用。
7. 标题与交接摘要使用隔离、无工具的请求，不进入工作会话；允许推理模型伴随正文返回原生推理块，但只提取正文，工具块、截断或空正文仍明确失败，不泄露隐藏推理。

## Risks / Trade-offs

- 非 Claude 模型无官方支持 → Buildr 明确兼容路径并按版本/模型实测，失败保留准确原因；不宣传任意模型全功能通过。
- 原生升级引入字段变化 → 固定 SDK、核验程序和真实事件，补齐契约及子进程测试。
- 中断后排队输入继续执行 → 使用原生回执核对，必要时关闭本执行独占控制资源；不杀其他执行，不伪造业务终态。
- 原生详情格式变化 → 有界、安全、准确匹配；无法证明归属即缺失，不按文本猜测。
- 真实账号验证涉及消费 → 默认测试本机协议替身和真实 CLI，不隐式使用用户付费账号；未验证组合如实列出。

## Migration Plan

新增执行方和 API 来源，不修改旧记录身份。已有 Agent 继续工作；新增 SDK 随私有库交付。回退时不删除新原生历史与账号。候选仅在独立工作树验证，正式激活交给既有唯一执行器。
