## Context

现有连接模块按类型登记提供者（Provider），保存本机连接与独立加密凭据，并向网页和命令行接口（CLI）提供相同连接身份。MySQL 专业操作已隔离，但表单、类型与命令目前只支持 MySQL。需求及动机见 proposal.md。

## Goals / Non-Goals

**Goals:** 复用连接与凭据治理，通过 Nacos HTTP 开放接口（OpenAPI）交付完整文本操作和逐次生产授权方法。

**Non-Goals:** 不复制 Nacos 控制台，不建设通用许可层，不接入服务实例、配置新增删除、灰度或业务重启；不声称对本机全权限程序提供不可伪造的人类身份保证。

## Decisions

### 复用连接专业提供者

增加 `configuration/nacos`；专业配置为 `consoleUrl`、`username`、`namespaceId`、`defaultGroup`、`production`、`apiVersion`。保存原网站 URL，规范化同目标接口基址；地址禁止内嵌账号密码。环境继续为自由标签，生产标识独立明确，不按 URL 或环境文本猜测权限。默认范围为 public / DEFAULT_GROUP，版本默认为 auto，可明确选择 v1/v2/v3。

### 直接调用接口并保留机器入口

使用现有 Node.js HTTP 能力，不新增官方命令行工具（CLI）二进制依赖。Nacos 接入层（Adapter）负责认证、路由差异、文本与返回格式；应用层负责连接版本和生产授权输入；命令入口复用 `buildr connection nacos <namespaces|list|get|diff|publish>`。配置列表/读取/发布保留完整标识和文本，限制响应大小、页大小与超时，不自动抓取全部配置。

### 比较复用真实文件

`get` 返回完整内容和摘要，智能体（Agent）使用普通文件工具准备候选。`diff` 支持候选文件或明确第二连接/配置，生成有界文本差异及当前发布范围。`publish` 必须提交 `expectedRevision`、`expectedMd5` 与候选文件，不用连接登记版本代替外部内容版本。初版只发布已存在配置。

### 生产授权属于本次内容

用户指令来自智能体（Agent）的原生对话。生产发布要求独立 JSON 输入，包含授权来源 `source`、用户原意 `statement` 及 `scope`；范围绑定工作空间（Workspace）、连接（Connection）、连接版本、命名空间（Namespace）、分组（Group）、`dataId`、配置格式 `type`、`expectedMd5` 与完整新内容的 SHA-256 摘要。`diff` 返回可审阅的范围，不自动产生授权；技能（Skill）要求先展示差异，再取得用户针对本次发布的同意。

通过范围校验后，系统在调用发布能力前记录本机单次使用（Single Use）事实。同一工作空间（Workspace）与连接（Connection）上的同一 `source` / `statement` 只能用于一次生产发布尝试，不因恢复旧内容、发布失败或结果未知而重新可用；再次发布前先观察当前内容，再取得新的用户授权。记录只保存使用身份摘要和时间，不保存配置内容或授权正文，不建立永久已批准状态。此校验限定具体生产动作，不能独立鉴别人类，也不能阻止本机全权限调用方伪造来源。读取缺少格式时先尝试从管理详情补齐；生产实际发布仍未确认格式时不消耗授权，普通读取继续返回可用正文。

### 发布前核对与可观察结果

普通 `publish` 不以原生比较并交换（CAS）为必需条件。已确认兼容的服务器版本与接口优先提交 `casMd5`，结果标记 `concurrencyProtection: native-cas`。旧版、未知、自定义或已知忽略该参数的路线采用 `concurrencyProtection: preflight-recheck`：提交前再次读取最新管理详情，核对配置身份、完整正文摘要及已绑定格式 `type`，保留当前元数据（Metadata），再提交普通 `POST`。发现正文或格式变化、配置不存在或必需详情无法读取时，拒绝本次发布；能力不足本身不阻断其他可正常执行的发布。

二次读取只缓解覆盖旧观察的风险，最后读取与写入之间仍有竞争窗口，不能承诺原子保护。结果必须返回实际 `concurrencyProtection` 及对应局限提示，不把 `preflight-recheck` 描述为原生比较并交换（CAS）。Nacos 的新增或更新语义（Upsert）也可能在并发删除后重建配置，不承诺严格存在性保护。发布成功再回读，分别返回 `published` 与 `verified`；网络结果未知不自动重发。服务重启仍由后续明确授权的工具承担。

旧版 `v1` 发布返回明确的纯文本 `Cas publish fail, server md5 may have changed.` 时，报告配置冲突及发布已拒绝；其他错误正文或传输中断仍保留结果未知，不据此推断没有写入。

经用户授权，已在测试部署的专用临时配置上实测 `4.6.0-SNAPSHOT` / `v1`：正确摘要可以发布，但携带旧摘要的 `casMd5` 请求头（Header）仍返回成功，随后配置详情确认正文已被更改。这证明该部署的该路径未执行原生比较并交换（CAS）校验，不能登记为原生保护；该路线使用二次读取并正常发布，明确披露竞争窗口。版本标识不能代替实际接口的执行事实。上述探针的专用测试配置已删除并通过读取返回 `HTTP 404` 确认清理；本轮随后通过真实命令行接口（CLI）完成专用临时配置的二次读取发布和回读验证，保留格式及说明元数据，使用旧摘要的再次发布被拒绝；临时配置已删除并确认不存在。证据不覆盖其他部署、真实业务配置或生产发布。

用户对本轮开发与二次读取方式的授权，不替代每次真实生产发布针对具体目标和差异的授权；生产授权范围校验与本机单次使用（Single Use）规则保持不变。

### 简单网站入口与导航修复

复用现有连接抽屉（Drawer）和 MySQL 控件，创建时选择类型，编辑时锁定。Nacos 地址在正常链接中以 `_blank` 与 `noopener noreferrer` 打开，密码和访问令牌（Access Token）不进入网址。补全已存在连接页面在 Codex 固定入口的路由映射，恢复左侧菜单可达性。

## Risks / Trade-offs

- 自定义 Nacos 构建或网关路线 → 自动模式与显式版本选择，原生比较并交换（CAS）未确认时使用二次读取；必需读取或发布接口不可用只影响相应动作。专用临时配置实测只能证明所测接口。
- 原生比较并交换（CAS）与二次读取的保证不同 → 返回实际保护方式、竞争窗口及并发删除限制，保留回读与冲突报告，不用二次读取冒充原子保护。
- 对话授权来源不能由本机调用独立证明 → 强制输入绑定范围，技能（Skill）逐次取得真实用户授权，说明其保证边界。
- 配置内容可能含业务秘密 → 不自动写仓库或任务正文，文件由用户/智能体（Agent）在明确目标下管理，不输出认证秘密。

## Migration Plan

无数据迁移与新增依赖；Nacos 作为新增专业类型，MySQL 配置、凭据和命令保持兼容。代码交付与本机自举激活分开，不从任务候选覆盖日常环境。
