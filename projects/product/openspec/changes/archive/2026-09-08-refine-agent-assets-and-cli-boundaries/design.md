## Context

审查基线为 `df61f0cd`。资产应用通过共享对象隐式互调；Doctor、安装状态和更新应用解释命令参数并修改进程输出；包资产文件同时解析资源和修复业务登记。架构扫描只识别 `.mjs`，遗漏当前 `.ts`。

## Goals / Non-Goals

目标：显式依赖、唯一业务登记责任、可直接调用的结构化应用、有效生产源码扫描，以及真实代码地图。
非目标：改变公开命令、HTTP、JSON、持久化和业务结果；机械拆分 Task/Workspace、前端或查询与命令。

## Decisions

- `agent-assets/module.ts` 保留装配（Composition）职责，逐一创建技能、命令、组件、包维护、投射应用；依赖类型归属各应用。实际循环协作只通过具名延迟函数连接，不把共享可变对象交给应用。内部辅助方法仅向真实消费者公开。
- 包资源清单读取归属数据访问（Persistence）；资产比较保留在包维护应用；项目/服务登记修复移入 Workspace 应用并通过公开能力提供。包模板与技能清单仍由资产模块负责，通过明确回调维持原修复顺序与事务范围。
- Doctor 接收目标、作用域、运行时与诊断选项，返回完整结果。命令接口负责默认参数、紧凑 JSON、人类输出及退出码。安装状态与更新采用同一边界原则；核对资产修改后的 Doctor 调用及 HTTP 消费者。
- 架构扫描共用真实源码文件范围，并加入 `.ts` 违规样本证明能失败；不靠文件行数推断职责正确。

## Risks / Trade-offs

- 隐式依赖改为显式连接可能遗漏方法 → 类型检查、真实装配、相关 CLI/HTTP 和同步回归。
- 移动登记修复可能改变迁移顺序或写入范围 → 保持事务路径、登记实体创建、旧文件处理和幂等语义；复用登记迁移与受管写入检查。
- 移动输出可能改变 JSON 或退出行为 → 对紧凑/完整 Doctor、安装与更新正常/失败结果执行公开入口检查。

## Migration Plan

在隔离目录实现，验证后正常提交、快进集成与推送；通过唯一自举程序激活，再按精确提交清理。无需数据迁移。回退需新的正常修复提交，不改写共享历史。
