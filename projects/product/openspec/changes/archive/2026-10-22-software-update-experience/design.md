## Context

现有更新应用在内存维护 prepare/apply，npm 生命周期尝试刷新启动器但仅警告失败，旧网页进程退出后没有可读取的阶段结果。现有网页交接已经提供同安装槽位认证和精确新版本健康核验，应继续复用。前端采用已确认的第三版原型，连接图标按用户最终修正仅改变轮廓颜色。

## Goals / Non-Goals

**Goals:** 保持精确版本、结果分离、跨实例接续和有界恢复；前端与 HTTP 共用确定性结果，失败仅影响相应步骤。

**Non-Goals:** 不建立通用安装渠道、不创建缺失启动器、不替代安装归属校验、不发布或改写共享开发环境。

## Decisions

- 在安装模块保存本机更新记录，以真实产品根定位同一更新范围；任务标识及记录版本约束阶段写入。进程重启时从记录接续，而不是依赖浏览器缓存或对话。
- 快照区分安装、启动入口、重连与运行版本核验。进程版本在启动时捕获，不能将安装后变化的磁盘版本当成当前运行版本。已有 Web 交接返回的精确身份继续作为新实例证明。
- 启动入口检查与修复复用 npm Launcher 的唯一归属与原子替换实现。故障保留为部分成功，继续尝试网页交接；修复动作只作用于同一精确安装。
- 新增恢复入口接收任务身份、精确版本和明确环节。与重新运行完整更新命令相比，可以避免重查标签后改变目标或重复下载。
- 前端更新状态由功能钩子（Hook）集中管理，更多菜单通过窄入口发起手动检查。连接中断后重新读取新会话和任务快照，再决定完成、版本不符或继续恢复；旧会话不能继续写入新实例。
- 顶部图标采用原界面默认的 14px，与 DSH 文字同字号、图文间距 8px，按钮高度 32px；更新入口使用无外圈的下载箭头，与既有轮廓图标保持轻量风格。
- 采用原型的紧凑布局；正式页面只展示真实版本与结果。没有真实发布说明时不编造修复列表，没有总下载量时使用不定进度。

## Risks / Trade-offs

- npm 替换成功与旧进程退出之间可能中断 → 阶段先落盘，新实例结合自身版本接续，不将辅助记录冒充安装权威。
- 启动入口或安装被外部修改 → 恢复前重新核对精确安装与归属；冲突保留现场。
- 存储或并发写失败 → 停止相关副作用并明确错误，不覆盖新记录。
- 真实 npm 更新有外部副作用 → 单元与系统检查使用明确替身及隔离目录，浏览器使用开发模拟；不对日常安装执行试更新。

## Migration Plan

HTTP 快照升级为 v2，同包前端同步消费。无旧持久记录时从空任务开始；未知或损坏记录只影响更新能力并明确报错。已确认原型保存到本变更；正式实现完成后保留源码与测试供后续收尾。

## Implementation Evidence

正式弹窗与任务原型共用 `UpdateDialog` 和更新视图模型，连接图标共用原有 `RobotOutlined`。页面已在隔离开发实例实际点通检查、下载、稍后安装、继续安装、真实实例重启及模拟结果恢复；模拟不改真实软件版本。安装、恢复、契约和版本通道相关的 48 项检查、16 项真实包与启动入口检查，以及 525 项前端逻辑检查通过，正式前端构建和后端类型检查通过。启动入口测试只写测试目录，不操作日常应用。Windows 原生桌面环境未执行，沿用已有快捷方式与脚本契约检查。

补充的全库测试目录归属审计仍报告三个与本次无关的既有缺项：`service-runtime-http.test.ts`、`service-runtime-module.test.ts`、`workspace-registry-scope.test.ts`；主目录基线同样失败。已补齐本次更新契约与恢复测试的现有分组归属，不扩大修改其他功能。复用主目录已经交付的 `a44fab81f` 类型声明修复作为工作树编译前置。
