## Context

动机见 `proposal.md`。`SourceControlWorkbench` 已依据代码库（Repository）、工作树（Worktree）、路径及比较层取得真实差异（Diff），再通过共享 `TaskDiffReader` 显示静态文字行；完整文件入口目前也明确只读。`FileEditingController` 与工作空间（Workspace）级编辑存储已经承担完整文件、历史、自动保存（Auto-save）、中文组合输入、受管区块（Managed Block）和外部冲突处理。新增能力应连接这两组现有职责。

## Goals / Non-Goals

**Goals:**

- 用成熟差异（Diff）呈现层支持旧侧只读、当前侧可编辑、行内定位和单块恢复。
- 当前正文及可撤销（Undo）事务（Transaction）仍归既有编辑状态所有，任何呈现模式都不创建第二份保存权威。
- 当前文件读取与比较基线必须属于同一已核对来源；缺少完整正文、来源或版本证据时仅停止相关编辑。

**Non-Goals:**

- 不扩展到索引、固定历史、删除文件的写入，不新增 Git 写入或改变已有只读命令行接口（CLI）和网页接口（API）。
- 不将共享任务（Task）阅读入口默认变为可写，不迁移保存协议或持久数据，不重建完整编辑器。

## Decisions

### 以 `@codemirror/merge` 承担呈现和变化计算

复用已采用的 CodeMirror，新增 `@codemirror/merge` 来呈现左右及上下对比、变化块和恢复操作。左右对比把基线侧固定只读，把当前侧事务（Transaction）交给共享控制器（Controller）；上下对比在当前正文之上显示只读旧删除内容。统一主题、语法、尺寸及焦点行为，不把旧行当作当前正文。

`MergeView` 不能直接持有现有共享 `EditorState`，因此保留局部呈现状态，用事务（Transaction）桥接将文本变更及选择映射到 `FileEditingController`；规范正文、历史和保存状态仍由后者唯一持有。撤销（Undo）、重做（Redo）及立即保存快捷键直接调用共享控制器（Controller），再同步呈现。合并扩展仅用于局部视图，不注入共享普通编辑器状态，避免返回资源管理器（Explorer）时残留旧删除装饰。

替代方案是在现有 `<pre>` 行列表上加入可编辑元素，需要自行维护行号、空白对齐、光标、输入法、历史及变化映射，成本和风险较高；另起完整编辑器又会重复已有保存体系。成熟呈现层只承担其擅长的工作。

### 共享完整当前文件及历史

通过现有 `useEditableFile`、`FileEditingController` 及真实来源选择器读取可编辑当前文件，共享资源管理器（Explorer）的文件身份。未暂存比较基线通过现有 `source-file` 的已暂存层读取，并保留固定对象版本；未跟踪文件使用空内容基线。严禁根据可见补丁（Patch）重建当前正文。两份完整内容及来源一致性均成立后开放当前侧编辑，保持现有读取范围与校验，不扩展接口协议。

直接输入与恢复必须走相同事务（Transaction）入口，使用现有保护范围及保存队列。模式变化只重建呈现所需配置，不清空编辑状态；中文组合输入和失焦继续通知现有控制器（Controller）。保存反馈、错误和冲突处理复用现有组件或抽取可复用的状态展示，不复制业务判断。

### 比较身份与恢复保持局部

编辑仅面向当前未暂存／未跟踪完整普通文本。已暂存和历史文件继续按固定版本阅读；图片、二进制、删除和受限文件沿既有分支展示。共享 `TaskDiffReader` 的默认只读行为不变，可通过明确传入的呈现内容和操作接点承接新视图。

变化块基于当前编辑状态和该比较层的基线生成；恢复提交精确范围的单次事务（Transaction），保留其他输入。每次恢复前由源代码管理（Source Control）接入层重读索引基线；若基线或所选身份已变，更新比较并取消旧块操作，提示重新核对，而非把旧范围应用到新基线。基线刷新不覆盖未保存正文。恢复触及保护范围时拒绝该事务（Transaction），不以整段替换绕过保护。

### 导航与保存刷新解耦

变化定位、数量及恢复结果直接来自当前文本比较，不等待自动保存（Auto-save）或目录刷新。前后定位适用两种呈现，首次选择定位首处；同文件刷新及保存只更新事实，不重置仍有效的光标、历史和阅读位置。无变化也保留已打开编辑现场，以便撤销（Undo）和继续输入。

## Risks / Trade-offs

- [完整侧内容与当前磁盘可能发生变化] → 复用来源和观察版本校验，编辑读取与比较层核对；外部变化保留草稿并进入既有冲突处理，过期基线不允许恢复。
- [模式切换或呈现层内部事务（Transaction）可能重置历史] → 共享编辑状态为唯一当前状态，恢复和输入统一派发；验证保存后撤销（Undo）、跨入口继续及模式切换。
- [上下对比的旧删除文本可能混入保存或输入法中间态] → 旧侧仅作为呈现装饰，保存读取完整当前原文；覆盖中文输入、末尾换行及不同换行格式的代表场景。
- [新增依赖增加构建体积且可能与既有 CodeMirror 版本不兼容] → 按锁文件核对依赖版本，使用正式前端构建及实际页面验证；无适用完整内容时保留既有只读阅读。
- [共享组件影响任务（Task）及图片阅读] → 新编辑能力采用显式接点，旧默认行为保持，并回归固定历史、图片和完整文件入口。

## Migration Plan

仅增加前端依赖、组件和按需数据接入，无持久数据迁移。现有响应和只读调用继续兼容；移除新接点可回退既有静态阅读，当前文件及共享保存历史不需要迁移。正常交付流程不包含发布或部署。
