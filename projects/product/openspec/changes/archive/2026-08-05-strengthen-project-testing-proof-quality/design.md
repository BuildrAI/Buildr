## Context

`project-testing` 当前使用正交模型指导 Agent 判断测试意图、执行边界、成本、选择范围、验证目标和证据 owner，并以最低充分边界开发测试。这个模型解决了“测试放在哪一层、何时运行多少”，但测试正文只有“能独立定位失败”的弱约束，缺少从待证明事实到测试案例与有效性证据的闭环。

本次只修改随包自然语言工作资产、对应 canonical spec、静态校验和契约测试。`project-testing` 继续没有 Result、Receipt、Application、provider contract 或自身持久状态；真实测试效果仍由后续项目实践和 Task Verification 观察。

## Goals / Non-Goals

**Goals:**

- 让 Agent 在选择最低充分边界前，先把待证明事实映射到公共可观察结果和最小关键案例。
- 防止空洞断言、只覆盖成功路径、mock 被测逻辑和有副作用测试无法重复运行。
- 为 Bug 修复保留可信回归证据，同时允许在无法安全运行旧实现时诚实报告 gap。
- 用最小 reference 审查卡和现有契约测试固定指导，不增加执行平台。

**Non-Goals:**

- 不规定固定 case taxonomy、覆盖率阈值、mutation testing 工具或 TDD 流程。
- 不要求每项变更穷举所有边界，也不把安全、性能、浏览器或移动测试自动纳入第一版。
- 不改变 Task Verification、`verification.yml`、Candidate 或 Release 生命周期。
- 不创建新的 capability contract、registry schema、Result 或状态存储。

## Decisions

### 1. 在执行边界选择前增加最小证据设计

每项关键待证明事实先写成公共可观察结果，再按风险选择正常、失败、边界与必要状态转换案例，随后选择能证明这些结果的最低充分执行边界。这样保留现有分层模型，同时避免 Agent 只按文件类型或代码结构机械生成测试。

不采用固定全量 checklist；不同领域的有效边界差异过大，强制穷举会制造低价值测试。Skill 只要求选择与遗漏理由可解释。

### 2. 回归有效性使用可证伪要求而非强制工具

Bug 回归测试必须说明它捕获的旧错误，并尽可能证明测试在修复前、错误实现或移除修复后失败。若旧版本执行有破坏性、成本过高或无法复现，Agent 明确报告替代证据与 gap，不伪造红灯历史。

不强制 mutation testing 或 checkout 旧代码；这些手段成本和风险依项目而异。

### 3. 断言公共行为，替身只隔离边界

测试优先断言返回值、状态变化、输出协议和公开副作用等公共可观察行为。mock、fake 或内存实现只替代外部协作者和不属于当前事实 owner 的边界，不复制被测算法或仅验证内部调用顺序；只有调用协议本身就是契约时才断言交互。

### 4. 状态质量按实际副作用条件触发

涉及文件、数据库、消息、缓存、全局配置或其他状态时，Agent 检查隔离、幂等、失败后清理和重复运行。纯函数测试不机械承担这些检查。

### 5. 现有静态与契约测试只固定指导，实践负责效果校准

扩充 package 静态校验和 `project-testing` 契约测试，检查质量闭环、回归有效性、替身边界和状态质量指导仍被交付；reference 增加两个代表性判断示例。第一版不构建 LLM evaluator 或第二套测试平台，实际 Agent 产出质量留给后续任务实践观察。

## Risks / Trade-offs

- [Agent 把案例类型当成必须穷举的模板] → 明确按风险选择最小关键集合，并允许说明不适用。
- [为了证明回归红灯而执行危险旧版本] → 只在安全、低成本、可复现时运行；否则记录替代证据和 gap。
- [公共行为约束阻碍必要协议测试] → 当交互协议本身属于待证明契约时允许断言调用参数、顺序或次数。
- [契约测试只证明文字存在] → 明确其边界；不宣称已经证明所有 Agent 行为，后续从实际任务观察再迭代。
