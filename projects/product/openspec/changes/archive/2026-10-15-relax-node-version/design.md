## Context

见提案（Proposal）。当前 `.node-version` 既被用作选用基准，也被多个入口误用为精确兼容限制；子进程的可执行文件身份核对则是另一项有效约束。

## Goals / Non-Goals

统一最低稳定版本 `24.15.0`，保留显式供给、NVM 与 PATH 的既有选择顺序，并让实际版本进入证据。工作空间保存的已观察 Node 程序不自动替换；外部 SDK 源码与包管理器版本不变化。

## Decisions

- `.node-version` 保留基准值，兼容判断采用三段稳定版本的最低值比较；主包与插件 `engines.node` 表达 `>=24.15.0`。不通过移动基准值临时掩盖问题。
- 共享执行环境新增最低版本校验，原有可执行文件与 PATH 一致性及针对已观察事实的精确比较保持。开发、候选、发布与插件各自入口接入相同语义。
- 持续集成（CI）仍可明确选择基准和宿主版本；这是实际检查组合，不再被当成本地执行的唯一合法版本。旧发布回执仍按原身份恢复，不重写历史。
- 当前认知（Current Knowledge）影响为发布流程、插件说明、开发入口说明及验证地图中的 Node 要求，按最终实现校准原位置，不新增图示或流程门禁。

## Risks / Trade-offs

更高主版本可能有尚未实测的依赖差异，报告实测版本与平台，实际失败继续局部诊断。预发布和无法识别版本拒绝；不把版本放行冒称全平台验证。改变真实 Node 输入会使依赖其身份的旧证据失效，该约束保持。

## Migration Plan

正常代码交付后生效，无用户状态迁移。必要时可回退本次代码；不切换本机默认 Node 或重装 DSH。
