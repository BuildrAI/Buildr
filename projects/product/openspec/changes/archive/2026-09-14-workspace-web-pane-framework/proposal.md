# 提案：Buildr Web 工作空间管理双栏组页签交互框架

## Why

工作空间管理当前使用「树形侧栏（项目及所属服务）+ 跳走式详情页」模型：在项目详情中查看服务会跳转到独立服务页，打断领域内探索；树形导航与内容区重复承载对象入口，层级认知负担重。经 2026-09-13 UX 审查与 2026-09-14 多轮原型迭代，用户已确认「双栏组页签」全局交互框架（原型证据：`outputs/ui-prototypes/workspace-management-2026-09-14/`，8 页浏览器验证通过）。现在将该框架落入 buildr-web 正式前端。

## What Changes

- 工作空间壳层改造：常驻左侧导航收敛为「项目 / 服务 / 技能 / 设置」四项平级同款入口，不再承载项目树；全域统一白底。
- 内容区采用双栏组页签模型：
  - 左组为页面级页签条：项目目录、项目全景、服务目录、服务全景均为可关闭页签，跨页持久于 localStorage，内容限宽居中（右组打开时自动收窄）；
  - 右组为对象级页签条：领域内点开的服务、文档、变更各自成签、页内对照，全部关闭时右组退场；
  - 两组之间为贯连 1px 分隔线（9px 拖拽热区，可调整两侧宽度），页签条高度处视觉连通；
  - 修改与 Agent 动作统一走抽屉层。
- 组件化统一：抽屉壳（eyebrow + 标题 + 副标题 + 关闭 + 底部状态与主按钮）、页签（色点区分对象类型）、按钮与下拉在相关页面间复用一致。
- 覆盖页面：项目目录、项目全景、服务目录、服务全景；技能页本次不改。
- 窄视口（≤1440px）右组降级为右侧浮动层。
- 既有路由（`/projects`、`/projects/:projectCode`、`/services`、服务详情与编辑路由）保持不变。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `buildr-web-client`：修改「Buildr Web 壳层必须采用上下结构」Requirement——工作空间区域导航由项目树改为四项平级入口，内容区引入双栏组页签模型与抽屉动作层；保留顶栏结构、既有路由、任务页行为与视觉 token 约束。

## 破坏性变更

无 API、路由或数据契约破坏；用户可见的界面组织方式改变（树形侧栏与跳走式详情被页签框架替代）。
