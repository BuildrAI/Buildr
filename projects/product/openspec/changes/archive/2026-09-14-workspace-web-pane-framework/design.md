# 设计：双栏组页签交互框架

## Context

buildr-web 为 React 18 + Vite + antd 5，页面按 feature 分目录（`src/features/{project,service,agent-assets,workspace}`），全局样式集中于 `src/styles.css`。当前工作空间壳层为「顶栏 + 224px 树形侧栏（项目及所属服务/服务/技能/设置）+ 内容区」，抽屉组件（AgentActionDrawer、MetadataEditDrawer、SkillActionDrawer 等）各自实现壳结构，宽度与头部形态不一致。交互框架、信息架构与关键视觉决策已在原型 `outputs/ui-prototypes/workspace-management-2026-09-14/` 中经多轮浏览器验证与用户确认，实现 MUST 以原型的布局与交互为准。

## Goals / Non-Goals

**Goals:**
- 落地双栏组页签框架：平级侧栏 + 左组页面级页签 + 右组对象级页签 + 贯连可拖分隔线 + 抽屉动作层。
- 抽屉壳、页签、按钮、下拉组件化统一，消除各页面一次性实现。
- 全域统一白底，视觉衔接连贯（页签条穿过分隔线视觉连通）。

**Non-Goals:**
- 不改动任务工作台区域、技能页内部结构、设置页信息架构（设置页仅随壳层继承侧栏与白底）。
- 不改变路由、API、数据模型；不引入新后端能力。
- 不做像素级还原之外的视觉重设计（沿用既有视觉 token 与 antd 5）。

## Decisions

### D1：双栏组页签，而非固定三栏或抽屉堆叠
左组常驻领域全景，右组承载点开的对象。固定三栏切碎空间且对象栏与内容重复导航（已在原型评审中被用户否决）；两层推挤抽屉回程复杂、语义错位（已否决）。

### D2：页签分两级，语义不混
- 页面级（左组条）：目录与全景，跨页持久于 localStorage（key 带 workspace 维度），可关闭；关闭当前页签切换到剩余页签或回目录兜底。页签项映射既有路由，点击即导航。
- 对象级（右组条）：服务/文档/变更，页内 React 状态，全关退场。对象内部视图切换（如服务的 README/AGENTS）使用对象内子 Tab，不占用页签条。

### D3：贯连可拖分隔线
1px 分隔线贯通内容区高度，9px 透明热区 `cursor: col-resize`，hover/drag 加粗变色；右组宽 `clamp(480px, 44vw, 960px)`，拖拽区间 420px～内容区 62%。分隔线在页签条高度处继承页签条底色，消除两组的视觉断层。≤1440px 时右组转为 fixed 浮动层、分隔线隐藏。

### D4：抽屉组件化
新增统一 `DrawerShell`（标识行 eyebrow + 标题 + 副标题 + 关闭 + 可滚动正文 + 底部「状态 + 主按钮」），基于 antd Drawer 封装；现有 AgentActionDrawer、MetadataEditDrawer 等迁移到该壳。页签条拆为可复用 `PageTabStrip`（左组、路由驱动）与 `ObjectTabStrip`（右组、页内状态驱动），页签以类型色点标识对象类型。

### D5：白底统一
壳层、侧栏、左右组内容区统一白底，分区仅由 1px 线条表达；页签条保留浅灰底以区分层级，hero 等卡片级渐变保留（卡片层而非区域底色）。

## Risks / Trade-offs

- 页面级页签持久化可能持有已删除项目/服务的陈旧路由：页签激活时目标不存在须回退目录并移除该页签。
- 树形侧栏移除后，服务归属项目的可见性下降：由项目全景的服务卡片与右组对象页签承担（用户已确认该取舍）。
- 右组对象页签为页内状态，刷新后丢失：可接受（阅读现场属暂态），页面级页签保留。
- 宽屏为主场设计（27 寸 2K），窄屏以浮动层降级保证可用，不为窄屏重排信息架构。
