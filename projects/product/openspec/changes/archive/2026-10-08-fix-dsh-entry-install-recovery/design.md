## Context

见提案与任务说明。开发安装查询中的启动器构建编号不同于运行产品来源身份，现有代码只核对开发渠道。主机端（Host）永久保留自动发现的连接。安装检查在上游 DSH 源码补丁内，现有配置档（Profile）锁、取消控制器和普通错误路径可继续复用。

## Goals / Non-Goals

目标是恢复正确身份与有界失败行为。沿用现有模块、公开查询、启动器与安装管理器，不引入第二个更新器、身份登记库、来源快照、自动卸载或桌面替换。

## Decisions

1. **健康与匹配分开。** Buildr 安装模块用现有来源身份生成机制比较当前来源和运行产品身份，公开匹配结果与原因。启动器编号、查询者 Node 不能替代来源证据；旧记录无法证明时报告未知。DSH 只消费结果。开发启动复用同样拒绝错误来源，由人或已授权智能体通过既有入口正常重启，不自动杀进程。
2. **失效恢复属于连接生命周期。** 在现有进程接入层统一管理显式/发现连接、共享打开及退出。只对 `installation-drift` 的自动连接清除缓存并重新发现一次；其他错误保持原边界。退出期间发现完成也不能启动后续查询。
3. **读取依赖现有取消。** 使用不会因特殊文件阻塞的打开方式并在文件描述符上复核类型和大小；有界读取接收现有操作信号及期限，所有资源由本次操作释放。只用超时竞速而留下阻塞读取不可接受。
4. **检查实际影响。** 无包名安装不能等同无目标。已有 Buildr 时，仅允许可证明版本不变的恢复；可能解析另一版本时沿用先卸载提示。冻结参数本身不是原样恢复证明，固定目标也须核对现装版本。别名先解析真实目标，再判断包族，不增加特殊名称保留政策。
5. **源码补丁是交付源。** 在独立源码副本内修改 DSH 安装器并运行原测试，重新生成相对现有基础补丁的增量和逐文件摘要，再从精确基线检查应用。安装器不会被打包进独立 Buildr 插件。

## Risks / Trade-offs

- 缺少来源字段的旧开发记录会被明确拒绝 → 保留健康状态并提供正常重启指引，不猜测或自动终止。
- 无包名恢复的过度限制会妨碍正常维修 → 回归覆盖固定版本不变、缺失包恢复、无关插件和确实换版本，限制仅作用于可能影响 Buildr 的动作。
- 特殊文件打开与取消存在平台差异 → 在本机真实文件系统及组件层证明，并明确未覆盖的原生平台；保持文件描述符与流的清理。
- 来源身份不包含未提交文件指纹 → 沿用既有提交身份边界，不扩大本轮版本模型。

## Migration Plan

代码候选先验证主体查询、独立插件和从原基线应用的安装器补丁。本轮不采用到日常 DSH、不发布；正式集成和运行环境激活在后续获授权的收尾中分别核对。当前知识只校准直接相关说明，历史采用记录保留。
