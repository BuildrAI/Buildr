## Context

`project-testing` 已负责 v4 地图的闭合结构、范围与版本校验，不执行测试。工作空间查询已有项目、服务及真实来源解析；任务验证消费地图声明，保存独立报告。动机见 `proposal.md`。本次扩展遵循现有职责，沿用当前地图版本和公开维护入口。

## Goals / Non-Goals

**Goals:** 使不同仓库和技术栈的服务能准确声明测试位置，智能体（Agent）能取得当前可用目录；对齐当前指导和 Buildr 自身采用事实。

**Non-Goals:** 不增加测试调度器、发现扫描器、任务执行状态、代码库登记副本或新报告模型。不检查通配符覆盖率，也不把命令成功等同于证明范围完整。

## Decisions

1. 每个测试族（Testing Family）可写 `location: {kind: project}` 或 `location: {kind: service, service: <code>}`。省略保持项目根语义且不强制补写；`scope.services` 只表达证明范围。选择显式字段而非按一个／多个服务数量猜根，避免现有跨服务聚合入口改变含义。
2. 服务绑定必须引用已登记且包含在该族 `scope.services` 中的服务代码（Service Code）。同一族只有一个路径根，`sourcePaths/testRoots/full.cwd` 都相对该根；多根采用独立测试族或已经存在的项目聚合入口。绝对路径、父目录穿越和反斜杠穿越不进入地图。
3. 地图 `inspect/validate/update` 返回当前 `locations`，条目为 `testing/kind/service?/root/cwd/status/diagnostics`；`root/cwd` 为本机解析结果，只读返回，不写入 YAML。继续复用工作空间查询返回的来源及已有根解析，不按目录布局猜测，也不新增独立代码库解析权威。
4. 结构合法性与当前可执行位置分开：登记根或命令工作目录不存在、不是目录或真实工作目录越出绑定根时，该族标记 `unavailable` 并给出原因，其余族继续可读。有效地图仍可维护；任务报告仍能保存真实检查。`kind: agent` 保留根且 `cwd: null`，具体执行由指引决定。位置为当次观察，执行前重读，不授予副作用授权。
5. 完整入口覆盖声明范围由智能体（Agent）依据实际工具判断。Buildr 自身将原合并的功能族分成 `buildr-functional` 与 `buildr-system`，分别消费既有脚本；前端逻辑测试独立声明为 `buildr-web-unit`，完整入口使用 `services/buildr-web` 已有 `npm test`。原 `buildr-web` 的浏览器入口不执行 `services/buildr-web/test`，因此从该族测试根中移除它。连同 `buildr-fast` 与 `buildr-environment-smoke` 共六族。归属规则直接关联真实模块路径并通过计划选择回归证明；不为统一名称新增聚合执行器。
6. 修复与本目标直接相关的 v3、旧统一执行命令和环境规划承诺；保留安装包、浏览器和真实工具链的证明边界。`project-testing-guidance` 按当前源技能校准：先补齐授权内缺失测试或选择映射，再按当前内容核对证据，复用有效检查、补充必要检查后记录报告；定向成功不能冒充全部边界通过，不新增阶段门禁。规范增量同步到当前规范但保留变更，不归档或发布。
7. 通用框架继续用六节点流程图（Workflow）表达使用主线和按需补建，说明 `project-testing`、`declaration-intake` 与 `task-verification` 的用途。产品采用文章以“测试对象—真实入口—证明范围”表说明六族和后端回归、候选入口的关系，并给出真实用例；代码地图（Code Map）承担实现定位，二者不混成测试目录清单。后端候选入口通过不能推导独立前端逻辑或浏览器检查通过。

## Risks / Trade-offs

- 老版本拒绝新字段 → 使用服务绑定前升级到支持版本；无新字段的既有 v4 声明继续兼容，无自动迁移。
- 本机根在观察后变化 → 指引要求执行前核对登记和当前根；不持久化绝对位置、不伪造环境就绪保证。
- 不可用服务扩大为全局阻塞 → 每族独立诊断，不把位置问题混成结构无效，不阻止其他服务检查或真实报告保存。
- 旧文清理扩大范围 → 只维护当前相关规范与消费者，历史与归档保留；已有知识文章解释最终能力，不再增加问题清单文章。

## Migration Plan

先完成字段和位置解析回归，再对齐技能（Skill）、模板、产品声明及选择映射。通过生成物、相关集成、完整低成本回归和知识阅读检查后，同步当前规范并更新开发预览。撤销新字段即可让地图回到旧消费者可读取的形态；不改既有用户地图和数据库。
