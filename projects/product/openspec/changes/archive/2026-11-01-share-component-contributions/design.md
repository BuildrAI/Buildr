## Context

参见 proposal.md。当前共享目录只收录技能及能力契约；组件补充原文直接从工作空间读取，生命周期会复制这些文件。组件已安装定义记录逻辑成员及完整性，适合保留为采用回执。

## Goals / Non-Goals

实现官方补充内容的显式来源引用及兼容迁移，不修改上游 OpenSpec 原文、不共享空间私有内容、不把组件安装回执或命令配置改为全局状态。

## Decisions

1. 在组件定义增加可选 `memberResources` 映射，仅支持 `source: buildr` 的已声明补充成员，并严格限定为同一逻辑成员的 `resources/workspace/…`。保留逻辑成员和完整性，不采用按缺失路径猜测来源的方式。
2. 共享收录仅扩展 `workspace/components/buildr/<id>/contributions/`；组件定义、命令配置、初始化材料和图标仍由原消费者管理。自有组件（包括自举贡献）不共享。
3. 各读取入口共用共享成员来源解析。已声明共享引用时发现本地副本视为冲突；旧无引用定义继续本地读取。安装规划同时校验共享内容，失败发生在删除前。
4. 正常同步通过已有集合预检、锁内现场签名和事务更新引用；安全旧副本只删除精确成员，目录仅在为空时删除，未知文件保留。已安装摘要跟随实际采用的共享原文，不因另一安装的包内原文不同而误报。

## Risks / Trade-offs

- 旧程序不理解新字段 → 迁移后使用当前开发版，不以旧程序管理；不增加另一套投射格式。
- 共享发布先于各空间采用 → 旧本地成员继续可读，已采用共享的空间按正常准备刷新回执；失败逐空间保留并可重试。
- 定制和并发变化 → 旧回执与当前摘要比较，锁内重验，事务保护；不强制删除目录和未知文件。

## Migration Plan

隔离环境验证新安装、旧副本迁移、重复同步、定制与链接保护、共享损坏、自有组件和卸载隔离。实现交付后由唯一自举执行器发布并迁移 Buildr，开发版按既有后台准备机制刷新 Jixian 和 Things；分别核实真实引用、文件清理及诊断结果。若激活需额外 Git 交付授权，保留已验证候选，明确报告该边界，不从候选直接改写共享资源。
