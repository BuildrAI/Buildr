## Context

[任务说明](@task/streamline-service-agent-rules)提出按实际操作风险精简服务规则。现有布局校验会拒绝缺少主程序规则文件的检出。

## Goals / Non-Goals

- 取消主程序规则的存在性要求，但不放宽源码归属、测试隔离或兼容入口要求。
- 不合并服务规则，不改变技能、用户规则、程序或发布行为。

## Decisions

1. 主程序已有产品总规则和规范说明职责、隔离验证与发布。规则文件可选，不新增替代文件。更新现有布局检查及其测试，不新增门禁。
2. Buildr Web 和 Harness 保留短规则，聚焦会话、验收、授权、账号资料和操作范围；开发目录索引、普通写法与历史说明不在本地规则重复。DSH 和 Harness Web 维持现状。

## Risks / Trade-offs

- 不能只删文件：规范和布局检查必须一起放宽，其他布局错误仍应报告。
- 缩短提示不能缩减保护或授权条件。对照原文逐项核对，保留必须遵守的边界，不拆改运行时行为。
