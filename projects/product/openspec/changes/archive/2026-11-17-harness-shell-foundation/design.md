## Context

独立入口由 `buildr-harness-web/src/HarnessApp.tsx` 装配完整对话及目录操作；`Workspace` 同时输出 `harness-shell` 容器。`styles.css` 维护该容器，`index.ts` 是前端组合出口。Development 目前经同源 iframe 消费完整网页，规范明确禁止它重组对话组件。

## Goals / Non-Goals

**Goals:** 建立可被真实独立入口消费的外壳边界，并以受控工作环境验证装配和生命周期。

**Non-Goals:** 不实现 Development 适配器、不改变现有界面默认值；不提前设计上下文、导航注册、通用链接路由或多个环境的生命周期。

## Decisions

1. **最小同页组合。** 新增 `src/shell/HarnessShell.tsx`，公开外壳和邻近定义的工作环境类型。环境只提供稳定身份、名称及 React 组件；不提供全局注册器或执行控制接口。`HarnessApp` 接受可选环境，默认入口不传。外壳不导入任何 Development 业务。
2. **保持子树位置。** 对话始终在外壳固定位置。环境首次打开后才渲染，收起使用隐藏而非卸载；切换开合不更换对话 key。按需加载不等于代码动态下载，同页环境仍是第一方可信代码。
3. **局部渲染隔离。** 环境组件置于自身错误边界，失败提示不显示原始异常。该边界不承诺隔离死循环、共享进程崩溃或外部副作用；不用第二个 iframe 伪装完整隔离。
4. **保留旧集成。** 本步不改 `buildr-web`。现有 iframe 继续消费未装配环境的 Harness 页面。下一步才决定如何把工程区域装入新外壳，不在本步复制工程页面。
5. **验证真实边界。** 浏览器组件夹具直接导入正式外壳；验证空装配、首次挂载、反复开合、对话 DOM/输入/滚动/控制保留、渲染失败和窄屏可访问。既有独立生产场景覆盖正式入口、认证及执行回归，夹具不冒充真实 Development 接入。

## Risks / Trade-offs

- 隐藏区域仍保有资源 → 仅首次打开时挂载，本步仅承诺状态保留；工程实际接入时再按其资源性质处理暂停。
- 工作环境与对话共用页面 → 错误边界只承接渲染错误，不声称插件权限或安全隔离。
- 新 API 尚未由真实 Development 消费 → 保持三个必要输入，不凭想象扩展协议；浏览器夹具证明装配，不宣称工程迁移完成。
- 当前知识说明未包含外壳入口 → `assess` 确认双产品架构说明和代码地图可补局部定位；现有嵌入链路与技术图仍适用。未获额外知识维护授权时只报告建议，不阻止实现。

## Migration Plan

先加入外壳，再让 `HarnessApp` 委托容器；保留对话、目录、设置及嵌入消息处理。构建产物不在源码中提交；未经集成及自举激活不安装到当前开发应用。回退只需撤回本任务前端差异，无账号或历史迁移。
