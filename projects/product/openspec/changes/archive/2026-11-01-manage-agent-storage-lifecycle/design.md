## Context

见 proposal.md。现有模型网关身份包含对话，连接应用按身份创建独立 HOME、原生配置和临时目录。隔离承载恢复语义，不能为节省空间改成共用原生会话。现有后台回收只处理带 confirmed 退出回执的实例，遗漏异常退出和物化后未启动的目录。

## Goals / Non-Goals

目标是让统一智能体服务（Agent Service）承担受管磁盘资源的事实观察与具体删除安全，并以公开包维护能力提供可组合的预览/执行；不把垃圾判定交给某个厂商，也不引入第二份会话或账号权威。不改对话身份、不清空原生配置、不对独立后台命令推断成功。

## Decisions

| 责任 | 位置 | 行为 |
| --- | --- | --- |
| 数据类别与原生控制证明 | 执行器适配器 | 声明可重建临时目录；报告原生控制组已退出 |
| 跨对话缓存及关闭后回收 | 连接应用的存储协作者 | 为同一接入分配 npm 缓存，保持 HOME/原生配置隔离 |
| 文件与系统占用观察 | 共享存储基础能力 | 只读计划、文件元数据身份、进程打开路径、符号链接保护和条件执行 |
| 后台运行时生命周期 | 独立进程模块 | 当前/待采用/存活引用保护、旧版本保留、物化和回收互斥 |

下载缓存按执行器接入分配，不跨账号配置共享；通过 npm 支持的缓存环境变量指定下载缓存，不改用户默认 npm 配置。对可核对来源和版本的干净插件市场检出保留单份种子，物化时采用强制写时复制，不使用硬链接或共享可变工作树。复制不支持或失败时保留原生缓存；关闭后可回收私有副本而不会让每轮从网络重新下载。Codex 只声明插件 staging 与旧 npm 下载缓存，不声明会话和状态库；Qoder/DSH 复用相同机制，不套用 Codex 私有路径。

采用文件与进程即时观察，不增加资源状态数据库。周期维护复用同一预览/条件执行能力，对账崩溃、失败启动或延迟释放后遗留的缓存和运行时；逐项锁定删除，不在全量扫描和整批清理期间独占存储。维护默认只读，执行绑定已观察计划；逐项重新检查内容身份、目录归属和进程占用。系统占用观察不完整时保留，失败不影响对话继续工作。

正常确认退出的旧后台继续及时回收；针对退出确认缺失或无回执的遗留对账，运行时保留当前、待采用、存活实例、实际被进程打开的目录，另保留最近一份完整回退版本；未使用满一天不进入这一路遗留回收。可重建目录的物化和删除共用窄存储锁，已有版本复用时刷新使用时间；旧内容摘要不变。新回收检查完整受管清单、目录真实位置和内容摘要，用户增改文件或符号链接不作为垃圾。

不采用共用 CODEX_HOME、删除全部 model-bindings、按 PID 不存在直接删除、仅按回执 confirmed 回收或把所有 Agent 缓存规则写进宿主的方案；前几者破坏隔离或在途环境，后两者无法闭环或违反统一服务职责。

## Risks / Trade-offs

- 系统文件占用观察具有平台及权限限制 → 观察未知时只保留，诊断显式可见。
- 文件系统与原生工具存在并发 → 自有物化/回收互斥，删除前重查路径和版本；活跃或近期目录保留。
- APFS 克隆共享使目录大小不等于独占块 → 报告逻辑移除的分配大小与实际可用空间变化，不承诺相等。
- 插件临时数据重新打开时可能重新获取 → 关闭后回收磁盘收益优先于无限保留；账号/会话不受影响。

## Migration Plan

不迁移原生身份或历史。新打开的执行器使用服务缓存，旧路径只作为维护候选。完成隔离集成验证后对 Buildr Dev 生成计划，清理已证明无引用的缓存与完整旧运行时，保留清单；程序采用与源码验证分别报告。旧版本回退不要求还原缓存，必要内容由工具重建。
