# 设计：共享资源目录自愈

## 现状与缺陷

共享集发布是「整目录构建 + 两次改名」：`.resources-next` 完整写入并校验 `resource-set.json` 后，旧目录改名到 `.resources-previous`，暂存目录改名到稳定路径。清单与目录同时出现，正常路径不会产生「有目录、无清单」。

问题出在消费与恢复的判定：

- `ensurePackageResources()` 只在 `resources` 目录不存在时发布；目录一旦存在而清单缺失，直接抛出 `readDescriptor` 的 ENOENT。
- `publishPackageResources()` 为退役来源保全读取旧清单，读取失败且存在 `skills/` 时抛出同一错误，阻止显式更新接管。
- 工作空间准备直接调用 `readSharedResourceSet()`，没有把失败映射为可执行提示。

结果是 `D:\BuildrData\resources` 这类现场（迁移或还原留下的半份目录）让准备永久失败，界面只显示裸 ENOENT。

## 判定：三种现场分开处理

| 现场 | 判定 | 处理 |
| --- | --- | --- |
| 清单可读且身份成立 | 已有共享集 | 只消费，不写入 |
| 清单缺失/损坏/不是普通文件，顶层只有自有条目 | 未识别目录 | 锁内按当前安装重建 |
| 清单缺失，顶层含其他条目 | 未知归属内容 | 保留现场，报告路径与条目 |
| 清单可读但文件缺失或损坏 | 有身份的损坏集 | 维持既有整目录替换（显式发布） |

「自有条目」为 `skills`、`contracts`、`components`、`commands`、`resource-set.json`，以及名字形如版本号的旧版共享目录（如 `1.0.0-abc123`）；封存区位于数据根 `local/preserved-skills/`，不在共享目录内，因此 `local/` 若出现在共享目录内按未知内容保留。除此之外的内容不能证明属于 Buildr，删除会丢失用户数据，因此只报告。该限制同时避免了「数据目录被错误配置到用户目录」时的误删。

## 恢复流程

普通准备与显式更新共用同一段锁内发布逻辑：

1. 目录不存在：按当前安装发布（既有行为，保留 `.resources-previous` 崩溃恢复）。
2. 目录存在且清单不可读：获取 `.resources.lock` 后重读清单。
   - 已被其他进程恢复：直接返回该共享集，不重复替换。
   - 仍不可读：检查顶层条目；含未知条目则抛出带路径的可识别错误，否则按当前安装替换并校验。
3. 退役来源保全只在旧清单可读时执行。旧清单不可读时无法证明来源属于待退役目录，跳过保全并替换当前集；封存区仍保留在数据根 `local/preserved-skills/`，不受替换影响。
4. 版本比较与已观察身份校验只在旧清单可读时生效；无清单时无法比较先后，按当前安装重建，不猜测顺序。

错误对象使用 `code: shared_resources_foreign_content` 与 `target` 字段，文案包含真实路径、未知条目和「移走该目录后重试」。

## Windows 瞬时占用

Windows 上目录改名与 `rm -rf` 会被杀毒、索引或正在读取资源的进程短暂占用，返回 `EPERM`、`EBUSY` 或 `ENOTEMPTY`。设计在切换与清理上做有界重试：最多 6 次，间隔 25ms 起的同步等待（`Atomics.wait`），总计不超过 1s；只对上述可重试错误重试，其他错误立即失败。重试耗尽后走既有回滚：把新目录移回暂存、把旧目录移回稳定路径，保留 `.resources-next` / `.resources-previous` 供下次显式恢复。清理临时备份失败不使已发布的共享集不可用：记录诊断，保留备份目录。

## 界面与诊断

工作空间准备把共享集不可用映射为 `workspace_resources_unavailable`：消息给出真实路径与「重试或移走目录」的可执行提示，原始错误进入准备记录的 `details`，不再作为 Alert 主文案。共享集恢复成功时不额外提示，按正常准备继续。

## 备选方案

- **逐文件修补缺失清单**：无法证明剩余文件属于当前集，重建更简单且不会形成混合版本。
- **删除任何无清单目录**：会丢失用户或外部工具的内容，拒绝。
- **仅在显式更新时恢复**：Windows 用户没有可触发的更新入口，问题仍无法自解；普通准备恢复是本变更的核心。
- **把重试放进通用文件工具**：影响面过大，先在共享集切换这一最易受占用的路径验证。

## 风险

- 无清单目录若属于更高版本的另一次发布，重建会降级内容；无身份时无法判断，且当前状态已不可用，按「未准备」重建是唯一可行恢复。数据根封存区 `local/preserved-skills/` 不随替换删除，减少能力损失。
- 重试引入同步等待，最坏增加约 1s；只发生在失败路径。
- 顶层条目白名单需要随共享集结构演进维护；新增自有目录时同步更新判定与测试。
