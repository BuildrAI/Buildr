## Context

动机与范围见 [proposal.md](proposal.md)。当前静态登记同时承担品牌身份、文件约定、技能（Skill）筛选、回执身份和诊断归因。Codex、Cursor、TRAE 已共用 `.agents/skills/`，而旧回执分别按品牌保存。未知品牌在多个入口被拒绝。现有 `.buildr/workspace.yml.runtime` 是历史 Node 配置，不是当前智能体（Agent）身份，不能复用或猜测。

## Goals / Non-Goals

**Goals:** 建立单一选择规则；默认提供标准文件能力；保留品牌事实和专用例外；共享文件只维护一个所有权；所有路径继续执行同一预检、冲突与回滚保证。

**Non-Goals:** 不认证所有未知品牌的发现/激活，不实现 DSH 插件，不添加智能体（Agent）调度、不自动改用户层投射、不发布或激活保留自举环境。品牌行为说明不是新的写入门禁。

## Decisions

### 1. 选择与执行分开

`getRuntimeAdapter(adapterId)` 保持严格，未知显式适配器（Adapter）报错。新增统一选择函数接收可空 `runtimeId` 和可选显式 `adapterId`，返回两种身份、选择原因和实际静态描述。`codex`、`dsh` 及无专用例外的有效标识选择 `agents-standard`；已有专用产品保留原实现。未指定时先使用明确选择/唯一现场受管方式，无既有方式时默认标准；多个不等价方式时写入要求明确选择，只读诊断仍可列出现有方式。

不采用“让 getRuntimeAdapter 任意未知输入回退”的方案，因为那会掩盖拼写错误和实现错误。原 `<agent>` 参数表达品牌，新增 `--adapter` 只选择文件约定。`init --source-only` 保留纯源资产入口；默认 init 采用统一接入。选择必须在任何写入之前完成。

### 2. 标准描述与品牌事实分开

标准文件描述使用原生规则（Rule）、`.agents/skills/` 和宿主相关的激活（Activation）说明。品牌附加事实只承载已核实的刷新、可选资源验证或探测；未知品牌安装和加载保持未确认。计划和诊断带 `runtimeId` 与 `adapterId`，投射身份不依赖品牌别名。不能从已有目录推断当前宿主身份。运行时发现与诊断的公开 JSON 分别升级为 `buildr.runtime-list/v2`、`buildr.doctor/v2`，因为有限品牌清单改为文件实现清单、`runtime.codex` 改为 `runtime.agentsStandard` 并非单纯增加字段。消费者按新版本迁移，不在 v1 身份下静默改义。

### 3. 通用适用性与一级输出

随包通用技能（Skill）省略 `runtimes`；读取产品声明时缺失表示通用，维护已有产品条目时移除过时的产品拥有白名单。用户明确列表仍按请求 `runtimeId` 判断，未知身份不获得任何品牌专有限制许可。标准共享根的目标路径统一为 `skill.id`，源路径和随附文件不变；能力绑定使用同一目标路径解析。其他厂商根保留既有布局。

### 4. 共享归属、迁移和清理

所有使用 `.agents/skills/` 的实现统一技能（Skill）归属 `agents-standard`，Cursor/TRAE 规则（Rule）仍由各自实现负责。回执放在既有 Buildr destination 控制目录，不进消费目录。读取候选时可识别旧 codex/cursor/trae canonical 回执及已有 runtime-root 旧回执；只有身份、完整清单、内容、权限一致时才在本次受管事务中迁移，之后不长期双写。

扁平化需要保留原 `runtimePath` 定位旧目录；同名不等于同一资产。迁移应检查所有旧回执、旧文件及新目标，未知额外文件和漂移阻止自动移动，不凭生成标记接管。写入、移除和回执更新一并计划，预检失败整组零写入，执行失败复用已有回滚。

共享根的孤儿判断使用所有仍启用的源声明，不以本次品牌可见子集删除他方仍有效投射。不同品牌显式限制可能让共享消费者能力绑定不同；须基于同一当前源状态比较共享根适用运行时的候选内容，发现差异就报告冲突，不能只比较上次 sourceDigest/renderDigest 推断冲突，以免阻止合法的绑定更新。

### 5. 复用确定性执行与测试入口

所有入口在选择后仍进入现有装配、预检和收敛实现。文件归属迁移不新增另一套执行器；公开查询继续通过既有契约生成输出，新增字段与旧兼容字段的语义明确。测试复用隔离临时工作空间（Workspace）和已有测试工具，不把主工作空间（Workspace）当试验对象。

## Risks / Trade-offs

- 默认初始化会多生成标准投射 → 明确破坏性变化与 `--source-only`，更新直接调用方和测试，不隐藏写入。
- 同根多个品牌旧回执不一致 → 拒绝自动决定，保留证据和全部文件。
- 标准路径不能覆盖任意宿主发现方式 → 只承诺标准文件准备；专用例外继续存在，品牌证据单独说明。
- 共享文件与运行时专属绑定无法同时满足 → 明确内容冲突，不放宽用户限制、不静默覆盖。
- 旧版本不能识别新归属 → 文档说明迁移后不能交替用旧版本管理；回退需恢复整个操作前文件与回执备份，而非删除新回执。

## Migration Plan

先发布具备新旧读取与严格预检的实现；用户下次明确维护目标时迁移对应 destination。保留现有接入方式和用户/工作空间（Workspace）边界。新旧回执等价则只迁移证据，不重写未变文件；多层目录只移动能证明归属的成员。默认选择和迁移不触发用户层写入。没有归属证明时不迁移，继续允许不依赖该投射的只读工作。
