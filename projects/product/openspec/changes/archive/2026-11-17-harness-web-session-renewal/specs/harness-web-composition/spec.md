## MODIFIED Requirements

### Requirement: 启动登录必须绑定准确网页入口而不泄露服务秘密

本机入口 MUST 从受保护的实例发现及就绪观察取得准确地址，不能只根据端口或 PID 信任页面。登录引导 MUST 使用短时单次、绑定产品/数据域/目标端点的票据或等价认证能力，不能向浏览器交出后台主令牌、模型凭据或宿主秘密。独立与 Development 页面会话 MUST 分离；鉴于回环地址不同端口的 Cookie 不隔离，独立入口 MUST 对会话命名和范围隔离并核验 Host/Origin，不能仅依赖 SameSite。有效会话在兼容换代后继续校验当前有效期和撤销状态。页面会话 MUST 使用有限的不活动窗口（30 天）并按认证活动滑动续期；续期 MUST NOT 使票据可重复使用，MUST NOT 恢复已撤销或已换绑撤销的会话。会话有效时加载页面文档 MUST 同步刷新浏览器 Cookie 寿命，Cookie MUST NOT 先于服务端会话失效。

#### Scenario: 登录引导与重复打开
- **WHEN** 启动入口确认准确服务和网页已就绪并打开浏览器
- **THEN** 票据 MUST 只兑换一次有限页面会话；重复点击复用现有入口，不创建后台或重复工作
- **AND** 过期、被重复消费或目标不符的票据必须拒绝，日志、URL query 和转发头不得含长期秘密

#### Scenario: 同机另一 origin 冒用页面状态
- **WHEN** 另一端口页面携带同机 Cookie 或伪造 Host/Origin 访问独立 Harness
- **THEN** 系统 MUST 拒绝越权访问，不因同属回环或 Cookie 名相同获得管理能力

#### Scenario: 长期使用后刷新恢复
- **WHEN** 同一浏览器在票据兑换后超过原固定寿命、但仍在不活动窗口内刷新页面（含兼容重启或更新之后）
- **THEN** 会话 MUST 仍有效并恢复页面，Cookie 寿命 MUST 同步刷新
- **AND** 超过不活动窗口、已显式登出或已换绑撤销的会话 MUST 拒绝，需重新从启动器引导登录
