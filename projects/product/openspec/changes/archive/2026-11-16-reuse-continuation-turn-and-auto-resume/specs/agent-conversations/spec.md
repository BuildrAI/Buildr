## MODIFIED Requirements

### Requirement: 纯接续执行轮必须准确呈现原始用户输入

对于由“继续上次执行”、系统自动恢复或既有失败轮恢复产生，且没有本执行轮直接用户消息的执行，系统 MUST 沿持久接续关系解析到最初实际用户输入身份；MUST NOT 按相邻条目、最近一条用户消息、文本相似度或当前分页顺序猜测。

当该持久来源指向的原用户输入回合（或同交互首个接续回合）已存在于当前可见信息流中时，界面 MUST 直接复用该既有对话回合，将接续通知、原生会话交接诊断、处理过程及最终答复合并呈现在同一回合内，MUST NOT 为同一次交互重复生成新的用户气泡或“继续上次要求”回合头部；前序已中断或失败执行的中间叙述 MUST 归入可折叠处理过程，仅由当前最新接续执行的结果作为正式最终答复，且该回合在最新接续执行运行期间仍 MUST 保持吸顶头部与当前执行身份、计时。

当原用户输入早于当前可见分页窗口且当前页尚无该交互的既有回合时，系统 MUST 在公开会话视图中提供该轮承接的原始用户输入快照并在首个可见接续轮的固定头部显示它，标明“继续上次要求”；同页后续指向同一原用户输入身份的再次接续 MUST 复用该接续回合。为保障历史已完成接续轮在后续新对话轮次到达后仍能准确合并，公开接续通知条目 MAY 携带只读的轻量来源引用（`runId` 与 `userEntryId`），不改变历史顺序、消息数量或分页游标；无法验证来源时 MUST 不合并或猜测归属。

#### Scenario: 手动继续上次执行

- **WHEN** 用户对已结束或待确认的原执行选择继续，新执行轮只有接续通知而没有新的用户消息
- **THEN** 若原执行对应的用户输入回合仍在当前可见流中，界面 MUST 直接复用该既有回合展示接续过程与结果，不重复生成用户气泡或“继续上次要求”头部
- **AND** 若原输入早于当前分页窗口，当前页首个接续轮固定头部 MUST 显示来源只读快照并标注“继续上次要求”
- **AND** 原有历史轮次、执行身份和消息顺序 MUST 保持不变

#### Scenario: 连续接续与系统恢复

- **WHEN** 接续轮再次被继续，或系统在中断后自动恢复原目标
- **THEN** 系统 MUST 沿接续链找到最初实际用户输入身份并复用同页内已有的原回合或首个接续回合
- **AND** 被后续接续取代的前序中断轮叙述 MUST 收纳在处理过程中，不产生多个重复的“继续上次要求”气泡
- **AND** MUST NOT 把接续通知、最近一条助手消息或其他执行的输入误作原要求

#### Scenario: 原输入不在当前分页

- **WHEN** 原用户输入早于当前首屏分页窗口，且同一原执行包含多条用户输入
- **THEN** 系统 MUST 使用已保存的准确来源或只读快照在当前页首个接续轮的固定头部显示该轮首个用户输入并标注“继续上次要求”
- **AND** 同页后续再次接续 MUST 复用该接续回合，MUST NOT 为显示固定头部而重复插入历史记录或破坏续读游标

#### Scenario: 直接输入或来源不可验证

- **WHEN** 执行轮包含本轮直接用户消息，或接续来源缺失、损坏或无法唯一匹配
- **THEN** 系统 MUST 优先使用或显示本轮直接输入；来源不可验证时 MUST NOT 绑定或并入其他用户输入回合
- **AND** 当前执行、历史记录和重试边界 MUST 保持原事实

### Requirement: 系统中断必须自动核对并接续原目标

Buildr 开发版与正式版 MUST 默认自动恢复已受理、非用户主动停止的系统中断，不以用户再发消息或页面打开为前提。服务退休（`releaseRetiredWork`）或空闲源释放（`releaseIdleSources`）因系统切换或重启中断已受理且非用户停止的在途执行时，系统 MUST 保留可信系统中断标记；并行换代期间，新代次服务 MUST 在观察到旧代次进程退出并释放控制资源后自动触发中断恢复核对。恢复 MUST 沿用原智能体（Agent）、账号身份、模型（Model）、档位、工作位置及权限。原执行仍在运行时 MUST 只恢复观察，已确认正常完成时 MUST 不追加重复工作。当原控制资源已核验释放、旧代次已退出且无活动工具、待决定及用户停止请求时，历史结果未知 MUST NOT 单独阻止自动接续原目标；恢复 MUST 保留未知结果，要求先查当前成果、原工具及未决副作用，MUST NOT 重放原提示或未知操作、推定独立命令退出、扩展权限或替用户决定。没有准确原身份、旧代次仍存活或资源释放未确认时 MUST 继续保护相关工作。

#### Scenario: 开发版重启后继续

- **WHEN** 系统中断、服务退休或并行换代旧代次退出导致原轮停止或准确控制资源已经释放，原组合仍有效且没有待决定
- **THEN** 系统 MUST 自动触发中断恢复并组织已有成果和原目标交给原组合执行，不要求人点击“继续原任务”或发送“继续”/“如何了”
- **AND** 结果未知仍保留未知，智能体 MUST 先核对事实再继续，不逐条重放旧工具

#### Scenario: 无法安全恢复

- **WHEN** 原执行仍运行、旧代次仍存活、控制释放未确认、原账号身份失配、额度或认证不可用，或存在待决定
- **THEN** 系统 MUST 只推进可安全观察的部分并保留准确原因，MUST NOT 重复执行、换组合或代答
- **AND** 用户主动停止 MUST 取消对应自动接续

### Requirement: 已释放的待确认对话必须提供继续与关闭出口

当对话未能自动恢复（例如自动恢复策略未启用、恢复预算耗尽、连接曾失配待确认或用户取消自动续行），且不存在明确活动工作、有效待回答问题或已提交待发送要求、原生控制资源均已确认释放时，系统 MUST 提供单一“继续原任务”出口。提示 MUST 以可见文案说明中断来源、结果未确认以及记录与已完成操作保留，提示本身 MUST NOT 再提供关闭、隐藏、重新读取或停止动作；关闭（隐藏）MUST 继续可从对话菜单完成，并沿用保留对话历史、未知执行与工具事实及关联 Task 状态的约束。继续 MUST 先核对原轮及成果，再接续未完成目标，不重放历史要求。读取仍未知时 MUST 明确说明没有取得新结束证据及可用动作，MUST NOT 把读取成功冒充工作完成。

#### Scenario: 服务重启中断后的单一继续出口

- **WHEN** 当前轮因服务退休中断、原生控制资源已释放、结果未知且没有待决定，且未触发或已耗尽自动恢复
- **THEN** 提示 MUST 显示可见的中断原因与“继续原任务”一个动作
- **AND** MUST NOT 显示关闭、隐藏、重新读取或停止动作
- **AND** 原记录、未知工具结果和已完成事实 MUST 保留

#### Scenario: 关闭遗留待确认对话

- **WHEN** 用户从对话菜单关闭原生控制资源均已释放、没有明确活动工作和有效待回答问题的待确认对话
- **THEN** 对话 MUST 从活动提醒撤下并保留在可恢复的历史中，原执行和未知工具结果 MUST 不变，关联 Task MUST 不被完成

#### Scenario: 另一原轮仍在工作

- **WHEN** 最新轮已释放但保留轮次尚未释放，或仍有明确活动工具、有效待回答问题或已提交的待发送要求
- **THEN** 关闭入口 MUST 不可用，隐藏 MUST 不掩盖相应活动，不发送替代停止命令

#### Scenario: 再次继续工作

- **WHEN** 用户选择继续已释放但结果待确认的原目标
- **THEN** 系统 MUST 先重新读取；取得正常结束和最终答复证据时 MUST 告知用户可直接提出新要求，否则按原执行身份核对已生效成果后接续，不自动重复旧操作

#### Scenario: 仍有活动工作的未知轮

- **WHEN** 当前轮结果未知但原生控制资源尚未确认释放
- **THEN** 提示 MUST 继续提供停止与重新读取，MUST NOT 把真实在途工作表达为可结束的历史
