## Context

现有源文件明确允许直接工作，OpenSpec 的规划和实施本地补充也保留这条路径。底层 `buildr.git-worktree-provider/v1` 已提供创建、检查和清理能力，创建检查不要求主目录干净。

## Goals / Non-Goals

目标是统一首次持久文件写入前的位置选择，并让已有任务位置可持续复用。只读检查、任务记录、依赖准备和资源管理保持各自职责；不增加全局许可、环境状态或自动合并，不改上游 OpenSpec 技能（Skill）。

## Decisions

1. 在任务分流技能（task-triage）集中定义默认隔离策略，描述明确命中持久文件修改；工作树技能（task-worktree）接受此交接，不再声明普通任务可以直接修改当前目录。
2. OpenSpec 创建、实施和规划修订入口引用同一位置策略，保留用户已明确的主开发分支例外。只改其中一个入口会留下绕行路径。
3. 继续使用现有能力契约（Capability Contract）与可选绑定；实际依赖隔离时局部停止，不能自动回退主目录。纯只读与任务记录不依赖该能力。
4. 对已有同任务位置先检查并复用，不搬走他人未提交文件，不自动初始化缺失仓库。主目录未提交内容不进入新工作树（Worktree），真实依赖需独立处理。
5. 更新既有路由检查、源资产静态检查与相关解释，复核代码地图（Code Map）和技术图（Technical Diagram）无结构变化；不创建重复规则或新增确定性路由程序。

## Risks / Trade-offs

- 新任务增加独立目录及按需依赖准备成本 → 同任务复用，检查范围与影响匹配。
- 文本指引无法物理拦截所有文件写入 → 检查发布和投射入口一致性，如实区分文本保证与运行时强制。
- 旧会话仍加载旧技能（Skill） → 交付后通过现有同步机制激活，不编辑派生副本。
- 并发任务仍可能修改相同语义 → 交付时继续检查合并冲突，隔离不保证自动合并安全。
