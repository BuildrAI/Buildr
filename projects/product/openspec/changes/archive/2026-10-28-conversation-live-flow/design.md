## Context

动机和用户决定见 [proposal.md](proposal.md) 与 [任务说明](@task/conversation-live-flow)。现状是普通发送依赖空闲和完整预览，对话修订随每条事件变化；原型阶段已形成平铺展示，当前正式入口沿同一组件实现。三家原生入口已核对：Codex 当前协议提供 `turn/steer`、`expectedTurnId` 和 `clientUserMessageId`；Qoder 1.0.55 支持带 UUID 的动态输入与 `priority: next`、`shouldQuery: false`；DSH 提供按 `requestId` 保存来源的 `mode: steer` 和同一原生事件订阅。

## Goals / Non-Goals

**Goals:** 在准确当前执行中可靠补充图文，保留独立尝试、接收与历史身份，落实已确认的固定上下文和简洁执行展示。

**Non-Goals:** 不改变原生压缩、账号来源、权限决定、停止证明或成果权威；不接管桌面会话（Session），不因追加再做交接或选择新模型，不建设另一套通用调度。

## Decisions

1. 新增有准确执行前置条件的补充入口，区别于启动新执行。对话应用拥有输入记录；执行器（Executor）只交付并返回接收凭据。请求身份支持幂等，原配置冻结，停止与授权不等待补充完成。短写入重读当前记录并按已观察版本保存，不持锁等待模型。
2. 每条尝试保存请求身份和原生输入身份。Codex 使用显式客户端输入编号；Qoder 使用 UUID 并等原生回显确认，不把写入管道当接收；DSH 保留原始请求来源，不把后续原生步骤误分为另一段业务对话。补充错误只影响该输入，未知先观察而不自动重发。浏览器为丢失回执保留同一请求编号及图片引用，明确拒绝后才允许新尝试。DSH 的原生取消会保留收件输入；停止时按准确请求来源删除本轮尚未消费的输入，接收与取消未核对前不把旧原生终态当作整轮结束。
3. 图片集合使用独立摘要作为观察版本，新协议随视图返回；旧客户端仍可用完整对话修订。上传后只接受附件字段和安全的新观察，不用旧完整快照覆盖实时事件。避免只在浏览器反复重试完整修订而在持续输出时仍冲突。
4. 信息流先按整轮来源确定唯一最终助手消息，再按用户补充的位置拆开过程。复用共同输入、过程和名称组件（Component）；原型传入内存动作，正式入口传入应用客户端（Client）。每段上下文使用局部固定定位，长用户输入采用默认收起和固定高度阅读。停止保留在固定对话顶部，避免阅读旧记录时失去控制入口。
5. 普通运行只在准确名称后显示呼吸灯与从持久开始时间计算的时长；等待和异常继续独立展示。保留历史配置，不从下一轮选择器推断旧模型。

## Risks / Trade-offs

- 完成临界点或断线 → 准确执行身份与独立尝试；确定拒绝保留草稿，未知保留记录并观察，不转送后续轮次。
- 同轮多条原生输入 → 使用请求和输入编号精确去重；禁止只按执行编号映射第一条。
- 动态输入的厂家终止语义不同 → 接收回执、待交付输入与原生终态分别处理；补充不会隐含回应授权。以协议及进程集成替身验证边界，真实账号未测范围明确报告。
- 固定头部遮挡内容 → 长输入有界、段间接替，并检查窄屏和历史分页的阅读位置。
- 历史缺少模型或阶段 → 保留未知说明和每轮最后助手消息回退，不改写旧记录。

## Migration Plan

采用新增可选字段和操作，无数据库破坏性迁移。先验证准确身份和原生输入，再启用正式界面；原型认可版保留来源副本并由共同源码重建当前评审页。未集成源码仅在独立工作树（Worktree）预览，不更新保留应用。
