## MODIFIED Requirements

### Requirement: 输入与反馈必须按真实能力呈现并保留草稿
对话 MUST 支持文本、流式回复、基本工具进度、文件改动反馈和错误展示；必要图片输入及模型（Model）选项 MUST 按当前接入版本、账号和模型（Model）的真实能力显示，不支持时 MUST 在发送前明确说明。输入区 MUST 提供当前对话的默认权限与受支持的完全访问选择，说明其仅用于下一轮原生执行；选择本身 MUST NOT 发送、改变活动执行或自动回答业务问题。执行中用户主动发送的普通图文 MUST 按当前执行身份补充；只编辑的输入仍为草稿，不显示成已送达；同一浏览器标签页刷新时，在本机存储可用的情况下 MUST 按对话身份恢复文本草稿，不承诺跨标签页、跨浏览器或多人同步。存储不可用 MUST 明确说明恢复限制，不阻止当前输入。

#### Scenario: 权限选择不跨对话继承
- **WHEN** 用户在当前对话选择完全访问后切换执行方、刷新或新建另一段对话
- **THEN** 当前对话 MUST 保留明确选择或读回实际本轮模式，未创建的草稿选择 MUST 仅转移到其准确新建对话
- **AND** 另一段新对话 MUST 使用默认权限，MUST NOT 从共享的新建偏好继承完全访问
- **AND** 选择模式不受支持时 MUST 保留用户意图并明确阻止发送，不静默降级

#### Scenario: 执行中继续输入
- **WHEN** 对话正在执行或等待回答、授权，而用户主动发送图文
- **THEN** 支持补充且身份确认时 MUST 交付当前执行并按真实接收结果展示；否则 MUST 保留内容并解释原因
- **AND** 普通补充 MUST 不隐含回答或批准，停止与当前请求回答仍可独立操作

#### Scenario: 刷新同一标签页
- **WHEN** 用户保留未发送文本后刷新同一浏览器标签页，且本机存储可用
- **THEN** 相同对话 MUST 恢复其文本草稿，MUST NOT 自动发送
- **AND** 其他对话草稿 MUST 不串入当前对话；已发送记录 MUST 从应用事实恢复，不能由草稿推定

#### Scenario: 不支持的图片或模型
- **WHEN** 用户选择图片或模型（Model），而当前接入不能使用它
- **THEN** 页面 MUST 在执行前明确不可用原因并保留其他输入，MUST NOT 悄悄丢弃图片或改用另一家执行

#### Scenario: DSH 模型选择范围
- **WHEN** 用户空闲时修改 DSH 模型（Model）
- **THEN** 界面 MUST 说明该选择还会更新此独立配置后续默认模型（Model），并显示真实生效结果
- **AND** 活动执行期间 MUST 不将下拉选择变化冒充本轮已切换

#### Scenario: 基本输入与反馈可操作
- **WHEN** 用户使用输入法、Enter、Shift+Enter 或键盘遍历对话控件
- **THEN** 输入法组合过程 MUST 不误发送，Enter 和换行行为 MUST 有明确说明，主要控件 MUST 有可访问名称及可见焦点
- **AND** 流式输出及展开工具反馈 MUST 保留用户当前阅读位置，不阻止停止或回应请求

#### Scenario: 发送入口始终一致
- **WHEN** 对话空闲或正在执行，用户编辑文字或添加图片
- **THEN** 输入框 MUST 始终提供发送按钮，有可发送文字或图片时可发，空内容时不可发，提交中的重复发送 MUST 被防止
- **AND** 停止 MUST 在固定的对话顶部独立提供，不替换或挤占发送按钮

### Requirement: 执行控制必须区分停止与未知状态
对话 MUST 明确显示执行中、等待补充信息、等待授权、正在停止、已确认停止、模型已中断但命令仍运行、执行状态待确认以及失败。停止、授权回复和问题回答 MUST 能在发送请求未结束时独立响应，并绑定产生请求的准确对话、执行和参与者。界面 MUST 根据真实反馈更新；时间经过、断开连接或前端关闭 MUST NOT 作为停止证明。原执行未结束或未知时 MUST 禁止在该对话另发并行执行及切换执行方启动工作；已确认当前执行时 MUST 允许有能力支持的普通补充，其他对话 MUST 不因此被阻断。

#### Scenario: 正常停止自动确认
- **WHEN** 用户停止本轮且系统收到模型与相关命令已结束的确认
- **THEN** 界面 MUST 自动显示已停止并恢复发送入口，保留历史、成果和草稿
- **AND** 用户 MUST 不被要求每次停止后再人工确认一次

#### Scenario: 模型中断但命令仍运行
- **WHEN** 模型已经中断但相关命令尚未退出
- **THEN** 界面 MUST 说明仍有命令运行并提供针对本轮剩余命令的停止操作
- **AND** 确认结束前 MUST 不显示已停止，也不能在同一对话新发或换家执行

#### Scenario: 回应原生问题和授权
- **WHEN** 原生执行请求回答问题或允许具体动作
- **THEN** 页面 MUST 展示实际来源、所需信息或动作范围，提交回答或允许、拒绝到准确原请求
- **AND** 过期请求 MUST 明确显示并刷新，MUST NOT 将回应转给输入框选中的另一位执行者

## ADDED Requirements

### Requirement: 对话必须固定当前输入与准确执行名称

每段对应的用户输入及助手名称行 MUST 在阅读其后内容时固定于滚动区域顶部，并随下一段上下文自然接替，不覆盖其他历史或造成整页跳动。名称 MUST 来自该段实际智能体（Agent）与模型（Model），不能被草稿选择或后续执行重标。长用户输入 MUST 默认收起，点击展开后在固定的有界高度内滚动阅读，并可再次收起；图片与完整原文 MUST 保留。正常执行 MUST 只在准确名称后显示呼吸灯与基于真实开始时间的持续时长，刷新不重新起算；失败、待回应、停止中、活动工具及未知状态 MUST 继续明确表达，不能被普通动画冒充。

#### Scenario: 滚动长执行历史
- **WHEN** 用户滚动阅读某次输入之后的长过程或答复
- **THEN** 对应用户输入和准确名称行 MUST 保持在内容顶部，进入下一段时 MUST 自然切换上下文
- **AND** 加载更早记录及实时追加 MUST 保持原阅读位置

#### Scenario: 长输入展开和收起
- **WHEN** 用户输入超过默认显示高度并点击展开
- **THEN** 完整内容 MUST 可在固定高度内滚动，名称行与对话正文 MUST 仍可见，点击收起 MUST 恢复紧凑显示

#### Scenario: 名称与持续时间
- **WHEN** 同一对话出现不同模型的历史回复，当前执行仍在运行
- **THEN** 各名称行 MUST 保留实际模型，呼吸灯与时间 MUST 紧随准确的当前执行名称，不在输入框上方重复显示运行状态
