## Context

见 proposal.md。现有读取受轮次、条数及字节上限保护；前端将结束轮过程折叠，原始条数无法代表可见内容高度。`useEarlierConversationEntries` 已拥有单批读取、取消、锚点与最新位置职责。

## Goals / Non-Goals

目标是在实际布局稳定后补足首屏，并继续尊重用户滚动。不修改服务分页格式、不自动展开过程、不移除容量保护，也不把所有历史一次装入页面。

## Decisions

- 在既有分页控制器内增加独立的首屏填充原因，复用原接口及同一活动请求；不用模拟用户上滚，避免把打开页面误算为阅读行为。
- 使用实际滚动高度与视口高度判断不足；延后两帧等待 Markdown 布局，同一布局机会合并。填充期间维持最新位置，用户阅读仍沿用原锚点补偿。
- 每次打开最多自动补四页。填满、没有更多记录、无新条目、游标重复、失败或用户接管均停止；预算耗尽后普通向上阅读仍可继续。相比无限补页，此限制避免超长折叠工具轮在后台耗尽全部历史。
- 每次回调读取当前选择和当前游标；切换和卸载取消请求及已排队的测量，迟到结果不能进入新对话。

## Risks / Trade-offs

- 超长折叠过程可能在预算内仍无法填满 → 保留普通向上续读，不伪造信息或扩大自动读取范围。
- Markdown 延迟填充或浏览器尺寸事件可能误触发 → 合并布局机会，维持一次活动请求并在请求前重读当前尺寸。
- 用户与自动补页同时发生 → 用户接管立即停止后续自动页，并按当前阅读位置接纳已返回的内容。

## Migration Plan

无数据迁移。回退前端即可恢复原行为，所有历史和续读游标保持原格式。
