## Context

现有 `ConversationApplication` 拥有对话、独立执行和交接；交接从原始记录组织分轮材料，并可生成不可变本地索引。前端 `ConversationPanel` 已覆盖草稿、发送、附件和独立控制，`AgentConversationsViewProvider` 允许隔离宿主绑定。动机见 proposal.md。

## Goals / Non-Goals

背景传递与执行控制分离，子对话只持有自己的可恢复上下文（Context）；不共享父对话原生执行身份，不引入新的工作调度器。不依赖进行中 `conversation-fork` 的未交付源码，不在本次修改其任务位置。

## Decisions

1. 新增公开 `childOf` 来源及私有 `inheritedContext`。来源记录直接父对话身份、标题、创建时间、已观察版本与截止序号；私有背景保留完整已保存消息和逐轮状态，不复制父执行、问题、队列或参与者绑定。相比原生分叉，这条统一路径能在父轮执行中或跨执行方时准确提供已保存背景。
2. 新指令首次发送时，将冻结背景与子对话自身记录交给现有分轮交接组织器；后续同一参与者只补未交付范围。子对话可见消息不重复显示父记录。首条子消息序号位于继承边界之后，避免来源序号冲突；标题只取子对话新输入。
3. 附件复制准确引用的原件及视频画面到新对话私有目录，保持独立读取；不复制未发送草稿。请求身份决定新对话编号，已存在时核对相同父对象与原观察版本后直接返回，避免丢失响应后的重复创建；并发落库冲突先读取同一对象。
4. 后端提供独立创建和分页查询子对话动作，父对话只读不改版本。前端浮窗通过独立展示绑定复用 `ConversationPanel`，不切换全局主对话选择；隐藏而不卸载已经访问的子窗口，保留输入和阅读位置，后台流式观察继续。
5. 所有入口集中于主对话右上方，横向空间不足时滚动而不合并为数量图标。只允许一个窗口展开，无遮罩，提供明确收起操作和真实运行/待回应状态。窄屏窗口限制在可视区域内。
6. 继承的工作位置只是子对话起点，不是永久共享约束。后续仍按用户新要求和适用规则使用现有任务（Task）及工作树（Worktree）能力；本功能不新增或替代任务分流与目录隔离策略。界面仅说明背景截止及按新要求独立处理，不持续显示固定共享目录警告；发送背景明确创建本身不切换目录，但不限制后续工作安排。

## Risks / Trade-offs

- 全量背景占用私有存储 → 单次冻结而非持续同步，长输入复用分轮索引，不静默丢失早期决定。
- 父轮仍在变化 → 读取时冻结准确版本与终态观察，未完成工作不伪装为完成；创建不等待父执行。
- 附件复制或并发失败 → 验证普通文件与大小，已存在文件必须内容一致；只保存准备完整的子对话，保留可重试的准确请求。
- 实际工作位置可能相同，也可能随新任务（Task）和工作树（Worktree）改变 → 不从对话父子关系推断文件隔离状态；后续按用户新要求安排，历史不授予新许可，写入仍重新观察真实现场。
- 现有架构说明和代码地图尚未覆盖子对话 → 已识别 `knowledge/docs/architecture/agent-integration.md` 与 `knowledge/code-map/technical-layers.md` 的补充价值；未获独立知识维护授权时只报告建议，不阻碍实现。

## Migration Plan

增加可选 JSON 字段，旧记录保持原行为，无数据迁移或新依赖。公开操作与 HTTP 数据结构同步更新并重新生成前端类型；候选只在本任务工作树（Worktree）验证，不更新开发版应用或默认安装。
