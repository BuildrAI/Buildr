## Why

用户确认任务当前改动物需要切到 IDE 的源代码管理面板才能看清，打断了对任务工作现场的连续观察。已确认原型把未提交的改动与本任务的提交合并为一个工作台：改动物、提交、按提交列出的文件与全文差异都在任务页内完成，且统一视图与并排对照按可用宽度自适应；正式实现以已确认原型的信息架构、布局和交互为准。

## What Changes

- 任务详情新增「改动与提交」内容标签，位于「任务收尾」之后，与工作阶段并列而非新增工作阶段；标签显示当前未提交改动的文件数。
- 工作台为主从式两栏：左侧仓库树按仓库分组，列出「更改」（未提交文件）与「提交」（展开可看该次文件改动）；右侧差异面显示选中文件的完整差异。
- 差异面提供统一视图（默认）、并排对照与全文三种视图：差异面不足约 1000px 时并排禁用并提示原因，够宽（如收起文件栏或宽屏）自动可用；文件栏可拖拽调宽并可收起。
- 工作台支持「展开全屏」：右屏脱离居中限宽满铺，左侧文件栏折叠为边侧条、悬停弹出浮窗；「恢复分屏」回到限宽居中。该浮窗交互本次只在任务模块实施，不预设为右屏通用行为。
- 原「提交记录」阅读标签并入「改动与提交」：提交按仓库分组展示，展开一条提交除完整说明与完整哈希外，列出本次提交改动的文件并可打开同一差异面。
- 新增只读读取：按任务范围读取各仓库工作区状态（修改、未跟踪、删除、重命名、冲突）、每条提交的文件清单与差异预览；不执行暂存、提交或回滚，未跟踪文件全文按新增行展示。

## Capabilities

### New Capabilities
- `task-changes-workbench`: 任务「改动与提交」工作台——仓库分组的未提交改动与本任务提交、按提交列出的文件、全文差异阅读面（统一/并排/全文）、自适应与全屏浮窗交互，以及支撑这些展示的只读工作区与提交文件读取。

### Modified Capabilities
- `task-git-commit-links`: 「提交记录」入口并入「改动与提交」内容标签，改为按仓库分组展示，展开提交保留完整说明与完整哈希并新增该次提交的文件改动列表；读取范围与关联判定不变。

## Impact

- 后端（services/buildr）：新增任务变更文件读取应用与只读 Git 状态/差异读取器；新增任务 HTTP 操作与契约（工作区改动、按提交列文件）；复用既有任务范围解析与 worktree 证据。
- 前端（services/buildr-web）：`TaskWorkPath` 内容标签增加「改动与提交」；新增 `TaskChangedFiles`、`TaskDiffReader` 组件与样式；`TaskCommitRecords` 调整为仓库分组并挂接提交文件列表；`TaskDetailPage` 接入新面板。
- 契约：扩展任务 HTTP 契约（`task-http-schema.ts`）与生成 DTO（`task-dto.ts`、`task-professional-http-dto.ts`）。
- 无破坏性变更：不修改提交关联判定，不改变已有 API 行为；新增能力为只读展示。
