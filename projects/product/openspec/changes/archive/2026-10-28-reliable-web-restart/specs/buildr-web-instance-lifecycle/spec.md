## ADDED Requirements

### Requirement: 同身份重启必须保留可验证的启动器归属

同身份重启 MUST 将经健康身份与实例观察摘要共同验证的原启动器身份保留到新实例，在启动锁内重新核验并校验其与当前产品和网页范围一致。安装更新改写启动器文件 MUST NOT 改变这次已观察的同身份归属；软件更新交接 MUST 继续采用新版安装身份。

#### Scenario: 开发启动器重启后继续更新
- **WHEN** 从开发启动器运行的健康实例完成页面重启
- **THEN** 新收据与健康响应 MUST 保留原已验证的启动器身份，后续同来源开发更新能够正常核验接管

#### Scenario: 身份文件已经变化
- **WHEN** 已观察旧实例的启动器身份文件被后续安装更新
- **THEN** 同身份重启 MUST 使用实际旧实例的已验证身份，MUST NOT 继承未核验的新文件内容

### Requirement: 页面重启和其他停止重建请求必须协调

同一实例的页面重启与开发更新 MUST 在认证退出处原子协调。页面重启进行时仅本次指定后继能够请求交接退出，其他请求 MUST 收到可恢复冲突并有界等待后重读。开发更新只可在重新证明同一来源与运行时后接续，MUST NOT 停止后来出现的外来实例。先进入退出的实例 MUST 拒绝后续页面重启。

内部同身份重启后继入口 MUST 携带本次私有退出资格，缺失时 MUST 明确拒绝，MUST NOT 退回普通认证退出。

开发更新开始前页面重启已经完成时，旧进程编号仅供追溯，MUST NOT 否定新鲜健康证明与收据共同核实的同来源实例；退出前仍 MUST 重新核对本次准确观察。

#### Scenario: 页面重启先受理
- **WHEN** 开发更新与已受理的页面重启同时请求退出同一实例
- **THEN** 更新 MUST 等待该重启结果，重新核对新实例；达到目标内容时复用，仍需更新时才继续接管

#### Scenario: 开发退出先受理
- **WHEN** 开发更新已经使旧实例进入退出，页面随后请求重启
- **THEN** 页面请求 MUST 被明确拒绝，不得启动竞争后继

#### Scenario: 等待期间出现外来实例
- **WHEN** 等待后实例的来源或运行时无法证明属于原已确认范围
- **THEN** 更新 MUST 保留该实例并报告冲突

### Requirement: 已确认失败的重启必须可再次发起

后继未成功启动且原实例尚未退出时，系统 MUST 保存该次失败原因并解除该次重启占用，允许新的会话授权重启。后继无结果的等待 MUST 有界，期限到达且原实例尚未进入退出时 MUST 撤销该次退出资格并释放占用；迟到后继 MUST NOT 使用已撤销资格停止或另起实例。旧请求的延迟失败或退出事件 MUST NOT 覆盖新的请求状态。

#### Scenario: 后继失败后再次重启
- **WHEN** 后继启动抛错、报告失败或提前异常退出，原实例仍可服务
- **THEN** 系统 MUST 显示失败原因且允许重新请求，重新请求 MUST 实际创建新一次后继

#### Scenario: 旧失败回调迟到
- **WHEN** 新重启已经受理后旧请求再次发出失败事件
- **THEN** 新请求 MUST 保持自己的状态和身份

#### Scenario: 后继一直没有启动结果
- **WHEN** 后继保持存活但在期限内未完成启动，原实例尚未进入退出
- **THEN** 系统 MUST 撤销其退出资格、显示有界失败并允许再次发起；迟到请求 MUST 被拒绝
