## Context

动机见 `proposal.md`。页面后继已在网页启动锁内核对实例摘要并执行认证退出；组织自举连续性脚本独立退出和重建，不参与这次交接。页面只能从原地址观察新页面会话，因此超时本身不能证明服务是否已经退出或在其他端口运行。

## Goals / Non-Goals

本次使同身份重启保留可证明的启动器归属；使两个合法重启入口在同一个旧实例处协调；让失败状态可见、占用可释放且允许再次发起。独立智能体执行后台维持既有版本采用机制，不增加强制停止动作；不引入第二套实例登记或常驻监督进程。

## Decisions

1. **从已验证实例继承身份。** 同身份后继使用经严格健康检查和观察摘要核验的旧实例 `launcherIdentity`，锁内再次核验，并以当前产品和网页范围执行身份校验。不能仅保留身份文件环境变量：安装可能已改写该文件。更新交接仍使用新版安装绑定。
2. **认证退出是协调点。** 页面重启每次产生独立私有标识，经子进程环境传给指定后继。该次重启期间，认证退出只接受该标识对应后继，其他停止重建请求收到可恢复冲突。退出已开始时沿用 `closing` 拒绝后续页面重启，消除单纯预检查的时间窗口。私有标识不进入命令行、日志、收据、公开健康信息或页面。
3. **开发连续性有界等待并重新核验。** 健康响应提供非秘密重启布尔状态用于发现。遇到正在重启或退出冲突时等待，重读健康实例、启动器来源和运行时；仅接续原已确认来源的替换实例。已达到目标内容时复用，仍需采用新版才继续认证退出；不同来源保留并报错。不能仅凭变化的进程编号重试停止。
4. **一次请求只维护自己的结果。** 页面重启的同步启动异常、失败上报、错误退出都能将本次标记为失败；旧回调不得清除新请求。后继存活但长时间没有结果时，原实例在尚未进入退出的前提下有界撤销该次私有标识并标记失败，允许新请求；任何携带已撤销或旧标识的迟到后继都不能退出实例。原服务进入退出后不回退成可重试的健康旧实例。私有环境变量在命令启动最早阶段从环境移除，内部一次消费，避免进入智能体后台和后续原生子进程。新增会话授权只读状态接口，页面在明确失败且原地址仍可用时重新请求重启。
5. **有界观察与诚实恢复。** 页面保持新页面会话轮换的完成依据，增加单次请求、正文读取及总等待的真实截止，兼容更新流程复用。已确认失败展示原因和真正重试；超时或不可达只表达原地址恢复尚未确认，提供继续连接与重新打开应用的恢复路径。保留现有原端口优先及冲突回退行为，实际地址继续由实例收据与启动入口发现，不冒称旧页面已恢复。

不采用监听句柄跨进程共享：它会在交接窗口同时接收旧新健康请求，要求重写令牌、收据及资源关闭次序，超出本轮所需协调范围。

## Risks / Trade-offs

- 旧程序没有新增健康字段 → 按既有检查继续，认证退出冲突仍作为等待信号；旧后继不携带标识不能冒充新请求后继。
- 原服务退出后原端口被外部占用 → 后继保留现有回退和日志；页面明确原地址未知，重新打开应用按权威收据发现实际地址。
- 后继已失败但回调晚到 → 使用本次请求身份判断，保留新请求结果。
- 其他任务的开发实例出现 → 核对原来源、运行时、健康与收据，拒绝接管。

## Migration Plan

无存储迁移。新字段和只读接口增量加入既有契约与生成客户端；在隔离域验证真实开发启动器、页面重启及后续连续性更新。候选代码不更新默认开发应用；交付后的正式激活仍由唯一自举执行器负责。
