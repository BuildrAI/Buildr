## Context
项目能力上下文仅在项目图中解析，常规技能投射使用工作空间图；当前自举与集鲜未配置项目需求和绑定。保留这层配置会形成选择与执行脱节。

## Goals / Non-Goals
删除项目能力配置和对应消费者，不改变工作空间能力体系、项目规则、命令需求、测试或准备声明。不修改外部工作空间或历史归档。

## Decisions
- 工作空间能力图成为唯一解析入口，删除跨项目绑定路由与逐项目重复诊断；技能生命周期影响只计算工作空间消费者。
- 项目 bind/unbind 在写入前明确拒绝，保留工作空间 scope 兼容写法，不静默扩大作用域。
- 项目创建、资产创建及基线修复不再生成文件，缺失不再影响项目完整性。
- Doctor 只观察已登记项目的旧文件：普通空配置和技能名单给出 info；非空 requires/bindings、未知格式、读取失败给出 warning，提示失效与核对需求，不参与能力图，不阻断其他操作。不自动迁移；同步仅清理安全的空需求/绑定和技能名单配置。
- 删除产品自举中的空效力声明文件，更新产品规则、知识与源技能指引；旧发布源路径保留为退休资产边界，防止旧资源再次写入。

## Risks / Trade-offs
含真实项目绑定的用户升级后选择可能改变，必须通过明确诊断和拒绝旧写入口暴露；不将局部配置自动搬到工作空间，以免影响其他项目。旧文件持续存在会有提示，但不会因过期技能 ID 破坏能力图。

## Migration Plan
随产品更新交付实现与指引。同步自动清理确认安全的空需求/绑定和技能名单配置；其余文件保持原文，按实际需要判断是否采用工作空间绑定。无需外部系统、发布或数据迁移。当前任务不激活未集成候选。

## Validation
覆盖项目创建/修复、缺失文件诊断、旧配置保全与分级提醒、项目 bind/unbind 零写入、能力图忽略旧配置、工作空间绑定与投射回归。更新关联知识和现有测试入口，不新增流程状态。

## 自动清理补充
同步预检只枚举登记且归属当前工作空间的项目，普通文件 schema 明确、仅四个已知字段、requires/bindings 为空且 skills 仅合法 ID 引用时允许清理。拒绝符号链接、未知格式与外部附加根。删除清单进入既有事务快照，写入前核对内容摘要及文件身份；漂移保留现场并停止相关写入；若事务快照后检测到外部修改，保留现有恢复日志并禁止自动回滚覆盖新内容，普通内部失败仍按快照恢复。只读 Doctor 不清理，重复同步幂等。
