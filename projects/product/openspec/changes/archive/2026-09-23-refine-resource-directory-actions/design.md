## Context

服务以 repositoryId/modulePath 定位代码。项目已有未登记目录选择；代码库已有真实 Git 根校验；技能网页目前只提供智能体指令，skills remove 会删除目录。

## Goals / Non-Goals

统一目录登记与保留文件的移除语义。保留共享服务与唯一代码库引用，不新增文件删除能力，不搬迁既有代码、不自动克隆或修改远端、不绕过组件受管约束。

## Decisions

1. 服务表单输入工作空间相对服务目录及其观察身份；已有目录在 projects/*/services/ 下按层级有界发现。新建选择项目，使用 projects/<项目>/services/<标识>。后端自动解析真实 Git 根并复用代码库；未处于现有仓库时保留已有代码库选择或新代码库声明能力，无可识别 Git 时仅生成待准备的本地代码库声明，不报告可用，也不自动初始化或猜测远端；不能把普通目录伪装为已准备仓库。
2. 保持 repositoryId/modulePath 为持久定位，目录选择只作为创建输入。兼容旧接口输入；新流程不再创建根 services/<code> 文档副本。已有目录登记零写文件，新建文件与清单在既有可回滚事务中提交。
3. 代码库候选只扫描工作空间根、repositories/、projects/ 与其 services/ 的真实仓库根。外部路径继续使用既有显式输入。被服务引用的代码库拒绝移除，并说明需先调整服务引用。
4. 技能候选从 workspace skills/ 有界读取 SKILL.md，跳过已登记及组件受管目录。新增可以登记已有目录或创建本地技能入口。清单版本与目录观察在事务内复验，保留其他声明。移除继续披露能力引用影响及组件边界，只写清单。
5. 公共目录操作保留固定右侧，采用紧凑列宽、小内边距和同排中性按钮。项目既有登记流程复用，代码库和技能补齐入口；确认说明保留文件，危险强调只用于最终确认。

## Risks / Trade-offs

- 陈旧目录与链接逃逸 → 校验规范路径、真实目录、目录身份、清单版本并在事务内复核。
- 移除代码库导致悬空引用 → 阻止被引用代码库移除，不级联移除服务。
- 移除技能影响能力选择 → 显示影响，保留能力绑定诊断；组件受管技能使用组件维护入口。
- 历史脚本依赖 skills remove 删除文件 → 文档显式说明语义变化，不保留隐式破坏性分支。

## Migration Plan

无批量迁移。新输入可选、旧清单不改写；只有用户提交时创建或移除登记。回退代码不恢复曾移除的登记，保留文件始终可检查及重新登记。
