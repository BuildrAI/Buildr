# 新增 buildr dev 热更新开发模式

## 为什么

Buildr 的四个服务在开发中都会频繁改动，但当前每次改动都走完整的开发版准备链路：构建 harness-web、harness 和 buildr-web，重建启动器，切换 agent-service 运行单元并重启开发版。一次约 50 秒，页面和对话会中断，前端改动尤其无法快速反馈。

## 改变什么

- 新增一条 `buildr dev` 开发命令，同时运行四个服务的活版本：
  - `buildr-web` 与 `buildr-harness-web` 使用 Vite 开发服务器，前端改动通过热更新反馈；
  - `buildr` 从源码运行并在改动时重启；
  - `buildr-harness` 在改动时快速重建并切换运行单元。
- 两个前端在开发模式下通过同一本机开发宿主取得会话，并代理 `/api`；harness 页面继续挂在 `/harness/`。
- 开发模式使用 development profile 的既有数据目录，一个命令启动、一个命令停止。

## 不改什么

- 交付收尾的全量准备、安装、重启和内容证明。
- 发布版、独立 Harness 页面和正式包的行为。
- 自举激活按运行输入判断是否更新的规则。
- 开发模式不产生交付证明，也不替代正式验证。

## 是否破坏性

不涉及数据结构、API、兼容性或发布产物变化；新增的是开发期命令与本地进程编排。
