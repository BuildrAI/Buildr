## ADDED Requirements

### Requirement: 原生上下文压缩阶段必须准确可见

系统 MUST 依据准确原执行的原生压缩信号显示“正在压缩上下文，请等待”及持续时间，不改变原执行的控制状态，不主动触发压缩，不根据静默或 Token 数变化推断压缩。系统 MUST 隔离其他执行及子智能体的事件。压缩结束、失败、执行终态或停止时 MUST 清除进行中提示；压缩失败 MUST 保留安全诊断，不据此虚构整轮失败。刷新和重连 MUST 保留可靠的已观察阶段，不确定时 MUST 不继续声称正在压缩；可靠的准确原生观察可重新确认阶段。

#### Scenario: 原生压缩开始和结束
- **WHEN** 当前执行提供匹配身份的压缩开始事件，随后提供结束事件
- **THEN** 系统 MUST 在开始后展示压缩等待及持续时间，在结束后恢复正常执行展示，不将压缩完成报告为任务完成

#### Scenario: 无信号或无关事件
- **WHEN** 仅发生无输出、上下文占用下降、旧轮次或子智能体压缩事件
- **THEN** 系统 MUST NOT 将其推断为当前主执行正在压缩

#### Scenario: 刷新及异常结束
- **WHEN** 已观察的压缩期间页面刷新、执行停止、执行失败或原状态无法确认
- **THEN** 刷新 MUST 读取同一阶段事实；停止、失败及不确定状态 MUST 不残留正在压缩提示，且不重发原操作
