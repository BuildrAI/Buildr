## MODIFIED Requirements

### Requirement: 运行配置按内部智能体可用性交接

服务目录、服务详情和任务本地运行的配置入口 MUST 使用同一交接语义。用户触发配置入口时，Buildr Web MUST 先打开统一的配置交接抽屉，说明目标服务与工作空间、智能体将完成的步骤、本次允许的影响、配置完成标准和完成后查看真实配置的位置；完整请求 MUST 可按需展开，并可在展开处复制。在用户明确确认“运行配置”之前，页面 MUST NOT 创建对话、提交请求或修改 `services/<service-code>/runtime.yml`。

用户确认后，存在已启用且就绪的可用执行入口时，Buildr Web MUST 直接提交本次配置请求并打开现有内部对话展示真实执行过程，不得再要求用户复制同一段请求。没有可用执行入口或可用性读取失败且尚未提交执行时，MUST 在同一抽屉内保留复制交接并明确尚未执行，不得伪装成已经执行。

配置提交 MUST 复用内部对话现有的智能体、模型、权限和恢复选择，不得建立运行配置专用执行状态或绕过既有授权。提交期间 MUST 防止同一动作重复提交；提交前的可用性、提交中和未创建执行前的失败反馈 MUST 在交接抽屉内可见。已经创建对话、恢复原提交或提交结果未知时，MUST 打开或恢复对应对话、关闭交接抽屉并如实反馈，不得静默重复提交或以复制交接替代原执行。

提交成功后，Buildr Web MUST 按工作空间保存本次交接的目标服务、原对话身份和交接前的运行定义快照，并在刷新页面、切换页面或经任一入口返回后恢复该观察。恢复的观察 MUST 只用于阻止同一服务重复发起、显示“配置中”或“检查中”并提供回到原对话的入口；MUST NOT 被当作配置成功、验证完成或运行定义事实。

该服务已有进行中的交接时，服务状态 MUST 保持“配置中”或“检查中”，配置入口 MUST 回到原对话，交接抽屉 MUST NOT 再次提供可提交的确认动作。工作空间内已有其他服务的交接进行中时，入口 MUST 说明原交接仍在进行并保持其他服务运行不变，不得提交第二项配置。

关闭或取消交接抽屉 MUST NOT 创建对话、提交请求或修改运行定义。交接抽屉的说明也 MUST NOT 被当作配置已经验证、进程已经就绪或业务验证完成。

#### Scenario: 打开入口先交代再执行

- **WHEN** 用户从任一服务运行配置入口触发操作
- **THEN** 页面打开配置交接抽屉，显示目标服务、智能体将完成的步骤、本次允许的影响和完成后的查看位置，并保持“尚未执行”
- **AND** 此时不创建对话、不提交请求、不修改 `services/<service-code>/runtime.yml`

#### Scenario: 已接入时直接配置

- **WHEN** 用户在交接抽屉中确认“运行配置”，且当前存在已启用且就绪的内部智能体
- **THEN** Buildr 直接提交一次绑定当前工作空间和服务的配置请求，打开现有内部对话展示受理、执行、待回应和结果状态，并关闭交接抽屉，不要求用户复制同一段请求

#### Scenario: 取消或关闭不产生执行

- **WHEN** 用户在确认前关闭或取消交接抽屉
- **THEN** 页面不创建对话、不提交请求、不修改运行定义，入口保持可再次发起

#### Scenario: 未接入时保留复制

- **WHEN** 用户确认“运行配置”，但当前没有可用内部智能体，或提交前读取失败且尚未创建配置执行
- **THEN** 交接抽屉保持打开并明确尚未执行，说明真实原因，将复制同一配置请求作为可用操作交给外部智能体

#### Scenario: 提交结果未知

- **WHEN** 配置请求已经创建对话、恢复了原提交或提交响应未能确认
- **THEN** 页面打开或恢复对应对话并关闭交接抽屉，如实展示原提交的状态，不自动生成另一次执行，也不把复制指令作为默认下一步

#### Scenario: 重复点击配置

- **WHEN** 用户在一次配置提交尚未完成时再次确认配置入口或提交动作
- **THEN** 页面不提交第二个相同请求，并继续在交接抽屉中显示原动作的真实状态

#### Scenario: 刷新或切换页面后仍处于配置中

- **WHEN** 已确认提交的运行配置交接仍在执行，用户刷新页面、切换到其他页面，或经服务目录、服务详情、任务本地运行任一入口返回
- **THEN** 页面继续显示该服务的“配置中”或“检查中”，原入口提供回到原对话的操作，且不显示可再次提交的配置入口
- **AND** 恢复的状态只来自本次交接记录、原对话执行事实和运行定义读取，不推断配置成功

#### Scenario: 同一服务再次触发配置入口

- **WHEN** 该服务已有进行中的运行配置交接，用户再次触发该服务的配置入口
- **THEN** 页面回到原对话，不打开可提交的第二个交接抽屉，也不提交新请求

#### Scenario: 交接进行中触发另一服务

- **WHEN** 工作空间内已有一项运行配置交接正在进行，用户触发另一服务的配置入口
- **THEN** 页面说明原交接仍在进行，不提交第二项配置，其他服务已有运行和既有配置保持不变

### Requirement: 配置结果以真实运行定义和执行事实验收

内部对话中的请求受理、执行完成或智能体文字声明 MUST NOT 被页面直接转换为配置已验证或已生效。Buildr Web MUST 继续通过现有本地运行读取与刷新机制观察 `services/<service-code>/runtime.yml`、验证时间、诊断和实例快照；已有实例 MUST NOT 因保存新定义而自动重启。对话展示执行事实，运行定义页面展示配置事实，两者不得互为第二权威。

配置交接的完成观察 MUST NOT 依赖发起入口是否仍打开：交接存在期间，Buildr Web MUST 持续核对原对话执行状态；执行结束或达到观察上限后 MUST 停止观察并清除交接记录。清除记录只结束本次界面观察，MUST NOT 修改运行定义、对话或验证结论。原对话不可读取或已不存在时 MUST 明确结束观察并说明原因，不得伪造配置结果。

执行正常结束且运行定义可读时，完成反馈 MUST 提供打开该服务启动入口的操作，并复用现有启动抽屉与确认流程；MUST NOT 自动启动进程，MUST NOT 跳过代码来源与连接环境确认，MUST NOT 在运行定义不可读或执行未正常结束时提供该入口。启动入口 MUST 只消费一次，刷新或返回页面不得自动再次打开。

复制交接抽屉 MUST 优先呈现目标、影响和完成后的查看位置，完整请求按需展开；内部执行路径 MUST 提供与原入口一致的等待和失败反馈。无论采用哪条路径，页面均不得把配置写入、进程就绪或单一探针表述为完整业务验证。

#### Scenario: 执行后查看配置

- **WHEN** 智能体已经保存并验证新的运行定义，用户仍在或返回服务页面
- **THEN** 页面通过现有读取机制显示新的验证时间、配置和诊断，不需要用户从对话复制配置内容。

#### Scenario: 执行结束但未形成有效定义

- **WHEN** 对话本轮结束，但运行定义不存在、未变化或读取仍有诊断
- **THEN** 页面继续显示真实缺口，不仅凭对话完成状态显示“配置成功”。

#### Scenario: 已有运行保持原快照

- **WHEN** 服务已有运行实例且智能体保存了新的运行定义
- **THEN** 既有实例不被自动停止或重启，页面继续区分实例启动快照与当前定义。

#### Scenario: 完成观察跨越页面切换

- **WHEN** 用户已离开发起配置的页面，而交接仍在观察期内
- **THEN** Buildr Web 继续核对原对话，执行结束后按运行定义可读性给出结果并清除交接记录；返回服务页时显示的仍是当前运行事实，不依赖发起页面是否打开

#### Scenario: 完成后直接启动本地

- **WHEN** 配置执行正常结束，且 Buildr 能读到该服务的运行定义
- **THEN** 完成反馈提供“启动本地”，打开该服务的启动抽屉，由用户确认代码来源、连接环境并启动进程
- **AND** 该入口只消费一次，刷新或返回页面不会自动再次打开；运行定义不可读或执行未正常结束时只提供“查看服务”

#### Scenario: 原对话不可读取

- **WHEN** 完成观察无法读取原对话，或原对话已不存在
- **THEN** 页面说明无法核对本次配置结果并结束观察，不把不可读取当作配置完成或失败，也不重复提交请求
