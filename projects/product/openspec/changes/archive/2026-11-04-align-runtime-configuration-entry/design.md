## Context

运行配置由内部对话中的智能体执行，完成事实来自原对话执行状态与 `services/<service-code>/runtime.yml` 的读取。现有实现把“这次交接属于哪个服务、对应哪段对话”保存在页面组件的 `useState` 中，因此刷新或切换页面即丢失；服务目录重新显示“开始配置”，交接抽屉也回到“尚未执行”。对话事实本身持久保存，缺少的只是交接索引与其观察者。

## Goals / Non-Goals

**Goals:**

- 刷新、切换页面或跨入口返回后，同一服务仍显示进行中的运行配置，并可直接回到原对话。
- 交接进行中不允许对同一服务发起第二次配置；其他服务的入口说明真实原因。
- 完成观察不依赖发起页面是否打开，并在结束后恢复入口状态。
- 配置执行正常结束且运行定义可读时，完成通知直接打开该服务的启动抽屉，用户确认后即可启动。
- 三个入口的动作名统一为“运行配置”。

**Non-Goals:**

- 不新增后端接口、数据库记录或运行配置专用执行状态。
- 不改变配置请求正文、完成判定、运行定义格式、对话提交与恢复协议。
- 不把交接记录当作配置成功、验证通过或运行定义事实。
- 不自动启动服务、部署或重试失败配置。

## Decisions

### 1. 交接索引保存在浏览器本机，而不是新增后端状态

记录按工作空间保存在 `localStorage`，键包含 Buildr Web profile，避免同一浏览器上正式版与开发版互相串用。记录只含 `workspaceId`、服务 `code` 与 `name`、`conversationId`、交接前的运行定义签名 `baseline` 和 `startedAt`。

不新增后端的理由：对话执行状态与运行定义已经是权威事实，缺的只是“哪段对话在配置哪个服务”的索引；对话视图没有服务关联字段，要补成后端事实需要同时改对话模型、接口、迁移与清理。新增第二份配置状态还会与对话事实形成双权威，重演“受理即成功”的风险。

代价是只在同一浏览器 profile 内恢复；清空站点存储或换用另一浏览器后回到原有行为（入口可再次发起）。此时真实完成事实仍以对话与运行定义为准，界面不会伪造成功。

### 2. 记录以模块级存储加订阅共享，读取时校验

新增 `runtimeConfigurationHandoff.ts`：内存快照为唯一读取源，写入时同步持久化并通知订阅者；读取时校验必需字段与时间，损坏条目丢弃而不是让页面崩溃。`useRuntimeConfiguration` 与状态单元格读取同一工作空间记录，因此三个入口与刷新后的页面天然一致，无需各自维护状态。

记录使用“按工作空间单条”而不是列表：同一工作空间同时只应有一项配置交接，这与现有“交接进行中不并发发起第二项”的约束一致；实现仍按工作空间键存放，便于后续放开并发而不改变存储形状。

### 3. 完成观察上移到应用壳层，只挂载一次

原实现由服务目录、服务运行区和任务本地运行各自渲染观察组件，页面关闭即停止。改为在应用壳层挂载一次 `RuntimeConfigurationOutcome`，以当前工作空间记录为输入：存在记录时每 3 秒读取原对话，执行进入终态后读取一次运行状态、按运行定义可读性给出结果通知、清除记录并广播运行状态变化事件；达到 30 分钟上限只结束观察并提示可回对话查看。

这样离开页面仍能对齐结果，也避免三个入口重复轮询和重复通知。观察本身不写业务事实，清除记录只结束界面观察。

### 4. 进行中的入口语义

已有交接时：同一服务的入口与状态摘要回到原对话（状态单元格仍显示“配置中/检查中”）；其他服务的入口提示原交接仍在进行，不打开可提交抽屉。交接抽屉额外做防御性判断：若目标服务已有进行中的交接，主操作变为“查看对话”，不提供第二次确认，覆盖存储写入失败或另一浏览器同时提交等边界。

### 5. 命名

服务目录行操作、服务运行区未配置入口、任务本地运行提示与交接抽屉主操作统一使用“运行配置”；抽屉标题保持“运行配置”，说明文字中的完成标志不变。已完成定义入口（“配置启动与连接”“交给智能体检查配置”）不在本次范围。

### 6. 完成后直接给启动入口，但不自动启动

结果通知在“执行正常结束且运行定义可读”时同时提供“启动本地”：点击后登记一次内存中的启动请求并导航到该服务的本地运行视图；服务页先切到“本地运行”，运行区在运行状态读取完成后打开现有启动抽屉并消费请求。服务详情常以目录旁的预览呈现，导航地址会回落到目录并丢掉查询参数，因此请求不写入地址，也不进入存储；刷新或超过一分钟未消费时自然失效。进程启动、代码来源与连接环境仍由用户在抽屉内确认，观察器不直接调用启动接口。

只在结果 tone 为完成或检查完成时给出该入口：定义有变化但执行未正常结束、定义不可读或对话不可读取时只提供“查看服务”，避免把未完成验证的配置催促为启动。启动入口复用现有 `StartWorktreeModal`，不新增启动旁路。

## Risks / Trade-offs

- [只在同一浏览器恢复] → 记录是索引而非权威；换浏览器时入口可再次发起，用户仍能从对话与运行定义看到真实结果。若后续需要跨浏览器一致，应由对话模型承载服务关联，而不是扩大本机状态。
- [全局观察增加轮询] → 仅在存在交接记录时轮询，单次 3 秒间隔，结束后立即停止。
- [存储损坏或写入失败] → 读取校验丢弃无效记录，写入失败不影响已提交的对话与运行事实；抽屉的进行中判断仍限制同一服务重复提交。
- [完成后启动入口] → 只在完成或检查完成且运行定义可读时出现；入口只消费一次，不自动启动进程，也不跳过代码来源与连接环境确认。
- [旧行为回退] → 移除持久化与全局观察即可回到页面内状态，不涉及数据迁移。

## Migration Plan

无数据迁移。已有对话、运行定义与实例不受影响；部署后首次打开页面时没有交接记录，入口行为与现状一致。
