## Context

当前参与者占用判断将已释放的历史未知视为忙碌，并在当前轮已结束但旧后台仍持有控制时直接拒绝新输入。独立参与者、历史交接、准确旧执行控制和持久待发送唯一身份已经存在。

## Goals / Non-Goals

**Goals:** 新指令不因历史疑点或旧控制清理永久阻塞；复用可安全复用的会话，否则在同一 Buildr 对话中独立接续；保持此前单一取消交互。

**Non-Goals:** 不更改旧操作结果、不强杀旧后台、不重放输入或工具、不引入超时即判定成功的规则，不进行 Git 交付或开发应用更新。

## Decisions

- 将历史结果未知与当前控制持有分开。已释放的历史轮次不阻塞复用；最新未知轮次仍隔离，避免继续一个结果不确定的原上下文。有效待回答请求仍保留归属。
- 删除“当前轮终态且旧后台存活就拒绝”的额外门禁。原控制仍占用时沿用独立参与者机制，保存准确旧执行与可追溯的原生会话替换，而非伪装原会话接管。
- 不以停止旧轮作为新输入的前提。保留原控制和资源释放证明；重复待发送核对沿用原客户端请求身份，只投递新要求一次。

## Risks / Trade-offs

- [独立原生上下文不具有旧上下文的隐式记忆] → 保留同一可见对话、交接资料与前后原生身份，要求接续核对现场；可安全复用时仍优先复用。
- [历史疑点被误当成成功] → 不更改历史状态或未知工具，回归断言历史身份、结果及原控制保持。
- [真实共享资源被错误释放] → 不修改执行器释放与停止逻辑，继续执行原有真实资源保护检查。
