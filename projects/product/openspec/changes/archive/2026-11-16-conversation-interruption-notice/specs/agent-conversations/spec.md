## ADDED Requirements

### Requirement: 未知执行提示说明真实中断来源

系统 MUST 根据已保存记录区分系统中断、已请求停止和无法确认三类来源，并在提示中以可见文案说明本轮中断与结果未能确认，MUST NOT 把系统自动中断表达为用户请求停止。提示 MUST 同时说明原记录与已完成操作保留；存在未结束工具或后台命令时 MUST 说明其结束记录尚缺、可能仍在运行。完整技术诊断可保留在按需查看的说明中，MUST NOT 作为唯一可见原因。

#### Scenario: 服务重启中断本轮

- **WHEN** 记录中的诊断说明服务退休中断了本轮执行
- **THEN** 提示 MUST 说明服务重启中断了本轮且结果未能确认
- **AND** MUST NOT 表达为用户请求停止，也 MUST NOT 宣称旧执行已停止或工作成功

#### Scenario: 已请求停止但未确认结束

- **WHEN** 记录存在停止请求且诊断没有说明系统中断
- **THEN** 提示 MUST 说明已请求停止但尚未确认结束，不推断停止发起者

#### Scenario: 无法归因的未知执行

- **WHEN** 记录只有未知状态，没有服务中断或停止请求证据
- **THEN** 提示 MUST 说明本轮执行中断、结果未能确认，不猜测具体原因

## MODIFIED Requirements

### Requirement: 已释放的待确认对话必须提供继续与关闭出口

系统 MUST 为没有明确活动工作、有效待回答问题或已提交待发送要求、且原生控制资源均已确认释放的待确认对话提供单一“继续原任务”出口。提示 MUST 以可见文案说明中断来源、结果未确认以及记录与已完成操作保留，提示本身 MUST NOT 再提供关闭、隐藏、重新读取或停止动作；关闭（隐藏）MUST 继续可从对话菜单完成，并沿用保留对话历史、未知执行与工具事实及关联 Task 状态的约束。继续 MUST 先核对原轮及成果，再接续未完成目标，不重放历史要求。读取仍未知时 MUST 明确说明没有取得新结束证据及可用动作，MUST NOT 把读取成功冒充工作完成。

#### Scenario: 服务重启中断后的单一继续出口

- **WHEN** 当前轮因服务退休中断、原生控制资源已释放、结果未知且没有待决定
- **THEN** 提示 MUST 显示可见的中断原因与“继续原任务”一个动作
- **AND** MUST NOT 显示关闭、隐藏、重新读取或停止动作
- **AND** 原记录、未知工具结果和已完成事实 MUST 保留

#### Scenario: 关闭遗留待确认对话

- **WHEN** 用户从对话菜单关闭原生控制资源均已释放、没有明确活动工作和有效待回答问题的待确认对话
- **THEN** 对话 MUST 从活动提醒撤下并保留在可恢复的历史中，原执行和未知工具结果 MUST 不变，关联 Task MUST 不被完成

#### Scenario: 另一原轮仍在工作

- **WHEN** 最新轮已释放但保留轮次尚未释放，或仍有明确活动工具、有效待回答问题或已提交的待发送要求
- **THEN** 关闭入口 MUST 不可用，隐藏 MUST 不掩盖相应活动，不发送替代停止命令

#### Scenario: 再次继续工作

- **WHEN** 用户选择继续已释放但结果待确认的原目标
- **THEN** 系统 MUST 先重新读取；取得正常结束和最终答复证据时 MUST 告知用户可直接提出新要求，否则按原执行身份核对已生效成果后接续，不自动重复旧操作

#### Scenario: 仍有活动工作的未知轮

- **WHEN** 当前轮结果未知但原生控制资源尚未确认释放
- **THEN** 提示 MUST 继续提供停止与重新读取，MUST NOT 把真实在途工作表达为可结束的历史

### Requirement: 停止未确认时的显式继续出口

用户已请求整轮停止且当前轮状态未知时，界面 MUST 提供“继续原任务”，不以旧轮受理回执、资源释放、工具结束证明为前提。显式接续 MUST 校验原轮身份、已观察版本及执行组合，保留原执行、问题和未知结果；MUST 使用独立上下文，先核对成果与未知副作用，不重发原输入、不代答问题、不声称后台已停止。已提交待发送要求 MUST 先被处理以避免重复接续；陈旧或重复提交 MUST 不重复启动新轮。正常工作中的原轮 MUST NOT 因刷新自动接续。关闭对话的原约束不变。

#### Scenario: 停止未知后继续

- **WHEN** 用户点击停止未确认轮次的“继续原任务”
- **THEN** 系统 MUST 保留旧轮并启动独立新上下文，提示先核对已有成果和未知操作；不等待旧轮结束

#### Scenario: 原输入未确认接收

- **WHEN** 停止未知且原轮未取得受理回执
- **THEN** 系统 MUST 允许显式独立接续，但不重发原输入或断言其未送达

#### Scenario: 身份或版本已变化

- **WHEN** 点击后原轮身份、版本或执行组合变化
- **THEN** 系统 MUST 拒绝陈旧提交并保留草稿，重复请求不得再次创建执行
