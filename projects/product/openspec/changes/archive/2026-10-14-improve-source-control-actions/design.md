## Context

动机和范围见 [proposal.md](proposal.md)。现有分支（Branch）管理、独立获取远程（Fetch）和普通精确推送（Push）已有身份及版本保护；当前缺少同步（Sync）协调能力。前端（Frontend）由 `SourceControlWorkbench` 接收可替换的分支（Branch）扩展，真实请求由功能内适配层负责。

## Goals / Non-Goals

目标是复用现有读取和写入能力，提供具体工作树（Worktree）的清晰同步入口与可信阶段结果。同步（Sync）始终以当前已跟踪上游（Upstream）为目标。

本轮不增加通用 Git 命令执行器、多级操作目录、自动提交、自动建立上游（Upstream）、强推或批量同步（Sync）。只交换导航显示顺序，现有默认路由和页面恢复语义保持。

## Decisions

1. 来源名称和可点击的分支（Branch）组成可收缩名称区域；状态、任务（Task）及末尾固定宽度的三个点在其外自然占位。长名称省略并保留完整提示，窄栏必要时换行状态，保证全部数字和图标可达。分支（Branch）浮层（Popover）保留原检出（Checkout）和切换交互，操作菜单（Menu）承接获取远程（Fetch）及同步（Sync）。标题全部获取同样移入操作菜单（Menu），刷新保留独立按钮。相比继续固定分支列，这能使名称与所属分支（Branch）关联清楚且不挤占状态。

2. 有非零远程差异时，上下箭头和数量组成同步（Sync）快捷按钮，悬停（Hover）与键盘聚焦提示“先拉取并变基，再推送”及已观察上游（Upstream）。文件状态独立查看详情；已确认两方面均无差异时保留勾选详情。菜单（Menu）仍提供同步（Sync），使没有常驻差异数量时也可主动操作。执行中两个入口共用等待状态并防止重复发送。

3. 新增 `GET /code/sync-context` 与 `POST /code/sync`，前者返回绑定来源、分支（Branch）、完整提交（Commit）、文件及索引（Index）、上游（Upstream）和相关配置的版本，后者要求 `expectedRevision`。前端（Frontend）点击后先核对观察结果与点击来源行身份、分支（Branch）和提交（Commit），再执行；不增加无必要二次确认。接口（API）仅通过既有同源会话（Session）写入授权开放，不扩大只读入口。

4. 后端（Backend）协调固定上游（Upstream）获取、必要整合和普通精确推送（Push），不串接受用户配置影响的裸 `pull && push`。只获取对应引用（Ref）；仅落后时快进（Fast-forward），分叉时变基（Rebase）重放相对本次固定上游（Upstream）未推送的提交（Commit）。上游（Upstream）非快进改写、待重放范围包含合并提交（Merge Commit）、不安全外部内容过滤器（Filter）或无法证明安全关系时停止整合。只有确实需要整合时要求文件和索引（Index）干净；无需整合时允许推送并保留未提交内容。

5. 抽取已有精确推送（Push）实现供两种应用复用。正常获取会改变上游提交（Commit），因此推送前重新观察当前版本并核对原目标配置，不把本次操作的预期变化当漂移。应用内 Git 写入共用公共目录（Common Directory）互斥；外部工具仍逐阶段校验身份和事实。获取、整合、推送各自保留结果，冲突保留现场并停止后续推送；超时或结果未知不自动重试。

6. 完成后沿既有来源变化事件（Event）触发按代码库（Repository）的局部重新观察，发起组件卸载不丢失更新，迟到响应不覆盖其他来源。历史筛选和固定提交（Commit）阅读保持。已有命令行接口（CLI）只读边界不变；现有智能体（Agent）无需新增写入入口，按明确来源和失败结果继续判断即可。

## Risks / Trade-offs

- 远端可能在获取后变化 → 普通精确推送（Push）校验实际远端并拒绝陈旧范围，保留本地已完成成果。
- 变基（Rebase）可能冲突 → 保留冲突现场、提供查看改动入口，明确推送未执行。自动中止会隐藏可继续处理的工作，因此本轮不采用。
- 只能证明相对固定上游（Upstream）未推送，不能证明所有其他远端从未共享 → 界面和规范准确表达范围，不声称全局共享历史证明。
- 一行信息较多 → 生产托管浏览器（Browser）检查名称后分支（Branch）、独立图标和窄栏几何关系，不以宽屏截图代替窄栏验证。

## Migration Plan

无持久数据迁移，新增同步（Sync）接口（API）为增量能力，既有获取和推送协议保留。构建时同步生成前端（Frontend）类型；回退源码及生产托管产物即可移除新入口，不撤销已经成立的 Git 操作。
