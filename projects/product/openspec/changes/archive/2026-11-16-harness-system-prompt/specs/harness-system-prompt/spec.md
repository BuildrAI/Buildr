## Purpose
为 Buildr 管理的工作对话提供一份用户可修改、可启停的统一系统提示词，在保留厂商原生行为及业务权限边界的前提下跨执行器追加，并准确表达本轮提交内容和生效版本。

## ADDED Requirements

### Requirement: 配置域统一提示词
Harness SHALL 提供名称为「Buildr Harness 系统提示词」的配置，默认启用已确认的简洁表达文案，支持读取、版本保护修改、启停和恢复默认内容。

#### Scenario: 首次使用与修改冲突
- **WHEN** 配置尚未保存或保存携带陈旧修订
- **THEN** 读取默认启用文案，陈旧写入拒绝且不覆盖当前内容。

### Requirement: 原生追加与支持观察
Harness SHALL 保留原生指令和权限，并通过 Codex、DSH、Qoder、Qoder CN、Claude Code 与支持扩展的 Antigravity 原生机制追加同一有效文案，不改写用户消息，不影响独立辅助标题。

#### Scenario: 执行器不支持
- **WHEN** 当前原生执行器未提供追加能力
- **THEN** 本轮支持情况明确显示不可用，不声称已注入，不退化为用户消息。

### Requirement: 按轮固定与隔离
Harness SHALL 为新轮固定提示词原文、版本、启停和交付能力快照；配置变化不得修改已开始的执行，并 SHALL 在下一轮使用新内容且保留原对话历史与旧执行控制。

#### Scenario: 修改后继续或切换
- **WHEN** 用户修改提示词后发送下一轮或切换执行器
- **THEN** 使用新版本，必要时重建原生上下文接续，不重发已受理输入，也不串改其他执行。
