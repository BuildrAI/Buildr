## Context

现有不可变索引保存条目修订、工具元数据和原生引用，`history` 已按来源分页，工具正文仅由 `entry` 读取。问题是接续提示把内部 JSON 路径当作第一阅读入口，压缩路径又省掉了轮次目录。

## Goals / Non-Goals

**Goals:** Agent 不必整读索引就能发现轮次并读取必要历史；密集工具历史下可消息优先；默认查询、来源身份和错误边界保持兼容。

**Non-Goals:** 不迁移或分片索引，不删除历史，不引入辅助模型摘要，不改网页界面，不改变授权、任务状态或工具执行。

## Decisions

1. 压缩交接附最近轮次的有界目录（ID、范围、状态），并始终保留全来源分页命令；目录不含正文，明确旧轮次未列出但可查。相比增加新的目录接口，直接使用已有轮次元数据成本更低。
2. `history` 增加 `view: all|messages`，缺省 `all`。messages 在固定来源和轮次筛选后去掉有 tool 引用的记录，再按过滤后集合解释 cursor/limit；通知与普通消息仍按原修订读取。视图参数须在续页时保持一致，不能混用游标。
3. 宿主 HTTP 历史入口透传相同 view 参数并使用同一 schema 校验，网页旧调用不变。保留原索引格式及单次历史读取预算。整文件大小不再成为接续门槛；不靠提高读取限制、换模型或按行切割单行 JSON 解决问题。
4. 普通交接的轮次引用只给 history 参数，不将内部路径标为本轮正文；来源路径仍保留在应用记录供诊断和旧消费者使用。

## Risks / Trade-offs

- 目录过多导致接收容量再次超限 → 目录限定条数与字节数，省略时说明其只是导航，不省略真实来源。
- 过滤可能吞掉通知或授权纠正 → 仅按已有 tool 引用过滤，消息与 notice 均保留；混合条目跨页测试。
- 新参数与生成客户端类型不一致 → 使用现有 schema 生成入口并验证类型；旧调用不传新参数仍保持兼容。
- 回滚 → 无持久格式变更，撤回源码即可；既有来源和回执无需改写。
