## Purpose

定义独立 `buildr-agent` 服务（Service）的职责、执行者（Executor）契约及首版 Codex、DSH 与 Qoder 原生智能体（Agent）的本机接入边界，使人能够在独立配置中登录并使用真实可用能力，同时准确区分账号、进程、权限和恢复状态，保留外部桌面应用及既有一次生成能力的原有行为。公共交互能力与实际执行者（Executor）分离，为以后经独立设计与验收的 Buildr 自研智能体（Agent）保留接入边界，不在本变更实现自研执行能力。

## ADDED Requirements

### Requirement: 首次程序准备与连接
系统 MUST 发现明确来源的本机可用程序并按版本系列检查兼容性；第一版兼容 Codex `0.163.x`、DSH `0.2.x`、Qoder CLI `1.1.x`，包含各系列内的预发布版本；显式或已绑定程序缺失 MUST NOT 静默回退。多来源 MUST 允许明确选择，已有原生绑定和独立配置 MUST 保留。缺失时 MUST 提供官方安装引导或按显式安装动作准备固定版本的独立程序；固定下载版本 MUST NOT 被当作唯一兼容版本。用户 MUST 不必手动安装 SDK 或单独下载 App Server。浏览器工具 MUST 继续由智能体（Agent）按技能（Skill）准备。

#### Scenario: 缺失程序到首次登录
- **WHEN** 用户选择一家尚无可用程序的接入并执行准备
- **THEN** 系统 MUST 展示对应官方安装入口或独立安装动作，按准确尝试显示进展和失败，并在程序验证后进入独立官方登录
- **AND** MUST 仅在实际账号和非空模型目录检查通过后显示可用

#### Scenario: 重试、取消与原绑定
- **WHEN** 准备重复、取消、失败或发现外部安装版本变化
- **THEN** 系统 MUST 保留既有程序、账号和对话，取消本次拥有的动作并拒绝陈旧改绑；重试 MUST 重新观察当前事实
- **AND** MUST NOT 自动更新、覆盖原程序或复制桌面凭据

### Requirement: 浏览器工具发现与官方准备方式

Buildr MUST 保持厂家账号配置隔离，并为原生子进程提供原用户目录的路径线索及准确的 Playwright 浏览器缓存路径；显式 `PLAYWRIGHT_BROWSERS_PATH`（包括包内安装值 `0`）MUST 保留，未设置时 MUST 解析原用户的官方默认缓存。系统 MUST NOT 为复用工具复制厂家桌面凭据或恢复全部用户环境。浏览器工具 MUST 由智能体（Agent）按随包技能（Skill）发现、复用或通过官方方式准备，不要求工具管理平台或统一安装目录。

#### Scenario: 独立账号复用已有浏览器工具
- **WHEN** 三家原生接入使用各自独立账号目录，且原用户已安装可用浏览器工具和匹配浏览器
- **THEN** 智能体 MUST 能按已提供路径发现并复用它们，重启后路径语义保持
- **AND** 账号凭据与外部桌面配置 MUST 保持隔离，工具可用 MUST 通过实际页面操作验证

#### Scenario: 缺少浏览器验证能力
- **WHEN** 任务需要页面验证而当前工具不可用
- **THEN** 随包方法 MUST 指引智能体先检查已有工具，再沿用官方安装和缓存方式准备，并报告实际操作结果或准确失败
- **AND** 安装成功、HTTP 成功或浏览器同内核 MUST NOT 被当作真实页面验证成功

### Requirement: 智能体服务必须独立维护并随现有宿主交付

新增智能体服务（Agent Service）MUST 以 `services/buildr-agent/` 为独立源码、依赖、构建及验证单元，拥有接入、统一对话、参与关系、执行协调、私有交互存储和语义事件。第一版 MUST 以私有库（Private Library）由 Buildr 同进程宿主（Host）装配，并随现有 Buildr 发行包交付；MUST NOT 因源码独立而要求用户另装常驻服务、启动额外端口或配置另一套本机认证。厂家原生进程仍由各适配器（Adapter）按其实际方式管理。

Buildr 宿主（Host）MUST 保留应用配置域（Profile）解析、工作空间（Workspace）及任务（Task）权威查询、本机身份认证、超文本传输接口（HTTP）与服务端事件流（SSE）传输责任。`buildr-agent` MUST 通过显式注入的窄接口使用必要宿主能力，不导入宿主业务模块内部实现、不直接改写任务或工作资产，也不依赖浏览器请求／响应对象。前端仍归属 `buildr-web`，MUST 通过受认证接口使用安全的公开契约，不能直接依赖服务私有存储或厂家软件开发工具包（SDK）。

#### Scenario: 在没有源码相邻目录的正式安装中运行
- **WHEN** 用户从正式 Buildr 发行包安装并打开新对话能力
- **THEN** 所需 `buildr-agent` 构建产物及运行依赖 MUST 已包含在该发行包的可解析路径中
- **AND** MUST NOT 依赖开发工作树、相邻源码目录、实验脚本或未交付的本机依赖
- **AND** 本机认证及传输 MUST 使用当前 Buildr 宿主（Host），不要求额外启动智能体服务（Agent Service）进程

#### Scenario: 单独验证智能体服务的核心行为
- **WHEN** 维护者验证统一对话、交付或停止状态
- **THEN** `buildr-agent` MUST 能以替身执行者（Executor）和显式宿主端口验证自身行为，不要求启动 Buildr Web 或调用真实模型
- **AND** 实际安装验证 MUST 另行覆盖宿主装配、运行依赖及三家真实接入，不能由核心单元验证代替

### Requirement: 统一对话必须通过执行者契约调用实际工作能力

公共对话、交付、存储和事件契约 MUST 面向执行者（Executor）的稳定身份、能力声明、会话（Session）创建与恢复、输入交付、状态观察、请求回应及中断，不绑定 Codex、DSH、Qoder 的封闭枚举或命令行（CLI）传输假设。具体程序路径、厂家配置、协议编号及私有恢复资料 MUST 由对应实现解释；公共层保留准确来源和绑定，不能将一种厂家的结构解释为其他执行者（Executor）的上下文。

第一版实际装配及界面可选项 MUST 只包含具备已验证适配并通过当前版本系列及实际协议检查的 Codex、DSH、Qoder。执行者（Executor）标识可扩展 MUST NOT 意味着任意标识可执行；未注册、未装配、能力不支持或当前不可用 MUST 局部拒绝相应操作并保留对话，不自动回退或伪造成功。未来自研 Buildr 智能体（Agent）若实施 MUST 作为另一个执行者（Executor）满足同一公共契约，可以采用自身运行与恢复方式，不要求伪装成外部命令行（CLI）。本变更 MUST NOT 建立自研推理循环、动态插件市场、自动团队或尚不存在的 Buildr 执行选项。

#### Scenario: 发送目标只有标识而没有可用实现
- **WHEN** 请求引用未装配的执行者（Executor），或已装配实现没有支持该操作的实际能力
- **THEN** 公共服务 MUST 在产生该操作副作用前返回准确不可用原因，并保留用户输入和既有绑定
- **AND** MUST NOT 根据标识字符串猜测启动命令、改投默认厂家或创建假的参与记录

#### Scenario: 验证不采用外部命令行的执行契约
- **WHEN** 使用符合公共契约的测试替身验证创建、发送、观察、中断和恢复
- **THEN** 公共对话及事件处理 MUST 不要求该替身提供厂家命令行（CLI）进程、程序路径或某一家专属配置结构
- **AND** 测试替身 MUST 仅用于验证职责边界，不能注册为面向用户的自研 Buildr 智能体（Agent）或据此宣称未来能力已经实现

### Requirement: 三家接入必须使用明确的原生执行路径

Buildr MUST 通过 Codex `app-server`、DSH `web` 完整宿主（Host）及其官方客户端（Client）、Qoder 官方软件开发工具包（SDK）与配套 `qodercli` 提供新接入。接入 MUST 核对实际程序来源、兼容版本及所需协议能力，不以桌面窗口正在运行作为前提。系统 MUST 保留各家模型执行、工具选择及原生会话（Session）恢复责任，不以模型接口替代完整原生执行能力。

#### Scenario: 桌面应用未运行
- **WHEN** 用户选择已安装且通过兼容检查的原生接入
- **THEN** Buildr MUST 能按该接入方式启动自有原生执行环境，不要求打开厂家桌面窗口
- **AND** MUST 准确报告程序不可用、版本不兼容或协议能力不足的具体接入，不阻止其他可用接入

#### Scenario: 程序版本发生变化
- **WHEN** 已登记程序的实际来源或版本与已验收记录不同
- **THEN** Buildr MUST 重新核对受影响的兼容能力；同一程序来源及独立配置内的系列兼容更新 MUST 保留连接、账号、参与者和原生上下文编号，不因程序文件或完整版本变化要求重新登录
- **AND** 跨系列更新或实际协议不兼容 MUST 局部拒绝，保留旧对话及原生身份
- **AND** MUST NOT 仅根据品牌相同就向新的不明配置恢复旧原生编号

### Requirement: 每家使用独立且按应用配置域隔离的配置

第一版每个应用配置域（Profile）内每家 MUST 使用一套 Buildr 独立配置，通过用户已有的厂家账号登录。正式版、开发版及预览环境 MUST 使用各自已解析的本机数据根，不共享或自动复制外部桌面配置、凭据和历史。连接身份 MUST 绑定提供者、程序来源、准确配置目录及配置来源身份；普通模型选择 MUST NOT 被当作账号来源改变。接入 MUST 不要求新建厂家账号，也 MUST 不提供共享配置、多账号池或通用自带密钥（BYOK）中心。

#### Scenario: 同一接入用于不同工作空间
- **WHEN** 用户在同一应用配置域（Profile）中切换已登记工作空间（Workspace）
- **THEN** 已建立的厂家连接 MUST 可以继续使用，每段对话仍保存自己的归属及执行位置
- **AND** MUST NOT 为每次页面切换重新登录或复制凭据

#### Scenario: 开发预览验证接入
- **WHEN** 隔离预览环境建立新的厂家连接
- **THEN** 登录、配置、历史及接入记录 MUST 只进入该预览的私有数据根
- **AND** MUST NOT 修改正式版、开发版日常实例或外部桌面应用的配置

#### Scenario: 配置目录被替换
- **WHEN** 保存的配置来源与当前实际来源不匹配
- **THEN** 相关恢复或发送 MUST 返回明确诊断并保留原绑定
- **AND** MUST NOT 把旧原生编号转交其他目录或自动创建替代上下文

### Requirement: 官方登录必须表达独立的尝试与实际账号状态

Buildr MUST 使用各家公开支持的官方登录路线，由后端持有准确登录尝试（Attempt），前端仅观察安全状态并打开官方授权页面。状态 MUST 区分初始化、等待浏览器、成功、取消、超时和失败；完成后 MUST 分别核对账号及模型可用性。目录存在、凭据文件存在或登录进程退出 MUST NOT 单独证明账号与模型可用。前端关闭 MUST 不自动取消登录或退出账号，取消和重试 MUST 作用于准确尝试。

#### Scenario: DSH 登录地址稍后产生
- **WHEN** 原生登录开始只返回初始化状态，稍后才提供授权地址
- **THEN** Buildr MUST 继续观察同一尝试并在地址可用后展示登录入口
- **AND** 宿主退出导致尝试丢失时 MUST 如实报告失效，不显示为可直接恢复的待授权登录

#### Scenario: 登录过期
- **WHEN** 原生账号状态明确要求重新登录
- **THEN** Buildr MUST 保留连接身份、对话及原生历史，提供该独立配置的官方重新登录
- **AND** MUST NOT 自动切换账号或重发失败前可能已被接收的指令

#### Scenario: 旧登录尝试迟到
- **WHEN** 已取消或被替代的登录尝试返回成功或失败事件
- **THEN** Buildr MUST 按准确尝试身份核对结果，不覆盖当前尝试的状态

### Requirement: 可用模型和权限必须按真实接入能力呈现

模型目录 MUST 保留实际默认模型、逐模型支持的思考深度（Reasoning Effort）及其默认值。发送 MUST 在副作用前校验当前模型与显式档位的合法组合；原生适配 MUST 每轮明确采用本轮选择或该模型真实默认值，MUST NOT 静默继承另一模型或执行方的旧档位。本轮实际模型与档位 MUST 可持久恢复；不支持该能力时 MUST 不虚构可用选项。

Buildr MUST 从准确连接读取实际可用模型及输入、授权、提问、停止和恢复能力，并按固定版本组合验收。默认 MUST 使用已声明的独立对话默认策略：Codex 为 `on-request` 与 `workspace-write`，DSH 为原生目录给出的默认权限预设，Qoder 为软件开发工具包（SDK）的 `default`。用户 MUST 可以为当前对话显式选择已被该接入声明支持的完全访问模式。该模式 MUST 映射厂家原生的免逐次工具审批设置，不能以自动回答所有原生请求冒充。各家的工具许可与操作系统隔离语义 MUST 分别准确说明，不因界面名称一致就宣称隔离等价。模型选择带来的原生配置副作用 MUST 准确说明；不支持的能力 MUST 明确不可用，不能由模拟成功代替。

#### Scenario: 完全访问与业务提问分离
- **WHEN** 用户显式选择某接入支持的完全访问模式并发送
- **THEN** 适配器 MUST 在准确本轮执行开始前应用该家真实原生权限参数，正常工具操作不再要求逐次授权
- **AND** 补充业务信息的问题 MUST 继续交给用户；未知原生交互 MUST NOT 因完全访问而自动批准或代答
- **AND** 辅助标题生成 MUST 保持原隔离限制，旧一次生成与外部桌面配置 MUST 保持不变

#### Scenario: 从完全访问恢复默认权限
- **WHEN** 用户将下一轮模式改回默认权限，或换回曾以完全访问执行的原生上下文
- **THEN** 适配器 MUST 根据本次明确模式重新应用原生策略，MUST NOT 因原生上下文粘性设置继承上一轮完全访问
- **AND** 仅切换选择 MUST NOT 改变正在执行的权限、回答既有授权或触发新执行

#### Scenario: 执行者不支持所选权限模式
- **WHEN** 当前接入未声明或无法实际应用完全访问
- **THEN** 系统 MUST 在工作输入产生副作用前局部拒绝，保留选择、草稿与原有上下文
- **AND** MUST NOT 静默降为默认、自动切换执行者或修改全局账号配置

#### Scenario: 切换模型后再次发送
- **WHEN** 用户在同一原生上下文切换到思考深度（Reasoning Effort）目录不同的模型
- **THEN** 系统 MUST 清除不兼容的旧选择，发送前采用当前模型合法选择或真实默认值
- **AND** 刷新和原生恢复后 MUST 能读回本轮模型与档位，而不是将界面默认显示当成实际生效证明

#### Scenario: DSH 修改默认模型
- **WHEN** DSH 原生模型选择同时保存该独立配置的默认值
- **THEN** Buildr MUST 说明其对该连接后续使用的影响
- **AND** 外部桌面配置和其他提供者连接 MUST 保持不变

#### Scenario: 所选模型不支持图片或交互方式
- **WHEN** 用户请求当前版本或模型不支持的输入或操作
- **THEN** Buildr MUST 在发送前明确限制并保留用户文本及输入材料
- **AND** MUST NOT 默默丢弃图片、伪造授权选项或改投另一家

### Requirement: 工作目录与规则技能发现不得被误作访问边界

原生执行 MUST 使用对话保存的准确工作目录（CWD），沿用适用的规则（Rule）、技能（Skill）发现与原生权限。工作空间（Workspace）归属及起始目录 MUST NOT 被定义为全部文件访问边界；跨目录操作 MUST 遵守实际权限和目标位置的适用约束。独立配置未包含的用户级技能、工具连接或桌面扩展 MUST 如实表达，不能声称自动继承桌面全部能力。

#### Scenario: 从 Buildr 工作空间访问另一目录
- **WHEN** 用户要求处理另一已授权目录中的文件
- **THEN** 原生智能体（Agent）MUST 能按实际权限读取并处理该位置，重新核对目标规则与当前文件
- **AND** 对话所属工作空间（Workspace）MUST 不因文件位于别处而自动改变

#### Scenario: 用户级能力未包含在独立配置
- **WHEN** 新连接没有外部桌面配置中的某项技能（Skill）或工具连接
- **THEN** Buildr MUST 显示准确缺口及适用配置入口
- **AND** MUST NOT 自动复制整套桌面配置或据此否定其他可用工作

### Requirement: 原生进程必须按拥有关系和真实存活状态管理

Buildr MUST 只管理本接入创建且身份可证明的原生进程与连接。浏览器关闭 MUST 不等于 Buildr 后端退出；断开接入 MUST 停止其新请求并释放本连接资源，但不能被解释为账号退出、历史删除或活动命令已经停止。后端退出 MUST 有界处理中断与自有资源释放，保留未确认执行的状态；第一版 MUST 不承诺后端退出期间活动工作持续运行。旧进程退出未确认时 MUST 不启动会造成同一执行重复运行的替代进程。

#### Scenario: 前端关闭后重新打开
- **WHEN** 对话页面关闭而 Buildr 后端及原生执行仍在运行
- **THEN** 重新打开 MUST 能观察原执行及其待回应事项，不因页面关闭创建第二次执行

#### Scenario: 断开存在活动执行的接入
- **WHEN** 用户断开正在执行或等待回应的接入
- **THEN** Buildr MUST 保留对话与已有成果，并准确表达中断、仍有活动工具或状态未知的观察
- **AND** MUST NOT 显示未经确认的“已停止”，也不能关闭外部桌面应用或其他连接的工作

#### Scenario: 后端重启发现未确认执行
- **WHEN** 后端恢复后发现上次执行未有确认终态
- **THEN** Buildr MUST 先恢复准确配置并观察原生状态与历史
- **AND** MUST NOT 仅凭原进程号不存在或传输连接断开自动重发上一条指令

### Requirement: 私有交互存储必须与工作资产及原生上下文分离

新接入 MUST 在当前应用配置域（Profile）的 `dataRoot/agent-service/` 中保存私有交互库及厂家独立配置。私有库 MUST 仅保存连接索引、统一可见对话及内部关系、执行和交付尝试等交互事实，不复制任务（Task）状态、工作资产（Work Asset）或原生隐藏上下文。账号凭据及原生恢复数据 MUST 由各家准确配置保管。业务记录、必要图片、原生配置及诊断 MUST 保持本机私有并排除版本管理和自动同步；存储损坏或版本超前 MUST 保留现场并局部报告，不自动删除重建。

#### Scenario: 初始化新交互库
- **WHEN** 当前应用配置域（Profile）首次建立内部对话
- **THEN** 交互数据 MUST 写入该配置域私有存储，不创建或迁移工作空间（Workspace）的任务及业务事实
- **AND** 原有接入索引和外部会话关系 MUST 保持不变

#### Scenario: 存储升级失败
- **WHEN** 私有交互库升级或事务写入失败
- **THEN** 本次未完成变更 MUST 回滚，已有可读历史及原生配置 MUST 保留
- **AND** MUST NOT 用原生日志猜测重建全部 Buildr 事实或改写工作空间数据库

### Requirement: 本机通信和诊断不得泄露认证秘密

新命令、历史及服务端事件流（SSE）MUST 使用当前本机应用的同源与会话认证，校验目标连接、工作空间（Workspace）和对话身份。原生账号令牌、Cookie、子进程通信秘密及敏感配置 MUST NOT 进入前端事件、公共错误、可见对话或普通诊断导出。官方登录地址仅可作为当前登录动作的受控导航，不得记录其敏感查询参数或成功回调内容。原生诊断目录 MUST 按敏感状态保护，不能因 Buildr 日志已脱敏就声明其可公开。

#### Scenario: 未认证订阅对话事件
- **WHEN** 请求缺少有效本机会话认证或来源不符合当前应用边界
- **THEN** Buildr MUST 拒绝读取对话事件和提交控制动作
- **AND** MUST NOT 把认证秘密放进事件流查询参数作为绕过方式

#### Scenario: 原生错误包含认证信息
- **WHEN** 原生返回值、日志或登录回调带有秘密
- **THEN** 前端与可共享诊断 MUST 只呈现脱敏后的相关错误和下一步
- **AND** 必须保留的原生敏感文件 MUST 留在本机私有范围

### Requirement: 新接入必须与既有一次生成和外部会话关联并存

新接入 MUST 使用独立身份、配置、接口及数据，不扩展、迁移或双写旧 `agent-operations`、`native-session-links` 与桌面桥。旧一次生成的默认选择、临时上下文、只读或禁用工具策略及串行队列 MUST 继续只约束其原用途，不能作为新持续对话的统一执行策略；旧外部关系 MUST 继续按原协议查看、解除与准确打开。新增能力 MUST 不改接提交说明、“提出新目标”等既有动作。

#### Scenario: 新对话切换执行方
- **WHEN** 用户在内部对话中选择另一家接入
- **THEN** 旧一次生成默认选择、外部桌面关联及进行中请求 MUST 保持不变

#### Scenario: 原提交说明生成继续使用
- **WHEN** 用户调用既有提交说明生成入口
- **THEN** 该入口 MUST 沿用既有调用、权限与结果行为
- **AND** MUST NOT 因新接入存在而创建持久内部对话
