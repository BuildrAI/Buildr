## MODIFIED Requirements

### Requirement: Buildr Web 必须提供可扩展的 React Web 客户端并保持行为等价
Buildr Web 客户端 MUST 以 React 实现，源码 MUST 位于 `product/buildr-web` Service 的前端工程根，并 MUST 通过构建产物由本机 Buildr Web HTTP interface（归属 `product/buildr`）同源托管。用户可观察的**已挂载路由 path 与功能交互** MUST 保持等价，包括工作空间列表、开始/设置、任务列表与详情页签、Task-scoped Change、项目、服务、文章、Agent Action 抽屉、退出应用与 preview 身份条；视觉呈现、布局密度与动效 MAY 在经确认的 UI 重设计范围内变化，且 MUST NOT 被解释为对路由或功能交互等价的破坏。客户端 MUST NOT 直连 SQLite、manifest 或文件系统 path，MUST NOT create Task，也 MUST NOT 在页面内执行专业任务。新增内部对话 MUST 经受保护的本机应用接口（API）委托原生智能体（Agent）执行，并显示真实执行事件、请求用户回答或授权；前端 MUST NOT 自行实现推理或工具执行循环，也 MUST NOT 绕过现有应用（Application）直接写入任务（Task）或工作资产。

#### Scenario: 生产托管 React shell
- **WHEN** 用户通过 `buildr web`、已安装 npm CLI 启动的本机应用或官方/开发 launcher 打开 Buildr Web
- **THEN** HTTP interface MUST 返回来自构建产物的应用 shell
- **AND** 页面 MUST 成功读取注入的本机 session meta 并加载同源静态资源

#### Scenario: 路由行为等价
- **WHEN** 用户访问既有 Workspace 深链或全局路由
- **THEN** React 客户端 MUST 渲染对应功能视图
- **AND** MUST NOT 要求用户学习新的 URL 方案作为 UI 重设计条件

#### Scenario: 产品边界保持
- **WHEN** 用户在 React Buildr Web 中操作 Task、Project、Service 或 Agent Action
- **THEN** 既有页面动作 MUST 继续只维护允许的低风险 metadata 或生成 Agent prompt；新增内部对话 MUST 仅通过明确的发送、回答、授权或停止操作委托原生智能体（Agent）执行
- **AND** MUST NOT 创造第二套 Task writer 或绕过 Application

#### Scenario: 前端源码根位于 buildr-web
- **WHEN** 维护者检查 Buildr Web React 源码位置
- **THEN** 权威源码根 MUST 为 `projects/product/services/buildr-web`
- **AND** MUST NOT 将 `projects/product/services/buildr/web` 继续作为权威前端源

#### Scenario: 视觉重设计不改变功能交互契约
- **WHEN** Buildr Web 完成经确认范围的视觉/布局/动效重设计
- **THEN** 既有功能步骤（打开工作空间、浏览项目/服务/文章、查看任务与 Agent Action）MUST 仍可在相同路由 path 下完成
- **AND** MUST NOT 以外观或 class 名变化为由要求新的 API、session 或产品能力

#### Scenario: 内部对话委托原生执行
- **WHEN** 用户在内部对话明确发送指令或回应原生执行请求
- **THEN** 客户端 MUST 通过受保护的本机应用接口（API）提交准确对话及请求身份，并显示实际反馈
- **AND** 原生智能体（Agent）对任务（Task）或工作资产的专业操作 MUST 继续使用各自现有能力及授权边界，页面 MUST NOT 成为第二套任务写入者
- **AND** 既有提交说明生成、外部桌面会话与 Agent Action MUST 保持各自原有入口和行为

### Requirement: Buildr Web 壳层必须采用上下结构
Buildr Web 应用壳（App Shell）MUST 在顶部保留品牌、共同工作空间范围及原有交给 Agent 操作；桌面全局对话入口 MUST 收拢到对话侧边图标和面板控制，顶部 MUST NOT 重复呈现，窄屏 MUST 保留可达入口；“工作台”“工作空间”和“代码”三个一级区域 MUST 依次放在原工作区左侧始终可达的竖向图标列中。选定范围的三个区域 MUST 共享相同 workspaceId。三个区域 MUST 共享同一套中屏页面页签与右屏，一级区域入口切换 MUST NOT 清空或替换已打开页签。工作台 MUST 提供概览与任务入口；工作空间 MUST 使用对应二级导航承载总览、项目、服务、代码库、连接、技能和文章七个平级入口，导航标签 MUST 使用中文，七个入口 MUST 采用一致的行式呈现（图标 + 文案、相同行高），MUST NOT 在左侧导航内展开项目树或所属服务列表。项目详情与服务详情 MUST 保留右上角编辑入口；视觉 token、Ant Design 5 与离线 CSP 边界 MUST 保持既有约束。

三个区域的内容区 MUST 采用同一套双栏组页签模型，二级菜单 MUST 默认收起；收起时悬停一级图标 MUST 在图标列旁浮出对应二级导航，移入后可继续操作，移出后收回，并支持显式固定展开和收起。一级入口与二级导航 MUST 支持键盘及触屏使用，不依赖悬停才能到达。导航 MUST 独立于中间页面、右侧资料和对话的收起状态；代码区域的资源管理器 MUST 使用单独约 280px 的文件树窄栏及剩余宽度的文件阅读区，MUST 独立保存目录宽度，MUST NOT 继承普通列表或详情的默认均分比例。代码区域左侧 MUST 提供资源管理器和源代码管理两个菜单；源代码管理 MUST 展示真实全部登记实例的分层改动、本机提交历史与文件阅读，读取失败及未知状态明确可辨，不伪造改动或历史结果。

三个区域的双栏规则保持：
- 中屏 MUST 为已打开的目录、工作台概览与任务、工作空间总览、项目主页、适用知识页面及代码区域的资源管理器与源代码管理提供可复用的页面标签；从菜单或一级区域入口打开页面 MUST 新建或激活对应标签，并将激活标签置于中屏首位，其余标签保持相对顺序顺延。服务详情、代码库详情、技能详情、文章详情及服务知识 MUST 继续使用副屏，不新增详情主标签；页面标签支持关闭并保留同工作空间现场。关闭最后一个页面标签时 MUST 按当前所在一级区域入口补开默认标签：工作台补开概览，工作空间补开工作空间总览，代码补开源代码管理。
- 右组 MUST 跟随当前中屏页面标签并只展示该标签注册的对象级页签：在项目全景、服务全景或代码页内点开文档、变更等对象时，MUST 在右组以页签就地展开，MUST NOT 跳离当前领域页面；切换中屏标签 MUST 切换为该标签的右组内容，没有右组内容时右组 MUST 退场；页面标签关闭时 MUST 一并关闭该标签注册的右组对象页签，右组页签全部关闭时右组 MUST 退场，中屏恢复独占。
- 两组在并排完整展开时 MUST 以贯连的分隔线连接，MUST 支持拖拽调整右组宽度；两组的页签条在分隔线处 MUST 视觉连通；两组内容区 MUST 各自独立滚动。区域收起与暂看 MUST 使用共享内容区的竖向标签和浮窗规则，不关闭已有对象。
- 左组的项目、服务、代码库、技能、文章与任务目录以及工作空间总览、项目主页及组成、知识页面 MUST 铺满可用主区域并保留两侧留白；标题、搜索和表格 MUST 共享对齐边界，打开右组后目录 MUST 填满剩余左组空间，关闭右组或折叠侧栏后 MUST 自动利用新增空间；工作台概览外框 MUST 同样利用可用主区域；长篇正文及表单内容 MUST 独立保持适合阅读的宽度上限，技术图、代码地图和宽表格 MUST 利用内容区可用空间；右组打开且两组完整并排、没有已保存手动比例时，左右两组 MUST 均分信息区可用宽度（不含左侧导航及中间分隔线）；已保存手动比例时 MUST 优先恢复该比例。
- 既有修改项目、修改服务与交给 Agent 等动作 MUST 统一在抽屉层完成，抽屉 MUST 采用一致的壳结构（标识行、标题、副标题、关闭与底部状态区）。
- 壳层与内容区 MUST 使用统一的白底，不得以不同区域底色分割主要分区。

一级图标 MUST NOT 因当前浏览路由显示深色选中背景；悬停预览和固定二级导航时 MUST 使用原选中底色联动对应一级组，不使用小点或线标；收起时鼠标点击一级图标 MUST NOT 跳页或固定；固定展开时 MUST 停止悬停预览，点击其他一级图标 MUST 直接切换固定组，重复点击当前组 MUST 保持展开，固定状态仍由原收起按钮关闭。二级导航浮窗或固定面板 MUST 明确其区域名称，已有内部语义分组及菜单项的当前选择 MUST 保持。对话是原工作内容区之外的独立面板，MUST NOT 改写原中屏及右屏的页签、对象归属和折叠规则。

#### Scenario: 顶栏承载主导航
- **WHEN** 用户在选定 Workspace 中切换工作台、工作空间和代码
- **THEN** 原工作区左侧图标列 MUST 依次呈现“工作台”“工作空间”“代码”，保持同一工作空间范围
- **AND** 工作台 MUST 默认展示日常概览，并保留任务入口；工作空间 MUST 展示工作空间内容
- **AND** 工作台与工作空间业务菜单 MUST NOT 混入环境维护分组；智能体（Agent）账号配置 MUST 通过独立入口打开，不替代任何业务菜单

#### Scenario: 收起时一级图标预览对应二级导航
- **WHEN** 二级导航收起，鼠标悬停工作台、工作空间或代码图标
- **THEN** MUST 显示其真实二级导航，移开后收回；鼠标点击一级图标 MUST NOT 跳转或固定页面

#### Scenario: 固定导航通过一级图标直接切组
- **WHEN** 二级导航已固定展开，用户悬停或点击其他一级图标
- **THEN** 悬停 MUST NOT 打开临时浮层或替换固定组；点击 MUST 一次切换对应固定二级菜单，并联动一级选中底色及保存所选组
- **AND** 重复点击当前组 MUST 保持展开；键盘及触屏 MUST 可切组；原工作页签、当前网址及菜单宽度 MUST 保留
- **AND** 使用原按钮收起后 MUST 恢复悬停预览
- **AND** 用户点击浮层的展开按钮时 MUST 固定该组并联动一级组标记，已有页面页签及中右工作屏 MUST 保持
- **AND** 键盘和触屏 MUST 有明确的等价展开入口

#### Scenario: 顶部入口打开或聚焦默认页签
- **WHEN** 用户从对应二级导航选择概览、工作空间总览或代码页面
- **THEN** 系统 MUST 激活已打开的目标页签，没有时打开对应目标，代码页保持上次有效入口或源代码管理
- **AND** 已打开的其他页面页签 MUST 保持；一级入口已移至竖向图标列，其鼠标点击 MUST NOT 触发该页面切换

#### Scenario: 进入 Workspace 直接打开任务列表
- **WHEN** 用户进入可用 Workspace、点击品牌或切换工作空间
- **THEN** MUST 打开该 Workspace 的工作概览，不因此固定导航或改变一级图标背景
- **AND** `/workspaces/:workspaceId/` MUST 重定向到工作概览，`/workspaces/:workspaceId/overview` MUST 直接展示概览；既有 `/tasks` 深链保持

#### Scenario: 平级领域导航
- **WHEN** 用户查看工作空间左侧导航
- **THEN** MUST 呈现总览、项目、服务、代码库、连接、技能、文章七个平级入口，行式一致
- **AND** MUST NOT 在导航内展开项目树或项目所属服务列表
- **AND** 当前领域入口 MUST 有可辨认的选中态

#### Scenario: 收起后的对话可临时操作
- **WHEN** 用户悬停已收起的对话图标
- **THEN** MUST 临时显示同一对话并支持输入、历史、选择执行者、发送及回答授权，自己的下拉浮层 MUST 保持可用
- **AND** 点击对话图标或固定展开按钮 MUST 固定展开，收起按钮 MUST 位于标题栏右侧
- **AND** 临时与固定展示间切换 MUST 保留草稿、当前对话及实际执行；创建的迟到回执 MUST NOT 覆盖较新的收起意图

#### Scenario: 选项与停靠宽度一致
- **WHEN** 用户调整停靠对话宽度或选择执行者、模型和思考档位
- **THEN** 停靠宽度 MUST 限制在320–800px，正文与输入栏 MUST 使用该宽度，不附加产生空白的较小居中容器
- **AND** 智能体（Agent）与模型 MUST 使用两个独立选择器，先选择执行方再选择该执行方的模型；更换执行方 MUST 使用其默认模型并清除原模型及档位，更换模型 MUST 清除不适用档位，选择本身 MUST NOT 创建或发送执行；权限与附件 MUST 位于输入栏左侧，智能体（Agent）、模型、实际支持的思考档位和发送 MUST 位于右侧；选择器 MUST 使用一致的行高、清晰文字、背景和交互状态，菜单开合 MUST NOT 改变输入栏高度，窄屏按完整控件自然换行，不截断正常名称或添加重复说明前缀；账号配置 MUST 从对话内部打开

#### Scenario: 页面级页签生命周期
- **WHEN** 用户从菜单或一级区域入口打开工作台概览、任务、目录、工作空间总览、项目主页、适用知识页面、资源管理器或源代码管理
- **THEN** 中屏 MUST 新建或激活对应可复用页面标签，并将该标签置于首位，已打开的页面同样 MUST 能通过标签恢复
- **AND** 点击既有标签 MUST 恢复对应页面现场，关闭最后一个页面标签 MUST 按当前所在入口补开默认标签
- **AND** 页面级标签集合 MUST 在同一工作空间内跨页面和三个一级区域入口之间保持

#### Scenario: 项目与服务上下文导航
- **WHEN** 用户从项目目录或服务目录选择项目或服务
- **THEN** 项目 MUST 打开可复用主标签，服务 MUST 使用同类复用副屏并保留目录
- **AND** 左侧导航 MUST 保持平级入口且正确标记当前领域，不展开项目树或所属服务列表

#### Scenario: 独立展开与折叠
- **WHEN** 用户在全景内点开或关闭某个文档、变更对象
- **THEN** MUST 只在右组打开或关闭对应对象页签，不跳转当前页面
- **AND** 关闭对象页签 MUST NOT 影响中屏全景的选中与滚动状态；仅收起区域 MUST 保留对象页签、内容及未保存输入
- **AND** 页签与关闭控件 MUST 支持键盘操作并提供可访问名称

#### Scenario: 领域内对象在右组就地展开
- **WHEN** 用户在项目主页打开文档或服务，或在服务副屏打开文档与变更
- **THEN** 主屏项目或目录 MUST 保持；项目文档在右组标签展示，服务下级资料在原副屏位置阅读且可返回
- **AND** 关闭全部右组标签 MUST 恢复原工作内容主区域，不在该工作内容区新增第三分屏；独立对话面板的开关 MUST 保持

#### Scenario: 右屏跟随当前中屏页签
- **WHEN** 用户切换中屏页面标签或关闭一个页面标签
- **THEN** 右组 MUST 切换为当前页面标签注册的对象页签；当前页面标签没有右组内容时右组 MUST 退场
- **AND** 关闭页面标签 MUST 一并关闭该标签注册的右组对象页签，其他页面标签的右组页签 MUST 保留

#### Scenario: 贯连分隔线可调宽
- **WHEN** 右组存在、两组完整并排且用户拖拽两组之间的分隔线
- **THEN** 右组宽度 MUST 随拖拽在允许区间内调整
- **AND** 分隔线 MUST 贯通内容区高度，并在页签条高度处与两条页签条视觉连通
- **AND** 悬停与拖拽时分隔线 MUST 有可辨认的强调态

#### Scenario: 详情保持通栏
- **WHEN** 用户从服务或文章目录进入详情
- **THEN** 详情 MUST 在副屏展示并保留来源目录；为详情增加可用宽度时 MUST 可收起中间页面并复用同一详情内容
- **AND** 当前区域的左侧导航 MUST 保持可达

#### Scenario: 项目与服务路由保持
- **WHEN** 用户通过 URL 直接访问项目或服务的详情及编辑地址
- **THEN** MUST 保留既有 `/projects`、`/projects/:projectCode`、`/services`、服务详情及编辑路由
- **AND** MUST NOT 改变项目和服务的身份、归属或关联语义

#### Scenario: 项目新增入口
- **WHEN** 用户点击项目目录的创建入口
- **THEN** MUST 打开既有项目创建指令交互（抽屉），不直接创建源资产

#### Scenario: 任务页宽屏并排列表与详情
- **WHEN** 用户在宽屏打开任务列表或详情
- **THEN** 工作台内容区 MUST 分别提供完整列表与独立详情，打开详情不得自动选择其他记录；返回 MUST 保留查询范围、分组与已浏览位置
- **AND** `/tasks` 与 `/tasks/:taskId` 路由 MUST 保持不变

#### Scenario: 任务页窄屏避免横向溢出
- **WHEN** viewport 宽度为 390px 且用户打开任务详情
- **THEN** 详情 MUST 可见并可操作
- **AND** 页面主容器 MUST NOT 横向溢出
- **AND** 任务列表与详情 MUST 各自可独立浏览；关联资料在宽屏并排阅读、空间不足时使用可关闭阅读层

#### Scenario: 项目页宽屏并排列表与详情
- **WHEN** 用户在宽屏打开项目目录或项目主页
- **THEN** 项目主页 MUST 使用可复用主标签，展示项目简介、工作入口、文章与知识、关联服务和项目资料
- **AND** 文档与服务 MUST 在副屏打开并保留主页
- **AND** `/projects` 与 `/projects/:projectCode` 路由 MUST 保持不变

#### Scenario: 项目页窄屏避免横向溢出
- **WHEN** viewport 宽度为 390px 且用户打开项目主页
- **THEN** 详情 MUST 可见可操作且主容器无横向溢出
- **AND** 副屏在并排空间不足时 MUST 使用可关闭阅读层，关闭恢复主内容

#### Scenario: 列表筛选保持一行
- **WHEN** 用户打开任务列表或项目、服务目录
- **THEN** 搜索与筛选控件 MUST 出现在标题下方的同一工具行
- **AND** MUST NOT 使用独立竖排筛选表单卡作为默认布局

#### Scenario: 服务菜单名称
- **WHEN** 用户查看工作空间导航
- **THEN** 服务集合入口 MUST 显示“服务”，继续使用原有 `/services` 路由
- **AND** 本次 MUST NOT 改变项目和服务的身份、归属或关联语义

#### Scenario: 窄屏降级
- **WHEN** 可用容器宽度不足以并排阅读且打开右组
- **THEN** 副屏 MUST 使用可关闭、可键盘返回的覆盖式阅读层，关闭后恢复原主屏
- **AND** viewport 宽度为 390px 时主要操作 MUST 可见，页面不得横向溢出

#### Scenario: 克制的视觉反馈
- **WHEN** 用户悬停、聚焦或操作导航、页签与分隔线
- **THEN** MUST 能辨认可操作目标与当前选择，正文阅读区域 MUST 保持清晰层级
- **AND** 减少动态效果偏好 MUST 被尊重，装饰动效 MUST NOT 延迟内容或阻止操作

#### Scenario: 工作空间浏览状态持续
- **WHEN** 用户拖动页面标签或分隔线后重新进入同一工作空间
- **THEN** 浏览器存储可用时 MUST 恢复该工作空间的标签顺序和手动分屏比例
- **AND** 其他工作空间 MUST 使用各自偏好，窗口缩放导致的临时尺寸修正 MUST NOT 覆盖保存的比例
- **AND** 存储不可用或内容损坏 MUST NOT 阻止浏览

#### Scenario: 保持已打开页面
- **WHEN** 用户切换已访问标签或暂时进入工作台再返回
- **THEN** 已打开页面 MUST 保留滚动、筛选、草稿和页面内容，不因切换、收起或暂看清空页签栏或重复整页加载
- **AND** MUST NOT 按隐藏时长自动释放页面；显式关闭或切换工作空间 MAY 释放

#### Scenario: 标签拖动反馈
- **WHEN** 用户拖动页面标签调整顺序
- **THEN** 标签 MUST 跟随指针，相邻标签 MUST 平滑让位并在松手后落位，拖动 MUST NOT 触发页面切换
- **AND** MUST 支持键盘排序和关闭，减少动态效果偏好下 MUST 取消非必要动画

#### Scenario: 项目内服务直接打开主屏主页
- **WHEN** 用户在项目主页点击服务卡片或访问旧服务详情地址
- **THEN** MUST 按登记身份在副屏打开或复用服务详情，MUST NOT 新增服务主标签
- **AND** 项目主页及已有文档现场 MUST 保留；旧地址无法解析时 MUST 显示局部错误而不猜测身份

#### Scenario: 副分屏默认左右均分
- **WHEN** 用户没有保存手动比例并打开副分屏
- **THEN** 左右并排时两组 MUST 等宽，缩放窗口后仍 MUST 等宽
- **AND** 用户 MUST 可以拖动调整并保存工作空间（Workspace）比例；关闭全部副分屏标签后主屏 MUST 恢复全部信息区宽度

#### Scenario: 宽屏资源目录铺满主区域
- **WHEN** 用户在宽屏浏览项目、服务、代码库或技能目录
- **THEN** 标题、搜索与表格 MUST 填满侧栏右侧的可用内容区域并保持两侧留白，不受固定内容上限阻止继续展开
- **AND** 窗口缩窄时 MUST 减少留白并保持搜索与操作可访问，不扩大页面级横向溢出

#### Scenario: 目录与详情并排
- **WHEN** 用户从目录打开详情、拖动分隔线或关闭详情
- **THEN** 目录 MUST 填满当前可用左组区域，搜索和已观察内容 MUST 保持
- **AND** 详情与表单 MUST 保持既有操作行为，长文 MUST 保持适合阅读的宽度约束

#### Scenario: 图表与正文采用不同阅读宽度
- **WHEN** 用户切换知识说明、技术图、代码地图，或展开任务详情
- **THEN** 长文 MUST 保持受限行宽，技术图和宽表格 MUST 能利用可用内容宽度
- **AND** 页面标题和主要操作 MUST 保持对齐，目录及正文 MUST 不叠加重复外层留白

#### Scenario: 窄屏文章目录
- **WHEN** 文章列表所在容器变窄
- **THEN** 项目、稿件状态及更新时间 MUST 在摘要中保持可读，文章及操作 MUST 不依赖横向滚动
- **AND** 原有搜索、筛选、收藏、编辑、查看原文和删除入口 MUST 保持

#### Scenario: 从任意页面进入代码区域
- **WHEN** 用户在任务、项目、文章或其他当前工作空间页面通过“代码”的悬停二级导航选择代码入口
- **THEN** 系统 MUST 激活上次有效的代码页签；没有有效代码页签时 MUST 进入同一工作空间的源代码管理；直接访问 `/code` MUST 使用相同兜底目标，资源管理器 MUST 可由代码区域菜单显式进入，并恢复仍有效的代码库与文件查看状态
- **AND** 左侧 MUST 仅标记当前代码区域菜单，不同时高亮工作空间代码库入口

#### Scenario: 文件树与普通页面宽度独立
- **WHEN** 用户从已调宽的项目详情进入资源管理器
- **THEN** 文件树 MUST 使用自己的保存宽度或约 280px 默认宽度，文件阅读区使用剩余空间
- **AND** 资源管理器中的宽度调整 MUST NOT 改变项目、任务或普通目录的分屏偏好

#### Scenario: 源代码管理分屏
- **WHEN** 用户进入源代码管理并拖动中屏上下或中右边界
- **THEN** 页面 MUST 使用共用分隔组件调整对应尺寸，恢复阅读后保留尺寸与所选文件
- **AND** 提交（Commit）列表 MUST 使用简洁标题及引用、任务（Task）和展开操作，不常驻短提交标识或时间列；完整标识和时间 MUST 通过可选择复制的悬停信息表达，点击记录 MUST 在右屏正式详情展示完整字段、引用、准确任务（Task）入口及不重复标题的正文，详情顶部 MUST 对齐且不留空白占位

#### Scenario: 源代码管理工作树与过滤
- **WHEN** 登记代码库（Repository）具有主目录及多个Git工作树（Worktree），或多个来源显示相同名称
- **THEN** 源代码管理 MUST 在代码库（Repository）内显示全部真实来源名称和状态，各自真实分支（Branch）或完整提交（Commit）标识 MUST 能通过按需信息层及阅读标题核对，代码库（Repository）行即主工作树（Main Worktree）；选择具体来源 MUST 同时控制未提交变更（Uncommitted Changes）和提交历史（Commit History），MUST NOT 按名称聚合或提供独立历史来源过滤
- **AND** 代码库（Repository）目录区域、各来源及比较层 MUST 可折叠，保留有效阅读现场；“未提交变更”和“提交历史” MUST 有清楚选中状态
- **AND** 来源列表 MUST NOT 常驻分支（Branch）摘要列，实际分支（Branch）或完整提交（Commit）标识 MUST 在可选择复制的按需信息层保留，右侧远程、文件及任务（Task）列 MUST 对齐且远程与任务（Task）图标明显区分；完整路径 MUST 按需悬停选择与复制，下方两种模式 MUST 不重复来源栏
- **AND** 主来源及子来源 MUST 使用相同列边界，名称 MUST 利用原分支（Branch）列释放的宽度，数字与无差异标识 MUST 紧凑对齐；右侧阅读标题的完整来源 MUST 仅在点击后于标题下方展开，保留实际路径及分支（Branch）或固定提交（Commit）复制，常规悬停 MUST 不自动显示来源浮窗

#### Scenario: 源代码管理和任务双向关联
- **WHEN** 用户由任务查看全局源码或由明确关联提交查看任务
- **THEN** 两个区域 MUST 仅通过准确来源和返回入口双向关联，原任务“改动与提交”继续在任务内部查看
- **AND** 从任务进入源码 MUST 预选已确认的来源范围，返回 MUST 保留任务标签和文件选择

#### Scenario: 左侧菜单不重复顶部区域名称
- **WHEN** 二级导航收起，用户悬停一级图标或通过键盘、触屏打开该区域导航
- **THEN** 对应二级菜单 MUST 按浮窗展示其真实原有入口与区域名称，临时查看 MUST NOT 改变当前工作页或对话
- **AND** 用户移入浮窗 MUST 能继续操作，移出 MUST 收回；用户 MUST 能固定展开或再次收起导航，一级图标列始终保留
- **AND** 有意义的内部菜单分组、当前菜单项选中状态与窄屏菜单访问 MUST 保持

#### Scenario: 源代码管理图片阅读
- **WHEN** 用户选择所选工作树（Worktree）的可读取图片或固定提交（Commit）中的图片变化
- **THEN** 源代码管理 MUST 在共享阅读壳中按真实比较层显示图像，单侧全宽且不保留不存在版本的占位，双侧宽栏并排、窄栏上下；超限及不支持对象 MUST 保留所在侧和消息，每侧8MiB读取限制明确表达，MUST NOT 用空文字差异（Diff）代替图片
- **AND** 来源、固定完整提交（Commit）及原读取保护 MUST 保持；默认文字、其他二进制、既有完整图片与返回行为 MUST 不变

#### Scenario: 激活页签置首并滚回最左
- **WHEN** 用户在中屏页面组或右屏对象组新开、点击、键盘确认激活、通过导航或程序激活页签，或关闭当前页签后选择后继
- **THEN** 系统 MUST 将被激活页签移至所属组第一位，其他页签保持相对顺序，且只将所属页签条滚到最左
- **AND** 重复点击已激活页签 MUST 同样置首并滚到最左；箭头键仅移动焦点时 MUST NOT 改变激活和排序
- **AND** 各组与各来源页面的对象顺序 MUST 独立保留，切回来源页面或恢复已保存中屏页签时 MUST 使当前激活项在首位；内容身份、草稿、筛选及正文滚动 MUST 保留，页内固定视图页签 MUST NOT 因此重排
- **AND** 手动排序 MUST 继续可用，下一次激活时 MUST 重新将对应项置首

## ADDED Requirements

### Requirement: 全局对话必须独立于业务页面打开
Buildr Web MUST 在全局目录及任意工作空间（Workspace）页面提供同一全局对话入口；打开、关闭、浏览历史或恢复对话 MUST 不要求进入任务（Task），也 MUST NOT 自动发送指令。新对话首次执行前 MUST 确定可用的工作空间（Workspace）及准确起始目录（CWD）；未确定时 MUST 引导用户选择并禁止发送。浏览页面或切换工作空间（Workspace）MUST NOT 静默改变已有对话的归属、起始目录（CWD）或当前执行。

主对话按钮与面板边界 MUST 共用显隐状态并恢复原对话及历史视图；另一段对话新增待回应 MUST NOT 劫持普通展开。待回应提示 MUST 有独立明确的操作入口，只有点击该提示才定位相应目标。边界控件替换为收起／展开形态时 MUST 保留可操作的键盘焦点，手机没有可见侧轨时 MUST 回到全局入口。

#### Scenario: 在全局目录打开对话
- **WHEN** 用户尚未进入工作空间（Workspace）而打开全局对话入口
- **THEN** 界面 MUST 能查看历史或准备新对话；已有对话 MUST 使用其保存的工作空间（Workspace）及目录
- **AND** 未确定执行范围的新对话 MUST 在发送前要求选择可用工作空间（Workspace），不能借用未确认的最近页面范围

#### Scenario: 浏览其他页面继续当前对话
- **WHEN** 用户打开对话后切换业务页面或工作空间（Workspace）
- **THEN** 当前对话身份、保存的归属、目录、历史和草稿 MUST 保持，界面 MUST 明确显示该对话自己的执行位置
- **AND** 新页面内容 MUST NOT 自动作为指令发送，也 MUST NOT 自动替换当前对话

### Requirement: 对话面板必须与原工作双屏独立共存
对话 MUST 默认位于原工作区最右侧，并支持收起、调整宽度、单独展开及移到左侧。移到左侧 MUST 将整个对话面板放在一级图标列之前；对话历史 MUST 在同一面板内替换显示并随面板移动，不新增并排历史栏。打开、关闭、调整或移动对话 MUST 保留原导航、中屏、右屏的页面、对象、折叠状态、滚动、未保存输入与手动宽度偏好。窄窗口 MUST 保持主要操作可达，无页面级横向溢出；关闭临时阅读或展开状态 MUST 恢复原工作现场。

悬停二级导航 MUST 保持工作区完整上下高度并使用紧凑内部间距；固定导航与对话 MUST 复用原有拖动组件及标题栏分隔标记。对话顶部 MUST 只常驻历史、短标题、新建与更多等高频入口，低频位置、账号、专注、停靠及标题操作 MUST 归入对应浮层或更多菜单；底部模型与思考深度（Reasoning Effort）MUST 按真实能力紧凑呈现，不以空白宽度填满输入栏。

#### Scenario: 日常两屏与展开四屏
- **WHEN** 二级导航和对话都收起，且原工作中屏与右屏均打开
- **THEN** 原工作内容 MUST 保持两屏；固定展开二级导航时 MUST 成为三屏，再打开对话时 MUST 成为四屏
- **AND** 用户收起原中屏或原右屏 MUST 仍能保留一块主工作屏，不要求关闭或重建当前对话

#### Scenario: 将对话移到一级目录之前
- **WHEN** 用户选择将对话移到左侧，再移回右侧
- **THEN** 左移时整个对话面板 MUST 位于一级图标列左边，右移时 MUST 位于原工作区右边
- **AND** 对话身份、历史、草稿与原工作屏状态 MUST 保持，移动 MUST NOT 触发执行

#### Scenario: 收起或单独展开对话
- **WHEN** 用户收起对话，或暂时单独展开后返回
- **THEN** 当前执行 MUST 不因界面显隐而停止，原工作页面与编辑现场 MUST 保持
- **AND** 窄窗口中对话输入、停止及关闭入口 MUST 可达，MUST NOT 以强行压缩所有屏幕造成页面横向溢出

### Requirement: 对话历史必须按统一对话组织
历史 MUST 以稳定的 Buildr 对话（Conversation）身份展示主题、时间、必要状态及可选任务（Task）信息，并支持打开、新建、搜索标题、重命名及从最近记录隐藏和恢复。Codex、DSH、Qoder MUST 作为实际参与来源展示，MUST NOT 以厂家拆分同一对话或设置按厂家分类的主历史。隐藏 MUST 不删除历史或停止执行，仍有待回应或未知执行的对话 MUST 保持可发现。

#### Scenario: 多位参与者仍是一条历史
- **WHEN** 同一对话先后由 Codex、DSH 和 Qoder 参与
- **THEN** 历史 MUST 仍以同一标题和身份展示一个条目，参与来源可以辅助说明
- **AND** 打开、重命名或隐藏 MUST 不替换各家的原生会话（Session）绑定

#### Scenario: 隐藏记录中的待回应
- **WHEN** 已从最近记录隐藏的对话出现待回答、待授权或执行状态未知
- **THEN** 用户 MUST 仍能从全局待回应提示或统一历史准确找到它
- **AND** 恢复显示 MUST 保留原记录与任务（Task）关系，不创建替代对话

### Requirement: 任务必须准确创建或打开内部对话

内部对话入口 MUST 在加载、创建和加载动画退出后保持稳定可访问名称，加载状态 MUST 单独表达，MUST NOT 因装饰图标残留而丢失动作身份。

任务（Task）详情 MUST 单独展示内部对话数量和打开入口；没有内部对话时 MUST 创建关联该准确任务（Task）的对话，一个时 MUST 直接打开，多个时 MUST 先让用户选择。一个任务（Task）可以有多个内部对话；第一版一个内部对话 MUST 最多关联创建时选择的一个可选任务（Task）。旧外部原生会话（Session）关系、数量、接口和打开行为 MUST 保持独立；普通对话、新建内部对话及打开动作 MUST NOT 自动创建、激活或推进任务（Task）。

#### Scenario: 加载结束但装饰动画仍未退出
- **WHEN** 任务内部对话读取已完成且按钮可用，但加载图标的退出动画尚未移除
- **THEN** 按钮 MUST 仍以“打开对话”的稳定名称可发现和操作
- **AND** 当前真实加载状态 MUST 与装饰图标生命周期分离，不要求截图、固定等待或手动刷新才能恢复
#### Scenario: 任务尚无内部对话
- **WHEN** 用户点击没有内部对话的任务（Task）的打开对话入口
- **THEN** 系统 MUST 创建并打开关联准确工作空间（Workspace）与任务（Task）的内部对话
- **AND** 输入框 MUST 保持未发送状态，任务（Task）状态 MUST 不变

#### Scenario: 任务只有一段内部对话
- **WHEN** 用户打开具有一段内部对话的任务（Task）
- **THEN** 入口 MUST 直接打开该准确对话，不借用桌面焦点或其他任务（Task）的最近记录

#### Scenario: 任务存在多段内部对话
- **WHEN** 用户点击具有多段内部对话的任务（Task）的打开入口
- **THEN** 系统 MUST 展示可辨认的准确对话列表并按用户选择打开，MUST NOT 默认猜测最近一段
- **AND** 用户 MUST 可以明确另建任务（Task）对话，旧外部会话数量 MUST 不计入此列表

#### Scenario: 旧工作动作继续原职责
- **WHEN** 用户点击提出新目标、继续工作、提交说明生成或外部会话入口
- **THEN** 系统 MUST 保持各自原有行为，MUST NOT 将这些动作改接为普通内部新对话

### Requirement: 账号界面必须表达独立配置与真实状态
账号界面 MUST 为 Codex、DSH、Qoder 各展示一套独立配置的接入状态，使用各家官方登录，并区分程序不可用、尚未登录、等待官方完成、检查中、可使用、登录过期和失败。界面 MUST 以实际检查结果更新，不以目录、凭据存在或登录页面已打开推断成功。第一版 MUST 不提供共享桌面配置切换、多账号池或通用自带密钥（BYOK）配置中心；断开 MUST 明确保留登录、配置及历史，不冒充退出账号或已停止执行。

#### Scenario: 完成登录后检查
- **WHEN** 用户发起官方登录并返回声明已完成
- **THEN** 界面 MUST 继续显示准确登录尝试及账号检查状态，收到真实检查结果后才显示可使用
- **AND** 取消、超时或失败 MUST 保留既有对话和配置，错误只影响相关接入

#### Scenario: 过期后恢复
- **WHEN** 某家账号过期且用户重新登录
- **THEN** 界面 MUST 保留原历史和绑定，检查通过后才允许继续该接入
- **AND** MUST NOT 自动创建替代会话（Session）或重发未知结果的指令

#### Scenario: 断开存在活动执行的接入
- **WHEN** 用户断开仍有未确认活动执行的接入
- **THEN** 对应对话 MUST 呈现执行状态待确认并保留历史与草稿，不能直接显示已停止
- **AND** 其他接入的对话及工作页面 MUST 保持可用

### Requirement: 输入与反馈必须按真实能力呈现并保留草稿
对话 MUST 支持文本、流式回复、基本工具进度、文件改动反馈和错误展示；必要图片输入及模型（Model）选项 MUST 按当前接入版本、账号和模型（Model）的真实能力显示，不支持时 MUST 在发送前明确说明。输入区 MUST 提供当前对话的默认权限与受支持的完全访问选择，说明其仅用于下一轮原生执行；选择本身 MUST NOT 发送、改变活动执行或自动回答业务问题。执行中输入 MUST 仅保留为未发送草稿，不显示成已送达；同一浏览器标签页刷新时，在本机存储可用的情况下 MUST 按对话身份恢复文本草稿，不承诺跨标签页、跨浏览器或多人同步。存储不可用 MUST 明确说明恢复限制，不阻止当前输入。

#### Scenario: 权限选择不跨对话继承
- **WHEN** 用户在当前对话选择完全访问后切换执行方、刷新或新建另一段对话
- **THEN** 当前对话 MUST 保留明确选择或读回实际本轮模式，未创建的草稿选择 MUST 仅转移到其准确新建对话
- **AND** 另一段新对话 MUST 使用默认权限，MUST NOT 从共享的新建偏好继承完全访问
- **AND** 选择模式不受支持时 MUST 保留用户意图并明确阻止发送，不静默降级

#### Scenario: 执行中继续输入
- **WHEN** 对话正在执行或等待回答、授权、停止确认，而用户输入或按发送快捷键
- **THEN** 新内容 MUST 保留为草稿，MUST NOT 追加已发送消息或假称指令已送达
- **AND** 本轮结束后 MUST 由用户明确发送，停止与当前请求回答仍可操作

#### Scenario: 刷新同一标签页
- **WHEN** 用户保留未发送文本后刷新同一浏览器标签页，且本机存储可用
- **THEN** 相同对话 MUST 恢复其文本草稿，MUST NOT 自动发送
- **AND** 其他对话草稿 MUST 不串入当前对话；已发送记录 MUST 从应用事实恢复，不能由草稿推定

#### Scenario: 不支持的图片或模型
- **WHEN** 用户选择图片或模型（Model），而当前接入不能使用它
- **THEN** 页面 MUST 在执行前明确不可用原因并保留其他输入，MUST NOT 悄悄丢弃图片或改用另一家执行

#### Scenario: DSH 模型选择范围
- **WHEN** 用户空闲时修改 DSH 模型（Model）
- **THEN** 界面 MUST 说明该选择还会更新此独立配置后续默认模型（Model），并显示真实生效结果
- **AND** 活动执行期间 MUST 不将下拉选择变化冒充本轮已切换

#### Scenario: 基本输入与反馈可操作
- **WHEN** 用户使用输入法、Enter、Shift+Enter 或键盘遍历对话控件
- **THEN** 输入法组合过程 MUST 不误发送，Enter 和换行行为 MUST 有明确说明，主要控件 MUST 有可访问名称及可见焦点
- **AND** 流式输出及展开工具反馈 MUST 保留用户当前阅读位置，不阻止停止或回应请求

### Requirement: 执行控制必须区分停止与未知状态
对话 MUST 明确显示执行中、等待补充信息、等待授权、正在停止、已确认停止、模型已中断但命令仍运行、执行状态待确认以及失败。停止、授权回复和问题回答 MUST 能在发送请求未结束时独立响应，并绑定产生请求的准确对话、执行和参与者。界面 MUST 根据真实反馈更新；时间经过、断开连接或前端关闭 MUST NOT 作为停止证明。原执行未结束或未知时 MUST 禁止在该对话新发执行及切换执行方启动工作，其他对话 MUST 不因此被阻断。

#### Scenario: 正常停止自动确认
- **WHEN** 用户停止本轮且系统收到模型与相关命令已结束的确认
- **THEN** 界面 MUST 自动显示已停止并恢复发送入口，保留历史、成果和草稿
- **AND** 用户 MUST 不被要求每次停止后再人工确认一次

#### Scenario: 模型中断但命令仍运行
- **WHEN** 模型已经中断但相关命令尚未退出
- **THEN** 界面 MUST 说明仍有命令运行并提供针对本轮剩余命令的停止操作
- **AND** 确认结束前 MUST 不显示已停止，也不能在同一对话新发或换家执行

#### Scenario: 回应原生问题和授权
- **WHEN** 原生执行请求回答问题或允许具体动作
- **THEN** 页面 MUST 展示实际来源、所需信息或动作范围，提交回答或允许、拒绝到准确原请求
- **AND** 过期请求 MUST 明确显示并刷新，MUST NOT 将回应转给输入框选中的另一位执行者

### Requirement: 收起对话后必须能准确发现待回应
全局对话入口 MUST 显示当前应用配置域内待回答、待授权和必要执行未知状态的轻量提示；一段待回应时 MUST 直接定位准确对话，多段时 MUST 在统一历史中呈现可选择条目。提示 MUST 不自动打开面板、切换业务页面或创建通知中心；已隐藏记录中的必要事项 MUST 保持可发现。

#### Scenario: 单条待回应
- **WHEN** 对话面板收起后某段对话等待授权或回答，用户点击全局提示
- **THEN** 面板 MUST 打开该准确对话及待回应请求，保留原草稿与工作页面

#### Scenario: 多条待回应
- **WHEN** 多段对话需要用户回应或核对执行状态
- **THEN** 全局入口 MUST 显示必要数量，打开后 MUST 在统一历史优先呈现这些准确对话供选择
- **AND** 已处理事项 MUST 按真实状态消退，不以当前任务（Task）状态推测待回应

### Requirement: 对话必须显示保存的执行位置
对话 MUST 分别呈现保存的工作空间（Workspace）、准确起始目录（CWD）及可选任务（Task）；新对话 MUST 允许在首次发送前确认执行位置。工作空间（Workspace）归属 MUST 不被显示为文件权限边界；跨目录工作 MUST 沿用原生实际权限和相关目录规则，不因当前浏览页变化而静默改变执行位置。

#### Scenario: 起始目录位于另一个工作空间
- **WHEN** 对话归属 Buildr 工作空间（Workspace）但明确选择另一目录执行
- **THEN** 界面 MUST 分别显示归属和实际保存目录，不始终以 Buildr 名称代替路径或根据路径猜归属
- **AND** 原生实际权限或目录不可用时 MUST 明确反馈，MUST NOT 自动换到当前页面目录

#### Scenario: 查看业务页面不注入上下文
- **WHEN** 用户在对话旁打开任务（Task）、代码或文档
- **THEN** 页面浏览 MUST 不改变对话保存的目录，也不自动发送其内容
- **AND** 本版 MUST 只接收用户显式提供的文本、受支持图片和准确任务（Task）引用，不扩展为自动界面上下文或成果导航

### Requirement: 手动切换与恢复必须显示真实接续范围
同一对话 MUST 允许空闲时手动选择下一位智能体（Agent），选择本身 MUST 不发起执行；标题、身份、草稿、可选任务（Task）及已有消息来源 MUST 保持。发送前 MUST 可查看将交付的实际记录、来源及范围；换回已有参与者 MUST 恢复其准确原生会话（Session）并只补缺失的可见内容。容量不足 MUST 保留原历史和草稿，并允许继续原参与者或由用户明确提供可查看的精简接续说明，MUST NOT 静默截断或自动摘要。刷新或重连 MUST 先恢复已保存记录并观察原执行，MUST NOT 将恢复按钮当成重发未知指令。

#### Scenario: 选择下一位但尚未发送
- **WHEN** 用户将执行者从 Codex 改为 DSH
- **THEN** 界面 MUST 保持同一对话并展示准确接续预览，MUST NOT 立即发送或把仅选中的 DSH 记为实际参与者

#### Scenario: 换回原参与者
- **WHEN** DSH、Qoder 已参与后用户换回 Codex 并准备发送
- **THEN** 预览 MUST 标明恢复 Codex 原生上下文并只展示它尚未收到的可见记录，不能将整段历史重复交付伪装成恢复
- **AND** 每条已有消息 MUST 保留实际来源，不能随当前选择重标

#### Scenario: 接续内容超过容量
- **WHEN** 实际待交付内容超过目标执行方容量
- **THEN** 界面 MUST 阻止本次发送并保留历史、草稿，明确提供继续原参与者或编写精简接续说明的选择
- **AND** 用户确认的说明 MUST 可查看并保留准确来源，后续参与者接续时仍可获取，MUST NOT 修改或删除原历史

#### Scenario: 刷新和失联后恢复
- **WHEN** 页面刷新、重连或后端重启后无法确认原执行结果
- **THEN** 界面 MUST 保留已恢复的历史、草稿与准确参与身份，显示待确认并允许重新观察原执行
- **AND** 观察到命令仍活动时 MUST 继续呈现活动状态，不能自动重发、换家或报告已停止

#### Scenario: 对话入口收拢且待回应可达
- **WHEN** 用户在桌面收起、暂看或固定展开对话
- **THEN** 顶部 MUST NOT 重复显示对话按钮；侧边图标或面板控制 MUST 保持当前对话开合
- **AND** 待回应提示 MUST 随侧边或标题栏保留，点击才显式定位待回应对话，普通开合 MUST NOT 自动换到其他对话
- **AND** 窄屏侧边隐藏时 MUST 保留顶部入口及待回应提示，移动后的显式待回应入口 MUST 保持键盘焦点可达
