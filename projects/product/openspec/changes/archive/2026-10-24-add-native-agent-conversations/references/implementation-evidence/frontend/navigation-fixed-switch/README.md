# 固定二级导航切组修复

本轮只修左侧固定导航的切换逻辑，右侧对话及三家接入保持现状。仍在 `agent-dialog` 工作树，未提交、整合、推送、归档或发布。

## 原因与修复

`AppPrimaryNavigation.tsx` 原来始终启用悬停预览；固定组之外的一级图标仍可显示浮层，而鼠标点击被过滤，只有键盘与触屏能进入显式打开逻辑。结果是固定展开后无法通过一次鼠标点击切换菜单组。

现在仅在收起态启用预览，固定态停止悬停定时器与浮层显示；鼠标、键盘和触屏入口直接切换固定组。重复选择当前组保持展开，原收起按钮及宽度拖动继续使用，切组不跳转工作页或清空页签；保存固定组，刷新后恢复。键盘切组后进入对应二级菜单，收起后恢复原悬停方式。没有修改共享 `usePanePeek.ts` 或对话组件。

原浏览器检查曾把“固定后悬停别组、点击不切换”当作预期，本轮已修正该断言。

用户同时询问电脑操作（Computer Use）。当前安装程序的 `features list` 显示 `computer_use stable true`，证明该版本包含且启用相应能力开关；这不是完整接通证明。Buildr 使用独立配置，当前该配置没有模型上下文协议（MCP）服务或插件登记；执行环境不继承桌面通信环境，接入也没有提供客户端电脑操作工具的处理。当前尚未完成官方桌面操作服务的独立接线和真实动作验证，不能按已可用功能承诺，也不能说命令行本身不支持。
