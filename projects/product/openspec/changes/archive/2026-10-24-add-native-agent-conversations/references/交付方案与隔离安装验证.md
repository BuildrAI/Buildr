# 智能体接入交付方案与隔离安装验证

本文接续用户已确认的独立账号、统一对话及三条原生接入方式，补充首次安装与工具准备的职责。本文是待实施的交付设计；本轮只修改方案及隔离实验，不改变正式功能，也不提交、整合或发布。原变更 `add-native-agent-conversations` 继续表达当前正式实现，本轮新增交付行为尚未并入该实现。

## 1. 用户得到什么

用户安装并打开 Buildr，在对话设置选择 Codex、DSH 或 Qoder，使用“准备并连接”。Buildr 检查实际程序、来源和兼容性；缺少程序时提供官方安装入口或在已获授权的独立目录准备兼容程序。用户完成官方登录后即可对话。需要真实页面验证时，由智能体（Agent）按技能（Skill）检查已有工具，补齐必要组件并实际完成页面操作。用户不需要先理解命令行（CLI）、浏览器内核或手工组合工具。

| 责任主体 | 本轮确定的职责 |
| --- | --- |
| 人 | 选择智能体（Agent）、完成官方账号登录，决定业务目标与权限并验收结果。 |
| Buildr | 最初程序发现、兼容检查、连接、独立配置与登录状态；管理统一对话及准确原生恢复。最初的智能体（Agent）准备不能依赖尚未接通的智能体（Agent）。 |
| 智能体（Agent） | 读取规则（Rule）和技能（Skill），调查当前现场、选择工具、准备缺失能力、执行并验证真实结果。 |
| 技能（Skill） | 提供环境检查、工具选择、安装、操作、失败恢复和完成依据的方法。具体命令、准备顺序与工具选择不写入长期规则（Rule）。 |
| 官方程序与现成工具 | 执行模型调用、文件及命令操作、浏览器控制，并维护自身实际状态；Buildr 不重写浏览器引擎或通用依赖安装平台。 |

## 2. 当前接入与桌面应用的关系

| 对象 | 当前实际执行方式 | 与桌面应用的关系 |
| --- | --- | --- |
| Codex | 独立 `codex app-server --listen stdio://`，使用 Buildr 自己的配置根。 | 原实现验证使用独立安装的 `@openai/codex@0.163.0`。本轮增加 ChatGPT App 内程序的发现与隔离兼容验证。复用程序文件不等于连接桌面对话或继承桌面工具。 |
| DSH | 独立 `dsh web --no-open --port 0` 完整宿主（Host），Buildr 使用官方客户端（Client）。 | 先前验证入口确实位于 DeepSeek Harness 桌面包内，其启动器用桌面包内 Electron 运行命令行（CLI）。本轮改用单独安装的官方 `@deepseek-ai/dsh@0.2.1-rc.2` 验证，避免把桌面安装包当成唯一来源。 |
| Qoder | 官方软件开发工具包（SDK）管理匹配版本的 `qodercli`。 | 原验证使用独立下载的命令行（CLI）；本轮安装 `@qoder-ai/qoder-agent-sdk@1.0.55` 并使用其下载的配套 `qodercli@1.1.75`。不需要 Qoder 桌面包。 |

独立原生进程不自动继承桌面会话、插件、浏览器工具、登录状态或电脑操作（Computer Use）。用户安装桌面应用的选择与 Buildr 的执行接入分别维护。依赖桌面包中的程序文件时，卸载或更新该包会影响程序来源，需要重新检查；这与桌面主程序是否一直运行是两种不同依赖。

三家桌面主程序完全退出后的对照仍按用户先前决定暂缓。本轮不自动退出任何桌面应用；独立程序路线和真实工具执行的结果，不冒充已完成退出对照。

## 3. 程序发现、缺失与兼容

### Codex 的发现

用户侧推荐提供 ChatGPT App 官方下载入口，同时保留独立命令行（CLI）安装。按用户已指定的程序优先核对；未指定时，检查正常命令搜索路径（PATH）和官方应用包，展示实际发现的来源，避免多个安装间静默切换。

缺少 ChatGPT App 时展示官方下载安装入口和“安装后重新检查”；下载器或系统安装器尚未完成时，不伪造 Buildr 已安装的状态。用户明确选择单独准备命令行（CLI）时，才走对应的独立程序准备路线。本轮以当前已安装的 App 验证发现与兼容，同时验证缺失诊断；不冒充已经在无 App 的全新操作系统重装过 ChatGPT。

macOS 本轮检查 `/Applications/ChatGPT.app` 与用户 `Applications` 下的同名应用，兼容发现旧 `Codex.app`。不靠名称判断身份：读取实际应用标识、签名、真实可执行路径及 `--version`。本机已观察的程序位于 `Contents/Resources/codex-cli/bin/codex`；旧包可能位于 `Contents/Resources/codex`。这些路径是已知候选，找不到时返回准确缺失原因，不扫描或猜测其他应用的私有接口。Windows、Linux 的安装发现需要在对应系统验收，不能由 macOS 结果推断。

本机 ChatGPT App 的应用标识为 `com.openai.codex`，程序版本为 `0.163.0-alpha.11.2`。正式适配器当前只接受 `0.163.0` 和 `0.163.0-alpha.11.1`，因此正式功能尚不能直接连接这个应用内版本。本轮只在临时副本增加准确版本候选，先验证官方协议、登录、模型、工具执行和恢复；不能仅删除版本检查或接受任意版本。

### DSH 与 Qoder 的准备

DSH 支持官方命令行（CLI）与网页宿主（Web Host）安装路线，桌面包不作为必需安装。Qoder 优先使用固定软件开发工具包（SDK）所声明的配套运行程序；配套下载失败时显示其真实原因，不要求用户先安装桌面应用，也不自动混用系统中另一个版本。

准备仅作用于用户明确选择的接入，不一次安装三家。下载使用官方来源及其可用完整性校验，记录实际版本和路径；不使用不受控的 `latest` 作为长期兼容承诺。缺失、下载失败、程序不能运行、协议不兼容、未登录和没有可用模型必须分别诊断。某一接入失败不妨碍其他已可用接入和工作台功能。

### 更新与原生恢复

原生会话（Session）绑定准确程序、配置根和原生编号。程序、版本或配置来源改变后重新核对兼容性，不静默换号或新建对话冒充恢复。第一版不自动升级厂家运行程序，也不承诺应用更新后的任意版本都兼容。发现外部应用已经更新时，保留现有历史并准确提示；原生恢复的迁移需要按真实兼容验证处理，不能通过重写绑定标识绕过现有保护。

## 4. 账号与配置

每家一套 Buildr 独立配置，覆盖独立用户目录、厂家配置和临时目录。使用官方账号登录或授权；Buildr 不提取桌面凭据、不把桌面已登录作为当前接入已登录。登录页面完成后，必须从运行程序读回账号及实际模型目录，再显示可用。

关闭页面、断开程序、退出账号与删除历史是不同动作。准备失败和重试不得删除已有账号或对话；重复准备时重新观察并复用已经成立的安装和认证事实。官方登录地址只在准确登录尝试中短暂提供，不写入公开报告、源代码或长期会话记录。取消和超时只作用于该次尝试。

隔离验收使用全新空白配置完成首次登录，不复制桌面或正式接入凭据。验收完成后准确停止本轮进程；临时账号资料的定向清理独立记录，保留不含秘密的结果和复现方法。

## 5. 浏览器工具由智能体准备

浏览器操作（Browser Use）描述能力，Playwright 是浏览器自动化工具。Chromium 是开源浏览器项目，Chrome、Tabbit 是基于它的浏览器产品；相同基础不自动证明工具能连接或操作。无窗口模式（Headless）与有窗口模式（Headed）是运行方式；Playwright 还提供单独的 Chromium Headless Shell，不能把这个精简程序直接当成完整可见浏览器。

| 当前现场 | 智能体（Agent）的处理方式 |
| --- | --- |
| 用户指定 Tabbit，已有对应技能（Skill）和 `tabbit-cli` | 按技能（Skill）检查实际安装与连接，在自己的页签（Tab）完成最小真实操作。可用时复用；不因安装过技能（Skill）就声称已连接。 |
| 已有 Playwright CLI 与匹配浏览器 | 检查版本、配置和实际操作，复用可用组件，不重复下载。 |
| 缺少可用浏览器工具 | 在独立目录准备官方 Playwright CLI 与匹配版本的浏览器。截图及结构交互可使用 Chromium Headless Shell；需要观察或接手时准备完整 Chromium，或采用已验证兼容的现有浏览器。 |
| 浏览器安装、连接或页面操作失败 | 保留真实失败，修复本次拥有的目录或选择其他现成工具；不改用户共享浏览器配置，不干扰其他任务，不把失败扩散到整个智能体接入。 |

安装后的工具可以按用户复用，浏览器配置、会话、套接字与输出按本次执行隔离。工具位置由现场发现与工具本身维护，不在 Buildr 建立第二份必须持续同步的通用工具登记。Windows、macOS、Linux 的工具安装与权限按真实平台核对。

独立账号目录与真实系统用户目录要分别识别。智能体（Agent）的独立 `HOME` 不代表系统用户没有安装 Tabbit 或用户级工具；检查真实系统用户和已明确提供的稳定工具入口，不因此共享厂家账号或桌面配置。

本轮实践补充的方法：首次打开前显式选择已核验的浏览器或可执行路径，不能让 Playwright CLI 默认寻找未安装的系统 Chrome；页面打开后等待真实业务元素可见，不能把初始空快照作为页面内容；长临时路径下使用独占的短套接字目录。复用服务依赖时，区分依赖包、锁文件和会重建的 Vite 开发缓存；需要严格只读或并行隔离时，把缓存迁移到本次拥有的位置，不能仅凭软链接宣称整个依赖目录只读。

第一版只补浏览器操作（Browser Use）的日常验证闭环。电脑操作（Computer Use）、厂家桌面专属浏览器和任意系统界面自动化不纳入本轮。

## 6. 代表场景与完成边界

以生猪竞拍工作台真实源码为场景：独立安装 Buildr 和厂家程序，连接并完成官方登录；智能体（Agent）调查真实服务代码，自行检查与准备浏览器工具，验证候选启动和公开登录页的真实截图、点击、键盘输入与断言；保存隔离运行定义并读回，由安装后的 Buildr 托管启动，再次检查页面，停止准确实例并确认停止。

服务源代码使用真实提交 `1519ba71411b78fd58cda950e71615a340fcf9f9` 的隔离副本。同锁文件的现有服务依赖作为缓存复用，Vite 启动可能重建开发缓存，但未安装或更新服务依赖；本轮不把它描述为在空机上重新安装全部私有业务依赖。浏览器工具和厂家程序从空目录实际准备，账号从空配置实际登录。公开登录页验证不包含鉴权后竞拍业务、真实验证码、真实账号登录或业务写入。

缺少程序、兼容拒绝、首次连接未登录、官方登录成功、真实模型目录、进程重启后的恢复、工具准备、真实页面操作、配置读回与停止分别保存证据。最小协议握手或安装成功均不能替代后续真实执行。本轮已完成的范围见第9节及本机任务材料，未覆盖部分明确保留。

## 7. 本轮隔离实现位置

实验根由 `/tmp/buildr-agent-delivery-root.txt` 指向。本轮只复制正式源码到临时目录，新增程序发现试验，并在复制的 Codex 适配器中加入准确的 `0.163.0-alpha.11.2` 候选。通过现有制包实现生成未发布的开发候选，在独立安装前缀完成安装；不会替换本机 Buildr 或正式预览。

浏览器准备方法放在各隔离工作空间（Workspace）的 `.agents/skills/browser-tool-preparation/SKILL.md`，不写入正式资源或用户全局技能（Skill）。实验最终核对正式实现文件摘要和真实集鲜源码，报告新增工具、可复用结果、失败、清理与未验证边界。若以后决定正式实施，再把已验证的交付行为纳入对应变更、设置界面和接入实现。

隔离包沿用当前任务工作树的旧服务运行实现：`start` 先输出 `starting`，其进程仍持有子进程；当前主开发版本已经调用 `waitForRun`，接口参数也有差异。本轮智能体（Agent）按准确安装包的 `--help` 操作，通过独立查询、真实页面和停止读回完成验证，不把初始输出当成就绪。该基线差异单独记录，未在本轮修改旧服务实现，也不据此宣称当前主开发版本存在同样问题。
