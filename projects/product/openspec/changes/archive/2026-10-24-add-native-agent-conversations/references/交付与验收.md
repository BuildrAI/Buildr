# 内部对话交付与验收

本轮按用户授权收口实现，交付目标为开发主线整合与日常开发版更新；不发布。三家在日常开发版的重新接入、官方登录与真实任务验收留给用户。归档前后的文档移动不代表重新执行了历史实验。

## 本轮交付

- Codex 应用服务（App Server）、DSH 完整网页宿主（Web Host）、Qoder 软件开发工具包（SDK）管理的原生程序，保持既有三条接入方式；独立账号、统一可见对话、分别恢复原生上下文。
- “准备并连接”完成本机发现、准确来源选择、同系列兼容检查、缺失安装引导或独立准备、官方登录和真实账号模型验证。兼容系列与固定下载版本分离，不因系列内 RC 或补丁变化破坏原绑定。
- 工具由智能体（Agent）按随包方法发现和准备，沿用官方 npm 与 Playwright 安装位置，不新增工具管理平台。账号主目录仍隔离；`BUILDR_HOST_HOME` 提供路径线索，`PLAYWRIGHT_BROWSERS_PATH` 保留覆盖或指向原用户官方缓存，三家可以复用已有浏览器。
- 智能体源码、依赖、实际编译产物和宿主准备后的私有包纳入现有开发版内容证明与重建；冷准备先构建私有服务，失败不冒充开发版已更新。
- 保留原工作双屏和旧一次生成／外部会话关联。修正本次导航浮层的焦点残留、其他菜单释放焦点取消悬停计时、顶部说明浮层遮挡，并让原浏览器检查使用实际悬停／固定导航方式。

## 责任与后续验收

当前说明以[智能体接入责任边界](../../../../../knowledge/docs/architecture/agent-boundaries.md)为准。用户的[分层思考](智能体接入分层架构说明.md)和[接入架构与实施方案](接入架构与实施方案.md)作为可回读的认知与历史设计材料；模型和内核的协同差异没有受控因果实验，不能据此承诺效果等价。原生内核负责模型请求级组装与执行循环，Buildr 提供准确目标、对象、上下文材料、控制和界面。

用户后续从日常开发版账号设置开始，分别发现／选择程序、准备并连接、完成官方登录，再通过内部对话开展实际任务；缺少浏览器工具时让智能体按随包方法准备，并验收真实页面结果。本版不包含电脑操作（Computer Use）、桌面全部扩展、自动分工或工具管理窗口。桌面应用全部退出的独立对照仍按用户决定暂缓，不自动退出任何桌面程序。
