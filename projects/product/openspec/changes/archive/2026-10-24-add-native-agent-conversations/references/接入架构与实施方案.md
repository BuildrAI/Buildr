# Buildr 内部智能体接入架构与实施方案

> 正式变更 `add-native-agent-conversations` 已获用户授权进入实现：见[提案](../proposal.md)、[详细设计](../design.md)与[实施清单](../tasks.md)。本文保留实施前调研与讨论依据；具体行为以该变更及[本轮实现验证](implementation-evidence/README.md)为准，历史最小实验不替代正式实现的验收。

本文件为 2026-10-23 审查后形成的实施前方案。用户已确认 Codex 应用服务（App Server）、DSH 完整宿主（Host）、Qoder 官方软件开发工具包（SDK）三条接入方式，以及独立配置、统一可见对话、各家恢复原生上下文的方向，随后授权正式实现。第一版做好日常对话和执行的完整闭环，不以桌面版全部功能等价为目标。原有接入及代码全部保持，未来退场另行讨论。已定布局保留；三家历史最小实验及真实接续只承担原有可行性证明范围。

## 1. 产品目标与范围

人在 Buildr 当前工作空间（Workspace）中能够完成咨询、读取资料、修改文件及持续推进工作。智能体（Agent）负责理解目标、选择工具与执行；Buildr 负责接入、交互、准确状态、历史和工作对象的必要引用。完整闭环指新建或打开对话、表达要求、查看过程、及时处理授权或问题、确认结果或停止、稍后准确恢复；不要求复刻每家桌面应用。

| 第一版交付 | 范围与完成边界 |
| --- | --- |
| 三家接入与账号 | 每家一套独立配置，官方登录，展示准确账号状态及实际可用模型；选择兼容执行程序。 |
| 普通对话与任务对话 | 同一套全局界面和历史；普通咨询不要求任务。任务零／一／多个内部对话分别创建、直接打开、选择准确对象。 |
| 输入与反馈 | 文本输入、流式回复、工具进度、基本文件改动与错误反馈；必要图片输入按所选版本及模型真实能力逐家验收，不扩展为通用附件解析中心。 |
| 原生交互与停止 | 原生默认权限和逐次授权、补充问题、及时停止；分别呈现停止中、确认停止、活动工具未退出与状态未知。 |
| 历史与恢复 | 统一可见记录、准确原生编号、重连及重启恢复；结果未知先观察，不盲目重发。 |
| 手动选择下一位执行者 | 同一段对话顺序参与；可查看实际接续内容，换回各自原生上下文再补充增量。 |
| 工作现场 | 沿用真实文件、已有规则、技能与权限；支持已授权的跨目录工作，显示保存的准确执行位置。 |
| 已定布局 | 全局入口、统一历史、左右停靠、导航悬停和原工作双屏；收起后有最小待回应提示。 |

| 后续方向 | 第一版保留的边界 |
| --- | --- |
| 共享桌面配置、多账号池、通用自带密钥（BYOK）配置 | 首版仅使用独立配置和已经验证的官方登录；厂家支持不等于固定版本组合已验收。 |
| 自动页面或选区上下文、智能体生成界面（Agentic UI）、成果导航 | 保留显式输入、准确对象引用和结构化来源；先不改造具体业务现场。 |
| 并行团队、自动分工、跨任务关系管理 | 一段对话同一时刻一位执行者；第一版一段对话最多关联一个可选任务。 |
| 桌面专属浏览器、语音、扩展市场、自动化及完整差异编辑器 | 不随原生进程自动带入，不作为首版全部等价目标。 |
| 长历史自动摘要、跨家自动记忆 | 首版提供有界且可查看的接续；超限保留草稿并明确处理，不静默摘要。 |
| 后端退出后持续执行的独立常驻宿主 | 首版证明重启恢复，不据此承诺后端退出期间活动执行仍持续运行。 |

任务中新增内部“打开对话”入口；既有外部桌面关系、接口与入口保持原样，内外关系分别标明，不混成一个数量、不双写或自动迁移。“提出新目标”等现有工作动作继续承担原职责，不改接成普通新对话。一个任务可以有多段内部对话；第一版一段对话只在创建时保留一个可选任务引用，不增加批量绑定、跨任务移交或关系管理器。底层身份可以日后扩展，不能据此提前增加界面范围。

本次跨家真实接续已在合成场地通过。分屏原型仍为模拟交互；正式实施需逐项用真实事件替换并验收。所选程序、接口或模型缺少某项能力时准确说明，不因为三家共用界面而显示成全部可用。

## 2. 接入路径

| 对象 | 推荐入口 | 进程归属与粒度 | 选择原因与差异 |
| --- | --- | --- | --- |
| Codex | `codex app-server --listen stdio://` | Buildr 为一个准确配置来源管理独立服务；服务可承载多段会话（Session） | 原生接口（API）包含账号、历史、工具事件、授权、提问和停止。按实际程序生成协议，固定通过验证的版本。 |
| DSH | `dsh web --no-open --port 0` 的完整宿主（Host）＋官方客户端（Client） | Buildr 管理独立完整宿主（Host），连接令牌仅留在后端；可承载多段会话（Session） | 使用其执行能力，不嵌入 DSH 页面。软件开发工具包（SDK）及智能体客户端协议（ACP）当前交互与历史能力不足以直接实现目标。 |
| Qoder | `@qoder-ai/qoder-agent-sdk` 启动匹配版本的 `qodercli` | 每段活动会话（Session）由一个独立执行进程承载 | 持续输入使用异步消息流；账号、停止、问题、工具与历史通过正式软件开发工具包（SDK）处理。固定其配套命令行（CLI）版本。 |

Qoder 已实测存在 `qodercli login` 官方浏览器登录流程，Buildr 可启动该流程、展示授权链接并重新检查账号。它不是软件开发工具包（SDK）内的浏览器登录方法。临时实验发现的内部环境变量不能成为正式产品唯一依赖。

独立进程、独立配置和独立账号是三个选择。不能因为服务由 Buildr 启动，就声称账号、历史或全局设置已经隔离。

第一版必须保留的实际差异：

| 能力 | Codex | DSH | Qoder |
| --- | --- | --- | --- |
| 执行入口 | `codex` 的应用服务（App Server）模式，结构化双向消息 | `dsh` 的完整网页宿主（Web Host），官方客户端（Client）调用接口 | 官方软件开发工具包（SDK）管理匹配的 `qodercli` 进程 |
| 模型与设置 | 从当前账号及原生接口（API）读取真实选项 | 选择模型还会保存该独立配置的默认值，需明确提示 | 使用当前 Qoder 账号可用模型；自定义模型组合另验收 |
| 规则与技能 | 保留实际发现来源，独立配置不自动复制桌面扩展 | 完整宿主（Host）配置及智能体资产目录分别绑定 | 固定版本需显式启用 `.agents/skills` 发现，核对真实加载 |
| 权限 | 沿用原生批准与适用的隔离能力 | 沿用原生工具权限和授权请求 | 工具许可不等同操作系统隔离；按真实请求回复 |
| 停止 | 中断轮次后还需核对本轮命令退出，必要时精确终止 | 通过原生取消并观察工具与轮次终态 | 通过原生中断并观察本轮工具退出；不能只关闭消息流 |
| 桌面附加能力 | 内置浏览器等桌面宿主能力不自动带入 | 桌面原生窗口、麦克风等附加能力不自动带入 | 桌面浏览器、编辑工作区和扩展界面不自动带入 |

权限、模型、图片及运行中干预均按固定版本的真实能力显示。第一版先用原生默认权限和逐次授权，不提供三家含义不同却外观相同的“只读／完全访问”切换。运行中的新想法可以先保存在草稿里；只有某家的追加指令或排队能力经过真实验证，才单独显示相应动作和准确后果，不把“草稿已保存”显示成“指令已送达”。

## 3. 职责与权威来源

| 责任方 | 持有事实 | 承担动作 |
| --- | --- | --- |
| Buildr 前端 | 当前选中对象、未发送草稿、可重建的显示状态 | 分屏、输入、实时显示、授权和问题交互 |
| Buildr 对话应用 | 统一对话身份、标题、可见记录、参与及任务关系、接入身份、配置来源、自己的进程与待处理请求 | 组织用户可见历史、校验准确执行方、构造接续输入、调用原生操作、管理连接与失败恢复 |
| 各家原生运行时（Runtime） | 各自原生执行历史、上下文压缩、模型执行、工具与原生权限状态 | 运行智能体（Agent）循环、加载规则和技能、保存和恢复各自原生上下文 |
| 文件、代码库及外部系统 | 真实成果及其当前版本 | 继续作为工作现场的权威来源 |

Buildr 不实现推理或工具选择循环，但须持久保存属于自己的统一可见对话记录；这不是把三家的全部原生日志再复制一次。用户消息、显示消息、参与变更和相应原生来源引用属于 Buildr；内部推理、原生上下文压缩和执行恢复状态由各家管理。文件及外部系统仍是工作成果的权威来源，聊天不能证明现场未变化。短期事件缓存（Cache）支持页面重连，缺口按各参与关系重新观察原生历史并去重补齐；缓存（Cache）和界面推断不能替代真实执行状态。

关闭分屏、离开页面、停止当前执行、释放服务、退出账号分别处理。前端关闭不应偷偷停止工作；停止本轮也不删除历史或撤销已经发生的文件修改。

## 4. 账号、配置与版本

第一版每家仅采用一套独立配置，账号页不提供配置来源选择；共享已有配置只保留为后续方案：

| 方式 | 用户得到什么 | 必须说明的边界 |
| --- | --- | --- |
| Buildr 独立配置：第一版唯一方式 | 使用专用目录，通过官方方式登录原有账号，独立保存设置与历史 | 不承诺自动带入原桌面插件、个人配置或全部用户级技能。 |
| 使用已有本机配置：后续可选 | 明确选择已有配置，复用其登录、设置与可用扩展 | 全局设置、登录和历史可能与其他应用共享；需准确说明写入范围。 |

**已确认默认选择 Buildr 独立配置**，仍使用用户原有的服务商账号，通过官方方式重新登录，不要求注册新账号。程序本体可以复用已安装的兼容命令行（CLI），但配置、登录状态和历史放在 Buildr 的本机私有目录，不放在工作空间（Workspace）的受版本管理目录中。本次三家均完成全新独立官方登录，没有复制旧桌面凭据。

独立配置默认按本机用户与接入管理，可以服务多个工作空间（Workspace）；每段对话仍保留自己的起始目录（CWD）。第一版每家一套接入即可，数据身份保留扩展多账号的余地，不先增加账号池或自动切换。分别展示程序可启动、账号状态、模型目录和实际执行结果，不能把目录存在显示成已登录，把登录进程退出码或凭据存在显示成模型可用。

- Codex：`CODEX_HOME` 影响配置、认证、历史、日志及部分技能。正式接入使用公开登录路线；本机版本标记内部专用的认证接口（API）不作为产品承诺。认证资格仍需按 Buildr 的实际发行形态核对官方要求。
- DSH：`DSH_HOME` 管理账号、设置及原生会话存储；`DSH_AGENTS_HOME` 是另外的智能体资产／技能来源，不能把它当作原生历史目录。两者均精确绑定，恢复时完整保留配置及历史。完整宿主（Host）使用的配置文件（Profile）与桌面配置不能直接等同；浏览器登录由原生账号接口（API）处理。
- Qoder：`QODER_CONFIG_DIR` 包含配置和账号等状态。软件开发工具包（SDK）的 `qodercliAuth()` 读取所选配置的命令行（CLI）登录。独立配置通过同一目录的官方登录建立认证，不在正式产品中提取桌面凭据再拼装登录。

登录流程由新服务持有，前端只观察状态和打开官方页面。DSH 的 `startSignIn` 先返回 `initializing`，随后通过原生状态观察得到 `waiting-browser` 及地址；登录宿主退出会丢失未完成的尝试，不能把它当作可跨进程恢复的完整登录。完成后新宿主读取凭据、资料与模型已真实验证。Codex 和 Qoder 同样在官方完成回执后核对账号及模型目录。关闭前端不自动取消或退出账号，超时、取消和重试均作用于准确登录尝试。

“断开接入”只释放 Buildr 拥有的服务。退出账号是独立动作，必须说明共享范围；第一版可以保留在明确的账号设置中，不用断开按钮代替。

DSH `0.2.1-rc.2` 的 `session.selectModel` 还会保存该设置来源的默认模型，不能展示成“只改变当前对话”。第一版使用 Buildr 独立设置来源，选择时仍提示它会影响该接入此后的默认模型。模型选择在空闲时进行，不以修改下拉项冒充当前活动执行已切换模型。将来支持共享设置时另行明确保存范围，不能先写共享默认值再恢复，伪装成没有副作用。

Qoder 官方命令行（CLI）支持通过 `/model → Custom` 配置自带密钥（BYOK），这是厂家已有能力。本次固定软件开发工具包（SDK）与命令行（CLI）组合尚未验证加载该自定义模型后的完整执行链路；不能承诺任意传入模型地址和密钥即可使用。第一版先交付已验证的官方 Qoder 登录与账号模型，不新增通用模型供应商配置中心，也不将自带密钥（BYOK）描述为永久不支持。

记录程序真实路径、版本、配置真实路径与来源版本。路径或配置来源变化时，旧对话保持原身份并返回明确诊断；不能无声地把旧原生编号交给新目录。更新程序后重新进行有界兼容检查，不能仅按“支持某品牌”判断兼容。

## 5. 规则、技能与跨目录工作

起始目录（CWD）用于确定开始工作的位置与发现上下文，不是完整的文件读取边界。读写权限、额外可写目录和原生授权应分别说明。

正式接入保留原生发现方式，使用工作空间（Workspace）已投射的 `AGENTS.md`、`.agents/skills` 及该程序支持的来源。对话开始和恢复后检查实际加载结果，不重复把全部规则和知识塞进每条消息。独立配置不意味着把工作空间（Workspace）复制一份；原生进程直接以真实目录开始工作。用户级技能、工具连接协议（MCP）配置与桌面宿主专属扩展分别核对，不能承诺仅登录就全部继承。

本轮实验分别检查真实 Buildr 目录的只读发现，以及合成场地中的行为。发现列表证明能找到资料，模型真实执行才证明该次规则和技能被使用；两种证据不能混报。

跨到另一个工作空间（Workspace）时，智能体（Agent）应主动读取目标适用规则。不能假定任意跨目录读取都会自动注入目标规则；也不能仅因 `cd` 成功就声称目标上下文已加载。必要的原生授权显示在同一对话中，Buildr 不建立第二套通用许可规则。

Qoder 软件开发工具包（SDK）的出厂技能策略与命令行（CLI）有差别，不能默认等同桌面环境。本轮匹配版本中，仅选择配置来源并不能加载 `.agents/skills`，需要通过正式设置透传明确给出 `settings.skills.loadFromAgentsDirectory=true`，再核对初始化结果和真实技能调用。真实 Buildr 目录中有 38 项项目技能；原生内置条目另行计数，不以“总数相同”代替来源检查。该设置纳入固定版本兼容检查。桌面宿主（Host）私有工具和环境管道同样不能直接继承到独立进程。

实验中临时目录可能属于默认可写例外。证明跨目录写入权限时必须显式处理该例外，不能把 `/tmp` 中一次写成功当成任意目录都可写。

## 6. 统一对话、参与关系与原生恢复

### 身份与存储职责

会话（Conversation）属于用户的一段工作，智能体（Agent）是参与者。一个 Buildr 对话可以关联多家原生会话（Session），同一家也可能因准确配置来源不同有不同绑定。不能继续采用“一段 Buildr 对话固定一家、一个原生编号”的模型。

下列为实施前的拟议关系，并非已交付的数据协议：

```ts
type Conversation = {
  id: string;
  workspaceId: string;
  title: string;
  cwd: string;
  revision: string;
};
type ConversationParticipant = {
  id: string;
  conversationId: string;
  agentConnectionId: string;
  configIdentity: string;
  provider: 'codex' | 'dsh' | 'qoder';
  nativeSessionId: string | null;
  deliveredThrough: number;
};
type ConversationEntry = {
  id: string;
  conversationId: string;
  sequence: number;
  participantId: string | null;
  kind: 'message' | 'participation-change' | 'execution';
  nativeEntryId?: string;
  runId?: string;
  content: unknown;
};
```

`Conversation.id` 是任务关联、标题、草稿及历史入口使用的稳定身份，不随执行方改变。标题由 Buildr 维护，原生标题只可作为初始建议；重命名无需假定三家都支持同一接口（API）。参与关系绑定准确接入、配置来源和原生编号；账号秘密与操作系统进程编号不写入这些业务记录。参与人数按实际已有回复或执行计算，仅选择下拉项不等于该执行方已经参与。

`configIdentity` 识别准确程序来源、配置根和配置文件（Profile）；普通模型选择不是账号来源变化。`workspaceId` 表示归属与开始入口，不是文件访问边界。`deliveredThrough` 记录已向该参与者交付的可见记录位置，用于判断换回原执行方时缺少哪些中间内容；不能以它代替原生执行完成事实。最终字段以确认后的规范和真实接入能力收敛，不为原型增加独立状态系统。

### 创建、查看与恢复

新建先建立 Buildr 对话，用户可以选择下一位执行者；发送时才按需创建或恢复准确原生会话（Session）。从任务“打开对话”不会自动发送指令。若原生已创建但关联保存失败，保留创建尝试及已知原生身份，重新观察后修复，不能重试即另起一段。原生未提供幂等能力时，明确处理结果未知，不承诺跨系统严格只执行一次。

Codex 本次发现：`thread/start` 返回编号不等于已持久保存可恢复历史；首条用户消息前调用 `thread/turns/list` 会报未物化，关闭后可能无法恢复该空编号。仅对本次新建且确知尚未发送的对象将历史视为零；已有绑定必须按准确编号读取，失败不得吞掉或冒充空历史。创建尝试、实际发送确认和持久原生身份分别核对。

普通对话不要求任务关联。任务入口由新服务维护内部关系，引用稳定的 `conversationId`，传递准确任务编号及读取入口；不扩展旧外部会话关系。一个任务可以打开多段内部对话；第一版每段对话最多保留一个可选任务引用，从任务入口创建时绑定，不因增加参与者重复关联，不新增跨任务关系管理器。底层将来可以扩展关系类型，但不据此交付多对多管理界面。界面浏览另一任务不会自动更换当前对话，也不会自动把该页面作为新执行上下文。

查看历史首先读取 Buildr 统一可见记录，必要时按每个参与关系补齐原生消息和当前状态。原生条目按参与身份与准确原生条目标识去重；不支持稳定标识的来源须验证自己的重读映射，不能猜测通用去重算法。工具记录和授权不是普通聊天消息的可重放指令。原生历史补齐不能改变原来的消息归属或让同一用户消息显示多次。

继续时恢复所选参与者原来的接入、配置来源与准确原生编号，不用“最近一段”猜测。先核对它是否仍在执行或等待回应，再由用户发送新要求。刷新、重连和服务重启均不自动重发上一条可能已产生副作用的指令。未确认的发送保留草稿与诊断，先观察原生事实。

### 同一段对话切换执行方

第一版由用户手动选择下一位执行者，顺序参与；不增加自动分工、并行团队或跨对话移交机制。切换选择本身不发送、不创建新的历史主题、不改变任务、不覆盖前面的消息身份。输入框显示下一位执行者，消息及授权请求显示实际来源。

发送到另一家前，构造有界的接续输入：用户目标、已明确约束、必要的可见对话及操作结果、准确任务引用和保存的起始目录（CWD）。发送前可以展开查看实际正文、记录范围、来源、执行位置和将收到的新要求；不能只列“目标、相关历史”等类别作为预览。不得发送账号凭据、原生隐藏推理或无关工作空间资料；不能假装迁移了对方的内部上下文。目标规则和当前文件仍由接续方核对。

第一版不建设自动摘要或记忆管理器。超过已验收的接续容量时明确显示无法完整携带，保留全部历史和当前草稿，不默默截断或发送。用户可以继续原参与者，也可以明确提供或确认一份可查看的精简接续说明；界面必须说明这是精简内容并展示实际发送正文，不冒充完整历史。只在原执行已确认结束时，才允许将该说明交给另一家开始执行。

换回先前参与者时，恢复它自己的原生会话（Session），再补充尚未交付的相关变化。补充记录作为上下文参考，不重演先前工具操作、授权或用户命令。接续输入需保存实际交付范围与来源，供失败诊断和重连核对；原生不能准确恢复时明确显示原因，由用户决定另起执行上下文，不能静默冒充连续恢复。

交付位置只在原生确认接收后推进，并关联实际原生输入身份及来源序号；保存实际输入范围、内容摘要值（Digest）、交付尝试与未知结果以供核对，不保存秘密。超时但结果不明时先观察原生历史和工作文件，不自动重发整包指令。历史工具调用和授权不作为新的协议请求再次提交。单一序号不能替代原生接收、执行完成或文件事实。

同一 Buildr 对话第一版只允许一个活动执行者。执行、等待授权、等待回答、仍有活动工具、正在停止或原执行状态未知时，不能切换到另一家发送新工作；先观察原生状态，确认原执行结束。停止、授权与回答始终指向产生请求的原参与者及执行，不跟随输入框选择改投另一家。一家不可用不妨碍阅读统一历史和保存草稿；只有原执行已确认结束，才可明确选择其他已接入执行方继续，不自动代选。断开接入本身不能证明这一条件成立。

本次补充已真实验证 Codex → DSH → Qoder → Codex：同一实验对话、三组原生绑定；换回时最初关键词未重新注入，Codex 仍准确回忆并结合两家补充。三家随后均冷恢复原编号、无工具回忆前文，工作文件不变。详见[补充验证](probes/continuity/REPORT.md)。这只证明有界合成历史的接续与原生恢复；产品级历史补齐、去重、断线一致性、长历史压缩及运行中异常仍需正式实现后验收。同一家更换模型继续按原生实际能力处理，DSH 默认模型的保存范围仍须准确呈现。

归档与“从最近列表隐藏”属于 Buildr 的对话管理；不冒称三家均有同样的原生删除能力。删除统一记录与删除原生历史是不同动作，第一版不合并提供含糊的删除按钮。

## 7. 事件、交互与停止

适配层（Adapter）将原生事件转换为界面需要的少数语义，同时保留来源和准确请求身份：消息增量、工具开始/结束、文件改动、等待授权、等待回答、执行完成、执行失败、执行中断与历史需要刷新。

建议公开事件字段包括 `conversationId`、`participantId`、Buildr 执行标识 `runId`、当前服务代次、原生本轮标识、原生条目标识、原生请求标识、事件种类与安全载荷。服务重启后代次变化，不能把迟到的旧事件或旧授权回复应用到新执行。

授权和补充问题必须走原生回复接口（API），回复时校验对应参与者、执行、原生请求及配置来源仍有效。Buildr 显示原生动作、作用对象及可选决定，不自己推测“已允许”并执行工具。未知事件可以给出安全的文字反馈；未知交互不能默认批准。

后端对同一原生对话串行校验命令准入及必要的短期状态写入，多个页面可以观察；不能持锁等待整个模型轮次结束。停止、有效授权回复和问题回答必须及时送达当前准确请求。第一版运行中补充先保留草稿，待本轮结束后发送；只有经过真实验证的原生追加或排队方式才作为单独能力开放，并说明是即时干预还是下一轮处理。不同会话（Session）按原生能力并行。Codex 和 DSH 不能复用当前“一次生成按接入排队”的规则去锁住整个聊天服务；Qoder 按活动会话（Session）持有执行进程。

前端通过受本机应用认证保护的命令接口（API）发送动作，通过服务端事件流（SSE）订阅后端安全事件。每次连接先同步原生状态，再追增量；短期缓存（Cache）序号失效时重读历史。原生账号或 DSH 的连接令牌、Cookie 不进入前端事件。

停止先发送原生中断，再显示“正在停止”。适配层（Adapter）自动观察模型轮次终态与相关活动工具、终端的停止事实，得到确认后自动更新；停止请求返回成功、轮次进入中断终态，都不能单独证明命令已退出。本轮 Codex 前台心跳命令已复现这个差异。存在仍运行或状态不明的命令时，显示“对话已中断，相关命令仍运行／状态待确认”，不能显示笼统的“已停止”。

优先使用该提供者（Provider）的原生精确终端终止能力，按当前本轮记录的原生进程标识处理，不能清理同一对话早先有意保留的后台服务。确有必要升级处理时，只作用于 Buildr 拥有的明确执行对象并说明范围。共享一个宿主（Host）的其他会话（Session）不得随之被误停；无法证明目标工具已停时保留诊断，不能用服务连接断开冒充停止完成。

Codex 本轮已验证的组合是：`turn/interrupt` 后核对本轮的 `commandExecution.processId`，若它仍在原生后台终端列表中，调用 `thread/backgroundTerminals/terminate(threadId, processId)`，再确认该终端退出。实测子进程消失、心跳停止，同一对话仍可继续。该精确接口（API）目前需要实验协议能力，纳入固定版本要求；不使用全对话 `clean` 代替本轮精确终止，也不能按操作系统进程编号猜测原生 `processId`。

Qoder 本轮还观察到 `AskUserQuestion` 实际消息中的 `questions[] / answers{}` 与静态工具类型不一致。适配层（Adapter）按固定版本的真实消息验证输入和回复，不直接根据静态类型拼界面；该差异必须有真实工具调用回归。

服务异常退出后，保留历史和已发生的改动，重新读取原生状态。不能将“没收到结果”自动解释成“没有执行”，也不能自动重试工具命令。对于未确认的发送，界面保留具体诊断和用户草稿；先核对历史、原执行及工作现场，再决定是否重新发送。断开接入、连接失败或消息流结束均不能把对话直接设为“已停止”。

收起对话面板后，全局入口保留待授权／待回答的计数或状态点，点击定位准确对话。原执行状态未知时也保留可发现的提示；无需通知中心、自动弹窗或系统推送。工作页面继续通过已有查询和显式刷新读取当前事实，不为了提示新增通用事件总线。

## 8. 独立智能体服务与具体执行者

当前已确认把 `services/buildr-agent/` 作为独立源码服务（Service）维护。它负责账号、统一对话、参与绑定、接续、执行控制和私有交互数据；前端仍在 `buildr-web`，Buildr 后端负责本机应用装配、鉴权和网页接口。首版同进程装配、随 Buildr 主包交付，不新增常驻守护进程（Daemon）或独立公开发布包。

`buildr-agent` 服务与未来的 Buildr 自研智能体（Agent）需要分开：前者提供统一交互和执行接入，后者可以作为一种实际执行者（Executor），与 Codex、DSH、Qoder 并列服务 Buildr。公共契约不强制所有执行者使用命令行进程或厂家配置格式；当前三家原生适配各自处理这些细节。本版不实现自研推理循环，也不在界面提供不可用的占位执行者。

| 边界 | 第一版安排 |
| --- | --- |
| `services/buildr-agent/` | 独立源码、依赖、公开库入口、私有存储、执行者契约及测试；只启用经过验证的三家实现。 |
| `services/buildr/` | 通过公开库入口装配服务，注入已解析配置和工作空间／任务查询能力，承担鉴权与网页传输。 |
| `services/buildr-web/` | 账号、统一历史、输入、消息及工具交互；不直接调用原生进程。 |
| `services/dsh-plugin/` | 保持原外部桌面插件的职责及交付方式。 |

实施时通过已有项目组成能力登记第四个服务，保留原三个服务。新服务以私有本地包（Library）显式纳入开发准备和主包捆绑交付；开发与正式安装走同一公开入口。安装验收须证明移走相邻源码后，服务、厂家客户端、运行依赖和迁移资源仍完整可用，不能仅新增目录并依赖跨目录导入。

公共服务不反向导入 Buildr 宿主源码，宿主不深入读取新服务内部实现；需要工作空间和任务事实时通过明确端口核对。旧 `agent-operations`、`native-session-links`、桌面桥、原接入登记与接口不扩展、不迁移、不双写。内部任务关系仍指向统一对话，外部关系仍指向原生会话（Session）。

私有交互数据继续位于应用配置域（Profile）的 `dataRoot/agent-service/`，代码服务名称变化不要求更改接口或数据路径。文件、任务和外部系统仍是工作成果的权威来源。具体源码布局、公共契约、打包与生命周期决定以[正式详细设计](../design.md)为准。

### 全局入口与当前页面布局

- 保留原来的导航和工作屏职责，只将顶部一级目录移到原工作区左侧固定的竖向图标列：工作台、工作空间、代码。图标列不展开文字，也不计为一块工作屏。
- 悬停一级图标时浮出该目录原有的二级导航，移入可继续操作，移出收起，也可固定展开。工作台使用现有的“概览、任务、我关注的项目”；工作空间和代码同样导入真实导航。任务列表不是二级导航，不将其移入该面板。
- 原中屏仍显示任务列表等页面内容，原右屏仍显示任务详情等对象内容。直接复用现有 `WorkspacePaneStage`、页签和分隔条，各自保留折叠、悬停暂看、展开、滚动与宽度调整。打开、关闭或查看对话历史不自动折叠、移动或重建这两块工作屏。
- 对话由独立全局入口打开，默认另外增加在最右侧。菜单支持移到左侧，此时整个对话区位于一级图标列之前；历史随对话移动，原导航和两块工作屏保持状态，也可切回右侧。日常二级导航和对话都收起时，是原来的两块工作屏；只固定展开二级导航为三屏，再打开对话为四屏。原中屏或右屏收起一块，就保留一块主工作屏。窗口变窄时沿用原有自适应行为。
- 对话历史在同一对话面板内替换显示，不新增并排历史栏；按主题、任务、时间和状态组织，参与人数辅助显示，不按 Codex、DSH、Qoder 分类。历史、对话和草稿独立于导航展开状态。
- 对话在应用外壳（App Shell）中管理，不隶属于工作台或任务。每段对话保留自己的工作空间（Workspace）与起始目录（CWD）；浏览其他页面不静默改变执行位置，也不自动发送页面内容。
- 任务“打开对话”是定位相关对话的快捷入口：零关联创建，一个直接打开，多个先选择。当前工作对象变化不替换正在使用的对话。
- 同一段对话手动选择下一位执行者，发送才接续；每条回复、工具操作和授权保留来源。当前轮次或活动工具未确认结束时先观察或停止，不允许换家发送。账号设置和历史仍在对话区访问；收起后全局入口保留待回应及必要的状态提示。

本轮原型直接复用当前任务列表、任务详情、对象页签、应用壳、主题、分隔条、悬停控制及账号抽屉（Drawer）的来源，只在原型入口替换数据和副作用。对话、授权、账号及多位参与者均为内存演示，不调用三家真实服务；另行完成的真实接续实验不等于界面已经接通。正式源码、路由、安装及共享配置未修改；候选源码与构建入口保留在既有隔离工作树（Worktree）。

### 为图形界面与对话界面（GUI＋Talk UI）保留的基础

1. 全局对话独立于任务详情及具体业务页面；浏览页面不会静默改变执行位置或发送上下文。
2. 使用现有任务编号、文件路径和系统链接引用同一对象；文件或业务系统继续持有当前内容，不新增工作对象库，也不把聊天副本当成果权威。
3. 输入边界可容纳用户显式提供的文字、图片及准确任务引用；以后可增加用户主动提供的选区，第一版不自动抓取所有页面上下文。
4. 消息、工具结果、文件改动及授权保留结构化来源和请求身份；前端先显示基本内容和已有链接，不提前建设任意界面生成引擎。
5. 人或智能体（Agent）修改后，原页面复用已有查询和刷新读取同一当前事实；接续方再次核对真实文件，不新增通用事件总线，也不要求所有变化自动唤醒智能体（Agent）。

这些是新单元的输入、引用和事件边界，不是另建一套平台的清单。第一版先让日常对话与工作页面可靠共存，具体业务现场的融合按真实用例逐步扩展。

## 9. 实施顺序与验收

| 阶段 | 可独立评审的成果 | 完成依据 |

第一版验收重点：

1. 在当前工作空间（Workspace）下提问和执行，原生规则与技能来源可检查，实际调用有证据。
2. 跨目录读取和修改遵守实际原生权限，目标规则由智能体（Agent）核对；不额外禁止用户已有的跨工作空间（Workspace）工作方式。
3. 工具执行中的停止准确作用于本轮目标；分别覆盖停止中、已确认停止、工具仍运行和状态未知。仅在证明本轮相关工具退出且不再延迟写入后显示确认停止；不误停早先有意保留的后台服务。
4. 重启服务后按准确编号读取历史、继续追加，历史上下文保留，不生成替代对话、不重放上一条指令。
5. 断线、账号失效、版本不兼容与单家不可用分别报告，不阻断其他接入。
6. 默认独立配置，Buildr 日志和前端事件不写秘密；原生运行目录及诊断按敏感状态保护、导出前脱敏，断开接入不退出账号。本轮发现 Codex 原生诊断和登录成功地址会包含认证信息，因此不能仅凭 Buildr 协议日志已脱敏就承诺整个原生目录或浏览器回调可公开。共享配置不纳入第一版。
7. 文本、图片、流式输出、工具结果、授权、补充问题及模型选择依据所选版本和模型的真实能力验收，不支持的输入或动作明确显示；权限采用原生默认和逐次授权，不伪造三家等价档位。
8. 同一轮等待授权时能够回复，长命令执行时能够停止，不被上一条发送占用的锁阻塞。运行中补充保留草稿且不误报送达；原生追加或排队若要开放，必须额外提供对应真实验证。
9. 同一段对话手动更换参与者后，标题、草稿、任务关系和已有消息来源不变；显示准确执行位置及实际接续正文。超限不默默摘要，原执行未知不换家发送。本次真实接续及换回已通过，正式服务的交付确认、未知结果处理与历史补齐仍需验收。
10. 一级目录始终保持竖向图标列，位于原工作区左侧；对话默认最右，可整体移到一级图标列左边。悬停显示真实二级导航；原中屏、右屏保留自身折叠与展开。二级导航及对话都收起时为两块工作屏，展开二级导航为三屏，新增右侧对话为四屏。收起后仍能发现并返回等待回应的准确对话。
