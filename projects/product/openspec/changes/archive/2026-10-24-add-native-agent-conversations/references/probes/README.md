- `continuity/`：2026-10-23 全新独立登录、四步跨家接续、换回原执行方、三家冷恢复及独立清理证据；先读其 `REPORT.md`。

不包含认证缓存、原生诊断数据库、原生会话存储、已下载程序或 `node_modules`。代码中出现的配置文件路径是实验程序的读取入口，不包含文件秘密。各家账号及进程清理证据另见子目录。

## 复现边界

程序是按当次机器与路径冻结的实测来源，部分仍包含当次唯一临时目录、程序路径、实际 Buildr 只读发现目录和 DSH 非临时测试场地。**不要直接从这个代码库目录运行模型实验。**

再次验证时，由执行者：

1. 核对本轮授权、准确程序与固定版本，将所需脚本复制到新建的独占操作系统临时目录。
2. 在新副本中把 `/tmp/buildr-agent-integration-wgc0iS` 替换成新实验根；DSH 非临时缓存场地也换成新的独占路径。保留两组兄弟目录与实际权限差异，不能把跨写负向探针全放到默认可写的临时目录而不处理例外。
3. 依据相应锁文件（Lockfile）只在新临时目录安装依赖，核对实际版本。Codex 仍需原生可执行程序，不从协议摘要推断其版本兼容。
4. 建立独立账号配置；官方登录需要用户完成。没有有效账号时只能执行发现及未登录路径，不能把它们作为模型执行证明。凭据不写进脚本或证据。
5. 按三家 `REPORT.md` 的实际命令顺序执行。新场地只准备输入和规则，清除复制来的合成输出及旧原生编号；恢复测试应使用这一次新创建的准确编号。
6. 核对实际文件结果、原生历史、活动工具和进程；停止不能只看中断回执。完成后清理本次凭据、敏感原生日志和自有进程，再脱敏保全证据。

Codex `--approved-cache-snapshot` 和 DSH `step2.mjs` 都会读取已有认证来源并在隔离目录中临时使用。它们是本轮明确范围内的验证手段，不是正式产品自动导入凭据的设计；后续执行者须重新核对仍有效的账号使用授权，不默认复制无关配置。

原实验目录中的账号与部分原生历史已清理，因此不能把保留的原生编号当成当前仍可打开的用户对话。
