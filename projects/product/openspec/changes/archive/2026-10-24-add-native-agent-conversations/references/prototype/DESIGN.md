## 保留的布局

- 顶部工作台、工作空间和代码一级目录移到原工作区左侧固定竖向图标列；图标列不展开文字，不计为一屏。
- 悬停一级图标浮出其原有二级导航；移入可操作、移出关闭，可固定展开。工作台为概览、任务、我关注的项目，任务列表不进入导航。直接复用 `AppNavigation` 与 `usePanePeek`。
- 原中屏任务列表、原右屏任务详情完整保留，继续使用真实 `WorkspacePaneStage`，保留各自折叠、悬停暂看、展开、滚动与宽度调整。对话操作不自动折叠工作屏。
- 对话是全局独立入口，默认增加在最右侧；历史在同一对话面板切换，不按提供者（Provider）分类。移到左侧时，整个对话区位于一级图标列之前，历史随它移动，原导航及工作屏状态保留。
- 日常二级导航和对话都收起时是原来的两屏；展开二级导航为三屏，再打开对话为四屏。原中屏或右屏收起后保留一块主工作屏；窄窗口沿用原有自适应行为。
- 任务零／一／多个内部对话分别创建、直接打开、选择准确对象。第一版一段对话最多关联一个可选任务；普通咨询不依赖任务，不新增跨任务关系管理器。
- 页面浏览不自动推进任务、注入上下文或改变对话保存的起始目录（CWD）。关闭与恢复对话保留原工作屏状态。

## 本轮修正的交互

| 审查问题 | 本轮设计要求 |
| --- | --- |
| R1 首版范围与旧入口职责 | 账号页每家一套固定独立配置，移除共享桌面配置选项。旧“提出新目标”等工作动作不改接普通新对话；任务中内部对话与外部会话分别显示，外部入口仅说明保留原职责。 |
| R2 停止与失联状态 | 提供正在停止、已确认停止、模型已中断但工具仍运行、状态待确认的演示。正常路径收到模拟停止回执后自动更新；未知或仍运行时可重新检查，不要求每次停止都人工确认。断开接入不能直接变成已停止。 |
| R3 真实能力差异 | 采用原生默认权限和逐次授权，不提供三家语义不同却相同的“只读／完全访问”档位。模型按当前接入显示；DSH 说明选择同时影响独立配置的后续默认模型。运行中补充保留草稿，不误报成已送达。 |
| R4 执行位置与接续预览 | 显示保存的准确目录、工作空间（Workspace）与可选任务。换家前可查看实际将交付的内容和记录范围，不只显示类别。超容量保留草稿，可以继续原参与者或明确提供可查看的精简接续说明，不默默摘要；已确认的说明作为可见材料保留给后续参与者。 |
| R5 收起后的待回应提示 | 全局入口显示待授权、待回答及必要的未知状态提示，点击返回准确对话；不增加通知中心或自动弹窗。 |

同一段对话可手动选择 Codex、DSH、Qoder 顺序参与，保留身份、历史、草稿、任务和消息实际来源。选择下一位不立即发送。执行、等待授权、等待回答、停止中、工具仍活动或原执行状态未知时，不能换家启动新工作；恢复联系并确认原执行结束后再继续。原生授权和回答始终送给产生请求的参与者，不随输入框选择改变来源。

各条路线固定为：Codex 的 `codex app-server`、DSH 的 `dsh web` 完整宿主（Host）、Qoder 官方软件开发工具包（SDK）管理配套 `qodercli`。共享界面不意味着权限、模型、图片、追加指令和桌面扩展自动等价。原型示例账号、模型和状态只用于评审交互，不是实时可用性查询。

## 第一版范围与后续基础

第一版形成新建／打开、输入、流式回复、工具反馈、原生授权及提问、停止、错误处理、历史、准确恢复和手动切换执行方的完整链路。文本为必需；必要图片输入按实际接入版本和模型能力逐家验收，不扩成通用附件解析中心。运行中新增内容先保存在草稿，只有真实验证后的追加或排队能力才单独开放。

第一版不增加共享配置、多账号池、通用自带密钥（BYOK）配置中心、桌面专属浏览器、语音、扩展市场、自动化、完整差异编辑器、并行团队、自动分工、长历史自动摘要或额外的 Buildr 常驻宿主进程。Qoder 官方已有自带密钥（BYOK）路径，但固定软件开发工具包（SDK）组合尚未完成相应执行验证；不把它描述为永久不支持。

为图形界面与对话界面（GUI＋Talk UI）保留的基础限于：独立全局对话身份；用户显式提供的文本、图片及任务引用；已有任务编号、文件路径和系统链接；带准确来源的结构化消息、工具及授权事件。工作成果仍由真实文件与业务对象持有，原页面沿用已有查询和刷新读取当前事实。首版不新增工作对象库、通用事件总线、任意界面生成引擎或自动页面上下文。
