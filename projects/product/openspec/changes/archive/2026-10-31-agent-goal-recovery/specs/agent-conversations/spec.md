## RENAMED Requirements

- FROM: `### Requirement: 开发版必须自动接续可确认的系统中断`
- TO: `### Requirement: 系统中断必须自动核对并接续原目标`
- FROM: `### Requirement: 正式版必须明确表示未完成执行`
- TO: `### Requirement: 自动恢复必须保留未完成事实并防止重复执行`

## MODIFIED Requirements

### Requirement: 系统中断必须自动核对并接续原目标

Buildr 开发版与正式版 MUST 默认自动恢复已受理、非用户主动停止的系统中断，不以用户再发消息或页面打开为前提。恢复 MUST 沿用原智能体（Agent）、账号身份、模型（Model）、档位、工作位置及权限。原执行仍在运行时 MUST 只恢复观察，已确认正常完成时 MUST 不追加重复工作。准确控制资源已释放且无活动工作及待决定时，历史结果未知 MUST NOT 单独阻止智能体先核对现状并继续原目标；恢复 MUST 保留未知结果，要求先查当前成果、原工具及未决副作用，MUST NOT 重放原提示或未知操作、推定独立命令退出、扩展权限或替用户决定。没有准确原身份或资源释放证明时 MUST 继续保护相关工作。

#### Scenario: 开发版重启后继续
- **WHEN** 系统中断导致原轮停止或准确控制资源已经释放，原组合仍有效且没有待决定
- **THEN** 系统 MUST 自动组织已有成果和原目标并交给原组合执行，不要求人发送“继续”或“如何了”
- **AND** 结果未知仍保留未知，智能体 MUST 先核对事实再继续，不逐条重放旧工具

#### Scenario: 无法安全恢复
- **WHEN** 原执行仍运行、控制释放未确认、原账号身份失配、额度或认证不可用，或存在待决定
- **THEN** 系统 MUST 只推进可安全观察的部分并保留准确原因，MUST NOT 重复执行、换组合或代答
- **AND** 用户主动停止 MUST 取消对应自动接续


### Requirement: 自动恢复必须保留未完成事实并防止重复执行

系统 MUST 保留系统中断及旧轮未知结果，不能冒充用户停止或工作完成。自动接续 MUST 使用持久唯一请求身份并关联原运行，重复启动及并发核对 MUST 不重复发送。连续失败 MUST 共享持久有界恢复预算，至多三次自动接续并退避；恢复执行再次中断 MUST 在剩余预算内继续，MUST NOT 一次失败后永久冻结目标或形成无限恢复链。发送前中断 MUST 可按同一恢复意图接续。新用户要求、用户停止、必要决定或实际身份变化 MUST 阻止旧恢复覆盖当前工作。已正常完成的对话及普通正式任务 MUST NOT 被启动核对自动重跑。

#### Scenario: 重复启动与发送前中断
- **WHEN** 自动恢复意图已保存后系统再次退出，或并发请求恢复相同原运行
- **THEN** 系统 MUST 沿同一请求身份核对受理事实并只接续一次，不生成重复业务输入

#### Scenario: 恢复再次中断
- **WHEN** 同一目标的自动恢复再次因系统连接失败中断
- **THEN** 系统 MUST 在共享的三次预算内自动接续，耗尽后给出准确原因并保留成果

#### Scenario: 取消与新要求
- **WHEN** 人停止恢复、提交新要求或原轮已正常完成
- **THEN** 系统 MUST 取消旧恢复意图，不覆盖新轮、不继续旧目标


#### Scenario: 正式版启动
- **WHEN** 正式版发现具有可信系统中断来源的未完成执行
- **THEN** 系统 MUST 默认自动核对并按原目标恢复，保留未完成与未知事实，不因发行角色要求用户补发消息

### Requirement: 原生连接中断必须自动核对并安全恢复

宿主仍运行时原生连接确认断开，系统 MUST 保留准确会话和执行身份，重建同一绑定并有界自动核对。已受理且非用户停止的中断 MUST 纳入同一原目标自动接续策略，开发版与正式版 MUST 一致。只有原执行已停止，或准确原控制资源已释放且无活动工具及待决定时，才可自动交给原组合先核对成果再继续；未知历史结果 MUST 保持未知而不冻结全部目标。用户停止 MUST 取消待执行的接续。已确认失效的连接 MUST NOT 持续复用；诊断 MUST 区分观察中断与账号或程序不可用。

#### Scenario: 宿主存活时连接断开
- **WHEN** 已受理连接断开且准确原执行已停止或控制资源已释放
- **THEN** 系统 MUST 按原组合自动接续，保持同一目标来源、原权限及有界恢复身份

#### Scenario: 结果仍不确定
- **WHEN** 原执行仍运行、身份失配或资源释放尚未确认
- **THEN** 系统 MUST 继续核对并保护原工作，不另起重复执行

#### Scenario: 用户停止或待决定
- **WHEN** 用户主动停止或中断前存在待回答及待授权事项
- **THEN** 系统 MUST 不自动续做相关工作

#### Scenario: 存量未知执行
- **WHEN** 启动后存在已受理但缺少可信系统中断来源的未知执行
- **THEN** 系统 MUST 核对原生事实，MUST NOT 仅凭未知状态自动重跑历史；当前已提交的新要求继续独立执行


### Requirement: 控制资源释放后的显式继续

用户已明确要求继续原目标、准确原轮已受理且结果未知、原控制资源释放已经核验、没有待决定及该对话的在途工作、并且原参与者、模型来源、模型、档位和权限保持一致时，系统 MUST 允许用准确原轮身份手动预览并接续一次。系统 MUST 保留原轮未知结果、工具条目和原生执行引用，接续提示 MUST 要求先核对当前成果及未知命令，MUST NOT 重放原指令或工具、推定独立命令退出、宣称旧工作成功或代答问题。预览和发送 MUST 校验同一已观察版本与准确原轮；没有释放证明、存在待决定或选择变化时 MUST 拒绝此例外。普通发送和排队 MUST NOT 冒充该显式请求。具有可信系统中断来源的自动恢复 MUST 按原目标恢复契约独立判断，不以历史结果未知为整个目标的阻塞；同样 MUST 先核对现场且不得重放未知操作。

#### Scenario: 已释放但原结果未知时明确继续
- **WHEN** 用户要求恢复原对话，准确资源释放已成立，原轮仍有未知工具结果且没有其他在途工作或待决定
- **THEN** 原组合的显式继续 MUST 被接受一次，原轮和工具结果 MUST 继续保持未知并可查，接续提示 MUST 要求先核对现状

#### Scenario: 没有释放证明或存在待决定
- **WHEN** 释放未确认、原轮身份或版本变化、请求仍待答、原轮中断前有未解决决定、或者选择发生变化
- **THEN** 手动继续 MUST 被拒绝，原记录和输入 MUST 保留

#### Scenario: 禁止隐式恢复未知结果
- **WHEN** 页面刷新、后台重启、自动恢复、普通发送或排队发生
- **THEN** 系统 MUST NOT 据资源释放直接重发或续做未知操作；满足系统中断恢复契约时 MAY 自动发起先核对成果的原目标接续

### Requirement: 异常结束必须提供原目标恢复动作

一轮执行（Run）异常结束或已结束但没有可见答复时，界面 MUST 在异常附近提供“重试”或“继续”入口，不依赖用户是否切换模型或智能体（Agent）。未送达请求 MUST 恢复原输入及附件；已接收请求 MUST 先核对已有成果并接续原目标，MUST NOT 逐条重放旧工具。恢复 MUST 使用用户当前选择的执行组合，保存为关联原执行的系统动作，MUST NOT 额外制造用户“继续”消息、重写历史或清空草稿。原执行与工具未确认结束且控制未核验释放、有待用户决定或正在自动重试时 MUST NOT 另起重复恢复执行；系统中断 MUST 优先自动核对并接续，未知状态 MUST 保留准确事实和核对入口。恢复提交 MUST 校验原执行身份及当前版本，重复提交 MUST 保持同一执行身份；迟到或过期请求 MUST NOT 接续其他轮次。

#### Scenario: 同一执行组合恢复未送达或中断请求
- **WHEN** 用户没有切换选择，在异常提示旁点击“重试”或“继续”
- **THEN** 系统 MUST 根据原送达事实恢复原请求或接续原目标，保留历史并且不新增用户“继续”消息

#### Scenario: 切换模型或智能体后恢复
- **WHEN** 用户选择另一模型或智能体（Agent），再点击恢复动作
- **THEN** 系统 MUST 按当前选择组织原目标及交接，保留草稿和原附件，恢复动作只执行一次

#### Scenario: 未知、过期和正常完成不重做
- **WHEN** 执行状态未知、工具未结束、来源轮次已变化，或已经正常答复
- **THEN** 系统 MUST 拒绝直接重发，保留现场；未知可核对，正常答复不展示异常恢复入口

## ADDED Requirements

### Requirement: 同一执行组合的内部恢复必须透明

同一智能体（Agent）、账号身份、模型（Model）、档位、思考强度及权限下的内部重连或原生上下文（Native Context）重建 MUST 继续同一可见对话及原目标。系统 MUST 传递必要原始历史和当前成果来源，但 MUST NOT 仅因参与者或上下文编号变化生成用户交接事件、展示“交接内容”或要求人工确认交接。真正更换执行组合 MUST 保留既有交接及来源核对能力。已有历史交接记录 MUST 保持原样。

#### Scenario: 同组合替代失效上下文
- **WHEN** 同组合因系统故障需要新的原生上下文
- **THEN** 原目标和来源 MUST 自动送达，用户 MUST 不看到虚假的换人交接动作

#### Scenario: 真实切换模型
- **WHEN** 用户明确更换智能体、账号、模型或执行配置
- **THEN** 系统 MUST 按真实选择组织交接并保留来源，不与内部恢复混淆

### Requirement: 已释放历史执行必须与当前待处理分离

准确资源已释放且无活动工作、未知工具或待决定的历史旧轮 MUST 保持可追溯，但 MUST NOT 在当前输入区域常驻“保留原执行”折叠项或被当作仍需人工处理的执行。仍有活动、未知工具或待决定时 MUST 继续呈现准确风险与可执行动作。系统 MUST NOT 因收起或移除提示改写旧结果、删除原引用或冒充目标完成。

#### Scenario: 仅终态未知的旧轮已回收
- **WHEN** 旧控制已释放，全部工具有完成回执，且没有原问题或待决定
- **THEN** 当前对话 MUST 继续原目标，不展示无操作价值的常驻旧执行折叠项，原历史仍可核对

#### Scenario: 仍有真正未决工作
- **WHEN** 控制尚未释放、存在活动或未知工具、或需要用户决定
- **THEN** 页面 MUST 保留准确风险和必要控制，不隐藏真实问题
