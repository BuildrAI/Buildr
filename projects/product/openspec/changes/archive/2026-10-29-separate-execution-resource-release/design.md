## Context

当前 AgentService.activity 将持久化未结束记录计为 unfinished-execution，retiring 依赖该结果。close 后的 confirmed 又依赖同一计数，形成历史疑点锁住资源的循环。ConversationApplication.busy 同时承担防重发和资源持有判断，需要分开。

## Goals / Non-Goals

目标：保留成果与历史结果的真实不确定性；以准确原生执行和受管资源证据确认结束及释放；空闲旧后台可退役，活跃或无法确认的资源不能误放行。非目标：替智能体验收业务目标、删除用户历史、绕过未知工具结果的重发保护、接管旧版本没有证明的资源。

## Decisions

1. 三类事实分开。正式任务和成果仍由原权威负责；RunView 增加可选 executionState 与 resourcesReleased，原 status 和工具记录继续保留结果不确定性。释放事实绑定原 run/participant/generation，不能使未知结果自动重发。
2. 执行器提供可选的准确控制资源核对能力。返回可释放与原执行判断，允许控制资源可释放但独立命令仍未知。Codex 与 Qoder 结合准确身份、原生结束/进程退出事实、自有控制进程组及 SDK 后台任务证明关闭控制连接不会中断其仍持有的工作；待决定、活动控制子进程或身份不匹配时保守。
3. POSIX 原生 RPC 使用独立控制进程组，核对不能排除其中仍活动的子进程。原生命令会新建独立进程组甚至进程会话（Process Session），因此控制组空闲仅证明可释放控制资源，不能推断独立命令结束。原生主进程退出而工具结果缺失时保留 executionState=unknown 和未知工具结果；不终止独立命令，不重发。Windows 缺少对应控制组证明时保守；不引入系统 Python、Perl 或名称匹配。关闭后再次核对，晚退控制资源继续保留原持有并核对。
4. ConversationApplication 逐同源资源组核对全部持有者，只有全部可释放且没有本轮辅助工作时关闭该资源，成功后分别保存释放事实和原执行判断，不强制二者同时结束。一个仍活动的对话不得被同组其他记录越过。
5. 后台忙闲与关闭确认使用实际工作和未释放资源；历史未知仍影响对话续做准入，不能单独阻止无资源旧后台退役。已释放资源的记录仍可通过准确终态观察补回结果，但不得被迟到活动事件复活。隐藏仅对已确认执行结束且资源释放的未知结果生效，仍活动或资源未知的隐藏对话继续可见。

## Risks / Trade-offs

- 进程会话（Process Session）无法证明原生明确登记的后台工具或脱离执行管理的工作 → 已知原生后台任务和无法核对情况不放行；保留未知结果及人工核对，不推定业务成功。
- PID 被复用或范围漂移 → 不按恢复的 PID 发送信号；只观察准确自有 ChildProcess 的组，空闲事实对原执行单调保存。实际关闭仍使用原持有对象。
- 旧数据和旧后台无新证明 → 保留原观察与控制，不伪造释放，不要求迁移所有历史。
- 并发停止或新输入 → 释放前后核对同一运行身份和资源组持有者；原执行记录保持未知可阻止下一轮自动开始。

## Migration Plan

可选字段不改变旧资料格式，按既有兼容后台并行采用；新证据仅用于准确所属执行。回退时未知结果仍不能自动重发。验证须包含有工具仍存活时不释放、未知结果但资源已结束时释放，以及另一真实执行不受影响。
