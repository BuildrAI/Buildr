## Context

动机见 proposal。现有监督器启动两个 Vite 子进程，抓取宿主 meta/cookie 并代理 API；Buildr 使用 Node watch 直接重启，Harness 通过不可变运行单元交接。9519 的监听由 Harness 协调代次拥有，不应把网页开发变更扩展为执行核心重启。

## Goals / Non-Goals

目标是固定入口、最小更新范围、失败可恢复和真实版本可见。不建立通用后端热替换框架，不承诺零断连、不自动回滚数据或用户文件，也不把热更新产物作为交付证明。

## Decisions

### 同源开发适配

以 dev-only 动态适配挂载 Vite middlewareMode，两个 root 与 base 明确分开，HTML 由宿主经过 transformIndexHtml 后注入自己的会话。HTTP/API、网页资源和 upgrade 都保留原宿主认证；开发 CSP 使用 nonce 和准确同源 WS，不全局放宽生产策略。独立网页显式 `--live` 选择开发源码根，只在 development profile 接受；配置保留在既有网页端点状态中，使兼容代次恢复相同入口。旧静态入口和生产构建保留。

### 受控后端更新

去抖监督器只监听源码输入，排除生成目录、node_modules 和前端。每批取不可变代码快照，使用 Node 开发加载钩子从快照加载源码但保留原模块 URL，保持 checkout 归属和文件路径语义。准备与模块导入检查失败不退出旧宿主；切换后启动失败则用上一快照恢复。资源、依赖安装和数据库不自动回滚；涉及依赖不兼容时明确保留未采用状态。不同于裸 watch，监督器掌握切换、恢复和子进程退出。

### Harness 和契约

继续调用既有包准备及代次交接，不更改旧执行退休规则。准备、类型生成和激活使用新进程，避免常驻监督器导入旧包。契约生成成功后协调宿主重启；失败与超时重新观察实际后台，分别报告当前和目标，不把异常一律说成旧版保留。批次中又发生变更只触发下一批最新内容。

### 单一更新窗口

开发后台切换和正式开发安装共用按真实 Git common-dir 定位的短更新锁，自举锁存在时开发监督器暂停。正式流程结束后重读 development 实例，仅在可认证、同一 checkout 的实例上恢复；不抢占未知进程或其他工作树，不扫描 previews。正式激活本身仍完全由原执行器负责。

## Risks / Trade-offs

- [后端重启导致连接断开] → 复用已有会话续期、草稿和流重连，不重发结果未知的写入；不承诺所有 React 状态在整页刷新后保留。
- [代码快照与依赖变化] → 明确快照覆盖代码与当前已准备包；依赖声明变更需要重新准备，恢复不伪称可回退任意依赖/数据。
- [双 Vite 路由与认证] → 资源、HTML、WS 分别做集成与浏览器验证，API 不进入 SPA fallback。
- [开发失败影响执行] → 前端不注册执行重启监听，Vite 初始化及请求错误只在网页边界返回，释放监听时先关闭其 Vite 实例。
- [激活并发] → 共享更新锁保护准备/切换，自举锁保护整个正式窗口，实时实例身份决定恢复对象。

## Migration Plan

删除 5173/5174 参数及代理，默认打开宿主地址；CLI 说明解释独立 `--live`、生产预览不启用开发适配。变更归档后正式入口按现有自举执行器激活；开发模式不替代该过程。
