## Context

现有扫描器已提供有界、安全、去重的 62 份文档发现，知识索引保留独立主题/成果身份，前端复用普通 Markdown 与既有成果阅读器。当前缺的是读者组织，文件扫描和读取边界可继续复用。

## Goals / Non-Goals

**Goals:** 同一知识入口明确切换阅读方式，作者能够用阅读章节组织所有文档，普通正文和补充阅读层次清楚，未编排及旧索引保持可用。

**Non-Goals:** 不新增文档编辑器、智能体调度、权限机制、数据库、全文索引或正文副本，不改变正式图示和代码地图的阅读器。

## Decisions

- 在 `knowledge/index.yml` 增加可选 `documentSections`。每章包含 `id/title/summary/entries`，条目使用 `location/path/title/summary` 和可选 `supplementary`，位置缺省为 `scope`。沿用一个阅读索引，避免前端按路径猜业务语义；七个实际章节由内容审查决定，不硬编码进产品。
- 最多 64 个作者章节、1000 个条目；匹配只消费已发现的文件。目录输出 `sections` 与每个文档的 `sectionId/summary/supplementary`，保留原身份和路径。未匹配编排的真实文件进入保底 `unorganized`；重复引用按首个有效条目处理并诊断。
- 编排校验归文档阅读责任方，局部错误不影响已有主题索引投影；旧主题 HTTP 响应不夹带未校验的新元数据。目录版本同时反映文件发现和编排变化，正文复用同一编排结果。
- 主页面与侧读共享顶部两种模式。文档提供轻量章节导航，让首屏能了解章节全貌并快速选择；列表呈现用途与按顺序排列的标题/摘要，补充阅读折叠；搜索覆盖全部内容及章节文字，命中辅助条目时可直接阅读。文件位置只在正文次要展示，保留旧链接与返回搜索。
- 当前自举编排覆盖 62 份，主要正文优先，图示依据、语言副本和纯导航等按实际用途设置补充属性。其他项目未编排时保留完整普通文档列表，不复制 Buildr 的章节模板。

## Risks / Trade-offs

- 编排需要维护 → 移动或删除只形成局部诊断，新文件始终可发现；阅读不自动写回。
- 元数据混入主题协议会扩大故障 → 文档责任方独立解释，主题响应保持闭合，补回归验证。
- 大量辅助资料继续挤占注意力 → 同章补充阅读默认折叠，搜索及总数仍覆盖。

## Migration Plan

新增字段可选，旧索引和旧文档地址继续可用；同时交付前后端契约与当前内容编排。回退实现时一并回退新增编排字段，无正文或数据库迁移。
