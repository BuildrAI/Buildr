## Context

现状是三层分置：核心规则声明"收尾"不授权远端删除，`task-finish` 承载清理方法，`git-worktree-provider` 契约只管本地资源。缺口在于推送侧只受"有无远端用途"的智能体（Agent）判断约束，而删除侧需另授权——不对称使残留必然发生；且 `task-finish` 指向 Git 操作提供者（Provider）执行删除，但该提供者未路由 `branch deletion`。

## Goals / Non-Goals

目标：没有特殊授权时，工作空间（Workspace）不推送任务分支（Branch）到远端、不留任务分支在远端。非目标：不替各仓库默认授予删除授权——授权仍按仓库规则分配；不改动发布引用（Ref）的绑定政策；不新增状态库、收据或流程门禁。

## Decisions

- 两条不变量进核心规则源 `resources/workspace/AGENTS.md`：授权边界属于规则（Rule）层并对所有入口生效，技能（Skill）正文只承载方法；技能可随维护精简，授权语义不应随之漂移。
- "不留"是处置义务而非删除义务：删除仍受归属、交付保全、活动用途与实时观察提交约束；授权或安全条件不满足时逐项报告或提出最小授权问题——残留显式化，替代静默保留。
- 推送授权绑定生命周期：授权推送任务引用时同步确定处置（默认随用途结束删除），避免收尾时才暴露授权缺口。
- 枚举不依赖会话记忆：对任务范围每个仓库以任务分支名查询实际远端，分支名取自工作树证据或任务记录的 `branch`；手工另建的远端引用归属未知时保留并报告，不扩大删除。
- 远端删除作为 `git-operations` 的 `delete-remote-ref` 操作（Operation）而非原生命令直删：远端引用是共享状态，统一走提供者的身份核验、条件删除与 effects 报告。契约保持 v1——新操作由 consumer 逐个显式选择，未选择它的调用行为不变，属增量兼容。
- 工作树提供者（Provider）保持纯本地：开放合并请求（Pull Request）、未结束运行等远端协作语义不是本地资源删除安全能核验的。

## Risks / Trade-offs

- 删除授权未覆盖的仓库在收尾时会得到逐项残留报告或一次最小授权问题：这是设计意图，用显式化替代静默残留；仓库可声明持续授权消除重复询问。
- rebase 留下的过期远端 tip：保全证明落在"交付提交由保留引用（Retained Ref）持有"，而非旧 tip 的祖先关系，与 worktree 契约放弃祖先/补丁等价检查一致。
- 远端在检查后变化：按已观察提交条件删除并在漂移时 `blocked`，不改用无条件删除。

## Migration Plan

metadata-only：更新源资产后随正式自举同步投射到工作空间（Workspace）即生效，不直接编辑受管投射副本。无数据迁移；既有仓库持续授权（如 `BuildrAI/Buildr`）独立适用。
