## Context

动机见 `proposal.md`。当前任务记录（Task Record）、项目资料读取及 OpenSpec 收敛实现均可运行于无 Git 现场；阻塞来自默认隔离指引和直接消费者。Git 工作树（Worktree）提供者只保证真实代码库位置及删除安全，不应承担任意资料的工作位置。

知识维护是技能（Skill）与专业文件工具协作；知识接口是读取入口。原始清单已声明任务能力 `v4`，相关静态检查仍要求 `v3`，且旧 `v3` 契约留在未映射交付目录；旧契约仅用于退役测试，原字节移入测试夹具（Fixture），保留退役元数据并校正当前版本断言。

任务材料写入具备摘要版本保护，但只写本机任务材料目录，不能转作任意项目文件写入接口。应用锁不能保护任意外部编辑器。

## Goals / Non-Goals

**Goals:** 让任务开始、资料维护、材料引用、规范操作和收尾采用同一真实归属判断；纯非 Git 资料可执行，未知身份不能被放行；现有专业动作继续拥有其版本和副作用边界。

**Non-Goals:** 不改变 Git 提供者或契约（Contract），不增加绑定、许可层、位置登记或任意文件写入接口；不扩展非 Git 根下独立 Git 子仓库的检出布局，不引入自动保存或所有编辑工具的并发事务。

## Decisions

### 由任务分流选择，专业能力执行

任务分流技能（task-triage）集中解释 Git、明确非 Git、未知身份三种情况。其他技能和 OpenSpec 增强引用同一结果，只增加自身必要条件，不各造分类器或状态。继续强制所有资料建仓库会违背现有产品承诺；让 Git 提供者伪造非 Git 工作树会破坏其稳定保证，因此均不采用。

### 判断真实文件现场

按目标与最近现存父目录检查真实路径、祖先或目标链接、登记来源及实际 Git 边界。父仓库中的新文件、未跟踪或被忽略文件仍属于相应 Git 现场；没有本目录 `.git` 不能判定非 Git。观察失败、损坏或已登记仓库缺失与明确没有仓库不同。缺少 Git 工具时，使用其他可核验的当前来源判断；无法确认只停止该写入，不增加所有资料任务必须安装 Git 的门禁。

已核验的工作空间（Workspace）入口别名可以按实际身份归一；新出现或悬空链接不能自动授予外部目标的写入范围。混合任务逐对象判断，保持当前独立 Git 范围的隔离要求。

### 普通资料的保护按工具能力报告

修改前重读路径、内容或缺失状态；专业能力支持条件版本时提交其已观察摘要或版本。普通文件工具使用最小、可核对补丁，并在写前发现身份或内容变化时保留现场、重新判断。覆盖或替换前确认原内容可保全，不能通过重放旧版本、自动恢复或覆盖他人文件消除冲突。写后从真实成果读取正文与来源，不能仅用记录成功或工具回执验收。

这提供可执行的工作指引，不能保证观察与普通编辑之间不存在竞态。验证分别证明专业版本条件和真实智能体（Agent）工具的受控冲突行为，不自制测试写入器冒充产品通用原子保护。

### 保留已有专业所有权

任务正文、本机材料和数据库继续使用现有产品动作；项目普通资料由所属专业工具在已核对位置维护。OpenSpec 对实际 Git 位置保持主线与变基（Rebase）核对，非 Git 材料按当前内容和规范来源核对。收尾只对实际存在且属于本任务的 Git 对象执行 Git 动作；非 Git 回读成果后登记实际结果。

## Risks / Trade-offs

- 把 Git 查询失败当非 Git → 明确区分未知与合法无仓库，保留父仓库、缺失目标和链接检查。
- 消费入口仍强制工作树 → 同步任务材料指引、五个增强、随包静态检查与完整投射测试。
- 普通工具被描述成原子保护 → 明确其证明范围；复用已有专业版本冲突和恢复测试，另做真实文件工具观察。
- 改动仅留在源码 → 核对随包资源与增强内容摘要；本轮收尾时再由唯一自举能力更新受管副本，不提前覆盖当前实现。

## Migration Plan

没有数据迁移。候选工作树中修改源资产与消费者并验证，交付后通过正式更新和同步采用新指引。既有 Git 任务、记录版本、能力契约和清理证据继续有效；回退指引时保留已经形成的真实资料和任务结果，不以回退为由删除或覆盖成果。
