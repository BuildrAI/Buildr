## Context

当前已持久保存 isParent；副屏按资源 kind 复用，全部任务共用 task 标签；关联选择器允许省略 onCreate。父任务直接完成需要完整快照、所有子任务终态和验收依据。

## Goals / Non-Goals

按 prototype.html 实现已确认页面。无任务新建界面，不增加贡献模型、历史管理页面或自动完成推断。普通任务仍使用现有详情阅读框架。

## Decisions

- 扩展副屏槽位以区分组合与普通任务，沿用路由和页面容器；文档用既有阅读组件。保留各标签阅读状态。
- 组合详情独立组件，复用关联选择器、状态标签、任务客户端及 Markdown 阅读。概览优先读取关联变更的 design；若没有，使用目标中明确方案链接；不虚构方案正文。
- 新增 task-record 的显式结束操作。输入 observed record、父子 snapshot、整体结果、每个未结束普通子任务的 detach/complete/abandon。全部写入在同一 SQLite 事务中校验并提交，失败零写入；无需在前端编排多个写请求。
- 备注可空，空备注保存中性的动作说明，不声称测试或交付。原 complete/abandon 输入不变。完成依据由该明确请求及当前子任务事实构造，独立推进任务保持原状态并解除关系。
- 嵌套组合任务不递归结束；未结束组合子项只允许独立推进，需在其自身页面明确验收。避免一个普通子任务选择覆盖另一组合的完成授权。
- hasChildren 保持既有查询语义；任务类型以 isParent 单独过滤，避免空组合被分类为普通。

## Risks / Trade-offs

- 陈旧父子观察可能丢失新增任务 → 服务端写事务比对完整 snapshot。
- 标签迁移可能覆盖上下文 → 为组合保留独立槽位并兼容旧 task 地址。
- 数据重读导致用户输入丢失 → 冲突保留选择和说明，重新读取后仅补齐新任务。
- 当前知识文章与术语将受影响 → 先核对任务系统相关文章，记录需要同步的具体陈述；非必要知识扩写不纳入。

## Migration Plan

无数据库迁移，新增接口保持原接口兼容，前后端构建一起交付。删除新入口即可回退，已经成立的任务结果保留。
