## Why

rc.56/rc.57 的失败及本轮 Windows 诊断说明：远端制包、多轮完整验包和重复安装扩大了发布的不确定性。将原包生产与必要验证留在本机；GitHub 正常路径只校验保全数据及独立公开，对端冒烟独立可选，不再决定发布资格。

## What Changes

- 新准备默认先在冻结的本机检出目录生成唯一原包，完成通用和当前系统检查。
- 根据真实本机系统对称选择可选对端：macOS 对 Windows，Windows 对 macOS。默认不派发对端测试；正常保全可使用中立系统，不构成该系统的产品验证。
- 冻结 `buildr.local-required-remote-optional/v1` 平台策略；汇总明确标记对端未验证，不把旧失败或未执行伪装成通过。历史候选不自动降级。
- 独立冒烟只在最低 Node 下一次安装、检查 CLI 和 Web 健康；不重复 SDK、源码、工作空间生命周期或第二次 Host Node 验包，不生成完整候选证明。
- 本机准备结束前使用正式消费函数预演主包证明聚合及插件原包／完整证明读取；只读已有结果，不重建或重测。
- 为尚未公开、未被主线采用且运行已结束的新候选提供默认只读撤回计划；准确授权后先保全，再清理当前载体、数据及正式准备分支和当前运行附件。公开或未知请求不自动处理。
- 将输入分类策略版本、验证配方、消费契约和声明范围随交接冻结；新来源绑定显式携带分类策略版本，旧绑定继续按原协议读取。
- 冻结原包、验证范围和输入解释；交接保留真实本机执行来源，不能把本机结果伪装成 Actions 执行。
- 原包与本机证明通过不可变临时引用交接，远端只读取数据并上传供正式发布消费的同字节附件，不创建 GitHub Release Assets。
- 保留已有发布身份、准确原包授权、main 保护及旧记录读取；新准备不进入旧的远端制包／补验链。
- 独立插件与联合候选均由本机自动准备准确 DSH SDK、构建和完整验证插件原包；校验有效的 SDK 可复用，GitHub 不重新准备 SDK 或重建插件。
- **BREAKING**：新候选的生产责任和源码验证覆盖策略改变；另一系统的源码专项不再作为每次发布自动全量重跑的前置条件。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `open-source-release-governance`：本机必要验包、对端独立可选冒烟、不可变数据交接和独立公开消费。

## Impact

发布源码位于 `skills/buildr-release/scripts/`；验证与结果复用继续归 `projects/product/services/buildr/test/verification/`；GitHub 工作流只负责执行边界。同步更新对应测试、发布技能和现有流程说明。此变更不授权公开发布、远端派发、npm 身份变更或分支保护变更。
