## ADDED Requirements

### Requirement: 未公开新候选撤回必须按精确身份保全并接续
Buildr MUST 为新本机原包模型候选提供默认只读撤回计划。执行 MUST 使用准确计划身份及独立授权，与原操作串行，先校验并保全原包、证明、源码及日志，再按准确身份清理当前选择的临时载体、数据和准备分支及当前运行附件。原运行和审计记录 MUST 保留；已进入撤回的选择 MUST NOT 被普通准备、恢复或公开重新建立资源。

#### Scenario: 安全撤回及重复执行
- **WHEN** 候选尚无公开请求、未被主线采用、运行已终止且资源归属与计划一致，用户明确授权准确计划
- **THEN** 先在规范工作空间保全原字节、源码、证明及日志，逐个删除准确资源并回读
- **AND** 重复执行只采用已确认不存在的资源，不重复请求

#### Scenario: 身份或活动冲突
- **WHEN** 存在公开意图或历史公开请求、主线采用、活动运行、开放合并请求、引用漂移、档案变化或无法核对的请求
- **THEN** 停止相关清理，保留已发生效果及具体诊断，不强杀、不回滚主线、不改变公开事实

#### Scenario: 删除结果未知
- **WHEN** 清理请求响应丢失或未能确认资源不存在
- **THEN** 原操作保留准确请求意图，后续只回读实际结果，不自动重发
- **AND** 部分成功仍如实保存，缺少保全证明时不继续删除

### Requirement: 本机准备必须预演正式消费并冻结验证规则
Buildr MUST 在新准备分发前使用正式消费者的读取和覆盖逻辑预演已有原包与证明，MUST NOT 为此重复制包或执行测试。新交接 MUST 绑定输入分类策略版本及定义、验证配方、消费契约、平台策略和用户声明范围；新来源绑定 MUST 显式携带分类策略版本并按该版本校验，历史来源绑定保留原解释。

#### Scenario: 消费预演失败
- **WHEN** 原包已生成但证明缺失、插件对端不符或正式读取不能消费
- **THEN** 返回具体本机消费失败，保留原包并停止该交接分发
- **AND** 不重制包、不伪造执行来源、不启动新测试轮

#### Scenario: 规则或范围漂移
- **WHEN** 接续准备或消费时发现冻结规则与当前解释不兼容
- **THEN** 在相关消费边界明确拒绝，不覆盖旧交接或自动改用新规则
- **AND** 支持的历史分类策略仍按其已冻结版本解释

#### Scenario: 保留原包的独立验证器修复
- **WHEN** 冻结候选需要修复证明消费代码
- **THEN** 系统必须核对独立验证来源与原产品具有相同构建输入，只读消费原产品配方及证明并保留双方准确身份
- **AND** 不得替换原包、改写原始证明、变更冻结范围或授予独立验证器公开权限

### Requirement: 插件候选必须在本机完成 SDK 准备与完整验证
Buildr MUST 对新独立插件及联合候选在本机自动准备准确 DSH SDK、构建并完整验证唯一插件原包。SDK 仅在输入、工具、平台、实际依赖和生成物均校验有效时复用；GitHub MUST NOT 重新准备 SDK 或重建插件。真实桌面验收与公开授权保持独立。

#### Scenario: 独立插件准备
- **WHEN** 仅选择 DSH 插件与准确已公开 Buildr 对端
- **THEN** 本机完成 SDK、插件构建及完整兼容验证
- **AND** 远端仅校验并保全同一插件原包与真实证明，不生产主包或执行主包对端验包

#### Scenario: SDK 复用失效
- **WHEN** SDK 输入、构建工具、实际依赖、平台或生成物变化
- **THEN** 不采用旧准备结果，并在独占新目录准备 SDK
- **AND** 不覆盖历史结果、不把准备命中伪装成插件验证通过

### Requirement: 新候选必须由本机生产唯一原包
Buildr MUST 在干净的冻结本机检出目录完成适用源码验证后生产唯一原包，并在本机完成通用与当前系统的原包验收。GitHub MUST NOT 为新模型重新生产原包或重复执行通用检查。所有验收及正式发布 MUST 消费同一份准确字节。

#### Scenario: macOS 开发者准备候选
- **WHEN** 在 macOS 准备新候选
- **THEN** 本机生产原包并完成通用和 macOS 验收
- **AND** GitHub 正常路径只校验并保全原包与本机证明；Windows 冒烟可独立选择，不是发布前置

#### Scenario: Windows 开发者准备候选
- **WHEN** 在 Windows 准备新候选
- **THEN** 本机生产原包并完成通用和 Windows 验收
- **AND** GitHub 正常路径只校验并保全原包与本机证明；macOS 冒烟可独立选择，不是发布前置

#### Scenario: 对端验收失败
- **WHEN** 本机验收已通过而对端系统验收失败
- **THEN** 原包与本机有效结果保留，对端失败如实独立记录，不阻止新平台策略候选的发布准备
- **AND** 不重新制包、不把失败或未执行伪装为通过

### Requirement: 本机原包交接必须是不可变数据
Buildr MUST 将交接内容绑定准确产品提交、原包摘要、清单及冻结验证范围，并保留真实本机执行来源。远端 MUST 从冻结产品源码执行校验，只将交接引用当作数据读取。交接 MUST NOT 创建正式标签、GitHub Release 或 npm 写入；临时数据引用 MUST 纳入原发布的精确身份清理。

#### Scenario: 原包或交接内容变化
- **WHEN** 交接包、分块、清单或验证范围与冻结摘要不一致
- **THEN** 接收和发布消费停止相关动作，不重新打包或覆盖已有证明

#### Scenario: 真实本机证明被远端采用
- **WHEN** 远端汇总本机已经完成的检查
- **THEN** 校验原证明的内容适用性并保留本机来源
- **AND** 不将本机执行伪装为远端执行，不要求原包必须由 GitHub 生产

### Requirement: 新候选的公开消费必须独立于验包执行
Buildr MUST 在宣布新候选可公开之前校验正式发布器能够消费该原包与证明。公开作业 MUST 保留准确授权、原包完整性、来源收敛和受保护发布身份，不重新执行源码验证或制包。历史候选 MUST 保留原模型及真实结果，不因新流程覆盖而改写。

#### Scenario: 原包通过本机必要验收
- **WHEN** 准备形成可发布上下文
- **THEN** 使用同一冻结的消费契约验证原包和完整证明
- **AND** 正式公开仍需单独授权

### Requirement: 对端冒烟必须独立于候选发布门槛
Buildr MUST 为新主包候选冻结本机必需、对端独立可选的平台策略；缺少本机或通用必要证明仍 MUST 拒绝消费。可选对端未验证 MUST 在汇总中明示，MUST NOT 把未执行、旧失败或中立系统的数据保全声称为对端通过。无此策略的历史候选 MUST 保持原验证要求。

#### Scenario: 对端未验证
- **WHEN** 本机与通用必要验证通过且未运行对端冒烟
- **THEN** 候选可按本机必要覆盖完成准备，汇总明确对端未验证
- **AND** GitHub 仅校验并保全原包和证明，不执行重型验包

#### Scenario: 独立对端冒烟
- **WHEN** 明确选择另一系统检查同一原包
- **THEN** 使用实际最低 Node 一次安装、验证 CLI 身份和 Web 健康，并回收所属进程
- **AND** 不运行 SDK、源码、工作空间初始化同步卸载或第二次安装，不生成完整候选证明

#### Scenario: 历史降级或伪造覆盖
- **WHEN** 为旧候选声称仅保全，或修改新候选的固定策略以扩大可选范围
- **THEN** 拒绝相关动作，保留原验证要求和真实失败

#### Scenario: 读取历史失败
- **WHEN** 读取旧模型下失败或已撤回的发布
- **THEN** 保留其历史事实，不自动转为新候选或触发公开写入
