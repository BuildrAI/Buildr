## ADDED Requirements

### Requirement: 组合任务必须汇总自身及直接子任务的实际提交

组合任务提交查询 MUST 有界读取自身与直接子任务当前关系和仓库范围，按实际仓库身份及完整哈希值（Hash）去重，返回带有效任务尾注（Trailer）的可达提交并标明来源任务。每条提交 MUST 同时满足其真实所属任务的仓库范围，不得把其他任务或更深层后代自动纳入。普通子任务 MUST 继续仅查询自身提交。

#### Scenario: 多个子任务分别交付
- **WHEN** 父任务与两个直接子任务分别在工作空间及服务仓库留下带各自任务尾注的提交
- **THEN** 父查询 MUST 返回全部这些提交及准确来源，普通子任务查询 MUST 仅返回自身提交
- **AND** 同一仓库和同一提交 MUST 不重复计数，不修改实际尾注

#### Scenario: 在组合任务查看提交文件
- **WHEN** 用户选择汇总结果中的子任务提交及其文件
- **THEN** 文件列表和固定提交差异 MUST 依据同一授权查询范围及完整哈希值（Hash）读取
- **AND** MUST NOT 将子任务当前未提交工作区内容混入组合提交结果

#### Scenario: 超限或局部读取失败
- **WHEN** 直接子任务数量超限或某个来源不可读取
- **THEN** 查询 MUST 返回已读取结果及未覆盖诊断，不得把部分结果表述为全量

## MODIFIED Requirements

### Requirement: 网页和命令必须呈现同一真实提交内容
普通任务详情 MUST 在「改动与提交」内容标签内按仓库分组展示本任务关联提交，组内按提交时间从新到旧；不再有独立的「提交记录」阅读标签。组合任务 MUST 沿已有「提交记录」入口使用同一文件与差异阅读方式。展开一条提交 MUST 保留完整提交说明（Commit Message）与完整哈希（Hash），并列出该次提交改动的文件；文件可进入与未提交改动相同的差异阅读面。该入口 MUST NOT 新增为任务工作阶段或状态；网页和命令继续使用同一真实提交内容，本机可达读取范围与关联判定保持不变。

#### Scenario: 查看并展开提交
- **WHEN** 用户从任务详情打开提交阅读入口并在左侧仓库树的「提交」分组中展开一条提交
- **THEN** 页面 MUST 显示同一提交的完整说明和完整哈希值（Hash），并支持复制
- **AND** 显示该次提交改动的文件列表，选择文件在右侧差异面查看其改动
- **AND** 原有任务状态和当前工作阶段 MUST 保持不变

#### Scenario: 成功读取没有匹配项
- **WHEN** 全部声明的范围读取成功且没有符合条件的提交
- **THEN** 页面 MUST 显示当前检查范围内无关联提交，区别于读取失败

#### Scenario: 入口并入工作台
- **WHEN** 用户打开普通任务的「改动与提交」
- **THEN** 在左侧仓库树的「提交」分组中查看本任务提交，不再有独立的「提交记录」内容标签

#### Scenario: 关联范围不变
- **WHEN** 普通任务提交记录读取返回结果
- **THEN** 关联判定、读取范围与本机可达提交（含未推送）与变更前一致；组合任务仅按明确直接子任务扩展汇总范围
