## ADDED Requirements

### Requirement: 收尾和验收必须集中展示交付资料

普通任务的任务收尾和组合任务的验收 MUST 提供关联变更（Change）的额外交付资料入口，保留实际目录结构，按需阅读支持的文档、文本和图片。既有交付结果 MUST 继续表达实际完成情况与待处理事项，文件存在 MUST NOT 被表述为脚本已执行、配置已生效或部署完成。标准方案文件保持现有入口，不新增顶层文件管理页或强制分类。

#### Scenario: 已完成任务仍有外部待处理事项
- **WHEN** 交付结果说明代码已交付，而数据库脚本、配置或部署尚待处理
- **THEN** 用户 MUST 能在收尾或验收查看原结果和相关资料，不改变原完成结论或待处理表述

#### Scenario: 没有额外资料
- **WHEN** 任务没有关联变更或不存在额外文件
- **THEN** 页面 MUST 保持原交付结果可读，不要求生成文件或登记占位资料

## MODIFIED Requirements

### Requirement: 组合任务使用精简阅读页面
Buildr Web MUST将组合详情分为概览、子任务、验收和提交记录。标题后只标记组合任务；列表只展示标题、状态与至多一行任务目标及悬停全文预览，不重复目标和归属。概览 MUST先展示可点击的子任务状态数量，下方直接读取一份已有方案文档，无方案时如实提示。提交记录 MUST 汇总自身和直接子任务提交并标明来源，复用普通任务的完整提交说明、提交文件及差异阅读方式。

#### Scenario: 统计过滤
- **WHEN** 用户点击某状态数量
- **THEN** 页面 MUST进入子任务并按该状态过滤

#### Scenario: 阅读子任务提交
- **WHEN** 用户在组合任务选择一条子任务提交并展开文件
- **THEN** 页面 MUST 显示完整提交说明及可复制的完整哈希值（Hash），并在同一阅读区显示所选文件差异

### Requirement: 工作台分屏与提交阅读保持统一
Buildr Web MUST 将菜单头部和页面标签栏置于同一顶部层，下方内容分屏使用一致细竖线、短抓手和可拖动操作区；固定清单 MUST 只呈现一个分隔。文件与提交目录 MUST 有明确标题和紧凑对齐的仓库、分支、数量摘要，只展开非空内容，不逐仓库重复展示零数量空分组。用户 MUST 能在正文阅读、选择并复制完整提交说明与完整哈希；同一路径在工作区及各个提交中的差异 MUST 按所选来源分别呈现。

#### Scenario: 折叠菜单并固定清单
- **WHEN** 用户折叠菜单、查看改动与提交并固定实施清单
- **THEN** 顶部栏 MUST 同层对齐，下方分隔样式一致且清单边界没有重复竖线

#### Scenario: 阅读完整提交和同路径差异
- **WHEN** 用户选择提交及其中一个在其他来源同名的文件
- **THEN** 正文 MUST 完整显示可选可复制的提交内容，并读取所选提交内该文件的差异

#### Scenario: 已完成任务与失效选择
- **WHEN** 已结束任务没有未提交改动，或刷新确认原所选改动已经消失
- **THEN** 页面 MUST 优先提供当前关联提交并清理确定失效的选择，不永久停留在旧差异错误
- **AND** 来源不明或读取失败时 MUST 保留明确诊断，不自动读取另一工作树（Worktree）的同名文件
