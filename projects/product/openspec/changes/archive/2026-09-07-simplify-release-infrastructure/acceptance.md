# 发布基础设施验收

本次只交付发布基础设施到 `dev`，未发布新版本，也未修改 rc.30 的标签、npm 包或 GitHub Release。当前流程入口为 `projects/product/knowledge/flows/open-source-release.md`。

## 根因与处理

| 问题 | 最终处理与证据 |
|---|---|
| 准备分散、干净检出依赖残留 | `candidate-environment.ts` 统一锁定依赖、精确产品 Node、生成代码、测试上下文、前端和消费准备；托管作业从干净检出执行。 |
| 消费产物仍加载构建工具 | 构建依赖仅在构建分支加载；宿主与发布消费者使用最小依赖。六组宿主 Node 及固定 npm 的无写入发布检查使用原包。 |
| 候选与发布复制检查和参数 | `release-consumption.ts` 维护共享检查配方及覆盖；候选执行真实平台启动，发布消费已验证包，删除重复宿主与启动器发布作业。 |
| 修复后强制演练再完整候选 | 演练成为按需验收；精确源码、包字节和相关输入匹配时直接复用完整结果。普通开发仍使用相关检查。 |
| 人工搬运关联材料、引用与工作位置混淆 | `release-orchestration-runner.ts` 提供准备、查看、发布、恢复入口；固定基线和有序来源，自动组合任务、工作树、运行编号与上下文。技能使用锁定 Node 执行器。 |
| 部分写入被当作整体失败 | 本地引用、远端推送、标签、npm、GitHub 和登记分别保留已确认或未知效果；重试先回读。真实临时 Git 与本地服务覆盖响应丢失和后续失败。 |
| 未知查询被当作版本不存在 | 区分明确 404、权限、网络、无效响应和冲突；公开仓库先确认可读；只有明确暂态故障有限恢复。 |
| 测试进程未遵守并发预算、退出原因丢失 | 发布测试入口消费既有工作进程预算，保留详细退出诊断；行为测试证明单工作进程串行及异常退出码保存。 |
| 启动锁可能在写入过程中被抢走 | 复用既有原子文件锁；空或未知锁不回收，旧进程号格式可读，释放核验所有者。已取消完成等待的计时器。 |

保留 rc.30 已有的生成材料准备、Windows 命令启动、正式远端发布引用、冻结 dev 来源、300 秒集成上限、60 秒启动器接管等待和发布原包等修复。
