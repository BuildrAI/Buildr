## Why

集鲜现场的分支切换会重复枚举和校验同一来源，成功后前端还等待分支清单并重读全部代码库。页面没有明确获取远程（Fetch）入口，用户只能在其他工具更新本机远程跟踪记录后发现新分支。

## What Changes

- 分支切换保留写前版本、占用、过滤器及写后事实校验，减少单次观察内的重复来源读取；成功反馈不等待后续分支清单。
- 源代码管理支持明确 `repositoryId` 的局部只读观察，切换后只更新对应代码库及当前受影响内容；手动全量刷新保持。
- 增加单个代码库和全部已观察代码库的获取远程（Fetch），依据已观察 Git 身份与本机远程配置执行，按实际仓库去重并逐库反馈。
- 获取远程完成后更新相关目录和已打开的分支清单，不执行拉取（Pull）、合并、变基、分支切换或清理远程跟踪引用。
- 不包含破坏性变更；既有缺省全目录读取、写入授权及只读工作进程保持兼容。
- 采用已确认紧凑原型：状态只常驻非零数量，双干净状态合并并可展开完整事实，任务入口自然占位；分支入口在最右侧统一64像素、窄栏24像素，给名称及树层级留出空间。

## Capabilities

### New Capabilities

- `code-remote-fetch`：显式单库与批量获取远程、来源和配置保护、局部失败及页面结果反馈。

### Modified Capabilities

- `code-source-control`：明确单库观察范围和页面合并规则，保留其他代码库当前事实与阅读现场；收敛紧凑状态、任务自然占位及等宽靠右的分支入口。
- `code-branch-management`：切换完成后的局部重新观察与不等待后续读取的反馈边界。

## Impact

- 后端 `modules/code` 的目录读取、分支观察、获取远程应用及 HTTP 契约；复用已有 Git 子进程执行器和同源会话写入授权。
- 前端 `features/code` 的读取合并、分支完成通知和现有操作入口；数据传输对象由当前生成入口产生。
- 新增 `POST /code/fetch`，扩展 `GET /code/source-control` 的可选 `repositoryId`；不向只读命令或工作进程注册写入能力。
- 验证采用真实集鲜只读计时和隔离本地 Git 远程，不对集鲜业务目录执行测试写入；无新增依赖或运行时配置。
