## Context

动机见 `proposal.md`。源代码管理已按真实工作树（Worktree）观察；分支（Branch）写入仍在一个请求内多次发现相同来源，页面成功通知会重新读取全部目录。现有提交和推送已有同源写入授权及异步 Git 执行器，可复用而不引入第二套运行状态。

## Goals / Non-Goals

**Goals:** 将分支写入、后续局部读取及获取远程（Fetch）分开反馈；保留身份、现有成果与迟到结果保护，兼容原有全量读取。

**Non-Goals:** 不自动获取、拉取、合并、变基、清理引用或修改远程配置；不向只读工作进程开放写入；不为 Git 操作建立持久任务队列。

## Decisions

### 请求内复用来源观察

分支操作使用请求局部的来源读取会话（Session），减少同一观察内目录枚举；写前、写后仍重新核对登记根、公共目录（Common Directory）、成员及必要版本。不得跨请求缓存身份，或省略占用、过滤器与未提交成果保护。相比只减少校验次数，该方案保留现有写入边界。

### 保持完整单库观察

`GET /code/source-control` 增加可选 `repositoryId`，缺省行为保持；明确单库时在工作树和状态读取前过滤，未知实例返回错误。返回该库全部工作位置、覆盖与诊断，沿用既有响应。任务关联必须的严格来源发现仍保留。相比前端全量读取后筛选，该方案减少主要 Git 开销。

前端在页面数据层维护各库请求次序及工作空间（Workspace）身份；单库结果只替换该库，互不取消。全量结果不能覆盖启动之后较新的单库结果，旧工作空间结果被丢弃。局部失败保留既有目录并在对应动作反馈；初始化无目录时允许全量读取。分支写入成功立即结束操作反馈，目录和分支列表在后台重新观察；无关库的读取版本不随目标库变化。

### 绑定已观察实例的显式获取

`POST /code/fetch` 接受 `repositories: [{repositoryId, expectedGitId, expectedCheckoutId}]`，1–128 个不同实例；不接受目录、命令或远程地址。全部入口提交页面实际观察的实例集合，避免登记变化扩大写入范围。`expectedCheckoutId` 取已观察登记来源身份，绑定目录与 Git 元数据的设备、inode 和创建时间；`gitId` 仅作公共目录分组，不能单独保护同路径替换。服务端重新取得登记、真实 Git 公共目录与检出身份，不匹配或没有已确认身份只拒绝该实例。

同一公共目录且有效远程地址与映射一致时去重；同公共目录的登记实例因工作树配置形成不同有效配置时局部拒绝该组，避免替用户选择地址。每批最多两个仓库并行，同库远程依次执行，单次远程有超时。复用现有异步 Git 执行器并按公共目录防止重叠操作。结果逐实例、逐远程表达 `succeeded|failed|unavailable|unknown`；超时及部分完成不重发，按实际结果保留已知效果。

服务端读取并固定远程地址及获取引用映射，执行前复核登记、身份与远程配置；只允许目标在 `refs/remotes/` 的映射。本次 Git 进程通过独占完整别名映射固定已扩展的有效地址，避免 `insteadOf` 再次重写到其他远程；将获取映射重写到本次独占的 `refs/buildr-fetch/<uuid>/` 内部临时范围（现有分支清单不枚举）；来源与配置复核后，用 `update-ref --no-deref --stdin` 原子事务及获取前目标旧值比较发布到原远程跟踪引用，并删除本次临时引用。符号引用（Symbolic Ref）包括悬空目标不能被解引用到本地分支；目标并发变化使发布失败。仅本能力调用禁用引用事务钩子（Hook）与文件监视程序（Filesystem Monitor），保留 Git 凭证与传输配置；原提交和推送执行器语义不变。临时清理只作用于本次独占范围及相同检出身份，清理问题不得否定已确认发布。显式使用 `--no-tags`、`--no-prune`、`--no-prune-tags`、空 `--refmap=`，关闭标签自动跟随、清理、递归子模块和配置引发的额外映射；不更改本地分支、索引（Index）及工作文件。危险或不支持映射局部拒绝，避免使用 `pull` 代替。凭证继续由本机 Git 管理，不显示地址中的敏感信息。

### 沿用现有操作入口

分支管理底部增加“获取远程”，代码库目录标题提供“全部获取远程”；现有刷新只读本机状态。显示真实进行状态和简洁逐库结果。单库完成通知携带库身份，不依赖原行组件仍挂载；重新读取该库及仍打开的分支清单。全部获取允许一次全目录读取。数据传输对象（DTO）沿用当前生成入口。

## Risks / Trade-offs

- 联网耗时与认证失败 → 有界执行、逐远程结果及局部继续，不能将请求超时报告为无效果。
- 远程配置可在获取期间改变 → 执行前复核并固定地址、映射；执行后漂移报告未知，重新观察引用，不自动重试。
- 并发全量与局部读取回滚新事实 → 按库次序合并，加入延迟和跨空间回归。
- 严格任务来源发现仍有全局成本 → 保留正确性，仅消除重复发现及无关状态读取，实测报告剩余耗时。
- 批量全部获取扩大联网量 → 用户显式触发，按真实库去重、并发上限及局部失败，不隐式后台获取。

## Migration Plan

接口兼容增加，无持久模式变更。先用隔离本地远程验证，再构建候选预览；集鲜现场只做只读计时。回退实现时保留已获取的远程跟踪引用，不尝试恢复或删除用户 Git 事实。日常开发版采用仍按本轮实际交付授权及唯一自举执行器处理。


## 已采用的来源列表布局

用户追加指出右侧状态、任务和分支固定栏挤压名称，并选择先看可交互原型、再实施。[名称优先布局对照原型](prototypes/source-control-density.html)已生成并归入当前变更；用户在等宽靠右修订后明确确认按原型实施，状态为 `adopted`。正式页面与原型共享相关组件和样式，演示操作仍只改变离线数据。

推荐将每行次要信息紧凑组合：只常驻非零数量，确认远程和文件均无差异时合并为一个可展开的标记，没有任务不保留空槽；未知、未跟踪和不可读取继续分别表达。完整状态可由鼠标或键盘打开，分支仍可就地管理。原型提供现状／紧凑及260／440宽度对照，所有操作仅改变离线演示数据。

用户评审追加分支入口应等宽靠右，已确认修订为常规栏64像素、目录宽度不超过320像素时24像素；常规栏文字左齐、箭头右齐，长名称省略并保留完整名称提示。实际单独查看入口测得九行按钮在260／440两种宽度下均等宽、右沿一致，包含不可用行；分支菜单仍可正常打开。窄栏信息较多时仅该行状态移至名称下方。

已通过真实任务的方案设计与单独查看入口核验，两页均可切换，状态详情及功能说明可读；独立浏览器另验证分支、任务、文件、模拟获取与说明定位。原型源码位于 `services/buildr-web/src/prototypes/source-control-density/`，由 `tools/build-source-control-density-prototype.mjs` 构建；用户确认版本已保全，正式共同组件完成后重新构建并验证任务内两页及单独查看。重建源观察摘要内联于HTML，提交观察为c9d9e34b9，包含76项相关来源及当时未提交内容摘要。

此设计改变现有固定列及两个干净图标的表达要求，本变更对应delta规范已收敛为已确认布局。实施保留完整状态详情、路径复制、任务入口、真实分支管理及读取版本保护；原型不替代正式验证。此前Fetch及分支性能候选和仍适用的验证结果复用，完成后按用户明确要求集成并更新日常开发版。
