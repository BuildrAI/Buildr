## Context

两端共享展示和读写底层，但独立 Harness 的适配器只返回当前工作目录。工程登记、任务工作树生命周期和工程交付仍由 Development 拥有。

## Goals / Non-Goals

从获准目录有界发现实际 Git 仓库，再发现各自关联检出，两个面板共享选择；不跟随目录软链接或扫描范围之外的独立仓库，不改变对话执行位置，不将 Git 动作解释为任务授权。

## Decisions

以原目录身份为锚，通过 Git 注册清单证明关联，传递不透明检出身份而非浏览器指定绝对路径。每次重新验证成员和公共目录，失效不回退。文件按来源、相对路径和版本区分；大文件续读使用原版本。Git 变更必须显式发起并按实际对象校验，不强制覆盖、不自动推送。

## Risks / Trade-offs

逻辑范围和文件系统身份独立校验；外部程序仍可能并发改变现场，未知写入先核对。工程业务策略不随底层复用迁移。
