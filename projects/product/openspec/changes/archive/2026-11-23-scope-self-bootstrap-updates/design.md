## 方案

预检与执行共享 Git 差异分类；预检单独返回各阶段路径、继续执行的条件，不取得写锁或启动后台。Harness 网页/后台在开发运行更新中单独列出。正常执行仍按原顺序处理工作空间、开发运行与插件，预检不替代执行时复查。

当其他阶段通过并因 DSH 在运行而尚未安装时，复用原完整结果作为接续输入，不增加状态库。接续验证同一工作空间、交付、远端及保留提交，从已交付源码重新核对候选身份，只运行原插件步骤及必要入口与 Doctor 检查；不重建网页。先前结果或当前源码不匹配，保留原配置。故障不自动重试；普通执行不停止 DSH。

显式更新并重开是在原自举独立执行器中启用的选项。待更换的候选先校验。由开发插件的宿主加载登记确认当前桌面的 PID、绑定的本机目录及版本；对照 macOS 应用身份、子进程和实际已装文件后，才向单一实例请求正常退出。换装后按已核验的原绑定重新打开；以新进程的加载回执和安装包身份分别确认。在无法核实旧实例或正常退出时保留待安装。旧插件尚未具备加载证明，需要先完成一次原流程换包；不通过名称或端口推断归属，不退出或重启已关闭的桌面。
