## Why

代码库编辑只开放名称与说明，使集成分支等声明只能通过文件或智能体（Agent）修改。声明编辑与实际 Git 操作应独立，用户能在页面完成管理并理解尚待执行的对齐动作。

## What Changes

- 开放代码库地址、远端名称、集成分支和目录编辑，稳定身份与代码标识保持不变。
- 本地仓库可独立声明集成分支，不要求先配置远端。
- 保存只更新声明，保留版本保护，核对目录及模块边界，不执行切分支、改远端、克隆或搬迁。
- 单仓库状态区分可用与待对齐，展示实际远端、当前分支及缺失目录或模块，提供后续处理指引。
- 详情和编辑按需读取本地 Git 配置，缺失声明自动补入实际地址，显式展示声明与实际差异，多远端歧义不猜测。
- 服务编辑中的代码库选择复用过滤、新增和选项，保存时原子登记新代码库并更新引用，取消不登记。
- 新增代码库时从 Git 地址末段自动填写标识及 `repositories/<末段>`，去除末尾斜杠与 `.git`，保留手动修改；编辑既有代码库不自动改身份或目录。
- 向后兼容既有清单读取，无破坏性代码操作。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `repository-instance-registry`: 完整声明编辑、独立本地集成分支与对齐反馈。

## Impact

涉及关系应用、来源校验、HTTP 契约、工作树（Worktree）起点读取、前端编辑与状态组件、已有测试及维护指引；不引入依赖和新的执行入口。
