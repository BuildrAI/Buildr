## Context

既有编辑接口（API）只接收名称与说明。Git 来源的地址、远端与集成分支成组保存；本地仓库没有该组字段。单仓库状态已独立读取。

## Goals / Non-Goals

开放声明字段，保持稳定身份、清单版本和文件边界。保存不执行 Git 写操作；不在本次新增智能体（Agent）调度或远端访问。

## Decisions

- 编辑请求沿用 flat `url`、`remote`、`integrationBranch`、`path` 字段；省略保持原值，空地址表示撤销远端声明。远端声明仍要求有效集成分支。
- 本地仓库新增可选 `source.integrationBranch`；远端仓库继续使用 `source.git.integrationBranch`，禁止两处同时声明。所有受影响读取统一兼容两种来源；后续工作树未指定起点时使用声明的集成分支，显式任务起点优先。
- 目录变化时只读校验存在位置的真实 Git 根、重复位置和服务模块边界；不存在位置与缺失模块形成待对齐状态，允许保存目标声明。
- 状态接口返回明确对齐状态和实际值，详情按当前版本读取并隔离陈旧响应；列表仍不扫描 Git。当前分支不同不阻止可用性。
- 表单复用来源字段组件，展示引用服务影响。详情提供对齐指令抽屉，明确当前只生成指引。

- 增加单仓库本地配置读取接口（API），先验证真实根，再读取远端列表、地址和当前分支，不扫描工作区状态。选择顺序为已声明远端、当前分支跟踪远端、origin、唯一远端；多远端无明确选择返回未选定。
- 详情以实际地址展示，声明不同则另外显示目标；编辑保留已声明目标，声明缺失时自动填入本地配置，不覆盖已经输入的草稿。集成分支不从任务分支推断。读取失败与确实未配置明确区分，读取不写清单。

- 服务编辑传入 `repository` 草稿或已有 `repositoryId`，二者互斥；复用代码库创建校验和现有清单事务，仓库登记与服务引用一起成功或一起失败。新增字段在同一抽屉内展开，外层输入保留。

- 新增表单从 HTTP/SSH/SCP 地址解析仓库末段，自动值随地址更新；标识与目录分别跟踪手动修改，手动值优先。已有草稿按保留输入处理，既有仓库编辑禁用自动推导。

## Risks / Trade-offs

- 声明暂时与本地不一致：状态清楚区分，不自动覆盖代码。
- 符号链接绕过目录边界：对已有根和模块解析实际路径后校验。
- 旧清单兼容：不批量迁移；旧来源可读，编辑时规范化来源，稳定身份保持。

## Migration Plan

随产品代码交付新能力，真实工作空间声明只有用户编辑才改变；回归原接口字段省略语义与新字段校验。
