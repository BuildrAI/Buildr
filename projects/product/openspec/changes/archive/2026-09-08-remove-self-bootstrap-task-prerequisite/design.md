## Context

现有脚本先查询已完成任务，再读取变化范围；这使已经交付的规则调整仍无法投射。任务编号还参与未推送后继识别。

## Goals / Non-Goals

目标：有无任务记录均可按真实变化激活；重复执行和推送失败恢复不重复提交；规则与组件改动可发现。
非目标：不改变业务交付、任务生命周期、发布授权，不接受未提交或未交付的源内容。

## Decisions

保留唯一执行器，`--task` 仅作为可选说明，不查询任务数据库。用基线、交付提交、分支、远端和宿主的摘要标记新的激活提交；保留旧任务标记恢复的兼容分支。继续检查真实 Git 根、祖先关系、远端包含、干净目录和精确暂存。

范围分类增加根及项目/服务的 AGENTS.md、rules、components 和 commands；命中后走既有同步与入口检查。普通无关文档返回 not-applicable。已安装组件、用户目标与实际变化决定适用性，不根据提交作者或任务状态猜测。

## Risks / Trade-offs

可选任务编号减少关联信息，但不参与安全证明。恢复摘要不含任务编号，避免补充或移除说明导致重复写入；改变基线或目标不能认领之前未推送的后继。组件完整性随源修改一起刷新。真实自举只在源码交付后运行。
