## Context

上一变更已经正确实现了 Parent Plan、真实 Child/binding 与 Contribution Handoff 的只读组合逻辑，但正式页面没有沿用已确认 UI Preview 的信息架构。生产实现保留了旧的三项摘要，并把贡献项渲染为纵向长卡片；同时，原 design 错误写入“不新增弹窗详情”，导致预演中的详情侧栏被移除。现有浏览器测试只断言文案、顺序与导航，无法发现这种结构性偏差。

本次不改变后端 read model 或业务权威，只重新设计 `ParentCoordinationPanel` 的页面结构，并把关键视觉关系变成可验证的 DOM 与布局约束。

## Goals / Non-Goals

**Goals:**

- 让真实父任务页面在信息层级、密度、状态表达和详情交互上与已确认 UI Preview 一致。
- 一屏内同时看清贡献项、实际子任务、贡献交接/依赖和下一步行动。
- 把四项迁移摘要、横向四列行、详情侧栏与窄屏降级写入正式验收。
- 保持中文界面、父子任务标准路由和 Contribution Handoff 交付证明边界。

**Non-Goals:**

- 不要求像素级复制预演 HTML 的全局应用壳、字体或 mock 数据。
- 不修改 Parent Coordination v3、Parent Plan、Task Record、Development、Review、Verification 或 Finish。
- 不新增迁移详情路由、进度存储或前端缓存。
- 不把 UI Preview 文件本身变成规范或验证证据。

## Decisions

### 1. 顶部摘要改为四项真实迁移维度

父任务目标卡保持现有真实页面框架；右侧行动卡保留推荐下一步与刷新操作，但底部固定展示“已交付、剩余工作、已取代、进行中”四项。计数由当前 `contributions` 与 matching Child delivery 即时派生，不复用旧的“可启动、已明确处置、最终验收”摘要。

行动卡下方增加紧凑来源说明，明确“父任务计划 + 直接子任务 + 贡献交接”和“不写回父任务计划”。这既复现预演的信息层级，也防止用户把摘要误认为新的进度台账。

备选方案是继续保留旧三项摘要并仅调整卡片样式；这正是当前偏差的一部分，不能满足已确认预演。

### 2. 贡献项使用固定语义的横向紧凑行

桌面端每行采用四个区域：

1. 贡献项：priority、中文状态标签、标题与稳定 ID；
2. 实际子任务：可导航标题、中文状态、Task ID 与交付证明；
3. 贡献交接或依赖：非空 delivered/residual/superseded 标签、nextAction，或依赖与阻塞原因；
4. 详情入口：独立的箭头按钮。

行本身可打开贡献项详情；子任务链接使用标准任务详情路由并阻止触发行点击。无实际子任务时仍保留第二列，用“尚未绑定”和预期子任务说明维持稳定扫读位置。

备选方案是纵向卡片加 `<details>`；它会显著拉长页面并把跨项比较信息拆散，因此移除。

### 3. 恢复贡献项详情侧栏

使用现有 Ant Design `Drawer` 展示贡献项目标、实现方向、边界、计划依赖、预期子任务和 matching Handoff 证明。侧栏只读取当前已加载的 Parent Coordination 结果，不创建路由、请求或持久化状态；关闭后回到原滚动位置。

子任务标题仍直接导航到标准任务详情页。详情侧栏是 Contribution 的辅助阅读层，不是独立任务页面，因此不与既有导航要求冲突。

### 4. 响应式布局按信息优先级降级

宽屏保持四列横向行；中等宽度压缩列宽；窄屏改为“贡献项在首行，子任务与交接信息依次堆叠，详情箭头固定右上”的单列结构。四项摘要在窄屏变为两列，但标签与数值全部保留。

不通过隐藏子任务、交付摘要或阻塞原因换取窄屏空间。

### 5. 浏览器验收验证结构而非仅验证文本

测试除现有业务断言外，还应验证：四项摘要名称与数量；桌面行的四个语义区域处于同一横向带；详情箭头打开侧栏；子任务链接不会打开侧栏而会导航；窄屏区域按单列顺序排列且无水平溢出。使用稳定 `data-*` 标识与 bounding box 关系断言，不绑定脆弱的具体像素值。

## Risks / Trade-offs

- [真实文案比 mock 数据更长] → 使用最小列宽、换行与两行截断；完整信息在详情侧栏可读。
- [整行点击与子任务导航冲突] → 子任务链接显式停止行级点击，键盘焦点分别落在链接和详情按钮。
- [多 Child 或多交接摘要造成第三列拥挤] → 子任务与交接标签允许换行，行高按内容增长，但不回退为分散的大卡片。
- [布局断言过度脆弱] → 只验证相对排列、可见性、溢出和交互，不固定颜色值或像素级截图。
- [旧 CSS 残留互相覆盖] → 删除已不再使用的纵向进度卡与旧 rail/drawer 样式，保留单一实现路径。

## Migration Plan

发布新的 `buildr-web` 构建与 tracked `web-dist` 即可启用。无数据迁移。若需要回滚，只回滚前端提交；Parent Plan、Child、Contribution Handoff 与 Task 生命周期事实不受影响。

## Open Questions

无。UI Preview 已确认页面结构，本 Change 将其转写为正式、可验证的实现约束。
