# 按界面预演稿重做父任务贡献进度视图

## 一句话摘要

将已确认 UI Preview 的四项迁移摘要、横向紧凑进度行和贡献项详情侧栏真实落地到 Buildr Web，并用布局级浏览器验收防止再次偏离。

## 背景与问题

上一版本正确实现了动态分组、中文状态、Child 导航和 Contribution Handoff 交付证明，但生产页面沿用了旧摘要并采用纵向长卡片，与用户确认的预演在信息架构、视觉密度和详情交互上明显不一致。现有测试只证明文案和行为存在，没有证明页面按确认结构呈现。

## 目标与非目标

目标是让真实父任务页面采用四项迁移摘要、横向四区域进度行、行内状态/交接/阻塞信息、详情侧栏和完整响应式降级。非目标是像素级复制预演的全局应用壳、修改后端 read model、增加进度存储或改变任何任务生命周期 authority。

## 受影响用户或角色

主要影响在 Buildr Web 中查看和协调 Parent Task 的用户；Child Task 使用者仍通过标准任务详情页工作。

## 核心流程

用户进入 Parent Task 后，先查看推荐行动和四项迁移摘要，再按三个固定分组横向扫读每个 Contribution、实际 Child 与交接/依赖事实。点击行或详情箭头打开只读侧栏；点击 Child 标题直接进入标准 Child Task 详情。

## 关键变化

- 旧三项摘要替换为四项迁移事实摘要，并显示动态派生来源。
- 纵向贡献卡替换为紧凑横向进度行。
- 恢复贡献项详情侧栏，移除默认展开的计划方向与边界。
- 桌面与窄屏都保留 Child、Handoff、下一步行动和阻塞事实。
- 浏览器测试验证相对布局、侧栏交互、导航隔离和无水平溢出。

## 影响、风险与兼容性

改动仅涉及 Buildr Web 展示与 tracked `web-dist`，不改变 API 或数据。主要风险是长文案和多 Child 导致行高增加，将通过可换行布局、截断和侧栏完整阅读缓解。现有 Parent/Child、Development、Review、Verification 和 Finish authority 保持兼容。

## 验收摘要

真实桌面页面必须与预演保持相同的信息层级：四项迁移摘要、三个固定分组、四区域横向进度行和详情侧栏；窄屏完整降级且无水平溢出。Child 导航与 Handoff 交付证明边界继续通过正式浏览器验收。
