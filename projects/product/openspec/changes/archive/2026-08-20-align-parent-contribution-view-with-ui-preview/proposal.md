## Why

已交付的父任务贡献进度页面虽然满足分组、中文文案和交付证明等行为要求，但其信息架构和视觉层级没有按用户确认的 UI Preview 落地：紧凑横向进度行被实现为纵向长卡片，迁移摘要仍沿用旧指标，详情侧栏也被错误移除。现在需要把已确认的页面结构提升为正式可验证要求，修正真实页面并防止仅靠文案断言再次通过验收。

## What Changes

- 父任务顶部使用“已交付、剩余工作、已取代、进行中”四项迁移摘要，并明确动态派生来源与不写回父任务计划。
- 每个贡献项使用与 UI Preview 一致的紧凑横向行，固定呈现贡献项、实际子任务、贡献交接/依赖信息和详情入口。
- 在行内使用中文状态标签、交付摘要标签、下一步行动与阻塞原因，减少纵向展开和信息跳读。
- 恢复贡献项详情侧栏，用于查看目标、方向、边界、依赖和交付证明；子任务仍通过标准任务详情路由导航。
- 在窄屏下按预演规则把横向行降级为单列信息块，不丢失状态、子任务、交付和阻塞事实。
- 浏览器验收增加布局结构、四项摘要、侧栏交互和关键元素相对位置检查，不再只验证文案、顺序和 URL。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `local-app-web-client`: 将父任务贡献项动态迁移进度的已确认信息架构、详情交互和响应式布局纳入正式页面要求与浏览器验收。

## Impact

- 受影响前端：`buildr-web` 的父任务协调面板、样式与布局辅助模型。
- 受影响验证：Buildr Web 单元测试、Local App 集成测试、生产托管浏览器测试和 tracked `web-dist`。
- 不改变 Parent Coordination v3 API、Parent Plan、Task/Development/Review/Verification/Finish authority 或任何持久化结构。
- 不包含破坏性 API 或数据变更。
