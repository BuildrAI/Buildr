# 简化 Workspace 代码组织

## 一句话摘要

按Java面向对象设计（OOD）思路合并过细文件，保留重要领域和技术边界。

## 背景与问题

一轮重构后，创建用例和小Hook被单独拆出，增加阅读跳转；共享运行时仍暴露内部方法。维护者需要能直接理解目录、对象和用例的代码地图。

## 目标与非目标

合并Project/Service应用，集中来源文件系统能力，粗拆领域动作表单；保持现有用户界面、命令、协议和数据。主要服务代码维护者，不新增产品操作流程。

## 核心流程

接口接收输入 → 所属应用编排 → 领域对象、具名仓储、来源技术对象 → 接口返回结果。

## 关键变化

应用文件合并；重要技术能力独立；小Hook就近维护；明确对象依赖；文档提供目录与方法级代码地图。

## 影响、风险与兼容性

涉及两个Service及相关模块消费者。重点验证动态调用、路径保护、失败清理、CLI输出顺序与前端表单参数。

## 验收摘要

文件数与跳转成本减少；领域独立；层边界清晰；全部相关测试通过。
