## Why

上一轮将独立逻辑单元过多转为独立文件，增加跳转阅读成本。本次按用户确认的 Java 面向对象设计（OOD）原则合并过细文件，同时纠正层边界和隐式依赖。

## What Changes

- Project/Service创建合并进所属应用，Workspace保留查询、命令与操作三个应用文件。
- 来源目录技术操作集中到一个文件系统协作者，保留Git与管理保护两个重要技术边界。
- 每日演进查询分组回到现有应用；命令参数和输出回到接口。
- 运行时仅公开明确方法，仓储以具名对象注入，不再通配导出所有私有方法。
- 前端目录状态小文件合并回页面，共享文档Hook移入lib；动作抽屉按领域粗拆表单。
- 不改变公开命令、HTTP、存储格式与可见界面；无外部破坏性变更。

## Capabilities

### Modified Capabilities

- `product-source-layout`：取消创建用例必须独立文件的约束，按隔离价值和实际体量决定文件边界。
- `buildr-web-service`：允许页面内Hook，领域动作自行拥有表单和状态。

## Impact

影响Buildr后端Workspace模块、实际跨模块消费者和Buildr Web领域组件、结构测试与代码地图。无新增依赖、数据迁移或全局状态库。
