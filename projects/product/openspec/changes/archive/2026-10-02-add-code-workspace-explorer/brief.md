# 代码板块与资源管理器变更说明

本变更关联任务 `code-workspace-explorer`，整体需求和验收边界见唯一[任务说明](@project/tasks/code-workspace-explorer/brief.md)。

本次把代码查看从工作台/工作空间的业务页面中分出独立顶层区域，建设可多选代码库范围的只读完整文件浏览，并让任务文件入口准确定位同一真实目录或历史版本。现有代码库登记仍为稳定身份来源，任务与 Git 文件现场保持各自权威。

关键取舍是首版代码库范围多选，任务只按服务引用预选普通筛选条件，完整文件树不按任务改动裁剪；项目/服务组合多选暂缓。文件树使用专门的窄栏宽度、文件占用剩余内容区；从任务进入时明确携带代码库、工作目录/版本与文件身份，返回时恢复原审阅。现有任务限定 Markdown 接口（API）不扩大为通用代码读取；新能力单独限定到已登记代码库的已核对位置。

本变更不实现全局提交历史、Git 写操作或文件编辑；源代码管理菜单明确处于后续建设状态。首次实施涉及路径与版本校验、读取上限、取消与迟到响应处理以及现有路由兼容。

技术材料见[提案](proposal.md)、[设计](design.md)、[实施清单](tasks.md)；界面原型（UI Prototype）位于 `prototypes/repository-explorer.html`，原型说明只表达预期交互，不证明正式实现。

## 当前认知影响评估（assess）

实施时需复核 `knowledge/docs/architecture/technical.md` 及后端/前端代码地图中的导航、模块和文件读取职责，按实际授权范围校准；复核结果纳入实施清单，不新建第二份影响状态。核心对象身份沿用既有术语，无需本轮新增长期术语定义。

本轮修订依据现有 `projects/manifest.yml` 的 `serviceIds` 与 `services/manifest.yml` 的 `repositoryId` 关系，只消费登记事实，不新增或修改组成。任务范围预设与文件位置/版本明确分开；当前知识正文仍不写入未实施能力。

用户审看反馈已确认：当前目录搜索接入随产品交付的 ripgrep，历史版本仍搜索指定提交；不以旧累计扫描预算遗漏普通源码。Markdown 正文采用产品统一1200px限宽，右上角沿用“展开阅读 / 恢复分屏”，分隔线的命中区域不得形成布局留白。本轮只校准这一阅读与搜索范围，任务及代码库权威不变。

后续反馈确认顶栏43px、短竖线及对象标签共享工作空间样式；内容结果按文件聚合多匹配行、文件名后显示代码库，可展开逐行定位并同时高亮行与字串。旧首条字段保留，新协议扩展匹配行数组；相同查询的阅读和折叠不重搜，历史对象与只读身份保持原边界。

本轮按人工查看的目标收敛为网页双字符门槛、默认全部展开和每库200匹配行，保留100文件及CLI/HTTP单字符兼容。校准选择框聚焦、搜索模式选中态，以及“代码库目录 / 任务关联目录”与实际路径说明；忽略开关只展示当前位置的忽略内容。代码库登记、任务位置及Git管理目录边界均未改变，已有技术架构和地图职责仍适用，无需扩展长期知识维护范围。

最新审看增加搜索结果第二行相对路径，并将当前/历史文本完整读取额度从1 MiB提升为2 MiB。图片、搜索、身份及只读边界保持，按真实大文本和路径布局证明兑现；既有职责说明仍适用，无新增长期知识维护范围。

用户最新决定将完整文本读取采用5 MiB，超限告警并提供可靠分段阅读；内容搜索文件块只切换匹配展开，具体匹配才定位。此次扩展同一只读file接口的修订及分页元信息，当前与历史共享有界能力，异步CLI/HTTP/读线程正确等待，单段界面和匹配边界如实表达。新增基础设施职责需在源码与规划中校准；当前知识保留已交付事实，不将候选流式能力冒充默认产品已激活。
