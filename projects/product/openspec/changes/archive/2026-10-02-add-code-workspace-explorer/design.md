## Context

动机与外部范围见[提案](proposal.md)及[任务说明](@project/tasks/code-workspace-explorer/brief.md)。当前 `AppShellView` 只支持 `workbench|workspace`，`navigationState` 把非工作台路由归入工作空间；`WorkspacePages` 与 `WorkspaceStage` 提供页面和对象标签、可调分屏与阅读恢复。任务 `TaskDiffReader` 已独立保持所选文件，Git 读取应用通过 `resolveTaskRepositoryScope` 解析项目/服务及受管工作树（Worktree），其 Git 标识与资产清单中的实例标识不同。

当前代码库清单已提供实例稳定身份、位置和局部可用状态。任务文档入口只接受任务范围 Markdown，本次通用代码阅读不会扩大它的允许范围。现有 `buildr-web-client` 的两区域顶栏和默认均分承诺需要明确增量修改，普通页面行为保持。

## Goals / Non-Goals

目标是在相同工作空间身份下建立独立代码区域、受界限的只读文件能力与准确任务定位，使人和智能体（Agent）都能核对真实文件。外部契约见三份规范增量。

不实现全局 Git 历史列表、暂存/提交/推送/分支切换或文件编辑。历史文件只承接已有任务提交的明确定位；全局源代码管理由下一子任务交付。

## Decisions

### 三个区域共享工作空间，代码查看状态独立

增加 `/workspaces/:workspaceId/code/explorer` 和明确待建设的源代码管理菜单；顶栏任意页面可达。代码查看状态放在壳层已有状态机制中，按工作空间区分，记录实例、位置、展开目录、搜索、打开文件与文件树宽度。客户端（Client）保存的偏好不是代码身份权威，每次读取仍由应用核对。相对原型曾使用的跨区域固定侧栏，这个方案保持现有导航职责，并把文件树限定在代码区域。

### 代码库范围多选，任务只是入口预设

首版只提供代码库多选；空筛选表示当前工作空间全部已登记实例，多个已选实例按根分组显示各自完整文件树。筛选范围和当前阅读的文件/目录身份分别保存，改变范围不关闭已打开文件；范围外仍在阅读的文件明确标识并可主动加入范围。

“查看源文件”根据任务显式服务范围，沿现有服务 `repositoryId` 引用收集并去重实例，预填普通范围筛选；不按任务提交、改动文件或服务 `modulePath` 裁剪文件树。仅有项目范围时读取项目已登记 `serviceIds` 再解析代码库；没有可确定范围时显示全部并说明原因，失效引用局部诊断。示例中 buildr、buildr-web 共用一份实例，应只选一次。

任务预选之后，用户可以修改或清空范围，原任务上下文只负责返回导航；筛选不成为授权边界，也不写回任务或资产登记。实际文件读取仍受所选实例与已核对位置限制。精确文件入口同时携带实例、目录/版本、路径及行位置，保证文件实际来源，不能拿范围筛选替代位置身份。

项目多选、服务多选及代码库多选的复杂组合后续按实践扩展，复用现有项目→服务→实例引用，最终结果仍为代码库集合，不新建第二套关系。资源管理器和下一阶段源代码管理可共用这一范围模型，显示内容分别为整库文件与真实 Git 观察。

### 目录窄栏与阅读标签分属两个内容组

目录默认 280px，可在约 240–420px 范围拖动；阅读区右上角沿用“展开阅读 / 恢复分屏”文案与图标，保留目录宽度、搜索和文件位置，与任务/项目分屏比例分开保存。分隔线使用共享组件（Component），命中区域覆盖边界而不占空白带。Markdown 阅读正文沿用 `--reading-content-width: 1200px` 和既有文档字号行高，原文继续满宽源码展示。多个来源使用对象级标签，身份键包含实例、位置或完整提交与相对路径；窄屏目录按需显示。

### 稳定实例与真实 Git 身份显式关联

选择范围来自现有资产清单，不维护第二份代码库登记。文件请求使用 `repositoryInstanceId + locationId/version + relativePath`；服务端由已登记实例默认位置或受管工作树证据解析位置，客户端不提交任意绝对根路径。任务定位根据任务服务的实例引用与当前 Git 位置核验关联；多个候选无法唯一确定时展示选择，不按目录/分支名猜测，不按远端地址合并。

### 独立文件读取应用复用 HTTP 与 CLI

后端新增代码文件读取职责，内部解析默认目录、任务目录和明确完整提交版本；目录枚举、文件正文与搜索分别有界、按需读取。共享文件系统路径身份能力核对真实包含关系，拒绝越界、符号链接逃逸和 Git 管理目录；图片以有界内容响应读取，Markdown 资源也由同一限定身份解析。读取结果携带实际观察摘要、类型、完整性及局部诊断。HTTP 与 CLI 是同一应用的入口，前端不直接读文件系统。

目录与搜索保持有界读取，文件读取允许异步流式处理；HTTP 通过既有固定容量的读取工作线程（Worker）执行并等待结果，不阻塞主线程。目录与文件继续有界按需读取。当前目录的文件名和内容搜索使用随产品交付的 ripgrep，禁用外部配置与链接跟随，默认遵守忽略规则及既有构建目录排除；不再以累计 3000 文件、16 MiB 或 2.5 秒截断正常全库搜索。搜索保留进程时间、输出与结果上限并报告实际覆盖，达到上限不能冒充零匹配；历史搜索使用指定提交的 Git 对象，不检索当前工作目录。打开结果或切换同一来源文件不重搜，查询/范围/版本/忽略规则变化或主动刷新才重新执行。已登记位置通过 Git 核对实际代码库根目录，旧服务子目录不会成为整库浏览的裁剪边界。

### 任务关联是定位与导航，不新增任务作者

任务提供“查看源文件”以预选普通代码库范围，从当前差异提供“查看完整文件”以精确定位文件。只读定位返回实例、位置、文件及可选行范围；返回信息保留任务路由、阶段、差异来源和所选文件。资源管理器不会把当前目录选择写回任务范围，不新增任务生命周期、文件附件库或第二 Task writer。历史提交的查看使用同一完整提交标识，缺失不回退到当前同名文件。

### 原型与正式界面接续

复用正式顶部栏、导航、分隔线、标签、Markdown 和差异组件，原型只提供模拟数据与受控内存导航。覆盖代码资源管理器、多代码库范围、任务服务预选、精确文件定位与返回、收起目录、搜索、文档/图片以及源代码管理待建设态。最新原型位于 `prototypes/repository-explorer.html`，旧版保全于本次讨论临时目录；仅新版作为本变更的评审来源。

## Risks / Trade-offs

用户进一步审看确认：代码顶部采用与工作空间相同的43px栏和短竖线，对象标签提取为真正共享组件（Component）。内容搜索按文件聚合多条匹配行，后端以可选 `occurrences` 字段扩展原 `path/line/excerpt`，旧字段仍表达首条匹配；名称搜索无匹配行。每个代码库结果最多100文件、累计200匹配行，截断如实报告并引导缩小关键词或范围。文件名后显示所属代码库，完整路径留作悬浮提示；所有匹配文件默认展开，仍可独立折叠，摘要围绕首次命中裁切。字串高亮按字面、大小写不敏感的原始文本范围执行，不受源码语法着色分段影响；点击匹配会定位行与命中文字，Markdown内容命中使用原文。折叠、展开与定位只改变阅读状态，不重新搜索。

人工检索以定位和理解为目标，不提供批量替换工作流（Workflow）。网页文件名与内容查询在去除两端空白后至少包含两个非空白Unicode字符才发送搜索；不足时提示输入门槛并清除旧结果。命令行（CLI）及网页接口（API）仍兼容1–200字符的明确查询，持久查询协议不收窄。聚焦边界只由代码库选择框外层表达，内层输入框不重复描边；搜索模式采用清楚的主题选中状态。

查看位置文案改为“代码库目录 / 任务关联目录 / 历史提交”，直接呈现当前实际路径。代码库目录表示登记位置中的实时磁盘文件（含未提交修改），不表示合并所有工作树（Worktree）；从任务进入可切换该任务已核对目录，没有独立工作树时沿用代码库目录。首版不提供任意工作树枚举。忽略开关仅放开当前目录的Git忽略规则与常见构建目录排除，隐藏名称本身不是忽略条件，Git管理目录始终禁止；所选目录不存在的内容不能从其他目录补入。

两种搜索结果的文件名下均展示代码库根内的相对文件路径，单行省略并通过悬浮显示完整值；路径在折叠匹配行后仍保留；文件名模式点击打开，内容模式点击只展开/折叠，具体匹配行才打开并定位。代码库身份在首行，实际绝对目录在查看位置中呈现，避免在每个结果重复机器前缀。当前及固定历史版本文本完整读取上限为5 MiB，超过边界告警并按512 KiB段阅读，单段渲染，不累计为大文件全文；图片8 MiB与搜索100文件/200匹配行、执行和输出预算保持。

- 任务 Git 身份与登记实例身份混淆 → 显式核验关联及位置，不复用路径字符串作为唯一文件键。
- 单个目录缺失拖累全部代码库 → 按实例返回局部状态，保留其他选择和已读内容。
- 大目录或内容搜索阻塞 → 懒枚举、有界搜索与读取、实际覆盖提示；不把未执行或截断称为完整。
- 快速切换根目录后的旧响应污染阅读 → 请求代次/取消与文件身份同时核对，失败或其他来源响应不进入成功缓存。
- 文件树继承普通页面的均分比例 → 使用独立代码目录宽度键，仅扩展必要共享参数。
- ripgrep 运行依赖宿主安装或候选打包遗漏原生文件 → 锁定 `@vscode/ripgrep-universal`，候选打包复制并登记各平台二进制（Binary）的摘要、权限及许可证。跨平台离线交付会增加约58 MB解包资源；当前宿主完成实际安装与命令行（CLI）/网页接口（API）验证，其他平台先核对产物清单，不冒充已运行验证。
- 历史文件误读当前内容 → 版本绑定完整提交，已退役的任务目录不影响仍可核验的登记代码库提交对象；删除/缺失如实表达，“查看当前文件”另开来源标签。

## Migration Plan

保留现有地址、代码库登记、任务材料和任务记录协议；新增代码路由与读取协议，不迁移业务数据。浏览器偏好缺失/损坏使用默认值，显式关闭或切换空间释放对应阅读状态；不按隐藏时长清除。候选构建只在任务工作树运行，不激活共享自举环境；正式集成和激活后再校准当前说明，回退时旧入口仍可使用。

## Verification and knowledge scope

方案审查核对三域导航与既有分屏承诺、路径边界、实例/Git 身份关系和任务往返；实现审查核对目标兑现及同源只读边界。审查结论由任务专业入口维护，规划文件不代替审查证据。实现阶段直接验证目录/越界/大文件/迟到响应、多仓库同名文件、服务引用去重、任务预选与清除筛选、完整文件树、实际目录及历史版本、返回审阅和 1440/900/390 尺寸；正式浏览器证据来自生产托管，原型检查不替代它。

已有知识评估见[变更说明](brief.md)。本轮只安排受影响的实际地图与技术解释复核，不把未实现能力写回当前事实；若发现需要修改现有长期知识，明确具体范围后按已有授权处理。

### 大文件分段读取契约

沿用 `file` 操作，增加互斥 `page` / `line` 定位参数、与行定位一起使用的 `matchQuery` 字面词，以及续读的 `expectedRevision`。响应增加 `revision` 和可空 `page`，后者提供段序号/总数、实际字节范围、全局行号与续行标记，适用时给出首次匹配的真实字节区间。字节页边界最多回退3字节至字符首字节，保证UTF-8字符完整并避免空末段；跨页命中按当前页可见范围高亮并说明续读，不扩大页造成重复。当前文件修订身份依据物理位置和文件统计版本，读前后核对；历史身份绑定完整提交与Git对象，流式扫描只保留目标段。扫描/定位受时间预算约束，不全量装入内存。CLI、直接HTTP和读工作线程都等待异步结果；目录/搜索原有行为保持。

前端沿同一文件身份替换单段内容，前后段沿已观察修订读取；迟到响应按文件/读取代次隔离。搜索匹配不在当前段时直接按行与字面词加载目标段，真正全局行号进入选择与协作指令。Markdown分段显示原文，不将片段渲染为完整文档；不完整文件不启用完整修改入口。
