## Why

查看完整源码与相关实现仍依赖外部编辑器；任务的差异审阅缺少准确进入完整文件并返回的路径。用户已确认用独立“代码”板块承载随时可用的文件与 Git 查看能力，本次先交付资源管理器闭环。

## What Changes

- 在共同工作空间（Workspace）范围下新增“代码”顶层区域，保留工作台和工作空间；代码区域左侧提供“资源管理器”和明确待建设的“源代码管理”。
- 资源管理器支持当前工作空间代码库（Repository）多选范围，未筛选时显示全部，使用约 280px 的独立文件树窄栏与可展开的文件阅读区，支持文件名/内容搜索、源码、文档和图片阅读。
- 增加代码库限定的只读目录和文件读取能力，基于稳定身份及已核对位置解析文件，显式表达缺失、局部不可读、截断与不支持类型。
- 任务“查看源文件”只预选其服务引用的代码库（去重），显示整库文件树；用户可扩展、清除筛选，不新增任务专属文件集合。项目多选、服务多选的组合过滤留待后续实践。
- 从任务入口、未提交改动或所选提交（Commit）定位完整文件，保持对应工作目录或明确版本，并提供返回任务的审阅恢复。
- 查看状态按工作空间、代码库和目录/版本区分；不新增任务写入面、任意文件读取或自动 Git 操作。
- 不含破坏性变更；既有工作台、工作空间、代码库登记、任务及文档地址保持兼容。

## Capabilities

### New Capabilities

- `repository-file-explorer`: 已登记代码库的目录/文件只读观察、文件身份与版本、搜索、阅读及安全失败边界。

### Modified Capabilities

- `buildr-web-client`: 三个顶层区域与代码区域的双栏浏览、独立文件树宽度和查看状态。
- `task-changes-workbench`: 从差异打开准确来源的完整文件并返回原任务审阅。

## Impact

- 前端：`src/app/AppShellView.tsx`、`navigation.ts`、`AppNavigation.tsx`、`WorkspacePages.tsx`、共享分屏与标签；新增 `features/code/` 页面、钩子（Hook）与客户端（Client），扩展任务文件入口。
- 后端：复用工作资产清单和受管工作树（Worktree）身份解析；新增独立代码文件读取应用（Application）及超文本传输协议（HTTP）/命令行接口（CLI）能力与生成数据传输对象（DTO）。
- 需要对应目录边界、符号链接（Symbolic Link）、读取上限、异步来源切换和任务往返的检查，沿用离线托管和会话（Session）边界，不新增依赖或后台扫描。
- 实施完成时复核现有前端/后端代码地图（Code Map）与技术说明中受影响职责；本轮仅评估和安排，未把未来能力写成当前事实。
- 属于组合任务 `code-workspace` 的第一子任务 `code-workspace-explorer`，全局源代码管理留给 `code-source-control`。
