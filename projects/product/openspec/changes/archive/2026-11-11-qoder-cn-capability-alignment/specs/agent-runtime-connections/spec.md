## ADDED Requirements

### Requirement: Qoder CN ACP 对话必须保留准确消息与控制语义

Qoder CN 接入 MUST 保留连续文本片段、思考、工具及最终回复的顺序和独立身份，在确认正常轮次结束时结算已接收文本；MUST NOT 把跨工具的全部正文合并，或以正常文本结束推定工具成功。工具更新 MUST 保留先前已知名称和输入。接入 MUST 在输入送达前校验并应用真实模型、推理和权限配置，完全访问 MUST 映射原生免审批模式而非代答许可。接入 MUST 隔离准确上下文的已观察历史；恢复回放 MUST NOT 重复入库或混入新轮。取消 MUST 只作用于准确会话及执行，并以原生结算而非通知发出证明停止；断连、未知终态或未结工具 MUST 保留未知，MUST NOT 自动重放工作。尚未接入的提问、补充和完整原生历史导入 MUST NOT 被宣称支持。

#### Scenario: 工具前后正文与正常结束
- **WHEN** 原生依次输出正文、思考、工具调用及结果、最终正文，并返回 `end_turn`
- **THEN** 各段 MUST 按顺序保持不同身份，正常文本 MUST 不再为运行中，最后助手正文可由现有界面提取为最终回复
- **AND** 仅含状态的工具更新 MUST 保留名称与输入，失败结果 MUST 保持失败而不是成功

#### Scenario: 权限模式与模型检查
- **WHEN** 用户选择完全访问或切回默认权限，并选择明确模型与推理强度
- **THEN** 原生 `mode` MUST 分别应用 `yolo` 或 `default`，模型与强度 MUST 按实际选项校验，失败时 MUST 不提交工作输入

#### Scenario: 取消尚未确认或连接丢失
- **WHEN** 发出取消尚未收到原生结束回执，或原生连接断开
- **THEN** 接入 MUST 不仅凭通知发出报告停止；断连 MUST 保留未知状态并清理失效审批，MUST NOT 向新执行复用旧批准或重放工作

#### Scenario: 网页提交工具批准
- **WHEN** 用户点击工具批准卡片，网页传入原生字符串选项 ID
- **THEN** 接入 MUST 把该准确选项提交给原生请求；非法选项 MUST 保留待批准请求，允许一次 MUST NOT 被扩大为持久授权

#### Scenario: 轮次历史与准确控制对象
- **WHEN** 同一运行对象执行多轮或恢复不同上下文，或收到错误执行身份的停止及批准请求
- **THEN** 历史 MUST 只返回准确上下文已观察的条目并保留先前轮次；错误身份 MUST 被拒绝且不影响原执行；原生回放 MUST 不成为新轮输出

#### Scenario: 截断及工具未结
- **WHEN** 原生因输出上限结束，或正常正文结束时工具仍未结
- **THEN** 接入 MUST 保留明确截断或未结状态，不把该轮或工具报告为完整成功，不以新输入覆盖未知工作
