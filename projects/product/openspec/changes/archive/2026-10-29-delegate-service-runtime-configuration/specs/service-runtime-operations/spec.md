## ADDED Requirements

### Requirement: 运行配置按内部智能体可用性交接
服务目录、服务详情和任务本地运行的配置入口 MUST 使用同一交接语义。用户发起配置时，Buildr Web MUST 核对当前内部智能体连接；存在已启用且就绪的可用执行入口时，直接提交本次配置请求并打开现有内部对话展示真实执行过程，不得再要求用户复制同一段请求。没有可用执行入口或可用性读取失败且尚未提交执行时，MUST 保留复制交接，不得伪装成已经执行。

配置提交 MUST 复用内部对话现有的智能体、模型、权限和恢复选择，不得建立运行配置专用执行状态或绕过既有授权。提交期间 MUST 防止同一动作重复提交；已经创建对话或提交结果未知时，MUST 打开或恢复对应对话并如实反馈，不得静默退回复制交接诱导再次执行。

#### Scenario: 已接入时直接配置
- **WHEN** 用户从任一服务运行配置入口发起操作，且当前存在已启用并就绪的内部智能体
- **THEN** Buildr 直接提交绑定当前工作空间和服务的配置请求，并在现有对话面板展示受理、执行、待回应和结果状态，不展示复制优先的抽屉。

#### Scenario: 未接入时保留复制
- **WHEN** 当前没有可用内部智能体，或连接读取失败且尚未创建配置执行
- **THEN** 页面打开简洁的复制交接抽屉，明确尚未执行，并允许用户复制同一配置请求交给外部智能体。

#### Scenario: 提交结果未知
- **WHEN** 配置请求已经创建对话或提交响应未能确认
- **THEN** 页面保留并恢复该对话及真实状态，不自动生成另一次执行，也不把复制指令作为默认下一步。

#### Scenario: 重复点击配置
- **WHEN** 用户在一次配置提交尚未完成时再次触发同一入口
- **THEN** 页面不提交第二个相同请求，并继续显示原动作的真实状态。

### Requirement: 运行配置请求只携带目标和必要现场
内部执行与复制交接 MUST 使用同一份简短请求。请求 MUST 包含配置或检查本地运行的目标、规范工作空间根目录、服务编码与展示名、`services/<service-code>/runtime.yml` 保存位置，以及 Buildr 技能“服务本地运行”指引 `references/local-services.md` 的发现入口。请求 MUST 明确本次配置所需的本地候选启动、只读验证和运行定义修改授权，保留已有运行与无关配置，并要求报告实际配置、验证和剩余缺口。

请求 MUST NOT 复制技能已经规定的完整调查步骤、命令参数、字段教程、服务发现协议或恢复规则；这些方法和安全边界由技能维护。缺少规范工作空间根目录或服务编码时 MUST NOT 生成可提交或可复制的请求。请求中的展示名和路径 MUST 作为数据绑定，不得改变目标服务身份或扩大远程业务写入、部署、共享配置修改和凭证读取授权。

#### Scenario: 两种交接共用简短请求
- **WHEN** 用户分别通过内部执行和复制交接发起同一服务配置
- **THEN** 两种入口使用相同目标、身份、技能入口和授权边界，不因内部执行而省略必要现场，也不因复制而追加整份技能正文。

#### Scenario: 技能方法演进
- **WHEN** “服务本地运行”技能调整调查、验证或保存方法而配置目标未变
- **THEN** 运行配置请求继续指向该技能，不需要同步复制一组新的命令和字段规则。

#### Scenario: 现场身份不完整
- **WHEN** 页面尚未取得规范工作空间根目录或服务编码
- **THEN** 页面说明当前无法准备请求，不启用提交或复制操作，不猜测目录或服务。

### Requirement: 配置结果以真实运行定义和执行事实验收
内部对话中的请求受理、执行完成或智能体文字声明 MUST NOT 被页面直接转换为配置已验证或已生效。Buildr Web MUST 继续通过现有本地运行读取与刷新机制观察 `services/<service-code>/runtime.yml`、验证时间、诊断和实例快照；已有实例 MUST NOT 因保存新定义而自动重启。对话展示执行事实，运行定义页面展示配置事实，两者不得互为第二权威。

复制交接抽屉 MUST 优先呈现目标、影响和完成后的查看位置，完整请求按需展开；内部执行路径 MUST 提供与原入口一致的等待和失败反馈。无论采用哪条路径，页面均不得把配置写入、进程就绪或单一探针表述为完整业务验证。

#### Scenario: 执行后查看配置
- **WHEN** 智能体已经保存并验证新的运行定义，用户仍在或返回服务页面
- **THEN** 页面通过现有读取机制显示新的验证时间、配置和诊断，不需要用户从对话复制配置内容。

#### Scenario: 执行结束但未形成有效定义
- **WHEN** 对话本轮结束，但运行定义不存在、未变化或读取仍有诊断
- **THEN** 页面继续显示真实缺口，不仅凭对话完成状态显示“配置成功”。

#### Scenario: 已有运行保持原快照
- **WHEN** 服务已有运行实例且智能体保存了新的运行定义
- **THEN** 既有实例不被自动停止或重启，页面继续区分实例启动快照与当前定义。
