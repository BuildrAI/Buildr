## Purpose

让用户在项目资料与资源管理器（Explorer）中直接编辑已明确来源的当前文本文件，两入口共享编辑、保存与错误恢复行为，并以实际文件身份和已观察版本保护人与智能体（Agent）的共同工作现场。

## ADDED Requirements

### Requirement: 两个入口统一编辑真实文件

系统 MUST 在项目资料 README.md、AGENTS.md、由项目资料内链接逐层打开的项目当前 Markdown 文档，以及资源管理器（Explorer）的当前普通文本文件中提供相同的阅读/编辑面板与保存行为。编辑 MUST 读取完整原文，按工作空间（Workspace）及真实文件身份共享当前内容和编辑历史；来源选择 MUST 明确区分项目登记来源、代码库及检出目录，不能按同名文件或分支名称替代。文件信息 MUST 紧凑显示相对路径、目录与版本，完整绝对路径可查看。

面板 MUST 仅提供“阅读”和“编辑”两种主状态。阅读 Markdown 时 MUST 显示渲染后的正文，其他文本 MUST 正常显示文件内容，不另设“原文”或“阅读模式”。仅 Markdown 的编辑状态 MUST 提供可开关的预览（Preview），非 Markdown 文本 MUST NOT 显示预览入口。切换文件、退出编辑或变为只读时 MUST 关闭预览，且 MUST NOT 清空内容或编辑历史。

阅读/编辑切换 MUST 保持控件等宽、位置与文件路径布局稳定；预览（Preview）MUST 作为单独的编辑辅助操作显示，不挤动主切换。当前绑定的权限或只读政策变化 MUST 在正文版本不变时仍更新可编辑状态，并保留输入与编辑历史。

#### Scenario: 同一文件跨入口继续编辑
- **WHEN** 用户在项目资料修改文件后，从资源管理器（Explorer）打开同一实际文件
- **THEN** 两入口 MUST 呈现同一当前内容、保存状态和可继续的编辑历史
- **AND** 不同检出目录的同名文件 MUST 保持独立

#### Scenario: 阅读与编辑的模式保持清晰
- **WHEN** 用户阅读 Markdown 或普通文本，然后进入编辑
- **THEN** Markdown 的阅读显示渲染正文，普通文本正常显示内容；编辑均允许修改完整原文
- **AND** 仅 Markdown 编辑时显示预览（Preview）开关，返回阅读再进入编辑时预览默认关闭

#### Scenario: 进入项目资料内的下级文档
- **WHEN** 用户从项目资料的当前文档点击项目内 Markdown 链接，或继续进入下一层文档
- **THEN** 系统 MUST 以该文档的真实项目来源和相对路径打开同一阅读/编辑面板，并沿用自动保存（Auto-save）、快捷键及保存冲突处理
- **AND** 返回上一篇 MUST 恢复对应文件的内容与编辑历史；只读边界和项目来源内的路径限制继续有效

#### Scenario: 刷新后返回项目下级文档
- **WHEN** 用户从项目下级文档打开资源管理器（Explorer），刷新页面后返回项目
- **THEN** 系统 MUST 恢复该项目的资料入口、当前文档路径和返回上一篇的导航历史，再读取真实正文
- **AND** 导航恢复 MUST NOT 保存正文副本、跨项目恢复或绕过相对路径校验

### Requirement: 默认自动保存与快捷键历史

进入编辑后的文件 MUST 默认自动保存（Auto-save），停止输入片刻、失焦或切换时尝试保存；组合输入 MUST 不发送尚未完成的中间内容。系统 MUST 支持平台常用撤销（Undo）、重做（Redo）与立即保存快捷键，不显示单独撤销、重做按钮。保存、预览或入口切换 MUST 不清空编辑历史；保存期间继续输入 MUST 不被旧响应覆盖或误标已保存。

#### Scenario: 保存后撤销并继续输入
- **WHEN** 用户修改已保存，随后使用 Cmd+Z、Cmd+Shift+Z 或对应平台快捷键
- **THEN** 编辑器 MUST 正确撤销或重做，结果继续自动保存（Auto-save）

#### Scenario: 中文组合输入和在途保存
- **WHEN** 用户使用中文输入法，或某次保存尚未完成时继续输入
- **THEN** 系统 MUST 保留完整输入，组合完成后才保存，且只在最新输入已写入后显示已保存

### Requirement: 保存验证来源和已观察版本

保存 MUST 使用明确登记来源、规范化相对路径、已观察文件身份、来源身份和内容版本；服务端 MUST 重新核对来源、实际路径、文件内容、可编辑范围及本机会话（Session）写入授权。保存 MUST NOT 接受任意绝对路径、目录穿越、符号链接（Symbolic Link）写入或 Git 管理目录。文件不存在、来源漂移或版本变化 MUST 局部失败并保留输入。写入 MUST 保留 UTF-8 文件头、换行与权限，不能通过页面展示结果重建正文。

#### Scenario: 保存前磁盘文件已变化
- **WHEN** 文件当前版本与请求的已观察版本不同
- **THEN** 系统 MUST 返回冲突及可读取的最新版本，MUST NOT 按旧版本保存

#### Scenario: 来源映射被替换
- **WHEN** 项目来源或所选检出目录的实际身份发生变化
- **THEN** 系统 MUST 拒绝旧观察对应的写入，MUST NOT 将内容保存到替代目录

### Requirement: 冲突和失败保留用户输入

外部变化与本地修改同时存在时，系统 MUST 暂停该文件保存并保留双方内容，提供对照、编辑合并结果、按最新观察再次保存及明确采用磁盘内容的操作。采用磁盘内容 MUST 告知替换输入的后果。未处理冲突 MUST NOT 静默覆盖；合并后再次外部变化 MUST 继续冲突。普通保存失败 MUST 显示真实状态、保留输入并支持重试，其他文件继续工作。

#### Scenario: 合并结果遇到第二次外部变化
- **WHEN** 用户对照双方后保存合并结果，但磁盘又发生变化
- **THEN** 系统 MUST 保留合并结果，重新显示最新冲突，不能绕过版本检查

#### Scenario: 失败后重试
- **WHEN** 文件暂时不能写入，用户稍后重试
- **THEN** 系统 MUST 使用仍保留的当前输入尝试保存，成功前不能显示已保存

### Requirement: 编辑范围维持明确边界

历史内容、二进制文件、超限或片段阅读 MUST 保持只读。Buildr 管理的生成副本 MUST 按来源维护，受管区块（Managed Block）MUST 保持原文不变，完整受管文件允许修改区块外内容；受管标记损坏时 MUST 明确拒绝受影响写入。新增编辑能力 MUST 不自动开放服务、知识、任务或技能其他入口，不自动执行 Git 提交、推送或发布。

#### Scenario: 编辑根规则的用户部分
- **WHEN** 文件含完整受管区块（Managed Block），用户只修改区块外内容
- **THEN** 系统 MUST 允许保存，并验证受管内容仍与已观察原文一致

#### Scenario: 尝试编辑只读内容
- **WHEN** 用户查看历史文件、大文件片段、生成副本或试图修改受管区块（Managed Block）
- **THEN** 系统 MUST 显示对应边界且服务端拒绝不允许的保存
