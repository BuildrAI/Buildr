## Context

现有服务已有缓存/运行时清理计划、存储锁、占用观察和条件回收；Qoder 诊断文件未接入。原生 projects 会话正文不属于日志回收范围，logs/sessions 中的结束事件仍是冷恢复的证据来源。用户允许不能及时清理时延迟处理，并要求未来能接入其他可回收数据。

## Goals / Non-Goals

目标是按适配器声明复用统一回收器，分离诊断文件与业务恢复状态，保护准确上下文关联的必要证据，自动重试并不阻塞对话。非目标是重写原生会话、压缩、引入任意路径清理配置、维护永久队列或新建结束事实权威库。

## Decisions

| 职责 | 归属 |
|---|---|
| 声明诊断文件范围、生产者及所属上下文 | Qoder 适配器；共用契约允许其他执行器后续声明 |
| 从权威对话头读取活动/未知恢复依赖 | ConversationRepository 的只读投射，失败时保护全部会话证据 |
| 观察文件身份、占用、生产者退出及稳定窗口 | 共用存储维护应用与文件回收器 |
| 条件删除、逐项保留理由、预算 | 既有 collectAgentStorage；每轮有界，不把未处理对象当已删除 |
| 自动触发及延迟重试 | 执行后台的独立维护工作线程，同一后台最多一个清理线程 |

1. 诊断候选独立于 cache，不把日志冒充可重建缓存。运行目录验证 manifest 与目录中的 PID/run_id 关系；SDK 日志按确切已退出生产者识别；会话段关联 session ID。未知格式、链接、非单一所有权、活跃生产者与占用未知都保留。
2. 默认仅考虑修改时间超过 15 分钟且生产者已退出的日志，避免与即时失败诊断竞争。不只按 PID 的不存在推断业务结束：对话权威头中的活动、未确认、待回答或尚未释放控制依赖继续保护对应 session 事件；不保留无依赖的全量运行调试日志。保护读取失败只阻止会话证据删除，独立运行日志仍可清理。
3. 不裁剪、合成或替代原生结束事实；未确认上下文的结构化事件保留原字节。恢复完成或权威状态不再依赖后，后续周期可释放。正常原生恢复继续使用原 projects 正文，不改文件位置或协议。
4. 在既有清理入口中重新发现候选，复核身份、生产者、系统占用与上下文保护，存储锁内做窄重命名/回收，变化恢复或保留。目录未知内容不扩大删除；文件段按文件单元回收。公开结果不暴露日志内容、参数或认证。
5. 后台使用独立工作线程，初次延迟启动，后续周期重试；每轮最多处理有限对象，优先较大可回收项。线程失败/锁冲突不影响对话，下一周期重新观察。没有新的持久队列、清理请求状态或运行结束权威。

## Risks / Trade-offs

- 原生进程长时间存活、未确认执行或占用观察不可用时可能继续占空间；明确保留并延迟，不能用空间压力覆盖恢复证据。
- 不建立单独的小回执库，保护粒度为必要会话事件段；它们相对大运行日志更小且避免改写恢复协议。未来如需缩小到行级证据应另行证明。
- 进程退出后仍可能有继承的描述符，必须结合系统占用复核。PID 被复用时保守延迟。
- 清理线程崩溃可能留下隔离的回收对象，后续只在能恢复来源证明时处理；不能扫描删除任意 .reclaim 名称。
- 不从未集成候选启动共享用户环境；验证使用隔离文件、SQLite 与进程现场，完整发行入口另作必要检查。
