## Why

智能体（Agent）接续工作时，即使 Git 当前事实可以证明对象身份和成果保全，缺少 Buildr 历史登记仍使清理无法继续；当前实现还会在没有登记时直接返回 `cleaned`，无法证明实际目录和分支（Branch）已经不存在。应以当前事实保护删除安全，并准确报告结果。

## What Changes

- 为已有工作树（Worktree）的检查和清理增加显式、仅本次使用的当前对象输入，核验实际 Git 身份，不补造创建历史。
- 保留已有登记的冲突保护、完整交付核验、未保存内容保护、逐仓版本核验和精确本地删除；缺少登记自身不再成为永久障碍。
- 没有登记且没有足够对象输入时返回具体诊断，不返回 `cleaned`；只有实际删除或逐项确认不存在后才能报告清理完成。
- 同步 `task-worktree`、`task-triage`、`task-finish`、已有协作约定和当前说明，补充正常、拒绝、重试和多仓库场景。
- 现有已登记调用保持兼容；纠正无依据成功结果。创建默认目录和远端操作授权不变，不新增长期登记库。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `task-environments`：允许以明确的当前对象输入接续检查和清理，区分历史证据缺失与真实身份冲突，准确表达清理结果。

## Impact

影响 Buildr Service 的 Git 工作树（Worktree）命令行接口（CLI）、提供者（Provider）、内置技能（Skill）及其直接消费者（Consumer），以及相关测试、命令参考和任务协作说明。沿用现有协作约定版本并同步内置消费者；扩展可选输入，不撤销现有删除安全保证。不涉及网页界面、发布或真实旧任务资源删除。
