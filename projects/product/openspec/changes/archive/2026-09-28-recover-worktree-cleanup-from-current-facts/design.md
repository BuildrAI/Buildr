## Context

问题与范围见 [proposal.md](proposal.md)。现有检查和清理以 Git 公共目录（Common Directory）中的历史登记定位对象；检查在缺失时拒绝，清理却直接返回 `cleaned`。删除本身已经核对源版本、未保存内容、交付保留位置并条件删除分支（Branch）。

## Goals / Non-Goals

**Goals:** 允许不同智能体（Agent）依据明确的当前对象继续检查和清理，复用现有删除核验，准确区分历史记录与本次观察。

**Non-Goals:** 不自动猜测任务归属，不迁移目录，不新建接管登记、不保存虚构的创建时间或起点，不判断业务交付等价，不删除远端资源，不扩展预览（Preview）管理或任务关联自动发现。

## Decisions

1. 检查和清理接受可选 `observedCheckouts`；命令行接口（CLI）使用 `--observed-checkouts <json-file>`，文件内容为数组，每项含 `selector`、`sourceRepository`、`checkoutPath`、`branch`。调用方明确完整对象集合与本次操作授权；软件从 Git 和当前项目、服务来源核实身份。根目录可以是明确提供的既有位置；创建仍使用 `.worktrees/<task-id>`。拒绝相对路径、身份混淆、重复项、主目录、锁定位置和不完整的嵌套集合。
2. 已有登记继续优先使用。显式观察不能掩盖损坏或冲突的登记；同时提供时核对同一集合与身份。缺失时只在内存中形成当前观察，起点未知返回 `null`，不写入历史证据。结果标注 `evidenceSource: stored|observed|none`。
3. 两条路径共用实际删除流程。观察路径要求完整的源与交付提交（Commit），保持未保存内容、保留位置、删除前版本重验与条件删除。调用方仍须核实正在进行的工作和需保留的忽略文件；Git 锁定与其他检出位置由程序保护。
4. 没有登记也没有显式对象时返回 `blocked` 和可执行的接续指引，不能推断已经清理。显式对象在部分删除后可以复用：重新验证剩余分支（Branch）与占用，逐项确认不存在，允许幂等重试。不存在的对象不伪报为本次删除。
5. 当前对象读取与核验独立为基础设施（Infrastructure）职责，原提供者（Provider）继续拥有创建和删除。直接消费者（Consumer）的技能说明一并更新，协议保持向后兼容的可选输入；已有内部调用没有观察输入时维持原有检查诊断。

## Risks / Trade-offs

- 明确输入不是归属证明 → 核对当前来源、Git 公共目录（Common Directory）、精确登记路径、分支（Branch）和完整仓库集合；只在已授权范围使用。
- 父目录删除可能包含未列出的嵌套代码库（Repository） → 删除前检查嵌套 `.git`，遇到未知对象保留现场；不跟随符号链接（Symbolic Link）。
- 检查后状态可能变化 → 每次删除前重查源身份与交付保留位置，删除分支（Branch）前重查其他检出位置并使用精确版本条件。
- 本次观察不持久化 → 中断后重传原始对象集合，按现场重新核验；不引入另一套恢复状态。

## Migration Plan

已有登记无需迁移。产品候选同时交付实现、说明和测试；正式启用仍沿用正常交付与自举流程。旧版本不会支持新参数，不能宣称只改说明即可生效。任务关联自动发现未支持宿主位置时，保留具体路径并报告关联状态，不补造历史登记。
