## Context

问题见[提案](proposal.md)。当前服务声明 `local.routing` 即触发任务身份检查，界面也禁用主工作库。应用本身已有 QA 发现配置，普通启动不需要任务上下文；前端多直接地址后端能力已存在。

## Goals / Non-Goals

**Goals:** 普通服务按所选代码及远程环境启动，开发任务一键本地联调；无对应检出的分支（Branch）自动使用独立工作树（Worktree），保留原目录与改动。

**Non-Goals:** 不增加路由文件版本，不修改 Java 协议，不创建主工作库泳道（Lane），不改变共享 QA，不伪造任务或 `verifiedAt`。

## Decisions

### 1. 普通主工作库不进入任务泳道

单服务入口显式使用普通启动模式；即使所选真实目录属于任务或存在 `local.routing`，也不准备泳道（Lane）、不写或注入路由文件、不保存任务路由观察。旧未指定普通模式的调用继续兼容原有主库与任务语义。发现下游未指定、`auto` 或 `remote` 时沿应用原有 QA 配置启动；`local` 或显式发现运行目标被准确拒绝。任务目录继续生成原 `buildr.local-service-routing/v1`，原任务选择、循环组合、目标漂移及重启前校验保持。

采用这一路径可直接利用已有应用配置。相比为普通启动新增范围协议，成本与用户目标更匹配。未知目录或矛盾身份只阻止对应动作，不回落其他目录；新旧运行记录保持可读。

### 2. 服务列表按用途呈现

普通启动优先真实主工作库；前后端统一只选择工作树（Worktree）、分支（Branch）及远程连接环境，不展示逐下游选项。远程环境由已验证运行定义提供，未声明环境时兼容应用现有配置。来源目录的任务归属与本次是否任务运行分开，服务页普通启动不隐式加入任务。任务入口一键启动所选前后端，自动使用本任务就绪实例，未选本地服务使用远程环境。

选择其他分支（Branch）不切换已有目录：对应分支已有工作树（Worktree）则复用，没有则在工作空间（Workspace）的本机目录创建独立检出。代码模块负责登记来源、Git 身份与引用版本核对、创建和复用；服务模块负责模块路径、运行来源及启动。远程分支仅按已观察引用创建本地跟踪分支，不隐式获取远端。分支漂移或占用冲突准确报错，现有目录、未提交内容和已有运行保留。

验收调整后，不再保存脱离工作树（Worktree）的待启动分支（Branch）选择。复用 `BranchManagementPopover`：默认检出切换调用现有代码能力及版本校验；用户也可在独立目录使用未检出的分支（Branch），完成准备后立即选择返回的真实工作树（Worktree）。已在其他目录使用的分支（Branch）直接切到该目录。所有操作限定服务所关联代码库（Repository），实际目录、当前分支（Branch）和提交（Commit）一致后才能启动，普通切换不重置或丢弃改动。

同一工作空间（Workspace）中重复读取通过有界、短时的界面读取缓存（Cache）合并，缓存（Cache）生命周期随界面上下文结束。后台刷新保留已知内容；写入仍由服务器重新验证。启动按钮悬停或聚焦时预先读取所需配置；冷读取在原按钮就地反馈，数据可用后打开完整弹窗。单服务远程入口不枚举任务本地候选，任务入口保持原候选语义。服务目录复用该读取机制，避免切页重复空载。

本地运行仅保留标题处的一个启动动作，空态说明指向该动作；验证状态以紧凑图标及时间并入配置标题，完整路径继续独立呈现。服务目录的启动采用柔和主题底色，常用服务复用工作台 `saved-resource` 的 `service:<id>` 身份和个人持久化，不新增服务源字段；已收藏服务排在前面，常用筛选与项目和运行状态条件共同生效。

### 3. 复用私有现有入口，核对全部连接

私有包装器在无路由文件时按现有应用配置普通启动，继续以准确运行身份隔离本次本机进程与适用临时副作用，并使用适合该启动方式的就绪检查；有路由文件时保留既有任务联调入口。无需修改 Java 路由协议。

私有客户端普通启动只使用统一远程网关基址并保留原请求路径，新请求无须先登记完整后端清单。现有直接地址声明仅供任务本地覆盖；任务实际启动的本地目标才转换对应前缀，其他请求继续使用所选远程网关，独立通道与模拟接口保持。具体业务映射及域名保留在所属工作空间（Workspace）。

配置提示词（Prompt）和服务指引要求先验证普通启动的网关基址与完整路径，再按当前开发任务核对需要本地覆盖的请求；不要求全量长期下游清单，一个探针不代表全部业务验收。私有代码修改在所属真实代码库完成，本产品变更不扩大写入边界。

### 4. 当前知识影响

已核对并校准 `projects/product/knowledge/code-map/technical-layers.md` 的“服务本地运行”：说明单服务远程环境与任务自动本地联调的入口分离、独立代码检出及其真实所属代码模块和界面来源。任务泳道（Lane）仍仅同任务，原有模块依赖方向保持，新来源选择和独立检出链接已补充；维护现有说明，不新建地图（Code Map）或技术图（Technical Diagram）；无术语定义变化。

## Risks / Trade-offs

- [包装器仍要求路由文件] → 在所属代码库验证无文件启动路径、准确进程身份和就绪条件，不以产品按钮放开代替应用可启动。
- [普通启动误进入任务注册] → 验证没有路由文件注入及泳道（Lane）元数据，同时回归原任务组合。
- [网关前缀重复或本地路径错误] → 对每个已核实后端分别验证远程路径保留与本地转换，未覆盖业务请求明确报告。
- [普通 QA 启动被误报为完整业务联通] → 分别报告进程就绪、协议检查、实际请求和未执行项，不伪造 `verifiedAt`。

## Migration Plan

产品和私有包装器分别修改并验证后，用户明确启动时采用普通主工作库路径；已有运行不自动重启，任务路由格式不迁移。客户端只更新已核实的多后端声明与代理转换；现有不明映射保持。退回旧入口时保留文件与运行事实，不改共享 QA。
