# 当前实现审查与改进

审查范围：本任务的知识模块、前端阅读与导航、两个主题的文章和地图、建设指引。依据用户截图、实际网页和当前工作树（Worktree）源码。主要用户是熟悉软件工程但不熟悉当前技术栈的项目负责人，首要任务是理解职责、追溯依据并提出修改；环境为桌面浏览器，支持鼠标和键盘。

结论：后端的职责分层可以保留，重点问题在前端职责集中和缺乏上下文的内容组织。按真实维护边界拆分，不引入形式化的多层转发或全局状态库。

## 优先处理的问题

### [P1] 地图文件树不可点击，职责解释与路径表分离

证据：原地图使用纯文本树，另以长路径表重复文件；截图中职责列被挤成竖排。实际浏览发现公共 Markdown 渲染器不支持嵌套列表，会把子目录压为一个段落。

影响：用户既看不到清楚的组织关系，也无法从树直接追到真实文件。

依据：组块化（Chunking）、接近律（Law of Proximity）。

处理：地图明确范围根，先解释规范、入口、应用、领域规则、数据访问及技术支撑，再以标准嵌套链接组织文件；公共渲染器补齐嵌套列表，复用既有链接安全处理，不发明第二种地图文件格式。技能（Skill）使用名称、标识和职责表。

权衡：只展开主题相关分支，既能定位又避免全量文件树；全景地图继续暂缓。没有数据库或某层时如实说明。

验证：嵌套父子关系、有序与任务列表、危险链接和脚本转义回归；真实页面点击文件、规范与技能详情。

### [P1] 阅读页面集中处理目录、正文、引用与请求

证据：原 `KnowledgePage.tsx` 内部同时实现 Markdown 分段、递归成果展示、目录、来源读取与副屏状态；来源请求只使用局部序号，跨范围继续阅读的取消责任不统一。

影响：新增一个视图会同时修改不相干的职责，迟到请求和上下文错误更难定位。

处理：页面保留导航和范围编排；`KnowledgeCatalog` 负责分类检索，`KnowledgeArtifactReader` 统一内嵌及独立阅读，`useKnowledgeReading` 负责绑定范围的请求状态与取消，纯筛选和指令构造独立验证。切换主题清除旧来源选择；保留原生浏览历史与查询条件。

权衡：只提取真实稳定职责，未为每个按钮建立状态层或接口层；使用函数与类型表达职责，不强制改成类。

验证：类型构建、筛选与身份回归；页面快速切换、关闭副屏和切换项目后恢复。

### [P2] 新标签打断项目层级，三类目录缺少一致入口

证据：原项目详情与“项目 · 知识”重复主标签，技术图列表与文章入口不同，缺少统一检索。

影响：用户需要记住多个页面的关系；找内容与阅读内容混在一起。

依据：认知负荷（Cognitive Load）、相似律（Law of Similarity）。

处理：项目详情与知识复用同一项目标签，面包屑表达进入层级；三个分类使用相同检索和列表，并统一进入主屏详情；正文引用才在副屏对照，切换正文保留已有阅读。项目入口使用完整可点击区域与清晰动作。

权衡：默认不同时打开两个独立项目主标签；并排对照由副屏承担。检索针对当前索引的标题、说明和路径，不宣称全文或跨项目搜索。

验证：旧标签恢复去重、切换后恢复检索、项目返回、三个分类空结果和清除条件、技术图独立建设。

### [P2] 页面默认重复铺开所有来源

证据：文章及地图已链接技能和代码，页尾再次展开完整“依据与建设方法”，每行重复“来源内容一致”。

影响：阅读结束后仍需面对没有职责上下文的长清单；一致标签容易被误解为新一轮语义验证。

依据：组块化（Chunking）、认知负荷（Cognitive Load）。

处理：规范、方法和代码解释就近呈现；取消独立“来源核对”栏目，变化、缺失或不可读就近关联具体文件。

权衡：观察信息保留在读取结果与接续上下文，正常阅读不承担维护清单；不能为了简洁隐藏真实异常。

验证：正常状态下没有重复长表；来源异常仍提示且能逐项追溯。

### [P2] 图示正文重复传输

证据：原 HTTP JSON 响应包含图示 HTML 和图源正文，页面随后通过隔离地址再次加载图示。

影响：同一大文件重复传输，调用方收到并不使用的可执行正文。

处理：协议输出保留身份、摘要、状态与诊断，剔除图示和图源正文；原隔离图示端点继续读取并校验版本。

权衡：此处只消除重复响应；当前仍按已声明来源读取摘要，不承诺后台索引或增量语义分析。

验证：真实 HTTP 回归断言 JSON 不带图示正文，独立图仍可读，陈旧版本仍拒绝，沙箱策略不变。

## 保留与后续边界

- 保留领域模型（Domain）、应用服务（Application）、基础设施（Infrastructure）、接口（Interface）与模块装配的现有职责。知识文件是唯一正文，读取不会成为第二个写入者；函数工厂与依赖传入已能表达协作，无须仅为设计模式增加转发层。
- 当前索引限制在局部范围，单类最多 500 项，目录检索可由已有元数据完成。数据库可在实际出现跨项目检索、规模或延迟证据后再评估；届时应是可重建检索数据，不替代文件权威。
- `code-architecture` 指导真实结构，`code-map` 指导解释与文件定位，`current-knowledge-maintenance` 组织整体成果与同步。术语职责继续由原能力承担，未新增契约或必需依赖。
- 构建告警提示现有 Ant Design 公共块体积超过建议阈值；本轮没有引入依赖，页面行为不因此失败。是否拆分公共包需要基于加载测量另行权衡，不借当前阅读改进扩大为全站构建重构。
- 原生渲染器仍是当前产品支持的 Markdown 子集，本轮补齐实际需要的嵌套列表，不宣称完整 CommonMark。真实人的理解程度与产品满意度仍由用户试用判断。


## 后续试用修订：事实导航与完整图示

依据相似律（Law of Similarity）和工作记忆（Working Memory），三个列表统一进入主屏详情；只把正文关联放到副屏，并按明确身份保留多项阅读。修复导航状态缺省时清空资源副屏的行为，多个文件和原技能详情都能随正文切换保留，接续时包含实际已观察版本。

地图纳入规范和真实实现，成果目录列出实际文件。普通 Markdown 的加粗目录表示作者选定的业务展开边界，独立树组件提供紧凑行距、目录与引导线折叠、键盘操作；不按技术栈硬编码目录名称。文件通过可选 `summary` 展示经核实的总体说明；成果通过可选 `files` 声明图源、展示与依据等相关文件，与事实 `sources` 区分。

独立图示原先被统一设为 embed 模式，现仅文内预览使用；独立详情使用原生成 HTML，放大阅读只扩大容器，不复制内部控件。图示专用响应保留原内容并允许本地导出，原型策略保持；不开放同源、外部连接或顶层导航。实际验证原生主题及 SVG 生成，下载落盘未取得回执，未将数据生成当作文件保存成功。

同时修复来源范围比较仅看标识、不比较类别的问题：不同类别即使恰好标识相同，仍需检查项目与服务的真实关联。对应反例验证拒绝未关联服务的读取。


## 阅读细节与维护闭环核查

### 阅读改进

原图示容器最大 980 像素，独立图内容结束后仍有额外高度。当前改为 520–800 像素的随窗口高度变化的阅读区域，长图沿用原生滚动及放大阅读；1600×1100 窗口实测 792 像素，相比原规则 935 像素减少 143 像素。未改写 Archify 生成文件或隔离策略，也不承诺跨隔离文档的自动内容高度。

“建设方法”从散落链接改成名称与职责的统一列表，按技能（Skill）身份归并；同一技能的参考文件进入详情查找。实际 556 像素分屏中显示六项方法，无横向溢出。共用 `SkillHome` 默认加载 `SKILL.md`，其他文件折叠并可检索；在 Archify 的 76 个参考文件中实际检索和打开 `viewer-runtime.md`，返回正文后切换当前知识维护也读取正确内容。

### 两条维护路径

| 路径 | 当前落实与本轮修正 | 证据与限制 |
|---|---|---|
| 普通开发修改事实 | `task-triage` 初判与最终复核、`code-architecture` 职责变化交接、OpenSpec 原有 `reconcile` 均交给当前知识维护；本轮补清主动告知受影响成果、校准建议与授权判断 | 阅读调用方及 v3 约定，静态走查已有授权、未授权、无影响与冲突；未用文本检查声称任何智能体必然提醒 |
| 用户主动建设或维护主题 | 网页保留主题、范围、事实观察，指令以真实文章及必要关联为交付；新增整组关联检查要求。直接请求覆盖该主题范围内必要建设，既有授权不重复确认 | 本轮实际生成完善指令，核对整组维护、范围外决定与未执行说明；前轮真实第二主题建设和受控维护证据仍适用 |
| 阅读期间发现源文件变化 | 已登记文件在打开或刷新时比较观察，逐项提示变化、缺失和不可读，阅读不写回 | 后端实现及原增改删零写入回归保持不变；没有持续监听、任意文件影响自动推断或后台智能体调度 |

结论：已支持当前阶段“用户引导建设、授权后整体维护、开发中按方法判断和提醒”。这是一套由智能体（Agent）执行的方法加上确定性阅读能力，不是保证任意事实变化都会自动唤醒和修复的守护系统。提醒未授权时保留现有知识及观察；授权后核对真实含义再更新，不能只刷新摘要消除提示。

三类成果的专业方法、v3 协作和局部失败边界保留。普通开发可继续无关工作，用户不必逐文件决定；本轮未增加数据库、审批队列、调度服务或新契约版本。
