## Purpose

提供面向智能体（Agent）的独立代码地图（Code Map）建设方法，将已确认的代码架构原则与真实实现组织映射到用户可阅读的职责、目录和文件，并支持按实际变化维护、核验来源与说明未覆盖范围。

## ADDED Requirements

### Requirement: 代码地图必须表达实际职责到文件的组织
Buildr MUST 提供独立 `code-map` 技能（Skill），按目标范围建设项目、服务、业务模块及文件之间的实现映射；MUST 结合语言、框架和已确认约束解释模块分层与依赖，不机械要求前后端采用相同目录。地图 MUST 区分当前实现、推荐结构与尚未确认的职责。

#### Scenario: 建设后端与前端地图
- **WHEN** 已授权范围包含后端服务与前端服务
- **THEN** 地图分别表达各自职责组织及真实目录文件，公共能力只有在实际存在时才显示
- **AND** 本轮独立导航止于文件，不要求用户阅读方法索引或源码正文才能理解职责

#### Scenario: 架构要求与代码存在差异
- **WHEN** 已确认架构要求与当前文件组织不一致
- **THEN** 地图分别展示实际结构和差异，不把建议结构冒充当前实现或擅自修改代码

### Requirement: 专业制作必须核对来源并局部维护
`code-map` MUST 支持明确范围的建设、更新和检查，核对路径存在、职责及必要依赖语义，并返回实际成果、来源、检查和未覆盖范围；MUST NOT 以目录扫描结果代替全部职责判断。

#### Scenario: 文件移动但职责保持不变
- **WHEN** 当前范围的文件路径改变且职责关系未变
- **THEN** 仅更新相关定位和引用，保留仍适用的职责说明和技术图（Technical Diagram）

#### Scenario: 来源已删除或无法核实
- **WHEN** 地图来源不再存在或职责无法确认
- **THEN** 检查明确指出相关项及影响，不补造文件、职责或已验证结论


### Requirement: 地图必须把规范与实现组织连成可读解释
`code-map` MUST 说明范围根和必要祖先目录，以原生链接组织到文件层的职责树；MUST 解释规范约束、实际存在的协议入口、应用用例、领域规则、数据访问和基础设施怎样协作。未实现的层或入口 MUST 如实说明，不为套分层而补造。技能（Skill）以面向人的名称、标识与职责呈现，具体文件路径放在按需查看的来源中。

#### Scenario: 含工作方法的能力地图
- **WHEN** 同一能力包含智能体指导方法与运行时代码
- **THEN** 分别呈现工作方法协作和程序调用，将规范依据与实现职责就近组织，文件树可直接进入真实文件


### Requirement: 地图必须区分事实来源和成果文件
`code-map` MUST 将相关规范、实现及必要配置组织为有解释的事实来源导航，另列当前架构文章、地图、图源、展示及依据文件。MUST 标明默认展开的业务目录与文件职责，文件说明应来自实际核对，不将解释成果冒充代码或规范事实。

#### Scenario: 制作完整主题地图
- **WHEN** 用户需要理解一个跨前后端的架构主题
- **THEN** 地图列出规范及前后端业务目录，默认显示到业务范围，展开后能到文件；成果目录列出真实文件而非只列空目录
