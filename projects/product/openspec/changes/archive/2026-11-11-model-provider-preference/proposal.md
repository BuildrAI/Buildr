## Why

模型来源只能在模型级别逐个停用，无法整体隐藏一个供应商；用户停用后，该来源仍占据“账号来源”和会话模型选择器。切换智能体时，选择器又会回落到官方默认模型，覆盖用户刚选过的模型。与此同时，对话信息流中的本地文件链接无法正常解析打开，DSH 在 500K 模型上约 41K Token 就反复触发上下文压缩，三者都直接破坏日常对话体验。

## What Changes

- 新增账号来源级停用状态，与账号“已断开／未登录”严格分离。停用保留凭证、登录尝试、历史对话、租约与模型偏好，但来源不再出现在默认账号列表、模型目录和会话模型选择器中，也不参与新租约。
- 账号来源管理提供“停用来源”和“显示已停用／重新启用”的明确入口；已停用来源仍可按需读取，已选模型失效时给出局部说明与重新选择入口。
- 会话模型偏好由全局单值改为按智能体（`connectionId`）记忆；切换智能体恢复该智能体上次明确使用的模型、档位与推理强度，不使用官方默认模型替代有效记忆，记忆失效时留空提示选择。
- `file://` 本地 Markdown 链接只在 Buildr 已有来源访问边界内解析和打开，不能把任意本机路径暴露给对话内容；不可安全访问时显示可理解、可复制的局部提示。
- DSH 容量修复由 conversation-rendering-compaction 负责，停止把模型最大输出能力当作默认请求输出上限。

非破坏性变更；既有账号、对话、租约与模型偏好保持可读，新增状态和接口字段向后兼容。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `model-usage-controls`：新增来源级停用、默认隐藏、可恢复读取与重新启用的语义。
- `independent-agent-model-setup`：以按智能体记忆替代官方模型优先回落，并明确来源停用后的选择与失效提示。
- `agent-conversations`：模型记忆改为按智能体保存；本地文件链接按 Markdown 目的地安全解析；原生压缩触发保留可用预算。

## Impact

涉及 `buildr-agent` 模型账号持久化、视图、目录与租约，`buildr` 模型账号 HTTP 契约与路由，`buildr-web` 账号来源管理、模型选择器与会话偏好存储，以及 DSH 网关模型声明和对话 Markdown 渲染。需要为存储迁移、旧偏好迁移、停用来源的显式读取和压缩阈值计算补充测试。
