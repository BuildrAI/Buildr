## Context

动机见 proposal.md。现有 `useSourceControl` 只首次读取及接收当前页面内部操作通知，页面保留挂载不构成重读；已有单库读取和按库拒绝旧响应。每次读取无条件提高版本会连带重读历史、正文及提交上下文。后端读取经有界工作线程（Worker）运行，不能由长轮询占用或在 HTTP 主线程重复同步执行 Git。

## Goals / Non-Goals

实现当前工作空间（Workspace）按变化自动跟进，保留阅读与输入，并控制多库开销。不添加依赖、操作系统守护进程、自动远程获取或新的写入能力。

## Decisions

- 后端共用按工作空间（Workspace）管理的文件观察服务。真实工作目录及 Git 管理目录通过既有身份发现，变化只表示来源失效，再由现有读取获得真实状态。连续事件短合并且设最大等待；同库单飞，在途新事件保留一次后续核对，避免取消饥饿。重复订阅共用观察；闲置和服务退出释放资源。监听失败返回诊断，前端低频核对弥补漏事件。排除纯 Git 对象写入等无关高频噪声，不能简单忽略全部被忽略目录而漏掉跟踪文件。
- 新增独立 HTTP 长轮询（Long Polling）`GET /api/v1/workspaces/:workspaceId/code/source-control-watch?cursor=...`，返回 `{cursor, repositoryIds, refreshAll}`，可选 `refsRepositoryIds` 区分引用变化及必要诊断；首次、服务重启或过期游标（Cursor）要求重建观察。稳定等待有界且可取消，不占代码读取工作线程（Worker）。使用现有认证和工作空间（Workspace）身份边界。
- 前端功能内共享默认目录观察，由应用层装配到导航和页面。自动核对合并同库请求并限制并发，真正变化才提高受影响版本；显式刷新保留强制重读语义。任务范围的选择独立保存，但消费同一失效来源。隐藏页面不读取不需要的历史和正文，恢复前台或页面激活补查。
- 导航小圆点表示已观察到存在未提交改动；文件树使用同一来源的状态及祖先变化提示。刷新静默保留数据，失败显示旧观察诊断。固定历史不随当前 HEAD 自动清空；文件退出未提交列表时保留原身份，可核对的已打开当前文件继续沿用共享编辑及撤销（Undo），其他阅读对象原位说明。大文件保留已打开片段及其版本，继续读取时仍校验版本。分支（Branch）切换的成功响应立即更新已确认事实，后续观察不能用旧改动冒充新分支状态。
- 两入口首次优先 `isRegistered`／`source.checkoutId` 对应的工作空间登记目录，`isMain` 只表达真实 Git 主工作树（Worktree）。保留 `groupId: main` 协议值，来源主标签直接显示真实工作树（Worktree）名称；登记、任务角色和分支（Branch）作为辅助信息。多代码库名称集合按已选范围计算，不拿首个目录代表整个组；同名不同路径明确消歧。
- 当前来源选择与事实观察分开：现有工作空间（Workspace）提供器装配轻量共享选择，仅保存递增意图序号和 `{repositoryId, checkoutId}` 身份集合及首选来源，不保存文件正文、草稿或历史。明确的用户筛选、来源选择或本次文件／任务入口才发布选择；默认初始化、自动观察及被动接收不发布。新显式入口优先，普通导航在页面激活时接收尚未应用的选择；同身份不调用重置阅读的路径，失效身份不按名称或路径替换。
- 资源管理器接收来源只调整目录范围，保留已开文件、历史页签和编辑会话（Session），范围外正文沿用已有提示并显示自身真实来源。源代码管理保存各来源的文件、固定历史、搜索、全文片段及阅读滚动，返回原来源时恢复；提交说明继续按已有来源键隔离保存。圆点悬停及辅助说明明确“当前工作空间有未提交变更，包含其他代码库或工作树”，切换来源或打开页面不清除。
- 新历史文件入口仅在检出身份明确时发布一次来源选择；只有固定提交（Commit）的历史版本独立保留自身阅读，不推断成任务工作树（Worktree）。普通历史页签激活不重放入口或发布当前来源。
- 刷新中不创建空错误槽，真实局部失败在成功确认前保留。前端过滤空诊断，分别表达自动更新、状态读取、来源关联、搜索及目录读取的影响，原位展开具体原因；HTTP 成功但局部状态受限的诊断也按真实代码库及目录显示，重试只核对受影响代码库。状态或关联诊断不能冒充文件内容不可读，目录失败显示真实来源和绝对路径。圆点仍只表达全域未提交变更，不随刷新或阅读改变含义。
- 同一工作树（Worktree）的观察版本变化可重新核对当前差异；已有差异数据时保留正文并静默更新，首次打开才展示读取提示。同一文件的外部正文替换也保留当前滚动位置及有效选区，显式定位继续按用户意图执行。忽略输出的过滤深入已跟踪祖先的非跟踪子目录，避免本机数据库临时文件造成自触发读取，同时保留已跟踪资产的真实更新。

## Risks / Trade-offs

- 大目录事件风暴 → 合并、限流、只重读受影响来源；低频补偿不与事件重复派发。不能把每个事件转换为全目录读取。常见输出目录在任意深度按 Git 忽略规则有界核对及短期缓存，索引（Index）已跟踪的文件及祖先不被过滤。资源树的同路径内容保存只更新正文及装饰；新增、删除、重命名及恢复只核对变化路径的已加载祖先，分支（Branch）、身份或不完整观察变化时保守核对该来源。
- 工作树（Worktree）的 `.git` 为文件、共用引用及原子保存 → 复用实际 Git 管理目录身份及目录监听，不猜 `.git` 布局；监听失效重新发现。
- 漏事件或平台资源限制 → 恢复前台、重连、低频兜底；如实保留诊断，不承诺任何规模都固定 1 秒完成。
- 旧请求覆盖与范围切换 → 保留按来源序列及取消机制，跨工作空间（Workspace）响应不采用。
- 自动更新打断阅读或频繁禁用提交 → 语义版本去重，保持组件身份、草稿及选择；真实提交前仍校验已观察版本。

## Migration Plan

无持久数据迁移。新后端接口与前端同包交付，观察服务生命周期随本机应用；回退源码与构建即可恢复既有手动读取。开发验收使用独立预览，收尾交付后由自举更新的唯一执行器处理适用开发应用更新；不包含正式发布。

收尾集成主线 `4176605ce` 的逐库渐进刷新。共享观察装配复用其轻量登记及每批最多两个逐库请求，将进度完整传入目录合并；全量批次与局部补查分别有界调度，同范围同库局部请求合并，实际 Git 读取仍复用宿主的两个工作线程（Worker），避免两个初始化批次占满局部补查配额。首次任务选择等待真实范围完成，不以是否显示加载提示判断就绪。登记等待不作为失败，默认来源按登记顺序、库内登记检出身份共同确定。成功且完整的轻量登记仅按代码库身份释放已注销监听，不用尚未读取的空工作树替换已确认监听；在途读取持有同一观察生命周期的票据，注销后的旧响应不能重建监听，观察容量或关闭不阻止权威读取。局部读取仍保持局部边界。
