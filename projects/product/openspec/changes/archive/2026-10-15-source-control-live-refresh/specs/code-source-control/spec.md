## ADDED Requirements

### Requirement: 文件变化驱动共享自动观察

本机应用 MUST 在当前工作空间（Workspace）被使用期间持续感知已登记来源的文件及 Git 元数据变化，包括外部编辑、原子保存、暂存、提交及分支（Branch）变化。系统 MUST 合并连续变化并限制最大等待，同一来源读取期间的新变化 MUST 至少触发一次后续核对且不得无限取消在途读取，按受影响代码库（Repository）局部重新核对真实状态；多个页面 MUST 共享观察，MUST NOT 为导航或每次文件保存重复扫描全部来源。无实际内容变化的自动观察 MUST NOT 反复失效历史、正文或提交上下文。恢复前台、重新进入或观察连接恢复 MUST 补充核对，监听失败或漏事件 MUST 有低频补偿及可辨认诊断。观察 MUST 不获取远程或执行 Git 写入。

#### Scenario: 外部编辑与多库隔离
- **WHEN** 用户停在资源管理器或其他页面，智能体（Agent）连续修改一个代码库（Repository）的文件
- **THEN** 合并变化后自动更新该来源，其他来源不因每次保存被重读，导航提示与文件标记反映相同观察

#### Scenario: 已修改文件再次保存与 Git 操作
- **WHEN** 已有改动的文件再次保存，或外部工具执行暂存、提交、切换分支（Branch）
- **THEN** 即使文件数量不变，相关内容及状态仍自动更新

#### Scenario: 已跟踪目录内的本机忽略数据变化
- **WHEN** 某目录包含已跟踪资产，而其被忽略的本机数据子目录产生连续临时文件变化
- **THEN** 被忽略数据不触发重复状态核对，同目录内已跟踪资产的真实变化仍被感知

#### Scenario: 恢复连接及局部失败
- **WHEN** 页面休眠后恢复、服务重连或一个来源不可读
- **THEN** 系统补查当前事实，失败来源保留最后结果并说明待更新，其他来源继续更新，未知不可表示为干净

### Requirement: 自动更新保持阅读和输入

自动观察 MUST 原位更新数据，保留仍适用的来源、工作树（Worktree）、文件选择、展开、筛选、滚动及输入中的提交说明；MUST NOT 清空页面、跳回顶部或弹出常规成功通知。所选历史提交（Commit）MUST 按固定身份保持，新提交进入列表不能切走阅读；所选改动退出列表时 MUST 保留原文件身份，不默认替换为其他文件。已打开且来源仍可核对的可编辑当前文件 MUST 继续保留共享正文、输入、撤销（Undo）与阅读状态；真实文件删除或来源不可确认时 MUST 原位说明并保留输入。手动刷新 MUST 仍可立即核对。

#### Scenario: 阅读及输入期间有外部变化
- **WHEN** 用户正在阅读差异（Diff）、输入提交说明或阅读固定历史，外部工具保存或提交文件
- **THEN** 相关状态更新，输入与阅读位置保持，固定历史不切走

#### Scenario: 已有差异的后台核对
- **WHEN** 当前差异已读取且同一工作树（Worktree）发生变化
- **THEN** 后台核对保留当前正文且不反复展示首次读取提示；同一文件正文更新后保留有效选区和阅读位置

#### Scenario: 所选文件退出改动列表
- **WHEN** 用户选中的文件被外部恢复或提交，已不在未提交列表中
- **THEN** 其他文件不被自动选中；可核对的已打开当前文件继续编辑和撤销（Undo），按最新可确认的比较表达变化；其他阅读对象原位说明已无未提交改动

### Requirement: 跨代码入口显示一致变化提示

源代码管理入口 MUST 以小圆点表达当前观察到存在未提交改动，含义不随已读而消失；资源管理器当前文件视图 MUST 显示修改、新增等真实状态及祖先目录的变化提示。状态 MUST 按代码库（Repository）、工作树（Worktree）和路径匹配，历史文件视图 MUST 不套用当前状态。读取不完整或失败 MUST 不伪装成完整无改动。

圆点的悬停及辅助说明 MUST 明确聚合当前工作空间（Workspace）内代码库（Repository）和工作树（Worktree）的未提交改动；当前来源干净不代表整个工作空间（Workspace）干净，打开页面或切换来源 MUST NOT 清除圆点。

#### Scenario: 未打开源代码管理也能感知
- **WHEN** 用户尚未打开源代码管理，在外部保存已登记来源中的文件
- **THEN** 导航入口及当前资源树自动出现变化提示，打开源代码管理后能看到同一来源的实际状态

### Requirement: 两入口对齐当前来源且保留阅读

资源管理器和源代码管理 MUST 使用代码库（Repository）和检出身份对齐当前工作树（Worktree），首次优先工作空间登记目录。界面 MUST 明确区分工作空间登记目录与真实 Git 主工作树（Worktree），MUST NOT 将两者使用同一含糊来源提示。明确的用户来源选择或文件／任务入口 MUST 能被另一入口发现；自动观察、默认初始化及被动接收 MUST NOT 抢占选择。新的显式入口优先且只应用一次，失效来源 MUST 保留原身份并显示不可用，MUST NOT 按名称或路径替换。

普通跨入口往返且来源未变时 MUST 保留文件、固定历史、搜索、展开、滚动和输入；显式切换来源时 MUST NOT 将原正文或草稿标为新来源，原来源的输入和阅读现场 MUST 可在返回时接续。

新历史文件入口只有在明确检出身份时才对齐当前来源；仅有固定提交（Commit）的历史版本 MUST 保留自身阅读来源，MUST NOT 推断为任务工作树（Worktree）。普通历史页签激活 MUST NOT 重放入口或改变当前来源。

来源主标签 MUST 显示真实工作树（Worktree）名称，角色与分支（Branch）作为辅助信息；多库聚合 MUST 表达真实名称集合及范围，不以首个目录冒称全组。刷新中的空错误 MUST NOT 产生警告；真实诊断 MUST 按自动更新、状态、来源、搜索或目录的实际影响表达，并可原位展开具体原因和可确认的路径，MUST NOT 将状态更新失败冒充文件内容不可读。

#### Scenario: 登记目录与 Git 主树不同
- **WHEN** 工作空间登记目录是独立工作树（Worktree），真实 Git 主工作树（Worktree）位于另一目录
- **THEN** 两入口首次选择登记目录的同一检出身份，并以分支（Branch）和路径清楚提示来源

#### Scenario: 双向显式选择与自动观察
- **WHEN** 用户在任一入口明确选择另一工作树（Worktree），然后进入另一入口，期间文件变化触发自动观察
- **THEN** 当前来源按真实身份对齐，自动观察不重置选择，同身份返回不重置阅读或输入

#### Scenario: 显式入口及失效来源
- **WHEN** 新的任务或文件入口指向另一真实来源，或当前来源消失
- **THEN** 新的明确入口优先且只应用一次；失效来源保持原身份的不可用状态，已有正文和输入不被标为其他来源
