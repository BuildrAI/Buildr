## Why

文件保存或外部工具写入后，当前代码状态依赖手动刷新，保留挂载的页面返回时也可能停在旧观察。用户已确认按文件变化自动更新，并要求多代码库（Repository）下避免重复读取、保留阅读与输入。

验收发现两个入口的默认来源不一致：资源管理器的“主目录”实际是工作空间登记目录，源代码管理却默认 Git 主工作树（Worktree）。登记目录属于独立工作树（Worktree）时，编辑和查看改动会落在不同位置，用户容易误判自动更新失效。

## What Changes

- 由当前工作空间（Workspace）共享文件与 Git 元数据变化感知，合并连续变化并按受影响代码库（Repository）局部重新观察；恢复前台和重连时补查。
- “源代码管理”、导航入口与“资源管理器”共享当前结果，自动更新文件标记、目录提示和有改动提示。
- 自动更新保持阅读位置、固定历史选择及提交说明；读取失败保留上次结果并显示过期诊断。
- 两入口以真实代码库（Repository）和检出身份共享当前来源，首次默认工作空间登记目录；来源提示区分登记目录和 Git 主工作树（Worktree），圆点说明整个工作空间（Workspace）的改动范围。自动观察不改变用户的来源选择，跨入口往返保留阅读和输入。
- 无破坏性变更，不增加依赖、常驻守护进程或自动远程操作。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `code-source-control`：补充变化驱动的共享自动观察、多库性能、跨入口提示及阅读保持承诺。

## Impact

影响 `buildr` 的代码模块（Module）和本机 HTTP 生命周期、新增有界长轮询读取；影响 `buildr-web` 的代码状态观察、导航、文件树和阅读状态。复用现有 Git 身份及局部状态读取，不改变提交、同步或获取远程的授权。
