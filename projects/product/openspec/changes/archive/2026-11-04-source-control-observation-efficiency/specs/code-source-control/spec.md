## ADDED Requirements

### Requirement: 有界共享观察核对频率

共享代码状态观察 MUST 优先由真实来源变化驱动局部核对。健康、可见且没有新变化时，默认全库安全补偿 MUST 以最近一次完整核对完成为起点，每五分钟执行一次。仅窗口聚焦或保留页面激活、且页面未经历隐藏时，MAY 复用 30 秒内已完整核对的结果，MUST NOT 因同一段可见期内的重复聚焦反复扫描全部来源。持久缓存、仅登记清单、未完成或请求失败的读取 MUST NOT 被当作新的完整核对。

显式刷新、真实文件或 Git 变化、页面从隐藏恢复以及观察连接恢复 MUST 不受上述短期复用限制；读取中的新变化仍 MUST 保留一次后续核对。监听存在诊断时，默认补偿间隔 MUST 至多 30 秒，MUST 保留真实诊断及最后可核对结果。上述自动观察 MUST NOT 执行远程获取或 Git 写入。

#### Scenario: 无变化的可见页面
- **WHEN** 全库刚完成核对，健康监听下没有来源变化
- **THEN** 两分钟时不再安排一批全库读取，五分钟边界仍安排安全补偿
- **AND** 其间完成的新全库核对从完成时重新计算补偿边界

#### Scenario: 重复聚焦与保留页面激活
- **WHEN** 页面连续可见，完整核对完成不到 30 秒，窗口反复聚焦或保留页面重新激活
- **THEN** 共享观察复用该次真实结果，不额外扫描全部来源

#### Scenario: 手动读取及真实变化
- **WHEN** 用户显式刷新，或真实文件及 Git 元数据发生变化
- **THEN** 即使仍处于短期复用窗口，也执行对应真实核对；局部变化不升级为全库扫描

#### Scenario: 隐藏或连接中断后恢复
- **WHEN** 页面曾隐藏或观察连接中断，随后恢复
- **THEN** 补查不被最近核对时间跳过，仍保留阅读现场与未知事实

#### Scenario: 监听失效与不完整读取
- **WHEN** 存在监听诊断，或当前读取中止、失败、截断、仅有缓存或登记清单
- **THEN** 不伪装成新完整核对；监听诊断保持至多 30 秒补偿
