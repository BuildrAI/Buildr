## Context

实测服务页空闲时每两分钟产生 26 次逐库 Git 查询。对话执行期间同类查询约 250 毫秒，最慢接近一秒；此外活动摘要存在独立的瞬时延迟，本变更不把减少 Git 请求解释为该延迟已消失。相关代码集中在共享观察器，HTTP、数据存储和真实来源监听无需变更。参见 [任务说明](@task/web-agent-restart)。

## Goals / Non-Goals

降低连续可见页面中没有新变化的重复全库读取，同时保持显式、事件和恢复边界。保留现有最近读取时间与失败/缓存表达；不新增全局状态库或控制 Agent 执行，不减少 Git 身份校验。

## Decisions

1. 仅成功、未截断且非缓存的完整默认目录核对更新本观察器的完成时间；部分库更新不证明全库已核对。
2. 连续可见期间，30 秒内的聚焦/保留视图激活复用已核对结果。中止、真实变化、显式刷新和恢复路径沿原有调度，避免用统一限流吞掉变化。仅增加 debounce 无法阻止相隔数秒的重复全库读取，故采用完成时间判断。
3. 健康全库补偿设为五分钟，并从完成时间重新计时。监听有诊断仍至多 30 秒补偿。相比完全取消补偿，该做法保留漏事件恢复；相比持续两分钟全扫，减少约六成周期性逐库查询。

## Risks / Trade-offs

健康监听静默丢事件时，纯安全补偿最迟可到五分钟；真实变化通常立即走原生通知，显式读取、隐藏恢复和重连仍立即补查。失败或仅缓存的读取不能延长“新鲜”窗口，且界面继续显示实际读取时间。作用域、身份和并发边界沿原实现，不能以减少请求掩盖来源错误。

## Migration Plan

无数据迁移或新依赖。先验证共享观察单元与生产浏览器，再通过既有开发版采用入口更新前端；当前执行服务和用户对话不作为可任意停止的资源。旧客户端继续按旧策略，不涉及 API 兼容破坏。
