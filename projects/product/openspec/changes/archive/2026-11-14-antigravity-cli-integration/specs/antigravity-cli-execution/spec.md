## Purpose

定义 Buildr 接入 Google 官方 Antigravity CLI（`agy`）与 Google 个人账号（免费、Google AI Pro、Ultra）的行为，使用户在 Buildr 中准备独立程序、使用官方登录、选择账号可用模型，并获得与其他原生执行方一致的交互、控制与恢复能力，同时保持账号凭据只由官方客户端使用、旧对话不在其他账号下执行的边界。

## ADDED Requirements

### Requirement: Antigravity 程序必须由 Buildr 独立准备且版本受控

系统 MUST 通过官方发布清单为 Antigravity 准备 Buildr 独立受管的 `agy` 程序，准入主版本为 `1.x.x`，MUST NOT 绑定或接管用户自行安装的 `agy`。系统 MUST 在该连接的私有配置中关闭 `agy` 自动更新，并 MUST NOT 执行官方安装脚本中修改用户 shell 或环境路径的步骤。程序版本只能通过 Buildr 的显式检查与更新动作改变；受管程序在使用中被外部改变时 MUST 按程序身份变化处理，不得继续视为原绑定。

#### Scenario: 首次准备
- **WHEN** 用户在智能体页对 Antigravity 执行准备
- **THEN** 系统 MUST 从官方清单下载并校验当前平台的最新 `agy`，写入受管目录并完成协议握手检查
- **AND** 用户主目录下的 `agy` 设置、shell 配置与已安装程序 MUST 保持不变

#### Scenario: 运行后程序未自更新
- **WHEN** Buildr 使用受管 `agy` 完成多轮执行
- **THEN** 受管程序文件身份 MUST 保持不变，新版本只在用户执行 Buildr 程序更新后生效

### Requirement: Antigravity 执行必须使用官方 ACP 并保留原生执行责任

系统 MUST 通过 `agy acp` 标准输入输出协议执行 Antigravity，模型调用、工具选择、工具执行与会话保存 MUST 由 `agy` 原生负责；系统 MUST NOT 用模型接口或其他执行方替代。每个会话 MUST 使用对话保存的准确工作目录。执行方 MUST 声明只接受 Google 个人账号来源并按账号身份原生直通，选择其他来源 MUST 在副作用前拒绝。

#### Scenario: 选择其他供应商模型
- **WHEN** 用户为 Antigravity 选择非 Google 个人账号来源的模型并发送
- **THEN** 系统 MUST 在工作输入前拒绝并说明 Antigravity 只使用 Google 个人账号模型，保留草稿

### Requirement: Antigravity 进程必须按对话隔离

每段对话 MUST 使用自己拥有的 `agy` 进程与进程组，同一对话 MAY 在配置相同且无未结工作时复用；不同对话 MUST NOT 共享进程。停止、取消超时后的强制终止与资源回收 MUST 只作用于本对话的进程组，MUST NOT 中断其他对话。完全访问 MUST 映射为原生免逐次审批设置；若该设置只能在进程启动时确定，权限模式变化 MUST 重建本对话进程，恢复旧会话 MUST NOT 继承上一轮的免审批状态。

#### Scenario: 两段对话并发时停止其中一段
- **WHEN** 两段对话同时运行 Antigravity，用户停止其中一段且取消超时
- **THEN** 系统 MUST 只终止该对话的进程组，另一段对话 MUST 继续运行且状态不受影响

#### Scenario: 完全访问往返切换
- **WHEN** 同一对话先以完全访问执行一轮，再切回默认权限并发送
- **THEN** 新一轮 MUST 在默认权限下运行，工具请求 MUST 重新要求审批，MUST NOT 沿用上一轮免审批

### Requirement: Antigravity 必须注入当前交互政策并如实处理政策变化

系统 MUST 通过官方追加系统提示能力，把当前 Buildr 交互政策与进展语言要求注入新建的原生会话，使智能体在工具执行前输出简短说明；不支持该能力时 MUST 如实诊断而非静默省略。恢复会话时，若原生支持更新追加提示，系统 MUST 应用当前政策；若不支持且会话创建时的政策版本与当前版本不同，系统 MUST 保留旧历史并开启新的原生会话，在发送前明确提示“本轮将开启新的 Antigravity 会话”，MUST NOT 把这次发送呈现为原生会话已恢复。政策未变化时 MUST 正常恢复原会话。

#### Scenario: 新建会话
- **WHEN** Buildr 为 Antigravity 新建原生会话
- **THEN** 会话 MUST 带有当前 Buildr 交互政策与进展语言要求

#### Scenario: 政策变化后恢复且原生不能更新提示
- **WHEN** 交互政策已升级，用户在旧 Antigravity 对话中继续发送，而原生恢复不能更新追加提示
- **THEN** 系统 MUST 提示本轮将开启新的 Antigravity 会话，旧历史保持可查看，新会话 MUST 带有当前政策

### Requirement: Antigravity 过程输出必须保持顺序、分段与准确状态

系统 MUST 把 `agy` 的正文片段、思考片段、工具调用、工具更新、计划与最终正文映射为统一对话条目：连续正文累积为同一段，遇到工具、思考或原生消息身份变化时结束当前段并开启新段，使工具执行之间的说明作为独立过程条目显示；思考 MUST 单独保存且不混入正文。工具条目 MUST 保留原生工具身份、名称、输入、位置与结果，按原生类型映射为命令、读取、编辑、搜索、网页读取等统一工具类别；仅含状态的更新 MUST 保留先前已知名称与输入；失败 MUST 保持失败。高频片段 MUST 合并发布且不得丢失或乱序。正常结束时 MUST 先结算已接收正文与工具再报告完成；原生仍在后台继续工作时 MUST 保持运行；正文结束 MUST NOT 被当作工具成功的证明。

#### Scenario: 工具前后都有说明
- **WHEN** `agy` 依次输出说明、工具调用及结果、再一段说明、第二个工具、最终正文并正常结束
- **THEN** 两段说明与最终正文 MUST 是不同条目且按原顺序显示，工具 MUST 各自完成
- **AND** 运行结束后最后一段正文 MUST 可作为最终回复显示，中间说明 MUST 作为过程说明显示

#### Scenario: 截断、拒绝或未结工具
- **WHEN** 原生以输出上限、轮次上限或拒绝结束，或正文结束时仍有工具未结
- **THEN** 系统 MUST 报告对应停止原因或未结状态，MUST NOT 报告为完整成功

### Requirement: Antigravity 审批与提问必须交给用户准确回答

系统 MUST 把原生工具权限请求映射为审批卡片，并把用户选择的准确原生选项回传同一请求；“允许一次” MUST NOT 被扩大为持久授权，系统 MUST NOT 自动选择持久授权选项。原生业务提问 MUST 映射为单选、多选或自由输入问题，验证后回传同一请求；无法表达的提问 MUST 取消该请求并给出诊断。完全访问 MUST NOT 以自动回答请求冒充，也 MUST NOT 代答业务问题。

#### Scenario: 默认权限下的工具审批
- **WHEN** 默认权限下 `agy` 请求执行命令
- **THEN** 系统 MUST 显示审批并等待用户选择，选择 MUST 只作用于该请求

#### Scenario: 完全访问中的业务提问
- **WHEN** 完全访问已生效且 `agy` 发出业务提问
- **THEN** 系统 MUST 显示问题并等待用户回答，不因权限模式自动作答

### Requirement: Antigravity 停止、断连与恢复必须依据真实状态

停止 MUST 先请求原生取消并等待准确结算；只有收到原生取消结算，或本对话进程组已被终止且核验为空闲时，系统才可报告已停止，后者 MUST 将未结工具标记为未知；仅凭取消请求已发出 MUST NOT 报告已停止。原生连接断开 MUST 保留未知状态、清理失效审批，MUST NOT 自动重放工作。后台重启或回收后再次发送 MUST 按准确原生会话冷恢复，会话不存在时 MUST 明确报告并按统一规则开启新上下文，不得把旧会话编号交给其他配置或账号。历史读取 MUST 来自准确会话的原生记录，回放内容 MUST NOT 重复入库或混入新轮。

#### Scenario: 停止长时间命令
- **WHEN** 用户停止正在运行命令的 Antigravity 执行
- **THEN** 系统 MUST 取得原生取消结算或核验本对话进程组已退出后才报告已停止，未能证明结果的工具 MUST 保持未知

#### Scenario: 重启后打开历史对话
- **WHEN** Buildr 后台重启后用户打开曾使用 Antigravity 的对话并继续发送
- **THEN** 系统 MUST 恢复准确原生会话与已有历史，不重复显示旧条目，不重发上一条指令

### Requirement: Google 个人账号来源必须由 Antigravity 托管官方登录并仅供 Antigravity 使用

系统 MUST 使用 `agy` 官方支持的 Google 个人账号登录路线，接受免费、Google AI Pro 与 Ultra 账号。来源可用的条件 MUST 是 `agy` 确认当前 `oauth-personal` 登录有效、可建立稳定绑定身份且返回非空可用模型目录：当 `agy` 在官方协议字段中公开账号标识时，系统 MUST 显示该账号并以账号标识摘要作为绑定身份；当 `agy` 已确认个人账号登录但不公开账号标识字段时，系统 MUST 在连接私有状态中建立受管登录世代身份、如实显示 `agy` 未公开邮箱并说明终端原位换号需执行切换账号；当 `agy` 返回的账号字段损坏或认证归属无法确认时，来源 MUST 表示为身份不可确认且不可用于发送。系统 MUST 显示订阅档位，档位不可读时 MUST 显示“档位不可读”且不影响使用。来源 MUST 显示 `agy` 实际报告的可用模型及思考深度；额度 MUST 只展示官方可观察事实，不可读时 MUST 标明不可读并提供官方入口，MUST NOT 根据模型列表或用量估算余额或档位。来源 MUST 声明仅供 Antigravity 使用且不提供网关推理：其他执行方中显示为不可选并说明原因，系统 MUST NOT 为其签发租约，也 MUST NOT 在 Buildr 内提取、保存或转发其登录凭据。

#### Scenario: 登录免费账号
- **WHEN** 用户以未订阅的 Google 个人账号完成登录，`agy` 确认登录有效并返回可用模型
- **THEN** 来源 MUST 显示当前 Google 账号状态、免费档位与可用模型，对话中可选择 Antigravity 与这些模型

#### Scenario: 档位不可读
- **WHEN** `agy` 确认登录有效且可建立绑定身份并返回可用模型，但没有提供可识别的档位
- **THEN** 来源 MUST 可用并显示“档位不可读”，MUST NOT 推断为免费、Pro 或 Ultra

#### Scenario: 账号身份无法确认
- **WHEN** `agy` 返回损坏的账号标识字段或认证归属无法确认
- **THEN** 来源 MUST 显示身份不可确认，相关发送 MUST 在工作输入前拒绝

#### Scenario: 在 Claude Code 中查看 Google 账号模型
- **WHEN** 用户为 Claude Code 打开模型选择
- **THEN** Google 账号模型 MUST 显示为不可选，并说明受官方授权限制仅可在 Antigravity 中使用

### Requirement: 旧对话不得在其他 Google 账号下执行

每段 Antigravity 对话 MUST 绑定选择时的账号身份（`agy` 公开账号标识时为其摘要，未公开时为该次受管登录世代身份）。每轮工作输入前，执行方 MUST 观察 `agy` 当前认证状态与身份并与绑定身份比对：当 `agy` 公开账号标识且终端或其他客户端切换了账号、或经过退出/过期/重新登录使登录世代变化、或认证归属无法确认时，系统 MUST 拒绝输入、保留草稿，并要求用户重新选择模型或重新登录，MUST NOT 以新身份继续执行旧对话，也 MUST NOT 把旧原生会话交给新身份恢复。

#### Scenario: 账号或登录世代变化后继续旧对话
- **WHEN** 用户在终端切换到其他已公开标识的账号，或经退出/重新登录更换了当前登录世代后，回到 Buildr 的旧 Antigravity 对话发送
- **THEN** 系统 MUST 在工作输入前拒绝，说明账号已变化，并提示重新选择模型

### Requirement: Google 账号必须支持停用、退出与切换并与发送协调

系统 MUST 为 Google 个人账号来源提供三种操作：停用供应商只在 Buildr 内停止使用该来源，MUST NOT 改变本机 `agy` 登录；退出账号 MUST 通过 `agy` 官方退出动作清除登录，并断开 Antigravity 连接、关闭其运行时；切换账号 MUST 先完成官方退出再发起新的官方登录。由于 `agy` 登录保存在当前系统用户的系统密钥环中，退出与切换 MUST 在确认前说明会同时影响本机其他使用同一登录的 `agy`，并列出该连接正在运行的对话。

Buildr 发起退出或切换时，系统 MUST 先暂停该连接的新发送，并对仍在运行的轮次按统一停止规则处理；在途轮次未能证明已停止时 MUST 中止退出或切换并说明原因。退出失败或结果未知时，系统 MUST 先重新观察账号身份：仍为原账号则恢复发送；已退出则来源转为未登录；仍无法确认则保持暂停并提供重试。三种操作 MUST NOT 删除对话或原生历史；仍引用原账号的对话 MUST 在下一次发送前要求重新登录或选择其他模型。系统 MUST NOT 直接读取、复制、改写或删除系统密钥环条目。

#### Scenario: 停用后重新启用
- **WHEN** 用户停用 Google 账号来源后重新启用
- **THEN** 本机 `agy` 登录 MUST 仍然有效，来源无需重新登录即可恢复

#### Scenario: 有对话运行时切换账号
- **WHEN** 用户在一段 Antigravity 对话运行中确认切换账号
- **THEN** 系统 MUST 暂停该连接新发送并停止运行中的轮次，确认停止后才执行官方退出与新登录
- **AND** 新账号登录后，引用旧账号身份的对话 MUST 在下一次发送前要求重新选择模型

#### Scenario: 退出结果未知
- **WHEN** 官方退出动作超时或连接中断，结果未知
- **THEN** 系统 MUST 重新观察账号身份后决定恢复发送、转为未登录或保持暂停，MUST NOT 在身份未确认时恢复发送

### Requirement: Antigravity 授权地址必须只经登录尝试交付

系统 MUST 沿用现有登录尝试机制交付官方授权地址或授权码输入要求：地址 MUST 只出现在绑定该次登录尝试的状态中，仅在尝试处于等待浏览器授权期间可读，供界面作为受控导航打开；尝试完成、取消、过期或被新尝试替代后 MUST 不再返回该地址。已取消或被替代尝试的迟到结果 MUST 按尝试身份核对后丢弃，不覆盖当前状态。授权地址、授权码、令牌与回调内容 MUST NOT 进入对话事件、可见对话、普通诊断或日志；必须记录时 MUST 脱敏查询参数。

#### Scenario: 取消登录后旧地址失效
- **WHEN** 用户取消正在等待授权的登录尝试，随后旧授权页完成回调
- **THEN** 取消后的状态 MUST 不再返回授权地址，迟到结果 MUST 被丢弃且不改变账号状态

### Requirement: Antigravity 凭据与本机环境必须保持隔离边界

原生进程 MUST 使用该连接的私有主目录保存 `agy` 设置、会话记录与日志，不读取或修改用户主目录中的 `agy` 设置、全局技能、钩子与 MCP 配置；系统 MUST 如实说明这些用户级能力未包含在 Buildr 独立配置中。登录凭据由 `agy` 保存在系统密钥环，系统 MUST 为原生进程保留访问当前用户密钥环所需的最小会话环境，MUST NOT 为此恢复全部用户环境。令牌与原生敏感输出 MUST NOT 进入前端事件、可见对话或普通诊断。

#### Scenario: 用户已在终端使用 agy
- **WHEN** 用户在终端已登录 `agy` 并配置了个人技能与 MCP
- **THEN** Buildr 的 Antigravity 连接 MUST 可以复用同一系统密钥环登录，但 MUST NOT 加载或修改其个人设置、技能与 MCP 配置
