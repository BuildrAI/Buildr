## Context

动机见 `proposal.md`。现有 `SourceControlWorkbench` 分别保存变更范围、历史代码库（Repository）、工作树（Worktree）和分支（Branch），导致来源切换不能唯一确定下方内容；`history()` 未指定 `branch` 时以全部本机引用为起点。已有代码只读应用、任务（Task）工作树（Worktree）证据提供者（Provider）、提交（Commit）详情读取及公共差异（Diff）阅读组件可以复用，无需第二套事实或持久状态。

本次用户已明确授权修复交互；实施复用真实应用壳和共享组件，不生成新原型。旧规范有跨库名称聚合承诺，本次在 `code-source-control` 和 `buildr-web-client` 同时显式修改，其余旧场景保留。

本轮验收进一步收紧来源行对齐和列表信息密度：分支（Branch）紧随来源名称，路径按需查看，历史由紧凑列表、悬停摘要和右侧详细阅读共同承载，不改变已核对来源及固定文件的事实边界。

## Goals / Non-Goals

**Goals:** 让具体 `repositoryId` 与 `worktreeId` 成为两种阅读模式的唯一来源；把已观察状态和可证明的任务（Task）关联显示在来源旁，阅读对象始终绑定比较层及完整版本。

**Non-Goals:** 不增加 Git 写入、抓取远程、任意目录选择、任务（Task）关联编辑或新的持久表；不改任务（Task）内部阅读职责，不把分支（Branch）全部祖先历史误称为本任务（Task）独有提交（Commit），不扩展长期知识写入范围。

## Decisions

1. **单一具体来源。** 用代码库（Repository）及工作树（Worktree）的联合身份保存当前来源，代码库（Repository）行选中主工作树（Main Worktree），目录图标仅折叠子来源。两种模式从同一身份派生查询和文件清单；任务（Task）范围只用于初始预选，全部来源仍可选择。相比继续联动多个筛选状态，这直接消除了不同模式的来源漂移；相比跨库名称聚合，它保留真实独立身份。同一任务（Task）的跨库成员通过准确任务（Task）入口联系，查看时仍单选具体成员。

2. **状态各自表达。** 沿用 `upstream`、`ahead`、`behind`、`fileCount`，不把“登记”作为状态标签。主行与子行使用同一图标、来源身份、远程、文件及任务（Task）五格布局，来源身份内的名称与分支（Branch）共用列比例；按全目录已观察数字确定共享远程及文件列宽，混合数量和无差异标识时紧凑对齐。图标尺寸、点击区域及间距一致；远程使用同步方向或跟踪状态标识，任务（Task）使用任务标识，不能共用近似的链路图标。有未提交文件使用实心文件标识，无变更使用轮廓标识，未知文件保留独立语义。上游（Upstream）与文件各自保留未知、不可读取和确认无差异语义；可访问名称及悬停说明补足图标含义。已有上游（Upstream）但无法计算数量与完全没有跟踪必须区别。远程数量说明来自本机远程跟踪引用，不声称反映远端即时变化。来源名称与分支（Branch）同行，目录路径通过可选择悬停层（SelectableHoverCard）按需展示，支持移入停留、选择文字和点击复制，不另设固定展开路径行；窄宽度允许摘要省略，完整身份仍可核对。目录信息层首行显示“任务：标题”或真实未关联／未确认状态，第二行统一“代码库名称 · 工作树 · 工作树名称”，主来源名称为主工作树（Main Worktree），尚未读取的身份明确说明。各处任务（Task）图标提示统一“任务：标题”，不改变关联证据。

右侧阅读标题中的代码库（Repository）与工作树（Worktree）摘要必须可收缩并在自身范围内省略，保留版本摘要及操作空间，不覆盖信息、任务（Task）或展开阅读按钮。来源按钮仅在点击后于标题下方展开内联位置详情，显示实际目录和当前分支（Branch）或完整固定提交（Commit），支持复制、关闭及键盘操作；切换工作树（Worktree）时收起。常规悬停不自动展开来源信息，位置信息不展示内部观察版本、原始任务（Task）编号或底层读取解说。仅简化展示，既有 `expectedRevision`、完整提交（Commit）标识和来源联合身份继续保护读取。

来源路径及提交（Commit）摘要悬停层（Hover Card）只因键盘可见焦点或指针悬停而从触发行打开、保持；点击触发行选择来源或展开提交（Commit）时立即关闭摘要，同次指针停留及延迟悬停不能重新打开，以免遮挡后续来源、模式或文件操作。离开后再次悬停或键盘重新聚焦可以查看信息；未点击而离开触发行与信息层且没有信息层内部焦点时，仍按既有短延迟关闭。移入信息层、键盘聚焦及复制按钮仍保持可操作，不要求先点击空白。共享可选择悬停层（SelectableHoverCard）的默认焦点及点击行为保持兼容，仅来源路径及提交（Commit）摘要选择键盘焦点与点击关闭模式。

目录路径及历史行摘要的纯悬停继续放在中屏列表右边界之外，按右侧实际可用宽度收窄，不向左翻转或水平回推到列表。打开前取得边界和触发行位置；打开期间跟随列表尺寸、窗口变化及滚动更新，垂直位置可随视口（Viewport）边界调整。用户真正悬停打开后仍能沿同一文字列向上或向下选择相邻行，再横向移入信息层选字、复制；不能用点击后关闭替代此项验证。右侧标题的提交（Commit）摘要及未启用边界定位的共享调用保持原方式；完整来源使用上述点击展开的位置详情。

3. **历史摘要与详细阅读分层。** 正常分支（Branch）按所选来源可达范围读取，游离提交（Detached HEAD）按当前完整提交（Commit）标识读取，空来源返回空历史；保留显式 `branch` 参数兼容。搜索复用已有两字符归一化规则，低于门槛恢复未过滤历史并提示。列表用标题及紧凑的短标识、时间表达记录，引用与任务（Task）用图标摘要，悬停层（Hover Card）补足可复制的轻量信息；完整字段、引用及说明在右侧正式详情展示，说明正文去掉与标题重复的首行，任务（Task）沿用同一图标并显示准确完整名称，详情顶部不预留空白占位。正文末行若精确匹配已合法识别的 `Buildr-Task: <task-id>`，仅由对应任务（Task）字段表达，不重复显示原始尾注（Trailer）；复制完整信息仍使用原始 `commit.message`，无关联、冲突或不匹配的正文不删除。点击提交（Commit）行展开或折叠其文件，首次选择或改选不同提交（Commit）时将右侧切到该记录详情；点击文件才选择固定版本差异（Diff）。每个提交（Commit）行有独立展开状态，按来源及完整提交（Commit）标识缓存按需详情，允许多个行展开；折叠同一提交（Commit）不清除仍有效的已打开文件，不把文件改读为当前磁盘版本。

4. **两种任务证据各自保留。** 来源关联复用已选提供者（Provider）核对的工作树（Worktree）证据与当前任务（Task）查询，将唯一可读取身份作为 `taskId` / `taskTitle`；冲突或失效形成 `taskDiagnostic`。提交（Commit）关联继续使用合法 `Buildr-Task` 尾注，不把它倒推为整个来源的归属。来源行提供直接任务（Task）入口，选中来源的任务（Task）导航仍可发现；下方模式内容不再重复代码库（Repository）及分支（Branch）来源栏。历史图标的可访问名称、悬停摘要与右侧详情均表达准确任务（Task）名称；导航复用 `code-navigation` 的返回状态，不改变任务（Task）记录。

5. **应用壳局部消重。** 仅删除 `AppNavigation` 三处重复区域标题；保留顶部当前区域标记、导航可访问名称、内部关注分组和窄屏入口。既有主题及分隔组件（SplitDivider）继续承担选中状态与分屏，避免外围布局重画。

6. **图片按真实比较层阅读。** 图片读取复用 `readCodeFile` 的 PNG、JPEG、GIF、WebP 格式与每侧8MiB上限，差异（Diff）响应可选提供结构化旧侧和新侧。未跟踪新图为无旧侧与当前磁盘图；未暂存为索引内容到当前磁盘，已暂存为当前完整提交（Commit）到索引内容；历史为第一父提交（Commit）到所选完整标识，根提交（Commit）旧侧为空。新增或删除的一侧明确不存在，重命名旧侧使用 `previousPath`，不可读取或超限不能冒充缺侧。读取前后继续校验同次观察版本及具体工作树（Worktree），不猜其他目录、当前文件或提交（Commit）。前端复用共享阅读壳的可选正文插槽，仅源代码管理提供图片正文；真实缺一侧时仅显示另一侧全宽内容，以新增图片或删除前图片表达身份，不为不存在的版本保留大块占位。两侧均为文件对象时宽栏并排、窄栏上下；超限或不支持的文件对象保留所在侧及消息，不等同于缺侧，双方均缺失时仅显示局部无可预览内容提示。每侧显示真实比较身份，文字方向控件不能成为无效图片操作。既有完整图片入口及返回保持，不新增完整文件旧侧协议；删除前图片在旧侧直接可读。默认文字与其他二进制行为不变。

## Risks / Trade-offs

- [旧保存状态含多个独立筛选] → 恢复时只接受仍存在的具体联合身份，以已选文件或任务（Task）明确预选来源接续；不存在时显示真实缺口，不按名称替换。
- [历史请求迟到或详情缓存跨来源混用] → 查询、缓存及展开身份包含具体来源与完整提交（Commit）标识，旧请求取消或丢弃；切换源清除不适用的瞬时结果。
- [任务（Task）证据缺失、冲突或读取超限] → 局部诊断，不猜测入口，不阻断代码与历史阅读；跨库归属必须使用同一已验证任务（Task）身份。
- [单一分支（Branch）历史仍含共享祖先] → 保持 Git 可达语义；界面说明真实当前来源，不按任务（Task）尾注过度裁剪历史。
- [未指定分支（Branch）的接口行为收窄] → 保持参数结构及显式分支（Branch）查询，更新已有契约检查，验证正常来源、游离提交（Detached HEAD）、空来源与其他分支（Branch）隔离。
- [图片读取增加体积或读到不同观察现场] → 沿用每侧8MiB上限与原读取前后保护，明确不存在、失败、超限及格式不支持，不以空文本或其他版本替代；图片布局验证包含实际浏览器解码与宽窄栏。

## Migration Plan

无需数据库或源资产迁移。先补来源字段和历史默认范围，再把共享界面改为单一来源，更新已有契约与真实浏览器检查；生产构建及隔离托管验收通过后按本轮授权交付。回退通过恢复本轮源码即可，不包含任务（Task）记录或 Git 工作现场的数据写入。长期知识只核对当前职责和链接，必要建议记录到 `brief.md`，不在本轮批量改写。
