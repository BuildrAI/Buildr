## Context

搜索入口在 `buildr-web` 的对话列表，经本机 HTTP 的 `conversations` 列表动作进入 `buildr-agent` 的 `querySummaries`。当前实现用 `instr(lower(...))` 同时匹配 `summary.title` 和 `body.view.entries[].text`，没有索引；真实库约 127 条对话、115MB body JSON 中约 84MB 是工具日志。前端每次按键都会发起统计请求和每个工作空间组请求，共享读取用独立的 15 秒超时信号，调用方取消不会停止底层请求。完整列表的模型统计摘要当前是静态展示，`filter` 状态没有写入入口。

## Goals / Non-Goals

**Goals:**

- 把搜索范围收敛到标题与用户/助手可见消息，降低噪声并让大库读取的扫描量从约 84MB 工具文本降到约 1MB 消息文本。
- 返回并展示命中片段，让用户理解为什么出现该结果。
- 去重逐键请求，取消真正作用于底层读取，统计读取不随关键词变化。
- 恢复规范已要求的模型统计点击筛选。

**Non-Goals:**

- 不引入 FTS5、倒排索引或数据库迁移；也不改变历史记录的存储结构。
- 不改变工具日志、thinking、通知的保留与详情读取。
- 不改变活动优先级、隐藏筛选、游标分页或执行统计口径。

## Decisions

1. **搜索谓词限定为标题与可见消息。** 每条 entry 必须满足 `kind='message'`、`role in ('user','assistant')` 且 `thinking` 不为真。标题仍从 `summary.title` 读取，消息从 `body.view.entries` 读取。新旧两个列表入口（`querySummaries` 与 `listConversations`）共用同一谓词构造，避免行为分叉。
   - 备选：继续搜索全部 entry，只加 FTS。放弃原因是本步不做索引迁移，且工具日志噪声本身需要先收敛。
2. **多关键词按空白拆分并 AND。** 每个词项各自要求命中标题或一条可见消息；词项数限制为 6，沿用现有 200 字符上限。SQL 全部使用参数绑定，词项只参与 `instr/lower` 比较。
   - 备选：整段子串匹配。放弃原因是常见多词搜索无法命中被其他文字分隔的内容，用户会误以为过滤失效。
3. **命中片段由服务端派生。** `ConversationView` 增加可选 `searchSnippet`，只在列表读取且有搜索词时出现；取第一条匹配可见消息的文本，围绕最早匹配词项截取约 120 字符。片段不进入历史持久化，也不改变对话 revision。只对分页返回的候选行计算片段，避免加载全量正文。
   - 备选：前端从已加载 entry 计算。列表返回的 summary 已清空 entries，重新读取正文会扩大传输和内存；放弃。
4. **前端防抖与统计解耦。** 输入框保持即时值，查询值延迟 250ms；分组和分页使用查询值。顶部统计读取只依赖工作空间范围，不带关键词、隐藏或执行筛选；空态由各分组回报的过滤总数汇总，避免为统计再跑一次全量搜索。
   - 备选：统计请求继续带关键词。放弃原因是统计按规范不受搜索影响，却会额外执行一次全量搜索。
5. **共享读取按最后一个消费者取消。** 每个 URL 的 in-flight 读取拥有独立 `AbortController` 和既有 15 秒超时；消费者离开只减少引用，最后一个消费者离开时删除 flight 并中止底层 fetch。新消费者仍可加入已有 flight。
   - 备选：把调用方 signal 直接传给 fetch。放弃原因是会误伤共享同一读取的其他消费者。
6. **模型统计项复用现有摘要并接回筛选。** `ConversationExecutionSummary` 在有 `onFilter` 时把模型条目渲染为可切换按钮，点击设置/清除 `filter.kind='model'`；活动浮窗继续使用只读摘要。分组请求把模型条件传给服务端，继续使用既有模型筛选语义和“清除筛选”入口。
   - 备选：改用 `ConversationExecutionStats`。放弃原因是会改变完整列表现有布局和摘要口径，超出本步范围。

## Risks / Trade-offs

- **搜索范围变化会让过去只在工具日志中出现的对话不再命中。** → 规范明确范围，结果提供命中片段；若后续需要工具日志搜索，再以显式开关和 FTS 索引独立实现。
- **片段 SQL 会额外解析命中行的正文。** → 只对分页候选行计算，且片段长度有界；不改变主搜索扫描范围。
- **分组总回报可能让空态短暂延迟或误判。** → 只有分组明确返回 `total=0` 且无错误时才显示空态；未加载或折叠分组保持“未知”，不显示假空态。
- **防抖让结果延迟约 250ms。** → 输入仍即时响应；旧结果保留到新作用域开始，避免逐键闪烁。
- **新增可选响应字段需要 DTO 与校验同步。** → 字段保持可选，schema `additionalProperties:false` 中显式加入；重新生成前端 DTO 并跑类型检查。
- **共享读取的取消语义变化可能影响其他调用方。** → 以 URL flight 为边界，最后一个消费者才中止；写入失效继续只清空 flight 表，不取消已有消费者。

## Migration Plan

没有数据库迁移。`searchSnippet` 是可选的派生响应字段，旧客户端忽略即可。回滚时同时撤回前端读取与模型筛选装配、服务端片段与搜索谓词；历史数据无需恢复。FTS5 索引作为后续独立变更，另行评审存储与重建成本。
