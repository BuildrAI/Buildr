## MODIFIED Requirements

### Requirement: 对话历史必须按统一对话组织

历史 MUST 以稳定的 Buildr 对话（Conversation）身份展示主题、时间、必要状态及可选任务（Task）信息，并支持打开、新建、搜索标题、用户消息与助手可见消息、重命名及从最近记录隐藏和恢复。搜索命中消息时 MUST 在条目中展示来自该消息的有界命中片段；工具日志、通知、交接和思考内容 MUST NOT 作为搜索命中依据。Codex、DSH、Qoder MUST 作为实际参与来源展示，MUST NOT 以厂家拆分同一对话或设置按厂家分类的主历史。隐藏 MUST 不删除历史或停止执行，仍有待回应或未知执行的对话 MUST 保持可发现。

#### Scenario: 多位参与者仍是一条历史

- **WHEN** 同一对话先后由 Codex、DSH 和 Qoder 参与
- **THEN** 历史 MUST 仍以同一标题和身份展示一个条目，参与来源可以辅助说明
- **AND** 打开、重命名或隐藏 MUST 不替换各家的原生会话（Session）绑定

#### Scenario: 隐藏记录中的待回应

- **WHEN** 已从最近记录隐藏的对话出现待回答、待授权或执行状态未知
- **THEN** 用户 MUST 仍能从全局待回应提示或统一历史准确找到它
- **AND** 恢复显示 MUST 保留原记录与任务（Task）关系，不创建替代对话

#### Scenario: 搜索命中消息并解释结果

- **WHEN** 用户在历史中搜索一个只出现在用户或助手消息中的关键词
- **THEN** 历史 MUST 返回对应对话，并在条目中显示该消息的有界片段
- **AND** 仅工具日志、通知、交接或思考内容包含关键词的对话 MUST NOT 出现在结果中
