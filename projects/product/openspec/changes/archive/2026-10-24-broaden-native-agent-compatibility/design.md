## Context

统一程序策略目前同时承担版本筛选、固定下载和会话指纹中的版本命名空间。用户已安装官方 Codex `0.164.0-alpha.11.1`，但发现阶段仍只接受 `0.163.x`。另外两个接入也按次版本筛选。三家已有实际协议、账号和模型检查，不能把更窄的版本筛选当作这些检查的替代。

## Goals / Non-Goals

目标是让同主版本内更新可以继续连接验证，并保持已有账号和原生恢复身份。Codex、DSH 允许 `0.x.x`，Qoder CLI 允许 `1.x.x`，包含有效预发布版本；不同主版本仍返回局部诊断。

不更改厂家安装固定版本，不增加最低版本清单、自动升级、任意版本成功承诺或新的配置界面。三家真实登录和任务验收仍由用户执行，不修改其他进行中任务的依赖和回归工作。

## Decisions

1. **版本准入和实际可用性分开。** 版本字符串采用完整语义化版本语法，按主版本检查；候选符合范围仅允许进入现有协议握手、官方登录及实际账号和模型检查。实际协议失败保留账号和原记录，不自动降级或改绑。
2. **保留现有绑定命名空间。** 现有 v2 数据中的 `series` 已参与指纹。将其明确为固定的历史绑定命名空间，与新的主版本准入字段分开；既有字节与指纹均保持，无需数据迁移。程序准确路径、配置准确路径及配置来源身份仍逐项验证，不能借策略放宽接管其他配置。
3. **沿用一个程序策略。** 发现和三个执行器消费同一主版本策略；执行错误中的范围从策略读取。安全诊断与当前说明同步，并通过测试防止重新出现旧范围文字。

## Risks / Trade-offs

主版本为 0 的程序仍可能在次版本更新时改变协议，主版本筛选不保证真实兼容；这正是保留实际检查的原因。旧程序或较新的程序可能符合范围但实际检查失败，失败只影响相关接入。固定下载版本作为可复现安装基线保留。

保留 v2 的 `series` 名称是持久化兼容约束，不再解释为准入范围；改名或改值反而会改变已有指纹。测试需使用旧格式的实际来源字段和旧指纹验证恢复，而不只检查新版本字符串返回 true。
