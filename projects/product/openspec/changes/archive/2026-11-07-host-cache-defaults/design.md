## Context
现有sharedToolchainEnvironment、selectHostToolCaches与原维护worker已提供目录选择、锁、占用及版本复核。无需建立新管理平台。
## Goals / Non-Goals
标准宿主目录不存在时安全创建；保留安装及有价值下载内容；继续整类回收可证明无用编译缓存。账号、会话、成果与原生可写插件工作树不合并。
## Decisions
只在已核对宿主目录下逐级创建标准目录，拒绝符号链接与非本用户目录；已明确配置的可用路径优先。宿主不可用或标准路径不安全时保留兼容回退。Maven同样采用宿主.m2/repository，不复制settings.xml。
旧下载缓存不以目录名、可再生、已换路径或超龄直接删除。npm已声明的旧_cacache使用原发布器按文件排他发布，宿主已有索引桶优先，使用npm的cacache读取器校验全部内容摘要、可用源键及宿主已有响应。目标中已覆盖的有效文件逐项记录本次内存版本，删除前复查；未索引但有效的内容仍可按完整性摘要读取。损坏、占用、引用或版本变化都保留源目录，由现有worker重试，不增加持久迁移索引，不迁移凭据或_npx安装目录。其他下载仍在未证明覆盖时保留。Node/Python编译缓存默认使用宿主用户级公共缓存目录，其他应用需要使用同一路径配置才能共享。Buildr缓存目录仅在宿主不可用时兼容回退。编译缓存维持原worker与窗口。

Codex仅核验logs_1/logs_2数据库为纯日志schema，读取WAL中的当前schema；新增非日志表即保留。因生产者只有UUID，原诊断模块以完整配置静止及缓存用途引用作为另一种明确证明，普通Qoder PID/恢复保护不变。数据库与现存WAL/SHM作为最多3个文件的家族整体改名、复查，任一成员变化则全部恢复，大数据库不受小日志256 KiB批次限制。主文件最后删除，仍使用15分钟稳定窗口和原维护线程，不新建数据库或定时器。
## Risks / Trade-offs
空标准目录会较早创建，但不下载内容。旧缓存暂时占更多空间，换取避免无谓流量。插件继续保留必要可写副本，闲置后按准确来源清理，不使用可变硬链接。
## Migration Plan
不搬动现有账号或依赖。新执行采用新目录选择；旧执行保持原环境，结束后再观察。回退兼容路径不删除。
