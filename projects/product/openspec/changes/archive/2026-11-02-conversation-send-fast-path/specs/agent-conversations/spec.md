## MODIFIED Requirements

### Requirement: 接续超限必须保留历史并由用户明确选择

系统 MUST 分别遵守目标接入的字节容量与模型可用上下文预算，预留新输入和输出空间，不把固定 64 KiB 视为所有目标的上下文。正常交接 MUST 由 Buildr 直接组织；超过预算时 MUST 直接使用本地必要信息及可读取的分轮索引，发送和预览 MUST NOT 等待辅助模型摘要。原始记录 MUST 保留，摘要 MUST 标明来源和覆盖范围，MUST NOT 静默截断、把引用路径冒充已读取内容或要求用户手工总结。必要资料或附件仍无法安全交付时 MUST 保留草稿、说明限制并允许用户选择其他模型。

#### Scenario: 历史超过接续容量
- **WHEN** 直接组织的材料超过目标接收预算
- **THEN** 系统 MUST 直接提供本地可读取索引和准确覆盖说明，不调用辅助摘要模型
- **AND** 必要内容仍不能安全交付时 MUST 明确限制，不伪报完整交接

#### Scenario: 用户采用精简说明
- **WHEN** 旧客户端仍提交用户明确提供的精简说明
- **THEN** 系统 MUST 保存原文和来源并作为补充交付，不以该说明覆盖本地原始历史
- **AND** 后续换家或换回 MUST 仍从本地原始记录组织，不递归转发旧说明

#### Scenario: 旧模型不可用
- **WHEN** 旧模型额度不足、失效、不支持隔离整理或整理超时失败
- **THEN** 系统 MUST 不向原工作会话发送整理请求，也不阻止使用本地记录继续
- **AND** 索引缺失或不可读 MUST 明确失败，不能在缺少来源时声称交付完整

#### Scenario: 整理期间内容变化
- **WHEN** 预览后本地对话修订或模型绑定变化
- **THEN** 系统 MUST 拒绝把过期预览用于实际发送，保留草稿并重新读取当前事实
- **AND** 实际提交 MUST 使用所查看正文的准确版本，不再次悄悄生成另一份正文

## ADDED Requirements

### Requirement: 日常发送不依赖交接预览

普通发送 MUST 支持一次提交并在后端校验当前身份、版本、权限、附件容量与请求幂等性，不要求前端先取预览。显式交接预览 MUST 保留；携带预览令牌的提交 MUST 继续核验准确正文。可复用原生上下文且没有待补历史时 MUST 仅交付新要求、附件和必要控制信息，不生成交接来源文件。

#### Scenario: 同一会话日常续聊
- **WHEN** 原生上下文可复用且没有未交付的历史
- **THEN** 普通发送 MUST 不请求交接预览、不调用辅助摘要、不构建历史来源文件

#### Scenario: 直接提交重试
- **WHEN** 同一输入身份重复提交或提交基于过期版本
- **THEN** 系统 MUST 返回原已受理结果或明确冲突，不创建重复执行、不重放未知输入
