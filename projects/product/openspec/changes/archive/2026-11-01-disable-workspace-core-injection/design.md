## Context

初始化和内置资产同步分别调用同一默认区块写入函数，诊断比较完整随包原文；来源查询也用该原文证明历史 Buildr 来源。动机见 proposal.md。

## Goals / Non-Goals

- 目标：把用户根规则所有权还给用户，取消隐含的默认规则安装与恢复要求。
- 非目标：不批量清理已有工作空间，不改变其他受管文件的编辑保护，不发布或激活候选代码。

## Decisions

1. 删除默认区块写入和状态比较能力及其调用，而非增加开关或空模板。避免隐性副作用继续留在同步路径。
2. 保留历史原文，仅供精确的只读来源识别；缺少区块返回未知，不推断由 Buildr 管理。修改过的旧区块仍不能冒充已核实来源。
3. 同步逐字保留现有根文件，文件缺失时不创建。自动删除旧段会丢掉用户仍依赖的约定，因此只在用户明确授权的 Things 文件中整理。
4. Things 原有产品、数据和开发约束保留，补充目标接续、核实事实、局部失败隔离与沟通规则。每次专业术语双语表达按用户明确要求保留；不迁入 Buildr 产品哲学、资产治理和隐含推送授权。
5. 必要的使用说明回到随包技能（Skill），同步校准直接受影响的当前知识。无需能力契约升级，既有专业能力的输入、输出及授权不变。

## Risks / Trade-offs

- 旧版程序仍会注入 → 实现与运行环境分开报告，未经自举激活不宣称本机已切换。
- 没有根文件的规则发现与打包检查原来假设有文件 → 添加真实初始化、同步和诊断回归；规则投射场景显式准备自有根规则。
- 历史来源仍需要原文 → 保留只读历史参照，不再作为通用工作空间必读入口。
- 不自动清理旧段 → 其他工作空间需按各自授权整理，避免误删用户依赖内容。

## Migration Plan

无数据库迁移。新程序使用时停止注入，既有文件不变。Things 在独立工作树（Worktree）形成自有规则；本轮不提交、不推送、不执行正式自举激活。恢复旧版程序可能再次插入默认段，应明确区分代码修改与运行生效。
