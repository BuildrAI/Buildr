# 优化面向用户的中英文术语表达

## 一句话摘要

让 Buildr Core 要求 Agent 用简练中文向用户说明专业内容，在首次出现时交代英文原词，并为必须精确对应实现的文本保留英文。

## 背景与问题

现有 Core 分别要求术语一致和简明表达，但没有统一说明已有中文名称、没有稳定译名以及命令或错误原文等不同情况。Agent 因而可能连续使用未经解释的英文术语、在同一说明中更换译法，或者为追求中文而损失实现精度。

## 目标与非目标

- 合并现有两条重复规则，形成一条清晰的用户表达约束。
- 已有中文名称时首次使用“中文（English Term）”，后续优先使用中文。
- 没有稳定译名时允许保留英文，但首次出现须解释含义。
- 命令、代码标识、字段名、接口名、文件路径和错误原文等精确文本保留英文。
- 不建立新术语表，不修改术语治理流程或 runtime 发现机制。

## 受影响用户或角色

- 使用 Buildr 的用户：更容易理解 Agent 对产品设计、实现、问题、方案、进度和结果的说明。
- 使用 Buildr 工作资产的 Agent：获得统一、可执行的中英文术语表达边界。

## 核心流程

Agent 先用直接、简练的中文组织用户说明；必要专业术语首次出现时按是否已有稳定中文名称选择“中文（English Term）”或英文加含义解释，后续保持译法一致；需要与实现精确对应的文本始终保留英文。

## 关键变化

- 合并 Core 中的术语一致性与简明表达条款。
- 补充专业术语首次出现、后续称呼和稳定译法要求。
- 补充实现精确文本的英文保留边界。
- 增加 Core Rule 契约测试。

## 影响、风险与兼容性

变更只影响 Agent 面向用户的表达方式，不改变 CLI、API、数据或 runtime adapter。规则保留没有稳定译名和实现精确文本的英文例外，避免机械翻译。现有 workspace 通过 Buildr sync 获得新版 Core。

## 验收摘要

- package 中的 Core Rule 只保留一条统一的用户表达规则。
- 契约测试覆盖中文优先、首次中英文并列、译法一致和实现精确文本例外。
- OpenSpec 严格校验、受影响验证和 Buildr doctor 通过。
