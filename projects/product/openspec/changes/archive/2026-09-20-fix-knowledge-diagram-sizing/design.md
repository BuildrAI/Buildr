## Context

动机见[提案](proposal.md)。当前 `KnowledgeDiagram` 的文内预览使用固定 `aspect-ratio: 1.6`；`KnowledgeArtifactReader` 已区分嵌入模式与独立展示。知识应用先通过有界文件读取获得 HTML，HTTP 入口随后将 JSON 中图示正文清空，展示入口独立返回受隔离的原生 HTML。

当前 Archify 展示的主 SVG 以 `aria-labelledby` 关联 `archify-diagram-title`，有效 `viewBox` 提供实际比例。嵌入模式 `.diagram-container` 四周留白均为 `0.5rem`，当前默认字体下为 `8px`，总横向及纵向留白各 `16px`。任务总图与知识维护图的比例不同，固定预览比例分别导致空白或裁切。

## Goals / Non-Goals

**Goals:**

- 从同一次安全读取的当前展示计算尺寸，为前端提供足够且最小的只读元数据。
- 使文内预览在正文与副屏宽度变化时保持完整、紧凑的图面。
- 保留现有未知 HTML 回退、独立查看、放大阅读和脚本隔离。

**Non-Goals:**

- 不读取图源 JSON 推断展示尺寸，不解析图形语义，不修改 Archify 上游或生成 HTML。
- 不增加尺寸索引、后台监听、知识写回或父页面与隔离框架的同源访问。
- 工作台反馈布局和任务系统职责表达由同一任务的其他维护处理。

## Decisions

1. **在知识读取结果中计算 `diagramSize`。** 从已经读取的图示 HTML 识别原生主 SVG，严格解析 `viewBox` 的有限数值，仅接受正宽高；无法可靠识别时返回 `null`。识别主 SVG 而非第一个 SVG，避免把工具栏图标当作主图。保持纯文本检查，不执行脚本，不引入额外文件访问。使用同一展示读取结果，可避免配套图源未同步造成尺寸错误。
2. **扩展现有响应结构及生成类型。** 所有读取成果显式返回可空尺寸；图示正文仍由隔离展示入口提供，JSON 中保持 `null`。同步维护响应结构与生成类型，使新生产端与消费端一致。新前端兼容旧响应中缺少字段的情况；旧前端仍忽略新增尺寸并沿用原展示逻辑。
3. **仅让紧凑预览按真实比例自适应。** 将尺寸从成果读取组件传到图示组件，观察其实际容器宽度，按 `max(0, 宽度 - 16) × height / width + 16` 计算当前 Archify 嵌入高度。尺寸未知时保留既有回退。独立详情保留完整原生查看器及放大能力，实际页面验证应同时覆盖它们，避免通过裁切或限制原生内容掩盖问题。
4. **以不同形状的真实图与失败输入验证。** 后端覆盖主 SVG 识别、不同合法尺寸、错误及缺失尺寸、图源与展示不一致、非图示和 JSON 正文仍为 `null`；前端和实际阅读覆盖横图、较高图、容器缩放、回退及独立查看。已有安全读取测试只在受影响范围复用或补充。

## Risks / Trade-offs

- 原生展示模板未来改变标记或留白 → 无法识别时保留回退；当前模板留白由有界页面检查验证，未来修改模板时一并核对。
- 未知第三方 HTML 可能有其他布局 → 不猜测比例，返回 `null`。
- 新字段影响严格校验响应的消费者 → 更新现有契约及生成类型；不声称任意外部严格校验器都可无感升级。
- 框架宽度变化可能来自副屏或窗口 → 使用当前容器宽度并检查多种页面布局，不按固定桌面尺寸写死高度。

## Migration Plan

无需迁移文件或数据库。后端响应结构和前端一起交付；旧图或旧响应沿用回退。回退版本只恢复原固定尺寸行为，不改动知识内容或生成 HTML。
