## Context

参见 proposal.md。新连接通用模块已有安全的实例选择与程序上下文；旧 MySQL 查询页面、认证和偏好仍绑定旧 SQLite 实例。本任务与通用连接硬化和实例文件命名两项并行实施，共享文件采用最小追加，三项专业程序与测试目录独立。

## Goals / Non-Goals

保持通用声明和上下文协议不承载系统业务动词；保持 MySQL 查询工具独立、复用现有布局与只读执行器。旧路径继续可用，不自动迁移认证，不新增专业控制台，不执行真实调度写入或生产动作。

## Decisions

1. 三个完整源目录及各自测试独立交付。Kibana、XXL-JOB 程序随技能携带实现，不运行时依赖产品旧模块；XXL-JOB 通过声明的 Buildr 只读入口确认服务登记，专业关联和授权记录使用实例隔离的 `privateStateRoot`。
2. MySQL 新增独立 `mysql-query` 模块和明确版本的命令/页面接口，复用旧只读 SQL 执行器。通用连接应用只追加内部 `useSelected` 回调端口，复用当前选择校验并仅向装配的内置查询应用交接配置认证，不新增公开凭据接口。查询应用再核验内置技能来源和字段契约。
3. MySQL 专业测试与发现使用随 Buildr 安装的 `buildr-mysql` 程序，只接收私有上下文并复用随包数据库驱动；避免技能脚本猜测 npm 路径或要求额外客户端。该程序不承载查询页面及偏好状态。候选与正式包分别核对程序发现和无认证帮助。
4. 查询前端复用既有组件，通过显式来源与实例版本适配独立客户端。新连接页仅增加 MySQL 查询动作与右屏查询接续，不改已有表单设计；新旧身份与请求隔离，查询偏好继续本机保存。
5. 新规范使用独立能力及 mysql-query 增量，避免改写并行任务正在维护的通用连接规范。最终按开发主线实际变化核对必要兼容性。

## Risks / Trade-offs

- 原专业代码较多，移植可能丢失保护 → 保留既有错误、边界与结果语义，用独立进程模拟和邻近旧回归核对。
- 通用认证硬化仍在变化 → 内部端口只复用 selected 校验，不复制认证算法，最终核对对应追加方法适配。
- 新专业程序需要随包可发现 → 正式包安装验收，开发候选使用独立 PATH，禁止覆盖默认安装。
- 集鲜 QA 的实际接口或权限可能受限 → 有界只读验证并报告实际覆盖，模拟写入保护不冒充真实写入成功。

## Migration Plan

仅增加可安装内置技能和新查询消费入口；现有旧实例继续原样使用。真实验收从用户授权的 QA 连接选择目标，通过仅本机隔离输入准备候选新实例；不改变原实例，不将认证或业务正文写入公共成果。正式安装、自举激活和常规 Git 交付分别按后续实际授权处理。
