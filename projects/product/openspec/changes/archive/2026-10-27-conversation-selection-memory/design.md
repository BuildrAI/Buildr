## Context

当前模型账号检查通过统一的 `changed` 路径保存观察并生成新修订。即使只有额度或观测时间变化，或者检查的是另一个账号，也会产生新修订。对话发送把调用方观察到的账号修订作为硬性前置条件，前端又把所有 409 统一显示成恢复提示，因此形成“配置一个账号，另一个对话看起来被中断”的体验。

对话选择目前只有会话内状态和按工作空间的新草稿；生成提交说明已有独立的 `buildr.execution-model` 浏览器偏好。新增偏好必须继续保持前端现有职责边界，不引入全局状态仓库（Store）。

## Goals / Non-Goals

**Goals:**

- 让账号修订只表达该账号影响模型选择的实质变化，并保证不同账号互不干扰。
- 让发送使用当前准确来源重新校验，而不是把旧修订本身当成失败条件。
- 让前端冲突反馈对应真实原因。
- 以软件级浏览器偏好记住对话智能体、权限和模型选择，并保持与执行模型选择器分离。
- 在同一工作空间恢复完全访问，跨工作空间收窄为默认权限。

**Non-Goals:**

- 不改变模型账号存储格式、登录流程、网关协议或凭据隔离。
- 不把偏好保存到工作空间、任务（Task）或对话服务，不跨设备同步。
- 不把新偏好应用到已有对话或历史运行记录。
- 不改变提交说明执行模型的选择与持久化键。

## Decisions

### 账号修订使用实质选择指纹

在模型账号检查完成、写回观察前比较账号身份、启停、状态、账号标签与规范化模型目录。模型按标识排序，思考档位与服务档位也按稳定顺序比较；额度、观测时间、诊断文本和返回顺序不进入指纹。只有指纹变化才更新该账号修订，但仍保存额度与观察时间。

替代方案是保留每次检查都更新修订，只在发送时忽略不匹配。该方案无法解决模型设置页并发保存与账号修订无意义翻动，因此不采用。

### 发送核对当前来源而不是固定旧修订

发送预览仍记录账号身份与当时的修订用于解释，但准备新请求时以当前账号快照为准：身份必须一致，模型必须存在且启用，档位和思考深度必须由当前能力支持。旧修订不再单独构成失败条件。

这样可以安全吸收只读目录刷新或无关字段变化，同时仍在登录来源变化、模型停用或移除等实质情况下拒绝。替代方案是在输入中携带完整能力指纹，但会扩大协议与兼容面，当前校验已足以证明本次绑定。

### 对话模块记忆与模型选择器记忆分别保存

使用两个新的、按应用配置域限定的 `localStorage` 键：

- 对话模块偏好保存智能体和权限；同一对象表达二者属于同一对话上下文。
- 对话框模型选择器偏好保存智能体绑定、模型来源、模型、服务档位和思考深度。
- 既有 `buildr.execution-model` 保持不变，形成与执行模块选择器相互独立的第三类记忆。

偏好使用版本化 JSON，未知或损坏值按无偏好处理。新增内存状态只是当前页面回退，不建立新 Store，也不把服务端列表缓存放入偏好。

### 只解析新对话的恢复选择

新对话从软件级偏好解析智能体和模型；已有对话继续优先使用本轮运行记录或本会话选择。用户明确更改选择时写入偏好；目录刷新只同步账号修订时不得写偏好。这样打开旧对话不会改变下一次新建对话的默认值。

完全访问权限偏好同时保存最近明确选择的工作空间。只有当前新对话工作空间一致时才恢复完全访问；默认权限可跨工作空间恢复。

### 前端按错误码恢复

409 先按错误码分类。只有预览过期、模型来源失效或对话修订冲突等确实需要重读的情况才刷新对话、接入和模型目录；忙碌、权限不支持、模型停用等错误直接显示服务端准确原因。所有恢复路径都保留草稿。

## Risks / Trade-offs

- [旧修订自动采用当前能力] → 必须在采用前重验账号身份、模型启停、档位、思考深度与执行方兼容性；实质不满足仍然失败。
- [账号目录顺序不同造成修订翻动] → 对模型、档位和思考档位使用稳定排序后再比较。
- [跨工作空间恢复完全访问] → 只保存最近选择的工作空间并在不同工作空间强制默认权限，界面显示实际生效值。
- [模型偏好引用已删除来源] → 不套用失效来源；回退到当前智能体官方默认选择，不自动选择其他共享套餐。
- [浏览器存储不可用或多标签页竞争] → 当前页面状态继续可用，偏好写入是可选的；多标签页以后写入者为准，不把偏好作为执行授权或真实成果权威。
- [用户已存在同工作空间完全访问运行] → 新对话恢复的是最近明确选择而非历史对话扫描，避免把打开旧记录误当作新的授权来源。

## Migration Plan

没有服务端数据迁移。首次使用新版本时读取不到新偏好，沿用当前默认选择；用户下一次明确选择后开始保存。部署后可回退到旧版本，旧版本会忽略新键并继续使用原有会话内选择与执行模型偏好。
