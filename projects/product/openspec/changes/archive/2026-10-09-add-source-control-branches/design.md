## Context

见 [proposal.md](proposal.md) 与[任务说明](@task/source-control-branches)。现有 code 应用按已登记来源读取，工作树（Worktree）标识由 Git 登记与公共目录形成，历史有有限扫描、分页和观察版本。当前自动 HTTP/CLI 映射全部为读取；第七版原型（Prototype）中的操作与作者（Author）过滤仍使用模拟状态，不能直接作为真实实现。

## Goals / Non-Goals

目标是把已采用的交互接到可重新观察的真实 Git 事实，保持读取与写入职责分离、局部失败和兼容边界。范围以 proposal 和两份规范为准，不引入新的状态库、框架、全局门禁或操作组合。

## Decisions

1. **独立分支（Branch）应用。** 清单、目标解析和切换放入 code 功能内的专用职责；复用已登记来源解析和稳定工作位置身份。已有历史与文件读取保持只读，替代把写入加入通用读取映射的做法，避免误暴露为只读命令或工作进程（Worker）动作。
2. **版本绑定写入。** 切换输入为来源身份、已观察位置版本、完整目标引用（Ref）和已观察提交（Commit），服务器重读并验证。观察版本包括本地与远程尖端、上游（Upstream）关系和工作位置状态，远程条目复用本地项时仍保护该项自身的已观察成果。普通 Git 切换保留非冲突内容；保护同名项、占用和进行中操作。失败以当前事实表达，不自动保存、强制、拉取（Pull）或回滚。使用有界写入执行器，保持参数数组和命令注入边界，关闭不属于该动作的钩子（Hook）执行。
3. **本地跟踪语义。** 远程独有项由一次普通跟踪检出（Checkout）同时建立本地项与切换；已有对应项使用本地当前成果。与直接重置已有本地项相比，此设计不会覆盖用户本地提交（Commit）。同名不同上游（Upstream）需要明确新名称。
4. **服务器历史过滤。** 完整本地／远程引用（Ref）解析及精确作者（Author）邮箱过滤在扫描和分页层完成，条件进入游标（Cursor）。作者（Author）选项独立读取并报告扫描范围，不从单页结果推断全量。作者（Author）浮层（Popover）提供明确的姓名／邮箱搜索框和“我的提交（me）”快捷项；前者定位候选，后者使用具体工作位置有效已配置的作者（Author）邮箱，选择后都沿用精确邮箱筛选。无法确认邮箱时只禁用快捷项。保留旧本地名称及显式短关键词参数兼容。
5. **复用真实组件（Component）与原型。** 将第七版界面组件（Component）和必要样式归入 code 功能，读取与异步切换由专用钩子（Hook）和既有客户端（Client）处理。读取范围按真实来源保存；“当前”是动态范围，完整引用（Ref）是固定范围。已有任务（Task）调用保持原默认行为，历史文件继续固定完整提交（Commit）。
6. **有界清单与刷新。** 读响应沿用现有观察与覆盖字段；按需更新本机记录，不隐式联网。操作完成后重新读取目标位置与分支（Branch）清单，晚到响应不能覆盖新选择。界面请求取消不等于撤销已经发出的写入，写入结果按真实响应及重读处理。

## Risks / Trade-offs

- 目录或引用（Ref）并发变化 → 写前重新解析身份和版本，失败保留现场并返回具体原因。
- Git 写入可能受到文件系统失败或进程中断影响 → 保留并报告实际效果，禁止误报零写入或自动丢弃恢复。
- Git 默认允许覆盖被忽略文件，配置的内容过滤器（Filter）可能执行外部命令 → 明确禁止覆盖被忽略内容；必须外部转换的切换局部拒绝，保持正确文件和本机执行边界，不静默禁用转换。
- 作者（Author）与历史扫描有上限 → 延续有限观察与截断说明，不能把当前页当作全量候选。
- 共用组件（Component）会影响任务（Task）阅读 → 扩展按入口选择启用，保留固定版本及来源恢复测试。
- 原型（Prototype）基线早于当前主线 → 按文件核对差异后迁入；旧 HTML 与来源归入本变更，不覆盖原版。

## Migration Plan

所有新读取字段和过滤参数保持可选，旧客户端（Client）读取与任务（Task）入口行为保持；新写入走明确独立路由。无需数据迁移或新依赖。采用变更内保全的第七版原型（Prototype）作为交互依据；仅候选环境通过不宣称主应用已生效。
