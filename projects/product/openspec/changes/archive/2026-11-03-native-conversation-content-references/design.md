## Context

v5 已将正文按条目修订单份保存，但详情、附件及完整历史仍依赖 Buildr 副本。仓储同步读取覆盖历史、搜索、分叉、交接和恢复，不能只替换一个展开按钮。原生历史投影有截断和过滤，不作为去副本证明。

## Goals / Non-Goals

保持消息身份、修订、顺序、全文搜索、工具详情和新附件的正常读取语义；用户已允许丢失本次开发配置的历史附件及旧路径兼容性。仅改变已证明正文的物理归属。保留正在执行、结果未知、待回答和有未释放依赖的本地副本。本轮不归档原生文件，不改变视频输入，不减少第三组交接投射。

## Decisions

1. 原生适配器负责发现确切配置中的上下文文件、工具调用/结果和原生媒体。Codex 按 rollout 的会话和调用身份；Qoder 按账号配置根的 projects 会话、消息和 tool_use/tool_result（模型绑定根不保存其会话正文）；DSH 按 v4 事件、调用和附件身份。未知格式或无法准确重建的条目不转换。
2. 共用存储层只读取适配器证明的有界原生片段：受管相对路径、文件片段、编码、原始片段摘要，以及片段内的值定位。文本引用可保留少量固定格式文字和来源片段组合，不复制大正文。读取时核对范围、链接、片段摘要、解码预算及最终原始正文摘要；追加允许旧片段仍可校验，改写或缺失明确失败。缓存只在内存中有界保存，不落另一份永久原文。
3. 正文内容增加原生引用编码，保留原内容修订及原始长度。仓储在所有完整读取路径统一解析引用；普通分页为原生引用保留有界预览，搜索仍只访问本地可见消息。控制路径以延迟正文访问保留准确条目身份，未读取正文时的保存不触发原生加载；相同修订保存不把引用重新写回完整正文，迟到修复产生新修订并重新证明。
4. 存储升级到 v6，沿用现有 owner 与迁移保全，不重建 v5 条目表。旧后台存在时延迟格式采用；升级不转换正文；在迁移owner排除不兼容写入器时一次启用SQLite增量回收。完成一致性备份和格式切换后，由既有独立维护线程逐批证明并转换已有及新记录，事务内比较内容版本和恢复依赖；失败仅保留该项。后台维护不发送模型请求或打开原生执行通道。
5. 附件只在原生记录/原生附件库有独立、摘要相同的完整字节时改为引用。普通新附件的原视频、未发送内容或格式不支持时继续保存；本次开发期历史原件按单独的准确快照清理授权执行，不把丢弃变成产品默认策略。普通媒体读取返回原始字节；只有执行器确需本地文件路径时才物化可回收副本，活动引用保护该副本。旧原生记录和已发交接路径不再阻止清理，不扫描全部原生日志和交接文件做旧路径兼容；旧路径可能失效，这是已获用户接受的历史兼容性损失。
6. 复用既有维护线程、读取入口与账号隔离，不增加通用作业平台、每轮快照库或另一套压缩归档。物理转换不改变逻辑消息修订；结果报告区分正文候选字节、实际移除副本和 SQLite 空闲页，不能把数据库内释放直接称为操作系统回收。独立维护每批最多归还2MiB空闲页，写入或检查点繁忙时延迟，不在普通维护执行整库VACUUM。

## Risks / Trade-offs

- 原生格式改动、SDK 投影不同或来源不完整 → 字节比对不通过即保留本地，不能为了覆盖率猜测原文。
- 原生唯一正文被外部删除 → 明确缺失并保留引用，不伪造空内容、不重新执行；备份必须同时保全 Buildr 元数据和被引用的原生数据。
- 同步详情读取成本 → 按片段读取、有界解码与有限内存缓存；目录发现和存量转换在独立线程，普通列表不扫描原生历史。
- 开发期历史唯一原件和旧本地路径丢失 → 明确旧附件可能不可读，不虚构无损迁移；本次清理只作用于已观察且无活动、未知、待回答或待发送依赖的历史快照，不清理新上传附件。
- 未经支持的原生归档/清理可能破坏引用 → 本轮维护不会清理原生会话目录；长期归档必须继承引用保护。

## Migration Plan

先在隔离文件/数据库/进程验证 v5→v6、兼容旧格式、片段重读及失败保全。候选不修改真实用户库；交付采用后由唯一写入后台安全升级，随后分批转换。迁移失败保留旧库；新输入写入后不使用旧备份覆盖。压缩归档继续由 agent-conversation-tiering 另行实施。

## Development History Cleanup

用户已明确授权本机 Buildr Dev 的开发期历史附件可丢失。一次性操作由当前保留检出目录读取已完成对话和准确文件快照，复用现有存储归属、进程占用与文件版本检查；再次核对对话头和保护依赖后按精确文件删除，包括原视频唯一原件。仅删附件文件，不迁移共享数据库、不修改原生会话、不激活候选；未知或已变化对象保留并报告。后续新上传没有该一次性快照身份，不被此操作删除。
