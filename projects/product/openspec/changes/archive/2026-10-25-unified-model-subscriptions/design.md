## Context

现状见提案。`buildr-agent` 是主包捆绑的私有库，三家执行器（Executor）与独立原生配置已存在，账号、目录和连接就绪目前耦合。对话用准确恢复引用及观察版本管理原生执行，必须保留。

## Goals / Non-Goals

目标是独立选择执行方与套餐模型、首批 Devin、账号来源可追溯、现有程序和会话安全接续。用户已授权方案、实现及验证连续推进。此次不发布新包、不部署、不修改默认桌面账号、不执行真实业务写入或制造 Qoder 个人套餐的未知裸模型接口。

## Decisions

1. **交付**：在现有私有库内增加 `model-access`，由主包现有宿主装配。同一进程按需启动仅监听本机的认证模型入口；不增加用户安装服务。相较直接依赖 DSH 插件或 Go 后台，这能保持独立生命周期与当前 Node 发布体系。
2. **数据**：套餐账号、动态模型能力与模型绑定分开。原生账号凭据仍由唯一原生 owner 或明确新登录的账号 vault 管理；公共视图仅保存引用和摘要。原生来源桥只操作 Buildr 私有配置，不能自动读取桌面默认目录。
3. **协议**：暴露 Responses、Chat Completions、Messages，适配器保留原始协议对象。同协议优先直通；跨协议转换保留消息顺序、角色、工具调用身份、图片和来源限定的推理信息。不支持的语义准确报错，不静默丢弃。
4. **消费者**：Codex 使用私有网关配置和匹配已装版本的模型目录；Qoder 使用 `resolveModel`；DSH 使用自有 overlay 的 `llm-pi-ai`。原厂登录不是统一网关推理的通用前置，Qoder 自身启动认证单独检查。
5. **绑定**：网关以受限本机凭据/路由绑定账号、模型与对话；每轮不可变。登录和断开轮换本机接入身份，普通检查不轮换；界面仅在来源身份未变时刷新观察版本，避免旧上下文或旧付费选择被用于新账号。执行环境可使用稳定网关身份和模型路由。跨来源上下文不兼容时复用现有可见历史接续机制，新建准确原生上下文，旧绑定保留。刷新未知执行不重发。
6. **Devin**：参考 DSH 镜像 `7c6d13b4f1b7801c36e6ce8d154ce7b90ae923b4` 的 PKCE/Connect/protobuf 与 CLIProxyAPI `bc0643405a1d0adf77dd0f109972ac3313d66397` 的转换边界，保留 MIT 来源与许可证。动态模型变体映射，终止帧错误不冒充成功；无 refresh grant 时重新核验/登录。
7. **界面**：账号配置中区分程序与模型套餐；模型选择保留来源分组，执行历史显示真实来源；额度支持不可读与更新时间。提供同一公开应用接口供界面、HTTP 及智能体（Agent）发现，不新增自动选账号或付费回退。

## Risks / Trade-offs

- Qoder 自定义本机地址、辅助模型调用及平台认证差异 → 使用已装 SDK 验证主请求、标题、压缩和子执行，不以模拟返回代替真连接。
- Qoder 个人套餐没有已证明输出路径 → 单独记录可用性缺口，不把云端智能体任务包装为裸推理。
- 私有模型协议漂移 → 固定参考版本、窄适配与协议替身测试；真实套餐额度另行验证。
- 并行登录刷新可能覆盖新凭据 → 凭据 owner 唯一，按观察版本比较更新与失效。
- 停止不代表已产生费用撤销 → 中止上游传输并保留已发生调用与未知用量。

## Migration Plan

保留现有连接、原生配置与对话；新选择来源时才建立网关环境。不批量移动旧凭据。新增字段缺失按原生模式解释。取消新模式可继续旧原生路径，保留真实历史。正式入口说明需随实现校准；仅验证不自动激活保留自举环境。
