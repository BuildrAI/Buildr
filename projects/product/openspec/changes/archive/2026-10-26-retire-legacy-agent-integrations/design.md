## Context

动机与授权见 proposal.md。统一模型能力已拥有账号、模型目录、版本检查、协议转换、取消和凭据；旧代码模块直接依赖旧生成应用。任务页同时展示内部对话和外部关系。

## Goals / Non-Goals

目标是统一模型配置和单次生成入口，彻底去除外部关联。内部对话、账号和任务事实保持现有所有权；不迁移外部聊天，不移除 DSH 插件的网页席位。

## Decisions

- 单次生成属于智能体私有库的应用能力，通过现有模型租约调用；不创建持久对话、不提供工具，不再另建供应商后台。业务模块继续准备材料并验证结果和来源版本。
- 生成请求显式固定账号、模型、账号身份与观察版本。界面从现有模型目录选择，不恢复旧默认智能体；未选择模型时仅禁用生成，手填与提交照常。
- 生成具有短期内存状态和准确取消身份，查询及取消由所属工作空间保护；调用时限覆盖准备和响应读取，失败不重发、不切换账号，迟到输出不替换草稿。
- 退役旧模块、契约、命令、按钮和技能自动关联指引。启动时只清理当前配置与已登记工作空间中已知的旧关系文件；符号链接或非普通文件局部报告，不跟随删除，不备份。清理失败不阻止其他功能。
- DSH 插件保留网页入口和启动管理，去掉桌面生成与会话导航服务。替代方案保留旧桥会形成未使用的认证与监听面，因此不采用。

## Risks / Trade-offs

- 删除关系不可恢复 → 用户已明确授权不保全，只删除 Buildr 自有固定文件，不访问厂商聊天或账号。
- 模型协议返回结构不同 → 复用现有统一协议转换，业务仍校验提交说明与来源；不以提示词替代工具隔离。
- 旧客户端仍调用旧接口 → 退役后不再路由，不提供恢复关联或旧生成的兼容入口。
- 现有活跃任务可能修改相邻界面 → 独立工作树实施，不修改其他任务位置，交付时核对差异。

## Migration Plan

先完成新单次生成及其边界测试，再切换业务与前端，随后删除旧实现和清理数据。更新相关技能源与当前说明。回退代码不会恢复已删除关系，不能宣称可恢复历史；外部聊天不受影响。

## 规范退役表达

旧 Codex 协作和跨提供者关联保留最小退役约束：旧入口不得恢复登记或关系，旧文件按固定范围清理。原有协作要求全部移除，保留的条目只表达已确认的退役结果与删除边界。
