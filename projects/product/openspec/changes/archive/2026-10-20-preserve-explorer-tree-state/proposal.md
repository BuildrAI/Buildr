## Why

工作树（Worktree）选项把多库目录名无限换行，挤占下拉列表。用户切换到源代码管理（Source Control）再返回时，文件树又被清空展开状态，无法接续浏览。旧资源管理器（Explorer）规范要求重进即折叠，与较新的跨入口保留现场规范冲突，需按本次明确需求统一。

## What Changes

- 普通导航往返保留用户展开和折叠的目录；首次进入仍默认折叠，显式文件定位仍展开对应祖先。
- 工作树（Worktree）选项主名称限制为单行省略，保留真实完整名称、路径提示、角色及数量。
- 预览文案最终统一：只给真实 Git 主工作树（Main Worktree）标注“主工作库”；其他目录无角色标签。主工作库在下拉列表中固定排在其他目录前面，同类选项保持原顺序；排序不改变当前选择。目录接口附带可选的 isMain 观察字段，由 Git 当前列表确认，与登记或预览位置无关；未知或混合组选项不冒称主目录。帮助文字只说明选择对应目录查看文件。
- 提升展开速度：明确默认目录的只读操作避免重复枚举无关工作树（Worktree）及任务关联；移除资源管理器（Explorer）收展动画，保留已有目录结果与真实校验。
- 不改变来源身份、筛选、读取与写入授权，不涉及数据迁移或破坏性接口变化。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `repository-file-explorer`：将普通重新进入即折叠改为同一保留页面内维持目录现场；约束工作树（Worktree）组选项的展示高度。

## Impact

影响 Buildr Web 的 `CodeExplorerPage`、`RepositoryFileBrowser`、局部样式和资源管理器（Explorer）浏览器检查，以及 Buildr 只读代码应用的默认目录解析与对应检查。无需新增依赖、服务端接口或持久状态。
