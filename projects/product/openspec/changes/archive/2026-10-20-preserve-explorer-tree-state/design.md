## Context

见 `proposal.md`。代码区域通过现有页面保留机制维护资源管理器（Explorer），目录展开状态已由 `RepositoryFileBrowser` 的局部状态保存。丢失现场源于路由（Route）变化后主动清空，不是缺少状态存储。下拉选项的真实名称集合已正确生成，异常源于允许无限换行。

## Goals / Non-Goals

保留同一页面生命周期内用户的目录现场，并限制选项高度。无需刷新网页后恢复状态，无需新增全局状态或本机持久化；不改变跨代码库身份和工作树（Worktree）分组。

## Decisions

- 移除普通导航产生的折叠请求，复用页面已有局部状态。首次状态仍为空，显式文件定位仍合并必要祖先。相比新增存储与恢复逻辑，此方案直接消除覆盖现场的原因，也保留用户手动折叠的选择。
- 搜索期间只隐藏现有树组件（Tree Component），恢复目录时复用同一实例，避免底层在重新挂载（Mount）时根据子目录自动展开用户已折叠的父目录；仍保留父目录内部的展开记忆。
- 名称集合单行省略，辅助角色和目录数量独立显示，已有悬停提示保留完整路径。相比仅显示首个名称，不会冒称整个多库范围；相比无限换行，不会占满选项列表。
- 修改旧规范中“保留页面重新激活也全部折叠”的承诺，与较新的 `code-source-control` 跨入口保留现场要求统一。
- 预览文案最终统一：只给真实 Git 主工作树（Main Worktree）标注“主工作库”；其他目录无角色标签。主工作库在下拉列表中固定排在其他目录前面，同类选项保持原顺序；排序不改变当前选择。目录接口附带可选的 isMain 观察字段，由 Git 当前列表确认，与登记或预览位置无关；未知或混合组选项不冒称主目录。帮助文字只说明选择对应目录查看文件。
- 性能追加：真实默认目录请求初测476–608毫秒。只读目录、文件和搜索在未指定任务且明确检出身份匹配登记目录时，直接采用该目录的当前身份，不枚举所有关联目录及任务证据；不同检出、明确任务及历史读取仍沿用既有路径。所有读取继续保留路径包含关系、忽略边界和结束时身份校验，Git 写入调用不启用此优化，不使用跨请求身份缓存。
- 资源管理器（Explorer）禁用目录收展动画，避免已读取目录仍等待动画，以及动画期间不能连续展开。沿用现有按来源、忽略条件和路径缓存与刷新机制，不预读整棵树或新增全局缓存。

## Risks / Trade-offs

- 长名称无法在单行全部显示 → 保留完整文字、搜索、路径提示及目录数量；通过窄宽度浏览器（Browser）检查确认可选择。
- 移除重置可能影响显式定位 → 回归首次进入、未打开文件时的手动展开与折叠、已打开文件往返、刷新及同文件再次定位。
- 无数据或接口迁移；交付为前端构建更新，回退可恢复既有代码。
