## Context

现有发布编排（Release Orchestration）已把正式发布与后续任务登记、资源清理分开；Git 收敛及生命周期仍要求正式发布分支存在。现有操作文件可保留派发意图与上下文，不需要新增状态库。见[提案](proposal.md)。

## Goals / Non-Goals

- 目标：在同一发布授权范围内清理本轮确定的引用，允许清理后从真实发布事实继续恢复。
- 非目标：批量清理历史分支、改变发布产物、修改主线、删除官方标签或新增通用 Git 管理。

## Decisions

1. **授权随本轮派发意图绑定。** 新发布把清理政策及上下文身份写入已有操作文件；恢复只消费匹配记录。单纯升级工具或恢复旧发布不形成删除授权。底层独立清理入口仍要求显式删除参数。
2. **源码保全依靠历史关系。** 删除前验证远端版本标签与发布提交一致、发布源码确实位于该提交历史中、当前主线仍包含该发布提交。同文件树不能代替历史保全；旧压平合并记录保留原引用。
3. **幂等清理属于现有 Git 责任方。** 先核对完整资源清单；存在的本轮引用必须匹配预期提交，以已观察值进行条件删除；不存在的引用在官方证据有效时属于已清理。其他版本及未知资源不纳入。
4. **兼容两种历史结果。** 生命周期接受已核验保留与已核验清理；只有新政策绑定成功的标准发布执行正式分支删除。恢复不重新创建分支、打包或发布。
5. **知识只维护唯一正文。** 发布流程正文说明具体条件和恢复；技能指向该正文，避免复制流程。代码地图与系统图的职责关系未改变，无需重画。

## Risks / Trade-offs

- 删除后恢复误依赖原分支 → 以发布证据中的完整源码提交及远端标签重验，测试重复恢复和登记失败后的接续。
- 核验与删除之间分支移动 → 使用已有按预期提交删除及远端回读能力，保留冲突事实。
- 旧授权被扩大 → 缺少匹配清理政策时保留原分支，测试历史操作文件。
- 平台拒绝删除 → 如实报告清理受阻，发布成功事实保持；本次测试仅使用隔离本地远端，不声称验证生产权限。

## Migration Plan

新版本从下一次明确授权发布开始应用清理政策。历史发布记录保持原行为；已删除分支可凭完整保全证据继续恢复。回退旧工具前须认识其仍依赖分支，不自动重建已清理分支。
