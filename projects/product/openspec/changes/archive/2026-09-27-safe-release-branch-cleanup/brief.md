# 发布成功后的分支清理

用户希望发布成功后自然清理临时发布分支，而不是每轮遗留远端引用。本次实现未来发布的清理与恢复，不批量删除历史分支。

验收：新授权发布成功后清理本轮分支，官方标签与源码历史完整；引用漂移、标签缺失或源码未保全时拒绝删除；删除后重试不重发产品；旧发布没有新授权时不删除。

当前知识影响（assess）：`knowledge/docs/flows/open-source-release.md` 的保留策略必须更新；`skills/buildr-release/SKILL.md` 指向唯一正文。职责目录和系统关系没有变化，现有代码地图及技术图仍适用；无新术语，不新增图、地图或长期文档。

实现及检查：发布流程正文与技能已更新（reconcile）；现有图和代码地图仍适用。四个现有测试文件的 32 项检查全部通过，覆盖隔离本地远端的真实删除、删除后任务登记失败接续、标签保留、同树但历史未保全、分支漂移、新旧授权及不同发布上下文。未执行 GitHub 生产分支删除、平台审批或 npm 发布。
