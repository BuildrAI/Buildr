# 任务与 Git 提交双向关联

关联任务：`2026-09-27-task-git-commits`。

用户需要在一个任务内看到多次 Git 提交（Commit）的说明与哈希值（Hash），同时在每次有明确任务的提交说明（Commit Message）中记录任务编码。普通提交归属一个任务，无任务的提交继续可用。

用户已确认可交互界面原型（UI Prototype），本轮实施真实 Git 提交关联。原型已按任务关联的规范变更（OpenSpec Change）组织，入口为 [任务提交记录原型](ui-prototype/task-git-commits.html)；正式界面可通过任务“方案设计”阅读关联原型。原型使用模拟数据，不能证明真实 Git 查询、编码写入或双向关联已经完成。

候选界面在“任务收尾”后增加第五个阅读标签“提交记录”，不增加工作阶段。查看重点是多条说明与哈希值（Hash）的可读性、完整信息展开与复制，以及空状态、读取失败的区别。编码格式与成立条件见 [设计](design.md)，可验证承诺见 [规范](specs/task-git-commit-links/spec.md)，实现与验证进展见 [实施清单](tasks.md)。

本需求不包含代码差异浏览、分支管理、历史改写或复杂统计。用户已另行授权修复原型默认归入、无关联变更的任务发现，以及独立预览复用统一阅读器；这些修复按实施清单第 1 组独立验证，不能代替真实 Git 关联实施。实施沿用已确认布局，去掉展开详情中重复的“关联当前任务”行；完整提交说明中的任务编码保留。真实读取、正式页面和提交技能（Skill）接入已实现，并通过隔离 Git 往返、契约、回归及宽窄屏浏览器验证。当前成果位于任务工作树（Worktree），尚未提交或安装到运行中的 Buildr Web；后续收尾须完成实际交付与自举同步，不能把候选验证当作安装结果。
