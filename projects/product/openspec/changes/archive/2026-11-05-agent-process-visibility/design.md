## Context

当前 DSH 执行器在投影时直接丢弃 `reasoning` 片段（`executors/dsh/protocol.ts`），条目类型只有 `message | tool | notice | handoff`；渲染侧对旧的 `thinking` 标记条目执行 `continue` 跳过。共用交互指引已要求工具执行前先给可见说明，但没有运行期观察：模型连续多步不说话时，界面只剩工具调用。

## Goals / Non-Goals

**Goals:**

- 思考片段有独立、可折叠的展示位置，且不改变既有对话语义。
- 连续无说明时给模型一次轻量提醒，不引入拦截或新的门禁。

**Non-Goals:**

- 不改变工具组折叠、最终答复选择、停止与重试。
- 不为 Codex / Qoder 增加提醒（它们的提示词通道不同，本次只做 DSH）。
- 不迁移历史记录，不清理已落库的思考条目。

## Decisions

**1. 新增条目类型 `thinking`，而不是复用 `message` + `thinking` 标记**

用户明确要求思考不能作为助手步骤消息。新增 kind 让语义在数据层就分开：最终答复选择、模型历史、标题、交接、工具分组、步骤计数都按 `kind` 过滤，天然排除思考。旧的 `thinking: true` 标记继续保留并映射到同一渲染分支，保证历史一致。

**2. 投影顺序与消息内容一致，只有签名的不产生条目**

DSH 的 `assistant/message` 可能同时带 text、reasoning 和 tool-call。按内容顺序分别产条目，保证折叠块落在实际位置。只有签名、没有明文的推理没有可读内容，不产生条目。

**3. 折叠块不预渲染 Markdown**

思考可能上万字。折叠态只显示「思考 · N 字」；展开时才挂 Markdown 渲染，避免长过程里每轮都付出渲染成本。

**4. 提醒做成独立的 DSH 插件，按连续步数触发**

插件监听 DSH 的 `session/event` 统计「连续没有可见文本的助手步」，在 `agent/pre-step` 瀑布里委托下游决定后，达到阈值（默认 6）且本段未提醒过时追加一条来源为 `buildr:narration-reminder` 的用户角色上下文消息；出现可见文本即清零。提醒本身会以 `user/message` 回放进会话事件，因此计数只响应来源为空或 `user` 的真实用户消息，避免自己重置自己。不采用 `inbox.prepend('next-step', …)`：那会额外开启一个步骤，而这里只需要在同一步的请求里多一句上下文。

**5. 提醒不进对话主线**

Buildr 的投影只接受 `source.kind` 为空或 `user` 的用户消息（`isUserInput`），提醒的来源标记因此不会产生用户气泡，也不会进入交接材料。

**替代方案**：在静态提示词里加重语气——已证明模型会忽略，且无法按现场调节；在 Buildr 侧合成说明文字——违反「不得以事后生成的叙述冒充助手原话」。

## Risks / Trade-offs

- [提醒对模型无效] → 提醒不阻塞执行，最差退化为现状；效果按真实会话核对，不宣称必然提升。
- [思考内容过大拖慢页面] → 默认折叠、展开才渲染；沿用现有详情加载路径。
- [提醒进入 DSH 原生历史] → 来源为插件标记，Buildr 侧过滤；DSH 桌面端查看时可能看到一条上下文消息，属于可接受的取舍。
- [阈值过低导致刷屏] → 同一段连续无说明只提醒一次，出现可见文本后重置。

## Migration Plan

无数据迁移。旧条目按 `thinking: true` 渲染；提醒插件随执行器启动生效，阈值由执行器装配时的插件配置给出，移出补丁列表即可停用。

## Open Questions

- 阈值 6 是否合适，需要在真实会话里观察后调整；不改变规范。
