## MODIFIED Requirements

### Requirement: 历史已释放未知不得单独保持对话活跃
系统 MUST 在摘要、已读和历史列表查询中一致解释历史执行。当前执行已结束且历史未知执行没有明确 active 状态、也没有 running 或 unknown 工具时，历史未知本身 MUST NOT 保持对话活跃，无论其控制资源是否已记录释放。未知执行和工具证据 MUST 保留，真实活动工作、未读和有效问题 MUST 继续可发现。旧派生摘要 MUST 按相同规则解释，不要求用户发送新消息。

#### Scenario: 旧摘要仍标活跃
- **WHEN** 历史未知没有在途工作但旧摘要仍为 active，当前已完成且所有消息已读
- **THEN** 列表 MUST 按普通历史对话处理，重开和标记已读不恢复错误活跃，原未知结果保持不变

#### Scenario: 历史存在真实在途工具
- **WHEN** 历史执行存在明确运行中或 unknown 工具，或 active 执行状态
- **THEN** 系统 MUST 保留活跃，不以缺少释放记录或旧摘要掩盖真实在途工作

#### Scenario: 未受理旧轮没有在途工作
- **WHEN** 旧轮 accepted=false、status=unknown、没有工具和执行引用，当前轮已完成且消息已读
- **THEN** 历史旧轮 MUST NOT 单独保持对话活跃；unknown 记录、诊断和送达未知事实 MUST 保留

#### Scenario: 未读和有效问题
- **WHEN** 当前执行已结束但存在未读消息或有效待回答问题
- **THEN** 对话 MUST 继续保持活跃并可发现

### Requirement: 对话搜索必须匹配可解释内容并返回命中片段

对话搜索 MUST 以对话标题、对话 ID 和用户、助手可见消息为范围；工具调用与输出、通知、handoff、思考片段 MUST NOT 单独构成命中。关键词去除两端空白后按空白拆分为多个词项，每个词项 MUST 至少命中对话 ID、标题或一条可见消息，全部词项满足时才返回该对话。对话 ID 使用不区分大小写的子串匹配，不要求完整 ID。搜索范围 MUST 在单空间与“全部工作空间”视图保持一致。命中发生在可见消息时，列表响应 MUST 返回该消息的有界片段，片段 MUST 来自实际匹配的可见消息且 MUST NOT 改写历史记录；ID 或标题已命中时 MAY 省略片段。关键词、工作空间或筛选变化后，旧读取结果 MUST NOT 覆盖当前结果，分页 MUST 只使用当前关键词对应的有效位置。

#### Scenario: 标题和可见消息参与搜索

- **WHEN** 用户输入关键词，对话 ID、标题或某条用户/助手可见消息包含该关键词
- **THEN** 系统 MUST 返回对应对话，并在命中可见消息时返回有界命中片段

#### Scenario: 仅 ID 子串命中

- **WHEN** 用户输入对话 ID 的一部分，标题和用户/助手可见消息均不包含该片段
- **THEN** 系统 MUST 返回该对话，且 MAY 不返回消息片段；匹配 MUST 不区分大小写

#### Scenario: 工具日志不构成命中

- **WHEN** 对话只有工具调用、工具输出、通知、handoff 或思考内容包含关键词，ID、标题和用户/助手可见消息均不包含
- **THEN** 系统 MUST NOT 将该对话作为搜索结果返回

#### Scenario: 多关键词按 AND 匹配

- **WHEN** 用户输入由空白分隔的多个关键词
- **THEN** 系统 MUST 只返回每个关键词都命中对话 ID、标题或任一用户/助手可见消息的对话

#### Scenario: 搜索变化时旧结果不覆盖

- **WHEN** 用户快速修改搜索关键词或切换工作空间，旧关键词请求随后返回
- **THEN** 列表 MUST 继续展示当前关键词对应的结果，旧结果 MUST NOT 覆盖当前范围或游标
