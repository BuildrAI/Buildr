## Context

现有主题导航、右侧分页卡片和文档章节列表分别维护搜索、选中与展开；主屏和服务侧读又有不同导航生命周期。原因见提案。真实正文仍由已登记成果或有界文档发现读取，索引已支持默认主题和可选章节。

## Goals / Non-Goals

**Goals:** 将选中正文与目录查询解耦，复用已有阅读器；两种模式提供相同空间结构、有效默认入口及可恢复的阅读上下文。

**Non-Goals:** 不做全文检索、不新增正文编辑、远程搜索、数据库、依赖或独立文档站；不扩大文件访问权限，不改变接续智能体（Agent）的执行方式。

## Decisions

1. **同一阅读框架。** 顶部切换阅读方式，宽屏左目录右正文；窄屏及侧读目录可折叠，搜索仍处于目录上方。正文标题留在阅读区，页面标题稳定表示范围。探索和建设动作移到页级动作区；同一主题的说明、图和地图从其目录分支选择，正文不再重复一排分类。删除竞争性的右侧全局分类、搜索及大卡片目录。
2. **完整轻量导航。** `navigation` 在现有主题摘要旁新增 `artifacts`，只含 `id/title/kind/path/objects`，沿用索引最多500项及体积限制。搜索可结合一次返回的主题说明，不把长说明重复到每个成果。无需逐页请求所有正文或完整来源。原 `catalog` 的20项分页、游标和版本约束保持，供既有调用者使用。
3. **独立查询与阅读状态。** 按范围和阅读方式保存查询、类型与树展开，选中正文独立。搜索匹配标题、主题或章节说明以及兼容路径；临时展开命中的祖先与补充材料，不修改用户原展开集合。清空搜索恢复集合，切换正文保留查询。不同范围隔离状态，浏览返回恢复适用定位；异步旧响应不覆盖新范围。旧明确对象、成果、来源或文档地址优先，不被默认入口覆盖；`browse=all`继续进入主题阅读，默认入口可读。
4. **现有文件作为入口。** 索引可选 `entryDocument: { location?: string, path: string }`，默认位置为`scope`。它与章节编排一样独立容错，只匹配当前安全发现的文件，文档响应新增`entryDocumentId: string|null`。未配置或失效时保留目录与选择提示，不猜首条、不扩大扫描。入口条目放左树顶层、章节中去重，计数仍是同一个真实文件。索引读取旧投影剥离此辅助字段，坏入口不破坏主题。
5. **内容只做必要校准。** 自举项目主题入口保留`product-overview`，《Buildr 使用与开发手册》从补充材料提升为文档入口。维护该正文、知识维护说明、实现地图及有关索引格式参考，不新增手册。现有结构图职责关系仍成立，不因布局变化重画。

## Risks / Trade-offs

- 完整导航规模大于单页 → 只读取有界元数据，不携带正文或来源；不重复主题长说明。
- 成果关联多个主题 → 允许多处链接但同一身份与正文，数量按唯一成果计算；未关联成果仍可检索。
- 默认入口与旧地址竞争 → 明确定位优先，搜索与类型变化不得重置右侧正文。
- 主屏和侧读出现差异 → 共用目录模型和渲染，分别验证历史返回、不同宽度、无索引和局部错误。
- 入口移出章节使计数难理解 → 入口全局只计一次，章节显示实际剩余项，补充材料全部参与搜索。

## Migration Plan

响应只增加字段，旧索引不必迁移，原分页接口保留。构建和回归通过后按当前任务交付并由唯一自举执行器更新本机。出现问题可按实际提交回退实现和可选入口配置，正文无需移动。
