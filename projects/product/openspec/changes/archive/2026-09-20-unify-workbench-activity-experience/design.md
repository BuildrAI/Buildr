## Context

见 [提案](proposal.md)。现有任务列表同时使用旧管理容器和新列表边框。工作概览读取显式关注请求。每日演进的摘要已位于工作台，但完整视图仍由项目副屏承载，摘要链接没有日期。底层只读数据来源已一致，无需改动接口（API）与存储。

## Goals / Non-Goals

**Goals:** 使用同一动态页承载摘要及完整阅读，以网址（URL）中的项目、日期和分组保留用户现场；清楚区分待答复事项与普通待办。

**Non-Goals:** 不新增自动执行、通知、数据生成或报告审批；不重建页面设计系统，不改变任务状态与每日演进存储。

## Decisions

1. `/activity` 或仅含 `project` 的地址展示最近摘要，明确 `project` 与 `date` 时展示完整详情。复用已有详情组件，日期与分组由地址控制，避免复制另一份读取与分组实现。
2. 项目主页以“项目动态”作为工作入口，保留项目资料用于文档。旧 `?document=daily` 使用替换导航进入动态页，已有日期保留，缺省延续本机今天；历史摘要链接始终带实际日期。
3. 日期使用本机日历日，生成指令采用页面当前日期。刷新同时更新当前读取；切换项目或日期时清理旧内容并防止过期响应覆盖。任务链接携带返回地址。
4. 回应区域保留现有显式请求来源和答复机制，标题改为“等我回应”，解释三类事项。空态以一行状态显示；异常仍局部可见。
5. 任务表格仅保留内部边框；加载区只在确实有续载动作、加载状态或错误时存在，保留已有元素标识。

## Risks / Trade-offs

- 旧链接或已收藏入口 → 保留重定向并验证日期传递。
- 摘要与详情发生日期错位 → 项目、日期、分组均按同一地址读取；检查刷新和前进后退。
- 原分组或任务导航丢失 → 保留四问、提交、三个查看维度和任务返回路径，实际浏览器验收。
- 跨页样式相互影响 → 使用功能范围内的样式，并验证窄屏。

## Migration Plan

无数据迁移。随前端构建交付新入口和旧链接兼容，回滚前端即可恢复旧入口，既有数据不变。
