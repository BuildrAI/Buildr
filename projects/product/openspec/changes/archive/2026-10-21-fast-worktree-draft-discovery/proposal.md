# Change: fast-worktree-draft-discovery

## Why

文章列表为发现任务工作树草稿，每次请求对每个已登记来源执行全量 Git 身份核对；在含多个独立 Git 仓的工作空间中，单次列表产生约 170 个同步 `git` 子进程、耗时约 2.5s，并以 `spawnSync` 阻塞本机 Web 的事件循环。草稿发现只需要低代价观察，完整核对可以下沉到真正读取与写入的时刻。

## What Changes

- 文章列表改为从已登记任务工作树证据与文件系统观察发现草稿：读取证据登记的检出位置下 `docs/publications/`，以文件系统级核对（检出目录存在且非符号链接、`.git` 指向登记来源的 Git 公共目录、当前分支与登记一致）替代列出前的完整 Git 身份核对。
- 工作树文章的详情、原文、资源、编辑与保存维持现有完整核对（任务范围、项目登记、工作树身份与内容版本）不变；失效来源在打开时按既有错误拒绝。
- 登记后检出位置被移除或文件系统核对不一致时，该来源不列出草稿并产生局部诊断，不影响其他来源与主目录文章。
- 无破坏性迁移；列表响应结构、来源任务标记与版本字段语义不变。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `buildr-web-workspace-application`：工作树草稿发现的依据与核对时机——发现改用登记证据与文件系统观察，完整身份核对保留在访问时刻。

## Impact

- `services/buildr`：publication worktree reader 的列表路径改为轻量发现；task worktree provider 需要补充以文件系统观察实现的证据枚举能力；相关单元与集成测试同步更新。
- 行为影响：登记后工作树漂移时，列表表现为"不列出该来源草稿 + 局部诊断"，而非列出前完成 Git 核对；打开或编辑仍按完整核对拒绝。
- 无依赖、构建、部署或发布变化。
