## Context

目录只读索引元数据，正文另行读取。当前主题树逐一列出全部成果，因此正文内嵌图又成为目录项；已有 `relations.kind: contains` 能表达包含关系。动机与范围见 proposal.md。

## Goals / Non-Goals

- 目标：共享导航自动合并已声明包含关系的图入口，并保留检索和独立阅读；统一智能体会话用语，把主题文章组织为连续章节。
- 不改变成果身份、图展示及读取边界，不预读所有正文，不新增隐藏字段或依赖，不改变智能体执行、协议及关系数据。

## Decisions

1. 复用 `contains` 表达内嵌图或地图，`guides` 表达文章中的真实图或地图参考链接，按实际 Markdown 引用校准 Product 全部主题。运行时只从索引传递有界、合法的包含关系；不扫描正文，也不引入第二个手工隐藏状态。
2. 主副屏共享目录计算。主题中已有可达文章承载时取消对应图和地图节点；文章吸收图与地图的名称、路径和类型匹配。图没有承载说明的主题、未归类独立图、旧索引继续可达。文档目录保持实际 Markdown 文件条目和扫描范围，仅补已登记文章的图地图检索信息；地图实际文件不被主题规则移除。
3. 目录数量按实际阅读入口去重；后台 `artifactCount` 仍表达全部登记数，仅用于已有知识判断。全文和图读取保留原索引，显式旧图链接及文内独立查看不受目录合并影响。
4. 产品用“会话（Session）”表示带身份与上下文的智能体工作单元，持续或临时均可；“对话”表示交流内容。Codex 原生 `thread`、ACP `session`、代码标识和参数保持各自语义。
5. 主题只组合直接归属文章，按索引顺序以文章标题分章；共用章节定位行为，当前主题目录或文内文章链接定位本阅读面内章节，不新建路由或副屏历史。主题外条目、文档目录和明确单篇地址保留原行为；子主题独立，不递归拼接。
6. 正文保持一份可独立阅读的来源，不写手工上一章、下一章或返回导航。现有知识维护技能说明标题、顺序、引用与简练原则；确定性阅读行为由组件负责，不增加配置或技能。

7. 参考关系只影响同组可见文章已承载的重复入口；独立或仅图地图主题保持可达。保留既有非图承载者包含图的能力，新增包含地图和普通参考只由文章承载，并忽略自引用。图与地图可按真实关系逐层查到最终文章，遍历有界且终止循环，不新增持久状态。

## Risks / Trade-offs

- 包含登记可能与正文脱节 → 本轮核对全部现存嵌入链接并覆盖消费者；维护图文时同步包含关系，无有效关系时按旧目录显示。
- 误隐藏其他主题唯一图入口 → 仅在同一目录分组存在可达承载说明时合并，并验证多主题、仅图主题和独立链接。
- 正文加载后目录恢复重复 → 主副屏的元数据与完整索引均传递同一包含关系到共享函数。
- 会话与本机 HTTP 会话同词 → 术语表显式限定智能体作用域，不混用进程、对话或身份协议。
- 主副屏同时出现同文 → 章节定位限定当前阅读根，并复用已有滚动容器和恢复行为；正文加载失败不伪造章节。

## Migration Plan

增加向后兼容的导航关系元数据，校准当前索引；旧索引无关系继续原行为，旧图标识与链接保留。回退代码不影响知识正文、图源和会话关系。执行针对性逻辑测试、闭合契约检查、构建与主副屏实读；本轮不发布或调用模型。
