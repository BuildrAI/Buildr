## Context
沿用 ConversationEvents 的统一提交出口，不接管执行器，也不写任务或对话记录。见 proposal.md。

## Goals / Non-Goals
覆盖每次视图发布及可见消息更新；不提供入站控制、不转发内部思考与原始工具内容，不扫描历史补发，不提供可靠投递保证。

## Decisions
- conversation_updated 包含 revision、进程 generation、递增 sequence、运行状态、待回应请求快照、关闭卡片标识及消息增量。旧四类通知保持原有事件标识与摘要。
- 助手/用户 message 正文进入事件，以便接收方对齐目标；tool 仅发送身份与状态，不发送 input/text/name；notice/handoff 仅发送元数据。问题卡片发送标题、描述、问题选项；审批仅发送身份/种类，不发送可能含命令的正文。所有外发字符串替换已知 webhook 地址与密钥。无法泛化识别任意正文中的未知秘密，调用方仍须避免在聊天中粘贴凭据。
- 启动后的首次视图只发送启动后创建的消息；建立已有消息指纹，后续流式更新按内容版本发送，避免同一内容重复、又保留旧消息的新变化。不宣称消息已最终完成。
- 请求消失只表达 closed，不猜测已回答、取消或审批同意；其后的运行变化及用户回复继续作为事实发送。
- 配置文件为 {url, secret}，由 BUILDR_AGENT_WEBHOOK_CONFIG 指定路径或真实宿主主目录默认路径。仅接受当前用户所有的私有普通文件，拒绝链接、组/其他用户权限及过大内容。显式/存在文件无效时关闭通知，避免误用旧地址；无文件时兼容旧环境变量。
- 16 并发和 512 待发送项及 16 MiB 等待正文上限吸收正常流式突发；队列满、失败与退出仍可能丢事件，不重试。接收端用 generation/sequence 排序及 eventId 去重。诊断不记录 URL、秘密或响应正文。

## Risks / Trade-offs
正文外发扩大数据面 → 明确只对授权接收端启用，过滤内部思考/工具内容并脱敏已知配置。有限缓存淘汰、进程重启和网络失败 → 明确尽力投递边界，不把 HTTP 成功等同 Bot 处理成功。

## Migration Plan
安全创建 ~/.buildr-webhook.json 并验证内容与权限，旧文件仅在逐字核验未变化后移除。候选代码通过验证后仍需交付并走唯一自举激活入口；用户后续已授权必要交付与正式激活，仍不修改任务数据、不强停其他执行。回退时移走统一文件可恢复旧环境变量入口，不覆盖对话或任务库。
