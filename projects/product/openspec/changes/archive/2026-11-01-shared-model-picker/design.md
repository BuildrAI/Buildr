## Context

动机见 [proposal.md](proposal.md)。当前 `ExecutionModelSelect` 以平铺菜单记住执行模型；对话输入已具有来源分组、搜索、推理强度与服务档位交互。`agent-conversations` 已承诺两类偏好独立，不能因复用界面回退。提交生成经代码模块短期请求调用统一模型能力，已有 `serviceTier`；本次仅新增可选 `reasoningEffort` 的贯通，不重做执行协议。

## Goals / Non-Goals

**Goals:**
- 统一模型选择的展示与操作，公共界面不依赖对话功能模块；模型目录、偏好所有权和生成副作用边界明确。
- 显式受支持参数准确执行，旧偏好和未传参数的调用继续可用。

**Non-Goals:**
- 不合并对话和提交的偏好、已发送运行记录、草稿或上下文统计。
- 不新增状态库、账号目录、模型提供者、工具能力、持久对话或自动生成/提交；不更新运行中的开发应用。

## Decisions

1. **受控公共界面 + 场景适配。** 从对话输入抽出搜索、账号分组、状态、强度与档位控件至 `src/components/`，共享纯映射留在 `src/lib/`。调用方提供候选、当前选择、能力与操作回调，组件只持有本实例弹层等临时状态。不选择“让提交引用对话局部组件或上下文”，以免反向依赖及用量泄漏；也不复制两份控件，避免交互继续分叉。
2. **共享事实，不共享偏好。** 对话继续拥有自己的模型、档位和按执行方/来源/模型保存的强度记忆；提交执行入口使用独立存储键和内存状态，记住模型、档位及各模型强度。选择恢复须按当前账号身份与模型能力核对，档位变化后不发送已失效强度。保留现有执行模型身份键，扩展参数采用独立且可选的兼容存储；存储失败只退化为当前页面状态。公共组件不读写存储，也不以共享目录缓存混存场景选择。
3. **显式强度优先，缺省仍轻量。** 提交请求的 `reasoningEffort?: string` 与既有 `serviceTier?: string` 一同从前端选择经 HTTP、应用输入传到统一 `generate`。准确身份和观察版本继续必需；支持性仍由当前目录及模型能力校验，不猜测或静默替换无效显式选择。未显式指定时沿用现有最低可排序推理强度或模型默认策略，不改变账号全局配置。使用统一模型能力现成校验，不新增重复的提供者分支。
4. **保留紧凑入口。** 提交区域仍用生成图标和选择入口，不常驻模型控制面板，也不展示对话上下文用量；详细配置按需展开，鼠标与键盘行为复用已有交互。对话上下文用量继续属于对话输入区，不成为公共模型控件属性。

## Risks / Trade-offs

- [抽取丢失对话键盘、焦点或来源定位行为] → 两入口复用同一组件，并以针对性交互回归覆盖搜索、分组、强度、档位与关闭/恢复。
- [存储键复用导致场景串扰] → 分离持久键与内存状态，覆盖切换模型、刷新、同页面双入口及存储不可用。
- [目录或档位变化使已记强度失效] → 恢复时核对当前能力，无有效偏好时使用当前轻量默认，不传失效参数。
- [旧规范将轻量等同固定最低强度] → 本变更显式修订 `code-source-control` 两个相关要求，保留有界材料、60秒预算、无工具、来源/草稿保护与失败隔离。

## Migration Plan

无需数据迁移或新增依赖。保留现有模型身份偏好及对话存储语义；新增提交强度/档位偏好可缺省。旧客户端不传 `reasoningEffort` 时保持原有行为，服务档位字段不改名。回退代码时旧模型选择仍可读取，额外偏好可忽略；不能因此清空对话偏好或改写历史。

实现后按实际职责路径校准 `knowledge/docs/architecture/agent-integration-generation.md` 第9行及必要实现入口，保留其材料与取消说明；只做有界知识复核，不新建图、地图或第二份需求正文。
