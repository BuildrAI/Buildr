## MODIFIED Requirements

### Requirement: 紧凑提交说明与操作

未提交变更模式 MUST 在文件列表前提供默认单行说明输入框、右侧紧凑生成图标及模型选择入口，下方提供提交主按钮与提交并推送选择。多行说明 MUST 在同一输入框按需扩展；功能区域 MUST 不单独常驻执行者名称。模型选择 MUST 复用对话输入区的公共交互，提供搜索、账号来源分组、可用状态及当前模型支持的推理强度和服务档位操作；提交区域左侧 MUST NOT 显示对话上下文用量。公共模型选择界面 MUST 不依赖对话上下文或保存场景偏好，选择本身 MUST NOT 创建对话、发起生成或执行 Git 写入。顶部全局入口及智能体抽屉（Drawer）的原有配置、关闭和窄屏行为 MUST 保留，详情及生成结果来源提示 MUST 按需展示对应确认配置。

提交模型选择、服务档位和各模型推理强度 MUST 在应用配置域内独立持久记忆，MUST 与对话的持久选择及临时交互状态隔离；账号和模型目录 MUST 继续使用同一事实来源。恢复时 MUST 核对当前来源、可用性及档位能力，MUST NOT 发送已失效强度；浏览器存储不可用时 MUST 保持当前页面选择与手写说明可用。

主按钮 MUST 固定执行“提交”。下拉菜单 MUST 不再重复“提交”，且 MUST 依次显示“提交并同步”“提交并推送”；菜单项 MUST 在点击时直接执行对应动作并立即关闭菜单，MUST NOT 仅切换主按钮模式而要求再次点击，MUST NOT 记住上次菜单动作并改变主按钮含义。主按钮、菜单触发器及菜单项 MUST 使用一致的可执行条件：上下文未就绪、无变更、说明为空、说明生成中、写入中或提交结果待核对时 MUST 不可执行；执行时 MUST 继续核对当前来源与已观察版本并防止重复请求。向下箭头 MUST 在其按钮内水平、垂直居中，与主按钮保持等高及连续的组合边界，在正常和窄栏均可辨认。

生成 MUST 以当前具体来源全部未提交变更为目标范围，固定来源及已观察内容；读取不足 MUST 明示，不把截断当成全部内容。说明草稿与结果 MUST 按代码库（Repository）和工作树（Worktree）独立保留；切换来源、取消或失败 MUST 不清除原说明，迟到响应 MUST 不覆盖另一来源或新草稿。内容变化 MUST 提示核对。生成说明、Git 写入与既有代码读取 MUST 保持各自失败边界。

已有清单、差异（Diff）、历史及完整文件读取 MUST 继续遵守确定性只读边界；提交和推送 MUST 由 `code-commit-operations` 的显式写入能力承担，MUST NOT 因查看、筛选或刷新而触发。

#### Scenario: 日常手写或生成后提交
- **WHEN** 用户在未提交变更中手写说明，或点击图标生成后修改
- **THEN** 页面 MUST 在同一区域呈现可编辑结果及提交操作，默认布局 MUST 紧凑，读取和历史 MUST 保持

#### Scenario: 来源切换保留独立草稿
- **WHEN** 用户填写说明后切换工作树（Worktree），再返回
- **THEN** 原说明 MUST 保留，其他来源 MUST 不接收本来源的生成或提交结果

#### Scenario: 本次选择与全局显示
- **WHEN** 用户在提交入口搜索并按账号分组选择模型、更改受支持强度和档位，再更改对话选择并刷新
- **THEN** 两入口 MUST 分别恢复自己的有效选择；提交入口 MUST 使用与对话相同的模型配置交互，不显示对话上下文用量，不改写对话草稿或历史运行
- **AND** 提交选择 MUST 在一次生成后保留，选择与刷新本身 MUST NOT 发起生成或 Git 写入

#### Scenario: 配置失效或存储不可用
- **WHEN** 已记推理强度不再受当前档位支持，或浏览器存储不可用
- **THEN** 系统 MUST 不发送失效强度，存储失败 MUST 不阻止当前页面选择、生成或手写说明；不可用模型 MUST 明确不可用，不静默换账号

#### Scenario: 固定主按钮与有序组合动作
- **WHEN** 用户填写说明并打开提交菜单
- **THEN** 主按钮 MUST 为“提交”；菜单 MUST 仅依次显示“提交并同步”“提交并推送”，不重复普通提交
- **AND** 点击任一菜单项 MUST 立即关闭菜单并仅发起一次对应动作；动作结束或来源切换后主按钮 MUST 仍执行普通提交

#### Scenario: 提交后同步结果分别表达
- **WHEN** “提交并同步”的本机提交成功，而后续获取、整合或推送失败、不可用或未知
- **THEN** 页面 MUST 保留并显示已成立提交及独立同步结果，MUST NOT 将其表达为提交失败或通过再次提交来重试
- **AND** 同步成功 MUST 显示“已提交并同步”；无上游 MUST 保留提交并说明尚未同步，MUST NOT 猜测目标

#### Scenario: 禁用和等待保持一致
- **WHEN** 提交上下文、说明、生成状态或写入状态导致主按钮不可执行，或菜单打开后状态发生变化
- **THEN** 菜单 MUST 同样不可执行，陈旧或重复事件 MUST NOT 产生额外写入

#### Scenario: 提交箭头组合对齐
- **WHEN** 页面处于正常或窄栏布局，说明为单行或多行
- **THEN** 箭头 MUST 在自身按钮内水平、垂直居中，两个按钮 MUST 等高、相连且只保留组合外侧圆角

### Requirement: 提交说明采用轻量执行

提交说明 MUST 经内部模型能力请求同一已选模型（Model）的无工具单次生成，MUST 指定60秒调用预算，MUST NOT 修改原生全局配置或正式任务配置。`/code/commit-message` MUST 接受可选 `reasoningEffort`，并将明确且受支持的强度及既有可选 `serviceTier` 原样传至统一模型 `generate`；未传强度时 MUST 使用当前模型声明的最低可排序强度，无法排序或不支持覆盖时 MUST 使用模型默认，不猜测 `low`。Buildr MUST 在硬字节预算内准备必要资料，智能体（Agent）MUST 一次生成且不自行补读。输出 MUST 遵循适用提交规范，必要时添加正文，不预设条数，MUST NOT 编造未提供的内容或测试结果。

单次生成 MUST 复用统一模型能力的账号身份、观察版本、可用性和参数支持性校验，MUST NOT 通过持久对话或工具调用实现。参数、来源、临时无工具调用能力或配置路由无法确认时 MUST 局部失败并保留草稿，不静默更换模型、协议或执行者。普通 Git 提交及推送 MUST 继续由直接 Git 能力承担；既有材料、来源和草稿版本校验及取消边界 MUST 保持。

#### Scenario: 显式配置贯通
- **WHEN** 用户选择受支持的服务档位及非最低推理强度并生成提交说明
- **THEN** HTTP 请求、应用输入与统一模型 `generate` MUST 使用相同的 `serviceTier` 和 `reasoningEffort`，MUST NOT 强制覆盖为最低强度或更改账号设置

#### Scenario: 旧请求未指定推理强度
- **WHEN** 调用方省略 `reasoningEffort`
- **THEN** 请求 MUST 保持兼容，系统 MUST 使用模型声明的最低可排序强度或模型默认，不影响既有服务档位传递

#### Scenario: 非法或不支持的配置
- **WHEN** 请求字段不符合类型约束，或显式参数不受当前账号模型及档位支持
- **THEN** 系统 MUST 按现有请求及模型能力边界拒绝或失败，保留草稿，不静默降级为另一强度或账号

#### Scenario: 真实源码变更快速生成
- **WHEN** 用户对实际工作树（Worktree）的较多源码变更发起生成
- **THEN** 系统 MUST 在60秒调用预算内交付符合规则的结果或明确失败并保留草稿；性能验收 MUST 使用真实源码场景，MUST NOT 仅以填充大文件代替

#### Scenario: 使用 DSH 验证同一场景
- **WHEN** 用户选择能力已通过验证的 DSH 生成提交说明
- **THEN** 系统 MUST 使用既有有界材料、规范及来源版本校验，经不创建持久对话的统一模型能力一次生成且不调用工具；界面 MUST 原位呈现可编辑结果，并能查看实际配置

#### Scenario: DSH 生成能力局部失败
- **WHEN** DSH 不能确认临时无工具调用、受支持的所选推理强度或配置路由要求
- **THEN** 系统 MUST 保留已有说明和直接 Git 操作，明确本次失败，不自动改用 Codex 或其他模式
