## MODIFIED Requirements

### Requirement: Antigravity 程序必须由 Buildr 独立准备且版本受控

系统 MUST 通过官方发布清单为 Antigravity 准备 Buildr 独立受管的 `agy` 程序，准入主版本为 `1.x.x`，MUST NOT 绑定或接管用户自行安装的 `agy`。系统 MUST 在该连接的私有配置中关闭 `agy` 自动更新，并 MUST NOT 执行官方安装脚本中修改用户 shell 或环境路径的步骤。系统 MUST 观察受管程序的文件身份，以验证自动更新约束实际生效。程序版本只能通过 Buildr 的显式检查与更新动作改变；受管程序在使用中被外部改变时 MUST 按程序身份变化处理，不得继续视为原绑定，并 MUST 提供本规范定义的显式恢复路径。

#### Scenario: 首次准备
- **WHEN** 用户在智能体页对 Antigravity 执行准备
- **THEN** 系统 MUST 从官方清单下载并校验当前平台的最新 `agy`，写入受管目录并完成协议握手检查
- **AND** 用户主目录下的 `agy` 设置、shell 配置与已安装程序 MUST 保持不变

#### Scenario: 运行后程序未自更新
- **WHEN** Buildr 使用受管 `agy` 完成多轮执行
- **THEN** 受管程序文件身份 MUST 保持不变，新版本只在用户执行 Buildr 程序更新后生效

#### Scenario: 运行期间受管程序被改变
- **WHEN** 受管程序文件在连接使用期间被自身或外部更新改变
- **THEN** 系统 MUST 在工作输入前或在下一轮开始前中断受影响执行，报告程序身份已变化
- **AND** 系统 MUST 关闭该程序的对话进程，保留对话记录、账号登录和用户尚未完成的输入

## ADDED Requirements

### Requirement: 受管程序身份变化必须可以显式恢复

系统 MUST 在程序更新观察中区分官方版本与受管程序文件身份。当文件身份与连接绑定不一致时，系统 MUST 报告“程序身份已变化”，MUST NOT 仅因本地版本等于官方最新而显示为“已是最新”或隐藏恢复动作。

系统 MUST 为用户提供显式动作：重新从官方发布清单核对受管程序的来源、版本与摘要，并重装到受管目录。该动作 MUST NOT 直接信任或继续使用磁盘上已被外部改变的现有文件。为恢复已失配的绑定，系统 MUST 允许重装与本地相同的官方最新版本；MUST NOT 以“目标版本不高于当前版本”拒绝该恢复动作。

重装 MUST 在切换前释放该连接正在使用的程序进程，安装并校验成功后更新连接保存的程序身份，保留原生对话历史、账号登录与其他连接的运行状态。恢复完成后，用户保留的输入可以继续发送；系统 MUST NOT 自动重放未确认完成的工作。

若 `agy` 不响应连接私有配置中的自动更新开关，系统 MUST 如实诊断该事实，并 MUST 在每次程序身份变化后仍提供上述恢复路径，MUST NOT 把关闭自动更新的配置描述为已验证生效。

#### Scenario: 程序自更新后从界面恢复
- **WHEN** 受管 `agy` 自行更新导致文件身份与连接绑定不一致，用户在程序界面检查更新
- **THEN** 系统 MUST 显示程序身份已变化及明确的恢复动作
- **AND** 用户执行恢复后，系统 MUST 从官方清单重新核对并重装受管程序，更新连接绑定，使该连接恢复可用

#### Scenario: 本地版本已是最新但身份失配
- **WHEN** 本地受管程序版本等于官方最新版本，但文件身份与连接绑定不一致
- **THEN** 系统 MUST 允许重新安装该相同版本以恢复绑定
- **AND** MUST NOT 以版本不高于当前版本为由拒绝恢复

#### Scenario: 恢复不重放旧轮次
- **WHEN** 用户完成程序身份恢复并在原对话中继续
- **THEN** 系统 MUST 使用恢复后的受管程序与准确原生会话继续
- **AND** MUST NOT 自动重放此前未确认完成的输入或工具操作
