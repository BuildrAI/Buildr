## Context

见 [proposal.md](proposal.md) 的问题与范围。当前实现中，OpenAI API 来源只读取 `/v1/models` 的 `id`，并在适配器内把 `images` 固定为 `false`、不设置 `reasoningEfforts`；Qoder 来源只消费 `/models` 的 `chat` 分组，额度只读取 `orgResourcePackage`；Web 侧 `modelSourceViews` 只用额度观察时间生成来源卡片的观察标签，`modelSourceName` 则把订阅来源映射为 `Codex`。这些事实共同造成了本次反馈中的五个现象。

## Goals / Non-Goals

**Goals:**

- 在确定性、可测试的本机代码中表达 OpenAI 官方已确认的模型能力，不增加运行时文档抓取。
- 让 Qoder 的套餐与资源包都进入同一额度事实，并让账号级耗尽判断与真实可用额度一致。
- 让 QoDuck 等仅出现在 `app` 分组的真实模型进入目录，同时保持 key 去重和偏好稳定。
- 让模型来源名称与执行智能体名称分开表达，来源快捷行不折行。
- 对无法读取的 ChatGPT API 余额保持诚实未知，不制造零余额。

**Non-Goals:**

- 不改变模型调用协议、执行器名称、账号存储格式或模型 id。
- 不增加 OpenAI 管理员密钥、会话 Cookie 或第三方账单抓取。
- 不声称支持官方页面未列出的输入模态。

## Decisions

### 使用静态官方能力目录，不在运行时抓取文档

为 OpenAI API 模型增加独立的能力目录模块，按基础模型 id 保存官方模型页已确认的显示名、输入模态、工具、上下文、最大输出和推理档位；带日期快照在查找时归一为基础模型，但返回给调用方的 `id` 保持原快照。未知模型只返回真实 id 与文本/工具保守能力。

选择静态目录而不是运行时读取官方文档，是因为模型目录检查必须稳定、低延迟且不依赖文档站点可用性；文档内容变化应由代码审查和测试显式更新。也不使用 Codex 订阅目录作为 API 能力来源，因为两者能力边界不同（例如订阅目录包含 `ultra` 档位，而 `gpt-6.1-sol` 的 API 文档只列到 `max`；订阅默认上下文也与 API 文档不同）。

### 以可用额度总量计算 Qoder 账号级剩余

Qoder `/usage` 的套餐额度与资源包额度都进入 `windows`：套餐窗口使用 `userQuota`，资源包窗口优先使用个人账号的 `addOnQuota`，并保留 `orgResourcePackage` 兼容。账号级 `remainingPercent` 按所有可用窗口的剩余总量除以总量计算；当服务商明确返回 `isQuotaExceeded` 时以该事实为准，否则不会仅因套餐窗口为 0 就判定账号耗尽。无法取得总量时退回窗口最小值，但仍保留各窗口事实。

这比只取窗口最小值更符合执行拦截逻辑：`modelQuotaFailure` 只读取账号级 `remainingPercent`，若继续取最小值，资源包有余额的个人账号仍会被错误阻止。各窗口仍独立展示，避免把资源包余额混入套餐百分比。

### 合并 Qoder chat 与 app 分组并按 key 去重

模型发现先处理 `chat` 分组，再处理 `app` 分组中未出现的 key。相同 key 以 `chat` 配置为准，`app` 仅补充只在该分组返回的真实模型（例如 `lmodel / QoDuck`）。合并后的模型继续使用真实 `key`、`display_name`、`is_vl`、`thinking_config`、`context_config` 与调用配置。

不把 `app` 分组单独做成新的模型分类，是因为当前模型目录和偏好都按账号 + 模型 key 管理，单独分类会增加 UI 与偏好迁移成本；按 key 去重也能避免 `app` 分组重复列出所有 `chat` 模型。

### 模型来源名称与执行智能体名称分离

`modelSourceName` 只表达模型来源：订阅来源为 `ChatGPT`，API 来源为 `ChatGPT API`，DSH 接入的 DeepSeek 账号为 `DeepSeek`。执行身份继续使用执行智能体名称：Codex 显示 `Codex`，DSH 显示 `DSH`，通过独立的执行者名称映射生成状态行。来源快捷行改为不折行的横向可滚动容器，保留全部来源和键盘可达性。

如果把执行智能体也统一改名为 `ChatGPT` 或 `DeepSeek`，会混淆“谁执行工具”和“谁提供模型”，破坏现有状态行与执行统计。只改模型来源名称即可满足区分来源的目标，同时保留 Codex/DSH 作为执行智能体身份。

### ChatGPT API 不把用量接口当作余额接口

普通 OpenAI API Key 对组织账单接口返回 403；`/v1/usage?date=` 只返回按日用量，不返回剩余余额。实现保留额度未知状态，但用模型账号的 `observedAt` 生成“API Key 模型来源 · 观察时间”，并在额度说明中明确费用与余额由 OpenAI 平台管理。不新增管理员凭据或会话 Cookie 读取。

## Risks / Trade-offs

- **官方能力目录随新模型漂移** → 目录项带有官方来源说明与测试；未知模型保守回退，不阻止真实模型使用；后续按官方页面增量更新。
- **模型显示名变化影响用户识别** → 底层 id、账号偏好和租约不变；显示名只影响界面文案，刷新后仍绑定同一模型。
- **QoDuck 的实际调用路径可能与 chat 模型不同** → 只使用服务商返回的真实配置，不伪造参数；若上游拒绝，按现有错误保真路径显示，不回退成静默换源。
- **合并 app 分组可能引入非对话模型** → 只补充 `enable !== false` 的真实模型，并继续复用现有对话模型过滤与调用校验；先用当前账号响应和测试确认 QoDuck 形状。
- **账号级 remainingPercent 合并口径改变** → 只影响额度耗尽判断与概览百分比；各窗口仍独立展示，额度读取失败不阻断模型目录。
- **来源快捷行横向滚动在窄视口可能隐藏末尾来源** → 保留键盘聚焦与可滚动容器，不通过隐藏来源来维持单行。

## Migration Plan

1. 先发布 provider 目录与额度解析；模型 id 不变，已有账号、偏好和对话绑定直接复用。
2. Web 只更新显示名、来源名称、观察标签和布局，不迁移账号或模型偏好。
3. 若需要回滚，移除能力目录与 `app` 分组合并即可；底层模型 id、凭据和已有模型偏好仍可读取，未知能力回到保守表达。
