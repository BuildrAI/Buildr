## ADDED Requirements

### Requirement: 对话工作区与对话共用导航

独立 Harness Web MUST 在对话信息流顶部将标题与消息正文左对齐，将更多操作和工作区开关放在同一内容栏的右端，开关位于更多操作右侧，不新增占位顶栏。左侧 MUST 按新建、当前对话、对话列表排序；点击当前对话不关闭工作区。右侧工作区首页 MUST 提供“资源管理器”和“源代码管理”两个模块入口；打开模块后 MUST 在右侧以可独立关闭的标签呈现；“＋” MUST 在标签下方显示同一首页和所有模块，不隐藏已打开项；选择已打开模块 MUST 激活原标签，MUST NOT 重复创建或重置其内容；两个模块 MUST 能同时保持打开，切换活动标签 MUST 保留另一标签的阅读和编辑现场，关闭最后一个标签 MUST 返回首页，资源管理器不重复展示目录工具栏，完整目录位置仍可核对。

#### Scenario: 从对话进入文件或变更
- **WHEN** 用户打开工作区，先打开资源管理器，再用“＋”打开源代码管理
- **THEN** 对话仍在左侧，右侧 MUST 同时保留两个模块标签；切换时不丢弃未保存的输入，关闭任一标签不关闭另一标签

### Requirement: 对话工作区跟随准确工作空间

独立 Harness Web MUST 在对话右侧提供可收起的工作区，分别提供资源管理器和源代码管理切换入口，文件或差异 MUST 在右侧内容区查看，不替换对话。工作区 MUST 按可独立装配的内容组织，新增内容不要求修改对话执行模型。

右侧 MUST 使用当前对话所属工作空间，或新对话已选工作空间所解析的目录；已登记的 Development 工作空间和本机目录均 MUST 无需重复登记。不能解析时 MUST 说明原因，MUST NOT 选用其他目录或沿用旧工作空间。无对话也无已选工作空间时 MUST 保留显式打开本机目录的能力。切换展示 MUST NOT 改写对话执行目录或丢弃未保存的文件输入。

#### Scenario: 切换两个不同工作空间的对话
- **WHEN** 用户从一个工作空间的对话切到另一个工作空间的对话
- **THEN** 右侧 MUST 保留已打开的模块标签及活动项，并切换到后者的准确目录，前者正在读取的结果、文件选择和差异 MUST NOT 显示为后者的内容

#### Scenario: 新对话尚未发送消息
- **WHEN** 用户已选择新对话的工作空间但尚未发送消息
- **THEN** 右侧 MUST 能直接打开该工作空间的文件或查看其 Git 状态，无需再次选目录或启动模型

#### Scenario: 工作空间暂不可用
- **WHEN** 当前对话的工作空间无可用目录
- **THEN** 右侧 MUST 显示局部原因且对话仍可用，MUST NOT 自动替换成其他目录
