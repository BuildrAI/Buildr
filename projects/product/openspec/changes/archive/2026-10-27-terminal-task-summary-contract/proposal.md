## Why

工作台任务行无条件优先显示工作摘要的最近进展，终态任务的结论因此被收尾前的旁白覆盖。本次 Rule 资产退役任务在任务记录已是 `completed`、结果摘要完整的情况下，卡片仍显示"等待用户明确收尾授权后执行自举同步、提交集成推送与 worktree 清理"，人看到的是"任务没处理"。同时命令行契约写"任务终态后不再修改"，实现却只对检查适用性结论设限，智能体据此判断会走"恢复 active → 改摘要 → 重新 complete"的重路径。

## What Changes

- 工作台任务行按任务状态选择摘要来源：进行中（`todo`/`active`）显示工作摘要的最近进展，终态（`completed`/`abandoned`）显示任务结果摘要；两者都缺失时退回任务目标。
- 摘要来源不因工作摘要的更新时间早于任务结果写入时间而改变，避免终态任务回退显示收尾前的旁白。
- 工作摘要在终态任务的真实写入边界写进契约：终态仍可补写进展、下一步与当前节点，该写入不改变任务状态与结果；命令行帮助 MUST 与实际边界一致，不再宣称终态后整体不可修改。检查适用性结论的终态冻结沿用既有检查要求，本变更不重复定义该规则。
- `buildr task work-context` 帮助文本与实现一致，不再宣称终态后整体不可修改。
- 不新增状态、门禁或审批；不改变任务四态、结果权威与工作摘要独立权威的既有分工。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `daily-workbench`: 工作台任务列表按任务状态选择摘要来源，终态任务显示结果摘要。
- `task-work-context`: 终态任务仍可补写工作摘要的进展、下一步与当前节点，且该写入不改变任务事实；命令行帮助与实际写入边界一致。

## Impact

- 影响 Buildr Web 工作台任务行的显示逻辑与 `buildr-web` 相关测试；不改接口契约与数据形状。
- 影响 `buildr` 的 `buildr task work-context` 帮助文本与相关集成测试；命令行为本身不变。
- 不影响任务详情页展示、任务四态、结果记录、工作摘要独立权威与 Agent 指令内容。
- 不引入破坏性变更：既有数据与路由照常显示，只是终态任务行的主文案来源从工作摘要切换为结果摘要。
