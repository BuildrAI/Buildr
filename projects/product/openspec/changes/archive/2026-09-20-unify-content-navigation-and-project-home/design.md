## Context

现状与动机见 proposal.md。壳层已缓存目录并通过 ResourcePreviewContext 展示服务、代码库和技能；文章页面却自行注册主标签。知识完整阅读组件已支持安全相对引用和图示，文章相关资料仅消费 content。编辑页已有 revision 校验、上传、未保存保护和冲突对照。

## Goals / Non-Goals

**Goals:** 保留同一对象身份、来源列表状态与阅读位置；共用壳层分屏与领域阅读组件；所有新显示行为在生产构建和真实浏览器验证。

**Non-Goals:** 不改变文章源文件、发布记录与权限模型，不新增全局状态库，不改变任务详情的整页导航，不部署开发候选到保留工作空间。

## Decisions

1. 扩展既有资源预览处理文章，单类详情复用同一标签。展开阅读只调整当前阅读区域，不重新挂载正文或新增主标签；展开按当前可见段落定位，恢复原分屏滚动。宽窄切换使用同一阅读节点与覆盖层样式，保留遮罩、焦点与键盘关闭。直接地址由目录加详情还原；缓存中的旧非项目主标签过滤或转为现行入口。
2. 编辑器从页面提取为领域抽屉。桌面提供足够正文宽度，窄屏全宽，底部固定保存状态和操作；列表、详情及旧编辑地址共用。保存成功更新当前详情，关闭恢复现场；关闭、遮罩与键盘退出统一执行未保存保护。上传资源与保存正文仍分开。编辑抽屉由按工作空间隔离的文章编辑上下文稳定持有，浏览器后退或关闭阅读区不卸载草稿；显式关闭会刷新原阅读与列表，以观察其他入口可能已经修改的新版本。
3. 知识采用不依赖路由主标签的嵌入阅读器，保留对象、成果和来源响应；按索引登记的文内引用补读所需成果。来源 Markdown 与成果正文共享阅读能力：补读以来源正文也可起步，并使用实际来源范围匹配索引与路径，避免把服务来源误当项目文件。来源可切换原文，非 Markdown 代码仍逐行只读。下级在当前副屏阅读并有返回；技能复用现有安全资料预览，不开放任意路径。原项目知识主阅读方式继续保留。
4. 项目主页使用紧凑标题、主要工作入口、并列文章/知识入口、服务与资料分组；窄容器自然单列。辅助动作降低权重，删除仍保留原确认流程。统计只表达真实内容。关联服务使用单一列表行结构，图标、名称说明、导航与解除关联各有独立空间，避免全局列表样式挤压。知识排在文章之前。服务主页身份与职责居首；无知识内容不显示空入口，有独立知识时在文档区次要呈现。代码库名称、模块路径、声明分支、实际分支与远端各自换行对齐，状态与检查操作单独成行。
5. 旧服务双段地址通过登记信息解析真实服务身份并进入共用副屏，未匹配则展示局部不可用提示，不能猜测服务身份。旧文章 edit 地址打开同一抽屉。

## Risks / Trade-offs

- 文章副屏可读宽度减少 → 提供展开阅读和窄屏适配；编辑使用独立宽抽屉。
- 页面缓存与抽屉关闭可能丢失输入 → 保留编辑状态、版本冲突逻辑，验证所有关闭入口与保存后的原位置。
- 单成果响应缺少图示正文 → 按已登记引用补读，失败保留其他正文和可理解提示。
- 旧标签存储含文章或服务知识 → 恢复时归一化到当前入口，项目标签保留。

## Migration Plan

代码与规范增量在同一任务工作树完成，不提前改主规范。生产构建验证新旧地址与读写行为；本轮不涉及数据迁移或自动发布。回退代码不改变既有文章内容与登记身份。
