## Context

见 proposal.md。现有 SSE 每次推送完整压缩工具视图；提醒每五秒返回完整运行/保留执行与工具数组。版本校验和重连必须继续可信。其他任务正在修改任务关联入口，本任务不重画该入口。

## Goals / Non-Goals

目标是减少只读传输和重复启动；不承诺网络面板零取消，不改变模型速度、执行状态、授权或后台生命周期，不直接激活候选。

## Decisions

- 增量仅在明确协商后启用，默认完整事件保持旧客户端兼容。首事件完整；其后按稳定条目 ID 传变化与顺序，其他对话元数据完整替换，保证字段删除可见。仅保留连接内一份基准，不创建持久事件状态。
- 接收端校验对话、代次、基准 cursor 与 revision，失败关闭观察并走已有重连；不猜测缺失数据。更早的本地历史仍由既有 mergeConversationView 合并。
- 进程内部与 HTTP 边界均缩小连续事件；内部客户端还原公开完整 ServiceEvent，避免上层业务承担压缩协议。协议只传变化小于快照时使用增量。
- 提醒新增独立摘要读取，直接投影 pending 状态，不传执行详情，旧 pending 不变；采用新操作前核对后台能力，兼容后台回退到原读取再投影。
- 相同只读请求在客户端按准确路径合并；消费者取消只结束自己的等待，不中断共享网络；短命挂载延迟到下一任务启动，避免 StrictMode 或同步导航立即启动再取消。关闭实时流和用户取消写入不适用此策略；短暂读取不无限缓存；写入前后失效在途共享槽，避免写入后的新观察加入写入前的旧请求。原在途完成不能清除更新槽。

## Risks / Trade-offs

- 增量错拼风险 → 连接局部基准、全身份校验、异常重连快照、删除/重排回归。
- 共享读取在无人等待后仍短暂完成 → 仅有界 GET，下一次仍读取最新，不扩展到写操作、附件或流。
- 传输缩小不等于浏览器渲染和模型延迟都解决 → 分开报告测试数据与未验证事项。

## Migration Plan

先提供兼容服务端和客户端适配；旧请求与未协商订阅保持完整响应，新端连接旧后台回退。候选仅在任务工作树测试，收尾授权后才集成及正式自举激活。
