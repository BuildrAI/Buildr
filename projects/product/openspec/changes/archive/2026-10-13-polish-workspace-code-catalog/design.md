## Context

见 [proposal.md](proposal.md)。`AppLayout.tsx` 组装工作空间（Workspace）菜单，`SourceControlRepositories.tsx` 及现有样式负责来源目录。原 `useSourceControlBranches.tsx` 依赖行内组件触发目录重读，组件卸载后不能可靠更新后来进入的同一工作空间（Workspace）页面；等待整体重读也会延迟目录中的实际分支（Branch）显示。

后端状态读取已经按真实代码库（Repository）和工作树（Worktree）身份组织，但重复调用通用来源解析会多次枚举同一批成员。现有超文本传输协议（HTTP）返回字段、目录身份校验及观察版本可继续使用。

## Goals / Non-Goals

目标是让界面层级清楚、已成立的切换事实及时可见，并让同一工作空间（Workspace）当前有效的目录实例重新观察原来源。样式沿用现有主题，当前阅读与明确固定的历史范围继续独立。

不新增写入能力、面向人的跨工作空间（Workspace）消息、通知中心、持久执行记录、跨请求观察缓存（Cache）、自动重试或远程抓取（Fetch）。提交及推送沿用既有路径。本轮不创建界面原型（UI Prototype），不修改上游 OpenSpec。

## Decisions

1. **名称和状态采用各自的对齐规则。** 菜单的名称栏与右侧选中标记分开，未选项同样预留标记位置。来源目录只缩进子工作树（Worktree）的图标和名称，保留右侧远程、文件、任务（Task）及分支（Branch）操作列的共同边界。整行缩进会破坏状态比较，因此不采用。
2. **先采用有效写入结果，再重新观察。** 确认成功响应属于发起时的具体来源，且不早于该工作树（Worktree）当前观察后，立即更新对应行的实际分支（Branch）和提交（Commit）；随后在后台重读目录及受影响的当前内容。按目标工作树（Worktree）的 `readAt` 与结果的 `readAt` 比较，较旧结果不修改目录，仍触发后台重读。固定提交（Commit）及明确指定的历史范围保持。后台读取失败独立显示，不把已完成的切换改报为失败，也不将旧内容当作新分支（Branch）的已确认内容。
3. **来源更新通知不依赖原组件挂载。** 发起切换时固定工作空间（Workspace）、代码库（Repository）及工作树（Worktree）身份，接口（API）完成路径通过功能内变化事件（Event）使当前同一工作空间（Workspace）的目录重新观察；原页面卸载后，新实例仍可订阅。同一结果不能更新当前其他工作空间（Workspace），离开原页面不取消或重新发送已发写入。事件（Event）只承接读取更新，原行内成功或失败提示保持既有作用域，不扩展为全局消息。
4. **只在本次采集内复用成员清单。** 每个代码库（Repository）的一次读取复用已枚举成员，针对具体成员在状态采集前后核对真实身份，并在采集后重新核对 Git 登记和当前代码库（Repository）来源。保留时间、数量与局部失败边界；下次请求重新枚举。无需引入并发调度或跨请求缓存（Cache）。

## Risks / Trade-offs

- 新的缩进减少名称可用宽度 → 保留按需完整名称与路径，验证长名称、窄分屏和状态列对齐。
- 切换完成与后台重读不同步 → 分开写入结果和读取状态，过时读取不得覆盖更新的观察，失败保留已知事实并允许重试读取。
- 离开页面后返回的结果可能指向其他工作空间（Workspace），或晚于较新的来源观察才送达 → 按原身份筛选订阅者，较旧结果只触发后台重读，不更新无关目录或回退当前观察、不自动重新发送写请求。
- 请求内复用清单期间工作树（Worktree）可能移除或被替换 → 采集后重新核对登记及具体目录身份，失败只影响该成员。

## Migration Plan

无需数据迁移或接口（API）升级。前后端按原构建方式交付，回退代码即可恢复原界面与采集实现，不处理业务数据或 Git 历史。
