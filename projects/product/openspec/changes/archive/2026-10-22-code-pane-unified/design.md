## Context

代码页由两个独立页面组成，均使用本地两栏：`CodeTreePane` + `RepositoryFileBrowser`（资源管理器）和 `SourceControlWorkbench`（源代码管理）。资源管理器已用 `ObjectTabStrip` 维护多个文件页签；源代码管理把列表、列表上下分屏和单个阅读对象放在同一组件内，阅读对象由 `changeFileKey` / `historyFileKey` / `commitHash` 等单一选择状态表达。

`CodeSourceControlPage` 目前在 `SourceControlWorkbench` 外再渲染一条仅含“源代码管理”的 `ObjectTabStrip` 与 `object-tab-panel`，与中屏页面页签重复。`CodeTreePane` 标题为“资源管理器”，同样与页面页签重复。两处展开阅读按钮当前都显示文字。

## Goals / Non-Goals

**Goals**

- 保留现有两栏和列表内上下分屏，不接入共享中屏/右屏。
- 移除代码页内重复的页面标识；源代码管理保持单对象阅读，资源管理器保留多文件页签。
- 阅读控件只显示图标，保留可访问名称、提示和键盘操作。
- 保持工作树切换、任务入口、分支选择、编辑、滚动位置和现有读取保护。

**Non-Goals**

- 不改变代码读取、差异比较、Git 写入或任务关联语义。
- 不把代码文件提升为中屏页面页签，不新增全局右屏。
- 不改变已保存的文件树宽度偏好或页面路由。
- 不改变提交详情、图片阅读和编辑器的既有内容。

## Decisions

### 1. 保留本地两栏，只移除重复页内页签

删除 `CodeSourceControlPage` 中的 `ObjectTabStrip` 和 `object-tab-panel` 包裹，让 `SourceControlWorkbench` 直接铺满页面；左栏标题改为“代码库”，保留代码库列表折叠与操作。资源管理器把 `CodeTreePane` 标题改为“目录”，避免重复页面页签和栏内已有的“文件”分组标题，不改两栏结构。

备选：接入 `WorkspacePaneHostProvider` 改三栏。会引入共享右屏对象、宽度和关闭清理的第二套语义，超出本次问题范围，否决。

### 2. 阅读区顶部固定两个视图页签，左栏保留列表切换，每个视图内保持单对象阅读

`SourceControlWorkbench` 保留左栏原有的“未提交变更 / 提交历史”分段切换，并在阅读区顶部固定渲染两个不可关闭的同名视图页签：

- 左栏分段切换紧邻它所切换的列表，只决定列表显示未提交变更还是提交历史；阅读区页签表达当前阅读视图，与中屏页面页签使用同一对象页签外观。两处入口各存一份状态，切换任一处都不改动另一处；只有在列表中选择文件、比较层或提交时，阅读区才切到该对象所属视图。
- 视图只有这两个，不新增页面级页签，也不为文件或提交创建页签。
- 每个视图内选择另一个文件、比较层或提交时替换当前阅读对象；不在阅读区累积文件页签。
- 两个视图分别保留自己的选择：未提交视图保留变更文件与比较层，历史视图保留固定提交、历史文件与提交详情状态；切换后恢复对应现场。
- 完整文件与提交详情是临时阅读对象；通过“返回差异”或重新选择左侧文件回到差异，返回目标遵循当前视图。
- 切换工作树时保存两个视图的选择与阅读状态，返回时恢复；阅读视图与左栏列表模式各自保持全局，不随工作树切换。
- 视图页签复用 `ObjectTabStrip` 的外观与键盘操作，通过 `panelId` 关联阅读区面板，关闭能力关闭。

依据：用户需要在本次改动与历史变更之间快速切换，并各自保留现场，同时希望在阅读区顶部看到“未提交变更”“提交历史”两个独立页签，明确当前读的是哪一个；文件级页签则没有价值，因为变更列表本身很短且与任务范围直接对应。左栏切换保留在列表正上方，用户在列表侧仍能直接切换，但它是列表的导航而不是阅读内容的开关：点击阅读区页签只表达“我要读哪一个视图”，不应把用户正在浏览的列表跳走，反之切换列表也不应替换正在阅读的对象，因此两处入口各存一份状态，只有选择列表中的对象才驱动阅读区。资源管理器的文件树规模大、定位成本高，多文件页签仍有明确收益，因此保持现状。

备选：两处入口绑定同一个视图状态（任一处切换都同时改变列表与阅读内容）。实现早期采用过该绑定，实际使用时点阅读区页签会连带把左栏列表跳走，打断正在进行的浏览，用户明确要求取消联动，否决。只保留阅读区页签并移除左栏切换，或只保留左栏切换：前者让紧邻列表的切换消失，用户需要在两栏之间来回找开关；后者让阅读区顶部空置，读的是本次改动还是历史变更没有可见标识，同样否决。按工作树分组的差异页签需要额外维护页签集合、标签消歧、关闭与空态，本次实际使用没有逐文件保留的价值，一并否决。

### 3. 阅读状态与位置

- 每个工作树保存最近选择的变更文件、历史文件、提交详情、对比模式、完整文件分页和滚动位置；返回时恢复。
- 页面隐藏时保留读取缓存与选择；返回代码页时恢复当前对象。
- 完整文件或提交详情只是临时视图，不成为再次返回代码页时的独立导航目标。

### 4. 图标化展开阅读

`ReadingToggle` 增加 `iconOnly` 选项，只渲染全屏/退出全屏图标，通过 `Tooltip` 提供“展开阅读 / 恢复分屏”，保留 `aria-label` 与键盘可操作性。源代码管理把展开按钮放在阅读区视图页签行右端；资源管理器沿用文件页签行位置。源代码管理没有当前对象且未展开时不显示展开按钮；已展开但当前对象被清空时保留“恢复分屏”，避免列表隐藏后无法退出。资源管理器在窄屏文件树隐藏时保留恢复目录入口。

## Risks / Trade-offs

- [两个视图页签与单对象阅读组合，仍需区分“视图”和“文件”层级] → 页签只表达未提交/历史两个视图，文件仍由左侧列表选择；不引入关闭、改名或工作树维度。
- [视图切换可能丢失各自现场] → 未提交与历史本已使用独立选择状态，切换只改变当前视图；浏览器检查验证往返恢复，不复制选择。
- [工作树切换恢复依赖现有阅读保存逻辑] → 复用按工作树保存的选择、分页和滚动位置，并验证阅读视图与左栏列表模式各自保持全局。
- [左栏较窄时两个页签平分栏宽，窄阅读区中展开图标又与来源操作争用横向空间] → 页签不显示装饰圆点、固定文案并在栏内平分；窄栏检查确认两个页签、展开图标与提交信息、任务入口均可见且不重叠。
- [左栏列表模式与阅读区视图可以不一致] → 这是有意取舍：列表保留用户正在浏览的记录类型，阅读区只表达当前读的对象；两处各有可见选中态，浏览器旅程断言切换任一处不改动另一处，并断言在列表选择对象时阅读区切到其所属视图。
- [现有浏览器旅程依赖文字展开按钮和阅读区页签位置] → 更新受影响选择器与断言，保留稳定 `data-*` 定位和可访问名称。

## Migration Plan

无数据迁移。已有文件树宽度、分屏比例和读取缓存键保持；阅读选择仍只存在于当前页面会话，切换工作空间或刷新页面后按现有页面生命周期处理。
