## Context

动机及范围见[提案](proposal.md)，任务正文见[任务说明](@task/task-artifact-continuity)。当前额外说明由 Buildr 的 OpenSpec 贡献、知识维护 v3 和前后端专用读取组成；OpenSpec 上游标准产物不包含该增强。

## Goals / Non-Goals

目标是同一业务目标只有一套源码隔离位置、每个任务只有数据库正文，具体变更继续使用既有标准产物。保留历史文件和普通阅读能力。

本轮不改变 OpenSpec 上游技能、模板、模式定义、CLI，不批量迁移历史正文，不修改 TaskRecord.brief 数据结构，不增加隔离转移状态或专用命令。

## Decisions

### 接续原型的实际执行位置

任务分流（Task Triage）拥有唯一位置选择约定，原型技能交接当前确认版本、源码根、隔离标识及分支。尚无正式任务但已有原型代码位置时，核验同一目标后以既有隔离标识登记正式任务，由现有工作树提供者 inspect 接续，不改目录名或另建实施分支。已有正式任务时使用其位置。仅临时 HTML 而没有代码检出时，正常为开发创建位置。身份冲突保留现场，不通过复制绕过。

选择稳定标识接续，避免引入数据库中的第二套隔离登记或跨任务自动接管。

### 退役 Buildr companion

删除 Buildr ChangeModel 的专用 brief 字段和自动读取，前端方案目录与详情以标准 artifacts 为入口，移除专用面板及缺失告警。旧 brief.md 仍通过原有受限普通文档读取访问；相对及项目根链接维持既有语义，不扫描同名文件、不自动填充 TaskRecord.brief。

具体变化说明由 proposal 表达，技术选择由 design 表达，不另建替代说明文件或改动上游模板。

### 知识维护能力 v4

v3 最低保证包含变更说明维护，直接删保证会冒充兼容。因此新增 v4 并迁移内置提供和调用声明；原样保留 v3 契约，用户自有依赖和绑定不静默改写。内置消费者必须可路由，用户旧依赖按真实提供者局部诊断。知识维护继续负责代码地图、技术图和解释文档，取消额外说明创建保证。

## Risks / Trade-offs

- 旧客户端使用专用 brief 字段 → Buildr 前后端同次修改并构建验证，标准 artifact 身份和任务正文不变。
- 旧链接被退役面板连带破坏 → 用 active/archived 真文件和普通链接验证阅读，保留文件及显式迁移能力。
- 已有原型隔离归属不明 → 由原提供者核验，保留现场和未提交成果，不迁移或借用其他任务位置。
- OpenSpec 组件范围误改 → 修改仅在 Buildr 贡献层；验收比对六份上游技能源码哈希，模式与上游产物约定不改。

## Migration Plan

先在候选工作树修改 Buildr 增强、契约及消费入口，完成专项检查和构建。后续正式交付时由唯一自举执行器同步源资产并更新主应用。历史文件不重写，回退使用仍保留的先前交付版本，不以补造说明恢复。
