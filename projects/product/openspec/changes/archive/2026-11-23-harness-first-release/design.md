## Context

开发插件是已构建的薄桥，当前绑定本机开发包；现有发布工具默认只认 Development 和旧插件。

## Goals / Non-Goals

用户可按任一顺序安装正式 Harness 和 DSH 插件；开发与正式分别复用正确的数据域。不在 DSH 内安装第二份 Harness，不拆仓库，不修改旧插件或扩大支持平台。

## Decisions

- 复用正式 Harness 的默认系统启动器及其安装身份；认证桌面请求不接受来自网页的路径或进程参数。缺少身份给出安装/修复指引，按同一路径复检。
- 开发绑定保持显式，使用通过构建和激活的保留入口；更新以新网页内容和兼容激活事实为准。优先保留草稿及未保存写入，不以切回侧栏冒充刷新。
- DSH 以 0.2.x 为评估范围；装载所需能力不满足时只影响插件。保留准确实测版本。核心版本与插件版本分别指定，固定正式候选兼容范围。
- 现有 Skill 接入两个独立目标；候选原包不重复制包。发布必须精确核对授权、候选来源、校验值和已发生效果，保持 npm 和 GitHub 字节一致。

## Risks / Trade-offs

正式默认启动器未建立或绑定漂移时提示重新登记，而不是猜测 npm PATH；不兼容的 DSH API 不以关闭认证或修改官方配置为代价。未验证的平台和宿主不标成通过。文档更新现有发行正文、产品边界和插件 README，不新增平行知识入口。
