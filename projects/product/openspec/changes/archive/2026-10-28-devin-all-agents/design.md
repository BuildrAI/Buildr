## Context

Devin 来源模型的门禁经历了两次收紧：最初只允许 SWE-2，后来放开到 Codex 全部模型，但 Qoder 仍整体置灰。该限制的出发点是"只开放已验证组合"，而不是协议差异。

当前实现中三种执行方共用本机模型网关：Codex 以 responses 协议连入，Qoder 与 DSH 以 chat-completions 连入，最终都由 Devin 适配器转换协议。Codex 指令与工具说明的改写发生在适配器内部，对来源模型一视同仁；模型之间只有目录元数据差异（图片能力、上下文窗口、思考档位变体、组合模型）。执行方之间唯一相关的真实差异是 Qoder 只接受 low/medium/high/xhigh/max 思考档位，且该约束已在 `qoderGatewayPolicy` 中给出 `agent_reasoning_unavailable` 的准确诊断。

## Goals / Non-Goals

**Goals**

- Codex、DSH、Qoder 可选择 Devin 账号下任一已启用、可用的模型。
- 不可用、停用、执行方无法表达的档位或能力按真实原因说明，保留草稿与其他可选组合。
- 保留真实失败：上游拒绝、额度或能力不足按实际错误呈现，不自动换源或提高权限。

**Non-Goals**

- 不改变工具说明改写、权限绑定、原生上下文接续逻辑。
- 不改变 Qoder 的思考档位白名单，也不新增跨执行方的能力探测。
- 不证明 Qoder 个人套餐能供出 Devin 来源模型；该边界仍由"未知套餐输出路径必须如实表达"覆盖。

## Decisions

- **删除模型选择层的执行方门禁。** 路径中没有可靠的逐执行方、逐模型协议差异数据；维护白名单会产生第二套能力权威并随上游目录变化失准。可用性改由模型自身的启用、可用与停用状态决定。
- **档位与能力限制留在执行路径。** Qoder 无法表达的思考档位由既有策略返回具体原因；选项不因执行方类型整体置灰，用户能看到可选项并获得可执行的原因。
- **失败如实呈现。** 放开选择不等于承诺模型质量；内容策略、额度或工具回合失败按上游错误返回，不自动换源重放，也不把单次失败表达为厂家永久不支持。
- **保留"未知输出路径"边界。** Qoder 消费外部模型与 Qoder 个人套餐供出模型是两个事实，后者仍未证明，继续如实区分。

## Risks / Trade-offs

- **Qoder 个别模型因档位不匹配不可用。** 缓解：沿用 `agent_reasoning_unavailable` 诊断，用户可改选档位或执行方。
- **真实失败反馈可能增加。** 缓解：错误沿用现有上游诊断通道，不新增静默重试或自动降级。

## Migration Plan

无持久迁移。既有选择、草稿和对话历史按当前可用性重新观察；此前被置灰的 Qoder×Devin 与其他模型组合恢复为可选。
