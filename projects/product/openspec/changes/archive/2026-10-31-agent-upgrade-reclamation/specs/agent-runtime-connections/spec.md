## ADDED Requirements

### Requirement: 新版激活完成必须证明准确后台已启用

系统 MUST 在新版本激活时以准确运行内容登记目标，并核验目标后台实际就绪且接收新工作后才报告激活完成。兼容新旧共存时 MUST 不等待旧任务结束才启用新版；旧任务与控制 MUST 保留原归属。请求受理、文件已安装或旧后台空闲 MUST NOT 单独代表新版启用。失败或有界等待超时 MUST 保留真实诊断与旧工作，不自动重放操作。

#### Scenario: 旧任务执行中新版激活
- **WHEN** 兼容新版已激活且旧后台仍有正在执行的任务
- **THEN** 新版 MUST 启动并接收新任务，旧任务 MUST 连续执行且不重复投递

#### Scenario: 目标已登记且旧后台空闲
- **WHEN** 不支持并行的目标等待且旧后台资源已经准确释放
- **THEN** 系统 MUST 自动推进交接并核验新版就绪，MUST NOT 要求再提交任务触发切换

#### Scenario: 新版没有实际启动
- **WHEN** 目标被受理但新版启动失败或就绪等待超时
- **THEN** 激活 MUST 报告未完成和明确原因，保留旧工作及已保存输入；对同一目标的明确重试 MUST 再核验真实启动结果

## MODIFIED Requirements

### Requirement: 预启动与已使用资源按连续空闲回收

Buildr MUST 对尚未采用的选择准备连接提供默认30分钟连续空闲回收，最多一分钟检查间隔；准备完成开始计时，普通观察和目录检查 MUST 不续期。已采用连接 MUST 在工作及相关辅助持有者结束并取得准确释放证明后及时自动回收，MUST NOT 继续沿用未采用准备的30分钟保留期。执行、未结工具、待回答问题和未经准确证明释放的资源 MUST 不因超时中断。并发发送与关闭 MUST 保持准确归属；断开、升级和退出 MUST 覆盖未采用准备，失败保留未确认事实。

#### Scenario: 预启动后未使用
- **WHEN** 准备成功后连续空闲30分钟且未被工作采用
- **THEN** 后台 MUST 关闭准确自有连接并释放相应模型绑定，不删除账号、历史或用户数据

#### Scenario: 长时间执行或等待
- **WHEN** 超过30分钟仍有执行、工具或待回答问题
- **THEN** 超时回收 MUST 不停止该工作或清除问题

#### Scenario: 回收后再次发送
- **WHEN** 资源已回收且用户再次发送
- **THEN** Buildr MUST 按原准确上下文冷恢复，不重发旧要求

#### Scenario: 已采用连接执行结束
- **WHEN** 预启动连接已被工作采用且该工作及相关辅助持有者结束，原生资源可安全释放
- **THEN** 后台 MUST 及时自动回收连接及对应临时模型凭据，MUST NOT 等待30分钟才回收
