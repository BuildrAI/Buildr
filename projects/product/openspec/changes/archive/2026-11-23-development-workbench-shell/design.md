## Context

现有 `AppShellHeader` 挂在工程面板内，`HarnessShell` 又单独渲染开合行。第二版原型确认右侧用对话工作区、无变更卡；最终确认修订为左侧保留真实空间选择器、中间模式、右侧保留现有操作。

## Goals / Non-Goals

保留同一 React 对话、已有工程页和代码工具的业务所有权。无新后台、业务路由、目录权限或简版资源管理器；独立 Harness 不变。

## Decisions

1. 把既有产品顶栏移到两列之上。模式为应用布局；对话位置和上一个工程页不因为按钮切换而换身份。现有工程深链接仍打开工作空间。
2. 工作台只在明确打开侧栏时展示文件/Git。复用 Harness 标签与首页外观，并由 Development 原工程代码页及其已认证 API 提供内容；不把独立目录 API 透传给 Development。
3. 对话继续由 Harness 唯一渲染。沿用侧边对话、收起、导轨和宽度行为。用明确导航来源区分工作台里的代码工具和原有工程深链接。

## Risks / Trade-offs

工具切换涉及既有路由，需分别保全管理页面和工作台工具选择，并防止用 A 空间的对话误展示 B 空间的代码。窄屏要保留模式和面板入口，无横向滚动。正式验证用托管构建，不以原型替代。
