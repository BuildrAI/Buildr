## Context

动机见 [proposal.md](proposal.md)。`useMarkdownDocumentViewer` 当前无请求时效或卸载失效，默认历史写死 `README.md`。项目主页实际初始选择可以是 `AGENTS.md`。文章草稿由工作空间内 `ArticleEditorProvider` 和编辑抽屉持有，普通同工作空间导航保留它；跨空间、全局目录和独立原型路由会释放。当前 `BrowserRouter` 无法提供正式导航阻止钩子（Hook），仅拦截链接点击会漏掉浏览器历史跳转。

## Goals / Non-Goals

**Goals:** 保持一个当前读取、真实阅读历史和一个文章编辑现场；保护实际将释放现场的离开，保留保存中请求身份。

**Non-Goals:** 不增加草稿持久库、全局业务状态仓库、后台接口或路由地址；不改布局；不强制所有页面使用统一读取框架，不承诺浏览器关闭后恢复未保存正文。

## Decisions

1. 阅读钩子（Hook）就地增加请求世代与卸载失效，成功、失败、最终加载状态统一核对世代。重置也使请求失效并结束旧等待；项目初始读取替换历史。路径与正文随当前请求完成一致更新，旧请求不追加历史。优先本功能简单职责，不新增跨领域请求库。
2. 生产入口采用现有 React Router 的数据路由器（Data Router），由最外层路径匹配继续装配现有 `App` 地址与页面壳，接入稳定 `useBlocker`。不改路径、不增加加载器或路由级数据缓存。使用原生导航阻止能力覆盖程序导航与浏览器历史；拒绝通过全局点击拦截和补写历史模拟它。具体装配须用项目已锁定版本验证。
3. 草稿及保存状态仍属于文章编辑抽屉。退出保护由现有文章编辑职责消费真实 `dirty` 和 `busy`，不复制第二份稿件。对会卸载提供者的目标先阻止导航，再复用既有“继续编辑 / 放弃修改”确认；取消重置导航，确认只执行当前目标。保存中退出立即取消并提示等待，成功或失败都不重放旧退出。重复导航和保存期间打开确认不得形成两份退出状态。
4. 硬刷新/关闭沿用 `beforeunload`，覆盖未保存或保存中；不在规范中保证浏览器一定弹窗。保存和资源上传依旧使用原观察版本及原工作空间，跨空间被阻止期间全局请求上下文不能改变。

## Risks / Trade-offs

- 路由入口调整可能改变相对导航或页面缓存 → 保持既有 `App` 路由树，核对项目、服务、文章、任务及独立原型地址与前进后退；不引入数据加载器。
- 阻止导航后重复点击、确认期间关闭编辑或开始保存可能留下陈旧目标 → 统一由当前导航阻止对象和编辑状态决定动作，保存中确认不得放行，结束编辑时清除退出状态；添加真实行为检查。
- 初始文档与项目身份变化可能留下旧请求或历史 → 初始读取明确替换历史，换项目/卸载使先前请求失效；受控承诺检查覆盖迟到成功、失败、返回和重置。
- 临时提示可能打断正常浏览 → 仅保护真正释放编辑现场的目标；同工作空间普通页面保留抽屉并直接跳转，符合连续工作与真实反馈需求。

## Migration Plan

只替换随包网页源码，无源资产或数据库迁移。开发先验证局部逻辑与生产构建，再执行生产托管浏览器场景；交付沿用当前产品流程。回退原提交即可还原网页实现，但回退后原有退出保护缺口再次存在。
