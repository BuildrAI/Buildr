## ADDED Requirements

### Requirement: 主对话必须提供统一的原生子智能体查看体验

统一对话 MUST 在执行器提供明确派发关系时，提供派发位置与子智能体列表入口，以同一只读界面查看来源、已观测状态、过程和结果。系统 MUST NOT 从普通命令或输出猜测关系，查看、切换与返回 MUST 保留原对话与未发送草稿。

#### Scenario: 分别查看 Claude Code 和 Codex 子智能体
- **WHEN** 原生提供准确派发身份及子执行记录
- **THEN** 用户 MUST 能以相同方式打开、切换并返回原派发，子智能体的过程 MUST NOT 混入主答复
- **AND** 子智能体的已知派发要求、进展、工具、下一级派发及结果 MUST 使用同一只读对话流呈现，无需切换到另一页看结果

#### Scenario: 一轮已折叠或用户希望查看整个对话的派发
- **WHEN** 已读记录包含子智能体派发，且该轮处理过程被折叠
- **THEN** 该轮标题下 MUST 保留子智能体名称、状态和直达详情的入口；展开后仍 MUST 在原派发位置显示
- **WHEN** 用户打开对话标题栏的子智能体入口
- **THEN** 系统 MUST 先显示按真实执行归属分组的总览，展示已知派发要求或结果、状态及父子关系；仍有未读历史时 MUST 表明名单尚不完整并允许补读

#### Scenario: 只有部分记录
- **WHEN** 子线程不可读或原生未报告结果
- **THEN** 系统 MUST 保留已确认关系和已有过程，未读到的信息不得冒充已完成或已回传

### Requirement: 子智能体依赖必须独立于后台身份

主流程有原生等待证据时 MUST 保持执行中并显示等待对象；只有主流程确认结束且仅剩独立后台工作时才 MUST 以仅后台运行呈现。子智能体结束不证明主流程收到结果。

#### Scenario: 主流程等候审查后恢复
- **WHEN** 当前执行的原生阶段仍在等待子执行
- **THEN** 系统 MUST NOT 将模型的一段输出结束识别为整轮只剩后台命令；等待结束后 MUST 恢复主流程的准确展示
