# 极简任务收尾

默认收尾由智能体（Agent）依据技能（Skill）组合已有工具完成目标，不再补齐旧候选、交接或五阶段状态链。

## 背景与范围

旧默认路径会让已可观察的成果受内部状态阻塞。本次只重构收尾及必要消费者；不新增 Buildr 接口、应用或数据库，不发布，不重写研发、发布和专用父任务计划。

## 实际变化

- 技能从两套正式/普通流程改为按现场推进；默认不调用 `task next`、旧执行器或对账。
- 已有任务结果直接保存，界面显示已完成但不伪称机器验证；终态查询不再重启研发。
- 受管环境清理按身份、所有权与当前保留提交保护内容，不再读取旧收尾证明。
- 同一自举脚本可从真实 Git 与已完成任务核验输入，保留激活、交付和清理边界。
- 删除强制旧流程文案、最低 40 行和最低 1500 字符的收尾静态检查；通用格式与绑定检查保留。

## 验证与限制

- 任务结果、终态、环境控制器和工作树定向组：62 项通过。
- 自举回归：91 项通过，其中三个新场景使用真实本地 Git 远端，安装与诊断采用测试替身。
- 技能契约与核心边界：9 项通过；任务记录端到端：5 项通过。
- 新多独立仓库场景通过；补强删除前保留分支漂移检查后，两个直接清理场景再次通过。
- TypeScript 检查、正式前端构建、三组接口声明检查和包静态检查通过。
- 浏览器任务全流程最终通过（2 项，144.85 秒），临时工作空间已清理。此前两次失败来自路由切换的等待不足，另一次来自已退役的旧完成状态断言；均已修正并完成重跑。正式构建产物与临时重建逐文件一致。

没有运行无关全量测试，没有真实词元（Token）计量，不声称已获得整体性能提升。历史执行器仍可显式使用，不为默认路径生成其证据。无法证明内容等价的非线性历史保留资源，由智能体进一步核实。
