## Context

既有任务记录应用已提供 `task complete`。当前阻力集中在技能强制走研发交接、任务完成投影要求收尾关联、环境清理只认可旧交付结果以及自举只接收旧运行投影。

## Goals / Non-Goals

目标：默认路径短、依赖少，支持有无任务及多仓库，事实与结果可重新观察；文档集中描述实际参与者。
不做：新交付状态库、通用动作引擎、新应用、独立服务仓库启动、新智能体适配、发布或全任务系统重写。

## Decisions

1. 智能体（Agent）负责目标，技能（Skill）提供判断方法和安全边界，原生工具与现有接口执行操作。固定组合只留给真正稳定且需要统一控制副作用的自举动作。
2. `task complete` 只记录已有任务的结果摘要，不制造候选、交接或机器验证结果。无旧关联的完成记录仍为 `completed`，`delivered` 保持 false，明确没有机器交付证明。
3. 清理自身的安全不变量是身份和所有权明确、没有未保存内容、仍有受控仓库持有全部提交。已完成任务可用保留仓库的当前分支提交证明包含关系；这不声称远端已交付。不同历史、脏内容或未知资源保留待处理，不制造语义等价证明。
4. 默认技能不调用旧执行器；旧执行器的显式调用和历史读取暂不删除，也不为新路径生成其记录。现有专用父任务计划和发布链不在本次重写，普通父子关系不依赖它们。
5. 自举仍使用同一个技能脚本，直接模式接收明确任务、基线、交付提交和目标引用，由脚本复核当前 Git 和任务身份。调用者提供的是待验证输入，不是成功证明。只执行适用的同步、精确提交推送、开发应用更新、入口验证与最终诊断。
6. 一份 `openspec/knowledge/flows/task-closeout.md` 解释真实完整行为，架构入口只链接；技能不复制源码说明。历史方案和审查报告标明事实日期。

## Risks / Trade-offs

- 完成记录可能只是人的声明 → 不把 `completed` 自动投影为已通过机器验证，不伪造远端或测试证据。
- 拣选或变基导致提交不相等 → 自动清理保留资源并报告原因；智能体可在独立证明安全后选择对应工具，不增加通用语义证明平台。
- 自举改动影响共享本机环境 → 仍由唯一脚本核对分支、远端、干净状态和可恢复副作用；不发布 npm。
- 旧专用执行器仍在源码中 → 文档明确它不属于默认路径；本次不把退役整个研发、发布和父任务计划扩成前置任务。

## Migration Plan

先迁移默认技能和任务结果消费者，再放开独立清理，最后对齐自举消费者。数据不迁移，已有结果保留。旧执行入口不再作为新收尾的前置。通过定向真实仓库测试验证内容保全、部分成功和重复执行。

## Open Questions

没有阻止本次实施的未决问题。未测试交付的业务风险判断继续按实际项目约束处理，不在这里新增统一豁免政策。
