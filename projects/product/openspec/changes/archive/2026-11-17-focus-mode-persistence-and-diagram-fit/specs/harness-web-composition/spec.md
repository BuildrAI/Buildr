# harness-web-composition Specification Delta

## MODIFIED Requirements

### Requirement: Development 必须保留对话模块展开偏好
Development 与嵌套的 Harness 网页 MUST 在同浏览器配置域内记住用户明确选择的展开或收起状态、专注或分屏模式以及专注模式下的对话列表展开状态，刷新时稳定恢复，不得因可驱逐工作缓存占用浏览器存储配额或嵌入式 iframe 初始化握手顺序而退回默认状态；无偏好保持收起及分屏默认。普通分屏模式刷新时仍保持分屏对话视图；收起面板或退出专注模式 MUST 同步清理专注与对话列表展开偏好。嵌入式页面再次加载时，宿主 MUST 重新下发当前模式与列表视图配置，在内层确认首次配置前不得以默认对话视图覆盖已恢复的列表视图；切换专注或分屏模式事件 SHOULD 携带明确目标状态。写入浏览器持久化存储遇到配额异常时，MUST 允许按需清理可重建的源码控件缓存后重试，并结合同标签页会话存储兜底；浏览器存储完全不可用 MUST NOT 阻止当前操作；恢复 MUST NOT 发送消息。

#### Scenario: 刷新恢复展开
- **WHEN** 用户处于展开的分屏对话模式或收起状态并刷新页面（包括存在缓存占用浏览器存储配额的场景）
- **THEN** 外层模块 MUST 稳定恢复展开与分屏模式或收起状态，不因刷新退回专注或丢失当前模式，原对话由 Harness 自身恢复

#### Scenario: 刷新恢复专注模式与对话列表
- **WHEN** 用户进入专注对话模式并切换对话列表展开状态后刷新页面（包括 `buildr:source-control-cache:*` 已占满 `localStorage` 或 iframe 重新加载的场景）
- **THEN** 页面 MUST 稳定保持在专注对话模式，桌面满足并排宽度时对话列表 MUST 保持刷新前的展开或收起状态，原对话选择与草稿保持不变，且不自动发送消息
