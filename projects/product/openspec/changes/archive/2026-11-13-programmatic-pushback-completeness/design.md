## Context

事件回推由 `@buildr-ai/buildr-agent` 的视图差分投影生成，并由 Buildr 宿主按程序接入凭据配置。现有投影只保存 run 状态、请求签名与静态详情，无法表达节流中的最新中间消息、连续空闲时间或完整卡片身份。

## Decisions

1. 投影状态扩展为每个 run 保存活动签名、最后活动时间、已完成工具数、进度签名、上次进度推送时间与待发送的最新中间消息。活动签名覆盖消息、工具状态与 run 状态，恢复后重置停滞状态。
2. `run.progress` 在首个新中间消息满足间隔时立即推送；随后同一 run 相邻推送至少间隔五分钟，间隔内只保留最新一条。周期检查负责在窗口结束时推送待发送内容。
3. `run.stalled` 只针对 starting/running/tools-active；连续二十分钟活动签名不变时推送一次，状态保存在持久投影中，恢复后允许下一轮空闲再推送。
4. 终态事件从持久对话记录读取该 run 的最后一条可见 assistant 消息，原样放入 `finalReply`；`summary` 继续最多 500 字。轻量接口按 runId 读取同一事实，不返回完整对话。
5. 终态 URL 使用相对程序 API 根的 `/workspaces/{workspaceId}/conversations/{conversationId}/runs/{runId}/final-reply`，只要求 read 权限。
6. 凭据权限快照由宿主在程序调用、回推配置操作与凭据变更后写入私有回推存储；事件生成时读取该快照，保证 payload 字段存在且与最近一次宿主观察一致。
7. 进度与停滞开关持久化在每凭据回推配置中，默认 true；关闭时对应事件不生成，不影响其他事件和补查。

## Risks

- 事件体变大，尤其终态回复与问题卡；轻量 URL 为接收端提供按需读取路径，但终态所需完整回复仍直接入 payload。
- 活动签名包含流式消息文本，文本持续变化会延后停滞判定；这符合“有新记录”的语义，但会消耗持久投影计算。
- 进度五分钟合并与现有超限合并分别处理：前者是产品节流，后者是速率压力保护，二者均保留最新内容。
