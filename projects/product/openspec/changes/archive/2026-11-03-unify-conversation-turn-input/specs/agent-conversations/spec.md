## MODIFIED Requirements

### Requirement: 输入与执行反馈必须构成日常使用闭环

对话 MUST 支持文本输入、流式回复、基本工具进度、必要文件改动与错误反馈；必要图片 MUST 按所选接入及模型的真实能力提供有界输入和本机私有保存。不支持或超限时 MUST 在发送前说明并保留草稿。输入框明确提交的文字或图文 MUST 在同一可见对话开启新轮，MUST NOT 隐式作为原轮补充。系统 MUST 在独立新轮原生确认受理后结束旧问题等待并保留未回答事实，MUST NOT 补造回答、许可或旧操作成功。问题卡片回答 MUST 绑定准确原请求并继续原轮，不因输入框草稿或模型选择改变而自动交接。Codex、DSH、Qoder MUST 遵守相同语义。Adapter声明支持纯问题释放、同组合只有普通问题等待且无活动工具时，系统 MUST 在准确旧轮安全结束后优先复用原生会话；控制未知或有活动工具时 MUST 保全原身份并安全隔离，不强杀共享宿主或重放历史。未发送输入仍为草稿，MUST NOT 因输入或刷新自动交付。补充 MUST 不切换参与者、模型、权限或执行位置，不隐含回应原生授权和业务问题。

#### Scenario: 执行中主动补充图文
- **WHEN** 当前执行身份已确认且仍在运行，用户保持相同选择并主动补充文字、图片或图文组合
- **THEN** 系统 MUST 将该输入交付新轮并独立保存其尝试与接收结果；旧问题等待结束，原操作结果按真实事实保留
- **AND** 界面 MUST 沿用普通消息展示，不要求切换插入或排队模式

#### Scenario: 执行中继续编辑
- **WHEN** 用户只编辑输入而未提交发送
- **THEN** 系统 MUST 保留草稿，不自动发送；用户明确提交新要求时 MUST 按所选组合独立接收，MUST NOT 假称已送达或重发原未知操作

#### Scenario: 图片输入超过限制
- **WHEN** 图片不符合所选模型支持范围或超过已声明大小
- **THEN** 系统 MUST 提示受影响图片和原因，并保留可继续编辑的文本与材料
- **AND** MUST NOT 通过静默删图把请求显示成完整发送

#### Scenario: 等待明确授权时补充
- **WHEN** 原执行等待授权或业务问题，而用户发送普通补充
- **THEN** 旧问题 MUST 结束活动等待并保留未回答事实；新输入 MUST NOT 作为原请求的回答或批准
- **AND** 新轮尚未受理时 MUST 保留输入和原等待事实，不以预览或选择变更清理原问题

#### Scenario: 文件已被其他入口修改
- **WHEN** 智能体（Agent）继续读取或修改已有成果
- **THEN** 工作依据 MUST 是当前文件或外部系统事实，历史工具摘要不能证明内容仍未变化
- **AND** 工作页面 MUST 能继续使用原查询与刷新读取同一成果，不要求新增通用工作对象库

## ADDED Requirements

### Requirement: 新轮接续必须保留原执行工作并固定归属
Agent Service MUST 统一轮次与问题接续语义，Adapter MUST 只映射其原生能力。Adapter支持纯问题等待释放时 MAY 在同一原生会话接续；否则Service MUST 在独立上下文调度新轮。新指令 MUST NOT 终止旧轮活动工具或后台任务，MUST NOT 在执行途中改写run或条目的参与者归属。独立新轮未原生受理时 MUST 保留旧卡片和执行。同会话已释放等待而新轮启动失败时 MUST 如实保留不可回滚事实与新指令，不补造回答或重放旧操作。

#### Scenario: 独立新轮启动失败
- **WHEN** 新轮因模型、网络或配额失败而未原生受理
- **THEN** 原问题及执行 MUST 保持，不因本地submit成功而关闭

#### Scenario: 工具执行期间提出新要求
- **WHEN** 旧轮有活动工具或后台任务，用户发送新要求
- **THEN** 新轮 MUST 独立接续，旧工具继续保留准确控制和结果；MUST NOT 调用整轮停止以清理问题

#### Scenario: 适配器不支持纯问题释放
- **WHEN** 原生没有可用的纯问题释放能力
- **THEN** Service MUST 在独立新轮受理后核对旧轮真实等待与活动工具，再安全释放等待或保留原控制，MUST NOT 改写新轮归属或重复停止
