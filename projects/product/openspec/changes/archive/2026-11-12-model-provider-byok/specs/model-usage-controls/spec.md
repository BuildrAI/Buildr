## MODIFIED Requirements

### Requirement: 右下角入口悬停查看全部已启用来源额度

系统 MUST 在右下角供应商设置图标悬停或键盘聚焦时显示全部已启用供应商中已登录或已连接账号的额度概览，保留账号身份、平台报告的每个周、日、小时或其他额度窗口、余额币种、剩余 credits（平台返回时）与观察时间；不得只展示当前模型账号或只展示周窗口。概览 MUST 按供应商显示名称稳定排序，同一供应商内按账号名排序；供应商顺序不得随接口返回顺序或刷新变化。未知、失败和旧观察 MUST 明确表达。点击 MUST 保留打开原设置的行为。供应商级停用 MUST 按供应商停用规则隐藏其账号；模型级停用 MUST NOT 隐藏已登录或已连接账号。

#### Scenario: 多账号混合额度
- **WHEN** 已启用供应商中的已登录或已连接账号分别提供周窗口、日或小时窗口、账户余额或未知额度
- **THEN** 悬停概览逐账号显示对应事实及时间，无百分比的余额不产生进度条，模型级停用不隐藏已登录或已连接账号

#### Scenario: 多来源按显示名称排序
- **WHEN** 已登录或已连接账号来自 `ChatGPT`、`ChatGPT API`、`DeepSeek`、`Qoder`、`Qoder CN` 与自定义供应商等供应商
- **THEN** 概览 MUST 按供应商显示名称排序，同一供应商的多个账号按账号名排序
- **AND** 排序 MUST NOT 改变账号身份、额度事实或点击行为

#### Scenario: 自定义供应商额度未知
- **WHEN** 已启用的自定义供应商已保存配置且模型可用，但没有可读取的平台额度
- **THEN** 概览 MUST 显示该供应商及额度未知事实
- **AND** MUST NOT 将其显示为零余额或耗尽

#### Scenario: 读取失败及入口可用
- **WHEN** 概览读取失败或没有已登录或已连接账号
- **THEN** 显示读取失败或空状态，点击按钮仍能打开原设置，未登录与断开账号不伪装为已登录

### Requirement: 账号卡片必须支持独立 ChatGPT API 来源原位配置

账号设置 MUST 提供与订阅账号分开显示的内置 `ChatGPT API` 供应商卡片。未配置时 MUST 在原卡片提供密码输入与保存动作，不要求切换独立页面；内置 `ChatGPT API` 卡片 MUST NOT 提供 URL 输入。用户自定义供应商 MUST 使用独立编辑界面声明名称、Base URL、协议、可选 API Key 与模型列表，并按 `custom-model-providers` 规范管理。校验成功后 MUST 在同一卡片展示供应商状态、模型入口、观察时间及额度未知事实；校验失败 MUST 保留输入操作与其他供应商，不得把失败账号显示为已登录。订阅供应商与 API Key 供应商 MUST 能同时显示为已连接或可用，不提供互斥启用要求。供应商列表 MUST 按显示名称稳定排序，`全部供应商` 固定在首位，使 `ChatGPT` 与 `ChatGPT API` 相邻显示，并使自定义供应商按名称参与排序。

#### Scenario: 首次配置 API Key

- **WHEN** 用户在 ChatGPT API 卡片填写密钥并保存
- **THEN** 卡片 MUST 显示校验中状态，完成后显示可用模型与观察时间
- **AND** 密钥 MUST 以密码输入呈现且保存后不再显示原文

#### Scenario: 无效密钥诊断

- **WHEN** 保存的密钥被服务商拒绝
- **THEN** 卡片 MUST 显示具体认证或权限诊断并允许重新输入
- **AND** 其他账号卡片 MUST 保持原状态和模型

#### Scenario: 管理已连接 API Key

- **WHEN** ChatGPT API 供应商已连接
- **THEN** 用户 MUST 能刷新模型、更换密钥、管理模型启停和上下文并断开该供应商
- **AND** 断开或更换 MUST 不影响 ChatGPT 订阅账号及无关供应商

#### Scenario: 订阅和 API Key 同时可用

- **WHEN** ChatGPT 订阅账号和 ChatGPT API 供应商均已成功连接
- **THEN** 两张供应商卡片 MUST 同时保持可用状态
- **AND** 系统 MUST NOT 要求停用其中一个供应商才能启用另一个

#### Scenario: 账号来源名称排序

- **WHEN** 账号设置同时展示 ChatGPT 订阅、ChatGPT API、自定义供应商与其他供应商
- **THEN** 供应商列表 MUST 按显示名称排序，`ChatGPT` 与 `ChatGPT API` MUST 相邻
- **AND** `全部供应商` MUST 始终位于供应商列表首位，排序不得改变当前选择或账号状态

#### Scenario: 自定义供应商卡片

- **WHEN** 用户添加并保存有效的自定义供应商配置
- **THEN** 供应商列表 MUST 显示其卡片、供应商状态、模型入口、观察时间与额度未知事实
- **AND** 配置无效时 MUST 保留输入操作并显示诊断，其他供应商 MUST 保持原状态

### Requirement: 账号来源停用必须默认隐藏且保留账号事实

系统 MUST 以独立于登录、断开和账号可用状态的持久化供应商状态表达供应商停用，MUST NOT 复用“断开”语义。停用 MUST 保留凭证、登录尝试、账号身份、历史对话、已有租约与模型偏好，MUST NOT 更换身份、释放已有租约或使凭证失效。

停用供应商 MUST 从默认供应商列表、模型目录、模型选择器和额度概览中隐藏，MUST NOT 参与新对话或新执行的模型租约。系统 MUST 继续支持按准确账号身份读取停用供应商及历史记录；已有执行 MUST 继续到终态，不因供应商停用被中断。账号管理 MUST 提供明确的“显示已停用供应商”和“重新启用”入口；重新启用 MUST 恢复同一供应商及其既有凭证和偏好，不要求重新登录或重新填写自定义配置。

#### Scenario: 停用来源后隐藏且可恢复
- **WHEN** 用户停用一个已登录或已连接的模型供应商并刷新页面
- **THEN** 该供应商不再出现在默认供应商列表和模型选择器中，也不能创建新租约
- **AND** 管理界面通过“显示已停用供应商”仍能读取该账号，重新启用后恢复原账号、模型偏好与登录或连接状态

#### Scenario: 停用不破坏历史与运行中工作
- **WHEN** 供应商停用前已有历史对话或正在执行的租约
- **THEN** 历史对话和运行记录仍按原供应商可读，运行中的租约不被中断
- **AND** 新执行 MUST 明确拒绝该供应商，而不是伪装为模型不存在或账号未登录

#### Scenario: 模型级停用与来源级停用分离
- **WHEN** 用户只停用某供应商下的一个模型
- **THEN** 该供应商仍出现在供应商列表和额度概览中，仅该模型退出新选择
- **AND** 供应商级停用才隐藏整个供应商，两种状态互不覆盖
