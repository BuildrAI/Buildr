## MODIFIED Requirements

### Requirement: 停止必须区分模型中断和活动工具退出

用户停止时系统 MUST 先发送原生中断并显示正在停止，自动观察本轮模型及相关活动工具的真实结果。中断请求成功或模型本轮结束 MUST 不单独证明命令退出。仍有活动工具时 MUST 显示准确未停项并提供可验证的针对性停止；状态无法确认时 MUST 明确未知。只有本轮相关执行已确认停止且不会继续延迟写入时，才可显示已停止。停止 MUST 不误停此前用户有意保留、与本轮无关的后台服务。

#### Scenario: 正常停止得到完整确认
- **WHEN** 原生确认本轮中断且相关活动工具均退出
- **THEN** 系统 MUST 自动显示已停止并保留历史和已发生的修改
- **AND** MUST 不要求用户为正常路径再手动核验一次

#### Scenario: Codex 中断后命令仍在运行
- **WHEN** 模型本轮已中断而本轮原生终端仍有活动命令
- **THEN** 系统 MUST 显示命令仍运行，并按准确原生终端身份停止与核对退出
- **AND** MUST NOT 用全对话清理或未经核实的操作系统进程号替代针对性处理

#### Scenario: 当前工具不支持单独停止
- **WHEN** 原生接入无法按准确工具身份单独停止某活动命令
- **THEN** 界面 MUST 不将该工具展示为可单独停止，仍保留活动事实与重新观察入口
- **AND** 单工具停止被拒绝时 MUST 保留原本轮状态，MUST NOT 先标为整轮正在停止或据后续空闲误标全部已停止

#### Scenario: 断线后结果未知
- **WHEN** 连接断开导致不能确认执行或工具终态
- **THEN** 系统 MUST 显示状态未知并允许重新观察，保留历史和草稿
- **AND** 未确认结束前 MUST 拒绝该对话的普通新执行、自动接续或换家发送，但不阻止其他独立对话；用户明确继续原目标且满足“控制资源释放后的显式继续”全部条件时，MUST 允许该次手动接续并保留旧结果未知

## ADDED Requirements

### Requirement: 控制资源释放后的显式继续

用户已明确要求继续原目标、准确原轮已受理且结果未知、原控制资源释放已经核验、没有待决定及该对话的在途工作、并且原参与者、模型来源、模型、档位和权限保持一致时，系统 MUST 允许用准确原轮身份手动预览并接续一次。系统 MUST 保留原轮未知结果、工具条目和原生执行引用，接续提示 MUST 要求先核对当前成果及未知命令，MUST NOT 重放原指令或工具、推定独立命令退出、宣称旧工作成功或代答问题。预览和发送 MUST 校验同一已观察版本与准确原轮；没有释放证明、存在待决定或选择变化时 MUST 拒绝此例外。普通发送、排队及自动恢复 MUST NOT 获得此例外。

#### Scenario: 已释放但原结果未知时明确继续
- **WHEN** 用户要求恢复原对话，准确资源释放已成立，原轮仍有未知工具结果且没有其他在途工作或待决定
- **THEN** 原组合的显式继续 MUST 被接受一次，原轮和工具结果 MUST 继续保持未知并可查，接续提示 MUST 要求先核对现状

#### Scenario: 没有释放证明或存在待决定
- **WHEN** 释放未确认、原轮身份或版本变化、请求仍待答、原轮中断前有未解决决定、或者选择发生变化
- **THEN** 手动继续 MUST 被拒绝，原记录和输入 MUST 保留

#### Scenario: 禁止隐式恢复未知结果
- **WHEN** 页面刷新、后台重启、自动恢复、普通发送或排队发生
- **THEN** 系统 MUST NOT 据资源释放自动重发或续做未知操作
