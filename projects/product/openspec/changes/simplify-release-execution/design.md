## Context

现有验证框架已能逐项保存和复用结果，但发布入口混入编辑要求，插件预检要求运行完整 SDK 与旧对端检查；默认输出大量细节并由智能体反复接续。公开发布收尾还依赖本机自举激活。

## Goals / Non-Goals

**Goals:**
- 只修改发布动作、验证必要性和 Codex 介入三项。
- 一轮集中收集失败；修复后复用仍有效的成功结果，只补失败和受影响检查。
- 保留准确来源、版本、原包、授权、功能、安装和兼容证明。

**Non-Goals:**
- 不重写验证框架，不新增旁路状态库，不改变候选内容，不执行公开发布。
- 不通过删减真实功能测试宣称发布已加速。

## Decisions

1. 本机开发应用激活继续由原唯一执行器负责，但不再是发布完成条件；登记或清理失败只恢复对应步骤。
2. 删除 README 编辑断言。有独立价值的架构、文档和规范静态检查保留可显式选择的开发入口，移出候选必跑集合；涉及产品实际功能的测试保留。
3. 插件增加使用现有证明存储的源码单元入口，无需 SDK 或旧对端。准确对端的完整安装与兼容验证不变。
4. 发布命令默认摘要，完整结果可显式获取或写文件；等待由同一程序执行，遇真实失败、缺少本机证明或授权时返回明确缺项，不自动重复公开副作用。

## Risks / Trade-offs

本机实测的五项修复只调整检查边界：删除统一文件大小门槛、历史大小例外及三项专门测试；源码网页检查改用轻量页面替身，删除与真实前端验收重复的页面结构及内容断言。Git 引用检查仍在原五秒期限内等待目标事件。混合资料场景只证明无关代码保全，复用纯资料场景的其余证明；资产整组上限由三分钟调为五分钟，子场景时限不变。只运行受影响入口，首轮失败修正后只补该用例，不新增入口或整套重跑。原测试价值清单保留原审查时点。

- 文档编辑缺陷不阻止发布，开发阶段仍可选择对应检查。
- 自动等待需有时限并可中断，超时保留原运行身份；不能把等待结束当作成功。
- 本轮用定向回归证明行为，完整发布实际节省留待下一次真实发布测量。

## 本轮测试价值审查

先全量分类，再删除无独立价值的固定措辞、任意篇幅、重复工具版本和实现快照；混合文件中的真实功能、数据保护、安装兼容和实际接口证明保留。执行检查程序里的重复要求一并删除。完整核销见 [测试价值审查](test-value-review.md)。

此前的 C 类删除与本轮已授权的三项机制调整分别记录；删除数量不能证明发布耗时或模型用量下降，完整发布节省仍待实际测量。

## 发布现场修复的三项限定调整

1. 现有 `test:changed` 同时选择受影响、无需候选原包的 `package-selector` 源码检查；最终原包消费者仍留在制包后。现有持续集成（CI）的开发反馈同时适用于 `dev` 的直接推送，沿用准确差异基线，不新增作业或检查。
2. 原有快速检查和验证工具检查仍执行，但不再自动成为所有其他检查的前置条件。只保留各检查已声明的真实依赖；独立失败由既有调度器集中返回。
3. 可执行辅助测试代码按真实导入归属，不因无关辅助文件修复使所有证明失效；目录发现、非代码材料和未知动态读取仍保守绑定。既有 `test:focus` 使用正常执行器、资源限额及证明存储，保留用例名称与耗时；诊断成功直接采用，不再另做同条件的正式重跑。

不增加测试文件、检查入口、额外门禁或自动重试；不提高超时时限来掩盖未定位的问题。
