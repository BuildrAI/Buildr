## Why

一次候选准备因重复开发检查、完整插件预检和智能体反复查看运行进度耗时过长。发布后还等待本机开发应用更新，扩大了发布完成条件。本轮只精简已确认的三项，不改变公开授权、准确原包和真实兼容证明。

## What Changes

- 发布完成不等待本机开发应用更新；任务登记和安全清理保留既有事实并只恢复失败动作。
- 删除 README 固定标题、章节和编辑表达的发布检查；有独立价值的文档、架构与规范静态检查保留在相关开发入口，真实功能与原包兼容检查继续保留。
- 本机插件源码预检只执行可复用的独立单元测试，完整插件验证留给准确候选配对。现有发布程序负责持续等待并默认输出摘要，完整证据仍可保存。

- 全量审查三个服务的测试及执行入口，按 A/B/C 分类，删除 C 类及检查程序里的相同要求；此前审查阶段未改变调度依赖和结果复用粒度。
- 接续用户授权，仅补齐现有日常检查选择、解除全局失败阻断，并收窄辅助测试代码的结果失效范围；正式定向诊断通过后直接复用，不新增流程或检查。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `release-collection-model`: 收窄发布完成条件和验证选择，减少重复执行与智能体介入。

## Impact

影响发布技能及其脚本、产品既有验证定义、插件本机验证入口和相应说明。不重新打包、不派发公开发布，不改变现有候选原字节及其历史证明。
