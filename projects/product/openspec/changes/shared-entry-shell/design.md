## Context

当前 `AppLayout` 通过 `navigationState` 判断工作台、工作空间或代码区域，并渲染对应左侧导航。`WorkspacePages` 已经按工作空间保存页面页签和已访问页面，`WorkspacePaneHost` 已按当前页面标签筛选右屏对象；`WorkspaceStage` 让任务列表、服务目录等项目注册自己的页面与右屏内容。代码资源管理器与源代码管理已有独立的文件树和文件页签。

缺口集中在页签识别与入口跳转：工作台概览不是页面页签，代码页签被排除在共享页签栏之外，关闭最后一个页签固定回项目目录，顶部代码入口固定去源代码管理。

## Goals / Non-Goals

**Goals:**

- 三个顶部入口共用 `WorkspacePages` 的一套页面页签和 `WorkspacePaneHost` 的右屏。
- 顶部入口只打开或聚焦默认页签，不改变已打开页签集合。
- 右屏继续由当前页面标签注册，切换和关闭页面标签时保持正确归属。
- 保持代码页内部文件页签、文件树宽度和源代码管理分屏不变。

**Non-Goals:**

- 不把代码文件提升为全局页面页签。
- 不新建第二套壳层、全局状态仓库或后端接口。
- 不改变右屏已有的拖拽、折叠、暂看和滚动恢复交互。

## Decisions

### 复用 `WorkspacePages`，扩展页签识别

在 `tabForPath` 中增加工作台概览页签，并让 `dir:code:*` 页签参与共享页签栏与排序；代码页仍由 `CodeExplorerPage` 渲染，文件页签留在页面内部。备选方案是新建一套三入口壳层，但会复制页签持久化、保留页面和右屏逻辑，且容易再次分叉。

### 代码页使用共享页签栏

代码页不注册共享右屏内容，因此 `WorkspacePaneHost` 对代码保持禁用；由 `FallbackPageHeader` 渲染共享页面页签栏。这样代码页上方只有一条页面页签，文件页签仍在编辑器内部。备选方案是让代码页也注册 pane host，但会引入空右屏或额外占宽。

### 右屏归属沿用现有页面注册模型

`WorkspacePaneHost` 已按 `currentPath` 选择当前页面标签注册的对象页签，无需新增全局映射。关闭页面标签时同时清除该路径的 preview 状态，避免重新打开页面时恢复已关闭的右屏对象。

### 默认页签由纯函数解析

增加区域到默认页签的纯函数：工作台为概览，工作空间为工作空间总览，代码为源代码管理。关闭最后一个页签时从当前路由解析区域并补开默认页签。顶部入口跳转使用同一套目标：工作台固定概览，工作空间固定工作空间总览，代码优先恢复 `AppLayout` 观察到的上次有效代码路径。

### 工作台概览使用 functional 页面布局

工作台概览成为页面标签后，继续使用页面自身的最大宽度和内边距；将其标记为 functional 页面，避免 `.workspace-page` 叠加第二层留白。

### 不迁移存储格式

页面页签继续使用现有 localStorage 键和 `tabForPath` 校验。旧数据中无法识别的路径会被丢弃；代码页签已在 `tabForPath` 支持范围内，不需要数据迁移。

## Risks / Trade-offs

- [代码页出现两条页签栏] → 共享页面页签保持在顶部，文件页签保持在编辑器内部；视觉层级沿用页签条样式，不合并两类身份。
- [顶部工作空间入口不再恢复上次页面] → 工作空间总览会作为默认页签打开，其他页面页签仍保留；用户可通过页签一键恢复。
- [旧存储中出现此前隐藏的代码页签] → 仅保留 `tabForPath` 可验证的路径，无效路径自动丢弃。
- [关闭最后一个页签后立即重开默认页签] → 这是已确认行为；关闭动作仍保留同工作空间的其余页签，不会清空整个工作空间现场。

## Migration Plan

无数据或接口迁移。发布后首次进入沿用现有页面页签存储；回滚只需恢复前端代码。代码页签和概览页签在旧版本中不可见，不会被旧版本误用。
