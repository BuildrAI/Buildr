## MODIFIED Requirements

### Requirement: 智能体服务必须独立维护并随现有宿主交付

智能体服务（Agent Service）MUST 以 `services/buildr-agent/` 为独立源码、依赖、构建及验证单元，拥有接入、统一对话、参与关系、执行协调、私有交互存储和语义事件，并作为 Buildr Harness 的核心提供公共客户端、契约及本机独立进程承载。Buildr Development MUST 随包交付兼容负载，既有用户使用 Development MUST 不必另装常驻服务、手动启动端口或配置另一套后台认证；可选独立产品的安装与网页承诺由相应能力规范定义，不以本条源码独立代替交付完成。两入口 MUST 共享同用户同配置域的逻辑服务及资料，不能各起一套写入核心。厂家原生进程仍由各适配器按其实际方式管理。

Development 宿主 MUST 保留其工作空间及任务权威查询、页面身份认证和同源代理责任。Harness MUST 拥有通用 HTTP/SSE 协议、目录宿主及执行私有数据的唯一维护；其核心 MUST 通过版本化执行操作、宿主能力和运行管理约定接入，不导入 Development 业务内部实现、不直接改写任务或工作资产，不依赖浏览器请求对象。Development 消费者 MUST 只使用公开能力，不依赖服务私有存储或厂家 SDK；前端所有权由前端能力规范维护。

#### Scenario: 在没有源码相邻目录的正式安装中运行
- **WHEN** 用户从正式 Development 发行包安装并打开对话能力
- **THEN** 所需核心构建、独立进程入口及运行依赖 MUST 已包含在可解析的发行路径中，后台按准确身份自动发现或启动
- **AND** MUST NOT 依赖开发工作树、相邻源码目录、实验脚本或未交付本机依赖
- **AND** 浏览器 MUST 继续使用 Development 同源认证入口，用户不必另外安装或手工配置 Harness

#### Scenario: 单独验证智能体服务的核心行为
- **WHEN** 维护者验证统一对话、交付或停止状态
- **THEN** 核心 MUST 能以替身执行者和显式宿主能力验证，不要求启动 Development 或调用真实模型
- **AND** 安装及真实接入验证 MUST 分别覆盖宿主装配、运行依赖与实际支持的原生路径，不能由核心单元验证代替

#### Scenario: 独立产品接入边界验证
- **WHEN** 目录宿主使用相同公开客户端及交付运行单元
- **THEN** 系统 MUST 完成对话、交接、回应及停止，不加载 Development 的任务、工作空间或网页模块
- **AND** 独立 Harness 产品可消费该能力，但源码独立和替身通过 MUST NOT 单独证明独立安装验收完成

### Requirement: 原生进程必须按拥有关系和真实存活状态管理

系统 MUST 只管理本接入创建且身份可证明的原生进程与连接。浏览器关闭 MUST 不等于执行后台退出；Development 或独立网页宿主普通退出、重启 MUST 仅断开该入口连接，已受理执行、模型转接、待回应与结果保存 MUST 继续由共享独立后台持有。断开具体原生接入 MUST 停止其新请求并释放本连接资源，但不能被解释为账号退出、历史删除或活动命令已经停止。

执行后台自身退出 MUST 有界处理中断与自有资源释放，保留未确认执行的状态，不承诺后台自身退出期间活动工作持续运行。旧后台或相关原生执行的持有状态未确认时 MUST 不启动会造成同一执行重复运行的替代者。兼容后台更新 MUST 按原轮归属与共享配置唯一维护责任并行承接，新版不得恢复仍由旧后台持有的工作；不兼容升级 MUST 等待真实释放及有界交接。宿主重连 MUST 不产生新执行恢复代次，跨入口控制 MUST 始终路由到准确持有者。

#### Scenario: 前端关闭后重新打开
- **WHEN** 对话页面关闭而共享后台及原生执行仍在运行
- **THEN** 任一获相应权限的入口重新打开 MUST 能观察原执行及待回应，不创建第二次执行

#### Scenario: 断开存在活动执行的接入
- **WHEN** 用户断开正在执行或等待回应的原生接入
- **THEN** 系统 MUST 保留对话与已有成果，并准确表达中断、活动工具或未知状态
- **AND** MUST NOT 显示未经确认的“已停止”，也不能关闭外部桌面、其他连接或另一产品无关工作

#### Scenario: 后端重启发现未确认执行
- **WHEN** 执行后台自身恢复后发现上次执行未有确认终态
- **THEN** 系统 MUST 先恢复准确配置并观察原生状态及历史，再按所属来源策略判断可否安全接续
- **AND** MUST NOT 仅凭 PID 消失或传输断开自动重发上一条指令

#### Scenario: Buildr 主程序重启而后台仍存活
- **WHEN** Development 主程序重启并发现原独立后台
- **THEN** 系统 MUST 重连并观察原执行，保留原生身份、后台代次和待回应
- **AND** MUST NOT 调用后台退出或以主程序重启为由自动发送续做

#### Scenario: 另一产品控制旧代次执行
- **WHEN** 获授权入口对兼容退役代次仍持有的轮次发送准确停止或答复
- **THEN** 请求 MUST 作用于原持有者，不被新版接成新轮；结果未知必须保留并查询，不重复执行
