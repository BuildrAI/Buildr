## 上下文

首期目标来自集鲜工作空间的原型评审：本地受管启动 + QA 部署提交，运行定义服务级维护，不接管 CI/CD 页面。原型已确认信息架构：工作台只读汇总、服务目录合并状态列、服务详情集中管理，启动/QA/日志/识别统一抽屉。评审版原型 HTML 归入本变更 `prototypes/`（正文与阅读器），源码候选位于同工作树 `projects/product/services/buildr-web/src/prototypes/service-runtime/`；正式前端实现 MUST 按其信息架构、布局与交互开发。本设计只覆盖 Buildr 产品侧职责；连接技能（如集鲜云雀）在其自己的工作空间实现适配器程序。

## 关键取舍

### 运行定义放工作空间服务资产目录
运行定义写入 `services/<service-code>/runtime.yml`（Git 跟踪），而不是服务代码仓库或项目目录。理由：服务被多个项目共享，定义属于工作空间对服务的事实；Git 跟踪使来源与变更可审查；智能体与人都能按同一路径读写。代价：跨工作空间不共享定义，接受（运行定义与本地环境强相关）。工作目录字段相对每个检出根解析，启动时结合具体工作树。`environments` 是环境映射：首期预置 `qa`，其他环境由智能体识别时追加；目录状态列固定在本地之外显示一个环境并以计数提示其余环境，浮窗与详情按数据展开，不为增加环境修改表格列。

### 受管进程归属本机 runtime
启动/停止/端口/就绪/日志由 `buildr` 服务的本机 runtime 承担，经既有 runtime HTTP 表面暴露给 Web 与 CLI，不新增独立守护进程。运行记录与日志落在 `.buildr/local/service-runtime/runs|logs/<run-id>`（Git 忽略）。崩溃残留风险：运行记录保存 pid，runtime 启动时对账清理僵尸记录；未知结果只报告不猜测。

### 端口分配全局避让
端口在 workspace 级受管实例集合内分配，并探测本机占用；首选端口被占用时递增避让并记录说明。不做跨机器或跨 workspace 协调（超出首期）。

### 部署走连接技能程序而非内置客户端
Buildr 不内置云雀客户端：连接技能在连接声明中登记部署程序（Program），Buildr 经 `connection-skill run` 的私有子进程通道调用它提交部署、查询远端分支与最近结果。连接技能的槽位（Hook）在校验中限定 `effect: read`，因此写效果的提交只能走程序，这一约束保持不变，认证不进入 Buildr 日志或页面。归一化结果结构固定（state/version/at/externalUrl），使换 CI/CD 提供者只需新连接技能实现同契约。代价：首期依赖集鲜工作空间补齐云雀适配器；Buildr 侧以契约测试（mock provider）证明自身行为。

### 首期不做手动配置
运行定义只由智能体发现并验证后写入；页面只读展示来源与验证时间，配置有误重新配置。理由：用户判断大概率由 Agent 配置，手动字段等真实纠错需要再评估，避免先造字段后造功能。重新配置直接替换定义但保留来源与验证时间，不引入差异合并 UI。

### Web 复用既有壳层与抽屉
三页与抽屉全部复用应用壳、页签（PageTabStrip）与 DrawerShell；目录状态列合并本地与环境行以保证行高一致与可扩展（新增环境只加数据）；截断时悬停/点击浮窗查看全量。服务主页紧随标题栏使用“详情/运行与部署”两个 antd 页签（Tabs），运行与部署区块内部再以页签切换本地与各环境；详情在前，避免运行内容插在文档与代码库之间。不新增全局状态仓库（Store），页面状态局部维护。

## 兼容与迁移

- 无破坏性变更：新增文件与表面；既有服务登记、连接技能运行时要求不变。
- 旧工作空间无 `runtime.yml` 时服务显示“尚未配置”，不影响其他功能。
- 运行记录与日志为本机状态，不迁移、不提交。

## 风险

- 受管进程孤儿化：pid 对账 + 停止只作用于记录内 pid。
- 部署未知结果：契约禁止自动重试，界面引导到外部系统核对。
- 端口竞争：启动时探测 + 失败即报告，不做预留锁。
