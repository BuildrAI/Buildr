## MODIFIED Requirements

### Requirement: 自动标题必须是与工作上下文隔离的简短摘要

用户输入被受理后，系统 MUST 立即以首条用户消息的规范化截取生成兜底标题，并 MUST 明确标记该标题来自首条消息，MUST NOT 把它标为智能摘要或冒充智能体（Agent）总结。首个轮次成功完成后，系统 MUST 通过一次独立的、无工具的、有界的模型请求尝试生成智能标题；该请求 MUST NOT 复用或写入工作的原生会话、不追加工作消息、不重放工具、不改变执行位置或原生恢复身份。系统 MUST 只在首个轮次完成后自动尝试一次，后续消息、刷新和服务重启 MUST NOT 自动重复尝试。自动生成失败时，系统 MUST 保留当前兜底标题（没有兜底标题时保留中性名称）并记录可解释的失败状态，MUST NOT 把标题替换为失败提醒文本。手动改名 MUST 优先于自动标题，迟到结果 MUST 校验准确对话及已观察版本。

#### Scenario: 执行开始后尽早回填

- **WHEN** 新对话的首次执行开始且用户输入被执行方受理
- **THEN** 系统 MUST 立即用该条用户消息生成兜底标题并标记来源，MUST NOT 等待模型返回
- **AND** 首轮成功完成后系统 MUST 再尝试一次独立智能标题，早期不回填不影响本次执行

#### Scenario: 自动标题全部失败

- **WHEN** 自动智能标题请求失败且标题仍为首条消息兜底标题或中性名称
- **THEN** 系统 MUST 保留当前标题并记录失败状态与原因
- **AND** 系统 MUST NOT 把标题写成失败提醒，MUST NOT 因该失败新增自动重试，工作执行与回复 MUST 不受影响

#### Scenario: 用户在自动标题返回前改名

- **WHEN** 用户已经手动保存名称，原智能标题稍后完成或失败
- **THEN** 系统 MUST 保留手动名称，MUST NOT 用后台结果或失败状态覆盖
- **AND** 原工作对话及执行状态 MUST 不受起名成功或失败影响

#### Scenario: 厂家只返回首句截取标题

- **WHEN** 执行方原生标题元数据表明结果为简单回退截取而非模型摘要
- **THEN** 系统 MUST 不将其标为已生成摘要标题
- **AND** 系统 MUST 使用首条消息兜底标题或独立模型请求，MUST NOT 向工作会话塞入起名指令

#### Scenario: 旧对话请求简短标题

- **WHEN** 用户对已完成且具有真实问答的准确对话明确请求“生成简短标题”
- **THEN** 系统 MUST 以已观察修订有界生成该段对话的名称，MUST NOT 根据猜测批量覆盖其他旧名称
- **AND** 请求期间用户再次手动保存名称时 MUST 保留新的手动名称，失败 MUST 不影响工作历史或发起工作重放
- **AND** 显式手动生成失败 MUST 保留当前名称及失败状态，MUST NOT 改写标题

#### Scenario: 标题失败后切换执行方

- **WHEN** 自动智能标题失败后用户切换到新的参与者继续该对话
- **THEN** 系统 MUST NOT 自动再次尝试生成，MUST 保留当前兜底标题
- **AND** 用户仍可显式请求生成或手动命名，工作执行 MUST 不受影响

#### Scenario: 旧标记与切回已尝试执行方

- **WHEN** 记录来自旧版本、带有旧尝试标记，或用户切回已经尝试过的参与者
- **THEN** 系统 MUST 按新规则把标题视为可手动或显式覆盖，MUST NOT 因旧标记自动重试
- **AND** MUST NOT 把旧失败当成已生成标题，也 MUST NOT 因切换、刷新或重启重复自动请求

#### Scenario: 标题调用跨层时间预算一致

- **WHEN** 原生标题请求需要读取模型目录并等待模型返回
- **THEN** 外层调用 MUST 覆盖已承诺的内部请求预算，MUST NOT 在内部合法等待期间提前报原生超时，整体仍保持有界

#### Scenario: 取消独立标题

- **WHEN** 标题请求超时或调用方取消
- **THEN** 系统 MUST 按准确辅助请求释放连接与响应，不中断工作执行或其他对话
- **AND** 未确认释放时 MUST 保留原因并保留当前标题

### Requirement: 中性标题必须提供可解释的生成状态

标题状态 MUST 允许用户区分等待首轮完成、正在生成、已生成、兜底标题、手动设置、生成失败、能力不可用和旧记录状态未知。兜底标题 MUST 与智能标题区分展示，使查看者能判断名称来自首条消息而非模型摘要。系统 MUST 保留失败不阻塞工作、手动改名优先、只在首轮完成后自动尝试一次以及重启不重复消耗尝试的约束；MUST NOT 为消除中性名称而截取首句冒充摘要或自动重放工作。自动智能标题失败 MUST 只在状态与原因中体现，MUST NOT 写入失败提醒标题或冒充已生成的摘要标题。

#### Scenario: 新对话仍在执行

- **WHEN** 新对话首轮执行开始且输入已被受理
- **THEN** 系统 MUST 展示首条消息兜底标题并说明其来源
- **AND** 智能标题 MUST 在首轮成功完成后尝试一次，不得仅因执行未结束而写入失败提醒或重复请求

#### Scenario: 自动标题失败

- **WHEN** 智能标题生成超时、结果不合格或生成期间对话版本变化
- **THEN** 系统 MUST 保留当前兜底标题、失败原因及工作历史，并提供适用的显式生成入口
- **AND** 刷新、后续普通消息或重启 MUST NOT 无界重复自动生成，MUST NOT 写入失败提醒标题
