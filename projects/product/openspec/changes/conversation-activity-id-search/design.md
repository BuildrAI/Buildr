## 上下文

对话列表的活跃判断同时参与摘要、已读和历史列表。当前实现把历史保留执行中 `status=unknown` 且 `resourcesReleased` 缺失的轮次视为仍在活动，这与“当前轮已完成、旧轮没有在途工作”的真实现场不一致。搜索条件目前由标题和可见消息组成，ID 只用于展示和复制。

## 决策

### 历史未知只在真实在途时保持活跃

`conversationActive` 的历史分支增加一条收敛规则：保留执行 `status=unknown`、`executionState` 不是 `active`、且没有 `running` / `unknown` 工具时，不再保持对话活跃。`unknown` 记录、诊断和“原输入是否送达未知”的事实保持不变，仍可追溯。

不采用 `supersededBy` 一刀切：历史轮可能仍有运行中工具，直接标记替代会掩盖真实工作。新的条件只排除“没有在途工作”的纯未知状态，`active` 执行和 `running` / `unknown` 工具仍保持活跃。也不要求先把 `resourcesReleased` 补成真：这条旧轮没有受理回执和执行引用，无法诚实地补造释放证明；活跃判断不应依赖一个无法观察的事实。

### 读取时解释已有投影

已有 `is_active=1` 的摘要不会因为代码更新自动消失。列表查询本来就有“历史候选按当前规则重新解释”的兼容路径，只需把带保留 `unknown` 执行的行也纳入候选，再用完整、版本匹配的活动头部调用同一 `conversationActive`。这样现有 `93d4491f` 不需要数据库迁移或批量回填，刷新列表后即按普通历史排序；下一次保存或标记已读会把投影自然收敛。

代价是摘要列在收敛前仍可能保留旧值。列表、活动提醒和排序使用读取时的解释结果，用户可见行为一致；`markSeen` 也会用同一规则重写。若后续需要所有读取入口立即一致，可在下一次读取修复或保存时统一，不新增后台迁移。

### 搜索加入 ID 子串

搜索条件改为每个词项命中 `id`、标题或一条可见消息之一，仍按空白拆分、全部满足（AND）。ID 使用 `instr(lower(id), lower(?))`，与现有标题/消息文本匹配一致，不区分英文大小写、不要求完整 ID、不支持正则或通配符。命中片段仍只从可见消息派生；仅 ID 或标题命中时没有消息片段，列表行照常展示。

参数绑定从每个词项两个值变为三个值，`querySummaries` 与 `listConversations` 共用同一条件，避免两套搜索语义分叉。ID 是当前行已有列，子串扫描只作用于已按空间和分页范围筛选的行，不需要新增索引或改变分页游标。

## 风险与兼容

- **兼容性**：API 字段、前端组件和数据库结构不变；搜索只扩大命中范围，旧查询结果仍包含原有标题/消息命中项。
- **排序**：搜索仍按活动优先和最近用户输入排序，不改为相关度排序。
- **真实在途工作**：`executionState=active`、`running` / `unknown` 工具、未读消息、待回答问题仍保持活跃，不会被历史未知收敛规则隐藏。
- **性能**：历史候选只增加 `is_active=1` 且带保留 `unknown` 的行；ID 子串匹配在已限定空间/隐藏范围的行上执行，规模有限。
- **数据**：不做迁移、不批量回填、不修改现有 `unknown` 证据；只改变读取解释和后续保存结果。

## 验证

- 活跃判断：未受理 `unknown` 无工具旧轮 + 当前 `completed` + 已读 → 不活跃；有 running/unknown 工具或 active 执行 → 活跃；未读或待回答 → 活跃。
- 列表：`93d4491f` 不再进入 `activeOnly`，排序回到普通历史；再次读取不写数据库。
- 搜索：ID 子串（含大小写差异）可命中；标题/消息搜索保持；多关键词 AND；仅 ID 命中无消息片段；`listConversations` 与 `querySummaries` 一致。
- 静态检查和相关集成测试通过。
