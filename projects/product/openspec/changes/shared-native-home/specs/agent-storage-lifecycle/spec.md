## MODIFIED Requirements

### Requirement: 所有Agent默认共用工具运行环境与缓存

服务 MUST 从公共执行入口向所有当前与未来执行器提供同一工具缓存根，不以执行器的storage声明或品牌作为共享前提。npm、Yarn、编译、Python和Maven等受管缓存 MUST 按工具分区而非Agent分区；同版本、架构和内容的运行环境及不可变依赖 MUST 单份物化。服务 MUST 保留不同版本需求、账号配置与凭据隔离；工具与缓存共享 MUST NOT 通过合并完整用户目录实现。原生程序自身 home 的粒度、原生会话与 home 级状态的共享边界由「网关模式原生 home 按连接共享」约束，不属于本条的工具缓存共享。

#### Scenario: 新接入执行器未声明存储能力
- **WHEN** 新执行器使用公共执行入口但未声明storage
- **THEN** 它与Codex、DSH、Qoder获得同一默认工具和缓存位置，账号配置与凭据仍独立；原生 home 粒度按共享 home 要求执行

#### Scenario: 不同Agent使用同一依赖或Node
- **WHEN** 多个Agent或保留版本需要同内容和执行权限的Node或受管不可变依赖
- **THEN** 它们复用单份物理内容，运行时各自的身份、路径视图与恢复控制仍准确

#### Scenario: Maven与Java复用
- **WHEN** Agent使用已经可用的Java/Maven
- **THEN** 复用已验证的安装位置与公共Maven仓库，私有settings.xml及账号配置不被合并

## ADDED Requirements

### Requirement: 网关模式原生 home 按连接共享

服务 MUST 让 Codex 与 DSH 网关模式的原生 home 指向连接级共享根，同一连接的全部对话、模型与账号复用同一个 home；MUST NOT 因切换模型、账号或配置新建 home。账号、模型、对话与轮次的隔离 MUST 由网关令牌强制，MUST NOT 依赖目录边界。home 级状态库（目标、记忆、线程历史等）MUST 按原生语义在该 home 内跨对话共享。租约专属的模型配置 MUST 放在租约临时路径并经启动参数引用，MUST NOT 写入共享 home。原生登录模式 MUST 保持每连接一个 home 不变。多个进程并发使用同一共享 home MUST 保持状态库完整且各自会话可恢复。

#### Scenario: 换模型不新建 home
- **WHEN** 同一对话切换模型、账号或推理配置
- **THEN** 复用同一连接级共享 home，不产生新的 home 目录

#### Scenario: 隔离由网关令牌强制
- **WHEN** 两个不同账号或模型的租约进程共用同一个 home
- **THEN** 各进程只能经自己的网关令牌路由到准确的账号、模型与对话，目录相同不改变路由与计费边界

#### Scenario: 多进程并发共 home
- **WHEN** 多个原生进程同时向同一共享 home 写入状态
- **THEN** 状态库完整性校验通过，各进程的会话可独立恢复，不互相损坏

#### Scenario: 租约专属配置外移
- **WHEN** 网关模式准备模型配置
- **THEN** 配置写入租约临时路径并经启动参数引用，共享 home 不新增租约专属文件

### Requirement: 共享 home 状态库按完整引用证明维护

服务 MUST 提供共享 home 状态库的显式维护入口：默认 dry-run 逐项报告候选（线程身份、大小、判定理由与总收益），仅在完整证明无任何对话头、原生工具内容或交接来源引用后，经显式确认才清理无引用线程并收缩库。自动维护 MUST NOT 删除状态库内容。任何来源不可读、绑定身份无法解析或引用缺失上下文时 MUST 保留受影响范围。清理 MUST 沿用稳定窗口、系统占用观察与删除前后身份复核；任何不确定 MUST 保留。

#### Scenario: 无引用线程经确认回收
- **WHEN** 某线程完整证明无任何引用，且用户显式确认 dry-run 收据
- **THEN** 清理该线程并收缩库，逐项记录结果

#### Scenario: 被引用线程保留
- **WHEN** 线程仍被原生工具详情或交接来源引用
- **THEN** 保留该线程，不纳入删除

#### Scenario: 未确认不删除
- **WHEN** 维护调用未显式确认
- **THEN** 仅报告候选，不删除任何状态库内容

#### Scenario: 不确定保留
- **WHEN** 引用来源不可读、身份无法解析或计划后发生身份漂移
- **THEN** 保留受影响范围，不扩大删除

### Requirement: 死租约 home 双轨迁移与整目录回收

服务 MUST 让新参与方使用连接级共享 home，已有参与方保留其准确旧租约 home；内容解析 MUST 双轨——有持久化准确路径用路径，无则按原租约身份反算，保证历史工具详情与交接可读。服务 MUST NOT 迁移或合并旧租约 home 的状态库。旧租约 home 仅在完整证明无任何参与方、原生工具、交接或保留运行引用，且过稳定窗口、无系统占用时，才作为整目录回收候选；默认 dry-run，经显式确认删除。

#### Scenario: 历史内容双轨可读
- **WHEN** 读取切换前旧租约 home 中的历史工具详情或交接来源
- **THEN** 经持久化路径或原租约反算准确定位，内容完整可读

#### Scenario: 死 home 经确认整目录回收
- **WHEN** 旧租约 home 完整证明无任何引用、过稳定窗口且无占用，并经显式确认
- **THEN** 整目录回收，逐项记录结果

#### Scenario: 活跃 home 保留
- **WHEN** 旧租约 home 仍有参与方、原生工具、交接或保留运行引用
- **THEN** 保留该 home，不纳入删除

#### Scenario: 不合并旧状态库
- **WHEN** 新参与方改用共享 home
- **THEN** 不合并旧租约 home 的 SQLite，旧 home 随引用消失自然淘汰
