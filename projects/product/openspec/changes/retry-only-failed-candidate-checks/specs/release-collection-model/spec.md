## MODIFIED Requirements

### Requirement: 精确候选结果必须可直接作为最终验证
完整候选结果 MUST绑定真实产包源码提交、产物字节与清单、验证源码、实际平台及宿主兼容要求等执行事实。同轮已通过检查 MUST保留，完整演练或候选 MUST允许直接复用；用途标签、任务登记或临时载体变化 MUST不导致重新构建和全量执行。受控补验在构建输入不变时 SHALL保持原产包源码和原字节，并以独立验证源码证明新增或修复的检查；不满足该证明的旧格式继续按原精确源码边界读取。

#### Scenario: 全绿演练被纳入同一源码
- **WHEN** 已验证源码和产物未变，纳入后的相关输入全部匹配
- **THEN** 最终准备 MUST复用同一完整aggregate和tarball
- **AND** MUST重新核验当前选择、main关系及临发布公开状态，而不重新pack

#### Scenario: 源码或相关执行条件变化
- **WHEN** 产品构建输入或产物字节变化
- **THEN** 工具 MUST重新核对实际新产物，原包结果不能冒充新包执行结果
- **AND** 真正改变内嵌产包源码身份或构建输入时 MUST重新构建，不能只凭tree相同复用旧包

#### Scenario: 仅验证工具修复
- **WHEN** 验证源码变化但原产包源码及真实构建输入保持不变
- **THEN** 工具 SHALL消费原包并记录独立验证来源，只补齐失败及尚未执行检查
- **AND** MUST不冒称原包由后来的验证提交生成，不重写原始成功或失败记录

#### Scenario: 补验来源不改变发布权限
- **WHEN** 完整候选保留原包并绑定独立验证来源，随后准备公开发布
- **THEN** 发布 MUST使用受保护主线或通过既有发布恢复准入的执行来源
- **AND** 验证来源 MUST仅作为证明来源；不能替代发布执行来源，也不能改变原恢复上下文

### Requirement: 发布接续应复用逐项结果并减少智能体轮询
发布 SHALL 每轮完整收集必需检查，保存普通执行日志；同轮成功结果 MUST 保留，仅重跑失败项并首次执行未执行项。源码、测试、参数、Node 或依赖摘要变化 MUST NOT 使本轮成功项重新执行；MUST NOT 建立文件影响依赖或证明失效判定替代这一策略。新候选轮次 SHALL 重新完整执行。独立失败 MUST 汇总后交由用户决定修复。实际平台、原包身份及公开发布授权 MUST 继续核对。

#### Scenario: 一轮测试出现多个失败
- **WHEN** 本轮检查存在多个失败且用户同意修复
- **THEN** 程序 MUST 保留已通过项与原始执行来源，只补跑失败及尚未执行项
- **AND** 修复源码、测试或环境后 MUST NOT 根据摘要变化重复执行成功项

#### Scenario: 开始新候选轮次
- **WHEN** 准备新的候选轮次
- **THEN** 程序 MUST 完整执行必需检查，MUST NOT 自动继承上一轮成功项

#### Scenario: 平台或原包尚未验证
- **WHEN** 本轮缺少某个必需平台或实际原包的检查
- **THEN** 程序 MUST 首次执行相应检查，源码成功日志 MUST NOT 冒充原包或另一平台结果

#### Scenario: 任一系统开发并由远端补齐差异
- **WHEN** 本轮本机已有通用及本机平台成功结果
- **THEN** 远端 MUST 只补缺失平台、必要制包及原包检查，保留普通原始日志及来源
- **AND** 最低宿主 Node 检查 MUST 使用实际 24.15.0

#### Scenario: 远端候选尚未结束
- **WHEN** 同一发布命令持续等待的远端运行仍在进行
- **THEN** 程序 SHALL 有界等待同一运行并返回简洁结果，完整日志 MUST 可读取
- **AND** 接续 MUST NOT 重复派发已存在公开副作用

#### Scenario: 日常交付与独立失败收集
- **WHEN** 一个独立检查失败
- **THEN** 其他独立检查 MUST 继续执行；实际生产依赖失败 MUST 阻止其消费者
- **AND** 程序 MUST 汇总全部已观察失败，不自动删除失败检查或未经用户同意修复

#### Scenario: 插件功能已验证且桌面交付边界未变化
- **WHEN** 插件源码单元检查已在本轮通过
- **THEN** 完整候选 MUST 保留该成功结果，首次执行准确配对及 SDK 消费检查
- **AND** 未执行真实桌面操作 MUST 如实报告，公开发布 MUST 保持逐包授权

#### Scenario: 修复辅助代码或定向诊断
- **WHEN** 用户同意修复失败检查的辅助代码并执行定向检查
- **THEN** 同轮其余已通过项 MUST 保留；定向通过结果 MUST 以原始日志接续，无需为证明再执行
