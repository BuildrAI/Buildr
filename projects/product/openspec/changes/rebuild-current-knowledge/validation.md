## 来源与覆盖

以本次规范变化、当前 `src/modules/agent-assets/` 实现、资源和组件清单，以及用户明确的建设目标为依据。v3 主技能与参考材料从产品 `resources/` 修改；默认内置调用方同步迁移，术语依赖按需。工作空间自有 `skills/buildr-release/SKILL.md` 的来源身份为 `workspace:...`，只更新实际消费的发布文档链接，未手改随包受管副本或 `.agents/` 投射。

代表模块核对解析、组件贡献、局部能力依赖、目标计划、冲突预检、写入和归属记录。不覆盖所有适配器内部实现、远程来源全部分支、组件安装全流程、宿主新会话加载或生产环境状态。当前文档的迁移不等于重新审计整个产品。

## 七个代表场景

| 场景 | 本次证据与结论 |
|---|---|
| 事实变化影响已有映射 | 实际实施：目录和 v3 协作变化使现有代码地图总树、技能体系说明与流程入口受影响，已按相关段落更新并检查 |
| 有价值缺口但尚未授权 | 静态走查：把“为其他模块新建关系图”作为范围外输入，主技能要求先给出覆盖、文件、视角、来源与用途，状态为局部 `attention`；本次没有借此批量补图 |
| 明确授权一组建设 | 实际实施：根据用户授权自行选择技能投射模块并连续完成三类成果，没有逐文件确认，也没有为每张地图创建 `brief.md` |
| 来源变化但成果仍适用 | 实际核对：本次技能源目录新增参考文件，但源码中的组合、计划和写入算法未变；机制地图沿用真实关系，未虚构算法修改 |
| 规范与实现冲突 | 源资产静态走查：旧 v1 的全局停止条件与技能正文冲突，通过本次规范和协作迁移处理，没有只改解释掩盖；新流程要求后续真实业务冲突局部停止确定结论写入 |
| 仅改解释文档 | 实际实施：后续目录说明、图的空白布局和正式规范同步只追加相关文档、图或规范检查，复用内容与条件未变的代码测试 |
| 单项成果未完成 | 实际过程：图的引导视角检查失败时保留地图、源资产及其他已通过结果，只修复和复查该图，没有将局部失败扩为全任务重做 |

这是一轮真实交付加静态场景走查；未执行独立模型会话的自动行为评测，也不声称文本测试能保证智能体每次必然遵循这些步骤。
