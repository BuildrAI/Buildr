## MODIFIED Requirements

### Requirement: 插件公开发布必须使用独立可信身份
独立插件公开发布 SHALL 仅由明确授权的 GitHub 托管工作流（Workflow）通过开放身份连接（OIDC）完成，MUST 使用插件自己的包、版本和 npm 信任绑定。发布身份 MUST 匹配仓库、工作流文件和受保护环境；MUST NOT 回退读取本机或环境中的长期 npm 令牌（Token）。候选准备与发布 SHALL 分开触发，普通提交和主包发版 MUST NOT 自动公开插件。

#### Scenario: 只准备候选
- **WHEN** 维护者手动选择准备独立插件候选
- **THEN** 工作流 MUST只生产并验证一次最终候选，或核验并接纳已有完整验证原包，不执行公开发布

#### Scenario: 缺少或错误可信身份
- **WHEN** 发布现场不是已声明的托管工作流身份，或开放身份连接（OIDC）认证缺失、过期或不匹配
- **THEN** 发布 MUST 停止，不消费本机长期凭据或声明产品已公开

#### Scenario: 受保护接纳已有原包
- **WHEN** 源码候选已完整验证且准确被受保护main纳入
- **THEN** 准备 SHALL原样运输并接纳该候选，不再完整验证、构建或打包
- **AND** 公开发布身份仍 MUST绑定真实main、独立工作流和插件自己的授权

### Requirement: 插件候选必须可搬运且绑定唯一字节
插件候选 SHALL 绑定确切源码、服务源码树、版本、正式包名、固定来源软件开发工具包（SDK）摘要及唯一压缩包的大小和完整性。跨作业运输 MUST 使用可搬运文件身份，不依赖构建机器绝对路径；发布 MUST 验证原字节，MUST NOT 重打包。来源或字节漂移 MUST 阻止该发布。

#### Scenario: 候选跨作业消费
- **WHEN** 发布作业下载匹配源码的已验证候选
- **THEN** 发布 MUST 在核对完整身份与摘要后消费同一压缩包

#### Scenario: 来源或字节改变
- **WHEN** 候选来自其他源码、包名、版本或压缩包字节发生变化
- **THEN** 发布 MUST 在公开写入前拒绝该候选

#### Scenario: 原包从源码候选进入主分支准备
- **WHEN** main准备消费源码候选运行的原包及聚合
- **THEN** 系统 MUST分别核验原源码身份、选择、SDK、对端、完整检查及受保护main父关系与整树一致
- **AND** 原candidate与压缩包字节 MUST保持不变，不把源码身份改写成main提交
