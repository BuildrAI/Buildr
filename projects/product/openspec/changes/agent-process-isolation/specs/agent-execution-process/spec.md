## Purpose

定义本机独立执行后台与接入产品之间可复用的执行操作、宿主能力和运行管理契约（Contract），使工作跨主程序重启持续，兼容版本并行承接新旧工作，按对话接续待发送指令，并按准确持有关系退出及清理。

## ADDED Requirements

### Requirement: 执行后台必须独立于接入主程序存活

系统 MUST 在每个应用配置域（Profile）按需提供独立执行后台，持有对话、交接、原生执行、账号、模型转接、待回应及私有交互数据。兼容版本 MAY 同时运行，已有执行 MUST 保持准确归属。Buildr 主程序普通退出、重启或客户端断开 MUST 仅释放相应连接，不停止已受理工作、不清除待回应、不改变其后台代次或触发第二次执行。后台自身退出或异常恢复 MUST 核对原生事实，不能冒称持续运行。

#### Scenario: 执行期间重启主程序
- **WHEN** 已受理执行正在输出，Buildr 主程序退出后重新启动
- **THEN** 系统 MUST 重新连接同一后台并读回准确执行及未订阅期间保存的输出
- **AND** 后台代次及原生执行身份 MUST 保持，不能重复发送工作

#### Scenario: 等待用户决定时界面断开
- **WHEN** 原执行存在待回答或待授权请求而页面和主程序连接关闭
- **THEN** 后台 MUST 保留原请求，重连后用户能回应准确请求
- **AND** 系统 MUST NOT 自动批准、生成替代请求或把断连当作用户取消

### Requirement: 三组公开契约必须具有可替换语义

系统 MUST 明确定义版本化的执行操作、宿主能力和运行管理三组契约（Contract），规定输入输出、身份及观察版本、实际副作用、失败和断连语义。核心、通用客户端（Client）与进程承载 MUST 只通过该边界使用接入方能力，不要求 Buildr 内部模块、业务实体、数据库或浏览器请求对象。Buildr MUST 作为实现方提供自身能力，其他宿主 MUST 能按同一语义接入。

#### Scenario: 更换宿主实现
- **WHEN** 相同后台使用一个符合约定的最小宿主（Host）代替 Buildr 接入
- **THEN** 对话、交接、回应及停止 MUST 能继续通过公开契约完成
- **AND** 最小宿主 MUST 不必伪造 Buildr 任务、项目登记或内部模块

### Requirement: 执行操作必须保留准确受理与控制事实

执行操作 MUST 保留原请求身份、对话修订、执行和参与者身份以及后台代次，区分本地登记、原生受理、未受理和结果未知。传输超时或断开 MUST 不自动证明未执行；重新连接 MUST 先核对原请求。停止、回应与订阅取消 MUST 各自作用于准确对象，订阅或客户端释放 MUST 不中止对话。历史交接、模型来源、权限及原生控制边界 MUST 保持既有语义。

#### Scenario: 已登记发送的返回连接丢失
- **WHEN** 后台登记发送后客户端未收到响应而重新连接
- **THEN** 相同原请求身份 MUST 能查到其准确登记与受理观察，不创建第二轮工作
- **AND** 仍未知时 MUST 保留未知，不以新的请求身份自动重发

#### Scenario: 旧回应迟到
- **WHEN** 回应引用过期修订、执行或后台代次
- **THEN** 系统 MUST 明确拒绝并要求重新观察，不能应用到其他请求

### Requirement: 宿主能力必须解析环境并核验可选外部对象

宿主能力 MUST 以带来源身份的执行范围及可选外部对象引用工作，返回准确环境、当前观察版本、核验结果及可查询范围。普通对话 MUST 不要求业务任务（Task）；后台 MUST 不直接扫描 Buildr 登记或写入外部状态。不同来源相同编号 MUST 不碰撞，历史引用映射 MUST 保留。后台 MUST 核对本机目录、原生绑定及已有权限，宿主核验 MUST 不自动扩大工具授权。

#### Scenario: 无业务任务的宿主开始工作
- **WHEN** 宿主提供准确默认目录而没有项目或任务体系
- **THEN** 后台 MUST 能创建并执行普通对话，保存其准确环境绑定

#### Scenario: 外部对象来源重名
- **WHEN** 两个明确来源各自提供相同对象编号
- **THEN** 系统 MUST 按来源与范围核验准确对象，不能串用绑定或授权

### Requirement: 宿主暂时不可达必须只影响依赖新核验的动作

创建、改变关联和开始需要宿主事实的新执行前，系统 MUST 取得当前必要核验并在副作用前校验适用的观察版本。已受理执行 MUST 不依赖宿主持续在线。宿主不可达 MUST 与对象失效、观察冲突分别表达；后台 MUST 仍能保存、观察、停止及处理准确原请求，不能以旧观察冒充新核验或因失联启动替代工作。后台异常恢复后发起续做 MUST 遵守同一核验要求。

#### Scenario: 宿主在执行中离线
- **WHEN** 工作已经受理且宿主暂时失联
- **THEN** 原执行 MUST 保留并继续，必要控制与结果保存 MUST 不被无关核验失败阻断
- **AND** 需要新核验的新动作 MUST 明确报告不可达或等待，重连后重新核验

### Requirement: 本机连接必须核验身份并保持配置域隔离

后台连接 MUST 核验数据根、应用配置域（Profile）、后台准确身份、契约版本及调用方认证，MUST NOT 仅凭端口或进程号复用。正式版、开发版和各预览 MUST 保持独立后台与数据范围。网页 MUST 继续通过 Buildr 的既有认证入口接入，后台凭据和厂家秘密 MUST 不进入网页、事件、日志或公共错误。用户 MUST 不必另装服务或手动配置端口、后台凭据。

#### Scenario: 地址上运行了其他后台
- **WHEN** 发现的地址返回不匹配身份、数据根或契约版本
- **THEN** 系统 MUST 拒绝错误复用并保留对方工作，不接管、不关闭、不读取其数据

### Requirement: 配置维护与对话执行必须保持唯一持有责任

后台启动、重新发现和版本采用 MUST 保证同一配置域只有一个共享账号与接入配置维护者，同一对话只有一个活动执行持有者。旧后台转为只完成已有工作前 MUST 完成配置维护并停止周期刷新，新后台确认取得维护权后才接新工作。私有交互 MUST 使用版本检查并保存同一权威历史；后台 MUST NOT 持陈旧账号缓存全量覆盖当前配置，MUST NOT 恢复其他仍活跃代次的执行。接入产品 MUST NOT 创建同进程核心或对话副本。

#### Scenario: 两个窗口并发启动
- **WHEN** 两个接入窗口同时请求使用同一配置域
- **THEN** 它们 MUST 发现相同当前入口及有关旧执行持有者，不产生重复轮次或两个配置维护者

### Requirement: 活动运行内容必须保留且可独立启动

后台使用的编译文件、完整运行依赖及 Node.js 绑定 MUST 构成准确、受保留的运行单元；新构建、安装和更新 MUST 不覆盖活动单元或活动使用的原生程序。运行单元 MUST 能从没有相邻 Buildr 源码或业务模块的安装目录启动，并通过同一公开契约承载工作。产品版本、实际后台运行摘要与待采用摘要 MUST 分别可观察。

#### Scenario: 活动后台遇到新构建
- **WHEN** 后台仍执行而产品准备了新版
- **THEN** 活动运行内容 MUST 保持可读和完整，后续加载及工具控制不因目录替换失效
- **AND** 系统 MUST 准确显示仍在使用旧版与等待原因

#### Scenario: 复制后安装目录独立启动
- **WHEN** 将交付运行单元放到不含 Buildr 相邻源码和业务模块的目录
- **THEN** 最小宿主 MUST 能通过同一入口完成创建、发送、交接、回应及停止，不读取隐藏的开发路径

### Requirement: 兼容新版必须承接新工作并保留旧轮控制

新版准备好且两边显式声明兼容的并行协议与资料格式时，系统 MUST 在新版确认就绪后将新执行交给新版，旧后台 MUST 继续持有原轮输出、停止、问题、审批、模型转接及保存。同一对话 MUST 等待原轮和有关辅助工作释放再开始下一轮，其他旧对话 MUST NOT 阻塞该对话接续。未声明并行能力或资料不兼容时 MUST 沿用受保护的空闲交接，不强停、不冒险迁移。独立后台工具 MUST 按真实归属处理，不误停用户保留的服务。

#### Scenario: 等待授权时发现新版
- **WHEN** 原执行等待用户决定且新版已准备
- **THEN** 系统 MUST 继续由原后台处理准确原请求，兼容新版可承接其他新执行

#### Scenario: 空闲切换与发送竞争
- **WHEN** 发送恰好与空闲暂停接收并发
- **THEN** 发送 MUST 明确成为已保存待发送、已登记执行或尚未受理并保留草稿，不混淆三种事实
- **AND** 系统 MUST 不丢失已显示受理的输入，也不在两版各执行一次

### Requirement: 切换失败必须保持事实并可安全恢复

自动采用 MUST 在共享配置维护权准确释放后才由新版获得该维护权，已有对话仍由原后台保存。页面和主程序退出 MUST 不取消已受理采用。启动失败或交接中断 MUST 保留准确目标、已发生步骤和诊断，按真实持有状态恢复。非并行交接仍 MUST 确认旧后台退出。资料不再兼容旧版时 MUST 不启动旧版读写或回滚覆盖。接入不兼容时 MUST 保留旧工作观察控制或推迟激活，不能强制中断工作。

#### Scenario: 新版未就绪时保留旧工作
- **WHEN** 新版启动或维护权交接失败
- **THEN** 系统 MUST 保留原轮与待发送内容，按准确持有事实恢复或显示原因，不能报告采用成功

#### Scenario: 新版启动失败
- **WHEN** 旧后台已释放而新版未就绪
- **THEN** 系统 MUST 如实显示失败，仅在数据兼容和持有权可确认时恢复旧运行单元
- **AND** 不能安全回退时 MUST 保留数据与原因，不宣称切换成功

#### Scenario: 交接时主程序再次退出
- **WHEN** 版本交接已受理而主程序连接关闭
- **THEN** 交接 MUST 能独立完成或留下可恢复的准确事实，不因客户端丢失重复启动后台

### Requirement: 已提交的待发送内容必须可靠保存并自动接续

系统 MUST 允许原轮尚未结束时提交下一条指令，按对话可靠保存一条待发送内容、明确选择、附件引用、稳定原请求身份及修订。页面 MUST 回显提交等待，未实际受理前不得显示执行中。等待内容 MUST 可按观察修订修改或取消，跨页面、主程序及后台重启保留。普通草稿 MUST NOT 自动发送。

原轮确认结束、有关局部工作释放且当前新版就绪后，后台 MUST 重新核对对话历史、宿主事实、目录、账号身份、模型及权限，使用准确原请求身份生成当前预览并自动登记。未确认停止或未知工具 MUST 保持等待；失效选择与失败 MUST 保留内容和原因，不自动换模型或扩大权限。受理返回丢失 MUST 查询原请求，不盲目重发。

#### Scenario: 停止期间提交并关闭主程序
- **WHEN** 用户点击停止后提交下一条指令，并在原轮停止前关闭 Buildr
- **THEN** 待发送内容 MUST 保留，原轮实际结束且所需宿主事实可核验后自动交给新版，无需用户再次发送
- **AND** 同一原请求 MUST 只登记一轮，其他旧对话可继续原执行

#### Scenario: 修改或取消与自动发送竞争
- **WHEN** 用户按观察修订修改或取消待发送内容，同时后台开始接续
- **THEN** 系统 MUST 原子确定成功修改取消或发送已开始的冲突，不能既报告取消成功又开始该执行

### Requirement: 旧后台必须按实际工作退出并安全清理

旧后台 MUST 在自己的执行、待回应、活动或未知工具、辅助工作及重要写入全部结束后正常退出，MUST NOT 因新版工作仍运行而等待，也不得因页面转向新版就提前退出。系统 MUST 在确认准确旧进程退出且释放成功后，仅清理无任何保留引用的实例和运行文件；历史、账号、附件及成果 MUST 保留。释放未知时 MUST 保留并报告，预览停止及离线维护 MUST 核对全部新旧实例。

#### Scenario: 两段旧对话分别结束
- **WHEN** 第一段旧对话结束并进入新版，第二段旧对话仍在运行
- **THEN** 旧后台 MUST 保留第二段工作，第一段可在新版继续；第二段结束且无其他旧工作后旧后台正常退出

#### Scenario: 运行单元仍被其他实例引用
- **WHEN** 某旧实例已经退出但它的运行单元仍由另一保留实例引用
- **THEN** 系统 MUST 保留该运行单元，只清理可证明不再引用的内容

### Requirement: 预览停止与维护必须覆盖所拥有的后台

预览的停止和清理 MUST 纳入该预览拥有的执行后台及实际写入，保持现有默认保留数据和明确彻底清理的语义。连接、账号及运行时沿用的目标处于活动状态时，系统 MUST 不旁路覆盖其数据或文件；维护通过拥有者能力或明确离线方式执行。来源环境 MUST 保持只读，预览会话、附件和交接资料 MUST 不跨环境复制。

#### Scenario: 停止后彻底清理预览
- **WHEN** 已明确请求清理预览而其后台退出尚未确认
- **THEN** 系统 MUST 保留目录并报告未停项，不能因网页进程退出就删除数据

### Requirement: 现有业务与可见行为必须保留归属

拆分 MUST 保持既有页面地址、默认工作位置、对话/原生身份、任务关联、交接材料、活动及已读语义。Buildr MUST 继续负责业务材料、外部状态和界面；单次生成 MUST 仅通过模型能力接入，保留取消、预算、来源及草稿校验，不自动获得跨重启业务恢复或新增持久对话。

#### Scenario: 通过后台生成提交说明
- **WHEN** Buildr 发起或取消一次提交说明生成
- **THEN** 后台 MUST 使用准确选定模型，Buildr 继续校验和应用结果
- **AND** 拆分 MUST 不触发提交、切换付费来源或创建工作对话
