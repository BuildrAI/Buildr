## Context

进程独立化已由 `agent-process-isolation` 任务交付。本轮在 `0514b7be1ad297050f86295447fdcd0ed030da39` 基线上接续[并行更新任务说明](@task/agent-parallel-updates)，实现新旧后台并行和待发送接续。旧阶段真实验证及厂家、跨平台缺口保留在 `implementation.md` 与既有任务结果，不改写成本轮完成证明。下列源码路径相对 `projects/product/`。

当前 `services/buildr-agent/src/process/` 已提供认证回环通信、公共客户端（Client）、独立承载、受保留运行单元及空闲交接。缺口是只有一个当前实例和整个资料根的持有锁；所有操作连接同一实例，新代次将外代次活动执行视为中断。对话库已有事务（Transaction）和修订检查，账号目录仍由单个应用缓存并全量保存，不能直接解除单实例限制。

## Goals / Non-Goals

**Goals:**

- 主程序更新重启不打断已受理执行，兼容新版及时承接新执行。
- 一轮执行（Run）及其停止、问题、审批、模型转接和保存始终归属原后台；同一对话只在原轮真正结束后交接。
- 用户先提交下一条指令，待发送内容跨页面、主程序及后台重启保留，条件满足后自动发送且不重复执行。
- 共享账号配置保持唯一维护责任；旧后台全部工作结束后退出，只清理不再引用的运行文件。
- 保持三组公共契约（Contract）、最小宿主可替换性、历史、权限、活动、已读、标题、附件及模型来源边界。

**Non-Goals:**

不迁移活动原生上下文（Native Context），不在同一对话同时开始两轮，不并行读写不兼容资料，不建设通用调度平台、远程执行或独立发行，不自动强杀。真实厂家与平台按实际证据报告。

## Decisions

### 1. 接入、执行与成果归属

Buildr 拥有浏览器认证、工作空间（Workspace）与任务（Task）查询、页面及业务结果。`buildr-agent` 拥有三组契约、通用传输、后台实例、私有交互及执行，不导入 Buildr 业务模块。代码及外部成果仍由原业务能力维护。

| 对象 | 维护者与边界 |
|---|---|
| 当前接收入口 | 已确认就绪的新版；只代表新执行去向 |
| 已受理轮次 | 准确后台代次；控制不能跟随当前入口改绑 |
| 对话正文与附件 | 原私有交互库，按对话版本保存，不复制历史 |
| 账号、登录、程序准备、模型目录 | 当前配置维护者；交接完成旧维护活动，旧后台不再刷新或写回配置 |
| 原轮模型转接与原生连接 | 原后台保留到工作结束；读取当前账号快照，不持陈旧缓存覆盖配置 |
| 待发送内容 | 私有持久存储，稳定原请求身份和独立修订，不伪装成已受理轮次 |

### 2. 多实例发现与准确路由

保留一个当前接收入口，为每个仍需保留的代次保存认证私有实例记录。数据根、配置域、实例、代次、运行摘要和进程身份共同核验；端口或进程号不足以复用或清理。其他仍活跃代次不触发异常恢复。

读取、事件及原轮控制使用所属代次；全空间列表从同一私有库读取真实状态。主程序重连为有关后台重新连接同一宿主来源；断开客户端不停止后台。事件跨代次继续取得当前事实，迟到事件不覆盖新轮。

新轮只在当前接收后台发起。原轮尚有执行、待回应、活动或未知工具、恢复、整理、标题或保存时，不在同一对话开始下一轮。该对话释放后即可进入新版，不等待其他对话。

### 3. 并行采用与共享维护

运行单元按内容摘要保留代码、依赖和 Node.js，不覆盖活动文件。元数据声明并行协议及存储兼容范围；只有两边均支持且资料格式相容时并行。

采用新版时短暂关闭旧后台的新执行入口，完成必要配置维护、停止周期刷新，将共享配置维护权交给新版。旧后台保持原轮控制、输出及保存；对话按准确持有者写入，修订冲突显式处理。旧后台的账号观察只读当前快照，不能全量写回旧内存。明确断开账号或接入仍作用于相关旧轮，不因多实例扩大授权。

新版确认就绪后才成为新执行入口。启动失败保留旧工作和运行目录，只有准确持有与资料兼容可确认时恢复原接收方。未声明并行能力的旧版首次升级保留原有空闲交接；不兼容升级不能在旧工作存活时迁移资料。

### 4. 提交等待与自动发送

每段对话首版保留一条待发送内容，保存文字、附件引用、明确执行方、模型、权限、稳定原请求身份及独立修订。提交成功立即回显并显示“等待上一轮停止，新版就绪后将自动执行”，实际受理前不显示执行中。普通草稿不自动发送。

按观察修订修改或取消。调度持有与修改取消竞争必须有确定结果：等待时可更改，开始登记后冲突并重读，不悄悄撤回原生执行。页面、主程序重启不丢内容；后台重启先查询原请求，不因返回丢失新建身份重发。

原轮确认结束、局部工作释放且新版就绪后，重读历史与必要宿主事实，复核目录、账号来源身份、模型及权限，生成当前交接和预览，以保存的原请求身份登记。不能沿用过期预览、自动换模型、提高权限或重放审批。

原轮停止未确认、工具未知、宿主不可达或新版未就绪保持等待；选择失效或真实失败保留内容与原因，允许修改取消，不无限重试已失败执行。等待超时不等于停止成功。

### 5. 退出、清理与维护

旧后台只完成已有工作，忙闲只统计自己持有的工作，不把新版活动或待发送算作旧工作；所有执行、待回应、活动或未知工具、辅助任务、写入结束后正常关闭，未知释放仍保留。

确认准确旧进程实际退出且释放成功后，才移除实例记录和无当前、待采用、保留实例引用的运行单元；不删除历史、账号、附件或成果。不按目录年龄或进程号删除。预览停止覆盖全部新旧后台，未停确认不删资料；离线维护检查全部存活实例，不能只看当前入口。

## Risks / Trade-offs

- 配置维护权和对话持有分开核验，周期刷新和异常恢复不得跨代次争抢。
- 待发送需要持久状态及去重，但只限定对话内一条，不建设通用队列。
- 受理结果未知先保留并查询，不能靠网络重试承诺精确执行一次。
- 原生上下文只能在原轮结束后按准确绑定恢复；不兼容时保留消息，不能悄悄用空白历史。
- 安装更新和后台采用分别观察，不兼容升级仍可能等待。

## Migration Plan

1. 保留初始独立化交付，扩展公开声明、兼容标记、实例发现与代次存活判断。
2. 实现配置维护交接、对话路由、恢复过滤、事件及全部预览实例停止。
3. 实现待发送保存、修订、取消、恢复和自动发送，接入既有认证网页与对话展示。
4. 真实子进程覆盖两版重叠、两个旧对话独立释放、停止审批、跨重启待发送、修改取消、返回丢失、失败及清理。
5. 执行相关静态、单元、集成、生产托管界面检查；真实厂家、平台、自举激活及发布分别报告。
