# 设计

## 目标

任务里能看到哪些工作树，就能启动哪些服务；不看项目范围。

## 判定

1. **只看证据**：读取 `buildr.git-worktree-provider/v1` 中登记给该任务的检出；目录存在但无证据不算。
2. **身份一致**：证据中的来源仓库、检出目录、分支要与当前 Git 观察一致；否则不覆盖该服务。
3. **不用范围**：任务范围声明不参与可启动判定，也不写入任何状态。
4. **同一泳道**：路由上下文仍由 `taskId` 生成，服务数量不影响泳道身份；前端仍按 `local.backends` 解析，已就绪的后端替换为本地地址，其余走 QA。

## 非目标

- 跨任务复用、工作树登记写入口、准备新工作树入口。
- 修改任务范围，或把服务自动写入范围。
- 服务端泳道注入方式的默认值。

## 风险

- 误把其他任务的目录算作本任务：由证据归属与 Git 身份校验阻止。
