## Context

任务当前在主工作空间的 SQLite 保存顶层记录；项目说明通过工作树读取，本机说明和关联清单保存到 `.buildr/local/task-materials/`。记录摘要由完整记录计算，列表仓库目前会读取记录全列。现有编辑入口已支持版本冲突和保留草稿；预览仅复制数据库。动机见提案。

## Goals / Non-Goals

统一任务说明的数据归属、读写与缺失表达，并保留其他材料的文件现场。旧文件只作为显式导入来源和历史保全；不建立长期数据库与文件双写，不批量编造缺失正文，不增加文档平台或云同步。

## Decisions

1. 任务记录协议升级为 v4，新增 `brief: string | null`，任务管理能力契约同步升级。数据库追加连续迁移，不改写已有脚本。正文保留 Markdown 内容，按明确体积限制校验；空正文统一为空值。所有任务类型共用字段，待办可暂缺真实正文，开始执行时由智能体形成。
2. 正文写入由同一任务应用完成，使用 `recordDigest` 并发校验。正文变化属于任务理解变化，进入记录版本；终态更正保留旧正文，组合任务验收观察包含正文摘要。材料与专业结果仍各自维护，不增加统一就绪门禁。
3. 列表只读取正文摘要与其他摘要字段，不读取或返回正文和结果历史载荷；详情和单任务命令读取正文。正文与完整历史各自计算内部摘要并参与记录身份，保证同一任务在列表和详情拥有相同版本，历史更正仍受保护，不保存另一份正文。
4. 任务说明节点直接读取记录，不等待材料或 OpenSpec；编辑抽屉增加 Markdown 正文输入，保留现有短目标、冲突处理与阅读排版。变更说明始终是辅助材料，不用作任务正文兜底。`@task/<task-id>` 指向同一工作空间中的稳定任务入口；项目文件使用明确工作空间路径，沿用受限读取。
5. 旧正文采用显式迁移命令：观察记录、旧唯一 `brief` 关联及实际正文版本，核对后导入；不选主变更，不扫描同名文件。原文件保持，迁移后旧说明关联解除，其余角色及版本保留。正文为空时，专用导入动作可为终态普通或组合任务补入真实旧说明，保持既有状态、结果与历史时间，不绕过普通更正的验收约束。批次先收集完整分页任务身份，再逐项重新观察与写入，避免更新时间变化跳过任务。源文件中可解析的相对文档链接转换为明确项目或同任务材料引用；项目编码必须属于任务项目、服务项目或变更项目范围且真实登记，路径逐段编码，支持附接项目的真实根。不可明确解析的链接和缺失来源报告具体诊断，不扩大读取范围。
6. 新记录说明不再通过材料应用建立引用；公开清单使用 v2，方案、实施和交付继续通过原有材料能力读取。普通材料更新必须在内部保留尚未迁移的唯一旧说明关联，并在发布前验证合并清单的数量与大小；旧清单只用于迁移及诊断。迁移中途失败分别报告已成立的记录写入和关联释放。已有记录正文时，显式迁移只核对版本并释放旧关联，不修改正文；这也支持部分失败后已编辑正文的安全重试。数据库升级与正文导入分开执行，普通读取零写入。
7. 候选只能升级自身隔离预览数据库；保留工作空间在正式交付后由合法入口升级并导入。新版本数据由同一主工作空间维护，不随分支切换。旧程序遇到更高迁移版本按已有边界拒绝，不绕过版本检查。

## Risks / Trade-offs

- 正文不再随代码提交保全 → 使用任务数据库现有备份机制，旧文件原样保留，不长期双写。
- 导入时文件或记录发生变化 → 同时核对已观察记录、关联与正文，冲突保持现场，不自动重放。
- 旧链接依赖文件目录 → 保留原文历史，导入时规范化可证明的链接，明确失败与未覆盖。
- 新字段扩大列表读取成本 → 明确使用不含正文的列表投影，并检验记录版本一致。
- 预览与保留数据库版本不同 → 由候选准备自己的副本，正式应用更新后才操作主任务库。

## Migration Plan

先完成字段、协议和读写入口，再完成显式导入与前端及技能调整；在隔离数据库覆盖真实旧来源、刷新、缺失和并发冲突。正式采用前保存一致数据库备份，通过合法保留入口升级与导入可读的旧独立说明，核对导入结果与稳定链接；不删除旧文件，不静默补写没有说明的历史任务。失败保留可恢复数据与逐项结果，不自动降级数据库或覆盖新正文。
