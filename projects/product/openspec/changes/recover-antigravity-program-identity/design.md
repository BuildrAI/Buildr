## Context

动机见 `proposal.md`。当前实现的关键事实：

- 连接记录保存 `bindingData.executableDigest`，其值为 `sha256(JSON([realpath, dev, ino, size, mtimeMs]))`，不是文件内容摘要（`executors/native-process.ts`）。
- 运行时打开连接时会比较该摘要；同路径文件摘要变化时拒绝继续（`executors/antigravity/index.ts`）。执行期间由 `AntigravityCoordinator.verifyExecutableUnchanged` 再次校验并关闭对话进程。
- 程序更新检查只比较官方版本，不观察文件身份（`application/program-updates.ts`）。本地版本等于官方最新时状态为 `latest`，前端据此不显示更新按钮（`agent-program-view.ts`）。
- 升级任务在目标版本不高于当前版本且为受管程序时直接拒绝（`application/program-upgrades.ts`）。
- 清单安装发现目标版本目录已存在时只验证版本并复用，不重新下载或替换（`executors/program-manager.ts` 的 `verifyExistingManagedManifest`）。
- 绑定身份（`bindingIdentity`）由程序路径、连接配置目录和设备身份计算，不包含程序版本或文件内容；升级和同路径重装不会改变它，因此旧原生会话仍可恢复。
- 连接私有配置写入的 `autoUpdate: false` 未阻止 `agy` 1.5.9 自更新；更新目录留下成功状态与旧二进制重命名痕迹。

## Goals / Non-Goals

**Goals**

- 让“文件身份失配”成为可观察、可诊断、可恢复的状态，且恢复动作重新取得官方受管程序而不是接受磁盘现状。
- 保持现有安全边界：不在身份变化后的程序上继续旧对话，不重放未确认的工作。
- 用最小的服务边界变化完成恢复，不把内部绑定摘要暴露为公共字段。

**Non-Goals**

- 不改变其他执行器的程序更新语义。
- 不尝试接管官方桌面应用或用户自行安装的 `agy`。
- 不在本变更中承诺用文件系统权限强制阻止第三方更新器；以身份观察和恢复路径保证可用性。

## Decisions

### 1. 在程序更新观察中增加身份状态，由服务内部读取绑定摘要

`ProgramUpdates` 新增一个由 `AgentService` 注入的只读读取器，取得该连接保存的 `executableDigest`（新增内部方法，例如 `ConnectionApplication.bindingDigest(id)`）。检查时用与运行期相同的算法计算当前文件摘要并比较，向视图输出 `identityState: 'consistent' | 'changed' | 'unobserved'`。

- `unobserved` 用于没有绑定摘要的旧记录或无法读取文件的状态，不阻止版本检查。
- 身份状态独立于版本 `status`：本地版本等于最新时仍可为 `changed`。
- 公共视图只暴露状态和诊断，不暴露摘要值。

备选：把 `bindingData` 加入 `ConnectionView`。否决，公共视图会携带内部绑定细节，且扩大 API 面。

### 2. 复用程序更新动作，允许身份失配时同版本重装

恢复动作仍调用 `connections.upgradeProgram`，输入为官方最新版本。服务端在以下条件同时成立时允许 `order === 0` 的重装：

- 目标是受管程序且路径仍在受管目录；
- 该连接的文件身份与绑定不一致；
- 目标版本在兼容范围内且等于官方清单当前版本。

`order > 0`（目标低于当前）仍拒绝。前端根据 `identityState === 'changed'` 显示“重新核对并安装”，并在确认说明中写明会关闭该程序、重装同版本、保留账号与历史。

备选：新增独立的 `restoreProgram` 操作。否决，行为与显式更新高度重合，会增加客户端分支与状态。

### 3. 程序管理器提供受控的替换安装

`install` 增加显式的替换模式（内部输入，例如 `replaceExisting: true`），只由恢复流程传入：

- 下载并校验官方清单负载到 staging；
- 将现有受管目录原子改名为 `.previous-<uuid>`，再把 staging 改名为目标目录；
- 对替换后的程序执行版本与兼容性校验；
- 失败时恢复原目录并保留原绑定；成功后保留旧目录直到连接切换完成，再清理。
- 复用现有符号链接、路径归属、版本与摘要校验，不新增外部路径写入。

普通准备仍保持“已存在目录不覆盖”的语义，避免静默改变用户既有安装。

### 4. 重装后刷新绑定并保留原生身份

`replaceProgram` 在关闭旧运行时后打开新程序，保存新的 `bindingData`。程序路径保持原锚定路径（`programSource` 或原 executable），因此 `bindingIdentity` 不变化，旧对话可继续恢复原生会话。恢复完成后保留用户输入，不自动重放失败轮次。

### 5. 自动更新关闭作为待验证事实处理

先在实现阶段核对 `agy` 1.5.9 实际读取的更新配置位置与键名（二进制字符串、程序日志、官方说明）。若存在有效键，补充到连接私有配置；若不存在，保留当前写入并如实诊断“配置无法保证关闭”。无论结果如何，文件身份观察与恢复路径都必须独立成立，界面不得把“已写入 autoUpdate:false”表述为“已阻止自更新”。

## Risks / Trade-offs

- [恢复动作仍可能遇到程序被外部进程占用] → 先按现有程序切换闸门释放 Runtime；替换失败保留旧目录与原绑定，报告可重试。
- [同版本官方包内容与本地不同] → 以官方摘要、版本和兼容范围校验为准，校验失败不切换。
- [更新器持续自更新，恢复后再次失配] → 身份状态每次检查重新计算；用户可再次执行恢复。若频率过高，后续再评估受管目录写保护，本次不承诺。
- [前端把“已是很新”与“身份变化”混淆] → 身份状态优先于版本状态显示；更新按钮条件加入 `identityState === 'changed'`。
- [替换期间崩溃] → 保留 `.previous-*` 目录与失败记录，下次检查仍报告身份变化并允许重试。

## Migration Plan

- 无数据迁移。新字段为增量，旧客户端忽略即可。
- 旧连接没有绑定摘要时显示 `unobserved`，版本检查与既有行为不变。
- 回滚代码不会破坏已保存的绑定摘要格式；已恢复连接继续按现有校验运行。

## Open Questions

- `agy` 1.5.9 是否支持通过私有配置真正关闭自动更新，需在实现时以程序行为和日志确认；该答案只影响诊断与约束方式，不改变恢复路径。
