# 在 DSH 里打开 Buildr：一个不用学的新入口

GitHub：[https://github.com/BuildrAI/Buildr](https://github.com/BuildrAI/Buildr)

如果你同时在用 Buildr 和 DSH（DeepSeek Harness），以前的动作是这样：在 DSH 里跟智能体（Agent）聊着，想看一眼 Buildr 里的东西，就得切浏览器、找启动器、翻窗口。回来还得重新找到刚才的位置。

现在少一个动作：**DSH 侧栏底部多一个 Buildr 入口，点一下就开。**

## 它就长在你会看的地方

不是新窗口，也不是新面板。它就在侧栏底部，和设置、账号这些你每天都会点的地方排在一起。所以不需要记它在哪里，也不用学新的操作方式。

点下去之后有三种情况，都不需要你判断：

- Buildr 已经在跑 → 直接打开。
- Buildr 没在跑 → 先把它启动起来，再打开。
- 正在启动 → 入口显示正在准备；万一失败，会明白地告诉你，可以再点一次。

## 你正聊着的东西不会被打断

这是我们在做的时候最在意的一点：**打开 Buildr 不会动你当前的对话。**

Buildr 在 DSH 右侧栏的浏览器标签里打开，中间的会话原样留着。你回来的时候，刚才那段对话、那个正在跑的任务，都还在。

## 为什么只有一个入口

有人会问：我也在开发 Buildr，能不能顺便在 DSH 里打开开发版？

能，但那**不是给用户的入口**。开发和日常使用是两件事，混在一起的结果通常是：普通用户被要求回答一个他答不上来的问题——“你要开哪个版本？”

所以这一版只做一件事：**打开你的正式版 Buildr，不做任何选择。** 需要开发版入口的开发者，另有一条独立的路，跟这条互不干扰。

## 怎么装

插件公开发布后，两种安装入口都行：

- **在 DSH 的插件里填包名 `@buildr-ai/dsh-plugin`**，DSH 自己下载安装；重启后即可使用入口。
- **直接跟 DSH 里的智能体说一句**“把 Buildr 加到 DSH 里”，剩下的它来做。

不需要 clone 仓库、不需要自己编译、不需要本机登记，也不需要手改配置文件。当前文章仍是待发布草稿；是否已能安装以 npm 注册表实际公开状态为准。

## 不想要了也很干净

在 DSH 的插件管理里禁用或卸载，入口就没了。**它从不改动 Buildr**，所以卸掉它不会影响你原来怎么用 Buildr。

## 一点说明

这个入口需要 **DSH 桌面版**，因为它用的是侧栏底部这个位置；在浏览器里打开的 DSH 没有这个位置。

退出并重新打开 DSH 后，点击 Buildr 会回到原来的右侧标签，不会重复打开；如果标签显示「上次打开」，再点「恢复页面」才会加载网页。已经加载的页面不会因为再次点击 Buildr 被强制刷新。

我们是把“能用”和“已经验证”分开说的：这个入口的实际位置、点击行为、对话保留，都在真实桌面版上核对过；而跨平台等其他边界，会明确标注验证范围，不靠推测下结论。
