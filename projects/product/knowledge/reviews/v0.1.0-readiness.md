# 0.1.0 准备审查

观察日期：2026-09-27。源码基线：`2e921b0777c728791d621c329512879e56b0944c`，版本 `0.1.0-rc.37`。这是当前准备工作的处理清单，不是另一份产品手册。

## 当前判断

目前除集鲜实际体验外，没有其他用户。首版围绕现有真实使用收敛：由智能体（Agent）安装 Buildr 和适用的启动器（Launcher）、解释工作对象，引导用户在网页中配置工作空间（Workspace）、项目（Project）、服务（Service）和代码库（Repository），再在智能体（Agent）工具中打开工作目录开展任务（Task）。人能查看和接续成果。无需补全文章、每日演进、云端协作或复杂升级兼容，也无需重写现有架构。

三个具体问题已完成修复并通过针对验证；最后审查另清除了一个已退役的无效页面入口，并修正两处技能（Skill）参考链接。当前没有发现还需要扩大产品范围或重写架构的首发前置。通用旧版兼容、自动备份和发布平台扩展可以后置。下面区分修复结果、本次验证和正式发布仍需完成的步骤。

## 已修复的三个问题

| 问题 | 原来会发生什么 | 修复后的结果 |
| --- | --- | --- |
| 恢复文件时写错地方 | 一次更新中断后，如果原目录被移动或改了指向，恢复操作可能覆盖原工作目录之外的文件 | 恢复前检查整组目标、备份及控制路径；危险现场拒绝写入并保留恢复依据 |
| 本机网页接受不该接受的读取 | 打开其他网站时，对方可能借浏览器尝试读取本机 Buildr 资料，而当前请求主机校验不足 | 所有页面和接口分发前校验实际监听地址与端口，异常请求被拒绝 |
| 改了目标却复制到旧指令 | 先生成“处理订单”的指令，再改成“处理库存”，旧指令仍可复制 | 输入或范围变化即撤下旧指令，旧请求与复制反馈不能恢复旧结果 |

第三项最容易在日常使用中遇到。前两项属于边界缺口，用户少可以降低复杂兼容建设的优先级，不能消除资料保护的价值。

### 1. 中断恢复可能越过原工作目录

**场景：** 更新工作资产时中断，留下备份。恢复前，某个上层目录被替换为指向外部位置的符号链接（Symbolic Link）。例如原本位于工作空间（Workspace）内的技能目录，现在实际指向另一个目录。

**原问题：** 开始更新时检查了链接边界，但恢复时只比较路径字符串；底层恢复直接删除目标、再复制备份。字符串仍像在原目录内，实际文件操作却可能跟随上层链接写到外部。自动回滚（Rollback）也复用相同底层逻辑。当前证据是临时文件复现，不代表所有普通中断都会损坏数据。

**修复：** 手动恢复和自动回滚（Rollback）共享边界校验：核对当前根目录身份、每个目标及祖先目录、备份来源，拒绝越界或不符合既有策略的链接；先校验整组，再在具体删除或写入前复核。恢复失败保留备份、日志与锁，不能报告已经完成或继续清理证据。路径复核只能缩小并发变化窗口，不能宣称彻底抵御任意恶意进程同时改目录。

**验收：** 正常恢复仍成功；上层链接被替换、备份来源异常、多个目标中一个失效时，不触碰外部文件；自动回滚（Rollback）同样受保护。实现：[恢复入口](../../services/buildr/src/modules/workspace/application/workspace-operations.ts)、[文件事务](../../services/buildr/src/infrastructure/filesystem/workspace-mutation.ts)。

### 2. 本机网页没有统一确认访问目标

**场景：** Buildr Web 正在本机运行，浏览器同时打开一个恶意网站。对方可能利用域名解析重绑定（DNS Rebinding），尝试让对其域名的请求到达本机 Buildr 端口。

**原问题：** 路由（Router）在返回页面、静态文件和业务读取前，没有统一核对请求主机（Host）。写入已有来源和会话（Session）保护，但读取不能只凭“服务监听本机”就判定可信。真实路由（Router）已用内存样例证明异常主机请求能读到样例项目；完整浏览器攻击链及实际资料泄漏未验证，风险程度仍有这层证据限制。

**修复：** 在任何路由（Router）分发之前，根据服务端实际监听配置核对主机名和端口，拒绝未知、缺失或异常主机；不能用请求自报的主机建立信任，也不能只在写入接口加检查。保留已有来源、会话（Session）和健康检查密钥，覆盖页面、静态文件及全部业务读取。支持哪些本机地址以真实启动方式为准，不泛化放行任意域名。

**验收：** 合法本机页面、启动器（Launcher）、健康检查与关闭流程继续正常；异常主机在得到页面或任何项目资料之前被拒绝。实现：[网页路由](../../services/buildr/src/web/http/router.ts)、[已有写入保护](../../services/buildr/src/web/http/session.ts)。

### 3. 改了目标，仍然能复制旧指令

**场景：** 用户选择订单项目（Project），输入“修复取消订单”，生成指令后又改为“检查库存”，或者换了项目（Project）、服务（Service）。界面输入已经变了，下面仍显示可复制的旧指令。

**原问题：** 表单输入和生成结果分别保存，输入变化没有让旧结果失效。请求返回时也没有核对它对应哪一版输入，慢请求可能覆盖后来生成的结果；切换项目（Project）时还可能保留旧服务（Service）选择。这会让用户把错误范围或目标交给智能体（Agent），并非只是一处文案滞后。

**修复：** 共享请求版本标识，输入变化和新请求都会使上一版本失效。任何影响指令的字段变化，立即撤下旧结果及复制入口；只接受仍匹配当前输入的最新请求结果。项目（Project）切换时清空不再适用的服务（Service），并核对其他使用同一反馈组件（Component）的生成表单，避免只修一个入口。

**验收：** 生成后改目标、切项目（Project）、切服务（Service）、请求期间修改输入、连续请求乱序返回，都不能复制不匹配的指令；重新生成后可正常复制。实现：[指令表单](../../services/buildr-web/src/features/task/components/TaskAgentAction.tsx)、[结果反馈](../../services/buildr-web/src/components/AgentActionFeedback.tsx)。

三项修复均已落在本次工作树（Worktree）中。恢复和请求主机（Host）的核心用例取得了修复前失败、修复后通过的对照；页面在隔离运行环境中检查真实交互。它们尚未进入公开安装版本。

### 最后审查补充修复

- “创建变更”按钮仍调用已经移除的接口，任何正常输入都会返回 404。依据现行规范中“变更只作为任务内只读内容”的边界，移除旧按钮、表单及两个无效接口调用；用户仍可通过开始工作交给智能体（Agent）推进变更。
- 两处技能（Skill）参考不再指向安装包缺失页面或已删除章节，分别连接本机运行时说明与当前任务协作章。技能（Skill）交付范围和安装策略未改变。
- 开发检查不再要求已合并的架构迁移台账或安装指南旧整句，改为核对现行技术说明及真实工作边界；没有恢复重复文档来满足旧检查。

### bootstrap 命令是否值得保留

用户所问的 `buildr bootstrap guide` 只输出安装与入口技能（Skill）恢复说明，不执行安装、初始化或更新。删除它会失去“已经安装 Buildr、但技能（Skill）尚未可用时，离线读取完整指引”的入口；这些实际业务能力仍由原有命令负责，不会随之消失。

建议可将必要内容并入已有帮助和产品入口参考，修正所有调用后删除这条重复命令，不再新增一个同义入口。若暂保留，正文应放进程序资源并保持短小。当前不删除，只给出取舍。`src/bootstrap/` 是命令分发和模块装配的真实实现，与这条说明命令不同，不能作为同一删除对象；Buildr 自举（Self-Bootstrap）则已由组织自己的方法管理。

## 发布前还剩什么

产品范围可以收敛到现有能力，不再增加新的功能前置。文档站、阅读器（Renderer）图文补齐、资源目录搬迁、`bootstrap guide` 命令取舍以及规则（Rule）和技能（Skill）进一步精简，均作为后续优化。

正式发布剩余的是现有发布流程：

1. 交付本次改动，确定 0.1.0 的最终版本材料及发布内容；本次变化已记入根目录 `CHANGELOG.md` 的 `Unreleased`，当前包版本仍为 `0.1.0-rc.37`。
2. 对冻结源码执行一次完整候选验证（Candidate Verification），核对实际安装包、支持平台与首次使用流程。
3. 发布同一份通过验证的产物，回读公开版本与安装结果。

本轮审查与修复按常规收尾交付 `dev`，实际交付提交以 Git 为准；0.1.0 的正式发布仍按上述流程单独执行。资源目录迁移和命令删除未实施；现有技能（Skill）全部继续交付。本报告直接维护当前结论，不再另建一份同内容审查。
