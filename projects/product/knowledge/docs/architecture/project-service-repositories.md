# 项目、服务与代码库如何协作

这篇文章帮助你判断怎样组织工作、从业务目标找到代码，以及调整或移除关联会影响谁。先区分四个对象，就不必用目录结构猜测它们的关系。

## 从业务目标走到代码位置

| 对象 | 回答的问题 | 关键关系 |
| --- | --- | --- |
| 工作空间（Workspace） | 在哪里共同工作和查找资料？ | 提供登记与资料入口，其中可以有多个项目（Project） |
| 项目（Project） | 要实现什么业务目标？ | 组织业务资料，关联零个或多个服务（Service）；可以先于代码建立 |
| 服务（Service） | 哪一部分实现承担这项职责？ | 可以被多个项目（Project）共用，但只指向一个代码库实例（Repository Instance） |
| 代码库实例（Repository Instance） | 实际使用哪份代码，来源和位置是什么？ | 可以承载多个服务（Service），各自定位到其中的模块或整个代码库（Repository） |

例如，两个业务项目（Project）可以共用同一个账号服务（Service）。它们引用的是同一身份，不会复制服务（Service）或代码；其中一方解除关联，另一方仍可继续使用。

页面中称为“代码库”的对象，登记的是一份有明确身份和位置的代码库实例（Repository Instance）。即使远端地址相同，不同目录或用于并行协作的不同集成分支（Integration Branch）也可能需要分别登记，不能仅凭地址相同合并。

这些关系表示业务组成与代码位置，不表示服务（Service）之间的运行调用。目录嵌套也不决定唯一归属：多个实现可以在同一个 Git 代码库（Repository）中，子目录不因此成为独立代码库（Repository）。[关系图](../../archify/flows/project-service-repositories.html)展示了允许的共享方式。图中的 `project-a`、`project-b` 和 `shared-service` 是说明共享关系的例子，不代表当前登记对象；连线也不是部署或运行拓扑。

## 登记不等于代码已经准备好

Buildr 根据项目（Project）的关联找到服务（Service），再由代码库实例（Repository Instance）的实际目录和服务（Service）的模块位置找到代码。登记可以先于代码准备；本地目录缺失时，关联仍保留，但需要准备代码后才能开展相关工作。

同样，集成分支（Integration Branch）说明协作目标，不等于本地当前检出的分支（Branch）。保存来源、目录或分支声明，本身不会克隆代码、搬移文件、改写远端配置或切换分支（Branch）。这些操作由智能体（Agent）核对实际目录、Git 状态和授权后执行，已有内容与未完成工作必须保留。

已有目录也可以登记使用，保存登记不会补写原目录中的文件。查看和调整关系从工作空间（Workspace）的“总览”或相应对象详情进入；具体配置与首次使用见[开始使用](../guides/getting-started.md)。

## 改动前，先判断影响范围

| 你想做的操作 | 会发生什么 |
| --- | --- |
| 解除一个项目（Project）与服务（Service）的关联 | 只解除这一方引用，其他关联与代码保留 |
| 移除项目（Project）登记 | 移除该登记及其服务（Service）引用，保留目录、共享对象和历史任务（Task） |
| 移除服务（Service）登记 | 解除所有项目（Project）对该身份的引用，保留文件、代码库（Repository）和历史任务（Task） |
| 移除代码库（Repository）登记 | 仅在没有服务（Service）引用时允许；代码与 Git 文件保留 |
| 修改共享职责或代码位置 | 影响所有引用方，需要核对它们的用途及实际代码位置 |
| 保存时内容已被别人修改 | 拒绝过期写入，需要重读当前内容，不能覆盖其他修改 |

界面中的“移除”只取消登记，当前没有永久删除源码的入口。保留的目录可以重新登记，但不能把重新登记当作自动恢复旧身份；历史任务（Task）仍保留原来的记录。

共享不意味着所有使用方的规则（Rule）自动合并。开展一项工作时，应按明确涉及的项目（Project）、服务（Service）及实际代码目录核对适用边界；不一致时需要明确处理，不能凭目录名决定。

## 怎样保持组成准确

新增、替换或停用某项实现时，让智能体（Agent）核对这次变化影响哪些关联，并在同次工作中维护。只登记已经确认的组成：没有在代码中发现使用，不足以否定已确认用途；尚未决定的方案也不应先登记为事实。

没有组成变化时不必写入，Buildr 也不承诺后台自动识别变化。界面与智能体（Agent）读取同一登记；已有组成图由它派生，不另存一套图中关系。具体执行方法见[项目组成维护技能（Skill）](../../../services/buildr/resources/workspace/skills/buildr/project-composition-maintenance/SKILL.md)。
