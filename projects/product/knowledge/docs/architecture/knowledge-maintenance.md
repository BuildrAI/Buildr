# 知识建设与维护

范围：Buildr 的知识建设与阅读能力。规范与代码提供事实依据，解释文档帮助人理解职责，图示表达关系，代码地图定位真实实现。本文说明当前代码中的实现；发布状态以实际交付版本为准。

## 从想弄懂的问题开始

项目或服务知识先呈现理解主题，默认打开已指定的整体认识；主题目录保留父子关系，阅读时可继续选择其他主题。说明、技术图与代码地图在主题内查看，“全部资料”保留分类检索。“了解与探索”提供看全貌、跟一个场景、深入某部分和自由提问；正文可选择“追问当前内容”。智能体（Agent）按当前问题核实最新事实后解释，普通提问不自动新增或修改长期知识。

希望保留长期说明时，“构建架构知识”接收主题、关注范围和阅读问题；技术图分类可单独发起“构建技术图”，已有内容可选择“完善当前内容”。这些入口先形成可查看复制的接续指令，由用户交给智能体（Agent）执行；生成或复制不代表调查或建设已经完成。

建设时核对规范、代码和已有知识，以目标、职责、关键关系、行为和重要取舍组织结构化解释，按需要引用视图。调查可以深入实现，展示按当前判断选择粒度；事实、设计依据、推断和建议就近区分。实际成果与必要关联进入同一知识首页，具体方法见[建设指引](../../../services/buildr/resources/workspace/skills/buildr/current-knowledge-maintenance/references/architecture-knowledge.md)。

[项目、服务与代码库如何协作](project-service-repositories.md)是按这个过程形成的真实主题。建设范围已明确时连续完成必要文章与引用，范围外新主题或修改事实源则先说明影响并取得相应决定。

## 谁建设事实，谁解释事实？

[OpenSpec](../../../services/buildr/resources/workspace/skills/openspec/openspec-propose/SKILL.md) 指导规范，[代码架构（code-architecture）](../../../services/buildr/resources/workspace/skills/buildr/code-architecture/SKILL.md) 指导代码。规范描述应该怎样，代码反映已经怎样；发现差异需要明确两边事实。

[当前知识维护（current-knowledge-maintenance）](../../../services/buildr/resources/workspace/skills/buildr/current-knowledge-maintenance/SKILL.md) 根据真实影响组织维护，按需要采用 [Archify](../../../services/buildr/resources/workspace/skills/buildr/archify/SKILL.md)、[代码地图制作（code-map）](../../../services/buildr/resources/workspace/skills/buildr/code-map/SKILL.md) 与 [术语治理](../../../services/buildr/resources/workspace/skills/buildr/terminology-governance/SKILL.md)。具体维护由智能体（Agent）按授权执行。

## 职责怎样落到实现？

工作方法以技能（Skill）源文件交付，阅读能力由后端知识模块和 Buildr Web 共同提供。局部索引连接唯一文件正文；知识正文读取不会自动改写成果。资料页面另行记录最近访问，收藏操作另写工作台个人偏好，两者均不改写知识成果。文内图示按实际图形比例适配阅读宽度，独立详情保留原生缩放与说明；不识别的图示使用通用视窗。主题与成果在主屏阅读，文中图、地图及文件在副屏对照，切换正文保留已打开内容；地图中的规范、技能职责和可点击文件树说明这项能力怎样落实。

## 目录多了怎样连续阅读？

主题目录一次读取完整的轻量结构，不读取正文与来源，不受资料分页影响；宽阅读区并列显示，窄阅读区可折叠展开。目录依照已有主题及父子关系，不自动展开所有文件；没有正文的父主题仍可连接子主题。

全部资料中的架构知识、技术图与代码地图按每页 20 项读取，在已加载列表的第 15、35、55 项附近自动请求下一页。检索在服务端覆盖整个当前分类，标题、主题说明与文件路径均可匹配；资料目录只返回条目摘要，正文与引用按打开的内容读取。没有归入主题的资料仍可找到。

进入文章后返回目录，会保留已经加载的条目和阅读位置。主阅读区的面包屑始终可见，向下阅读后可一键回到顶部；副屏有自己的滚动位置。续页失败会保留已读条目，允许重试；索引版本改变时提示刷新，不把两个版本的目录静默拼在一起。

## 怎样阅读开发中的知识？

原生开发预览（Development Preview）可以从已登记工作树（Worktree）启动独立 Buildr Web，按该位置的项目与服务登记读取知识。知识页显示“开发中”，可展开查看当前知识来源目录和预览启动时的分支、提交及修改状态；启动身份不冒充文件的实时版本，普通实例不显示该提示。

正文、图与代码引用继续遵守同一预览工作空间（Workspace）的来源解析和读取边界。技能（Skill）引用读取该位置登记的已安装技能，不能把它自动解释为产品资源目录中的候选源文件。文件更新后重新打开或刷新即可核对当前内容。

当前使用独立预览地址；主应用中尚无“当前版本／开发中”的知识版本切换入口。开发通道标志只描述运行产品的渠道，不代表所读文档处于开发中。

## 变化之后怎样保持准确？

新增来源时补齐有用关联，文件移动时更新路径，职责改变时核对说明与关系，删除来源时先确认替代实现和历史用途。无语义影响的修改不要求重画图。

知识页面直接读取当前本地文件。正文、图示或来源被修改后，重新打开或刷新即可查看最新内容；页面只提示实际缺失或无法读取的文件，其他可读内容保持可用。

索引用于关联文件与对象，不承担历史版本管理。旧索引保留的摘要不触发过期、变化或待核对提示，也不要求用户确认；读取不会改写正文或索引。需要修改时，使用现有编辑工具或“完善当前内容”入口继续工作。当前不提供知识编辑、历史对比或确认流程。

[术语解释](../knowledge-maintenance-terms.md)说明事实源、映射层及当前阅读。[维护规范](../../../openspec/specs/current-knowledge-maintenance/spec.md)与[实际文件测试](../../../services/buildr/test/integration/knowledge-query.test.ts)分别提供行为承诺和验证依据。

## 什么时候提醒，什么时候实际维护？

普通开发改动规范或代码后，智能体（Agent）按实际影响定位已有文章、图和地图，并说明哪里需要校准。只有代码修改授权时，先提出一组具体维护建议，等待授权；已有同范围维护授权时说明影响后连续完成，不逐文件确认。文件变化而表达仍成立时核对并保留，不要求重画。

用户主动要求建设或维护某个架构主题，授权覆盖这个主题所需的文章、必要图示、代码地图（Code Map）、术语与阅读关联。完成要看真实内容是否准确、关联能否打开、页面是否可读；不能只更新一篇文章就宣布整组同步。

开发中的影响判断由智能体（Agent）依据当前规范和实现完成；网页负责展示当前文件及真实读取限制，不将文件版本变化变成人的核对任务。生成建设指令后仍需交给智能体实际执行；当前不预建 Git 历史页面或云端版本管理。
