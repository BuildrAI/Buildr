# Buildr 怎样接入智能体（Agent）

Buildr 的内部对话与单次生成共用智能体（Agent）和模型（Model）配置。内部对话提供持续执行；提交说明只按给定材料调用一次模型。旧 Codex、DSH 接入及外部桌面会话（Session）关联已退役。本文依据当前候选实现，不代表已发布或真实账号验收。

## 内部对话由谁维护

`services/buildr-agent/` 是独立的智能体服务（Agent Service）代码单元，维护账号接入、统一对话、执行控制、原生上下文恢复和私有交互库。它作为私有库 `@buildr-ai/buildr-agent` 被 Buildr 本机宿主（Host）装配，与主包统一发行，首版不要求用户再安装一个 Buildr 后台服务。

Buildr 宿主负责本机认证、HTTP 与事件流、已登记工作空间（Workspace）和任务（Task）身份；前端负责对话、草稿、历史、发送预览和授权答复。三家执行器（Executor）负责各自进程、官方登录、规则（Rule）与技能（Skill）发现、工具执行及原生历史。这里的服务（Service）边界也不等于未来自研的 Buildr 智能体（Agent）：未来自研执行者可以沿同一执行器（Executor）契约与 Codex 等并列接入，当前没有该实现。

| 执行方 | 当前接入形态 | 配置与运行边界 |
| --- | --- | --- |
| Codex | `codex app-server --listen stdio://` | 每套独立配置一个应用服务（App Server），承载多个原生上下文；与桌面共享代码能力不等于复制桌面全部功能 |
| DSH | `dsh web --no-open --port 0` 与官方客户端（Client） | 启动完整本机网页宿主（Web Host），使用其会话、工具与账号能力；不依赖既有 DSH 桌面插件 |
| Qoder | 官方软件开发工具包（SDK）与独立 `qodercli` | 私有工作进程（Worker）隔离 SDK 环境；每次活跃执行由 SDK 管理原生命令行（CLI）进程 |

原生程序由“准备并连接”发现并核验真实路径、实际版本及来源。软件开发工具包（SDK）和 DSH 客户端随主包携带；缺少原生程序时提供官方安装引导或显式的独立准备动作，不修改全局安装或自动升级。兼容版本由[统一程序策略](../../../services/buildr-agent/src/executors/program-policy.ts)维护，执行适配和准备使用同一策略，缺少一家不阻止其他已就绪接入。

## 账号与配置怎样接入

“准备并连接”依次发现本机程序、选择准确来源、核对兼容性、准备独立配置，程序准备完成后不自动发起模型账号登录；用户在“模型”页按需登录并启用模型。多个可用来源需要选择；指定程序或原绑定程序缺失不静默回退。Codex 优先引导安装含 Codex 的官方 ChatGPT App，核验应用标识、官方签名和内附程序版本，也允许独立安装 CLI。DSH 准备固定官方 CLI；Qoder 优先解析 SDK 配套程序，缺少时准备固定配套版本，用户无需手动安装 SDK 或单独下载 App Server。

准备进度、来源、失败与取消在“智能体”页显示；切换厂家、关闭面板或刷新可继续查询准确尝试。服务重启后重新观察安装和账号，不把旧尝试当作仍在运行。安装只作用于本应用配置域 `agent-service/programs/`；失败及取消清理本次暂存和进程，保留既有程序、登录和会话。版本准入按主版本：Codex、DSH 接受 `0.x.x`，Qoder CLI 接受 `1.x.x`，包含有效预发布版本与构建标记；符合版本范围仅允许继续连接验证，不代表协议必然兼容。下载版本仍固定，实际协议、账号、模型及所需能力检查决定是否可用。版本准入与固定会话绑定命名空间分开；同一程序来源及独立配置内的兼容更新保留账号、连接和原生会话，不因本次范围放宽改变既有指纹；来源或配置身份改变、范围外版本及实际协议失败提供局部诊断，不能改用另一程序冒充恢复。浏览器操作工具继续由智能体（Agent）按技能（Skill）检查和准备，不属于 Buildr 原生程序安装器。

首版每家一套 Buildr 独立配置，可服务多个工作空间（Workspace）。启用接入后检查程序与账号，用户通过官方登录页完成登录，再读取该账号的可用模型；连接成功、登录流程结束和模型实际执行成功是不同事实。没有从桌面复制令牌（Token）或默认配置，也不自动继承桌面插件、用户级技能（Skill）、工具连接或模型设置。

配置保存在本机网页运行配置（Profile）的 `dataRoot/agent-service/connections/<provider>/`；统一对话保存在同根的 `conversations.sqlite`，图片保存在 `attachments/`。这些是私有运行数据，不写入工作空间（Workspace）源资产或 Git。页面显示可用状态、非秘密账号摘要及配置路径，登录地址仅属于当前登录尝试；凭据由各家原生配置保存，不通过消息或诊断返回。断开保留账号、配置和对话，停止及退出只释放本接入拥有的执行资源，不能以“已断开”冒充执行已确认停止。

DSH 在对话中选择模型会改变这套独立配置的后续默认模型；因为配置独立，不改外部桌面的默认模型。统一模型套餐组件允许在本应用配置域中明确登录 Codex、Devin 和 DeepSeek 账号，供三家原生智能体独立选择。套餐来源与原生程序准备分开，模型请求由本机认证网关转换协议，工具及权限仍由原生智能体负责。Qoder 消费外部套餐使用软件开发工具包（SDK）的逐次模型选择；其私有账号通过固定上游签名模型协议供出推理，工具仍留在所选执行方。

当前 Devin 已验证的 Codex 路径为 SWE-2 的默认权限和用户显式选择的完全访问：Devin 来源只对两个已知 Codex 命令工具的用途说明使用含义相同的表达，名称、参数说明和结果配对保留；默认权限区块仅将已知的 `justification` 审批问题单句作等义表达，示例、其他必要规则以及实际沙箱和审批策略保持不变。其他 Codex/Devin 模型及 Qoder/Devin 暂不开放；界面按模型及权限重新校验，保留旧选择和草稿，不自动提高权限。Devin 来源的 Codex 参与上下文同时绑定权限：改变权限后使用对应原生上下文，保留旧记录并按现有接续交付可见历史，避免把旧模式内部指令混入新模式；旧配置首次使用新绑定会创建对应上下文。DSH 可继续使用 Devin。声明接纳或额度错误不等于工具执行及完整回合已通过。

输入栏左侧呈现附件与权限，右侧依次为独立的智能体（Agent）、模型、思考档位和发送控件。原生模式切换执行方使用其默认模型并清除原模型和档位；统一套餐模式保留所选来源并重新校验兼容性，切换模型清除原档位；选择只更新草稿，不因此开始执行。选择器保持一致行高、清晰正文色和白色背景，悬停与选中状态一致，菜单开合不改变输入栏高度；窄屏按完整控件换行，正常名称不省略。

对话选择具有软件级（Application-level）记忆，跨工作空间保存上次明确使用的智能体与模型选择器，不写入单个工作空间或对话服务。智能体与权限属于对话模块偏好；模型选择器偏好独立保存模型来源、模型、服务档位（Service Tier）和思考深度（Reasoning Effort）。生成提交说明继续使用独立的 `buildr.execution-model`，两者互不改写。偏好只用于新对话：恢复前按当前接入、模型目录、来源可用性和执行方兼容性重新核对；失效来源回退当前智能体的官方默认选择，不自动借用另一共享套餐。已有对话继续使用本轮运行记录或本对话明确选择，不因后来的软件级偏好被追溯改写。

模型目录同时保留实际默认模型、逐模型支持的思考深度（Reasoning Effort）及默认档位。输入栏仅显示该模型支持的选项；发送预览和本轮执行保留实际模型与档位，刷新后按执行记录恢复。切换模型或执行方不会沿用不兼容的旧档位。DSH 选型后重新观察原生目录并通知对话重新读取连接，避免界面仍把旧默认值当成当前事实。

输入区提供“默认权限／完全访问”。完全访问仍由用户显式选择，换家后分别应用各家的原生设置；它只影响后续执行，不自动回答业务问题或批准未知交互。软件级权限记忆记录最近一次明确选择及来源工作空间：同一工作空间的新对话可以恢复完全访问，跨工作空间的新对话从默认权限开始。发送预览及实际本轮保存模式，恢复时每轮重新应用，避免完全访问残留到后来的默认执行。只支持默认模式的接入不能静默接受完全访问。

| 执行方 | 默认权限 | 完全访问 |
| --- | --- | --- |
| Codex | Buildr 明确使用 `on-request` 与 `workspace-write` | 原生 `never` 与 `danger-full-access` |
| DSH | 原生权限预设目录给出的默认值 | 原生 `/permission danger-full-access`，读取会话权限快照确认 |
| Qoder | 软件开发工具包（SDK）的 `default` | 原生 `bypassPermissions` 与 `allowDangerouslySkipPermissions` |

这些名称不代表三家的操作系统隔离能力相同，也不改变外部桌面配置、旧一次生成策略或辅助标题的受限执行。单个活动工具只有具备准确原生停止身份时才提供单独停止；不支持时保留活动事实和观察入口，不能把局部停止失败标成整轮已经停止。

## 怎样创建、执行和恢复对话

全局“对话”入口在任意页面可用，默认停靠右侧，历史也在对话区域查看。新对话可以不选工作空间（Workspace），此时使用稳定的 `~/.buildr/default-workspace/` 默认目录（共享数据根显式覆盖时随其解析；预览及测试使用隔离应用根下同名目录）；也可以在开始前选择、更换或取消业务工作空间（Workspace）。选择不跟随左侧页面变化。对话一旦创建，所属工作空间（Workspace）和起始目录（Working Directory）不再更改；历史消息在对话区域独立滚动。任务页的“打开对话”在没有内部对话时创建带该任务身份的对话，有一段时直接打开，多段时供选择；关联任务不会替代原生目录或自动修改任务状态。

桌面不再保留重复的顶部对话按钮，侧边图标和面板边界只切换开合，恢复原对话或历史视图；待回应数量随收起侧轨或固定标题栏保留，仍是单独的明确入口，点击才定位相应对话。桌面收起后保留对话图标，悬停可临时操作同一对话，点击才固定展开；展示切换保留草稿、记录及执行，收起按钮放在标题栏右侧。手机通过全局按钮恢复。二级导航收起时，一级图标悬停预览，鼠标点击不跳页，浮层内展开才固定对应组；固定后不再生成悬停浮层，点击一级图标直接切换固定组，重复选择当前组保持展开，仍用原按钮收起。键盘和触屏也可在固定态切组。预览或固定组使用原选中底色，不跟随浏览路由，也不改变已打开的工作页签。导航浮层保持工作区全高。固定导航、对话和原工作双屏使用同款分隔手柄及标题栏标记。对话停靠宽度为320–800px，正文和输入使用面板宽度；底部执行者、模型及档位完整显示并可换行，账号与配置归入对话内部。

对话标题用于定位主题。新对话首轮成功后，优先采用可信的原生摘要标题；Codex 和 Qoder 也可用独立有界请求生成短标题，不向工作上下文塞入起名指令。DSH 只接受来源明确的模型摘要事件，原生首句截取回退不冒充总结。自动生成失败不影响工作、重启不重复发起；手动名称优先。对没有可靠来源标记的旧标题不批量猜测覆盖，用户可在更多菜单对当前对话明确“生成简短标题”；当前执行方不能提供摘要时显示局部原因。

起始目录是规则（Rule）、技能（Skill）发现及执行的起点，不是禁止跨目录的沙箱（Sandbox）。执行者依据原生权限与用户授权访问其他目录；Buildr 不把当前页面、所选对象或整个任务正文静默注入每条指令。实际执行始终重新核对文件、资料及当前现场。

发送前核对对话版本、接入、模型、工作位置和实际交付内容；受理后立即记录本轮执行，流式展示回答、工具摘要、原生问题和授权请求。模型来源按当前账号观察重新核对身份、可用性、模型启停、档位、思考深度和执行方兼容性，调用方携带的旧账号修订不单独构成失败条件。界面对 409 按错误码分类：只有预览过期、对话修订冲突或模型来源失效等需要重读的情况刷新当前事实；执行忙碌、权限不支持和真实不兼容直接显示服务端原因，并保留草稿。停止与答复走独立控制入口，不等待模型整轮结束。停止时区分模型中断、仍有命令运行、已确认停止和状态未知；工具摘要超长时明确标记截断，完整内容仍在准确原生历史中。

重新打开先读 Buildr 统一历史，再对各参与者按原程序、独立配置、起始目录和原生上下文身份恢复。页面刷新或宿主（Host）重启不会自动重发原指令，也不重放旧授权；无法确认是否受理或执行是否结束时保留“待确认”（`unknown`），重新观察原执行。已完成和已停止的持久事实不因失去活跃连接被改写为未完成。

浏览器验证工具由智能体按[接入环境说明](../../../services/buildr/resources/runtime/skills/buildr/references/agent-operations.md#内部对话与持续执行)发现和准备。账号 `HOME` 保持独立，`BUILDR_HOST_HOME` 提供原用户路径线索；`PLAYWRIGHT_BROWSERS_PATH` 保留明确覆盖或解析到原用户的官方默认缓存，允许三家复用已有浏览器。Buildr 不新增工具管理平台或统一安装目录。关于接入、自研与职责分层，见[责任边界](agent-boundaries.md)。

## 同一对话怎样切换执行方

历史按对话组织，消息标明参与者，不按 Agent 厂商分组。同一对话同一时刻只执行一轮；有未处理执行、问题、授权或未知状态时先处理，用户仍可写草稿。

首次选择另一家时，为其建立准确的原生上下文（Context）。Buildr 从本地原始记录按轮次组织用户输入、助手说明、动作结果与位置、能确认的成果及最后答复，附上工作目录、来源范围和本次要求。问题答复仍属于原执行轮次；逐轮终态和失败诊断持续保留，不被后续成功覆盖。多次交接不会把上一次交接包再嵌套进去。换回已有参与者时，恢复其原上下文（Context），只补尚未收到的记录；隐藏推理及厂家私有压缩格式不相互迁移，历史操作与一次性许可也不重放。

正常交接由 Buildr 直接组织，不调用原模型（Model）。材料超过接入字节限制或已知上下文（Context）的保守预算时，才尝试有界、无工具且与工作会话（Session）隔离的原模型（Model）精简；当前共享模型来源和 Codex 原生隔离能力可参与，其他原生接入没有该能力时直接回退。额度耗尽、不可用或整理失败时，提供本地完整索引及分轮资料供按需读取，摘要只作辅助，标明其摘录覆盖范围。文件、脚本和日志正文不重复塞进请求；历史图片保留准确本地引用，当前新增图片仍校验真实接收能力。必要资料或当前图片仍无法安全交付时说明限制、保留草稿并允许选择其他模型（Model），无需用户手写总结。

界面只提示实际改变的智能体（Agent）和模型（Model），交接详情从对话所在一侧展开。轮次使用紧凑列表，“完整交接内容”默认收起；原文框内是实际提交的文字，页面说明在框外。接收待确认、未接收和已接收分别展示；已提交的正文快照保持不变，接收状态按当前事实更新。正常发送不再强制二次确认交接清单。

图片可通过文件选择、粘贴截图或拖放加入输入区，发送前提供缩略图、放大预览与移除。沿用 PNG、JPEG、WebP、GIF、每次最多4张及单张8 MiB边界，校验失败保留文字和已添加材料；发送后的图片通过当前对话的认证读取接口按需加载，刷新后仍可查看，不把本机路径或认证令牌放进图片网址。

Codex 使用原生本地图片输入；Qoder 在软件开发工具包（SDK）的用户消息中发送带媒体类型的 Base64 图片块；DSH 使用原生提示内容（Prompt Content）的图片分支。图片字节随明确发送动作交付，具体模型的视觉能力仍以厂家实际响应为准；执行端支持图片不等于所有模型均已通过识图验证。

模型与推理强度共用紧凑入口，智能体（Agent）保持独立选择。浮层只提供厂家返回的实际档位，切换模型清除旧强度，并可恢复模型默认值；不把普通闪电图标当作加速模式能力。桌面对话默认宽度620像素，与账号配置抽屉一致，拖动下限560像素，底部权限和执行选择保持同一行；旧的窄宽度偏好在读取时修正，移动端沿用全屏适配。

## 为图形与对话交互留下什么基础

图形界面（GUI）和对话界面（Talk UI）共享工作空间（Workspace）、任务（Task）及实际成果身份；对话只保存交流和执行观察，不成为代码、文档或任务状态的唯一权威。首版将工作位置、任务关联、发送预览、观察版本与独立控制留在公开契约中；未来业务现场接入应传明确对象身份和已观察版本，由原业务能力保护写入，不能把页面焦点或历史消息当作写入许可。

## 单次生成与任务关联

提交说明从现有模型（Model）目录明确选择账号和模型，经过统一模型能力执行，不创建持久对话，不提供工具。业务负责有界材料、输出结构、任务尾注和来源版本检查；取消、超时或来源变化保留草稿。实现见[提交说明怎样生成](agent-integration-generation.md)。

内部对话与任务（Task）的关联保持可选。一个任务可有多段内部对话，入口按准确身份打开；普通咨询无需任务。关联用于查找和接续，任务进展、验证和完成继续依据当前成果。

外部桌面关联、旧登记、桌面生成和会话导航接口已经删除。正式应用启动时清理当前配置及已登记工作空间中的固定旧文件，不迁移、不备份关系历史；开发预览不触碰真实数据。清理遇到链接、写入锁或异常文件时局部报告，其他功能可继续使用。外部桌面聊天、账号、新模型配置与内部对话不在清理范围内。

## 统一模型套餐

实现位于 `services/buildr-agent/src/model-access/`，作为私有库随主包捆绑交付；不是新增公开 npm 包。账号元数据和模型观察保存在本应用 `agent-service/model-access/`，厂商凭据由其唯一提供者管理。Devin及按需添加的额外账号明确发起独立浏览器登录；原生账号直接复用已有登录。DeepSeek 由私有 DSH 宿主账号服务持有凭据，通过固定目的地的认证桥接委托模型请求，不向网页或网关消费者导出凭据。

公共模型入口由宿主的 `/api/v1/app/agent-service/model-accounts` 与 `/model-catalog` 管理，沿用本机认证与写入校验；执行方只取得绑定账号、模型、对话和执行方的本机访问凭据。三个模型协议入口只在回环地址监听，不以系统代理环境变量代替套餐连接。

每轮保存 `modelAccountId` 和来源摘要。跨来源或模型的原生状态不能通用时，仍在同一可见对话中保留不同参与绑定，并交付尚未见到的可见历史。旧原生模式和已有对话保留；断开、刷新和未知执行都不自动重发。额度不可读按未知显示，不根据静态模型列表或估算用量推断剩余套餐。

每个模型账号独立维护选择修订（Revision）。只有身份、启停、状态、账号标签、模型目录或影响模型选择的偏好发生实质变化时才更新该账号修订；模型与档位按稳定标识比较，额度、观测时间、诊断文本和返回顺序变化不更新修订。检查一个账号不更新其他账号，因此使用 Qoder 的对话不会因 Devin 的刷新或配置变化出现假冲突。发送以当前账号快照重新计算预览和本机绑定，只有登录来源变化、模型移除或停用、能力或权限不兼容等真实失效才拒绝。

### 复用原生账号

Buildr自动将已连接的Codex、DSH、Qoder账号发现为共享模型来源。登录与续期仍由对应原生运行实例负责；Codex通过app-server取得有效凭据，DSH同一宿主装配固定上游桥，Qoder只读该Buildr私有配置的账号，使用签名模型协议传递工具定义及结果。账号身份变化或断开撤销旧来源；旧独立套餐和会话保留为额外账号。Qoder套餐模型可由Codex、DSH消费，工具仍由所选执行方执行。

### 模型额度与使用偏好

“智能体与模型”分为“智能体”和“模型”：前者仅管理程序接入与检查；后者在同一账号卡片完成登录和额度查看，按上游实际返回的日、周等窗口保留剩余比例、重置时间和观察时间。额度读取失败保留带旧时间的已知窗口并明确过期观察；平台没有返回时显示未知，不据此拒绝可用模型。

上下文窗口以K显示（1K=1000词元），内部保存整数词元。模型启用和上下文窗口保存在本应用配置域的独立偏好中，按账号与稳定模型标识保留；目录刷新不覆盖用户选择，新发现模型默认停用。迁移既有普通模型保留启用意图，组合模式默认关闭。上下文覆盖可恢复默认，不能超过已知平台报告上限，实际执行再按选定服务档位的上限取有效值。偏好写入通过 `/model-accounts/:accountId/preferences` 携带 `expectedRevision`，冲突必须重新读取，不手写账号存储。

Devin 的模型系列、思考强度及服务档位通过明确配置映射归并，组合模式单独搜索、分页和启停；缺少可归并信息的条目保持独立，不编造支持组合。每轮记录 `serviceTier`，租约身份包含有效上下文及档位；配置变化创建对应原生上下文，停用拒绝新执行，已经接受的当前调用继续。断开模型账号只撤销该来源的本机租约，保留原生程序与已有登录，其他套餐仍可使用。

配置不提供默认模型搭配。对话切换智能体时优先选择其已配置、启用且可用的官方来源模型，仍允许手动选择其他来源；官方来源不可用时不自动消费其他套餐。跨工作空间的新对话恢复上次模型选择器偏好，但仍按当前目录重新观察，已有对话保留自己的实际模型。模型元数据读取先返回已有观察，后台并发检查；手工刷新各来源独立反馈。Qoder使用其他来源模型仍需其厂家基础平台登录，该授权要求不等同于必须购买Qoder套餐。

上下文窗口使用单个输入框，支持整数或K后缀，按千截断显示，不因显示截断自动保存；清空恢复平台值。程序详情在对应智能体卡片内展开，模型名居中，悬停或聚焦时呈现选择状态。

### 上下文窗口来源与用量

模型页使用来源模型目录的窗口观察：Codex读取`/codex/models`的`context_window`默认值与`max_context_window`最大值，DeepSeek读取`/models`的`context_window`，Qoder读取平台`/models`配置的`context_config`默认值和全部可选窗口范围，Devin读取`GetCliModelConfigs`的模型与档位配置。该值表示当前来源可用窗口，不声称是模型理论能力。模型目录观察缓存于本机模型账号元数据，手动设置另存偏好；显示值按千截断，未编辑不自动保存截断值。恢复默认移除手动覆盖，回到来源报告值。档位容量与用户配置共同决定生效值。

程序检查仅核验程序与独立配置，不等待账号或在线模型目录。账号观察及模型刷新仍由模型页负责，使用Qoder其他来源模型时仍遵守厂家基础登录要求。

对话模型名前提供上下文用量入口。Codex的`thread/tokenUsage/updated`以`last.totalTokens`记录最近上下文观察，不能使用累计计费`total`冒充占用。仅向同一执行方和模型显示对应观察；未提供此事件的来源显示尚未收到报告，不估算百分比。

服务重启后的恢复以被中断的执行（Run）为范围，不扫描任务的进行中状态。网页监听就绪后，开发运行配置（Profile）自动核对准确原生执行：仍运行则只观察，已完成则更新结果；确认停止、没有活动或未知工具且没有待用户决定时，沿用原参与者、模型来源与权限接续一次。系统接续单独标记，不伪造用户输入或重跑全部命令。正式运行配置（Profile）不自动发起续做，显示“执行未完成”和原因。主动停止、额度耗尽、身份失配和结果不明保留原因，不盲目重试。
