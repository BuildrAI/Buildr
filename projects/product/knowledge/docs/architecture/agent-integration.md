# Buildr 怎样接入智能体（Agent）

Buildr 的内部对话与单次生成共用智能体（Agent）和模型（Model）配置。内部对话提供持续执行；提交说明只按给定材料调用一次模型。旧 Codex、DSH 接入及外部桌面会话（Session）关联已退役。本文依据当前候选实现，不代表已发布或真实账号验收。

## 内部对话由谁维护

Codex、DSH与Qoder新工具采用v9兼容边界下的原生调用引用。适配器首次投射工具时标记正文由原生持有，Buildr只保存配置域、会话、轮次、调用ID及编排元数据，工具正文、缺失片段和折叠文本预览不落库，也不逐条比较收益。实时详情沿现有SSE视图传递，传输缓存有界；工具详情的live标记让前端在执行结束后继续接收原生引用切换。原生完成记录可读后清除实时展示，展开通过entry-detail直接读取原生详情。执行控制状态独立更新，源缺失只影响详情。旧正文编码仍沿准确片段引用与有界补转路径。DSH按原生事件与rpc归属读取完整详情，Qoder的SDK执行编号与原生promptId不同，不作为原生筛选条件；通过会话内唯一工具调用及来源消息定位，内部按prompt与工具消息读取，子工具先核对唯一原生父调用及消息归属，再读取该会话下的subagents记录。JSONL与DSH压缩帧均有界遍历，不把整份会话载入内存；普通快照及内部控制回包使用紧凑视图，不隐式读取正文。DSH在原生适配器中合并累计文字并定期让出事件循环，工具、问题及终态保持即时有序交付。附件完整性和唯一原件边界沿既有实现。

`services/buildr-agent/` 是独立的智能体服务（Agent Service）代码单元，维护账号接入、统一对话、执行控制、原生上下文恢复和私有交互库。它通过私有包 `@buildr-ai/buildr-agent` 提供独立执行进程（Agent Process）和公共客户端（Client），与主包统一发行，用户不需要另外安装服务。本文描述当前候选实现，尚未激活到保留环境。

Buildr 宿主负责页面认证、网页 HTTP 与事件映射，以及已登记工作空间（Workspace）和任务（Task）身份；执行后台（Execution Backend）持有原生连接、统一对话、交接、待回应、模型转接、辅助生成和私有数据写入。前端负责对话、草稿、历史、发送预览和授权答复。各执行器（Executor）负责各自进程、官方登录、规则（Rule）与技能（Skill）发现、工具执行及原生历史。这里的服务（Service）边界也不等于未来自研的 Buildr 智能体（Agent）：未来自研执行者可以沿同一执行器（Executor）契约与 Codex 等并列接入，当前没有该实现。

| 执行方 | 当前接入形态 | 配置与运行边界 |
| --- | --- | --- |
| Codex | `codex app-server --listen stdio://` | 每套独立配置一个应用服务（App Server），承载多个原生上下文；与桌面共享代码能力不等于复制桌面全部功能 |
| DSH | `dsh web --no-open --port 0` 与官方客户端（Client） | 启动完整本机网页宿主（Web Host），使用其会话、工具与账号能力；不依赖既有 DSH 桌面插件 |
| Qoder / Qoder CN | 官方软件开发工具包（SDK）与独立 `qodercli` / `qodercn` | 私有工作进程（Worker）隔离 SDK 环境；相同配置的正常轮次可在历史和未结工作证明完整时复用原生连接，否则按准确原编号冷恢复 |
| Claude Code | 官方 `@anthropic-ai/claude-agent-sdk` 与独立 `claude` CLI | 不维护原生账号登录（`account: 'source-required'`），只经本机模型网关消费 Anthropic Messages 兼容来源 |
| Antigravity | 官方发布清单受管 `agy acp`（ACP 协议） | 连接级协调者配合按对话（会话、权限、账号身份与受管程序摘要）隔离的 `agy acp` 子进程组；私有 `HOME` 下设置 `autoUpdate: false`，不接管外部 `agy` 或注入 shell |

原生程序由“准备并连接”发现并核验真实路径、实际版本及来源。软件开发工具包（SDK）和 DSH 客户端随主包携带；缺少原生程序时提供官方安装引导或显式的独立准备动作，不修改全局安装或自动升级。兼容版本与分发策略由各执行方模块在[统一程序策略](../../../services/buildr-agent/src/executors/program-policy.ts)注册，执行适配和准备使用同一策略，缺少一家不阻止其他已就绪接入。

### 执行方声明、模型路径绑定与兼容边界

公共编排层（`application/`、`model-access/application.ts`、`executors/` 公共模块与前端 `agent-conversations`）不以执行方品牌字面量作条件分支，而是统一消费执行方声明（`modelPolicy`、`runtimeTraits`、`nativeContent`、`distribution`）与模型来源声明（`sharing`、`inference`、`presentation`），实现见[模型策略与兼容判定](../../../services/buildr-agent/src/domain/model-policy.ts)：

1. **执行方模型策略（`modelPolicy`）与运行特性（`runtimeTraits`）**：每个执行方声明基础账号要求（`connection-ready` 或 `source-required`，可选 `readySourceSupersedesConnection`）、原生来源集合与传递/绑定方式（`delivery`、`exclusive`、`binding`），以及支持的网关线协议（`openai-responses`、`openai-chat-completions`、`anthropic-messages`）；`runtimeTraits` 声明网关配置下的共享原生主目录策略、升级验证方式（`runtime-verify` 或 `account-probe`）、临时账号探针支持以及传输中断识别委托（`ExecutorObservationLost`）。
2. **两条模型路径的绑定契约**：打开运行时与发送前先由 `resolveExecutionModelPath()` 确定唯一路径：
   - **网关路径**：来源声明 `inference: 'gateway'` 且非当前执行方的原生直通来源时，签发绑定账号、模型、对话与执行方的短期本机网关租约（Lease），原生进程只接触回环端点与临时令牌。
   - **原生直通（`gateway-lease`）**：Qoder 与 Qoder CN 选择自身原生来源时保留既有租约与 `nativeModel{ executor, modelId, accountIdentity }` 校验，由 `checkedGateway()` 核对执行方标识与绑定方式一致。
   - **原生直通（`account-identity`）**：面向不提供网关推理的原生来源（如 Antigravity 的 Google 个人账号 `native-antigravity`），准备与发送均**不签发网关租约**，而是在打开前校验来源就绪、账号身份一致、模型在当前来源目录且启用，向执行方传入互斥的 `nativeSource{ accountId, accountIdentity, modelId, model }`，并由执行方在工作输入副作用前再次核对当前原生账号身份与模型。
3. **来源共享范围（`sharing`）、推理方式（`inference`）与展示声明（`presentation`）**：模型来源默认 `sharing: { kind: 'gateway' }`、`inference: 'gateway'`；声明 `executor-exclusive` 的来源只允许指定执行方原生使用并向其他执行方公开明确原因，拒绝跨执行方签发租约；声明 `inference: 'none'` 的来源不提供网关推理，禁止签发任何网关租约，并从单次生成（`models.generate`）、提交说明与直接执行模型选择器中排除。账号与目录视图通过 `presentation` 公开厂商名称、卡片名称、额度标签、API Key 提示、额度不可读说明及官方账单链接，前端不再硬编码厂商账单或品牌映射（仅保留离线历史展示兜底表）。
4. **静态兼容与发送时可用性分离**：服务端以唯一纯函数 `sourceCompatibility()` 根据双方声明计算静态兼容，并在账号与目录视图投射 `executorCompatibility{ connectionId, compatible, reasonCode, reason }`；前端只依据该结论禁用不兼容模型并保留原模型名与悬停原因（字段缺失时前端按兼容放行，交由发送端裁决）。发送时可用性由服务端在工作输入前按固定顺序实时校验：连接已准备 → 连接基础账号就绪（若声明 `readySourceSupersedesConnection` 且所选原生来源已就绪，则不被陈旧连接观察先行拒绝）→ 所选来源存在且启用 → 来源状态 `ready` → 静态兼容 → 账号身份未变 → 模型存在且启用 → 图片、服务档位与推理强度支持。因此静态兼容但已过期或停用的模型明确返回过期或停用原因，不误报为来源不兼容。
5. **原生工具详情注册（`nativeContent`）**：各执行方通过 `defineNativeContent()` 注册自身的会话根目录、符号链接与路径越界保护及按需详情读取器（见[原生内容边界](../../../services/buildr-agent/src/storage/native-content.ts)）；公共层只对已注册 `nativeContent` 的执行方登记 `nativeTools` 并在对话条目投射 `nativeDetail: true`，前端据此脱敏折叠摘要并按需拉取详情；未注册执行方保留已保存摘要，详情读取明确返回不提供原生详情。
6. **程序分发策略（`npm` 与官方清单 `manifest`）与失败边界**：程序策略除 npm 包安装外，支持官方发布清单（[清单解析](../../../services/buildr-agent/src/executors/program-release.ts)与[归档安装](../../../services/buildr-agent/src/executors/program-archive.ts)）。清单读取手动处理重定向，逐跳校验 `https:` 与主机白名单（最多 5 跳、响应上限 64 KiB），校验 `sha512` 格式、严格 SemVer（禁止路径分隔符与越界字符）及主版本准入，读取失败直接报错而不静默降级到固定旧版本。归档安装使用独立临时目录 `.prepare-<attemptId>`，流式下载限制 512 MiB 并完整核验 SHA-512，进程内解析 `tar.gz` 单一目标成员（拒绝符号链接、硬链接、设备节点与路径越界，限制最多 16 个成员、解压上限 1 GiB）或落盘独立二进制，设置可执行权限、清理 macOS 隔离扩展属性并通过 `--version` 核对版本后，才原子重命名到 `programs/<provider>/<version>/` 并经同目录临时文件原子切换 `prepared.json`。同一提供者的并发准备互斥归并；任何阶段取消或失败均清理本次临时目录，既有程序、`prepared.json` 与连接绑定保持可用。

统一执行条目通过可选 `parentToolId` 保留原生父工具来源。主助手、子任务报告和工具结果沿同一公共契约保存，但子任务内部输入不成为用户要求，子报告不重复充当主助手最终答复、标题材料或交接说明；结果仍可从原工具详情核对。缺少可靠来源的旧记录不按文本相似度猜测归属。三家适配保留各自原生执行方式，Buildr 不另建替代推理循环。

Qoder 使用外部模型时，在实际工作连接初始化之后、首条输入交付之前核对基础账号和真实模型目录，避免为同次工作再启动一条账号检查连接。安全复用要求目录、模型、思考档位、权限一致，前轮正常结束且历史、工具、待决定与追加确认均结清；历史变化或证据不完整即冷恢复。控制资源释放仍需关闭准确空闲连接并核对自有进程，不能以复用或模型终态证明工具成功。

## 流式事件怎样减少重复传输

应用层对原生执行器或SDK交付的文字片段逐片段执行原有事务，提交成功后才发布事件，不在传输层增加合并等待或打字延时。进程与浏览器连接可协商`delta-v2`：首次是有界完整快照，后续仅发送变化头部、必要条目顺序、文字后缀及变化元数据；正文修正采用完整条目替换。未变化的历史轮次状态、条目ID列表和累计正文不随每个片段重复发送。工具正文仍由原生持有，详情按原有引用读取。

接收端按工作空间、对话、后台代次、游标、修订和JavaScript字符串偏移校验基线；字段删除、条目删除与重排显式表达。基线错误拒绝拼接，已有重连机制从新快照恢复，不重放用户或工具请求。旧`delta-v1`和完整事件继续兼容，浏览器遇到旧HTTP协商拒绝可对只读订阅有界回退。后台SSE仅在已发布视图仍符合当前修订、已读和待发版本时复用它；其他写入和保留代次仍沿读回与轮询更新。有界观察队列及控制身份边界保持原义。

## 隔离工具怎样读取共享资源

已验证完整目录覆盖的原生执行器默认使用明确宿主 `HOME` 和标准 `TMPDIR`。Codex/DSH 网关模式的原生 home（`CODEX_HOME`、`DSH_HOME`/`DSH_AGENTS_HOME`）按连接共享一个、全对话复用，账号/模型/对话/轮次隔离由网关令牌强制而非目录，home 级状态库（目标、记忆、线程历史）按原生语义跨对话共享，租约专属模型配置外移到租约临时目录；参与方持久化准确 home 根，旧参与方保留原租约 home 并双轨解析。Qoder 内容按账号共享（`QODER_CONFIG_DIR`）；原生登录模式仍每连接一个 home。无覆盖保证时保留私有HOME兼容模式；声明 `credentialScope: 'host-keyring'` 的执行器（如 Antigravity）在使用连接私有 `HOME`（`.gemini/antigravity-cli/`）的同时，在 Linux 上保留系统密钥环所需的会话环境变量（`DBUS_SESSION_BUS_ADDRESS`、`XDG_RUNTIME_DIR`），其他执行方环境不变。Buildr自身的标题请求等仍保存在准确私有目录。工具和依赖优先使用本机来源，Buildr共享目录仅作缺失时后备。Qoder新原生组件复用供应商自身按版本和用户组织的宿主临时缓存，不另建组件目录。工具环境中的 `BUILDR_HOST_HOME` 仅用于定位宿主共享能力与用户级 Git 配置；显式 `BUILDR_PRODUCT_DATA_DIR` 优先，并由环境白名单保留，不转发其他账号凭据。共享资源根按“显式产品目录、合法绝对宿主主目录、当前主目录”定位。

本机采用回执描述工作空间生成入口的准备结果，不是读取共享源的许可。任务工作树即使没有该回执，也能只读使用已声明且摘要、路径和权限均有效的共享文件；不复制资源或回执、不隐式同步，损坏仍按准确来源拒绝。

## 对话中的文件输出

统一条目通过可选 `presentedFiles` 保存原生明确展示的文件路径及说明，并保留条目、参与者和执行归属。DSH 的 `present` 调用在完成后显示卡片；旧记录缺少此字段时，仅从准确成功调用的原参数生成只读视图，必要时按原条目内容版本读取详情，不重写历史或重新执行工具。助手说“已提供文件”本身不是卡片来源。

文件卡片在处理过程收起时仍可见。预览按需复用已登记代码来源的有界读取，Markdown 复用现有阅读组件；打开沿同一准确来源进入资源管理器。文件声明不授予任意本机读取权限，来源不可核验、缺失、访问拒绝及类型限制就地说明，不按同名文件替换目标。Markdown 角括号仅作为目的地语法，打开回调接收解析后的真实路径；跳转前核实文件，避免错误父目录级联请求。

## 后台换代与原生会话连续性

旧后台保留当前轮和待回答问题；结束后先由执行器确认逻辑静止，再关闭准确拥有的空闲运行时，最终核验物理控制资源已释放。Qoder 的会话关闭不等于 SDK 守护进程退出，工作进程在关闭时还需关闭自己加载的 SDK 守护进程。结束准备检查不是物理释放证明，更不证明未知业务操作成功。

同一执行选择优先匹配最新且可安全复用的原生会话。已释放控制资源的历史未知轮次不再单独占用最新已完成会话，历史结果仍保持未知。当前轮已结束但存活旧后台尚未确认释放时，新要求在同一 Buildr 对话内以独立原生上下文接续，保留旧控制并记录会话替换及未释放原因，不回退旧会话、不冒充原会话接管。已释放且可安全复用时，新后台恢复同一原生身份；最新轮本身未知或原轮仍在途时，新目标同样使用独立上下文，保留原控制、问题和未知副作用，不重放旧输入。

对话条目的 `nativeSession` 增量记录后台接管或原生会话替换的原因、前后会话与后台身份。只有原生恢复或创建成功才写入，受理、失败和送达未知沿准确本轮回执更新；它不将后台变化描述为模型切换，也不回填过去没有证据的交接。

## 主程序与执行后台怎样连接

### 产品动作怎样交给内部智能体（Agent）

服务“运行配置”是复用内部对话的产品动作：服务目录、服务详情与任务本地运行先通过同一[交接抽屉](../../../services/buildr-web/src/features/service-runtime/components/RuntimeConfigurationDrawer.tsx)说明目标、步骤、授权影响和完成标准，用户确认“运行配置”后才由[配置动作](../../../services/buildr-web/src/features/service-runtime/configurationAction.ts)提交[简短请求](../../../services/buildr-web/src/features/service-runtime/configurationPrompt.ts)。请求携带规范工作空间（Workspace）与服务（Service）身份、技能入口和本次本地验证授权，不复制调查与命令教程。

[共享对话上下文（Context）](../../../services/buildr-web/src/features/agent-conversations/AgentConversationsContext.tsx)的 `startTextConversation` 与[文本提交原语](../../../services/buildr-web/src/features/agent-conversations/conversation-product-action.ts)负责实时选择和首条请求去重：可用时直接打开现有对话，未接入或提交前读取失败时在同一交接抽屉内保留复制；已有未确认请求或提交响应丢失时先核对原身份，不换通道再执行。它们复用手工发送的首条提交记录、模型（Model）、权限及恢复机制，不新增后台接口或服务专用执行状态。

调查、候选启动、验证及保存仍由[服务本地运行技能（Skill）](../../../services/buildr/resources/runtime/skills/buildr/references/local-services.md)指导智能体（Agent）完成。提交成功后按工作空间保存[交接记录](../../../services/buildr-web/src/features/service-runtime/runtimeConfigurationHandoff.ts)，服务行显示“配置中”或“检查中”；刷新或切换入口后仍恢复该状态并回到原对话，同一服务不再打开可提交的配置入口。[完成判定](../../../services/buildr-web/src/features/service-runtime/configurationOutcome.ts)只在本次配置对话执行正常结束且 `services/<service-code>/runtime.yml` 可读时提示“运行配置已完成”，执行结束但定义不可读时提示“配置尚未完成”，由在应用壳层挂载一次的[结果反馈](../../../services/buildr-web/src/features/service-runtime/components/RuntimeConfigurationOutcome.tsx)通知并清除记录，不依赖发起页面；完成或检查完成且定义可读时，通知直接提供“启动本地”打开启动抽屉，进程仍由用户确认后启动。完成不代表服务已启动或业务验证通过；对话受理或结束不单独生成“配置成功”，保存定义也不重启已有实例。交接记录只是浏览器本机的界面索引，不建立服务与对话的持久关联，也不表示配置或验证结果。

### 公共执行边界

公开边界包含三组版本化契约（Contract）：执行操作（Agent Operations）、宿主能力（Host Capabilities）和运行管理（Lifecycle）。Buildr 通过宿主能力解析准确执行范围、核验可选工作对象并列出查询范围；后台只依赖来源、对象编号和已观察版本，不加载 Buildr 任务或工作空间模块。新工作必须重新核验环境；宿主暂不可达不取消已经受理的执行，也不把对象判为不存在。

同一数据根及配置域（Profile）只允许一个配置维护者（Metadata Owner），兼容版本可保留多个执行代次（Generation），每轮工作继续由其准确持有者控制。公共客户端（Client）使用认证回环通信，事件流只负责观察；Buildr 退出仅释放本次连接，重新打开后读取同一后台代次和原生执行。响应丢失时以原 `clientRequestId` 核对受理结果，不自动重发；后台本身退出仍沿既有准确恢复规则处理。

后台从编译后的私有包、完整运行依赖和准确 Node.js 内容生成受保留运行单元（Runtime Unit），放在私有数据根的 `agent-service/process/runtimes/`。新构建不会覆盖活动内容。新版本激活从实际交付包声明目标；公共客户端（Client）发现内容不同后提交目标，激活调用方等待准确新版实例就绪、接收新工作；普通控制连接仍可读取和控制旧任务，不因启用失败失去停止或回应入口。宿主按自身运行单元校验响应契约：两侧运行单元不一致或存在待切换单元时，契约差异属于版本对齐窗口，宿主返回可恢复的 `agent_service_aligning` 状态并保留上次观察，不按违约报告失败；两侧一致时的契约违约仍如实暴露。`requestRuntime` 只表示请求受理，`activateRuntime` 返回实际启用结果；开发应用安装入口通过 `activateAgentServiceRuntime` 核对目标摘要、实例身份和接收状态，不能仅凭文件已安装或主应用健康报告升级完成。旧后台不会自行监测源码变化，未声明目标时空闲也不触发换版。

支持并行的兼容版本先启用新版接收新任务，旧任务、问题和工具仍由原代次（Generation）处理，直到其资源安全排空后自动退出。新要求可通过既有待发送记录（Pending Send）保全，按准确归属和版本重新核验后交付，不重发未知操作。不支持并行时沿用受保护的空闲交接进程（Handoff Process）；已登记目标后无需额外发送任务触发切换。新版未就绪、启动失败或有界等待超时均不算激活完成，保留旧工作及明确诊断；同一目标的明确重试重新核验实际启动。
激活准备被短暂 storage 锁（启动、迁移、维护）阻塞时，空闲 owner 可按既有生命周期所有权 drain；忙或主线程 stall 的 owner 拒绝空闲停止后被保留，激活在有界预算内重试准备，再经上述并行交接完成，不把“停止旧 owner”作为兼容目标的前置条件。

任务（Task）的成果是否完成、原执行是否结束、执行后台（Execution Backend）的控制资源是否释放分别判断。`RunView.executionState` 表示原执行状态，`resourcesReleased` 只表示原后台已释放该准确运行的控制资源；二者均不替代成果验收。原生主进程退出后，工具可在独立进程中继续，释放空闲控制连接不能证明该工具已结束，因此执行和操作结果仍可保持未知。明确登记的后台任务、待决定、辅助工作和仍活动的控制进程组继续受保护；关闭后再次核对，晚退资源未释放时保留准确持有。资源已释放的历史未知结果不再锁住空后台，但仍阻止自动重发及排队续发，后续准确终态可补回结果。隐藏仅对原执行结束且控制资源释放的未知记录免除活动提醒，不能掩盖仍未知的执行。旧执行器缺少证明时保持保守。仅因保留历史未知执行而保持活跃、且无其他可解释状态的对话，列表归为“状态待确认”并计入待确认计数，不无声置顶。用户可对没有 active 执行状态、没有 running 工具且无有效问题的保留 unknown 轮显式“结束提醒”（`attentionSettled`）：只解除该轮对列表活跃的影响，不宣称完成、不终止进程、不释放资源、不重发操作，unknown 证据与诊断保留；真实在途证据、未读与有效问题仍保持可发现，属主代退出后的资源释放对账不受结算影响。

连接只在被工作时建立，不提前准备，也不为尚未采用的连接保留等待窗口；一旦被工作采用，执行、标题及观察等相关持有者结束后便按准确证明及时回收。正常结束和历史核对都会安排所属资源释放，迟到的原生结束证明或模型请求采用退避重查；物理关闭后再次确认无在途请求，撤销对应临时凭据。持久原生历史继续保留，下一轮按原上下文恢复。回收与新输入交错时，新输入等待同一资源释放后重新获取，不关闭正在使用的资源，也不重复投递。

Codex、Qoder、DSH 与 Antigravity 共用 `OwnedControlResource` 保存准确控制归属及核对进程组空闲，各自适配器（Adapter）只提供原生执行、待决定和辅助工作事实。Antigravity 按对话（会话引用、权限模式、账号身份与受管二进制摘要）启动独立的 `agy acp` 进程组，停止时先发 `session/cancel` 有界等待，超时仅终止本对话进程组并核验为空，不影响并发的其他对话。DSH 通过官方后台任务（Job）订阅核对首个完整列表，观察后立即退订；仍运行、停止中或观察失败均不能释放该控制资源。共用应用层还保护该准确模型连接上的在途请求，不因其他对话的模型调用阻止无关资源释放。DSH 恢复时补写的 `TOOL_OUTCOME_UNKNOWN` 表示工具结果未知，不是完成回执；已准确收到的同次工具完成事实继续保留。控制进程退出后关闭失效通信载体，避免连接重试自身继续占用旧后台。

通过既有认证入口 `GET /api/v1/app/agent-service/runtime` 可观察准确实例、代次、当前/待采用内容摘要及忙闲原因。任务预览（Task Preview）不持有后台会话令牌，改由 instance-secret 认证的 `/api/v1/health` 携带非阻塞 `agentRuntime` 快照观察候选就绪，仅当当前 digest 等于钉住候选、接收新工作且无待切换单元时才宣告启动成功。普通主程序退出不会停止后台；预览停止才按其准确所有权停止后台，退出或工具释放未确认时不清理资料。模型目录沿用、连接重定位等离线维护与后台启动共用持有锁，不能旁路覆盖活动配置。首次从同进程版本升级必须等旧执行和待回应结束并关闭旧版，再启用独立后台。旧版缺少原子暂停接收契约（Contract），自动交接发现既有智能体（Agent）资料仍由旧主程序持有时保留旧实例并提示先退出，不用磁盘空闲快照冒充原子迁移。


Qoder 与其他执行器使用同一生命周期：实例只在执行期间持有，安全结束后按准确证明回收，不再为同一选择额外保留实例。升级、退出、断开和明确交接仍立即核验释放。

共享对话快照与紧凑历史投射使用已有工具预览，不触发旧原生引用读取或旧工具正文解压、校验；显式完整历史和详情读取仍保留原内容及校验。旧 DSH 文件呈现声明缺失时，只在读取阶段按准确工具修订补取并在有界内存中缓存，输出保存生成快照不补读正文。

### 可重建缓存与旧运行时

磁盘生命周期由统一智能体服务（Agent Service）管理。执行器（Executor）声明可重建临时目录及控制资源退出证明；共享存储能力负责路径归属、文件观察身份、系统进程占用与条件删除。不同 Agent 和模型继续作为独立工具接入，同一可见对话和各方原生上下文的关系保持不变。

所有执行器默认使用宿主工具标准缓存目录，宿主不可用时才回退到 `agent-service/toolchains/cache`；npm、Yarn、Node 编译、Python、pip 与 uv 的公共选择由统一执行环境提供，新执行器无需逐项声明。程序安装和探测也复用同一选择。公共环境复用明确存在的 Java/Maven 安装与本机 Maven 仓库，不投射 Maven settings.xml、npm 凭据或其他账号配置。旧执行器声明的可重建缓存，在创建归属、稳定窗口、占用和版本复查均通过后，将缺失条目以排他发布方式合入公共缓存，已有公共缓存条目优先，成功后才回收旧目录；中断保留原目录并在后续维护接续。可核对的插件市场检出保留一份缓存种子，通过文件系统写时复制（Copy-on-Write）物化成各上下文可独立修改的副本；回收私有临时副本不要求下一轮重新下载整套插件。文件系统不支持安全克隆时保留原缓存作为兼容回退。`HOME`、原生配置、账号和会话不合并。Codex 的插件临时副本位于各自 `codex-home/.tmp/plugins`，目录仍是干净的 Git 临时检出、未发现本地插件登记，且准确控制进程组退出、没有其他进程引用该环境后才可回收；恢复所需的会话、状态库和账号文件继续保留。工作结束后的进程释放不等于删除整个环境。

执行运行单元中的 Node 和不可变包文件使用 `toolchains/objects` 的只读内容对象与硬链接视图，同内容、同执行位只保存一份；新准备的原生Agent程序包在安装与版本核验后也通过原维护工作线程物化同一内容对象，不在HTTP主线程扫描安装树。运行版本路径、摘要和旧清单保持兼容，私有清单与运行契约文件不共享。已退出且没有当前、待采用或存活引用的保留版本，可在维护线程中转换为同内容视图而继续保留回退能力；仍被进程打开的版本延迟处理。对象没有视图硬链接、超过保留窗口、内容摘要及身份复查通过后才可回收。原生会话、来源引用、业务工作空间及可变 node_modules 不进入内容对象。

正常确认退出的旧后台由既有存储维护线程延迟回收，启动约五秒后首次观察，同类扫描至多每分钟一次；接口主线程不执行系统文件占用扫描。后台每分钟对账已闲置的可重建缓存，以及确认缺失和无回执的保留运行时（Runtime Unit）。诊断积压可以分批加速处理，但不提高正常退出版本的扫描频率。当前、待采用、存活或被系统进程打开的版本受保护；已使用不足一天的内容保留，另保留最近一份完整旧版本。超过保留期且内容完整、无实际引用的目录，可在退出确认缺失或无实例回执时回收。新增文件、内容修改、符号链接或观察失败形成保留理由；物化与回收使用同一窄存储锁。

受管程序包（`programs/<执行器>/` 下的版本包目录与遗留 `.prepare-*` 准备目录）由同一维护计划按真实引用回收：仍被连接绑定（含绑定数据与程序来源）、未完成更新记录的回退来源或待切换目标、当前策略默认安装位置引用，仍被进程打开，或未满一天稳定窗口的目录保留并报告原因；已完成的更新记录只是历史观察，不钉住旧包。引用观察失败保守保留受影响范围；全部引用解除后由后续周期自动回收，不要求人工清理，也不触碰账号配置、原生会话或非受管外部程序。实现见 [程序包引用与候选](../../../services/buildr-agent/src/storage/program-packages.ts)。

公开私有包入口提供 `inspectAgentStorage({ dataRoot })` 和 `collectAgentStorage(plan)`。前者默认零写入，返回每个对象的观察身份、大小、候选状态与原因；后者重新盘点，只处理原计划中仍符合条件且身份相同的对象。Linux/Windows 或权限不足无法取得完整进程文件观察时，维护保留内容并返回诊断。计划不能作为后续长期删除授权，也不能把目录大小当作 APFS 独占空间。

```js
import { inspectAgentStorage, collectAgentStorage } from '@buildr-ai/buildr-agent';
const plan = inspectAgentStorage({ dataRoot: profileDataRoot });
// 智能体核对具体候选和已有用户授权后，才调用执行能力。
const result = collectAgentStorage(plan);
```

实现入口：[连接存储生命周期](../../../services/buildr-agent/src/application/executor-storage.ts)、[维护计划与条件执行](../../../services/buildr-agent/src/application/storage-maintenance.ts)、[文件与系统占用](../../../services/buildr-agent/src/storage/files.ts)、[运行时回收](../../../services/buildr-agent/src/process/cleanup.ts)。本机具体清理结果属于维护操作证据，不写入长期产品知识。

## 账号与配置怎样接入

Qoder 的软件开发工具包（SDK）与执行程序按同一个安装包加载，核对包内声明版本；较新程序缺少配套库时拒绝局部接入。升级候选先完成隔离、无工具的真实对话，再持久切换程序绑定；失败关闭候选并恢复旧组合，保留原账号和会话。工作会话初始化已明确拒绝时记录未送达，已经提交而失去回执仍记录未知。

DSH 的目标自动续行按目标创建或显式修改时的请求归属，不能借用最近用户输入。新的明确输入先暂停旧目标自动续行，保留目标正文；历史回读按原生请求身份校正已有条目归属。重试回执建立独立显示轮次，迟到的旧答复归回原轮；界面不再常驻展示“保留原执行”提示。

“准备并连接”依次发现本机程序、选择准确来源、核对兼容性、准备独立配置，程序准备完成后不自动发起模型账号登录；用户在“模型”页按需登录并启用模型。多个可用来源需要选择；指定程序或原绑定程序缺失不静默回退。Codex 优先引导安装含 Codex 的官方 ChatGPT App，核验应用标识、官方签名和内附程序版本，也允许独立安装 CLI。DSH 准备固定官方 CLI；Qoder 优先解析 SDK 配套程序，缺少时准备固定配套版本，用户无需手动安装 SDK 或单独下载 App Server。

准备进度、来源、失败与取消在“智能体”页显示；切换厂家、关闭面板或刷新可继续查询准确尝试。服务重启后重新观察安装和账号，不把旧尝试当作仍在运行。安装只作用于本应用配置域 `agent-service/programs/`；失败及取消清理本次暂存和进程，保留既有程序、登录和会话。版本准入按主版本：Codex、DSH 接受 `0.x.x`，Qoder CLI 与 Antigravity CLI 接受 `1.x.x`（其中 Antigravity 声明 `managedOnly: true`，仅接受从 Google 官方发布清单下载并经 SHA-512 校验的受管独立二进制，拒绝外部非受管 `agy` 与原位二进制篡改），包含有效预发布版本与构建标记；符合版本范围仅允许继续连接验证，不代表协议必然兼容。下载版本仍固定，实际协议、账号、模型及所需能力检查决定是否可用。版本准入与固定会话绑定命名空间分开；同一程序来源及独立配置内的兼容更新保留账号、连接和原生会话，不因本次范围放宽改变既有指纹；来源或配置身份改变、范围外版本及实际协议失败提供局部诊断，不能改用另一程序冒充恢复。浏览器操作工具继续由智能体（Agent）按技能（Skill）检查和准备，不属于 Buildr 原生程序安装器。

首版每家一套 Buildr 独立配置，可服务多个工作空间（Workspace）。启用接入后检查程序与账号，用户通过官方登录页完成登录，再读取该账号的可用模型；连接成功、登录流程结束和模型实际执行成功是不同事实。没有从桌面复制令牌（Token）或默认配置，也不自动继承桌面插件、用户级技能（Skill）、工具连接或模型设置。

配置保存在本机网页运行配置（Profile）的 `dataRoot/agent-service/connections/<provider>/`；统一对话保存在同根的 `conversations.sqlite`，图片保存在 `attachments/`。这些是私有运行数据，不写入工作空间（Workspace）源资产或 Git。页面显示可用状态、非秘密账号摘要及配置路径，登录地址仅属于当前登录尝试；凭据由各家原生配置保存，不通过消息或诊断返回。断开保留账号、配置和对话，停止及退出只释放本接入拥有的执行资源，不能以“已断开”冒充执行已确认停止。

DSH 在对话中选择模型会改变这套独立配置的后续默认模型；因为配置独立，不改外部桌面的默认模型。统一模型套餐组件允许在本应用配置域中明确登录 Codex、Devin 和 DeepSeek 账号，也允许添加自定义供应商（BYOK），供三家原生智能体独立选择。模型供应商与原生程序准备分开，模型请求由本机认证网关转换协议，工具及权限仍由原生智能体负责。Qoder 消费外部套餐使用软件开发工具包（SDK）的逐次模型选择；其私有账号通过固定上游签名模型协议供出推理，工具仍留在所选执行方。

DeepSeek 的权益按账户余额观察，不按套餐限额推算。Buildr 通过 DSH 官方账号的 `getBalance` 只读能力取得充值与赠送钱包，同币种以精确十进制合计，不同币种分列；凭据仍由原生账号管理，不新增任意网络转发。余额读取失败不否定已发现的模型，保留可识别的旧观察，未知不等于零。右下角“智能体与模型设置”图标悬停或键盘聚焦会逐供应商显示所有已登录账号的余额或平台报告的周、日、小时等额度窗口；“模型”页的供应商卡片使用同一事实并保留观察时间与读取诊断。读取不到最新额度时浮层直接展示上次观察，不额外提示非实时，观察时间见各供应商行的悬停标题；只有供应商本身待确认时另行说明。浮层只读取共享观察，关闭后停止定时读取，点击仍打开原设置。

Codex、DSH 与 Qoder 都可使用 Devin 供应商的任一已启用模型：Codex 经本机网关把 responses 协议转换为 Devin 协议，Devin 供应商只对两个已知 Codex 命令工具的用途说明使用含义相同的表达，名称、参数说明和结果配对保留；默认权限区块仅将已知的 `justification` 审批问题单句作等义表达，示例、其他必要规则以及实际沙箱和审批策略保持不变。界面按模型可用性、启停与供应商状态重新校验，保留旧选择和草稿，不自动提高权限，也不用某一模型的拒绝或额度错误推断其他模型不可用；Qoder 只接受部分思考档位，无法表达的档位在发送时给出具体原因。Devin 供应商的 Codex 参与上下文同时绑定权限：改变权限后使用对应原生上下文，保留旧记录并按现有接续交付可见历史，避免把旧模式内部指令混入新模式；旧配置首次使用新绑定会创建对应上下文。DSH 可继续使用 Devin。声明接纳或额度错误不等于工具执行及完整回合已通过。

供应商的 `sourceEnabled` 只控制新选择与目录可见性，不等于登录状态 `enabled` 或断开账号。默认列表与模型目录排除已停用供应商，管理页可显式包含停用项并重新启用；凭据、身份和模型偏好保留，在途租约不被释放，新执行明确拒绝该供应商。DSH 网关传递真实有效窗口，但不把供应商的 `maxOutputTokens` 无条件映射为默认请求 `maxTokens`；请求默认、窗口适配与压缩由原生执行器负责，实际请求只受供应商报告的最大输出能力保护。

输入栏左侧呈现附件与权限，右侧依次为独立的智能体（Agent）、模型、思考档位和发送控件。切换执行方恢复该连接上次明确使用的模型；没有有效模型记忆时留空提示选择，不自动采用官方默认模型。切换模型或执行方后，选择器按当前供应商和档位恢复该模型仍支持的上次推理强度，没有可用记忆时继承默认值。选择只更新未发送配置，不因此开始执行。选择器保持一致行高、清晰正文色和白色背景，悬停与选中状态一致，菜单开合不改变输入栏高度；窄屏按完整控件换行，正常名称不省略。

对话选择具有软件级（Application-level）记忆，跨工作空间保存上次明确使用的智能体与模型选择器，不写入单个工作空间或对话服务。智能体与权限属于对话模块偏好；模型选择器偏好按智能体连接独立保存模型供应商、账号身份、模型和服务档位（Service Tier），并按执行方、供应商身份和模型分别记住明确选择的思考深度（Reasoning Effort）。生成提交说明继续使用独立的 `buildr.execution-model`，两者互不改写。最近智能体和模型的自动初始选择只用于新草稿；已有对话在主动切换模型时也可恢复该模型的强度。恢复前按当前接入、模型目录、供应商可用性和档位重新核对；失效供应商保留原记忆并提示重新选择，不自动采用官方默认模型或另一共享套餐。已有对话继续使用本轮运行记录或本对话明确选择，不因后来的软件级偏好被追溯改写；浏览器存储不可用也不阻止当前页面选择和发送。

模型目录同时保留实际默认模型、逐模型支持的思考深度（Reasoning Effort）及默认档位。输入栏仅显示该模型支持的选项；发送预览和本轮执行保留实际模型与档位，刷新后按执行记录恢复。切换模型或执行方不会沿用不兼容的旧档位。DSH 选型后重新观察原生目录并通知对话重新读取连接，避免界面仍把旧默认值当成当前事实。

输入区提供“默认权限／完全访问”。没有已保存选择的新草稿初始选择完全访问；用户在工作空间（Workspace）内明确选择过某种权限后，新草稿及刷新优先恢复该选择，切回默认权限不会清掉其他工作空间的记忆。旧单槽偏好兼容读取，旧全局默认选择仍有效。已有对话保留自身运行模式或准确选择，旧轮次缺失模式仍按默认权限解释。换家后分别应用各家的原生设置；权限只影响后续执行，不自动回答业务问题或批准未知交互。发送预览及实际本轮保存模式，恢复时每轮重新应用，避免完全访问残留到后来的默认执行。只支持默认模式的接入不能静默接受完全访问。

| 执行方 | 默认权限 | 完全访问 |
| --- | --- | --- |
| Codex | Buildr 明确使用 `on-request` 与 `workspace-write` | 原生 `never` 与 `danger-full-access` |
| DSH | 原生权限预设目录给出的默认值 | 原生 `/permission danger-full-access`，读取会话权限快照确认 |
| Qoder | 软件开发工具包（SDK）的 `default` | 原生 `bypassPermissions` 与 `allowDangerouslySkipPermissions` |
| Claude Code | Agent SDK 默认审批，逐次回调用户确认 | 原生 `bypassPermissions`（`allowDangerouslySkipPermissions`） |
| Antigravity | 原生 `default` 模式，经 ACP `session/request_permission` 单次确认（不提供持久授权选项） | 对话进程启动参数 `--dangerously-skip-permissions`（不写入持久会话；切回默认重建进程，业务提问仍走 `elicitation/create` 等待回答） |

这些名称不代表三家的操作系统隔离能力相同，也不改变外部桌面配置、旧一次生成策略或辅助标题的受限执行。单个活动工具只有具备准确原生停止身份时才提供单独停止；不支持时保留活动事实和观察入口，不能把局部停止失败标成整轮已经停止。

## 怎样创建、执行和恢复对话

全局“对话”入口在任意页面可用，默认停靠右侧，历史也在对话区域查看。新对话可以不选工作空间（Workspace），此时使用稳定的 `~/.buildr/default-workspace/` 默认目录（共享数据根显式覆盖时随其解析；预览及测试使用隔离应用根下同名目录）；也可以在开始前选择、更换或取消业务工作空间（Workspace）。选择不跟随左侧页面变化。对话一旦创建，所属工作空间（Workspace）和起始目录（Working Directory）不再更改；历史消息在对话区域独立滚动。任务页的“关联对话”始终先展示数量浮层，选择已关联对象才打开；新对话动作进入带该任务身份的草稿，首次发送才创建并保存完整引用。打开或选择不发送指令；关联任务不会替代原生目录或自动修改任务状态。

桌面不再保留重复的顶部对话按钮，侧边气泡负责当前对话、列表图标负责对话列表：点击打开或切换到目标视图，再次点击收起。列表图标只显示一个静态数字：待决策与待查看合计大于零时显示暖色待处理数，否则显示绿色确定执行数，两者均为零而仍有未受理提交时显示其活动数，否则隐藏。可访问说明保留两类准确数量，未知执行独立提示，不冒充待处理或执行中。数量从完整空间范围汇总，不由已加载的一页推算。有效未回应问题（含非阻塞提问）都计入待决策；仍在执行时同时显示“待决策 · 执行中”，待决策与执行数分别统计，活动总数去重。列表再次打开沿用当前结果和加载更多窗口，真实消息或交互事实变化后刷新，只有手动折叠空间再展开才恢复五条。列表和提醒同优先级按最近用户输入或有效问题答复排序，助手输出、工具日志、刷新、改名和查看不改变排序时间；助手消息仍更新未查看与活动事实。提醒浮窗按待处理、执行中分组，再按工作空间组织，按既有筛选独立分页；不再显示分类按钮和重复的维度统计；顶部保留一小块按真实智能体（Agent）与模型（Model）组合的执行中摘要，数据来自完整范围聚合，不由当前一页猜测。完整对话列表移除常驻分类统计栏与未知执行提示条，保留执行分布筛选（“执行中模型”摘要）、空间范围、搜索与分页；搜索只匹配标题与用户/助手可见消息，按空白词项 AND，命中消息显示有界片段，工具、通知、handoff 与 thinking 不参与命中；输入防抖后读取，旧结果不覆盖当前范围；完整列表的模型统计项可点击切换筛选，再次点击或清除恢复；执行统计独立于关键词与统计筛选。未知执行由条目“状态待确认”徽标与入口说明表达。悬停或筛选不确认消息已查看，只有可见最新正文确认准确查看位置。桌面收起后保留对话图标，悬停可临时操作同一对话，点击才固定展开；展示切换保留草稿、记录及执行，收起按钮放在标题栏右侧。手机通过全局按钮恢复。二级导航收起时，一级图标悬停预览，鼠标点击不跳页，浮层内展开才固定对应组；固定后不再生成悬停浮层，点击一级图标直接切换固定组，重复选择当前组保持展开，仍用原按钮收起。键盘和触屏也可在固定态切组。预览或固定组使用原选中底色，不跟随浏览路由，也不改变已打开的工作页签。导航浮层保持工作区全高。固定导航、对话和原工作双屏使用同款分隔手柄及标题栏标记。对话停靠宽度为320–800px，正文和输入使用面板宽度；底部执行者、模型及档位完整显示并可换行，账号与配置归入对话内部。

已提交未受理的指令从已有待发送记录派生“等待发送”或“发送失败”，均纳入活动对话总数。投递中仍为等待发送，受理后回到原执行状态；两者逐条展示具体原因，取消沿用准确对话中的既有版本及可取消性。待发送本身不增加执行中模型或待决策，已有真实执行和问题仍独立计数；活动摘要只传状态、原因及时间，不传未发送正文。

对话标题用于定位主题。用户输入被执行方受理后，系统立即用首条用户消息的规范化截取生成兜底标题，并明确标记来源，不冒充智能摘要；同时并行发起一次独立的、无工具的、约 10 秒的模型请求尝试智能标题，不等待首个轮次完成。智能标题返回后替换兜底标题，即使首轮仍在执行。Qoder 与 Qoder-CN 原生账号走既有原生 `/chat` 模型通道（Qoder-CN 有网关租约时保留网关路径），不复用或写入工作原生会话，也不向工作上下文塞入起名指令；Codex 与 DSH 保持各自独立通道。每段对话只自动尝试一次，后续消息、刷新和重启不再重复发起；失败保留兜底标题并在状态中记录脱敏原因，不再回填「生成标题错误，请手动修改」。手动名称始终优先，迟到的自动结果不覆盖。对没有可靠来源标记的旧标题不批量猜测覆盖，用户可在更多菜单对当前对话明确“生成简短标题”；当前执行方不能提供摘要时显示局部原因。

起始目录是规则（Rule）、技能（Skill）发现及执行的起点，不是禁止跨目录的沙箱（Sandbox）。执行者依据原生权限与用户授权访问其他目录；Buildr 不把当前页面、所选对象或整个任务正文静默注入每条指令。实际执行始终重新核对文件、资料及当前现场。

发送前核对对话版本、接入、模型、工作位置和实际交付内容；受理后立即记录本轮执行，流式展示回答、工具摘要、原生问题和授权请求。模型供应商按当前账号观察重新核对身份、可用性、模型启停、档位、思考深度和执行方兼容性，调用方携带的旧账号修订不单独构成失败条件。界面对 409 按错误码分类：只有预览过期、对话修订冲突或模型供应商失效等需要重读的情况刷新当前事实；执行忙碌、权限不支持和真实不兼容直接显示服务端原因，并保留草稿。停止与答复走独立控制入口，不等待模型整轮结束。主停止通过 `stop-all` 覆盖准确对话受理时的当前轮、保留轮、所属派生工作及追加队列，并取消已提交待发送与自动续行，未提交草稿和其他对话保持。停止请求使用稳定身份；后台保存冻结范围，跨代次分发精确单轮控制，页面关闭后仍由原持有者处理。Qoder CN 的追加队列不能由单条取消原子清空时，按独占控制归属终止其受管资源；单条取消无效则在有限等待后升级终止并核对退出。精确单轮和单工具仍使用原 `stop`，不隐式扩大范围。停止时区分模型中断、仍有命令运行、已确认停止和状态未知；控制资源退出不冒充独立执行工具的终态，无完成回执的副作用继续保持未知；工具摘要超长时明确标记截断，完整内容仍在准确原生历史中。

重新打开先读 Buildr 统一历史，再对各参与者按原程序、独立配置、起始目录和原生上下文身份恢复。页面刷新或宿主（Host）重启不会自动重发原指令，也不重放旧授权；无法确认是否受理或执行是否结束时保留“待确认”（`unknown`），重新观察原执行。已完成和已停止的持久事实不因失去活跃连接被改写为未完成。

浏览器验证工具由智能体按[接入环境说明](../../../services/buildr/resources/runtime/skills/buildr/references/agent-operations.md#内部对话与持续执行)发现和准备。账号 `HOME` 保持独立，`BUILDR_HOST_HOME` 提供原用户路径线索；`PLAYWRIGHT_BROWSERS_PATH` 保留明确覆盖或解析到原用户的官方默认缓存，允许三家复用已有浏览器。Buildr 不新增工具管理平台或统一安装目录。关于接入、自研与职责分层，见[责任边界](agent-boundaries.md)。

## 同一对话怎样切换执行方

历史按对话组织，消息标明参与者，不按 Agent 厂商分组。当前交互与保留执行分别维护：所有执行方的问题卡片回答继续准确原轮，输入框提交新指令始终开启新轮，不自动追加当前轮。独立新轮原生确认受理后才结束旧问题等待并保留未回答事实；适配器声明支持纯问题释放、同组合且没有活动工具时，才在准确等待释放后复用原生会话。原生不支持时由服务先隔离新轮，再核对旧等待并安全释放。停止未知或有活动工具时保留原控制；旧操作不因新输入被批准、覆盖或重发。

首次选择另一家时，为其建立准确的原生上下文（Context）。Buildr 从本地原始记录按轮次组织用户输入、助手说明、动作结果与位置、能确认的成果及最后答复，附上工作目录、来源范围和本次要求。问题答复仍属于原执行轮次；逐轮终态和失败诊断持续保留，不被后续成功覆盖。多次交接不会把上一次交接包再嵌套进去。换回已有参与者时，恢复其原上下文（Context），只补尚未收到的记录；隐藏推理及厂家私有压缩格式不相互迁移，历史操作与一次性许可也不重放。

日常消息直接提交，由后端在同一次受理内校验身份、版本、权限、容量及请求去重，不强制先请求交接预览；用户主动查看交接内容时仍可获取准确预览，携带旧预览令牌提交仍须核对其版本。原生上下文可复用且没有待补历史时，仅发送新要求、附件及必要控制信息，不生成历史来源文件。交接由 Buildr 直接组织，材料超过接入字节限制或模型上下文的保守预算时直接提供轻量轮次目录与分页历史入口，内部索引由系统解析；发送与预览均不等待辅助模型摘要，也不新增后台摘要调度。文件、脚本和日志正文不重复塞进请求；历史图片保留准确本地引用，当前新增图片仍校验真实接收能力。必要资料或当前图片仍无法安全交付时说明限制、保留草稿并允许选择其他模型（Model），无需用户手写总结。

界面只提示实际改变的智能体（Agent）和模型（Model），交接详情从对话所在一侧展开。轮次使用紧凑列表，“完整交接内容”默认收起；原文框内是实际提交的文字，页面说明在框外。接收待确认、未接收和已接收分别展示；已提交的正文快照保持不变，接收状态按当前事实更新。正常发送不再强制二次确认交接清单。

相同智能体（Agent）、供应商账号、模型（Model）、档位、推理强度与权限组合内部重建上下文（Context）时，继续组织原始记录和当前成果来源，不生成用户交接事件。已受理的无组合变化旧交接条目也不显示“交接内容”；实际组合变化仍保留接收状态与详情。用户从输入框发送新指令（包括同一智能体和模型）后，Buildr先保存固定参与者和问题接续计划，独立新轮原生受理后才关闭旧卡片，再由准确原后台释放纯问题等待。活动工具或后台任务不被整轮停止。支持原生纯问题释放的同会话路径在发送前释放等待；后续启动失败时保留不可回滚事实，不事后改写本轮归属。卡片回答只提交原轮，不随输入框模型选择自动交接。升级启动时，同样依据历史中已受理、确有组合变化且匹配投递身份的交接记录，回补存量旧轮的替代关系并结束过期问题等待；升级回补不把历史普通补充、未投递预览和无组合变化的内部重建推定为切换；新语义只在新轮实际受理时建立替代关系，不重放存量消息。当前执行及其原归属保持不变，已请求停止的旧轮只观察，不重复停止。页面和本机控制读取由当前后台投射共享记录，避免旧后台重新呈现过期交互。未回答仍为未回答，迟到问题事件或观察快照不能重新激活旧卡片。新要求不等待停止确认；旧执行、工具及未知操作结果保留真实历史，默认不再显示旧轮核对入口或反复追加内部善后说明。只有实际影响当前目标且需要用户决定时，才说明具体影响。单独选择、查看交接及取消尚未投递的新要求不触发上述善后，仍有效的原问题和有意保留的独立工作保持原归属。准确控制资源已释放且没有活动或未知工具、待决定的其他旧轮也只留在历史中；未被确认切换替代且仍有未知工具或问题的旧轮继续提供核对入口。工具过程在归入准确轮次及用户补充分段后重新合组，其他执行的插入不切碎本段摘要，实时指示只属于当前最新组。未回答问题只保护依赖该回答的动作；准确等待结束后不追加技术性存档消息，内部事实、有效问题和明确用户回答继续保留。

DSH 和 Qoder 的普通问题支持“其他”自定义回复，多选可同时提交固定选项及自定义文字；旧记录遗漏这项能力声明时按原生已支持的能力兼容，明确关闭的声明不被覆盖。Codex 保留原生声明的自定义能力。自定义回答仍须明确提交，空回答不可提交，工具审批不扩展为自由回答。

图片可通过文件选择、粘贴截图或拖放加入输入区，发送前提供缩略图、放大预览与移除。沿用 PNG、JPEG、WebP、GIF、每次最多4张及单张8 MiB边界，校验失败保留文字和已添加材料；发送后的图片通过当前对话的认证读取接口按需加载，刷新后仍可查看，不把本机路径或认证令牌放进图片网址。

Codex 使用原生本地图片输入；Qoder 在软件开发工具包（SDK）的用户消息中发送带媒体类型的 Base64 图片块；DSH 使用原生提示内容（Prompt Content）的图片分支；Antigravity 在 ACP `session/prompt` 中发送内联 Base64 图片块。图片字节随明确发送动作交付，具体模型的视觉能力仍以厂家实际响应为准；执行端支持图片不等于所有模型均已通过识图验证。

模型与推理强度共用紧凑入口，智能体（Agent）保持独立选择。浮层只提供当前供应商和服务档位支持的实际强度；切换模型恢复该模型上次明确选择且仍可用的强度，否则使用默认值，不发送失效强度；不把普通闪电图标当作加速模式能力。桌面对话默认宽度620像素，与账号配置抽屉一致，拖动下限560像素，底部权限和执行选择保持同一行；旧的窄宽度偏好在读取时修正，移动端沿用全屏适配。

## 为图形与对话交互留下什么基础

图形界面（GUI）和对话界面（Talk UI）共享工作空间（Workspace）、任务（Task）及实际成果身份；对话只保存交流和执行观察，不成为代码、文档或任务状态的唯一权威。首版将工作位置、任务关联、发送预览、观察版本与独立控制留在公开契约中；未来业务现场接入应传明确对象身份和已观察版本，由原业务能力保护写入，不能把页面焦点或历史消息当作写入许可。

## 单次生成与任务关联

提交说明从现有模型（Model）目录明确选择账号和模型，经过统一模型能力执行，不创建持久对话，不提供工具。业务负责有界材料、输出结构、任务尾注和来源版本检查；取消、超时或供应商变化保留草稿。实现见[提交说明怎样生成](agent-integration-generation.md)。

内部对话与任务（Task）保持多对多关系，普通咨询仍无需任务。一段对话可关联多个已登记工作空间的任务，一个任务可有来自不同空间的多段内部对话；引用以工作空间身份与任务编码共同确定。关系只在对话记录的 `taskLinks` 保存，任务侧反查同一份关系，不维护副本；旧 `taskIds/taskId` 只投影对话所属空间的部分，旧数据按原空间解释，旧字段写入保留异空间引用。两端入口按准确身份打开，不按最近活动猜目标，也不改变对话执行目录。

正常工作不要求人手动补关联。智能体在当前准确绑定的内部对话中创建、激活或明确接续本轮实际执行任务后，按[任务技能](../../../services/buildr/resources/workspace/skills/buildr/task-manager/SKILL.md)维护关联。仅提及、只读查询或浏览其他任务不自动关联；外部会话缺少准确内部绑定时不猜关系。

[本机对话控制命令](../../../services/buildr-agent/src/process/conversation-control.ts)的 `read` 返回当前 `revision`、完整 `taskLinks` 及旧字段；`link-task` 接收准确 `taskId`，可选 `workspaceId` 指定任务空间，未提供时使用当前对话空间，在同次调用内读取当前集合并使用该观察版本通过原有对话更新接口追加关系，复用宿主任务校验与版本事务；可选 `expectedRevision` 可钉住调用方明确观察，避免跨工具调用的执行更新让关联动作反复使用过期版本。关系元数据由当前后台处理，不交回仍持有原生执行的旧后台；旧执行继续结束时保留新关联。其他任务关联保持，重复追加不写入；冲突后重读判断，响应未知先读回，不重放。该命令不启动后台、不发送消息，也不修改任务状态或执行目录。任务登记与关系保存独立，关联失败保留已成立任务，不能冒充已关联。

对话底部“关联任务”和任务详情“关联对话”只常驻图标与数量；悬停向上展开，点击固定，键盘与触屏可用。浮层显示已关联对象、来源空间及准确标识，点击对象导航，独立按钮解除；搜索按完整名称或标识精确匹配可访问空间的必要分页，不自动建立关系。新增和解除后保持浮层打开；零项显示0，读取失败不冒充零。手动关联只用于补充或纠正，可逐项添加、解除引用。关联用于查找和接续，不等于已授权执行所有任务；任务进展、验证和完成继续依据当前成果。以上描述对应本仓库实现，安装环境是否采用仍以实际交付和激活为准。

外部桌面关联、旧登记、桌面生成和会话导航接口已经删除。正式应用启动时清理当前配置及已登记工作空间中的固定旧文件，不迁移、不备份关系历史；开发预览不触碰真实数据。清理遇到链接、写入锁或异常文件时局部报告，其他功能可继续使用。外部桌面聊天、账号、新模型配置与内部对话不在清理范围内。

## 统一模型套餐

实现位于 `services/buildr-agent/src/model-access/`，作为私有库随主包捆绑交付；不是新增公开 npm 包。账号元数据和模型观察保存在本应用 `agent-service/model-access/`，厂商凭据由其唯一提供者管理。Devin及按需添加的额外账号明确发起独立浏览器登录；原生账号直接复用已有登录。DeepSeek 由私有 DSH 宿主账号服务持有凭据，通过固定目的地的认证桥接委托模型请求，不向网页或网关消费者导出凭据。

公共模型入口由宿主的 `/api/v1/app/agent-service/model-accounts` 与 `/model-catalog` 管理，沿用本机认证与写入校验；执行方只取得绑定账号、模型、对话和执行方的本机访问凭据。三个模型协议入口只在回环地址监听，不以系统代理环境变量代替套餐连接。

“添加供应商”列表由 Agent Service 的供应商声明生成，覆盖内置 API Key 来源、独立订阅登录来源、linked 共享账号和自定义供应商；已接入的非自定义供应商显示为已接入并禁止重复添加，自定义供应商可添加多个端点。由 Codex、DSH、Qoder 智能体连接托管登录的来源在列表中标明归属，其登录继续在“智能体”页管理，模型页不创建第二份登录。供应商侧栏支持按名称、账号标签或自定义端点搜索，并按订阅账号、API Key、自定义供应商、智能体接入分组；搜索只影响呈现，不改变所选供应商和模型偏好。拥有独立本机凭据的供应商可从卡片操作菜单删除：确认层列出将清理的登录凭据或 API Key、模型列表与启用偏好，并读取仍以该供应商作为当前模型来源的对话数量；确认后按 `expectedRevision` 校验，拒绝仍有活动模型请求的账号和智能体托管账号，停止登录尝试、关闭运行时、撤销该账号租约并删除账号私有凭据目录。删除不删除或隐藏任何对话；仍引用该供应商的对话在下次发送时提示重新选择模型。linked 供应商删除后保存抑制标记，后台自动发现不会重建空账号；用户再次通过“添加供应商”接入时清除标记。删除只清理 Buildr 本机数据，不删除服务商侧账号、订阅或远端密钥；Qoder CN 的共享登录被删除后，对应智能体连接显示未登录。托管来源的“退出登录”经确认后断开对应智能体连接、关闭运行时并撤销租约，对话与服务商账号保留。读取旧账号存储时，单账号内置供应商的历史重复账号按可用状态与模型、凭据完整度保留一项，其余账号及私有凭据目录被清理，避免列表长期保留无法再新增的旧卡片。

跨协议工具响应按稳定调用身份核对参数增量与完整回执；完整事件可补齐缺失后缀，重复快照不重复拼接，冲突明确失败。名称分片与并行调用分别累积，完整工具校验后再向下游交付，缓冲有界；同协议响应保持原样。DSH 使用 GPT 时沿 Responses 同协议通道，Qoder 使用 GPT 时经过 Responses 与 Chat Completions 转换；一种组合通过不代表其他供应商、图片和子任务组合已获真实验收。

每轮保存 `modelAccountId` 和供应商摘要。跨供应商或模型的原生状态不能通用时，仍在同一可见对话中保留不同参与绑定，并交付尚未见到的可见历史。旧原生模式和已有对话保留；断开、刷新和未知执行都不自动重发。额度不可读按未知显示，不根据静态模型列表或估算用量推断剩余套餐。

每个模型账号独立维护选择修订（Revision）。只有身份、启停、状态、账号标签、模型目录或影响模型选择的偏好发生实质变化时才更新该账号修订；模型与档位按稳定标识比较，额度、观测时间、诊断文本和返回顺序变化不更新修订。检查一个账号不更新其他账号，因此使用 Qoder 的对话不会因 Devin 的刷新或配置变化出现假冲突。发送以当前账号快照重新计算预览和本机绑定，只有供应商身份变化、模型移除或停用、能力或权限不兼容等真实失效才拒绝。

### ChatGPT 订阅与官方 API Key

ChatGPT 订阅与 `ChatGPT API` 是两个独立供应商，可同时启用：Codex 订阅账号继续使用原生登录与续期；`ChatGPT API` 供应商使用独立账号、凭据目录、模型目录和租约，不读取或替换 Codex 桌面凭据。账号设置分别显示订阅卡片与 `ChatGPT API` 卡片；模型选择器分别显示 `ChatGPT` 分类与独立的 `ChatGPT API` 分类，执行智能体仍显示为 `Codex`，不把执行者名称当作供应商名称。DSH 与 DeepSeek 同样分开表达：DSH 是执行智能体，DSH 接入的 DeepSeek 账号在模型侧显示为 `DeepSeek`。不提供要求停用另一供应商的互斥模式开关。API Key 供应商不表达套餐权益或订阅额度，任一供应商失败不影响另一供应商。

内置的 `ChatGPT API` 供应商只接收密钥，不提供 URL 输入，固定访问 OpenAI 官方 API `https://api.openai.com/v1`；需要自定义地址时应添加自定义供应商，不改写内置官方端点。它通过 `GET /models` 核对密钥并发现文本对话模型，通过 `POST /responses` 完成推理。目录过滤嵌入、语音、转写、图片生成、审核、实时音视频、`gpt-live-*` 与搜索专用模型。官方模型列表只返回 id 等基础字段；Buildr 按 OpenAI 官方模型页补充已知模型的显示名、图片输入、工具、上下文窗口、最大输出和推理档位，带日期快照按基础模型归一，底层调用 id 保持原值。无法从官方来源确认的模型保持保守表达，不按名称或订阅状态猜测权益。官方 API 不提供剩余余额读取，账号卡片显示额度未知并指向 OpenAI 平台用量与账单；`/v1/usage` 只表示按日用量，不作为余额。

密钥保存在账号私有目录的 `model-api-key.json`，文件权限为 `0600`，账号公共元数据、普通读取和宿主响应都不包含密钥原文。配置候选密钥时先读取官方模型目录，验证成功后才原子替换旧密钥；失败保留旧密钥与已有可用状态。账号身份由密钥的不可逆摘要派生，替换密钥会撤销该账号的旧本机租约。推理请求使用 `store: false` 与 `reasoning.encrypted_content` 支持无状态多轮推理；执行方仍通过统一本机网关取得绑定模型、流式响应、工具调用、取消和跨协议转换。

### 自定义供应商（BYOK）

“模型”页可添加用户声明的自定义供应商：填写供应商名称、API 协议、Base URL，可选使用 API Key，并在供应商卡片中启用或停用、编辑配置或断开。API 协议支持 OpenAI 兼容 Chat Completions、OpenAI Responses、Anthropic Messages 与 Gemini；协议随账号保存，编辑时回填，新增、编辑与模型发现都按当前选择传递。Base URL 必须是 HTTP 或 HTTPS 绝对地址，不能包含用户名、密码、查询参数或片段；内置供应商仍固定访问各自官方端点，用户声明的地址只属于对应自定义供应商。获取模型列表通过 `GET <Base URL>/models` 读取候选：OpenAI 兼容与 Responses 使用 Bearer；Anthropic Messages 附加 `anthropic-version: 2023-06-01` 与 `x-api-key`，按 `has_more`/`last_id` 有界分页；Gemini 使用 `x-goog-api-key`，按 `nextPageToken` 有界分页，只保留支持 `generateContent` 的模型并去掉 `models/` 前缀。端点未提供列表时提示手动添加；候选加入、手动添加和编辑都按模型 id 合并，目录由用户维护，再次发现不会清空已配置模型。自定义目录中的模型默认停用，启用、上下文窗口等偏好在账号内按稳定模型 id 保留。

自定义供应商与内置供应商共用账号元数据、模型目录、租约和本机网关。API Key 只保存在账号私有目录的 `model-api-key.json`，文件权限为 `0600`；公共元数据、宿主响应、事件、诊断与日志都不包含密钥原文，未使用 API Key 时按匿名端点接入。账号身份由 `custom:<协议>:<Base URL>:<密钥摘要|anonymous>` 派生，修改地址、协议或密钥会撤销该账号已有的本机租约。推理经统一本机网关转发到所选协议端点：Chat Completions 使用 `<Base URL>/chat/completions`，Responses 使用 `<Base URL>/responses`，两者按配置携带 `Authorization: Bearer`；Anthropic Messages 使用 `<Base URL>/messages`，携带 `anthropic-version`、`x-api-key` 与 Bearer；Gemini 使用 `<Base URL>/models/<模型 ID>:generateContent` 或 `:streamGenerateContent?alt=sse`，携带 `x-goog-api-key`。上游请求拒绝重定向；执行方只取得本机网关地址与短期令牌，不接触自定义地址或上游密钥。Gemini 只作为自定义供应商的上游协议，不作为执行方入口：请求转换为 `contents`/`parts`/`systemInstruction`/`functionDeclarations`/`generationConfig`，响应的文本、`thought` 推理分片、函数调用、用量与结束原因转回统一事件；远程图片地址不能直接作为 Gemini 输入，工具结果只支持文本。自定义端点没有额度接口，模型卡片显示额度未知，模型仍可正常使用；未知不等于零或已耗尽。端点可达与模型目录发现只属于配置检查，不证明模型实际推理、图片或工具调用已通过。

### 复用原生账号

Buildr自动将已连接的Codex、DSH、Qoder账号发现为共享模型供应商。登录与续期仍由对应原生运行实例负责；Codex通过app-server取得有效凭据，DSH同一宿主装配固定上游桥，Qoder只读该Buildr私有配置的账号，使用签名模型协议传递工具定义及结果。账号身份变化或断开撤销旧供应商；旧独立套餐和会话保留为额外账号。Qoder套餐模型可由Codex、DSH消费，工具仍由所选执行方执行。

### 独立 Google AI 订阅模型来源

[Google AI 供应商](../../../services/buildr-agent/src/model-access/providers/google-ai-proxy.ts) 由 Agent Service 启动和关闭本机代理。模型账号复用该配置域中已有的 OAuth 登录，按模型选择代理协议，通过现有模型网关供兼容 Harness 使用。模型目录和 Gemini、Claude / GPT 的额度窗口归属于同一个供应商，四个窗口取自同一次 daily 响应。


### Google 个人账号与 Antigravity 协调

[Google 个人账号来源](../../../services/buildr-agent/src/model-access/providers/antigravity.ts)（`native-antigravity`）由 [Antigravity 执行器](../../../services/buildr-agent/src/executors/antigravity/index.ts)托管登录（`oauth-personal`），支持免费账号、Google AI Pro 与 Google AI Ultra。当受管 `agy` 确认 `oauth-personal` 已登录、绑定身份可建立且模型目录非空时，来源状态为 `ready`；原生 `_meta.antigravity.tier` 可识别时展示对应档位，不可识别时展示“档位不可读”但仍可使用；模型目录为空或认证归属不可确认时进入 `failed`（“身份不可确认”或无可用模型）并在发送前拒绝。官方 ACP 未公开额度窗口时如实显示不可读并链接到 Antigravity CLI 的官方 `/usage` 用量说明，不按档位或模型名称推算剩余配额。

OAuth 令牌仅保存在系统密钥环 `jetski-standalone-oauth-token`（与本机终端 `agy` 共享，与桌面 IDE 分离），Buildr 不直接读取、写入或删除系统密钥环条目；来源声明 `sharing: executor-exclusive(['antigravity'])` 与 `inference: 'none'`，其他执行方显示不可选原因并拒绝签发网关租约，单次生成与提交说明自动排除该来源。发起登录时，短命登录子进程经专用 `PATH` 打开器替身捕获官方 PKCE 授权地址，地址仅在 `waiting-browser` 期间经 `LoginAttemptView.url` 返回，完成、取消、过期或被替代后清除，日志脱敏且不进入对话事件。

每轮输入前，执行方通过协调者被动探针（设置 `SSH_CONNECTION=1` 阻止未登录时拉起浏览器）核对当前认证与绑定身份：当 `agy` 返回显式账号字段时采用不可逆摘要 `agy-account:<sha256>` 比对；因 `agy` `1.5.8` 未在 ACP 公开邮箱或用户标识，无显式账号字段时由协调者在连接私有目录维护登录世代 `agy-epoch:<uuid>`，在退出、切换或观察到未登录/过期时轮换并拒绝旧对话在新账号下继续执行。模型页提供“停用供应商”“切换账号”与“退出登录”：停用只更新 `sourceEnabled: false`，保留密钥环登录；退出与切换先列出运行中对话并说明本机终端 `agy` 影响，再将连接级发送闸门（`sendGate`）置为暂停（暂停期间新发送直接拒绝并保留草稿，不进入待发送队列），统一停止运行中轮次（任一轮次缺少已停止证据则中止操作并恢复闸门），关闭全部对话进程后执行原生 `logout`。若 `logout` 超时或结果未知，系统重新被动观察认证状态：已未登录则清除世代并断开；仍已登录但无法证明仍为原账号时保持闸门暂停并提供重试或重新核对。新建与恢复会话通过 `_meta.antigravity.systemPrompt.append` 注入当前交互政策；当版本未声明恢复更新能力且政策摘要变化时，发送前明确提示“本轮将开启新的 Antigravity 会话”并保留既有对话历史。

### 模型额度与使用偏好

“智能体与模型”分为“智能体”和“模型”：前者仅管理程序接入与检查；后者在同一账号卡片完成登录和额度查看，按上游实际返回的日、周等窗口保留剩余比例、重置时间和观察时间。额度读取失败保留带旧时间的已知窗口并明确过期观察；平台没有返回时显示未知，不据此拒绝可用模型。Qoder 的套餐额度与 `addOnQuota` 资源包分别展示，平台返回剩余与总量时同时显示剩余 credits 数量，账号级剩余比例按可用额度总量计算，资源包仍有余额时不会因套餐为 0% 判为耗尽；`/usage` 的 `dedicatedResourcePackages` 中每个 `available` 为 `true` 的资源包也生成独立窗口，名称优先取 `displayLabels` 的 `title.valueI18n['zh-CN']`（其次 `value`，缺失回退“千问专属积分”），显示该包的剩余与总量及到期时间；专属积分只在对应模型系列内抵扣，不计入账号级剩余比例或耗尽判断。`/models` 的 `chat` 与 `app` 分组按 key 合并并优先 `chat` 配置，因此只出现在 `app` 分组的 `QoDuck` 也进入目录。右下角供应商额度浮层按供应商显示名称稳定排序，同一供应商内按账号名排序，与“模型”页的供应商顺序一致。

上下文窗口以K显示（1K=1000词元），内部保存整数词元。模型启用和上下文窗口保存在本应用配置域的独立偏好中，按账号与稳定模型标识保留；目录刷新不覆盖用户选择，新发现模型默认停用。迁移既有普通模型保留启用意图，组合模式默认关闭。上下文覆盖可恢复默认，不能超过已知平台报告上限，实际执行再按选定服务档位的上限取有效值。偏好写入通过 `/model-accounts/:accountId/preferences` 携带 `expectedRevision`，冲突必须重新读取，不手写账号存储。

Devin 的模型系列、思考强度及服务档位通过明确配置映射归并，组合模式单独搜索、分页和启停；缺少可归并信息的条目保持独立，不编造支持组合。每轮记录 `serviceTier`，租约身份包含有效上下文及档位；配置变化创建对应原生上下文，停用拒绝新执行，已经接受的当前调用继续。断开模型账号只撤销该供应商的本机租约，保留原生程序与已有登录，其他套餐仍可使用。

Codex 按上游目录的 `service_tiers` 与 `additional_speed_tiers` 发现可用速度档位，快速模式（Fast Mode）对应响应请求的 `service_tier: "priority"`，标准档位清除此请求字段；没有报告支持就不提供可切换选项，不按模型名称猜测，也不写死费用倍率。切换档位显式绑定准确模型账号，保留目标档位支持的思考深度（Reasoning Effort），不自动发送或修改外部桌面配置。

配置不提供默认模型搭配。对话切换智能体时优先选择其已配置、启用且可用的官方供应商模型，仍允许手动选择其他供应商；官方供应商不可用时不自动消费其他套餐。跨工作空间的新对话恢复上次模型选择器偏好，但仍按当前目录重新观察，已有对话保留自己的实际模型。模型元数据读取先返回已有观察，后台并发检查；手工刷新各供应商独立反馈。Qoder使用其他供应商模型仍需其厂家基础平台登录，该授权要求不等同于必须购买Qoder套餐。

上下文窗口使用单个输入框，支持整数或K后缀，按千截断显示，不因显示截断自动保存；清空恢复平台值。程序详情在对应智能体卡片内展开，模型名居中，悬停或聚焦时呈现选择状态。

### 上下文窗口观察与用量

模型页使用供应商模型目录的窗口观察：Codex读取`/codex/models`的`context_window`默认值与`max_context_window`最大值，DeepSeek读取`/models`的`context_window`，Qoder读取平台`/models`配置的`context_config`默认值和全部可选窗口范围，Devin读取`GetCliModelConfigs`的模型与档位配置。该值表示当前供应商可用窗口，不声称是模型理论能力。模型目录观察缓存于本机模型账号元数据，手动设置另存偏好；显示值按千截断，未编辑不自动保存截断值。恢复默认移除手动覆盖，回到供应商报告值。档位容量与用户配置共同决定生效值。

程序检查仅核验程序与独立配置，不等待账号或在线模型目录。账号观察及模型刷新仍由模型页负责，使用Qoder其他供应商模型时仍遵守厂家基础登录要求。

对话模型名前提供上下文用量入口。Codex的`thread/tokenUsage/updated`以`last.totalTokens`记录最近上下文观察，不能使用累计计费`total`冒充占用。同一对话页面保留最近一次真实报告及原模型、账号与窗口口径：新一轮尚未报告或选择下一轮模型时继续展示该观察并标明观察来源，不把旧用量除以新选择窗口；新报告（包括合法零值）到达后整体替换。报告缺窗口时只用同一真实供应商同档位的目录窗口补足，无法确认则不显示百分比；不同工作空间与对话不沿用，新对话明确尚未收到报告。

服务重启或执行观察中断后的恢复以准确的被中断执行（Run）为范围，不扫描任务的进行中状态。开发与正式运行配置（Profile）都自动核对原生执行：仍运行则恢复观察，已完成则补齐结果；确认停止且工具全部结束，或准确原控制资源已释放且没有活动工具、必要用户决定和该对话在途工作时，按原智能体（Agent）、模型供应商、模型（Model）、档位、推理强度、权限及工作目录接续原目标。控制资源释放不证明独立操作已结束；原轮与未知结果继续保留。接续先读取原始记录、真实成果和未知副作用，再处理尚未完成的工作，不直接重发原要求或逐条重放工具。系统接续不伪造用户输入，不扩大授权或代答问题。纯接续执行轮在固定头部显示持久接续关系指向的准确原始用户输入，并标注“继续上次要求”；该展示只借用来源快照，不作为新的用户消息写入历史或改变分页顺序。主动停止、必要决定、身份失配及无法核对的活动工作仍受保护。

用户主动停止后，旧轮状态仍未知时，界面提供“结束等待并继续”。该动作不等待旧原生观察或资源释放证明，按准确原轮和当前版本显式接续；新轮强制使用独立上下文，保留旧执行、未知命令和必要问题，先核对已有成果及可能仍在运行的操作，不重发原输入、不代答问题，不宣称旧工作已停止。未取得受理回执也不能阻塞这个出口；已有待发送要求应先处理，重复提交复用同一新执行。原有已释放恢复与关闭对话的限制不因该出口放宽。

接续沿用现有持久尝试记录，以 `host-recovery:<原 runId>` 去重，并与暂时失败重试共用每条链最多三次的预算和退避。发送前重启恢复同一提交身份，重复扫描不增加次数；用户停止或新输入改变当前执行后，过期恢复不能继续发送。准确控制资源释放后由后台自动唤起接续，不依赖页面刷新或用户补发“继续”。Buildr 宿主接入时更新自身拥有来源的恢复策略，使旧启动参数不阻止新策略生效；其他嵌入方的显式设置仍保留。预算耗尽时保留已有成果和具体原因，不伪称目标完成。

### 异常参数流与整轮停止

共享模型入口在同协议直通和跨协议转换前，按工具调用身份有界检查参数增量：参数总量1MiB、连续空白32KiB、单事件8MiB。异常时中断准确上游请求并返回原协议错误；不反复解析累计参数，不保存参数正文。普通流字节保持原样，超限不冒充完成。

整轮停止先持久保存取消意图，中断该轮模型租约（Lease）并拒绝迟到调用；DSH 在准确执行谱系内暂停目标、取消派生子任务和所属后台工作，再确认空闲。重新连接但没有原轮控制权时明确失败并保留原工具快照。原生取消失响应时，只可终止身份完全匹配且没有其他受保护工作的独占宿主进程组；共享宿主不强停。已完成成果保留，缺少完成回执的工具仍为未知。重新读取不重发，重试沿用原提交身份，旧执行未释放和副作用未核对时不得另跑一份。

原生消息通道（RPC）在逐条投射与持久化之间按8条或8毫秒让出调度，并对标准输出施加背压（Backpressure）。密集模型输出不能占住整个后台，让读取、停止和定时任务得到执行；消息保持原顺序，已收到的回复在进程退出时先排空，不能因主动让出调度误报回执丢失。

开发应用提前激活执行后台时，当前来源与旧范围来源 `legacySourceId` 均显式绑定 `buildr`，与正式网页宿主（Host）保持一致。接受健康检查不等于能创建对话；真实进程检查须覆盖激活后经宿主建立同范围对话。

旧后台交接继承错误来源时，激活入口先用真实只读查询识别；只有来源失配且全部新旧后台空闲时，才由公开生命周期能力重建并重新核对。存在运行工作或退出未确认时保留原后台，不能把接受连接当作激活成功。

### 后台变化依据与失败说明

新进程只按准确前任记录比较运行内容摘要，保留检测时间、前任代次及前后摘要；摘要不同表示运行内容变化，相同表示同内容进程重启，不推测触发者或提交。观察随既有私有实例记录持久保存，仅在原生会话交接的前任代次匹配时进入交接事件；旧历史缺少证明时显示来源未记录，不回填。

失败提示分别读取受理事实和工具结果：未确认受理不等于未送达；工具未结束或结果未知时先核对，不授予重放。普通对话记录保留与原生会话可恢复是不同事实，界面不以记录存在承诺原生执行成功。原始技术诊断保留在可展开详情中，恢复和控制规则不变。

执行异常由 Agent Service 统一恢复：执行器将协议坏流、观察断连和进程退出归一化为可选故障事实，保留脱敏原诊断；服务按准确观察、控制资源释放、未回应问题、当前输入和持久预算决定接续。输入受理、执行结束、资源释放与工具操作结果分别保留，恢复先核对原对话和已有成果，不猜补工具参数或重放未知操作。旧执行器未提供结构化故障时继续原有策略。

Buildr 隔离 DSH 的前台 shell 超时由原生执行器终止，默认层覆盖配置关闭自动转后台；独立能力预设仍返回超时提升结果时，原生工具结果钩子按 原生工具返回的 jobId 与 owner 核对归属并执行 jobs.kill/wait，确认后返回超时失败，未确认则保留作业与准确提示；只有显式 `run_in_background` 的服务继续保留原生作业身份。`tools-active` 表示模型结束但后台作业仍在，不能仅凭它保持活跃提醒或计入模型执行统计；未读、待决策和其他模型运行仍独立保留。历史仍显示后台状态并提供准确停止，统计变化不证明作业退出或资源释放。旧缓存活跃标记通过版本匹配的轻量状态头只读重算。

## 怎样核对 Buildr 参与了哪些内容

当前候选在原输入尝试和原私有对话记录附加可选参与元数据（工具观察以原工具 ID 关联，不改变旧公开条目形状），不复制正文或建立第二份执行流水。执行器在显示截断前记录实际收到的文本体积和可证明的错误／退出码；应用只标记已知 Buildr 发送包装及适配器报告的交互策略，原输入与工具身份负责去重。恢复的旧记录可以没有字段，不能解释为未使用。

宿主通过可选 `observeParticipation` 能力复用资产来源查询，提供有界规则／技能可发现观察，并核对当前安装或开发 CLI 入口。来源确认只确认对象归属；当前供给版本不反推历史观察版本，PATH 同名命令仍是候选。宿主离线或超时只形成观察缺口，不更改工作结果。

单次 `conversations.participation` 与范围 `conversations.participationSummary` 共用原记录投影；SQLite 中的参与索引以对话修订校验，可删除重建，失效时返回部分覆盖。页面和准确绑定的对话控制脚本只读同一应用。汇总区分来源、动作、结果与版本依据，失败比例排除未知结果，字节不换算费用。隐式加载不可观察，统计只能为优化提供线索，不能自动判定资产无价值。详见 [候选设计](../../../openspec/changes/archive/2026-11-03-observe-buildr-participation/design.md)；候选实现及本机测试不等于已激活或真实账号验收。

当前“Buildr 参与”和“Buildr 参与汇总”两个界面入口暂时隐藏；自动采集、存储、只读查询及内部查看实现保留。隐藏状态不挂载面板、不自动请求参与数据。


## 对话事件回推（按凭据）

统一视图的提交出口 `ConversationEvents` 将状态变化交给私有包 `@buildr-ai/buildr-agent` 的按凭据回推投影，不修改执行器或任务记录。只有被程序接入凭据接管的对话才生成事件：`decision.requested`、`run.progress`、`run.completed`、`run.failed`、`run.stopped`、`run.stalled`。事件含 machine、对话与 run 身份、当前凭据 `scopes`/`allowFullAccess`；终态事件含完整 `finalReply` 和只读取该 run 最终回复的 `finalReplyUrl`；决策卡含全部问题、选项及回答身份。只有已写完（`status=completed`）的 assistant 中间消息按 run 至少五分钟一次合并推送；运行中连续二十分钟无消息、工具或状态记录才产生一次停滞事件，单个长工具运行期间的观察心跳与工具正文重新投射（native 骨架、按需读取）都不算活动，计时锚定最后真实记录时间，恢复后重新计时。程序发现入口返回 `buildId`，操作目录、单操作文档（`x-buildr-build-id`）与帮助同步显示；完整 OpenAPI 正文不写入 `buildId`，`contractVersion` 仍只摘要 API 契约内容。

凭据回推配置由 Buildr Web 宿主管理，密钥保存在本机私有文件；管理入口仅网页会话可用。事件投影在 `programmatic-pushback.sqlite` 事务保存并进入持久事件流，按凭据限流合并、租约领取、仅 2xx 确认、指数退避及重启补推；总开关停用只停止投递，仍可经 `events` 补查，单事件开关关闭则不生成对应进度或停滞事件。接收端只接收与转发，不承担业务判断与投递调度。详细配置、payload 字段、轻量回复接口与联调口径见产品 Buildr Skill 的 `references/agent-operations.md`。候选验证、共享服务采用和接收端处理是不同事实，不相互替代。
问题接续的服务策略位于[对话应用](../../../services/buildr-agent/src/application/conversation-application.ts)，安全释放与通用兜底位于[问题等待释放](../../../services/buildr-agent/src/application/question-wait-release.ts)。[执行器契约](../../../services/buildr-agent/src/contracts.ts)的可选 `endQuestionWait` 只允许释放准确纯问题等待；[Codex适配器](../../../services/buildr-agent/src/executors/codex/index.ts)使用原生轮次中断并等待真实终态，不调用后台终端清理。未提供该能力的执行器由服务在原生观察证明“仅问题等待、无工具与后台工作”后调用通用控制。释放意图保存在原尝试记录，防止重启或响应丢失后重复操作；原问题回答与释放互斥，工具审批不因新轮自动批准或撤销。


## 按轮交接与来源读取

交接仍按实际轮次组织用户输入、追加、纠正、问题回答、助手说明与最终答复；没有最终答复或执行未知时明确保留。正常交接直接组织消息，超过接收预算时给有界的轻量轮次目录及可直接使用的 `history` 参数，不要求智能体先整文件读取内部索引，也不依赖辅助模型摘要。目录仅列最近且预算容纳的轮次，省略时明确说明，并保留不指定轮次的全来源分页入口。交接说明是可选导航，不能替代原始要求或提升历史授权。

`handoff-materials/<conversation-id>/index-<digest>.json`的新来源只保存轮次元数据、条目修订和必要工具元数据，不再导出整轮正文。新原生工具同时保留准确调用引用，因此交接时仍在执行的工具可在结束后从原生会话读取；不因展示状态更新而失去调用身份，也不保留正文兜底。索引身份固定覆盖范围，相同来源复用文件。旧已发来源和回执继续可读，本轮不破坏性清理历史路径。

本对话控制命令的`history`按`sourceId`、可选`roundId`、`cursor`与`limit`读取消息及工具元数据。可选 `view: messages` 只读消息和通知，适合先核对用户要求、纠正、问题回答与助手说明；省略视图或使用 `all` 保持原有消息和工具元数据结果。游标按所选视图筛选后的集合计数，返回`nextCursor`时保持来源、轮次和视图不变继续分页。`truncatedIds`是明确的消息片段，`unavailable`逐条标明缺失修订。`entry`携带同一来源、条目ID和修订读取完整消息或原生工具详情。范围只允许当前绑定对话，子对话从自身冻结继承读取；缺失不重放或修补原记录。

已发回执只保留来源、轮次元数据和实际发送正文的SHA256，不重复保存整份提示词。交接抽屉按展开读取轮次，工具继续单独展开读取。预览中可见的消息与工具概况不代表已读取全部工具详情；发送身份、原生恢复和执行资源释放仍独立核对。

公共存储按用途维护，不设容量预算或因大小提前淘汰：已安装运行环境和依赖有引用就持续保留；无视图引用的不可变对象从最后硬链接引用变化起至少保留30天，并完整校验及复查占用。npm/pip等下载正文缓存保留30天，Node/Python编译加速缓存7天，已确认结束的测试临时现场沿原24小时窗口。Yarn/uv可能兼作已安装依赖来源，未证明外部安装引用已解除时不整目录过期删除。宿主Maven仓库、原生会话、账号、工具安装和_npx不统一过期。

原维护worker自动发现所有连接及模型域的HOME，包括未来执行器；有界扫描只读文件元数据，不跟随链接。最新发现写入私有`agent-service/process/storage-observation.json`，报告生成时间、扫描完整性、观察到的逻辑/路径分配量、工具归属和调查动作；它是可替换的诊断快照，不是引用库或删除依据。Agent可通过公开inspectAgentStorage即时读取同样结果。未知目录只形成调查线索。旧私有HOME内的无用编译缓存可按整类退役；安装依赖和下载内容在统一位置覆盖或组件废弃未证明前保留，不要求人工逐包审批。清理前后仍须核验执行/恢复引用、系统占用与对象版本。公共环境设置node-gyp与Corepack路径，后续可重新下载或构建；账号、原生会话、恢复数据、任意安装及成果保留。保留窗口不构成下载内容的单独删除依据。

缓存使用观察位于toolchains/cache-use，六个零正文文件记录保守的最后可能使用时间。公共执行入口在真实原生轮开始和结束更新观察，程序安装更新npm下载观察；维护发现消费者或恢复引用时也延后窗口。首次维护才发现的旧缓存从当前重新起算，缺少/损坏观察保留，不用目录mtime推断最后使用。删除前再次核对使用观察和原引用/占用/身份，不增加包索引数据库；观察写入不触发任务重发。

## 中断诊断的私有时间线

Agent Service 在实际产品数据目录的 `agent-service/diagnostics/` 保存 `lifecycle-<pid>-<generation>.jsonl`。先从实例记录核对准确数据目录和后台代次，再用 `conversationId` / `runId` 查 `run-state`，沿 `executionId`、`contextId`、`controlId` 与 `childPid` 串起原生进程事件。`service-start` 的前代标识和 `service-launch` / `service-child-exit` 可连接跨后台恢复，不按同名进程猜归属。

`stop-request` / `stop-result` / `stop-failed` 表示控制请求及结果；`native-close-request` 和 `native-signal` 区分拥有者关闭、关闭超时升级信号与停止执行。`native-exit` 保留真实退出码或信号；`service-uncaught-exception` 只保留错误代码，`service-signal` 与 `service-close-result` 标识正常退出路径。`observation-lost` / `observation-restored` 标记连接观察故障及恢复，不能当作命令结束。`native-tail-repair` 表示恢复时观察到原生补齐的未知回执；日志 `time` 是本次实际观察时间，不把原生日志沿用的工具时间当成真实中断时间。

日志只保存结构化标识、状态、计数和错误代码，不保存提示词、工具参数输出、环境、认证地址、Cookie、完整错误或堆栈。目录权限 `0700`，文件 `0600`；每个后台的日志单文件最多 2 MiB，轮换两份，每次创建写入器最多保留 64 份非活动进程日志，活动进程日志不因跨后台清理而删除。日志不可写会输出一次固定诊断，不改变执行和恢复策略。

SIGKILL、主机断电或父子进程同时被强制终止时，进程自身可能来不及记下退出。后继启动的前代关联、缺失的正常关闭回执及仍存活父进程的子退出记录可缩小边界，但不能单凭“没有日志”认定退出信号或操作者；需要系统级审计才可能进一步证明。旧无标识混合日志只能作线索，不能填补历史事实。

历史副本清理沿原worker、锁、占用与版本复查处理无用编译缓存及Qoder已完成载荷；下载和安装依赖的复用价值未核实前保留。缓存消费者与会话恢复证据分别判断：控制已释放，或旧执行确认结束且准确控制组已消失时，历史结果证据不永久保护下载缓存；未知业务结果、原生会话和恢复证据保持原状。活动、待发请求、占用或观察失败的对象保留，后续维护自动重试。宿主目录仍由原工具和操作系统管理，Buildr不取得统一删除权限。

宿主标准缓存与Maven仓库尚未创建时，服务在已核对且可安全写入的宿主HOME下逐级创建标准目录，不复制账号配置，不下载包；拒绝链接逃逸，宿主不可用时保留共享兼容目录。

通用编译缓存同样优先宿主公共目录：macOS默认使用`~/Library/Caches/node-compile`和`~/Library/Caches/python`，其他平台使用用户缓存根；明确的公共配置优先。Node自行按版本/架构隔离编译结果，三家Agent只隔离原生账号/会话。公共路径约定不代表其他应用自动配置共享，也不赋予Buildr删除整个宿主缓存的权限。旧私有编译缓存等待原消费者释放后退役，不重新写回私有目录。Buildr原生程序、可恢复运行版本、不可变共享对象与管理记录仍归应用数据目录，不冒充系统包缓存；插件保留共享种子和必要的独立可写工作副本。

公共编译缓存的消费者核对复用缓存用途引用，不将仅需保留的原生历史当作缓存消费者；待发送、未释放工作、身份不明或占用仍保护。Node/Python明确切到宿主公共目录且旧消费者消失后，原Buildr编译目录按退役处理，无需再等待当前缓存保留窗口；删除前再次核对公共选择、使用引用和身份。下载内容不适用该退役路径。

升级后的退出与回收规则对开发版/正式版使用同一实现：退役后台仍持有工作时保留，原生资源准确释放后自动退出，维护worker回收已无引用程序。pending中的adopted只是完成回执，不能永久保护旧程序；已确认退出且实例身份精确匹配的旧current指针也不再保护程序。待采用、未知状态、不匹配回执、活进程及必要回退继续保留，回收后仅清理对应程序的过期控制指针，不改写业务结果。

旧npm下载缓存沿现有worker批量合并到选定公共npm目录，原排他发布器保留宿主已有索引，以npm自身cacache完整性读取验证所有旧正文与可用键，并在删除前复查源目录、目标文件、引用和占用。未索引正文也保留按摘要复用价值；失败或活动时保留旧目录，下次维护重试。不移动npm凭据，不删除_npx安装工具，不以年龄清空宿主缓存。

Codex的logs_1/logs_2只有经适配器读取完整SQLite视图证明是纯日志schema后，才进入原诊断维护；UUID不冒充PID。整份配置静止、无执行消费者且满足稳定窗口时，数据库/WAL/SHM整体改名复查，任一成员变化全部恢复，主文件最后删除。原生会话、state、thread_history、账号、记忆及队列数据库不按此策略删除。
