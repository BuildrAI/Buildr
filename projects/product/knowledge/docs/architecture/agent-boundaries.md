# Buildr 与智能体的责任边界

Buildr 接入成熟智能体（Agent），让用户在同一工作现场表达目标、执行并验收。产品价值在工作资产、明确对象、交互和结果，不以重新实现推理循环为前提。本说明吸收接入讨论中的分层思考；具体可观察行为以 OpenSpec 主规范及当前 `agent-process-isolation` 候选增量为准。

## 为什么采用接入

| 层次 | 当前责任 |
| --- | --- |
| 模型权重与推理契约（Inference Contract） | 厂家提供模型及调用约定，Buildr 按真实可用能力选择 |
| 智能体内核（Agent Harness） | 原生程序负责推理循环、上下文组装与压缩、工具选择及原生会话恢复 |
| 工作协调与界面 | Buildr 负责独立接入、统一可见对话、显式上下文、执行控制及工作对象的准确关联 |
| 业务能力与外部工具 | 原业务能力维护状态和写入边界；智能体按任务选用已有工具，Buildr 提供自己的确定性能力与必要使用方法 |

这是一张责任解释图，不表示各家实现具有完全相同的分层，也不表示 Buildr 已替代厂家的全部编排或生态。同模型跨内核体验差异可能来自提示词、工具、上下文处理和模型协同适配；当前实验没有对这些因素作受控归因，不能把体验判断当作定量结论。

接入保留厂家成熟执行能力，允许 Buildr 先验证日常对话、工具工作、停止及恢复的实际闭环。适配器（Adapter）把协议差异限制在厂家边界；公开服务契约允许以后新增自研执行者，但不预先显示尚不存在的能力。三条真实接入及已验证边界见[智能体接入](agent-integration.md)。

## 进程独立后的依赖方向

执行后台（Execution Backend）持有对话、原生执行、交接、待回应、模型与私有数据；Buildr 持有页面接入、工作对象权威、任务状态和业务校验。两者通过执行操作、宿主能力、运行管理三组版本化契约（Contract）连接。宿主可以替换，准确来源及观察版本不能省略；默认目录可以没有业务任务。

后台可以调用 Buildr 提供的宿主能力，但不能导入 Buildr 的任务、工作空间、网页模块或内部验证器。以后增加独立产品入口时，可以替换页面与宿主实现，复用同一客户端（Client）和执行后台；本轮不实现独立产品、单独发行或新的推理循环。

## 上下文与工具如何分工

Buildr 提供明确目标、约束、工作目录、已有对象身份及必要可见接续材料。原生内核决定每次模型请求如何组合、压缩和使用这些材料。工作资产保持可检索、可独立查看；对话不成为代码、文档或业务状态的唯一权威。

原生账号保持独立；工具路径线索不代表继承外部桌面的凭据、技能或扩展。浏览器验证由智能体按随包方法检查和准备现成工具，优先复用本机安装，缺失时沿用官方机制。Buildr 不实现另一个浏览器引擎、插件市场或通用工具管理器；电脑操作（Computer Use）暂不纳入第一版。

## 什么时候再考虑自研

需要改变推理循环、上下文策略或工具语义，厂家路线成为已证实瓶颈，或成本与数据约束无法通过现有接入满足时，才值得评估自研。届时需承担循环正确性、工具协议、请求级上下文、模型适配、停止与恢复，以及持续兼容演进；不能仅把模型接口接到聊天窗口就视为等价替代。

未来自研执行者仍应满足同一公开契约。工作资产、业务写入边界、统一交互和确定性能力可以复用，实际效果仍按真实结果与外部观察验收，不根据对内核内部行为的猜测宣称完成。
