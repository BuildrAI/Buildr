# 日常使用 Buildr

[阅读目录](../README.md) · [开始使用](getting-started.md)

准备好工作目录后，像平时一样向智能体（Agent）表达目标。Buildr 提供项目资料、工作方法和记录；你参与判断，查看实际成果。

## 说清目标与边界

给出问题、已有材料、期望结果和修改范围即可。不知道文件在哪里时，先描述问题：

> 检查退款失败的原因，结合业务约定和代码说明依据，暂时不要修改。

> 按刚才确认的方案完成修改，保留无关内容，验证后说明结果和剩余问题。

这些不是固定口令。智能体（Agent）负责查找依据、选择方法和准备适合的工作位置，不需要你先操作内部流程。

| 目的 | 可以这样说 | 应得到的结果 |
| --- | --- | --- |
| 了解 | “先调查，不修改。” | 结论、依据与不确定项 |
| 讨论 | “给我范围明确的方案。” | 目标、取舍与验收方式 |
| 实施 | “按方案做。” | 实际改动与必要检查 |
| 接续 | “读取最新资料，继续这项工作。” | 已完成、剩余部分与后续行动 |
| 交付 | “收尾。” | 成果到位、已有结果登记与遗留说明 |

## 通过网页查看与参与

让智能体（Agent）打开 Buildr Web，选择对应工作空间（Workspace）和项目（Project），查看资料、任务（Task）与成果。

任务（Task）详情按“任务需求、方案设计、开发实现、任务收尾”组织材料。网页可以准备交给智能体（Agent）的指令，复制到相应对话后继续；保存答复不会自动唤醒执行。使用生成指令时确认内容仍与当前目标一致。

## 中断或换人之后

继续同一目标时，提供任务（Task）标识或成果位置：

> 继续这项工作。先读取最新目标、我的答复和实际改动，说明已经完成与剩余部分，再在已有授权内推进。

关键在于读取当前成果，而不是复述旧对话。多个独立目标可以分开推进，最终仍按整体目标验收；具体方法见[任务协作](../architecture/task-system.md)。

## 怎样算交付完成

看实际文件和目标系统：改动是否到位、检查覆盖了什么、哪些问题还没有解决。任务（Task）的完成状态本身不能证明代码已推送或应用已更新。

明确说“收尾”，会授权当前工作范围内的常规 Git 提交、集成和普通推送。发布、部署、改写共享历史或覆盖他人内容等更大影响，需要明确授权。精确边界见[核心规则](../../../services/buildr/resources/workspace/AGENTS.md)。

## 留下有用的方法

经过验证、以后还会用到的方法，可以请智能体（Agent）整理成技能（Skill）。资料变化时更新原文；不要为同一个主题不断新建说明。复盘和每日演进按实际需要使用。

需要备份或更新时读[数据保全](data-and-upgrades.md)，出现具体问题时读[排查问题](troubleshooting.md)。
