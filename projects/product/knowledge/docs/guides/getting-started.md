# 开始使用 Buildr

让智能体（Agent）协助安装，在 Buildr 中配好工作范围，再到你熟悉的智能体（Agent）工具中开始工作。本页先说明怎样开始与判断完成；更新、恢复和数据保全按需查阅。

[阅读目录](../README.md) · [了解 Buildr](../overview.md) · [工作对象之间的关系](../architecture/project-service-repositories.md)

## 安装与配置

把本项目链接交给正在使用的智能体（Agent）：

> 请参考 https://github.com/BuildrAI/Buildr 帮我安装 Buildr 和启动器（Launcher）。结合我的工作解释工作空间（Workspace）、项目（Project）、服务（Service）和代码库（Repository），打开 Buildr，引导我完成必要配置。已有资料和代码请继续使用，不要覆盖或重新初始化。

智能体（Agent）核对环境和当前发布版本，安装官方包 `@buildr-ai/buildr`。安装包包含网页；macOS 和 Windows 使用启动器（Launcher）打开，其他平台通过本机浏览器使用。普通使用无需克隆本仓库，也不需要先学习命令。

先确认共同工作的目录，再说明项目（Project）要实现的目标；涉及代码时，关联承担实现职责的服务（Service）及实际代码位置。没有代码也可以先组织资料，不必把所有对象一次建齐。登记关联不会自动克隆或移动代码，需要时由智能体（Agent）协助处理。[关系说明](../architecture/project-service-repositories.md)解释怎样选择这些对象。

配置完成后，在智能体（Agent）工具中打开**同一个工作空间（Workspace）目录**。它负责核对适用资料与方法是否可发现，必要时按[工具适配说明](../../../services/buildr/docs/agent-runtime-adapters.md)刷新入口。

满足以下结果，就可以开始实际工作：

- Buildr 能打开，显示的是你要使用的工作空间（Workspace）。
- 项目（Project）的目标、资料及所需代码位置正确；暂不需要的对象可以不建。
- 智能体（Agent）工具已打开同一目录，能够读取当前资料和适用方法。

没有可用的智能体（Agent），或需要手动恢复时，查[安装与恢复命令](../../../services/buildr/docs/cli-reference.md#首次使用)。已安装版本的 `buildr help` 提供本机命令帮助；具体安装和恢复方法由随包 [Buildr 技能（Skill）](../../../services/buildr/resources/runtime/skills/buildr/SKILL.md)维护。

## 在智能体（Agent）中工作，在网页中查看

像平时一样给出目标、已有材料、期望结果和修改范围，例如：

> 为订单列表增加按状态筛选，沿用现有界面和测试方式。完成后说明改动、验证结果和仍未解决的问题，并更新受影响的资料。

只想了解问题时，说明“先调查，不修改”；需要先讨论时，说明“先给出范围和验收方式”。这些不是固定口令。智能体（Agent）负责查依据、选择方法和准备工作位置，你参与真正需要判断的取舍。

Buildr 用于查看资料、已登记的任务（Task）、进展和成果。需要持续跟进的工作，让智能体（Agent）保存目标、关键进展和成果位置。聊天与 Git 提交不会自动变成工作记录；网页保存意见也不会自动唤醒执行，需要回到智能体（Agent）工具继续。详细协作方式见[从讨论到交付](../architecture/task-system.md)。

## 接续与交付

中断或换工具后，给出已有任务（Task）标识或成果位置，请智能体（Agent）先读取最新目标、你的答复和实际改动，再在已有授权内继续。接续依据当前成果，不只复述旧对话。

验收时看三件事：实际成果在哪里，哪些检查已通过，还有哪些问题或未完成动作。任务（Task）显示完成，不等于代码已推送、应用已更新或已经发布。

明确说“收尾”，会授权当前工作范围内可核验的常规 Git 提交、集成和普通推送。发布、部署、改写共享历史或覆盖他人内容仍需相应的明确授权，详见[核心规则](../../../services/buildr/resources/workspace/AGENTS.md)。经过验证、以后还会使用的方法，可以请智能体（Agent）整理为技能（Skill）；资料变化则维护原文，避免再造一份说明。

## 更新与数据保护

在对应工作空间（Workspace）中告诉智能体（Agent）：

> 更新 Buildr 和这个工作空间（Workspace）。先核对当前版本、目录和已有数据，保留可恢复的副本；完成后分别说明产品版本、网页与启动器（Launcher）是否可用，以及这个工作空间（Workspace）是否已采用更新。不要覆盖原资料或直接降级数据。

**更新 Buildr 包含网页。** 工作空间（Workspace）采用新能力还需要同步工作资产与当前工具入口；正在运行的旧实例、启动器（Launcher）绑定和工具加载结果也要核对。无需另提一次网页更新，但仅安装新版包不能证明这些结果都已完成。

你需要知道备份在哪里、重要资料与本机记录是否仍可读、哪些结果已验证。Git 不包含全部本机记录。备份与恢复的具体检查由智能体（Agent）或维护者完成，见[数据保全与恢复](../architecture/buildr-data-design.md#数据保全与恢复)。先停止相关写入再备份；关闭浏览器不等于停止 Buildr，不能只复制运行中的 SQLite 主文件。当前没有统一备份或跨机器自动恢复工具。

## 按现象排查

把错误原文交给智能体（Agent），先核对实际版本、目录与工具并保留现场。不要通过删除整个 `.buildr/`、重新初始化或改写受管输出来“清空错误”。没有智能体（Agent）可用时，按对应参考处理。

| 现象 | 先核对什么、依据在哪里 |
| --- | --- |
| 安装失败、无法启动 | Node.js 要求和实际安装入口，见[安装参考](../../../services/buildr/docs/cli-reference.md#首次使用) |
| 更新后页面仍旧、版本不清 | 实际产品版本、所选更新轨道、旧进程及启动器（Launcher）绑定；确认归属后正常退出旧实例 |
| 工具看不到技能（Skill） | 工具身份、目录与刷新要求，见[适配说明](../../../services/buildr/docs/agent-runtime-adapters.md)；入口缺失时查[入口恢复](../../../services/buildr/docs/cli-reference.md#入口不可用与恢复) |
| 页面没有资料或任务（Task） | 当前目录、筛选、登记和本机记录；换机器不会自动带来历史 |
| 知识链接打不开 | 文件存在性、阅读关联，以及链接指向正文还是图源；GitHub 不直接运行交互图 |
| 保存提示冲突 | 重读其他入口的修改，再决定如何处理，不覆盖新内容 |
| 更新提示数据或迁移问题 | 停止写入、保留现场和副本，再核对程序与数据版本 |
| 关闭浏览器后仍在运行 | 通过页面“退出 Buildr”停止；异常进程先核对归属 |
| 交付或发布部分成功 | 保留已从 Git 或目标平台确认的结果，只恢复剩余动作，不重复发布 |

已有工作空间（Workspace）可让智能体（Agent）按[命令参考](../../../services/buildr/docs/cli-reference.md)执行诊断。诊断只证明实际检查范围，不证明工具已经加载方法或业务目标已完成。安装归属、来源或授权不清时，只暂停受影响操作。

需要反馈时，向 [GitHub Issues](https://github.com/BuildrAI/Buildr/issues)提供系统、Buildr 与 Node.js 版本、所用工具、目标与步骤、期望和实际结果、错误原文，以及首次安装或升级来源、是否可在无敏感数据的目录复现。去掉令牌（Token）、实例密钥、个人路径与业务内容；疑似漏洞按[安全报告](https://github.com/BuildrAI/Buildr/blob/main/SECURITY.md)私密提交。
