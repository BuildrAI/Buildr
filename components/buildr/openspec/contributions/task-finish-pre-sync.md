在任何 canonical spec sync 前，从 Buildr workspace root 和 Project registry 解析 `<workspace>`、`<project>` 与 `<change>`。当 Change 有 delta specs 时，先调用 Task Finish 的 archive rehearsal helper；helper 必须在隔离 planning copy 前一次聚合全部可检测的 MODIFIED Requirement/Scenario compatibility findings，再使用当前 OpenSpec CLI 预演 archive。记录 OpenSpec version、Change、owner、结果、cleanup status，以及绑定 change、delta/canonical digest 和 executable identity 的 convergence receipt；任一 finding、rehearsal failure 或 cleanup retained 都必须停止。没有 delta specs 时记录 not-applicable。

随后运行 `buildr openspec check <change> --stage pre-sync --project <project> --target <workspace> --json`，并只在 receipt 仍处于 `rehearsed` 且 identity 未变化时推进到 `pre-sync`。active change 的 apply 阶段不得预写 canonical specs，只有 check 返回 `ok: true` 后才可执行 agent-driven canonical sync，再把同一 receipt 推进到 `canonical-sync`。结果不是 `ok: true`、receipt stale 或顺序不匹配时，停止尚未执行的 canonical sync、final assurance、archive、commit、rebase、merge、push 或 cleanup。Rehearsal 不替代 pre-sync/post-sync，也不得修改真实 planning root；canonical 已改变后不得刷新 baseline 或重新领取 pre-sync 来制造事后授权。
