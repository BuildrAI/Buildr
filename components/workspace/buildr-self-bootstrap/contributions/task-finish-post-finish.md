### Buildr 自举 Workspace 激活

本节是当前自举Workspace对整份Task Finish Skill的更具体覆盖规则；Agent必须在执行`finish run`前读取本节，不能先按前文把所有blocked Result终止后再处理本节。它只改变retained Doctor blocked后的Agent下一步，不改写Product五阶段或把Doctor failure伪装为passed。

以下两种Result只调用一次`buildr-self-bootstrap-sync`，该Skill再只启动一次自身携带的`scripts/closeout.mjs`：

- `complete`：同一个Formal Task Finish Result成功、Environment cleanup完成且最终报告尚未完整收尾；
- `doctor-blocked`：同一run已经完成carrier交付与remote readback，phase为`deliver`、唯一current failure operation为`retained-doctor`、存在matching product resume token、Environment尚未cleanup，且冻结Task Contribution至少命中一个专属动作。

调用只传`run id`、canonical Workspace与Environment retained Node executable；runner通过Product CLI的`--detail self-bootstrap`只读取得`buildr.task-finish-self-bootstrap-input/v1`稳定投影，并从中消费Task、Agent、remote/target、唯一Workspace repository、run container、repository carriers、final或remote-after ref、resume token与冻结Task Contribution paths。内部Task Finish Result major只由Product projector归一化，Agent和runner不得直接解析。多仓库Task只使用Workspace repository的activation paths；Service repository不能触发根自举，Workspace无贡献时直接`not-applicable`。不得由Agent创建或修改execution capsule，也不得从HEAD、dirty tree、当前diff或时间重新分类贡献。非Doctor failure、partial delivery/remote evidence不完整、matching product resume token缺失或无适用动作时保持普通blocked结论，不调用专属Skill。

Skill本地runner通过Product只读Finish inspect取得同一稳定投影并形成单一去重plan。它首先只读证明carrier inventory：matching current与每个可证明foreign run container及其全部repository carrier必须满足非symlink、受container包含、selector/identity/realpath唯一且resume identity匹配；经证明的foreign container只作为精确untracked ignored root隔离，tracked/staged差异仍阻断。foreign cleanup或occupancy释放只作为原owner advisory，不阻塞当前closeout，也不授权跨owner恢复或删除。未知稳定投影major、symlink、越界、重复realpath、inspect失败或Workspace/path/carrier/resume identity不可证明时，在activation effects前fail closed。

完成Git root、target branch和clean tree证明后，runner在任何retained target mutation、sync、安装、重启、入口验证、Doctor或Finish resume前，以`Task/run + remote:targetBranch`通过retained Product内部driver获取Task Finish target lease，并在每个潜在副作用阶段前刷新、按token fencing释放。另一个owner占用相同target时，以空activation effects返回可重试waiting diagnostic；不同target不因该lease互相阻塞。matching terminal complete row和retained Doctor blocked row都能临时持有self-bootstrap lease；Product resume清除lease后，runner继续前必须重新获取。普通用户Workspace没有本Skill或自举收尾，普通Finish只使用既有短deliver lease。

runner在lease内读取latest remote target；clean retained branch可fast-forward且后继链具有Buildr provenance时只用fetch与`merge --ff-only`更新，再从头核验全部既有preflight。无法fast-forward、出现未知commit/merge/dirty tree/remote或identity漂移时停止，不得merge commit、rebase、stash、reset、force push或冲突猜测。旧`--retry-after-foreign-clear true`参数仅兼容接受，不再形成特殊模式，runner和owner建议不再生成它。

若`doctor-blocked` Result在latest target之后已经落后，runner在sync、安装、重启和Doctor前先用current token恢复同一Finish run；第一次精确返回`task-finish.target-race`时，只再用新token恢复一次，并在每次Product调用后重新获取lease。返回新的complete或retained Doctor blocked Result时重建plan后继续；精确Delivery Adaptation required时返回matching carrier、resume、完整冻结commit message与可移植preparation hints，且除必要的latest-target fast-forward外不得执行sync、安装、重启、入口验证或Doctor。第二次仍race、其他blocked/failed或identity不完整时停止，不调用第三次resume或第二次runner。

取得lease并完成latest-target收敛后，workspace package inputs或Buildr runtime Skill source执行retained sync与精确普通commit/push/readback；push后的remote readback只做固定小次数重试，不重复push。Local App inputs先用instance secret认证安装前默认Development Web，随后用Environment retained Node直接执行retained checkout的development-only Launcher manager。它不得调用npm-owned公开`buildr web launcher`命令；manager结果必须证明同一checkout、HEAD和retained Node后才继续。安装前存在健康development实例时，runner自带helper必须通过retained `projects/product/buildr`、retained Node与新Launcher identity在原loopback端口恢复服务并验证health、新PID、source/HEAD/Node；原本未运行、stale或其他channel时保持按需启动。恢复失败只回收本次启动且PID可证明的异常进程并停止后续动作，不回退已成功更新的Launcher。所有适用动作完成后，runner注入Environment retained Node并显式执行retained `projects/product/buildr`，通过closed development identity核对launcher、CLI entry与Node，再通过`version --json`核对development channel、source commit和package/version；不得解析、执行、创建或覆盖PATH默认`buildr`。该runner只属于当前自举Workspace，不进入Buildr用户npm package或普通Workspace Skill集合。`complete`路径通过已验证的retained Project bridge执行一次最终指定Agent Doctor；`doctor-blocked`路径通过同一显式入口使用current run与matching token恢复同一Formal Finish，由resume中的指定Agent Doctor形成唯一最终结论，成功后才cleanup。没有匹配时记录`not-applicable`，不得覆盖Doctor failure。

条件不唯一、evidence不闭合、lease被占用、Project bridge或入口链/Node/channel/source/version不一致或任一步失败时停止后续不安全动作，并保留runner已报告的阶段effects、lease operation与development entry identity evidence。`complete`路径明确报告“主任务已交付、自举Workspace激活未完成”；`doctor-blocked`路径明确报告“Formal Finish仍被Doctor阻塞、自举恢复未完成”及current product resume事实。不得改写Candidate、Verification、Review、decision、handoff或Task Record，也不得启动第二个orchestrator或绕过runner补做sync、Buildr Web Dev安装、development entry检查或Doctor；只有专用target-race adaptation diagnostic允许Agent按其中matching carrier/token与guidance继续Task Finish owner动作。
